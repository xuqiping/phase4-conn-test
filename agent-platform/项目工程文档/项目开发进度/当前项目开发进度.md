#### 2026-06-02 聊天流式与 Doubao 模型修复记录

**问题现象：**

- `/chat` 页面发送任意消息后，助手消息显示为空或没有可见文字。
- 切换模型时曾误用 `doubao-seed2.0-code`，实际可用模型 ID 为 `doubao-seed-2.0-code`。
- 登录页出现过 `Network Error`，经确认是前端 Vite dev server `5173` 未监听导致的代理失败，不是后端登录接口故障。

**排查过程：**

- 分别验证后端 `8080` 和前端 `5173` 端口状态，确认后端登录接口可直接返回 `200 success`。
- 通过前端代理 `http://localhost:5173/api/auth/login` 复测，确认重启 Vite 后代理链路恢复。
- 直接请求 `/api/llm/user/models/available`，确认数据库中的 Doubao 模型 ID 为 `doubao-seed-2.0-code`。
- 直接请求 `/api/chat/messages/stream`，定位到后端 SSE 流未完整输出，以及 OpenAI 兼容供应商流式 chunk 解析过滤过严。

**修复内容：**

- `ChatController.doStream()` 从只读取首个事件改为完整消费 `sendMessageStream()` 的 Flux，并将 `THINKING`、`CHUNK`、`DONE`、`ERROR` 事件逐个发送给前端。
- `OpenAICompatibleProvider.chatStream()` 支持对响应 chunk 按换行拆分，兼容 `data: {...}` SSE 行和原始 JSON 行，避免 Doubao 流式内容被过滤为空。
- 默认聊天模型、Agent 路由默认模型、工作流 LLM 节点默认模型、记忆提取模型和前端默认选中模型统一改为 `doubao-seed-2.0-code`。
- 前端 Chat Store 对 SSE `ERROR` 事件追加助手错误消息，提升页面可见性。
- 当前故障处理期间发现的 `Network Error` 通过重启 Vite dev server 解决，并记录为运行环境问题。

**验证结果：**

- 后端关键测试通过：`ChatControllerTest,DefaultChatStrategyTest,OpenAICompatibleProviderTest`。
- 后端完整测试曾通过：`mvn -q test`。
- 前端测试通过：`npm test -- --run`，30 个测试通过。
- 直接请求 `/api/chat/messages/stream` 可看到 `THINKING → CHUNK → DONE` 事件序列。
- 直接请求 `/api/chat/messages` 可获得完整助手文本回复。

#### 2026-06-02 Kimi/GLM 协议与认证设置修复记录

**问题现象：**

- `k2.6` 使用 Kimi/Claude 供应商时，聊天流式接口只返回 `DONE`，没有 `CHUNK` 内容。
- GLM 5.1 使用 `https://open.bigmodel.cn/api/anthropic` 时，供应商名称必须写成 `claude` 才能测试连通。
- 登录过期后继续发起请求时，前端没有统一回到登录页；登录超时时间只能依赖后端固定配置。

**根因：**

- `ClaudeProvider.chatStream()` 和早期 OpenAI 兼容流式解析存在同类问题：把 `bodyToFlux(String.class)` 的 chunk 误认为单行 SSE，未按换行拆分，也未兼容裸 JSON。
- `LlmConfig` / `LlmGateway` 使用 `name == "claude"` 判断调用协议，导致供应商名称承担了唯一标识和协议类型两个职责。
- 前端 Axios 拦截器在认证失效时尝试刷新 token，而不是按照当前需求直接清除登录态并跳转登录页。

**修复内容：**

- `ClaudeProvider` 流式解析改为按行处理，兼容 `data: {...}`、裸 JSON 和 `[DONE]`。
- `llm_providers` 新增 `protocol` 字段，支持 `OPENAI_COMPATIBLE` 与 `ANTHROPIC`；供应商 `name` 只作为唯一标识。
- `ProviderManageTab.vue` 增加协议下拉；GLM 当前配置为 `name=glm`、`protocol=ANTHROPIC`。
- 新增 `system_settings` 表和 `SystemSettingController`，管理员可在设置页配置登录超时时间。
- `JwtUtil` 支持传入动态 access token 有效期，`AuthService` 登录/刷新时读取系统设置。
- `request.ts` 对非登录接口的 401 统一清理本地认证信息并跳转 `/login?redirect=...`。

**验证结果：**

- `k2.6` 真实流式接口返回 `CHUNK hello → DONE`。
- GLM 5.1 在 `name=glm` 下测试连通成功，返回模型 `glm-5.1`。
- 认证设置从 `900000ms` 临时改为 `300000ms` 后，重新登录返回 `expiresIn=300000`；随后已恢复 `900000ms`。
- 登录接口复测：后端直连约 301ms，前端代理约 2344ms，未出现请求超时。
- 后端相关测试通过：`AuthServiceTest,JwtUtilTest,SystemSettingServiceTest,LlmConfigTest,LlmGatewayTest,ClaudeProviderTest,OpenAICompatibleProviderTest,ChatControllerTest`。
- 前端测试通过：`npm test -- --run`，30 个测试通过。

## 3. 注册现在有什么限制？ ✅ 已查实（2026-08-22）

| 限制 | 值 | 位置 |
|---|---|---|
| 同 IP 注册频次 | **5 次/60 秒** | AuthService.checkRegisterRateLimit（Redis 固定窗口，超了 429「注册过于频繁」） |
| 同用户名尝试频次 | 5 次/60 秒 | 同上（防盯着抢注/探测） |
| 用户名唯一 | 必检 + DB 唯一索引双保险 | uk_users_username |
| 邮箱唯一 | 填了才查 + DB 唯一索引 | uk_users_email |
| 密码强度 | 6-100 位 + 复杂度策略 + 弱密码字典 + 不能=用户名 + bcrypt 72 字节上限 | PasswordPolicy |
| 协议勾选 | 必须勾《用户协议》《隐私政策》 | @AssertTrue |
| 图形验证码 | ❌ **注册/登录都没挂**（滑块验证码只挂在发短信码上） | —— 见第 4 条 R5 |
| 默认角色 | 注册即 `user` 普通用户 | —— |

配套防线（登录侧，顺带说）：同账号密码错 5 次锁 15 分钟；同 IP 1 小时失败超 20 次封禁；撞库检测；异地登录提醒；TOTP 两步验证（用户可自助绑定）。

## 4. 邮箱登录/注册/找回密码的安全及资金安全风险清单 ✅（2026-08-22，按严重度排）

**🔴 高（直接烧钱 / 直接盗号）**

- **R1 假邮箱批量注册 = 烧 LLM 配额（资金）**：注册不验证邮箱真伪，机器人用 `a@x.com`、`b@x.com` 无限造号。若平台给新号任何免费额度/试用积分 → 每个假号都是真金白银的模型调用费。现有 5 次/60s/IP 只能减速，分布式 IP 随便绕。**建议**：邮箱验证码验证通过才放行注册（或新号未验证前禁调 LLM）。
- **R2 账号无找回渠道即失财**：邮箱可留空注册 → 用户忘密码=账号永久丢失，号里**充值的积分/余额随号蒸发**（用户资金纠纷 + 客服成本）。**建议**：充值前强制绑定并验证邮箱。
- **R3 邮箱失陷 = 全链失陷**：找回密码是唯一重置通道，用户邮箱被盗 → 攻击者一键重置 → 卷走号内积分/资产。重置后虽踢全会话，但攻击者已换新密码。**缓解**：高危操作（改绑邮箱/找回密码）要求过 TOTP（平台已有 MFA，但不强制）；重置成功给旧邮箱发「已重置」告警（现无此通知）。

**🟡 中（骚扰 / 枚举 / 费用）**

- **R4 邮件轰炸（资金+口碑）**：重发验证 60s/邮箱、找回 3 次/h/账号——都按「目标邮箱」维度限，攻击者拿你的平台当免费轰炸机给别人邮箱刷屏（发信走阿里云/邮件服务，**按量计费=资金**，且被邮件商拉黑影响送达率）。IP 维度只有找回有（10/h），**重发验证没有 IP 维度**。**建议**：重发/找回统一加 IP+全局双维度；同 IP 日发信总量封顶。
- **R5 注册/登录无图形验证码**：滑块验证码组件已有（CaptchaService），但只保护发手机短信码。注册、登录、找回三个公开端点裸奔 → 自动化脚本零成本。**建议**：连续失败 N 次后强制滑块（渐进式，别一上来就烦正常用户）。
- **R6 用户名枚举**：注册接口直接回「用户名已存在」→ 攻击者可批量探测已注册用户名，为撞库/钓鱼供弹药（登录侧已用统一话术+dummy bcrypt 堵死，注册侧还开着）。**建议**：若改邮箱验证码注册，此口自然消失；短期可接受（用户名非敏感标识）。

**🟢 低（已防住，列着安心）**

- R7 找回 token：30 分钟 + 单次用完即删 + SecureRandom 随机 → 已防重放/爆破。
- R8 密码：bcrypt + 弱密码字典 + 新旧密码不同 → 已防弱口令。
- R9 重置后踢全部会话（含攻击者已登录的会话一并踢）→ 已防「改了密码还被挂着」。
- R10 全程审计（register/login/login_locked/ip_banned 落 audit_log）+ 异地登录提醒 → 事后可追溯。
- R11 短信找回密码未实现（TODO 抛「暂未实现」）→ 入口别开，开了就是半成品暴露面。

**一句话总结**：框架防线（限流/防爆破/审计/MFA）都在，**最大缺口是「注册不验邮箱真伪」+「注册/登录没挂图形验证码」**——这两个决定批量假号的成本，直接挂钩模型调用费。要不要做（改邮箱验证码必填注册 + 渐进式滑块），你拍板，做的话按 SDD 流程起规格。

## C. 腾讯邮箱个人接入（傻瓜式，两条路）

### 路线 1：QQ 邮箱（纯个人，5 分钟，无需域名）
1. 浏览器开 **mail.qq.com**，登录你的 QQ 邮箱。
2. 顶部「**设置**」→ 点「**账户**」标签 → 往下滚到「**POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服务**」这一节。
3. 找「**POP3/SMTP 服务**」→ 点「**开启**」→ 按提示用手机发短信验证 → 得到一串 **16 位授权码**（⚠️ 这是授权码，**不是 QQ 密码**，只显示一次，抄下来）。
4. 平台后台（admin）→「设置」→「认证通道」→ 邮件通道：
   - 通道类型选 **SMTP**
   - host 填 `smtp.qq.com`，端口 `465`，SSL 开
   - 用户名 = 你的完整 QQ 邮箱地址（如 `12345@qq.com`）
   - 密码 = 刚才那串 **16 位授权码**
   - 发件人昵称 = 你的平台名（如「XX智能平台」）
5. 点「**发送测试邮件**」→ 给自己另一个邮箱（或就这个 QQ 邮箱）发一封 → 收到即通。
6. 打开「启用」开关 → 完成。注册验证信、找回密码信都会从这个 QQ 邮箱发出。
- ⚠️ 限制：QQ 邮箱 SMTP **日发信量有上限**（个人量级几百封/天），早期够用；发件人地址**必须**是该 QQ 邮箱，不能伪装别的地址。

### 路线 2：腾讯企业邮箱免费版（推荐，发信信誉好、可用自己域名）
1. 开 **exmail.qq.com** → 注册「免费版」→ 需要一个**域名**（没有就先用路线 1）。
2. 按向导在域名商后台配 **MX/SPF 记录**（腾讯给一步一步的图文向导，照抄即可，生效约 10 分钟-24 小时）。
3. 企业邮管理后台 → 新增成员 `noreply@你的域名` → 该成员登录企业邮 → 「设置 → 邮箱绑定 → **安全登录**」→ 开启「**客户端专用密码**」→ 生成一串专用密码。
4. 平台后台填：host `smtp.exmail.qq.com`、端口 `465`、SSL 开、用户名 `noreply@你的域名`、密码 = 客户端专用密码。
5. 测试邮件 → 收到 → 开启用 → 完成。发件人显示 `平台名 <noreply@你的域名>`，专业且不易进垃圾箱。

### 选型一句话
- 没域名、先跑起来 → **路线 1**；有域名、要长期运营 → **路线 2**（域名在阿里云/腾讯云买，几十块/年）。
- 两条路都不用改代码——后台「认证通道」页填完即用（A 节开发完成后）。

## 解决了什么问题（用户地图）

| 谁 | 场景 | 之前 | 现在 |
|---|---|---|---|
| 库 OWNER | 想给重要库指定更强的问答模型 | 全局一个默认模型，库库相同 | 建库/编辑自选「问答模型」，空=跟随全局默认；模型下线自动回退不中断 |
| 库 OWNER | 换向量模型后检索质量骤降不知原因 | 静默生效，存量向量混空间 | 保存即弹强提示「需重建索引」，读后手动关闭弹窗 |
| 授权对象 | 只被授予读的库 | 部分接口误判可写（越权） | 严格分档：读=看，写=传，管理=治理；按钮与服务端同步 |
| 库 OWNER | 敏感资料入库怕被整本拖走 | 授权成员可下载原件/看切片/跑检索调试 | 开「保密库」：成员只能问答召回内容，原件下载、切片原文、检索调试全封死；OWNER/管理员不受限；公开库禁开 |

## 技术说明（按 5 步）

1. **越权修复**（16d4ae5d）：canRead/canWrite/canManage 谓词按档位严格判定（高位隐含低位），授予位不再越级放行；grant/revoke 补审计。
2. **前端 per-KB 按钮显隐**（390b78af）：VO canWrite/canManage 驱动上传/治理/编辑/删除按钮；销毁类操作=OWNER/admin。
3. **模型可选**（43777f20 后端/0d099746 前端）：V131 加 `answer_model` 列；保存校验须在启用 CHAT 白名单；检索期 `resolveAnswerModel` 空或已下线→null→LlmGateway 全局默认（下线不中断）；RAG 问答链路三处 LlmRequest 按库透传；换 embedding 且有文档→VO.warning 重建索引横幅。
4. **保密开关后端**（3752bb16）：V131 同文件加 `confidential` 列；`KnowledgeConfidentialGuard` 静态判定；列表/单查剔 fileRef 留元数据、asset 403、nodes 403、检索调试 403 早退；问答链路（/ask、chat kbIds）= 唯一内容出口；PUBLIC 互斥；切换走 kb_update 审计。
5. **保密前端**（3bce17f3）：CitationVO +confidential 标志（per-KB 受限登记 nodeId 透传，缓存 CitationRef 同步携带，旧缓存条目=false 且 asset 403 兜底）；聊天下滑引用隐藏缩略图/下载；检索调试面板保密库灰显禁选；文档管理原件入口换保密提示；库列表 🔒 保密徽标；建库表单保密开关+PUBLIC 互斥。

**附带修复**：计划 2 误建的 `V100__asset_allow_public_copy.sql` 与存量 V100 撞版本号（下次启动 Flyway 直接失败），改名 `V132`（ce33ec93），零迁移成本。

## 关键坑（沉淀）

- 新增迁移前必须全量 `ls db/migration` 核对版本号——「记上次用到几」会踩撞号（V100 撞号实证）。
- Evidence/L2Candidate 这类贯穿 record 不带上下文 ID 时，别硬改 8 处签名——在产出循环侧建 `Set<nodeId>` 集合，消费点查表。
- 答案缓存回放旧条目缺新字段（boolean 反序列化=false）：隐藏类 UX 标志必须配后端接口级强制（403 兜底），不能只靠标志。
- owner 越过守卫的单测证明：不 stub 完整 happy path，让下游自然报错（NOT_FOUND / NO_VISIBLE_DOCS），用错误码区分「被挡」与「过门没货」。

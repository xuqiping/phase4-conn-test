# 3.2 核心术语与黑话

## I.01 核心术语（按治理流程排列）

### 治理组织与流程

| 术语 | 定义 |
|---|---|
| 数据所有者(Data Owner) | 对特定数据域负有质量、安全、合规责任的业务负责人 |
| 数据管家(Data Steward) | 执行日常数据治理操作（标准制定、质量监控、问题整改）的角色 |
| 数据治理委员会 | 跨部门治理决策机构，通常由CDO/CIO牵头，业务/IT代表参与 |
| 治理运营化 | 将治理从"项目制"转为"持续运营"——嵌入组织日常，而非一次性交付 [来源:CSDN | 置信度:📚中 | 2025-12] |

### 元数据与血缘

| 术语 | 定义 |
|---|---|
| 业务元数据 | 业务含义、业务规则、指标口径、业务负责人 |
| 技术元数据 | 表结构、字段类型、ETL脚本、存储位置 |
| 操作元数据 | 数据使用频次、最近访问时间、查询用户、性能指标 |
| 数据血缘(Data Lineage) | 数据从源系统→ETL→存储→分析→报表→模型的完整流转路径 |
| 影响分析(Impact Analysis) | 某字段变更时，下游依赖的报表/模型/接口受哪些影响 |
| 根因分析(Root Cause Analysis) | 某报表数据异常时，沿血缘逆向上溯定位问题源 |

### 数据质量

| 术语 | 定义 |
|---|---|
| 完整性 | 必填字段非空率、记录完整率 |
| 准确性 | 数据值与真实值的一致程度 |
| 一致性 | 同一实体在不同系统中的数据是否一致 |
| 及时性 | 数据从产生到可用的时间延迟 |
| 唯一性 | 无重复记录（去重率） |
| 有效性/规范性 | 数据值是否符合预定义格式与业务规则 |
| 数据探查(Data Profiling) | 系统性扫描数据集，自动发现质量问题的过程 |
| 质量规则引擎 | 自动执行质量校验规则（如"手机号必须11位数字"）并产出质量报告 |

### 数据标准与主数据

| 术语 | 定义 |
|---|---|
| 数据元标准 | 最小不可分数据单元的命名、定义、类型、长度规范 |
| 指标口径 | 指标计算逻辑、统计范围、时间口径、数据来源的统一定义 |
| 主数据(Master Data) | 跨系统共享的核心业务实体（客户/产品/组织/账户）的"唯一真相" |
| 参考数据(Reference Data) | 标准化代码表（如地区码、行业码、性别码） |
| MDW(主数据仓库) | 集中管理主数据的系统，确保单一来源 |

## I.09 黑话与含义

| 黑话 | 含义 | 正式术语 |
|---|---|---|
| "数据洗一遍" | 对数据做探查和清洗 | 数据探查+数据质量修复 |
| "建字典" | 建数据标准/数据元标准 | 数据标准管理 |
| "画血缘" | 梳理数据流转链路 | 数据血缘追踪 |
| "挂指标" | 给指标绑定口径定义 | 指标标准化 |
| "洗数据" | 清洗脏数据/重复/不一致数据 | 数据质量整改 |
| "打标签" | 对数据做分级分类标记 | 数据分级分类 |
| "对口径" | 不同部门统一指标计算逻辑 | 指标口径统一 |
| "治理入表" | 将数据作为无形资产计入财务报表 | 数据资源会计核算 |

## I.10 易混淆概念辨析

| 概念A | 概念B | 区别 |
|---|---|---|
| 数据治理 | 数据管理 | 治理=制定规则与监督；管理=执行规则与操作。治理是"立法+监督"，管理是"执法" |
| 元数据 | 数据字典 | 元数据范围更广（含业务/技术/操作三层）；数据字典通常是技术元数据的子集 |
| 数据质量 | 数据安全 | 质量=数据"对不对"；安全=数据"该不该看"。两者正交但互补 |
| 主数据 | 交易数据 | 主数据=缓慢变化的实体（客户/产品）；交易数据=频繁变化的事件（订单/日志） |
| 数据血缘 | 数据溯源 | 血缘=正向追踪数据的流向；溯源=逆向追踪数据的来源 |
| DCMM | DAMA | DCMM=中国国标，侧重成熟度评估；DAMA=国际框架，侧重知识体系与方法论 |

# 4.2 数据治理启动SOP

## 适用场景

企业/产品数据治理从0→1启动——数据对不上、质量差、合规有风险，但还没建过体系化治理。

## 前置条件

- 有明确的业务痛点驱动（如"指标打架""数据出错""合规审计不过"）
- 有高层支持（CDO/CIO/VP级别sponsor）
- 至少1名数据治理PM/数据管家可投入

## 六步SOP

### 第1步：确定治理范围与痛点（1周）

| 动作 | 产出 | 负责人 |
|---|---|---|
| 收集业务方痛点（访谈/问卷） | TOP10痛点清单 | 治理PM |
| 按影响面+紧急度排序 | 治理优先级矩阵 | 治理PM+业务方 |
| 选定首个治理域（如"交易数据"或"客户数据"） | 首域范围文档 | 治理委员会 |

**铁律**：首域不超过2个核心数据域，不贪大。

### 第2步：组建治理组织（1周）

| 角色 | 职责 | 人员 |
|---|---|---|
| 治理sponsor | 资源审批+跨部门协调 | VP/CDO |
| 治理PM | 推进项目+流程设计+工具选型 | 数据PM |
| 数据所有者 | 定义标准+审批质量规则+推动整改 | 业务负责人 |
| 数据管家 | 日常治理操作（标准维护/质量监控/问题跟踪） | 数据分析师/业务分析师 |
| 数据工程师 | 技术实现（ETL改造/规则部署/血缘采集） | 数据工程师 |

### 第3步：数据盘点与标签（2-3周）

| 动作 | 产出 |
|---|---|
| 自动扫描数据源（数据库/API/文件） | 数据资产清单 |
| 补录业务元数据（谁负责/业务含义/使用场景） | 元数据补录进度表 |
| 数据分级分类（L1-L4敏感度标记） | 分级分类标记表 |
| 生成数据地图（核心实体+关系+流向） | 数据地图可视化 |

### 第4步：定义标准与规则（2-3周）

| 标准类型 | 产出 | 示例 |
|---|---|---|
| 命名规范 | 表/字段/指标命名规则 | `dwd_trade_order_di` |
| 指标标准 | 核心指标口径定义 | GMV=成交金额-退款金额 |
| 质量规则 | 核心表质量检测规则 | 手机号非空率≥99.9% |
| 权限规则 | 数据访问与脱敏规则 | L3+需审批+脱敏 |

### 第5步：工具部署与规则上线（2-3周）

| 动作 | 产出 |
|---|---|
| 治理平台选型与部署 | 治理平台运行环境 |
| 元数据自动采集配置 | 元数据自动刷新 |
| 质量规则部署到平台 | 质量检测自动化运行 |
| 血缘自动采集配置 | 血缘自动生成 |
| 数据目录上线 | 数据资产可搜索/可浏览 |

### 第6步：运营与迭代（持续）

| 动作 | 频率 |
|---|---|
| 质量巡检报告 | 每日/每周 |
| 质量问题分派与跟踪 | 实时 |
| 标准迭代更新 | 每月 |
| 治理域扩展（新增数据域） | 每季度 |
| DCMM自评 | 每年 |

## 关键里程碑

| 里程碑 | 时间 | 验收标准 |
|---|---|---|
| M1 首域治理启动 | T+2周 | 治理组织成立+首域范围确认 |
| M2 盘点与标准完成 | T+6周 | 数据资产清单+核心指标标准+质量规则 |
| M3 治理平台上线 | T+9周 | 质量自动检测+血缘自动生成+数据目录可用 |
| M4 首域治理达标 | T+12周 | 核心表质量评分≥85+指标口径统一 |

## 常见失败点与应对

| 失败点 | 根因 | 应对 |
|---|---|---|
| 推不动/业务不配合 | 没有业务sponsor | 找到最痛的业务域，让业务方看到收益 |
| 标准定了没人遵守 | 没有纳入流程管控 | 在发布流程加入"质量门禁" |
| 治理平台买了没人用 | 只买了工具没建流程 | 先用Excel跑通流程再上工具 |

## 1. 调整后的后续阶段

### 阶段 5A：联调前置配置收口

**目标：** 先统一服务端地址和启动配置，避免后续桌面端、管理后台、服务端联调时因为端口不一致失败。

**状态：** 未完成。

**必要性：** 必须做。当前 `server/src/main/resources/application.yml` 默认 `server.port=8088`，但 `admin-web/.env.development` 和桌面端 `App.vue` 默认指向 `http://localhost:8080`。

### 阶段 5B：桌面端账号 UI 与认证 Store

**目标：** 让用户可以在桌面端完成登录、注册、退出，并让登录成功后自动绑定设备和刷新授权快照。

**状态：** 未完成。

**必要性：** 必须做。这是商业授权闭环的最大缺口。

### 阶段 5C：桌面端授权状态展示

**目标：** 让用户知道当前是匿名试用、等待审核、商业授权、离线缓存、账号禁用或设备禁用状态。

**状态：** 未完成。

**必要性：** 必须做。否则授权系统虽然生效，但用户无法理解为什么模块可用或不可用。

### 阶段 5D：匿名试用过期后的免费模块选择

**目标：** 匿名试用 7 天结束后，用户可以在桌面端选择一个长期免费模块，并每 30 天更换一次。

**状态：** 未完成。

**必要性：** 建议做。它是匿名生命周期的完整闭环；如果暂时不做，匿名过期后只能看到模块不可用原因，无法自助恢复免费模块。

### 阶段 5E：真实环境端到端联调

**目标：** 使用 PostgreSQL、Redis、真实后端、管理后台和 Tauri 桌面端执行商业授权闭环验收。

**状态：** 未完成。

**必要性：** 必须做。自动化测试不能替代真实进程、浏览器、桌面端和本地 Store 的集成验证。

### 阶段 6：商业版安全与运营增强

**目标：** 在第一版可用后，补 Rust 二次校验、后台 Dashboard、匿名设备运营页、系统设置页等增强能力。

**状态：** 未开始。

**必要性：** 非第一版阻塞项，建议在端到端联调通过后再排期。

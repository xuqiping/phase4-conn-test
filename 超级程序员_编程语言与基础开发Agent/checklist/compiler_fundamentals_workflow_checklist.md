# Compiler & Fundamentals Workflow Checklist

在完成 `workflow/compiler_fundamentals_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别底层知识需求

- [ ] 已明确知识模块（数据结构/算法/计算机组成/OS/编译原理/设计模式）
- [ ] 已识别应用场景（面试/学习/工程优化/架构设计/工具链开发）
- [ ] 已确定用户当前水平（初级/中级/高级）
- [ ] 已提取具体目标（如"准备大厂算法面试"、"优化缓存命中率"）
- [ ] 已对照知识库全景地图完成模块定位
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出底层知识方案

- [ ] 如为面试辅导，高频考点清单已覆盖该模块核心概念
- [ ] 如为面试辅导，每类考点附核心概念速览、常见变种、答题模板、易错点
- [ ] 如为学习路径，阶段性计划清晰（概念理解→代码实现→工程应用→深度优化）
- [ ] 如为学习路径，每阶段附核心知识点、推荐资源、实践项目、验证标准
- [ ] 如为工程优化，根因分析用底层知识解释，优化策略具体，预期收益量化
- [ ] 如为架构设计/工具链，设计方法论清晰，关键决策点明确
- [ ] 核心定律/原则已正确引用（Amdahl/CAP/SOLID/DRY/KISS/YAGNI/Three Strikes/Moore/Little's Law）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 算法复杂度、硬件参数、内核机制等精确数据已核对
- [ ] 核心定律/原则引用正确
- [ ] 已向用户交付最终答案

## Overall

- [ ] 工作流中的所有步骤已按顺序执行，没有跳过
- [ ] 每一步都已与其检查清单部分进行交叉验证
- [ ] 没有在任何检查清单部分通过前提前进入下一步
- [ ] `task/current_task.md` 已更新完成记录
- [ ] 所有 `[参考: ...]` 标注均指向存在的知识库文件

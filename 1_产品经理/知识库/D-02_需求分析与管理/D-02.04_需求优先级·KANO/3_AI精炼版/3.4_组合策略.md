# 3.4 组合策略

## 为什么KANO需要组合

KANO的**局限**：只解决需求的定性分类（"这是什么类型的需求"），不解决定量排序（"这个需求的价值有多大"）。当PM面对50+需求时，仅靠KANO分类+Better-Worse排序仍不够——还需考虑**覆盖面、影响力、信心度、开发成本**等维度。

| KANO的强项 | KANO的弱项 |
|---|---|
| 需求属性的科学分类 | 无法量化商业价值 |
| 揭示满意度非线性关系 | 不考虑开发成本与工期 |
| 动态漂移诊断 | 不考虑覆盖用户数差异 |
| 辅助MVP范围界定 | 缺乏信心度评估机制 |

## 常见组合模式

### 模式一：KANO定性 + RICE定量（推荐组合）

**逻辑**：KANO定类别 → RICE定分值 → 交叉决策

```
Step 1: KANO分类 → 每个需求获得M/O/A/I/R标签
Step 2: KANO标签转RICE的Impact权重
         M → Impact=2（必须做，不做=严重问题）
         O → Impact=3（做了有线性收益）
         A → Impact=2（做了出彩但不做无碍）
         I → Impact=0（不做）
Step 3: 完整RICE评分 = (Reach × Impact × Confidence) / Effort
Step 4: 交叉校验——KANO的M类即使RICE分低也应优先保障
```

| 维度 | KANO提供 | RICE提供 |
|---|---|---|
| 需求属性 | ✅ M/O/A/I/R分类 | ❌ |
| 覆盖面 | ❌ | ✅ Reach |
| 影响力 | ✅ 转化Impact权重 | ✅ Impact本身 |
| 信心度 | ❌ | ✅ Confidence |
| 开发成本 | ❌ | ✅ Effort |

### 模式二：KANO + MoSCoW

**逻辑**：KANO的M/O/A/I直接映射MoSCoW

| KANO类别 | MoSCoW映射 | 说明 |
|---|---|---|
| M(必备) | **Must** | 不做=产品不可用 |
| O(期望) | **Should** | 做了有显著收益，不做有不满 |
| A(魅力) | **Could** | 做了出彩，资源允许再做 |
| I(无差异) | **Won't** | 不做 |
| R(反向) | **Won't** | 绝不做 |

> 适合场景：Sprint规划、迭代排期，快速从KANO映射到MoSCoW优先级桶。[来源:📚训练知识 | 📚中]

### 模式三：KANO + ICE

**逻辑**：KANO提供Impact权重，ICE框架简化评分

```
ICE分 = Impact(KANO权重) × Confidence × Ease
         ↑                        ↑
    M=2/O=3/A=2/I=0          开发简易度1-10
```

> 适合场景：轻量级快速排序，适合初创团队。[来源:📚训练知识 | 📚中]

## B端vs C端的KANO差异

| 维度 | C端产品 | B端产品 |
|---|---|---|
| 必备需求判定标准 | 用户体验基线（不满足→流失） | 合同/合规要求（不满足→违约/罚款） |
| 期望需求特征 | 线性强（更快/更多/更好） | 功能完整性（能不能覆盖我的业务流程） |
| 魅力需求来源 | 创新交互/个性化/社交 | 效率倍增/AI自动化/跨系统集成 |
| 无差异化风险 | 功能堆砌（用户用不到） | 过度定制（满足单客户但通用性差） |
| KANO问卷难度 | 用户多→易抽样→问卷可行 | 关键用户少→问卷不适用→访谈+观察替代 |
| Better-Worse解读 | 整体用户群的统计结果 | 需按客户分层（大客户vs小客户各自计算） |

> B端关键洞察：大客户的KANO分布可能与小客户完全不同——对大客户是必备(M)的需求，对小客户可能是无差异(I)。不能混合计算后取平均。[来源:📚训练知识 | 📚中]

## 组合决策流程

```
1. KANO问卷 → 每个需求获得M/O/A/I/R标签 + SI/DSI系数
2. 内部排序：
   - M类：按DSI绝对值排序（不做的损失大到小）
   - O类：按SI×|DSI|排序（改善空间×缺失风险）
   - A类：按SI排序（惊喜度大到小）
3. 引入RICE/ICE量化评分（覆盖面+成本+信心度）
4. 交叉校验：
   - RICE高分但KANO为I → 砍（数据好看但用户不在乎）
   - KANO为M但RICE低分 → 保（必须做，不能因量化分低而跳过）
   - KANO为A且RICE高分 → 冲（差异化亮点+高商业价值）
5. 输出最终优先级清单
```

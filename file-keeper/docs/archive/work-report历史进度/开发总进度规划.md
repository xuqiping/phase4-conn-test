## 0. 总体说明与快速定位

### 模块概况

工作汇报模块（`work-report`）是 File Keeper 的增值功能模块，覆盖 **工作记录、每日安排、报告模板、报告规则、AI 总结、定时生成、飞书推送** 等完整链路。该模块已按 [`3_新增模块实施指导.md`](../../项目相关文档/3_新增模块实施指导.md) 完成 Step 1~8 全部开发，后端、前端、Rust、管理后台、文档、测试均已交付。

### 最近一次重要调整（2026-06-23）

**问题**：桌面端登录 15 分钟后，访问工作记录/每日安排等接口频繁报“未认证”。

**原因**：后端 JWT access token 统一设置为 15 分钟，而桌面端 `workReport.ts` 直接使用 access token 请求接口，没有做静默刷新。

**处理**：后端按角色区分 token 有效期。

| 角色 | access token 有效期 | 说明 |
|---|---|---|
| `super_admin`（管理后台） | 15 分钟 | 保持后台安全策略不变 |
| `user`（桌面端） | **24 小时** | 解决桌面端频繁掉线问题 |

**涉及文件**：

- [`server/src/main/java/com/superprogrammer/config/AuthProperties.java`](../../../server/src/main/java/com/superprogrammer/config/AuthProperties.java) —— 新增 `clientAccessTokenHours` 配置
- [`server/src/main/java/com/superprogrammer/security/JwtService.java`](../../../server/src/main/java/com/superprogrammer/security/JwtService.java) —— 按角色选择过期时间
- [`server/src/main/resources/application.yml`](../../../server/src/main/resources/application.yml) —— 新增 `client-access-token-hours: 24`

> 该调整**不影响**模块授权到期时间；模块授权仍由 `user_module_entitlements.expires_at` 独立控制。

## 7. 风险与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|---|---|---|---|
| 飞书开发者账号/应用申请延迟 | 中 | Step 5 阻塞 | 提前申请，先用测试环境 webhook 验证 |
| AI API 响应慢或不稳定 | 中 | 报告生成超时 | 设置 30 秒超时 + 降级策略 |
| 桌面端 Tab 过多影响 UX | 低 | 界面拥挤 | 考虑底部 Tab 或侧边栏重构 |
| 多平台时区处理复杂 | 中 | 定时任务不准 | 统一使用 `Asia/Shanghai`，后续支持用户时区 |
| 工作记录数据量增长快 | 低 | 查询变慢 | 按 `user_id + log_date` 建联合索引 |

# 3.4 数据质量与标准

## 数据质量管理

### 六维度质量评估体系

| 维度 | 定义 | 典型检测规则 | 示例 |
|---|---|---|---|
| 完整性 | 必填字段非空率 | NULL率<1%；必填字段空值告警 | 用户注册手机号缺失 |
| 准确性 | 数据与真实值一致程度 | 交叉校验/业务逻辑校验/外部比对 | 订单金额与支付记录不一致 |
| 一致性 | 同实体跨系统数据一致 | 跨源比对/MD5一致性校验 | CRM客户名与ERP客户名不一致 |
| 及时性 | 数据从产生到可用的时间 | 延迟>阈值即告警 | 实时报表T+1才有数据 |
| 唯一性 | 无重复记录 | 主键/唯一约束/相似度去重 | 同一用户多条记录 |
| 有效性 | 数据值符合预定义格式 | 正则校验/枚举校验/范围校验 | 邮箱格式错误、年龄>150 |

### 质量管理闭环流程

```
数据探查(Profiling) → 质量评估(Score) → 问题发现(Alert) → 根因分析(RCA) → 整改修复(Remediation) → 复核验证(Verify) → 持续监控(Monitor)
```

**关键规则**：
- 每个核心数据表至少覆盖4个质量维度
- 质量评分<85分的表必须进入整改流程
- 质量问题必须有"发现→分派→修复→验证"闭环
- 严重质量问题（如金融数据错误）需升级至数据所有者

### 质量规则引擎设计

| 规则类型 | 说明 | 示例 |
|---|---|---|
| 空值检测 | 字段非空校验 | 手机号不为空 |
| 格式校验 | 正则/枚举匹配 | 邮箱格式/身份证18位 |
| 范围校验 | 数值/日期范围 | 年龄0-150/日期不超当天 |
| 唯一性校验 | 主键/联合唯一 | 订单号全局唯一 |
| 一致性校验 | 跨字段/跨表比对 | 订单金额=∑明细金额 |
| 业务逻辑校验 | 复合业务规则 | 注册日期≤首购日期 |
| 统计异常检测 | AI驱动的异常发现 | 某字段值分布突变为异常 |

## 数据标准管理

### 数据标准体系三层结构

| 层 | 内容 | 产出物 |
|---|---|---|
| 数据元标准 | 最小数据单元的命名/定义/类型/长度/约束 | 数据元标准字典 |
| 指标标准 | 指标名称/口径/维度/计算逻辑/数据源 | 指标口径规范 |
| 模型标准 | 表命名规范/分层规范/字段命名规范 | 建模规范文档 |

### 命名规范典型规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 库名 | `{业务域}_{层级}` | `trade_ods`, `user_dwd` |
| 表名 | `{层级}_{业务域}_{实体}_{时间粒度}` | `dwd_trade_order_di` |
| 字段名 | `{业务含义}_{类型后缀}` | `user_id`, `pay_amt`, `is_vip` |
| 指标名 | `{修饰词}_{原子指标}_{时间周期}` | `7d_pay_amt_sum` |

### 指标口径统一

**指标口径冲突的典型场景与解法**：

| 冲突场景 | 根因 | 解法 |
|---|---|---|
| GMV不同部门数字不同 | 口径不同（含/不含退款、含/不含优惠券） | 全公司统一GMV口径定义，写入指标标准 |
| DAU不同团队差异大 | 登录口径不同（设备级/账号级/去重口径） | 明确DAU基准口径+派生口径定义 |
| 转化率定义不一致 | 分母不同（UV/PV/会话数） | 定义转化率必须标注分母+起始事件 |

**口径统一铁律**：每个核心指标有且仅有一个"权威口径"，写在数据标准中；派生口径必须标注基准口径+差异说明。

## 主数据管理

### 主数据四类

| 类型 | 说明 | 关键属性 |
|---|---|---|
| 客户主数据 | 统一客户视图 | 客户ID/名称/行业/等级/地址 |
| 产品主数据 | 统一产品视图 | 产品ID/SKU/规格/分类/定价 |
| 组织主数据 | 统一组织架构 | 组织ID/层级/负责人/地域 |
| 账户主数据 | 统一账户视图 | 账户ID/类型/余额/状态 |

### 主数据管理核心原则

1. **单一来源**：每个主数据实体有且仅有一个"系统记录"（System of Record）
2. **黄金记录**：跨系统冲突时，以优先级最高的源为准合并为"黄金记录"
3. **双向同步**：主数据变更自动推送到所有消费系统
4. **版本追踪**：主数据历史变更可追溯

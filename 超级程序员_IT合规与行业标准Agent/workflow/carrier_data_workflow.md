# Carrier Data Modeling Workflow

## Purpose

基于运营商套餐与用户数据建模知识框架，提供运营商核心数据体系的标准化执行路径，覆盖三域架构、套餐计费建模演进、用户画像标签体系、信令与位置数据、数据合规变现五大核心领域。

## Prerequisites

- 已明确运营商数据域范围（B域业务/O域运营/D域数据）
- 已了解数据合规要求（个保法/数安法/密码法/电信条例）

## Steps

### Step 1: 运营商三域架构梳理

**Goal**: 梳理B域/O域/D域三域架构，明确各域的数据资产、系统边界与数据流向
**Completion criterion**: 输出《运营商三域架构蓝图》，三域系统清单完整，数据流向图覆盖核心接口，TM Forum SID对齐

依据运营商三域架构框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 运营商核心数据体系]：
1. B域（业务支撑域）：
   - CRM系统：客户信息管理/销售线索/服务工单
   - 计费系统：话单采集/批价/出账/缴费/欠费管理
   - 营业系统：开户/变更/销户/套餐订购/业务办理
   - 核心数据：用户资料/套餐信息/账单数据/支付记录
2. O域（运营支撑域）：
   - 网管系统：设备监控/告警管理/性能分析/配置管理
   - 资源系统：网络资源/频谱/IP地址/机房/光缆
   - 故障系统：故障申告/派单/处理/闭环
   - 核心数据：告警数据/性能指标/资源状态/拓扑关系
3. D域（数据运营域）：
   - 数据中台：数据采集/存储/治理/服务
   - AI平台：模型训练/推理/发布/监控
   - 数据变现平台：标签服务/模型服务/API服务
   - 核心数据：用户画像/位置轨迹/DPI上网/消费偏好
4. 统一信息模型：TM Forum SID（Shared Information/Data Model）
   - 定义统一实体：客户/产品/服务/资源/规格/定价
   - 建立跨域映射关系，消除数据孤岛
执行：
- 盘点各域系统清单（系统名称/厂商/版本/数据量/接口数量）
- 绘制《三域数据流向图》：采集→清洗→存储→加工→服务→消费
- 识别数据孤岛与断点，制定《数据贯通计划》
输出：《运营商三域架构蓝图》+ 《系统清单》+ 《数据流向图》+ 《数据贯通计划》

### Step 2: 套餐计费建模演进

**Goal**: 设计支持5G-A多维计费的套餐计费模型，支撑体验即服务（EaaS）演进
**Completion criterion**: 输出《套餐计费模型设计书》，支持GB+QoS+时延+可靠性多维计费，计费准确性≥99.99%

依据套餐计费建模演进框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 套餐计费建模演进]：
1. 4G单维计费模型：
   - 维度：流量（GB）+ 语音（分钟）+ 短信（条）
   - 结构：套餐包（月租含定额）+ 超出阶梯计价
2. 5G多维计费模型：
   - 新增维度：QoS等级（优享/极速/尊享）+ 时延（低时延切片）+ 可靠性（高可靠切片）
   - 结构：基础套餐 + 网络切片增值服务 + 权益包（视频/云盘/会员）
   - 案例：中国移动5G加速卡，ARPU提升15-30元
3. 5G-A体验计费模型：
   - 维度：下行速率（Mbps档位）+ 上行速率 + 覆盖场景（室内/室外/低空）
   - 结构：速率承诺 + SLA保障（可用性/时延抖动）+ 按体验分级定价
4. 6G Token化/EaaS前瞻：
   - Token化：将网络能力抽象为Token（算力Token/连接Token/存储Token）
   - EaaS（体验即服务）：按体验质量定价，而非按资源用量定价
   - 案例：云游戏按"流畅体验时长"计费，而非按流量计费
执行：
- 梳理现有计费系统数据模型（批价规则/优惠规则/账务规则）
- 设计新计费模型与现有模型的兼容映射
- 制定《计费系统升级路线图》：参数扩展 → 规则引擎重构 → 实时计费能力
输出：《套餐计费模型设计书》+ 《计费规则引擎设计》+ 《计费准确性测试方案》

### Step 3: 用户画像标签体系建设

**Goal**: 建立六维用户画像标签体系，支撑精准营销、网络优化与数据变现
**Completion criterion**: 输出《用户画像标签体系规范》，标签数量≥3000个，联邦学习跨域建模方案确定

依据用户画像标签体系框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 用户画像标签体系]：
1. 六大维度标签设计：
   - 基础属性：年龄/性别/地域/职业/收入/终端类型
   - 通信行为：通话频次/时长分布/漫游行为/换机周期/ARPU
   - 消费偏好：套餐类型/增值业务/支付方式/欠费记录/信用等级
   - 位置轨迹：常驻地点/通勤路线/出行模式/商圈偏好/旅游偏好
   - DPI上网：APP偏好/内容偏好/时段分布/流量消耗/视频清晰度
   - 终端属性：品牌/型号/系统/屏幕/芯片/5G支持/换机意向
2. 标签层级：
   - 原始标签：直接从数据采集（如信令原始记录）
   - 统计标签：聚合计算（如近30天日均流量）
   - 预测标签：模型输出（如换机概率/离网风险）
   - 综合标签：多维度融合（如高价值客户/夜间流量党）
3. 标签管理：
   - 标签定义：名称/口径/数据源/更新频率/责任人
   - 标签质量：准确率（抽样验证≥95%）、覆盖率（目标人群≥90%）、稳定性（波动<10%）
4. 隐私保护：
   - 联邦学习跨域建模：用户数据不出域，模型参数加密交换
   - 差分隐私：标签统计结果添加噪声，防止个体推断
   - 标签分级：L1-L5脱敏级别，对应不同使用权限
执行：
- 参考中国移动梧桐平台（4200标签/1100亿次调用）设计规模目标
- 搭建标签管理平台：标签注册/血缘/质量监控/生命周期管理
- 输出《用户画像标签体系规范》+ 《标签质量监控报告》+ 《联邦学习实施方案》

### Step 4: 信令与位置数据管理

**Goal**: 建立5G信令数据管理体系，支撑网络优化、位置服务与合规监管
**Completion criterion**: 输出《信令数据管理规范》，信令采集完整性≥99.9%，位置脱敏五级体系落地

依据信令与位置数据框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 信令与位置数据]：
1. 5G信令数据管理：
   - 信令量特征：5G信令量比4G增长10倍（连接密度/切片管理/边缘计算）
   - 采集架构：信令采集层（各接口镜像）→ 信令解析层（协议解码）→ 信令存储层（时序数据库）
   - 存储策略：热数据（7天，SSD）+ 温数据（90天，SATA）+ 冷数据（3年，对象存储）
2. DPI数据识别：
   - 挑战：TLS 1.3使传统DPI识别率降至60%（SNI加密）
   - 方案：AI-DPI基于流量指纹（包大小分布/时序特征/突发模式）维持88%识别率
   - 应用：带宽调控/内容计费/安全审计/广告推送
3. 位置数据脱敏五级体系：
   - L1：详细轨迹（GPS级精度，严禁对外，仅限内部网络优化）
   - L2：栅格位置（100m×100m栅格，经审批可用于城市规划）
   - L3：区域位置（商圈/社区级，可用于精准营销）
   - L4：城市级（地级市粒度，可用于人口流动分析）
   - L5：省级/全国级（完全脱敏，可公开发布）
4. 位置服务应用：
   - 网络优化：基于位置的业务热点分析/容量规划/覆盖优化
   - 应急调度：灾害区域人员分布/疏散路径规划
   - 商业分析：商圈人流/消费潜力/选址辅助
执行：
- 部署信令采集与解析系统（如华为SIG/中兴ZSmart）
- 建立AI-DPI模型训练流水线（特征工程→模型训练→在线推理→效果评估）
- 配置位置数据脱敏引擎，按L1-L5自动分级处理
输出：《信令数据管理规范》+ 《DPI识别准确率报告》+ 《位置脱敏实施指南》

### Step 5: 数据合规变现体系建设

**Goal**: 在个保法/数安法/密码法多重监管下，建立合规的数据对外服务体系
**Completion criterion**: 输出《数据合规变现体系方案》，隐私计算平台上线，对外服务合同含合规条款，2025年数据要素中标规模目标明确

依据数据合规变现框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 数据合规变现]：
1. 数据资产盘点：
   - 内部价值：网络优化/精准营销/客户服务/反欺诈
   - 外部价值：金融风控/保险定价/广告投放/城市规划/交通优化
   - 2025年数据要素中标规模：三大运营商10.47亿元
2. 隐私计算技术底座：
   - 联邦学习：多方联合建模，原始数据不出域，模型参数加密交换
   - MPC（安全多方计算）：多方联合统计/查询，密码学保证中间过程不泄露
   - TEE（可信执行环境）：硬件隔离区（Intel SGX/ARM TrustZone/华为TrustZone）内处理敏感数据
3. 对外服务产品：
   - 标签服务：API查询用户标签（需用户授权+脱敏处理）
   - 模型服务：输出风险评分/意向预测（不输出个体数据）
   - 报告服务：群体洞察报告（人口流动/消费趋势/行业分析）
4. 合规管控：
   - 合同条款：数据使用范围/禁止再识别/安全责任/审计权利/违约追责
   - 用户授权：明示同意+单独同意（敏感个人信息）+ 撤回机制
   - 审计追溯：每次数据调用留痕（谁/什么/何时/为何），支持监管审计
5. 商业模式：
   - 按调用量计费：API调用次数×单价
   - 按效果计费：模型提升效果分成
   - 按项目计费：定制化洞察报告/联合建模项目
执行：
- 部署隐私计算平台（如蚂蚁链摩斯/腾讯云隐私计算/自研联邦学习平台）
- 梳理可对外服务的数据产品清单，评估合规风险等级
- 与金融/保险/政府等客户签订数据服务协议
输出：《数据合规变现体系方案》+ 《隐私计算平台架构》+ 《对外数据产品目录》+ 《数据服务合同模板》

## Post-Workflow

3. 全部通过后输出《运营商数据体系总纲》并归档

# 企业级精准知识库 RAG 开发进度 6

## P1 Step 4：D0/S1/C2/E3 类型化分块

- 用 `ChunkFactory` 与策略注册表替换 `KnowledgeNodeWriter.splitL2()`，Writer 只负责治理校验、节点关系和持久化，不再自行猜测切块方式。
- 采用双轨兼容映射：D0 继续由文档 `l1_metadata` 承载；S1 写旧 `L0`；C2/E3 写旧 `L2`。新粒度、Chunk 类型和分块器版本写入 metadata，现有 PostgreSQL 检索协议保持可用。
- 普通文档按完整段落聚合，目标 300～600 token；短章节允许低于 300，禁止跨章节拼接；Overlap 复制完整段落且最多 100 token。
- CLAUSE、FAQ、LIST、PROCEDURE 保持原子 C2，仅在超过 600 token 时安全切分；TABLE_ROW 与 VISUAL_REGION 生成 E3，PAGE 生成 C2/PDF_PAGE。
- S1、C2、E3 保存稳定 `parentPath/previousPath/nextPath`、`chunkOrdinal/titlePath/locator`；L2 `nodeType` 使用真实 chunkType。
- Chunk 继承 `tenantId/kbId/documentId/versionId/ownerId/authorityLevel/confidentialityLevel`；缺少 documentId 或 kbId 时拒绝写入，禁止无归属节点。
- `BizMetrics` 新增固定低基数的 S1/C2/E3 分块数量和耗时指标；日志只记录文档、版本、数量、分块器版本与耗时，不写正文。

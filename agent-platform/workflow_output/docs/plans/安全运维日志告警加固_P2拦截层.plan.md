# 安全运维日志告警加固 · P2 拦截层

> 主索引：[安全运维日志告警加固.plan.md](安全运维日志告警加固.plan.md)
> 规格：[../specs/安全运维日志告警加固.md](../specs/安全运维日志告警加固.md)
> 依赖 P1（C1 表 + C2 RateLimiter + C3 BanService）。
> P2 = 拦截层（SecurityGateFilter 热路径 + IP 黑名单 + login_attempts + 4 热规则）。当场拦 + 自动封。

## P2 目标
- SecurityGateFilter 热路径拦截器（IP 黑名单 → 全局限流 → 注入特征）
- ip_blacklist Redis 镜像（自动+手动封 IP）
- login_attempts 记录 + 4 热规则（暴破/撞库/注入/RATE_BURST）
- 限流接入高频端点（chat/media/导出）

### C5 — SecurityGateFilter 热路径拦截器
**目标**：新增 OncePerRequestFilter，在 JwtAuthenticationFilter 之后，按顺序热路径校验：IP 黑名单 → 全局限流 → 注入特征。命中即拦 + 写 security_events + 触发钉钉(高危)。

**动作（伪代码）**：
```
common/security/SecurityGateFilter (OncePerRequestFilter, @Order 在 JwtFilter 后):
  doFilterInternal(req, resp, chain):
    ip = clientIp(req)   // 复用 MdcUserFilter 的 IP 提取（X-Forwarded-For 首段 + 防 XFF 伪造，见坑）
    path = req.getRequestURI()

    // 1. IP 黑名单（Redis 镜像，hasKey 极快；miss 不查库）
    if ipBlacklistCache.isBlocked(ip):
        securityEventService.record(IP_BLOCKED_HIT, HIGH, ...auto_action=NONE 已封)
        → 403（固定话术，不透传「被封」）
        return

    // 2. 全局 per-IP 限流（fixed window，复用 C2 RateLimiter）
    if !rateLimiter.checkFixed("rl:ip:"+ip, globalIpPerMinute, 60):
        securityEventService.record(RATE_BURST, MEDIUM, user=null, ip, detail={path})
        bizMetrics.apiRateLimited("global_ip")
        → 429 RATE_LIMIT
        return

    // 3. 注入特征（仅对带参数的请求扫，GET query + POST body 限 ≤8KB 防 DoS）
    if injectiveContent(req):
        securityEventService.record(SQLI_PROBE/XSS_PROBE/PATH_PROBE, HIGH, ...,
            detail={matched: 片段(脱敏截断)})
        // 累犯封 IP（同 IP 1h 内 ≥3 次注入命中 → ipBlacklistService.autoBlock(ip, INJECTION, 1h)）
        → 403
        return

    chain.doFilter(req, resp)

common/security/InjectionDetector:
  // 预编译正则集（static final，启动加载，非每请求编译）
  SQLI_PATTERNS = [UNION SELECT, OR 1=1, ' OR ', -- , ; DROP, INFORMATION_SCHEMA, ...]
  XSS_PATTERNS  = [<script, javascript:, onerror=, onload=, <iframe, ...]
  PATH_PATTERNS = [../, ..\\, %2e%2e, /etc/passwd, ...]
  String detect(payload):  // 返回命中类型或 null；payload 先 URL decode + 小写
```
**涉及文件（7）**：
- `common/security/SecurityGateFilter.java`（新建）
- `common/security/InjectionDetector.java`（新建，纯函数易测）
- `common/security/IpBlacklistService.java`（C6 建，此处用 isBlocked）
- `common/security/SecurityEventService.java`（C5 起轻量版 record，C8 扩完整；先建 record 入库）
- `common/security/entity/SecurityEvent.java` + `SecurityEventMapper.java`（实体/Mapper，新建）
- `auth/security/SecurityConfig.java`（注册 SecurityGateFilter 在 JwtFilter 之后）
- `common/metrics/BizMetrics.java`（+injectionBlocked/ipBlocked）

**依赖**：C1（security_events/ip_blacklist 表）、C2（RateLimiter）。

**验证**：
- 单测 `InjectionDetector.detect`：正常参数返 null；`' OR 1=1`/`<script>`/`../etc` 各命中对应类型；URL 编码解码后命中。
- 单测 SecurityGateFilter：IP 黑名单命中 403；全局限流超阈 429；注入 payload 403 + 写 security_events。
- 单测大 body（>8KB）跳过注入扫描（DoS 防护）。
- E2E：`GET /api/x?u=' OR 1=1` → 403 + security_events 一行 SQLI_PROBE；同 IP 第 3 次 → ip_blacklist 自动加 1h。

**坑**：
- *性能*：注入正则扫每请求参数。**规避**：预编译 static；只扫带参数请求；body 限 8KB（超跳过，大文件上传端点白名单）；正则用 find 非全匹配。
- *误报*：正常用户输入含 `'` 或 `<`（如聊天内容）。**规避**：注入特征要求**组合模式**（如 `UNION SELECT` 两词同现）非单字符；chat 消息内容**不扫**（仅扫 URL query + 表单参数键值），消息内容走 P3 Prompt 规则。
- *XFF 伪造*：攻击者伪造 X-Forwarded-For 绕 IP 限流/黑名单。**规避**：IP 取「可信代理链」——若部署无反向代理，XFF 不采信，用 `request.getRemoteAddr()`；若有 Nginx，配 `server.forward-headers-strategy` + Nginx 设 XFF 覆盖写。**部署必做**：确认部署拓扑，配 IP 提取策略（system_settings `security.ip.trust_proxy`）。
- *顺序*：SecurityGateFilter 必须在 JwtFilter 之后（否则无 userId 上下文），但在 Controller 之前。

### C6 — IP 黑名单服务（自动+手动，Redis 镜像）
**目标**：ip_blacklist 表 + Redis 镜像（启动加载 + 增删同步），热路径查 Redis 不查库。

**动作（伪代码）**：
```
common/security/IpBlacklistService:
  // 启动加载（@PostConstruct）：未过期的 ip_blacklist 行灌进 Redis Set/独立 key
  @PostConstruct loadIntoRedis():
      ipBlacklistMapper.selectActive(now)  // banned_until IS NULL 或 > now
        .forEach(ip -> redis.opsForValue().set("ipban:"+ip, "1", ttlOrPermanent))

  boolean isBlocked(ip):  // 热路径用，Redis hasKey
      try: return redis.hasKey("ipban:"+ip)
      catch: return false（降级放行；接受，注入特征/限流仍拦）

  // 自动封（规则触发）
  autoBlock(ip, reason, durationHours):
      upsert ip_blacklist(ip, source=AUTO, reason, banned_until=now+duration)
      redis.set("ipban:"+ip, "1", durationHours, HOURS)
      securityEventService.record(IP_AUTO_BLOCKED, HIGH, ...)

  // 手动封（admin）
  manualBlock(ip, reason, permanent):
      upsert ip_blacklist(ip, source=MANUAL, reason, banned_until=permanent?null:now+default)
      redis.set(...)
      @AuditLog(action="ip_block")

  unblock(ip):
      delete from ip_blacklist where ip=?
      redis.delete("ipban:"+ip)

common/security/controller/IpBlacklistController:  // admin 用，P4 前端调
  POST /api/security/ip/block   @RequirePermission("security:ban:manage")
  POST /api/security/ip/unblock @RequirePermission("security:ban:manage")
  GET  /api/security/ip/list    @RequirePermission("security:ban:manage")
```
**涉及文件（5）**：
- `common/security/IpBlacklistService.java`（新建）
- `common/security/entity/IpBlacklist.java` + `IpBlacklistMapper.java`（实体/Mapper）
- `common/security/controller/IpBlacklistController.java`（新建）
- `common/metrics/BizMetrics.java`（+ipBlocked）

**依赖**：C1（ip_blacklist 表）。

**验证**：
- 单测 `loadIntoRedis` 启动加载 + 过期行不加载。
- 单测 `isBlocked` Redis hit/miss/降级。
- 单测 `autoBlock`/`manualBlock`/`unblock` 表+Redis 同步。
- 单测过期自动解（banned_until 到期，定时任务清理 Redis 残留 key）。
- E2E：admin 手动封 IP → 该 IP 请求 403 → 解封 → 恢复。

**坑**：
- *缓存不一致*：DB 改了 Redis 没同步。**规避**：所有增删走 service（autoBlock/manualBlock/unblock）双写；启动加载兜底；不直接改表。
- *过期清理*：banned_until 到期后 Redis key 若有 TTL 自动消失；permanent（banned_until=null）的永不过期需手动解。定时任务（每小时）扫表清过期行。
- *IPv6*：存 VARCHAR(64) 够；IPv6 归一化（压缩/全展开存同格式），防同 IP 多种写法绕过。**规避**：写入前 `InetAddress.getByName(ip).getHostAddress()` 归一化。
- *误封 NAT*：公司/校园 NAT 单 IP 多用户，封 IP 误伤。**规避**：自动封 IP 时长偏短（1h），且仅 HIGH 规则触发；admin 可手动解。

### C7 — login_attempts + 4 热规则
**目标**：登录尝试记录入库 + 暴破/撞库检测；RATE_BURST 屡犯升级；4 热规则接入自动响应。

**动作（伪代码）**：
```
auth/service/AuthService（登录成功/失败处接线，现有 login 方法内）:
  // 成功：loginAttemptsService.record(identifier, userId, ip, success=true, geo)
  // 失败：record(...success=false, fail_reason)
  // 暴破检测：每次失败后检查
  boolean locked = loginAttemptsService.checkBruteForce(identifier, ip)
  if locked:
      user.setStatus(LOCKED); user.setLockedUntil(now+15min); update
      banService.revoke(userId, LOCKED)   // 删 session + ban 标记
      securityEventService.record(LOGIN_BRUTE_FORCE, HIGH, userId, ip, auto_action=ACCOUNT_LOCKED)
      → LOGIN_LOCKED

common/security/LoginAttemptsService:
  record(...): insert login_attempts（异步，小线程池，不阻登录主链）
  checkBruteForce(identifier, ip):
      // 同 identifier 5 次/15min（COUNT，走索引 idx_login_id_time）
      long fails = mapper.countFailsByIdentifier(identifier, now-15min)
      if fails >= 5: return true   // 锁该账号
      // 撞库：同 IP 20 个不同 identifier/5min
      long distinctIds = mapper.countDistinctIdentifierByIp(ip, now-5min)
      if distinctIds >= 20:
          ipBlacklistService.autoBlock(ip, CREDENTIAL_STUFFING, 1h)
          securityEventService.record(CREDENTIAL_STUFFING, HIGH, ..., auto_action=IP_BLOCKED)
      return false

  geo(ip): ip2region 查归属地（IMPOSSIBLE_TRAVEL 用，P3）

RATE_BURST（C2 RateLimitInterceptor 接线）:
  // 429 时累计：Redis INCR "rlburst:"+uid/ip，TTL 1h
  // ≥3 次 → securityEventService.record(RATE_BURST, MEDIUM)
  // 若 ≥10 次 → ipBlacklistService.autoBlock(ip, RATE_BURST, 30min)
```
**涉及文件（7）**：
- `common/security/LoginAttemptsService.java`（新建）
- `common/security/entity/LoginAttempt.java` + `LoginAttemptMapper.java` + xml
- `auth/service/AuthService.java`（login 接 record + checkBruteForce）
- `common/ratelimit/RateLimitInterceptor.java`（C2 建，+RATE_BURST 累计）
- `common/metrics/BizMetrics.java`（+loginBruteForce/credentialStuffing）
- ip2region 依赖（pom + `resources/ip2region.xdb`，Apache 2.0）
- `common/security/GeoIpService.java`（ip2region 封装，IMPOSSIBLE_TRAVEL/P3 用）

**依赖**：C1（login_attempts 表）、C3（BanService 锁号）、C6（IpBlacklistService 封 IP）。

**验证**：
- 单测 `checkBruteForce`：5 次失败返 true；20 不同 identifier 触发撞库封 IP；COUNT 走索引。
- 单测 geo：ip2region 查返回市级归属地。
- 单测 RATE_BURST：3 次 429 → MEDIUM 事件；10 次 → 封 IP。
- E2E：u1 同 IP 连续 5 次错密码 → 第 5 次 LOCKED + 钉钉（P4）+ 该号 401；同 IP 20 个不同号 → IP 封 1h。
- E2E：chat 连续 21 次 → 第 21 次 429；1h 内 10 次 429 → IP 封 30min。

**坑**：
- *性能-暴破检测 COUNT*：每次登录失败 COUNT，高频暴破压 idx_login_id_time。**规避**：窗口 15min，索引覆盖 `(identifier, created_at)`，COUNT 走索引快；或 Redis 计数器（`loginfail:id:{id}` INCR TTL 15min）替代 COUNT，更轻。**决策：用 Redis 计数器，DB login_attempts 仅留取证（异步写）。**
- *账号枚举*：暴破锁定不同号=锁定多个真实用户（DoS）。**规避**：LOCKED 时长短（15min）；撞库（多号）封 IP 而非锁每个号。
- *ip2region 数据更新*：归属地库需定期更新（**后续再说**，初版用发布时快照）。
- *异步写 login_attempts*：小线程池（core1/max2），失败吞（取证丢失可接受，主链不阻）。

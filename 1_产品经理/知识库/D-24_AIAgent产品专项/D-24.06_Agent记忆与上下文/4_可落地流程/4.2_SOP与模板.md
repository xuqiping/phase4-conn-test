# 一、4 套 SOP

## SOP 1：记忆架构设计（先决策该不该上、上什么）—— 1-2 小时

**目标**：80% 记忆系统过度设计源于本该不上却硬上。本 SOP 保证 1-2 小时内决策"该不该上 + 上四层哪几层 + 选哪个框架"。[来源:Futurum Research 2026 / LightMem 2026 ICLR | 🔍高 | 2026]

**步骤**：
1. **三问诊断**（15 分钟）：① 是否需要跨会话连续性？② 是否需要用户个性化记忆？③ 单会话上下文会不会超限？三问全否 → 不上
2. **失忆代价评估**（15 分钟）：类比旅行 Agent 偏好流失 40% / 财务汇率遗忘 / 代码架构约束丢失 事故，评估本场景失忆代价
3. **四层架构配置**（30 分钟）：用模板 T1《记忆架构选型决策表》逐层配 ✅/❌——工作/情景/语义/程序性
4. **框架选型**（30 分钟）：六大框架（Mem0/Letta/Zep/LangMem/agentmemory/Anthropic Memory Tool）按场景匹配 + 时间敏感→Zep + 隐私敏感→Letta + 高召回→agentmemory
5. **存储后端 + 自托管决策**（15 分钟）：向量库/图库/关系库 + 自托管 vs 云服务（合规驱动）

**关键判定标准**：旅行/客服/陪伴→Mem0 或 Zep（时间敏感）；长程自治理/隐私敏感→Letta；高召回编码→agentmemory；Claude 生态→Anthropic Memory Tool；缺情景记忆是失忆头号根因；配语义记忆必须配投毒防御。

## SOP 2：上下文管理设计（防 Context Rot）—— 2-3 小时

**目标**：长任务不配 Compaction 必然 Context Rot。本 SOP 按 Claude Code 五层标杆配齐 Compaction + 提示缓存 + Goldilocks Zone。[来源:Anthropic Claude Code / Karpathy 2025 | 🔍高 | 2026]

**步骤**：
1. **Context Rot 评估**（20 分钟）：单会话预期 token + Lost in the Middle 风险 + 二次方注意力成本 + 缓存脆弱性
2. **五层 Compaction 配置**（40 分钟）：用模板 T3《Compaction 策略配置表》配 L1 工具输出截断 → L2 历史总结 → L3 Dump 文件 → L4 AGENTS.md → L5 Reset+Ralph Loop
3. **提示缓存优化**（20 分钟）：稳定前缀 + 可变后缀 + 缓存键设计 + 缓存命中率监控
4. **Goldilocks Zone 配比**（20 分钟）：工具描述/记忆条目/历史对话/Few-shot 四要素配比——太少乱猜 / 太多分心
5. **渐进式披露设计**（20 分钟）：工具元信息/记忆条目按需加载，避免一次性灌满（Vercel 工具 15→2 是标杆）
6. **长任务持久化**（20 分钟）：Checkpoint + 文件系统 + Ralph Loop 自动重建

**关键产出**：Context Rot 防御方案 + 五层 Compaction 配置 + 提示缓存方案 + Goldilocks 配比 + 渐进式披露 + 长任务持久化。

## SOP 3：记忆安全设计（防投毒防删库）—— 2 小时

**目标**：94% 记忆型 Agent 可被投毒、91% 存在严重漏洞、PocketOS 自主删库。本 SOP 系统化设计记忆安全。[来源:Stanford/MIT/CMU 2026-07 / PocketOS 事故 | 🔍高 | 2026-07]

**步骤**：
1. **Memory Poisoning 投毒防御**（30 分钟）：用模板 T4《记忆安全自查清单》逐项配 5 类防御（输入过滤/写入校验/签名验证/异常检测/蜜罐记忆）
2. **91% 漏洞治理**（30 分钟）：847 部署研究逐项 OWASP Agent 安全自查
3. **破坏性操作防护**（20 分钟）：PocketOS 删库警示——二次确认 + 不可逆操作人工接管 + 备份隔离
4. **记忆主权三原则**（20 分钟）：完整性（不可未授权篡改）+ 保密性（PII 加密+访问控制）+ 受控遗忘（必须能彻底删除）
5. **最小权限 + 沙箱**（10 分钟）：读写权限角色最小化 + 高风险操作沙箱
6. **多 Agent 跨记忆注入防护**（10 分钟）：AgentCard 签名验证 + 跨 Agent 记忆隔离（如多 Agent）

**关键产出**：投毒防御方案 + 91% 漏洞治理表 + 破坏性操作防护 + 记忆主权配置 + 最小权限矩阵 + 沙箱方案 + 跨 Agent 注入防护。

## SOP 4：失忆事故补救（应急诊断与修复）—— 1-2 小时

**目标**：记忆系统上线后必然遭遇失忆事故。本 SOP 提供应急诊断与修复流程，6 类失忆根因 60 分钟内定位。[来源:腾讯云《Agent Memory 工程化落地》 / Futurum Research | 🔍高 | 2026]

**步骤**：
1. **失忆现象采集**（10 分钟）：用户反馈"不记得"/ 推荐异常 / 个性化丢失——用模板 T6《失忆根因诊断表》记录现象
2. **6 类根因诊断**（20 分钟）：① 缺情景记忆层 ② CRUD 缺 Read 写入失败 ③ 召回率不足 ④ Context Rot 淹没 ⑤ 记忆被投毒篡改 ⑥ TTL 过早衰减
3. **AgenTracer 轨迹回放**（15 分钟）：记忆轨迹回放定位哪条记忆缺失/错误
4. **应急补救**（15 分钟）：缺失→紧急补写 / 错误→纠错回溯 / 投毒→隔离清洗 / 衰减→调整 TTL
5. **全链路修正**（15 分钟）：用户反馈 → 记忆修正 → 所有关联记忆回溯修正
6. **根因根除**（15 分钟）：补齐缺失层 / 补齐 CRUD-M / 调召回阈值 / 加 Compaction / 加投毒防御 / 调 TTL

**关键产出**：失忆根因诊断报告 + 应急补救方案 + 全链路修正记录 + 根因根除改进项。

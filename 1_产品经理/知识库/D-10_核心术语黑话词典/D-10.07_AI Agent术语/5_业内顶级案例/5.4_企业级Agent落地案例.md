# 案例：企业级Agent落地——数字员工/Harness Engineering/护栏

## 术语映射

| 术语 | 在本案例中的体现 |
|---|---|
| Digital Worker | 企业不叫Agent，叫"数字员工"——客服、财务、HR各有数字员工 |
| Harness Engineering | 每个数字员工都有完整的执行环境、权限、监控、审批流 |
| Guardrails | 按岗位设定操作边界——数字财务员工不能转账，只能对账 |
| HITL | 高风险操作（如审批、合同签署）必须人确认 |
| Long-Term Memory | 数字员工积累企业知识库，越用越熟悉业务规则 |
| Agent Evaluation | 用历史数据评测数字员工完成率、准确率、异常率 |

## 典型企业级Agent架构

```
用户请求 → 意图识别 → 路由到对应数字员工
→ 数字员工执行(Guardrails约束)
→ 关键节点HITL审批
→ 执行结果 → 监控审计日志
```

## 产品决策启示

1. **先做Harness再做Agent**：没有安全带的Agent绝对不能上线
2. **用"数字员工"而非"Agent"卖**：客户更容易理解，也更符合企业采购逻辑
3. **评测先行**：上线前必须用历史数据通过评测，不能"上线再看"

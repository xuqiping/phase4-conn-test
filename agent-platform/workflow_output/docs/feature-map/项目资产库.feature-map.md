# 项目资产库 · Feature Map（代码-功能速查）

> B/C 类功能。资产库 = 五类资产 × 五叙事角色双轴矩阵 + 项目级三角色授权 + 版本/一致性包 + 画布双向打通 + 节点@引用。
> 后端独立 `asset` 包（canvas 单向只读依赖，零回归）；前端 `components/asset/` + 画布打通散落 `components/canvas/`。
> 配套：[设计方案](../docs/plans/项目资产库设计方案.md)｜[plan](../docs/plans/项目资产库.plan.md)｜[User-Ops](../docs/user-ops/项目资产库用户操作手册.md)｜[README](../../workflow_output/开发进度/项目资产库/README.md)

## 一句话原理

把创作中反复用的「提示词/剧本/图片/视频/音频」当**资产**存进**项目**，用「类型 × 叙事角色」双轴分类归档，配**版本快照**让画布引用某版后不被新版冲掉，再让画布节点能**入库产新资产**或**从库引用资产**，节点间还能用 **@** 互引上游产出。

## 数据模型（Flyway V56–V59，全新建表，回滚=drop）

| 表 | 用途（生活比喻） | 关键字段 |
|---|---|---|
| `asset_projects` | **项目**=一个创作项目（一部短片的所有素材归一处） | owner_id / narrative_roles(JSONB 五桶) / deleted |
| `asset_project_members` | **成员授权**=谁能进这个项目（户主/同住人/访客） | project_id / user_id / role(OWNER·EDITOR·VIEWER) UNIQUE(project,user) |
| `assets` | **资产**=一件素材（一张人物图） | project_id / media_type / status(DRAFT·LOCKED·ARCHIVED) / current_version(乐观锁) |
| `asset_versions` | **版本快照**=素材的某一次定稿（图 v1/v2，画布引用锁某版） | asset_id / version / content(JSONB) / file_id / gen_meta(谱系) |
| `asset_role_links` | **叙事角色挂载**=素材归到哪个角色桶（这张图是「人物」） | asset_id / role_key |
| `asset_bindings` | **画布↔库台账**=资产产自哪个节点(PRODUCED)/被哪个节点引用(REFERENCE) | asset_id / node_id / canvas_id / kind |

> **大白话**：项目像文件夹，资产像文件夹里的文件，版本像文件的「历史版本」（只读快照），叙事角色像贴在文件上的彩色标签（人物/道具/场景/风格/通用），绑定台账像「这个文件是哪个画布节点生成的/被哪些节点引用」的借阅登记。

**索引**：`assets(project_id,media_type,updated_at) WHERE deleted=0` 部分索引缩圈；`role_links(asset_id)`；`members(user_id)`。角色筛选走 `asset_role_links` 关系表（不查 JSONB）。

## 技术原理大白话注解

- **双轴矩阵**：像 Excel 行(类型)列(角色)交叉，「图片×人物」=所有人物图。计数徽章用一条 `GROUP BY media_type, role` 聚合返全图，**不每格一次 count**（防几十次查询）。
- **版本快照**：引用资产时**锁定当时那一版**，资产升 v3 不影响已引用 v2 的内容（画布引用存版本号）。`current_version` 乐观锁防两人同时提交撞车（UPDATE WHERE current_version=? 0 行=冲突→CONFLICT）。
- **咽喉点（AclService）**：所有项目级请求必经的权限门，三判 owner/member/admin，否则 403。viewer 只读可引用（resolve 通），写操作全拒。
- **PRODUCED/REFERENCE 绑定**：资产详情页「使用记录」=这张图是哪个画布节点**产出**的(PRODUCED)、被哪些节点**引用**了(REFERENCE)，双向台账。
- **@引用祖先链**：@只能引用**经连线能回到的上游**（反向 BFS）。@沿既有连线 ⇒ 被引用方拓扑序必在前 ⇒ 先跑完 ⇒ 运行前插值拿到的上游产出已物化。占位符存 **node id**（重命名不断链），**不递归**展开（防 A@B、B 含 @ 死循环）。
- **断链灰显**：删连线/删上游节点后，@占位符指向的节点不在祖先集 → `findBrokenMentions` 检出 → 属性面板黄色 warn + 运行时降级注入「【断链】」（不级联失败）。
- **L9 重名序号**：同画布节点 label 不许重复，新建/粘贴/重命名三入口都过 `uniqueLabel`（撞名→「图片 2」「图片 3」），占位符存 id 不受 label 改名影响。

## 踩坑批注

- **JSONB 角色筛选**：角色过滤走 `asset_role_links` 关系表（不查 JSONB 全表扫描），先用部分索引缩圈。
- **N+1 防护**：列表查出 asset ids 后 `IN` 批查 role_links 内存组装，不每资产查一次。
- **大版本 content 懒加载**：版本列表只 select meta，content（剧本全文）按需单取。
- **重命名查重契约**：`onRenameBlur` 的 `allLabels` 必须**按节点 id 剔除自身**传入，非按值剔——否则另一节点的同名也被误剔导致漏判。
- **响应式祖先集**：computed 内调 `boardRef.getEdges()`，其 `return edges.value` 在 computed 中被 Vue 追踪，增删边自动重算，**无需手动 tick**。
- **MentionTextarea 用原生 textarea 非 n-input**：需 `selectionStart`/`setSelectionRange` 精准光标做 @唤起+中段插入，n-input 不暴露光标 API。
- **画布→库单向只读依赖**：`asset` 包调 `CanvasService.loadOwned`（只读 DTO），canvas 包不 import asset，保 canvas 零回归（设计 §十四）。

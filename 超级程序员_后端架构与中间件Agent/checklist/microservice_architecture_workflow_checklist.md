# Microservice Architecture Workflow Checklist

在完成 `workflow/microservice_architecture_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别微服务/分布式需求场景

- [ ] 已明确场景类型（服务拆分/基础设施选型/分布式事务/限流熔断降级/多租户/渐进式演进）
- [ ] 已识别当前架构阶段（单体/模块化单体/宏服务/已拆分微服务）
- [ ] 已提取团队与规模约束（团队人数、日活用户量、服务数量预期）
- [ ] 已提取稳定性要求（金融级可靠性、资金交易、可用性目标）
- [ ] 已提取特殊约束（SaaS多租户、数据一致性要求、合规要求）
- [ ] 已对照知识库核心决策点完成初步判断（团队<50人用单体/宏服务、金融交易关注分布式事务、SaaS关注多租户）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出微服务/分布式架构方案

- [ ] 如为服务拆分，DDD领域驱动设计方法论已说明（Bounded Context定义边界、Event Storming识别事件）
- [ ] 如为服务拆分，渐进式拆分路径已给出（单体→模块化单体→宏服务→微服务）并标注触发条件
- [ ] 如为基础设施选型，四件套已覆盖（注册中心Nacos/Consul、配置中心Apollo/Nacos、网关Envoy/Kong、分布式事务Seata/SAGA）
- [ ] 如为基础设施选型，注册中心选型对比已覆盖（AP优先vs CP强一致、本地缓存、K8s原生支持）
- [ ] 如为基础设施选型，配置中心选型对比已覆盖（三层模型、灰度发布、Vault密钥管理）
- [ ] 如为基础设施选型，网关架构设计已覆盖（多层网关：边缘→BFF→业务网关）
- [ ] 如为基础设施选型，分布式事务已用PACELC模型替代CAP做决策
- [ ] 如为基础设施选型，SAGA/TCC/2PC/Seata选型对比已给出并附业务场景匹配表
- [ ] 如为稳定性设计，限流4算法（计数器/漏桶/令牌桶/滑动窗口）已对比并给出推荐
- [ ] 如为稳定性设计，熔断三态状态机（Closed/Open/Half-Open）已说明并附Sentinel配置示例
- [ ] 如为稳定性设计，降级四级矩阵（核心/重要/次要/装饰）已输出并附降级开关设计
- [ ] 如为多租户，三模式选型对比已覆盖（完全共享/独立DB/独立部署）
- [ ] 如为多租户，租户隔离策略已覆盖DB层/缓存层/MQ层
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 输出内容无知识性错误
- [ ] 已向用户交付最终答案

- [ ] 没有在任何检查清单部分通过前提前进入下一步

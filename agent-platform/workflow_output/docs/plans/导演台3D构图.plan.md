## 背景与目标

画布新增 `director` 节点：点开进浏览器内 Three.js 3D 构图编辑器（积木素模+几何+群众阵列），多机位/FOV/画幅，机位视角截图回流画布成 ImageNode——解决多镜头站位/比例一致性（spec §1）。性能红线：服务器零渲染零新端点；three chunk 懒加载主包零增量；关闭 modal GPU 内存归零。

## 技术实现坑点预判与规避措施

| 技术点 | 坑 | 规避 | 验证 |
|---|---|---|---|
| OrbitControls × TransformControls | 同拖事件互抢（gizmo 拖动时画布跟着转） | 监听 gizmo `dragging-changed`，拖拽期 `orbit.enabled=false` | 手拖 gizmo 视角不转 |
| three 资源释放 | 关 modal 只移 DOM，geometry/材质/renderer 滞留显存 | dispose 清单化（遍历 scene.traverse dispose geometry/material → renderer.dispose + forceContextLoss → 移除 canvas）；共享图元 geometry 走预设缓存只 dispose 一次 | DevTools 开关 modal×3 内存增量 <10MB |
| 截图改 renderer 尺寸 | 直接 setSize 破坏主视口状态/闪烁 | 顺序化：暂存当前尺寸 → setSize(画幅分辨率≤2048) → render → toBlob → finally 恢复尺寸+重渲染；toBlob('image/webp',0.92) 不支持时回退 jpeg | 同机位两次截图像素尺寸一致 |
| 按需渲染 | 常驻 rAF 空转耗电发热 | invalidate 模式：控件 change/交互才排帧；静止 2s 停 rAF | 静置 Performance 面板无持续 GPU 帧 |
| InstancedMesh 阵列 | 行列/间距参数改动后实例矩阵不刷新 | 参数变→重算 instanceMatrix + count；12×12 上限 | 改间距群体即时重排 |
| happy-dom 无 WebGL | 单测环境 import three 崩/假挂 | 逻辑层 `director/sceneModel.ts` 零 three import；渲染层组件不进单测断言 | vitest 全绿无 WebGL 依赖 |
| undo 深拷贝 | 相机拖动每帧推栈爆内存 | structuredClone 快照；仅「交互结束」（dragging-changed false / 输入 blur）推栈；栈深 50 丢最旧 | 拖一次 gizmo 只推 1 条 |
| 节点↔画布通信 | Vue Flow 节点 emit 不冒泡 | `InjectionKey<DirectorBridge>` provide（openEditor/saveScene/screenshotDone），CanvasBoard provide、DirectorNode inject | 打开/保存/截图三链路通 |
| letterbox 与截图不一致 | 视口全屏形状≠画幅，截图所见非所得 | 机位视角：相机 aspect=画幅，视口 CSS 遮幅框纯显示；截图按同 aspect 尺寸渲染 → 天然一致 | 16:9 与 9:16 各截一张核对比例 |
| 响应式性能 | pixelRatio 4K 屏全开爆 GPU | `setPixelRatio(min(dpr,2))`；ResizeObserver 跟 modal 尺寸 | 高分屏帧率达标 |

## 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| InjectionKey | 带 TypeScript 类型的 provide/inject 钥匙，拿错类型编译期就报 | 节点组件向画布要「打开编辑器」入口 |
| InstancedMesh | 一个模型画 N 份只花一份开销 | 12×12 群众阵列 |
| invalidate 渲染 | 只有画面脏了才画下一帧，静止就停 | 拖动时 60fps，撒手 2 秒后 0fps |
| letterbox 遮幅 | 上下压暗留出目标画幅的取景框 | 电影上下黑边 |
| structuredClone | 浏览器原生深拷贝，比 JSON 快且支持更多类型 | undo 快照整场景复制 |

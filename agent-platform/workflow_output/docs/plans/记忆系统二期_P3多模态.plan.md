# Implementation Plan for 记忆系统二期 · P3 多模态文件记忆

> 主索引：[记忆系统二期.plan.md](记忆系统二期.plan.md) ｜ 规格 FR-201~205
> 依赖：P1 完成（路由层复用）。与 P2 可并行（文件交集仅 api/memory.ts，错峰到各自最后的前端 Step）。

## 本模块坑点预判

| 坑 | 规避 | 验证 |
|---|---|---|
| PDF/PPT 解析库吃内存（200 页） | 分页流式解析，逐页出 chunk 落库后释放；D4 上限硬卡 | 200 页 PDF ingestion 堆内存不飙 |
| 转写/多模态调用慢且贵 | 全异步 worker；每文件一次汇总 LLM（分块要点合并出 l1/l2），禁每页一次总 LLM | 单课件 LLM 调用次数 ≤ 页数/批大小 + 1 |
| 上传接口被刷大文件 | 大小/类型在网关层先拒（Content-Length + mime 白名单），解析前二次校验真实大小 | 超限断言 413 友好话术 |
| 聊天消息与附件的关联丢失 | 消息表加 attachment_file_ids（或关联表），turn 的 raw/L2 记录「含附件《名》」 | 上传后发消息，turn 能回溯文件 |
| 文件 ACL 放行越权 | 只调资产库共享放行已有方法；项目条目 file 下载按「条目所在项目成员」判 | 非成员下载 403 |
| 向量深读召回噪声 | chunks top-k≤5 + 相似度阈值；reflect 判定不通过不深读 | 无关提问不触发深读 |

## 实现步骤

- [x] **Step 1：V69 建表 + 聊天附件上传**（FR-201）✅ 2026-08-08 commit 66bc106（11 新测试绿，chat+file 313 绿）
  - **目标**：`memory_asset_memories` / `memory_asset_chunks` 建表；聊天支持附件
  - **动作**：DDL（asset_memories：owner_user_id/file_id/file_kind/l1/l2/tag_ids[]/ingest_status；chunks：asset_memory_id/chunk_no/chunk_text/chunk_embedding halfvec(2048)/page_ref；chunks 索引 (asset_memory_id,chunk_no)）；聊天上传端点复用 stored_files（source=CHAT），mime 白名单 + 50MB/页数/时长校验（页数/时长在上传后解析预检，超限拒收并提示）；消息体携带 file_ids
  - **文件**：`db/migration/V69__create_memory_asset_tables.sql`、`chat/entity/MemoryAssetMemory.java`、`MemoryAssetChunk.java`、对应 Mapper×2、`file/FileStorageService.java`（CHAT 上传校验钩）、聊天消息 DTO/实体（附件字段）
  - **依赖**：P1 Step 1
  - **验证**：上传课件成功登记 stored_files；超限文件 413

- [x] **Step 2：ingestion worker（解析+总结+分块）**（FR-202/205）✅ 2026-08-08 commit 3b62723（17 新测试绿，chat+file 330 绿）
  - **目标**：一文件一条记忆 + chunks
  - **动作**：`MemoryAssetIngestWorker`（@Scheduled + SKIP LOCKED，沿用 ConsolidationWorker 模式）：按 file_kind 分派——IMAGE→多模态描述+OCR；PPT/PDF/DOC→逐页要点（图页多模态/文页文本）+page_ref；AUDIO/VIDEO→转写+时间戳锚点；汇总一次 LLM 出 l1/l2+tag 建议（tag 走 MemoryTagResolver 归一进个人库）；状态机 PROCESSING→READY/FAILED（FAILED 可重试）；解析失败降级弱记忆（仅元数据+「读不懂内容」标注）
  - **文件**：`chat/service/internal/MemoryAssetIngestWorker.java`、`MemoryAssetIngestService.java`（分派+汇总）、`MemoryAssetChunkService.java`
  - **依赖**：Step 1
  - **验证**：课件上传→READY+l1/l2+每页 chunk 带 page_ref；坏文件→FAILED 可重试；无文字层扫描件→降级弱记忆

- [ ] **Step 3：文件记忆召回 + 深读**（FR-203）
  - **目标**：召回命中文件 → 总结+卡片；细节问 → 分块深读
  - **动作**：pipeline 加 ⑥.5：READY 文件记忆按 tag 命中 → l1/l2 进装配（结构化「文件卡片」块：file_id+名称+页数+可下载标记）；reflect 判需深读 → chunks 向量 top-5 注入（prompt 要求引用带 page_ref）；文件 CLEANED → 装配标「原文件已删除」
  - **文件**：`chat/service/internal/MemoryRecallPipeline.java`、`MemoryAssetRecallService.java`（新）、`MemoryAssetChunkService.java`（top-k）
  - **依赖**：Step 2、P1 Step 5
  - **验证**：问「那个课件讲什么」→总结+卡片；问「hooks 那页」→带页码回答；删文件后总结仍可召回

- [ ] **Step 4：文件记忆路由进项目 + ACL 放行**（FR-204）
  - **目标**：文件总结过路由，命中进项目条目
  - **动作**：ingestion READY 后调 P1 MemoryRoutingService（文本=文件 l1/l2）；命中→entries 行 content_type=FILE+file_id；文件下载鉴权扩展：stored_files 放行「该文件被某 ACTIVE FILE 条目引用且请求者是该条目项目 ACTIVE 成员」（复用资产库共享放行方法）
  - **文件**：`MemoryRoutingService.java`（文件入口）、`MemoryAssetIngestService.java`（READY 钩子）、`file/FileStorageService.java`（放行分支）、`AssetAclService.java`（复用）
  - **依赖**：Step 2、P1 Step 3
  - **安全检查**：放行仅走已有 ACL 路径
  - **验证**：课件进项目→成员可下载；非成员 403；作者删文件→项目条目标失效

- [ ] **Step 5：前端文件卡片 + 文件记忆页签**（FR-203/205）
  - **目标**：聊天附件 UI + 召回文件卡片 + 记忆面板文件列表
  - **动作**：聊天框附件上传（进度/超限提示）；AI 回复渲染文件卡片（图标/名称/页数/下载/「展开第 N 页」）；MemoryManagerPanel 加「文件记忆」页签（列表+状态+删除）；api/memory.ts 加端点
  - **文件**：`frontend/src/components/chat/`（附件上传组件、MessageFileCard.vue 新）、`frontend/src/components/memory/MemoryAssetMemorySection.vue`（新）、`MemoryManagerPanel.vue`、`api/memory.ts`
  - **依赖**：Step 3/4
  - **验证**：手测上传→提炼中→READY→提问召回卡片→下载；删除后卡片标失效

## 整体验证（P3）

- [ ] E2E：上传 32 页课件 → 一条 READY 记忆 → 问「讲了什么」得总结+卡片 → 问「第 12 页细节」得带页码回答 → 课件被路由进项目 → 项目成员下载成功
- [ ] 降级：上传损坏 PDF → FAILED 可重试；上传无文字扫描件 → 弱记忆+明示话术

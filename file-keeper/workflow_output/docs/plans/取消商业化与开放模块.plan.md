# 取消商业化与开放模块实现计划

> Phase 2 产出。Phase 3 逐项勾选执行；只含伪代码，不含真代码。
> 来源规格：[取消商业化与开放模块设计](../specs/取消商业化与开放模块设计.md)
> 影响评估：[影响评估-取消商业化与开放模块](../changes/影响评估-取消商业化与开放模块.md)
> 安全策略：[security_strategy.md](../specs/security_strategy.md)

## 1. 目标与实施原则

- 本地模块（文件、进程、剪贴板、截图）免登录且始终开放。
- 服务端模块（工作汇报、AI、互动收件箱、灵感、推送）要求登录，登录后不再检查模块权益。
- 注册用户立即激活；设备数量不限；账号禁用和设备禁用继续生效。
- 商业授权运行链路退出，旧接口与数据库结构进入废弃兼容期，不在本轮物理删除。
- 使用 TDD（测试驱动开发：先写失败测试，再写最小实现）推进每个行为变更，每个 chunk（可独立验证的小改动）完成后提交。

## 2. 子计划与顺序

| 顺序 | 子计划 | 目标 |
|---|---|---|
| 1 | [桌面端与 Rust](取消商业化与开放模块-1-桌面与Rust.plan.md) | 本地模块开放、服务端功能登录门、设备身份解耦、移除原生命令授权门禁 |
| 2 | [服务端与数据](取消商业化与开放模块-2-服务端与数据.plan.md) | 注册即激活、设备不限量、保留禁用、移除模块权益检查、兼容旧接口 |
| 3 | [管理后台、文档与回归](取消商业化与开放模块-3-后台文档回归.plan.md) | 移除商业运营入口、同步真相源、执行全量回归 |

依赖顺序：子计划 1 的设备身份接口先稳定；子计划 2 再替换服务端访问校验；子计划 3 最后收口 UI、文档与验证。

## 3. 技术坑点预判与规避

| 技术点 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| 设备身份解耦 | `deviceIdentity` 目前由 `commercialAuthStore` 提供，直接删除会让工作汇报和 AI 请求缺少 `deviceId` | 新建独立 `deviceStore`/`device` API，先迁移消费者，再停用商业 Store | Store/API 单测；登录后请求 URL 仍含同一 `deviceId` |
| 设备禁用 | 现有禁用判定依赖授权快照；移除快照后可能绕过禁用 | 抽出 `requireActiveDevice`（确认设备属于用户且为 active）并用于所有服务端模块入口 | 禁用设备访问工作汇报/AI 返回 403；正常设备通过 |
| 已禁用设备心跳 | `registerOrHeartbeat` 对已有设备只更新时间，当前未先检查状态 | 已有设备若 disabled 则立即拒绝，不更新 lastSeen | `DeviceBindingTest` 覆盖禁用设备重新注册 |
| 剪贴板生命周期 | 由“授权变化”改为“应用生命周期”后，重复启动可能产生多线程监听 | 保留前端幂等标记和 Rust 服务端幂等；挂载启动、卸载停止 | 重复调用测试 + 手工观察仅一个监听器 |
| Token 刷新 | `authStore` 当前刷新失败会初始化匿名授权 | 改为只清会话；本地模块保持可用，服务端页回登录引导 | 刷新失败测试；本地 Tab 不被隐藏 |
| 服务启动配置 | `AuthProperties` 当前强制要求 entitlement 私钥 | 移除 entitlement 私钥启动校验，但保留 JWT secret 强校验 | 无授权私钥的 Spring 测试上下文可启动；空 JWT 仍失败 |
| 旧客户端兼容 | 旧客户端仍调用匿名/登录授权接口，且旧 Rust 二进制可能依赖签名凭据 | 新客户端完全不用授权接口；兼容接口返回稳定快照；授权私钥改为可选，仅配置时为旧客户端临时签发全模块凭据 | 旧接口 Controller 测试不出现 500；未配私钥时服务可启动 |
| Flyway 双数据库 | PostgreSQL 与 H2 对状态迁移 SQL 的兼容存在差异 | V16 只使用标准 `UPDATE ... WHERE ...`，不删约束/表 | `FlywayMigrationTest` 同时验证迁移后状态 |
| 控制器重复校验 | 7 个 Controller 各自复制模块判断，容易漏改 | 统一改为设备访问服务；每个 Controller 只执行“身份 + active 设备 + 资源归属” | 全局搜索不再出现 `authenticatedSnapshot` 于 workreport/ai |
| 管理后台无测试框架 | `admin-web` 只有 build 脚本 | 本轮不引入新测试栈；使用 TypeScript 构建 + 浏览器路由/交互走查 | `npm --prefix admin-web run build` + 手工验收 |

## 4. 安全检查清单

- [ ] JWT 登录、refresh、logout 仍正常，未登录服务端接口仍返回 401。
- [ ] 账号 `disabled` 后 refresh token 失效，服务端模块不可访问。
- [ ] 设备必须属于当前用户且状态为 `active`；禁止仅凭任意 `deviceId` 访问。
- [ ] 工作汇报、AI、收件箱、灵感、SSE 仍按 `principal.userId()` 隔离数据。
- [ ] 推送凭据与 AI API Key 的 AES-GCM 加密、脱敏回显不变。
- [ ] 本地文件路径、剪贴板内容、截图和进程信息仍不上传服务端。
- [ ] Rust 移除商业门禁后，路径、区域、PID、窗口句柄等输入校验不被删除。
- [ ] 管理员禁用账号/设备继续写审计日志。
- [ ] 废弃接口不泄漏权益历史、签名材料或内部异常堆栈。
- [ ] 不新增依赖；现有依赖安全边界不扩大。

## 5. 功能联动点清单

| 触发动作 | 联动对象 | 预期变化 | 边界验证 |
|---|---|---|---|
| 应用未登录启动 | 本地 Tab、剪贴板监听 | 本地 Tab 全可用，剪贴板监听启动 | 重启、重复挂载、监听启动失败 |
| 未登录点击工作汇报 | 工作汇报内容、登录弹窗 | 不发业务请求，展示登录引导并可打开登录 | 取消登录后仍停留引导；登录成功后加载 |
| 未登录打开 AI 设置 | AI 配置区域、登录弹窗 | 不加载配置，展示登录引导 | 关闭设置、登录失败、重新打开 |
| 登录成功 | 设备注册、工作汇报/AI | 自动注册/心跳设备；服务端功能可加载 | 新设备、已有设备、禁用设备 |
| 退出或 refresh 失败 | 服务端数据、本地模块 | 清理用户态数据并回登录引导；本地模块不受影响 | 退出取消/接口失败/并发刷新 |
| 管理员禁用设备 | 设备心跳、服务端请求 | 后续访问返回 403；本地模块继续可用 | 当前设备与其他设备分别验证 |
| 注册成功 | 用户状态、后台统计 | 用户立即 active，不进入待审核队列 | 邮箱/手机号注册、重复注册 |
| 移除商业后台入口 | 路由、侧栏、用户详情、设置 | 不再显示权益/试用/额度；用户与设备禁用保留 | 直接访问旧路由、浏览器后退、刷新 |

## 6. 运维考量清单

- [ ] **做—可观测性**：保留登录、refresh、账号禁用、设备注册/禁用、AI、推送失败日志；不记录 Token、API Key 或推送密钥。
- [ ] **做—迁移日志**：Flyway V16 由标准迁移日志记录；上线前备份 `users` 状态分布。
- [ ] **做—兼容监测**：短期统计旧授权/匿名接口调用量，调用归零后再规划物理删除。
- [ ] **做—回滚**：代码按子计划 chunk 提交；V16 不删数据，回滚代码时单独评估已激活用户是否需要恢复审核状态。
- [ ] **不做—功能开关**：本变更是明确产品决策，不增加“重新开启商业授权”运行时开关，避免双逻辑长期并存。
- [ ] **不做—新增缓存**：模块权益查询被删除，不引入新缓存；设备查询为单行索引查询。
- [ ] **不做—限流改造**：本轮不改变登录、AI、Webhook 既有限流/超时策略。
- [ ] **后续—物理清理**：待兼容接口调用归零后，另立 Phase 6 删除权益、匿名试用、离线授权表/字段/代码。
- [ ] **告警调整**：删除权益过期、匿名试用异常告警；保留登录失败率、设备禁用拒绝率、AI/推送失败率。

## 8. 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| TDD | 先写一个会失败的测试，再写最少代码让它通过 | 先断言“未登录可打开剪贴板”，看到失败后再删门禁 |
| chunk | 一次可独立验证和回滚的小改动 | “设备身份从商业 Store 拆出”单独提交 |
| 废弃兼容期 | 旧入口暂时还在，但新代码不用，观察无人调用后再删 | `/api/anonymous/authorization` 暂留 |
| 资源归属 | 数据必须属于当前登录用户 | 用户 A 不能读取用户 B 的工作记录 |
| Flyway | 数据库版本脚本管理工具 | 新增 `V16__activate_pending_users.sql` |

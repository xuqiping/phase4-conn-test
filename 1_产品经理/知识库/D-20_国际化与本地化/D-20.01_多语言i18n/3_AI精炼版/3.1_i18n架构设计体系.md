# 3.1 i18n架构设计体系

## 一、定义与边界

**i18n（Internationalization，国际化）**：在产品架构层面预留多语言/多地区支持能力，使产品无需工程改造即可适配新语言。i18n是"架构准备"，l10n（Localization，本地化）是"具体适配"——先i18n后l10n。

**核心原则**：文案与代码分离、动态加载语言资源、UI适配不同语言特性（长度/方向/格式）。

## 二、文案外置：资源文件体系

### 资源文件格式对比

| 格式 | 适用平台 | 示例 | 优缺点 |
|---|---|---|---|
| JSON | Web/跨平台/Node.js | `{"hello": "你好"}` | 通用性强，易读写；无元数据支持 |
| PO/MO | gettext系(PHP/Python) | `msgid "hello" msgstr "你好"` | 支持翻译记忆/上下文注释；格式较重 |
| strings/XML | iOS(.strings)/Android(.xml) | `<string name="hello">你好</string>` | 原生支持；平台绑定 |
| YAML | Rails/Ruby | `hello: "你好"` | 可读性好；缩进敏感 |
| ARB | Flutter | `{"@@locale": "zh", "hello": "你好"}` | Flutter官方格式；支持元数据 |

### 命名规范建议

```
locales/
├── en/          # 英语（基准语言）
│   ├── common.json
│   ├── home.json
│   └── settings.json
├── zh-CN/       # 简体中文
│   ├── common.json
│   ├── home.json
│   └── settings.json
├── ja/          # 日语
├── ar/          # 阿拉伯语
└── ...
```

**最佳实践**：按功能模块拆分而非全量单文件——避免单文件过大、便于团队并行翻译。

## 三、动态语言切换

### 切换机制设计

| 维度 | 方案 | 说明 |
|---|---|---|
| 语言检测 | 浏览器locale / 系统语言 / 用户手动选择 | 优先级：用户选择 > 系统语言 > 浏览器locale |
| 资源加载 | 同步预加载 / 按需异步加载 | 大型应用按需加载，减少首屏体积 |
| 切换体验 | 无刷新切换 / 整页刷新 | 前端框架(i18next)支持无刷新 |
| 持久化 | localStorage / Cookie / 用户Profile | 登录用户存Profile，未登录存localStorage |

### i18next框架核心概念

| 概念 | 说明 |
|---|---|
| namespace | 按模块拆分翻译命名空间（common/home/settings） |
| interpolation | 变量插值（`{{name}}` → 用户名） |
| plurals | 复数处理（英语one/other，阿拉伯语6种复数形式） |
| fallbackLng | 回退语言（缺少翻译时回退到基准语言） |
| suspense | React中异步加载翻译资源 |

## 四、RTL（从右到左）布局适配

### RTL语言列表

阿拉伯语(Arabic)、希伯来语(Hebrew)、波斯语(Persian/Farsi)、乌尔都语(Urdu)等约12种语言为RTL方向。

### RTL适配要点

| 维度 | LTR→RTL适配方法 |
|---|---|
| 布局方向 | `direction: rtl` 翻转整体布局 |
| 图标方向 | 方向性图标（箭头/返回按钮）需镜像 |
| 文本对齐 | 默认右对齐 |
| 间距 | margin/padding的left/right互换（用logical properties: `margin-inline-start`） |
| 动画 | 滑入/滑出方向翻转 |

**CSS Logical Properties**（推荐）：
```css
/* 传统（硬编码方向） */
margin-left: 16px;
/* 逻辑属性（自动适配RTL） */
margin-inline-start: 16px;
```

## 五、字符膨胀率管理

不同语言表达同一含义的字符长度差异显著，UI须预留弹性空间：

| 语言 | 相对英语膨胀率 | 示例 |
|---|---|---|
| 英语 | 基准(100%) | "Settings" (8字符) |
| 中文 | -10%~+10% | "设置" (2字符) |
| 德语 | +20%~+35% | "Einstellungen" (13字符) |
| 法语 | +15%~+20% | "Paramètres" (10字符) |
| 芬兰语 | +30%~+40% | "Asetukset" (9字符，但长词多) |
| 阿拉伯语 | +20%~+25% | "الإعدادات" |

**PM设计要点**：
- 按钮文案预留**+40%**宽度空间
- 避免固定宽度，使用弹性布局
- 长文案考虑截断+Tooltip或换行
- 表单标签考虑垂直排列

## 七、常见坑

1. **"硬编码文案"**：把文案直接写在代码里是i18n的头号大忌——任何用户可见文字都应外置到资源文件。
2. **"忽略复数形式"**：英语只有one/other，但阿拉伯语有6种、俄语有3种复数形式，直接拼接`{{count}} items`会出问题。
3. **"RTL只翻转布局"**：RTL不只是布局翻转——图标方向、动画方向、甚至进度条方向都需翻转。
4. **"按英文长度设计UI"**：德语/芬兰语比英语长30-40%，按英文设计的按钮在德语下会截断。
5. **"日期/时间格式硬编码"**：不同地区的日期格式差异大（MM/DD/YYYY vs DD/MM/YYYY），须用Intl API或dayjs等库处理。

## 八、国内外对比

| 维度 | 中国出海产品 | 海外成熟产品 |
|---|---|---|
| i18n成熟度 | 起步阶段，常"先做中文再补英文" | 架构层面原生i18n，从Day 1支持 |

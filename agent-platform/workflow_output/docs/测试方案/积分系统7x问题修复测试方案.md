# 积分系统 7x 问题修复 · 测试方案

> 覆盖 7x-1（500修复）/7x-2（导出导入模板）/7x-3（has_reference 定价）/7x-4（审查标志 + 推送参数）。
> 含功能联动用例（正向/反向/旧任务边界）。Phase 4 按本方案逐项傻瓜式验证。

## 前置条件
- 后端已跑 V95 迁移（`pricing_rule.has_reference` 列存在，旧行 DEFAULT FALSE）
- admin 账号（有 `pricing:manage` 权限）
- 至少配了 1 个 CHAT 模型价表、1 个 VIDEO 模型价表（VIDEO 候选）
- PG 里 `llm_providers.deleted` 是 INTEGER 列（验证 500 修复用）

---

## TC-1 · 图片价表创建不再 500（7x-1）

**步骤**：admin 进「价表配置」→ 新增 → 选一个 IMAGE 模型 → 填图片单价 → 保存
**预期**：保存成功（200），不报 500；库里该行 `video_billing_mode` 为 NULL（不泄漏 'TOKEN'）
**联动反向**：再分别创建 CHAT / EMBED / VIDEO 各一行，全部成功（验证不是只有 IMAGE 修了）

## TC-2 · 价表导出（7x-2）

**步骤**：点「导出」→ 确认 → 下载 JSON
**预期**：文件名 `pricing-rules-yyyy-MM-dd.json`；内容是当前全量价表数组；含 hasReference 字段；明文价格无密钥

## TC-3 · 下载模板（7x-2）

**步骤**：点「下载模板」
**预期**：文件名 `pricing-template-yyyy-MM-dd.json`；每行 kind/providerId/providerName/model 预填，价格字段为 null；**已配置的模型不在模板里**（联动 availablePricingModels 过滤）；CHAT/IMAGE/VIDEO 按 kind 区分

## TC-4 · 导入新建（7x-2）

**步骤**：基于模板填几行新模型价格 → 点「导入」→ 选文件 → 确认（提示预计新增 N）→ 导入
**预期**：提示「新增 N / 更新 0 / 失败 0」；列表出现新行

## TC-5 · 导入覆盖（7x-2 upsert）

**步骤**：导出当前价表 → 改其中 1 行的价格 → 导入 → 确认（提示预计更新 1）
**预期**：提示「新增 0 / 更新 1」；该行价格已变、`effective_from` 刷新为导入时刻；后续调用按新价

## TC-6 · 导入非法行不中断（7x-2）

**步骤**：构造含 1 行脏数据（如 providerId=99999 不存在）+ 1 行合法数据的 JSON → 导入
**预期**：提示「新增 1 / 更新 0 / 失败 1」；合法行落库；console 有失败原因

## TC-7 · 导入超限拒绝（7x-2）

**步骤**：构造 201 行 JSON → 导入
**预期**：提示「单次导入上限 200 条」（400 错误）

## TC-8 · 视频配双价（7x-3）

**步骤**：为 seeddance 配两行：开关关=20元/百万，开关开=10元/百万
**预期**：列表显两行，「参考视频」列分别显「无参考」「有参考」；候选下拉仍可见 seeddance（has_reference 维度不同不冲突）

## TC-9 · 计费命中 fallback（7x-3）

**步骤**（需能触发真实视频生成或 mock）：
- 只配 false=20 行 → 提交一个带参考视频任务 → 计费按 20（fallback 到 false）
- 配 false=20 + true=10 → 带参考视频任务计费按 10，无参考任务按 20
- 只配 true=10 不配 false → 无参考任务报「价表未配置」（不无限兜底）
**预期**：fallback 到 false 行生效；精确命中 true 行；只配 true 时无参考报错

## TC-10 · 首尾帧图不算参考视频（7x-3/7x-4 边界）

**步骤**：提交一个带首帧图（kind=image）的视频任务 → 看任务详情 hasReference 标志 + 计费命中
**预期**：hasReference=false（首帧图不算参考视频）；命中 false 价表行

## TC-11 · VideoGenView 参考标志（7x-4）

**步骤**：分别提交「无参考」「带参考视频」「带首帧图」三种任务 → 看任务头标签 + 历史列
**预期**：任务头分别显「无参考」「有参考视频」「无参考」；历史「参考视频」列对应显「无/有/无」；旧任务显「-」

## TC-12 · Canvas 参考标志 + 推送参数（7x-4）

**步骤**：画布提交一个带参考视频的视频任务 → 成功后选中节点
**预期**：节点角标显「参考」；属性面板 taskId 行旁显「有参考视频」；点「请求参数」能看 submittedRequest + providerRequestSnapshot 两个 tab；刷新画布后字段仍在（hydrate 保留）
**旧任务边界**：迁移前的旧节点无推送快照 → 面板提示「该历史任务未记录发送快照」

## TC-13 · 推送参数脱敏（7x-4 安全）

**步骤**：看 providerRequestSnapshot 内容
**预期**：媒体 URL 被替换为 `{redacted:true, fileId, transport, mime?, bytes?, sha256?}`，不含二进制/data URI

## TC-14 · 导入文件含 hasReference 但后端旧版（7x-2 兼容）

**步骤**：导出的 JSON 含 hasReference 字段 → 想象导入到未跑 V95 的旧后端
**预期**：`@JsonIgnoreProperties(ignoreUnknown=true)` 保证旧后端不炸，hasReference 被忽略按 false 落库（双向兼容）

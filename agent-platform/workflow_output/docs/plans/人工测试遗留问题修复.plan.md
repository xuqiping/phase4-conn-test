## 通用技术坑点预判（各子计划另有专属坑表）

| 技术点 | 坑 | 规避 |
|---|---|---|
| SSE 裸线程 ThreadLocal | ChatController SSE 用裸 `new Thread()`，BillingContext/SecurityContext 手工 set/clear（BillingContext.java:10 注释） | 新代码在同线程内 set/clear，PROGRESS 定时器回调不得读 ThreadLocal |
| 幂等键 | 聊天 hold/settle/debt 多腿操作，网络重试或 SSE 重连易双记 | 全部幂等键化：`chat-hold-{messageId}`、`chat-settle-{messageId}`、`debt-{userId}-{refType}-{refId}` |
| points_ledger 大表 | 消费入口若 SUM 流水表判欠款会拖慢所有提交 | 欠款用冗余列 `debt_points`（V157），流水只作明细 |
| 组账本新类型污染对账 | MEMBER_* 若被对账聚合误算进资金等式 → 永久「不平」假警报 | 对账 SQL 用 type 白名单（ALLOCATE/RECLAIM/CONSUME/REFUND），显式排除 MEMBER_* |
| 前端两套尺寸实现 | ImageGenView 与 PropertyPanel 已分叉，改一处漏一处 | 比例推导/选项抽公共工具（子计划 C），两处消费同一实现 |

## 术语表

| 术语 | 大白话 | 案例 |
|---|---|---|
| HOLD 预扣 | 先冻住预估的钱，完事多退少补 | 开聊前冻 300，实耗 120 退 180 |
| PROGRESS 事件 | 服务器边生成边报「目前已花约 X」 | 每秒一条，答完换准确数 |
| DEBT 欠款 | 钱不够时扣光余额、差额挂账 | 10 分干了 300：扣 10 欠 290 |
| MEMBER_* 流水 | 给成员配/收额度的历史记录 | A 班张三先后被配 100+50=累计 150 |
| 对账恒等式 | 划入−消耗+退款=现存，不平=有 bug | 划 1000 花 300 退 50 → 池里必须 750 |
| WxH 推导 | 把「16:9+2K」换算成具体像素 | 16:9+2K → 2731x1536 |

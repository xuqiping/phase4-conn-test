# 3.2 流失预警与增购路径

## 1. Churn（流失）3层信号模型

### Layer 1 · 行为信号（产品数据可见）

| 信号 | 含义 | 预警级别 |
|---|---|---|
| 登录频次持续下降 | 用户不再活跃 | 🟡 |
| 关键工作流完成率下降 | 用而无效 | 🟡 |
| 活跃用户数收缩 | 从多部门退回单部门 | 🔴 |
| 功能使用范围缩小 | 从5+模块退回1-2个 | 🔴 |
| 支持工单激增 | 客户遇到大量问题 | 🟡 |
| 支持工单归零 | 客户放弃求助 | 🔴（最危险） |

> **最反直觉的信号**：工单归零≠客户满意——可能是客户已经放弃，不再期望你的产品能解决问题 [来源:Gainsight | 置信度:🔍高]

## 2. 流失预警流程

```
信号捕获(3层) → 健康度降级 → CSM判断(是真风险还是噪音?) → 干预计划 → 执行 → 效果评估
```

**CSM判断要点**：
- 单一信号≠确定流失（登录下降可能只是季节性波动）
- 2+信号叠加=高概率流失 → 必须干预
- 组织信号>行为信号——Champion离职是比登录下降严重得多的信号

**干预动作优先级**：
1. P0：Champion确认/新Champion培养 → 防关系断裂
2. P1：高管触达/价值重申 → 防决策层放弃
3. P2：使用障碍排查/培训 → 防使用下滑
4. P3：续约优惠/增值服务 → 经济挽留

## 3. 增购4条路径

### 路径1：向上销售（Upsell）— 同产品升档

- **定义**：客户从低版本升级到高版本（如Starter→Professional）
- **触发条件**：客户使用量接近当前版本上限/需要高级功能
- **PM角色**：设计清晰的功能分层（详见D-17.02），让升级理由自然可见

### 路径2：交叉销售（Cross-sell）— 新产品/模块

- **定义**：客户购买新产品线/新模块（如用CRM的客户增购营销模块）
- **触发条件**：客户在其他业务场景有痛点 → 公司有对应模块
- **PM角色**：产品模块间打通数据流/工作流 → 让交叉使用成为自然延伸

### 路径3：使用深化（Adoption Expansion）— 更多用户/部门

- **定义**：客户从1个部门扩展到3+部门使用（License扩容）
- **触发条件**：某部门成功→其他部门有类似需求
- **PM角色**：降低跨部门推广门槛（管理后台/多租户/部门隔离）

### 路径4：新场景拓展（Use Case Expansion）— 新使用场景

- **定义**：客户用同一产品解决更多业务问题
- **触发条件**：产品能力可覆盖客户的其他业务场景
- **PM角色**：产品灵活度+场景模板 → 让客户自行发现新用法

## 4. 增购驱动NRR的计算逻辑

```
NRR = (期初ARR + Upsell金额 + Cross-sell金额 + License扩容 - Downgrade - Churn) / 期初ARR

提升NRR的3个杠杆：
1. 增大Upsell+Cross-sell+License扩容 → 主动增购
2. 减少Downgrade → 防降级（价值维持）
3. 减少Churn → 防流失（续约率提升）
```

**行业标杆**：Top SaaS公司的NRR提升主要靠**增购**而非防流失——流失率降到5%以下后，增购才是NRR>120%的引擎 [来源:SaaS Capital/OpenView | 置信度:📚中]

## 5. 增购时机判断

| 客户阶段 | 推荐增购路径 | 信号 |
|---|---|---|
| 0-6月（Onboarding） | 不推荐增购 | 先确保使用成功 |

| 24月+（Strategic） | 全路径 | 战略合作+共创 |

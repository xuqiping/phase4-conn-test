## 1. Token

| 字段 | 内容 |
|---|---|
| 英文全称 | Token |
| 定义 | LLM处理文本的最小单位，一个Token约对应0.75个英文单词或0.5-1个中文字符 |
| PM解读 | Token是AI产品的"计价单位"和"容量单位"。理解Token才能算成本、设限制、估延迟 |
| 常见误解 | 以为1个字=1个Token（中文的Token化不如英文高效；生僻字可能占2-3个Token） |
| 口径注意 | 不同模型的Tokenizer不同，同一段文字在不同模型中的Token数可能差30%+ |
| 来源 | [📚训练知识]

## 2. 上下文窗口 / Context Window

| 字段 | 内容 |
|---|---|
| 英文全称 | Context Window |
| 定义 | 模型单次能处理的最大Token数（含输入+输出）。如128K表示最多处理约12.8万个Token |
| PM解读 | 上下文窗口是模型的"短期记忆容量"。它决定了一次对话能塞多少材料、能处理多长的文档 |
| 趋势 | [来源:公开信息 | 🔍高 | 2026-01] 2025-2026主流模型上下文：128K~1M（Gemini Pro 2M, Claude 200K, GPT-4o 128K） |
| 常见误解 | 以为上下文窗口内信息都同等重要（超长上下文中，中间位置的信息容易被"遗忘"——"丢失在中间"现象） |
| 来源 | [📚训练知识]

## 3. 量化 / Quantization

| 字段 | 内容 |
|---|---|
| 英文全称 | Quantization |
| 定义 | 用更低精度（如INT8/INT4）存储和计算模型参数，减少内存占用和推理成本 |
| PM解读 | 量化是"用精度换成本"——4-bit量化可能只损失1-3%能力，但内存降到1/4。产品落地几乎必做 |
| 常见误解 | 以为量化=大幅降质（INT8量化几乎无损；INT4在多数场景可接受；关键场景需做A/B对比） |
| 来源 | [📚训练知识]

## 4. 蒸馏 / Distillation

| 字段 | 内容 |
|---|---|
| 英文全称 | Knowledge Distillation |
| 定义 | 用大模型（教师模型）的输出训练小模型（学生模型），使小模型在特定任务上接近大模型水平 |
| PM解读 | 蒸馏是"大师教徒弟"——DeepSeek-R1蒸馏到7B小模型，在特定任务上接近原版671B的效果，但成本降低两个数量级。2025年MIT年度十大AI热词之一 |
| 常见误解 | 以为蒸馏后的小模型能力全面接近大模型（蒸馏只在训练数据覆盖的分布上有效；超出分布仍会退化） |
| 来源 | Hinton et al., 2014; [来源:MIT Technology Review | 📚中 | 2025-12]

## 5. 混合专家 / Mixture of Experts / MoE

| 字段 | 内容 |
|---|---|
| 英文全称 | Mixture of Experts |
| 缩写 | MoE |
| 定义 | 模型架构中设置多个"专家"子网络，每次推理只激活部分专家，用稀疏激活降低计算成本 |
| PM解读 | MoE是"大模型低成本运行"的关键架构——总参数671B但只激活37B，意味着能力大但成本可控。2025年已成为万亿参数模型的主流架构 |
| 对比Dense | Dense模型每次推理激活全部参数，MoE只激活部分。MoE推理成本低但内存仍需加载全部参数 |
| 来源 | [来源:CSDN | 📚中 | 2025-11]

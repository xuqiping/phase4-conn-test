## 技术实现坑点预判与规避措施

| 技术点 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| 哈希链写入并发 | 两线程同读同一条 prev_hash → 分叉双链 | 写入串行化：`pg_advisory_xact_lock(审计链固定key)` 包住「读末行 hash→插新行」；审计本就是异步单消费者小池，竞争极低 | 并发灌 50 条审计后链校验通过 |
| HMAC 密钥泄露 | 密钥进代码/配置仓库等于链可伪造 | `AUDIT_HMAC_KEY` 环境变量注入，启动缺失拒绝启动（沿用 JwtUtil fail-fast 范式）；入 G1 轮换清单 | 无环境变量启动炸；有则正常 |
| 链校验性能 | 全表重算随数据量线性增长 | 每日增量校验（从上次锚点行起算）+ 每周全量；先全量 MVP（当前量级可忽略） | 手动 UPDATE 一条 → 次日报断链 |
| 单点登录踢人体验 | 用户被踢后不明所以；Redis 挂全员掉线 | 被踢响应固定话术「账号已在别处登录」；**Redis 故障降级放行 + WARN**（沿用 S1 防爆破模式，不杀主链）；旧 token（无 sid claim）一律视为失效强制重登一次 | A 登录→B 登录→A 请求 401；停 Redis 仍可请求 |
| sid 塞进 JWT | 改 JwtUtil 签名波及全部签发/解析调用方 | sid 作为新 claim 追加（不改既有 claim）；generate 方法加带 sid 重载，旧签名保留编译过渡；refresh 旋转沿用同 sid（会话延续） | 登录→refresh→请求全链绿 |
| 在途计数泄漏 | 进程崩溃/流中断 INCR 未 DECR → 用户永久被闸 | 计数键带 TTL（30min）兜底自动释放；正常路径 try/finally DECR；媒体异步任务由 worker 完成/失败回调 DECR。**已知近似（Phase4 回写）**：存活任务 >30min 时键过期→槽位被遗忘→该用户可超额并行（fail-open 方向，宁松勿死锁） | 杀进程后 30min 内自动恢复可跑 |
| 闸门误伤内部调用 | embed/记忆管线等系统内部 LLM 调用被用户余额闸死 | 闸门只挂**用户主动入口**：LlmGateway chat/chatStream + MediaGenTaskService 提交；embed 及系统任务（userId=null）不过闸 | KB 索引不受低余额影响 |
| 阈值动态配置 | @Value 静态配置改阈值要重启 | 挂 system_settings（SystemSettingService 实时查库范式），键 `billing.low-balance.threshold`/`billing.low-balance.max-inflight`，非法值回退默认 | admin 页面改 100→50 立即生效 |

## 安全检查清单

- [ ] **A01 越权**：B1 扫描兜底注解缺失；B2 断言 403 非 404/500；被踢会话全端点失效。
- [ ] **A04 不安全设计**：低余额闸门服务端判定（余额实时查库，不信前端）；计数增减与任务生命周期严格配对。
- [ ] **A07 认证失效**：A8 会话踢出；refresh 须带 sid 且匹配当前会话。
- [ ] **A08 完整性**：审计哈希链 + 外部锚定；DB 层 REVOKE 双保险。
- [ ] **A09 日志**：踢会话/闸门拦截/断链全部写安全审计 + 日志。
- [ ] **降级原则**：Redis 故障时单点登录与并行闸门均降级放行 + WARN（可用性 > 强制力，与 S1 一致）。
- [ ] **错误话术**：被踢/被闸话术固定，不透传余额具体值以外信息。

## 性能考虑与验证计划

- [ ] **单点登录开销**：每请求多 1 次 Redis GET（session 比对）+ 1 次 system_settings SELECT（开关实时查库，无缓存——Phase4 回写确认；热路径成本与 S1 防爆破查询同级），与既有黑名单 GET 同量级；合并两次 GET 为一次 pipeline 可选优化（MVP 不优化）。
- [ ] **并行闸门开销**：任务入口 INCR + 余额查询（预检本就查余额，复用同一次），出口 DECR；每任务 +2 Redis 操作。
- [ ] **链写入**：advisory lock 仅在审计异步池内串行，不碰请求线程。
- [ ] **链校验**：每日凌晨低频任务，非请求路径。

## 功能联动点清单

- [ ] **A8 → 钉钉免登**：loginByDingTalk 同走 issueTokens，同样踢旧会话（预期一致）。
- [ ] **A8 → 已在线用户**：上线瞬间全部旧 token 无 sid → 强制重登一次（一次性，配合 G1 轮换公告合并执行最佳）。
- [ ] **A8 → S1 黑名单/logout**：logout 黑名单保留（防登出后 token 残留复用）；sid 比对在黑名单之后。
- [ ] **L7 → 计费铁律**：闸门拦截是「拒新任务」，绝不影响在途任务完成与扣费/退款链路。
- [ ] **L7 → 充值回血**：充值后余额 ≥ 阈值即自动恢复并行，无需额外动作。
- [ ] **L7 → 媒体异步任务**：提交占槽 → worker 完成/失败释槽；任务超时失败也必须 DECR。
- [ ] **D1 → 日志系统 AuditLogService**：链写入收敛在 insert 咽喉点，11+ 标注点零改动。
- [ ] **D2/D5 → S1 V80**：points_ledger REVOKE 已落，本阶段补 audit_logs 与其余钱表核查。

## 实现步骤

- [ ] **Step 1：D1 审计哈希链写入** `[P] 可并行`
  - **目标**：audit_logs 每行带 prev_hash/record_hash，任何单行篡改/删除全链可证伪。
  - **动作**：V81 加列（存量行不回填，决策见运维考量清单）；`AuditLogService` insert 咽喉点包 `pg_advisory_xact_lock`：读末行 record_hash → 拼 `HMAC(canonical(row)+prev_hash, AUDIT_HMAC_KEY)` → 写新行；密钥环境变量注入 + 启动 fail-fast。
  - **文件**：`db/migration/V81__audit_hash_chain.sql`、`common/audit/AuditLogService.java`、`AuditHashChainService.java`（新建）
  - **需人工介入**：否（但生产须配 AUDIT_HMAC_KEY）
  - **验证**：并发灌 50 条 → 逐行重算全链通过；手改一行 → 该处及之后全断。

- [ ] **Step 2：D2+D5 DB 权限分离核查补齐** `[P] 可并行`
  - **目标**：应用账号对审计/钱表物理上只增不改。
  - **动作**：V81 内对 audit_logs REVOKE UPDATE/DELETE（DO 块判 agent_app 角色存在，沿用 V78 范式）；核查 payment_orders/user_points_balance/idempotency_keys 是否需同样收紧（流水只增，余额行须 UPDATE 故不动）；结果记入 plan 备注。
  - **文件**：`db/migration/V81__audit_hash_chain.sql`（REVOKE 段）
  - **需人工介入**：否（本地 postgres 超管下 REVOKE 无效，随 H2 生产 agent_app 账号生效）
  - **验证**：以受限角色 UPDATE audit_logs → 权限拒绝。

- [ ] **Step 3：D3 链校验 + D4 外部锚定** `[依赖: Step 1]`
  - **目标**：断链每日自动发现并告警；链根外存防整库篡改后重算假链。
  - **动作**：`AuditChainVerifyService`（新建）：全量逐行重算比对，断点写安全审计 + ERROR；@Scheduled 每日 03:40（错开 S1 对账 03:20）；校验通过则当日末行 record_hash 追加 logs/audit-anchor.log（随 sync-offsite 异地）；admin 手动校验端点 GET /api/audit/logs/verify-chain（Phase4 回写：落在 AuditLogController，权限 system:audit:read）。
  - **文件**：`common/audit/AuditChainVerifyService.java`、`common/audit/AuditLogController.java`（加端点）
  - **需人工介入**：否
  - **验证**：手改一行 → 定时/手动校验报断链行号；anchor 文件逐日增长。

- [ ] **Step 4：B1 权限注解覆盖扫描** `[P] 可并行`
  - **目标**：任何新端点漏标 @RequirePermission 即被发现。
  - **动作**：启动期 ApplicationRunner 扫全部 @RequestMapping 方法：无注解且不在白名单（auth/login、actuator、sidecar 回调等显式登记）→ WARN 清单 + 计数指标；白名单集中一处维护。
  - **文件**：`common/security/PermissionCoverageScanner.java`（新建）、白名单配置
  - **需人工介入**：否
  - **验证**：临时加个裸端点 → 启动日志出现该行。

- [ ] **Step 5：B2 越权测试脚手架 + B3 收口红线** `[P] 可并行`
  - **目标**：越权回归机制化，归属校验命名统一。
  - **动作**：抽象 `AbstractPrivilegeIT`：given 用户A建资源 → when 用户B 读/改/删 → then 403；首批覆盖 file/asset/kb 三域各 1 条示范；命名红线写入 CLAUDE.md 或规范文档：按 id 取数方法必须 `getXxxScoped(id, userScope)`。
  - **文件**：`src/test/java/.../common/AbstractPrivilegeIT.java`（新建）、三域示范 IT
  - **需人工介入**：否
  - **验证**：故意去掉某咽喉点归属校验 → 对应 IT 红。

- [x] **Step 6：A8 单点登录（SEC-FR-008）** `[P] 可并行`
  - **目标**：同账号仅一处在线；新登录后旧设备 token 立即失效（含 refresh）。
  - **动作**：登录/钉钉登录/注册即生成 `sid=UUID` 写 Redis `session:user:{userId}`（TTL=refresh 有效期 7d，每次登录覆盖写=踢旧）；JwtUtil 加 sid claim（access+refresh 都带，refresh 旋转沿用同 sid）；JwtAuthenticationFilter 在黑名单检查后比对 sid 与 Redis 当前值，不符→拒绝（固定话术 40104）；refresh 接口同样比对；logout 比对 sid 删 session 键（Phase4 修复：只删自己会话，防 logout-bomb）；Redis 故障降级放行+WARN；`auth.single_session.enabled` system_settings 开关默认开；被踢写安全审计（auth/session_kicked）。
  - **文件**：`auth/service/AuthService.java`、`auth/security/JwtUtil.java`、`auth/security/JwtAuthenticationFilter.java`、`ErrorCode.java`（+40104）、`system/service/SystemSettingService.java`（+开关）
  - **需人工介入**：否（上线即全部旧 token 强制重登一次，公告合并 G1）
  - **验证**：A 登录→B 登录→A 请求 401（40104）、A refresh 也 401；停 Redis 全链可请求；开关关闭恢复多会话。

- [x] **Step 7：L7 低余额并行闸门（SEC-FR-126）** `[依赖: 无（S1 L1 已落，直接复用余额查询）]`
  - **目标**：余额 < 阈值（默认 100，管理员页面可配）时该用户禁止多任务并行，只允许一个在途任务跑完再跑下一个。
  - **动作**：`InflightGateService`（新建）：Redis `inflight:u:{userId}` INCR/DECR + TTL 30min 兜底；判定=余额（预检同一次查询复用）< `billing.low-balance.threshold` 且 inflight ≥ `billing.low-balance.max-inflight`（默认 1）→ 抛新 ErrorCode 42902「余额不足，请等待当前任务完成」；挂点：LlmGateway chat/chatStream（流式 acquire 移入 Flux.defer 订阅期执行，doFinally 配对 DECR；组装期异常同样释放——Phase4 修复：组装期 acquire 存在「未订阅/组装抛异常」双泄漏路径）+ MediaGenTaskService 提交（worker 完成/失败/超时 DECR）；embed 与 userId=null 系统任务不过闸；SystemSettingService + SystemSettingController 加 billing 分组两键 + 前端设置页两项；拦截写安全审计（billing/inflight_rejected）。
  - **文件**：`billing/service/InflightGateService.java`（新建）、`llm/LlmGateway.java`、`media/service/MediaGenTaskService.java`、`media/service/MediaGenTaskWorker.java`、`ErrorCode.java`（+42902）、`system/service/SystemSettingService.java`、`system/controller/SystemSettingController.java`、前端设置页
  - **需人工介入**：否
  - **验证**：余额 99 用户连发 2 对话→第二个 42902；第一个完成后第二个可发；余额充到 100 立即恢复并行；杀进程 30min 后槽位自动释放；admin 改阈值立即生效。

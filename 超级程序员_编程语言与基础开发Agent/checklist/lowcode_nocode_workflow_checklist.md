# Low-Code & No-Code Workflow Checklist

在完成 `workflow/lowcode_nocode_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别低代码/无代码场景

- [ ] 已明确场景类型（平台选型/企业落地/创业应用/平台使用教学）
- [ ] 已识别目标用户（企业IT/业务人员/独立开发者/创业者）
- [ ] 已提取应用复杂度（简单表单→中等系统→复杂核心系统）
- [ ] 已提取预算范围
- [ ] 已提取特殊约束（信创/数据安全/定制化/系统集成）
- [ ] 已对照知识库平台分类完成初步判断
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出低代码/无代码方案

- [ ] 如为平台选型，对比表覆盖技术维度和商业维度至少各3项
- [ ] 如为平台选型，5×3决策矩阵（技术5维×商业3维）已给出
- [ ] 如为企业落地，COE治理框架完整（组织/培训/评审/运维）
- [ ] 如为企业落地，实施路线图清晰（试点→推广→规模化→优化）
- [ ] 如为企业落地，关键风险清单已覆盖（技术债/平台锁定/性能/安全）
- [ ] 如为无代码创业，阶段漏斗清晰（想法→验证→MVP→增长）
- [ ] 如为无代码创业，核心工具栈推荐具体（Bubble/Webflow/Glide/Airtable/Vercel/Supabase/Stripe）
- [ ] 如为无代码创业，Lean Canvas和Mom Test方法已说明
- [ ] 如为无代码创业，规模化瓶颈分析已给出（何时迁移到Pro Code）
- [ ] 关键趋势点已标注（AI原生低代码/Pro Code+Low Code融合/信创替代加速/一人公司主流化/独立开发者出海）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 输出内容无知识性错误
- [ ] 已向用户交付最终答案

## Overall

- [ ] 工作流中的所有步骤已按顺序执行，没有跳过
- [ ] 每一步都已与其检查清单部分进行交叉验证
- [ ] 没有在任何检查清单部分通过前提前进入下一步
- [ ] `task/current_task.md` 已更新完成记录
- [ ] 所有 `[参考: ...]` 标注均指向存在的知识库文件

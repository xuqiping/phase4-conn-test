# Feature Map · 图片视频历史分页与预览缓存

> Phase 3 产物。功能-代码速查表（面向维护者）。无建表，无 Flyway 变更。
> 用户操作步骤见 [../user-ops/图片视频历史分页与预览缓存用户操作手册.md](../user-ops/图片视频历史分页与预览缓存用户操作手册.md)

## 一句话描述

视频/图片生成历史从一次 50 条全量拉取改为服务端分页；参考图/首尾帧/产出图获得悬浮放大+点击灯箱；文件预览获得会话内 LRU + 跨会话 ETag 304 两级缓存。

## 调用链路

```
历史列表：View(筛选/翻页) → buildHistoryQuery → listTasks → /api/media/tasks
         → MediaGenController.list → QueryService.page → Mapper.countHistory+selectHistory → PageResult
文件预览：View(chip/瓦片) → fetchFilePreview → 命中 filePreviewCache(零请求)
         └ miss → GET /api/files/{id} → FileController.get(load 鉴权→EXFIL 计数→ETag 头) → blob 入池
悬浮/灯箱：瓦片 mouseenter(300ms) → HoverPreviewImage(复用已加载 objectURL) / click → MediaLightbox
```

## 关键技术注解

### 1. count 与 list 同参数（防 total 漂移）
- **一句话**：总数与当页数据用同一组归一化后的过滤参数查两次。
- **大白话**：总数说 23 条、列表却只有 8 条，就是两者 where 条件不一致的「漂移」。`page()` 先归一（query strip/转义、kind 白名单、时间校验）再同时传给 count 和 list。
- **生活化**：图书馆报馆藏 23 本，书架上得真摆出对应那 10 本——两个数字必须出自同一张检索条件单。
- **踩坑**：@Select `<script>` 两方法 where 块必须逐字同步维护，改一处忘另一处就漂。

### 2. remote 分页 + 筛选重置（L1/L5）
- **一句话**：翻页由前端发参数、后端返回对应页；筛选变化或切条数都回落第 1 页。
- **大白话**：不重置页码，第 3 页筛选后可能直接空列表卡死；切大条数后第 5 页可能越界。
- **踩坑**：n-data-table 要加 `remote`，否则 Naive UI 自己切本地数据不走请求。

### 3. rangeType：day vs datetime
- **一句话**：图片页日期选择器选「整天」，视频页选「精确时刻」，尾部边界处理不同。
- **大白话**：图片页选 8 月 10 日，要含当天 23:59:59.999 全天（`to=尾日+24h-1ms`）；视频页选 10:30 就是 10:30 整（原样）。盲目统一会把某一页的筛选范围弄错。
- **生活化**：酒店「住一天」按晚算，会议室「约到 10:30」按点算——同为时间，口径不同。

### 4. 缓存 Blob 而非 objectURL
- **一句话**：LRU 里存原始 Blob，每次命中 `URL.createObjectURL` 新建。
- **大白话**：objectURL 一旦被某处 revoke 就成死链，缓存它等于埋雷；Blob 是原料，随时能重新发一个新的 URL，各方 revoke 各方的互不干扰。
- **生活化**：共享的是「面粉」，各家自己烙饼自己吃，不存在把别人嘴里的饼抢走。

### 5. LRU 逐出（满条数/满字节/单条超限不入池）
- **一句话**：Map 插入序即新旧序，头部最旧；超限从头逐出；一条就超过字节上限的巨物直接不收。
- **大白话**：不设巨物守卫，一条 200MB 视频能把整池清空还超限。
- **生活化**：仓库 80 个货位+128MB 容量，装满扔最久没人动的；一台超宽机床连门都进不来，直接拒收。
- **踩坑**：测试别真分配 128MB——工厂限额构造注入，单测用 10 字节上限跑真实逻辑。

### 6. ETag/304（Spring MVC 自动短路）
- **一句话**：ResponseEntity 设 `.eTag(""{fileId}-{size}"")`，请求带 If-None-Match 且命中时框架自动返 304 零 body，控制器无需手写比对。
- **大白话**：指纹没变服务器只说「没变」，浏览器用本地副本，省掉几 MB 重传。`no-cache`=每次都要回来验指纹（不是不缓存）；`private`=只许本人浏览器存，不进共享代理。
- **生活化**：门卫核对照片没变就挥手放行，不用重新领通行证。
- **踩坑**：鉴权和审计必须在缓存判定前——304 也算一次访问，归属校验不能被缓存头短路。此处 load→EXFIL 计数在控制器内、304 短路在框架写响应时，时序天然正确。

### 7. HoverPreviewImage 悬浮零请求
- **一句话**：previewSrc 用调用方已加载的 objectURL，悬浮放大不重新发请求。
- **踩坑**：300ms 防抖用 `setTimeout` + mouseleave 清理 + unmount 清理，漏一处就泄漏定时器；受控 popover（trigger=manual）才能和点击灯箱不叠层（L2）。

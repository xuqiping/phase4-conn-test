# 项目资产库 · 设计方案

> 定位：AI 影视创作的**项目级资产中枢**。画布是"生产车间"，资产库是"仓库与标准件库"——画布产出物入库沉淀，生成时从库中取用"一致性资产"注入，形成创作闭环。
> 依据：产品经理知识库 D-05.01（信息架构）、D-19.02（提示词工程化）、D-02（优先级）；业界基准 LTX Studio Elements / Katalist / DAM 最佳实践（BugSmash、echo3D、Orange Logic）。
> 关联：[24-无限画布创作页](../../../项目工程文档/项目功能介绍/速查表/24-无限画布创作页.md)（需求第 8 项"完整资产库+项目级授权"即本文档）

## 二、信息架构：双轴矩阵 + 标签自由层

### 2.1 核心模型

**项目（Project）是资产的唯一命名空间与授权边界。** 项目内用"双轴矩阵"组织资产：

```
轴A · 内容类型（5类，固定）        轴B · 叙事角色（受控词汇，可扩展）
┌─────────┐  ┌────┬────┬────┬────┬────┐
│ 提示词   │  │人物│道具│场景│风格│通用│
│ 剧本     │  │    │    │    │    │    │
│ 图片     │  │    │    │    │    │    │
│ 视频     │  │    │    │    │    │    │
│ 音频     │  │    │    │    │    │    │
└─────────┘  └────┴────┴────┴────┴────┘
```

- **轴A 固定 5 类**（用户需求定死），**轴B 默认 5 桶**：人物 / 道具 / 场景 / 风格 / 通用，项目级可自定义增删（受控词汇由 owner/editor 维护，防"标签腐烂"——DAM 实践：受控词汇 > 自由标签）。
- **一个资产可同时挂多个叙事角色**（如一张图既是"场景-客栈"又是"人物-老板娘出场场景"）——避免 D-05.01 警告的"强迫归类"坑：分类是多对多挂载，不是单父文件夹。
- **第三自由层：标签（tags）**，用于临时/探索性标记（"废案""待重绘""第三版备选"）。

> 为什么不是文件夹树：D-05.01——树状强迫单父归类，矩阵型支持多角度进入。创作场景"按人物找全部物料"和"按类型找全部图片"都是高频入口，双轴正好覆盖；标签兜底长尾。

### 2.2 导航与搜索（两条腿）

- **导航**：项目详情页 = 顶 Tab（内容类型）× 左侧栏（叙事角色）的矩阵筛选器，点击格子即得交集；默认进「全部」格。
- **搜索**：项目内全局搜索（名称/标签/提示词正文），中文分词+拼音模糊（D-05.01：中文必支持）；结果条显示 缩略图+名称+所属角色+版本状态。资产量 >500 后搜索为主入口。
- **每格显示计数徽章**（人物·图片 12），空状态给"从画布入库/本地上传"双引导。

## 三、资产元数据模型（三层 + 生成谱系）

沿用 DAM 三层元数据，并加 AI 创作特有的第四层：

| 层 | 字段 | 说明 |
|---|---|---|
| **描述层** | name / description / narrative_roles[] / tags[] | 用户可编辑 |
| **技术层** | media_type / file_id / 尺寸 / 时长 / 格式 / 大小 | 上传/入库时自动提取（图片读宽高，视频读时长分辨率——复用 javacv） |
| **权利层** | created_by / source（上传·画布入库·AI生成）/ 状态机状态 | 自动 |
| **生成谱系层（AI 特有）** | prompt / negative_prompt / model / seed / 参考图资产id[] / 来源画布节点 | AI 生成或画布入库时自动捕获——**这是"可复现性"的关键**，DAM 业界 2025 共识：生成参数必须随资产入库 |

**命名规范（taxonomy-in-filename）**：导出/下载文件名自动拼 `{项目}_{角色}_{名称}_v{版本}.{ext}`，资产脱离系统后仍可溯源（DAM 实践）。

## 四、五类资产的差异化设计

| 类型 | 存储形态 | 专属能力 |
|---|---|---|
| **提示词** | 结构化文本：用途（文生图/文生视频/扩写/分镜）+ 正文 + 负向词 + 变量槽位 `{{character}}` | **版本管理 + diff**（D-19.02 工程化）；一键"发送到画布文本/视频节点"；变量槽位可与人物资产绑定（注入人物标准描述） |
| **剧本** | 富文本 + **分场结构**（场号/场景/人物/对白，JSONB） | AI 拆分场（复用 LlmGateway + parseScenes 容错）；**分场 → 画布故事板段**联动（分场即镜头清单）；场里出现的人物/场景自动提示"是否建档为资产"（LTX Elements 首次出现即建档的最佳实践） |
| **图片** | file_id + 缩略图 | 多角度图集（人物三视图）；设为主参考图；发到画布图片节点 |
| **视频** | file_id + 时长/分辨率 | 复用抽帧/截取工具；发到画布视频节点/故事板 |
| **音频** | file_id + 时长 | 波形预览（后续）；配乐/配音/音效子标签 |

## 五、一致性资产包（Consistency Pack）—— 差异化杀手锏

对标 LTX Elements / Katalist 并超越：**人物/道具/场景三类资产，其"资产详情"聚合为一个一致性包**：

```
人物「老板娘」
├─ 主参考图（cast 定装照，1张，换它=换演员）
├─ 多角度图集（正/侧/背/表情，N张）
├─ 标准描述片段（"30岁女性，旗袍，丹凤眼…"，供提示词变量槽注入）
├─ 生成参数基线（model/seed/风格词，可空）
└─ 使用记录（被哪些画布节点/分镜引用 —— 双向追溯）
```

**生成时注入**：画布图片/视频节点选择"引用资产"→ 主参考图作首帧/img2img 输入 + 标准描述片段拼入 prompt——一次配置，全片一致。这就是 AI 影视"一致性"工业解法的产品化。

## 六、版本与生命周期状态机

**版本**：自动版本（编辑/换图即 v+1，带时间戳与操作人，DAM 实践：无人工干预）；变体归组——小幅调整（裁切/调色）作为同资产的 version，不另起资产（collections for variants）。

**状态机**（轻量四态，不做重审批流）：

```
草稿 → 已定稿 →（被引用锁定）→ 归档
 ↑_____回退_____┘
```

- **已定稿（Locked）的资产被画布引用时，引用的是版本快照**——后续资产迭代到 v3，已生成镜头仍指向 v2，避免"设定改了、成片崩了"（DAM：版本隔离防冲突）。
- 归档 = 软删语义，不进默认列表但可检索。

## 七、授权模型：项目级三角色 + 平台权限双层

### 7.1 双层结构

```
第一层 · 平台功能权限（现有体系）：asset:write（@RequirePermission，菜单/API 兜底，同 canvas:write 范式）
第二层 · 项目数据权限（新增）：asset_project_members 表
```

### 7.2 项目角色矩阵

| 能力 | 查看者 viewer | 编辑者 editor | 所有者 owner |
|---|---|---|---|
| 浏览/搜索/下载资产 | ✅ | ✅ | ✅ |
| 引用资产到画布 | ✅（只读引用） | ✅ | ✅ |
| 上传/编辑/入库/删资产 | ❌ | ✅ | ✅ |
| 版本定稿/归档 | ❌ | ✅ | ✅ |
| 维护叙事角色受控词汇 | ❌ | ✅ | ✅ |
| 邀请/移除成员、改角色 | ❌ | ❌ | ✅ |
| 转让所有者 / 删项目 | ❌ | ❌ | ✅ |

- owner 唯一；admin 旁路全量（同 CanvasService ownership 范式）。
- **被授权用户同样需要 `asset:write` 平台权限**——双层都过才可见项目（与平台现有"菜单隐藏+页内403+API403"三重兜底一致）。
- **离开授权即失访**：member 移除后项目从其列表消失；其在画布中已引用的资产快照**不受影响**（引用的是版本快照 file_id，属引用方画布数据）。
- 后续扩展位：链接分享（带过期时间的只读链接）、按资产单独授权——表结构预留 `share_links` 扩展空间，MVP 不做。

## 八、与无限画布的双向打通（闭环核心）

```
画布  ──产出物一键入库──▶  资产库          （图片/视频/音频/文本产物 → 选项目+角色落格）
画布  ◀──引用资产注入──  资产库          （节点选参考图/提示词/剧本分场）
```

| 方向 | 设计 |
|---|---|
| **画布 → 库**（五类节点全覆盖，映射与规则见下） | 节点右键「存入资产库」→ 弹窗选项目/叙事角色/命名 → 自动捕获生成谱系（prompt/seed/上游节点）。解决画布产出物散落在 stored_files 无组织的问题 |

**节点入库映射**（任意节点都可入库，用户选项目与落格位置）：

| 画布节点 | 入为资产 | 说明 |
|---|---|---|
| 文本节点 | 提示词资产 | 正文 + 用途标记（扩写/文生图/文生视频） |
| 脚本节点 | 剧本资产 | 已拆分场的，分场结构一并入库 |
| 图片节点 | 图片资产 | 上传/衍生/焦点编辑/抽帧图同一路径 |
| 视频节点 | 视频资产 | 生成视频/截片段/故事板成片均可 |
| 音频节点 | 音频资产 | — |

**入库规则**：
- 前置条件：节点须有产出物（file_id 或正文），空节点拦截提示；未生成的视频节点可降级"仅存提示词资产"
- 权限：弹窗项目列表只出现用户为 owner/editor 的项目（viewer 不可入库），平台层过 `asset:write`
- 自动捕获：prompt/seed/model/上游节点写入 `gen_meta`；落一条 `asset_bindings(bind_type=PRODUCED)` 供双向追溯；source=CANVAS；**复用原 file_id 不复制文件**
- 重复入库：该节点已有 PRODUCED 绑定时，默认建议「存为该资产的新版本」而非新建（变体归组）
| **库 → 画布**（五类全覆盖，按类型引入矩阵见下） | 图片/视频/音频节点属性面板加「从资产库选择」（替代裸上传）；文本/脚本节点加「插入提示词资产」；视频节点图生视频可直接选人物主参考图（虚拟上游，无需在画布摆图片节点） |

**按类型引入矩阵**（任何资产都可引入画布）：

| 资产类型 | 引入方式 |
|---|---|
| 提示词 | 文本/脚本节点插入正文；变量槽位 `{{character}}` 绑定人物资产自动注入标准描述 |
| 剧本 | 脚本节点载入；（P2）分场一键生成故事板段骨架 |
| 图片 | 图片节点载入；或视频节点「从库选参考图」作首帧/img2img 输入 |
| 视频 | 视频节点载入，可继续抽帧/截取/进故事板 |
| 音频 | 音频节点载入 |

**引用语义（有意设计，非缺陷）**：
- 引入的是**版本快照**（asset_id + version + file_id），不是活链接——资产迭代到新版本，画布节点不自动变，防"设定改了成片崩了"；节点上提供「更新到最新版」手动操作
- viewer（只读成员）**也能引用**资产到自己的画布——引用产物归引用方，但不能改库内资产
- 资产归档/授权移除不影响画布中已引用的快照（file_id 语义属引用方）
| **剧本 → 故事板** | 剧本资产分场一键生成故事板段落骨架（场号→段 label） |
| **双向追溯** | 资产详情页"使用记录"列出引用它的画布/节点；画布节点徽标显示"来自资产·老板娘 v2" |

## 九、后端设计（`asset/` 包，零回归原则同 canvas）

包：`com.superprogrammer.asset`（controller/service/entity/mapper/dto），独立于既有包，复用只读。

### 9.1 数据表（Flyway V56~V59）

```sql
-- V56 项目
asset_projects(id identity PK, name, description, owner_id, cover_file_id,
               narrative_roles JSONB  -- 项目自定义角色桶，默认[人物,道具,场景,风格,通用]
               + BaseEntity 五字段 + deleted)

-- V57 资产 + 版本
assets(id identity PK, project_id FK, media_type VARCHAR(16),  -- PROMPT/SCRIPT/IMAGE/VIDEO/AUDIO
       name, description, tags JSONB, status VARCHAR(16),      -- DRAFT/LOCKED/ARCHIVED
       content JSONB,            -- 提示词正文/剧本分场结构（非文件类）
       gen_meta JSONB,           -- 生成谱系：prompt/model/seed/参考资产[]/来源画布节点
       current_version INT, ...)

asset_versions(id identity PK, asset_id FK, version INT, file_id,  -- 文件类指 stored_files
       content JSONB, change_note, created_by/at)                  -- 版本快照，引用即锁版本

asset_role_links(asset_id FK, role_key)   -- 资产↔叙事角色 多对多

-- V58 授权
asset_project_members(id identity PK, project_id FK, user_id, role VARCHAR(8),  -- VIEWER/EDITOR
       granted_by, UNIQUE(project_id,user_id))   -- owner 不落表，owner_id 即所有者

-- V59 资产↔画布绑定（双向追溯）
asset_bindings(id identity PK, asset_id FK, asset_version INT, canvas_id, node_id, bind_type)  -- REFERENCE/PRODUCED
```

- 文件实体复用 `stored_files`，新 `SOURCE_ASSET` 常量（同 SOURCE_CANVAS 范式）。
- 索引：`(project_id, media_type, updated_at) WHERE deleted=0` 部分索引；members 表 `(user_id)` 供"共享给我的"列表。

### 9.2 API（前缀 `/api/assets`，全端点 `@RequirePermission("asset:write")`）

```
项目：  POST/GET /projects · GET/PUT/DELETE /projects/{id}
成员：  GET/POST /projects/{id}/members · PUT/DELETE /members/{userId}
资产：  POST /projects/{id}/assets · GET /projects/{id}/assets?type=&role=&q=&status=
        GET/PUT/DELETE /assets/{id} · POST /assets/{id}/archive · /lock
版本：  GET /assets/{id}/versions · POST /assets/{id}/versions（换图/改版）
上传：  POST /projects/{id}/upload（落 SOURCE_ASSET）
打通：  POST /assets/{id}/send-to-canvas · POST /canvas-import（画布产出入库，canvas 包调用）
绑定：  GET /assets/{id}/usages（画布引用列表）
```

**归属咽喉点**：`AssetService.loadAccessible(projectId, user)` —— owner 或 member 或 admin 三判，写侧端点复用（同 CanvasService.loadOwned 范式）。

### 9.3 复用（只读）

`FileStorageService.storeStream(SOURCE_ASSET)` · `LlmGateway.chat`（剧本分场/AI 打标）· `VideoFrameService`（库内视频抽帧）· 现有用户/角色体系（成员选择器数据源）。

## 十一、分期路线（MoSCoW + RICE 简评）

| 期 | 范围 | 理由 |
|---|---|---|
| **P0 · MVP** | 项目 CRUD + 五类资产 CRUD（上传/文本类）+ 双轴分类 + 搜索 + 成员授权三角色 + 平台权限接入 | 用户需求全要素的最小闭环：项目/五类/人物道具场景/授权一个不能少 |
| **P1 · 闭环** | 版本+状态机 + 画布双向打通（入库/引用/绑定追溯）+ 一致性包 | 价值放大器：打通后资产库才从"网盘"变"生产标准件库"；依赖画布已就绪（已就绪✅） |
| **P2 · 智能** | AI 自动打标（多模态）+ 剧本分场→故事板联动 + 提示词 diff/AB + 以图搜图（embedding）+ 链接分享 | 效率与体验增强，RICE 中 R 高但 E 大，放后期 |

## 十二、无限画布优化建议（评审结论）

画布本身已扎实（35 测试绿、拓扑重跑、故事板），以下是结合资产库设计发现的优化点，按价值排序：

1. **产出物闭环缺失（最高优先）**：画布产出物（抽帧图/截片段/成片/上传素材）现在只落 `stored_files`，删画布后"保留但无处可寻"。P1 打通「一键入库」后，画布成为资产的生产端——这是画布当前最大的产品缺口。
2. **参考图只能"上游连节点"**：图生视频必须画布上有图片节点。资产库就绪后应支持「从库选参考图」直连（虚拟上游），减少画布节点噪音。
3. **快照 ≤5MB 限制的长期解法**：snapshot JSONB 内嵌提示词正文是体积大头。提示词/剧本资产化后，节点可存 `assetRef` 而非全文，快照瘦身 + 单一事实源（改资产即改所有引用它的节点）。
4. **打组模板（C 系列未做项）的正确归宿是资产库**：节点组模板本质是"可复用创作资产"，入库后天然获得版本+授权能力，比在 canvas 包内单建模板表更顺。
5. **故事板段与剧本分场脱钩**：现在故事板只是视频段列表。剧本资产落地后，段可绑定分场（场号/对白随段走），为后续"成片带字幕/场记单导出"铺路。
6. **小项**：节点「上游缺失标红」策略可复用到资产引用（资产归档≠删除，引用快照不受影响——保持现有"不级联删"哲学，已一致✅）；抽帧产物命名（"抽帧（AT 3s)"）建议入库时沿用 `{角色}_{名称}_v{n}` 规范。

## 十三、画布节点 @引用机制（新增设计，补数据流断点）

**背景**：现网画布节点间唯一的内容引用是「图片→视频参考图」（C8 连线自动取上游图 fileId，[CanvasView.resolveUpstreamImageFileId](../../../../frontend/src/views/CanvasView.vue)）；文本/脚本节点运行只发自己的 prompt/synopsis，上游产出不外流（CanvasNodeRunnerService.runText/runScript），跨节点复用靠手动复制粘贴。

**设计**：文本/脚本/视频节点的 prompt 输入框支持 `@` 唤起引用选择器，插入占位符 `@{{node:xxx}}` / `@{{asset:xxx}}`；**前端插值层**在运行前把占位符替换为被引用方产出再提交。

**@可选范围（硬约束）**：仅**当前节点经连线可达的祖先链**——直接上游节点 + 上游的上游（传递闭包，反向 BFS 沿 edges 求祖先集）。无连线可达的节点不出现在选择器中。资产库资产不受此限（非节点，无连线概念）。

**节点命名唯一性（硬约束）**：同一画布内节点 label 不允许重复——新建/粘贴自动加序号（图片 → 图片 2），重命名查重拦截。占位符本体存 **node id**（重命名不断链），label 唯一性服务于 @选择器与手输场景的人脑消歧。

| @对象 | 注入内容 |
|---|---|
| 文本节点 | outputText |
| 脚本节点 | scenes 分镜序列化文本 |
| 图片/视频/音频节点 | prompt + 产物元信息（文件本体走参考图通道，不做文本插值） |
| 提示词资产 | 资产正文（含变量槽位） |
| 人物/场景资产 | 一致性包「标准描述片段」 |

**关键决策**：
1. **@沿既有连线，拓扑天然成立**：祖先链约束 ⇒ 每条 @引用必对应一条上游路径 ⇒ Kahn 拓扑序已保证被引用方先跑，**无需隐式边**；环检测仍由现有重跑前检查覆盖（连线成环时祖先集本身构造不出，选择器为空并提示解环）
2. **前端解析、后端零改动**：CanvasNodeRunnerService 保持无状态（只收最终 prompt），插值发生在前端 onRunNode 之前——对现有 canvas 包零回归
3. **失效语义复用「上游缺失」**：被 @节点未跑/被删 → 标红提示，不级联；**连线被删后原 @引用降级为"断链引用"**（灰显 chip，运行前提示重连或移除）
4. **与提示词变量槽位同一引擎**：`@` 引用"祖先节点产出/资产"，`{{slot}}` 引用"资产属性"，共用一套插值解析器（前端 utils/interpolate.ts）

## 十四、风险与边界

| 风险 | 缓解 |
|---|---|
| 双轴分类被用成"两个都要选"的负担 | 叙事角色默认「通用」，零选择成本；受控词汇由 owner 维护 |
| 授权后资产被 viewer 截图外泄 | MVP 不做 DRM；水印/禁下载放 P2 后评估（B 端信任场景优先效率） |
| 版本爆炸（每次微改都 v+1） | 文本类节流合并（同 canvas 800ms 落库哲学）；变体归组规则 |
| 成员移除后其画布引用失效争议 | 引用=版本快照 file_id，语义上属于引用方，不受影响（§7.2 已定） |
| 与 canvas 包的循环依赖 | 打通走 `asset` 调 `canvas` 只读 DTO 或事件式解耦，canvas 不 import asset（保持 canvas 零回归） |

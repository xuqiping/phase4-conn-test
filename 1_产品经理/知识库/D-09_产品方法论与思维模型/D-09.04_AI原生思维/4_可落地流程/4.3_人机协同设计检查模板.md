# 4.3 人机协同设计检查模板

## 使用场景

在做AI原生产品设计时，用本模板逐项检查人机协同设计是否完整。适用于：新AI产品从0-1设计、现有产品AI化改造、AI功能需求评审。

---

## 检查清单

### A. 三层分区完整性

| # | 检查项 | 是否通过 | 备注 |
|---|---|---|---|
| A1 | 是否为每个AI介入的环节明确了三层分区（自主/确认/审批）？ | ⬜ | |
| A2 | AI自主域是否标注了置信度阈值？（低于阈值则升级到确认域） | ⬜ | |
| A3 | 确认域是否设计了信息密度方案？（AI给人类呈现什么信息做判断） | ⬜ | |
| A4 | 审批域是否标注了合规/法律红线？（哪些必须人类决策） | ⬜ | |
| A5 | 三层之间是否有明确的升级/降级流转规则？ | ⬜ | |

### B. HITL四要素

| # | 检查项 | 是否通过 | 备注 |
|---|---|---|---|
| B1 | **触发条件**：是否定义了系统自动流转 vs 路由给人类的具体条件？ | ⬜ | 例：置信度<0.8 → 路由人类 |
| B2 | **信息密度**：人类接收的信息是否经过AI摘要+高亮+推荐选项处理？ | ⬜ | 不是甩锅原始数据 |

| B4 | **性能监控**：是否设置了兜底率趋势和人类处理耗时监控？ | ⬜ | 兜底率上升=AI能力衰退预警 |

## 评分标准

- 全部通过：✅ 可进入灰度发布
- A/B类有未通过：⚠️ 需补充人机分区和HITL设计后再评审
- C/D类有未通过：⚠️ 需补充驾驭工程和Evals后再开发
- E类有未通过：🔄 可在灰度阶段迭代优化

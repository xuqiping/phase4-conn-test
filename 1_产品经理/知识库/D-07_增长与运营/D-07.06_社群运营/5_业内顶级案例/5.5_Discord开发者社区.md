## 社区架构设计——联邦制治理

### 服务器(Server)→频道(Channel)→话题(Thread)三层架构

```
Server（服务器/社区）
  ├── #announcements（公告频道）
  ├── #general（综合讨论）
  ├── #help（求助区）
  ├── #showcase（展示区）
  ├── Role: Admin（管理员）
  ├── Role: Moderator（版主）
  ├── Role: Contributor（贡献者）
  └── Role: Member（普通成员）
```

### 权限与治理系统

| 治理层级 | 能力 | 典型配置 |
|---|---|---|
| 服务器Owner | 所有权限+设置 | 创始人/核心团队 |
| Admin | 管理成员+频道+规则 | 运营团队 |
| Moderator | 删帖/禁言/移动内容 | 社区版主 |
| Role-based权限 | 按角色分配频道访问权 | 不同层级不同权限 |

## 关键策略：社区优先原则

### 1. Bot生态——让社区自建工具

- Discord开放Bot API → 社区开发者自建管理/互动/分析Bot
- 代表Bot：MEE6(管理)/Dyno(自动化)/Midjourney(AI绘图，本身就是Discord Bot)[来源 | 置信度:高 | 2025]
- Bot生态让Discord变成**可编程社区平台**

### 2. 频道架构设计最佳实践

| 频道类型 | 目的 | 典型命名 |
|---|---|---|
| 信息频道 | 官方公告/规则/FAQ | #announcements, #rules |
| 讨论频道 | 主讨论区 | #general, #help |
| 专题频道 | 特定主题深度讨论 | #api, #design, #bugs |
| 社交频道 | 非正式聊天 | #off-topic, #memes |
| 语音频道 | 实时语音/屏幕共享 | 🔊Lounge, 🔊Focus Room |

### 3. Midjourney案例——Bot即产品

Midjourney以Discord Bot起步，用户在Discord内用/imagine命令生成图片：
- 无需独立App→零下载门槛
- 社区展示→天然的内容裂变
- 其他用户可见创作→激发灵感+社交驱动
- Discord频道即Gallery→内容沉淀 [来源 | 置信度:高 | 2025]

## PM启示

1. **Bot生态=社区可编程性**：开放API让社区自建工具，PM不需要做所有功能

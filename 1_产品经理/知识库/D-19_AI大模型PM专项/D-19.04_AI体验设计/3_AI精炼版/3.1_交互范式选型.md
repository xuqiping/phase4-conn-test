# 3.1 交互范式选型

## 一、六大AI交互范式

AI产品的交互范式决定了用户体验底色。2026年已从"无脑塞对话框"演进为"按任务复杂度×可控度×响应时长选范式"。

| 范式 | 核心机制 | 适用任务 | 典例 | 优势 | 局限 |
|---|---|---|---|---|---|
| **对话式Chatbot** | 多轮自然语言对话 | 问答/开放创作/咨询 | ChatGPT/豆包/Claude | 灵活开放/学习成本低 | 长任务难管理/历史难追溯 |
| **补全式Copilot** | 用户主导,AI实时补全建议 | 写作/编程/表格/设计 | GitHub Copilot/Cursor/Notion AI | 用户可控/AI辅助/低延迟 | 需用户懂领域/AI权重低 |
| **自主式Agent** | AI自主规划+执行多步任务 | 复杂任务/自动化流程 | Manus/Devin/AutoGPT/星辰智能体 | 全自动/释放人力 | 不确定性高/需HITL护栏 |
| **Canvas画布式** | 大画布上AI实时编辑/迭代 | 长文档/代码/设计协作 | Notion AI Canvas/Cursor Composer/Figma AI | 可视化/可对比版本/可控 | 画布设计复杂/移动端难 |
| **生成式UI(GenUI)** | AI按意图动态生成界面组件 | 数据查询/操作流转/可视化 | OpenTiny GenUISDK/Vercel v0/Google GenUI | 突破文字壁垒/一站式交互 | 性能代价/认知负荷/稳定性 |
| **零UI/静默AI** | AI后台自动运行,关键节点通知 | 后台自动化/订阅/日程 | iOS智能日程/Gmail智能回复/智能清理 | 零打扰/低侵入 | 信任门槛高/出错难纠正 |

> 来源：[IXDC2026/什么值得买/OpenTiny | 🔍高 | 2026-01~06]

## 二、范式选型矩阵（任务复杂度 × 可控度 × 响应时长）

PM选择交互范式的三维度决策：

### 2.1 按任务复杂度选

| 任务复杂度 | 推荐范式 | 典例 |
|---|---|---|
| 单轮简单问答（"今天天气？"）| 对话式 | 通用Bot |
| 多轮创作（写一篇报告）| 对话式 + Canvas（生成后编辑）| Notion AI |
| 实时补全（边写边建议）| Copilot | GitHub Copilot |
| 长流程自主任务（订机票+订酒店+排日程）| Agent + HITL | Manus |
| 结构化操作（查数据/填表/审批）| GenUI | v0/OpenTiny GenUI |
| 后台自动化（订阅管理/清理垃圾）| 零UI | iOS智能建议 |

### 2.2 按可控度选

- **用户主导型任务**（用户清楚要什么）→ Copilot/Canvas（用户可控，AI辅助）
- **AI主导型任务**（任务复杂需AI规划）→ Agent（AI自主，HITL护栏）
- **混合型任务**（部分用户主导部分AI主导）→ Copilot为底+Canvas为面+Agent为钩

### 2.3 按响应时长选

| 响应时长 | 推荐策略 |
|---|---|
| <500ms | 实时补全（Copilot Tab） |
| 1-3s | 流式呈现（ChatGPT打字机） |
| 3-10s | 阶段化提示 + 流式 + 取消 |
| >10s | 异步任务 + 进度通知 + 后台运行 |

## 三、LUI + GUI 融合（2026主流方向）

纯对话式（LUI Language UI）已暴露"用户说不清楚"的瓶颈：设计师反复改Prompt仍难贴近画面、数据分析师难以用文字精确指代图表局部、程序员难以仅凭文字让AI理解特定代码结构 [来源:知乎IAI模型 | 🔍高 | 2026-04]。2026主流是LUI+GUI融合：

- **LUI优势**：灵活、开放、自然
- **GUI优势**：精准、可见、可操作
- **融合模式**：自然语言给意图 + GUI给精准控制 + GenUI给可视化界面
- **典型产品**：Google GenUI（用户提问→AI返回定制化软件界面）、Vercel v0（描述需求→生成可交互UI代码）、OpenTiny GenUISDK（前后端一体化GenUI框架）

## 四、生成式UI（GenUI）深入

| 维度 | 说明 |
|---|---|
| **定义** | AI在对话过程中动态生成并实时渲染UI界面，让AI不再局限于纯文字输出，而是能"画"出表单、按钮、图表、卡片等组件 [来源:OpenTiny | 🔍高 | 2026-03] |
| **三大突破** | 1. 界面重构文字（用UI替代纯文本输出）2. 打破两步交互（不再"先聊天→再操作"，融合为一步）3. 让AI更懂业务（组件库承载业务逻辑） |
| **典型框架** | OpenTiny GenUISDK（国产开源，前后端一体化）/ Vercel v0 / Google GenUI Research / MCP+前端组件协议 |
| **适用场景** | 数据查询/操作流转/审批表单/可视化报表/商品推荐卡片 |
| **代价** | 性能消耗大（多模态生成）/ 认知负荷重（动态界面学习成本）/ 稳定性挑战（生成UI可能不规范）/ 测试复杂 |
| **不该用GenUI** | 简单文本就能解决 / 输出高度结构化且稳定 / 性能敏感场景 |

## 五、多模态输入输出设计

### 5.1 多模态输入融合

| 输入方式 | 适用场景 | 设计要点 |
|---|---|---|
| 语音 | 车载/家居/无障碍/实时对话 | 实时转写可见/打断能力/口音鲁棒性 |
| 图像 | 视觉问答/截图分析/OCR | 上传便捷/局部选区/多图对比 |
| 手势 | AR/VR/空间计算 | 手势识别容错/反馈即时 |
| 情感感知 | 客服/陪伴/教育 | 隐私边界/不要"假装共情" |
| 文件 | 文档分析/数据处理 | 拖拽支持/批量上传/格式兼容 |

### 5.2 多模态输出融合

| 输出方式 | 适用场景 | 设计要点 |
|---|---|---|
| 文本流式 | 通用问答/创作 | 打字机效果/Markdown渲染 |
| 图像生成 | 设计/插画/营销图 | 多图对比/参数可调/版权标注 |
| 视频生成 | 营销/教育/娱乐 | 进度反馈/片段预览/编辑能力 |
| 语音合成 | 朗读/陪伴/无障碍 | 自然度/情感/可调速 |
| 可视化图表 | 数据分析/报表 | 可交互/可下钻/可导出 |

### 5.3 GPT-4o级实时语音对话设计要点

- 全双工对话（说与听同时进行，可打断）
- 情感识别与共情（声调/语速/暂停）
- 多模态上下文（语音同时看到的屏幕内容也进入上下文）
- 隐私边界（不录制非必要场景）

## 六、2026前沿趋势

1. **零UI/静默AI兴起**——AI Agent在后台自动完成任务，用户只在关键节点被通知；交互从"主动发起"转向"被动接收"[来源:什么值得买 | 🔍高 | 2026-01]
2. **液态玻璃美学**——动态光影和物理质感营造深度感，成为2026主流视觉语言（Apple Vision Pro推动）
3. **空间化叙事**——滚动驱动故事进程，创造沉浸式浏览体验
4. **设计师角色转移**——从"画界面"转向"定义规则"，AI按实时意图动态创建UI，设计师重心转向规则系统/组件约束/质量边界 [来源:优设网 | 🔍高 | 2026-02]
5. **AI工作流6大设计模式**——_ROUTER/AGGREGATOR/PREDICTOR/TRANSFORMER/ROUTER+PREDICTOR/SUPERVISOR模式，从问答式AI开发进化到工程化AI工作流 [来源:腾讯云 | 🔍高 | 2026-02]
6. **企业Super Agent上下文工程**——六层上下文分裂与合并/可信回退/压缩引擎/知识飞轮/统一VFS，企业级Agent体验从单点交互转向长流程连续体验 [来源:腾讯云 | 🔍高 | 2026-07]

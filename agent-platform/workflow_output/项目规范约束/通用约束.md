# 通用约束 · 跨所有模块

> 所有模块共用的编码/命名/响应/异常/安全规范。模块特有约束另建 `<模块>约束.md` 并在 AGENTS.md 索引。

## 后端
- 包名：`com.superprogrammer`，模块包：auth/agent/workflow/engine/execution/runtime/chat/knowledge/llm/project/file/system/common。
- 分层：controller → service → mapper（MyBatis-Plus BaseMapper）；跨模块用 Facade 接口 + DTO，**禁止循环依赖**。
- 响应：统一 `R<T>`（`{code,msg,data}`），分页 `PageResult<T>`。
- 异常：业务异常抛 `BusinessException(ErrorCode)`，全局异常处理器转 `R`；错误信息不泄漏内部实现。
- 实体继承 `BaseEntity`（id/created_by/created_at/updated_by/updated_at/version/deleted）。
- 权限：方法级 `@RequirePermission("resource:action")`，切面 `RequirePermissionAspect` 拦截。
- API 前缀 `/api/`；认证 Header `Authorization: Bearer {token}`。
- **不可逆操作禁暴露端点 + 反射断言守契约**（计划12B 沉淀）：误并/误拆类操作不可逆（如标签归一误并致已生成 summary 的 tag_id 漂移），控制器**刻意不提供** merge/split/re-extract 端点，仅留最小补救面（owner 改 label/补 aliases，id 不变）；用反射单测断言控制器方法名/VO 字段集**不含**禁用语义，API 演进时有人不慎加上必红（防锈蚀）。
- **LLM 判官「安全落空」默认值**（计划12B 沉淀）：LLM 批判同义/分类时，失败/解析异常/空集 → 安全默认（判否、走新建、返 null），**绝不乐观误判**——误并/误采纳不可逆，宁可保守多做一次也不并错。范式见 `MemoryTagResolver.judgeSynonym`。
- **LLM prompt 动态数值注入用命名 token**（M3 沉淀）：prompt 模板含既有 `%s` 字符串占位符时，需再注入**可变数值**（计数/阈值）用命名 token `{NAME}` + helper `replace`，**不用 `%d`**——`String.format` 的 `%d`/`%s` 顺序强耦合，数值增删易错位。范式见 `MemoryConflictJudge.applyEntitiesConfig`。

## 数据库（PostgreSQL 16 + pgvector）
- 主键 `GENERATED ALWAYS AS IDENTITY`。
- 逻辑删除 `deleted` + `@TableLogic`；乐观锁 `version`；自动填充审计字段。
- 向量 `halfvec(2048)` + HNSW `halfvec_cosine_ops`，不用 `vector(2048)`。
- 配置类灵活字段用 JSONB。建表走 Flyway 新版本脚本，旧脚本不可改。
- **已执行 Flyway 迁移不可编辑**（Flyway checksum 锁，改了启动 `FlywayValidate` 报错）——发现已上线迁移有遗漏/bug，**加新版本补丁迁移**（如 V47 漏改 → V48 补），不回头改旧脚本。版本号是软标签，plan 里别硬绑数字（顺延即可）。
- **MyBatis mapper XML 放 `src/main/resources/com/superprogrammer/<模块>/mapper/xml/`**（镜像包路径），**不放 `src/main/java` 下**——Maven 默认不打包 src/main/java 的非 java 文件 → 运行期 `BindingException: Invalid bound statement (not found)`。配 `mapper-locations: classpath*:/com/superprogrammer/**/mapper/xml/*.xml` 即命中。
- **PG 特型列在 MyBatis XML 的算子/类型坑**（V33 + 计划12A 实跑教训）：① 数组重叠算子 `&&` 须转义 `&amp;&amp;`；② halfvec 距离 `<=>` 须转义 `&lt;=&gt;`（裸 `<` 致 mapper XML 解析崩）；③ BIGINT[] 更新走 XML 显式 `#{col,typeHandler=...LongArrayTypeHandler}` 或 Mapper 注解 cast，**勿用 LambdaUpdateWrapper.set**（不读 `@TableField` typeHandler → streaming 静默 fallback 丢值）。
- **halfvec 距离阈值过滤也须转义 `<=`**（计划12B 实跑教训）：`WHERE (anchor_embedding &lt;=&gt; #{q}::halfvec) &lt;= #{threshold}`——`<=>` 和 `<=` 两个都得 XML 转义，裸任一 `<` 致启动期 mapper 解析崩。
- **XML `<insert>` 漏 `useGeneratedKeys` → 主键不回填返 null**（计划12B 实跑教训）：自定义 XML insert（带 halfvec/数组等非实体列走 `@Param("m")`）须显式 `<insert id=".." useGeneratedKeys="true" keyProperty="m.id">`，否则实体 `m.getId()` 永远 null（DB 行已插但拿不到 id）；纯 BaseMapper.insert 无此问题（MyBatis-Plus 自动回填）。
- **PG 拒 varchar→timestamptz 隐式转换**（计划12E IT 实跑教训）：`JdbcTemplate` 给 `TIMESTAMP WITH TIME ZONE` 列传字符串字面量，须显式 `?::timestamptz` cast（PG 不做 varchar→timestamptz 隐式转换，报「字段类型为 timestamp with time zone 但表达式类型为 character varying」）；纯 TIMESTAMP（无时区）同理加 `::timestamp`。
- **flat provenance 数组包含查询 `@>` 无需 XML 转义**（计划12E 沉淀）：查 `source_turn_ids @> [T]` 受影响行，`@>` 包含算子在 mapper XML 裸写不崩（异于重叠算子 `&&`/距离 `<=>` 须转义 `&amp;&amp;`/`&lt;=&gt;`）。
- **@Transactional 自调绕代理 → 抽独立 TxService bean**（计划12E 沉淀，同 IndexJobTxService 先例）：含 LLM 调用的方法**不能整体 @Transactional**（秒级阻塞+计费持 DB 连接）；需事务化的写库段（如 summary+coverage+冲突原子）抽到独立 `*TxService` bean，主 service 跨 bean 调用经 Spring 代理生效；同类自调 `this.txMethod()` 绕代理 @Transactional 失效。
- **纯 Mockito 单测遇 `LambdaUpdateWrapper.set()` 须先填 MP lambda 缓存**（计划12 F-4b 前置沉淀，承 IndexJobTxServiceTest 范式）：`set(SFunction,...)` 在**构造时**即解析列名（异于 `LambdaQueryWrapper.eq` 延迟到拼 SQL），无 Spring 上下文时 TableInfo 未初始化 → `MybatisPlusException: can not find lambda cache`；`@BeforeAll` 用 `TableInfoHelper.initTableInfo(new MapperBuilderAssistant(new MybatisConfiguration(), ""), Entity.class)` 填充。**修复III E/F 补注**：`LambdaQueryWrapper.eq(SFunction,...)` 在 MP 3.5.5 同样会在 wrapper 被 mapper mock 捕获前解析（AuthServiceTest/AssetMediaBridgeServiceTest 实测）——凡 service 用 lambda wrapper 的纯 Mockito 测试统一 `@BeforeAll` 注册，别赌哪条 API 延迟解析。
- **读软删行（取已删项目名等）须走 XML 自定义 SQL**（计划12 F-4b 前置沉淀）：`@TableLogic` 只给 MP wrapper/`selectById` 自动拼 `deleted=0`；业务上要读「已软删」的行（如 restore 折叠板显示已删项目名），在 mapper XML 裸写 SQL（无 deleted 过滤）即可绕过，勿为此关全局逻辑删除。
- **软删表的 `ON DELETE CASCADE` 永远不触发，级联清理须 app 层补**（计划12 写侧 hook 沉淀）：`@TableLogic` 软删 = `UPDATE deleted=1`，PG 外键 `ON DELETE CASCADE` 只在真 DELETE 时触发 → 建表注释里「项目删除 CASCADE 自动清」全是一厢情愿（memory_summaries/members/acl/settings 等行全残留）。软删主实体的级联清理必须挂在 service 删除流程里显式做（范式：`MemoryLifecycleHookService.onProjectDeleted` 同事务逐表清）。
- **`updateById` 默认 NOT_NULL 策略丢 null：显式置 null 须走 `LambdaUpdateWrapper.set(col, null)`**（计划12 写侧 hook IT 实跑教训）：`entity.setX(null); updateById(entity)` 生成的 SET 不含该列（静默不生效）；要「清空某列」（如重加入清 departed_at）必须用 UpdateWrapper 显式 `.set(Entity::getX, null)`。
- **唯一约束含软删行：re-add 须「复活」而非 insert**（计划12 写侧 hook IT 实跑教训）：uk 约束（如 `uk_project_members_project_user`）不带 `WHERE deleted=0` 时软删行仍占位，remove 后再 add 直接 insert 撞 uk；范式 = mapper XML `findAnyState`（绕 @TableLogic）→ deleted=1 则 `setDeleted(0)`+`updateById` 复活，否则才 insert。建部分唯一索引（`CREATE UNIQUE INDEX ... WHERE deleted=0`）可根治但老表改约束须新 migration 权衡。

## 定时任务 / worker
- **FOR UPDATE SKIP LOCKED 锁生命周期三段**（计划12E 沉淀，类 IndexJobWorker）：双节点互斥 worker = ① claim（`@Transactional` 短事务 `SELECT ... FOR UPDATE SKIP LOCKED` + 同事务 `UPDATE locked_until`）→ ② process（事务外跑业务+LLM）→ ③ release（单行 UPDATE 清 `locked_until`，成功附 `last_run_at` 幂等锚点/失败不清允许重试）。互斥靠 `locked_until` 时间戳持久化挡他节点（非靠行锁——行锁随事务提交释放）；`last_run_at >= periodStart` 跳过=幂等防重复计费。

- **BaseMapper.insert 走 `@TableField(typeHandler=...)` 正常**（计划12C IT 实跑验证）：与 V33 教训的 `LambdaUpdateWrapper.set` **不读** typeHandler 不同，`BaseMapper.insert(entity)`（实体 `autoResultMap=true`）**会**正确序列化 `Long[]`/`TEXT[]` 等特型列 → 写入 bigint[]/text[] round-trip 一致。结论：**写入用 `insert` 或 XML 显式 typeHandler；更新特型列不用 `LambdaUpdateWrapper.set`**（用 `Mapper.updateXxx` 显式 typeHandler 或 XML）。范式见 `MemoryGenerationService.writeTurn`（BaseMapper.insert 带 Long[] project_ids）+ `MemoryTurnMapper.updateProjectIds`（更新走显式 typeHandler）。

## 安全
- JWT 双 Token：access 15min + refresh 7d；登出入 Redis 黑名单。
- 密码 BCrypt（cost=10）；连续 5 次失败锁定 15 分钟。
- 用户 LLM API Key 用 AES 加密存储（`AesEncryptService`）。
- 加密配置通用读写走 `SystemSettingService.getDecryptedValue(key)` / `upsertEncrypted(key,plaintext,desc)`（AES 存 `system_settings`，不回显明文）；新供应商 key 复用此范式（如联网搜索 `search.*.api-key`）。
- 敏感配置（JWT_SECRET / DB_PASSWORD / RUNTIME_CALLBACK_TOKEN）走环境变量，**fail-closed 未注入拒启动**。
- sidecar 回调校验 `X-Runtime-Token`；`callback_client` 用 `trust_env=False` 避免系统代理拦截。
- **外部服务降级链范式**（联网搜索沉淀）：可插拔 provider 学 `LlmProviderInterface`（`getName`/`available`/`search`），`search()` 失败**返空不抛**避免异常类型打架；service 层把"空结果"当"可能失败"触发兜底（外部→自建→空），外部重试 1 自建不重试；审计日志含 traceId + query 脱敏 + provider + 结果数 + 耗时。
- **多源 CITATION 帧前端累积合并**：同一条消息可能收多个 CITATION 事件（KB 引用 + 联网 web 引用），前端须累积拼接，不可后者覆盖前者；引用编号空间隔离（web 顺延 KB max index 避免 `[n]` 撞号）。
- **抓取类 SSRF + sanitize 必备**：服务端抓网页须 `assertPublicUrl`（解析所有 A/AAAA 防公网 IPv4+内网 IPv6 绕过，拒私有/环回/链路本地/组播段）+ 正文 sanitize 去 control char/零宽/折叠空白/截断防 prompt 注入。

## 安全（安全体系 S2 沉淀）
- **B3 归属校验命名红线（SEC-FR-012）**：按 id 取数且须校验归属/可见性的方法，命名必须 `getXxxScoped(id, userScope)`（或 `loadXxxAccessible`）——方法名自带「已收口」语义；裸 `getById(id)` 只许用于无归属概念的公共数据。评审/扫描见到用户域裸 getById 即打回。
- **B2 越权测试红线（SEC-FR-011）**：用户域新端点须配越权 IT（继承 `common/security/AbstractPrivilegeIT`：A 建→B 读/改/删→断言 403）；越权必须显式 403，404 可接受，**500 绝不可接受**（=归属校验缺失）。B 须持平台权限，保证 403 来自数据层而非注解层。
- **B1 端点登记红线（SEC-FR-010）**：新端点要么标 `@RequirePermission`/`@PreAuthorize`，要么显式登记进 `SecurityEndpointRegistry`（PUBLIC_PATHS 须同步 SecurityConfig permitAll；AUTHENTICATED_ONLY_REVIEWED 须写评审依据）；启动扫描 WARN 出现新行必须当日处理。
- 审计链：`audit_logs` 只 INSERT/SELECT；写审计只走 `AuditLogService.record/fromMdc`（链式咽喉点自算哈希）；detail 只带脱敏字段名+reason 码，严禁密码/token 原文。
- **哈希链存算一致性三坑（SEC-FR-040 实证）**：①IDENTITY 主键插入前未知——**id 一律不进哈希内容**；②**jsonb 保序不保形**（PG 重排键/规范化数字）——参与哈希的 jsonb 字段两侧必须同走 canonicalJson（排序键 + BigDecimal toPlainString 数字 + 无空白）；③timestamptz 经 pgjdbc 读回=UTC+微秒——入库值若靠 DB DEFAULT/未截断会算不过，写入时显式 `OffsetDateTime.now(UTC).truncatedTo(MICROS)`。
- **@WebMvcTest 加构造器依赖连锁（A8 实证）**：给全局 Filter/Controller 加依赖（如 JwtAuthenticationFilter +SessionService），所有 `@Import` 它的 @WebMvcTest 都要补 `@MockBean`——全量套件才能暴露，跑目标测试发现不了。
- **actuator 双 mapping 坑（B1 实证）**：引 actuator 后容器有 2 个 RequestMappingHandlerMapping，按类型注入炸 NoUniqueBeanDefinition——须 `@Qualifier("requestMappingHandlerMapping")`。
- **降级放行统一范式（S1/S2 一致）**：Redis 依赖的安全强制（防爆破/单点登录/在途闸门）故障时一律**降级放行 + WARN**，可用性 > 强制力；拒绝类响应用固定话术不透内部细节。

## 安全（安全体系 S3 沉淀）
- **C2 前端渲染红线（SEC-FR-054）**：前端禁 `v-html` / `innerHTML =` 裸渲不可信内容（LLM 输出/知识库证据/用户昵称全是不可信文本=存储型 XSS 面）。默认用插值渲染；**LLM/AI 生成内容渲染管道（markdown/富文本）引入之日必须配 DOMPurify 消毒**；确需 HTML 注入点的，整行登记 `scripts/security/frontend-html-allowlist.txt`（注明：全段转义/DOMPurify 依据 + 测试覆盖）过 `frontend-html-gate.sh` 门禁。白名单含行号，上游插行会假红，更新行号即可。
- **门禁脚本尾行坑**：grep 结果管道进 `while read` 做行级过滤时必须 `printf '%s\n'`（补尾换行）——无尾换行时最后一行被 read 静默丢弃=门禁漏报（SEC-FR-054 首版实证，同修 S1 mybatis 门禁）。白名单 `grep -F -f` 前同样要剔空行（空模式匹配一切→门禁无声永绿）。
- **横切可选依赖进 @InjectMocks 单测**：`@RequiredArgsConstructor` 服务加 `@Autowired(required=false)` 字段后，Mockito 走构造注入策略**不会**填该字段——测试须 `ReflectionTestUtils.setField` 手工种，否则检查静默跳过、测试假绿（S3-Step4 实证）。
- **AI 检测层不自残**：围栏/打码/泄露检测/封顶/扫描任何异常一律原文直通或放行 + WARN——检测挂了宁可漏检不掐断业务主链；开关全部进 EDITABLE_KEYS 热调（`security.ai.*` / `security.llm.session-token-cap`）。
- **事件 payload PII 红线（S3 重申）**：安全事件 payload 只带 ids/计数/长度（sessionId/used/cap/chars/hits），**永不带内容原文**（消息/文档/提示词）。
- **降级范式漏网之鱼三则（S2 Phase4 实证）**：①**存量裸调**——新增降级点后必须 grep 同一资源的**所有**调用面（isTokenBlacklisted 裸调 hasKey 排在 SessionService 降级之前，Redis 宕机全员 401）；②**会话键删除须持 sid 比对**（clearSession GET 后 sid 相等才 DEL——盲删=被踢旧会话在降级窗口 logout 可踢飞新会话，logout-bomb）；③**反应式流的资源获取须 Flux.defer 订阅期执行 + doFinally 配对**（组装期 acquire 有「未订阅/组装抛异常」双泄漏路径）；配套：计数型闸门**先读判定配置再 INCR**（读配置失败降级不动计数，避免无配对 INCR）、**release 不查计费开关**（计数后运行期关计费仍须配对释放）。

# M2 时间线记忆 · 用户操作手册

> 功能→步骤→界面变化→预期结果。受众:普通用户。

## 前置
- 已登录,打开对话页 → 记忆面板(底栏记忆图标或记忆抽屉)。
- 有同 key 冲突时才会看到「待解决的记忆冲突」卡。

## 场景 1:解决冲突 + 设时间线标
| 步骤 | 界面变化 | 预期 |
|---|---|---|
| 1. 发消息触发冲突(如先说住萧山,再说住拱墅) | 记忆面板顶部出现「待解决的记忆冲突」卡 | 卡显候选(新+旧) |
| 2. 看卡上「时间线:是/否」 | 默认「未设(默认非时序)」 | 首次可选 |
| 3. 住址类点「是」 | 「是」按钮变 success 绿,「未设」消失 | 该 key 标=时序,后续复用 |
| 4. 点「合并保留」 | 卡消失,「我的记忆」刷新 | 值列显时间线:`2026-06-25 住萧山;2027-01-01 住拱墅` |
| 5. 再发同 key 冲突 | 新冲突卡「时间线」直接显「是」(不再问) | 按已设标 merge |

**反向**:步骤 3 选「否」→ 合并后值列显中文逗号拼接(如 `小美,小芳`),非时间线。

## 场景 2:自定义合并(手改值)
| 步骤 | 界面变化 | 预期 |
|---|---|---|
| 1. 冲突卡点「自定义」 | 出现 textarea,默认填旧 value | 可手改 |
| 2. 改值(如把「住萧山」改「住萧山区市心路」) | textarea 内容变 | — |
| 3. 点「确认自定义」 | 卡消失,记忆刷新 | 值=你改的;updated_at 刷;重 embed |

**半选/反向**:textarea 清空点确认 → 后端返失败(校验非空),提示「解决失败」,卡保留。

## 场景 3:看时间线记忆
| 步骤 | 界面变化 | 预期 |
|---|---|---|
| 1. 「我的记忆」表找时序 key(如 home_city) | 「值」列 | 多段日期行(每行:灰色日期 + 内容) |
| 2. 找非时序 key(如 child_name) | 「值」列 | 原样单串,无分段 |
| 3. 老数据(无日期前缀) | 「值」列 | 当单值显示,不崩 |

## 场景 4:改时间线标
| 步骤 | 界面变化 | 预期 |
|---|---|---|
| 1. 该 key 有新冲突卡 | 「时间线」显当前标(是/否) | 可重设 |
| 2. 点另一选项 | 标翻转 | source=USER_OVERRIDE(优先级最高),下次 merge 按新标 |

## 注意
- 时序标 per-key:同一 key 全局生效(不分项目)。
- daily_log/日记类 key 自动时序,不需手设。
- AI 回答不入记忆(只记你说的);想记 AI 答案需 M5「记一下」通道(待上线)。

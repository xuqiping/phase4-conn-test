# 3.4 指标设计方法论

## B.01 指标优先级判定

### ICE优先级框架

| 维度 | 评分(1~10) | 说明 |
|---|---|---|
| Impact 影响力 | 该指标对业务的影响多大 | 直接影响NSM=高分 |
| Confidence 置信度 | 我们有多确信这个指标重要 | 有数据支撑=高分 |
| Ease 可操作性 | 团队能多容易地度量和影响它 | 采集成本低+可行动=高分 |

**ICE总分 = I × C × E**，优先构建高分指标。

## I.06 从业务目标到指标的5步法

```
业务目标 → 用户价值假设 → 关键行为 → 度量指标 → 指标阈值
```

| 步骤 | 做什么 | 产出 | 示例 |
|---|---|---|---|
| 1.明确业务目标 | 当前阶段最关键的业务目标 | 1句话 | "提升用户留存" |
| 2.用户价值假设 | 留存用户因为获得了什么价值 | 假设陈述 | "每日读3篇+的用户留存率>60%" |
| 3.关键行为 | 哪些行为代表价值获得 | 行为清单 | "阅读3篇/收藏/分享" |
| 4.度量指标 | 给每个行为定义量化指标 | 指标定义 | "7日内阅读≥3篇的用户占比" |
| 5.指标阈值 | 当前值是多少、目标值是多少 | 基线+目标 | "当前22%→目标35%" |

## I.07 定量+定性混合设计

| 方法 | 适用场景 | 产出 |
|---|---|---|
| 定量先行 | 已有大量行为数据 | 量化指标+趋势+阈值 |
| 定性先行 | 新产品无数据 or 指标含义不明 | 用户访谈+问卷→提炼度量维度 |
| 混合三角验证 | 高风险决策 | 定量发现"是什么"+定性解释"为什么" |

**定性→定量转化示例**：
- 用户说"这个功能不好用" → 定量指标：任务完成率/错误率/耗时
- 用户说"我经常找不到入口" → 定量指标：搜索使用率/导航层级深度

## I.09 护栏指标设计实操

### Three-Bucket护栏模型

| 护栏桶 | 度量什么 | 设计原则 |
|---|---|---|
| **质量桶** | 用户体验底线 | 低于阈值=红灯报警、立即暂停优化 |
| **收入桶** | 商业健康度 | 逐步监控、异常时回滚 |
| **技术桶** | 系统承载能力 | 绝对红线、触发即熔断 |

### 护栏指标设计三问

1. **如果NSM创新高，什么可能同时在变差？** → 那就是护栏指标
2. **过去有没有"优化一个指标损害另一个"的教训？** → 把被损害的设为护栏
3. **用户价值链条上，哪些环节不能断？** → 断链点=护栏

## I.10 核心清单：指标体系健康度自查

| 检查项 | 通过标准 |
|---|---|
| 有且仅有1个NSM | 全员能背出，无争议 |
| Input指标可归属 | 每个指标有明确责任团队 |
| 无虚荣指标 | 每个指标都有"如果它变了，我会做什么"的答案 |
| 有护栏指标 | NSM+至少3个护栏 |
| 定性+定量混合 | 纯量化指标体系需补充定性维度 |
| 指标间无对冲 | 无"A升导致B降"的零和指标对 |
| 有基线有目标 | 每个指标都有当前值+目标值 |

## 2. 功能-代码映射

### 2.1 沙箱白名单与越界判定（FR-001）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 路径归一化 | `core-sandbox::path::resolve_logical` | 不碰文件系统先把 `.` / `..` 算清楚，避免 TOCTOU。 |
| 安全拼接 | `core-sandbox::path::safe_join` | 相对路径里出现 `..` 直接拒，禁止爬出项目根。 |
| 真实路径解析 | `core-sandbox::path::normalize` | 能 `canonicalize` 就用真实路径（破符号链接），文件不存在再回退逻辑解析。 |
| 白名单/黑名单判定 | `core-sandbox::policy::SandboxPolicy::check` | 先匹配拒绝清单（`~/.ssh`、系统目录），再匹配允许清单；命中白名单返回 `Decision::Allow`。 |

### 2.2 命令执行器（FR-003 地基）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 异步起进程 | `core-exec::exec::run` | `tokio::process::Command` 避免 UI 阻塞；stdout/stderr 各行读到 String。 |
| 输出截断 | `read_limited` | 默认各保留 8KB，超过就尾截断并提示，防内存爆。 |
| 超时杀树 | `kill_tree` | `sysinfo` 扫描子进程，Windows `taskkill /T`、Unix `kill -9` 一起杀。 |

### 2.3 环境探测与画像缓存（FR-005/AC-005）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 技术栈识别 | `core-exec::probe::probe` | 扫描 `package.json` / `requirements.txt` / `Cargo.toml` / `go.mod` / `Gemfile` / `composer.json`，输出 `EnvProfile { stacks, versions, install_commands }`。 |
| 缓存键 | `core-exec::profile::probe_and_cache` | key = `(path_hash, lockfile_hash)`；lockfile 不变则画像不变，秒级复用。 |
| 本地缓存表 | `core-state::env_profile` / `L5__env_profiles.sql` | SQLite 存 JSON 画像；WAL 模式读不阻塞写。 |

### 2.4 一键安装向导（FR-005/AC-006）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 缺失项转安装命令 | `core-exec::install::plan` | 按画像 + 当前 OS（Windows/macOS/Linux）生成 winget/scoop/brew/apt 命令。 |
| 执行安装计划 | `core-exec::install::run_plan` | 串行执行，失败即停；回调输出给前端日志流预留接口。 |
| 安装向导 UI | `src-ui/components/install-wizard/InstallWizard.tsx` | 展示缺失项/命令/风险说明，一键执行并回显结果。 |

### 2.5 全流程闭环 runner（FR-003/AC-004）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 阶段流水线 | `core-exec::runner::run_task` | `write → probe → install → run → fix → commit`，失败即停或进入修复循环。 |
| 文件读写沙箱 | `read_project_file` / `write_project_file` | 任何文件操作先过 `SandboxPolicy`，越界拒。 |
| 测试/lint 探测 | `pick_test_command` | Node 读 `package.json scripts.test`；Python `pytest`；Rust `cargo test`；Go `go test ./...`。 |
| 失败修复接口 | `FixStrategy` trait | MVP 用 `NoOpFixStrategy`；后续可接入云端 chat/estimate 生成补丁。 |
| 存档点 | `commit_checkpoint` | 成功后 `git commit -m "devpilot: ..."`，失败后 `devpilot-failed: ...`，都带 `--no-verify`。 |
| 状态机触发 | `commands::execute_build` | build 阶段才允许调用；自动开轮次/任务，跑 runner，回写结果，成功推进 accept。 |

### 2.6 两档审批模式（FR-009）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 危险命令清单 | `core-sandbox::approval::danger_level` | `rm -rf /`、`curl \| sh`、`mkfs`、`dd`、`format`、`reg delete`、系统目录写入等触发 Ask/Block。 |
| 自动/手动策略 | `ApprovalGate::check_command` / `check_file` | Auto 策略：普通命令放行，危险命令 Ask；Manual 策略：任何操作都 Ask。 |
| 审批持久化 | `core-state::approval` / `L4__pending_approvals.sql` | 待审批记录落库，断点续开可恢复；Tauri 提供 create/list/submit。 |

### 2.7 Secrets 管理（FR-012/AC-014）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 加密存储 | `core-state::secrets::{encrypt,decrypt}` | AES-256-GCM，密钥 = SHA-256(设备指纹：`hostname:username`)；优先 OS keyring，失败/不可用时回退加密落库。 |
| 名称索引 | `core-state::secrets::list` | DB 只存名称，值不在 SQLite 里裸奔。 |
| 进程注入 | `core-exec::secrets::inject_env` | 任务进程 env 加 `DEVPILOT_SECRET_<NAME>=<value>`。 |
| 输出脱敏 | `core-exec::secrets::redact` | 把 secret 值及其大小写变体替换为 `***`，再写 UI/日志。 |
| 管理 UI | `src-ui/components/secrets/SecretsPanel.tsx` | 增删改查；输入框 password，列表只显示名称。 |

## 3. 本地库表用途速查

| 表 | 用途 | P03 新增/改动 |
|---|---|---|
| `projects` | 项目档案 | 无 |

## 4. 关键联动点

- **创建项目** → `projects` + `workflow_states` 初始化（P01 已有）。
- **进入 build 阶段** → 前端显示 `BuildButton` → 调用 `execute_build` → runner 跑测试 → 成功自动推进 `accept`。
- **配置 Secret** → runner 执行时自动注入 env → 输出中 secret 被替换为 `***`。
- **安装向导** → `install_runtime` 调用 `run_install_plan` → 安装结果回显到 `InstallWizard`。
- **审批** → 危险命令/手动策略触发 `pending_approvals` → 前端列表 unresolved → 用户 submit 后记录 resolved。

## 5. 运维与限流

- **超时**：runner 测试命令默认 120s，安装命令 300s；超时会杀进程树。
- **日志透明层**：runner/install 都预留 `on_event` 回调，前端可接事件流（FR-038 预留）。
- **降级**：环境探测缓存命中不读文件系统；keyring 失败回退 AES-GCM 加密库。
- **CI 兜底**：本地 `cargo audit` / `npm audit` 因网络/镜像受限只 WARN，GitHub Actions 环境硬拦截。

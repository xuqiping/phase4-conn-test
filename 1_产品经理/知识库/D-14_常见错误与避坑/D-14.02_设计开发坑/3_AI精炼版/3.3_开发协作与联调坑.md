## 开发协作坑

### 1. 需求理解偏差 [D.01][I.01]

需求理解偏差是PM与开发之间最大的信息黑洞——PM写的≠开发理解的≠最终实现的。[来源:📚训练知识 | 置信度:🔍高]

| 偏差类型 | PM的表达 | 开发的理解 | 根因 |
|---|---|---|---|
| 语境偏差 | 基于用户场景描述 | 基于技术实现理解 | 两套语言体系 |
| 边界偏差 | 只描述正常流程 | 默认只实现正常流程 | 异常场景未被任何一方覆盖 |
| 优先级偏差 | "这个重要" | 可做可不做/放后面 | 没有量化优先级 |
| 含义偏差 | "类似XX的交互" | 不理解XX/理解成另一个XX | 指代不明+主观解读 |

> 核心原理(I.03)：沟通不是"我说了"= 对方就理解了。信息传递的损耗模型：你想表达的100% → 你说出的80% → 对方听到的60% → 对方理解的40% → 对方记住的20%。因此——关键信息必须用"对方复述确认"来闭环。[来源:📚训练知识 | 置信度:🔍高]

**减少需求理解偏差的3个动作**：
1. **需求评审后**：让开发用自己的话复述需求（不是念PRD）
2. **PRD关键逻辑**：用"当…时，应该…，否则…"的if-then格式写
3. **边界条件**：用表格穷举，而非自然语言描述

### 2. 接口对不齐 [G.02]

接口对不齐是前后端协作的经典灾难——不是能力问题，是契约问题。[来源:📚训练知识 | 置信度:🔍高]

| 对不齐的类型 | 后果 | 根因 |
|---|---|---|
| 字段名不一致 | 前端取不到值/取错值 | 没有API契约文档/文档与代码不同步 |
| 数据类型不一致 | 运行时类型错误 | 接口文档缺类型约束 |
| 枚举值不一致 | 状态展示错误 | 前后端枚举映射未对齐 |
| 空值处理不一致 | 空指针/空字符串/undefined混用 | 没有统一的空值约定 |
| 版本不一致 | 上线后接口报错 | 接口变更未通知/未版本化 |

**API契约先行原则** [I.10]：
- 前后端并行开发的前提=API契约先定义（Swagger/OpenAPI）
- 契约变更必须通知+经双方确认
- 契约=代码的一部分，纳入版本管理

### 3. 前后端联调灾难 [E.03]

联调是最容易变成"灾难"的环节——因为它是所有前置问题的集中爆发点。[来源:📚训练知识 | 置信度:🔍高]

| 联调灾难的根因 | 占比(经验估计) | 可前置预防 |
|---|---|---|
| 接口契约不一致 | 40% | API文档先行+Mock服务 |
| 数据格式/类型不匹配 | 25% | 契约中的类型约束 |
| 环境不一致 | 15% | Docker统一环境 |
| 业务逻辑理解分歧 | 15% | 需求评审闭环 |
| 其他(网络/权限/配置) | 5% | 环境checklist |

**联调避坑框架**：

```
开发前：API契约定义(Mock服务) → 前后端各自开发(基于Mock)
开发中：接口自测+单元测试 → 提测前完成契约验证
联调时：1天联调窗口 → 只处理契约偏差 → 不改逻辑
联调后：冒烟测试 → 核心路径回归 → 提测
```

> 经验数据(I.12)：有Mock服务+API契约的团队，联调时间平均缩短60%；没有的团队，联调占开发周期30-50%。[来源:📚训练知识 | 置信度:🔍中]

### 4. 测试覆盖不足 [I.01][I.03]

PM对测试的理解误区：测试=QA的事。实际上PM是"测试什么"的决策者。[来源:📚训练知识 | 置信度:🔍高]

| PM忽视的测试维度 | 后果 | PM应做的 |
|---|---|---|
| 核心路径测试 | 核心功能上线后崩溃 | 明确"不能挂"的核心路径清单 |
| 边界条件测试 | 边缘场景出bug→投诉 | PRD中穷举边界条件 |
| 兼容性测试 | 某些设备不可用 | 明确目标设备/浏览器矩阵 |
| 回归测试 | 新功能搞坏老功能 | 每次发版必须回归的核心路径 |
| 性能测试 | 高峰期系统崩 | 定义性能基线(→3.2) |

**PM必须提供的测试输入** [I.01]：

| 输入 | 作用 | 写在哪里 |
|---|---|---|
| 核心路径清单 | 确保关键流程不出bug | PRD验收标准 |
| 边界条件表 | 覆盖异常分支 | PRD边界条件章节 |
| 优先级分级 | 测试资源分配依据 | PRD优先级标注 |
| 目标设备矩阵 | 兼容性测试范围 | PRD非功能需求 |

### 5. 避险技法 [I.07]

| 技法 | 时机 | 具体做法 |
|---|---|---|
| 需求复述闭环 | 需求评审结束前 | 让开发复述+白板画流程 |
| API契约先行 | 开发排期前 | 用Swagger定义→前后端签名确认 |
| Mock服务 | 前后端并行开发 | 前端基于Mock开发→联调时切换 |
| 测试用例前置 | 开发启动前 | PM写核心路径+边界条件→QA补充 |
| 冒烟测试清单 | 每次提测前 | 10-15个核心路径→5分钟内快速验证 |
| 接口变更通知 | 任何接口修改 | 变更邮件+影响范围确认 |

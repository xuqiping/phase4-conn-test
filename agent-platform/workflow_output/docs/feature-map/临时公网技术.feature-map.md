# 临时公网技术 · Feature Map（Cloudflare Quick Tunnel）

> 本文记录本地开发环境把 Spring Boot 临时暴露为公网 HTTPS 的真实实现。当前用途是让 Ark 从公网回拉视频生成的参考视频。关联 [快速启动](../../../项目工程文档/0_快速启动.md#42-启用-ark-参考视频的本地启动)、[SeedDance 视频生成](SeedDance视频生成.feature-map.md) 和 [部署手册](../deploy/部署手册终.md#本地开发参考视频可选)。
>
> **适用范围**：仅限本地开发、联调和冒烟测试。Cloudflare Quick Tunnel 地址随机、可能变化、没有可用性承诺，不是生产部署方案。

## 一句话描述

本机运行 `cloudflared`，主动建立到 Cloudflare 的加密出站隧道，将临时分配的 `https://*.trycloudflare.com` 公网入口转发到 `http://127.0.0.1:8080`；Spring Boot 再通过带过期时间和 HMAC-SHA256 签名的下载 URL，只向 Ark 开放指定参考视频。

```text
Ark
  ↓ HTTPS 请求
https://随机子域名.trycloudflare.com
  ↓ Cloudflare 边缘网络
cloudflared 本机进程（主动出站连接）
  ↓ HTTP 转发
http://127.0.0.1:8080
  ↓
Spring Boot /api/media/reference/{fileId}?expires=...&sig=...
```

## 关键调用链

### 1. 创建临时公网入口

```text
启动 cloudflared
→ cloudflared 主动连接 Cloudflare
→ Cloudflare 分配 *.trycloudflare.com
→ 公网 HTTPS 请求被转发到 127.0.0.1:8080
```

本机不需要固定公网 IP、路由器端口映射或自签 HTTPS 证书。连接由本机主动向外建立，通常不需要开放公网入站 8080。

### 2. 后端启用能力

```text
PowerShell 加载 local-dev-env.ps1
→ 加载 local-media-reference-env.ps1
→ 启动 Spring Boot
→ application.yml 读取 MEDIA_REFERENCE_*
→ MediaGenProperties.isReferenceVideoConfigured()
→ MediaModelService 返回 referenceVideoEnabled=true/false
→ VideoGenView 启用或禁用参考视频入口
```

后端仅在启动时读取环境变量。修改临时域名、签名密钥或 TTL 后必须重启 backend。

### 3. Ark 回拉参考视频

```text
用户提交带参考视频的生成任务
→ MediaGenTaskWorker 读取 fileId
→ MediaReferenceUrlService.createVideoUrl(fileId)
→ 生成 expires + HMAC-SHA256 sig
→ ArkSeedanceProvider 发送 reference_video 公网 URL
→ Ark 访问 Cloudflare 临时域名
→ Tunnel 转发到 MediaReferenceController
→ 校验签名、过期时间、文件存在和 video/* MIME
→ 以 no-store 流式返回视频
```

签名 URL 相当于临时取件凭证。拥有完整 URL 的调用方在有效期内可以下载对应视频，因此 URL 不得写入普通日志；Provider 请求快照必须整体脱敏。

## 配置说明

`application.yml` 映射：

```yaml
media:
  reference:
    public-base-url: ${MEDIA_REFERENCE_PUBLIC_BASE_URL:}
    signing-key: ${MEDIA_REFERENCE_SIGNING_KEY:}
    ttl-seconds: ${MEDIA_REFERENCE_TTL_SECONDS:900}
```

本机私有配置示例：

```powershell
$env:MEDIA_REFERENCE_PUBLIC_BASE_URL = 'https://随机域名.trycloudflare.com'
$env:MEDIA_REFERENCE_SIGNING_KEY = '至少32字符的随机密钥'
$env:MEDIA_REFERENCE_TTL_SECONDS = '900'
```

启用条件必须全部满足：

- `public-base-url` 使用 `https://`。
- Host 不为空，且不是 `localhost`、`127.*` 或 `::1`。
- 签名密钥长度至少 32 个字符。
- TTL 大于 0。
- 当前选择的视频模型 `maxVideos > 0`。

只配置公网地址而未配置签名密钥，或只启动 Tunnel 而后端仍用普通方式启动，都会保持 `referenceVideoEnabled=false`。

## 本地启动与验证

### 启动 Tunnel

在独立 PowerShell 窗口运行：

```powershell
cd E:\workspace\agent-platform
.\.local-tools\cloudflared.exe tunnel `
  --url http://127.0.0.1:8080 `
  --no-autoupdate `
  --logfile .\.local-tools\cloudflared-active.log `
  --loglevel info
```

从日志取得本次 `https://*.trycloudflare.com` 地址，写入 `local-media-reference-env.ps1`。Quick Tunnel 重启后地址可能变化。

### 启动后端

推荐使用辅助脚本：

```powershell
cd E:\workspace\agent-platform
.\start-backend-media-reference.ps1
```

等价手动方式：

```powershell
cd E:\workspace\agent-platform\backend
. ..\local-dev-env.ps1
. ..\local-media-reference-env.ps1
mvn spring-boot:run
```

辅助脚本只加载配置并启动 backend，**不会自动创建、更新或守护 Tunnel**。

### 验证

```powershell
# 查看 Tunnel 域名、连接协议和错误
Get-Content E:\workspace\agent-platform\.local-tools\cloudflared-active.log -Tail 80

# 公网入口能否转发到本机 backend
Invoke-WebRequest https://你的临时域名/actuator/health -UseBasicParsing

# 当前 PowerShell 是否加载配置；不要打印密钥正文
$env:MEDIA_REFERENCE_PUBLIC_BASE_URL
$env:MEDIA_REFERENCE_SIGNING_KEY.Length
$env:MEDIA_REFERENCE_TTL_SECONDS
```

最终业务验证：刷新 `/video-gen`，确认参考视频上传与“从资产库选择”可用；提交真实任务后不再出现 `reference_video must be provided as a web url`。

## 技术原理注解（大白话版）

### 1. Cloudflare Quick Tunnel

- **原理**：本机 `cloudflared` 主动向 Cloudflare 建立长连接，Cloudflare 把公网 HTTPS 请求沿连接转回本机服务。
- **大白话**：本机主动打通一条“只出不进”的加密通道，Cloudflare 在公网摆一个临时门牌；外部请求先到门牌，再沿通道送到本机。
- **价值**：无需公网 IP、域名、端口映射和本机 HTTPS 证书即可完成第三方回调/回拉联调。

### 2. HMAC-SHA256 短期签名 URL

- **原理**：后端用 `fileId + 换行 + expires` 和服务端密钥计算 HMAC，下载端以常量时间比较验证签名。
- **大白话**：后端给某个文件开一张限时取件码；文件号或过期时间被改动，取件码立即失效。
- **安全边界**：它授权的是一条具体视频，不是登录用户身份；因此回拉端点可以免 JWT，但必须验证签名、过期时间和 MIME。

### 3. 前后端双重 Fail-closed

- 前端依据 `referenceVideoEnabled` 禁用上传和资产库选择。
- 后端提交任务时再次调用 `isReferenceVideoConfigured()`；即使绕过前端，未配置环境仍返回明确错误。
- **大白话**：页面先拦一次，后端检票口再拦一次，不能靠修改浏览器状态绕过部署条件。

## 安全边界与限制

- Quick Tunnel 会把指定的整个本机 HTTP 服务暴露到该临时公网域名，而不是只暴露参考视频端点；其他业务接口仍依赖 JWT/RBAC 保护。
- `/api/media/reference/**` 为 Ark 回拉而 `permitAll`，真正授权凭证是 `expires + sig`。
- 回拉响应只允许已存在的 `video/*`，设置 `Cache-Control: no-store`、`Content-Disposition: inline` 和 `X-Content-Type-Options: nosniff`。
- 临时 URL 可能出现在第三方请求链路中，必须避免写入普通日志、审计详情和前端错误信息。
- Tunnel 进程停止、网络断开或临时域名变化后，旧 URL 无法继续访问。
- Quick Tunnel 无 SLA，不用于生产，不承担稳定回调、固定域名或正式安全边界。

## 常见故障

| 现象 | 根因 | 处理 |
|---|---|---|
| 页面提示“当前环境未开放参考视频” | 只加载了 `local-dev-env.ps1` | 加载 `local-media-reference-env.ps1` 后重启 backend |
| Tunnel 正在运行但入口仍禁用 | 后端启动时没读到三项配置 | 用辅助脚本重启，检查变量长度和 URL |
| 公网健康检查失败 | Tunnel 断开、域名过期或 backend 未监听 8080 | 查 Tunnel 日志和本机端口 |
| 签名 URL 返回 403 | URL 过期、签名被改、签名密钥已轮换 | 重新提交任务生成新 URL |
| 签名 URL 返回 404 | 文件不存在或 MIME 不是 `video/*` | 检查 `stored_files` 元数据和文件生命周期 |
| Ark 报 `reference_video must be provided as a web url` | 实际请求仍发送 data URI/旧任务路径 | 查看 Provider 脱敏请求快照和任务代码路径 |
| Tunnel 重启后突然不可用 | Quick Tunnel 分配了新域名 | 更新环境文件并重启 backend |

## 生产替代方案

生产环境应选择以下之一：

1. 正式域名 + DNS + Nginx/网关 + 可信 CA HTTPS 证书。
2. Cloudflare Named Tunnel（绑定自有域名、受控配置和长期凭据）。

生产仍复用相同的 HMAC 短期签名端点，但 `MEDIA_REFERENCE_PUBLIC_BASE_URL` 必须换成稳定的正式 HTTPS 根地址。公网只开放 80/443，不直接开放 Spring Boot 8080。

---

## 数据库与迁移

本技术本身不新增数据库表和 Flyway 迁移。参考视频复用 `stored_files`；临时域名、签名密钥和 TTL 只从本机/服务器环境配置读取，不落业务数据库。

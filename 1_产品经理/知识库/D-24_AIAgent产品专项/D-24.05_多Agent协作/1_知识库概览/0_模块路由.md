# D-24.05 多Agent协作 — 知识库概览

## 一、本叶子的核心定义

**多Agent系统（Multi-Agent System, MAS）** = 多个 LLM 智能体（每个智能体拥有独立的循环、工具集、上下文窗口）通过某种拓扑结构、通信协议、状态管理机制协作完成共同目标的系统架构。区别于 D-24.04 的"单 Agent 工作流"——单 Agent 工作流讨论"一个 Agent 怎么把任务拆解为自己跑的多步骤"；多 Agent 协作讨论"如何让 N 个独立 Agent 分头干活再汇总，并解决协调、冲突、失败级联、状态一致性等系统级问题"。

**核心判断准则（Anthropic 2026-06 报告）**：增加更多 Agent 不总是让系统更聪明。某些场景下，single-agent 在同样模型下表现优于 multi-agent（特别是需要长链路串行推理的任务）。多 Agent 的真正价值是"关注点分离 + 并行探索 + 上下文隔离"，而不是"分工"。一旦智能达到一定阈值，MAS 才成为扩展性能的关键方式——未到阈值前 MAS 是负担。

[来源:Anthropic《Scaling Intelligence through Multi-Agent Collaboration》/ Redis Blog | 🔍高 | 2026-06/04]

## 二、三大子维度

1. **多 Agent 拓扑与编排模式**（→ 3.1）：解决"怎么拆 + 怎么连 + 控制流怎么走"。8种主流拓扑（Orchestrator-Worker / Hierarchical / Peer-to-Peer / Star / Mesh / Generator-Validator / 辩论 / 群体）+ Anthropic 五大工作流模式（提示链 / 路由 / 并行化 / 编排者-执行者 / 评估器-优化器）。三基因轴：控制拓扑（集中 vs 分布）、通信模式（直接 vs 共享 vs 委托）、状态管理（无状态 vs 有状态 vs Checkpoint）。MAST 分类法。
2. **通信协议与共享状态**（→ 3.2）：解决"Agent 之间怎么传递信息 + 怎么共享状态"。三种通信原语（Blackboard 黑板 / MessageBus 消息总线 / SharedMemory 共享内存）+ 四协议栈（MCP / A2A / ACP / Skill）+ 同步异步策略 + 冲突解决（投票 / 仲裁 / 优先级 / 契约化协作）。
3. **失败模式与安全可观测**（→ 3.3）：解决"崩了怎么不级联 + 安不安全 + 怎么追溯谁错"。Berkeley 14 种失败模式 + MAST 分类法 + 87% 失败率归因 + 跨 Agent 攻击面 + OWASP MCP Top 10 + AgenTracer 纠错 + 契约化协作 + 协同可信工程化。

## 四、为什么 PM 必须懂多 Agent 协作（6 条核心理由）

1. **65% 企业多 Agent 项目失败**——Gartner 2026-07 数据，企业多 Agent 项目因协作失控、状态不一致、死锁而失败的占比高达 65%。PM 不懂失败模式就只能眼睁睁看项目翻车。 [来源:腾讯云《驯服多智能体混沌》/ Gartner | 🔍高 | 2026-07]
2. **Anthropic vs Cognition 大辩论是行业路线分歧**——Anthropic 主张 MAS 在复杂任务上比单 Agent 高 90.2%；Cognition（Devin 团队）主张单 Agent + 长上下文压缩更稳健、好用、成本低。PM 必须懂两边逻辑才能为自家产品选对路线。 [来源:Anthropic / Cognition via 知乎 | 🔍高 | 2026-06]
3. **多 Agent token 15 倍单 Agent**——Anthropic 5-Agent 系统相对单 Agent 是 15 倍 token 消耗，token 单独解释 80% 性能方差。成本失控是 MAS 生产化头号杀手（Uber 2026-04 烧光全年 AI 编程预算；一家医疗企业 6 个月烧 1 万亿 Token / 600 万美元计划外支出）。 [来源:Anthropic / 腾讯新闻 | 🔍高 | 2026-06/07]
4. **2026 = Agent 联网元年**——MCP 注册 Server 突破 10 万、A2A v1.0 GA、企业内 Salesforce/ServiceNow/LangChain Agent 互联需求爆发。PM 必须懂协议栈才能做跨组织 Agent 产品。 [来源:腾讯云 / Anthropic / Google | 🔍高 | 2026-07]
5. **Berkeley 14 种失败模式 + MAST 分类法**是系统化排查能力的基础——87% 失败率归因（79% 是 specification 不清晰和 agent 间协调失败）。PM 拿到这个框架就能像 SRE 排查事故一样排查 MAS 翻车。 [来源:Berkeley / 知乎 / Redis Blog | 🔍高 | 2026-07]

## 五、8 条常见误区（PM 必须避开）

1. **"AI 越多越好"** —— 增加更多 Agent 不总是让系统更聪明。Berkeley 实测：加 3 个 specialist agent 后准确率反而降 15%。 [来源:Berkeley / 知乎 | 🔍高 | 2026-07]
2. **"多 Agent 就是分工"** —— 真正的难点不是分工而是协调。分工每家公司都会做，但协调（通信/状态/冲突/失败级联）才是 MAS 工程化的核心难题。
3. **"Agent A 审 Agent B 就够把关"** —— 实测 Agent A 经常"永远说 OK"（橡皮图章）——Validator Agent 与 Generator Agent 共享同源 prompt 偏好时审核形同虚设。 [来源:Berkeley / 知乎 | 🔍高 | 2026-07]
4. **"MAS 适合所有复杂任务"** —— 串行推理任务 single-agent 反而更优（Redis Blog 明确结论）。MAS 只在"关注点分离 + 并行探索 + 上下文隔离"三点都成立时才划算。
5. **"Agent 之间自由对话能涌现协作"** —— 65% 企业 MAS 因协作失控、状态不一致、死锁而失败。2026 行业已从"自由对话"转向"契约化协作"。 [来源:Gartner / 腾讯云 | 🔍高 | 2026-07]
6. **"MAS 上生产只是技术问题"** —— 框架选型陷阱：状态存在内存里 → 进程重启所有会话丢失。生产环境重构成本是原型的 10 倍。 [来源:福建开沿科技 Agent 编排框架横评 | 🔍高 | 2026-07]
7. **"Anthropic 都搞了 5-Agent，所以我们也要 MAS"** —— Anthropic 自己明确建议：从最简单的能跑通的模式开始，看哪里撑不住再往上演进。Generator-Validator 是最简单模式也是部署最广。 [来源:Anthropic / 知乎 | 🔍高 | 2026-06]
8. **"MAS = 群体涌现智能"** —— 现阶段 MAS 还做不到涌现，主要还是工程化协同。所谓"涌现行为"主要表现为失败涌现（cascading errors / context rot），而非智能涌现。

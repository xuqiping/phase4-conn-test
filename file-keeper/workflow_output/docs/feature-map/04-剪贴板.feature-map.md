# 剪贴板模块总结

## 1. 模块职责一句话

剪贴板模块负责监听系统剪贴板变化、持久化历史记录、提供分类检索与快速粘贴、支持 OCR 识别与链接预览，并在本地实现敏感内容检测与存储配额管理。

## 3. 核心数据流 / 调用链路

### 剪贴板监控链路

```
系统剪贴板变化
    → platform/windows/clipboard.rs (read_text/read_files/read_image)
    → commands/clipboard.rs::start_clipboard_monitor (500ms 轮询线程)
    → clipboard/mod.rs::ClipboardService.collect_*_snapshot
    → clipboard/storage.rs (SQLite INSERT/UPDATE)
    → 发射事件 "clipboard://changed" → 前端
    → clipboardStore.ts 监听 → scheduleReload(100ms 防抖) → loadItems()
```

### 用户复制链路

```
前端 ClipboardPreview/ClipboardList 点击复制
    → clipboardStore.copyItem(id, format)
    → api/clipboard.ts::copyClipboardItem
    → commands/clipboard.rs::copy_clipboard_item
    → ClipboardService.get_copy_text / get_file_copy_paths
    → platform/windows/clipboard.rs::write_text / write_files
    → ClipboardService.mark_written_text (记录 hash，避免监控回环)
```

### 快速粘贴链路

```
全局快捷键 (Ctrl+Shift+V 默认)
    → App.vue::handleClipboardShortcut
    → clipboardStore.openQuickPanel()
    → rememberClipboardTargetWindow() (记录当前前台窗口)
    → ClipboardQuickPanel.vue 弹出
    → 用户选择 + Enter
    → clipboardStore.pasteItem(id, format)
    → commands/clipboard.rs::paste_clipboard_item
    → 先 copy 到系统剪贴板，若 autoPaste=true 则向记录窗口发送粘贴键
```

### 截图录入链路

```
截图快捷键 → App.vue::handleScreenshotCapture
    → captureScreenshotRegion (Tauri 命令)
    → ClipboardService.collect_screenshot_bytes_snapshot_with_ocr_update
    → 保存 PNG 到 cache_dir/images/
    → SQLite 插入 image 记录
    → 若 enable_ocr=true，后台线程调用 ocr_provider.rs
    → OCR 结果更新到 ocr_text/note/search_text
    → 前端切换 clipboard tab 并选中该记录
```

## 4. 关键状态与 Store 说明

`file-keeper/src/stores/clipboardStore.ts` 使用 Pinia Composition API 风格定义，核心状态如下：

| 状态 | 类型 | 说明 |
|------|------|------|
| `items` | `ClipboardItemSummary[]` | 当前列表数据 |
| `selectedItemId` | `string \| null` | 当前选中项 ID（用于预览） |
| `selectedDetail` | `ClipboardItemDetail \| null` | 当前选中项详情 |
| `selectedIds` | `Set<string>` | 多选集合 |
| `searchQuery` | `string` | 搜索关键词 |
| `kindFilter` | `ClipboardKind \| 'all'` | 类型筛选 |
| `datePreset` / `customStartDate` / `customEndDate` | 日期筛选 | 支持 today/yesterday/last7Days/last30Days/custom |
| `settings` | `ClipboardSettings` | 剪贴板模块设置 |
| `storageUsage` | `ClipboardStorageUsage \| null` | 存储用量 |
| `isQuickPanelOpen` | `boolean` | 快捷面板开关 |
| `loading` / `error` | 状态 | 异步操作状态 |

Store 提供的关键方法：
- `startMonitor()` / `stopMonitor()`：启停监听，自动订阅/取消 `clipboard://changed` 事件
- `loadItems()` / `searchItems()`：加载列表（带防抖查询构建）
- `loadDetail(id)`：加载详情并同步列表中的 note
- `copyItem()` / `pasteItem()` / `deleteItem()` / `updateItemNote()`
- `toggleSelected()` / `selectAllVisible()` / `invertVisibleSelection()` / `clearSelection()`
- `selectedIdsForAction(fallbackId)`：智能判断使用多选还是当前项

## 6. 核心功能

### 6.1 监控剪贴板
- 后端 `start_clipboard_monitor` 启动独立线程，500ms 轮询 Windows 剪贴板
- 支持文本（`CF_UNICODETEXT`）、文件（`CF_HDROP`）、图片（PNG / `CF_DIBV5` / `CF_DIB`，DIB 自动转 PNG）
- 通过 SHA256 哈希去重，避免重复记录
- `mark_written_text` / `should_ignore_text` 机制防止“自己写入自己监听”的回环

### 6.2 历史记录
- SQLite 单表 `clipboard_items` 存储所有记录
- 支持类型：text / html / image / file / url / color / mixed / security_event
- 文本记录自动去重：相同文本再次复制时刷新 `created_at` 到顶部（`touch_item`）
- 每条记录包含：来源应用（进程名/窗口标题/PID）、使用次数、收藏/置顶标记、缓存状态、备注

### 6.3 搜索
- `search_text` 列在插入/更新时预计算归一化文本（小写、去空白）
- 支持按关键词模糊匹配（`LIKE %query%`）、按类型、按日期范围、按收藏筛选
- `rebuild_search_text_index` 可重建全量搜索索引（修复 OCR 备注等后期更新未同步到索引的问题）

### 6.4 复制 / 粘贴
- **复制**：支持 `original` / `plain_text` / `html` / `markdown` / `image_png` / `image_jpeg` / `file_copy`
- 实际实现中 `copy_clipboard_item` 优先尝试文件路径复制，否则回退到文本
- **批量复制**：`copy_clipboard_items` 将多个文本用换行拼接；文件则全部写入剪贴板
- **粘贴**：`paste_clipboard_item` 先复制到系统剪贴板，若 `autoPaste=true` 则激活之前记录的窗口并模拟粘贴键
- `remember_clipboard_target_window` 在打开快捷面板前记录当前前台窗口，用于后续自动粘贴定位

### 6.5 OCR
- 图片记录（截图或复制图片文件）支持 OCR 识别
- 双引擎策略：`ocr_provider.rs` 优先使用本地 sidecar (`file-keeper-ocr.exe`)，回退到 Windows 系统 OCR (`windows::Media::Ocr::OcrEngine`)
- OCR 结果保存到 `ocr_text` 与 `note` 字段，并同步更新 `search_text`
- 截图 OCR 在后台线程执行，不阻塞截图保存流程；完成后通过回调通知前端

### 6.6 链接预览
- 复制 URL 时自动识别并存储为 `url` 类型
- `enable_link_preview=true` 时，通过 `link_preview.rs` 发起 HTTP GET 请求（8秒超时），解析 HTML 提取 `<title>` 和 `<meta name="description">`
- 支持手动 `retry_link_preview` 重新抓取
- 预览结果展示在 `ClipboardPreview.vue` 的链接卡片中

### 6.7 安全策略
- `security.rs` 实现多层检测：
  - 信用卡号（Luhn 算法验证）
  - JWT Token / API Key 正则匹配
  - 私钥标记（`-----BEGIN PRIVATE KEY-----` 等）
  - 高熵字符串（长度 24-256，含大小写+数字，Shannon 熵 >= 4.0）
- 敏感内容不保存原文，仅插入 `security_event` 类型记录，记录拦截原因
- 来源应用检测：识别密码管理器进程（1Password、Bitwarden、KeePass 等）及用户排除列表
- `protectSensitiveContent` 设置开关

### 6.8 存储统计
- `ClipboardStorageUsage` 统计各类型 `cache_bytes` 总和
- 默认非文本缓存上限 2048 MB，单条上限 200 MB
- 支持按类型细分限制（image/file/html/linkPreview）
- `clear_non_text_cache` 可将非文本记录的 `cache_state` 设为 `cleaned` 并清零 `cache_bytes`
- 文件缓存策略：`backup` 模式复制到缓存目录；`reference_only` 仅记录原路径

### 6.9 设置
- `ClipboardSettings` 持久化到 SQLite `clipboard_settings` 表（JSON）
- 关键配置项：监控开关、快捷面板快捷键、自动粘贴、敏感保护、OCR、链接预览、存储上限、文件保存模式、备份目录、扩展名规则、排除应用列表

## 8. 已知缺口 / TODO

1. **ClipboardSecurityEvents.vue 未实现完整功能**：当前仅为静态提示卡片，未展示实际安全事件列表，也未提供查看/清除安全事件的操作入口。
2. **非 Windows 平台剪贴板读写未实现**：`platform/windows/clipboard.rs` 仅支持 Windows；`write_text` / `write_files` / `paste_to_remembered_window` 在非 Windows 平台返回错误提示。
3. **剪贴板监控轮询机制较简单**：当前为 500ms 固定间隔轮询，未使用 Windows 剪贴板查看器链（Clipboard Viewer Chain）或现代 API 实现事件驱动监听，存在少量延迟与性能开销。
4. **OCR 引擎在非 Windows 平台完全禁用**：`ocr_provider.rs` 在非 Windows 且缺少 sidecar 时返回 `disabled`。
5. **链接预览无缓存/限流机制**：每次 `retry_link_preview` 都会直接请求目标 URL，无本地缓存或请求频率控制。
6. **存储清理未自动触发**：`cache.rs` 提供了清理候选算法，但模块中未看到在超出配额时自动调用清理的代码路径，目前仅提供手动“清除非文本缓存”按钮。
7. **缺少收藏/置顶功能的 UI 入口**：`ClipboardItemSummary` 类型包含 `isFavorite` / `isPinned` 字段，Storage 表也有对应列，但前端组件中未看到收藏/置顶的操作按钮或筛选器（除 `favoriteOnly` 筛选外）。
8. **截图 OCR 状态未在前端实时反馈**：OCR 是后台异步执行，完成后仅更新数据库，前端没有 WebSocket 或轮询机制来实时显示“OCR 识别中”或结果更新。

# SOP：Walk the Board 站会引导手册

## 适用场景

每日站会（Daily Standup / Daily Scrum），替代传统"每人三问"汇报模式。

## 角色与职责

| 角色 | 职责 |
|---|---|
| Facilitator（Scrum Master/轮值） | 引导"走看板"、控时15min、记录阻塞 |
| 团队成员 | 聚焦工作项流动、主动暴露阻塞 |
| PM | 可选参与；仅在"需求优先级变化"或"需澄清需求"时发言 |

## 会前准备

- [ ] 看板已更新（每个在制品状态准确）
- [ ] 阻塞项已标红旗🔴
- [ ] 近期里程碑已标注

## 执行流程

### 阶段1：看板走查（8-10分钟）

**方向：从右到左**（接近完成→刚开始）

```
第一步：Done列 → 确认完成项（快速过，不展开）
第二步：Review/QA列 → 即将交付的项，有什么阻塞？
第三步：In Progress列 → 正在做的，有风险吗？需要帮助吗？
第四步：Ready列 → 下一步要做什么？有前置条件未满足吗？
```

**引导话术**：
- "这个卡在这3天了，需要什么帮助？"
- "这件事有人能帮忙吗？"
- "这个依赖的接口对齐了吗？"

### 阶段2：阻塞确认（3-5分钟）

- 收集所有阻塞项→记入阻塞清单
- 每个阻塞：Who/What/Since When/Need What
- 当场能解决的→立即安排
- 需要升级的→标注升级级别

### 阶段3：优先级变化（1-2分钟）

- PM（如果在场）：是否有优先级变化？
- "昨天业务方要求X提前，Y推迟"——一句话说完

## 会后动作

| 动作 | Owner | 时限 |
|---|---|---|
| 更新阻塞清单 | Facilitator | 站会结束15min内 |
| 阻塞升级 | 阻塞Owner | 超过1天未解决的阻塞 |
| 看板状态更新 | 各项Owner | 每日 |

## 常见问题处理

| 问题 | 处理 |
|---|---|
| 有人开始长篇讨论 | "这个很重要但不是全员讨论，[A和B]会后对齐，我们继续看板" |
| 15分钟到了还没走完 | 停在当前项——未走完的项说明问题项已暴露，剩余的用异步更新 |
| 有人缺席 | 异步补更——在Slack/飞书线程中更新"昨天做了/今天计划/阻塞" |
| 阻塞持续多天未解决 | 升级：阻塞>2天→L2级升级；>5天→L3级升级（→D-08.02项目管理的升级路径） |

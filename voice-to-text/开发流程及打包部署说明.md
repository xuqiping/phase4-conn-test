# Voice to Text - 实时语音转文字

基于 **Tauri 2 + Rust + Vue 3 + sherpa-onnx** 的跨平台桌面实时语音转文字应用。

支持**麦克风输入**和**系统音频内录**（WASAPI Loopback），可进行中英文实时语音识别。

---

## 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端 | Vue 3 + Pinia + Vite | 实时展示转写结果 |
| 后端 | Rust + Tauri 2 | 桌面框架、系统调用 |
| 音频采集 | cpal + WASAPI | 麦克风 / 系统音频内录 |
| 语音识别 | sherpa-onnx (ZipFormer) | 本地 ONNX 流式识别模型 |
| 打包 | Tauri CLI | 生成 .exe / .msi 安装包 |

## 开发环境准备

### 前置依赖

1. **Node.js** >= 18
2. **Rust** >= 1.77（建议通过 [rustup](https://rustup.rs/) 安装）
3. **Visual Studio Build Tools**（Windows C++ 编译器）

### 安装步骤

```bash
# 1. 安装前端依赖
cd voice-to-text
npm install

# 2. Rust 依赖会自动通过 cargo 下载，首次编译可能需要几分钟
```

### 下载语音模型

模型文件约 100MB，需要手动下载一次：

```bash
# 方式一：使用自动下载脚本（需要网络，支持代理）
npm run download-models

# 方式二：手动下载后解压到 models/ 目录
# 下载地址：https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-streaming-zipformer-small-bilingual-zh-en-2023-02-16.tar.bz2
```

## 开发流程

### 启动开发服务器

```bash
npm run tauri:dev
```

这会同时启动：
- Vite 前端开发服务器（http://localhost:5173）
- Tauri 桌面应用窗口（带热重载）

### 前端开发

前端代码位于 `src/` 目录，使用 Vue 3 + Pinia：

- `src/stores/app.ts` — 核心状态管理，处理与 Rust 后端的 IPC 通信
- `src/components/Controls.vue` — 录音控制、设备选择
- `src/components/Transcription.vue` — 转写结果展示

### 后端开发

Rust 代码位于 `src-tauri/src/`：

- `lib.rs` — Tauri 命令注册（`start_recording` / `stop_recording` / `list_audio_devices`）
- `audio/capture.rs` — 音频采集抽象，支持 cpal（麦克风）和 WASAPI loopback（系统音频）
- `audio/loopback.rs` — Windows 专属系统音频内录实现
- `stt/recognizer.rs` — sherpa-onnx 在线流式识别器，含重采样逻辑

### 前端构建

```bash
npm run build
```

生成静态文件到 `dist/` 目录，Tauri 打包时会自动引用。

## 使用说明

### 界面说明

1. **设备选择下拉框** — 选择麦克风或 `[系统音频] xxx`（系统内录）
2. **开始录音 / 停止录音** — 控制录音状态
3. **同时保存录音 (WAV)** — 勾选后会在停止录音时自动生成 WAV 文件
4. **转写结果区域** — 实时显示识别结果，灰色斜体为临时结果，白色为确认结果

### 操作流程

1. 打开应用，选择输入设备（默认麦克风）
2. 如需录制系统音频（如看视频时的字幕生成），选择 `[系统音频] xxx` 设备
3. 点击「开始录音」
4. 对着麦克风说话，或播放系统音频
5. 实时识别结果会出现在上方文字区域
6. 点击「停止录音」结束，如勾选了保存选项，WAV 文件会生成在程序同级目录

### 离线使用

本应用**无需联网**即可使用：
- 语音模型完全在本地 CPU 上运行
- 不调用任何云端 API
- 首次编译和模型下载需要网络，之后可完全离线

## 打包与分发

### 打包命令

```bash
npm run tauri:build
```

执行后会在以下目录生成安装包：

```
src-tauri/target/release/bundle/
├── msi/                    # Windows .msi 安装包
│   └── voice-to-text_0.1.0_x64_en-US.msi
└── nsis/                   # Windows .exe 安装包（推荐）
    └── voice-to-text_0.1.0_x64-setup.exe
```

### 打包后的安装文件位置

打包完成后，可直接拿去分发的安装文件位于：

| 安装包类型 | 完整路径 |
|-----------|---------|
| **MSI（推荐）** | `E:\workspace\voice-to-text\src-tauri\target\release\bundle\msi\voice-to-text_0.1.0_x64_en-US.msi` |
| NSIS | `E:\workspace\voice-to-text\src-tauri\target\release\bundle\nsis\voice-to-text_0.1.0_x64-setup.exe` |

> 只需复制其中一个文件给别人即可，无需复制整个项目文件夹。

#### ⚠️ 重要：NSIS 安装包存在 DLL 缺失问题

经实际验证，Tauri v2 生成的 NSIS 安装包（`.exe`）**不会包含**运行时所需的 DLL 文件，导致用户安装后无法运行；而 **MSI 安装包能正确包含所有 DLL**。

| 对比项 | MSI `.msi` | NSIS `.exe` |
|--------|-----------|-------------|
| 安装包大小 | ~8.5 MB | ~2.0 MB |
| 包含 DLL | ✅ 全部包含 | ❌ **缺失所有 DLL** |
| 安装后能否运行 | ✅ 可以直接运行 | ❌ 提示缺少 DLL，无法启动 |
| 推荐程度 | **⭐ 推荐** | 不推荐（当前有 bug） |

**结论：请优先使用 MSI 格式分发，或手动分发绿色版。**

### 打包前检查清单

1. **修改 Bundle Identifier**：`src-tauri/tauri.conf.json` 中的 `identifier` 不能是默认的 `com.tauri.dev`，必须改成唯一的值（如 `com.ap.voicetotext`），否则打包会报错：
   > `The default value com.tauri.dev is not allowed as it must be unique across applications.`

2. **确保模型文件已下载**：`models/` 目录必须存在且完整，否则程序运行时无法加载识别器。

3. **Release 目录说明**：`src-tauri/target/release/` **只有在执行过 `npm run tauri:build` 后才会生成**。之前开发时只有 `target/debug/` 目录。

### 国内网络打包注意事项

在国内打包时，Tauri 需要下载 **WiX**（MSI 工具）和 **NSIS**（安装包工具），这两个工具都从 GitHub 下载。如果不走代理，下载会超时失败。

**解决方式：设置代理后执行打包**

```powershell
# PowerShell
$env:HTTP_PROXY="http://127.0.0.1:7890"
$env:HTTPS_PROXY="http://127.0.0.1:7890"
npm run tauri:build
```

```bash
# Git Bash / WSL
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
npm run tauri:build
```

> 将 `7890` 替换为你自己代理的实际端口号。

### 需要额外拷贝的依赖文件

`sherpa-rs` 在编译时会自动下载 sherpa-onnx 的 C++ 动态库。打包时，以下文件**通常会被 Tauri 自动包含**，但如果手动分发绿色版，需要确认它们与 `voice-to-text.exe` 在同一目录：

| 文件 | 说明 |
|------|------|
| `voice-to-text.exe` | 主程序 |
| `onnxruntime.dll` | ONNX Runtime 推理引擎 |
| `onnxruntime_providers_shared.dll` | ONNX Runtime 共享提供程序 |
| `sherpa-onnx-c-api.dll` | sherpa-onnx C API |
| `sherpa-onnx-cxx-api.dll` | sherpa-onnx C++ API |

> 这些 DLL 位于 `src-tauri/target/release/` 目录下，是 Rust 链接时自动复制过来的。如果手动分发，建议将整个 `target/release/` 目录下所有 `.dll` 文件一并复制。

### 正常打包配置（不含模型）

这是当前项目默认的打包方式，安装包只包含程序和 DLL，模型需要单独提供。

**`src-tauri/tauri.conf.json` 中的 `bundle` 配置如下：**

```json
{
  "bundle": {
    "active": true,
    "targets": "all",
    "icon": [
      "icons/32x32.png",
      "icons/128x128.png",
      "icons/128x128@2x.png",
      "icons/icon.icns",
      "icons/icon.ico"
    ]
  }
}
```

> `targets: "all"` 会同时生成 MSI 和 NSIS 两种安装包。如只需 MSI，可改为 `"targets": ["msi"]`。

**打包命令：**

```bash
npm run tauri:build
```

**打包产物：**

| 安装包 | 路径 | 大小 | 可用性 |
|--------|------|------|--------|
| **MSI `.msi`** | `bundle/msi/voice-to-text_0.1.0_x64_en-US.msi` | ~8.5 MB | ✅ **推荐** |
| NSIS `.exe` | `bundle/nsis/voice-to-text_0.1.0_x64-setup.exe` | ~2 MB | ❌ 缺少 DLL，不推荐 |

**分发时需要额外提供：**
- `models/` 目录（压缩成 zip）

### 分发方式一：MSI 安装包 + 手动放置模型（推荐）

**适用场景**：模型文件较大（~100MB），希望安装包本身保持小巧。

**操作步骤**：
1. 按上面的「正常打包配置」执行 `npm run tauri:build` 生成安装包
2. 把 **`voice-to-text_0.1.0_x64_en-US.msi`** 发给用户（⚠️ 不要发 NSIS `.exe`，会缺少 DLL）
3. **另外单独**把 `models/` 目录压缩成 zip 发给用户
4. 用户双击安装 MSI 后，将 `models/` 解压到安装目录（如 `C:\Program Files\voice-to-text\models\`）

**优点**：安装包体积小，下载快，MSI 包含完整 DLL 可正常运行。
**缺点**：用户需要手动放置模型，多一步操作。

---

### 分发方式二：模型打包进 MSI 安装包（一键安装）

**适用场景**：希望用户一键安装即用，不需要额外手动复制模型文件。

**操作步骤**：

**1. 修改 `src-tauri/tauri.conf.json`，在 `bundle` 节点下添加 `resources`，并将 `targets` 指定为 `msi`：**

```json
{
  "bundle": {
    "active": true,
    "targets": ["msi"],
    "resources": {
      "../models": "models"
    },
    "icon": [
      "icons/32x32.png",
      "icons/128x128.png",
      "icons/128x128@2x.png",
      "icons/icon.icns",
      "icons/icon.ico"
    ]
  }
}
```

> **为什么只打 MSI？** 因为 NSIS 安装包存在 DLL 缺失问题（见上文说明），无法保证程序正常运行。指定 `targets: ["msi"]` 可以跳过 NSIS 打包，节省时间。

**2. 重新打包：**

```bash
npm run tauri:build
```

**3. 打包后的变化：**

| 对比项 | 不包含模型（方式一） | 包含模型（方式二） |
|--------|-------------------|-------------------|
| MSI 安装包大小 | ~8.5 MB | ~115 MB |
| 用户操作 | 安装后手动放 models/ | 一键安装即用 |
| 安装后模型位置 | `安装目录/models/` | `安装目录/models/` |

**优点**：用户零配置，双击安装即可使用；MSI 包含完整 DLL，安装后即可正常运行。
**缺点**：安装包体积暴增到 100MB+，分发和下载较慢。

**4. 代码适配（可选）**

如果模型被打包进安装包，安装后模型会位于安装目录下的 `models/` 文件夹中。你当前的 `lib.rs` 已经支持从**可执行文件所在目录**自动查找 `models/`，所以**不需要改代码**，打包进安装包后可以直接工作。

---

### 如何选择？

| 场景 | 推荐方式 | 说明 |
|------|---------|------|
| 通过网络分发（微信/邮件） | 方式一：MSI + 单独发模型 | 安装包体积小（~8.5MB），适合网络传输 |
| U 盘拷贝 / 局域网共享 | 方式二：MSI 一体安装包 | 一次拷贝，用户零配置 |
| 给用户最简单体验 | 方式二：MSI 一体安装包 | 双击安装即用，无需手动放模型 |
| 模型经常更新 | 方式一：安装包和模型分开更新 | 避免每次模型更新都重发安装包 |

## 常见问题

### 1. 打包报错：`com.tauri.dev is not allowed`

- 修改 `src-tauri/tauri.conf.json` 中的 `identifier`，改为唯一标识（如 `com.ap.voicetotext`）

### 2. 打包报错：`failed to bundle project timeout: global`

- Tauri 需要从 GitHub 下载 WiX / NSIS 打包工具，国内网络可能超时
- **解决**：设置代理环境变量后再打包（见上文「国内网络打包注意事项」）

### 3. 点击开始录音后闪退 / 报错

- 检查 `models/` 目录是否存在且模型文件完整
- 查看 `%APPDATA%\com.ap.voicetotext\logs\` 下的日志文件

### 4. 识别结果为 "[mock] 你好"

- 说明模型加载失败，回退到了 mock 模式
- 检查模型路径是否正确，模型文件是否损坏

### 5. 系统音频设备列表为空

- 仅限 Windows 平台支持系统音频内录
- 确保有活跃的音频输出设备

### 6. 首次编译特别慢

- `sherpa-rs` 会自动下载预编译的 C++ 库（约 50-100MB）
- 首次下载需要网络，之后会从缓存读取

### 7. 用户安装后提示缺少 DLL / 程序无法启动

**现象**：用户双击安装包安装后，打开程序提示缺少 `onnxruntime.dll`、`sherpa-onnx-c-api.dll` 等。

**原因**：Tauri v2 的 NSIS 打包器存在 bug，不会将运行时 DLL 打包进 `.exe` 安装包。

**解决**：
- **方案 A（推荐）**：改用 **MSI 安装包**（`bundle/msi/*.msi`），MSI 能正确包含所有 DLL。
- **方案 B**：直接分发绿色版——把 `target/release/` 下的 `voice-to-text.exe` + 所有 `.dll` 文件 + `models/` 目录一起打包成 zip，用户解压即用。
- **方案 C**：让用户自行安装 [Visual C++ Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe)（但本项目缺失的是 sherpa-onnx 和 ONNX Runtime 的 DLL，不是 VC++ 运行库，此方案无效）。

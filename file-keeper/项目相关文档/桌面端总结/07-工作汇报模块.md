# 工作汇报模块（Work Report Module）总结

## 1. 模块职责一句话

工作汇报模块负责收集用户的工作记录、固定工作、未来计划，按日报/周报模板生成报告，支持 AI 智能总结，并可通过飞书/钉钉/企业微信/Slack 推送到指定目标；同时提供定时任务按 cron 表达式自动生成分发报告。

## 3. 核心数据流 / 调用链路

### 生成报告

```
用户点击「生成报告」
  → WorkReportManagement.vue
    → workReportStore.generateReport(configId)
      → POST /api/client/work-report/reports/generate
        → WorkReportClientController.generateReport()
          → WorkReportService.generate(userId, configId)
            → 查询 ReportConfig、ReportTemplate
            → 查询 WorkLog、FixedWorkCompletion
            → 若 aiEnabled：AiSummaryService.summarize(...)
              → 读取用户 AI 配置 → 调用大模型 API → 失败降级为简单拼接
            → ReportTemplateEngine.render(template, context)
            → 保存 WorkReport
    → ReportViewer.vue 展示 currentReport
```

### 定时调度

```
Spring @Scheduled(cron = "0 * * * * ?")
  → ReportScheduleService.scheduleReports()
    → 扫描所有 enabled 的 ReportConfig
    → shouldTrigger(config, now) 按 cron + timezone 判断是否触发
    → WorkReportService.generate(config.userId, config.id)
    → ReportPushService.pushReport(report.id) 异步推送
```

### 推送报告

```
ReportPushServiceImpl.pushReport(reportId)
  → 查询 ReportConfig、ReportPushTarget 列表
  → 更新报告状态为 PUSHING
  → 遍历目标，根据 platform 选择 PushService 实现
    → FeishuPusher / DingTalkPusher / WeComPusher / SlackPusher
  → 记录 PushDelivery
  → 更新报告状态为 PUSHED 或 FAILED
```

### Git 日志导入

```
用户选择本地 Git 仓库
  → rustApi.fetchGitLogs(repoPath, since, until)
    → invoke('fetch_git_logs')
      → commands/work_report.rs::fetch_git_logs
        → 校验 work-report 模块离线授权
        → 执行 git log 并解析
    → workReportStore.importGitLogs() 逐条创建 WorkLog
```

## 4. 关键状态与 Store 说明

### `workReportStore` (`file-keeper/src/stores/workReportStore.ts`)

- **State**: `logs`、`fixedWorkItems`、`futurePlans`、`templates`、`configs`、`reports`、`currentReport`、`currentDate`、`startDate`、`endDate`、`activeMainTab`、`activeFixedSubTab`、`loading`、`error`
- **计算属性**: `todayLogs`、`sortedFixedWorkItems`、`sortedFuturePlans`
- **核心方法**:
  - `loadToday(date?)` / `loadLogs(start, end)`：加载工作记录
  - `saveLog` / `removeLog`：保存/删除工作记录
  - `loadFixedWork` / `saveFixedWork` / `toggleFixedWork` / `removeFixedWork`：固定工作
  - `loadFuturePlans` / `saveFuturePlan` / `completeFuturePlan` / `cancelFuturePlan` / `removeFuturePlan`：未来计划
  - `loadTemplates` / `loadConfigs` / `saveConfig` / `deleteConfig`：报告配置
  - `generateReport` / `loadReports` / `pushReport` / `removeReport`：报告实例
  - `importGitLogs`：从 Git 仓库导入提交记录

## 6. 核心功能详解

### 工作记录
- 按日期记录工作内容，支持标签、来源（MANUAL/GIT）
- 支持日期范围查询
- 可从本地 Git 仓库批量导入提交记录

### 固定工作
- 周期类型：每日 / 每周 / 每月
- 支持提醒时间、提醒日期、时区、推送平台
- 完成状态在报告生成时作为固定工作完成情况汇总

### 未来计划
- 记录未来待办事项，支持提醒
- 状态流转：PENDING → REMINDED/COMPLETED/CANCELLED

### 报告配置
- 日报/周报类型
- Cron 表达式控制生成周期（内置常用选项）
- 选择报告模板
- AI 总结开关 + 指定 AI 配置（或默认配置）
- 多个推送目标

### AI 总结
- 后端 `AiSummaryService` 根据用户 AI 配置调用大模型
- 支持 qwen / doubao / claude 三种 Provider
- API Key 服务端 AES 加密存储
- 调用失败时降级为简单 Markdown 拼接

### 报告生成
- 基于模板引擎 `{{key}}` 占位符替换
- 上下文包含：ai_summary、logs、fixedWork、report_type、generated_at

### 推送
- 支持飞书、钉钉、企业微信、Slack
- 异步推送，记录每次推送结果
- 失败支持重试（PushRetryService 定时扫描）

## 8. 已知缺口 / TODO

1. **AI 配置缺少独立测试**：新增 `AiConfigController` / `AiConfigService` 尚未补充单元测试。
2. **AI Provider 扩展性**：当前仅支持 qwen/doubao/claude，新增 Provider 需改 `AiSummaryService` switch。
3. **报告模板前端编辑**：当前模板由后端预置或管理后台维护，桌面端未提供模板编辑 UI。
4. **推送重试策略**：已有 PushRetryService，但重试间隔、最大次数、死信处理可进一步细化。
5. **定时任务单机调度**：当前使用 Spring `@Scheduled`，分布式部署时需考虑 Quartz/ ShedLock。
6. **AI 调用 Token 审计**：未记录每次 AI 调用的 Token 消耗与耗时。
7. **报告导出 UX**：导出 Markdown 后无自动打开或提示。
8. **Windows 系统通知未实现**：`show_work_report_notification` 在 Windows 下为预留空实现。

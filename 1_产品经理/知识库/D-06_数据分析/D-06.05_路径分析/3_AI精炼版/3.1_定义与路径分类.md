# 3.1 定义与路径分类

## A.01 核心定义

**路径分析（Path / User Flow Analysis）** 是追踪和分析用户在产品中实际行为序列的方法，记录用户"去了哪里→做了什么→去了哪里"，用于发现真实路径模式、识别导航问题和优化信息架构。

**一句话定位**：漏斗是"我们希望用户走的路"，路径分析是"用户实际走的路"。

## A.04 边界

**路径分析包含**：行为序列追踪、路径发现、Sankey可视化、路径对比、导航优化、信息架构诊断。

**路径分析不含**：指标体系（→D-06.01）、数据采集（→D-06.02）、漏斗分析（→D-06.03）、留存分析（→D-06.04）、归因推断（→D-06.06）。

## I.01 核心术语

| 术语 | 定义 |
|---|---|
| 路径(Path/Flow) | 用户在产品中的一系列有序行为序列 |
| 节点(Node) | 路径中的一个步骤（页面/事件/状态） |
| 边(Edge) | 两个节点之间的转移 |
| 路径深度(Path Depth) | 从起点到当前节点的步数 |
| 主路径(Primary Path) | 用户量最大的路径 |
| 替代路径(Alternative Path) | 非主路径但有意义的其他路径 |
| 环路(Loop) | 用户在若干节点间反复跳转 |
| 回退(Backtrack) | 用户返回上一个节点的行为 |
| 跳出(Exit/Bounce) | 用户在某节点离开产品 |
| Sankey图 | 用流量宽度表示路径规模的可视化方式 |

## I.03 四类路径

### 1. 页面路径（Page Flow）

追踪用户在页面间的跳转。

```
首页 → 搜索结果 → 商品详情 → 购物车 → 结算
```

- **用途**：导航优化、信息架构诊断
- **关键发现**：是否有大量用户走了非预期路径

### 2. 事件路径（Event Flow）

追踪用户触发事件的序列。

```
App打开 → 搜索 → 筛选 → 查看详情 → 收藏 → 分享
```

- **用途**：功能使用链路分析
- **比页面路径更精细**：同一页面上的不同行为可区分

### 3. 状态路径（State Flow）

追踪用户状态转换。

```
未注册 → 注册 → 试用 → 付费 → 流失 → 召回 → 回归
```

- **用途**：用户生命周期分析
- **与留存分析配合**：状态转换率=留存率

### 4. 跨端路径（Cross-Device Flow）

追踪用户跨设备的行为。

```
手机浏览 → 电脑下单 → 手机查看物流
```

- **用途**：多端协同优化
- **挑战**：跨端身份匹配

## 路径粒度选择

| 粒度 | 适用场景 | 优点 | 缺点 |
|---|---|---|---|
| 页面级 | 导航优化 | 简单直观 | 忽略页内行为 |
| 事件级 | 功能使用链路 | 精细 | 数据量大、噪点多 |
| 模块级 | 信息架构诊断 | 适度抽象 | 需要手动定义模块 |
| 状态级 | 生命周期分析 | 高度抽象 | 需要状态定义 |

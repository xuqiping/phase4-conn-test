## 按产品类型裁剪评审门

### C端小功能

| 评审门 | 裁剪策略 |
|---|---|
| 立项评审 | 跳过——PM自行判断即可 |
| 需求评审 | 简化——PM与开发口头对齐+简单文档 |
| Go-NoGo | 简化——QA冒烟通过+PM确认即可 |
| 复盘 | 可选——只对效果异常的功能复盘 |

### C端大功能

| 评审门 | 裁剪策略 |
|---|---|
| 立项评审 | 保留——大功能必须验证方向 |
| 需求评审 | 保留+强化——必须正式评审+文档闭环 |
| Go-NoGo | 保留+强化——灰度策略+AB测试验证 |
| 复盘 | 保留——数据驱动复盘 |

### B端标准交付

| 评审门 | 裁剪策略 |
|---|---|
| 立项评审 | 保留——B端投入大，立项更慎重 |
| 需求评审 | 保留+客户参与——重要需求需客户确认 |
| Go-NoGo | 保留+强化——SLA确认+UAT通过 |
| 复盘 | 保留——客户满意度+续约影响 |

### B端定制项目

| 评审门 | 裁剪策略 |
|---|---|
| 立项评审 | 强化——含合同条款/范围边界确认 |
| 需求评审 | 强化——客户方签字确认需求 |
| Go-NoGo | 强化——客户UAT+内部QA双验收 |
| 复盘 | 强化——项目复盘+合同交付确认 |

### 内部工具

| 评审门 | 裁剪策略 |
|---|---|
| 立项评审 | 简化——需求方与PM直接对齐 |

| 生命周期阶段 | 最重要的评审门 | 原因 |
|---|---|---|
| 导入期 | 立项评审 | PMF未验证，方向决策最关键 |

| 衰退期 | 复盘 | 判断衰退类型与退出策略 |

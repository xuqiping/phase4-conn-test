# BI Analytics Workflow Checklist

在完成 `workflow/bi_analytics_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别BI/数据分析需求场景

- [ ] 已明确场景类型（BI平台选型/报表设计开发/数据分析方法论/自助式分析/AI原生BI/A/B测试设计/数据可视化/国产BI选型）
- [ ] 已识别用户群体（业务人员/数据分析师/管理层/开发者）
- [ ] 已识别数据基础（是否有统一数仓/数据湖/数据治理/语义层）
- [ ] 已提取分析类型（描述性/诊断性/预测性/规范性）
- [ ] 已提取交互方式（静态报表/交互式Dashboard/自然语言查询/Agentic BI）
- [ ] 已提取合规要求（信创/数据安全/移动端）
- [ ] 已识别现有工具（Excel/Tableau/PowerBI/FineBI/Quick BI/自研ECharts/无）
- [ ] 已对照知识库核心洞察完成初步判断（治理不完善→先建治理/同名不同义→语义层/业务人员不会SQL→ChatBI/信创→国产BI/AI深度集成→Agentic BI）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出BI/数据分析方案

- [ ] 如为BI平台选型，架构演进已覆盖（传统三层→湖仓一体→AI原生→Headless BI）
- [ ] 如为BI平台选型，BI引擎对比已输出（Tableau/Power BI/FineBI/Quick BI/Smartbi/Metabase/Superset/Grafana/Redash）
- [ ] 如为BI平台选型，选型建议已给出（金融/政府/信创→FineBI/Smartbi/阿里生态→Quick BI/分析师→Tableau/Power BI/创业公司→Metabase/Superset/监控→Grafana）
- [ ] 如为BI平台选型，语义层独立化方案已说明（同名不同义问题/dbt Semantic Layer/Cube.dev/MCP协议集成）
- [ ] 如为BI平台选型，部署架构模板已给出（湖仓一体BI/实时BI/AI原生BI）
- [ ] 如为数据分析方法论，Gartner四层次模型已覆盖（描述性→诊断性→预测性→规范性）
- [ ] 如为数据分析方法论，用户行为分析三件套已输出（AARRR/漏斗/RFM）
- [ ] 如为数据分析方法论，A/B测试设计框架已说明（实验设计/指标选择/结果分析/陷阱规避/工具选型）
- [ ] 如为数据分析方法论，数据可视化最佳实践已覆盖（图表选型/Dashboard设计原则/常见反模式）
- [ ] 如为自助式分析，四代演进而已输出（IT开发→拖拽BI→AI对话→Agentic BI）
- [ ] 如为自助式分析，NLQ/ChatBI技术架构已覆盖（LLM+语义层+RAG三件套/准确率提升策略/多轮对话/安全与权限）
- [ ] 如为自助式分析，Agentic BI架构已说明（感知层/推理层/行动层/反馈循环）
- [ ] 如为自助式分析，准确率度量已列出（Text-to-SQL准确率/用户满意度NPS/响应时间P99/问题覆盖率）
- [ ] 如为报表开发，开发规范已覆盖（需求分析/原型设计/开发实施/验收上线）
- [ ] 如为报表开发，中国式报表专项已说明（复杂表头/交叉报表/套打报表/国产BI优势）
- [ ] 如为报表开发，移动端报表已输出（设计原则/技术实现/场景）
- [ ] 如为报表开发，报表治理已说明（生命周期管理/目录分类/重复合并/质量评估）
- [ ] 如为国产BI选型，国产BI对比已覆盖（FineBI/Smartbi/Quick BI/信创适配/政府金融市场占有率）
- [ ] 所有核心论断均能在知识库中找到支撑来源

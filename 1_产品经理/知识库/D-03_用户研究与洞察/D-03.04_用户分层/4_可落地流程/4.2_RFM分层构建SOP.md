## RFM分层构建6步SOP

### Step 1：数据准备与清洗

**输入**：用户交易明细表（user_id, transaction_date, transaction_amount）

**处理规则**：
1. 确定统计时间窗口
   - 高频产品（电商/外卖）：近90天
   - 中频产品（服饰/美妆）：近180天
   - 低频产品（家电/旅游）：近365天
2. 剔除异常值
   - 金额异常：超过99分位数的订单单独标记（可能是B端/批发）
   - 退款订单：正向金额记录，退款冲减
3. 生成RFM原始表

```sql
-- RFM原始计算
SELECT
  user_id,
  DATEDIFF(CURRENT_DATE, MAX(transaction_date)) AS recency,
  COUNT(DISTINCT transaction_date) AS frequency,
  SUM(transaction_amount) AS monetary
FROM transactions
WHERE transaction_date >= DATE_SUB(CURRENT_DATE, INTERVAL 90 DAY)
GROUP BY user_id
```

**产出**：`rfm_raw` 表（user_id, R, F, M）

### Step 2：阈值设定（三步校准法）

**2a. 分位数法建基线**
```sql
-- 五分位切分
SELECT
  user_id,
  NTILE(5) OVER (ORDER BY recency DESC) AS R_score,  -- R越小越好→倒序
  NTILE(5) OVER (ORDER BY frequency ASC) AS F_score,  -- F越大越好→正序
  NTILE(5) OVER (ORDER BY monetary ASC) AS M_score    -- M越大越好→正序
FROM rfm_raw
```

**2b. 业务规则微调**
- 对照分位数结果，检查阈值是否符合业务认知
- 例如：R分位数切出"0~7天|8~15天|16~30天|31~60天|61+天"，业务可根据"7天活跃/30天留存"校准为"0~7|8~30|31~60|61~90|91+"

**2c. 决策树验证**
- 用scikit-learn DecisionTreeClassifier(max_depth=3)以RFM为特征、目标变量（如是否付费/是否流失）为标签
- 决策树的分裂点即为数据驱动的天然阈值
- 将决策树阈值与2a/2b对比，取三者共识

**产出**：R/F/M各维度的分段阈值 + 得分映射规则

### Step 3：RFM评分与层级划分

**评分规则**：
- 每维度1~5分（五分位法）或1~3分（三分位法）
- R: 越小分越高（最近购买=高分）
- F: 越大分越高（频次多=高分）
- M: 越大分越高（金额大=高分）

**层级划分**：
- 简化版：R/F/M各按均值二分→高/低→2×2×2=8层（经典RFM八类）
- 精细版：R/F/M各按三分位→3×3×3=27层→按业务逻辑合并为8~12个可运营层级

**产出**：`rfm_scored` 表（user_id, R_score, F_score, M_score, segment_name, segment_code）

### Step 4：层级验证

**层间差异检验**：
```python
from scipy import stats
# 对每层ARPU/留存率做ANOVA
f_stat, p_value = stats.f_oneway(
    df[df.segment=='重要价值']['arpu'],
    df[df.segment=='重要保持']['arpu'],
    ...
)
# p < 0.05 → 层间有显著差异
```

**稳定性检验**：
- 连续3个月分别跑RFM分层
- 计算用户层级保持率：同一用户在3期中保持同层的比例
- 保持率≥70%为稳定

**产出**：验证报告（p值 + 稳定性系数 + 问题层级标记）

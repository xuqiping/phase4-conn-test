## 模板 需求池看板

### 一、Jira配置方案

**Issue Type层级**：Epic → Story → Sub-task

**自定义字段**：
- 来源(Single Select: 用户反馈/销售/内部/竞品/数据/管理层)
- KANO类别(Single Select: 必备/期望/魅力/无差异/反向)
- 紧急度(Single Select: P0/P1/P2/P3)
- RICE Score(Number)
- 业务价值(1-5)

**JQL看板查询**：
- 待评估：`status = "新建" ORDER BY created DESC`
- 待排期：`status = "确认" ORDER BY RICE_Score DESC`
- 本Sprint：`sprint = "Sprint XX"`
- 老化需求：`status in ("确认","搁置") AND updated < -90d`

**Board配置**：
- 列：新建 → 评估 → 确认 → 排期 → 开发 → 验收 → 上线
- Swimlane：按Epic分组
- Quick Filter：P0/P1紧急 / KANO必备 / 本Sprint

### 二、Notion配置方案

**数据库属性**：

| 属性名 | 类型 | 说明 |
|---|---|---|
| 需求ID | Title | 唯一编号 |
| 描述 | Text | 需求详细描述 |
| 状态 | Status | 新建/评估/确认/排期/开发/验收/上线/归档 |
| Epic | Relation | 关联Epic数据库 |
| 来源 | Select | 用户反馈/销售/内部/竞品/数据 |
| KANO | Select | 必备/期望/魅力/无差异/反向 |
| 优先级 | Select | P0/P1/P2/P3 |
| Story Point | Number | Fibonacci估算 |
| Sprint | Relation | 关联Sprint数据库 |
| 进入日期 | Date | 需求创建日期 |
| 最后更新 | Date | 最近更新时间 |

**视图推荐**：
- Board视图：按状态分栏的看板
- Table视图：全量需求的表格视图
- Calendar视图：按排期时间线展示
- Gallery视图：按Epic分组的卡片视图

### 三、Google Sheets轻量方案

适合需求量<50的小团队：

```
| ID | 标题 | 描述 | 来源 | KANO | 状态 | 优先级 | StoryPt | Sprint | 进入日期 | 备注 |
|----|------|------|------|------|------|--------|---------|--------|----------|------|
| REQ-001 | 一键导出 | 用户可一键导出... | 用户 | 期望 | 排期 | P1 | 5 | S12 | 2026-07-01 | - |
```

**条件格式**：状态列按颜色区分，优先级P0红色高亮，超90天未更新灰色。

### 四、使用规则

1. **所有需求进入统一池子**——不允许"空中需求"（微信群/口头的必须补录）
2. **每周至少更新一次**——需求池不能是"一年不管的死池"
3. **退役需记录原因**——不做的需求也要留底（避免重复提交）
4. **定期Review工具选型**——需求量变化时可能需要升级管理工具

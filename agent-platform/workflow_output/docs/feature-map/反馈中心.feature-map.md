## 2. 关键调用链

### 建议审核全链（抢态+通知+铃铛）
```
admin 点「采纳」→ AdminFeedbackView.review
 → POST /api/feedback/admin/suggestions/{id}/review
 → FeedbackService.reviewSuggestion
 → FeedbackSuggestionMapper.reviewIfStatusIn(id, to=ADOPTED, from=[PENDING,REJECTED])   ← 条件 UPDATE 抢态
   · 0 行 → 409「已被其他管理员处理」（CLOSED 终态先判，也 409）
   · 1 行 → FeedbackNotificationService.notify(userId, SUGGESTION_REVIEWED, 摘要文案)
用户侧：FeedbackNotificationBadge 每 3s GET /notifications/count（部分索引）
 → 点击通知 → POST /{id}/read + router.push /feedback?tab=suggestions
 → FeedbackCenterView watch route.query.tab 切到建议 tab，详情 modal 见官方回复
```

### FAQ 公开检索（脱敏在「字段不存在」层）
```
FeedbackCenterView FAQ 输入 → 300ms 防抖 → GET /questions/faq?kw=
 → FeedbackQuestionMapper.pageFaq：WHERE is_public=TRUE AND (title LIKE 'kw%' ESCAPE '\' OR content LIKE ...)
   SELECT 只挑 id/title/content/answer/answered_at —— SQL 层就不取 user_id/username
 → FaqVO 天然无提问人字段（反射单测钉死字段清单）
```

### 帮助文章（slug 直达 + 硬删释放）
```
admin 新建/编辑（slug 创建后锁定）→ 发布开关 setPublished
用户：GET /help/articles（仅目录字段，无 content_md 大字段）→ 点文章 GET /help/articles/{slug}
 → getPublishedBySlug：未发布/不存在统一 404「不存在或未发布」（不泄露草稿存在性）
admin 删除 → physicalDeleteById 真删行 → 同 slug 可立即重建（单测钉死）
```

## 3. 表与 SQL 注解（V141，生活比喻）

| 表 | 用途 | 关键字段/约束 | 比喻 |
|---|---|---|---|
| `feedback_suggestions` | 用户建议单 | `status` CHECK(PENDING/ADOPTED/REJECTED/CLOSED)；`username` 快照（改名不影响历史）；`attachment_file_ids` JSONB ≤3 | 意见箱里的信：署名照抄当时的名字，附件钉在信上 |
| `feedback_questions` | 用户提问单 | CHECK(OPEN/ANSWERED/CLOSED)；`is_public` 决定是否进 FAQ；`idx_question_faq` 部分索引只收公开已答 | 问诊室：医生答完可贴到公示栏（贴时隐去病人姓名） |
| `help_articles` | 说明文章 | `slug` 唯一 + 正则 `^[a-z0-9-]+$`；`published` 开关 | 公告栏文章：英文短链是门牌号，拆掉门牌（硬删）才能给新文章用 |
| `feedback_notifications` | 审核/回答通知 | `type` CHECK 两种；`read_at` NULL=未读；`idx_feedback_notify_unread` 部分索引只收未读 | 快递待取列表：取走（已读）就不进待取索引，数起来飞快 |

**状态机**：建议 PENDING→ADOPTED/REJECTED/CLOSED；ADOPTED↔REJECTED 可改判（重发通知）；CLOSED 终态。提问 OPEN→ANSWERED→CLOSED；首答通知、改答不通知。全部流转走条件 UPDATE，0 行=409。

## 4. 技术原理大白话

- **抢态（条件 UPDATE）**：`UPDATE ... SET status='ADOPTED' WHERE id=? AND status IN (...)`——两个管理员同时审一条，数据库只放行一个，另一个改 0 行报 409。像抢火车票：同一座位只出一张票。
- **部分索引**：`WHERE read_at IS NULL` 只给未读通知建索引。已读几万条不占索引，铃铛 count 恒快。像超市只给「未结账」篮子留通道。
- **脱敏字段不存在层**：不是「查了再抹掉」，而是 SQL 根本不 SELECT、VO 根本没这个字段——想泄露都没路。
- **username 快照**：提交时把用户名抄进单据。用户改名后，历史单据仍显示当时名字，admin 对账不穿帮。
- **markdown html:false**：渲染管线不放行原文 HTML，`<script>` 变成纯文本展示，XSS 天然免疫（vitest 有专例）。
- **硬删文章**：别的表软删（deleted 标记），文章真删——因为 slug 唯一索引占坑，软删会永远挡住同名重建。

## 5. 踩坑批注

- **JSONB 附件列**：实体要 `@TableName(autoResultMap = true)` + 字段 `typeHandler = JsonbStringTypeHandler.class`，否则 SELECT 回读是 String 不是 List。
- **限流分动作**：建议 `feedback_suggestion`、提问 `feedback_question` 分开计数（各 5 次/分/用户），互不挤占。
- **spec 偏差记录**：§7.5 原写「FAQ 脱敏为用户xxx」，实现升级为字段不存在层（更强），spec 文字未回改，以此为准。

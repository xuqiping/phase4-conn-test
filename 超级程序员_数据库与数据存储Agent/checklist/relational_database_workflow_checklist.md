# Relational Database Workflow Checklist

在完成 `workflow/relational_database_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别关系型数据库需求场景

- [ ] 已明确场景类型（数据库选型/架构设计/SQL优化/高可用方案/国产替代/迁移升级）
- [ ] 已识别业务类型（互联网OLTP/金融交易/政企政务/微软生态/SaaS多租户）
- [ ] 已提取性能要求（QPS目标、延迟P99、数据量、并发连接数）
- [ ] 已提取高可用要求（RTO/RPO、金融级可靠性、同步/异步复制）
- [ ] 已提取合规约束（信创要求、等保等级、数据不出域）
- [ ] 已识别现有数据库类型和迁移需求
- [ ] 已对照知识库五大方向完成初步判断（MySQL/PostgreSQL/Oracle/SQL Server/国产库）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出关系型数据库方案

- [ ] 如为数据库选型，五大方向对比已覆盖（性能特征/功能完备性/生态与工具/运维成本/信创适配）
- [ ] 如为数据库选型，最终推荐附决策理由和关键趋势标注（MySQL/PG开源主导/AI向量扩展/信创国产替代加速）
- [ ] 如为架构设计，存储引擎选型已说明（InnoDB Buffer Pool/MVCC/Redo Log机制）
- [ ] 如为架构设计，高可用架构已覆盖（主从复制/半同步/MGR组复制/Patroni/读写分离）
- [ ] 如为架构设计，分库分表策略已给出（ShardingSphere/分片键设计/全局ID生成）
- [ ] 如为架构设计，NewSQL替代路径已评估（TiDB/OceanBase vs 传统分库分表）
- [ ] 如为SQL优化，执行计划分析方法已输出（EXPLAIN解读/type优化目标）
- [ ] 如为SQL优化，索引优化策略已覆盖（B+Tree原理/覆盖索引/最左前缀/ICP）
- [ ] 如为SQL优化，常见慢查询优化模式已给出（全表扫描→索引/文件排序→覆盖/临时表→重写）
- [ ] 如为国产替代，国产库选型对比已覆盖（OceanBase/达梦/人大金仓）
- [ ] 如为国产替代，迁移评估方案已说明（兼容性测试/性能基准/数据一致性校验）
- [ ] 如为国产替代，迁移路径已给出（双写并行→灰度切换→老库下线）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 输出内容无知识性错误
- [ ] 已向用户交付最终答案

## Overall

- [ ] 工作流中的所有步骤已按顺序执行，没有跳过
- [ ] 每一步都已与其检查清单部分进行交叉验证
- [ ] 没有在任何检查清单部分通过前提前进入下一步
- [ ] `task/current_task.md` 已更新完成记录
- [ ] 所有 `[参考: ...]` 标注均指向存在的知识库文件

## 设计令牌与语义体系

### 两层令牌架构

**核心范式**：令牌分两层——**原始令牌（Primitive Token）** 承载值，**语义令牌（Semantic Token）** 承载决策意图。二者通过映射关系解耦。

```
原始层: color-blue-500 →  #1677FF
                ↕ 映射
语义层: color-interactive-primary → color-blue-500
                ↕ 映射
组件层: button-primary-bg → color-interactive-primary
```

| 层级 | 职责 | 修改代价 | 典型条目 |
|---|---|---|---|
| 原始层 | 值定义（色板/间距/字体库） | 低（仅改值） | `blue-500`, `spacing-4` |
| 语义层 | 决策意图（交互色/状态色/层级色） | 中（改映射） | `color-interactive-primary` |
| 组件层 | 组件属性（按钮背景/边框/阴影） | 高（组件级影响） | `button-primary-bg` |

[来源:W3C Design Tokens Community Group规范草案 | 置信度:🔍高 | 2025]

### Schema-As-Code（2025-2026前沿）

**核心思想**：将设计规范写成机器可读的YAML/JSON契约，使AI工具、代码库、设计工具共享同一份真值源（Single Source of Truth）。

```yaml
# schema-as-code 示例
tokens:
  color:
    interactive:
      primary:
        value: "{color.blue.500}"
        description: "主要交互元素背景色"
        immutable: true  # 不可变边界
    status:
      error:
        value: "{color.red.500}"
        description: "错误/危险状态色"
  spacing:
    base: 4px
    scale: [1, 2, 3, 4, 6, 8, 12, 16]
```

> **不可变边界（Immutable Boundary）**：语义令牌一旦定义，其语义不可被AI生成内容覆盖——防止AI"创意"打破品牌一致性。[来源:woshipm.com 语义翻译者方法论 | 置信度:📚中 | 2026-07]

### AI辅助令牌命名与一致性检查（2025-2026新范式）

**痛点**：令牌命名混乱（`primary-blue`vs`blue-primary`vs`brand-main`）→ 团队认知混乱 → 规范被弃用。

**AI辅助方案**：
1. **语义快照诊断**：AI扫描现有令牌库，识别命名冲突与语义断层 [来源:woshipm.com | 置信度:📚中 | 2026-07]
2. **自动命名建议**：基于W3C规范+团队命名约定，AI生成一致性命名方案 [来源:CSDN AI辅助Design Token命名 | 置信度:📚中 | 2026-07]
3. **跨工具同步校验**：Figma Variables ↔ Token Studio ↔ 代码变量三方一致性检查

### 暗色模式的令牌策略

**关键原则**：语义令牌必须在原始层做暗色映射，而非在组件层。

```
✅ 正确: color-surface-primary → 暗色模式自动映射 dark:gray-900
❌ 错误: button-bg → 手动为每个组件设暗色值
```

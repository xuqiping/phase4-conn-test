# 5.5 OpenAI的混合收入口径：订阅+API双模式的AI-ARR新范式

## 基本信息

- **时间**：2023–2026
- **主角**：OpenAI（Sam Altman / 产品团队）
- **产品**：ChatGPT / OpenAI API

## 背景

OpenAI是AI时代第一个大规模面临"订阅+按量"混合收入口径的公司。ChatGPT Plus是月度订阅（MRR），但API是按Token消耗计费（Usage Revenue）。两种完全不同的计费模式如何合并成统一的"AI-ARR"口径，成为2025-2026年AI行业最紧迫的口径问题。

## 混合收入口径拆解

### 收入构成

| 收入类型 | 计费方式 | 口径特征 | 占比(2025估) |
|---|---|---|---|
| ChatGPT Plus/Pro订阅 | 月费($20/$200) | 经典MRR | ~40% |
| API Usage | 按Token消耗 | 按量，高波动 | ~30% |
| ChatGPT Enterprise/Team | 年度合同 | 类SaaS ARR | ~20% |
| 其他（Fine-tuning/插件等） | 混合 | 非经常性+经常性 | ~10% |

### "AI-ARR"口径的争议

| 口径方案 | 计算 | 特点 | 支持者 |
|---|---|---|---|
| 方案A：纯订阅ARR | 只计入订阅+Enterprise MRR×12 | 口径清晰，但忽略API | 传统SaaS分析师 |
| 方案B：订阅ARR+年化API | MRR×12 + API最近月收入×12 | 含Usage但波动大 | AI行业从业者 |
| 方案C：订阅ARR+承诺API额度 | MRR×12 + 客户承诺的年度API额度 | 最稳定但低估潜力 | 企业客户视角 |
| 方案D：TTM Revenue | 滚动12个月总收入 | 最简单但混入非经常性 | PR/媒体 |

**行业趋势(2025-2026)**：方案B（订阅ARR+年化API消耗）正成为"AI-ARR"的半标准口径，但尚未被审计师完全接受。

## API Usage的收入口径特殊性

### 与传统订阅的差异

| 维度 | 传统SaaS订阅 | API Usage |
|---|---|---|
| 可预测性 | 高（月费固定） | 低（随客户用量波动） |
| NRR驱动因素 | 升级/增座席 | 用量增长（类似Snowflake） |
| 收入确认 | 按月确认 | 按消耗确认 |
| 流失表现 | 明确取消 | 用量萎缩（隐性流失） |
| CAC Payback | 可计算 | 难计算（首月API消耗低后续可能飙升） |

### "隐性流失"问题

API客户通常不会正式"取消"，但可能大幅减少API调用量。这种"隐性流失"导致：
- 传统Churn Rate严重低估实际流失
- NRR按订阅口径计算可能虚高（API客户仍在订阅列表中但已大幅降量）
- 需要引入"Usage NRR"作为补充指标

## 教训与启示

1. **AI产品的收入口径不能照搬SaaS**——Token计费+订阅混合=需要两口径并行
2. **"AI-ARR"是2025-2026年正在形成的行业标准**——PM需要跟踪口径标准化进程
3. **API Usage的"隐性流失"是最大口径盲区**——只看订阅流失会严重高估客户健康度

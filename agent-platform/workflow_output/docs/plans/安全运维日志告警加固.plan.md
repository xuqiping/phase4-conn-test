## 一句话目标
百万级平台「铜墙铁壁」：封号即时生效（堵真实洞 JwtFilter 不查 status）+ 8 类异常自动检测 + 分级自动响应 + 钉钉告警 + 日志 6 个月合规。

## 规格决策锁（来自 spec）
- 路线1·单机一体化（B 档应用层纵深），不引 Kafka/SIEM/UEBA-ML/CDN-WAF
- 分级自动响应：高危自动封 IP/锁账号，中危只告警
- 8 类检测：暴破撞库 / 越权注入 / 高频爬虫 / 异地行为 / 资源滥用计费外带 / Prompt 注入 / Token 盗号 / 特权变更
- 告警只钉钉（复用 Alertmanager 适配器）
- 封号=禁登录+删 session+ban 标记兜底（不连带封 IP）
- audit 永久不动 / security_events 半年运维可物理删 / 磁盘日志抬到 6 个月

## 规则码 vs 动作码（口径）
- **检测规则码**（13 个，写 security_events.event_type）：4 热（LOGIN_BRUTE_FORCE / CREDENTIAL_STUFFING / SQLI_PROBE / XSS_PROBE / PATH_PROBE / RATE_BURST）+ 9 冷（IDOR_PROBE / IMPOSSIBLE_TRAVEL / OFF_HOURS_SENSITIVE / DATA_EXFIL / POINTS_ABUSE / MEDIA_ABUSE / PROMPT_INJECTION / TOKEN_REUSE / PRIVILEGE_CHANGE）
  > 注：SQLI/XSS/PATH 是 3 个独立码（注入细分），热规则按「类」算 4 类（暴破/撞库/注入/高频），按「码」算 6 个。主索引「4 热/9 冷」按码计 = 共 15 检测码。
- **动作码**（写 security_events.auto_action）：NONE / IP_BLOCKED / ACCOUNT_LOCKED / ACCOUNT_BANNED / TOKEN_REVOKED（非检测规则，是响应结果）

## 全局技术坑点预判（详见各子 plan）
| 坑 | 场景 | 规避 |
|---|---|---|
| Redis QPS | 每请求 INCR 限流 + ban 标记 hasKey | Lua 脚本合并 INCR+EXPIRE；ban 标记仅封号用户存在（正常用户 hasKey miss 快） |
| 告警判定扫表 | 若查 audit_logs/llm_usage_logs | **禁扫表**，全走 Redis 窗口计数（埋点瞬间累加） |
| Redis 故障降级 | 限流/告警/ban 标记 | 限流降级放行（可用性 > 限流）；ban 标记降级=放行但 DB status 仍阻新登录/refresh |
| 单点登录开关耦合 | `AUTH_SINGLE_SESSION_ENABLED=false` → isCurrent 恒 true → 删 session key 无效 | 独立 `ban:user:{uid}` 标记，JwtFilter 单独校验，与单点登录解耦 |
| 告警风暴 | 异常持续刷量 | raise 去重（rule+user+ip 窗口 TTL）+ level 限速 |
| 误拦/误封 | 阈值过低误伤；admin 误封自己/唯一超管 | 阈值偏宽松 + 后台热调；封号自封/最后超管防护 |
| SSE 流不计入限流 | chat 流式应答 | 限流挂「提交」端点，非流端点 |
| ip2region 精度 | 异地检测误报（移动切 IP） | MEDIUM 只告警不封，可观察后调阈值 |

## 安全检查清单（P3 逐项验证）
- [ ] **鉴权**：封号 `user:manage`；3 新接口 `security:event:read`/`security:ban:manage`/`security:rule:manage`；限流对所有认证用户生效
- [ ] **输入校验**：封号 status ∈ {ACTIVE,DISABLED,LOCKED,BANNED}；reason 长度限；告警筛选参数 #{} 防注入；注入特征正则白名单
- [ ] **越权**：普通用户不能调封号/告警/规则接口（权限门控 + 测试）
- [ ] **审计**：封号/解封/规则开关/阈值改/手动封 IP 全走 @AuditLog
- [ ] **脱敏**：security_events detail_json 过 LogMasker；钉钉卡片不透传 PII；话术固定（不泄露「被封」）
- [ ] **防滥用**：封号防自封/最后超管；限流阈值可配；webhook URL 不进日志
- [ ] **不可篡改**：security_events 独立表，运维可物理删（与 audit V91 REVOKE 隔离）

## 功能联动点清单（详见各子 plan）
- 封号 ↔ 会话（删 session key → 下请求 401）；反向：解封须重登
- 封号 ↔ 前端列表（状态 Tag 变「封号」+ 按钮「解封」）
- 限流 ↔ 告警（429 累计达阈值 → RATE_BURST 事件）
- 限流 ↔ 前端（429 toast）；SSE 流不触发
- 告警 ↔ 侧栏 badge（轮询 60s）
- 告警 ACK ↔ 状态（条件 UPDATE 幂等）
- 封号 ↔ 在途任务（不中断已提交，仅阻新请求）
- 解封 ↔ ban 标记 key（删 key，用户须重登）
- 规则开关关 ↔ AutoResponder（总闸关=只告警不封）

## 运维考量清单（7 类，详见各子 plan「运维考量」节）
- 可观测：限流/告警/封号打 WARN 含 userId+traceId；BizMetrics 新增 `apiRateLimited`/`security_event_raised`/`ip_blocked`/`account_banned`
- 配置开关：`security.rate.enabled` / `security.response.auto_ip_block` / `security.response.auto_account_lock` / `security.alert.webhook.url` / 各规则开关+阈值（env 默认 + system_settings 热调）
- 可回滚：V96 纯新增表（DROP 即回滚）；拦截器/规则开关关即等效回滚
- 降级：Redis 故障限流放行；webhook 故障不阻 raise
- 运维入口：封号（用户管理页，已存）/ 告警 ACK（安全事件中心）/ 手动封解 IP（封禁管理页）/ 规则调阈值（规则配置页）
- 告警阈值：默认值见各子 plan；发给 admin 站内 + 钉钉（高危）
- 容量：security_events 半年清理任务；ip_blacklist/login_attempts 过期清理；logback 磁盘扩容（APP 12GB）

## 术语表
| 术语 | 大白话 | 案例 |
|---|---|---|
| 封号即时失效 | admin 封号后用户已签的 access token 不等 15min 过期，下一请求即 401 | 封号 → 删 session key + ban 标记 → JwtFilter 拒 |
| ban 标记 key | 独立于单点登录的 Redis 键 `ban:user:{uid}`，封号时设，JwtFilter 校验它 | 单点登录关时 sid 比对失效，ban 标记兜底 |
| 滑动窗口限流 | Redis ZSET 按时间戳记最近 N 秒内次数，超阈值拒 | per-用户 per-路由 600/min |
| 固定窗口限流 | Redis INCR + EXPIRE，统计「当前窗口内次数」 | 登录 per-IP 20/5min |
| 告警去重 | 同 rule+user(+ip) 去重窗口内只 1 条告警，防风暴 | 5min 内同 IP 暴破只告 1 次 |
| ACK | admin 在安全事件中心标记「已处理」，从未处理 badge 减 | 两人并发 ack → 条件 UPDATE 幂等 |
| 热路径/冷路径 | 热=同步当场拦(<1ms)；冷=异步秒级算 | 热:限流/注入；冷:异地/基线 |

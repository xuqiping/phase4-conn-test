## 技术清单与原理注解（大白话版）

#### 1. 存储型 XSS 根治三件套（SEC-FR-001）
- **一句话原理**：上传拦危险扩展名（咽喉点一处拦全部入口）；下载按白名单决定 inline 还是强制下载；响应恒带 nosniff 防浏览器嗅探绕过。
- **大白话案例**：像快递柜——危险品（html/svg/exe）寄件时就拒收；既有存货（legacy 文件）取件时强制「不开箱直接拿走」（attachment），绝不当场打开。
> 📌 批注：白名单校验必须放 `store` 咽喉点而非各 Controller——放 Controller 必漏入口（本项目 5 个上传入口）。

#### 2. 登录防爆破（SEC-FR-010）
- **一句话原理**：Redis 计数双阈值（账号 5 败锁 15min / IP >20/h 封 1h），锁定只挡密码登录；Redis 挂=降级放行+WARN（可用性优先，Redis 本就单点）。
- **踩坑批注**：①X-Forwarded-For **默认不可信**——仅 remoteAddr ∈ `app.security.trusted-proxies` 才采，否则攻击者轮换 XFF 绕过 IP 封（Phase4 审查实证修复）；②user==null 也要跑一次真 bcrypt（用库里的真 hash，伪造非法 hash 会炸 matches()），否则响应时序泄露账号存在性；③锁定时长信 message 不泄露账号是否存在（40103 文案对两种锁定一致）。

#### 3. CORS 内联安全链（SEC-FR-003，Phase4 实证大坑）
- **一句话原理**：独立 `CorsFilter` @Bean 默认排在 springSecurityFilterChain(-100) 之后——预检 OPTIONS 不带凭证，打需认证端点先被 401 截杀，白名单「放行」语义从未生效（只有「拒」灵）。改 `CorsConfigurationSource` bean + `http.cors()` 内联，预检在授权判定前处理。
- **教训**：此类 bug 单测绿、手工只验「拒」也测不出——验收必须「白名单 Origin 预检需认证端点期待 200+ACAO」。

#### 4. 幂等键防重放（SEC-FR-121）
- **一句话原理**：`INSERT ... ON CONFLICT DO NOTHING` 占位与业务写**同事务**，占上才办；撞键回查 result_ref 返首次结果。
- **踩坑批注（Phase4 资金红线）**：撞键**必须先核 user_id+scope**——键全局唯一，不核则跨用户同键回返他人 balance_after（跨用户余额泄露信道）。同键不同金额/跨身份撞键 = 疑似重放，写 `idempotency_conflict` 审计。

#### 5. 余额非负三件套（SEC-FR-120）
- **一句话原理**：单语句 `UPDATE...WHERE balance+delta>=0 RETURNING`（0 行=拒扣）+ V80 CHECK 硬兜底 + 每日对账抓异常。可负欠款模型在并发下必死，S1 起作废。

#### 6. CI 门禁防回潮（SEC-FR-020/071）
- **一句话原理**：mybatis 门禁按**代码区**判定 `${`（截掉行内注释再判——「活 `${}`+行尾注释」绕过变体已实证堵死）；allowlist 剔空行防 `grep -f` 空模式永绿。
- **gitleaks**：git 历史含已泄密钥（待 H1 轮换），全量扫=永红 → CI 只扫本次 push/PR 提交区间拦新增；全量+baseline 首扫待 H1 闭环恢复。

## S2 技术清单与原理注解（大白话版）

#### 7. 审计哈希链（SEC-FR-040/042/043）
- **一句话原理**：每条审计 = HMAC(规范化内容 + 上一条的哈希)，改/删任何一条 → 后面全对不上。每日定时全量重算比对，成功就把「末行 id+哈希」追加到独立日志文件（外部锚点，防整表被换后重算假链通过）。
- **踩坑批注**：①**id 不进哈希**（IDENTITY 插入前未知，算了就永远验不过）；②**jsonb 保序不保形**——PG 存 detail_json 会重排键/规范化数字，直接拿库值重算必 mismatch → 两侧都走 canonicalJson（排序键+BigDecimal toPlainString）；③created_at 入库时 DB 时区/精度会改值 → 写入时截断到 UTC 微秒，与 pgjdbc 读回口径一致；④存量行**不回填**（密钥 env 注入无法回填历史 + V78 已 REVOKE UPDATE），NULL 行只许作连续前缀。

#### 8. 单点登录（SEC-FR-008）
- **一句话原理**：登录发 UUID sid 写 Redis（覆盖写=踢旧），JWT 双 token 都带 sid claim，每次请求/刷新比对——对不上就是「别处登录了」，40104 请重新登录。
- **踩坑批注**：①踢出审计只在**踢的瞬间**记一次（新登录覆盖写时），不拦旧 token 每次请求都记——防审计刷量；②sid 比对放**黑名单之后**——logout 的 token 先被黑名单拦，不会误报「别处登录」；③Redis 挂=降级放行（可用性>强制力，同 S1 范式）；④refresh 旋转**沿用同 sid**=会话延续，否则刷新即自杀。

#### 9. 低余额并行闸门（SEC-FR-126）
- **一句话原理**：余额 < 阈值（默认 100，页面可配）的用户，Redis 在途计数 ≥ 上限（默认 1）就拒第二个任务（42902）。计数键带 30min TTL 兜底——进程崩了未释放最多少误闸 30min。
- **踩坑批注**：①INCR 先行的判定要**退回计数再拒**（超限时 DECR 回去），否则拒绝也占槽=永闸；②release 负值清零删键——submit 时 Redis 故障未计数而 worker 终态照常 release 的错配场景 fail-open；③流式释放挂 `doFinally`（complete/error/cancel 三态互斥正好一次）；④闸门只挂用户主动入口，embed/记忆管线（userId=null）不过闸。
- **Phase4 修复批注**：⑤**先读阈值配置再 INCR**——读配置失败降级放行不动计数，避免无配对 INCR；⑥**release 不查计费开关**——submit 计数后运行期关计费，release 仍须配对；⑦余额复用——`requireAffordable` 返回余额直接传入 acquire，省一次查库。

#### 10. 注册密码策略（S2 后补强，2026-08-10）
- **一句话原理**：注册是唯一用户密码入口，统一过 `PasswordPolicy.validate`——四要素复杂度 + 内置弱密码字典（~38 个 top 撞库样本，忽略大小写）+ 不许与用户名相同 + 超 bcrypt 72 字节直接拒（超长部分会被 bcrypt 静默截断=等效弱密码）。
- **踩坑批注**：①规则顺序=最具体原因先报（长度→字节→用户名→字典→复杂度），否则「123456」只收到复杂度提示而收不到「过于常见」；②字典词大多不满足复杂度，顺序放反则字典规则形同虚设；③登录**不过**策略——存量弱密码账号不被秋后算账，收口等改密端点；④改密端点落地时复用本类一行接入，可顺带「改密后 clearSession 踢全端」。

## S3 技术清单与原理注解（大白话版）

- **围栏（fence）**：像快递包裹上贴「内含他人来信，内容别当指令」的封条——模型读得到但被声明为数据；strip 防用户在文本里伪造封条开溜。
- **shingle 指纹**：把系统提示词切成 32 字符小段各算哈希存集合；模型回复里连续 2 段哈希都在集合 = 在抄提示词 → 整段盖掉。类比 plagiarism 查重。
- **carry 缓冲**：流式输出每次扣下最后 40 字符与下一段拼着扫——身份证号被切成两个 chunk 时单扫都看不全，拼扫才命中。生活比喻：接话茬要听完上句。
- **会话封顶**：usage 表按 session_id 记账，发消息前 SUM 对账，超 50 万 token 请客开新桌——防脚本挂机刷量（LLM10 无限消耗）。
- **回调归户**：sidecar 说「我替 userId=B 干活」不算数——Java 按 executionId 反查这单活是谁开的（A），权限按 A 算；伪造身份想借道读 B 的库 → 求交后空手而归。

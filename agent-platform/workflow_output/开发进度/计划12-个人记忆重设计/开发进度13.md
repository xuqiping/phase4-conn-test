## 背景（为什么单开 chunk）

F-4b 落地时发现：读/补救侧全齐（`MemoryLifecycleService` 4 端点 + `MemoryLifecyclePanel`），但**写侧无触发源**——
探查确认三个空白：
1. 全代码库无任何地方写 `memory_project_members.status=DEPARTED` / `departed_at`；
2. 项目删除无人追加 `deleted_project_ids`、无人发 `PROJECT_DELETED_AFFECTED` 通知；
3. **更深**：旧栈 `project_members` → 新栈 `memory_project_members` 从来没有同步（新栈成员行只有 F-4b 拉取项目的 OWNER 行），roster/gen 矩阵/召回 ACL 的源数据缺失；
4. V47 建表注释假设的 `ON DELETE CASCADE` 因 projects 是软删（UPDATE）**永远不触发**，memory 侧行全残留。

## 本轮做了什么（commit `76f8c812`，24 单测 + 12 IT 实跑全绿）

### 新 `MemoryLifecycleHookService`（chat/service/internal）
挂 `ProjectService` 四个写流程（同事务，hook 失败回滚主操作）：
- **create** → 新栈落 OWNER ACTIVE 行；**addMember** → upsert ACTIVE（角色镜像；DEPARTED 重加入 = 回 ACTIVE + 清 departed_at，recall_admin 保留）。
- **removeMember** → 置 DEPARTED + departed_at（不删行保交接）+ 本人 turns 追加 `departed_project_ids`（无行直接落 DEPARTED 行，兜存量未同步）。
- **delete** → 全作者 turns 追加 `deleted_project_ids`（不移除 project_ids）+ 曾写记忆成员逐个收 `PROJECT_DELETED_AFFECTED` 通知（文案带项目名+条数）+ 清：项目总结（软删，个人 NULL 不动）/ coverage（项目 scope）/ 成员行 / consolidation_scopes（**防 worker 复活总结**）/ recall_acl / gen 开关。
- 循环依赖规避：`MemoryLifecycleService` 已依赖 ProjectService，hook 只依赖 mapper → 单向无环。
- **连带调整**：`MemoryLifecycleService` 删掉自插 OWNER 行（改由 hook 随 create 落，否则撞 uk）。

### `MemoryTurnMapper` + XML（3 新语句，数组写走 XML 绕 LambdaUpdateWrapper 坑）
`appendDepartedProjectToMyTurns` / `markProjectDeletedForAllTurns` / `findAuthorsWithTurnsInProject`（新 DTO `MemoryProjectAffectedAuthorVO`），均 `NOT @>` 幂等防重复追加。

### V52 回填迁移（`V52__backfill_memory_project_members.sql`）
旧栈有效成员（未软删+项目未软删）→ 新栈 ACTIVE 行，角色 OWNER→OWNER 其余→MEMBER，`ON CONFLICT DO NOTHING`。
**版本偏移**：H 收尾 DROP 旧表顺延 V53。

### 旧栈存量 bug 修复（IT 暴露）

# 设置模块 10x 问题修复 · 测试方案

> 功能：人工测试问题单 10x_设置.md 5 问题修复
> 类型：**人工交互测试**（UI 显隐、权限、下载文件、导入预览需人眼/人点确认）
> 自动化已覆盖：路由守卫纯函数(14)、Sidebar 显隐(6)、模块开关(9)、导出导入 service 逻辑(14)、SettingsView Tab(1)
> 本方案聚焦**自动化无法断言的人工验证项**。

## 前置条件
- 后端已启动（`mvn spring-boot:run`），前端已启动（`npm run dev`）
- 准备 2 个账号：① admin（roles 含 `admin`）；② 普通用户（roles 仅 `user`，无任何权限码）
- admin 账号下至少有 1 条全局供应商配置（用于导出测试）

## 测试用例

### TC-1 问题5：admin 也看不到 Agent大厅/工作流/执行监控
| 步骤 | 预期 |
|---|---|
| 1. admin 登录 | 进入默认落地页（/chat 或 /knowledge，非 /agents） |
| 2. 看左侧菜单 | **不含**「Agent大厅」「工作流」「执行监控」 |
| 3. 浏览器地址栏手敲 `/agents` 回车 | 跳转回落地页，不显示 Agent 大厅内容 |
| 4. 手敲 `/workflow` `/executions` | 均跳转回落地页 |

**通过标准**：三个模块对 admin 完全不可见、不可达。

### TC-2 问题3：非 admin 看不到「设置」
| 步骤 | 预期 |
|---|---|
| 1. 普通用户登录 | 进入落地页 |
| 2. 看左侧菜单 | **不含**「设置」「用户管理」「角色权限」 |
| 3. 手敲 `/settings` | 跳转回落地页，不显示设置页 |

### TC-3 问题4：无权限模块不展示（普通用户）
| 步骤 | 预期 |
|---|---|
| 1. 普通用户（无 media:gen）登录 | 菜单**不含**视频生成/图片生成/视频剪辑/无限画布/资产库 |
| 2. 手敲 `/video-gen` | 跳转落地页 |
| 3. （可选）后端给该用户授 `media:gen`，重新登录 | 菜单出现视频生成/图片生成 |

### TC-4 问题1：「我的模型」Tab 已下线（admin）
| 步骤 | 预期 |
|---|---|
| 1. admin 进 `/settings` | Tab 列表**不含**「我的模型」，含「全局模型供应商/认证设置/计费设置/RAG召回/联网搜索」 |

### TC-5 问题1后端：对话走全局（存量用户配置失效）
| 步骤 | 预期 |
|---|---|
| 1. 在 DB 给某普通用户插一条 `user_llm_providers`（指向某 provider，自定义 endpoint/key） | — |
| 2. 该用户登录，进 `/chat` 发消息 | 对话正常返回，**使用全局 provider**（日志 `provider=全局name`，非用户配置的） |
| 3. 看后端日志 | `Llm调用 model=... provider=<全局>`，不出现「使用用户Provider」debug |

### TC-6 问题2：导出供应商（含明文 key）
| 步骤 | 预期 |
|---|---|
| 1. admin 进 `/settings` → 全局模型供应商 Tab | 看到「导出」按钮 |
| 2. 点「导出」 | 弹二次确认窗，提示「含明文 API Key」 |
| 3. 确认 | 浏览器下载 `llm-providers-YYYY-MM-DD.json` |
| 4. 打开 JSON | 含 provider 数组，`apiKey` 字段是**明文**（非 ENC...） |
| 5. 查后端 audit_logs | 有一条 `action=provider_export` 记录 |

### TC-7 问题2：导入供应商（预览 + upsert）
| 步骤 | 预期 |
|---|---|
| 1. admin 点「导入」选刚才导出的 JSON | 弹预览窗「共 N 条：预计新增 0 / 更新 N」（同名） |
| 2. 确认导入 | 提示「导入完成：新增 0 / 更新 N / 失败 0」，列表刷新 |
| 3. 构造一个含非法行（name 空、apiEndpoint 非 http）的 JSON 导入 | 提示「失败 K」，合法行仍导入 |
| 4. 导入超 200 条 | 后端返 400，前端报错（interceptor） |

**边界**：
- 导入同名 provider 且 apiKey 空 → 原 key **不被清空**（TC-8）
- 导入非 JSON 文件 → 提示「文件解析失败」

### TC-8 问题2边界：apiKey 空保留原值
| 步骤 | 预期 |
|---|---|
| 1. 记下某 provider 原 key（导出看明文） | 如 `sk-orig` |
| 2. 构造 JSON：同名，apiKey 字段删掉或留空，改 displayName | — |
| 3. 导入 | 更新成功，displayName 变 |
| 4. 再次导出该 provider | apiKey 仍是 `sk-orig`（未被清空） |

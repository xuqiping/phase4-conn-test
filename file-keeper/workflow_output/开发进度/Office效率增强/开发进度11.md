# Office 效率增强开发进度 11

> 记录日期：2026-08-26。范围是统一安全底座 Chunk 4：Worker 生命周期与协议。自动化测试与集中审查按用户要求留到 Phase 4。

## 1. 实现内容

- `protocol.rs`：建立版本 1 的共享 JSON Lines 协议；请求支持握手、检查、心跳、取消和关闭，响应支持就绪、心跳、进度、结果、取消、关闭和错误事件。
- `worker.rs`：启动无业务命令行参数的子进程，建立 stdin/stdout/stderr 管道，完成协议握手、版本/PID 校验、进度回调、请求超时和稳定错误码转换。
- `office_ooxml_worker.rs`：保留既有 inspect 返回字段并增加事件、协议版本、PID 和可选 taskId；新任务请求可先收到不含路径的 inspect 进度事件。
- `mod.rs`：注册协议和 Worker 生命周期模块，供 Chunk 7 的 Tauri 调度层接入。

## 2. 安全与运维边界

- 请求路径仍只通过 stdin JSON 传递，不进入命令行、错误文本或 Debug。
- stdout 单行限制 1 MiB；超限和畸形 JSON 转换为稳定错误码，不把原始响应回显到主程序日志。
- stderr 后台排空但只累计行数，不保存或回显正文，避免 Worker/Office 错误意外暴露路径或文档内容。
- 会话保存真实 `Child` 和 PID；握手返回 PID 必须与该 `Child` 一致。
- 心跳失败先请求优雅关闭；取消等待最多 10 秒，之后只对当前会话持有的 `Child` 执行 kill/wait，禁止按进程名误杀用户 Office。

# 文件管理模块（Files Module）总结

## 1. 模块职责一句话

文件管理模块是 File Keeper 桌面应用的核心模块，负责本地文件/文件夹的收藏、分组、搜索、排序、打开、编辑、批量操作以及最近文件追踪，并通过 Tauri 与操作系统交互完成真实文件操作。

## 3. 核心数据流 / 调用链路

### 添加文件/文件夹

```
用户点击 "添加文件" 按钮
  → AddFileButton.vue
    → pickFile() / pickFolder()  [file-keeper/src/api/files.ts]
      → @tauri-apps/plugin-dialog::open()
        → OS 文件选择对话框
    → validatePath(path)  [file-keeper/src/api/files.ts]
      → invoke('validate_path', { path })  [file-keeper/src-tauri/src/commands/files.rs]
        → std::path::Path::exists()
    → fileStore.addFile({...})  [file-keeper/src/stores/fileStore.ts]
      → 生成 UUID、计算 orderIndex、推入 files 数组
      → Pinia persist 自动保存到本地存储
```

### 打开文件

```
用户点击文件卡片/列表项
  → App.vue::handleFileClick(file)
    → fileStore.recordOpen(file.id)  // 更新 openCount 和 lastOpened
    → recentStore.addRecent(file)   // 加入最近打开列表
    → openFile(file.path)  [file-keeper/src/api/files.ts]
      → invoke('open_file', { path })  [file-keeper/src-tauri/src/commands/files.rs]
        → opener::open(path)  // 使用系统默认程序打开
```

### 图标懒加载

```
文件卡片/列表项进入视口
  → App.vue::setupIconLazyLoad(el, file)  // 全局 IntersectionObserver
    → 元素进入视口后推入 iconQueue
    → processIconQueue()  // 使用 requestIdleCallback 调度
      → 动态 import('./api/icons')::getFileIcon(path)
        → invoke('get_file_icon', { path, use_real_icon })  [file-keeper/src-tauri/src/commands/icons.rs]
          → Windows: SHGetFileInfoW → HICON → DIB → PNG → Base64
          → macOS/Linux: 返回 None（依赖前端扩展名回退）
      → fileStore.updateFile(file.id, { icon })  // 更新图标缓存
```

### 拖拽添加文件（系统 → 应用）

```
用户从系统文件管理器拖拽文件到应用窗口
  → Tauri onDragDropEvent  [file-keeper/src/App.vue::onMounted]
    → handleTauriDroppedPaths(paths)
      → processDroppedPath(path)
        → validatePath(path) + stat(path) 判断文件/文件夹
        → fileStore.addFile({...})
```

## 4. 关键状态与 Store 说明

### `fileStore` (`file-keeper/src/stores/fileStore.ts`)

- **State**: `files`（文件数组）、`searchQuery`（原始搜索输入）、`debouncedSearchQuery`（300ms 防抖后的搜索词）、`sortBy`（排序模式）
- **持久化**: `persist` 配置保存 `files` 和 `sortBy`，`importantActions` 触发立即持久化
- **核心 Getter `filteredFiles`**: 依次执行分组过滤 → 排序 → 搜索过滤（支持通配符 `*` 转正则），并记录 >50ms 的搜索性能日志
- **排序模式**: `custom`（按 `orderIndex`）、`openCount`（打开次数降序）、`name`（名称拼音排序）、`lastOpened`（最近打开降序）、`createdAt`（创建时间降序）
- **批量操作**: `batchOpen`、`batchDelete`、`batchMove`、`batchAddTags`
- **自定义排序**: `moveToPosition(id, targetPosition)` 支持在可见列表中 1-based 位置移动，gap-pack 重新分配 `orderIndex`

### `groupStore` (`file-keeper/src/stores/groupStore.ts`)

- **默认分组**: `all`（全部）、`recent`（最近打开，逻辑分组，不持久化文件列表）
- **自定义分组**: 用户可创建、重命名、删除（删除时文件自动移至 `all`）
- **持久化**: 保存 `groups` 和 `currentGroupId`

### `recentStore` (`file-keeper/src/stores/recentStore.ts`)

- 最多保留 10 条最近打开记录，独立持久化
- 与 `fileStore.recordOpen` 联动：打开文件时同时更新 `recentStore`

### `selectionStore` (`file-keeper/src/stores/selectionStore.ts`)

- **跨模块共享**: 被文件模块、剪贴板模块等共用
- 使用 `Set<string>` 存储选中 ID，支持 `toggleSelection`、`selectAll`、`clearSelection`
- App.vue 中绑定键盘快捷键：`Ctrl+A` 全选可见文件、`Escape` 清空、`Delete` 批量删除

## 5. 关键组件与组合式函数说明

### 组件

| 组件 | 文件路径 | 功能 |
|------|---------|------|
| `AddFileButton` | `file-keeper/src/components/AddFileButton.vue` | 通过 `confirm()` 让用户选择添加文件或文件夹，调用 `pickFile`/`pickFolder`，验证路径后存入 `fileStore` |
| `EditFileDialog` | `file-keeper/src/components/EditFileDialog.vue` | 模态对话框，编辑文件的图标（6 种预设）、名称（只读路径）、标签（最多 10 个，每个最多 20 字符）、所属分组；通过 `saved`/`close` 事件与父组件通信 |
| `GroupManager` | `file-keeper/src/components/GroupManager.vue` | 分组管理弹窗，显示分组列表（含文件计数）、支持行内重命名、删除分组（文件自动移至全部）、触发新建分组 |
| `RecentFiles` | `file-keeper/src/components/RecentFiles.vue` | 顶部工具栏的时钟图标下拉面板，展示 `recentStore.recentFiles`，点击后通过 `open-file` 事件交由父组件打开，支持清空历史 |

### 组合式函数

| 组合式函数 | 文件路径 | 功能 |
|-----------|---------|------|
| `useVirtualScroll` | `file-keeper/src/composables/useVirtualScroll.ts` | 基于 `@vueuse/core` 的 `useElementSize` 计算可视区域，支持 `itemHeight` + `itemsPerRow`（网格）或单行（列表），`overscan` 缓冲，返回 `visibleItems`、`totalHeight`、`handleScroll` |
| `useIconLazyLoad` | `file-keeper/src/composables/useIconLazyLoad.ts` | 基于 `IntersectionObserver` 的图标懒加载，全局图标队列 + 最大并发控制（`MAX_CONCURRENT = 5`），支持 `real`（系统真实图标）和 `generic`（扩展名推导）两种模式 |
| `useSortableFiles` | `file-keeper/src/composables/useSortableFiles.ts` | 基于 `sortablejs` 的分组标签栏水平拖拽排序，`onEnd` 时读取 DOM 新顺序调用 `fileStore.updateOrder` |

## 6. 核心功能详解

### 添加文件/文件夹
- 支持三种入口：顶部按钮（`AddFileButton.vue`）、"添加文件夹" 按钮（`App.vue::handleAddFolder`）、系统拖拽（`onDragDropEvent`）
- 添加时自动去重（基于 `path`），重复路径返回 `null` 并提示用户
- 新文件默认分配到当前分组（若当前为 `all`/`recent`，则分配到首个自定义分组）

### 打开文件
- 单击文件卡片/列表项打开（网格视图按住 `Ctrl`/`Cmd` 可多选，不打开）
- 打开时更新 `openCount` 和 `lastOpened`，并同步到 `recentStore`
- 调用 Rust `open_file` command，使用 `opener` crate 调用系统默认程序

### 编辑文件信息
- 右键菜单选择 "编辑信息" 打开 `EditFileDialog`
- 可修改：图标（6 种预设）、名称、标签（最多 10 个）、所属分组
- 路径字段只读（带 Lock 图标）

### 分组管理
- 默认分组：`all`、`recent`（不可删除、不可重命名）
- 自定义分组：可创建、重命名、删除；删除时该分组下文件自动移至 `all`
- 分组标签栏支持 `useSortableFiles` 拖拽排序
- 当前分组切换即时过滤文件列表

### 排序
- 5 种排序模式：`custom`、`openCount`、`name`、`lastOpened`、`createdAt`
- `custom` 模式下显示每个卡片的排序序号徽章，点击可输入新位置（1-based），调用 `moveToPosition` 重新排序
- 其他模式下序号徽章为只读灰色状态

### 虚拟滚动
- 网格视图：每行 5 个卡片，单项高度 220px，overscan 10
- 列表视图：每行 1 个，单项高度 60px，overscan 5
- 使用绝对定位渲染可见项，总高度由 `totalRows * itemHeight` 撑开滚动条

### 图标懒加载
- 两种模式：`real`（系统真实图标，Windows 下提取）、`generic`（扩展名推导）
- 通过 `IntersectionObserver` 检测元素进入视口，加入全局队列，最大并发 3-5 个
- 使用 `requestIdleCallback` 避免阻塞主线程
- 切换图标模式时，全部文件图标清空并重新触发懒加载

### 最近文件
- `recentStore` 独立维护最多 10 条记录，按打开时间倒序
- `RecentFiles.vue` 展示下拉面板，点击后通过 `open-file` 事件交由 `App.vue::handleFileClick` 打开
- 支持一键清空历史

### 批量操作
- 选中文件后底部弹出批量操作栏（固定底部居中）：打开、移动到分组、添加标签、删除、取消选择
- 批量操作函数定义在 `fileStore`：`batchOpen`（逐个调用 `openFile` 并 `recordOpen`）、`batchDelete`、`batchMove`、`batchAddTags`
- `batch.ts` 提供简单的权限检查（`canBatchOpen`/`canBatchDelete`/`canBatchMove`，目前仅检查 `length > 0`）

## 8. 已知缺口 / TODO

1. **图标提取平台支持不完整**: `icons.rs` 中 macOS 和 Linux 的 `extract_icon` 直接返回 `None`，仅 Windows 有完整实现。
2. **拖拽排序与虚拟滚动冲突**: `App.vue` 注释说明 "Drag-reorder for grid view disabled while virtual scroll is active"，网格视图的自定义排序目前通过序号徽章输入实现，而非拖拽。
3. **文件持久化非数据库**: 文件数据通过 `pinia-plugin-persistedstate` 保存到本地存储，未使用 SQLite/文件数据库，大数据量时可能性能受限。
4. **搜索性能监控仅日志**: `filteredFiles` 中超过 50ms 的搜索仅打印 `console.log`，无用户侧性能提示或优化措施。
5. **批量操作无撤销机制**: 删除、移动等批量操作直接修改状态，无 undo/redo 支持。
6. **路径验证仅检查存在性**: `validate_path` 仅调用 `Path::exists()`，不检查可读性/权限等。
7. **右键菜单位置硬编码尺寸**: 边界检测假设菜单尺寸 224x280，若菜单内容变化可能溢出屏幕。
8. **分组标签栏未使用虚拟滚动**: 分组数量多时横向滚动，但未做虚拟化或折叠处理。

## 9. 与其他模块的依赖关系

| 依赖模块 | 依赖方式 | 说明 |
|---------|---------|------|
| **进程管理模块** | `App.vue` 右键菜单 "关闭已打开的进程" | 调用 `findFileProcesses` / `closeProcess`（`file-keeper/src/api/processes.ts`），需 `canUseTab('processes')` 授权 |
| **剪贴板模块** | `App.vue` 标签栏切换、快捷键、截图 | 共用 `commercialAuthStore` 授权检查，`syncClipboardMonitor` 在授权变化时启停剪贴板监听 |
| **商业授权模块** | `App.vue` 全局 | `canUseTab(tab)` 通过 `commercialAuthStore.isModuleAllowed(tab)` 控制文件/进程/剪贴板模块的可用性；未授权时显示 `FreeModuleSelector` |
| **设置模块** | `App.vue` 工具栏图标模式切换、主题、视图模式 | `settingsStore.settings.iconMode` 控制图标懒加载模式；`settingsStore.effectiveTheme` 控制暗色/亮色主题；`settingsStore.settings.defaultView` 控制网格/列表视图 |
| **认证模块** | `App.vue` 顶部登录/退出 | `authStore` 控制登录状态，`commercialAuthStore` 控制模块授权，两者共同决定功能可用性 |
| **截图模块** | `App.vue` 全局快捷键 | 截图成功后自动切换到剪贴板标签页并刷新列表，与剪贴板模块联动 |

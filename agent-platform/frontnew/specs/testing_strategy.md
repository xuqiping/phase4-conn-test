# 测试策略 — frontnew

> 本项目是视觉验证工程：自动化测试护住「不崩」，视觉判断靠人工走查。

## 1. 自动化测试（vitest + @testing-library/vue）

| 范围 | 用例 | 类型 |
|------|------|------|
| 主题系统 | 切换主题后 `document.documentElement.dataset.theme` 正确、localStorage 持久化、刷新后恢复 | 单测 |
| 主题系统 | 4 主题 CSS 变量完整性：解析 tokens 文件断言每个主题定义了全部必需变量（防漏定义导致页面露底色） | 单测（读文件断言） |
| 节点卡片 | NodeCardBase 按 `status` prop 渲染对应状态类名（idle/running/done/error） | 组件测试 |
| 节点卡片 | 6 类型节点渲染出各自类型图标与类型色类名 | 组件测试 |
| mock 层 | mocks 导出的演示工作流覆盖 6 类型、≥10 节点、连线引用的节点都存在（防悬空边） | 单测 |
| 路由 | 5 个核心页路由均可渲染不抛错（冒烟） | 组件测试 |

不追求覆盖率数字，上述用例全过即可。

## 2. 人工交互测试清单（必须人工，AI 无法判断「好不好看」）

标记 **【人工】** 的项需用户在浏览器逐项确认：

| # | 检查项 | 方法 |
|---|--------|------|
| M1 **【人工】** | 4 主题 × 5 页面矩阵走查：无露底色、无对比度事故、无错位 | 逐组合切换浏览 |
| M2 **【人工】** | 画布节点 6 状态视觉：运行动画不刺眼、报错醒目、选中明确 | 画布演示流 |
| M3 **【人工】** | 100 节点缩放/平移流畅度（`?nodes=100`） | 手感+任务管理器 |
| M4 | 主题切换 <100ms 无闪烁 | 肉眼+Performance 面板 |
| M5 | 对比度达标：4 主题正文 ≥4.5:1 | Chrome DevTools 取色+对比度工具 |
| M6 | `prefers-reduced-motion` 开启时动效关闭 | 系统设置后刷新 |
| M7 | 键盘 Tab 可遍历侧边栏与主题切换器 | 键盘操作 |
| M8 **【人工】** | 生产构建 `pnpm build && pnpm preview` 与 dev 表现一致 | 构建后走一遍 M1 |

## 3. 冒烟工具

Phase 4 用 Playwright MCP 做页面级冒烟（截 4 主题 × 5 页面共 20 张截图供用户快速比选），并跑 M4/M5 的半自动化断言。

## 4. 明确不测

- 不测后端交互（无后端）；不测登录/权限（无守卫）；不测移动端断点（桌面优先）；不测 IE/旧浏览器。

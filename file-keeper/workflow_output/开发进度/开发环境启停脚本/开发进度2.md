# 开发进度 2

> 日期：2026-09-03

## 问题与根因

- 使用真实 `启动.ps1` 稳定复现 Java 后端 90 秒内未监听 `8088`。
- 同环境直接运行 Maven 得到 PostgreSQL `28P01`。
- 当前进程未继承 `FILE_KEEPER_DB_PASSWORD`，但 Windows 当前用户环境已配置，后端因此回退默认密码。
- 后端修复后，系统中已运行的安装版 `file-keeper.exe` 又被误判为当前项目开发版，导致 `1420` 未监听仍跳过 Tauri。
- Tauri/Vite 随后成功监听 `::1:1420`，但脚本只连接 `127.0.0.1`，因此错误等待 90 秒并报告超时。

## 修复

- `启动.ps1` 在进程级变量为空时读取 Windows 当前用户的 `FILE_KEEPER_DB_PASSWORD`。
- 密码仅通过子进程环境传递，不显示、不落盘。
- Tauri 开发版只以 Vite 严格端口 `1420` 判断是否已运行，不再使用全局同名进程判断。
- 通用端口探测同时尝试 IPv4 `127.0.0.1` 与 IPv6 `::1` 回环地址。
- Windows PowerShell 5.1 的默认 `TcpClient` 不能连接 IPv6 地址，因此两种回环地址分别使用对应的 `AddressFamily` 创建 socket。

## 验证范围

- Windows PowerShell 5.1 Parser。
- 从未继承密码变量的进程执行真实启动脚本。
- Java 后端 `8088` 与 Tauri/Vite `1420` 监听。
- Git diff 不含数据库密码明文。

## 验证结果

- Windows PowerShell 5.1 Parser：`0` 个错误，UTF-8 BOM 保留。
- 干净启动脚本退出码：`0`。
- Redis `6379`、PostgreSQL `5432`、Java `8088`、Vite `1420` 均监听。
- 项目开发版 `src-tauri/target/debug/file-keeper.exe` 实际运行且仅 `1` 个实例。
- 再次执行启动脚本全部跳过，日志窗口数量不增加。
- 后端 HTTP 可达；健康端点受认证保护并返回 `401`。

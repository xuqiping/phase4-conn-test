# AI 接入模块（AI Module）总结

## 1. 模块职责一句话

AI 接入模块为 File Keeper 提供可配置、可授权的大模型调用能力：用户在桌面端配置多条 AI Provider（qwen/doubao/claude），服务端加密存储 API Key，其他业务模块（如工作汇报）按用户/配置调用大模型，失败时自动降级。

## 3. 核心数据流 / 调用链路

### 保存 AI 配置

```
用户在 SettingsDialog → AI 模型 Tab 填写配置
  → AiConfigSettings.vue
    → aiConfigStore.saveConfig(id, form)
      → POST/PUT /api/client/ai-configs
        → AiConfigController
          → 校验 MODULE_AI 授权
          → AiConfigService.create/update
            → CredentialEncryptor.encrypt(apiKey)
            → AiConfigRepository.insert/update
```

### 生成报告时调用 AI

```
WorkReportService.generate(userId, configId)
  → 若 reportConfig.aiEnabled
    → AiSummaryService.summarize(logs, fixedWork, reportType, aiConfigId, userId)
      → AiConfigService.getEffectiveConfig(userId, aiConfigId)
        → 指定配置不存在 → 找用户默认配置
      → AiConfigService.getDecryptedApiKey(userId, aiConfigId)
      → 根据 provider 调用对应大模型 API（qwen/doubao/claude）
      → 异常/超时/空响应 → fallbackSummary 简单拼接
```

### 模块授权

```
管理员在 admin-web → 用户详情 → 授予权益
  → POST /api/admin/users/{id}/entitlements
    → EntitlementService.grant
      → validateModuleCode：白名单包含 ai
      → 写入 user_module_entitlements

桌面端启动/登录
  → commercialAuthStore.initializeAuthenticated
    → GET /api/client/authorization
      → AuthorizationService.authenticatedSnapshot
        → MODULE_CODES 包含 ai
        → 返回 modules 列表
    → SettingsDialog 根据 isModuleAllowed('ai') 显示 AI 模型 Tab
    → ReportConfigForm 根据 isModuleAllowed('ai') 显示 AI 配置选择
```

## 4. 关键状态与 Store 说明

### `aiConfigStore` (`file-keeper/src/stores/aiConfigStore.ts`)

- **State**: `configs`（配置列表）、`loading`、`error`
- **计算属性**: `defaultConfig`
- **方法**:
  - `loadConfigs()`：加载当前用户所有配置
  - `saveConfig(id?, config)`：创建或更新配置
  - `deleteConfig(id)`：删除配置
  - `setDefault(id)`：设为默认配置
- **安全设计**: 不配置 Pinia 持久化，API Key 不落本地磁盘

## 6. 核心功能详解

### 多配置管理
- 一个用户可创建多条 AI 配置
- 每条配置包含：名称、Provider、模型、API Key、自定义 Endpoint、Max Tokens、Timeout、启用开关
- 可设置一条默认配置

### Provider 默认建议
- 选择 Provider 时自动填充默认模型名
- 支持自定义 Endpoint（留空使用 Provider 默认）

### API Key 安全
- 传输：HTTPS
- 存储：服务端 AES-GCM 加密（`CredentialEncryptor`）
- 回显：前端列表/详情不回显 Key，编辑时密码输入框留空表示不变
- 本地：不进入 Pinia 持久化

### 授权控制
- AI 作为独立商业模块 `ai`
- 未授权用户看不到 AI 设置页，工作汇报中也不能选择 AI 配置
- 管理员可在 admin-web 给用户授权 AI 能力

### 降级策略
- 无有效配置：降级为简单 Markdown 拼接
- API Key 未配置：降级
- AI 调用超时/异常：降级
- 模型返回空：降级

## 8. 已知缺口 / TODO

1. **AI 配置单元测试缺失**：Controller、Service、Repository 均未写独立测试。
2. **Provider 扩展性**：新增 Provider 需要修改 `AiSummaryService` 的 switch。
3. **AI 调用审计**：未记录调用耗时、Token 消耗、模型名。
4. **流式输出未支持**：当前为非流式同步调用。
5. **Prompt 工程化**：当前为硬编码 Prompt，未支持用户自定义系统提示词。
6. **模型列表动态获取**：模型名由用户手动填写，未提供下拉推荐列表。
7. **AI 能力复用**：目前仅工作汇报使用，其他模块（如剪贴板摘要、进程备注生成）可接入。
8. **环境变量废弃后续**：`work-report.ai.provider/api-key/endpoint/model` 已废弃，需确认部署文档更新。

## 9. 与其他模块的依赖关系

| 依赖模块 | 依赖方式 | 说明 |
|---------|---------|------|
| **公共与基础设施** | 全局 | AI 配置入口放在 `SettingsDialog.vue`；使用 `useI18n`、Tailwind 主题 |

| **管理后台** | `admin-web` | 管理员给用户授权 `ai` 模块 |
| **凭证加密** | `CredentialEncryptor` | AI 配置复用已有的推送凭据加密服务 |

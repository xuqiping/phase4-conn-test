# 3.3 Agent模式与工作流

## Agent模式三要素

AI编程Agent区别于简单补全，需同时具备：

| 要素 | 含义 | 典型实现 |
|---|---|---|
| **自主规划** | 接收任务后自主拆解子步骤 | Claude Code的plan→execute循环 |
| **工具调用** | 调用文件读写/终端命令/搜索/API等工具 | Cursor Agent的file_edit/bash_search |
| **验证循环** | 执行后检查结果，失败则重试/调整 | Kiro的Hook自动验证、Claude Code的self-review |

> 三要素缺一不可——只有"生成代码"没有"调用工具"是补全不是Agent；没有"验证循环"则错误会级联放大。[来源:📚综合分析 | 📚中 | 2026]

## 自主度光谱

```
← 低自主度                                            高自主度 →
┌──────────┐  ┌──────────┐  ┌───────────┐  ┌──────────┐  ┌──────────┐
│ 代码补全  │→│ 对话编程  │→│ 半自主Agent│→│ 全自主Agent│→│Multi-Agent│
│ Tab接受   │  │ 审批执行  │  │ 关键点审批 │  │ 仅验收结果 │  │ 编排器调度 │
└──────────┘  └──────────┘  └───────────┘  └──────────┘  └──────────┘
  人工:100%     人工:70%       人工:30%        人工:10%       人工:5%
  AI:0%         AI:30%        AI:70%         AI:90%        AI:95%
```

[来源:📚综合分析 | 📚中 | 2026]

**PM核心关注**：自主度越高，效率提升越大，但**安全风险和失控概率也越高**。企业生产环境建议在"半自主Agent"档位起步，逐步提升自主度。

## 人机协作工作流

### 标准Agent工作流（6步闭环）

1. **意图表达**：开发者用自然语言描述任务（"给用户模块加一个邮箱验证功能"）
2. **AI规划**：Agent拆解子任务、评估影响范围、列出修改文件清单
3. **人工审批**：开发者确认规划（⬜关键安全门——**跳过=埋雷**）
4. **Agent执行**：Agent按规划执行代码修改、运行测试
5. **self-review**：Agent自检修改是否符合意图、引入测试是否通过
6. **人工验收**：开发者Code Review最终结果

### Kiro的Hook模式（2026创新）

Kiro引入"Hook"机制——在Agent执行的特定节点**自动触发预设检查**：
- Pre-commit Hook：Agent提交前自动跑lint+单元测试
- Security Hook：修改涉及权限/认证时自动触发安全扫描
- Spec Hook：Agent输出与Spec不一致时暂停等待人工确认

> Hook是"Agent模式的红绿灯"——让AI在关键路口必须停下来。[来源:AWS Kiro官方文档 | 🔍高 | 2026-06]

## Multi-Agent编排

| 模式 | 说明 | 典型场景 |
|---|---|---|
| 编排器+执行者 | 一个主Agent分配任务，多个专业Agent并行执行 | 大型功能开发：前端Agent+后端Agent+测试Agent |
| 级联Agent | Agent A输出作为Agent B输入 | 设计Spec→编码Agent→测试Agent |
| 竞争Agent | 多Agent并行实现同一任务，人类选最佳 | 高不确定性任务的方案探索 |
| 混合人机 | 人类在循环中做决策，Agent做执行 | 企业安全合规场景 |

> Multi-Agent是2026年最前沿方向但落地尚早——当前主要在PoC和实验阶段。[来源:CSDN AI编程工具2025年终总结 | 📚中 | 2025-12]

## PM在Agent工作流中的角色

| 阶段 | PM角色 | 关键输出 |
|---|---|---|
| 意图表达 | **需求精确度决定AI输出质量**——模糊需求=模糊代码 | 精确的用户故事+验收标准 |
| 人工审批 | 评估Agent规划是否覆盖边界case | 审批/打回决策 |
| 人工验收 | 关注业务逻辑正确性而非代码细节 | 验收确认 |
| 异常处理 | Agent无法完成时的降级决策 | 降级为手动编码/拆分任务 |

> PM最重要的贡献：**把模糊的业务需求翻译成AI可执行的精确Spec**。Spec越精确，AI输出越可靠——这本身就是Spec Coding的核心逻辑。

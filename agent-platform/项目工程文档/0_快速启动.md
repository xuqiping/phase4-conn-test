# 0. 快速启动

多 Agent 智能体平台本地启动指南。四组件：PostgreSQL + Redis + backend + frontend（+ 可选 runtime-sidecar）。

端口约定：

| 服务 | 端口 |
| --- | --- |
| PostgreSQL | 5432 |
| Redis | 6379 |
| backend（Spring Boot） | 8080 |
| runtime-sidecar（FastAPI） | 8090 |
| frontend（Vite dev） | 5173 |

---

## 1. 前置依赖

- JDK 17
- Maven 3.9+（全局 `mvn` 即可，仓库无 `mvnw` wrapper）
- Node.js 18+ / npm
- Python 3.10+（runtime-sidecar 必需）
- PostgreSQL 16（本机安装路径 `C:\Program Files\PostgreSQL\16`）
- Redis（本机安装路径 `C:\Program Files\Redis`）

---

## 2. PostgreSQL 启动（5432）

本机 data 目录：`C:\Program Files\PostgreSQL\16\data`。

### 方式 A：命令行 `pg_ctl`

```powershell
# 启动
& "C:\Program Files\PostgreSQL\16\bin\pg_ctl.exe" start -D "C:\Program Files\PostgreSQL\16\data" -l "C:\Program Files\PostgreSQL\16\data\pg.log"

# 停止
& "C:\Program Files\PostgreSQL\16\bin\pg_ctl.exe" stop -D "C:\Program Files\PostgreSQL\16\data"

# 状态
& "C:\Program Files\PostgreSQL\16\bin\pg_ctl.exe" status -D "C:\Program Files\PostgreSQL\16\data"
```

### 方式 B：Windows 服务（若安装时注册了服务）

```powershell
Start-Service postgresql-x64-16
Stop-Service  postgresql-x64-16
```

> data 目录下含 Flyway 迁移产物，不要手动删库表。库表 schema 由 backend 启动时 Flyway 自动迁移。

验证：

```powershell
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -d postgres -c "SELECT version();"
```

## 3. Redis 启动（6379）

本机安装路径：`C:\Program Files\Redis`。配置文件：`redis.windows.conf`（port 6379）。

### 方式 A：命令行前台运行

```powershell
& "C:\Program Files\Redis\redis-server.exe" "C:\Program Files\Redis\redis.windows.conf"
```

### 方式 B：作为 Windows 服务

```powershell
& "C:\Program Files\Redis\redis-server.exe" --service-install "C:\Program Files\Redis\redis.windows.conf"
Start-Service Redis
Stop-Service  Redis
```

验证：

```powershell
& "C:\Program Files\Redis\redis-cli.exe" ping
# 期望返回 PONG
```

## 4. backend 启动（8080）

依赖 PG（5432）+ Redis（6379）已起。Flyway 自动迁移 schema。

> ⚠️ **安全审计 #2 后必填 3 个环境变量**（`application.yml` 已删默认值，未注入则启动 fail-closed）：`JWT_SECRET`（空/命中旧弱密钥 → `JwtUtil @PostConstruct` 拒绝启动）、`DB_PASSWORD`（空 → Hikari 连不上库）、`RUNTIME_CALLBACK_TOKEN`（sidecar 回调共享密钥，必须和 §5 sidecar 同值）。
>
> **三者在 `agent-platform/local-dev-env.ps1` 里一次性写好（已 `.gitignore`，不入库）**，backend 和 sidecar 都 dot-source 它，保证 token 两边一字不差。首次部署先建此文件（见下）。

首次创建 `agent-platform/local-dev-env.ps1`（跑一次，值固定下来，别再随机）：

```powershell
$jwt = [Convert]::ToBase64String((1..64 | ForEach-Object { Get-Random -Maximum 256 }))
$tok = -join ((1..32 | ForEach-Object { '{0:x2}' -f (Get-Random -Maximum 256) }))
@"
`$env:JWT_SECRET = '$jwt'
`$env:DB_PASSWORD = 'aa64221886'   # 改成你本地 PG 密码
`$env:RUNTIME_CALLBACK_TOKEN = '$tok'
`$env:DINGTALK_ENABLED = 'true'
`$env:DINGTALK_APP_KEY = '钉钉开放平台抄的 AppKey'
`$env:DINGTALK_APP_SECRET = '抄的 AppSecret'
`$env:DINGTALK_AGENT_ID = '抄的 AgentId'

"@ | Set-Content e:\workspace\agent-platform\local-dev-env.ps1 -Encoding utf8
```

启动 backend（dot-source 同一文件 → 变量进当前 shell → 再跑 mvn，必须同一命令段）：

```powershell
cd e:\workspace\agent-platform\backend
. ..\local-dev-env.ps1
mvn spring-boot:run
```

> 测试源码已修绿，无需 `-Dmaven.test.skip=true`。JWT 黑名单走 Redis、业务库走 PostgreSQL，两者不可省略。

验证：`GET http://localhost:8080/api/...`（具体接口见各模块文档）。

## 5. runtime-sidecar 启动（8090，必需）

Python FastAPI。backend **默认 `runtime.gateway.mode=sidecar`**，启动 backend 前必须先起 sidecar，否则工作流执行请求会失败。

```bash
cd e:/workspace/agent-platform/runtime-sidecar
python -m pip install -r requirements.txt        # 首次
```

> ⚠️ **安全审计 #1 后必填 `RUNTIME_CALLBACK_TOKEN`**：`callback_client.py` 已自动读此 env 并给所有→Java 回调加 `X-Runtime-Token` 头（`trust_env=False`，直连不走系统代理）。**未设或与 backend 不一致 → 回调全 401**（工作流检索/Agent/Skill 节点全废）。值来自 §4 的 `local-dev-env.ps1`，**同一文件 → 天然同值，不用手抄**。

```powershell
cd e:\workspace\agent-platform\runtime-sidecar
. ..\local-dev-env.ps1
python -m uvicorn app.main:app --host 0.0.0.0 --port 8090
```

> 注：`local-dev-env.ps1` 会顺带把 `JWT_SECRET`/`DB_PASSWORD` 也设进 shell，对 sidecar 无害（它只读 `RUNTIME_CALLBACK_TOKEN`）。

gateway 连接配置（已写死，无需环境变量）：

```
runtime.gateway.mode=sidecar
runtime.gateway.sidecar-base-url=http://localhost:8090
runtime.gateway.java-callback-base-url=http://localhost:8080
```

- `mode=sidecar`（默认）：Java 调 `POST /api/runtime/executions`（8090）。
- `mode=mock`：Java 用 `MockRuntimeGateway`，无需 Python 进程。仅临时调试用，设 `RUNTIME_GATEWAY_MODE=mock`。

验证：`GET http://localhost:8090/health` → `{"status":"UP"}`。

## 附：关闭占端口进程

端口被占、需强制释放时用。

### 单行：查端口 PID 并杀

```powershell
# 5432 / 6379 / 8080 / 8090 / 5173 任换
Get-NetTCPConnection -LocalPort 8080 -State Listen |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Stop-Process -Id $_ -Force }
```

### 分步：先查后杀（更稳，能看清杀的是谁）

```powershell
# 1. 查端口占用的 PID + 进程名
Get-NetTCPConnection -LocalPort 8080 -State Listen |
  ForEach-Object { $p = Get-Process -Id $_.OwningProcess; "PID={0} {1} ({2})" -f $p.Id,$p.ProcessName,$p.Path }

# 2. 确认无误后杀
Stop-Process -Id <PID> -Force
```

### 一次杀所有同名进程（如杀残留 java / python / node）

```powershell
Get-Process java,python,node,redis-server,postgres -ErrorAction SilentlyContinue | Stop-Process -Force
```

> 杀 PG/Redis 进程会丢未刷盘数据，优先用正规停止命令（`Stop-Service` / `redis-cli shutdown`），端口残留再杀。

## 1. 目标

1. 视频生成历史分页展示：默认 10 条/页，可选 5、10、20、50；图片生成历史顺带统一同规格。
2. 参考图鼠标悬浮可放大预览、点击可全屏查看（灯箱）。
3. 图片加载一次后进入缓存：会话内不重复下载，跨会话走 304 再验证零流量。

## 3. 历史记录分页

### 3.1 后端契约

- `GET /api/media/tasks` 新增参数：
  - `page`（≥1，默认 1）
  - `pageSize`（枚举校验 5/10/20/50，默认 10；非法值回落 10 并不报错）
- 保留 `limit` 参数但标记废弃：传了 `limit` 且未传 `pageSize` 时按 `limit` 作为 pageSize 兼容旧调用（画布、入库弹窗等现有消费方不破坏）；同时返回结构**新增** `total` 字段。
- 响应结构：沿用列表 VO，外层新增 `{ list, total, page, pageSize }`（对齐 `PageResult<T>` 语义；老字段平铺保留一个过渡版本会导致双份维护，直接切换为包裹结构，前端同步改）。**计划期先盘点全部 `listTasks` 消费方**（图片/视频页之外，入库弹窗、管理视图等若有引用一并改造，防漏改拿到 undefined）。
- 排序不变（创建时间倒序）；`q/from/to/kind` 过滤逻辑不变，`total` 按过滤后计数。

### 3.2 前端契约

- **视频页**：n-data-table 由客户端分页改 **remote 分页**：`pagination: { page, pageSize: 10, pageSizes: [5,10,20,50], itemCount: total }`；切页/改每页条数触发 `loadHistory({ page, pageSize, ...filters })`；筛选（提示词/时间）变化重置回第 1 页。
- **图片页**：历史行列表下方加 n-pagination，同样默认 10、可选 5/10/20/50；列表渲染当前页数据，不再一次拉 30 条。
- 两页共享参数拼装逻辑（`buildHistoryQuery`），防两处漂移。

### 3.3 边界

- 不做无限滚动；不做后端游标分页（数据量级不需要）。
- 画布节点回填、入库弹窗、任务详情等按 taskId 直查的路径不经过此列表接口，不受影响。

### 4.2 组件抽取

- 新建 `frontend/src/components/media/MediaLightbox.vue`：从 `ImageGenView.vue:262-266` 内联灯箱抽取（Teleport + 遮罩 + Esc/点击关闭 + 图片居中可滚动）；props `src`、`alt`；图片页原内联实现替换为本组件（行为不变）。
- 新建 `frontend/src/components/media/HoverPreviewImage.vue`：n-popover trigger=manual 方案受控显示（mouseenter 300ms 防抖触发、mouseleave 关闭），内嵌 img（max 320px，保比例）；与点击灯箱解耦，可单独使用。
- 瓦片组件统一改为：外层包 `HoverPreviewImage` + click emit；图片页/视频页瓦片结构与样式对齐，避免三处各写一份。

### 4.3 边界

- 悬浮预览图直接复用已加载的 blob objectURL（瓦片本身已拉过图），**悬浮不产生额外网络请求**。
- 不做缩放/旋转/多图切换轮播（首版），灯箱为单图查看。

## 5. 图片缓存

### 5.1 会话内缓存（前端）

- `fetchFilePreview`（`/api/files/{id}`）接入模块级 LRU blob 缓存，实现镜像 `media.ts` 的 `mediaBlobCache` 模式：
  - 新增 `filePreviewCache`：上限 80 条 / 128MB（参考图多为 KB~MB 级小图，条数优先；字节上限低于媒体缓存，两缓存合计封顶 384MB 防 Frontend 内存失控）；
  - 缓存 **Blob 而非 objectURL**，命中时新建 objectURL 返回，调用方 revoke 语义不变（与 media.ts 一致）；
  - 单条超过 256MB 不缓存（直传直 revoke）。
- `mediaBlobCache`（任务文件）维持现状，两缓存 key 空间不同（`media:` / `file:` 前缀或分 Map），互不污染。

### 5.2 跨会话缓存（后端 304）

- `FileController` 的 `/api/files/{id}` 响应头补齐（对齐 `serveFile` 既有策略）：
  - `Cache-Control: no-cache, private`
  - `ETag: "{fileId}-{size}"`（资源指纹——浏览器下次带 If-None-Match 回问，内容没变服务端只回 304 空体）
  - `If-None-Match` 命中时返回 304，不写响应体。
- 安全不降级：该接口本就鉴权 + `nosniff` + 附件下载判定（`FileController.java:62-81`），加缓存头不改变授权语义；`no-cache` 保证每次仍回源过鉴权，仅省传输。

### 5.3 失效语义（回答 4x「待解答：当前进缓存的会更新吗」）

- fileId 内容不可变（新内容=新 fileId），所以「同一 fileId 内容变了」不存在；
- ETag 含 size 兜底：极端情况下文件被替换重写同 id，size 变 → ETag 变 → 缓存自动失效；
- 会话级 LRU：仅当前登录会话有效，登出/刷新清空，无泄露面。

## 6. 数据模型

无新表、无迁移。仅响应结构与缓存常量变化。

## 7. 测试策略

| 层 | 用例 |
|---|---|

## 8. 边界与不做

- 不含 6x「未复验」项（pro 180s 超时，属复验非设计）。
- 不做视频瓦片 hover 预览、灯箱轮播、图片编辑（编辑属 2x 画布项另规格）。
- 不改 `useLazyFilePreview`（资产卡片/画布的引用计数缓存）——两套缓存受众不同，合并留待后续性能专项。

## 9. 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| LRU 缓存 | 满了就扔掉最久没被用过的那条 | 缓存 6 张视频，看第 7 张时扔掉最早看的那张 |
| ETag / 304 | 服务器给文件发个指纹，浏览器下次带着指纹问「变没」，没变就回「没变」不传正文 | 2.9MB 视频二次打开几乎零流量 |
| 灯箱（lightbox） | 点小图后全屏居中的大图查看层 | 点缩略图弹出黑底大图，点空白处关闭 |
| remote 分页 | 翻页时才向服务器要那一页数据，一次只拿 10 条 | 第 3 页只请求第 21–30 条 |
| Teleport | Vue 把组件渲染到页面最外层 DOM 的机制，避免被父级样式裁剪 | 灯箱浮在全页面之上 |

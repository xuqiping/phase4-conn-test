## 2026-08-15 · Step 3 输出侧打码 + prompt 泄露指纹（SEC-FR-052/053）✅ `55e133b2`

- **`SensitivePatternCatalog`**：输出面敏感目录，正则与 LogMasker 同源（身份证18/手机号/银行卡13-19/apiKey·token·secret·password·authorization kv/Bearer），差异=整段替换 `***`（日志面留首尾排障，输出面面向用户全遮）。类注释立「双向同步红线」。`hits()` 预判 + `mask()` 无命中同引用返回（零拷贝）。
- **`OutputSanitizer`**：收口组件。同步 `maskSync`；流式 `openStream(userId)` 每订阅一个 `StreamMasker`（40 字符 carry：每发扣留尾段下拍合并扫，`flush()` 终态补尾——身份证跨 chunk 不漏）。泄露事件每流只发一次；payload 只带 `{channel, chars}`（PII 红线不带原文）。开关 `security.ai.output-mask.enabled` / `security.ai.prompt-leak.enabled` 默认开进 EDITABLE_KEYS；任何异常透传原文 + ERROR（检测层不自残——净化挂了宁可漏打码不掐断全部对话）。
- **`PromptLeakDetector`**：只指纹**静态资产**（SkillStep.config.systemPrompt + WorkflowNode.config.systemPrompt——按请求内动态 system 算会把用户复述自己记忆误判泄露，plan 自 critique 修正点）。32 字符 shingle 步进 8 取 hashCode，10min TTL 进程内缓存 + Skill/Workflow 保存钩子 `evict()` 主动失效（`replaceSteps`/WorkflowService 更新尾部，横切可选依赖范式）。响应滑窗**连续命中 ≥2** 才遮蔽（单窗碰撞误报门），命中区段替换 `[系统提示词内容已遮蔽]`。
- **网关挂点**：`LlmGateway.chat` 出口 `response.setContent(sanitizeSync(...))`；`chatStream` 在 doOnCancel 后接 `.concatMap(evt -> sanitizeStreamEvent(evt, masker))`——CHUNK/THINKING 过 feed，其余事件（DONE/ERROR/CITATION）前插 flush 尾段 CHUNK（保序 + 末尾不丢）。masker 在 `Flux.defer` 内创建（每订阅独立 carry）。
- **事件链 6 触点**：KIND_PROMPT_LEAK / SecurityEventTypes / PromptLeakRule（HIGH·ACT_NONE——遮蔽已在网关同步完成）/ DingtalkCardBuilder「Prompt泄露遮蔽」/ security.ts / EDITABLE_KEYS；指标 `security.ai.output.masked` + `security.ai.prompt.leak`。
- **测试**：SensitivePatternCatalogTest 6/6（五类命中/短数字不误伤/null 同引用）；OutputSanitizerTest 11/11（同步打码/复述遮蔽+事件/单窗碰撞不判/双开关关/设置异常/null/跨 chunk/flush 不丢/每流一次/feed 异常透传/evict 即时生效）；回归 LlmGateway×2 + Workflow + Agent×2 + SystemSetting = 90 绿。
- **踩坑**：StreamMasker 首版 `safe.length()<=CARRY` 分支清空 carry 但没回填——整个扣留缓冲被丢（流式正文静默消失），测试抓住后改 `carry.append(safe)`。

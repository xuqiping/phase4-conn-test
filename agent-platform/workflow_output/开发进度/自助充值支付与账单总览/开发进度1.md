## 关键决策（拍板回顾）

- **架构+接口先落，真实商户后接**：Alipay/Wechat 骨架 available()=false，填环境变量即激活；mock 通道全链路可测（服务端造签走真 handleNotify）。
- **不建金额钱包**：只记流水；「金额余额」口径=累计充值金额（20x#1 视图体现）。
- **幂等三层**：uk_payment_channel_order（部分唯一）→ markPaidIfPending 抢态 → uq_ledger_ref 兜底；前端 idemKey 会话 UUID。
- **终态后付款不自动入账**：安全事件 KIND_PAYMENT_NOTIFY_REJECT + 审计 payment_notify_terminal_order + 对账异常第三节 → 人工补单。
- **Σ 联动口径**：admin 充值记录汇总 = 当前筛选下的 PAID 合计；筛非 PAID 状态归 0（刻意，防误导）。

## 坑位记录（实施中实际撞到）

1. **渠道单号漏落库**：mock channelOrderId 派生自订单 id 但列 NULL → 回调反查不到（PaymentFlowIT 抓出）；修：precreate 结果带 channelOrderId，下单后 updateById 落库。
2. **Σ 口径**：初版汇总不看 status 筛选 → 筛 PENDING 仍显示已付合计（误导）；修：sum 查询叠加 status 条件，非 PAID 自然归 0（IT 断言）。
3. **users 表**：实体无 deleted 字段但 DB 列存在（UserMapper 在用 `u.deleted=0`）——余额视图 SQL 显式滤 `deleted=0`。
4. **Bash cwd 复位**：mvn 必须 `cd /e/workspace/agent-platform/backend` 前缀；IT 需 `-Dsurefire.excludedGroups=` 放开 integration tag。

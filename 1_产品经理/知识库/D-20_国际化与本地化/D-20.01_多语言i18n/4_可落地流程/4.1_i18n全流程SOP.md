# 4.1 i18n全流程SOP

## 适用场景

产品从单语言向多语言扩展——从架构选型到上线监控的端到端执行流程。适用于首次接入i18n或重构i18n体系的团队。

## Step 1：i18n架构选型

### 决策树

```
产品形态？
├─ Web应用 → i18next / vue-i18n / react-intl
│   └─ 资源格式：JSON（按模块拆分）
├─ iOS原生 → NSLocalizedString + .strings
│   └─ 资源格式：.strings
├─ Android原生 → strings.xml + AndroidX AppCompat
│   └─ 资源格式：.xml
├─ Flutter → flutter_localizations + .arb
│   └─ 资源格式：.arb
├─ 跨平台(React Native) → i18next + react-i18next
│   └─ 资源格式：JSON
└─ 多端统一 → 自建翻译中台 + 各端SDK适配
    └─ 资源格式：统一JSON → 各端构建时转换
```

### 选型检查清单

| # | 检查项 | 说明 |
|---|---|---|
| 1 | 框架是否支持动态语言切换 | 不需重启App即可切换 |
| 2 | 是否支持复数形式 | CLDR复数规则（阿拉伯语6种） |
| 3 | 是否支持RTL | direction: rtl 自动适配 |
| 4 | 是否支持命名空间 | 按模块拆分翻译文件 |
| 5 | 是否支持异步加载 | 大型应用按需加载语言包 |
| 6 | 是否支持回退语言 | 缺翻译时回退到基准语言 |
| 7 | 社区活跃度 | 月下载量/Star数/最近更新 |

## Step 2：文案外置——硬编码扫描与提取

### 硬编码扫描流程

```
1. 安装扫描工具（eslint-plugin-i18n / i18n-ally）
2. 配置扫描规则：
   - JSX文本节点 <div>你好</div> → 报警
   - 字符串字面量 "欢迎" → 报警（排除console.log/注释）
   - 模板字符串 `你好${name}` → 报警
3. 全量扫描 → 生成硬编码清单
4. 逐条提取到资源文件
5. 代码中替换为 t('key') 调用
```

### 文案Key命名规范

| 规范 | 示例 | 说明 |
|---|---|---|
| 模块.页面.元素 | `home.hero.title` | 清晰定位来源 |
| 动词.对象 | `common.button.submit` | 通用按钮复用 |
| 状态.描述 | `user.status.offline` | 状态文案 |
| 错误.类型 | `error.network.timeout` | 错误信息 |

**禁止**：用中文做key（`t('你好')`）、用序号做key（`t('text_1')`）、无层级平铺（`t('title')`）

## Step 3：翻译执行

### 翻译策略选择

| 策略 | 适用场景 | 成本 | 质量 |
|---|---|---|---|
| AI翻译+人工校对 | 首次翻译、大批量文案 | 低 | 中高 |
| 专业译员翻译 | 核心UI、品牌文案 | 中高 | 高 |
| 社区翻译 | 开源项目、长尾语言 | 低 | 中 |
| TM复用+AI增量 | 已有TM积累的迭代 | 极低 | 高 |

### 翻译工包准备清单

```
翻译工包(Translation Kit)包含：
├── 资源文件（待翻译的JSON/PO/strings）
├── 术语表（Glossary CSV）
├── 上下文说明文档
│   ├── 产品简介（1页）
│   ├── 各页面截图（标注文案位置）
│   └── 品牌语气指南（正式/友好/专业）
├── 翻译要求
│   ├── 字符限制（按钮≤10字符、标题≤20字符）
│   ├── 禁止翻译项（品牌名/变量占位符）
│   └── 特殊说明（RTL语言适配要点）
└── 交付格式要求（保持JSON结构/不修改key名）
```

### 翻译执行时间预估

| 文案量 | 语言数 | AI翻译+校对 | 专业译员 |
|---|---|---|---|
| 100条 | 5种 | 2天 | 1周 |
| 500条 | 10种 | 1周 | 3-4周 |
| 2000条 | 20种 | 2-3周 | 8-10周 |

## Step 5：上线与监控

### 上线检查

| # | 检查项 | 说明 |
|---|---|---|
| 1 | 语言切换功能 | 所有入口可切换且持久化 |
| 2 | 默认语言检测 | 根据浏览器/系统语言自动选择 |
| 3 | 回退机制 | 缺翻译时回退到英语而非显示key名 |
| 4 | SEO | hreflang标签正确（Web端） |
| 5 | 性能 | 语言包加载不影响首屏（异步加载） |

### 上线后监控指标

| 指标 | 说明 | 告警阈值 |
|---|---|---|

| 语言切换转化 | 切换语言后的留存变化 | 留存下降>5% |
| RTL页面Crash | 阿拉伯语/希伯来语页面崩溃率 | >0.1% |

## Step 6：持续迭代机制

| 机制 | 频率 | 说明 |
|---|---|---|
| 新文案i18n检查 | 每次PR | CI/CD自动拦截硬编码 |
| TM更新 | 每次翻译后 | 翻译结果回写TM |
| 术语库更新 | 每次新功能 | PM维护术语表 |
| LQA抽检 | 每季度 | 抽检各语言翻译质量 |
| 语言包瘦身 | 每半年 | 清理废弃key/过时翻译 |

## 常见踩坑

| 坑 | 后果 | 预防 |
|---|---|---|
| 先上线中文版再补i18n | 重构成本是原生i18n的3-5倍 | Day 1接入i18n |
| 不做CI硬编码检查 | 新功能持续引入硬编码文案 | eslint-plugin-i18n接入CI |
| 翻译完不做UI测试 | 德语膨胀导致按钮截断 | 必须做多语言截图测试 |
| 忽略RTL | 阿拉伯语市场直接不可用 | 首批语言包含1种RTL语言 |
| 不维护TM | 每次全量重译，成本浪费 | 建立TM+增量翻译机制 |

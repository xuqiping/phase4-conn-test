# 3.3 定性方法深度

## 半结构化访谈：需求收集的核心武器

半结构化访谈是PM发现隐含需求的**最高效定性方法**——有提纲但不被提纲束缚，灵活追问才能穿透L1表层到达L2/L3深层需求。[来源:📚训练知识]

### 访谈全流程

| 阶段 | 关键动作 | 常见错误 |
|---|---|---|
| **准备** | 确定访谈目标→写提纲（5-8个开放问题）→预演→筛选受访者 | 提纲问题太多（>10个）/全是封闭问题/只访谈友好用户 |
| **开场** | 建立信任→说明目的与保密→暖场问题 | 一上来就问核心问题，对方还没放松 |
| **深挖** | 开放提问→追问→再追问→切换话题 | 满足于第一层回答就跳走 |
| **收尾** | 总结关键发现→问"还有什么想补充的"→致谢 | 不做总结，遗漏关键信息 |
| **整理** | 24h内写访谈纪要→编码→交叉验证 | 一周后才整理，记忆衰减严重 |

### 追问五层法（The Five Whys for Interviews）

```
L1: "你想要什么功能？"
    → 用户说："我要导出Excel"
L2: "你导出Excel做什么？"
    → 用户说："我要给老板做周报"
L3: "为什么不用系统直接分享？"
    → 用户说："老板不看系统，只看Excel"
L4: "老板为什么只看Excel？"
    → 用户说："因为他在手机上看，系统没有移动端"
L5: "如果系统有移动端，你还导出Excel吗？"
    → 用户说："那就不需要了"
```

> 真实需求不是"导出Excel功能"，而是"让不看系统的决策者也能看到数据"。[来源:📚训练知识]

## 现场观察与沉浸式研究

| 方法 | 适用场景 | 核心价值 | 执行要点 |
|---|---|---|---|
| **伴随研究** | B端/SaaS用户工作流程 | 看到用户"怎么做"而非"说怎么做" | 全程安静记录，不干预不动手 |
| **影子跟班** | 实体场景（零售/医疗/工厂） | 发现用户自己都意识不到的操作习惯 | 至少跟3个完整工作周期 |
| **日记研究** | 长周期行为（健身/学习/消费） | 捕获时间维度的需求波动 | 用照片+语音降低用户负担 |
| **情境探查** | 复杂协作场景 | 理解人际交互中的需求 | 关注"求助""吐槽""变通"三个信号 |

> 现场观察的黄金法则：**用户说的× 用户做的√ 用户绕过系统偷偷做的√√√**。"绕过"是最强需求信号。[来源:📚训练知识]

## 焦点小组：慎用而非不用

| 适用 | 不适用 | 陷阱 |
|---|---|---|
| 需求探索初期的**方向发散** | 需求验证（群体压力导致从众） | 意见领袖主导 |
| 概念/原型的**初步反馈** | 收集个人深层动机 | 社会期望偏差（说好听的不说真实的） |
| 团队内部**对齐需求理解** | 取代一对一访谈 | 讨论偏离主题无产出 |

> 经验法则：焦点小组用于发现问题，不用于确认问题。确认必须回归一对一访谈。[来源:👥Nielsen Norman Group | 🔍高 | 2020]

## 定性数据分析：从访谈记录到需求条目

```
原始记录 → 开放编码（标记关键表述）
         → 轴心编码（建立表述间关联）
         → 选择性编码（提炼核心需求主题）
         → 需求条目（结构化输出）
```

| 编码层级 | 操作 | 输出 |
|---|---|---|
| 开放编码 | 逐条标记关键表述 | 标注片段集合 |
| 轴心编码 | 按场景/动机/痛点关联 | 主题集群 |
| 选择性编码 | 提炼核心需求+支持证据 | 需求条目清单 |

> 编码不是"给标签"，而是"建构理解"。好的编码让跨受访者的需求模式自动浮现。[来源:📚训练知识]

# 收录命中确认式回复 · 人工测试方案

> Phase 3 功能级预处理产出（5x #7，plan Chunk 4）。
> 关联计划：[../plans/5x记忆二期_第三轮问题修复.plan.md](../plans/5x记忆二期_第三轮问题修复.plan.md)
> **文档规模**：≤5000 tokens。

## 1. 为什么需要人工测试（判定依据）

- [x] 涉及 UI 交互（确认按钮点选、按钮置灰、流式回答渲染）
- [x] 需人工确认的业务流程（确认式回复形态、收尾文案体感）
- [x] 走真实异步收录（收录结果在项目面板肉眼核对）

**自动化已覆盖**：快检命中/排序/兜底名、确认点选状态机、防死循环、防重插 USER（后端单测 8 个全绿）。机器测不了：按钮渲染形态、SSE 流式体感、异步收录落库的端到端核对。

## 2. 前置条件

- **环境**：本地（后端 :8080 + 前端 vite）；Chrome/Edge。
- **数据准备**：测试账号 A；A 是项目 P1 的成员且 P1 生成开关开；P1 有**文件名硬规则**（如 pattern「课件」，enabled）；P1 的 anchor 就绪（总结可用可不配）。
- **依赖服务**：PostgreSQL / Redis / LLM 网关正常。
- **开关**：`rag.memory.inclusion-confirm.enabled = true`（默认已置，V127）。

## 4. 测试用例（联动，对应 plan 联动点清单）

| 编号 | 场景 | 操作步骤 | 预期结果 | 实际 | 通过? |
|---|---|---|---|---|---|
| TC1 | 输入命中硬规则→确认形态 | 1. 聊天页挂附件「数学课件.pdf」发消息「帮我看看课件」<br>2. 观察回复 | ①秒回模板文案「你输入的内容已命中项目 「P1」（附件《数学课件.pdf》命中规则『课件』）…需要我基于你的输入进行回答吗？」，**无 LLM 长输出**；②文案下有「✅ 需要回答 / 🚫 不用了」两按钮；③不再点选，直接再发一条纯文本新消息→正常 LLM 回答（同输入不阻塞后续对话） | | ⬜ |
| TC2 | 点「需要回答」→全量+收录 | TC1 后点「✅ 需要回答」 | ①按钮变「✅ 已选择回答」不可再点；②流式输出对原输入的全量回答；③等异步收录跑完（秒级），P1 项目条目出现该轮内容（收录照旧，未被确认流影响） | | ⬜ |
| TC3 | 点「不用」→收尾置灰 | 重发命中附件消息（换会话或新附件名再命中），点「🚫 不用了」 | ①按钮变「已选择不回答」；②追加收尾消息「好的，本次不作答。相关内容将按项目规则收录，可继续输入新消息。」，无 LLM 调用；③该轮内容仍按规则异步收录（DECLINE 只是不作答，不禁收录） | | ⬜ |
| TC4 | 规则删除/改名→缓存滞后 | 1. 命中一次确认后，管理员把 P1 硬规则停用<br>2. 立刻（<15s）再发命中附件<br>3. 等 >15s 再发一次 | ②TTL 内可能仍出确认文案（旧判定，可接受，仅文案滞后不产生错误收录——实际收录以异步路由为准）；③15s 后恢复全量回答。**偏离说明**：plan 写「保存即 evict + ≤30s」，实现为**纯 TTL 15s 无保存 evict**（避免 RuleService↔QuickCheckService 循环依赖；窗口减半，语义不变） | | ⬜ |
| TC5 | 多项目同时命中→全列 | A 同时是 P1（规则先建）与 P2（规则后建）成员且两项目都有命中规则，发命中附件 | 确认文案**同时列出 P1、P2**（各带命中文件与规则）；点「需要回答」后实际收录进**先建规则项目 P1**（Chunk2 先建者赢，与文案列全不矛盾） | | ⬜ |

## 5. 边界 / 异常场景

| 编号 | 场景 | 预期 | 实际 | 通过? |
|---|---|---|---|---|
| EC1 | 纯文本消息（无附件） | 不进快检（MVP 只做文件名确定性匹配），直接全量回答 | | ⬜ |
| EC2 | 二次点选（刷新页面后旧按钮再点/并发双击） | 服务端 400「可能已点选过」，前端提示确认失败，不重复生成 | | ⬜ |

| EC5 | 历史会话回看 | 确认消息按钮按服务端 metadata 状态渲染（PENDING→按钮；已点→状态标），刷新不复活按钮 | | ⬜ |

## 7. 备注 / 已知问题

- MVP 只做**文件名硬规则**确定性快检；文本语义命中维持事后异步收录（同步判语义必拖首字延迟）。
- 确认轮（模板文案/收尾消息）不进记忆生成——模板消息由确认分支直落，不经 processTurnAsync。

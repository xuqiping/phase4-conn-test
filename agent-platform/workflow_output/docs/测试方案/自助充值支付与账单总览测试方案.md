# 人工测试方案 · 自助充值支付与账单总览

> 来源：spec §9.2 五条（`../specs/自助充值支付与账单总览设计.md`）。机器测不了的才在这里——
> 状态机/幂等/对账已由 PaymentFlowIT + PaymentAdminQueryIT + 单测覆盖（真 PG）。
> 环境：后端 `billing.payment.mock-enabled=true`（it/dev 默认）；账号 admin/admin123 + 普通用户各一。

## TC-1 · 用户端完整充值（mock 全链）

**步骤**：
1. 普通用户登录 →「我的钱包」→ 右上角「充值」。
2. 金额输 `100`，渠道选「模拟支付」→「去支付」。
3. 收银台点「模拟支付成功」→ 等轮询（≤4s）。

**预期**：
- 弹窗提示「支付成功，积分已入账」，余额卡片立即 +1000（按当前阶梯比例，以弹窗「可得积分」为准）。
- 「充值记录」卡第一行六字段齐：时间=刚才 / 渠道=模拟支付 / 付款账号=mock-user@wallet / 金额=100.00 / 积分=弹窗所示 / 充值后余额=新余额；状态「已支付」。
- 累计条「累计充值 100 元，共 xx 积分」同步增加。
- 最近流水卡出现一条 RECHARGE。

## TC-2 · 双击/重复提交只一单

**步骤**：
1. 充值弹窗填好金额渠道，「去支付」**快速连点 3 次**。
2. 进收银台后刷新页面，重新打开弹窗**用同金额再下一单**；再改金额（如 100→50）提交。

**预期**：
- 连点只产生一个订单（网络面板或充值记录核对无重复 PENDING 单）。
- 同会话同金额重提交 → 返回原单（不新增记录）。
- 同会话改金额 → 提示「重复提交金额不一致，请刷新后重试」（409）。

## TC-3 · 订单过期自动关单

**准备**：临时把 `billing.payment.order-expire-minutes` 调为 `1`（重启后端），job 每分钟扫。

**步骤**：下一单不支付，等 2 分钟 → 刷新「充值记录」。

**预期**：该行状态「已关闭」；收银台侧轮询自动停止并提示订单已关闭。余额/流水无变化。
**恢复**：测完把 expire 调回 30。

## TC-4 · admin 两 tab 与手工 SQL 对账

**步骤**：
1. admin 登录 →「计费管理/账单总览」→「用户余额」tab。
2. 记下合计卡四数；用户名筛一个刚充过值的用户。
3. 手工 SQL 核对：
   ```sql
   SELECT COALESCE(SUM(amount_yuan),0), COALESCE(SUM(points_granted),0)
   FROM payment_order WHERE status='PAID';           -- ≈ 合计卡累计充值金额/积分（含历史）
   SELECT COALESCE(SUM(balance_points),0) FROM user_points_balance;  -- ≈ 余额合计
   ```
4. 点三列列头排序（余额/累计积分/累计金额）各一次。
5. 切「充值记录」tab：筛渠道=模拟支付 → 看汇总条；再筛状态=待支付。

**预期**：
- 合计卡与 SQL 差值仅来自筛选口径外数据（合计卡=全平台）。
- 排序方向正确，翻页不丢排序。
- 充值记录汇总条随筛选联动；筛「待支付」时汇总归 0（口径=已付，不误导）。

## TC-5 · prod 下 mock 开关拒启动

**步骤**：以 prod profile 启动后端且 `BILLING_PAYMENT_MOCK_ENABLED=true`。

**预期**：启动失败，日志含 `PaymentConfigGuard` 明确报「prod 环境禁止开启 mock 支付通道」。
**反向**：prod + mock=false 正常启动；dev/it + mock=true 正常启动。

## 通过标准

- TC-1~5 全部符合预期。
- 联动核对：TC-1 成功后 admin「充值记录」tab 能按用户名筛到该单且字段与用户端一致（两端同源）。
- 异常路径（TC-3 关单后 mock 补推成功回调）：admin 对账「支付渠道异常」第三节出现该单（人工补单线索），余额**不变**——由 PaymentFlowIT 覆盖，人工可选复核。

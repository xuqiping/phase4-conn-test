# 复制粘贴强化功能后续计划

更新时间：2026-05-31

## 短期优先事项

1. 完成桌面端实机回归
   - 启动 Tauri 桌面窗口。
   - 复制普通文本，确认列表自动刷新。
   - 连续复制相同文本，确认不会出现多条重复记录。
   - 复制不同文本，确认按时间顺序显示。
   - 右键记录执行“复制”，确认系统剪贴板内容正确，并显示复制成功提示。
   - 双击记录执行复制，确认选中记录能写回系统剪贴板，并显示复制成功提示。
   - 选中多条记录后按 Ctrl+C，确认按列表顺序批量复制，并显示复制条数。
   - 点击“批量复制”，确认多条记录复制正确。
   - 右键记录执行“删除”，确认单条记录消失。
   - 使用复选框、多选、全选、反选、删除选中，确认批量操作正确。
   - 取消勾选后确认绿色选中框立即消失。
   - 滚动大量剪贴板历史，确认顶部批量操作工具栏固定在列表顶部且不遮挡内容。
   - 对文件类型记录执行“打开文件”，确认能打开对应文件。
   - 对文件类型记录执行“打开文件所在目录”，确认能打开并定位到对应文件位置。
   - 对文件类型记录执行“复制文件路径”，确认系统剪贴板获得正确路径。
   - 复制单张图片文件，确认历史中归类为图片而不是普通文件。
   - 对图片记录执行“打开文件”和“打开文件所在目录”，确认行为正确。
   - 复制图片后确认列表缩略图和详情预览都能完整显示，不因裁切导致内容缺失。
   - 使用 `Win + Shift + S` 截图，确认截图会进入剪贴板历史并显示为图片记录。
   - 在浏览器中右键复制图片，确认常见 PNG/DIB/DIBV5 剪贴板图片能进入历史；若浏览器只提供私有格式，记录为后续兼容问题。
   - 复制带文字的图片或截图后确认 OCR 结果写入备注；如果系统 OCR 无结果，应确认不会显示错误。
   - 打开剪贴板顶部“剪贴板设置”，确认能看到“文件和图片保存方式”和“备份位置”。
   - 选择自选备份目录，复制新文件/图片文件，确认文件进入自选目录 `files` 子目录，图片进入自选目录 `images` 子目录。
   - 分别选择“备份副本”和“仅记录原始文件地址”，复制新文件/图片文件验证只影响新记录。
   - 在“仅记录原始文件地址”模式下复制文件和图片文件，确认只记录原始路径、不生成备份副本。
   - 在“仅记录原始文件地址”模式下截图，确认截图仍保存到图片缓存目录并进入剪贴板历史。
   - 复制同名文件到备份目录，确认备份名保留原名并追加“备份”，同名时追加编号。
   - 切换到剪贴板页，确认不再出现文件管理页的搜索、排序、路径、底部“共 X 个项目”等控件。
   - 切换到剪贴板页，确认首屏不再明显卡顿。

2. 剪贴板页面体验继续打磨
   - 根据桌面端实机反馈，评估复制成功提示的位置、颜色和停留时长是否需要调整。
   - 复制失败提示当前会显示具体错误，后续可统一为更友好的中文文案。
   - 观察剪贴板顶部工具栏在窄窗口下是否拥挤，必要时把筛选项折叠或换行。
   - 评估“剪贴板设置”是否还需要在空状态、侧边栏或快捷入口中重复展示。
   - 快速粘贴快捷键仍按既定方向放在快捷面板能力中继续完善。

3. 完善删除确认策略
   - 评估单条右键删除是否需要二次确认。
   - 批量删除建议增加确认弹窗，避免误删多条历史。
   - 确认弹窗样式可参考进程管理模块的确认对话框。

4. 优化右键菜单体验
   - 右键菜单位置靠近窗口边缘时需要避免溢出屏幕。
   - 点击菜单外、滚动列表、按 Esc 时关闭菜单。
   - 文件记录无可用路径时隐藏或禁用“打开文件目录”。
   - 后续可加入“复制纯文本 / 复制原格式”等格式选项。

5. 优化重复文本策略
   - 当前策略是相同文本不新增历史项，并刷新到列表顶部。
   - 后续可考虑在详情中区分“首次复制时间”和“最近复制时间”。
   - 后续可评估是否需要显示重复复制次数。

6. 完善错误提示
   - 复制失败已能显示明确提示，后续继续优化文案和样式。
   - 打开文件目录失败时显示路径不存在或权限不足提示。
   - 删除失败时恢复列表状态或提示重试。

## 中期事项

1. 文件和图片历史能力打磨
   - 文件副本缓存策略实机验证。
   - 自选备份目录在本地磁盘、移动硬盘和不可用路径下的实机验证。
   - “备份副本 / 仅记录原始地址”切换后的新旧记录行为验证。
   - 仅记录地址模式下，截图仍落入图片缓存目录的实机验证。
   - 图片缩略图显示和缓存清理验证。
   - Windows 截图、浏览器复制图片、资源管理器图片文件三类图片来源的兼容性验证。
   - 图片 OCR 在不同语言包、不同图片格式和大图下的表现验证。
   - 按类型配置空间上限。
   - 后缀白名单 / 黑名单设置界面打磨。

2. 搜索、筛选和备注体验
   - 搜索文本、文件名、来源应用、OCR 文本和备注内容。
   - 验证日期筛选：全部时间、今天、昨天、近 7 天、近 30 天、自定义起止日期。
   - 验证自定义日期结束日包含当天 23:59:59.999 前的记录。
   - 类型筛选、日期筛选、搜索关键词和批量选择联动。
   - 当前列表范围内全选和反选保持现有规则，避免误操作不可见记录。
   - 备注编辑区可继续优化为自动保存或离开记录前提醒保存，暂不作为首版强制项。

3. 安全防护体验
   - 敏感内容拦截后的安全事件展示优化。
   - 密码管理器来源识别实机验证。
   - 用户排除应用设置流程优化。

4. 快捷面板体验
   - 快捷面板打开速度回归。
   - 键盘选择、回车复制、Esc 关闭。
   - 自动粘贴关闭时默认只复制回剪贴板。
   - 自动粘贴开启时失败后仍保留在系统剪贴板。

5. 本地增强 OCR 方案设计
   - 先抽象统一 OCR Provider 接口，避免业务代码直接绑定 Windows 系统 OCR。
   - 设计 OCR 结果结构：纯文本、文本块、置信度、坐标框、引擎名称、耗时，方便后续搜索命中定位和图片文字高亮。
   - 优先采用 sidecar / 本地服务模式接入 RapidOCR，Rust 后端传入图片路径，OCR 引擎返回 JSON，降低直接绑定 AI 推理库的复杂度。
   - 设置页后续可增加 OCR 引擎选择：关闭、Windows 系统 OCR、本地增强 OCR。
   - 模型文件需支持离线部署和本地路径配置，避免运行时强制联网下载。

## 长期事项

1. 跨平台实现
   - 第一阶段只实现 Windows。
   - 保留 macOS / Linux 接口边界，后续再补平台实现。

2. 智能增强
   - Windows 系统 OCR 已接入，但后续目标是不再只依赖系统 OCR。
   - 优先调研并接入 RapidOCR + ONNX Runtime 作为本地增强 OCR 引擎，重点验证中文/中英混合截图、浏览器复制图片、资源管理器图片文件三类场景。
   - PaddleOCR 作为中文 OCR 能力、模型来源和后续训练/微调方向参考；首版不建议直接内置完整 PaddleOCR 运行环境。
   - Umi-OCR 作为桌面端 OCR 产品形态参考，重点参考其本地 OCR 引擎、截图 OCR、批量 OCR、命令行/HTTP 调用模式。
   - Tesseract OCR 可作为经典稳定备选，但不作为中文截图 OCR 的主力方向。
   - Surya OCR 更适合后续复杂 PDF、表格、阅读顺序和版面分析，不放入首版本地截图 OCR。
   - URL 预览默认关闭，用户开启后再联网。
   - 后续可加入本地摘要、格式转换、常用片段推荐等能力。

3. 云能力
   - 当前阶段不做云同步。
   - 云同步、跨设备同步、账号体系、端到端加密等能力后期统一设计和实现。

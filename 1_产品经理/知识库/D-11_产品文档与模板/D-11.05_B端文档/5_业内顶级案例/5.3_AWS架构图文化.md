# AWS Well-Architected Framework

## 案例基础

- **案例名称**：AWS Well-Architected Framework——B端文档标准化服务
- **时间**：2015-2025
- **主角**：Amazon Web Services

## 背景

AWS企业客户常问"你们方案好不好"但无法自证。AWS的解法不是PPT说"我们好"，而是提供一套**可量化、可自评**的架构评估框架——客户用这个框架自己评估方案质量。

## Well-Architected六大支柱

| 支柱 | 核心问题 | 评估方式 |
|---|---|---|
| 卓越运营 | 运维效率高不高？ | 检查清单+评分 |
| 安全性 | 安全合规过不过关？ | 安全自评+合规对照 |
| 可靠性 | 系统稳定不稳定？ | 架构Review+故障模拟 |
| 性能效率 | 性能/成本比好不好？ | 性能基准+成本分析 |
| 成本优化 | 花钱花得值不值？ | TCO对比+右sizing |
| 可持续性 | 环保达标不达标？ | 碳足迹评估 |

## 核心创新：文档即服务

AWS不卖"方案文档"，而是卖"框架+Review服务"——客户付费让AWS架构师用此框架Review自己的方案，评审报告=方案文档。这本质上是**文档产品化**——把PM的方案能力产品化。

## 影响后果

- 每年数万次Well-Architected Review [来源：AWS re:Invent | 置信度：📚中 | 2024]
- 成为B端云架构评估的行业事实标准

## 教训启示

1. **最好的B端方案文档是让客户自己证明**：不是你说好，而是客户用你的框架自己评估出好
2. **框架>文档**：给客户一个可自评的框架，比给一份精美的方案更有说服力
3. **文档可以产品化**：Review服务=文档能力的产品化变现

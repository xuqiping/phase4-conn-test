# agent-platform 部署要求（Windows Server）

> **部署模型：开发机构建，服务器只跑运行时。**
>
> - **开发机**：用 JDK/Maven/Node 把产物 build 出来（jar + dist + sidecar）。
> - **服务器**：只装**运行时**（JRE + PostgreSQL + pgvector + Redis + Python + Nginx），把产物丢上去跑。**服务器不装 Maven、不装 Node/npm**。
> - **前端独立打包**，Nginx 托管静态 + 反代 `/api` —— 改前端不用重打后端。
>
> 版本：2026-06-29｜本机（开发机）用户：Administrator

---

## 一、角色与产物

| 角色 | 机器 | 装什么 | 产出 |
|---|---|---|---|
| 构建 | 开发机（本机） | JDK 17 / Maven / Node | `agent-platform-*.jar` + `frontend/dist/` |
| 运行 | 服务器 | JRE 17 / PG16+pgvector / Redis / Python / Nginx | 跑 jar + Sidecar + Nginx |

**需要搬到服务器的产物（ship list）：**

| 产物 | 来源 | 服务器落点 |
|---|---|---|
| `agent-platform-0.1.0-SNAPSHOT.jar` | `backend/target/` | `C:\agent-platform\backend\` |
| `frontend/dist/`（整目录） | `frontend/dist/` | `C:\agent-platform\frontend\dist\` |
| `runtime-sidecar/`（整目录，含 `app/` + `requirements.txt`） | `runtime-sidecar/` | `C:\agent-platform\runtime-sidecar\` |
| pgvector 运行时文件（仅服务器 PG 无 pgvector 时） | 本机 PG16 | 服务器 PG16 的 `lib\` + `share\extension\` |

> Sidecar 是 Python，**塞不进 jar**，独立进程。仅使用工作流时才需要。

## 五、与 file-keeper 共存（同机部署）

两平台同机共存，端口与库名互不冲突：

| 资源 | file-keeper | agent-platform | 冲突 |
|---|---|---|---|
| 后端端口 | 8088 | **8080** | 否 |
| Sidecar 端口 | — | **8090** | 否 |
| PostgreSQL | 5432（库 `file_keeper`） | 5432（库 **`agent_platform`**） | 共享实例，分库 |
| Redis | 6379 | 6379 | 共享实例，建议分 db 索引 |
| Nginx 80 | 站点 A | 站点 B | `server_name` 分流或换端口 |

> pgvector 在 PG 服务器**只装一次**；`agent_platform` 库需 `CREATE EXTENSION vector`。

## 六、开发机：构建产物

> 本机齐备 JDK17/Maven3.9/Node24，直接 build。

### 6.1 后端 jar

```cmd
cd agent-platform\backend
mvn clean package -DskipTests
:: 产物：backend\target\agent-platform-0.1.0-SNAPSHOT.jar
```

### 6.2 前端 dist

```cmd
cd agent-platform\frontend
npm install
npm run build
:: 产物：frontend\dist
```

> axios `baseURL='/api'`（相对路径），由 Nginx 反代，**构建时不写死后端地址**。钉钉免登改 `.env.production` 的 `VITE_DINGTALK_*`。

### 6.3 Sidecar

Sidecar 不编译，整目录搬。服务器侧首次 `pip install`（见 §七-E）。

### 6.4 一键构建（可选，开发机）

```bat
@echo off
chcp 65001
cd /d %~dp0
cd backend && call mvn clean package -DskipTests && cd ..
cd frontend && call npm run build && cd ..
echo 产物：backend\target\*.jar + frontend\dist
pause
```

## 七、服务器：运行时安装 + 启动

> 服务器只跑运行时。下列为**首次安装**步骤。

### A. JRE/JDK 17（跑 jar，**不需要 Maven**）

- **下载**：https://adoptium.net/temurin/releases/?version=17 （JRE 更小；或直接 JDK）。
- **安装**：双击 MSI，设 `JAVA_HOME`，`Path` 增 `%JAVA_HOME%\bin`。
- **或免下载**：把本机 `C:\Program Files\Microsoft\jdk-17.0.19.10-hotspot` 整目录复制到服务器，设 `JAVA_HOME`。
- 验证 `java -version` 显示 17。

### B. PostgreSQL 16 + pgvector

- **下载**：https://www.postgresql.org/download/windows/ （16.x）。
- **安装**：记超管密码、端口 5432、数据目录。
- **装 pgvector**（服务器 PG 无则装）：
  1. 从本机打包 `vector.dll`（→ `lib\`）+ `vector.control` 及 `vector--*.sql`（→ `share\extension\`）。
  2. 覆盖到服务器 `C:\Program Files\PostgreSQL\16\` 对应目录，重启 PG 服务。
- **建库 + 扩展**：
  ```sql
  CREATE DATABASE agent_platform OWNER postgres ENCODING 'UTF8';
  \c agent_platform
  CREATE EXTENSION vector;
  SELECT extversion FROM pg_extension WHERE extname='vector';   -- 应返回 0.8.2
  ```
- **与 file-keeper 共用 PG**：跳过重装，只建 `agent_platform` 库 + `CREATE EXTENSION vector`。

> 向量列用 `halfvec(2048)` + HNSW（Doubao Embedding 2048 维超 HNSW ≤2000 硬限）。`V17` 迁移首行 `CREATE EXTENSION vector` 失败则后端起不来。

### C. Redis / Memurai

- **下载**：Memurai https://www.memurai.com/get-memurai （推荐）或 Redis Windows 5.x https://github.com/tporadowski/redis/releases 。
- **安装**：装为服务，端口 6379。服务管理器确认运行中。
- 本机是老版 3.0.504，**生产勿沿用**。

### D. Nginx（托管前端 + 反代后端）

- **下载**：https://nginx.org/en/download.html （stable zip）。
- **安装**：解压到 `C:\nginx`。
- **配置** `C:\nginx\conf\nginx.conf`：

  ```nginx
  server {
      listen 80;
      server_name agent.yourcompany.com;     # 与 file-keeper 站点用 server_name 分流

      location / {
          root   C:/agent-platform/frontend/dist;
          index  index.html;
          try_files $uri $uri/ /index.html;  # history 模式 SPA 回退（前端刷新不 404）
      }
      location /api/ {
          proxy_pass http://localhost:8080;   # 后端 8080，非 file-keeper 的 8088
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_buffering off;                # SSE 流式对话必须关缓冲
      }
  }
  ```
- **启动**：`cd C:\nginx && start nginx`；重载：`nginx -s reload`。

> Nginx 的 `try_files ... /index.html` 解决 history 模式刷新 404；`proxy_buffering off` 是 SSE 必需。file-keeper 无此两项 —— 两平台 Nginx 配置关键差异。

### E. Python + Sidecar（仅工作流）

- **下载**：https://www.python.org/downloads/windows/ （3.11.x）。
- **安装**：双击，勾 **"Add python.exe to PATH"**。验证 `python --version` ≥ 3.10。
- **或免下载**：用本机保留的 `python-3.11.9-amd64.exe`（见 §四）。
- **首次装依赖**（服务器跑一次）：
  ```cmd
  cd C:\agent-platform\runtime-sidecar
  python -m pip install -r requirements.txt
  ```
- **启动**：
  ```cmd
  python -m uvicorn app.main:app --host 0.0.0.0 --port 8090
  ```

### F. 启动后端 jar（**用 java，不用 mvn**）

```cmd
cd C:\agent-platform\backend
:: 注入生产环境变量后：
java -jar agent-platform-0.1.0-SNAPSHOT.jar
```

注册 Windows 服务（可选，WinSW）：把 §三 下的 `WinSW-x64.exe` 重命名 `agent-platform-backend.exe` + 同名 xml（写 env / jar 路径 / logpath），`install && start`。

## 十、更新部署（改了代码后）

- **只改后端**：开发机 `mvn clean package -DskipTests` → 替换服务器 jar → 重启 java 进程。**前端不动**。
- **只改前端**：开发机 `npm run build` → 替换服务器 `frontend\dist\` → `cd C:\nginx && nginx -s reload`。**后端不动**。
- **改 Sidecar**：替换 `runtime-sidecar\app\` → 若依赖变则重 `pip install` → 重启 uvicorn。

## 十一、与 file-keeper 部署的关键差异速查

| 维度 | file-keeper | agent-platform |
|---|---|---|
| 后端端口 | 8088 | **8080** |
| 数据库名 | `file_keeper` | **`agent_platform`** |
| pgvector | 不需要 | **必须**（halfvec 2048 + HNSW） |
| Python Sidecar | 无 | **必须**（8090，工作流） |
| Nginx `/api` 代理目标 | `:8088` | `:8080` |
| Nginx `proxy_buffering` | 默认 | **必须 off**（SSE） |
| Nginx `try_files /index.html` | 看其前端模式 | **必须**（history SPA 回退） |
| 免登集成 | 无 | 钉钉 H5（可选） |

## 十二、安全建议

1. **JWT_SECRET**：生产必须覆盖默认 base64 占位，≥32 字节随机串。
2. **数据库密码**：`DB_PASSWORD` 强密码，勿用 `aa64221886`。
3. **端口暴露**：仅放行 80/443；后端 8080、Sidecar 8090 不对外。
4. **HTTPS**：生产用 SSL，Nginx 监听 443。
5. **Redis 隔离**：与 file-keeper 共享实例时用不同 db 索引。
6. **备份**：定期备份 `agent_platform` 库（含向量数据）。

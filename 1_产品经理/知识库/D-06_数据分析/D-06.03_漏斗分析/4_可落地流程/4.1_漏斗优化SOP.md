# 4.1 漏斗优化SOP

## 概述

本碎片提供一套从"发现瓶颈"到"验证优化"的7步闭环SOP，并附3组Agent提示词，帮助产品经理在1~2周内完成一轮完整的漏斗优化迭代。

---

## SOP 7步闭环

### Step 1：定义漏斗范围

| 输入 | 动作 | 输出 |
|---|---|---|
| 业务目标（如提高付费转化率） | ①选择主路径/微转化/逆向/时间漏斗类型 ②确定起点和终点事件 ③定义步骤数（建议4~7步） | 漏斗步骤文档 |

**关键决策**：
- 主路径漏斗：适合季度OKR型目标
- 微转化漏斗：适合解决某个步骤的大流失
- 逆向漏斗：适合探索"成功用户做对了什么"
- 时间漏斗：适合评估转化时效

> ⚠️ 避坑：步骤数不要超过7步，超过7步的漏斗通常说明流程设计过于复杂，应先做用户旅程简化。[来源: Amplitude漏斗最佳实践 | 置信度:🔍高 | 2025]

### Step 2：设定时间窗口与分组

| 维度 | 推荐值 | 说明 |
|---|---|---|
| 时间窗口 | 闭合漏斗：同一会话；开放漏斗：7~30天 | 按业务周期调整 |
| 分组 | 渠道/设备/新老用户/版本 | 选2~3个最相关维度 |
| 对比基线 | 自身历史均值 or 竞品公开数据 | 优先自身基线 |

**时间窗口选择规则**：
- 电商下单：同一会话（闭合）
- SaaS试用转付费：14~30天（开放）
- 内容消费转化：7天（开放）
- 新手引导：首日（闭合）

### Step 3：数据采集与校验

1. **事件埋点确认**：核对每个步骤的事件是否已埋点、参数是否完整
2. **数据质量快检**：
   - 步骤N的用户数是否 > 步骤N+1（漏斗递减原则）
   - 整体转化率是否在行业合理区间（如电商2%~5%、SaaS试用转付费15%~30%）
   - 分组样本量是否足够（每组建议≥500用户）
3. **异常数据排查**：检查是否有因技术bug导致的数据断点（如某步骤用户数骤增）

> [来源:GrowingIO数据质量白皮书 | 置信度:🔍中 | 2025]

### Step 4：定位瓶颈步骤

**四象限诊断法**：

```
          流失率高
            |
   优先优化  |  深度分析
  (左上区)   |  (右上区)
            |
 ————————————————
            |
   持续监测  |  暂不处理
  (左下区)   |  (右下区)
            |
          流失率低
   步骤流量小 —————— 步骤流量大
```

- **左上区（优先优化）**：流失率高+流量大 → ROI最高的优化点
- **右上区（深度分析）**：流失率高+流量小 → 可能是细分人群问题
- **左下区（持续监测）**：流失率低+流量小 → 低优先级
- **右下区（暂不处理）**：流失率低+流量大 → 健康步骤

### Step 5：生成优化假设

使用**LIFT模型**（Landing page Influence Function for Tests）构建假设：

| LIFT维度 | 问题描述 | 典型假设 |
|---|---|---|
| 价值主张(Value Proposition) | 这一步给用户的核心价值是否清晰？ | "商品详情页利益点不够突出，导致加购率低" |
| 相关性(Relevance) | 页面内容与用户意图是否匹配？ | "搜索结果与用户关键词不匹配，导致跳出" |
| 清晰度(Clarity) | 用户是否清楚下一步该做什么？ | "CTA按钮位置不明显，导致点击率低" |
| 紧迫感(Urgency) | 用户是否有理由现在行动？ | "限时优惠提示不明显，导致犹豫流失" |
| 焦虑感(Anxiety) | 用户是否有顾虑阻碍行动？ | "支付页缺少信任标志，导致支付放弃" |
| 分散注意(Distraction) | 是否有太多干扰元素？ | "注册页有过多非必要字段，导致放弃" |

### Step 6：设计A/B实验

| 要素 | 说明 | 模板 |
|---|---|---|
| 实验假设 | 基于Step5的假设 | "如果[改动X]，则[指标Y]将提升[Z%]" |
| 核心指标 | 优化步骤的步骤转化率 | 如注册→激活的步骤转化率 |
| 护栏指标 | 不应下降的指标 | 如整体转化率、崩溃率 |
| 样本量 | 按最小可检测效应(MDE)计算 | 推荐使用EvansAB或Statsig计算器 |
| 实验时长 | 至少2个业务周期 | 按周维度观察 |

> 详见D-06.07实验与A/B的完整实验框架。

### Step 7：复盘与迭代

**复盘模板**：

```
1. 实验结果：[胜/负/不确定]  核心指标变化：[+X% / -X%]
2. 假设验证：假设是否成立？[是/否/部分]
3. 新发现：_________________________________
4. 下一步动作：
   - 胜出 → 全量发布 + 更新漏斗基线
   - 负面 → 回滚 + 修正假设 + 新实验
   - 不确定 → 增加样本量 or 细分分析
5. 经验沉淀：_________________________________
```

## Agent提示词

### 提示词1：漏斗诊断

```
你是一个数据分析专家。我将给你一个漏斗的各步骤数据（步骤名、用户数、转化率），请你：
1. 用四象限法判断每个步骤的优先级
2. 对流失率最高的步骤，用LIFT模型列出3~5个优化假设
3. 推荐最值得首试的假设，说明理由

漏斗数据如下：
[粘贴数据]
```

### 提示词2：分组对比分析

```
你是一个数据分析专家。我将给你同一漏斗在两个分组（如新用户 vs 老用户）的数据，请你：
1. 对比每步转化率差异，标注显著差异点
2. 分析差异可能的业务原因
3. 给出针对性优化建议

数据如下：
[粘贴数据]
```

### 提示词3：实验设计

```
你是一个A/B测试专家。基于以下信息，帮我设计一个实验：
- 漏斗瓶颈步骤：[步骤名]
- 优化假设：[假设内容]
- 当前转化率：[X%]
- 日均流量：[Y用户]

请输出：
1. 实验假设（如果...则...格式）
2. 核心指标和护栏指标
3. 最小样本量估算
4. 实验周期建议
5. 分流比例
```

# Agent 配置方式说明

## 1. 配置对象关系

当前平台中，Agent 的配置分为三层：

1. Agent：代表一个智能体，负责承接用户请求。
2. 能力：Agent 下的可调用能力，用于描述 Agent 能处理哪些类型的任务。
3. 步骤：能力的实际执行流程，系统按步骤顺序执行。

推荐理解方式：

```text
Agent
  └── 能力 Skill
        └── 步骤 SkillStep
```

## 2. Agent 如何选择能力

Agent 收到用户输入后，会根据当前 Agent 下的能力列表进行路由。

当前主要依据：

- 能力名称
- 能力描述

因此，能力描述不是普通备注，而是 Agent 判断“什么时候使用这个能力”的关键说明。

示例：

```text
能力名称：需求分析
能力描述：当用户提出产品功能、业务流程或系统建设想法时，分析需求并整理成结构化说明。
```

写能力描述时，应说明：

- 这个能力适合处理什么输入
- 这个能力不适合处理什么输入
- 期望输出什么结果

## 3. 能力配置字段说明

### 3.1 能力名称

简短表达能力用途。

示例：

```text
需求分析
代码生成
测试用例设计
文档总结
```

### 3.2 能力描述

用于 Agent 选择能力。建议写清楚触发场景。

示例：

```text
当用户描述一个新功能、业务流程、产品想法或系统建设需求时，分析目标、用户角色、核心功能、约束条件和验收标准。
```

### 3.3 类型

当前推荐填写：

```text
SEQUENCE
```

表示按步骤顺序执行。

### 3.4 能力配置 JSON

当前能力级配置 JSON 主要是预留字段。一般填写：

```json
{}
```

后续可用于放能力级高级配置，例如：

```json
{
  "model": "doubao-seed-2.0-code",
  "temperature": 0.3,
  "outputFormat": "markdown"
}
```

注意：当前实际执行链路主要读取“步骤配置 JSON”，能力配置 JSON 暂不作为主要执行依据。

## 4. 步骤配置字段说明

能力真正执行时，系统会读取能力下的步骤，并按 `stepOrder` 顺序执行。

### 4.1 步骤名称

说明这一步做什么。

示例：

```text
分析需求
生成方案
检查输出
```

### 4.2 动作

动作决定这一步由哪个处理器执行。

当前常用动作：

```text
LLM_CALL
```

表示调用大模型执行这一步。

### 4.3 步骤配置 JSON

步骤提示词写在步骤配置 JSON 的 `promptTemplate` 字段中。

`LLM_CALL` 推荐配置格式：

```json
{
  "promptTemplate": "请根据用户输入，分析其真实需求，输出：1. 目标；2. 用户角色；3. 核心功能；4. 约束条件；5. 验收标准。请用 Markdown 输出。",
  "model": "doubao-seed-2.0-code",
  "temperature": 0.7,
  "outputKey": "requirement_analysis"
}
```

字段说明：

| 字段 | 作用 | 推荐填写 |
|---|---|---|
| `promptTemplate` | 步骤提示词，决定模型怎么处理任务 | 必填 |
| `model` | 使用的模型 | 不确定时填 `doubao-seed-2.0-code` |
| `temperature` | 输出发散程度，越低越稳定 | 稳定任务填 `0.3`，创意任务填 `0.7` |
| `outputKey` | 当前步骤输出保存到变量中的名称 | 使用英文或下划线命名 |

## 5. 一个完整示例

### 5.1 能力配置

```text
能力名称：需求分析
能力描述：当用户提出产品功能、业务流程或系统建设想法时，分析需求并整理成结构化说明。
类型：SEQUENCE
能力配置 JSON：{}
```

### 5.2 步骤配置

```text
步骤名称：分析需求
动作：LLM_CALL
```

步骤配置 JSON：

```json
{
  "promptTemplate": "请根据用户输入，分析其真实需求，输出：1. 目标；2. 用户角色；3. 核心功能；4. 约束条件；5. 验收标准。请用 Markdown 输出。",
  "model": "doubao-seed-2.0-code",
  "temperature": 0.7,
  "outputKey": "requirement_analysis"
}
```

## 6. 填写建议

### 6.1 普通能力

如果只是想让 Agent 能处理一种任务，优先写好：

1. 能力名称
2. 能力描述
3. 步骤名称
4. 步骤动作 `LLM_CALL`
5. 步骤配置 JSON 中的 `promptTemplate`

能力配置 JSON 可以先填：

```json
{}
```

### 6.2 能力描述和步骤提示词的区别

| 内容 | 用途 | 示例 |
|---|---|---|
| 能力描述 | 帮助 Agent 判断是否选择这个能力 | “当用户提出产品功能需求时使用” |
| 步骤提示词 | 指导模型实际执行任务 | “请分析目标、用户角色、核心功能和验收标准” |

简单理解：

```text
能力描述：决定用不用这个能力。
步骤提示词：决定用了以后怎么工作。
```

## 7. 当前界面限制

当前界面仍直接暴露 JSON 配置，对非技术用户不够友好。

后续建议优化为：

- 步骤动作使用下拉框选择
- 当动作选择 `LLM_CALL` 时，显示“提示词模板”大文本框
- `model`、`temperature`、`outputKey` 做成普通表单字段
- 原始 JSON 收到“高级设置”中

## Step 9：兼容授权接口并移除授权私钥启动依赖（RED→GREEN）

- [ ] **目标**：新服务不依赖商业签名配置，旧客户端授权请求仍得到稳定响应。
- **动作**：
  - 先改测试定义兼容语义：登录授权快照中全部模块 allowed；匿名快照仅 files/processes/clipboard allowed，work-report/ai reason 为“请先登录”。
  - 简化 `AuthorizationService`：不查权益；仍检查账号/设备状态并返回兼容 DTO。
  - entitlement 私钥改为可选：配置时仅为旧客户端临时签发“全模块”兼容凭据；未配置时 `offlineToken=null`，服务正常启动；新客户端不读取该字段。
  - 匿名授权不创建/读取试用记录，仅返回固定兼容快照；匿名 trial/start 返回稳定的“本地功能可用、无需选择免费模块”兼容状态；选择/更换免费模块接口返回明确废弃响应。
  - `AuthProperties` 移除 entitlement 私钥必填和启动失败规则，保留可选解析与 JWT secret 强校验。
  - `application.yml` 与测试配置移除授权私钥必配项。
  - 保留旧表、Repository、Controller 源码到后续物理清理阶段，不新增写入。

## 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| active 设备校验 | 确认这台设备属于当前账号且没被管理员封禁 | 被禁用电脑访问 AI 返回 403 |
| 兼容快照 | 为旧客户端保留格式，但不再表达付费权益 | 登录快照全部 allowed 且无离线 Token |
| N+1 | 查一批数据时又逐条发很多 SQL | 本计划设备校验每请求只查一次设备 |

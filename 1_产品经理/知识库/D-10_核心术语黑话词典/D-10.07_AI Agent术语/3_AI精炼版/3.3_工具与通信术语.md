# 工具与通信术语

## 1. 工具调用 / Tool Use

| 字段 | 内容 |
|---|---|
| 英文全称 | Tool Use / Tool Calling |
| 定义 | Agent调用外部工具（API/数据库/搜索/代码执行器等）以完成LLM自身无法完成的操作 |
| PM解读 | Tool Use是Agent的"手"——没有工具的Agent只能在脑子里想，有工具的Agent才能动手做事。工具列表的设计是Agent产品的核心PM决策 |
| 来源 | [📚训练知识] |

## 2. 函数调用 / Function Calling

| 字段 | 内容 |
|---|---|
| 英文全称 | Function Calling |
| 定义 | LLM识别用户意图后，输出结构化的函数调用请求（函数名+参数），由宿主程序执行并返回结果 |
| PM解读 | Function Calling是Tool Use的具体实现方式之一——模型不是"自己调用"，而是"告诉我该调用什么函数，我来帮你调用"。这是安全设计：模型不直接执行，只建议 |
| 对比Tool Use | Function Calling是Tool Use的"实现协议"，Tool Use是"能力描述"。不同模型厂商的Function Calling格式不完全兼容 |
| 来源 | OpenAI, 2023 [📚训练知识] |

## 3. 模型上下文协议 / MCP

| 字段 | 内容 |
|---|---|
| 英文全称 | Model Context Protocol |
| 缩写 | MCP |
| 定义 | Anthropic于2024年11月发布的开放协议，标准化LLM与外部数据源/工具的连接方式——让Agent能统一接入各种工具和数据 |
| PM解读 | MCP是"AI的USB接口"——以前每个工具需要单独适配，有了MCP就像有了统一插口，工具即插即用。2025-2026年生态快速扩张 |
| 定位 | 解决"Agent怎么连接工具和数据"的问题——是Agent的"I/O层" |
| 来源 | [来源:Anthropic官方 | 🔍高 | 2024-11] |

## 4. 智能体间协议 / A2A

| 字段 | 内容 |
|---|---|
| 英文全称 | Agent-to-Agent Protocol |
| 缩写 | A2A |
| 定义 | Google于2025年4月开源的协议，目标是让不同平台/公司的Agent能互相发现、通信、协作——Agent之间的"社交协议" |
| PM解读 | A2A解决"不同Agent怎么互相说话"——如果说MCP是Agent连工具的协议，那A2A就是Agent连Agent的协议。现在由Linux Foundation治理 |
| 对比MCP | MCP=Agent连工具/数据（Agent→Tool），A2A=Agent连Agent（Agent↔Agent）。二者互补不替代 |
| 来源 | [来源:Google官方 | 🔍高 | 2025-04] |

## 5. 智能体通信协议 / ACP

| 字段 | 内容 |
|---|---|
| 英文全称 | Agent Communication Protocol |
| 缩写 | ACP |
| 定义 | 聚焦边缘/本地设备上Agent间通信的协议标准，与MCP(云端)和A2A(跨平台)形成"云-边-端"三层协议体系 |
| PM解读 | ACP是"MCP的边缘版"——当Agent需要与本地设备（手机、IoT、本地服务器）通信时，ACP提供标准化的方式 |
| 来源 | [来源:腾讯云 | 📚中 | 2026-06] |

## 6. 技能 / Skills

| 字段 | 内容 |
|---|---|
| 英文全称 | Skills |
| 定义 | Agent可执行的具体能力单元，是工具调用的高层封装——一个Skill可能包含多个Tool Call和决策逻辑 |
| PM解读 | Skills是Agent的"岗位技能"——Tool是"锤子和螺丝刀"，Skill是"会修电脑"。PM设计Agent产品时，应该用Skill为单位思考能力边界，而非逐个Tool |
| 分层定位 | Tool Use(L1) → Skills(L2) → Workflow(L3) → Agent(L4) |
| 来源 | [来源:CSDN | 📚中 | 2026-06] |

## 7. 回调 / Callback

| 字段 | 内容 |
|---|---|
| 英文全称 | Callback |
| 定义 | 工具执行完成后将结果返回给Agent的机制——Agent不需要轮询，而是工具执行完主动"回调"通知结果 |
| PM解读 | 回调机制决定了Agent的响应延迟模型——同步回调=等工具执行完才继续，异步回调=可以同时执行多任务 |
| 来源 | [📚训练知识] |

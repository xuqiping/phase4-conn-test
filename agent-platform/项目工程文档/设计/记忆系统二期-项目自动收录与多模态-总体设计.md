# 记忆系统二期 — 项目自动收录 + 项目授权 + 多模态文件记忆 · 总体设计

> 创建：2026-08-07
> 前作：[个人记忆重设计-总体设计.md](个人记忆重设计-总体设计.md)（一期，V47-V53 已落地）
> 方法论来源：产品经理知识库 D-19.07 长期记忆系统 / D-24.06 Agent 记忆与上下文 / D-19.12 多模态产品设计
> 性质：在一期「流水账 + 标签 + 总结」骨架上做**三个结构性改造**，不重推一期。

---

## 0. 一句话总览

个人对话**全量进个人流水账**（不再让用户选写入目标）→ 项目创建者给项目配「**收录规则**」（涉及什么内容算本项目的），写时由**路由层自动判定**并把**蒸馏后的条目**写进项目记忆（原文不出个人域）→ 项目可把记忆**授权给别的项目**（项目包含项目，单级不传递）→ 聊天支持上传图片/文件，**一个文件 = 一条记忆**（总结可召回、原文可回链、分块可深读）。

---

## 1. 为什么改（一期的三个死结 + 一个新需求）

| # | 一期模型的结 | 二期解法 |
|---|---|---|
| 1 | **写入目标靠用户手动勾**（§3.2 写入目标多选）：认知负担重，勾错=隐私泄露或项目缺记忆；默认勾{个人}又导致项目记忆靠自觉，永远收不全 | 取消手动写入目标。个人全量进流水账；项目归属由**创建者预先声明规则 + 路由层自动判定**，用户零操作 |
| 2 | **项目共享 = 流水账多挂 `project_ids[]`**：原文（raw）直接暴露给项目成员，隐私边界靠 ACL 细针脚（`memory_recall_acl` reader×target 矩阵）硬撑，复杂且误配即泄露 | 项目记忆**不再是流水账的挂载视图**，而是独立表 `memory_project_entries` 存**蒸馏条目**（L1/L2 级，无 raw）。原文永不离开个人域，ACL 从「人×人」简化为「项目成员=可读」 |
| 3 | **项目间记忆不流通**：A 项目想复用 B 项目的积累，只能把人拉进 B | 项目授权表 `memory_project_links`：B 的 owner 授权 B 进 A，A 召回 = A 条目 ∪ 被授权子项目条目。**单级、不传递** |
| 4 | （新需求）**记忆只有文字**：用户上传课件/图片/文件后无任何沉淀，下次问起 AI 不知道 | 多模态文件记忆：一文件一条目，总结进召回，原文可回链下载，分块支持深读 |

**方法论对齐**（知识库 D-24.06 四层模型映射）：

| 认知层 | 一期 | 二期 |
|---|---|---|
| 情景记忆 Episodic | `memory_turns` 流水账 | 不变（纯个人域） |
| 语义记忆 Semantic | `memory_summaries` 总结 | 个人总结不变；**项目总结升级为项目资产**（见 §8） |
| 共享语义记忆 | 流水账多挂 + ACL（弱模型） | `memory_project_entries` 项目条目 + `memory_project_links` 授权（强模型） |
| 外部记忆 External | 无 | 文件记忆（`memory_asset_memories` + 分块深读，RAG 轻量内化） |

D-19.07 的 CRUD-M 对照：一期只有 C+R+D（删除），二期补上 **M（路由自动归并进项目）** 与**受控遗忘的边界重划**（原文不出域，项目条目可独立淘汰而不动个人账本）。

## 2. 核心概念重定义

```
一期：turn.project_ids[] 多挂 + born_personal + recall_acl(reader×target)
二期：
  memory_turns          = 纯个人流水账（不再有 project_ids/born_personal）
  memory_project_rules  = 项目收录规则（创建者声明"什么内容算本项目的"）
  memory_project_entries= 项目记忆条目（蒸馏产物，项目资产，成员即可读）
  memory_project_links  = 项目授权（parent 包含 child，单级）
  memory_asset_memories = 文件记忆（一文件一条目 + 分块）
```

**关键安全断言**：`memory_turns.raw_content` / `l2_detail` 永不被任何项目端点返回；项目侧能拿到的最大信息粒度 = 路由 LLM 蒸馏出的条目文本。

## 3. 数据模型（4 新表 + 1 改 + 3 废）

### 3.1 `memory_project_rules` — 项目收录规则

**用途**：创建者/admin 声明「聊天中涉及什么内容，记忆自动进本项目」。

- `project_id`、`rule_text`（自然语言规则，如「涉及 SeedDance 视频生成的参数、工作流、排期的讨论」）、`positive_examples[]` / `negative_examples[]`（各 ≤5 条，显著提路由精度）。
- `anchor_embedding halfvec(2048)` + `anchor_tokens_tsv tsvector`：规则文本+正例的锚点，供路由粗筛（复用一期 `MemoryTagAnchorService` embed+jieba 管线）。
- `enabled`、`created_by`、`UNIQUE(project_id)`（v1 每项目一条规则，够表达；多条规则 v2）。
- 规则文本**对项目成员可见**（透明化：成员有权知道自己聊什么会被收录）；`negative_examples` 仅 owner/admin 可见（防规避）。

### 3.2 `memory_project_entries` — 项目记忆条目（核心新表）

**用途**：路由层蒸馏产出的项目记忆，**项目资产**，非用户资产。

- `project_id`、`author_user_id`（溯源谁聊出来的，仅元数据展示「张三·3 天前」）、`source_turn_id`（回指个人流水账，仅作者本人可顺藤；对其他人不可解析）。
- `tag_ids[]`（复用 `memory_tags`，归一在**作者个人标签库**做，展示层渲染作者名——D2 定案，详见 §4.3）。
- `l1_summary` / `l2_detail`：蒸馏文本，**生成时即脱敏**（prompt 明示「只保留与项目规则相关内容，剔除个人隐私、闲聊、情绪表达」）。
- `confidence`（路由置信度 0~1）+ `status`：`ACTIVE` / `PENDING_REVIEW`（置信度落入灰区进待确认队列，owner/admin 一键收/弃，见 §5.4）。
- `content_type`：`TEXT` / `FILE`（文件记忆被收录进项目时置 FILE + `file_id`）。
- 软删走 BaseEntity 约定；项目删除 → CASCADE 清（条目是项目资产，随项目死）。

### 3.3 `memory_project_links` — 项目授权（项目包含项目）

**用途**：「用户将该项目授权到其他项目」。**双向确认制**（2026-08-07 定案）：数据方发起、接收方审核，双方都点头才生效，防乱分享。

- `parent_project_id`、`child_project_id`、`granted_by`（child 的 owner）、`approved_by`（parent 的 owner/admin）、`created_at`、`approved_at`。
- `status`：`PENDING`（child owner 已发起，待 parent 审核）/ `ACTIVE`（parent 通过，召回生效）/ `REJECTED`（parent 拒绝，留痕防重复骚扰）。
- **流程**：child owner 发起「把 B 授权给 A」→ 行落 `PENDING` + A 的 owner/admin 收 `memory_notifications` 审核通知 → A 通过 → `ACTIVE` 召回生效；A 拒绝 → `REJECTED`，同一 (A,B) 组合 30 天内不可重复发起（防刷）。
- `UNIQUE(parent_project_id, child_project_id)`（重复发起走软删复活/状态翻转）；禁自环（parent≠child）；**单级不传递**（D7 定案）——A 含 B、B 含 C，A 召回不到 C；v2 若要传递须每一跳数据方显式确认。
- **召回只认 `ACTIVE`**：PENDING/REJECTED 的链不进任何召回与总结取数。
- **撤销双向**：child owner 随时撤（数据方兜底权）；parent owner/admin 也可随时移除（接收方清场权）。撤销即 DROP 行下次召回自然不含；已基于 child 条目生成的 parent 总结标 `STALE` 提示重生（复用一期 STALE 机制）。
- parent 成员召回 child 条目时带**来源标注**「来自授权项目·B」（D-19.04 信任透明原则：召回来源必须可解释）。

### 3.4 `memory_asset_memories` — 文件记忆

**用途**：一个上传文件 = 一条记忆。用户问及时召回到「总结 + 原文件回链」。

- `owner_user_id`、`file_id`→`stored_files`（复用 V40 文件登记，source=CHAT/ASSET 已有 ACL 咽喉点 `FileStorageService.load`）。
- `file_kind`：IMAGE / DOC / PPT / PDF / AUDIO / VIDEO / OTHER（按 mime 归类）。
- `l1_summary`（一句话：「《React 课件.pptx》：32 页，讲 hooks 原理与常见坑」）/ `l2_detail`（结构化详述：章节列表、每页要点、关键图描述）。
- `tag_ids[]`（进个人标签库，与对话记忆同一归一体系——「课件」和「我聊过的 hooks 问题」共享标签，召回自然合流）。
- `ingest_status`：PROCESSING / READY / FAILED（上传即返，异步 ingestion；FAILED 可重试）。
- **项目收录**：文件记忆同样过路由层 → 命中则蒸馏条目（content_type=FILE + file_id）进 `memory_project_entries`；**项目成员拿到的是文件引用，文件本身的读取权限走 `stored_files` ACL 放行**（复用最近提交的「资产库共享 ACL 放行」模式，不新开权限体系）。

### 3.5 `memory_asset_chunks` — 文件分块（深读层）

**用途**：课件的「每页/每节」级索引，对应 D-19.12「按视觉对象分块，不按文字段分块」。

- `asset_memory_id`、`chunk_no`、`chunk_text`（页要点/段落）、`chunk_embedding halfvec(2048)`、`page_ref`（页码/时间戳锚点，**语义锚点必须能反向定位原文位置**——D-19.12 幻觉对冲手段 1）。
- 召回命中文件记忆且 reflect 判定需深读时 → 向量检索分块 top-k 进 prompt；回答引用须带 `page_ref`（可审计、可跳转原文件对应页）。

### 3.6 改动与废弃

| 对象 | 处置 |
|---|---|
| `memory_turns` | **删列** `project_ids[]` / `born_personal` / `departed_project_ids[]` / `deleted_project_ids[]` → 纯个人流水账（`user_id` 唯一边界） |
| `memory_recall_acl` | **DROP**。项目条目是项目资产，成员即可读，reader×target 矩阵失去存在意义；`MemoryRecallAclResolver` 五路径简化为「项目成员=可读」 |
| 写入目标多选 UI / 首次勾项目确认弹窗 | **下线**。召回 scope 多选保留（读侧选择仍在；写侧无选择） |
| `memory_project_members` / 离职 DEPARTED / gen 双开关 / 冲突 pending / 总结 coverage | **保留**，语义微调见 §8 |

## 4. 写入链改造（取消手动指定 → 自动路由）

### 4.1 新写入链

```
对话结束 → processTurnAsync（不变）
  ① 前置过滤（不变，按侧独立 + 敏感黑名单）
  ② 生成 LLM 出双侧三层（不变）→ 落 memory_turns（恒个人）
  ③ 【新】项目路由 Router（异步，可与②并行粗筛）：
     a. 粗筛：turn 的 L1+tags 对用户 ACTIVE 项目的 rules 锚点做 向量+BM25 RRF
        → top-K 候选项目（K≤3，阈值低于粗筛直接无路由，零 LLM 成本）
     b. 精判：候选>0 时一次 LLM 批量判（prompt 注入各候选项目的 rule_text+正/负例+turn L1/L2）
        → 每项目输出 {hit, confidence, distilled_l1, distilled_l2, tag_suggestions}
     c. 落库：hit=true 且 confidence≥0.8 → ACTIVE 条目；0.5~0.8 → PENDING_REVIEW；<0.5 丢弃
     d. 蒸馏铁律：distilled 文本只含规则相关内容，prompt 明示剔除隐私；输出过 schema 校验
  ④ 【新】若本轮含文件附件 → 文件 ingestion（§7）
```

### 4.2 路由成本护栏（D-19.09 原则）

- 粗筛不过 → **零 LLM 调用**（绝大多数轮次走这里）。
- 精判**批量一次**：K 个候选项目一个 prompt 判完，不是 K 次调用。
- 用户无 ACTIVE 项目 / 项目 rule 未配/未启用 → 路由整步跳过。
- 路由失败降级 = 不收录（漏收可补，错收泄密；**宁漏勿错**）。

### 4.3 项目标签归一（D2 定案：案 A）

蒸馏条目的 tag 归一两案：
- **案 A（推荐）**：tag 归一在**个人标签库**做（author 的库），条目只存 tag_ids。项目聚合标签时 join 条目作者的库。优点：一套归一逻辑、与个人总结合流；缺点：标签名含个人色彩（「我：居住」出现在项目条目里怪）。
- 案 B：项目独立标签子库（subject 强制=项目名）。干净但多一套归一 + 跨项目标签不流通。
- v1 用 A，条目对外展示时 subject 渲染为作者名（复用一期「【张三·爱好】」装配规则）。

### 4.4 误收录治理（D-19.07 置信度分层落地）

- `PENDING_REVIEW` 队列：owner/admin 在记忆面板「收录审核」页签一键收（→ACTIVE）/弃（→软删 + 该 turn 加入该项目负例，反哺路由精度）。
- 成员可见「本条为何被收录」（命中规则文案 + 置信度），作者本人可**申诉撤回**自己产生的条目（作者删自己 turn → 级联软删其蒸馏条目，见 §8.3）。
- 四层置信度映射：≥0.8 直接收录（L2 中·推断过）；0.5~0.8 待裁决（L3 低）；<0.5 忽略；**冲突/疑似注入不进条目**（L4 待验证，只留个人域）。

## 5. 项目授权召回模型（项目包含项目）

```
项目 A 召回 scope =
  A 自有条目(status=ACTIVE)
  ∪ Σ child 条目 (memory_project_links 中 parent=A 且 status=ACTIVE)
  ∪ A 的项目共享总结（全员可读）+ 召回者自己在 A scope 下的个人总结

过滤：child 条目带来源标注；离职成员仍可读（条目是项目资产，但成员的读取权随
      memory_project_members.status=ACTIVE 判定，DEPARTED 即失读权——与一期「离职保交接」
      的差异见 §8.1）
```

- **写不穿透**：A 的成员不能往 B 写条目（授权是读单向）；B 的收录只在 B 的对话语境发生。
- **防环/防传递**：建链时校验 parent≠child 且 parent 不是 child 的（间接）祖先？v1 单级 → 无需防环，A 含 B 与 B 含 A 可同时存在但互不影响对方召回集（各查各的一级）。
- ACL 简化收益：一期 `readableAuthors` 五路径 + reader×target 矩阵 + recall_admin 全套删除，替换为「`memory_project_members.status=ACTIVE` 即可读本项目+被授权子项目条目」。**安全语义反而更强**：原文不可达，蒸馏条目本就面向项目。

## 6. 召回 pipeline 改造（七步 → 八步）

在一期七步的第 ① 步（scope 过滤）与第 ② 步（标签聚合）之间插入项目条目合流：

```
① 过滤: scopes × timeWindow × direction（不变；个人 scope = memory_turns 恒 born 个人）
①.5【新】项目条目合流: 对 scope 内每个项目 P：
        取 P 条目 ∪ P 的授权 child 条目（status=ACTIVE，content_type=TEXT 走标签流）
② 聚合标签: 个人 tags ∪ 项目条目 tags（跨 user 去重，不变）
③ LLM 选标签（不变）
④ 读总结（个人恒只读自己；项目 scope 读项目共享总结，全员可见）
⑤ reflect（不变）
⑥ 拼增量: 个人流水账按 coverage 判（不变）+ 未被总结覆盖的项目条目拼入
⑥.5【新】文件记忆: 命中 tag 的 READY 文件记忆 → L1/L2 进装配；
        reflect 判需深读 → memory_asset_chunks 向量 top-k + page_ref
⑦ 装配: 项目条目按 author 打前缀【张三·X】；授权来源标注【经授权项目·B】；
        文件记忆装配为「文件卡片」结构化块（file_id + 名称 + 总结 + 可下载标记）
```

- 降级：路由/文件检索任一步失败 → 跳过该源，不影响主干（每步 traceId 打点沿用）。
- LLM 次数上限不变（选标签 + reflect），文件深读复用 reflect 判定不新增调用。

## 7. 多模态文件记忆（ingestion 管线）

### 7.1 上传与摄取

```
聊天框附件上传（复用 stored_files，source=CHAT，owner=上传者）
  → 即返「文件已收到，记忆提炼中」 → 异步 ingestion worker：
    IMAGE      → 多模态 LLM 出图描述 + OCR 文本
    PPT/PDF/DOC→ 解析分页/分节 → 每页要点（图页走多模态，文页走文本）→ chunks
    AUDIO/VIDEO→ 转写（复用媒体管线能力）→ 摘要 + 时间戳锚点 chunks
  → 汇总出 l1/l2 + tag 建议 → 过路由层（同 §4.1③，文本=文件总结）
  → 落 memory_asset_memories(READY) + memory_asset_chunks
```

- **一文件一记忆**：无论 32 页课件还是 1 张截图，个人域里就是一条 `memory_asset_memories`，符合用户心智（「那个课件」而不是「32 条记忆」）。
- **语义锚点反定位**（D-19.12 幻觉对冲）：每个 chunk 带 `page_ref`，AI 引用文件内容必须能指到页码/时间点；回答中文件内容一律标注「来自《文件名》第 N 页」。
- **模态降级**（D-19.12 §3.2）：OCR/转写失败 → 降级为仅存元数据 + 文件名/类型/大小的弱记忆并告知用户「这份文件我只能记住它存在，读不懂内容」；扫描件无文字层 → 走多模态整页识别，仍失败则明示。
- **大小/类型上限**（D4 定案）：单文件 ≤50MB、文档 ≤200 页、音视频 ≤30 分钟；超限友好拒收并提示「拆分/截取重点后再传」。防 token 爆炸与 worker 长任务。

### 7.2 召回体验（D-19.04 信任透明）

- 用户问「上次那个课件讲了什么」→ 召回命中文件记忆 → AI 答总结 + 前端渲染**文件卡片**（图标/名称/页数/下载链/「展开第 N 页」深读入口）。
- 用户问细节（「hooks 那页讲的啥」）→ reflect 深读 chunks → 带页码引用回答。
- 文件被删（stored_files CLEANED）→ 记忆条目保留但标记「原文件已删除」，总结仍可召回（总结是记忆，原文是附件——权责分离）。

## 8. 一期机制的语义迁移

### 8.1 离职/删除生命周期

- **条目是项目资产**：成员离职 → 其产生的项目条目**留在项目**（已脱敏蒸馏，不存在「带走原文」问题），这天然解决一期「DEPARTED 人员记忆保交接」的复杂机制——`departed_project_ids[]` 随列删除而废，「同步召回已离开人员」开关在条目层不再需要（条目不属任何人）。
- 离职成员**失去项目条目读权**（status=DEPARTED 不可读），其个人流水账不受影响。
- 项目删除 → `memory_project_entries` / `memory_project_rules` / `memory_project_links`（双向）CASCADE 清；`memory_notifications(PROJECT_DELETED_AFFECTED)` 通知沿用。
- **文件记忆授权进项目后项目删除**：条目删，个人 `memory_asset_memories` 不动（文件是作者资产）。

### 8.2 项目总结共享化（D5 定案采纳 + 成员压缩权限细则）

一期铁律「总结恒只读自己」建立在「总结原料含他人原文」上。二期项目条目已脱敏且是项目资产 → **项目总结升级为项目共享资产**（`memory_summaries.project_id=P, user_id=NULL` 或新 `scope_owner=PROJECT` 标记，全员可读）：

- **共享总结写入权 = 仅 owner/admin**：项目共享总结只能由 owner/admin 手动触发或自动 worker 产生，普通成员**不能对项目做任何修改**。
- **成员可压缩，但只进自己口袋**：普通成员可以发起对项目内容的压缩，产出**只落进他自己的个人总结**（`user_id=自己`，标注「来源：项目 X」），供自己召回使用；对项目共享总结和其他成员零影响。这保留了「我自己消化一份」的出口，又不会把项目公共知识改乱。
- 收益：项目知识沉淀为单一权威日志（省 N 倍 token），成员另有私人消化通道。
- 个人总结完全不变（恒 `user_id=self` 只读自己）。
- 冲突裁决人：项目共享总结冲突 → owner/admin 裁决（原「作者裁决」语义映射到项目 owner）。

#### 8.2.1 嵌套授权下的总结关系（不变量：条目跨项目流动，总结永不跨项目）

授权链上流动的原料是**蒸馏条目**；每个项目的总结只用自己的召回 scope 压自己的，总结本身不出项目。

```
A 授权进 B（A=子，B=父）：
  A 的共享总结 = 只压 A 自有条目            → 仅 A 内可见
  B 的共享总结 = 压 B 自有条目 ∪ A 的条目   → 仅 B 内可见（与 B 召回 scope 一致）
```

- **B 的总结取数含子项目条目**：总结取数范围必须 = 召回范围，否则子项目条目在父项目里永远只能散装召回，父项目知识日志缺一半、token 省不下。
- **A 的总结不直接给 B**：A 的总结是 A 的内部视角；B 拿条目原料自己压自己的版本，避免「总结的总结」跨项目套娃的双重压缩失真。
- **撤销授权**：B 的共享总结已吃进 A 条目 → 标 `STALE`，worker 用剩余 B 自有条目重压，A 内容从新总结消失；旧总结在授权期间被 B 成员看过属正常（当时本就有读权）。
- **冲突裁决权随总结所有权**：B 总结里 A 条目与 B 条目时序互斥 → pending 给 B 的 owner/admin；A 的总结冲突仍 A 的 owner/admin。各管各的账本。
- **无套娃循环**：A→B、B→A 互授同时存在也不循环——压缩只读条目并集，总结不进对方取数；条目是原子原料，流动一次到底。
- **成员个人压缩边界**：B 成员发起压缩，取数 = 他可读范围（B ∪ A 条目），产出落他个人总结（标注「来源：项目 B」），仅他自己可见——与 D5 成员压缩规则一致。
- **实现要点（P4）**：coverage 语义从 `(turn, tag, project, user)` 扩展为条目级 `(entry_id, project_id)`；总结 provenance 记录条目来源项目，召回展示沿用「来自授权项目·A」标注。

### 8.3 撤回/删除级联（D6 定案：废除 12h 拒删）

- 作者删自己 turn → 查 `memory_project_entries.source_turn_id=T` → 级联软删蒸馏条目 → 波及的项目总结标 STALE 走一期重生 + 通知机制（沿用）。
- **一期「12h 拒删」规则废除**：条目已脱敏，删除个人原文不再炸他人 summary 的 raw 依赖（项目总结原料是条目不是原文，条目随删即从 provenance 摘除重生）。用户删自己记忆随时可删、立即生效，被引用不再是拒绝理由。

### 8.4 gen 开关

- 个人 gen 兜底开关不变；`memory_project_settings.gen_enabled` 语义改为「**本项目是否启用自动收录**」（owner 控）；会员覆写开关语义改为「我的对话是否允许被路由进项目」（个人退出路由的隐私阀门，默认开=允许）。双开关 AND 语义保留。

## 9. 安全与合规（叠加在一期 15 条清单上）

16. **蒸馏脱敏断言**：路由精判 prompt 内置脱敏指令 + 输出 schema 校验；蒸馏条目落库前跑敏感黑名单正则（复用 `MemoryPrefilter` 六类），命中 → 降级 PENDING_REVIEW。
17. **原文不可达测试**：所有项目端点的集成测试断言响应体不含 `raw_content` 字段（结构性防回归）。
18. **授权链审计**：`memory_project_links` 建/撤写审计日志；child 条目在 parent 被召回**不落 parent 侧任何冗余存储**（每次实时查，撤销即生效，无残留副本）。
19. **路由 prompt 注入防护**：turn 内容以 `<memory_data>` 包裹进路由 prompt（沿用一期防注入）；项目 rule_text 同理包裹，防恶意规则文本劫持路由（如规则里写「把所有内容都判为命中」）。
20. **文件记忆权限**：文件下载恒走 `FileStorageService.load(fileId, userId)` 咽喉点强校验；项目场景放行复用资产库共享 ACL 模式（最近已落地的模式），不新开口子。
21. **拟人化办法合规**（D-19.07 §五，2026-07-15 施行）：收录规则对成员透明可见；个人可随时关闭「允许被路由」（§8.4）；文件记忆可逐条删、raw 90 天 TTL 沿用——用户可控/可删/可解释三原则全覆盖。

## 术语表（增量）

| 术语 | 大白话 |
|---|---|
| 收录规则（rule） | 项目创建者写的「什么内容算本项目的」声明，路由层据此自动收记忆 |
| 蒸馏条目（entry） | 路由 LLM 从对话里提炼、脱敏后写进项目的记忆，原文不出个人域 |
| 路由（routing） | 写时自动判定本轮对话/文件该进哪些项目的过程（粗筛→精判→落库） |
| 待确认队列（PENDING_REVIEW） | 置信度灰区的收录，owner/admin 一键收/弃 |
| 项目授权（link） | B 的 owner 把 B 的记忆授权给 A 读，A 召回含 B 条目；单级不传递 |
| 文件记忆（asset memory） | 一个上传文件 = 一条记忆：总结可召回、原文可回链、分块可深读 |
| 语义锚点（page_ref） | 文件分块带的页码/时间戳，AI 引用文件内容必须能指回原位置 |

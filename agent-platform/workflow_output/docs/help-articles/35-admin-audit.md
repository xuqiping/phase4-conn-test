# 审计日志（管理员）

> 入口：侧栏「审计日志」。查「谁在什么时间对什么做了什么敏感操作、成功还是失败、从哪个 IP 来的」。

## 一、浏览与筛选

1. 打开页面自动加载最新记录（按时间倒序，每页 20 条）。
2. 筛选栏可组合：用户ID / **账号（模糊，如输 adm 查 admin）** / **模块下拉（中文）** / 动作 / 结果 / traceId / 时间段。
3. 点「查询」生效（页码回第 1 页）；「重置」清空条件。

**示例**：查今天所有登录失败 → 模块选「认证」+ 动作填 `login` + 结果选「失败」+ 时间段选今天 → 查询。

## 二、看单条详情

- 点行末「查看」→ 弹窗显示中文键值详情（账号/原因/模型/消耗积分等）。
- 失败记录内含原因码（如 `bad_password`）。

## 三、一键追调用明细（drill-down）

「对话完成」或「视频/图片生成成功」的审计行，详情弹窗底部有「**查看调用明细**」按钮：
1. 点击 → 新标签打开「账单总览·调用明细」，已按该请求过滤。
2. 能看到同一次请求的全部模型调用（模型名/输入输出 token/真实金额/积分/状态）。
3. 点 banner 上「清除」恢复全量。

> 老数据（功能上线前）没有关联键，按钮不显示。

## 四、排障配合

- 拿到 traceId 可交给开发/运维在日志里反查该请求全链。
- 查不到刚做的操作：审计异步落库有秒级延迟，等 1-2 秒重新查询。
- 详情里手机号/卡号应是打码形态（如 `138****8000`）；看到原文属安全 bug，立刻上报。

## 五、防篡改（无需操作）

每条审计带链式防伪指纹，每天凌晨自动全量校验；改或删任意一条都会断链告警——审计日志改不了不留痕。

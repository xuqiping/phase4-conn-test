## 关键设计决策（落地版）

1. **worker 纯 poll 而非 submit 即派发**（偏离 plan Step3 措辞，更低风险）：照抄 `IndexJobWorker` 验证模式——`@Scheduled` poll 认领 PENDING + 锁过期 RUNNING(`FOR UPDATE SKIP LOCKED`)，分发 `mediaTaskExecutor`。崩溃恢复免费（重启下次 poll 自动续跑），无需 `@PostConstruct`。代价：首次 createTask 最多延迟 pollMs(5s)，视频生成本身分钟级，可忽略。
2. **usage 估算用 Ark 官方 token/秒 费率表**（非 spec 字面像素公式）：spec 给的像素公式与 Ark 真实计费在 720p 恰好等价(5s/720p/24fps≈30.88万)，但 Ark 实际按 token/秒 费率(720p=61760/s)。用费率表更贴合 Ark 真实账单，且满足 spec 断言常量。Ark 返 `usage.total_tokens` 时用真值，估算仅作 fallback(ESTIMATED 标记)。
3. **图生视频参考图走 file_id→data URI**：复用 `POST /api/files` 上传(单一咽喉点归属校验)，submit 带 `refFileId`；worker `MediaStorageService.readAsDataUri` 读字节转 base64(≤8MB 校验)喂 Ark `image_url`。不在视频端点重做 multipart。
4. **media_gen_tasks 不继承 BaseEntity**：append-only 任务表不软删(spec §6 明确不加 deleted)，故 standalone entity(同 `StoredFileEntity` 思路)，加 `locked_until/attempt` 列支撑 SKIP LOCKED claim。
5. **videoUrl 不暴露 Ark 临时 URL**：VO 的 `videoUrl` 指向 `/api/media/tasks/{id}/download`(Content-Disposition 附件)，Ark OSS 临时链接仅 worker 下载时用一次即弃。

## 一句话描述
一个 traceId 串起一次请求的全部日志（含 SQL、异步任务、Python sidecar），敏感操作自动落 audit_logs 可前端查询，五类敏感信息全通道自动打码。

## 调用链路（关键路径）

```
请求进 → JwtAuthenticationFilter → MdcUserFilter(userId/username/clientIp 入 MDC)
       → RequestLogFilter(计时) → Controller
         ├─ 标 @AuditLog → AuditLogAspect 环绕 → AuditLogService.record → auditTaskExecutor 异步 INSERT audit_logs
         ├─ @Async/线程池 → CompositeTaskDecorator 快照 MDC+计费上下文 → 池线程恢复 → finally 清
         ├─ mapper SQL → log-prefix=sql. → logger "sql"（默认 OFF）→ sql.log
         └─ 调 sidecar → WebClient 自动插桩 traceparent → sidecar 中间件解析绑 contextvars → 回调 Java 时回注
日志出 → MASKED_* MaskingAppender 事件层打码 → CONSOLE 彩色文本 / APP_FILE·ERROR_FILE·SQL_FILE JSON
管理员 → 侧栏「审计日志」→ AuditLogView → auditApi.list → GET /api/audit/logs(@RequirePermission) → 分页表格
```

## 技术清单与原理注解（大白话版）

#### 1. traceId 全链路 — micrometer-tracing（`pom.xml` + `application.yml`）
- **采用技术**：micrometer-tracing-bridge-otel（Spring Boot 3 官方链路追踪，BOM 托管版本）
- **一句话原理**：请求进门就发一张「全程票号」(traceId)，之后这条请求产生的每条日志都自动印上票号。
- **大白话案例**：像医院就诊号——挂号拿一个号，验血/拍片/取药每张单子都印这个号，事后按号能调出全部记录。
> 📌 批注：必须引 `spring-boot-starter-actuator` 作自动配置载体；采样 `TRACING_SAMPLING_PROBABILITY` 默认 1.0，生产可降。**userId/traceId 只进日志，禁进 metric tag**（高基数撑爆 Prometheus）。

#### 2. MDC 用户上下文 — `MdcUserFilter.java`
- **采用技术**：SLF4J MDC + OncePerRequestFilter（排在 JWT filter 之后）
- **一句话原理**：把「谁发的请求」放进线程的随身小纸条，该线程打的每条日志自动带上 userId/username/IP。
> 📌 批注：finally **只 remove 自身 3 个 key，禁 MDC.clear()**——clear 会抹掉 micrometer 的 traceId 作用域断链。防串号靠「只清自身 + 每请求覆盖写」。

#### 3. 异步不断链 — `MdcContextTaskDecorator` + `CompositeTaskDecorator`
- **采用技术**：Spring TaskDecorator（任务提交时快照 MDC → 池线程执行前恢复 → finally 清理）
- **大白话案例**：像交接班记录——白班把备忘（上下文）写好交班，夜班（池线程）照着做，做完销毁备忘，不留给下一个任务。
> 📌 批注：ThreadPoolTaskExecutor 只收一个 decorator，多上下文用 Composite 组合；裸 ExecutorService 用 `MdcContextTaskDecorator.wrap(runnable)`。**新增线程池/异步点必挂，否则断链**（已入沉淀规范）。

#### 4. 脱敏制度化 — `LogMasker` + `MaskingAppender`
- **采用技术**：AppenderAttachable 事件层装饰（同 AsyncAppender 模式）+ 6 条 static 预编译正则（身份证/手机/银行卡/邮箱/apiKey  kv/Bearer）
- **一句话原理**：日志在「出门」前统一过一道打码机，console/JSON/SQL 全通道只打一次。
> 📌 批注：plan 原写 %mask converter——对 LogstashEncoder JSON 不生效需双机制，改 Appender 层一处生效。kv 正则带数字前瞻防误吞「Bearer」词。新敏感类别只加 LogMasker 正则。

#### 5. SQL 独立通道 — mybatis `log-prefix: sql.`
- **采用技术**：mybatis-plus 配置 `log-prefix: sql.` + logback `logger name="sql"`（additivity=false）
- **一句话原理**：所有 mapper 的 SQL 日志统一姓「sql」，一个开关管全部，默认 OFF。
> 📌 批注：`LOG_SQL_ENABLED=ON` 才产出 sql.log；免逐包登记 logging.level（未来新 mapper 包自动覆盖）。

#### 6. 跨语言一条链 — W3C traceparent（sidecar `logging_config.py`）
- **采用技术**：W3C traceparent 头 + structlog contextvars
- **一句话原理**：Java 调 Python 时把票号写进 HTTP 头，Python 取出来印在自己的日志上；回调时再带回来。
> 📌 批注：sidecar 缺 header → 自生成 uuid + 打 `trace_parent_missing=True` 标记（断链可观测）。Java 侧必须用 Spring 托管 WebClient.Builder 才自动插桩。

#### 7. 操作审计 — `@AuditLog` + AOP 异步落库
- **采用技术**：自定义注解 + Spring AOP 环绕 + 专用小池（core1/max2/queue500 AbortPolicy）
- **一句话原理**：敏感方法贴个标签，执行完（成败都）自动异步写一行「谁/何时/干了什么/结果/IP」。
> 📌 批注：落库失败仅 WARN + droppedCount，**绝不阻断业务**（失败期间审计缺失由 P3 告警兜底）。detail=参数 map 过 LogMasker + 200 字符截断。认证类（登录前无 MDC 身份）走 `AuditLogService.fromMdc` 手工建行，detail 只带 reason 码。

## 数据库表与 SQL 注解（Flyway）

#### 迁移脚本：`V77__audit_logs.sql`
- **脚本作用**：建操作审计表（append-only）。**全字段超集，安全体系 S1 的最小 audit_logs 作废复用本表（S1 迁移须改 V80+）。**
> 📌 批注：审计表**不继承 BaseEntity**（无 updated_at/deleted——只许插不许改）。

#### 表：`audit_logs`（操作审计表）
> 大白话：存「谁在什么时间对什么做了什么、成没成」，**一行 = 一次敏感操作**，只增不改不删。

| 字段 | 类型 | 用途（大白话） | 约束 / 索引 |
|---|---|---|---|
| id | BIGINT | 审计行编号 | 主键 IDENTITY |
| created_at | TIMESTAMPTZ | 发生时间 | 索引（idx_audit_created，查询按它倒序） |
| trace_id | VARCHAR(64) | 全程票号，可去 app.log 捞同请求全部日志 | — |
| user_id | BIGINT | 谁干的（登录失败时可能 NULL） | 索引（idx_audit_user） |
| username | VARCHAR(64) | 谁干的（冗余名字，防改用户名后查不到） | — |
| module | VARCHAR(32) | 哪个域：auth/user/role/agent/knowledge/billing/system | 索引（idx_audit_module） |
| action | VARCHAR(64) | 干了什么：login/register/recharge/delete… | — |
| target_type / target_id | VARCHAR | 对谁下手（如 role#3） | — |
| detail_json | JSONB | 参数摘要（已脱敏 + ≤200 字符，**禁 PII 原文**） | — |
| client_ip / user_agent | VARCHAR | 来源 IP / 浏览器（UA 截 256） | — |
| result | VARCHAR(16) | SUCCESS / FAIL（FAIL 的 detail 带 reason 码） | — |

#### 配套迁移
- `V78__audit_logs_revoke.sql`：DO 块判 `agent_app` 角色存在 → REVOKE UPDATE/DELETE/TRUNCATE（DB 层防篡改；本地超管环境自动跳过，**生产须先建 agent_app 非超管账号**）。
- `V79__audit_permission.sql`：seed `system:audit:read` 权限 + 授 admin 角色（前端日志中心的门禁）。

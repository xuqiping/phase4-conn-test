## 知识沉淀：PM的复利系统

### 1. 为什么要做知识沉淀

PM最大的浪费是"经验随项目流失"——做了10个项目但不系统沉淀的人，和做了3个项目但深度沉淀的人，后者在方法论和判断力上可能更强。[来源:📚训练知识 | 置信度:🔍高]

| 不沉淀 | 沉淀 |
|---|---|
| 每个需求从0开始判断 | 有需求判断checklists和模式库 |
| 每次评审靠临场发挥 | 有评审话术库和常见异议应对 |
| 项目做完就忘 | 每个项目都有复盘资产 |
| 能力停在"个人经验" | 能力升级为"可迁移方法论" |

### 2. 个人知识库架构

```
个人知识库
├── 项目复盘/           ← 每个项目结束后的结构化复盘
├── 方法论库/           ← 从项目中抽象的可复用方法论
│   ├── 需求判断方法论/
│   ├── 数据分析方法论/
│   └── 沟通方法论/
├── 碎片灵感/           ← 日常看到的案例/洞察/灵感
├── 模板资产/           ← PRD模板/评审话术/汇报模板
├── 学习笔记/           ← 书/课程/文章的笔记
└── 决策日志/           ← 重要决策的记录与回溯
```

### 3. 知识沉淀的节奏

| 时机 | 做什么 | 工具 |
|---|---|---|
| 每日 | 碎片灵感/决策记录（5min） | 笔记App/IM收藏 |
| 每周 | 整理碎片+写周报（30min） | Notion/Obsidian |
| 每个项目结束 | 结构化复盘（2h） | 文档/模板 |
| 每季度 | 方法论更新+知识库整理（2h） | 文档 |

### 4. 工具链选择

| 工具类型 | 推荐 | 特点 |
|---|---|---|
| 双链笔记 | Obsidian/Logseq | 本地存储+双链关联+Markdown |
| 全能工作台 | Notion | 数据库+文档+协作一体化 |
| 碎片收集 | 微信收藏/Flomo/Cubox | 移动端快速收集 |
| 项目文档 | 飞书/Confluence | 团队协作+企业级 |
| AI辅助 | ChatGPT/Claude/豆包 | 快速整理碎片→结构化文档 |

> 2025-2026新趋势：AI正在成为知识沉淀的"放大器"——把碎片口述给AI，AI帮你结构化整理成文档；把项目数据喂给AI，AI帮你做复盘分析。知识沉淀的门槛正在大幅降低。[来源:📚训练知识 | 置信度:📚中]

## 信息管理：过滤漏斗

### 信息漏斗模型

```
信息获取 → 信息过滤 → 信息处理 → 信息归档
  (多)       (少)       (精)       (用)
```

### 1. 信息获取

| 渠道 | 订阅策略 | 频率 |
|---|---|---|
| 行业Newsletter | 订阅3-5个高质量源 | 每周扫一遍标题 |
| 技术Blog | RSS/收藏夹 | 需要时搜索 |
| 社交媒体 | 关注<50个关键人 | 每天限时15分钟 |
| 书/课程 | 按需购买 | 每月1-2本/门 |

### 2. 信息过滤

- **标题过滤**：只看标题就有80%判断是否值得读
- **3秒决定**：打开后3秒决定继续/关掉/收藏
- **信息diet**：低营养信息（热搜/八卦/无数据观点）直接跳过

### 3. 信息处理

- **批注**：关键的标黄/写感想
- **关联**：这条信息和我的什么项目/方法论相关？
- **输出**：最好的处理是"用自己的话写出来"

### 4. 信息归档

- 归档到个人知识库对应分类
- 标签体系：#需求判断 #数据分析 #AI应用 #竞品…
- 定期清理：超过6个月未引用的信息可以归档或删除

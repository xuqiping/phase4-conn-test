# 安全运维日志告警加固 · Feature Map

> 范围：11x 需求（日志/运维/告警铜墙铁壁）。规格 `docs/specs/安全运维日志告警加固.md`，计划 `docs/plans/安全运维日志告警加固*.plan.md`。
> 架构一句话：**热路径快拦（网关式 Filter/Interceptor，Redis 计数，故障放行）+ 冷路径深挖（事件总线异步规则引擎，分级自动处置）+ 钉钉告警分级推送**。

| V104 | permissions +3 | security:event:read / security:ban:manage / security:rule:manage（admin 已授） |

## 关键决策/踩坑批注
1. **降级哲学**：热路径 Redis 故障=放行（可用性>强制力）；冷路径 Redis 故障=不命中（宁漏报不误封）。方向相反，各有道理。
2. **切片兼容红线**：@WebMvcTest 切片自动装 Filter/Interceptor/Advice → 其依赖普通 @Component 必须 ObjectProvider 延迟解析；既有 @InjectMocks 服务加横切依赖用 @Autowired(required=false) 字段注入。
3. **防递归**：AutoResponder 处置不 publish 事件；Worker 对 system 事件跳过。
4. **幂等重放防双计**：chargeIdempotent 事件发在 supplier 内（缓存命中不执行）。
5. **geo 分隔符坑**：ip2region geo 含 `|` → Redis 存 "geo|ts" 须 lastIndexOf 尾切。
6. **钉钉直推**：绕过 Alertmanager 适配器（它只收 Alertmanager 格式），直接打机器人 webhook + 加签。
7. **已知取舍**：热路径事件（SQLI/暴破）暂不推钉钉（防 Worker 双推），走 security.log + 指标 + 事件中心；后续可在热路径调用点旁补 dispatch。

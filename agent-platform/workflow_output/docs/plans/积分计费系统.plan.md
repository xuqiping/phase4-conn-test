# Implementation Plan for 积分计费系统（预付钱包 + 账单）

> Phase 2 产出。Phase 3 逐步勾选执行。只含伪代码，不含真代码。
> 来源规格：[../specs/积分计费系统.md](../specs/积分计费系统.md)（取代未实现的 TokenUsage统计）。
> 文档规模：≤5000 tokens。

## ⚠️ 对原有功能影响分析（用户要求零回归）

| 点 | 影响原功能? | 规避 |
|---|---|---|
| `LlmGateway` 6 出口加预检/扣减 | **风险点** | 预检/扣减包在 gateway 出口，调用方零改；`billing.enabled=false` 全短路（出问题关掉即停） |
| `LlmProviderInterface` 加 getId | 低 | default 方法，两 impl 覆写，老调用方零改 |
| `findProvider` 改返包装 record | 否 | private，仅 gateway 内 6 处调 |
| **chatStream Flux 序列** | **最高风险** | usage 采集走 **side-channel（AtomicReference 副作用）**，扣减在 `doOnComplete`，**绝不改发出的 StreamEvent 流**——否则 13 调用方回归 |
| `MediaGenTaskWorker.process` 加扣减 | 低 | markSucceeded 既有钩子点，插 charge；markFailed 插 refund（或本就没扣则跳） |
| 新表（钱包/流水/价表/比例/订单/usage_logs） | 否 | 独立 append-only 或单行 update，无业务依赖 |
| 采集异步 / 扣减同步 | 否 | 两写路径分离：采集复用独立池+攒批；扣减同步在调用线程单行事务 |

**结论**：两高风险 = ① 流式 usage 不扰动 Flux；② 并发扣减不超支。Step E/F + 测试着重处理。

## 技术实现坑点预判与规避

| 坑 | 规避 | 验证 |
|---|---|---|
| **并发扣减超支**（同 user 多请求同时扣） | `charge` 单事务：`UPDATE user_points_balance SET balance=balance-:pts WHERE user_id=:u RETURNING balance`（行锁，原子），再 INSERT ledger（balance_after=返回值）。禁先查后扣 | 多线程并发同 user 断言余额=初值−Σ、无超扣 |
| 流式 usage 末 chunk 被 `.filter(非空 content)` 丢 | side-channel：`chatStream` 入口建 `AtomicReference<TokenUsage>`，parseStreamChunk 解析 usage 写 ref；`doOnComplete` 采 + 扣 | 流式后断言账单有行+余额扣；SSE 与改造前字节一致 |
| usage 在末 chunk（choices 空）才到 | complete 与最后 chunk 都写 ref，取非空 | mock 末 chunk 带 usage 断言采到 |
| 扣减走异步池被丢 | 扣减**同步**在调用线程（不经 usageTaskExecutor）；仅采集异步 | 采集池满注入断言扣减仍发生 |
| 全局 provider 无 DB id | `LlmConfig` init 建 `Map<String,Long> nameToId` | 账单全局行 provider_id 非 null |
| 视频 token 口径≠文本 | 视频积分独立计，usage_logs.kind=VIDEO，**不与文本加总**；admin 可切 TOKEN/SECOND | 视频 SUCCEEDED 后账单有行，kind 正确 |
| 阶梯比例边界命中 | 命中 `min_amount<=amt<(max_amount||∞)`；按**单次消耗 ¥** 选档（非累积） | 边界值单测 |
| N+1 聚合（admin overview） | 用 GROUP BY 一次查，禁 per-user 循环 | EXPLAIN 无 N+1 |
| 支付回调重复到账（Phase2） | `channel_order_id UNIQUE` + 状态机校验（PENDING→PAID 单向） | 重复回调断言只入账一次 |
| 价表/比例改了历史漂移 | ledger/usage_log 落**当时** cost+points；询价按 `effective_from<=now` 最新 | 改价后旧流水不动 |

## 安全检查清单

- [ ] **鉴权**：admin 端点 `@RequirePermission("pricing:manage")`/`"points:recharge"`/`"usage:view"`；用户端点 ownership 硬过滤 `WHERE user_id=current`。
- [ ] **并发安全**：扣减原子 `UPDATE...RETURNING` + 行锁；退款同路径。
- [ ] **输入校验**：充值/价表金额>0；阶梯区间不重叠不漏（min/max 连续）；video_billing_mode ∈ {TOKEN,SECOND}；kind ∈ {CHAT,EMBED,IMAGE,VIDEO}；日期范围防超大区间拖垮查询。
- [ ] **支付幂等（Phase2）**：回调签名校验 + `channel_order_id UNIQUE` + 状态机；不存卡号，仅订单号。
- [ ] **数据最小化**：usage 日志不含 prompt/原文；余额/流水无 PII。
- [ ] **错误处理**：余额不足/扣减失败固定话术，不透传 e.getMessage()。

## 性能考虑与验证计划

- [ ] 采集异步，主链路零延迟（采集不计入响应）。
- [ ] 扣减同步单行事务 <5ms（UPDATE+INSERT，命中 PK/UNIQUE）。
- [ ] 采集攒批降压（50 行/200ms flush）。
- [ ] 聚合走索引；百万行后月分区（后续）。
- [ ] **性能验证（Phase4 重点）**：见下「测试着重」。

## 功能联动点清单

- [ ] **充值 → 余额+流水+订单**：admin grant（或 Phase2 支付回调 PAID）→ balance 涨 + ledger(RECHARGE/ADMIN_GRANT) + payment_order(PAID, channel)。边界：重复回调只入账一次（UNIQUE）。
- [ ] **消耗 → 余额−+流水+审计行**：调用成功扣 → balance 跌 + ledger(CONSUME, balance_after) + usage_logs(cost_yuan, points_consumed 回填)。边界：usage 为空（FAILED）不扣。
- [ ] **失败 → 全退**：扣后调用链抛/ provider 明确失败 → ledger(REFUND, +逆向) + balance 回涨 + usage_logs(status=FAILED)。边界：本就没扣到（usage 空）不重复退。
- [ ] **余额≤0 → 下次预检拦**：对话 chat/chatStream 入口、video submit 入口预检 balance>0，≤0 抛 BusinessException(INSUFFICIENT_POINTS)。边界：负数欠款也拦；admin grant 回正后放行。
- [ ] **admin 改价/比例 → 新调用按新值，历史不动**：写 effective_from 新行，不 UPDATE 旧行；询价取 `<=now` 最新。
- [ ] **用户删 provider ↔ 历史**：不级联删（append-only），usage_logs LEFT JOIN 容 null；余额不受影响。

## 运维考量清单

| 项 | 做/不做/后续 | 说明 |
|---|---|---|
| 可观测性 | 做 | 扣减/退款/充值流水日志含 userId/delta/balance_after；采集失败 WARN 计数 |
| 配置开关 | 做 | `billing.enabled`（总闸，关则跳预检+扣减，仅留采集）、`usage.collect-enabled`（沿用）、`billing.refund-on-fail`（默认 true） |
| 可回滚 | 做（上线前）/ 数据迁移（上线后） | V63-64 建表附 drop 回滚；上线有真实余额后不可 drop，改走迁移 |
| 限流/熔断/降级 | 做/后续 | 采集池满丢 WARN（同记忆池韧性）；支付网关超时/熔断 Phase2 做 |
| 运维入口 | 做 | admin 手动调账（grant/扣减修正）页；对账查询（Σledger.delta vs balance）端点 |
| 告警阈值 | 后续 | 单用户日扣异常/采集失败率/余额对账不平（MVP 仅日志，不接告警系统） |
| 容量/性能预案 | 后续 | usage_logs/ledger 月分区（百万行后） |

## ⚠️ 测试阶段着重（用户要求重点验）

1. **并发扣减不超支（难点最高）**：N 线程并发同 user 扣 → 余额=初值−Σ实际，无超扣；`UPDATE...RETURNING` 行锁验证。
2. **流式 cost 后扣 + SSE 字节回归**：末 chunk usage 采到、扣减在 doOnComplete；SSE 输出字节级回归（不改 Flux）。
3. **失败全退**：provider 抛异常 → 余额回滚 + 流水 REFUND。
4. **13 调用方不漏采**：逐一冒烟——对话/Agent/工作流 LLM_CALL/RAG问答/RAG索引 embed/记忆 embed×N/judge/查询扩展/文档解析/视频——每条账单+扣减出现。
5. **价表/比例生效**：admin 改价后新调用按新值，历史流水不动。

## 术语表

| 术语 | 大白话 | 案例 |
|---|---|---|
| side-channel | 不走主返回值，外层变量副作用传值 | usage 写 AtomicReference，不改 Flux |
| 预检>0+后扣 | 调用前验有余额，调用后扣真实用量 | 余额 1pt 放行，实扣 50→欠 49 下次拦 |
| UPDATE...RETURNING | 扣同时返回新余额，原子防超支 | `SET balance=balance-50 WHERE...RETURNING balance` |
| 阶梯比例 | ¥ 区间换不同积分比 | ¥0.5→100pt/¥，¥5→90pt/¥ |
| kind | 模型大类 | CHAT/EMBED/IMAGE/VIDEO |
| effective_from | 价/比例生效起点，历史不回改 | 改价写新行，旧调用仍按旧价 |

## 使用示例

PM 输入：
- Agent形态：多Agent协作（云端）
- 目标场景：企业级多Agent数据分析系统
- 目标市场：国内（金融行业，合规敏感）
- 团队能力：后端强/前端弱/无协议设计经验
- 时间预算：3 个月上线

Agent 输出（节选）：
- 段3 必选：MCP（调数据源）+ A2A（多Agent间协作）+信通院ATH适配层（必须）
- 段3 推荐：AG-UI（多Agent过程可视化，金融场景必须可见）
- 段3 按需：Skills（数据分析方法论封装，二期）
- 段4 总成本评级：中-高（金融合规+多Agent+前端改造+无协议设计经验）
- 段6 ATH/AIP 必须预留 Adapter 层，金融数据不出境
- 段8 渐进式：一期 MCP+A2A+ATH 适配，二期 AG-UI+Skills

## 调用要点

- 协议选型前先交叉引用 D-24.01 Agent产品形态，明确形态再选协议
- 国内合规场景必须预留 Adapter 层以便后续应对信通院 ATH 和信标委 AIP 国标
- 治理方案是生产 Agent 的硬要求（生产环境必须升级 MCP 2026-07-28 修订版）
- 团队能力弱时优先 MCP（生态成熟 SDK 多），延后 ACP（IBM Bee 国内生态弱需自研）

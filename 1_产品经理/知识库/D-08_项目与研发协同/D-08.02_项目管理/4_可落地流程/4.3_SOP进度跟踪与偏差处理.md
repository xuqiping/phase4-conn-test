# SOP：进度跟踪与偏差处理

## 适用场景

项目进入执行阶段后，PM需要周期性跟踪进度、识别偏差、决定是否纠偏。本SOP覆盖日常跟踪频率、偏差判断标准和纠偏决策流程。

## 角色与职责

| 角色 | 职责 |
|---|---|
| PM | 主导进度跟踪、偏差分析、纠偏决策 |
| Tech Lead | 提供技术层面的偏差评估和方案 |
| QA | 提供质量维度的进度反馈 |
| 业务方 | 接收偏差通报、参与优先级调整决策 |

## 每日跟踪（5分钟站会或异步更新）

### 输入
- 昨日完成的任务
- 今日计划的任务
- 阻塞/风险项

### 输出
- 阻塞清单（who/what/since_when/need_what）
- 依赖确认清单

### 规则
- 站会不讨论解决方案，只识别阻塞
- 阻塞超过1天的必须升级
- 异步团队用文档/Loom视频替代站会

## 每周跟踪（30分钟进度会）

### 输入
- 燃尽图/燃起图当前状态
- 风险登记册更新
- 各团队交付物完成百分比

### 偏差判断标准

| 偏差程度 | 判断标准 | 行动 |
|---|---|---|
| 🟢 正常 | SPI≥0.95 且 CPI≥0.95 | 继续执行 |
| 🟡 预警 | 0.85≤SPI<0.95 或 0.85≤CPI<0.95 | 分析根因+制定纠偏方案 |
| 🔴 严重 | SPI<0.85 或 CPI<0.85 | 启动纠偏流程+升级通报 |

### 纠偏决策流程

```
偏差识别 → 根因分析（5Whys） → 纠偏方案评估
  ├── 方案A：加资源（追加人力/加班）→ 评估：人力边际递减，Brooks法则风险
  ├── 方案B：缩范围（砍需求/降DoD）→ 评估：影响哪些交付物/业务优先级
  ├── 方案C：延日期（推迟里程碑）→ 评估：影响哪些依赖方/业务节点
  └── 方案D：组合方案 → 评估：以上组合的性价比

→ 选择方案 → 更新基线 → 通报相关方 → 执行监控
```

**纠偏决策红线**：
- 不允许"什么都不做期望自愈"——偏差不会自愈
- Brooks法则：向延期的项目加人通常让它更延期（新人有学习曲线且增加沟通成本）`[来源:Brooks·The Mythical Man-Month 1975 | 置信度:🔍高]`
- 缩范围时必须通知业务方，不能PM单方面"悄悄砍需求"

## 里程碑跟踪

每个里程碑到达前3天做预检：

| 检查项 | 通过标准 | 未通过处理 |
|---|---|---|
| 交付物完整度 | 100%完成DoD | 剩余项清单+影响评估 |
| 质量门达成 | P0=0, P1≤N | 遗留缺陷修复计划 |
| 部署就绪 | 部署方案已验证 | 部署演练/回滚验证 |
| 相关方确认 | 验收方已预审 | 安排预审会议 |

## 输出物

- **周进度报告**（模板）：本周完成 / 下周计划 / 风险与阻塞 / 偏差说明
- **偏差报告**（触发时）：偏差描述 / 根因 / 纠偏方案 / 影响 / 新基线
- **里程碑预检报告**：检查项状态 / 未通过项清单 / 建议

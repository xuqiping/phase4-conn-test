# 3.2 与KANO和RICE的映射

## KANO→MoSCoW直接映射

| KANO类别 | MoSCoW映射 | 逻辑 |
|---|---|---|
| **M(必备)** | **Must-have** | 不做=产品不可用 |
| **O(期望)** | **Should-have** | 做了显著改善，不做可暂缓 |
| **A(魅力)** | **Could-have** | 惊喜但非必需 |
| **I(无差异)** | **Won't-have** | 做不做无所谓→不做 |
| **R(反向)** | **Won't-have** | 做了反而不好→坚决不做 |

### 映射的例外

| 例外场景 | KANO类别 | MoSCoW调整 | 原因 |
|---|---|---|---|
| 合规截止日期 | O(期望) | **Must** | 有时间约束→必须按期交付 |
| 战略项目 | A(魅力) | **Should** | 战略方向→优先级提升 |
| 大客户强需求 | I(对全体) | **Could→Should**（对该客户分层） | 单客户重要→分层处理 |

## RICE→MoSCoW分位数分桶

RICE排序后按**分位数**切为四桶：

| MoSCoW桶 | RICE分位数 | 占比 |
|---|---|---|
| **Must** | Top 20-30% | 高RICE得分+KANO=M的需求 |
| **Should** | 30-60% | 中高RICE得分+KANO=O的需求 |
| **Could** | 60-85% | 中低RICE得分+KANO=A的需求 |
| **Won't** | Bottom 15% | 低RICE得分+KANO=I/R的需求 |

### RICE+KANO→MoSCoW的联合分桶流程

```
Step 1: RICE评分 → 量化排序
Step 2: KANO分类 → 定性标注
Step 3: 联合分桶：
  - RICE Top% + KANO=M → Must（量化高+定性必做）
  - RICE Top% + KANO=O → Should（量化高+期望）
  - RICE低 + KANO=M → Must（无论量化低，定性必做）
  - RICE高 + KANO=I → Won't（量化虚高，定性无感）
  - 剩余按RICE分位数分配到Should/Could
Step 4: 校验Must≤60%资源
```

## 三框架互补关系

| 框架 | 解决的问题 | 不解决的问题 | 与其他框架互补 |
|---|---|---|---|
| **KANO** | 需求是M/O/A/I/R哪类？ | 不考虑成本和覆盖面 | +RICE补充量化+MoSCoW补充取舍 |
| **RICE** | 哪个需求的商业价值最高？ | 不知道"必须做"和"可不做"的边界 | +KANO补充定性+MoSCoW补充分桶 |
| **MoSCoW** | 这次做什么、不做什么？ | 不解决桶内排序 | +RICE排序+KANO定性校验 |

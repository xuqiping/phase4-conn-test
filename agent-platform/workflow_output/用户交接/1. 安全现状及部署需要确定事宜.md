# 现状
1. 用户单点登录：只能在一处登录，换一处登录后就其他地方就直接掉线
2. 用户低余额的时候，不允许进行并行生成任务
3. 账号权限本身隔断
4. token鉴权、15min重刷，防止token被人拿到后可以长期冒用身份，需要使用https来防传输中数据泄露
5. 上传文件限制白名单后缀，限制危险类型（dll、bat、html）等上传
6. 日志系统，能看到每个用户的一些操作
7. 账单总览里可以看到具体各类大模型的调用消耗
8. 当前积分充值由系统管理员手动为账号充值积分
9. 对请求的速度会做一定的限制


# 部署要做的及一些功能的确定
1. HTTPS
2. 注册、登录和找回密码采取什么方式？短信验证（需接第三方接口），邮箱登录（需接第三方接口），直接账密登录，微信扫码登录（需要微信开放平台授权），要注意的风险：大量人员恶意获取验证码，消耗公司资金
3. 后续会采取各种行为验证，异常（如ip不断切换，请求高频率等，超过24小时长时间交互，爬虫等）行为，分类为高危、中危、低危，高危直接封号，中危告警发送至运维人员相关聊天软件中
4. 需要接入什么聊天软件（如钉钉）
5. 各类模型的接入
6. 后续积分的充值，是否由学员直接支付宝/微信充值
7. 部署后，需要开几个测试账户



# 后续安全方面一些规划
- 先把接口限流、请求体签名、双向证书的方案补一套方案，另外目前token存localStorage，有XSS风险，token可以改迁httpOnly cookie
- 目前靠文件名后缀判断，还没校验文件真实内容（magic number）。改后缀能骗过上传，但下载侧有兜底——骗进来的脏文件下载时仍强制另存不执行，所以伤不到用户，但库里会留垃圾文件

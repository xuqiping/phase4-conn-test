## 关键设计决策

- **徽标数据平铺在 node.data（非嵌套对象）**：`assetId/assetName/assetVersion/assetHasUpdate` 四字段平铺，与现有 fileId/prompt/outputText 风格一致；`useNodeAssetBadge(props.data)` 收 `Record<string,unknown>` bag（非窄接口）避免与 5 类节点各自 data 类型交叉摩擦，且响应式正确（props.data 是 reactive，computed 内访问字段被追踪，updateNodeData Object.assign 即时反映）。
- **「有新版」会话级非持久化**：`assetHasUpdate` 不入快照（onSave 仅剥 previewUrl，但该字段运行时挂上后会被下次加载重置为 undefined——因快照 clean 不含它）。检测靠属性面板「检查更新」按钮主动拉 `assetApi.get` 比对 currentVersion（L6「不自动变，手动更新」），不做每节点轮询（性能）。PLAN L6 原文：资产升版后徽标提示「有新版」不自动变。
- **重复入库三态前端化**：后端首次无 mode 检测到 PRODUCED 绑定重复 → 返 `created=false + duplicateAssetId/Version`；前端置 `duplicate` ref 显「存为新版本(NEW_VERSION)/另存为新资产(NEW_ASSET)」两按钮再带 mode 调（plan §S7 重复三态；L5「已有 PRODUCED 绑定默认存为新版本，可选新建」）。
- **mediaType 映射前后端对齐**：前端 `NODE_TO_MEDIA`（text→PROMPT/script→SCRIPT/image→IMAGE/video→VIDEO/audio→AUDIO）与后端 `AssetCanvasBridgeService.mapMediaType` 完全一致；AssetPicker 据此过滤列表，applyAssetResolve 据此决定写回字段（文本类解析 content JSON 取 body/synopsis+scenes，文件类取 fileId+预览）。
- **入库两入口**：节点右键（CanvasBoard `@node-context-menu`，L5 主入口）+ 属性面板「存入资产库」按钮（SaveToAssetDialog 同弹窗）。从库选择仅属性面板入口（不污染右键菜单）。
- **projectOptions 入库仅可写 / 选择全列**：入库须 requireWrite（editor+owner），SaveToAssetDialog 过滤 `role∈{OWNER,EDITOR}`；AssetPicker 全列（viewer 也可读引用，resolve 走 loadAccessible，设计 §7.2）。
- **顺带 bundle 一处 canvas 预存修复**：CanvasView.loadCanvas 的 `boardRef.value?.loadSnapshot(snap)` 前 `await nextTick()`（修「重进画布空白」历史 bug——editingId 触发 v-else 渲染，boardRef 下一 tick 才赋值，否则 boardRef.value===null 静默吞 loadSnapshot）。此修复在 S12 commit 前已在工作树（预存 M），与 S12 同文件故一并提交，commit message 已注明。

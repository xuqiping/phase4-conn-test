# Implementation Plan for 图片视频模块历史分页与预览缓存

> Phase 2 产出。Phase 3 逐步勾选执行。只含伪代码，不含真代码。
> 来源规格：[../specs/图片视频模块历史分页与预览缓存设计.md](../specs/图片视频模块历史分页与预览缓存设计.md)
> **本计划是六份四轮修复计划的第一份**：Step 3 产出的 `MediaLightbox`/`HoverPreviewImage` 共享组件被 [画布计划](无限画布四轮增强.plan.md) 与 [视频反推计划](视频反推与转绘.plan.md) 引用，必须先行。

## 背景与目标

- 4x#2：视频历史分页（默认10，可选 5/10/20/50）；图片页顺带统一。
- 4x#3 / 6x#1（重复项合并）：参考图悬浮放大 + 点击灯箱。
- 6x#2：图片加载缓存（会话内 LRU + 跨会话 ETag 304）。
- 附带回答 4x「待解答：进缓存的会更新吗」→ 规格 §5.3（fileId 不可变 + ETag 兜底）。

## 技术实现坑点预判与规避措施

| 技术点/功能块 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| `/api/media/tasks` 响应改包裹结构 | **破坏性变更**：未知消费方（入库弹窗、管理页等）拿到 undefined 崩溃 | Step 1 先全仓 grep `listTasks`/`GET /api/media/tasks` 消费方，逐一列入改造清单再动手 | grep 清单核对 + 全部消费方单测/手测 |
| `limit` 兼容路径 | 画布/旧调用只传 limit，新代码误判为非法 | limit 存在且 pageSize 缺省 → pageSize=limit；两者同传以 pageSize 为准 | 单测：三种传参组合 |
| n-data-table remote 分页 | 筛选变化未重置页码 → 第 3 页筛选出空列表卡死 | 筛选 watcher 里 `page=1` 再请求 | playwright：第3页改筛选回第1页 |
| LRU 缓存存 objectURL | objectURL 被 revoke 后缓存命中返回死链 | 缓存 **Blob**，命中时 `URL.createObjectURL` 新建（对齐 media.ts 既有模式） | 单测：命中两次拿不同 URL 且都可渲染 |
| ETag 304 与 axios blob | 304 无 body，axios 可能抛错或返回空 blob | 用原生 fetch 或 axios `validateStatus` 放行 304；304 时直接用浏览器缓存（浏览器自动处理，应用层拿到的就是 200 缓存体）——只验证不破坏 | 手测 Network 面板二次请求 304 |
| FileController 条件请求 | If-None-Match 比较大小写/引号不规范导致永不 304 | ETag 统一加引号小写十六进制；用 `request.getHeader("If-None-Match")` 全量比对（无弱比较需求） | 单测：首访 200 带 ETag，复访 304 |
| 双缓存内存 | mediaBlobCache(256MB)+filePreviewCache 合计超 400MB 前端 OOM | filePreviewCache 字节上限 128MB、条数 80（规格已定） | 单测逐出逻辑 |

## 安全检查清单

- [x] **鉴权**：分页参数为纯查询，沿用既有 `media:gen`；FileController 缓存头不改变鉴权时序（先鉴权后 ETag 判定）
- [x] **输入校验**：page≥1、pageSize∈{5,10,20,50}（非法回落不报错）；FileController 的 ETag 只用服务端生成的 fileId+size，不回显用户输入（前半 Step1 已落：resolvePageSize 白名单+page 归一；ETag 属 Step6）
- [x] **错误处理**：分页 count 与 list 同事务参数，防 total 与列表不一致（Step1 已落：page() 归一化参数同传 countHistory/selectHistory，单测覆盖）
- [ ] **审计**：FileController 若有 @AuditLog 保持命中（304 也算一次访问，审计不丢）
- [x] **依赖安全**：无新增依赖

## 性能考虑与验证计划

- [ ] total count 走 `COUNT(*)` 与 list 同 where（无 N+1）
- [ ] 304 后图片二次加载无 body 传输（Network 面板 bytes 对比）
- [ ] filePreviewCache 命中不发请求（拦截器计数单测）
- [ ] Phase 4 测量：历史首屏加载时间（50条全量 vs 10条分页）

## 功能联动点清单（含反向/边界）

| # | 触发动作 | 联动对象 | 预期变化 | 必测边界 |
|---|---|---|---|---|
| L1 | 筛选（提示词/时间）变化 | 分页器 | 重置第1页并重载 | 清空筛选同样重置；翻页时筛选条件保持不丢 |
| L2 | 点击参考图瓦片 | hover 浮层 | 浮层先关、灯箱后开 | hover 中直接点击不叠层；灯箱 Esc/遮罩关闭后 hover 状态复位 |
| L3 | 历史行点击回填（既有能力） | 分页器/表单 | 回填不影响当前页码 | 翻页后点行回填正常；回填后再翻页表单不清空 |
| L4 | 视频瓦片点击播放 | 表单还原回填 | 播放弹窗独立，不改表单 | 弹窗打开时提交表单不受阻；关闭后瓦片状态原样 |
| L5 | 切每页条数 | 当前页 | 超出新范围时回落第1页（如第5页×5条 → 改50条时回1页） | 回落后 itemCount 刷新正确 |

## 运维考量清单

| 类别 | 结论 | 说明 |
|---|---|---|
| 可观测性 | **做** | FileController 304 命中打 debug 日志（fileId+命中），便于排查「图片不更新」类工单 |
| 配置开关 | **不做** | LRU 常量前端固版；分页无灰度必要 |
| 可回滚 | **做** | 包裹结构为破坏性变更：**前后端必须同版本发布/同回滚**，发布单注明；ETag/缓存头可独立回滚（无状态） |
| 限流/熔断 | **不做** | 无新第三方依赖；轮询退避已在画布计划处理 |
| 运维入口 | **不做** | 无需补单/对账 |
| 告警阈值 | **后续再说** | 304 命中率若后续接入指标再定阈值 |
| 容量/性能 | **做** | 分页本身即容量方案（消除 limit=50 全量拉取） |

## 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| remote 分页 | 翻页才向服务器要那一页 | 第3页只请求21-30条 |
| 304 | 指纹没变，服务器回「没变」不传正文 | 二次加载图片零流量 |
| LRU | 满了扔最久没用的 | 缓存80张图，第81张挤掉最早那张 |
| 灯箱 | 点小图弹全屏大图层 | 黑底居中大图，点空白关闭 |

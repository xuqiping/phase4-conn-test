## 一、目标与范围

### 1.1 要解决的问题

现状盘点（`backend/.../auth/`）：

| 维度 | 现状 | 评价 |
|---|---|---|
| 注册入口 | `POST /api/auth/register`（账密+邮箱，邮箱**未验证**） | ⚠️ 邮箱不验证=垃圾注册+找回密码漏洞 |
| 登录入口 | `POST /api/auth/login`（仅账密） | 单一通道 |
| 防爆破 | 账号 5 次锁 15min / IP 20 次封 1h / dummy bcrypt 抹平时侧信道 | ✅ 业界水准 |
| 注册限流 | IP 60s 5 次 / 用户名 60s 5 次 | ✅ |
| 密码策略 | 大小写+数字+特殊字符+弱密码字典+bcrypt 72 字节 | ✅ |
| 会话 | JWT + 单点登录 sid + Redis 黑名单 | ✅ |
| 第三方 | 钉钉免登（自动建号） | 有 OAuth 模式可复用 |
| **找回密码** | ❌ **完全没有** | 最大缺口 |
| 邮箱验证 | ❌ 邮箱不验证 | 缺口 |
| 手机号 | ❌ 表里没有 phone 列 | 缺口 |
| 微信登录 | ❌ 无 | 缺口 |

### 1.2 本期范围（四项全做）

1. **邮箱验证 + 找回密码**：注册发验证邮件，找回密码走邮件重置
2. **手机号验证码登录/注册**：输入手机号收码，新号自动建号
3. **微信扫码登录/注册**：PC 端扫码，新号自动建号
4. **账号密码登录优化**：条件触发滑块验证码、异地登录提醒

### 1.3 已确认的关键决策

| 决策项 | 选择 | 理由 |
|---|---|---|
| 云厂商 | **阿里云一体**（短信+邮件），微信独立走微信开放平台 | 邮件几乎免费、短信略便宜、Java SDK 成熟 |
| 验证码闸门 | **AJ-Captcha 滑块**（发验证码前 + 登录失败 ≥3 次弹） | 防短信轰炸/撞库，零成本 |
| 找回密码通道 | **邮件+短信双通道** | 覆盖所有用户类型，成本可忽略 |
| 账号体系 | **独立账号+可绑定合并** | 延续现有 bind_type 模式，老用户可手动绑定 |
| 邮箱注册流程 | **注册即可登录，但未验证邮箱不可用于找回** | 降低流失（替代两步激活方案） |
| 异地登录提醒 | **一期做** | 用 ip2region（Apache 2.0）纯国内精度高 |
| 手机验证码登录 | **登录即注册**（号不存在自动建号） | 从根上消除账号枚举 |
| 找回密码话术 | **统一"若账号存在，重置链接已发送"** | 防账号枚举 |

### 1.4 开源库选型（全部可商用协议）

| 能力 | 库 | 协议 | 版本 |
|---|---|---|---|
| 微信 SDK | WxJava (`weixin-java-mp`) | Apache 2.0 ✅ | 4.6.0+ |
| 短信 | 阿里云官方 SDK (`dysmsapi20170525`) | 官方商用 ✅ | 3.0.0+ |
| 邮件 | 阿里云官方 SDK (`dm20231123`) | 官方商用 ✅ | 1.0.0+ |
| 滑块验证码 | AJ-Captcha (`spring-boot-starter-captcha`) | Apache 2.0 ✅ | 2.2.0+ |
| GeoIP 归属地 | ip2region | Apache 2.0 ✅ | 2.7.0+ |

> 注：JustAuth（MIT）可作为后续接入 QQ/微博等多平台的统一 OAuth 封装，本期微信/钉钉直接用 WxJava/现有钉钉代码即可，不强行引入新依赖。


### 3.2 账号模型：独立账号 + 可绑定合并

延续现有 `bind_type` 模式，新增 `user_credential` 凭证表解耦多种登录方式：

```sql
CREATE TABLE user_credential (
    id              BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id         BIGINT NOT NULL REFERENCES users(id),
    credential_type VARCHAR(20) NOT NULL,  -- PASSWORD/EMAIL/PHONE/WECHAT/DINGTALK
    identifier      VARCHAR(200) NOT NULL,  -- 邮箱/手机号/openid/unionid/用户名
    secret          VARCHAR(200),           -- 密码 hash（仅 PASSWORD 类型）
    verified        BOOLEAN NOT NULL DEFAULT FALSE,
    verified_at     TIMESTAMP WITH TIME ZONE,
    created_at      TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    deleted         INT NOT NULL DEFAULT 0,
    version         INT NOT NULL DEFAULT 0
);
```

**为什么用凭证表（而非直接在 users 加列）**：
- ✅ 新增凭证类型只加行不改表（未来加 QQ/微博零成本）
- ✅ 一个用户可绑多种凭证（邮箱+手机+微信都能登同一账号）
- ✅ `verified` 字段强制邮箱/手机验证后才可用，堵住"注册不验证=找回密码漏洞"
- ✅ 兼容现有：存量账密用户迁移写一条 PASSWORD 凭证
- ✅ 钉钉现有逻辑保留不动，二期可统一迁入

**users 表最小改动**：

```sql
ALTER TABLE users ADD COLUMN phone VARCHAR(20);
ALTER TABLE users ADD COLUMN wechat_unionid VARCHAR(100);
ALTER TABLE users ADD COLUMN wechat_openid VARCHAR(100);
CREATE UNIQUE INDEX uk_users_wechat_unionid ON users (wechat_unionid) WHERE wechat_unionid IS NOT NULL;
CREATE UNIQUE INDEX uk_users_phone ON users (phone) WHERE phone IS NOT NULL;
```

## 四、各通道详细流程

### 4.1 通道 A：邮箱验证注册（增强现有注册）

**流程**（注册即可登录，邮箱验证后才可用于找回）：

1. 前端填用户名+邮箱+密码+勾选协议
2. 后端校验用户名/邮箱唯一 → PasswordPolicy 校验密码
3. users 建号 `status='ACTIVE'`（可立即登录）
4. user_credential 写 PASSWORD 行（verified=TRUE）+ EMAIL 行（verified=FALSE）
5. 生成验证 token（Redis，`verify:email:<token>` → userId，TTL 24h）
6. 发验证邮件（阿里云 DM），正文带深链 `https://x/verify-email?token=xxx`
7. 前端提示"注册成功，请去邮箱验证（未验证邮箱不可用于找回密码）"

**邮箱激活**：用户点邮件链接 → 前端 VerifyEmailView → 调 `/verify/email` → 后端校验 token → EMAIL 凭证 verified=TRUE → 提示激活成功。

**重发邮件**：`/resend/email`，同邮箱 60s 限流。

**安全点**：
- token 用 `SecureRandom` 生成 32 字节 + Base64URL，不可猜测
- 邮箱唯一约束兜底（防并发注册）
- 邮件重发限流（同邮箱 60s 一次）

### 4.2 通道 B：手机号验证码登录/注册（新号自动注册）

**登录和注册同一接口**——手机号存在就登录，不存在就建号。

**发码流程** (`POST /sms/code`)：
1. 前端先过滑块验证码拿 captchaToken
2. 后端校验滑块 + 手机号格式（`^1[3-9]\d{9}$`，纯国内）+ 限流
3. 生成 6 位码（SecureRandom，Redis `sms:code:<phone>` → code，TTL 5min）
4. 阿里云 SMS 发送
5. 返回"验证码已发送"

**登录流程** (`POST /login/sms`)：
1. 校验码匹配 + 未过期 + 未用过
2. 查 user_credential PHONE 行
   - 存在且 verified → 登录发 JWT
   - 不存在 → 建号（username=phone, bind_type='phone', 无密码占位 hash）+ 建凭证 + 发 JWT
3. 删除已用验证码（防重放）

**限频**：同号 60s 一次、同号每天 10 次、同 IP 每天 30 次。

**安全点**：
- 滑块验证码是发码前置闸门（防机器人刷短信）
- 验证码用完即删
- 统一话术不区分"码错"和"号不存在"

### 4.3 通道 C：微信扫码登录/注册（新号自动注册）

复用现有钉钉模式，用 WxJava 走标准 OAuth2 网站应用流程：

1. 前端点"微信登录" → `GET /login/wechat/redirect` 生成授权跳转 URL（带 state）
2. 跳转微信授权页，用户扫码确认
3. 微信重定向回 `/login/wechat/callback?code=xxx&state=xxx`
4. 后端校验 state（防 CSRF）→ WxJava 用 code 换 access_token + openid + unionid + 用户信息
5. 查 user_credential WECHAT 行（按 unionid）
   - 存在 → 登录发 JWT
   - 不存在 → 建号（username=wx_<openid前8位>, bind_type='wechat'）+ 建凭证 + 发 JWT
6. JWT 通过 URL fragment（`#/login?token=xxx`）传给前端，前端存 store 跳首页

**配置开关**：`app.auth.wechat.enabled`（未配置 AppID 时前端不显示微信登录，同钉钉 `isDingTalkEnabled` 模式）。

**安全点**：
- state 参数防 CSRF（跳转时生成存 Redis，回调严格校验）
- AppSecret 仅后端环境变量持有
- redirect_uri 白名单后端固定

### 4.4 通道 D：找回密码（邮件+短信双通道）

1. 前端输入账号（用户名/邮箱/手机）→ `POST /password/forgot`
2. 后端查账号 → 拿绑定的邮箱/手机
3. 生成 reset_token（Redis `reset:pwd:<token>` → userId，TTL 30min）
4. **固定话术**："若账号存在，重置链接已发送"（不泄露账号是否存在）
5. 按账号绑定通道发（**前端选发哪个**，后端校验该通道凭证 verified=TRUE 才发；都未验证则不发但仍返回统一话术）：邮箱→链接邮件，手机→6 位码短信
6. 用户点链接（邮箱）或输码（手机）+ 新密码 → `POST /password/reset`
7. 后端校验 token/码 → PasswordPolicy 校验新密码 → 新旧不可相同
8. 更新 PASSWORD 凭证 secret → **失效所有会话**（sessionService 清该用户所有 sid）
9. 提示"重置成功，请登录"

**限频**：同账号 1 小时 3 次、同 IP 1 小时 10 次。

**安全点**：
- 账号枚举防护（统一话术）
- reset_token 用 SecureRandom 32 字节，用完即删
- 重置后强制踢所有会话（防 token 被盗后改密残留会话）

### 4.5 通道 E：账号密码登录优化

**E1. 条件触发滑块验证码**：同一账号失败 ≥3 次后，下次登录前端强制弹滑块。后端 login:fail 计数 ≥3 时返回 `captcha_required=true`，前端弹滑块，提交带 captchaToken 后端复验。

**E2. 异地登录提醒**（一期）：登录成功时比对上次登录 IP 的归属地（ip2region 离线库查），若跨省则发邮件/站内信提醒。

### 4.6 新增 API 端点

| 方法 | 路径 | 说明 | 鉴权 |
|---|---|---|---|
| POST | `/api/auth/register` | 现有，改流程（建号即 ACTIVE + 发验证邮件） | 公开 |
| POST | `/api/auth/verify/email` | 邮箱激活 token 校验 | 公开 |
| POST | `/api/auth/resend/email` | 重发激活邮件（限流） | 公开 |
| POST | `/api/auth/sms/code` | 发短信验证码（前置滑块） | 公开 |
| POST | `/api/auth/login/sms` | 手机号+码登录 | 公开 |
| GET | `/api/auth/login/wechat/redirect` | 生成微信授权跳转 URL | 公开 |
| GET | `/api/auth/login/wechat/callback` | 微信回调换 JWT | 公开 |
| POST | `/api/auth/password/forgot` | 发起找回 | 公开 |

```sql
    secret          VARCHAR(200),
    verified        BOOLEAN NOT NULL DEFAULT FALSE,
    verified_at     TIMESTAMP WITH TIME ZONE,
    created_at      TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    deleted         INT NOT NULL DEFAULT 0,
    version         INT NOT NULL DEFAULT 0
);

CREATE UNIQUE INDEX IF NOT EXISTS uk_credential_type_identifier
    ON user_credential (credential_type, identifier) WHERE deleted = 0;
CREATE UNIQUE INDEX IF NOT EXISTS uk_user_credential_type
    ON user_credential (user_id, credential_type) WHERE deleted = 0;
CREATE INDEX IF NOT EXISTS idx_credential_user
    ON user_credential (user_id) WHERE deleted = 0;

COMMENT ON TABLE user_credential IS '用户凭证表：一人多凭证（邮箱/手机/微信/密码）';
COMMENT ON COLUMN user_credential.credential_type IS 'PASSWORD/EMAIL/PHONE/WECHAT/DINGTALK';
COMMENT ON COLUMN user_credential.identifier IS '邮箱地址/手机号/openid/unionid/用户名';
COMMENT ON COLUMN user_credential.verified IS '是否已验证（邮箱点链接/手机收码/微信授权）';

-- 3. 迁移存量：账密 → PASSWORD（verified=TRUE），邮箱 → EMAIL（verified=FALSE）
INSERT INTO user_credential (user_id, credential_type, identifier, secret, verified, created_at)
SELECT id, 'PASSWORD', username, password, TRUE, created_at FROM users WHERE deleted = 0
ON CONFLICT DO NOTHING;

INSERT INTO user_credential (user_id, credential_type, identifier, verified, created_at)
SELECT id, 'EMAIL', email, FALSE, created_at FROM users
WHERE deleted = 0 AND email IS NOT NULL AND email != ''
ON CONFLICT DO NOTHING;
```

**迁移说明**：
- 存量 PASSWORD 凭证 `verified=TRUE`（老用户密码可用，不影响登录）
- 存量 EMAIL 凭证 `verified=FALSE`（老用户需登录后验证邮箱才能用于找回——原邮箱本就没验证过）
- 钉钉存量 `dingtalk_union_id` **暂不迁移**（现有 AuthService.loginByDingTalk 保留不动）

# 人工测试问题 1—4 修复性能目标

> 测量环境：Windows 10/11、常见办公电脑、Release 构建；Debug 数据只用于趋势参考。

## 1. 指标

| 场景 | 目标 | 测量方式 |
|---|---:|---|
| 主界面首次可交互 | 不因收藏项快捷键恢复增加超过 100ms 阻塞 | Performance 标记；恢复任务后台执行 |
| 100 个独立快捷键恢复 | ≤1.5s | 从恢复开始到全部成功/失败有结论 |
| 单个 `.lnk` 解析与复制 | P95 ≤500ms | 100 次本地样本统计 |
| 点击悬浮球到主窗口开始显示 | P95 ≤300ms | Tauri 事件时间戳 |
| 悬浮球空闲 CPU | 平均 <0.2% | 60 秒系统监控 |
| 进程刷新 | 相对现有基线增长 ≤10% | 同一进程集合前后对比 |
| 1 万条剪贴板记录分组首屏查询 | P95 ≤200ms | SQLite 查询计时，limit 100 |
| 1 万条剪贴板记录置顶/取消置顶 | P95 ≤100ms | 单事务计时 |
| 删除含 1 万条记录的分组 | P95 ≤500ms | 置空归属和删除事务计时 |

## 2. 资源限制

- 悬浮球只加载最小宿主组件，不挂载完整主应用 Store 和业务页面。
- 快捷键恢复不得无限并发；按有界队列注册，单项失败不重试风暴。
- 剪贴板查询必须分页，不允许为了分组统计把全部详情加载到前端。
- 窗口标题沿用一次 `EnumWindows` 结果，不为每行再次枚举系统窗口。

## 3. 退化处理

- 快捷键数量较大时主界面先可用，状态区显示后台恢复进度。
- SQLite 迁移或索引建立耗时超过 2 秒时显示“正在升级本地数据”，禁止重复启动迁移。
- 达不到查询目标时先检查查询计划与索引，不通过提高默认分页量掩盖问题。

## 4. 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| P95 | 100 次里至少 95 次不超过该时间 | 95 次悬浮球恢复在 300ms 内 |
| 有界队列 | 同时处理数量有限的任务队列 | 每次只注册少量快捷键 |
| 查询计划 | 数据库决定怎么找数据 | 是否真正使用分组索引 |

# 个人记忆 · 用户操作手册

> 面向所有用户（普通成员 / 项目 owner / admin）。只讲「用户能做什么 + 怎么做 + 看到什么 + 注意什么」。
> 技术原理见 [Feature Map](../feature-map/个人记忆.feature-map.md)，设计 why 见速查表 [09-个人记忆-设计与原理](../../../项目工程文档/项目功能介绍/速查表/09-个人记忆-设计与原理.md)。

**功能一句话**：把你在聊天里说过的话、传过的文件、被项目收录的内容，结构化沉淀下来；下次相关问题时 AI 自动召回辅助回答，并支持跨项目/跨个人按授权共享。

**统一入口**：聊天页右上角「记忆」按钮 → 打开记忆抽屉 [MemoryManagerPanel.vue](../../../frontend/src/components/chat/MemoryManagerPanel.vue)，9 个页签：
`流水账 · 标签库 · 总结 · 冲突裁决 · gen 矩阵 · 收录规则 · 收录审核 · 项目授权 · 文件记忆`

**适用对象速查**：

| 页签 | 普通成员 | 项目 owner | admin |
|---|---|---|---|
| 流水账 / 标签库 / 总结 / 冲突裁决 / gen 矩阵 / 文件记忆 | 本人 | 本人 + 项目管理 | 全局 |
| 收录规则 / 收录审核 | 只读 | 项目级配置 | 项目级配置 |
| 项目授权 | 本人 grant | 发起/审批 | 发起/审批 |

---

## 1. 对话自动留痕（流水账）

**你能做什么**：无需任何操作，每一轮对话（你说的一句 + AI 回的一段）系统自动各落一行流水账。随时查看自己的流水账、删 raw 原文。

**操作步骤**：
1. 正常在聊天页发消息、收回复。
2. 打开记忆抽屉 → **流水账** 页签 [MemoryTurnSection.vue](../../../frontend/src/components/memory/MemoryTurnSection.vue)。
3. 顶部工具栏切换「全部 / 仅 raw」、按关键词筛选、点「刷新」。
4. 每条卡片显示：方向 tag（「我说」=INPUT / 「回答」=OUTPUT）、时间、L1 概要、L2 详述、标签、**「收录于：项目X」**徽章。
5. 批量删：勾选行 →「删所选 N」→ 二次确认。

**预期结果**：
- 开生成时 → 落 L0 标签 + L1 概要 + L2 详述三层；卡片显示 L1/L2。
- 关生成时 → 仅落 raw 原文；卡片显「raw 未生成」黄标 + 原文内容。
- **被项目收录的对话**：INPUT 卡片和 OUTPUT 卡片**都会**显「收录于：项目X」蓝 tag（5x #2 两轮修复：V100 建链修新数据 + 第三轮 V125 存量回填修历史轮——修前仅 OUTPUT 显示且历史 INPUT 无收录标记；修后新旧 INPUT/OUTPUT 都挂收录链可反查）。

**注意事项 / 边界**：
- 流水账**仅本人可见**（恒个人域，user_id=作者），他人任何途径命中不了，无需额外隐私设置。
- raw TTL 90 天：`gen_done=false` 且超过 90 天的 raw 自动软删；已生成总结的 turn 其 raw_content 随 turn 保留（防溯源悬空）。
- 仅本人能看 / 能删自己的流水账，无导出。
- 删 raw 后若该 raw 被你的某条总结引用 → 该总结标 STALE，下次周期总结时重生。
- 被他人引用且引用方总结超过 12 小时的 raw → 拒删 403，提示改其他冲突裁决选项。

## 2. 设召回范围（这次提问 AI 参考哪些记忆）

**你能做什么**：多选召回 scope（个人 + 一个或多个项目），并按方向、时间窗过滤；选择持久化，下次会话沿用。

**操作步骤**：
1. 聊天输入框下方点「召回范围」气泡 [MemoryRecallScopePopover.vue](../../../frontend/src/components/memory/MemoryRecallScopePopover.vue)。
2. 勾选 个人 / 一个或多个项目（含你 owner 的、成员的、被授权只读召回的——后者标「授权」）。
3. 可选：设方向（仅我问的 / 仅 AI 答的 / 全部）、时间窗。
4. 勾选后 400ms 自动保存。

**预期结果**：下次提问，AI 自动带勾选范围内的相关记忆（流水账 + 总结 + 文件记忆）回答。

**注意事项 / 边界**：
- 取消全部勾选 → 空召回（AI 无记忆辅助，不报错）。
- 首次使用默认勾{个人}。
- 多选 = 并集（个人 + 多个项目记忆都参考）。
- 项目条目合流由 pipeline 按**当前会话所属项目**自动注入（不经 scope 多选），scope 多选只控制个人/项目总结层。
- **授权项目**：scope 候选里带「（授权）」后缀的项目（来自项目↔个人 grant 或项目↔项目 link 的 ACTIVE 授权），可只读召回其条目/共享总结，不能写入或总结它。

## 3. 标签库（主动加标签 + 改名补别名）

**你能做什么**：① 查看所有标签（按 subject 大类 + topic 主题分组）；② 主动新建标签（写时归一的补充，命中后新标签参与召回与总结）；③ 改标签展示名、补别名。**禁手动合并/拆分/重抽**。

**操作步骤**：
1. 打开记忆抽屉 → **标签库** 页签 [MemoryTagLibrary.vue](../../../frontend/src/components/memory/MemoryTagLibrary.vue)。
2. **新建标签**：点「新建」→ 填 subject（主体，默认「我」）/ topic（大类，13 个预置类）/ label（展示名）/ aliases（别名数组）→ 提交。
3. **改名/补别名**：点某行「编辑」→ 改 label 或加 aliases → 提交。
4. **被动归一**：聊天生成 L0 标签时，系统自动按 (subject, topic, label, aliases) 归一到既有标签；新概念自动建新行。

**预期结果**：
- tag_id 恒不变（改名/补别名只影响展示和归一命中，不动 id）。
- 新标签立即进入召回②标签聚合候选，下次相关对话会被 LLM 选择器选中。
- 别名参与后续写时归一（用户说「配偶」匹配上「妻子」标签）。

**注意事项 / 边界**：
- **禁手动合并/拆分/重抽标签**——误并不可逆，会让已生成总结的 tag_id 漂移、coverage 失效。
- 标签按用户隔离（per-user），他人标签看不到。
- subject='我' 且 owner≠当前用户时，装配时省略主体前缀（避免「张三·爱好」冗余）。

## 4. 总结（立即总结 + 重新总结 + 自动总结）

**你能做什么**：① 立即把新增流水账压成总结精华；② 重新总结（按标签/时间/方向筛选强制重压）；③ 加自动每日总结。总结卡片显方向 tag（输入/输出/综合）。

**操作步骤**：
1. 打开记忆抽屉 → **总结** 页签 [MemorySummarySection.vue](../../../frontend/src/components/memory/MemorySummarySection.vue)。
2. 顶部 scope radio 切换：**个人** / 你 owner 的项目 / 被授权只读项目（带「（授权）」后缀，且**无总结按钮**）。
3. **立即总结**（仅压新增，跳幂等闸）：点「立即总结」→ 弹框 [MemoryConsolidationDialog.vue](../../../frontend/src/components/memory/MemoryConsolidationDialog.vue) mode=instant → 选方向 radio（INPUT / OUTPUT / 综合）→ 确认。
4. **重新总结**（强制重压 + 筛选）：点「重新总结」→ 弹框 mode=resummarize → 选标签大类 / 时间范围 / 方向 → 确认。
5. **加自动总结**：弹框内勾「加入每日自动总结」。
6. 跑完后总结页出精华条。

**预期结果**：
- 总结卡片显示：所属项目名 tag（若 project_id 非空）+ subject:topic tag + **方向 tag**（「输入」=INPUT 蓝 / 「输出」=OUTPUT 绿 / 「综合」=BOTH 灰；个人总结按弹框所选方向，**项目总结按方向过滤取数**——第三轮 5x #4：总结时选「仅输入」就只压 INPUT 条目（综合 BOTH 条目双计入），INPUT 总结不挡 OUTPUT 再总结；修前项目总结恒吃全量）+ 状态徽标（CLEAN / PENDING_CONFLICT / STALE）。
- 来源行：「来源 N 条流水账」（个人总结）或「来源 N 条项目条目」（项目共享总结）。
- 个人总结 `user_id=你`，只你能读。

**注意事项 / 边界**：
- **项目总结仅项目 owner 可发起**（被授权只读项目的 scope 下「立即总结/重新总结」按钮隐藏——非 owner 即使个人通道也禁，呼应 Req1）。
- 立即总结：仅压距上次总结后有变化的 scope，无变化的 scope 不重复压。
- 重新总结：force=true 跳幂等闸，会重压该筛选范围内的全部（即使已总结过）。
- 自动总结：勾上的 scope 每天定时跑；**该 scope 该周期无新增未总结流水账时空跳过不耗 token**。
- **gen 矩阵关时**：自动总结 worker 只处理 `gen_done=true` 的 turn，raw 不进候选 → 若周期内全是 raw 则空跳过。raw 想要总结须开 gen 或手动走「立即总结」（详见第 7 节）。
- 「重新总结」的标签大类筛选：subject+topic 两个维度，选中后只压命中标签的 turn/entry。

## 5. 项目记忆条目（收录规则 → 精判 → 蒸馏 → owner 审核）

**你能做什么**：项目对话经「收录规则粗筛 → LLM 精判（零 LLM 护栏 + 三档分流 + 黑名单二次扫描）→ 蒸馏落库」后产生条目，owner/admin 审核（收录/弃），作者可撤回自己的。

**操作步骤**：
1. 打开记忆抽屉 → **收录审核** 页签 [MemoryEntryReviewPanel.vue](../../../frontend/src/components/memory/MemoryEntryReviewPanel.vue)。
2. 顶部选项目、切状态（待审核 / 已生效 / 全部）→ 刷新。
3. 每条卡片显示：L1 摘要、L2 详述（**脱敏蒸馏产物，不含对话原文**）、状态 tag、作者。
4. **owner/admin** 对 PENDING_REVIEW 行：点「收录」（→ACTIVE 生效）或「弃」（→追加为规则负例，最多保留 5 条，同类对话以后不再误收）。
5. **作者本人**对自己的条目：点「撤回」。

**预期结果**：
- 置信度 ≥0.8 的条目自动 ACTIVE，0.5~0.8 进 PENDING_REVIEW 待 owner/admin 处置，<0.5 直接不收录。
- ACTIVE 条目项目成员即可读（召回时合流），成员离职（DEPARTED）即失读权。
- 「弃」反哺规则负例后，下次同类对话精判时被黑名单二次扫描拦下，不再误收。

**注意事项 / 边界**：
- 条目是脱敏蒸馏产物（L1/L2 摘要层），**不含对话原文**——原文留在本人流水账，他人读不到。
- 成员只能见自己产生的条目 + 待审核全量；owner/admin 见全量。
- 收录规则配置在 **收录规则** 页签 [MemoryRulePanel.vue](../../../frontend/src/components/memory/MemoryRulePanel.vue)（owner/admin 可配 anchor 同步算、embed 失败强制停用；负例仅 owner 可见）。

## 6. 项目授权（项目↔项目 / 项目↔个人 / 公共池）

**你能做什么**：把你项目的记忆条目召回权授权给另一个项目、某个个人、或推入公共池给所有人申请；反过来也能申请召回他人的。授权即时影响召回，无缓存。

**操作步骤**：
1. 打开记忆抽屉 → **项目授权** 页签 [MemoryProjectLinkPanel.vue](../../../frontend/src/components/memory/MemoryProjectLinkPanel.vue)。

### 6a. 项目 ↔ 项目授权链
2. **发起授权**（我 owner 的项目 = 授权方 child）：「我授权出去的」区 → 选 授权方项目 →「→ 授权给 →」→ 选 被授权方项目 →「发起授权」。状态 PENDING。
3. **对方审批**（我 owner/admin 的项目 = 被授权方 parent）：「待我审批的」区 → 对 PENDING 行点「通过 / 拒绝」。通过后 ACTIVE，对方成员召回时单级一跳并入我项目条目（装配标「来自授权项目·X」）。
4. **非对称撤销**（5x 设计）：
   - **授权方（child owner）撤**：点「撤销」→ 状态维持 ACTIVE + 标「撤销审批中」→ **需被授权方 parent owner/admin 审批**（「待我审批的」区出现「对方申请撤销」→ 通过撤销 / 拒绝撤销）。
   - **被授权方（parent owner/admin）撤**：点「撤销」→ **即时 REVOKED**，我项目成员立即召回不到对方条目，并通知对方。
5. **撤回撤销申请**：授权方在「撤销审批中」态可点「撤回申请」。

### 6b. 项目 ↔ 个人授权
6. **项目主动授权个人**（我 owner/admin）：「项目授权给个人」区 → 选授权项目 → 搜被授权人 →「授权」→ **立即 ACTIVE**。
7. **个人申请召回某项目**：「我申请的召回」区 → 选项目 → 提交申请 → PENDING → 待项目 owner/admin 审批 → ACTIVE 后只读召回。
8. 任一方「撤销」→ 即时断召回。

### 6c. 公共池
9. **owner/admin 推入**：「公共池管理」区 → 对自己 owner/admin 的项目切「推入公共池」开关 → 推入后所有人可在公共池列表看到并申请。
10. **个人申请公共池项目**：在授权页/召回 scope 候选里点申请 → PENDING → 项目 owner/admin 审批 → ACTIVE。

**预期结果**：
- ACTIVE 授权：被授权方召回 scope 候选出现该项目（带「授权」tag），可只读召回条目/共享总结。
- 总结页 scope radio：授权项目并列，**无「立即总结/重新总结」按钮**（只读）。
- 被授权方读授权方共享总结时，卡片显**来源项目名 tag**（黄色）。
- 撤销即时影响召回（live 查询，无缓存）：被授权方立即召回不到。

**注意事项 / 边界**：
- 授权链单级不传递（A→B→C，B 不能把 A 的条目再授给 C）。
- 被授权方只读摘要/条目，原文不出个人域，不能写回。
- REJECTED 申请 30 天防刷（30 天内不可再申请同一对）。
- **删项目清链**（5x #5 修复）：项目删除时双向清 `memory_project_links`、清 `memory_project_user_grants`、清 `memory_entry_coverage`；即使 hook 漏，召回侧 link 查询带 `projects.deleted=0` EXISTS 子查询兜底，不返回悬空链。

## 7. gen 矩阵（生成开关 · 项目×owner/会员双开关）

**你能做什么**：控制项目对话是否调 LLM 生成 L0/L1/L2。owner 管项目级总闸，会员管本人覆写。任一关 → 仅写 raw 不生成。

**操作步骤**：
1. 打开记忆抽屉 → **gen 矩阵** 页签 [MemoryGenMatrixPanel.vue](../../../frontend/src/components/memory/MemoryGenMatrixPanel.vue)。
2. 顶部说明条（5x #6 文案澄清）：「项目记忆生成开关：owner 项目级 与 本人会员覆写 皆开才生成 L0/L1/L2（任一关仅写 raw 流水账）。关掉 = 该项目不再为你提炼总结，原 raw 仍保留，**但 raw 不会自动总结**（自动总结只处理已生成的 turn）—— 想要总结请开启生成，或在「总结」面板点「立即总结」手动压。」
3. 每个项目卡片：owner 开关（仅 OWNER 可改）/ 我的覆写开关（本人可改）/ 生效状态 tag。
4. 「一键关」：把所有本人会员覆写置 false（不碰 owner 开关）。

**预期结果**：
- effective = owner AND member。两层都开 → 生成 L0/L1/L2 + 进入候选总结。
- 任一关 → 不调生成 LLM，仍跑前置过滤，过过滤侧写 raw（`gen_done=false`，tag/L1/L2 空）。
- 自动总结 worker 只取 `gen_done=true` 的 turn，**raw 不进自动总结候选**。

**注意事项 / 边界**：
- owner 关 → 会员覆写无效（项目侧总闸关，会员开了也不生成）。
- 会员关 + owner 开 → 仍写 raw 不生成（会员自控）。
- 非项目会话读全局兜底 `rag.memory.gen.personal.enabled`。
- 三层（L0/L1/L2）同开同关。
- **raw 不会自动总结**：若你关了 gen 又想要总结，要么重新开 gen（等下次对话生成后再自动总结），要么立即手动走「总结」面板的「立即总结」（手动总结会 backfill raw 补 tag 后压缩）。

## 8. 文件记忆（上传 → 异步解析 → READY → 召回合流）

**你能做什么**：聊天附件自动解析为文件记忆（一文件一记忆）；解析 READY 后，相关问题时召回命中，AI 回答附带文件卡片。可下载原文件、重试失败、删除。

**操作步骤**：
1. 聊天输入框点 📎 上传附件（PDF / PPT / DOC / 图片 / 音频 / 视频）。
2. 附件 chip 显「解析中」(PROCESSING) → 系统异步 ingestion → chip 自动轮询状态（[ChatInput.vue](../../../frontend/src/components/chat/ChatInput.vue) 每 5s 刷新一次）。
3. 解析完成 → chip 显「就绪：召回可命中」(READY)。
4. 查看文件记忆：打开记忆抽屉 → **文件记忆** 页签 [MemoryAssetMemorySection.vue](../../../frontend/src/components/memory/MemoryAssetMemorySection.vue) → 列表显状态徽标 / 弱记忆标 / 一句话总结。
5. 下载原文件 / FAILED 重试 / 删除（删除后原文件与项目引用条目一并失效）。

**预期结果**：
- READY 文件的标签进入召回②标签聚合候选（5x #3 修复：修前聚合 SQL `findPersonalRecallTags` 只 UNION turns+summaries 漏 `memory_asset_memories`，文件标签恒不进候选、`collectFileCards` 恒空；修后补 asset_memories 一路，文件标签进候选）。
- 召回命中后，AI 回答附带 🗂 文件卡片（文件名 + 类型图标 + 可点下载）。
- FAILED 文件显错误原因 + 可重试（上限硬卡 retry_count）。

**注意事项 / 边界**：
- **「上传即问」场景**：文件未 READY（PROCESSING）时提问，召回不命中该文件（不注入半成品，保质量）。chip 变 READY 后会显式提示「已就绪，召回可命中」，此时再问即可命中。
- 弱记忆标：某些文件类型（如图片）只生成弱记忆标，召回权重低。
- 文件记忆按用户隔离（per-user），仅本人召回命中。
- 删除文件记忆 → 原文件 blob 删 + 项目中引用该文件的 FILE 条目同步失效。

## 9. 冲突裁决（时序矛盾四选项）

**你能做什么**：当你总结时 LLM 判定存在时序互斥冲突（如「住萧山」vs「住拱墅」），裁决选一种处理方式。

**操作步骤**：
1. 打开记忆抽屉 → **冲突裁决** 页签 [MemoryConflictSection.vue](../../../frontend/src/components/memory/MemoryConflictSection.vue)。
2. PENDING 行点开 → 弹框 [MemoryConflictJudgeDialog.vue](../../../frontend/src/components/memory/MemoryConflictJudgeDialog.vue)。
3. 四选一：**都留** / **新的** / **旧的** / **丢弃**（丢弃二次确认）。

**预期结果**：
- **都留 (KEEP_BOTH)**：两条按 created_at 自动排序都留，无需填日期。
- **新的 (KEEP_NEW) / 旧的 (KEEP_OLD)**：留指定一条，另一条软删（turns 保留）。
- **丢弃 (DISCARD)**：连带软删冲突总结**及其全部 source_turn_ids 流水账**（防死循环：软删后下次总结取数自然排除，worker 不再生成同冲突）。

**注意事项 / 边界**：
- 仅作者本人可裁决自己的冲突（别人改不了你的记忆）。
- 项目内不产生跨用户编辑冲突（别人只读你的，想补充→新建自己一条）。
- DISCARD 时若 source turns 被他人引用且引用方总结 >12h → 拒 403，提示改「都留/旧的」。
- 日期铁律：日期取 turn.`created_at`，禁 LLM 编年份（后端 `assertYearIronRule` 校验）。

## 10. 收录规则配置（owner/admin）

**你能做什么**：配置项目收录规则——主题/锚词（anchor）语义规则 + **文件名硬规则**（filename_patterns，子串命中即收录）；anchor 同步算、embed 失败强制停用、负例管理。

**操作步骤**：
1. 打开记忆抽屉 → **收录规则** 页签 [MemoryRulePanel.vue](../../../frontend/src/components/memory/MemoryRulePanel.vue)（仅 owner/admin 可改）。
2. 配 anchor 语义规则 / embed 失败停用开关 / 查看负例（弃条目时自动追加，最多 5 条）。
3. 配**文件名硬规则**：填 pattern 列表（如 `周报`、`.sql`）——上传附件文件名含该串即命中收录，同时触发聊天里的**收录确认式回复**（见第 13 节）。

**预期结果**：规则立即生效，影响下一轮对话的粗筛分流；硬规则命中文件走确定性收录，不依赖 LLM 精判。

**注意事项**：
- **文件名硬规则同一用户全局唯一**（第三轮 5x #8）：你 A 项目已配 pattern「周报」，B 项目再配「周报」或「 周报 」/「WEEKLY REPORT」同义归一后撞重 → 保存被拒（409），提示「已被项目『A』收录，需先在 A 项目删除后再添加」。跨用户不限制（别人配「周报」不拦你）。
- 路由并发多项目同时命中同一文件 → **先建规则的项目收录**，其余项目跳过（建规则趁早）。
- 负例仅 owner 可见；普通成员看不到此页签的编辑态。

## 11. 审计（聊天发消息记审计）

**你能做什么**：无需操作。每次聊天发消息（REST 或 SSE 流式）都写审计日志，含 userId / username / 时间。

**预期结果**（5x #7 修复）：
- 修前：SSE 流式发消息走裸 `new Thread()`，MDC 不跨线程继承 → 审计行 userId/username 全 null（REST 路径正常）。
- 修后：裸线程入口快照 + setContextMap 透传 MDC + `auditSendMessage` 显式盖戳兜底，**流式和 REST 都落值**。

**注意事项**：管理员可在审计后台按用户名/时间筛查发消息行为；普通用户无感知。

## 12. 通知（跨用户波及）

**你能做什么**：当别人撤回记忆波及你的总结、你参与的授权链状态变化、你被授权/被撤销时，收到通知。

**操作步骤**：
1. 聊天页右上角 badge [MemoryNotificationBadge.vue](../../../frontend/src/components/memory/MemoryNotificationBadge.vue) 显示未读计数。
2. 点开下拉列表查看详情 →「全部已读」。

**预期结果**：
- 通知类型：SUMMARY_AFFECTED_BY_RECALL（他人撤回波及你的总结）、LINK_REQUEST / LINK_RESULT（授权链发起/审批结果）、个人授权 grant 通过/撤销等。
- worker 重生完成的 STALE 总结通知自动标已处理。

**注意事项**：通知仅跨用户场景才发（你自己撤回自己的不通知）。

## 13. 收录确认式回复（命中硬规则先问再答，第三轮 5x #7）

**你能做什么**：无需操作。发消息带附件时，若附件文件名命中你某个「gen 开」项目的收录硬规则，AI **不再直接长篇回答**，而是先秒回一条确认消息：「你输入的『xx』已被项目『YY』收录，需要我回答吗？」——你点选后才决定是否全量回答。

**操作步骤**：
1. 正常发消息并带附件（文件名命中你项目的硬规则 pattern，如「周报-0816.docx」命中 pattern「周报」）。
2. AI 秒回模板确认消息（不调 LLM、不写记忆），气泡下方两个按钮：**「✅ 需要回答」** / **「🚫 不用了」**。
3. 点「需要回答」→ AI 基于你**原本的输入**流式全量回答（原文由服务端存档回读，不重传、不可篡改）；该轮照常异步收录进项目（幂等去重，不重复收录）。
4. 点「不用了」→ 落一条收尾消息，流程结束，不调 LLM。
5. 点选后按钮变为已选状态（灰色标），不可重复点。

**预期结果**：
- 命中瞬间回模板（确定性匹配，零 LLM 延迟）；多项目同时命中 → 确认文案列出全部命中项目，全量回答时收录按**先建规则**的项目（见第 10 节）。
- 确认消息和「不用了」收尾消息**不进你的记忆**（不污染流水账/三层）。

**注意事项 / 边界**：
- 只对**附件文件名**做确定性快检；纯文本消息不走确认（语义路由维持异步收录，不拖首字延迟）。
- 规则缓存 15 秒：刚增删硬规则后最坏滞后 15s 才反映到确认判定（仅确认文案滞后，实际收录以异步路由为准）。
- 快检异常自动放行走原全量路径（fail-open），不阻塞聊天。
- 管理员可热关：系统设置 `rag.memory.inclusion-confirm.enabled` 关 = 回旧行为（直接全量回答），无需发版。
- 人工测试走 [收录命中确认式回复测试方案](../测试方案/收录命中确认式回复测试方案.md)（5 联动 + 5 边界）。

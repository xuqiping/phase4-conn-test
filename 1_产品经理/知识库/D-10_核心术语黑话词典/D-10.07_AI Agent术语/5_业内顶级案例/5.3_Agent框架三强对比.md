# 案例：Agent框架三强对比——LangGraph/CrewAI/AutoGen

## 术语映射

| 术语 | 在本案例中的体现 |
|---|---|
| ReAct | LangGraph内置ReAct Agent模板 |
| Plan-and-Execute | LangGraph原生支持P&E模式 |
| Multi-Agent | CrewAI主打Multi-Agent；AutoGen也支持 |
| Orchestration | LangGraph的图编排≈显式Orchestration；CrewAI的流程≈隐式Orchestration |
| Agent DAG | LangGraph的StateGraph本质上就是Agent DAG |
| Memory | 三者都支持短期+长期记忆，但实现方式不同 |

## 框架对比 [来源:公开信息 | 📚中 | 2026]

| 维度 | LangGraph | CrewAI | AutoGen |
|---|---|---|---|
| 开发者 | LangChain团队 | CrewAI (独立) | Microsoft |
| 核心范式 | 图编排(灵活) | 角色协作(直觉) | 对话驱动(自然) |
| 适合场景 | 复杂工作流+精确控制 | 多角色团队协作 | 多Agent对话/研究 |
| 学习曲线 | 较陡(需理解图概念) | 较平(角色定义直觉) | 中等 |
| 适合PM程度 | ★★ | ★★★ | ★★ |
| 架构范式 | ReAct/P&E/Multi-Agent全支持 | 主打Multi-Agent | 主打Multi-Agent对话 |
| 生产就绪度 | 高 | 中高 | 中 |

## 产品决策启示

1. **选框架看场景而非热度**：需要精确控制→LangGraph；需要快速原型→CrewAI；需要对话协作→AutoGen
2. **PM能读懂CrewAI**：CrewAI的"定义角色→分配任务"模式最接近PM的思维
3. **框架会变，概念不变**：ReAct/P&E/Multi-Agent这些范式概念比任何框架都持久

## AI原型工具深度解析

### Vibe Prototyping范式

传统原型流程：需求文档 → 画线框 → 画高保真 → 连交互 → 测试

Vibe Prototyping流程：自然语言描述 → AI生成初始原型 → 人类精调 → 测试

| 维度 | 传统流程 | Vibe Prototyping |
|---|---|---|
| 从想法到原型 | 2-4周 | 30分钟-2小时 |
| 内容来源 | PM手动绘制 | AI基于大量设计数据生成 |
| 初始质量 | 取决于PM画图能力 | 取决于Prompt质量+模型能力 |
| 迭代方式 | 手动修改每个页面 | 自然语言描述修改→AI重生成 |
| 一致性 | 依赖设计系统 | AI自动遵循设计模式 |
| 局限 | 周期长但精确 | 快但需精调，复杂逻辑仍需手动 |

[来源:腾讯云开发者社区2026实测 | 置信度:📚中]

## 跨端原型策略

### 响应式原型 vs 多端独立原型

| 策略 | 实现 | 优势 | 局限 |
|---|---|---|---|
| 响应式 | 一套设计+断点适配 | 维护成本低 | 端特定交互无法体现 |
| 多端独立 | 每端独立原型 | 交互体验最优化 | 维护成本3x |
| 组件共享 | 共享原子+分子、独立有机体 | 平衡效率与体验 | 组件颗粒度需把控 |

### Figma跨端原型最佳实践

| 技巧 | 实现 | 效果 |
|---|---|---|
| Auto Layout | 弹性布局+约束 | 组件自适应宽度 |
| 组件变体 | Mobile/Tablet/Desktop变体 | 一处设计三端呈现 |
| 变量模式 | Values by Mode: Mobile/Desktop | 间距/字号按端切换 |
| Dev Mode | 按平台生成代码片段 | 开发直接取用 |

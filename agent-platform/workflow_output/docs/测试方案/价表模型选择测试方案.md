# 价表模型选择 · 人工测试方案

> Phase 3 功能级预处理产物。关联 FR-F20-01 与[实现计划](../plans/价表模型选择.plan.md)。自动化覆盖候选差集和防绕过；本文件覆盖真实管理页面交互。

## 1. 人工测试原因

- [x] 涉及可搜索下拉、空态、错误态和编辑锁定的 UI 交互。
- [x] 供应商启停与价表刷新需要真实前后端联动确认。

## 2. 前置条件

- 启动 backend/frontend，并准备拥有 `pricing:manage` 的管理员账号。
- 全局供应商各准备 CHAT、EMBEDDING、IMAGE、VIDEO 至少一个 ACTIVE 模型；另准备一个停用供应商和一条已配置价表。

## 3. 正常路径与联动用例

| 编号 | 场景与操作 | 预期结果 | 通过? |
|---|---|---|---|
| BP-01 | 打开新增价表并搜索供应商或模型 | 仅显示 ACTIVE 且未配置候选，标签为“供应商 · 模型” | ⬜ |
| BP-02 | 依次选择四类候选 | kind 自动映射为 CHAT/EMBED/IMAGE/VIDEO，不产生半选择 | ⬜ |
| BP-03 | 创建一条候选价表 | 新行出现；同一候选从下拉消失 | ⬜ |
| BP-04 | 打开现有价表编辑 | provider/model/kind 清晰显示并锁定；价格与生效参数可改 | ⬜ |
| BP-05 | 停用供应商后再次打开新增 | 候选消失；历史价表仍保留且可用于历史查询 | ⬜ |

## 4. 边界、安全与无障碍

| 编号 | 场景 | 预期 | 通过? |
|---|---|---|---|
| BE-01 | 所有候选均已配置 | 显示“所有全局模型均已配置价表”，不能手填身份 | ⬜ |
| BE-02 | 候选加载失败 | 显示错误且可重试，不误清现有价表 | ⬜ |
| BE-03 | 两个会话同时创建同一候选 | 仅一个成功，另一个得到固定冲突提示 | ⬜ |
| BE-04 | 直接调用 API 伪造 provider/model/kind 或编辑身份 | 服务端拒绝，不依赖前端禁用 | ⬜ |
| BE-05 | 键盘搜索、选择、清空、关闭弹窗 | 全流程可操作；锁定说明不只靠灰色表达 | ⬜ |

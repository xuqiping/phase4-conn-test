# 企业级精准知识库 RAG 开发进度 2

## 本轮目标

完成 P0 Step 3：统一 RAG Trace、MDC、同步/异步/SSE 上下文，并关联检索、重排、模型调用和计费日志。

## 已完成

- 新增请求级 `RagTraceContext` 与 `RagTraceService` 生命周期，形成 `traceId → retrievalRunId → rankingRunId → modelRequestId` 关联链。
- 单知识库与多知识库检索均创建 retrieval run，并记录成功、拒答和失败终态。
- Ranking 配置模式与实际模式分开记录。P0 当前实际执行 `HEURISTIC_PROXY`，明确记录降级原因，不伪装成 LLM/Rerank 调用。
- 同步 chat/embed 在异常时写入模型调用失败终态；流式调用在 usage、完成、错误和取消回调中短暂恢复 Trace。
- 流式模型调用创建后立即 detach，避免 Reactor 线程长期持有 ThreadLocal/MDC。
- Query Rewrite + HyDE 使用独立用途 `QUERY_REWRITE_AND_HYDE`；Embedding 和答案生成继续使用各自用途。
- Query、Prompt、输出和候选内容只保存 Hash/数量摘要，不进入 MDC 或业务日志。
- 控制台日志增加 retrieval/ranking/model/purpose 关联字段；JSON 文件日志继续携带完整 MDC。

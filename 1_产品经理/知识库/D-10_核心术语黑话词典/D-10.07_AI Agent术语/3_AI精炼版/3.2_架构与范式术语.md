## 1. ReAct / 推理+行动

| 字段 | 内容 |
|---|---|
| 英文全称 | ReAct (Reasoning + Acting) |
| 定义 | Agent在每一步交替进行推理(Thought)和行动(Action)的架构范式——边想边做，每步都观察结果再决定下一步 |
| PM解读 | ReAct是最基础也最常用的Agent范式。核心逻辑："想一步→做一步→看结果→想下一步"。适合探索性强、不确定任务 |
| 对比CoT | CoT只"想"不"做"，ReAct"边想边做"。ReAct更实用但Token消耗更多 |
| 来源 | Yao et al., 2022 [📚训练知识] |

## 2. Plan-and-Execute / 先规划后执行

| 字段 | 内容 |
|---|---|
| 英文全称 | Plan-and-Execute |
| 定义 | 先让Agent生成完整计划(Plan)，再逐步执行(Execute)的架构范式——先想清楚再做，而非边想边做 |
| PM解读 | Plan-and-Execute适合步骤确定、逻辑链长的任务（如复杂工作流）。缺点是计划可能基于不完整信息，需要重规划机制 |
| 对比ReAct | ReAct=边想边做（探索式），Plan-and-Execute=先想再做（规划式）。复杂确定性任务适合P&E，开放探索任务适合ReAct |
| 来源 | [📚训练知识] |

## 3. 反思 / Reflection

| 字段 | 内容 |
|---|---|
| 英文全称 | Reflection |
| 定义 | Agent在执行任务后回顾自己的输出，发现错误并自我修正的机制 |
| PM解读 | Reflection是Agent的"自我纠错"能力——不是做了就完，而是做完检查一遍。这大幅降低了Agent的出错率，但也增加了Token消耗 |
| 来源 | Shinn et al., 2023 (Reflexion) [📚训练知识] |

## 4. 多智能体 / Multi-Agent

| 字段 | 内容 |
|---|---|
| 英文全称 | Multi-Agent |
| 定义 | 多个Agent协作完成复杂任务的架构，每个Agent承担不同角色/功能，通过协议或编排系统协调 |
| PM解读 | Multi-Agent不是"更多Agent更厉害"，而是"专业分工+协作协议"。设计难点不在单个Agent，而在Agent间的协调与通信 |

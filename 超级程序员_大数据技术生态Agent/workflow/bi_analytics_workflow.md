# BI Visualization & Data Analytics Workflow

## Purpose

基于BI可视化与数据分析知识体系，为用户提供BI平台架构选型（湖仓一体+AI原生+Headless BI三引擎）、数据分析方法论（Gartner四层次/AARRR/漏斗/RFM/A/B测试）、自助式报表演进（IT开发→拖拽BI→AI对话→Agentic BI）、NLQ/ChatBI架构（LLM+语义层+RAG）、国产BI选型（帆软/Quick BI/Smartbi）及AI原生BI（Agentic BI/语义层MCP协议）的技术方案支持。覆盖数据治理是BI前置条件、40%分析查询由自然语言生成、语义层独立化解决同名不同义等核心洞察。

## Prerequisites

- 用户已明确BI可视化或数据分析场景或问题
- 知识库文件 `06_大数据处理与BI.md` 及子目录文件可访问

## Steps

### Step 1: 识别BI/数据分析需求场景

**Goal**: 明确用户的BI/数据分析需求类型、用户群体和数据基础
**Completion criterion**: 已确定场景标签、用户群体、数据基础和治理成熟度

1. 读取用户消息，提取以下信息：
   - 场景类型：BI平台选型 / 报表设计开发 / 数据分析方法论 / 自助式分析 / AI原生BI / A/B测试设计 / 数据可视化 / 国产BI选型
   - 用户群体：业务人员（非技术） / 数据分析师（SQL能力） / 管理层（Dashboard消费者） / 开发者（API/嵌入集成）
   - 数据基础：是否有统一数据仓库/数据湖（ODS/DWD/DWS/ADS分层） / 是否有数据治理（标准/血缘/质量） / 是否有语义层（指标口径统一）
   - 分析类型：描述性分析（发生了什么） / 诊断性分析（为什么发生） / 预测性分析（将会发生什么） / 规范性分析（应该怎么做）
   - 交互方式：静态报表（定时推送） / 交互式Dashboard（钻取/联动/筛选） / 自然语言查询（ChatBI） / Agentic BI（AI自主分析闭环）
   - 合规要求：信创（国产BI必选） / 数据安全（敏感数据脱敏/权限控制） / 移动端（App/小程序嵌入）
   - 现有工具：Excel / Tableau / PowerBI / FineBI / Quick BI / 自研ECharts / 无

2. 对照知识库中的核心洞察初步判断：
   - 数据治理不完善 → 必须先建治理再搞BI（80%失败根因）
   - 同名不同义问题严重 → 语义层独立化（dbt Semantic Layer/Cube.dev）
   - 业务人员不会SQL → ChatBI/NLQ（LLM+语义层+RAG，40%查询由自然语言生成）
   - 信创合规 → 帆软/Smartbi/Quick BI（政府金融市场占主导）
   - AI深度集成需求 → Agentic BI（AI自主分析：问题→查询→可视化→洞察→行动建议）

3. 如有信息缺失，向用户追问不超过2个澄清问题。

### Step 2: 输出BI/数据分析方案

**Goal**: 产出针对性的BI平台选型、数据分析方法论或AI原生BI方案
**Completion criterion**: 输出包含推荐BI平台、架构设计、分析方法论、实施路径

根据Step 1确定的场景，按以下分支处理：

**分支A — BI平台架构选型**：
1. 输出BI平台架构演进：
   - 传统三层架构：数据源（数据库/文件）→ ETL层（数据清洗转换）→ BI层（报表/Dashboard）。问题：数据搬运多、口径不统一、响应慢
   - 湖仓一体BI：数据湖（Iceberg/Delta/Paimon）→ 语义层（统一指标口径）→ BI引擎（直接查询湖仓数据）。优势：消除数据搬运、口径统一、实时性提升
   - AI原生BI：NLQ自然语言查询（LLM+语义层+RAG）+ Agentic BI（AI自主分析闭环）+ 智能推荐（自动发现异常/趋势/关联）。2026年40%分析查询由自然语言生成
   - Headless BI：语义层与可视化分离，语义层（dbt Semantic Layer/Cube.dev/MetricFlow）统一指标定义，前端（任何BI工具/自定义应用/API）消费统一指标。解决"一个指标N个报表N个口径"问题
2. 给出BI引擎选型对比：
   - Tableau（Salesforce）：可视化最强、拖拽体验好、生态丰富、适合分析师、价格较高、云端/本地部署
   - Power BI（Microsoft）：与Office/Excel/Azure生态深度集成、DAX计算强大、性价比高、适合微软生态企业
   - FineBI（帆软）：国产龙头、政府金融市场占有率高、中国式报表强（复杂表头/交叉表/套打）、信创适配好、本地化服务好
   - Quick BI（阿里云）：云原生、与阿里云数据产品（MaxCompute/DataWorks）深度集成、移动端好、适合阿里生态
   - Smartbi（思迈特）：国产、OLAP分析强（多维分析/钻取/切片）、Excel插件模式（业务人员用Excel连BI）、企业级权限管控
   - 开源/轻量：Metabase（简单查询+Dashboard+SQL原生）、Superset（Apache、可视化丰富、SQL Lab）、Grafana（时序数据/监控场景）、Redash（SQL查询+可视化+Dashboard）
   - 选型建议：金融/政府/信创→FineBI/Smartbi；阿里生态→Quick BI；分析师主导→Tableau/Power BI；创业公司/技术团队→Metabase/Superset；监控场景→Grafana
3. 输出语义层独立化方案：
   - 问题：同名不同义（"销售额"在不同报表中口径不同：含税/不含税/退款后/退款前）、同义不同名（"DAU"和"日活"和"每日活跃用户"）
   - 方案：语义层统一指标定义（dbt Semantic Layer、Cube.dev、MetricFlow/Transform、Headless BI架构）
   - 技术实现：指标YAML定义（名称/描述/计算公式/维度/数据源/刷新策略）→ 语义层服务（指标计算引擎）→ BI前端/API/ChatBI统一消费
   - MCP协议集成：语义层通过MCP协议成为AI Agent的数据消费标准接口（AI Agent调用语义层API获取指标定义和数据）
4. 附部署架构模板：
   - 湖仓一体BI：对象存储（S3/OSS）→ Iceberg数据湖 → Trino/StarRocks查询引擎 → 语义层（Cube.dev）→ BI前端（FineBI/Metabase/自定义）
   - 实时BI：Kafka → Flink实时计算 → Paimon实时表 → StarRocks外表 → BI秒级刷新（Flink实时入湖+StarRocks物化视图）
   - AI原生BI：用户问题 → LLM理解意图 → 语义层路由（指标匹配/维度匹配/时间范围解析）→ SQL生成（Text-to-SQL，准确率85%+）→ 数据查询 → 可视化生成（图表类型推荐）→ 洞察总结（自然语言解读）

**分支B — 数据分析方法论**：
1. 输出Gartner四层次分析模型：
   - 描述性分析（Descriptive）：发生了什么？（报表/Dashboard/数据可视化）。工具：BI报表、Excel透视表、SQL聚合查询。典型场景：日/周/月报、KPI监控、运营Dashboard
   - 诊断性分析（Diagnostic）：为什么发生？（根因分析/关联分析/下钻分析）。工具：OLAP多维分析（钻取/切片/旋转）、漏斗分析、留存分析、路径分析。典型场景：GMV下降原因分析、用户流失原因定位、异常订单排查
   - 预测性分析（Predictive）：将会发生什么？（趋势预测/分类预测/推荐）。工具：时间序列预测（ARIMA/Prophet/LSTM）、分类模型（逻辑回归/XGBoost/LightGBM）、推荐算法（协同过滤/矩阵分解/深度学习）。典型场景：销量预测、用户流失预警、信用评分、个性化推荐
   - 规范性分析（Prescriptive）：应该怎么做？（优化决策/模拟仿真/自动化行动）。工具：线性规划/整数规划、强化学习、A/B测试+因果推断。典型场景：库存优化（补多少/何时补/从哪补）、定价策略优化、营销预算分配、自动化运营（定价自动调整/库存自动补货）
2. 给出用户行为分析三件套：
   - AARRR模型（海盗指标）：Acquisition（获取：渠道/来源/成本）→ Activation（激活：首次使用/核心功能使用）→ Retention（留存：次日/7日/30日留存）→ Revenue（收入：ARPU/付费率/LTV）→ Referral（推荐：NPS/分享率/病毒系数K）
   - 漏斗分析：注册漏斗（访问→注册→完善信息→使用核心功能→付费）、电商漏斗（浏览→加购→下单→支付→复购）、每个步骤转化率+流失原因分析
   - RFM模型：Recency（最近消费时间）、Frequency（消费频率）、Monetary（消费金额），用户分群（重要价值客户/重要保持客户/重要发展客户/重要挽留客户/一般客户/低价值客户），附差异化运营策略
3. 输出A/B测试设计框架：
   - 实验设计：假设设定（H0/H1）、样本量计算（统计功效1-β=0.8、显著性水平α=0.05、最小可检测效应MDE）、随机化方法（简单随机/分层随机/桶化）、实验周期（考虑周效应/月效应/节假日）
   - 指标选择：北极星指标（1个核心指标，如转化率）+ 护栏指标（多个不可恶化指标，如加载速度/错误率/用户满意度）+ 辅助指标（多个观察指标，如停留时长/页面浏览数）
   - 结果分析：t检验（均值对比）、卡方检验（率指标对比）、Bootstrap置信区间、多重比较校正（Bonferroni/FDR）、分段分析（新老用户/设备类型/地域）
   - 陷阱规避：网络效应（社交网络中用户互相影响）、新奇效应（新功能短期兴奋）、幸存者偏差（只分析留存用户）、选择偏误（非随机分组）、样本污染（用户跨组切换）
   - 工具选型：自建（Airflow调度+统计检验Python/R）/ 商业化（Optimizely/VWO/神策/GrowingIO）/ 云厂商（阿里云ABTest/腾讯MTA）
4. 附数据可视化最佳实践：
   - 图表选型：比较（柱状图/条形图/雷达图）/ 趋势（折线图/面积图）/ 占比（饼图/环形图/堆叠柱状图）/ 分布（直方图/箱线图/小提琴图）/ 关系（散点图/气泡图/热力图）/ 地理（地图/热力地图）
   - Dashboard设计原则：目标明确（一个Dashboard一个主题）、信息层级（重要指标大+显眼→细节小+可下钻）、色彩规范（品牌色+语义色：绿色=好/红色=差/黄色=警告）、移动端适配（关键指标一屏可见）
   - 常见反模式：饼图过多（角度难比较）、3D图表（误导性强）、双Y轴（尺度欺骗）、颜色过多（视觉混乱）、缺少上下文（无同比/环比/目标值对比）

**分支C — 自助式分析与ChatBI**：
1. 输出自助式报表演进四代：
   - Gen 1 IT开发（2000-2010）：需求提交→IT排期→开发报表→验收交付。周期：数周/数月。痛点：响应慢、积压多、业务等不及
   - Gen 2 拖拽BI（2010-2020）：Tableau/PowerBI/帆软拖拽式操作。业务人员自助制作简单报表。痛点：复杂计算仍需IT支持、SQL门槛限制深度分析
   - Gen 3 AI对话（2020-2025）：ChatBI自然语言查询（"本月各渠道GMV同比如何？"→ LLM生成SQL→执行→可视化）。准确率70-85%。痛点：复杂多表Join/多步推理准确率下降、语义歧义
   - Gen 4 Agentic BI（2025+）：AI Agent自主分析闭环。用户提问→AI分解问题→自主查询多数据源→自动选择可视化→生成洞察解读→推荐下一步行动→自动创建监控告警。2026年趋势方向
2. 给出NLQ/ChatBI技术架构：
   - NLQ三件套（2026标配）：LLM（意图理解+SQL生成，GPT-4/Claude/Qwen/Llama）+ 语义层（指标/维度/表关系定义，dbt Semantic Layer/Cube.dev）+ RAG（历史查询/业务知识/数据样例，向量库检索相似查询作为Few-shot示例）
   - 准确率提升策略：语义层统一口径（消除歧义）、RAG检索历史成功查询（Few-shot Prompting）、Query改写（LLM理解用户真实意图→标准化查询）、查询结果校验（执行计划分析/结果合理性检查/异常值告警）
   - 多轮对话：上下文保持（对话历史+已查询结果+用户反馈）、意图切换检测（用户从"GMV"切换到"订单量"时自动重置上下文）、追问理解（"上个月的呢"→理解时间维度变化）
   - 安全与权限：查询权限控制（用户只能查有权限的数据表/字段）、敏感数据脱敏（手机号/身份证/金额自动 masking）、SQL注入防护（参数化查询/白名单校验/执行环境隔离）
3. 输出Agentic BI架构设计：
   - 感知层：用户问题接收（自然语言/语音/截图OCR）、意图识别（查询/分析/预测/预警/报告）、用户画像（历史查询偏好/权限/专业水平）
   - 推理层：问题分解（将复杂问题拆分为可执行的子查询）、数据路由（选择正确的数据源和表）、SQL生成（Text-to-SQL，多轮修正）、结果分析（异常检测/趋势识别/关联发现）、洞察生成（自然语言解读+可视化推荐+行动建议）
   - 行动层：自动创建Dashboard（将分析结果保存为可复用Dashboard）、自动设置监控告警（当指标异常时自动通知）、自动生成报告（定时生成+推送）、自动创建数据故事（数据+叙事+可视化组合）
   - 反馈循环：用户反馈（👍/👎、修改建议、追问）→ 模型改进（强化学习微调）→ 知识沉淀（成功案例入库RAG）
4. 附准确率度量：Text-to-SQL准确率（执行成功率/结果正确率/语义匹配率）、用户满意度（NPS）、查询响应时间（P99<3秒）、问题覆盖率（Top 100问题全部覆盖）。

**分支D — 数据可视化与报表开发**：
1. 输出报表开发规范：
   - 需求分析：报表目标（给谁看/解决什么问题/什么频率使用）、数据来源（哪些表/哪些字段/更新频率）、指标定义（每个指标的业务含义/计算公式/维度/时间范围）
   - 原型设计：低保真原型（线框图/Excel草图）、信息架构（指标层级/下钻路径/联动关系）、交互设计（筛选器/钻取/排序/导出/分享）
   - 开发实施：SQL开发（查询优化/索引使用/避免全表扫描）、BI配置（图表选型/颜色/布局/条件格式）、性能测试（加载时间/数据量/并发用户）、权限配置（行级权限/字段级权限/菜单权限）
   - 验收上线：数据准确性校验（与源系统对比/抽样验证/交叉验证）、业务验收（业务Owner确认口径正确）、性能验收（响应时间达标）、培训推广（用户手册/视频教程/FAQ）
2. 给出中国式报表专项：
   - 复杂表头：多行表头/斜线表头/合并单元格/分组小计/合计行
   - 交叉报表：行维度×列维度（如地区×时间→销售额矩阵）、动态行列（根据数据自动生成行列）
   - 套打报表：发票/单据/证书精确打印（位置精确到毫米）、分页控制（每页固定行数/尾页补空行）、连续打印（批量打印不浪费纸张）
   - 国产BI优势：帆软/FineReport在中国式报表领域领先，支持Excel导入导出、公式计算、复杂条件格式
3. 输出移动端报表：
   - 设计原则：一屏一主题（移动端屏幕小，每个页面聚焦1-2个核心指标）、触摸友好（按钮/筛选器/图表可触摸操作）、离线可用（关键数据缓存到本地）
   - 技术实现：BI原生移动端（FineBI/Quick BI App）、H5自适应（Metabase/Superset响应式）、微信小程序嵌入（iframe/JS SDK）、PWA（离线缓存+推送通知）
   - 场景：CEO移动端看数（每日关键指标推送）、销售外勤看业绩（实时订单/提成/排名）、门店店长看运营（客流量/转化率/库存/销售额）
4. 附报表治理：报表生命周期管理（创建→上线→使用监控→下线评估→归档/删除）、报表目录分类（按业务域/部门/用途/更新频率）、重复报表合并（发现5个报表都在查"销售额"→合并为1个标准报表）、报表质量评估（数据准确性/使用频率/用户满意度/维护成本）。

将结果保存到 `output/bi_analytics.md` 或直接在对话中呈现。

# Screenshot 模块总结

## 1. 模块职责一句话

Screenshot 模块负责为 File Keeper 桌面应用提供**区域截图**能力：通过全局快捷键唤起一个全屏透明遮罩窗口，让用户拖拽选择屏幕区域，随后调用 Rust 后端捕获该区域并保存为剪贴板历史中的图片项，同时触发可选的 OCR 文字识别。

---

## 3. 核心数据流 / 调用链路

```
用户按下截图全局快捷键
    ↓
App.vue: handleScreenshotShortcut()
    ↓
api/screenshotOverlay.ts: openScreenshotOverlayWindow()
    ↓ 创建新 WebviewWindow（label='screenshot-overlay'，URL='/?screenshotOverlay=1'）
    ↓
main.ts 检测到 ?screenshotOverlay=1，渲染 ScreenshotOverlayHost.vue
    ↓
ScreenshotOverlayHost.vue → ScreenshotOverlay.vue（全屏遮罩）
    ↓
用户在屏幕上拖拽选择区域
    ↓
ScreenshotOverlay.vue 计算 screen 坐标选区，emit 'capture' 事件
    ↓
ScreenshotOverlayHost.vue 捕获 'capture'，emit Tauri 事件 'screenshot://capture'
    ↓ 同时销毁遮罩窗口
    ↓
App.vue 监听 'screenshot://capture' → handleScreenshotCapture(region)
    ↓
api/screenshot.ts: captureScreenshotRegion(region)
    ↓ 调用 Tauri command 'capture_screenshot_region'
    ↓
commands/screenshot.rs: capture_screenshot_region()
    ↓ 1. 校验区域（尺寸、坐标范围）
    ↓ 2. 转换为物理像素（乘以 scale_factor）
    ↓ 3. 调用 platform/windows/screenshot.rs: capture_screen_region()
    ↓ 4. Win32 GDI 捕获屏幕位图 → PNG 字节
    ↓ 5. ClipboardService.collect_screenshot_bytes_snapshot_with_ocr_update()
    ↓ 6. 保存到剪贴板历史数据库，返回 item_id
    ↓ 7. emit 'clipboard://changed' 通知前端刷新
    ↓
App.vue 收到结果 → 自动切换到 Clipboard 标签页并加载新项详情
    ↓
（可选）OCR 完成后再次 emit 'clipboard://changed' 更新 OCR 文本
```

**取消链路**：用户按 Escape 或拖拽区域过小 → `cancel` 事件 → `screenshot://cancel` → `handleScreenshotCancel()` → 关闭遮罩窗口。

## 4. 关键组件说明

### 4.1 主窗口触发（App.vue）

- 在 `onMounted` 中注册截图全局快捷键（`settings.screenshotShortcut`），绑定到 `handleScreenshotShortcut()`。
- 使用 `isScreenshotOverlayOpen` 标志防止重复触发。
- 通过 `listen('screenshot://capture', ...)` 和 `listen('screenshot://cancel', ...)` 接收遮罩窗口的事件。
- 截图成功后：自动切换到 `clipboard` 标签页、清空筛选条件、加载剪贴板列表并打开新截图项的详情。
- 权限检查：截图功能绑定到 `clipboard` 模块的商业授权，未授权时拒绝执行。

### 4.2 覆盖层窗口（ScreenshotOverlay.vue）

- 全屏固定定位（`fixed inset-0`），半透明黑色背景（`bg-black/30`），十字光标（`cursor-crosshair`）。
- 监听 `mousedown` / `mousemove` / `mouseup` 实现拖拽选区。
- 同时维护两套坐标：
  - `clientX/clientY`：用于页面内选区框的实时渲染（CSS 定位）。
  - `screenX/screenY`：用于最终截图的实际屏幕坐标（传递给后端）。
- 选区框使用 `shadow-[0_0_0_9999px_rgba(0,0,0,0.35)]` 实现“暗角”遮罩效果，仅选区区域高亮。
- 最小选区尺寸为 8px，小于该值则触发 `cancel`。
- 支持 `Escape` 键取消。

### 4.3 Host 组件（ScreenshotOverlayHost.vue）

- 作为遮罩窗口的根组件，职责单一：将 `ScreenshotOverlay` 的 `capture` / `cancel` 事件通过 Tauri 的 `emit()` 转发给主窗口，然后立即 `destroy()` 自身窗口。
- 不处理任何业务逻辑，是连接遮罩层和主窗口的桥梁。

### 4.4 入口区分（main.ts）

```ts
const isScreenshotOverlayWindow = new URLSearchParams(window.location.search).has('screenshotOverlay')
const app = createApp(isScreenshotOverlayWindow ? ScreenshotOverlayHost : App)
```

同一套前端代码通过 URL 参数区分主窗口和遮罩窗口的渲染内容。

## 5. 核心功能

### 5.1 区域截图

- **前端**：用户在全屏遮罩上拖拽，前端计算 `screenX/Y` 坐标和 `devicePixelRatio` 构成 `ScreenshotRegion`。
- **后端**：`commands/screenshot.rs` 对区域进行多层校验：
  - 拒绝负宽高（`尺寸无效`）
  - 拒绝小于 8px 的区域（`区域太小`）
  - 坐标乘以 `scale_factor` 转换为物理像素
  - 检查坐标是否溢出 `i32` 范围（`坐标超出有效范围`）
- **平台层**：`platform/windows/screenshot.rs` 使用 Win32 GDI API：
  - `GetDC` 获取屏幕设备上下文
  - `CreateCompatibleDC` + `CreateCompatibleBitmap` 创建内存位图
  - `BitBlt` 从屏幕拷贝像素到内存位图
  - `GetDIBits` 读取像素数据（BGRA → RGBA 转换）
  - `image` crate 编码为 PNG 字节流
- 非 Windows 平台返回 `"当前平台尚未实现截图"`。

### 5.2 截图 OCR 状态

- `getScreenshotOcrStatus()` 查询当前 OCR 提供商状态。
- OCR 提供商类型：`local_sidecar` | `windows_system` | `disabled`。
- 截图命令 `capture_screenshot_region` 内部调用 `ClipboardService.collect_screenshot_bytes_snapshot_with_ocr_update()`，该服务会异步执行 OCR，完成后通过回调再次 emit `clipboard://changed` 事件，前端据此刷新 OCR 文本。

### 5.3 覆盖层交互

- **窗口属性**：`fullscreen: true`, `decorations: false`, `transparent: true`, `alwaysOnTop: true`, `skipTaskbar: true`, `resizable: false`, `backgroundColor: '#00000000'`。
- **复用机制**：`openScreenshotOverlayWindow()` 先检查是否已存在 `screenshot-overlay` 窗口，存在则直接聚焦复用，避免重复创建。
- **就绪等待**：通过 `tauri://created` 事件 + 轮询 `getByLabel` 双重机制确保窗口就绪后才聚焦，超时 1 秒。
- **关闭**：`closeScreenshotOverlayWindow()` 调用 `destroy()` 彻底销毁窗口。

## 7. 已知缺口 / TODO

1. **平台限制**：截图仅实现了 Windows 平台（`#[cfg(target_os = "windows")]`），macOS 和 Linux 返回 `"当前平台尚未实现截图"`。
2. **OCR 依赖剪贴板服务**：截图模块本身不独立管理 OCR，而是复用 `ClipboardService` 的 `collect_screenshot_bytes_snapshot_with_ocr_update`，这意味着截图功能强依赖剪贴板模块的数据库和服务。
3. **无截图编辑/标注**：截图后直接进入剪贴板历史，没有内置的标注、打码、裁剪等编辑功能。
4. **多显示器支持未明确**：Win32 GDI 使用 `GetDC(HWND(null))` 获取主屏幕 DC，多显示器场景下可能存在坐标映射问题（未在代码中显式处理）。
5. **Host 组件无错误处理**：`ScreenshotOverlayHost.vue` 中 `emit` 和 `destroy` 调用没有 try/catch，极端情况下可能静默失败。
6. **App.vue 中截图权限检查绑定 clipboard 模块**：`handleScreenshotShortcut` 和 `handleScreenshotCapture` 都检查 `canUseTab('clipboard')`，即截图功能被归类为剪贴板模块的子功能，而非独立模块授权。

## 8. 与其他模块的依赖关系

| 依赖模块 | 依赖方式 | 说明 |
|---------|---------|------|
| **剪贴板模块 (Clipboard)** | 强依赖 | 截图结果通过 `ClipboardService` 保存为剪贴板图片项；OCR 由剪贴板模块的 OCR 提供商处理；截图成功后自动切换到 Clipboard 标签页 |
| **商业授权模块 (CommercialAuth)** | 权限依赖 | 截图功能受 `clipboard` 模块授权控制，`App.vue` 中通过 `canUseTab('clipboard')` 判断 |
| **全局快捷键模块 (Shortcuts)** | 调用依赖 | `App.vue` 通过 `registerGlobalShortcut` / `unregisterGlobalShortcut` 注册截图快捷键 |
| **设置模块 (Settings)** | 配置依赖 | 截图快捷键从 `settingsStore.settings.screenshotShortcut` 读取 |
| **国际化 (I18n)** | 文案依赖 | 遮罩层提示文案使用 `t('screenshot.dragHint')`，错误提示使用 `t('screenshot.captureFailed')` / `t('screenshot.captureSuccess')` |
| **进程模块 (Processes)** | 无直接依赖 | 截图模块不直接依赖进程管理 |
| **文件模块 (Files)** | 无直接依赖 | 截图模块不直接依赖文件管理 |

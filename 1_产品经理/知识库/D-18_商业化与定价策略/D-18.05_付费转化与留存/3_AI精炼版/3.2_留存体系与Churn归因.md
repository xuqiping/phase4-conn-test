# 3.2 留存体系与Churn归因

## 一、留存定义——D1/D7/D30

### 1.1 留存率定义

**留存率（Retention Rate）**：某日/周/月注册的用户中，在后续第N日/周/月仍然活跃的比例。

| 指标 | 定义 | 衡量 |
|---|---|---|
| **D1留存** | 注册后第1天回来的用户比例 | 首次体验后的回访意愿 |
| **D7留存** | 注册后第7天仍活跃的用户比例 | 短期留存——Onboarding效果 |
| **D30留存** | 注册后第30天仍活跃的用户比例 | 中期留存——产品价值验证 |
| **D90留存** | 注册后第90天仍活跃的用户比例 | 长期留存——习惯形成 |

> PM诊断要点：D1/D7/D30构成留存"三看"——D1看首体验、D7看Onboarding、D30看产品价值。三者递减是正常的，但递减斜率决定留存健康度。

[来源:Amplitude / Mixpanel留存分析 | 🔍高 | 2026]

### 1.2 留存率基准（需查证）

| 产品类型 | D1 | D7 | D30 |
|---|---|---|---|
| SaaS工具 | 30-45% | 20-30% | 15-25% |
| PLG产品 | 40-55% | 25-35% | 15-25% |
| AI产品 | 20-35% | 10-20% | 5-15% |
| 消费类App | 25-40% | 15-25% | 5-15% |

> **AI产品留存基准显著低于SaaS**——虎嗅2026报告显示AI原生公司GRR/NRR不到SaaS的一半。AI产品的"尝鲜流失"模式不同于SaaS，需专门策略（→3.3详解）。

[来源:虎嗅2026 AI商业化报告 / Amplitude基准 | 🔍高 | 2026]

## 二、留存曲线形态——比数字更重要的是形状

### 2.1 三种留存曲线形态

留存曲线的形态比单一时间点的留存数字更能说明问题：

**笑脸曲线（Smile Curve）——健康**：
```
留存率
100%|*
    | *
    |  *
 50%|   *  *  *  *  *  *  *   ← 先降后平，趋于稳定
    |    *
    |      *  *
  0%|_______________________
     D1  D7  D14  D21  D30  D60
```
含义：初期流失（不合适/不感兴趣的用户离开），之后留存趋于稳定——核心用户留住了。**这是健康的产品**。

**直线下滑（Declining Line）——危险**：
```
留存率
100%|*
    |  *
    |   *
 50%|    *
    |     *
    |      *
    |       *
  0%|_______________________
     D1  D7  D14  D21  D30  D60
```
含义：用户持续流失，没有稳定点——"漏桶"严重，产品没有留住用户的价值锚点。**这是危险的产品，必须紧急干预**。

**微笑曲线滞后（Late Smile）——可改善**：
```
留存率
100%|*
    |  *
    |   *
 50%|    *
    |     * * * * * * *   ← 下滑更久但最终稳定
    |
  0%|_______________________
     D1  D7  D14  D21  D30  D60
```
含义：下滑时间更长才稳定——留存可以但Onboarding效率不够高，可优化缩短到达稳定期的时间。

[来源:Andrew Chen留存曲线分析 / Sequoia | 🔍高 | 2025]

### 2.2 曲线形态诊断决策

| 曲线形态 | 诊断 | 行动 |
|---|---|---|
| **笑脸（先降后平）** | 健康——核心用户留住 | 维持产品价值；扩大获客 |
| **直线下滑** | 危险——"漏桶"严重 | 紧急诊断：是Aha没到？Onboarding差？还是产品本身没价值？先修留存再谈增长 |
| **微笑滞后** | 可改善——Onboarding效率不高 | 优化Onboarding缩短到达稳定期的时间 |
| **断崖式下降** | 极危险——D1后大规模流失 | 首体验极差——紧急重构注册后首体验 |

> **PM红线**：D1留存高不代表留存好——如果曲线是"直线下滑"，D1再高也是假象。必须看曲线形态，不能只看单一时间点。

## 三、群组分析（Cohort Analysis）

### 3.1 什么是群组分析

群组分析（Cohort Analysis）将用户按某个共同特征（注册时间/渠道/行为）分组，追踪各组随时间的留存差异。比"整体留存率"更能发现问题和优化方向。

### 3.2 三种群组维度

**按注册时间（时间群组）**——追踪产品改进效果：
```
注册周      D1     D7     D14    D30
W1         35%    18%    12%    8%
W2         38%    20%    14%    10%   ← 版本更新后留存提升
W3         40%    22%    16%    13%
W4         42%    25%    18%    15%   ← Onboarding重构后
```

**按获客渠道（渠道群组）**——优化渠道配置：
```
渠道        D1     D7     D30
SEO         45%    28%    18%    ← 高质量渠道
SEM         35%    18%    10%    ← 付费广告质量一般
转介绍      55%    35%    25%    ← 最高质量
社媒        25%    10%    4%     ← 低质量渠道
```
→ 结论：加大SEO和转介绍投入，减少社媒低质量获客

**按行为（行为群组）**——发现留存驱动行为：
```
行为组               D7     D30
完成Aha的用户        65%    45%    ← Aha到达者留存远超
未完成Aha的用户      12%    3%     ← 大部分流失
使用3+功能的用户      70%    50%
仅使用1功能的用户     15%    5%
```
→ 结论：提升Aha到达率和功能使用深度是留存优化核心

[来源:Amplitude Cohort / Mixpanel | 🔍高 | 2026]

### 3.3 群组分析诊断要点

1. **先看时间群组**——产品迭代是否在改善留存？最近注册的用户留存是否在提升？
2. **再看渠道群组**——哪些渠道的用户留存最好？优化渠道配置
3. **最后看行为群组**——哪些行为与高留存强相关？→ 候选Aha行为和留存驱动行为

## 四、Churn归因——客户为什么流失

### 4.1 Churn阶段分布

流失不是均匀分布的——80%的流失集中在注册后30天内：

| 流失阶段 | 占比(需查证) | 根因 | 对策 |
|---|---|---|---|
| **注册后1-3天** | 30-40% | Onboarding失败/首体验差 | 重构Onboarding |
| **注册后4-7天** | 20-25% | 没到Aha/价值感知不足 | 优化Aha到达率 |
| **注册后8-30天** | 15-20% | 试用期失败/使用场景不匹配 | 精准引导使用场景 |
| **续费期流失** | 10-15% | 价格/竞品/需求变化/客户成功缺位 | CS预警+挽留 |
| **长期使用后流失** | 5-10% | 竞品替代/团队变动/业务转型 | 深度嵌入防迁移 |

> **PM红线**：80%的Churn集中在注册30天内——这不是"自然流失"而是"Onboarding失败"。可控的Churn必须管。

[来源:SaaS留存分析 / ProfitWell | 🔍高 | 2026]

### 4.2 Churn五因归因框架

流失原因不是单一的——必须分类归因才能对症下药：

| 流失原因 | 特征 | 占比(需查证) | 对策 |
|---|---|---|---|
| **产品不足** | 功能缺失/稳定性差/体验差 | 15-25% | 产品迭代补功能/修Bug |
| **价值感知差** | 用了但没感受到价值/Aha没到 | 20-30% | 优化Onboarding/Aha触达 |
| **价格太贵** | 付费时觉得不值/预算不够 | 15-20% | 价格分层/灵活定价/价值锚定 |
| **竞品替代** | 被竞品抢走/功能被替代 | 10-15% | 竞品监控/差异化/锁定效应 |
| **自然流失** | 团队变动/业务调整/非产品原因 | 15-25% | 接受/降低预期/批量运营 |

> **PM诊断要点**：价值感知差和产品不足合计占35-55%——这意味超过一半的流失是"产品自己可以改善的"。价格太贵只占15-20%——先修价值感知再调价格。

[来源:ProfitWell Churn归因 / OpenView | 🔍中 | 2026]

### 4.3 Churn归因调研方法

流失归因不能靠猜测——必须系统化调研：

1. **退出调研（Exit Survey）**——用户取消时弹出简短问券（1-2个问题）："为什么取消？" + "最需要改善什么？"
2. **流失回访电话**——对高价值流失客户（Enterprise/Mid），CS团队在流失后1周内电话回访深度了解原因
3. **行为数据归因**——从流失用户的行为日志分析：是否从某次使用后突然停止？是否始终未到Aha？是否只用了一个功能？
4. **竞品切换追踪**——流失用户是否转向竞品？（通过领英/行业观察/回访了解）
5. **群组交叉分析**——流失用户在渠道/行为/分层上有什么共同特征？

## 五、流失预警模型

### 5.1 主动vs被动防流失

被动流失管理（用户取消后挽留）转化率低（<10%[需查证]）——必须在用户取消前主动预警和干预。

### 5.2 预警信号矩阵

| 预警信号 | 含义 | 预警阈值建议 | 行动 |
|---|---|---|---|
| **使用频次下降** | 从日活变周活→月活 | 连续2周使用频次↓50% | CS团队主动联系 |
| **关键功能停用** | 核心功能使用停止 | 连续7天未使用核心功能 | 定向推送价值提醒 |
| **登录频次下降** | 活跃度下降趋势 | 连续14天未登录 | 邮件/推送召回 |
| **用量接近上限/大幅下降** | 用量模式异常变化 | 用量环比↓30%+ | 关怀外联+使用指导 |
| **座位/账号数减少** | 团队规模收缩 | 30天内减员>20% | CS紧急联系决策人 |
| **NPS/满意度下降** | 用户态度转负 | NPS<0或满意度<6分 | 安排回访+解决痛点 |
| **合同到期前60天无续约动作** | 续约风险 | 到期60天未确认续约 | 启动续约流程 |

### 5.3 客户健康度评分模型

将多个预警信号整合为"客户健康度评分"（Customer Health Score）：

```
健康度 = Σ(各信号权重 × 信号得分)

绿色(健康)  ：健康度 > 80 → 正常维护，推动扩张
黄色(关注)  ：健康度 50-80 → CS关注，定期check-in
红色(危险)  ：健康度 < 50 → 紧急干预，挽留行动
```

**构建步骤**：
1. 选取5-8个与流失强相关的信号变量
2. 用历史流失vs续约客户的数据训练权重
3. 设定绿/黄/红阈值
4. 月度/周度自动刷新健康度
5. CS团队按颜色分层行动

[来源:Gainsight / ClientSuccess CS框架 | 🔍高 | 2026]

## 六、挽留策略

### 6.1 流失前挽留（主动干预）

| 策略 | 适用场景 | 做法 |
|---|---|---|
| **价值回归提醒** | 使用频次下降 | 推送用户忘记的能功能/模板/新功能 |
| **CS主动联系** | 健康度转黄/红 | CS团队电话/邮件联系，了解困难 |
| **培训/Workshop** | 价值感知差 | 安排1对1培训/最佳实践分享 |
| **优惠/降级挽留** | 价格敏感 | 提供临时折扣或降级方案替代流失 |
| **功能升级优先** | 产品不足 | 为高风险客户优先开放Beta功能 |

### 6.2 流失时挽留（被动挽留）

| 策略 | 适用场景 | 做法 |
|---|---|---|
| **取消流程中途挽留** | 用户主动取消 | 取消页面设置"暂停而非取消"选项+优惠/降级 |
| **退出调研+即时响应** | 用户取消 | 1-2问调研+基于回答即时提供定制挽留方案 |
| **降级替代取消** | 价格型流失 | 推荐降级到更低价版本而非完全取消 |
| **数据导出宽限** | 已决定离开 | 提供数据导出期+30天内回归优惠 |

> **PM红线**：被动挽留转化率低（<10%），核心是把挽留前置到"流失前"而非"流失时"。健康度预警+主动干预是关键。

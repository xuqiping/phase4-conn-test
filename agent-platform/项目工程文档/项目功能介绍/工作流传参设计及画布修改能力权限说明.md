# 工作流传参设计及画布修改能力权限说明

## 一、背景

当前工作流画布支持引用 Agent 的 Skill 节点，并允许在节点属性面板中配置系统提示词、用户提示词、模型、温度、输出变量名等参数。

联调过程中发现两个核心问题：

1. 工作流节点配置与 Agent 大厅中的 Skill 主配置不是同一份数据。
   - 工作流保存的是 `workflow_nodes.config`。
   - Agent 大厅展示的是 `skills` 和 `skill_steps.config`。
   - 因此在工作流画布中修改提示词后，Agent 大厅仍可能看到旧提示词。

2. 多个 Agent 或多个 Skill 都可能定义相同的 `outputKey`，例如 `summary`。
   - 如果所有输出都写入全局变量 `summary`，后写入的节点会覆盖先写入的节点。
   - 下游节点无法明确知道引用的是哪个上游节点的输出。

本文档定义后续工作流传参、变量引用、提示词权限、节点配置同步的统一规则。

## 二、设计目标

1. 工作流节点修改 Agent 能力配置时，只有授权用户可以修改。
2. Agent 的系统提示词和用户提示词只对管理员、Agent 拥有者可见。
3. 普通用户可以引用 Agent 能力，但不能看到或修改内部提示词。
4. 普通用户可以通过公开参数给 Agent 能力传参。
5. 多个节点使用相同 `outputKey` 时不会冲突。
6. 工作流运行、执行监控、变量菜单都使用同一套传参规范。

## 三、数据归属

### 3.1 Agent 能力主配置

Agent 能力的主配置保存在：

- `agents`
- `skills`
- `skill_steps`

其中 LLM 能力的提示词主配置保存在 `skill_steps.config`，例如：

```json
{
  "systemPrompt": "你是一个联调摘要助手",
  "promptTemplate": "请总结以下联调内容：{{input}}",
  "model": "doubao-seed-2.0-code",
  "temperature": 0.2,
  "outputKey": "summary"
}
```

### 3.2 工作流节点配置

工作流节点配置保存在 `workflow_nodes.config`。

对于 SKILL 节点，节点配置分为两类：

1. 能力定义配置：`systemPrompt`、`promptTemplate`、`model`、`temperature`、`outputKey`
2. 调用参数配置：`inputMappings`、`outputAlias`、`nodeAlias`

授权用户修改能力定义配置时，需要同步回 `skill_steps.config`。

普通用户只能修改调用参数配置，不能修改能力定义配置。

## 四、权限规则

### 4.1 角色定义

| 用户类型 | 定义 |
| --- | --- |
| 管理员 | 拥有 `admin` 角色 |
| Agent 拥有者 | 当前用户是 `agents.created_by` 或 Agent 定义的 owner |
| 工作流拥有者 | 当前用户是 `workflows.owner_id` |
| 普通引用者 | 有权限使用工作流或 Agent，但不是管理员或 Agent 拥有者 |

### 4.2 提示词可见性

| 用户类型 | 可查看系统提示词 | 可查看用户提示词 | 可修改提示词 |
| --- | --- | --- | --- |
| 管理员 | 是 | 是 | 是 |
| Agent 拥有者 | 是 | 是 | 是 |
| 工作流拥有者但不是 Agent 拥有者 | 否 | 否 | 否 |
| 普通引用者 | 否 | 否 | 否 |

### 4.3 工作流节点配置权限

| 配置项 | 管理员 | Agent 拥有者 | 工作流拥有者 | 普通引用者 |
| --- | --- | --- | --- | --- |
| `systemPrompt` | 可读写 | 可读写 | 不可读写 | 不可读写 |
| `promptTemplate` | 可读写 | 可读写 | 不可读写 | 不可读写 |
| `model` | 可读写 | 可读写 | 不可读写 | 不可读写 |
| `temperature` | 可读写 | 可读写 | 不可读写 | 不可读写 |
| `outputKey` | 可读写 | 可读写 | 不可读写 | 不可读写 |
| `nodeAlias` | 可读写 | 可读写 | 可读写 | 可读写 |
| `inputMappings` | 可读写 | 可读写 | 可读写 | 可读写 |
| `outputAlias` | 可读写 | 可读写 | 可读写 | 可读写 |

后端必须做同样的权限校验。前端隐藏字段只能作为体验优化，不能作为安全边界。

## 五、配置同步规则

### 5.1 授权用户保存 SKILL 节点

当管理员或 Agent 拥有者保存工作流时：

1. 保存 `workflow_nodes.config`。
2. 将 SKILL 节点中的能力定义配置同步回对应 Skill 的第一步 `skill_steps.config`。

同步字段包括：

- `systemPrompt`
- `promptTemplate`
- `model`
- `temperature`
- `outputKey`
- 后续扩展字段，如 `maxTokens`

示例：

```json
{
  "skillId": 1,
  "agentId": 4,
  "nodeAlias": "integrationSummary",
  "systemPrompt": "你是一个提示词增强Agent",
  "promptTemplate": "你将对以下提示词做增强：{{input}}",
  "model": "doubao-seed-2.0-code",
  "temperature": 0.2,
  "outputKey": "summary"
}
```

保存后，`skill_steps.config` 也应同步为：

```json
{
  "systemPrompt": "你是一个提示词增强Agent",
  "promptTemplate": "你将对以下提示词做增强：{{input}}",
  "model": "doubao-seed-2.0-code",
  "temperature": 0.2,
  "outputKey": "summary"
}
```

### 5.2 非授权用户保存 SKILL 节点

当用户不是管理员，也不是 Agent 拥有者时：

1. 后端忽略请求中的敏感字段。
2. 不允许覆盖 `skill_steps.config`。
3. `workflow_nodes.config` 中不保存明文提示词。
4. 只保存调用参数。

示例：

```json
{
  "skillId": 1,
  "agentId": 4,
  "nodeAlias": "integrationSummary",
  "inputMappings": {
    "input": "{{start.message}}",
    "style": "简洁"
  },
  "outputAlias": {
    "summary": "integrationSummaryText"
  }
}
```

## 六、普通用户传参规范

普通用户无法看到 Agent 内部提示词，因此 Agent 拥有者必须为能力定义公开入参。

公开入参建议保存在 Skill 配置或 Skill Step 配置中：

```json
{
  "publicInputs": [
    {
      "key": "input",
      "label": "待处理内容",
      "type": "textarea",
      "required": true,
      "description": "传入需要处理的文本"
    },
    {
      "key": "style",
      "label": "输出风格",
      "type": "text",
      "required": false,
      "description": "例如：简洁、正式、口语化"
    }
  ]
}
```

Agent 内部提示词可以使用公开入参：

```text
你将对以下内容做增强：{{input}}
输出风格：{{style}}
```

普通用户在工作流画布中只看到公开入参表单：

- 待处理内容
- 输出风格

普通用户可以直接填写固定值，也可以引用上游变量：

```json
{
  "inputMappings": {
    "input": "{{requirementInput.message}}",
    "style": "简洁"
  }
}
```

运行时将 `inputMappings` 渲染为技能执行上下文变量：

```json
{
  "input": "上游节点输出内容",
  "style": "简洁"
}
```

## 七、变量命名与引用规范

### 7.1 禁止只依赖全局裸变量

不推荐跨节点直接引用：

```text
{{summary}}
```

原因是多个节点可能都输出 `summary`，会产生冲突。

### 7.2 节点级变量命名

每个节点必须有稳定节点别名 `nodeAlias`。

变量引用格式：

```text
{{nodeAlias.outputKey}}
```

示例：

```text
{{integrationSummary.summary}}
{{requirementReview.summary}}
```

即使两个节点的 `outputKey` 都是 `summary`，也不会冲突。

### 7.3 稳定节点别名规则

`nodeAlias` 是用户可读、可维护的稳定标识，不能使用纯时间戳 ID 作为主要引用标识。

建议规则：

- 默认由节点名称生成，如 `联调摘要生成` -> `integrationSummary`
- 允许用户手动修改
- 同一工作流内必须唯一
- 修改 `nodeAlias` 时，前端需要提示会影响已有变量引用
- 后端保存时校验唯一性

示例节点配置：

```json
{
  "nodeAlias": "integrationSummary",
  "outputKey": "summary"
}
```

输出变量路径：

```text
integrationSummary.summary
```

### 7.4 变量池结构

运行时变量池建议采用分层结构：

```json
{
  "nodes": {
    "integrationSummary": {
      "summary": "联调摘要内容"
    },
    "requirementReview": {
      "summary": "需求复核摘要"
    }
  },
  "globals": {
    "message": "用户输入"
  }
}
```

模板渲染支持：

```text
{{integrationSummary.summary}}
{{requirementReview.summary}}
{{message}}
```

裸变量只用于输入节点或显式导出的全局变量。

### 7.5 全局变量导出

如果用户确实需要将某个节点输出提升为全局变量，必须显式配置：

```json
{
  "outputAlias": {
    "summary": "finalSummary"
  }
}
```

下游可引用：

```text
{{finalSummary}}
```

如果多个节点导出同一个全局变量名，保存时应报错。

## 八、变量选择器交互

在用户提示词或公开入参输入框中输入 `/` 时，变量选择器应展示所有可用上游变量。

展示文本：

```text
联调摘要生成 / summary
需求复核 / summary
文本输入 / message
```

插入值：

```text
{{integrationSummary.summary}}
{{requirementReview.summary}}
{{textInput.message}}
```

变量选择器需要显示：

- 节点名称
- 稳定节点别名
- outputKey
- 数据来源节点

如果引用的是输入节点，也使用同样规范：

```text
{{textInput.message}}
```

## 九、运行时传参规则

运行 SKILL 节点时：

1. 读取当前节点的 `inputMappings`。
2. 渲染其中的变量引用。
3. 将渲染结果写入执行上下文。
4. 使用 `skill_steps.config` 中的主提示词执行。
5. 对管理员或 Agent 拥有者编辑过的节点，主提示词已经在保存时同步到 `skill_steps.config`。

示例：

```json
{
  "nodeAlias": "promptEnhancer",
  "inputMappings": {
    "input": "{{textInput.message}}",
    "style": "简洁"
  }
}
```

渲染后：

```json
{
  "input": "请帮我优化这段提示词",
  "style": "简洁"
}
```

Skill 内部提示词：

```text
你将对以下提示词做增强：{{input}}
风格要求：{{style}}
```

## 十、接口与后端校验要求

### 10.1 工作流详情脱敏

`GET /api/workflows/{id}` 返回工作流详情时：

- 管理员或 Agent 拥有者：返回完整 SKILL 节点配置
- 非授权用户：移除以下字段
  - `systemPrompt`
  - `promptTemplate`
  - `model`
  - `temperature`
  - 其他敏感模型调用配置

非授权用户仍可看到：

- `skillId`
- `agentId`
- `agentName`
- `nodeAlias`
- `publicInputs`
- `inputMappings`
- `outputAlias`

### 10.2 工作流保存过滤

`PUT /api/workflows/{id}` 保存时：

- 管理员或 Agent 拥有者：允许保存敏感字段，并同步到 `skill_steps.config`
- 非授权用户：忽略或拒绝敏感字段

建议对非授权用户返回明确错误，而不是静默忽略：

```json
{
  "code": 403,
  "message": "只有管理员或 Agent 拥有者可以修改能力提示词"
}
```

### 10.3 节点别名唯一性校验

保存工作流时校验：

- 同一工作流内 `nodeAlias` 唯一
- `nodeAlias` 不能为空
- `nodeAlias` 只能包含字母、数字、下划线，或采用系统认可的 slug 规则

## 十一、前端画布要求

### 11.1 授权用户属性面板

管理员或 Agent 拥有者看到：

- 节点名称
- 稳定节点别名
- 系统提示词
- 用户提示词
- 模型
- 温度
- 输出变量名
- 公开入参配置
- 调用参数映射

### 11.2 普通用户属性面板

普通用户看到：

- 节点名称
- 稳定节点别名
- Agent 名称
- Skill 名称
- 能力说明
- 公开入参表单
- 调用参数映射
- 输出别名

普通用户看不到：

- 系统提示词
- 用户提示词
- 模型底层配置
- 温度等敏感调用参数

### 11.3 保存和运行

点击运行时，前端应先保存工作流，再调用运行接口。

运行前保存必须遵守后端权限校验，不能绕过 Agent 拥有者限制。

## 十二、执行监控展示

执行监控中应展示：

- 每个节点的输入参数
- 每个节点的输出参数
- 节点名称
- 稳定节点别名
- 执行状态
- 错误信息

对于普通用户，执行监控不展示敏感提示词，只展示实际调用入参和输出。

## 十三、验收标准

1. Agent 拥有者在工作流 SKILL 节点修改提示词并保存后，Agent 大厅对应 Skill 的 `skill_steps.config` 同步变化。
2. 管理员具备同样能力。
3. 非 Agent 拥有者打开工作流时，看不到系统提示词和用户提示词。
4. 非 Agent 拥有者保存工作流时，不能修改提示词。
5. 普通用户可以通过公开入参给 Agent 能力传参。
6. 多个节点都输出 `summary` 时，下游通过 `{{nodeAlias.summary}}` 精确引用，不发生冲突。
7. `/` 变量选择器展示节点名称、稳定节点别名和 outputKey，插入 `{{nodeAlias.outputKey}}`。
8. 执行监控能看到每一步输入输出，但不泄露提示词。

## 十四、后续实现建议

建议按以下顺序实现：

1. 后端实现 Agent 拥有者/管理员判断。
2. 工作流详情接口对 SKILL 节点敏感字段脱敏。
3. 工作流保存接口校验 SKILL 节点敏感字段修改权限。
4. 授权用户保存时同步提示词到 `skill_steps.config`。
5. 前端属性面板按权限切换“能力编辑模式”和“能力调用模式”。
6. 引入 `nodeAlias` 并做唯一性校验。
7. 变量选择器改为插入 `{{nodeAlias.outputKey}}`。
8. 运行时变量池支持节点级命名空间。
9. 执行监控展示节点别名和完整输入输出。

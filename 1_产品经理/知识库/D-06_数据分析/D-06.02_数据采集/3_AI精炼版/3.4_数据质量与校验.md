# 3.4 数据质量与校验

## 数据质量三维度

| 维度 | 定义 | 度量方法 | 标准线 |
|---|---|---|---|
| **完整性** | 该采的是否都采了 | 事件上报率=实际上报/应上报 | >99% |
| **准确性** | 采的数据是否正确 | 属性填充率(非空)、值域校验、同行交叉比对 | 属性非空率>95% |
| **及时性** | 数据是否及时可用 | 端到端延迟=事件发生→数据可用 | 批处理<4h/实时<5min |

## 校验方法体系

### 1. 自动化校验

| 校验类型 | 方法 | 工具 |
|---|---|---|
| Schema校验 | 事件属性必须符合预定义类型/取值 | Great Expectations / dbt test |
| 异常检测 | 数值突变/空值飙升/频率异常 | Amplitude Anomaly / 自建规则 |
| 同源比对 | 同一行为的不同数据源交叉验证 | SQL Join + 差异率 |

### 2. 人工校验

| 方法 | 频率 | 适用 |
|---|---|---|
| 数据走查 | 每次新埋点上线 | 逐条验证事件/属性是否正确 |
| 看板监控 | 每日 | 核心事件量的日环比/周同比 |
| 对账 Audit | 每月 | 多系统数据对账（埋点vs日志vs财务） |

### 3. 埋点上线前校验清单

| 检查项 | 通过标准 |
|---|---|
| 事件名符合命名规范 | `模块_对象_动作` 格式 |
| 必传属性非空 | 上报数据中无空值 |
| 属性值域正确 | 枚举值在预定义范围内 |
| 无重复上报 | 同一事件不会因页面刷新触发两次 |
| 触发时机正确 | 在正确时机上报（如支付成功后而非点击时） |
| 数据延迟合理 | 事件发生→数据到达<预期延迟 |
| 隐私合规 | 无敏感信息明文传输 |

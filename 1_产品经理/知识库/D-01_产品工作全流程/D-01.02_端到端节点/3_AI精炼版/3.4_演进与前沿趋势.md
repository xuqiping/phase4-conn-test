## 理论演进

| 时期 | 代表 | 贡献 |
|---|---|---|
| 1970s | Royce(Waterfall) | 线性顺序节点：需求→设计→开发→测试→部署 |
| 1980s | Boehm(Spiral) | 螺旋模型：风险驱动的迭代节点 |
| 1990s | Cooper(Stage-Gate) | 阶段+质量门概念，引入"Go/Kill/Hold"决策 |
| 2000s | Schwaber(Scrum) | Sprint内的短周期节点循环：Plan→Develop→Review→Retro |
| 2010s | DevOps/CI-CD | 测试→部署节点自动化，部署频率从月级→日级 |
| 2020s | ProductOps | 产品运营一体化，节点间数据流自动化 |

## 前沿趋势 2025-2026

### 1. AI辅助节点执行

AI在各节点的应用正在从"辅助"走向"半自动"：

| 节点 | AI辅助方式 | 当前成熟度 |
|---|---|---|
| 需求调研 | AI分析用户反馈/工单自动提取需求条目 | 中（辅助级，需人工审核） |
| 分析定义 | AI辅助生成PRD草稿（从需求条目→用户故事→验收标准） | 中（草稿质量参差） |
| 设计评审 | AI自动检查设计稿与PRD的一致性 | 低（⚠️待核实） |
| 研发排期 | AI基于历史数据估算工时 | 中（偏差仍较大） |
| 测试验收 | AI自动生成Test Case / 自动化回归测试 | 高（成熟应用） |
| 上线发布 | AI灰度监控+自动回滚 | 高（大厂已普及） |
| 运营迭代 | AI自动生成数据复盘报告 | 中（辅助级） |

### 2. 持续交付(Continuous Delivery)压缩节点边界

传统七节点边界清晰——"做完了再传"。持续交付模式下，节点边界模糊化：
- "设计→开发"不再是"设计全做完再开发"，而是"设计一块开发一块"
- "测试"不再是"开发全做完再测试"，而是"边写代码边跑自动测试"
- "部署"不再是"手动上线"，而是"合并代码自动部署"

**PM影响**：节点不再按"阶段"流转，而是按"特性(Feature)"流转——每个Feature独立走完全链路。

### 3. DevOps与产品流程融合

传统PM流程止于"上线"，DevOps让"上线→监控→反馈→优化"闭环自动化：
- 上线即监控（自动化指标大盘+告警）
- 异常即回滚（AI判定+自动回滚）
- 反馈即需求（用户反馈自动归入需求池）

**趋势**：PM的"运营迭代"节点越来越自动化，PM更多做"判断"而非"收集"。

### 4. 远程/异步协作对节点流转的重塑

远程办公导致"节点同步传递"变难——评审会不能拉所有人。实践趋势：
- **异步评审**：设计稿上线→各位1天内异步评论→PM汇总闭环
- **文档驱动**：节点间传递物从"会议"变为"文档"，文档质量>会议效率

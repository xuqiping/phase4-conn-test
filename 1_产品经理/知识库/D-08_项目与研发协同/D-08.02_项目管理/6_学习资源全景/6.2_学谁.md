## 1. Frederick Brooks（弗雷德里克·布鲁克斯）

| 维度 | 内容 |
|---|---|
| 身份 | 《人月神话》作者、图灵奖得主、IBM System/360项目经理 |
| 国籍 | 美国 |
| 核心成就 | 主持IBM System/360开发；著《人月神话》提出"人月不可互换""没有银弹""第二系统效应"等经典论断 |
| **思维模型** | **复杂系统的不可压缩性**——软件项目的内在复杂度无法用人力线性堆叠来压缩；"概念完整性"优于功能完整性 |
| **行动范式** | 用"外科手术式团队"（一主刀+N助手）替代"人人平等"的大团队——一个架构师主导概念完整性 |
| 可学习点 | PM面对"加人能否加速"的决策时，用Brooks法则做第一性原理判断——沟通成本随人数N(N-1)/2增长 |
| 代表作 | 《人月神话》(1975) / 《没有银弹》论文(1986) |
| 来源 | `[来源:ACM图灵奖档案+著作 | 置信度:🔍高]` |

## 2. Eliyahu Goldratt（伊利亚胡·高德拉特）

| 维度 | 内容 |
|---|---|
| 身份 | TOC制约理论创始人、物理学家转管理学家 |
| 国籍 | 以色列 |
| 核心成就 | 创立TOC（Theory of Constraints）制约理论；著《目标》《关键链》等管理学小说 |
| **思维模型** | **系统产出由最弱环节决定**——优化非瓶颈环节不能提升系统产出，只会增加库存/在制品；用"缓冲集中管理"替代"每环节加安全垫" |
| **行动范式** | 五步聚焦法：识别瓶颈→利用瓶颈→服从瓶颈→提升瓶颈→回到第1步 |
| 可学习点 | PM排期时先找关键路径（瓶颈）→非关键路径只放汇入缓冲→关键路径末端放项目缓冲 |
| 代表作 | 《目标》(1984) / 《关键链》(1997) / 《绝不是靠运气》 |
| 来源 | `[来源:Goldratt Institute | 置信度:🔍高]` |

## 4. Tom DeMarco

| 维度 | 内容 |
|---|---|
| 身份 | 软件工程顾问、著《人件》《最后期限》 |
| 国籍 | 美国 |
| 核心成就 | 与Tim Lister合著《人件》（Peopleware）——关注团队动力学与工作环境；提出"90%综合征" |
| **思维模型** | **管理的对象是人不是任务**——团队生产力最大的敌人不是技术问题，而是组织环境问题（打断/噪音/压力/不合理期限） |
| **行动范式** | 用"流动状态（Flow）"视角看生产力——每次被打断需要15分钟恢复深度工作，频繁打断=生产力归零 |
| 可学习点 | PM做进度跟踪时，区分"被打断的忙碌"和"有产出的专注"——站会/消息/会议都在打断Flow |
| 代表作 | 《人件》(1987) / 《最后期限》(1997) / 《为什么软件这么贵》 |
| 来源 | `[来源:Atlantic Systems Guild | 置信度:🔍高]` |

| 维度 | 内容 |
|---|---|

| 可学习点 | PM面对纠结时，不做决定比做错决定代价更大——记录决策理由比决策本身更能积累能力 |
| 代表作 | 《让事情发生》/ 《How Design Makes the World》 |

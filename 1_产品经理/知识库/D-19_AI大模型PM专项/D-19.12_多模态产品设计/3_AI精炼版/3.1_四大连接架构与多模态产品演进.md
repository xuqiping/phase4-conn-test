# 3.1 四大连接架构与多模态产品演进

> 本碎片覆盖 D-19 基线维度：C.01/C.02/D.01/D.02/I.02

## 一、多模态产品的技术演进路径（5代际）

### 第1代：单模态独立模型（2020前）
- **代表**：BERT（纯文本）/ ResNet（纯图像）/ Wav2Vec（纯音频）
- **特征**：每个模态一个独立模型，模态间无关联
- **PM含义**：要做多模态产品需要把多个独立模型做编排拼接，工程复杂、效果上限低

### 第2代：CLIP 双塔模型（2021，OpenAI奠基）
- **代表**：CLIP / 中文CLIP / ALIGN / Fine-Grained CLIP
- **特征**：图像编码器与文本编码器分别编码，通过对比学习把图文映射到同一语义空间
- **优势**：跨模态检索（图搜文/文搜图）极强，工程简单可规模化
- **劣势**：不能做生成，不能做复杂跨模态推理
- **PM场景**：电商搜索/跨模态检索/内容审核/推荐召回
- *[来源:知乎·第十五章让AI学会看和听 \| 🔍高 \| 2026-03-25]*

### 第3代：拼接型VLM（Vision-Language Model，2023-2024）
- **代表**：LLaVA（早期）/ Qwen-VL（早期）/ MiniGPT-4
- **技术**：在LLM基础上接一个视觉编码器+连接层，把图像特征"翻译"成文本token喂给LLM
- **PM含义**：终于能用LLM"读图回答问题"，但视觉幻觉严重

### 第4代：深度对齐型VLM（2024-2025）
- **代表**：BLIP-2 / InstructBLIP / Qwen-VL Max / GPT-4V
- **技术**：引入Q-Former等深度对齐模块，对视觉信息做压缩+对齐
- **优势**：视觉信息更精细进入LLM，视觉幻觉开始降低
- *[来源:知乎·多模态大模型实习笔记 \| 🔍高 \| 2026-01-02]*

### 第5代：原生多模态（Native Multimodal，2025-2026主流旗舰）
- **代表**：GPT-5.5/5.6（OpenAI Hermes架构）/ Gemini 3.1 Pro（Google，200万token四模态）/ Claude Opus 4.7 / Sora 2（视频原生）/ Veo 3.1 / 通义千问3-Max
- **技术**：从训练起就混合多模态数据，不通过连接层"翻译"，模型本身原生支持多模态
- **优势**：视觉幻觉显著降低、跨模态推理强、模态天然对齐
- **劣势**：训练算力极大、不可解释、API调用贵
- *[来源:51CTO主流模型横评 \| 🔍高 \| 2026-05-19]*
- *[来源:知乎·第十五章视觉幻觉显著降低 \| 🔍高 \| 2026-03-25]*

## 二、四大连接架构深度解析

### 架构1：CLIP 双塔（检索之王）

```
[图像] → 图像编码器 → 图像向量 ↘
                                  对比学习 → 共享语义空间
[文本] → 文本编码器 → 文本向量 ↗
```

**核心机制**：对比学习让"猫的图片"和"猫"这个词的向量靠近，不匹配的远离
**变体**：
- **CLIP**：原始版本，词袋效应（bag-of-words）严重，"红苹果"和"苹果红"向量几乎一样
- **Fine-Grained CLIP**：解决CLIP的词袋效应+局部图像特征对齐失准 *[来源:360 Fine-Grained VLM \| 🔍高 \| 2026-07]*
- **多语言CLIP**：支持中文等多语言

**PM评估**：
- 计算快（独立编码+相似度计算）
- 不支持复杂推理
- 不能生成
- 工程成熟，开源版本多

### 架构2：Linear Projection（拼接型VLM）

```
[图像] → 视觉编码器(ViT) → 视觉特征 → Linear层 → 文本token表示 → [LLM] → 文本输出
[文本] → ────────────────────────────────────────→ [LLM]
```

**核心机制**：用一个线性层把视觉特征直接"翻译"成LLM能理解的文本token
**代表**：LLaVA早期、MiniGPT-4、Qwen-VL早期

**PM评估**：
- ✅ 工程简单，开源代码多
- ✅ 训练数据易得（图文对）
- ❌ 视觉细节丢失严重
- ❌ 视觉幻觉率高
- ❌ 不擅长复杂视觉推理（数学题、读小字、细粒度识别）

**适用场景**：MVP快速验证、轻量多模态产品、低算力团队

### 架构3：Q-Former（深度对齐）

```
[图像] → 视觉编码器 → 视觉特征 ─┐
                                  ├→ Q-Former(可学习查询) → 压缩视觉token → [LLM] → 文本输出
[文本] ──────────────────────────┘
```

**核心机制**：用一组可学习的"查询token"对视觉特征做"二次抽取+压缩"，把视觉信息压缩到几十个token再喂给LLM
**代表**：BLIP-2、InstructBLIP、Qwen-VL Max

**PM评估**：
- ✅ 视觉信息压缩+对齐，token省（视觉token从1024降到32）
- ✅ 视觉幻觉显著降低
- ✅ 适合长视觉上下文
- ❌ 训练复杂，预训练Q-Former需要两阶段
- ❌ 对齐粒度有限

**适用场景**：中重度多模态理解、图文混排文档理解（医疗影像+病历、PDF问答）、低延迟场景

### 架构4：Native Multimodal（原生多模态）

```
[文+图+音+视频混合训练] → 统一Transformer架构 → 多模态输出
```

**核心机制**：从训练起就用多模态混合数据，模型层面就没有"连接层"概念，原生支持多模态理解+生成
**代表**：GPT-5.6 / Gemini 3.1 Pro / Claude 4.7 / Sora 2 / Veo 3.1

**2026旗舰模型实测**：*[来源:太平洋电脑网2026主流AI模型横评 \| 🔍高 \| 2026-06-15]*

| 模型 | 多模态特性 | 上下文 | GPQA | 价格 |
|---|---|---|---|---|
| GPT-5.5/5.6 | 全模态原生+Mid-response Steerability | 百万token | 高 | 高 |
| Gemini 3.1 Pro | 文+图+音+视频四模态原生 | 200万token | 94.3% | 中（约2美元/百万token） |
| Claude Opus 4.7 | 文+图为主，视频生成保守 | 128K | 高 | 高 |
| GLM-5.1 | 文+图，性价比突出 | 128K-1M | 中 | 低 |
| Qwen3-Max | 文+图+视频，国产旗舰 | 256K | 中 | 中 |

**PM评估**：
- ✅ 视觉幻觉显著降低
- ✅ 跨模态推理强
- ✅ 长上下文（200万token打破壁垒）
- ❌ 训练算力极大（不可自研，只能调API）
- ❌ 不可解释
- ❌ API调用贵

**适用场景**：旗舰产品、对效果上限要求高、成本可承受（C端订阅/B端企业版）

## 三、四种架构选型决策表（PM核心方法论）

| 维度 | CLIP | Linear Projection | Q-Former | Native Multimodal |
|---|---|---|---|---|
| 主要用途 | 检索/召回 | MVP验证 | 文档理解 | 旗舰产品 |
| 工程复杂度 | 低 | 低 | 中 | 高（用API即可） |
| 视觉幻觉率 | N/A | 高 | 中 | 低 |
| 跨模态推理 | 弱 | 弱 | 中 | 强 |
| Token消耗 | 极低 | 中（视觉token多） | 低（视觉token压缩） | 高 |
| 训练成本 | 低 | 中 | 高 | 极高（不自研） |
| 适合团队 | 小团队+检索场景 | 创业团队 | 中型团队+垂直场景 | 任何团队（API） |
| 适合产品阶段 | 任何 | MVP/早期 | 中期 | 旗舰期 |

### PM选型四步法

1. **第一步：明确产品场景**——是检索？理解？生成？
2. **第二步：评估算力预算**——能否自研训练？还是必须用API？
3. **第三步：明确产品阶段**——MVP vs 旗舰
4. **第四步：权衡幻觉容忍度**——医疗等高敏感场景必须上原生多模态/Q-Former

## 四、模型演进对PM的反共识启示

1. **CLIP没过时**：虽然CLIP是2021的技术，但在跨模态检索场景仍是SOTA——原生多模态反而做不好检索
2. **Linear不等于很差**：很多场景LLaVA足够用，盲目上原生多模态是过度工程
3. **Q-Former的价值在压缩**：在token昂贵的时代，Q-Former把视觉token从1024压缩到32是巨大优势
4. **原生多模态≠全能**：Claude 4.7在视频生成仍保守——原生多模态也有专长方向
5. **2026视觉幻觉显著降低≠消除**：原生多模态降低幻觉但没消除，PM仍要做幻觉对冲（参D-19.10）

## 五、PM实操要点（落地清单）

1. 起步首选CLIP+Linear组合（检索+基础理解）
2. 中重度场景引入Q-Former（如医疗文档理解）
3. 旗舰产品直接调原生多模态API（GPT-5.6/Gemini 3.1）
4. 视觉幻觉对冲始终要做（不要因架构升级就放松）
5. token消耗按"原生>Q-Former>Linear>CLIP"递减
6. 检索场景CLIP系永远不可替代
7. 自研团队优先Q-Former（性价比天花板）
8. 不自研团队调原生多模态API（效果天花板）

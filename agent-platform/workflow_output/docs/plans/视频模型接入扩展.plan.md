## RA · provider 路由层 + V163（MVR-1）

- **目标**：worker 去 arkProvider 硬编码，按 provider 行 protocol 派发；存量 VIDEO 行补标 `ark`。
- **动作**（伪代码）：
  1. `MediaGenProvider` 接口：加 `String getId()`；`queryTask(String providerTaskId, Long providerId)` 上位为接口方法（多 provider 行各持密钥，查态必须知道用哪行 key；Ark 现两参私有版平移实现）。**IMAGE 链不动**（ArkImageProvider 同步生成、不在本接口）。
  2. Worker：构造注入 `List<MediaGenProvider>` → `@PostConstruct` 建 `Map<getId(), provider>`；建任务/查态（:149/:160）改：`provider = map.get(provider行.protocol)` → 未命中=任务 FAILED，话术「视频协议 {protocol} 未注册适配器」（含 taskId，不静默卡 PENDING）。
  3. `V163__media_video_provider_protocol.sql`：`UPDATE llm_providers SET protocol='ark' WHERE category='VIDEO' AND (protocol IS NULL OR protocol='')`。
- **涉及文件**：`media/provider/MediaGenProvider.java`、`media/provider/ArkSeedanceProvider.java`、`media/service/MediaGenTaskWorker.java`、`db/migration/V163__media_video_provider_protocol.sql`（4 个）
- **依赖**：无
- **验证**：junit（protocol→provider 命中；未注册→FAILED 可读话术）；WireMock Ark 建任务/查态全链回归（补标 ark 后仍命中）；真 PG Flyway V163 应用后 `\d` 确认 + 存量 Cdance 行 protocol=ark。回滚演练：`SET protocol=NULL WHERE category='VIDEO'`（记手册）。

- **涉及文件**：`billing/service/PricingConfigService.java`、`billing/service/PricingService.java`、`media/config/MediaModelCapabilityService.java`、`views/admin/PricingConfigView.vue`、`api/billing.ts`（5 个）

## 技术坑点预判

- **queryTask 必须带 providerId**：多 provider 行各持密钥——查态只传任务号会拿默认行 key，MiniMax/百炼必 401。接口签名 `queryTask(providerTaskId, providerId)` 钉死。
- **protocol 回填先于路由上线**：RA 同 chunk 内迁移+代码同发；只发代码不跑 V163=存量 Cdance 全部 FAILED「未注册适配器」。
- **FieldStrategy.ALWAYS**（V162 钉过）：SECOND 槽清空存 NULL 必须 ALWAYS，漏了=「导入 {} 清空」「编辑清槽」双双静默失效。
- **双 JSONB 撞脸 ×2**：`est_per_resolution`（预估）/`token_price_per_resolution`（TOKEN 扣费）/`price_per_second_per_resolution`（SECOND 扣费）同表三列同形态——review 盯字段名，用例显式互不串。
- **脏 JSON WARN 回落**：SECOND 槽解析失败回落通用秒价，不炸结算（fail-closed 退预扣代价大）。
- **归一双侧同函数**：768P/2K 大写直存则结算取 768p 取不到——存储时归一（normalize），结算侧同 `normalizeResolution`，一个函数。
- **字典≠能力**：字典 6 档是并集白名单；模型可见档必须走 capability 子集——把字典塞给 capability 会给 seedance 冒出 768p 档。
- **前端 slots 三处漂移**：est/token/second 三组槽数组若手写三份必漂移——单源派生（常量或类型）。
- **适配器轮询退避**：复用 Ark 间隔/上限常量；新渠道官方限流未知，超时+重试沿范式，别裸 while 打爆。
- **estimateRatePerSec 伪费率**（Worker:490）：usage 缺失兜底口径，P2 核对覆盖 2.5 的 4K 档（规格 §8 核对项①）。
- **Flyway 号位**：V162 已用；V163/V164 新文件；已发布迁移 checksum 一字不动。

## 运维考量清单（7 类逐条落字）

- **可观测性**：**做**——路由失败/适配器异常 WARN 含 taskId+protocol；指纹缓存/退避沿 Ark；不加新指标。
- **配置开关**：**做（天然）**——provider 行不配 models 即不可达，无需发版开关；能力可 config 覆盖。
- **可回滚**：**做**——V163 UPDATE 可逆（回 NULL 记手册）、V164 DROP COLUMN 可逆；能力默认=代码 revert；新 provider 删 models 行即下线。
- **限流/熔断**：**做（复用）**——出站超时/退避沿 Ark 范式；官方限流观察后调，不预设熔断器。
- **运维入口**：**做（零新增）**——任务失败原因可读（任务详情）；价表/能力配置页即调价入口。
- **告警阈值**：**后续**——D9 est-vs-实耗偏差监控已存在，新口径自动纳入；单独「路由失败率」告警不本期。
- **容量/性能**：**不做**——路由=内存 map 查表；JSONB 单行 ≤6 键；结算单次 parse 非热路径。

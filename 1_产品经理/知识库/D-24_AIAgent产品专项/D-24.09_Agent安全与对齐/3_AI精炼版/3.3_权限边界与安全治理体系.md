# 3.3 权限边界与安全治理体系

## 一、权限泛滥是 2026 第一杀手

### 1.1 write:* 通配符批量转账案例
腾讯云 2026-07《跨越信任鸿沟》剖析典型场景：客服 Agent 为处理退款申请，被授予了财务系统的 write:* 通配符权限，攻击者通过提示注入诱导其批量转账。根因：缺乏细粒度最小权限机制，权限模型沿用传统 RBAC 的粗粒度角色分配，未针对 Agent 任务动态授权。一个 Token 失守拖垮全系统。[来源:腾讯云《跨越信任鸿沟:AI Agent权限管控、审计追踪与合规治理实战》 | 🔍高 | 2026-07]

### 1.2 三重治理缺陷
腾讯云点明 Agent 越权的根因是三重治理缺陷：
1. **权限泛滥**：通配符权限，一个 Token 失守拖垮全系统
2. **审计缺失**：Agent 决策无留痕，事后无法定责
3. **兜底缺失**：无 Human-in-the-Loop 审批，无一键熔断

## 二、最小权限 Least Privilege——Agent 安全基线

### 2.1 最小权限原则
Agent 只授予完成当前任务所需最小权限，禁通配符。PM 设计 Agent 时第一问应是"它需要的最小权限是什么"，不是"给它什么权限能完成任务"。

### 2.2 RBAC 粗粒度 vs Agent 细粒度
| 维度 | 传统 RBAC（粗粒度） | Agent 专属权限（细粒度） |
|---|---|---|
| **授权单位** | 角色（客服/财务/管理员） | 任务（处理退款/查询订单/发送邮件） |
| **权限范围** | 角色对应的全量权限 | 当前任务所需的最小权限集 |
| **时效** | 长期有效 | 任务级动态授权，任务结束回收 |
| **通配符** | 常用 write:* / read:* | 禁用通配符，逐权限明确 |
| **审批** | 角色分配时审批 | 高危操作实时审批 |

### 2.3 任务级动态授权
Agent 权限应随任务动态变化：
- **任务启动**：授予当前任务最小权限
- **任务执行**：高危操作实时审批（Human-in-the-Loop）
- **任务结束**：权限回收
- **异常检测**：检测到越权倾向立即降权/熔断

## 三、阿里云 WAIC 2026 三层统一防护

### 3.1 三层统一一体化防护

## 五、审计追踪——事后定责基线

### 5.1 全量留痕
Agent 每个决策、工具调用、数据访问须全量留痕：谁（Agent 身份）+ 何时（时间戳）+ 做了什么（操作类型+参数）+ 为什么（决策依据）+ 结果（执行结果）。

### 5.2 异常告警
审计系统须实时检测异常：越权倾向、异常频率、危险操作链、预算异常燃烧等，触发告警。

### 5.3 事后定责
事故发生后，审计追踪是定责基础。无审计=事故无法定责=合规风险。腾讯云三重治理缺陷之二就是审计缺失。

## 六、Agent 安全成熟度模型

对标 AI SOC 成熟度，Agent 安全成熟度分级（综合腾讯云/阿里云模型）：

| 级别 | 名称 | 特征 |
|---|---|---|
| L0 | 无防护 | 接大模型即上线，无任何安全措施 |
| L1 | 基础防护 | 有输入/输出过滤，无执行层防护 |
| L2 | 系统防护 | 三段护栏齐全（输入/执行/输出）+ 审计 |
| L3 | 主动防御 | 红队测试 + 最小权限 + Human-in-the-Loop |
| L4 | 形式化验证 | 关键路径数学证明 + 自进化约束 + NIST 准入 |

NIST 2026-07 要求接入核心业务链路须达 L4。PM 应评估团队当前级别并规划升级路径。

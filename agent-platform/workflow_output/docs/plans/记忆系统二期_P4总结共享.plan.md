# Implementation Plan for 记忆系统二期 · P4 总结共享

> 主索引：[记忆系统二期.plan.md](记忆系统二期.plan.md) ｜ 规格 FR-301~305
> 依赖：P1 完成；FR-303 依赖 P2（links）；文件条目进总结依赖 P3 落库形态（可先做文本条目，P3 后补文件条目）。

## 本模块坑点预判

| 坑 | 规避 | 验证 |
|---|---|---|
| 一期「总结恒只读自己」假设遍布代码 | 共享总结用新 scope_owner=PROJECT 标记，老行 user_id 非空语义不变；读取按 (project_id, scope_owner) 分流 | 老个人总结召回不回归 |
| coverage 从 turn 级扩到条目级改坏召回判覆盖 | 新表/新列并存：`memory_entry_coverage`，turn coverage 不动；召回条目侧查新表 | 双表各自断言 |
| 撤销授权后 STALE 重压丢内容/重复压 | 重压取数=当前 ACTIVE 链实时算；worker 幂等（同 summary 同版本只压一次） | 撤销→重压→断言无 child 内容；重复触发只压一次 |
| 废 12h 后删除级联风暴 | 级联只软删条目+标 STALE，重压异步排队；批量删走分批 | 批量删 100 turn 不阻塞请求 |
| 成员压缩通道泄权（成员压了他读不到的） | 取数范围=该成员实时可读条目集（成员校验+ACTIVE 链） | 非成员调压缩端点 403 |

## 实现步骤

- [x] **Step 1：V70 扩列 + entry coverage 表**（FR-301/305）
  - **目标**：summaries 支持项目共享；条目级覆盖表
  - **动作**：`memory_summaries` 加 `scope_owner`（USER/PROJECT，默认 USER 兼容老行）+ `source_entry_ids BIGINT[]`（provenance）；建 `memory_entry_coverage`（UNIQUE NULLS NOT DISTINCT(entry_id,project_id)，随 entry/summary CASCADE）；索引
  - **文件**：`db/migration/V70__memory_summary_share_entry_coverage.sql`
  - **依赖**：P1 全部
  - **验证**：migrate 成功；老总结行 scope_owner=USER 不受影响

- [x] **Step 2：项目共享总结生成 + 读取**（FR-301/303）
  - **目标**：项目总结=项目资产，全员可读、owner/admin 可写
  - **动作**：ConsolidationService 项目分支改造：取数=项目 ACTIVE 条目 ∪ ACTIVE links child 条目（P2 接口）；产出 scope_owner=PROJECT + user_id=NULL + provenance=source_entry_ids；写 entry_coverage；读取端点按 scope_owner=PROJECT 放行全成员；触发权限：owner/admin（手动入口+自动 worker）；总结冲突 pending 裁决人=owner/admin（MemoryConflictResolutionService 项目分支鉴权改）
  - **文件**：`MemoryConsolidationService.java`、`MemoryConsolidationTxService.java`、`MemorySummaryReader.java`、`MemorySummaryController.java`、`MemoryConflictResolutionService.java`
  - **依赖**：Step 1、P2 Step 2（links 查询）
  - **验证**：owner 触发→共享总结全员可读；成员尝试触发项目共享总结 403；嵌套取数含 child 条目

- [x] **Step 3：成员个人压缩通道**（FR-302）
  - **目标**：成员可压项目内容进自己个人总结
  - **动作**：手动总结弹框加「压到我自己的总结」选项：取数=该成员实时可读条目集 → 产出 user_id=自己、scope_owner=USER、project_id=该项目 + 标注来源项目；对项目共享总结零写
  - **文件**：`MemoryConsolidationService.java`、`MemoryConsolidationController.java`（新参数）、前端 `MemoryConsolidationDialog.vue`（选项）
  - **依赖**：Step 2
  - **验证**：成员压缩后仅自己召回得到；项目共享总结不变

- [x] **Step 4：废除 12h 拒删 + 删除级联改造**（FR-304）
  - **目标**：删 turn 随时生效，级联条目
  - **动作**：`DELETE /turns/{id}` 删 12h 拒绝分支；级联：软删 `entries(source_turn_id=T)` → 波及总结（含共享总结，`source_entry_ids` 命中）标 STALE + 通知；worker 重生逻辑接 entry 级 provenance；授权撤销钩子：links 删 → parent 共享总结 STALE（重生取数实时算链）
  - **文件**：`MemoryTurnController.java`/`MemoryTurnViewService.java`（删拒删分支）、`MemoryConsolidationWorker.java`、`MemoryProjectLinkService.java`（撤销钩子）
  - **依赖**：Step 2
  - **验证**：被引用 turn 可删无 403；级联条目软删+总结 STALE→重压力后不含已删内容；撤销授权→重压后无 child 内容

- [x] **Step 5：召回总结读取改造 + 前端**（FR-301/303/305）
  - **目标**：召回读共享总结；标注来源项目
  - **动作**：MemorySummaryReader 项目分支读 scope_owner=PROJECT（全员）+ USER（自己）并集；装配带来源标注（含授权 child 条目来源）；前端总结页签区分「项目共享总结」（全员）/「我的总结」；冲突裁决 UI 权限按 owner/admin
  - **文件**：`MemorySummaryReader.java`、`MemoryRecallPipeline.java`、`MemorySummarySection.vue`、`MemoryConflictSection.vue`、`api/memory.ts`
  - **依赖**：Step 2/4
  - **验证**：成员召回命中共享总结；来源标注正确；成员无裁决按钮

## 整体验证（P4）

- [ ] E2E：owner 触发项目总结 → 成员召回到共享总结 → B 授权进 A 后 A 重压含 B 条目 → B 撤销 → A 总结 STALE 重压不含 B → 成员个人压缩一份自己的
- [ ] 回归：个人总结召回与一期行为一致；删 turn 无 12h 403

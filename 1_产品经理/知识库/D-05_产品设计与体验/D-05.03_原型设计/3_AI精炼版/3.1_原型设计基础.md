# 3.1 原型设计基础

## A.01 核心定义

**原型设计（Prototyping）** 是将抽象的产品概念、信息架构与交互逻辑转化为可视化、可操作、可测试的中间产物的设计过程。原型是"产品思维的第一次物质化"——在投入开发之前，以最低成本验证"做的是不是对的东西"。[来源: Buxton, 2007 "Sketching User Experiences" | 置信度:🔍高]

**一句话定位**：原型设计 = 在造房子之前先搭个模型——不关心砖用什么材质，只关心空间是否好用、动线是否顺畅。

## A.02 保真度谱系

| 保真度 | 表现形式 | 核心价值 | 适用阶段 | 制作耗时 |
|---|---|---|---|---|
| 草图(Sketch) | 纸笔/白板手绘 | 快速探索多种方案可能性 | 探索期 | 5-15分钟/页 |
| 低保真(Lo-Fi) | 灰度线框图，无视觉 | 验证信息架构与功能布局 | 定义期 | 30分钟-2小时/页 |
| 中保真(Mid-Fi) | 带基础交互的线框 | 验证交互流程与操作逻辑 | 设计期 | 2-6小时/页 |
| 高保真(Hi-Fi) | 接近最终产品的视觉+交互 | 可用性测试与开发交付 | 验证期 | 1-3天/核心流程 |
| 代码原型(Code Proto) | 真实代码实现的原型 | 验证技术可行性与复杂交互 | 技术验证期 | 1-5天/功能模块 |

**关键洞察**：保真度不是越高越好——过早进入高保真会锁定思维，过早进入代码会浪费工程资源。正确的节奏是"Low-Fi广泛探索 → Mid-Fi聚焦收敛 → Hi-Fi精准验证"。[来源: IDEO方法论; Google Ventures Design Sprint | 置信度:🔍高]

## A.04 边界与不含什么

**原型设计包含**：保真度选择策略、页面布局设计、交互连线与状态管理、组件复用、原型测试方法、AI辅助原型生成。

**原型设计不含**：信息结构定义（→D-05.01）、交互行为逻辑定义（→D-05.02）、视觉设计系统（→D-05.04）、前端代码实现、用户研究方法（→D-03）。

## B.02 原型分类维度

### 按媒介分

| 类型 | 优势 | 劣势 | 典型场景 |
|---|---|---|---|
| 纸面原型 | 零门槛、极速、无编辑器约束 | 不可复用、难以传递 | 早期探索、头脑风暴 |
| 数字原型 | 可复用、可分享、可迭代 | 工具学习成本 | 正式项目流程 |
| 代码原型 | 真实交互、技术验证 | 工程成本高 | 复杂交互/性能验证 |

### 按交互深度分

| 类型 | 交互能力 | 典型用途 |
|---|---|---|
| 静态原型 | 无交互，仅展示页面 | 快速对齐界面布局 |
| 点击原型(Hotspot) | 热区跳转，无过渡 | 流程走通验证 |
| 交互原型(Interactive) | 状态切换+过渡动效+条件逻辑 | 可用性测试 |
| 逻辑原型(Logic) | 变量绑定+条件分支+数据驱动 | 复杂业务逻辑模拟 |

## I.01 核心术语

| 术语 | 定义 |
|---|---|
| 原型(Prototype) | 产品概念的具象化中间产物，可被交互和测试 |
| 线框图(Wireframe) | 低保真的页面结构布局图，灰度无视觉装饰 |
| 保真度(Fidelity) | 原型与最终产品在视觉/交互/内容上的相似程度 |
| 热区(Hotspot) | 静态页面上的可点击区域，用于模拟交互跳转 |
| 连线(Connection) | 原型工具中页面或组件之间的跳转链接 |
| 状态(State) | 组件在不同条件下的视觉表现（默认/hover/active/disabled/error） |
| 变体(Variant) | 同一组件的不同状态/样式组合 |
| 组件(Component) | 可复用的UI单元，修改一处全局同步 |
| 设计令牌(Design Token) | 设计系统中最小的样式决策单元（颜色/间距/字号等） |
| 交互规格(Interaction Spec) | 描述交互行为的文档，含触发条件/响应动作/状态转换 |
| 可点击原型(Clickable Proto) | 通过热区连接模拟页面跳转的最低交互原型 |
| 模拟数据(Mock Data) | 原型中代替真实数据的占位数据 |

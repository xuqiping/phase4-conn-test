# 提示词与生成术语

> 维度勾选：D.01✓ D.05✓ G.02✓ I.01✓ I.02✓ I.03✓ I.10✓ I.12✓ A.04✓ D.02✓ E.04✓ +中英对照表

## 1. 提示词 / Prompt

| 字段 | 内容 |
|---|---|
| 英文全称 | Prompt |
| 定义 | 输入给LLM的文本指令或上下文，用于指导模型生成特定输出 |
| PM解读 | Prompt不是"搜索关键词"，而是"给实习生的工作说明书"。同样的事，说清楚和说不清楚，输出天差地别 |
| 常见误解 | 以为Prompt越长越好（冗余Prompt增加Token消耗且未必提升效果；关键在结构化与约束清晰） |
| 来源 | [📚训练知识]

## 2. 零样本 / Zero-shot

| 字段 | 内容 |
|---|---|
| 英文全称 | Zero-shot |
| 定义 | 不给模型任何示例，直接用指令要求输出。完全依赖模型预训练知识 |
| PM解读 | Zero-shot是LLM"即插即用"的体现，也是产品原型最快验证的方式。但复杂任务往往不够 |
| 来源 | [📚训练知识]

## 3. 少样本 / Few-shot

| 字段 | 内容 |
|---|---|
| 英文全称 | Few-shot |
| 定义 | 在Prompt中提供少量示例（通常3-5个），让模型理解输入-输出的期望格式和模式 |
| PM解读 | Few-shot是用"例子"代替"说明书"——当文字描述不够精确时，几个示例比长段描述有效得多 |
| 口径注意 | Few-shot的示例数量和选择质量直接决定效果；坏示例比没有示例更糟糕 |
| 来源 | [📚训练知识]

## 4. 思维链 / Chain-of-Thought / CoT

| 字段 | 内容 |
|---|---|
| 英文全称 | Chain-of-Thought |
| 缩写 | CoT |
| 定义 | 在Prompt中引导模型"逐步思考"，或在输出中展示推理过程的提示技术 |
| PM解读 | CoT是LLM推理能力的"开关"。不是模型不会推理，而是不引导就不一定自动推理。加一句"让我们逐步思考"可能显著提升准确率 |
| 常见误解 | 以为CoT是模型架构（CoT是提示技术，不是模型结构；但推理模型如o1会自动CoT） |
| 来源 | Wei et al., 2022 [📚训练知识]

## 5. 思维树 / Tree-of-Thought / ToT

| 字段 | 内容 |
|---|---|
| 英文全称 | Tree-of-Thought |
| 缩写 | ToT |
| 定义 | CoT的进阶版：让模型同时探索多条推理路径，评估每条路径的价值，选择最佳路径继续深挖 |
| PM解读 | CoT是"一条路走到黑"，ToT是"多路并行+筛选"。搜索/规划类任务更适合ToT |
| 来源 | Yao et al., 2023 [📚训练知识]

## 6. 检索增强生成 / Retrieval-Augmented Generation / RAG

| 字段 | 内容 |
|---|---|
| 英文全称 | Retrieval-Augmented Generation |
| 缩写 | RAG |
| 定义 | 先从外部知识库检索相关文档，再将检索结果作为上下文喂给LLM生成回答的技术架构 |
| PM解读 | RAG是"让模型翻资料再回答"——弥补LLM知识截止和幻觉问题的最主流方案。几乎所有企业级AI产品都用RAG |
| 常见误解 | ①以为RAG=搜索引擎+LLM（RAG的检索是向量语义检索，不是关键词搜索）②以为加了RAG就没有幻觉（RAG只能降低、不能消除幻觉） |
| 口径注意 | RAG详细方法论见D-19.08_RAG检索增强；本叶子只做术语定义 |
| 来源 | Lewis et al., 2020 [📚训练知识]

## 7. 幻觉 / Hallucination

| 字段 | 内容 |
|---|---|
| 英文全称 | Hallucination |
| 定义 | LLM生成看似合理但与事实不符的内容。包括：编造不存在的事实、引用不存在的来源、混淆已有信息 |
| PM解读 | 幻觉是LLM产品的"头号风险"。理解它的关键是：LLM的目标是"生成合理续写"而非"陈述事实"，二者并不等价 |
| 分类 | ①事实性幻觉（编造事实）②忠实性幻觉（与给定上下文矛盾）③推理幻觉（推理链条有误） |
| 常见误解 | 以为只有小模型才会幻觉（GPT-4也会幻觉，只是概率较低；所有LLM都无法完全消除） |
| 来源 | [📚训练知识]

## 8. 温度 / Temperature

| 字段 | 内容 |
|---|---|
| 英文全称 | Temperature |
| 定义 | 控制LLM输出随机性的参数，范围0-2。越高越随机/创意，越低越确定/保守 |
| PM解码 | Temperature=0适合代码/格式化输出（要确定性）；Temperature=0.7-1.0适合创意写作（要多样性）；>1.2通常过于混乱 |
| 常见误解 | 以为Temperature=0就一定输出相同结果（还有Top-p等采样参数影响；且不同API实现可能有浮点差异） |
| 来源 | [📚训练知识]

## 9. 核采样 / Top-p / Nucleus Sampling

| 字段 | 内容 |
|---|---|
| 英文全称 | Top-p / Nucleus Sampling |
| 定义 | 只从概率累积达到p的最小Token集合中采样。p=0.1表示只从概率前10%累积的Token中选 |
| PM解读 | Top-p比Temperature更精细：它过滤的是"不可能的选项"而非"调整概率分布"。通常与Temperature配合使用 |
| 来源 | [📚训练知识]

## 10. Top-k采样

| 字段 | 内容 |
|---|---|
| 英文全称 | Top-k Sampling |
| 定义 | 只从概率最高的k个Token中采样。k=50表示只从概率前50的词中选 |
| PM解读 | Top-k是"硬截断"（只看前k个），Top-p是"软截断"（看概率累积）。Top-p更灵活，已是主流方案 |
| 来源 | [📚训练知识]

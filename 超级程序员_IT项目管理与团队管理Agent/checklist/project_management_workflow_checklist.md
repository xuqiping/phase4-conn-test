# 项目管理方法论 Workflow Checklist

Use this checklist after completing every step of `workflow/project_management_workflow.md`. Every item must be answered **yes** before the step is considered complete. If any item is **no**, fix the output and re-validate.

## Step 1: PMP项目管理标准

- [ ] 项目章程产出：目标/高层级范围/干系人/PM授权/假设约束
- [ ] 干系人登记册完整：权力/利益矩阵四象限分类
- [ ] WBS遵循100%规则：子任务完全覆盖父任务，无遗漏无重复
- [ ] 工作包粒度8-80小时，远期用规划包（滚动式规划）
- [ ] CPM关键路径识别：零浮动路径明确，总工期确定
- [ ] CCPM关键链（如适用）：资源缓冲+汇合缓冲+项目缓冲已配置
- [ ] 进度基线：三点估算或类比估算，蒙特卡洛模拟（大型项目）
- [ ] 成本基线：BAC/PV/应急储备/管理储备
- [ ] 风险登记册：≥10条风险，每条有概率/影响/优先级/应对策略/责任人
- [ ] 沟通计划：频率/渠道/内容/责任人明确
- [ ] EVM监控：SPI/CPI/EAC/TCPI每周计算
- [ ] 变更控制：CCB组建，变更日志运行
- [ ] 所有`[参考: ...]`标注指向的知识库文件真实存在且章节可定位

## Step 2: 敏捷Scrum

- [ ] 3角色定义清晰：PO/SM/Dev Team职责无重叠
- [ ] 5事件节奏运行≥1个Sprint：计划/站会/评审/回顾全部完成
- [ ] Sprint长度固定（推荐2周），未来6个月不变
- [ ] Product Backlog有序，PO维护，持续梳理
- [ ] WSJF优先级公式应用或替代方法（MoSCoW/价值-effort矩阵）
- [ ] Story符合INVEST原则：独立/可协商/有价值/可估算/小/可测试
- [ ] DoD定义明确且团队全员同意，不可妥协
- [ ] Sprint Goal每个Sprint都有，工作围绕目标展开
- [ ] DORA四指标基线建立，目标精英级
- [ ] Velocity稳定（±10%波动），Burndown图正常
- [ ] Sprint回顾产出≥1个改进行动项并跟踪
- [ ] 规模化方案（如适用）：SAFe/LeSS/Nexus选型理由充分

## Step 3: 瀑布模型与混合方法论

- [ ] 方法论选择有明确理由：瀑布/敏捷/混合，基于需求稳定性/合规/规模/团队经验
- [ ] 瀑布7阶段定义：需求→设计→编码→测试→集成→部署→维护
- [ ] V模型映射（如适用）：左侧设计阶段与右侧测试阶段对称
- [ ] 基线控制：需求基线/设计基线/产品基线，每阶段结束建立
- [ ] 配置管理：配置项清单+版本号规则+变更控制流程
- [ ] 变更控制：CCB审批+影响分析+基线更新
- [ ] 文档体系：每阶段产出标准化文档，可追溯可审计
- [ ] 评审门禁：每阶段FTR正式技术评审，不通过不进入下阶段
- [ ] 混合模式（如适用）：外层瀑布里程碑+内层敏捷Sprint，桥梁设计清晰
- [ ] 混合模式适用场景匹配：政府/金融/医疗等合规+响应变化需求

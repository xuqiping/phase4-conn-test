# 3.3 Better-Worse分析

## 为什么需要Better-Worse

仅靠KANO五类别定性判定，**无法回答"同类别需求内部如何排序"**——当10个需求都是"必备型"时，谁先做？Better-Worse系数（又称满意度增量分析）通过量化**满足该需求能增加多少满意度、不满足会降低多少满意度**，在同类别内提供排序依据。[来源:📚训练知识 | 📚中]

## 两个核心系数

### 满意度系数（Better / SI = Satisfaction Index）

> **如果提供这个需求，满意度会提升多少？**

$$SI = \frac{A + O}{A + O + M + I}$$

- 分子：魅力+期望（提供后满意度提升的类别）
- 分母：所有有效类别（排除Q和R）
- 范围：0~1，值越大→提供后满意度提升越多

### 不满意度系数（Worse / DSI = Dissatisfaction Index）

> **如果不提供这个需求，满意度会降低多少？**

$$DSI = \frac{O + M}{A + O + M + I} \times (-1)$$

- 分子：期望+必备（不提供后满意度下降的类别）
- 取负值使DSI在坐标系中位于下方
- 范围：-1~0，绝对值越大→不提供后满意度损失越大

## 四象限解读

以SI为纵轴、DSI为横轴，原点为阈值交叉点，形成四象限：

```
         SI(改善提升)
              ↑
     Ⅳ       |       Ⅰ
   魅力优势区  |   高优先区
  (高SI低DSI) | (高SI高DSI)
              |
  ------------+----------→ DSI(缺失损失)
              |
     Ⅲ       |       Ⅱ
   低优先区   |   必备优势区
  (低SI低DSI) | (低SI高DSI)
              |
```

| 象限 | 特征 | 策略 |
|---|---|---|
| **Ⅰ 高优先区** | SI高且DSI高 | **必须做且要做好**——既有改善空间又有缺失风险 |
| **Ⅱ 必备优势区** | SI低DSI高 | **必须做但不期望惊喜**——不做有严重风险，做了用户也不会额外满意 |
| **Ⅲ 低优先区** | SI低DSI低 | **可暂缓**——做不做对满意度影响都不大 |
| **Ⅳ 魅力优势区** | SI高DSI低 | **差异化亮点**——做了能出彩，不做也没损失，是创新突破方向 |

## 阈值选择

四象限的划分依赖于SI和DSI的**阈值线**位置，常见取法：

| 阈值取法 | 计算方式 | 适用场景 |
|---|---|---|
| **均值法** | 所有需求的SI/DSI均值作为阈值 | 通用场景，简单直观 |
| **中位数法** | SI/DSI中位数 | 对极端值不敏感 |
| **固定阈值法** | SI=0.5, DSI=-0.5 | 标准化对比（跨产品/跨团队） |
| **业务定制法** | 按业务权重调整 | 有明确战略侧重时 |

> 实战建议：先用均值法快速定位，再用固定阈值法(0.5/-0.5)做跨项目横向对比。[来源:📚训练知识 | 📚中]

## 同类别内排序逻辑

Better-Worse的核心价值在于**同类别需求内部的精排**：

| KANO类别 | 内部排序依据 |
|---|---|
| **M(必备)** | DSI绝对值越大→越紧急（不做的损失越大） |
| **O(期望)** | SI×DSI绝对值越大→优先级越高（改善空间+缺失风险双高） |
| **A(魅力)** | SI越大→差异化价值越高（有限资源投到最大惊喜点） |
| **I(无差异)** | 按成本排序→低成本可做，高成本砍掉 |

## 排序优先级总逻辑

```
必备(M) > 期望(O) > 魅力(A) > 无差异(I)
  ↓          ↓          ↓         ↓
 DSI排序   SI×|DSI|排序  SI排序   成本排序
```

> 关键认知：**KANO解决"做什么类别"的问题，Better-Worse解决"同类别内先做什么"的问题**——两者配合才是完整的优先级体系。[来源:📚训练知识 | 📚中]

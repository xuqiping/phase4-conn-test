# 3.4 流失分析与预警

## G.02 核心方法

**流失分析**是留存的反面——研究用户为什么离开、什么时候离开、如何在他们离开前干预。

## 流失定义

| 流失类型 | 定义 | 判断标准 |
|---|---|---|
| 硬流失 | 用户明确注销/删除账号 | 注销行为 |
| 软流失 | 用户不再回访，但账号仍在 | 连续N天未登录（N因产品而异） |
| 付费流失 | 付费用户停止续费 | 订阅到期未续费 |
| 功能流失 | 用户仍活跃但不再使用某功能 | 功能使用频率降为0 |

**软流失判断窗口参考**：

| 产品类型 | 留存频率 | 流失判断窗口 |
|---|---|---|
| 日活型(社交/工具) | 每天 | 连续7天未登录 |
| 中频型(电商/新闻) | 每周2~3次 | 连续14天未登录 |
| 低频型(SaaS/旅游) | 每月1~5次 | 连续30天未登录 |
| 订阅型(视频/音乐) | 月付 | 到期未续费 |

## 流失预警信号

### 行为预警信号

| 信号 | 含义 | 预警等级 |
|---|---|---|
| 登录频率下降 | 从每日→每3日→每周 | 🔴高 |
| 核心功能使用减少 | 发帖/下单/搜索频次下降 | 🔴高 |
| 会话时长缩短 | 从10分钟→5分钟→2分钟 | 🟡中 |
| 负面行为增加 | 投诉/退款/差评 | 🟡中 |
| 探索行为减少 | 不再浏览新内容/功能 | 🟢低（早期信号） |
| 仅消费被动内容 | 从创造→消费→潜水 | 🟢低 |

### 流失漏斗模型

```
活跃用户 → 低活跃 → 边缘活跃 → 沉默 → 流失
(健康)   (早期预警)  (中期预警)  (晚期)  (不可逆)
```

| 阶段 | 特征 | 干预策略 | 成功率 |
|---|---|---|---|
| 低活跃 | 频率下降30%+ | 个性化Push/优惠 | 60%~70% |
| 边缘活跃 | 频率下降60%+ | 召回活动+核心功能引导 | 30%~40% |
| 沉默 | 连续N天未登录 | 邮件/短信触达 | 10%~20% |
| 已流失 | 超过判断窗口 | 大力度回归优惠 | 5%~10% |

## 流失归因框架

### 5大流失原因

| 原因类型 | 典型场景 | 诊断方法 |
|---|---|---|
| 价值不足 | 产品未能持续满足需求 | 核心功能使用率 vs 留存相关性 |
| 竞品替代 | 用户被竞品吸引走 | 竞品公开数据+用户调研 |
| 体验差 | 性能/BUG/交互差 | 崩溃率+差评+客服工单 |
| 场景消失 | 用户的原始需求消失 | 行业趋势+季节性分析 |
| 过度打扰 | 推送过多/广告太多 | 卸载前行为分析+卸载问卷 |

## 预警机制设计

### 定量预警规则

```
IF 用户过去7天登录次数 < 历史均值 × 50%
   AND 核心功能使用 < 历史均值 × 40%
THEN 触发「低活跃预警」→ 自动推送个性化内容

IF 用户连续14天未登录
THEN 触发「沉默预警」→ 发送召回邮件

IF 用户订阅到期前7天 且 使用频率 < 阈值
THEN 触发「续费风险预警」→ 客服/优惠干预
```

| 特征类别 | 典型特征 | 权重参考 |
|---|---|---|

| 负面特征 | 投诉次数、退款次数 | 中 |

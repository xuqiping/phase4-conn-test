# 价表模型选择 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增价表只能选择启用全局供应商中尚未配置的模型，编辑时锁定模型身份。

**Architecture:** 后端实时解析 `llm_providers.models`，按供应商类别映射计费 kind，并与现有 `(providerId, model)` 做差集。创建时锁定供应商行并二次校验，编辑时拒绝改变 provider/model/kind，从而不信任前端下拉。

**Tech Stack:** Spring Boot、MyBatis-Plus、Jackson、Vue 3、Naive UI、JUnit/Mockito、Vitest。

---

## 技术坑点、安全与运维

| 技术点 | 坑 | 规避与验证 |
|---|---|---|
| JSON 模型列表 | 空、坏 JSON、重复模型导致 500/重复候选 | 容错为空并 WARN；trim+去重；坏 JSON 单测 |
| 类别映射 | `EMBEDDING` 与计费 `EMBED` 名称不同 | 集中映射表；四类参数化测试，未知类别跳过并 WARN |
| 并发创建 | 两个管理员同时通过“未配置”检查 | 创建事务先 `SELECT provider FOR UPDATE`，锁内复查价表；并发测试 |
| 历史价表 | 停用供应商或编辑身份破坏旧询价 | 候选只看 ACTIVE；列表/询价保留历史；更新拒绝身份变化 |

- [ ] `pricing:manage` 覆盖候选、创建、编辑；不返回 apiKey/config。
- [ ] providerId/model/kind 服务端校验，错误使用固定业务文案。
- [ ] **做**：坏模型 JSON WARN 日志、创建日志含 providerId/model/kind；沿用 traceId。
- [ ] **不做**：缓存（供应商和价表配置量小，实时差集避免失效问题）、新配置开关、第三方调用、运维页。
- [ ] **后续再说**：供应商/模型达到万级再做分页；当前批量两次查询，无 N+1。
- [ ] 告警建议：模型 JSON 解析 WARN 或重复创建冲突持续增长；不需表分区。

## 功能联动点

| 触发 | 联动对象 | 预期变化与边界 |
|---|---|---|
| 打开新增 | 候选列表 | 重新加载 ACTIVE 未配置模型；空集显示空状态 |
| 选择候选 | provider/model/kind | 三项一起赋值；清空选择则三项一起清空，不保留半选择 |
| 创建成功 | 价表+候选 | 新行出现，相同组合从候选消失 |
| 打开编辑 | 身份字段 | 三项锁定；只允许价格、模式、生效时间变化 |
| 供应商停用 | 新增候选/历史价表 | 候选消失；历史行和历史询价不变 |

## 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| 差集 | 从全集去掉已有项 | 全局 5 模型减已配置 2 个，剩 3 个 |
| 行锁 | 事务期间让同一行的并发操作排队 | 同供应商的两个创建请求串行复查 |
| 三元身份 | 唯一说明价表归属的三项 | providerId + model + kind |

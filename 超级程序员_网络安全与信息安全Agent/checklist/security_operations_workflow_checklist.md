# Security Operations Workflow Checklist

在完成 `workflow/security_operations_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别安全运维/应急响应需求场景

- [ ] 已明确场景类型（安全日志分析/SIEM建设/入侵检测部署/应急响应体系/威胁狩猎/备份恢复/安全运营外包/AI驱动SOC）
- [ ] 已识别SOC成熟度（无SOC/基础SOC/智能SOC/自治SOC）
- [ ] 已提取IT资产规模（服务器/终端/网络设备/云资产/应用系统数量）
- [ ] 已提取主要威胁类型（勒索/APT/内部威胁/数据泄露/DDoS/供应链/Web入侵/钓鱼）
- [ ] 已识别现有工具（SIEM/EDR XDR/防火墙IDS IPS/SOAR/威胁情报）
- [ ] 已提取关键痛点（告警噪音/检测滞后/响应慢/日志不全/缺乏情报/人员不足）
- [ ] 已对照知识库核心能力完成初步判断（告警噪音→SIEM漏斗+UEBA/响应慢→SOAR+黄金30分钟/勒索→备份+WORM/云原生→eBPF/AI驱动→AI大模型+Agentic AI）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出安全运维/应急响应方案

- [ ] 如为SIEM，六层漏斗架构已覆盖（采集→归一化→存储→分析→响应→可视化）
- [ ] 如为SIEM，三阶段成熟度已说明（基础检测MTTD<4h/智能分析MTTD<1h/自治运营MTTD<15min）
- [ ] 如为SIEM，UEBA五维行为基线已输出（用户/设备/应用/数据/网络维度+评分模型）
- [ ] 如为SIEM，某集团案例已引用（2000+规则/告警量降70%/检出率提升3倍）
- [ ] 如为IDS IPS，分层部署原则已覆盖（边界IPS/核心NIDS/关键HIDS/云原生eBPF/工控OT旁路白名单）
- [ ] 如为IDS IPS，检测技术演进已说明（签名检测/行为签名/AI级联90+10/加密流量检测94%）
- [ ] 如为IDS IPS，规则生命周期管理已输出（开发→灰度→全量→监控/12万精简至3.5万案例）
- [ ] 如为应急响应，NIST六阶段已覆盖（准备→检测分析→遏制→根除→恢复→事后活动）
- [ ] 如为应急响应，CERT-RMM五级成熟度已说明
- [ ] 如为应急响应，勒索软件专项已输出（检测→SOAR 90秒隔离→黄金30分钟→不可变备份恢复）
- [ ] 如为应急响应，某金融机构案例已引用（三级应急体系/勒索零扩散/RTO<4h）
- [ ] 如为应急响应，应急演练矩阵已覆盖（桌面推演/模拟演练/实战演练/BAS持续验证）
- [ ] 如为SOC运营，KPI体系已输出（检测指标/响应指标/效果指标/成熟度指标）
- [ ] 如为SOC运营，SOAR平台设计已说明（Playbook编排/多工具集成/三层安全刹车/选型）
- [ ] 如为SOC运营，AI驱动SOC演进已覆盖（AI告警分级/攻击链还原/威胁狩猎/Agentic AI自主响应）
- [ ] 如为SOC运营，人员能力建设已输出（L1-L4分级/持续培训/认证路径）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 响应时间目标（MTTD<1h/MTTR<4h/黄金30分钟）准确
- [ ] 已向用户交付最终答案

## Overall

- [ ] 工作流中的所有步骤已按顺序执行，没有跳过
- [ ] 每一步都已与其检查清单部分进行交叉验证
- [ ] 没有在任何检查清单部分通过前提前进入下一步
- [ ] `task/current_task.md` 已更新完成记录
- [ ] 所有 `[参考: ...]` 标注均指向存在的知识库文件

# 3.3 需求建模与依赖关系分析

## 需求建模：将文字需求转化为视觉结构

### 三种核心建模工具

| 建模工具 | 适合场景 | 核心元素 | PM产出 |
|---|---|---|---|
| **用例图** | 识别系统边界与角色交互 | 参与者/用例/关系 | 功能范围+角色权限 |
| **流程图** | 描述操作步骤与分支逻辑 | 起止/操作/判断/分支 | 用户操作流程 |
| **状态图** | 描述对象状态变迁 | 状态/迁移/事件/条件 | 数据生命周期 |

### 用例图（Use Case Diagram）

```
┌─────────────── 系统边界 ───────────────┐
│                                        │
│   参与者: PM        用例: 创建需求      │
│      ○──────→   ○ 审批需求            │
│                                        │
│   参与者: 审批者     用例: 审批需求 ←───┘
│      ○──────→   ○ 驳回需求            │
│                                        │
│   参与者: 开发       用例: 领取需求      │
│      ○──────→   ○ 更新进度            │
│                                        │
└────────────────────────────────────────┘
```

PM关注点：每个参与者能看到/做什么？哪些用例是核心？哪些是边缘？

### 流程图：需求逻辑的骨架

| 流程类型 | 适用 | 关键节点 |
|---|---|---|
| **主营流程** | 标准操作路径（Happy Path） | 起点→操作→终点 |
| **分支流程** | 条件判断后的分叉 | 判断节点→A/B路径 |
| **异常流程** | 出错/超时/非法操作 | 异常触发→处理→恢复/终止 |
| **回退流程** | 操作撤销/状态回退 | 回退触发→状态还原→通知 |

> PM常犯的错误：只画Happy Path，忘了异常和回退。80%的bug来自那20%的异常路径。[来源:📚训练知识]

### 状态图：数据生命周期

```
需求状态流转：

草稿 → 提交 → 审批中 → 已通过 → 开发中 → 测试中 → 已上线
                  │                      │
                  ↓                      ↓
               已驳回 → 修改后重新提交   测试失败 → 返工
```

PM关注点：每个状态由谁触发？什么条件下可以前进/回退？停滞状态如何处理？

## 依赖关系分析

### 依赖类型

| 依赖类型 | 含义 | 举例 | 风险 |
|---|---|---|---|
| **前置依赖** | A必须在B之前完成 | 用户注册 → 下单 | 前置延迟→后续全部延迟 |
| **数据依赖** | A需要B的输出作为输入 | 商品信息 → 购物车 | 数据格式变更→连锁影响 |
| **技术依赖** | A依赖B的技术实现 | 前端展示依赖后端API | 技术方案未定→需求悬空 |
| **逻辑互斥** | A和B不能同时存在 | 折扣A与折扣B互斥 | 需求冲突未识别→开发返工 |
| **资源竞争** | A和B争抢同一资源 | 两个需求都要用推荐位 | 优先级必须明确 |

### 依赖矩阵

```
       需求A  需求B  需求C  需求D  需求E
需求A   -     前置    -     互斥    -
需求B   -     -      数据   -      -
需求C   -    数据→    -    技术    -
需求D  互斥    -     技术    -     资源
需求E   -     -      -     资源    -

→ 关键路径：需求A → 需求B → 需求C → 需求D
→ 风险点：A-D互斥，需提前决策取舍
```

## 冲突检测与约束识别

### 冲突检测清单

| 检查项 | 问题 | 处理方式 |
|---|---|---|
| 逻辑冲突 | 需求A和B说的是矛盾的？ | 标记冲突→与利益相关方确认优先级 |
| 体验冲突 | 功能A的交互与功能B矛盾？ | 设计统一规范 |
| 数据冲突 | 同一数据在不同需求中的定义不一致？ | 统一数据模型 |
| 时间冲突 | 两个需求的交付时间冲突？ | 排优先级 |

### 约束识别

| 约束类型 | 来源 | 如何识别 |
|---|---|---|
| **技术约束** | 技术架构限制 | 与技术负责人确认 |
| **合规约束** | 法律/监管要求 | 法务审核 |
| **时间约束** | 硬性截止日期 | 业务方确认 |
| **资源约束** | 人力/预算限制 | 项目管理确认 |
| **兼容性约束** | 旧版本向后兼容 | 技术评估 |

## AI辅助四象限与前沿趋势

### 一、LLM自动估算影响力与复杂度

**场景**：需求量大(>30条)时，PM逐条评估价值/复杂度耗时过长

**AI辅助流程**：
1. 输入需求描述（用户故事/PRD片段）
2. LLM生成：
   - **影响力预估**：基于需求描述中的关键词（"全部用户"/"支付流程"/"性能优化"等）推断影响面和商业价值
   - **复杂度预估**：基于需求描述中的技术关键词（"跨系统"/"实时"/"AI推理"等）推断实现复杂度
3. 生成初步四象限散布图
4. PM审核修正（重点关注"跨象限"误判项）

**Prompt模板示例**：
```
你是产品优先级分析助手。以下是N条需求描述，请为每条需求评估：
1. 影响力(1-5)：[1=极低...5=极高]，附推理依据
2. 复杂度(1-5)：[1=极低...5=极高]，附推理依据
3. 建议象限：[Q1/Q2/Q3/Q4]
4. 置信度：[高/中/低]

需求列表：
{需求列表}
```

### 二、动态象限漂移预警

**问题**：需求的价值和复杂度随时间变化——技术栈升级可能降低复杂度，竞品动作可能提升价值

**AI漂移预警机制**：
1. **基线锁定**：首次四象限评估时锁定各需求坐标(timestamped)
2. **触发信号**：
   - 技术债清理完成 → 重新评估相关Q2需求的复杂度
   - 竞品发布新特性 → 重新评估同类需求的价值
   - 用户数据变化 → 重新评估影响面
3. **预警输出**：
   - "需求A从Q2漂移到Q1（复杂度降低），建议提升优先级"
   - "需求B从Q1漂移到Q2（价值被重新评估），建议调整排期"

### 三、AI辅助四象限的精度局限

| 局限 | 原因 | 缓解方法 |
|---|---|---|
| 价值预估偏差大 | LLM不了解业务上下文 | 提供OKR/核心指标作为上下文 |
| 复杂度预估不准 | LLM不了解技术架构 | 提供系统架构图/Tech Lead评审 |
| 忽略组织政治 | AI无法感知利益相关者博弈 | PM补充"利益相关者权重" |
| 过度自信 | LLM倾向给出高置信度评分 | 强制要求附推理依据+参考文献 |

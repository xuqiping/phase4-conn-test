# 已解决
1. 新增价表改为从全局供应商的未配置模型下拉选择；已有 provider 专属价和历史全局价占用的同名模型均不会重复出现，后端创建接口同步防绕过
2. 图片模型设置单价报 500 ✅ —— 根因 `LlmProviderMapper.selectByIdForUpdate` 用 `deleted = false` 撞 PG 的 INTEGER 列（`V6:32`），所有 kind 创建价表都会 500，用户先配图片撞到而已。改为 `deleted = 0`；前端 savePricing 加 sanitizePricingPayload 清非 VIDEO 行的 videoBillingMode 泄漏（commit 1）
3. 价目表导出 / 模板上传 ✅ —— 镜像 LLM 供应商 export/import：`GET /pricing/export`（blob 下载）、`GET /pricing/template`（联动供应商未配置模型，区分 LLM/图片/视频）、`POST /pricing/import`（upsert 按 providerId+model+kind+hasReference，存在覆盖价格，上限 200，逐行容错）。前端三按钮 + 二次确认 + 客户端预检（commit 2）
4. 视频区分有无参考视频定价 ✅ —— V95 加 `has_reference BOOLEAN NOT NULL DEFAULT FALSE`；`findEffective` 加谓词 + fallback 到 false 行（不区分的模型配 1 行即可）；worker 从 `request.getAttachments()` 的 `kind=="video"` 算标志（不用 taskType，它被重载不可靠；首尾帧图 kind=="image" 不算参考视频）；前端表单加「是否含参考视频」开关 + 列表「参考视频」列（commit 1）
5. 视频生成后查看推送参数 + 是否有视频参考标志（用户追加）✅ —— `MediaTaskVO.hasReference` 计算字段（list/detail 都返）；VideoGenView 任务头标签 + 历史列；Canvas 节点角标 + 属性面板接 MediaTaskRequestDetails 面板。**推送参数已脱敏落库在 request_config.providerRequestSnapshot，无需新 DB 列**（commit 3-4）
6. 视频模型只能配有参考视频，或者单独配无参考视频 ✅ —— 根因：新增价表候选把「已配过无参考价的 VIDEO 模型」整条过滤掉，而编辑又禁止改身份（hasReference 不可改），UI 上没有任何入口能补第二行。修复（2026-08-14）：
   - 后端 `PricingConfigService.availablePricingModels`：VIDEO 候选改为「两面（有参考/无参考）都配齐才排除」，只配一面时候选保留并带 `hint` 提示（如「已配『无参考』价，本次新增为『有参考』价行」）；
   - 前端候选下拉 label 追加 hint；`onCandidateChange` 切候选时复位 `hasReference`（防上一行遗留值泄漏）；编辑模式 hasReference 开关 disabled（与后端「身份不可改」对齐，保存不再报错）。
   - 验证：`PricingConfigServiceTest` 30/30（新增 2 例：只配 false → 候选保留带 hint；两面配齐 → 候选消失）；实测 Cdance2.0 配完无参考后候选仍出现（带提示），API 创建 hasReference=true 行成功后候选消失。

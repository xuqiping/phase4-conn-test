# Phase 0 · 商业前置分析（值不值得做）

你是商业分析师 + 技术决策者。这是本工作流**区别于纯 SDD 的独特层**——SDD 默认"项目值得做"直接写规格；你先回答"做给谁、凭什么赢、怎么赚钱"。以原文为唯一权威，完整执行其「动作清单」，产出其「产物」，满足其「出口条件」：
→ `2_编程类可迭代workflow/Phase0_商业前置分析.md`

`$ARGUMENTS` 作为待分析的项目想法（若为空，问用户要一句话需求再开工）。

## 输入

- 一个项目想法（哪怕只有一句话）

## 必做（原文 7 步动作清单）

1. **需求分析**：解决什么问题？核心场景？最小可用范围在哪？
2. **联网分析竞品**：全球已有谁在做？强弱在哪？差异化空间？（需联网能力）
3. **分析受众群体**：谁会用？画像 / 痛点 / 付费意愿 / 获客渠道
4. **提升优化思路**：基于前三步把原始想法迭代得更锐利
5. **商业模式分析**：变现路径 / 推广渠道 / 定价方案与依据（参考行业行情）
6. **技术选型**：基于以上定技术栈（**服从商业模式，不是反过来**）
7. **定基调与总体规范初版**：跨模块通用约定（中英双语、授权体系、统一鉴权等）写进 `AGENTS.md` 初稿——后续所有模块的地基

## 产物

- `workflow_output/docs/项目分析/项目分析报告.md` —— 深度报告式，覆盖上面 1–5（核心交付）
- 技术选型结论 → 进报告 + Phase 1 的 architecture
- `workflow_output/项目规范约束/AGENTS.md` 初版 —— 项目级 AI 指令，Phase 3 持续织入
- 拷贝 `2_编程类可迭代workflow/项目模板/` 起新项目骨架（自带 `scripts/check_all` 最小质量门，Phase 3 起 commit 前必跑）

## 避坑（原文）

- **不要跳过商业分析直接写码**——一个人公司最大的浪费不是写错代码，是做出没人要的东西。
- 技术选型服从商业模式（"我想用 Rust" ≠ 商业需要 Rust）。
- 总体规范一旦定下，后续模块必须基于它开发。

## 技术坑点预判（全轮通用）

1. **事务回滚吞钱（缺陷1根因复现面）**：`chargeGroup` 旧结构「先扣池后卡限额、限额失败整单回滚」——重构后任何一腿失败不得回滚已成功腿：瀑布改为**各腿独立条件 UPDATE + 组内 try/catch 分级**，只有「组池行缺失」这类系统错误才整单回滚，业务性不足（池/名下不足）转下一腿。
2. **锁序死锁**：既有锁序 个人钱包→组池→成员行（类注释）。新路径全部沿用：划拨=个人→（组长个人 credit 走 PointsWalletService.adjust 内部锁个人②）→组池→成员；退组结算同序。**严禁**先锁成员再锁组池（与 chargeGroup 反向成环）。
3. **欠款归因算错**：溢出尾部归属必须按瀑布顺序倒推（组长垫=最后一段）。单测锁死四档算例（池足/池半+名下垫/池0名下垫/全组长垫），防「按比例均分」想当然。
4. **退款按腿反冲**：组账本无唯一约束，按 ref=taskId 查腿时须过滤 type（CONSUME/SELF_CONSUME/BACKSTOP），防 REFUND 腿混入导致双退。幂等键沿用 `media-hold-refund-/media-settle-refund-` 体系，SELF 腿新键段。
5. **V161 存量回填**：used>quota 行拆分依赖历史流水比例，BACKSTOP 流水 actor=组长但**不记 consumer**——回填只能按组级比例近似；写迁移前先 SELECT 统计受影响行数，>1000 行时改分批 UPDATE（PG 单语句大 UPDATE 锁表风险）。
6. **前端 WIP 冲突**：CanvasBoard.vue / MentionTextarea.vue / mentionLogic.ts / AssetProjectView.vue 工作区有用户未提交改动——C/D/F 实现基于现工作区续改，commit 只 `git add` 指定文件且**先确认 diff 内不含用户 WIP hunks 混提**（提交前 `git diff` 逐文件过目）。
7. **N+1**：上游面板递归取上游（D）一次遍历 edges 即可，禁逐节点查父；产出 tab 判重（F）批量查已入库 ref（一条 IN 查询），禁逐行请求。
8. **事件风暴**：E1 推送沿用「写咽喉发布」——划拨/还款/退组各腿只发一次 MEMBER/GROUP 事件（聚合 delta），不逐腿广播。

## 术语表

- 瀑布（waterfall）：一笔消耗按 组池→名下余额→组长兜底 顺序逐腿扣款的结算顺序。
- 名下余额（self_points）：成员从个人钱包划入组内、记在自己成员行上的钱，组长不可回收。
- 欠款拆分（debt_pool/debt_leader）：超限额溢出按「谁垫的钱」分别记账，还款各回各家。
- 豁免（调限额抵扣）：组长调高限额先抵欠款——债清但无资金流动（区别于划拨还款的真金白银）。
- 腿（leg）：一笔业务在账本里的一行流水；一笔消耗可拆多腿（CONSUME/SELF_CONSUME/BACKSTOP）。
- 光标锚定（caret anchoring）：@ 候选弹层定位在输入光标处而非输入框底部。

# 3.5 原型测试与验证

## I.12 权威方法

原型测试的核心权威来自三个体系：

### 1. Nielsen Norman Group 可用性测试框架

| 要素 | 内容 | 关键数据 |
|---|---|---|
| 测试用户数 | 5名用户即可发现85%的可用性问题 | Jacob Nielsen经典结论[来源:nngroup.com | 置信度:🔍高] |
| 任务设计 | 基于用户场景的真实任务 | 覆盖3-5个核心任务 |
| 出声思考法 | 用户边操作边说出想法 | 暴露认知过程 |
| 成功标准 | 任务完成率≥80%、无P0级问题 | 定量+定性结合 |

### 2. Google Ventures Design Sprint 验证框架

| 阶段 | 活动 | 产出 |
|---|---|---|
| Monday(理解) | 专家访谈+目标定义 | 策略+用户路径 |
| Tuesday(发散) | 独立草图方案 | 多个概念方案 |
| Wednesday(决策) | 投票+方案组合 | 选定方案+故事板 |
| Thursday(制作) | 1天制作高保真原型 | 可测试原型 |
| Friday(验证) | 5名用户一对一测试 | 验证结论+改进方向 |

[来源:GV Design Sprint手册 | 置信度:🔍高]

### 3. RITE方法(Rapid Iterative Testing & Evaluation)

| 原则 | 说明 |
|---|---|
| 快速迭代 | 发现问题→立即修改→重新测试 |
| 修改即测 | 不等问题积累，改完立刻验证 |
| 持续到收敛 | 直到连续2-3名用户无新问题 |
| 适用 | 高保真原型的微调迭代 |

## I.07 评估方法

### 按原型保真度选择评估方法

| 保真度 | 推荐评估方法 | 可获得的数据 |
|---|---|---|
| 草图/低保真 | 走查+认知预演+5秒测试 | 布局合理性、信息层级 |
| 中保真 | 任务式可用性测试+出声思考 | 操作流程、认知负荷 |
| 高保真 | SUS量表+任务成功率+录屏分析 | 量化可用性分数+问题诊断 |
| 代码原型 | A/B测试+行为数据分析 | 真实行为数据+转化指标 |

### 原型测试的关键指标

| 指标 | 计算方式 | 可接受阈值 |
|---|---|---|
| 任务完成率 | 成功完成任务人数/总测试人数 | ≥80% |
| 任务完成时间 | 从开始到完成的中位时间 | ≤竞品1.2倍 |
| 错误率 | 操作错误次数/总操作步骤数 | ≤10% |
| 求助率 | 询问"我该怎么操作"的次数 | ≤1次/任务 |
| SUS评分 | 10题5级量表标准化计算 | ≥68分(及格线) |
| 净推荐值(NPS) | 推荐者%-贬损者% | ≥0(对原型) |

### 原型测试的常见陷阱

| 陷阱 | 症状 | 规避方法 |
|---|---|---|
| 引导性提问 | "你觉得这个按钮是不是很清楚？" | 用开放式提问："你觉得这里可以做什么？" |
| 过早解释 | 用户不理解时立即解释设计意图 | 至少等待10秒，让用户自行探索 |
| 测试低保真看视觉 | 低保真收集视觉反馈 | 明确告知"这不代表最终视觉" |
| 样本偏差 | 只测内部同事 | 至少50%用户来自外部真实用户 |
| 单一任务流 | 只测"快乐路径" | 必须包含≥1个异常场景 |

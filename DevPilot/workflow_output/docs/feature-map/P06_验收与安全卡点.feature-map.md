## 2. 技术原理大白话

### 2.1 门禁为什么放在 Rust 侧？
前端把发布按钮禁用只是体验优化；真正拦截在 `enter_acceptance`/`request_release` 命令里再做一次严格校验（安全门禁状态、验收项全 pass/na）。改前端绕不过去，这叫纵深防御。

### 2.2 安全扫描扫什么？
三层：① 正则静态扫（密钥泄漏/鉴权缺失/数据库暴露），命中给 severity+file:line+建议；② `npm audit`/`cargo audit` 依赖漏洞；③ 密钥脱敏——只显示前 8 后 4 字符，扫描结果本身不泄密。L0 规模跳过依赖审计（本地无敏感面）。

### 2.3 为什么 selector 要手输？
预览是跨域 iframe，浏览器安全策略禁止读里面 DOM——程序拿不到你点的元素。所以降级为：圈选记坐标 + 手输 CSS selector（如 `#submit-btn`），plan 里已注明此取舍。

### 2.4 修复任务怎么闭环？
验收项标 fail（带定位+描述）→ 当前轮次末尾插一条 `source='fix'` 任务 → AI 修完标 done → 下次 `list_tasks` 时联动 SQL 把该验收项重置回 pending，逼人重新验收，不会「修完忘了验」。

### 2.5 冒烟怎么降级？
本机没 Node/Playwright → auto 项保持 pending + 大白话提示，不报错不拦截；报告为空 → 提示检查 dev server。截图存为证据，临时脚本跑完即删。

## 3. 建表注解（本地 SQLite，L9/L10 迁移）

| 表 | 用途 | 关键字段 | 关联 |

| acceptance_runs | 验收/冒烟/安全扫描运行记录 | kind(accept/smoke/security), status, details | 属于 project；只增不改，留历史 |

迁移：`L9__acceptance_security.sql`（建三表）、`L10__task_source_fix.sql`（tasks.source CHECK 加 'fix'，事务内重建表，子表 id 不变）。均已执行不可改。

## 4. 运维与降级

- **audit 网络失败**：降级 WARN 不拦截（沿用 check_all 本地审计降级约定）。
- **Node 缺失**：冒烟全跳过 + 提示，验收流程可继续走人工。
- **解析不到用例**：清单为空时界面提示先写测试方案文档，再点「重新生成」。

# 3.1 Agent工程方法论与范式演进

## 一、四代范式演进——AI 工程重心的代际迁移

腾讯云 2026-06 系统化提出 AI 工程四代范式演进，这是理解 2026 Agentic Engineering 的认知地基：

| 代际 | 范式 | 时期 | 核心命题 | 关键能力 |
|---|---|---|---|---|
| 第一代 | Prompt Engineering（提示词工程） | 2022-2024 | 怎么跟模型说话让模型听懂 | 提示词设计/Few-shot/CoT/角色设定 |
| 第二代 | Context Engineering（上下文工程） | 2025 | 怎么给模型喂对的信息让模型不糊涂 | 上下文组装/RAG/记忆/Compaction |
| 第三代 | Harness Engineering（脚手架工程） | 2025-2026 | 怎么给模型搭脚手架让模型可量化可对齐 | 评测/可观测/工具编排/Agent框架 |
| 第四代 | Loop Engineering（循环工程） | 2026 | 怎么设计循环让循环调度模型而非人逐条指令 | 目标/工具/记忆/安全/终止条件/验证机制系统设计 |

**关键澄清——四代是叠加累积不是推翻重来**：CSDN 2026-06 明确"Prompt Engineering 并未消亡，而是进化了"——GPT-5.4/Claude Opus 4.7/Gemini 3.1 Pro 能力提升后，提示词工程反而更精细化（结构化提示/变量化/版本管理）。四代演进是 AI 工程重心的代际迁移：第一代重心在"说对话"，第二代重心在"喂对信息"，第三代重心在"搭对脚手架"，第四代重心在"设计对循环"。每一代都在前一代基础上叠加，不是替代。[来源:腾讯云《为什么大厂都在偷偷搞Loop Engineering》/CSDN《Prompt Engineering从民间技艺到生产工程》| 🔍高 | 2026-06]

## 二、Vibe Coding → Agentic Engineering 范式跃迁

### 2.1 Vibe Coding 的诞生（2025-02）
2025-02 Andrej Karpathy（OpenAI 创始成员、特斯拉前 AI 总监）随手发推发明"Vibe Coding（氛围编程）"："我发明了一种新的编程方式，我称之为'氛围编程'。你完全沉浸在氛围之中，拥抱指数级增长，甚至忘记代码的存在……我总是'全部接受'，不再看差异对比。遇到东西不对，我就把报错扔给 AI，AI 修好我就继续。"Vibe Coding 迅速成为 2025 原型期主流——烧 token 换效率，快速验证想法。[来源:知乎《认知重建之后步入Agentic Engineering的工程革命》| 🔍高 | 2026-03]

### 2.2 认知重建——Vibe Coding 不适合生产
2026 行业完成集体认知重建，黄建 2026-04 微博《AI 时代工程师的新必修课：Agentic Engineering》总结三大认知转变：
1. **Coding agent 的本质**：在循环里执行工具来达成目标，不是聊天补全，是真正能跑代码、能迭代的 agent
2. **关键认知转变**：写代码变便宜了，但写出好代码没有
3. **好代码标准没变**——能运行、有测试、处理边界 case、文档同步、可维护。变的是：以前"这个功能不值得做"的理由消失了。现在的习惯应该是：先跑一个 agent session，10 分钟后再看结果

Vibe Coding 的"全部接受、不看 diff、忘记代码存在"适合原型期，但生产级 Agent 必须走 Agentic Engineering——好代码标准没有降，只是达到标准的路径变了。[来源:黄建微博/知乎《AET 01-当AI跨过代码生成》| 🔍高 | 2026-04]

### 2.3 Agentic Engineering 的概念确立
Simon Willison（Django 框架联合创建者、资深技术博主）在 Pragmatic Summit 炉边谈话深入探讨 Agentic Engineering，提出核心观点：Agentic Engineering 是 AI Agent 开发的新范式，传统编程范式（人类编写明确指令让计算机执行）正在被补充甚至部分替代。2026-06-23 亚马逊云科技中国峰会，亚马逊全球副总裁、亚太区联席总裁储瑞松宣布 Agentic 工程体系正在快速成熟，最早提示词工程已不再最重要，上下文工程和驾驭工程的探索仍在进行，循环工程成为新的热门方向。[来源:知乎《Agentic Engineering:AI Agent开发的新范式》/百度百科《Agentic工程体系》| 🔍高 | 2026-03~07]

## 三、Anthropic 五大工作流模式 + agentic loop

阿里云 2026-07 系统总结：2026 是 AI Agent 从概念验证走向工程化落地的关键转折年，Anthropic 提出的"工作流 vs 智能体"二分法已成行业共识：

### 3.1 工作流 vs 智能体二分法
- **工作流（Workflow）**：LLM 和工具通过预定义代码路径编排的系统 —— 确定性流程，工程师预设编排路径
- **智能体（Agent）**：LLM 自主决定执行路径与工具调用的系统 —— 概率性自主，模型动态决策

### 3.2 五大工作流模式
| 模式 | 装什么 | 适用场景 |
|---|---|---|
| **提示链（Prompt Chaining）** | 把大任务拆成串行小任务，前一步输出作后一步输入 | 翻译/摘要/代码生成→审查 串行任务 |
| **路由（Routing）** | 按输入类型分流到不同处理路径 | 客服分流/意图识别后分发 |
| **并行化（Parallelization）** | 多个 LLM 调用并行执行后聚合 | 投票/多视角评估/分块处理 |
| **编排者-执行者（Orchestrator-Worker）** | 编排者分解任务，Worker 并行执行，编排者聚合 | 复杂任务分解（D-24.05 多Agent协作基础） |
| **评估器-优化器（Evaluator-Optimizer）** | 一个 LLM 生成，另一个 LLM 评估反馈，迭代优化 | 写作打磨/代码优化/质量提升 |

### 3.3 agentic loop（智能体循环）
agentic loop 与五大工作流并列——LLM 在循环里"推理→行动→观察→重复"，自主决定何时调用什么工具、何时终止。这是 D-24.04 Agent 工作流设计的 ReAct 范式的工程化命名。

**行业现状**：五大工作流模式 + agentic loop 构成当前设计主流范式，行业正经历从"Harness"(脚手架)到"Loop Engineering"(循环工程)的范式跃迁。[来源:阿里云天池论坛《2026年AI Agent框架现状与趋势》| 🔍高 | 2026-07]

## 四、Agent Loop vs Loop Engineering——2026 最易混淆的概念

腾讯云 2026-06 反复强调这是 2026 最关键的概念区分：

| 维度 | Agent Loop（智能体循环） | Loop Engineering（循环工程） |
|---|---|---|
| **本质** | 运行时机制 | 系统设计学科 |
| **定义** | "推理→行动→观察→重复"的执行循环 | 设计目标/工具/记忆/安全/终止条件/验证机制的整体方法论 |
| **复杂度** | 30 行 Python 就能写出来 | 需要系统化工程设计与权衡 |
| **谁负责** | 工程师写代码实现 | 架构师/PM 系统设计 |
| **类比** | 发动机 | 汽车工程 |

### 4.1 关键人物言论（2026-06）
- **Peter Steinberger（OpenClaw 创始人）**：2026-06 初发文"别再手动给 AI 编码代理写提示词了，应该去设计一个能替你写提示词的系统"
- **Boris Cherny（Claude Code 负责人）**：跟进表示"我现在的日常工作就是写循环(Loop)，让循环去调度 Claude，自己不再逐条下达指令"
- **Google Cloud 工程团队**：同方向跟进循环工程实践

### 4.2 2026 讨论热点迁移
2026 讨论 2026 讨论热点已变成：Agent、Agent Runtime、Agent OS、Loop Engineering、Agent Governance。"还在简历上写精通 Prompt Engineering，猎头可能会礼貌地建议你更新一下技能树"——这不是 Prompt Engineering 消失，而是 AI 工程重心迁移到 Loop Engineering。[来源:腾讯云/新浪/网易/ZAKER《你还在手写Prompt?聪明的人早就用上了循环工程》| 🔍高 | 2026-06~07]

## 五、Coding agent 本质与关键认知重建

### 5.1 Coding agent 本质
黄建 2026-04 明确定义：Coding agent 的本质是"在循环里执行工具来达成目标"，不是聊天补全，是真正能跑代码、能迭代的 agent。这与 Anthropic 的 agentic loop 一致——循环 + 工具 + 目标三要素。

### 5.2 Anthropic 工程方法论
知乎 2026-07《AET 01-当AI跨过代码生成，真正的工程挑战才开始》引 Anthropic 团队原话："每当模型搞不定，就把任务双击打开，拆成更小的积木块，再重新组装成更大的目标。"——这是 Agent 工程方法论的核心：任务分解 + 重新组装，遇到搞不定就分解，分解到模型能搞定为止。

### 5.3 From Skill 模块化框架
知乎 2026-03《从第一性原理思考 Agentic Engineering》提出 agentic-engineering-framework——基于 Skill 的模块化 Agentic Engineering 框架，包含完整的 SDLCWorkflow、Best Practices、Self-Refinement 机制及项目定制指南。这是把 Agentic Engineering 从理念落到框架的工程化尝试。[来源:知乎《从第一性原理思考Agentic Engineering》| 🔍高 | 2026-03]

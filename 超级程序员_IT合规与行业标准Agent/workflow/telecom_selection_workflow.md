# Telecom Technology Selection Workflow

## Purpose

基于通信行业技术选型规范知识框架，提供通信技术选型的标准化决策路径，覆盖7+1评估矩阵、5G-A/6G选型、BSS/OSS重构、算力网络、物联网、卫星、信创、集采八大核心选型场景。

## Prerequisites

- 已明确选型场景（网络设备/IT系统/云服务/终端/芯片/软件）
- 已确定预算范围与决策周期

## Steps

### Step 1: 7+1评估矩阵建立

**Goal**: 建立通用的通信技术选型评估矩阵，覆盖技术/经济/战略/风险多维度
**Completion criterion**: 输出《技术选型评估矩阵模板》，7+1维度权重已根据组织战略调整，评分标准量化

依据7+1评估矩阵框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 7+1评估矩阵]：
1. 技术维度（权重25%）：
   - 成熟度（TRL等级≥7为商用就绪）
   - 性能指标（吞吐量/延迟/并发/可靠性）
   - 可扩展性（容量扩展倍数/升级路径）
   - 兼容性（与现网互联互通/标准符合度）
2. 经济维度（权重20%）：
   - TCO（总拥有成本）：CAPEX（采购/部署）+ OPEX（运维/能耗/人力）
   - ROI（投资回报率）：收入提升/成本节约/效率增益
   - 付款条件：分期/租赁/按需付费
3. 战略维度（权重15%）：
   - 技术路线一致性（与集团技术战略对齐）
   - 供应商战略关系（核心供应商/一般供应商）
   - 知识产权（自主可控/专利授权/开源许可）
4. 风险维度（权重15%）：
   - 技术风险（性能不达标/兼容性缺陷/安全漏洞）
   - 供应链风险（断供/涨价/地缘政治）
   - 合规风险（等保/密评/信创不达标）
5. 运维维度（权重10%）：
   - 运维复杂度（自动化程度/监控完善度/故障诊断难度）
   - 人员技能（现有团队掌握度/培训成本/招聘难度）
6. 生态维度（权重10%）：
   - 产业链成熟度（上下游供应商数量/替代品丰富度）
   - 社区/标准支持（开源社区活跃度/行业标准采纳度）
7. 时间维度（权重5%）：
   - 交付周期（从下单到上线）
   - 窗口期匹配（是否与业务高峰期/政策截止期冲突）
8. +1 合规维度（强制门槛）：
   - 等保测评：是否通过对应等级测评
   - 密评：密码应用是否通过安全性评估
   - 信创认证：是否在信创目录内
   - 入网许可：是否获得工信部入网许可证
执行：
- 为每个维度定义1-5分评分标准（1=极差，5=优秀）
- 设定合规维度一票否决项（如未通过等保测评直接淘汰）
- 加权计算综合得分：Σ(维度得分×维度权重)
输出：《技术选型评估矩阵模板》+ 《评分标准手册》+ 《合规检查清单》

### Step 2: 5G-A/6G技术选型

**Goal**: 完成5G-A网络升级与6G预研的技术选型，确保技术先进性与投资保护
**Completion criterion**: 输出《5G-A/6G技术选型报告》，设备厂商≥2家入围，技术路线有3年演进规划

依据5G-A/6G选型要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 5G-A/6G选型]：
1. 5G-A选型：
   - 无线设备：AAU（Active Antenna Unit）支持128T128R/256T256R，频段支持Sub-6GHz+毫米波
   - 核心网：5G SA核心网，支持网络切片/边缘计算/URLLC
   - 传输设备：SPN（Slicing Packet Network）支持FlexE硬切片/ SRv6
   - 厂商评估：华为（技术领先/生态完整/供应链风险）/ 中兴（性价比高/服务响应快）/ 爱立信（国际认证/ interoperability）
2. 6G预研选型：
   - 技术方向：通感一体化（通信+感知+AI融合）/ 太赫兹通信/ 智能超表面（RIS）/ 空天地一体化
   - 参考案例：紫金山实验室全球首个6G通智感融合外场试验网
   - 合作模式：与高校/科研院所联合预研，参与3GPP/ITU标准制定
3. 投资保护：
   - 硬件前向兼容：5G设备支持软件升级至5G-A
   - 频谱复用：现有Sub-6GHz频段可用于5G-A载波聚合
执行：
- 组织POC测试：选取典型场景（密集城区/工业园区/低空覆盖）进行设备对比测试
- 参考集采历史数据（价格/交付周期/故障率/客户满意度）
- 输出《5G-A/6G技术选型报告》+ 《POC测试方案》+ 《3年演进路线图》

### Step 3: BSS/OSS重构技术选型

**Goal**: 完成BSS/OSS中台化重构的技术选型，支撑业务敏捷与信创替代双目标
**Completion criterion**: 输出《BSS/OSS重构技术选型报告》，微服务框架+云原生平台+信创组件全部确定

依据BSS/OSS重构选型要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > BSS/OSS重构]：
1. 微服务框架选型：
   - Spring Cloud Alibaba：生态成熟/中文文档丰富/阿里巴巴背书/与Nacos/Sentinel/Seata集成
   - Dubbo：高性能RPC框架/阿里巴巴开源/适合大规模微服务集群
   - ServiceComb：华为开源/支持多语言/适合异构系统集成
2. 云原生平台选型：
   - Kubernetes：容器编排标准/生态最丰富/信创版（统信UOS+欧拉+OpenEuler）
   - 服务网格：Istio（功能最全）/ Linkerd（轻量）/ 自研（如中国移动自研服务网格）
3. 数据库选型：
   - 关系型：达梦（信创首选）/ OceanBase（阿里/高可用）/ TiDB（分布式/NewSQL）
   - 缓存：Redis（信创替代：Tendis/ Pika）
   - 消息队列：Kafka（信创替代：Apache Pulsar/自研）
4. 信创组件选型：
   - 芯片：鲲鹏920（ARM/华为）/ 飞腾D2000（ARM/天津）/ 海光C86（x86/中科曙光）
   - 操作系统：欧拉（OpenEuler/华为）/ 麒麟（Kylin/国防科大）/ 统信UOS
   - 中间件：东方通TongWeb（应用服务器）/ 金蝶Apusic / 中创InforSuite
执行：
- 制定《信创适配矩阵》：每个技术组件列出首选（信创）+ 备选（非信创但成熟）
- 评估迁移成本：代码改造量/数据迁移量/测试工作量/人员培训成本
- 参考中国电信OSS3.0国产化重构案例（CAPEX 28亿，经验与教训）
输出：《BSS/OSS重构技术选型报告》+ 《信创适配矩阵》+ 《迁移成本估算》

### Step 4: 算力网络技术选型

**Goal**: 完成算力网络关键技术选型，实现计算与网络资源的智能调度
**Completion criterion**: 输出《算力网络技术选型报告》，SRv6/CFN/RoCE/液冷等关键技术方案确定

依据算力网络选型要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 算力网络]：
1. 网络层选型：
   - SRv6（Segment Routing IPv6）：简化MPLS/支持网络编程/与SDN控制器协同
   - CFN（Compute First Networking）：算力感知路由协议（IETF草案阶段）
   - 意图网络：基于业务意图自动编排网络路径（Cisco DNA/华为iMaster）
2. 智算互联选型：
   - RoCE v2（RDMA over Converged Ethernet）：低延迟（μs级）/高吞吐/与现有以太网融合
   - InfiniBand：更低延迟/更高带宽/独立网络/NVIDIA主导
   - 选型考量：AI训练集群优先IB，通用算力集群优先RoCE
3. 智算中心基础设施选型：
   - 液冷技术：冷板式（成熟度高/改造小）/ 浸没式（效率最高/改造大）
   - 供配电：高压直流（HVDC）/ 分布式UPS/ 锂电储能
   - 机柜功率密度：传统8-10kW → 智算30-50kW+ → 需液冷支持
4. 算力调度平台：
   - 自研：中国移动算网大脑/中国电信天翼云智能调度
   - 开源：Kubernetes Volcano（批调度）+ Karmada（多集群调度）
执行：
- 评估现网设备SRv6支持情况，制定升级计划
- 智算中心选址：PUE≤1.25（西部）/≤1.30（东部），绿电比例≥80%
- 输出《算力网络技术选型报告》+ 《智算中心设计方案》+ 《算力调度平台架构》

### Step 5: 物联网技术选型

**Goal**: 完成物联网技术选型，覆盖RedCap、NB-IoT、Cat.1等主流技术的适用场景评估
**Completion criterion**: 输出《物联网技术选型报告》，每种技术的适用场景/成本/功耗/覆盖明确，模组选型≥2家

依据物联网选型要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 物联网选型]：
1. 蜂窝物联网技术对比：
   - NB-IoT：超低功耗（10年电池）/ 深度覆盖（20dB增益）/ 低速率（<200kbps）/ 适用：智能表计（电/水/气）、停车地磁
   - RedCap（5G Reduced Capability）：中等速率（<150Mbps）/ 低功耗/ 低成本（模组降至$15）/ 适用：工业传感器、可穿戴设备、监控摄像头
   - Cat.4 LTE：中速率（<150Mbps）/ 功耗较高/ 模组成本$20-30/ 适用：车载终端、POS机、广告屏
   - Cat.1 LTE：低速率（<10Mbps）/ 低功耗/ 模组成本$10-15/ 适用：共享设备、追踪器
2. 非蜂窝物联网技术：
   - LoRa：超远距离/ 私有网络/ 适用：园区/农场/油田
   - Zigbee：短距离 mesh/ 低功耗/ 适用：智能家居/工业传感
   - Wi-Fi 6/7：高吞吐/ 短距离/ 适用：室内高带宽场景（4K摄像头/VR）
3. 模组选型：
   - 厂商：移远通信/广和通/芯讯通/美格智能/高新兴
   - 评估：价格/供货稳定性/技术支持/认证齐全度（CCC/SRRC/CE/FCC）
4. 平台选型：
   - 连接管理平台：OneNET（移动）/天翼物联网平台（电信）/联通物联网平台
   - 应用使能平台：设备管理/规则引擎/数据可视化/OTA升级
执行：
- 梳理物联网应用场景清单（智能表计/车联网/工业互联网/智慧城市/智慧农业）
- 每个场景匹配最优技术，输出《物联网技术-场景匹配矩阵》
- 输出《物联网技术选型报告》+ 《模组评估表》+ 《平台对比分析》

### Step 6: 卫星通信技术选型

**Goal**: 完成卫星通信与地面网络融合的技术选型，覆盖终端/芯片/网络/频谱维度
**Completion criterion**: 输出《卫星通信技术选型报告》，天通/北斗/低轨卫星方案明确，终端芯片≥2家备选

依据卫星通信选型要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 卫星通信选型]：
1. 卫星类型选型：
   - 高轨卫星（GEO）：天通一号（中国电信）/ 覆盖广/ 延迟高（500ms+）/ 适用：语音/短信/应急
   - 中轨卫星（MEO）：北斗导航/ 定位+短报文/ 军用+民用双模
   - 低轨卫星（LEO）：星链（Starlink/美国）/ 银河航天（中国）/ 延迟低（20-40ms）/ 适用：宽带互联网
2. 终端选型：
   - 天通双模手机：华为Mate 60 Pro/ 荣耀/ 海信/ 模组芯片：华力创通/ 紫光展锐
   - 北斗终端：车载终端/ 船载终端/ 手持终端/ 芯片：和芯星通/ 华大北斗
   - 低轨终端：相控阵天线（成本高/ 功耗大）/ 适用：应急通信车/ 远洋船舶/ 航空器
3. 网络融合选型：
   - 3GPP R17 NTN：标准融合路径/ 透明载荷 vs 再生载荷
   - 5G+卫星：双模基站/ 卫星回传/ 应急快速部署
4. 频谱选型：
   - L频段（1-2GHz）：天通卫星/ 穿透力强/ 终端天线小型化
   - S频段（2-4GHz）：北斗/ 军民共用
   - Ka频段（20-30GHz）：低轨宽带/ 大容量/ 雨衰敏感
执行：
- 评估业务场景（应急通信/海洋/航空/偏远地区宽带）匹配卫星类型
- 制定《卫星通信业务发展路线图》：政务应急优先 → 海洋航空跟进 → 大众市场最后
- 输出《卫星通信技术选型报告》+ 《终端评估表》+ 《频谱使用计划》

### Step 7: 信创技术选型

**Goal**: 依据信创目录与替代路线图完成全栈信创技术选型，确保2027年100%替代目标达成
**Completion criterion**: 输出《信创技术选型报告》，六大层级（芯片/OS/数据库/中间件/应用/安全）全部有信创替代方案

依据信创选型要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 信创选型]：
1. 芯片层：
   - CPU：鲲鹏920（ARM/华为/服务器）/ 飞腾D2000（ARM/桌面+服务器）/ 海光C86（x86/服务器/兼容性好）/ 龙芯3A5000（MIPS→LoongArch/桌面）
   - GPU：景嘉微/ 摩尔线程/ 壁仞科技/ 适用：图形渲染/ AI训练推理
2. 操作系统层：
   - 服务器：欧拉（OpenEuler/华为/云原生优化）/ 麒麟高级服务器版（Kylin/政府首选）/ 统信UOS服务器版
   - 桌面：统信UOS桌面版/ 麒麟桌面版/ 适用：办公终端替代Windows
3. 数据库层：
   - 关系型：达梦（DM8/国产Oracle/政府首选）/ OceanBase（阿里/分布式/金融级）/ TiDB（PingCAP/分布式/NewSQL）/ 人大金仓（Kingbase/PostgreSQL兼容）
   - 非关系型：华为GaussDB（多模）/ 阿里HBase/ 腾讯Tendis（Redis兼容）
4. 中间件层：
   - 应用服务器：东方通TongWeb（市场份额最高）/ 金蝶Apusic / 中创InforSuite
   - 消息中间件：Apache RocketMQ（阿里开源）/ 华为MQ/ 自研
   - 缓存：Tendis（腾讯/Redis兼容）/ Pika（360/Redis兼容）
5. 应用软件层：
   - 办公软件：WPS（金山/替代Office）/ 永中Office
   - OA系统：泛微/ 致远/ 蓝凌（信创版已适配）
   - ERP：用友NC/ 金蝶EAS（信创版）
6. 安全层：
   - 密码设备：江南天安/ 三未信安（密码卡/加密机）
   - 安全芯片：国民技术/ 国芯科技
   - 安全软件：启明星辰/ 绿盟/ 深信服（信创版）
执行：
- 制定《信创替代清单》：每个非信创组件列出信创替代品+替代时间+替代风险
- 评估兼容性：信创组件与现有系统的兼容性测试计划
- 参考国资委79号文：2027年底央企100%完成替代
输出：《信创技术选型报告》+ 《信创替代清单》+ 《兼容性测试计划》+ 《替代路线图》

### Step 8: 集采流程技术选型执行

**Goal**: 将技术选型结果纳入集采流程，确保评标标准与技术方案一致
**Completion criterion**: 输出《集采技术规范书》，技术评分标准量化，合规维度一票否决项明确

依据集采流程选型要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 集采流程]：
1. 技术规范书编制：
   - 功能要求：必须满足项（一票否决）/ 重要项（高分）/ 一般项（基础分）
   - 性能指标：量化指标（如QPS≥10000/延迟<50ms/并发≥10000）
   - 兼容性要求：与现网系统互联互通测试用例
   - 信创要求：芯片/OS/数据库必须在信创目录内
2. 评分标准设计：
   - 技术分（60%）：技术方案先进性/ 架构合理性/ 性能达标度/ 兼容性/ 可扩展性
   - 商务分（40%）：价格/ 付款条件/ 交货期/ 维保服务/ 培训支持
   - 演示分（10%）：POC测试结果/ 现场演示/ 原型体验
3. 供应商评估：
   - 资质审查：营业执照/ 税务/ 社保/ 业绩证明/ 资质证书
   - 技术评估：研发团队规模/ 专利数量/ 行业案例/ 技术路线图
   - 商务评估：财务状况/ 交付能力/ 售后服务网络/ 价格竞争力
4. 风险控制：
   - 单一来源风险：核心组件至少2家备选供应商
   - 地缘政治风险：评估供应商供应链稳定性（芯片来源/ 制造地点）
   - 技术锁定风险：优先选择开放标准/ 接口开放/ 数据可迁移方案
输出：《集采技术规范书》+ 《评分标准模板》+ 《供应商评估表》+ 《风险控制清单》

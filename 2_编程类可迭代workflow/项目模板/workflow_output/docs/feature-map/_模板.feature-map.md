### 示例（照此格式填，填完删掉示例、换成真实内容）

#### 1. JWT 登录鉴权 — `backend/middleware/auth.ts`

- **采用技术**：JWT（JSON Web Token）+ 中间件拦截
- **一句话原理**：用户登录成功后，服务器发一张"电子通行证"（token），之后每次请求都带着它，服务器验签名才放行。
- **大白话展开**：老办法是服务器记"谁登录了"（session），服务器一多就记不全。JWT 把用户信息直接编进通行证本身，服务器不用记、只验签名，换哪台机器都认。
- **大白话案例**：像游乐场手环——买票时（登录）领一个盖章手环（token），之后玩每个项目（每次请求）都伸手环，工作人员只看章对不对（验签名），对就放行，不用每次回售票处确认你是谁。
- **为什么用它**（可选）：无状态、易横向扩展，比 session 适合前后端分离。**若该选型属于关键/反常规决策，回链 ADR 编号**（如「详见 ADR-003」）。
> 📌 批注：token 放 localStorage 有 XSS 风险，本项目改用 httpOnly cookie 存（见 AGENTS.md 鉴权约束）。

#### 2. 列表数据自动刷新 — `frontend/components/UserList.vue`

- **采用技术**：Vue 3 Composition API（`ref` / `watch`）+ axios
- **一句话原理**：把组件用到的数据包成"响应式变量"，数据一变，页面自动跟着更新，不用手动改 DOM。
- **大白话展开**：以前改了数据要亲手去改页面（操作 DOM），容易乱。Vue 帮你盯着数据，数据一动它自动把页面改好。
- **大白话案例**：像 Excel——你改了某个格子（数据），下面汇总公式（页面）立刻跟着变，你不用重新算一遍。
> 📌 批注：列表量大时用分页，别一次拉全部，否则页面卡（见性能约束）。

### 示例（照此格式填，填完删掉示例或改成真实内容）

#### 迁移脚本：`V1__create_user_and_order.sql`

- **脚本作用**：建用户表 `user` 和订单表 `order`，并把订单关联到下单用户。
> 📌 批注：脚本名 `V1__...` 必须严格按 Flyway 版本命名，已执行的脚本**不能再改**，要改结构就新加 `V2__...`（Flyway 靠版本号顺序执行，乱改名/改旧脚本会直接报错）。

#### 表：`user`（用户表）

> 大白话：存"谁注册了本系统"，**一行 = 一个用户**。

| 字段 | 类型 | 用途（大白话） | 约束 / 索引 |
|---|---|---|---|
| id | BIGINT | 用户的唯一编号 | 主键、自增 |
| username | VARCHAR(64) | 登录用的名字 | 唯一索引、非空 |
| email | VARCHAR(128) | 邮箱，用来找回密码 / 通知 | 唯一索引 |
| created_at | DATETIME | 注册时间 | 非空 |

#### 表：`order`（订单表）

> 大白话：存"谁在什么时候下了什么单"，**一行 = 一笔订单**。

| 字段 | 类型 | 用途（大白话） | 约束 / 索引 |
|---|---|---|---|
| id | BIGINT | 订单唯一编号 | 主键、自增 |
| user_id | BIGINT | **谁下的单**，关联到 `user.id` | 外键→`user.id`、加索引 |
| amount | DECIMAL(10,2) | 订单金额 | 非空 |
| status | TINYINT | 订单状态：0待付 / 1已付 / 2取消 | 非空，默认 0 |
| created_at | DATETIME | 下单时间 | 非空 |

#### 表关联（大白话 + 案例）

- **`order.user_id` → `user.id`（一对多）**：一个用户可以下很多笔订单，但每笔订单只属于一个用户。
  > 像「顾客 ↔ 购物小票」：一个顾客（user）对应很多张小票（order），每张小票上都印着是哪个顾客的（`user_id`）。
- **多对多示例**：用户 ↔ 角色通过**中间表** `user_role` 关联——一个用户能有多个角色，一个角色也能给多个用户。
  > 像「学生 ↔ 社团」靠「报名表」连起来：一个学生能报多个社团，一个社团也有多个学生，报名表就是中间表。

> 📌 批注（建表通用坑）：
> - **外键字段和常被查询的字段务必加索引**（`user_id`、`status`），否则数据一多查询就慢。
> - **大字段**（正文、富文本、JSON）拆到副表，别和主表混，拖慢主表查询。
> - **金额用 DECIMAL，别用浮点**，否则算账会出现 `0.1+0.2≠0.3` 的精度坑。
> - 状态/类型字段，在本节和 SQL 注释里都写明**取值含义**（0/1/2 分别是啥），别让人猜。

# File Keeper 使用场景

File Keeper 是一个轻量级的文件快速访问工具，通过可视化的卡片界面帮助用户管理和快速打开常用文件。本文档介绍典型的使用场景和最佳实践。

---

## 核心使用场景

### 1. 项目文档快速访问

**场景描述**：开发者需要频繁访问项目相关的文档、配置文件和笔记。

**使用方式**：
- 将项目的 README、API 文档、配置文件添加到 File Keeper
- 使用"项目"分组统一管理
- 通过打开次数排序，最常用的文档自动排在前面
- 使用搜索功能快速定位特定文档

**优势**：
- 无需在文件管理器中层层导航
- 一键打开常用文档
- 自动记录使用频率，优化访问效率

---

### 2. 学习资料管理

**场景描述**：学生或自学者需要管理大量的课程资料、教程、笔记和参考文档。

**使用方式**：
- 按课程或主题创建分组（如"数据结构"、"Web开发"、"机器学习"）
- 为文件添加标签（如"重点"、"复习"、"作业"）
- 使用自定义排序调整学习优先级
- 通过标签筛选快速找到特定类型的资料

**优势**：
- 可视化的卡片界面比文件列表更直观
- 标签系统支持多维度分类
- 打开次数统计帮助识别薄弱环节

---

### 3. 设计素材库

**场景描述**：设计师需要管理和快速访问常用的设计文件、素材和参考图片。

**使用方式**：
- 添加 PSD、AI、Sketch 等设计文件
- 使用分组区分项目或客户
- 通过文件图标快速识别文件类型
- 使用搜索功能定位特定素材

**优势**：
- 图标预览帮助快速识别文件
- 分组和标签支持灵活的组织方式
- 比传统文件管理器更快的访问速度

---

### 4. 工作文档中心

**场景描述**：办公人员需要快速访问各种工作文档、报告、表格和演示文稿。

**使用方式**：
- 按部门或项目创建分组
- 使用"最近打开"排序查看最新工作内容
- 为紧急文档添加"urgent"标签
- 通过搜索快速定位特定文档

**优势**：
- 减少在多个文件夹间切换的时间
- 自动记录最近使用的文档
- 支持快速筛选和搜索

---

### 5. 代码片段和配置文件管理

**场景描述**：开发者需要管理常用的代码片段、配置模板和脚本文件。

**使用方式**：
- 添加常用的配置文件（如 `.gitignore`、`tsconfig.json`）
- 保存代码片段和脚本文件
- 使用标签标记语言或用途（如"python"、"config"、"template"）
- 通过搜索快速找到需要的模板

**优势**：
- 比 IDE 的文件历史更灵活
- 支持跨项目的配置文件管理
- 可视化界面比命令行更友好

## 功能特性与使用技巧

### 搜索功能
- **实时搜索**：输入关键词即时过滤文件
- **搜索范围**：匹配文件名、路径、分组和标签
- **防抖优化**：输入停止 300ms 后执行搜索，避免卡顿

### 排序方式
- **自定义排序**：手动调整文件顺序，点击序号徽章编辑位置
- **打开次数**：最常用的文件排在前面
- **文件名**：按字母顺序排列
- **最近打开**：最近使用的文件排在前面
- **创建时间**：按添加时间排序

### 分组管理
- 为文件指定分组（如"工作"、"学习"、"项目"）
- 通过分组下拉框快速筛选
- 支持"全部"视图查看所有文件

### 标签系统
- 为文件添加多个标签
- 点击标签快速筛选相同标签的文件
- 标签支持自定义颜色（自动生成）

### 视图模式
- **网格视图**：卡片式布局，适合浏览和管理
- **列表视图**：紧凑布局，适合快速查找

### 性能优化
- **虚拟滚动**：支持管理 1000+ 文件而不卡顿
- **图标懒加载**：按需加载文件图标，加快启动速度
- **搜索防抖**：优化搜索体验，减少性能开销

## 最佳实践

### 1. 合理使用分组
- 按项目、主题或用途创建分组
- 避免创建过多分组（建议 5-10 个）
- 使用标签处理更细粒度的分类

### 2. 善用标签
- 为文件添加 2-3 个关键标签
- 使用一致的标签命名（如"重要"而非"重要的"）
- 定期清理不再使用的标签

### 3. 利用排序功能
- 日常使用"打开次数"排序，最常用的文件自动靠前
- 整理文件时使用"自定义排序"手动调整
- 查找最近工作内容时使用"最近打开"排序

### 4. 定期维护
- 删除不再需要的文件
- 更新文件的分组和标签
- 检查文件路径是否仍然有效

### 5. 搜索技巧
- 使用文件名关键词快速定位
- 搜索标签名筛选特定类型的文件
- 搜索分组名查看特定分组的文件

## 常见问题

### Q: File Keeper 会移动或修改我的文件吗？
A: 不会。File Keeper 只存储文件路径的引用，不会修改、移动或删除原始文件。

### Q: 可以添加多少个文件？
A: 理论上没有限制。虚拟滚动技术支持管理 1000+ 文件而不影响性能。

### Q: 文件被移动或删除后会怎样？
A: File Keeper 会在尝试打开文件时检测到路径无效，并提示用户。建议定期清理无效的文件引用。

### Q: 数据存储在哪里？
A: 所有数据（文件列表、分组、标签、统计信息）存储在本地的 `fileStore.json` 文件中，不会上传到云端。

### Q: 支持哪些文件类型？
A: 支持所有文件类型。File Keeper 会自动提取文件图标，并使用系统默认程序打开文件。

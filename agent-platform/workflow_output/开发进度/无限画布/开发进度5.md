## 本轮做了什么

### C11 视频抽帧（IC-12，R-2 javacv）

- **VideoFrameService** [canvas/service/VideoFrameService.java](../../../backend/src/main/java/com/superprogrammer/canvas/service/VideoFrameService.java)：javacv `FFmpegFrameGrabber` 流式 seek→`grabImage()` 单帧→`Java2DFrameConverter`→JPEG 字节。
  - 三态 `FrameMode`：`FIRST`（不 seek 直接抓）/ `LAST`（`setTimestamp(duration-200ms)`，尾帧预留防空洞）/ `AT`（`setTimestamp(second*1_000_000μs)`，越界 [0,duration] 抛 BAD_REQUEST）。
  - 流式按帧取不整片 load（R-2「大视频内存可控」）；finally 必 `grabber.release()`。
  - 失败固定话术「抽帧失败，请稍后重试」不透传 `e.getMessage()`（plan 安全清单）。
  - 配置 `canvas.frame-extractor=javacv`（默认；ffmpeg 系统进程分支留后续，未实现→UNPROCESSABLE 引导）。

### 端点 + 咽喉点（C11 chunk3）

- **CanvasController** `POST /{id}/nodes/{nodeId}/frames` [CanvasController.java](../../../backend/src/main/java/com/superprogrammer/canvas/controller/CanvasController.java)：body `{mode, second}` →
  ①`loadOwned`（画布归属）→②`resolveVideoFileId`（解析快照定位视频节点 + 校验 type=video + 读 data.fileId）→③`loadPath`（视频源文件 ownership 复检，防借他人 fileId 抽帧）→④`extract`→⑤`storeStream(SOURCE_CANVAS)` 产新图 fileId。
  失败不产空文件（plan 边界）：service 抛 → 端点直接返错，不落 stored_files。
- **FileStorageService.loadPath** [FileStorageService.java](../../../backend/src/main/java/com/superprogrammer/file/service/FileStorageService.java)：`load` 归属咽喉点拆出返 `Path`（javacv 需可 seek 的文件路径，非 InputStream）。`load` 改为委托 `loadPath`，零行为变化。
- **MediaTaskVO +resultFileId** [MediaTaskVO.java](../../../backend/src/main/java/com/superprogrammer/media/dto/MediaTaskVO.java)：同 `videoUrl` 归属门控（mayAccessFile && SUCCEEDED）暴露 stored_files.fileId。**根因**：`videoUrl` 是下载端点 `/api/media/tasks/{id}/download` 非 fileId，而抽帧 `loadPath` 需真 fileId。前端视频节点 SUCCEEDED 后存此 fileId 供抽帧直读。

### 前端抽帧面板（C11 chunk4）

- **PropertyPanel.vue** [PropertyPanel.vue](../../../frontend/src/components/canvas/PropertyPanel.vue)：视频节点块加「首帧 / 尾帧 / 第 N 秒」三按钮（AT 配 `n-input-number` 秒数输入）。`disabled` 当 `node.data.fileId` 空（视频未生成）。emit `extract-frame {node, mode, second?}`。
- **CanvasView.onExtractFrame** [CanvasView.vue](../../../frontend/src/views/CanvasView.vue)：调 `canvasApi.extractFrame` → `fetchCanvasPreview` 拉图 blob → `addNode(image)`（label=`抽帧(FIRST/LAST/AT Ns)`，带 fileId+previewUrl+parentFileId+sourceNodeId）→ `addEdge(video→image)` 自动连边。失败标红源视频节点不建空节点。
- **pollVideoTask / hydrateVideoPreviews** SUCCEEDED 分支补存 `fileId: resultFileId`（加载时按 taskId 重取亦填）。
- 修既有 tsc 隐患：模板内联 `(opts: {file:...})` 类型注解触发 TS1005 → 去注解 + `onPickFile` 参数宽松化；`refFileId` 赋值在闭包内丢 narrowing → 加 `if(node)` guard。

### 依赖（C11 chunk1）

- **pom.xml** [pom.xml](../../../backend/pom/pom.xml)：javacv 1.5.13 + ffmpeg 8.0.1-1.5.13。
  - 瘦身三招：①javacv exclude 14 无用 preset（opencv/openblas/artoolkitplus/flycapture/libdc1394/libfreenect/libfreenect2/librealsense/librealsense2/videoinput/leptonica/tesseract/android/jogl/jocl/gdx）；②**弃 ffmpeg-platform 全家桶**（含 android/mac/linux/win × arm64/x86_64 全 native，本机磁盘撑爆 → 磁盘不足报错），改 `ffmpeg` base + `ffmpeg classifier=windows-x86_64` 单平台（dev 跑测试够，~80MB）；③**部署 linux 服务器须追加 `<classifier>linux-x86_64</classifier>` 依赖**（见下「部署必做」）。
  - bytedeco 版本号规则坑：ffmpeg/ffmpeg-platform 版本 = `<ffmpegVer>-<javacvVer>`（8.0.1-1.5.13），非 1.5.13；javacv 本体 = 1.5.13。1.5.11 不存在（Central 最新 1.5.13）。

## 踩坑批注

| 坑 | 解 |
|---|---|
| ffmpeg-platform 全平台 native 撑爆 C 盘（200G 仅剩 41M，磁盘不足） | 弃 umbrella，改单平台 classifier（windows-x86_64），删已下 android/mac native + partial |
| bytedeco 版本号 `<ffmpegVer>-<javacvVer>`，写 1.5.13 解析失败 | javacv=1.5.13 / ffmpeg=8.0.1-1.5.13 分两 property |
| javacv 默认传 14 个无关 preset（opencv/tesseract/深度相机…） | exclude 全部，只留 ffmpeg 链 |
| videoUrl 是下载端点非 fileId，抽帧 loadPath 拿不到真文件 | MediaTaskVO +resultFileId（同门控），视频节点存 fileId |
| javacv 需 seekable 文件，InputStream 不行 | FileStorageService.loadPath 返 Path（load 咽喉点拆出） |
| 模板内联 TS 类型注解 `(opts:{file:{file:File\|null}})` 触发 vue-tsc TS1005 | 去注解 `(opts)=>fn(opts)` + 函数参数宽松化 |

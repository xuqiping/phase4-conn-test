# 3.4 标签与搜索系统

## 标签系统

### 标签设计流程

1. **收集来源**：从内容/竞品/用户/利益相关者收集现有标签
2. **标签审计**：标注不一致、歧义、冗余、遗漏
3. **定义标签体系**：建立统一命名规范（风格/语法/粒度）
4. **测试验证**：用卡片分类/首次点击测试验证标签可理解性
5. **纳入受控词汇**：正式文档化，团队对齐

### 标签命名规范

| 维度 | 规则 | 示例 |
|---|---|---|
| 语法风格 | 全站统一（全名词/全动宾/全动词） | ❌"设置/编辑/新建" vs ✅"设置/编辑资料/新建项目"（全动宾） |
| 粒度 | 同层级标签粒度一致 | ❌"购物/买衣服/图书" vs ✅"服装/图书/数码" |
| 用户语言 | 用用户词不用内部词 | ❌"CRM系统" → ✅"客户管理" |
| 简洁 | 导航标签 ≤5字 | ❌"个人账户中心" → ✅"我的" / "账户" |
| 无歧义 | 一词一义 | ❌"订单"（采购？销售？） → ✅"采购单"/"销售单" |

### 多语言标签注意事项

- **预留空间**：同一标签英文比中文长约1.5-2倍（"账户管理"→"Account Management"）
- **语义等价**：不是逐字翻译，而是功能等价（"发现"→"Discover"/"Explore"视语境）
- **文化适配**：导航逻辑在不同文化可能差异（东亚更接受密集层级，西方偏好扁平）

## 搜索系统

### 何时需要搜索

| 情况 | 判断 |
|---|---|
| 内容 >500 条 | 必须有搜索 |
| 用户有明确目标（找已知内容） | 搜索优先 |
| 用户在浏览探索（发现未知内容） | 导航+推荐优先 |
| B端/内部系统 | 必须有搜索（效率刚需） |

### 搜索系统设计要素

| 要素 | 说明 | 关键决策 |
|---|---|---|
| 搜索区域界定 | 搜哪里（全站/当前模块/指定范围） | 默认全站+高级筛选缩窄 |
| 搜索算法 | 匹配策略（精确/模糊/语义） | 中文必支持拼音+模糊+分词 |
| 结果排序 | 默认排序策略 | 默认相关性，可切换时间/热度 |
| 结果展示 | 每条结果展示什么 | 标题+摘要+高亮关键词+来源路径 |
| 空结果处理 | 搜不到怎么办 | 建议+热门内容+放宽条件重搜 |
| 搜索建议 | 输入时实时推荐 | 历史搜索+热门搜索+自动补全 |
| 高级搜索 | 多字段组合检索 | 适用B端/专业场景 |

### 搜索与导航的配合

**核心原则**：搜索和导航是互为补充的"两条腿"——导航适合浏览式探索，搜索适合目标式查找。绝不假设"有搜索就不需要导航"或"有导航就不需要搜索"。

| 场景 | 主力 | 辅助 |
|---|---|---|
| "我想买一双跑步鞋" | 搜索+筛选 | 分类导航可发现更多 |
| "我想看看有什么好看的" | 分类导航+推荐 | 搜索框待命 |
| "我要找上次的订单" | 搜索 | 导航不适用 |

## E.03 常见坑

| 坑 | 表现 | 修法 |
|---|---|---|
| 搜索无结果无引导 | "未找到结果"后用户无路可走 | 推荐+放宽条件+热门内容 |
| 标签和内容对不上 | 标签写A，内容是B | 标签审计+首次点击测试 |
| 中英文搜索体验差异 | 英文精确匹配还行，中文分词/拼音不行 | 集成中文分词+拼音模糊匹配 |
| 搜索结果信息过少 | 只有标题，用户无法判断是否是目标 | 展示摘要+高亮关键词+来源路径 |

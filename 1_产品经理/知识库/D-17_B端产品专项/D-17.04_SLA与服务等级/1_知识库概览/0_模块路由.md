# D-17.04 SLA与服务等级

## 是什么

**SLA（Service Level Agreement，服务等级协议）**：服务提供方与客户之间，就服务质量达成的**可量化承诺协议**——包含可用性、响应时间、吞吐量、错误率等指标，以及未达标时的违约责任。 [来源:Microsoft Learn/SaaS基础 | 置信度:🔍高]

**SLO（Service Level Objective，服务等级目标）**：SLA中的具体目标值（如"可用性≥99.9%"），是SLA的核心内容。

**SLI（Service Level Indicator，服务等级指标）**：衡量SLO是否达成的量化指标（如"当月正常运行时间/当月总时间"），是SLO的计算依据。

三者的关系：**SLI → SLO → SLA**（指标测量 → 目标设定 → 协议承诺）[来源:Google SRE Handbook | 置信度:🔍高]

## 核心要素

| 要素 | 说明 | 示例 |
|---|---|---|
| **服务范围** | SLA覆盖哪些服务/功能/API | "本SLA适用于Core API及管理后台，不含Beta功能" |
| **SLI指标** | 可量化的测量指标 | 可用性/响应P99/错误率/吞吐量 |
| **SLO目标** | 每个SLI的目标值+测量窗口 | "月度可用性≥99.9%" "P99延迟≤200ms" |
| **违约责任** | 未达标时的赔偿/处罚 | 服务抵扣（按未达标时间比例减免费用） |
| **排除条款** | 不计入SLA的场景 | 计划维护/不可抗力/客户侧网络/第三方依赖 |
| **报告与审计** | SLA达成情况的透明度机制 | 月度SLA报告/实时状态页/API可查 |

## 为什么B端PM必须懂SLA

1. **SLA是B端产品的"合同条款"**——B端客户采购时SLA是必谈项，不懂SLA=无法支持销售
2. **SLA驱动架构决策**——99.9%和99.99%的架构成本差异巨大，PM必须在成本与承诺间权衡
3. **SLA影响客户成功**——频繁SLA违约=客户满意度暴跌=流失，CSM的挽留挡不住SLA的硬伤
4. **SLA是竞品差异化的硬指标**——"我们99.99%，竞品99.9%"是最直接的差异化论据

## 常见误区

- **误区1**：SLA越高越好——99.99%的可用性意味着全年只能停4.5分钟，架构成本是99.9%的3-5倍 [来源:Google SRE | 置信度:🔍高]
- **误区2**：SLA只管可用性——完整SLA还需覆盖延迟/错误率/吞吐量/支持响应/数据持久性
- **误区3**：SLA是运维的事——SLA的设计（承诺什么、不承诺什么）是产品决策，运维只负责达成
- **误区4**：所有客户给同一个SLA——大客户需要定制SLA，长尾客户用标准SLA即可

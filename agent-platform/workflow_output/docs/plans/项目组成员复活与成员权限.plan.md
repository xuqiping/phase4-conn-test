# Implementation Plan for 项目组成员复活与成员权限

> Phase 2 产出。Phase 3 逐步勾选执行。只含伪代码，不含真代码。
> 来源规格：[../specs/项目组成员复活与成员权限设计.md](../specs/项目组成员复活与成员权限设计.md)
> 拍板：复活（revive）修 409；成员权限三维=角色+功能开关+可见性覆盖。

## 背景与目标

- 17x#1：移除→再邀请→接受报 409 `uk_pgm_group_user`（软删残留行撞全量唯一约束）。
- 17x#2：成员级权限——角色（OWNER/MANAGER/MEMBER）、可用功能开关（allowed_kinds）、成员级产出可见性覆盖。

## 技术实现坑点预判与规避措施

| 技术点/功能块 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| **复活 vs 并发双接受** | 两线程同时接受同一用户两张邀请，都走复活/插入路径 → 重复成员或 409 误报 | 复活=单条件 UPDATE（`WHERE deleted=1`），天然互斥：先到者得 1 行，后到者得 0 行→探针见活行→409「已是成员」 | IT：4 线程并发接受，恰 1 成功 |
| 复活继承脏状态 | 直接 `deleted=0` 会把移除前的 quota/角色/开关/覆盖带回来，语义诡异 | 复活 UPDATE 显式重置：quota=新邀请值、used=0、role='MEMBER'、两 jsonb=NULL | IT 断言五列复位 |
| **role 回填与 uk_pgm_owner** | 历史组长行 role 默认 MEMBER，建索引时多 OWNER/缺 OWNER | 迁移内 `UPDATE ... FROM project_groups` 回填后再建部分唯一索引；建组 INSERT 改 role='OWNER' 同步落 | migrate 冒烟+建组 IT |
| MANAGER 越权动 MANAGER/OWNER | 前端藏按钮但直调 API | service 层目标行 role 硬校验：运营端点仅允许目标 role='MEMBER'（任免除外=OWNER 专属）；OWNER 行一切写操作拒 `GROUP_OWNER_IMMUTABLE` | 单测矩阵全组合 |
| allowed_kinds 在 chargeGroup 漏卡 | 只在入口预检卡，未来新入口（工作流/API 直调）绕过 | chargeGroup 内部同事务校验（成员行锁本就持有，零额外 IO）；入口预检只做体验提前拦截 | 单测：直调 chargeGroup 禁 kind 拒 |
| 禁 kind 时在途任务 | 禁 VIDEO 瞬间有 RUNNING 视频任务 → 结算/退款怎么处理 | 拍板：开关只挡**新提交/新调用**，在途任务正常结算与退款（已估价预检过）；规格 §6 已写明 | IT：禁后在途任务结算成功 |
| 成员覆盖 jsonb 坏数据 | 手改库/旧版写入非法 key → 判定异常 | 读侧宽容（非法 key/值忽略落 base，同组级 overrideFor 模式）；写侧白名单 400 | 单测坏 jsonb 回落 |
| 可见性判定视角搞反 | 覆盖写在「观察者」还是「产出归属人」行上搞混 | 规格拍板：**归属人**行覆盖；outputs 查询把可见 kind 集合按「行 owner 的覆盖」逐行算——行数大时 N+1 | 规避：查询批量取组成员覆盖 map（一次 IN 查询）内存算；单测视角用例 |
| MANAGER 恒可见击穿 OWN | 组默认 OWN 时 MANAGER 看全部产出是否合规 | 拍板：MANAGER 视同组长可见（管理需要）；文档+user-ops 明示 | 单测 |
| 友好文案遗漏 | 复活后正常路径撞不到约束，但极端并发仍可能 | GlobalExceptionHandler 补 `uk_pgm_group_user` →「该用户已在项目组中」 | 单测直接 INSERT 撞约束 |

## 功能联动点清单

| 触发动作 | 联动对象 | 预期变化 | 边界（反向/取消/批量） |
|---|---|---|---|
| 移除成员 | 成员行 | 软删 | 反向=再邀请接受→复活（used 清零/权限默认）；**该用户在途媒体任务不受影响**（task 已带 gid 照常结算）；其 PENDING 邀请/申请不受影响（已独立状态机） |
| 接受邀请（复活路径） | 成员行+组流水 | 行复活+ADMIN_ADJUST 流水 | 邀请带 quota → 覆盖旧值；无 quota→NULL 不限；复活不计 ALLOCATE（不动钱） |
| 任免 MANAGER | 目标行 role + 前端 tab 可见性 | 目标用户下次拉 overview 看到管理 tab | 反向=降为 MEMBER 立即收回（无缓存）；OWNER 行不可任免（400）；MANAGER 不能任免任何人 |
| 改 allowed_kinds | 成员消耗能力 | 新提交/调用被挡 | 反向=恢复 null 全放开；**空数组=全禁**（合法）；在途任务照结算（不退款不拦截）；不影响个人计费路径（仅组分支） |
| 改成员可见性覆盖 | 产出列表+文件闸门 | 其他成员看该成员产出的范围变化 | 反向=清空覆盖回落组级；覆盖目标=MEMBER 行（OWNER/MANAGER 行恒可见，设了也无效——前端禁用+后端忽略）；只对后续查询生效，无历史重写 |
| 组级可见性变更（既有） | 成员覆盖 | 无联动——覆盖独立层，组级改动不清成员覆盖 | 成员覆盖恒优先于组级 |

## 运维考量清单

| 类别 | 决策 | 说明 |
|---|---|---|
| 可观测性 | **做** | 复活/任免/开关/覆盖变更打 INFO 日志（operator/target/groupId）；chargeGroup 禁 kind 拒打 WARN |
| 配置开关 | **不做** | 小特性无灰度必要；角色体系无高危路径 |
| 可回滚 | **做** | V140 加列+索引，回滚块：DROP 索引+列（数据丢失需确认）；复活/权限纯代码，回滚代码即恢复旧行为（旧代码不认识新列，PG 加列向后兼容） |
| 限流/熔断/降级 | **不做** | 无第三方依赖；管理端点低频 |
| 运维入口 | **后续再说** | 脏数据修复（如手工复活）暂用 SQL；不进本期后台页面 |
| 告警阈值 | **不做** | 无资源型指标；审计日志可事后追溯 |
| 容量/性能预案 | **做（评估）** | 成员行+3 列，50 人/组上限，增量可忽略；jsonb 列无索引无查询下推，无容量风险 |

## 术语表

| 术语 | 大白话 | 例子 |
|---|---|---|
| **复活（revive）** | 把软删行标回有效，不插新行 | 被移除成员回归，老行清零继续用 |
| **部分唯一索引** | 只对符合条件的行做唯一约束 | 每组只能有一个活的 OWNER |
| **条件 UPDATE** | 带前提的更新，0 行=前提不成立 | 复活时 `WHERE deleted=1`，并发只一人成功 |
| **稀疏覆盖** | 只存和默认不一样的项 | 只给 VIDEO 设 OWN，其余跟组默认 |
| **白名单校验** | 只接受列得出的合法值 | allowed_kinds 只认 5 种模块 |

# Computer Vision & Speech Workflow

## Purpose

基于计算机视觉与语音知识体系，为用户提供目标检测（YOLO）、图像分割（SAM万物分割）、语音处理（端到端SpeechLLM）、AIGC生成（DiT+世界模型）等感知智能技术的方案支持。覆盖YOLO v11 mAP@0.5=65.2%、SAM2/3全分割类型、VibeVoice 60分钟单次转写、国产可灵/即梦超越Sora等核心能力，以及GB 45438-2025国标强制AI生成内容加水印等合规要求。

## Prerequisites

- 用户已明确计算机视觉或语音场景或问题
- 知识库文件 `05_人工智能与机器学习.md` 及子目录文件可访问

## Steps

### Step 1: 识别计算机视觉/语音需求场景

**Goal**: 明确用户的感知智能需求类型、实时性要求和部署环境
**Completion criterion**: 已确定场景标签、任务类型、性能目标和部署约束

1. 读取用户消息，提取以下信息：
   - 场景类型：目标检测 / 图像分割 / 语音识别/合成 / AIGC生成（图像/视频/音频） / 多模态VLM / 工业质检
   - 任务类型：实时推理（毫秒级） / 批量处理（离线分析） / 交互式（人机对话）
   - 部署环境：云端GPU集群 / 边缘设备（Jetson/树莓派） / 移动端（iOS/Android） / 浏览器（WebGL/WebGPU）
   - 数据特点：图片数量/分辨率、视频时长/帧率、音频采样率/语种/方言、数据标注质量
   - 合规要求：是否需要内容审核、是否需要水印标识（GB 45438-2025）、隐私保护（人脸脱敏）

2. 对照知识库中的技术选型初步判断：
   - 实时目标检测（工业/交通/安防） → YOLO（v11，单阶段毫秒级推理）
   - 通用分割（任意对象/交互式/视频） → SAM2/3（万物分割，零样本迁移）
   - 长时语音转写（会议/采访/播客） → SpeechLLM端到端（VibeVoice 60分钟单次）
   - 文生图/视频/音乐（创意生成） → DiT+世界模型（国产可灵/即梦/Stable Diffusion 3）
   - 多模态理解（图文问答/视频分析） → VLM（GPT-4V/Claude 3/Qwen-VL/InternVL）

3. 如有信息缺失，向用户追问不超过2个澄清问题。

### Step 2: 输出计算机视觉/语音方案

**Goal**: 产出针对性的感知智能技术选型、架构设计或优化方案
**Completion criterion**: 输出包含推荐技术、模型选型、部署架构、合规策略

根据Step 1确定的场景，按以下分支处理：

**分支A — 目标检测**：
1. 输出YOLO系列演进与选型：
   - YOLOv8/v9/v10/v11对比：速度（FPS）、精度（mAP）、模型大小（N/S/M/L/X），附各版本创新点（v8解耦头/v9可编程梯度信息/v10无NMS/v11注意力增强）
   - 适用场景：工业缺陷检测（小目标、高精度）/ 交通监控（多目标跟踪、实时性）/ 安防人脸（隐私合规、低光照）/ 医学影像（病灶定位、可解释性）
   - 部署优化：TensorRT加速（FP16/INT8量化）、ONNX Runtime跨平台、OpenVINO（Intel CPU优化）、NCNN（移动端）、RKNN（瑞芯微NPU）
2. 给出训练数据策略：
   - 数据增强：Mosaic、MixUp、RandomAffine、CopyPaste（小目标增强关键）
   - 标注质量：边界框精确度、遮挡处理、类别平衡（长尾问题解决方案）
   - 迁移学习：COCO预训练 → 领域微调（冻结骨干网+训练检测头 → 全网络微调）
3. 输出评估与优化：mAP@0.5、mAP@0.5:0.95、FPS、F1-Score（类别不平衡时）、混淆矩阵分析、错误案例分析（假阳性/假阴性）。

**分支B — 图像分割**：
1. 输出SAM系列能力矩阵：
   - SAM 1：图像分割（点/框/涂鸦提示）、零样本泛化、Encoder-Decoder架构（ViT-H图像编码+Prompt编码+轻量掩码头）
   - SAM 2：视频分割（时序一致性、第一帧提示+自动跟踪）、实时性能优化
   - SAM 3：3D分割（医学影像/点云）、多模态提示（文本描述分割）
   - 适用场景：医学影像分割（器官/病灶）、自动驾驶（道路/行人/车辆）、电商（商品抠图）、内容创作（背景替换）
2. 给出传统分割模型对比：
   - 语义分割：U-Net（医学首选）、DeepLabV3+（ASPP多尺度）、SegFormer（Transformer-based）
   - 实例分割：Mask R-CNN（两阶段）、YOLACT（实时单阶段）、RT-DETR（端到端Transformer）
   - 全景分割：Panoptic FPN（统一语义+实例）
3. 输出部署优化：ONNX导出、TensorRT加速、移动端适配（CoreML/TFLite）、Web端（ONNX.js/WebGL）。

**分支C — 语音处理**：
1. 输出语音识别（ASR）选型：
   - 传统级联：Whisper（OpenAI，多语言强、开源）、FunASR（阿里，中文优化、说话人分离）、Paraformer（阿里，非自回归、速度快）
   - 端到端SpeechLLM：VibeVoice（60分钟单次转写、长上下文保持）、Qwen-Audio（音频理解+推理）、SpeechGPT（语音对话）
   - 选型因素：语种支持（普通话/方言/多语言）、实时性（流式vs批量）、说话人分离需求、标点恢复、Filler词过滤
2. 给出语音合成（TTS）选型：
   - 传统TTS：FastSpeech 2（速度优先）、VITS（质量优先）、Bark（多语言+情感+音乐）
   - 端到端：F5-TTS（流畅度优先）、CosyVoice（阿里，音色克隆、情感控制、多语言）、GPT-SoVITS（少样本克隆）
   - 应用场景：客服机器人（自然对话）、有声书（长文本连贯）、虚拟主播（实时口型同步）、导航语音（短指令清晰）
3. 输出语音交互架构：
   - 全双工：用户打断检测（VAD语音活动检测）、流式ASR（实时转写）、TTS流式合成（首包延迟<500ms）、对话状态管理（上下文保持）
   - 车载场景：噪声抑制（AEC回声消除+ANC降噪）、离线ASR（无网络可用）、多音区（主驾/副驾分离）
   - 客服场景：情绪识别（从语音特征判断用户情绪）、智能打断（AI不抢话）、意图识别（NLU层）

**分支D — AIGC生成**：
1. 输出文生图技术栈：
   - 核心架构：DiT（Diffusion Transformer，Stable Diffusion 3/FLUX.1）、U-Net（SD 1.5/2.1）、一致性模型（LCM实时生成）
   - 国产领先：可灵（快手，视频生成质量高）、即梦（字节，图文生成）、通义万相（阿里）、混元（腾讯）
   -  ControlNet：姿态控制（OpenPose）、深度控制（Depth）、边缘控制（Canny）、语义分割控制（Seg），附多ControlNet组合使用
   - LoRA微调：角色一致性（角色LoRA）、风格迁移（画风LoRA）、产品展示（商品LoRA）
2. 给出文生视频技术栈：
   - 架构演进：基于帧插值（Gen-1/2）→ 基于DiT原生视频（Sora/可灵/即梦）→ 世界模型（物理一致性、因果推理）
   - 关键技术：时序注意力（跨帧一致性）、3D VAE（时空联合编码）、运动先验（光流估计+运动轨迹）、长视频生成（分段生成+场景过渡）
   - 国产优势：可灵/即梦在视频生成质量上超越Sora（OpenAI已关停Sora独立产品），国内产品迭代更快
3. 输出合规与内容安全：
   - GB 45438-2025国标：AI生成内容强制加水印标识（显式水印/隐式水印）、内容溯源（生成时间/模型版本/用户身份）、平台责任（审核义务）
   - 内容审核：文本审核（敏感词/政治/色情/暴力）、图像审核（OCR+图像识别）、视频审核（帧采样+关键帧检测）
   - 版权保护：训练数据版权（是否获得授权）、生成内容版权归属（用户/平台/模型厂商）、风格模仿边界（不能模仿在世艺术家风格）

**分支E — 多模态VLM**：
1. 输出VLM选型对比：
   - 闭源：GPT-4V（最强通用理解）、Claude 3（多模态推理强）、Gemini（原生多模态、长上下文）
   - 开源：Qwen-VL（阿里，中文优化）、InternVL（商汤+上海AI Lab，文档理解强）、LLaVA（社区活跃、易扩展）、MiniCPM-V（端侧小模型）
   - 选型因素：图文理解能力、文档/OCR能力、视频理解、中文支持、推理成本、开源协议
2. 给出典型应用场景：
   - 文档理解：发票/合同/表格/手写体识别+结构化提取+问答
   - 视觉问答：电商商品问答（看图回答材质/尺寸/搭配）、医学影像问答（辅助诊断解释）
   - 视频分析：安防事件检测（打架/摔倒/聚集）、体育分析（动作识别/战术分析）、教育（课堂行为分析）
3. 输出端侧部署：模型量化（INT4/INT8）、推理框架（MNN/NCNN/TFLite/CoreML）、NPU适配（华为昇腾/高通骁龙/苹果Neural Engine）。

将结果保存到 `output/cv_speech_architecture.md` 或直接在对话中呈现。

### Step 3: 验证与交付

**Goal**: 确保感知智能方案技术可行、合规达标、与知识库一致
**Completion criterion**: 已通过 checklist 逐项核对

1. 读取 `checklist/cv_speech_workflow_checklist.md`。
2. 逐项核对输出是否覆盖要求的知识点。
3. 确认模型性能数据（YOLO v11 mAP、可灵vs Sora等）准确。
4. 如有遗漏或偏差，补充修正。
5. 向用户交付最终答案。

## Post-Workflow

1. 记录完成状态到 `task/current_task.md`。
2. 如需深入某一具体技术（如"SAM 2视频分割时序一致性优化"、"可灵文生视频Prompt工程技巧"），在当前 Agent 内继续追问并输出。

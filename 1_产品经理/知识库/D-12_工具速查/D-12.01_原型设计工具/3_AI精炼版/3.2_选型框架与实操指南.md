# 3.2 选型框架与实操指南

## 四维选型框架

原型工具选型不是"哪个最好"，而是"哪个最适合"。推荐按四个维度系统性决策：[来源:CSDN 2026-02 PM工具选型 | 📚中]

### 维度1：项目类型

| 项目类型 | 推荐工具 | 理由 |
|---|---|---|
| C端App/小程序 | Figma / 即时设计 / Pixso | 视觉保真度要求高+交互适中+协作频繁 |
| B端后台/企业系统 | Axure / 墨刀 | 交互逻辑复杂+动态面板+权限/角色模拟 |
| 快速MVP验证 | 墨刀 / 即时设计 | 低保真快速出+AI辅助+学习成本低 |
| 设计系统搭建 | Figma / Sketch | 组件库生态最强+Design Token管理 |
| 跨平台产品 | Figma / 即时设计 | Web端全平台可用+实时协作 |

### 维度2：团队规模

| 团队规模 | 推荐策略 | 关键考量 |
|---|---|---|
| 1-3人 | 墨刀/即时设计免费版 | 成本优先+快速出图 |
| 4-20人 | Figma/Pixso团队版 | 协作是核心+设计系统管理 |
| 20-100人 | Figma企业版+Axure | 设计团队Figma+B端产品Axure |
| 100人+ | Figma企业版+Axure+内部工具链 | 设计规范统一+工具链打通 |

### 维度3：协作需求

| 协作场景 | 推荐工具 | 理由 |
|---|---|---|
| 设计师+PM+开发实时协作 | Figma / 即时设计 | 实时多人+评论标注+Dev Mode |
| PM独立完成原型+评审 | 墨刀 / Axure | 逻辑表达+快速出图 |
| 远程团队 | Figma / Pixso | Web原生+无地域限制 |
| 离线/安全内网 | Axure | 桌面端+离线可用 |

### 维度4：成本考量

| 预算 | 推荐策略 |
|---|---|
| ¥0 | 即时设计/Pixso免费版（功能充足）+ 墨刀免费基础版 |
| ¥500/月/人内 | Figma Professional + 墨刀Pro |
| ¥500+/月/人 | Figma Organization + Axure 团队授权 |

## 原型设计标准工作流

### 阶段1：低保真线框图（Day 1）

| 步骤 | 工具 | 核心产出 |
|---|---|---|
| 信息架构梳理 | 白板(FigJam/墨刀白板) | 页面树+导航结构 |

| 步骤 | 工具 | 核心产出 |

## Design to Code（设计转代码）

2025-2026年Design to Code从"概念"走向"实用"：[来源:综合Figma Config 2026+社区评测 | 📚中]

| 方案 | 原理 | 成熟度 | 适用范围 |
|---|---|---|---|
| Figma Dev Mode | 官方开发模式：自动生成CSS/iOS/Android代码片段 | ⭐⭐⭐⭐ | Figma用户标准交付 |
| 墨刀交付 | 一键导出标注+代码+切图 | ⭐⭐⭐ | 墨刀全链路用户 |
| Locofy | Figma→React/HTML/CSS自动转换 | ⭐⭐⭐ | 前端团队React技术栈 |
| Anima | Figma→HTML/React/Vue代码 | ⭐⭐⭐ | 多前端框架场景 |
| Builder.io | AI视觉→代码+Figma插件 | ⭐⭐⭐ | AI辅助代码生成 |

### Design to Code注意事项

1. **自动生成代码≠生产级代码**：需要前端工程师review和重构
2. **适合做页面骨架**：自动生成约60%~70%的UI代码，逻辑层面仍需手写
3. **设计规范是前提**：如果设计混乱（命名不规范/组件不一致），转出来的代码也混乱
4. **响应式处理偏弱**：多端适配仍需人工介入

## 常见选型误区

| 误区 | 真相 | 应对 |
|---|---|---|
| "Figma最佳，所有人都该用" | Figma适合设计团队协作，但B端复杂交互不如Axure | 按场景组合使用，不做非此即彼 |
| "Axure过时了" | Axure在复杂B端场景仍是首选，交互逻辑无工具能替代 | B端团队保留Axure+补充Figma做视觉 |
| "免费版不够用" | 即时设计/Pixso免费版对中小团队功能充足 | 先用免费版验证需求再升级 |
| "原型工具=设计工具" | 原型侧重逻辑和交互验证，设计侧重视觉表现 | PM用原型验证可行性，设计师用设计工具出视觉 |
| "学一个工具就够" | 不同场景需要不同工具组合 | 建立核心工具+辅助工具的工具箱 |

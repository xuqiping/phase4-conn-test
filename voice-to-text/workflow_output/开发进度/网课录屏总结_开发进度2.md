## ✅ Step4 视频硬编落盘 + 三路录制集成（`1f37111` 4a + `f399720` 4b）

**4a 切片编码（FR-101/103）**
- `screen/encode.rs`：`SlicePlanner`（纯逻辑：15min 轮转/帧计数/manifest 记录）+ `SliceEncoder`（windows-capture `VideoEncoder`，H.264 4Mbps 30fps，2h≈3.6GB 符合 design 2-6GB）
- `capture.rs`：`RecordConfig{video_dir, frames_dir, slice_ms, trace}` + `start_with_record`；handler 内首帧懒建编码器（需真实宽高）；handler Drop finalize 末段；编码失败降级为仅捕获（O4，转写/音频不陪葬）
- **偏离计划**：`video_NNN.h264` → **`video_NNN.mp4`**（crate 的 MediaTranscoder 必须带容器，出不了裸流）；跨轨对齐靠 `video/manifest.jsonl` 每段 `start_ms/end_ms`（session 墙钟）
- 测试：5 单测（轮转/命名/计数/长时守恒）+ 真实编码冒烟（ignored，手动跑过：4s 出 video_001.mp4 + manifest）

**4b 三路集成（FR-101/102/103）**
- `screen/scene_detect.rs` 轻量入口：`SceneTap` 每 15 帧采样 → 64×36 灰度 SAD 预筛 → 变化帧存 320px 缩略图 + `frames/changes.jsonl`（不阻塞录制）
- `lib.rs`：`start_capture_session(session_id, hwnd, audio_device)` / `stop_capture_session()`：三路绑同一 `SessionClock` t0；转写实时 emit（复用 transcription 事件）+ final 句追加 `transcript.jsonl`；停止落 `audio.wav` → 状态 Recording→**Processing**（联动 L1）
- **顺手修隐患**：audio.wav 落盘前按 `actual_format`（新增，记录真实流格式）重采样到 16k 单声道 —— 原写法设备 48k 裸样本按 16k 写头会慢放 3 倍、三路时间轴错位
- 安全：session_id 走 SessionManager 路径穿越校验；重复录制/重复会话拒绝；屏幕轨启动失败时音轨收口
- 测试：22 单测绿；5min 真实联录冒烟留 Phase4（需人工选窗）

## ✅ Step5 精细抽帧去重（`00892d9` 5a + `430922e` 5b，FR-104）

**5a 视频解码采样**
- `screen/decode.rs`：`sample_video(path, step_ms, cb)` MF SourceReader 顺序解码 MP4 → BGRA top-down 回调流式出帧（2h@2Hz 不缓存全量）
- 坑位三连（注释已记代码里）：
  - 必须 `MF_SOURCE_READER_ENABLE_VIDEO_PROCESSING=1`，否则 SetCurrentMediaType RGB32 报 0xC00D36B4
  - windows 0.61 绑不了 `IMFMediaBuffer2`/`MFGetAttributeSize` → 用 1D Lock + GetUINT64 解尺寸
  - MF RGB32 输出 bottom-up → 拷贝翻 top-down；crate 文档称 `send_frame_buffer` 要 bottom-up **实测按 top-down 解释**
- 测试：合成视频回环（VideoEncoder 造 2 页 4s 片 → 解码采样断言间隔/单调/几何/方向亮带）

**5b 判页去重流水线**
- `scene_detect.rs` 完整化：32bin 灰度直方图 BHATTACHARYYA + pHash64（32×32→DCT-II→8×8 低频→**中位数**阈值）**双判 OR** + pending 去抖
- 两个设计级修正（单测抓住的）：
  - 双判必须 OR 不能串联 AND：同亮度分布异内容页（本机 e2e 的纹理翻页）直方图过不了，靠 pHash 通道救召回
  - pHash 用中位数不用均值：稀疏频谱图均值被强系数拉偏 → 区分度崩掉（split vs stripes 汉明仅 6）
  - 去抖 = pending 挂起**静置满 2.5s 窗才提交** + 段末 flush；早期实现"窗内变化直接丢弃"会把真翻页吞掉
- `extract_session_frames`：manifest 段偏移换算 session ts → 存 `page_<ts>.jpg`(1280w)/`thumb_<ts>.jpg`(320w) → `frames.json[{frame_ts, orig_path, thumb_path, ocr_text:null}]`
- `lib.rs`：`process_frames(session_id)` 命令（spawn_blocking，2h 解码不占 async runtime）；阈值包 `ExtractConfig`（O2 可配置面已留）
- 测试：29 绿含 e2e（合成 2 页切片 + manifest 5000ms 偏移 → ≥2 页/ts 带偏移/落图/占位字段）

# 本地持久化迁移约束

> 适用于桌面端 Pinia 持久化和本地 SQLite。首次来源：人工测试问题 1—4 修复 Chunk 1。

## 1. Pinia 持久化

- Store 结构变化时，通过 `persist.migrate(stored)` 在 `$patch` 前转换旧数据。
- 迁移函数必须是纯函数、可重复执行，不访问网络，不记录业务正文或完整路径。
- 新字段必须有安全默认值；未知枚举值回退到当前默认值。
- 过渡期间需要旧 UI 字段时，可保留运行时兼容别名，但必须在负责 UI 切换的后续 Chunk 删除。
- 迁移至少覆盖：旧值、新值优先级、非法值和缺失值。

## 2. SQLite

- 使用 `PRAGMA user_version` 读取版本并按顺序升级，禁止只靠“重复执行不报错”猜测版本。
- 全部结构升级在单事务内完成；成功后才提高版本，失败必须回滚。
- 本地迁移优先只新增表、列和索引；不得自动做破坏性降级。
- 数据库版本高于应用支持版本时拒绝打开，不能静默降级覆盖。
- 旧记录修复不得删除业务内容；孤立关联优先置空并回到安全默认状态。

## 3. 测试

- 至少验证：全新库、旧库保留数据、重复迁移、新版本拒绝降级。
- 若主 Tauri 二进制存在无关测试编译阻塞，可建立只引用目标模块的隔离 integration test；不能通过注释或删除无关测试规避。
- 隔离测试只解决编译边界，不得复制一份迁移实现，否则测试可能与生产逻辑分叉。

## 4. 术语表

| 术语 | 大白话 | 示例 |
|---|---|---|
| 纯函数 | 同样输入总得到同样输出，不偷偷改别处 | 旧设置对象转成新设置对象 |
| 静默降级 | 不提示就把新数据当旧数据覆盖 | 版本 99 的库被旧应用改回版本 2 |
| 隔离测试 | 只编译目标模块，绕开无关模块故障 | 单独运行剪贴板存储测试 |

## 常见混淆区分

- **Agent 产品形态 vs Agent 工作流设计 vs 多 Agent 协作**：形态是"Agent 产品的整体架构形式"（单Agent/多Agent/团队/人机协同/自主），工作流设计是"形态下的任务编排与流程控制"（拆解/重试/Human-in-the-Loop/状态管理），多Agent协作是"多Agent之间的协同机制"（分工/通信/冲突消解）。三者是形态（架构）→流程（编排）→协同（多体）的层级关系
- **Agent 通信协议 vs Agent 工具调用**：通信协议是"Agent 与外部（工具/其他Agent/UI）对话的标准"（MCP/A2A/AG-UI/Skills），工具调用是"Agent 调用具体工具完成任务的技术机制"（Function Calling/Computer Use/Sandbox）。协议是标准层，工具调用是实现层；MCP 是二者交汇点——既是协议也是工具调用标准
- **Agent 记忆与上下文(D-24.06) vs 长期记忆系统(D-19.07)**：D-24.06 聚焦 Agent 运行时的上下文管理与状态持久化（Compaction/工作记忆/会话连续性），D-19.07 聚焦 AI 产品的长期记忆系统设计方法论（记忆分层/CRUD-M/遗忘机制）。前者是 Agent 工程层，后者是记忆系统设计层，D-24.06 是 D-19.07 在 Agent 场景的工程化落地
- **D-19 AI/大模型PM专项 vs D-24 AI Agent 产品专项**：D-19 聚焦用大模型做 PM 的所有共通能力（含模型选型、提示词、RAG、Token、LLM 局限等底层能力），D-24 聚焦 Agent 专项深化（Agent 形态、通信协议、工具调用、多 Agent 协作、Agent 评测）。Agent 是 D-19.01 形态分类下的 L4 级形态，D-24 是 D-19.01 Agent 形态的深化专项
- **Agent 评测(D-24.07) vs 模型选型与评估(D-19.03)**：D-24.07 评测的是 Agent 系统的端到端任务完成能力（动态闭环：观察→规划→工具调用→反馈），D-19.03 评估的是 LLM 模型本身的能力（静态一问一答基准）。Agent 评测是模型评估在 Agent 场景的延伸，但挑战更大（状态ful、多步、工具依赖）

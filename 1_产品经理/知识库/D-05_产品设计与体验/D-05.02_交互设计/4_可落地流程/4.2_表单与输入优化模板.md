# 表单与输入优化模板

## Part A · 表单设计自检清单

### 结构层

| # | 检查项 | 标准 | 常见问题 |
|---|---|---|---|
| S1 | 必填项标识 | 标注*号或"必填"标签，非必填标"选填" | 标记了必填却不标记选填，用户无法判断哪些可跳 |
| S2 | 字段排列顺序 | 按用户认知顺序而非数据库字段顺序 | 注册表按"确认密码→邮箱→手机"排，用户心智需跳转 |
| S3 | 字段分组 | 超过7个字段必须分组，每组≤5个 | 20个字段的平铺表单，用户直接放弃 |
| S4 | 进度指示 | 多步表单必须显示进度条/步骤指示 | 用户不知道还有几步，中途放弃 |
| S5 | 默认值 | 能推断的字段必须预填默认值 | 国家/语言可从IP推断却不预填 |

### 交互层

| # | 检查项 | 标准 | 常见问题 |
|---|---|---|---|
| I1 | 实时校验 | 输入离焦后即时校验+提示 | 提交后才发现第一个字段错误，需重填大量内容 |
| I2 | 错误提示定位 | 错误提示紧贴出错字段 | 页面顶部统一报错，用户找不到哪个字段出错 |
| I3 | 键盘适配 | 不同输入类型唤起对应键盘（数字键盘/邮箱键盘） | 输入手机号弹出全键盘，需手动切换 |
| I4 | 自动聚焦 | 表单打开自动聚焦第一个输入框 | 用户需手动点击才能开始输入 |
| I5 | Tab序 | Tab键遵循视觉顺序跳转 | Tab跳转与视觉顺序不一致，混乱 |

### 情感层

| # | 检查项 | 标准 | 常见问题 |
|---|---|---|---|
| E1 | 占位符文本 | 给出格式示例而非空泛提示 | "请输入手机号"vs"13800138000"——后者更有效 |
| E2 | 反馈动效 | 输入成功给予微动效反馈 | 全程无反馈，用户不确定是否输入成功 |
| E3 | 提交保护 | 提交中禁用按钮+loading态 | 重复点击导致重复提交 |

## Part C · 输入方式选型决策树

```
开始：用户需要输入什么？
│
├─ 选项有限且≤7个？
│  ├─ 是 → 单选：Radio / 多选：Checkbox
│  └─ 否 → 选项有限且7-30个？
│     ├─ 是 → 下拉选择 Select
│     └─ 否 → 带搜索的下拉 Select with Search / 自动补全 Autocomplete
│
├─ 需要输入数字？
│  ├─ 范围已知 → Slider / Stepper
│  ├─ 精确数值 → 数字输入框（带格式校验）
│  └─ 金额 → 专用金额输入（自动千分位+小数位限制）
│
├─ 需要输入日期/时间？
│  ├─ 日期范围 → 日历范围选择器
│  ├─ 单个日期 → 日历选择器（快捷选项：今天/昨天/上周）
│  └─ 时间 → 时间滚轮选择器
│
├─ 需要输入长文本？
│  ├─ 格式自由 → Textarea（带字数统计）
│  ├─ 结构化 → 富文本编辑器
│  └─ 模板化 → 模板选择+变量填充
│
├─ 需要上传文件？
│  ├─ 图片 → 拖拽上传+预览+裁剪
│  ├─ 文档 → 拖拽上传+格式校验+进度条
│  └─ 批量 → 压缩包上传+批量解析
│
└─ 需要确认/同意？
   ├─ 单项 → Checkbox + 协议链接
   └─ 多项 → 逐项Checkbox（非全选）
```

### 选型速查表

| 输入需求 | 首选控件 | 次选控件 | 绝对不要 |
|---|---|---|---|
| ≤7选项 | Radio/Checkbox | Pill/Chip选择 | 下拉Select（选项少时折叠等于隐藏） |
| 7-30选项 | 下拉Select | 自动补全Input | 平铺Radio（太多选项视觉爆炸） |
| >30选项 | 带搜索Select | 两栏穿梭框 | 普通下拉（选项过多找不到） |
| 日期 | 日历Picker | 快捷按钮组 | 手动Input（格式混乱） |
| 金额 | 专用金额Input | 数字Input | 普通文本Input（无法校验） |
| 评价/评分 | 星级/滑块 | NPS量表 | 文本Input（无法量化） |
| 多步骤表单 | 分步向导 | Tab分组 | 长页面平铺（移动端尤其忌） |

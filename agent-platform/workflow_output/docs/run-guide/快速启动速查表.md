## 一句话启动（懒人版）
```powershell
.\start-all.ps1      # 本目录下，全量拉起（PG服务+Redis服务+sidecar+backend+frontend）
.\stop-all.ps1       # 全停（PostgreSQL 不动）；.estart-all.ps1 重启
```
手动顺序：PostgreSQL → Redis → runtime-sidecar → backend → frontend。

## 启动步骤（按顺序）

### 1. PostgreSQL（5432）
```
& "C:\Program Files\PostgreSQL\16\bin\pg_ctl.exe" start -D "C:\Program Files\PostgreSQL\16\data" -l "...\pg.log"
```
成功：`psql -U postgres -d postgres -c "SELECT version();"` 返回 16.x。

### 2. Redis（6379）
```
& "C:\Program Files\Redis\redis-server.exe" "C:\Program Files\Redis\redis.windows.conf"
```
成功：`redis-cli ping` → `PONG`。

### 3. 准备 `agent-platform\local-dev-env.ps1`（已 .gitignore）
注入：`JWT_SECRET`、`DB_PASSWORD`、`RUNTIME_CALLBACK_TOKEN`、`AUDIT_HMAC_KEY`（>=32 字符随机，审计哈希链 HMAC）、钉钉四项。**四项 fail-closed，未注入 backend 拒启动**。

### 4. runtime-sidecar（8090）
```
cd runtime-sidecar
python -m pip install -r requirements.txt   # 首次
. ..\local-dev-env.ps1
python -m uvicorn app.main:app --host 0.0.0.0 --port 8090
```
成功：`GET http://localhost:8090/health` → `{"status":"UP"}`。

### 5. backend（8080）
```
cd agent-platform\backend
. ..\local-dev-env.ps1
mvn spring-boot:run
```
成功：`Started ... in X seconds`，Flyway 自动跑迁移；`GET /api/...` 200。

### 6. frontend（5173）
```
cd agent-platform\frontend
npm run dev
npm install     # 首次
```
成功：Vite 打印 `Local: http://localhost:5173/`；浏览器可登录。

### 查端口 & 关端口
```powershell
# 查谁占了 8080
netstat -ano | findstr ":8080"
# 按 PID 强杀
taskkill /PID <PID> /F
# PowerShell 释放监听端口
Get-NetTCPConnection -LocalPort 8080 -State Listen | Select -Expand OwningProcess -Unique | % { Stop-Process -Id $_ -Force }
```

## 常见启动报错速查
| 报错 | 原因 | 解决 |
|---|---|---|
| `JwtUtil @PostConstruct` 拒启动 | 未注入 JWT_SECRET 或旧弱密钥 | local-dev-env.ps1 设随机 64 字节 base64 |
| Hikari 连不上库 | DB_PASSWORD 空（fail-closed） | 注入正确 PG 密码 |
| sidecar 回调全 401 | RUNTIME_CALLBACK_TOKEN 两端不一致 | dot-source 同一 local-dev-env.ps1 |
| 工作流执行失败 | mode=sidecar 但 sidecar 未起 | 先起 sidecar 或临时 `RUNTIME_GATEWAY_MODE=mock` |
| pgvector `>2000 dimensions for hnsw` | 用 vector(2048) 建索引 | 改 halfvec(2048)+halfvec_cosine_ops |
| 中文乱码 | JVM 默认 GBK | 启动加 `-Dfile.encoding=UTF-8` |
| 端口被占 | 残留进程 | 查 PID kill，优先 Stop-Service |

## 功能部署要点（按需）

### 项目资产库（Flyway V56–V59）
- **建表**：后端首次启动 Flyway 自动跑 V56(`asset_projects`+`asset_versions`+`asset_role_links`) / V57(`assets`) / V58(`asset_project_members`+`asset:write` 权限 seed) / V59(`asset_bindings`)。全新建表，无存量迁移，回滚=drop。
- **权限 gated**：`asset:write` 默认仅 **admin** 角色有（同 `canvas:write`/`media:gen` 范式）。普通用户须管理员在「角色权限」页授权才见「资产库」菜单。双层授权：平台层(`asset:write`) + 项目层(owner/member) 都过才可写。
- **无外部依赖**：纯 PG JSONB + 关系表，不引入新中间件。

### 视频模型能力配置（新增模型怎么设附件上限）
- **三层合并**（`MediaModelCapabilityService`，低→高）：保守兜底(1图/无音视频) → 内置前缀默认（id 含 `seedance-2`=9图/3视频/3音频/总12、`seedance-1`=1图）→ provider config `capabilities` 精确覆盖。
- **新模型接入**：① 模型 id 带 `seedance-2-`/`seedance-1-` 前缀 = 零配置；② 任意名 → 编辑 provider 的 config JSON 加 `"capabilities":{"<模型id>":{...}}`，字段只需写要改的（maxImages/maxVideos/maxAudios/maxAttachments/supportedRatios/supportedResolutions/minDuration/maxDuration/supportsGenerateAudio/videoDataUri），模型 id 须与 models 列表完全一致。
- **生效**：UI 编辑 provider 保存即自动 reload；直接改库须 `POST /api/llm/providers/reload` 或重启。
- 实例：本机 dev 库 seedance provider 的 `Cdance2.0` 即用此法配全量能力（2026-08-07，见 `人工测试问题/3. 模型接入问题.md`）。

### 视频剪辑（FFmpeg 后端渲染，Flyway V87）
- **建表**：后端首次启动 Flyway 自动跑 `V87__media_edit_tasks.sql`（`media_edit_tasks` 表 + `media:edit` 权限 seed）。append-only 任务日志 + 状态机（PENDING→RUNNING→SUCCEEDED/FAILED），`locked_until`+SKIP LOCKED worker 认领/崩溃恢复，`result_file_id` → `stored_files`（source=EDIT）。
- **权限 gated**：`media:edit` 默认仅 **admin** 有（同 `media:gen`）。普通用户须管理员授权才见 `/video-edit` 页可用。
- **FFmpeg 外部依赖（关键）**：渲染调系统 `ffmpeg`（单二进制，不需 ffprobe）。要求 **≥4.4**（滤镜用 `adelay=ms:all=1`，4.2.3 无 `all=`）。Windows 上 PATH 首个 ffmpeg 常是 ImageMagick 自带的 4.2.3 → 必须显式指现代版：设 `MEDIA_EDIT_FFMPEG_PATH=C:\ffmpeg-n7.1.1\bin\ffmpeg.exe`（本机用 7.1.1）。Linux 装 `ffmpeg` 包即可，无需此变量。
- **Windows 渲染坑（已在代码修，记录备查）**：filter_complex 的 `drawtext=fontfile=/textfile=` 若用绝对路径，盘符冒号 `C:` 被滤镜解析器当 option 分隔符 → `No option name near '/Windows/...'`。代码已改为：字体拷进 per-task workDir + `ProcessBuilder.directory(workDir)` + 相对名引用（`font.ttf`/`sub-N.txt`）。单引号包路径在 7.1.1 **不**保护冒号，勿回退。
- **字体**：字幕渲染需 CJK 字体。默认 `MEDIA_EDIT_FONT_FILE` 未设时探测 `C:/Windows/Fonts/simhei.ttf`（Win）/ macOS Arial Unicode / Linux `fonts-noto-cjk`。无字体且有字幕 → fail-fast（不静默降级）。
- **E2E 验证（2026-08-10）**：admin 登录 → `/video-edit` → 上传片段 → 加字幕 → 提交 → 任务 SUCCEEDED → 下载 mp4（3.0s / h264 1280×720@24fps + aac mono），ffmpeg 7.1.1 真渲染通过。

### 安全运维日志告警加固（Flyway V104，11x）
- **建表**：后端首次启动 Flyway 自动跑 `V104__security_hardening.sql`（`security_events` 半年留存 / `ip_blacklist` / `login_attempts` 30 天 / `users` +`ban_reason`+`locked_until` / 3 权限 seed `security:event:read`·`security:ban:manage`·`security:rule:manage` 自动授 admin 角色）。
- **权限三权分立**：3 权限默认仅 **admin** 有。普通用户无 `security:*` → 侧栏不显安全管理组、直输 URL 接口 403。
- **AUDIT_HMAC_KEY 传参坑（关键，2026-08-13 实证）**：`AuditHashChainService @PostConstruct` 校验非空+≥32 字符，缺失即启动崩。`mvn spring-boot:run` 的 `-Daudit.hmac-key=` 是 **mvn 进程参数，不传给 fork 的应用 JVM** → 仍崩。两种生效方式：① 改用 `-Dspring-boot.run.jvmArguments=-Daudit.hmac-key=...`；② **直接 jar 跑**（`java -jar`，`$env:AUDIT_HMAC_KEY` 继承到 java 子进程，实测稳）。`start-backend-claude.ps1` 当前用前者，需注意。
- **stale target/classes 坑**：删源码后 `target/classes` 残留旧 class（如曾误建 `common/security/GeoIpService` 与 `auth/service/GeoIpService` bean 名冲突）→ `ConflictingBeanDefinitionException`。`mvn clean package -Dmaven.test.skip=true` 全量重编清除。
- **ip2region.xdb（异地登录检测）**：`auth/service/GeoIpService` 启动加载 `resources/ip2region.xdb`（~11MB，GitHub lionsoul2014/ip2region）。缺失只 WARN 降级（异地提醒返"未知"，不阻断启动）。需手工放才生效。
- **钉钉告警**：在「安全规则」页配 webhook URL + 加签密钥，或 env `SECURITY_ALERT_WEBHOOK_URL`/`SECURITY_ALERT_WEBHOOK_SECRET`。未配=事件只入库不推钉钉。
- **D 盘日志**：≥25GB（四通道 180 天，网安法 21 条）。
- **单会话策略注意**：同账号新登录踢旧 session（`40104 账号已在别处登录`）。冒烟时 **curl 与 playwright 不要用同一账号**，否则互相踢 token。
- **E2E 验证（2026-08-13）**：admin12345 登录 → 4 安全页（大盘/事件/封禁/规则）渲染全绿；普通用户 idorprobe2 连打 12 次无权接口 → 403×12 → `IDOR_PROBE MEDIUM` 事件落库 → 事件中心可见 + 侧栏 badge(2) 60s 轮询联动 + ACK 后 badge→(1)；规则页改 idor 阈值 10→5 → `PUT /api/security/rules/security.rule.idor.threshold` 200 + DB 持久化热生效。
- **冒烟发现并修复的缺陷**：`GlobalExceptionHandler.handleBusinessException` 原不发 AUTHZ_DENIED 事件（只 `handleAccessDeniedException` 发），而 `@RequirePermission` 权限不足抛 `BusinessException(FORBIDDEN)`（非 Spring AccessDeniedException）→ 最常见 403 来源接不上 IdorProbe 规则。**已修**：handleBusinessException 加参数 `HttpServletRequest`，code 映射 403 时同样 publish。

### 资产库与画布四功能（修复XI，Flyway V169）
- **建表**：V169 存量迁移——`narrative_roles` 词汇表翻两级 `[{key,children}]`（幂等：已是两级结构跳过；读/入参双容错，老客户端不受影响）。无新表，回滚=还原该行 JSON。
- **改动面**：纯前端为主（画布右键菜单/官方库大卡片/组=大节点）+ 词汇两级 API；权限零新增（official 口径走既有 `asset:write`+项目层）。
- **冒烟脚本**：`docs/run-guide/smoke-xi.mjs`（Playwright 直跑，需前后端+PG；27 项覆盖四功能核心链含反向）。坑：**curl/API 播种与 playwright 别用同一账号**（单会话互踢）；vue-flow 自动化坑见 `开发进度/人工测试遗留问题修复XI/开发进度5.md`（pan 伴生 mousedown/元素级键盘焦点依赖/库选择集不随数组替换自清）。
- **E2E 验证（2026-09-02）**：smoke-xi 27/27；API p50/p95：canvas 列表 24/30ms、assets 10/15ms、project 10/14ms、vocab 11/25ms（本机 dev）。

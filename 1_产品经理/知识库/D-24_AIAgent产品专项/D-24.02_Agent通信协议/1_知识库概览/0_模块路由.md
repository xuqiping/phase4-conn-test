# D-24.02 Agent通信协议

## 是什么

**Agent 通信协议（Agent Communication Protocol）**：Agent 与外部世界（工具/其他 Agent/UI/能力市场）之间对话所遵循的标准——回答"Agent 怎么找工具、怎么调工具、多 Agent 之间怎么委派任务、Agent 怎么把过程推给前端、Agent 能力怎么打包可复用"。它是 Agent PM 做协议选型的核心命题：协议选错，集成成本翻倍、生态卡死、规模化阻塞。[来源:Agent协议层分析/Anthropic/Google/IBM/CopilotKit | 置信度:📚中]

**2026 业内共识——协议分层互补而非竞争**：Agent 协议不是"一个协议通吃"，而是云-边-端全域分层。业内已形成五大主流协议各占一层：
- **MCP（Model Context Protocol）= 接工具的万能插头**：Anthropic 2024-11 推出，2025-12 捐赠给 Linux 基金会 Agentic AI Foundation 治理，标准化"Agent ↔ 工具/数据源"连接，2026-07 月下载量 9700 万、注册 Server 超 10 万，已成事实标准 [来源:Anthropic/Linux基金会 | 🔍高 | 2026-07]
- **A2A（Agent-to-Agent Protocol）= 智能体间对讲机**：Google 2025-04 在 Google Cloud Next 推出，基于 HTTP+SSE+JSON-RPC，标准化"Agent ↔ Agent"任务委派与跨厂商互操作，2026 年进入 v1.0 GA、150+ 组织参与 [来源:Google A2A | 🔍高 | 2025-04/2026]
- **ACP（Agentic Context Protocol/Agent Communication Protocol）= 边缘智能体上下文层**：IBM Bee Agent Framework 主导推动，双层面设计（通信连接层+智能体上下文层），定位边缘本地协同场景，是与 MCP/A2A 并列的第三大协议 [来源:IBM Bee Agent Framework | 🔍高 | 2026]
- **AG-UI（Agent User Interaction Protocol）= 前端物流系统**：CopilotKit 2025-05 开源发布（MIT 许可），2026-06 获 Google 与 Microsoft 同时采纳，标准化"Agent ↔ 前端"实时通信，CopilotKit 完成 2700 万美元 A 轮融资 [来源:CopilotKit/AG-UI | 🔍高 | 2025-05/2026-06]
- **Anthropic Skills = 装进脑子里的经验包**：Anthropic 2025-10 推出的 Agent 能力封装格式，把领域 know-how 打包成 Skills 让 Agent 加载即用——与 MCP Tool 不互斥而是互补（Skill 是经验，Tool 是工具）[来源:Anthropic Skills | 🔍高 | 2025-10]

**核心认知——五协议不是五选一而是按形态组合**：单一协议覆盖不了完整 Agent 产品的所有通信需求。典型组合：单 Agent=MCP+AG-UI；多 Agent=MCP+A2A+AG-UI+Skills；边缘 Agent=ACP+（按需）MCP；企业级 Agent 系统=全协议栈（MCP+A2A+ACP+AG-UI+Skills）。

## 核心要素

| 要素 | 说明 | 典例 |
|---|---|---|
| **协议分层定位** | 五协议各占一层（工具/Agent间/边缘/前端/能力），非竞争而是互补 | MCP=工具层/A2A=Agent间层/ACP=边缘层/AG-UI=前端层/Skills=能力层 |
| **通信模式** | 协议底层通信机制（HTTP/SSE/WebSocket/JSON-RPC/stdio） | MCP用stdio+HTTP+SSE；A2A用HTTP+SSE+JSON-RPC；AG-UI用HTTP+SSE；ACP用本地消息 |
| **核心能力封装** | 协议承载的能力单元（Tool/Task/Context/Skill/UI Event） | MCP封装Tool；A2A封装Task+Artifact；Skills封装Skill指令集；AG-UI封装Event |
| **生态规模与成熟度** | 协议的采纳广度与生产就绪度 | MCP最成熟(10万+Server)；A2A次之(150+组织)；AG-UI/Skills/ACP新兴 |
| **国内标准化** | 中国信通院 ATH 握手协议、全国信标委 AIP 国标 | 信通院2026年发起ATH、50家企业试点；AIP国标推进中 [来源:信通院/信标委 | 🔍高 | 2026] |
| **协议选型决策** | 根据场景(单Agent/多Agent/前端交互/能力复用/边缘)选协议组合 | 单Agent=MCP+AG-UI；多Agent=MCP+A2A+AG-UI+Skills |
| **协议集成成本** | 集成难度与运维负担 | MCP集成最轻(社区SDK多)；A2A需编排引擎；AG-UI需前端改造；Skills需封装规范 |
| **协议治理与合规** | 协议的可观测、可追溯、可治理能力 | MCP 2026-07-28"史上最大修订"转向生产级智能体基础设施(全链路可治理+调用全流程可追溯+可观测三件套) [来源:MCP官方 | 🔍高 | 2026-07] |

## 为什么Agent PM必须懂Agent通信协议

1. **协议选错=集成成本翻倍+生态卡死**——单Agent误选A2A会增加编排复杂度，多Agent误选纯MCP会缺乏任务委派能力，前端缺AG-UI会让Agent过程不可见；协议是Agent PM做架构选型的第一分叉，下游集成成本、团队能力、生态广度全部由协议分叉决定 [来源:Agent协议选型实践 | 📚中]
2. **2026是Agent协议标准化元年，五大协议格局已定**——MCP(2024-11)/A2A(2025-04)/AG-UI(2025-05)/Skills(2025-10)/ACP(2025-2026)在18个月内集中涌现，Linux基金会/Google/Anthropic/IBM/CopilotKit五方主导，2026业内"协议分层互补"共识形成，PM必须懂格局否则选型跑偏 [来源:Linux基金会/Google/Anthropic | 🔍高 | 2026]
3. **MCP已成事实标准，2026-07-28史上最大修订重塑协议治理**——MCP月下载量9700万、注册Server超10万，是五协议中生态最成熟的一个；2026-07-28发布"史上最大修订"候选规范，从工具调用协议转型为生产级智能体基础设施（全链路可治理+调用全流程可追溯+可观测三件套）；不懂MCP等于不懂Agent工具层 [来源:MCP官方/Linux基金会 | 🔍高 | 2026-07-28]
4. **多Agent协作强制依赖A2A，跨厂商互操作成刚需**——2026 Anthropic 5-Agent报告证明多Agent协作胜出，企业普遍需跨厂商Agent互联（OpenAI+Anthropic+自研Agent混用）；A2A v1.0 GA + 150+组织参已成为Agent间任务委派事实标准，多Agent产品不集成A2A等于自建孤岛 [来源:Google A2A/Anthropic | 🔍高 | 2026]
5. **AG-UI是Agent过程可视化的关键，2026-06双大厂采纳**——前端不再只是"等结果"，而是实时看到Agent规划/工具调用/中间结果；AG-UI 2026-06获Google与Microsoft同时采纳，CopilotKit完成2700万A轮融资；人机协同/自主Agent前端不集成AG-UI只能自研SSE/WebSocket，成本高且无标准化 [来源:CopilotKit/AG-UI | 🔍高 | 2026-06]
6. **国内合规必须关注信通院ATH与信标委AIP国标**——中国信通院2026年发起智能体可信握手协议（ATH），全国信标委推动智能体互联协议（AIP）国家标准，50家企业已试点；面向国内市场（尤其国企/政府/金融）的Agent产品需提前对齐国标，否则后期改造成本巨大 [来源:信通院/信标委 | 🔍高 | 2026]

## 常见误区

- **误区1：五协议是竞争关系，必须五选一**——五协议是分层互补而非竞争：MCP=工具层、A2A=Agent间层、ACP=边缘层、AG-UI=前端层、Skills=能力层；一个完整Agent产品通常组合使用多协议（如单Agent=MCP+AG-UI，多Agent=MCP+A2A+AG-UI+Skills），不是二选一
- **误区2：把MCP等同于全部Agent协议**——MCP只是工具层协议，解决"Agent怎么调工具"；多Agent协作需A2A、前端交互需AG-UI、能力复用需Skills、边缘协同需ACP；只懂MCP的PM做不了多Agent产品
- **误区3：协议选型只看技术先进性**——协议选型要看四维：技术成熟度+生态规模+治理能力+国内合规；MCP技术先进但若面向国内国企市场，还需对齐信通院ATH；A2A先进但若团队无编排经验会增加集成成本
- **误区4：忽视MCP 2026-07-28修订的治理转向**——修订前MCP只是工具调用协议，修订后转向生产级智能体基础设施（全链路可治理+调用全流程可追溯+可观测）；用旧版MCP做生产Agent会缺可观测/可审计能力，必须升级
- **误区5：把Skills当成MCP的子集**——Skills是能力封装格式（know-how打包），MCP是工具调用协议（外部能力调用）；Skills让Agent加载"经验包"获得领域专长，MCP让Agent调外部工具；两者正交互补，不是包含关系
- **误区6：ACP只是IBM小众项目无需关注**——ACP是与MCP/A2A并列的第三大协议，双层面设计（通信连接+智能体上下文）独有边缘本地协同优势，在IoT/工业/边缘场景不可替代；做边缘Agent产品必须懂ACP
- **误区7：协议一旦选定无法更换**——协议可通过Adapter/网关层解耦，但中后期更换成本高（涉及工具/Agent/UI/能力全链路改造）；协议选型应在立项阶段用决策矩阵慎重定，避免反复

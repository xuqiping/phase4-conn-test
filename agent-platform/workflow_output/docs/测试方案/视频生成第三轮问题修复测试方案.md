# 视频生成第三轮问题修复测试方案

> Phase 3 自动化自验与 Phase 4 人工冒烟的共同基准；浏览器和真实 Provider 验证留到 Phase 4。

## 前置条件

- 普通用户可登录并访问视频生成页、资产库和无限画布。
- 账号至少有图片、视频、音频各一份，并有可用 SeedDance/Cdance 模型。
- 历史中包含成功、运行中、失败和旧版本任务。

## 核心用例

1. **AC-V3-01 多次引用**：插入第一个附件 chip 后继续输入 `@`，候选仍出现；连续插入两到三个附件，序列化 token、中文、换行和删除后再引用均正确。
2. **AC-V3-02 历史筛选**：提示词大小写、特殊字符和 `[from,to)` 时间边界正确；清空恢复；普通用户不可看到他人任务。
3. **AC-V3-03 参数恢复**：点击历史后恢复模型、提示词、比例、时长、分辨率、水印、音频和附件角色；失权附件只显示占位且不可重用。
4. **AC-V3-04 媒体预览**：历史成功行只在可视区加载视频；资产选择器显示图片/视频；失败时降级文字且不影响选择。
5. **AC-V3-05 持续轮询**：超过 600 秒仍保持运行；查询网络错误只退避重试；Provider 明确失败才落失败；页面销毁停止本地轮询但后端任务继续。
6. **AC-V3-06 请求快照**：新任务详情可查看并复制平台提交参数及实际 Provider 脱敏快照；旧任务明确提示未记录，不伪造。
7. **AC-V3-07 输入输出语义**：输入附件在 `inputAttachments` 和快照 `content[]` 中可追溯；未成功前 `videoUrl/imageUrls=null` 合理。

## 功能联动用例

- 改筛选条件后历史与行内预览同步重查，旧 object URL 被释放；清空和无结果空态正确。
- 点击历史后表单、附件、当前任务与轮询同时切换；模型下线和附件失权不静默替换。
- Provider `RUNNING` 时数据库安排下次查询并释放线程；`SUCCEEDED` 后下载、计费和历史同步更新。
- Provider POST 前保存脱敏快照；POST 失败仍保留该次实际尝试结构。
- 页面或节点销毁时停止本地轮询和释放 URL，不取消后端任务。

## 安全与通过标准

- API、数据库、日志和页面均不出现原始 `data:`、密钥或 Authorization。
- 预览文件仍经文件接口二次鉴权；筛选使用绑定参数并保持 ownership。
- 相关单测、前端构建、后端测试与最小质量门通过；Phase 4 浏览器冒烟逐项通过。

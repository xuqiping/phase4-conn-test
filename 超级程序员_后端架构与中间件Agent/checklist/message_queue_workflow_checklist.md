# Message Queue Workflow Checklist

在完成 `workflow/message_queue_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别消息队列需求场景

- [ ] 已明确场景类型（MQ选型/架构设计/工程实践/集群迁移/创业选型）
- [ ] 已识别应用类型（微服务事件总线/大数据流处理/金融交易/SaaS多租户/轻量异步）
- [ ] 已提取吞吐量等级（低<1万/中1-10万/高>10万/超高速日志流）
- [ ] 已提取可靠性要求（允许丢失/不丢失可重复/金融级精确一次）
- [ ] 已提取团队现状（已有集群需迁移/全新选型/云托管偏好）
- [ ] 已对照知识库四大产品定位完成初步判断（RabbitMQ/RocketMQ/Kafka/Pulsar）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出消息队列方案

- [ ] 如为MQ选型，9维评估法（吞吐/延迟/持久性/顺序/多租户/协议/生态/成本/团队）已应用
- [ ] 如为MQ选型，RabbitMQ/RocketMQ/Kafka/Pulsar选型对比表已输出
- [ ] 如为MQ选型，决策树已给出（金融→RocketMQ、大数据→Kafka、SaaS多租户→Pulsar、微服务事件→RabbitMQ/Pulsar）
- [ ] 如为架构设计，集群拓扑已覆盖（Broker部署模式、ZK vs KRaft、Proxy架构）
- [ ] 如为架构设计，Topic/Queue设计规范已给出（命名规范、分区策略、副本数建议）
- [ ] 如为架构设计，消费者组设计已覆盖（消费模式、重试策略、死信队列、消费位点管理）
- [ ] 如为工程实践，消费者幂等设计已说明（唯一ID+去重表+业务状态机校验）
- [ ] 如为工程实践，生产者可靠投递已覆盖（Confirm/ACK机制、事务消息、本地消息表+补偿）
- [ ] 如为工程实践，大消息处理方案已给出（大消息拆分、对象存储+MQ传引用ID）
- [ ] 如为迁移方案，双写灰度迁移三步法已说明（双写→Consumer切流→下线老集群）
- [ ] 如为迁移方案，数据一致性校验方案已覆盖（消息对账、MD5校验、延迟对账补偿）
- [ ] 如为迁移方案，回滚预案已给出（切流异常时快速回切）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 输出内容无知识性错误
- [ ] 已向用户交付最终答案

- [ ] 每一步都已与其检查清单部分进行交叉验证
- [ ] 没有在任何检查清单部分通过前提前进入下一步

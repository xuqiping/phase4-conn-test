> 承 [开发进度8.md](./开发进度8.md)。本篇记 **连线可删（自定义边×按钮 + window Delete）+ 焦点编辑框选**（2026-08-09，commit `3786b9a6`）。

## 背景

开发进度8 的「点边选中高亮 → Delete」用户实测仍删不掉。另报：图片节点「焦点编辑」拖拽框选时拉动图片而非画框。

## 根因（playwright + 代码深挖）

### 连线删除：删除依赖 boardRoot 聚焦 → 用户环境失效

`CanvasBoard` 删除链：`@edge-click`→`selectedEdgeId`+`boardRoot.focus()`→`boardRoot` 上的 `@keydown.delete`→`deleteSelected`。playwright（JS dispatch + 真实点击）均能删。但**用户实测失败**：点边后 `boardRoot` 聚焦被抢占（属性面板输入框 / IME / 其他控件）→ `boardRoot` 的 keydown 不触发 → Delete 无效。且**无可发现入口**（用户不知 Delete 键可用）。

### 焦点编辑：底图 `<img>` 原生 HTML5 拖拽劫持

`FocusEditOverlay` 的 `<img>` 原生可拖（HTML5 drag），mousedown 命中 img 即触发浏览器原生图片拖拽（幽灵预览→视觉「图片被拖动」），同时 stage 的 mousedown 虽记 start 但浏览器接管后续 drag → 框选断裂。`onMouseDown` 无 preventDefault，img 无 `draggable=false`。

### 补：结构变更落库（发现并修补既有缺口）

排查中发现 `CanvasBoard`（无限画布）**无任何结构变更保存触发**（连线增/删、节点拖动结束后不落库，仅 workflow 的 FlowCanvas 有 nodes-change）。新增 `structure-changed` emit（`onConnect`/`removeNodes`/`removeEdges`/`@node-drag-stop`）→ CanvasView `scheduleSave`，与用户操作手册「停手 800ms 落库」承诺对齐。

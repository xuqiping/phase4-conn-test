# File Keeper Desktop 认证与商业授权模块总结

## 1. 模块职责一句话

负责桌面端用户身份认证（登录/注册/退出）、设备身份管理、匿名试用与免费模块选择、登录用户设备绑定与商业授权快照查询，以及离线缓存与模块级门禁控制，是 File Keeper 商业版功能收口的核心安全模块。

## 3. 核心数据流 / 调用链路

### 3.1 登录链路

1. 用户在 `LoginForm.vue` 输入 identifier + password，调用 `authStore.login(baseUrl, identifier, password)`
2. `authStore` 调用 `authApi.login()` → `POST /api/client/auth/login`
3. 登录成功后，`authStore` 将 session（accessToken / refreshToken / user）写入内存并持久化到 `file-keeper-auth.json`（Tauri Store）
4. `authStore.login()` 接着调用 `commercialAuthStore.initializeAuthenticated(baseUrl, accessToken)`
5. `commercialAuthStore` 获取/创建设备身份 → 调用 `registerClientDevice()` → `POST /api/client/devices/register`（带 Bearer Token）
6. 然后调用 `getClientAuthorization()` → `GET /api/client/authorization?deviceId=...`（带 Bearer Token，附客户端时间戳）
7. 若授权快照包含 `offlineToken` 和 `offlineUsableUntil`，则通过 Tauri invoke `set_offline_token` 将离线 token 同步到 Rust 层，并调用 `check_offline_access` 缓存各模块离线权限

### 3.2 注册链路

1. 用户在 `RegisterForm.vue` 选择邮箱/手机，填写联系方式，点击“发送验证码”
2. 调用 `authStore.sendVerificationCode()` → `POST /api/client/verification/send`
3. 用户输入验证码，点击“校验验证码”，调用 `authStore.checkVerificationCode()` → `POST /api/client/verification/check`
4. 校验通过后，填写密码，点击“提交注册”，调用 `authStore.register()` → `POST /api/client/auth/register`
5. 注册成功后 UI 显示“注册成功，等待管理员审核”，不自动登录

### 3.3 设备注册链路

- 登录成功后，`commercialAuthStore.initializeAuthenticated()` 自动调用 `registerClientDevice()`，将设备身份（deviceId / fingerprintHash / deviceName）POST 到 `/api/client/devices/register`
- 服务端返回 `ClientDevice`，包含设备绑定状态、是否活跃等信息
- 若设备数超限，服务端返回 409，桌面端通过 `commercialAuthStore.error` 暴露错误

### 3.4 授权查询链路（登录用户）

- `getClientAuthorization()` → `GET /api/client/authorization?deviceId=...&clientTimestamp=...`
- 返回 `ClientAuthorizationSnapshot`，包含：mode='authenticated'、userId、accountStatus、deviceLimit、onlineRequired、offlineUsableUntil、offlineToken、deviceBinding、modules[]
- `commercialAuthStore` 将快照存入 `clientAuthorization`，并计算 `moduleAccess`（Map<ModuleCode, {allowed, reason}>）
- 若 `onlineRequired=false` 且存在 `offlineUsableUntil`，同步离线 token 到 Rust

### 3.5 匿名试用链路

1. 启动时 `App.vue` 调用 `authStore.restoreSession()`，若本地无 refresh token，则调用 `commercialAuthStore.initializeAnonymous(baseUrl)`
2. `initializeAnonymous()` 获取/创建设备身份 → `startAnonymousTrial()` → `POST /api/anonymous/trial/start`
3. 然后 `getAnonymousAuthorization()` → `GET /api/anonymous/authorization?deviceId=...&fingerprintHash=...`
4. 返回 `AnonymousAuthorizationSnapshot`，包含 mode='anonymous'、onlineRequired、modules[]
5. 匿名试用前 7 天 `inFullTrial=true`，三模块全可用；过期后 `trialExpired=true`，需选择免费模块

### 3.6 免费模块选择/更换链路

- 匿名试用过期且未选择免费模块时，`App.vue` 的 `showFreeModuleSelector` 计算为 true，主内容区显示 `FreeModuleSelector`
- 用户点击模块选项：
  - 首次选择：调用 `commercialAuthStore.selectFreeModule(baseUrl, moduleCode)` → `POST /api/anonymous/trial/select-free-module`
  - 更换：调用 `commercialAuthStore.changeFreeModule(baseUrl, moduleCode)` → `POST /api/anonymous/trial/change-free-module`
- 成功后再拉取 `getAnonymousAuthorization()` 刷新授权状态
- 后端限制：每 30 天只能更换一次，否则返回 409 错误

### 3.7 离线 token 链路

- 登录用户授权快照若包含 `offlineToken`，`commercialAuthStore.syncOfflineTokenToRust()` 调用 Rust `set_offline_token` 命令，传入 token 和剩余有效秒数
- Rust `auth.rs` 中的 `OfflineTokenState` 保存 token、设置时间、离线时长
- 当网络断开或刷新授权失败时，`commercialAuthStore` 检查 `hasValidOfflineClientAuthorization()`，若有效则设置 `usingOfflineClientAuthorization=true`
- 模块权限判断时，离线模式优先使用 Rust 层 `check_offline_access` 的签名校验结果（通过 invoke 调用），失败则回退到内存中的 `offlineAccessCache` 或 `moduleAccess`
- 退出登录或授权失效时，调用 `clearOfflineTokenInRust()` 清除 Rust 层 token

## 4. 关键状态与 Store 说明

### 4.1 authStore（`file-keeper/src/stores/authStore.ts`）

- **职责**：纯身份认证状态管理（与商业授权解耦）
- **状态**：
  - `accessToken: string | null` — JWT access token
  - `refreshToken: string | null` — JWT refresh token
  - `user: UserSummary | null` — 用户信息（含 status、deviceLimit、offlineCacheMinutes）
  - `loading: boolean` — 异步操作状态
  - `error: string | null` — 错误信息
  - `isAuthenticated: ComputedRef<boolean>` — 是否已认证
- **持久化**：使用 `@tauri-apps/plugin-store` 的 `Store.load('file-keeper-auth.json')`，key 为 `authSession`
- **关键行为**：
  - `login()`：登录成功后将 session 持久化，然后调用 `commercialAuthStore.initializeAuthenticated()`
  - `logout()`：调用后端 logout API，清除内存和持久化 session，然后调用 `commercialAuthStore.initializeAnonymous()`
  - `restoreSession()`：启动时从 Tauri Store 恢复 session，用 refresh token 刷新，失败则回退匿名授权

### 4.2 commercialAuthStore（`file-keeper/src/stores/commercialAuthStore.ts`）

- **职责**：商业授权、设备身份、模块权限、离线缓存的统一管理
- **状态**：
  - `deviceIdentity: DeviceIdentity | null` — 设备身份（deviceId / fingerprintHash / deviceName）
  - `trialStatus: AnonymousTrialStatus | null` — 匿名试用状态
  - `anonymousAuthorization: AnonymousAuthorizationSnapshot | null` — 匿名授权快照
  - `clientDevice: ClientDevice | null` — 登录用户设备信息
  - `clientAuthorization: ClientAuthorizationSnapshot | null` — 登录用户授权快照
  - `usingOfflineClientAuthorization: boolean` — 是否正在使用离线缓存授权
  - `offlineAccessCache: Map<ModuleCode, boolean>` — 各模块离线权限缓存
  - `loading / error` — 异步状态
- **计算属性**：
  - `moduleAccess: Map<ModuleCode, {allowed, reason}>` — 合并匿名和登录授权的模块权限，登录授权优先
- **关键行为**：
  - `initializeAnonymous()`：获取设备身份 → 启动匿名试用 → 查询匿名授权
  - `initializeAuthenticated()`：获取设备身份 → 注册设备 → 查询登录授权 → 同步离线 token
  - `isModuleAllowed(moduleCode)`：判断模块是否可用，离线模式优先使用 Rust 校验结果
  - `denialReason(moduleCode)`：返回模块被拒绝的原因
  - `handleAuthenticatedAuthorizationError()`：区分结构化 API 错误（清除授权）和网络错误（尝试使用离线缓存）

### 4.3 两个 Store 的关系

- `authStore` 不依赖 `commercialAuthStore`（除登录/退出时的初始化调用）
- `commercialAuthStore` 不依赖 `authStore` 的导入，但 `moduleAccess` 计算时会参考 `authStore.isAuthenticated`（在 `EntitlementStatus.vue` 中组合使用）
- 持久化文件共享：`file-keeper-auth.json`（`authStore` 存 `authSession`，`commercialAuth.ts` 存 `deviceIdentity`）

## 5. 关键组件说明

### 5.1 AuthDialog.vue

- 登录/注册弹窗，通过 `show` prop 控制显示
- 内部使用标签页切换 `LoginForm` 和 `RegisterForm`
-  emits：`close`（关闭弹窗）、`authenticated`（登录成功）
- 弹窗打开时默认选中登录标签页

### 5.2 LoginForm.vue

- 仅包含 identifier（邮箱或手机号）和 password 输入
- 提交时调用 `authStore.login()`，成功后 emit `success`
- 表单验证：必填检查

### 5.3 RegisterForm.vue

- 支持邮箱/手机两种注册方式（select 切换）
- 流程：发送验证码 → 校验验证码 → 提交注册
- 验证码校验通过后才允许提交注册（`codeVerified` 状态）
- 注册成功后显示“注册成功，等待管理员审核”，不自动登录

### 5.4 EntitlementStatus.vue

- 纯展示组件，只读取 `authStore` 和 `commercialAuthStore`
- 显示状态包括：
  - 匿名 7 天全功能试用中（含截止日期）
  - 匿名试用已过期 / 未选择免费模块
  - 匿名免费模块（显示当前模块名）
  - 等待管理员审核（`pending_review`）
  - 商业授权（显示 files/processes/clipboard 各模块授权状态）
  - 离线缓存截止时间
  - 授权异常（显示 `commercialAuthStore.error`）
- 不同状态使用不同颜色边框/背景：绿色（已授权）、黄色（警告/待审核）、红色（异常）

### 5.5 FreeModuleSelector.vue

- 仅在匿名试用过期且未选择免费模块、且当前无可用模块时显示（由 `App.vue` 的 `showFreeModuleSelector` 计算属性控制）
- 展示三个模块选项：文件管理、进程管理、剪贴板
- 首次选择调用 `selectFreeModule()`，更换调用 `changeFreeModule()`
- 已选择模块显示“已选择”标签，其他模块可点击更换（每 30 天限制由后端控制）
- 选择成功后 emit `selected`，`App.vue` 收到后切换回可用模块并同步剪贴板监听

## 6. 核心功能

### 6.1 桌面端登录/注册

- 支持邮箱或手机号作为登录标识符（`identifier`）
- 注册需先发送验证码，再校验验证码，最后提交注册
- 注册后用户状态为 `pending_review`，需管理员审核后才能获得商业授权
- 登录成功后自动绑定设备并拉取授权快照

### 6.2 验证码流程

- `sendVerificationCode()` → `POST /api/client/verification/send`
- `checkVerificationCode()` → `POST /api/client/verification/check`
- 支持邮箱和手机号两种联系方式
- 开发环境使用固定验证码 `123456`（由后端配置 `FILE_KEEPER_VERIFICATION_DEV_FIXED_CODE` 控制）

### 6.3 匿名试用

- 新设备首次启动自动获得 7 天全功能试用（`inFullTrial=true`）
- 试用期间 files/processes/clipboard 三模块全可用
- 试用过期后（`trialExpired=true`），若无免费模块选择，则模块不可用，强制显示 `FreeModuleSelector`

### 6.4 授权状态展示

- `EntitlementStatus` 组件常驻于 `App.vue` 顶部工具栏
- 实时反映当前是匿名试用、等待审核、商业授权还是异常状态
- 登录用户显示各模块授权明细（已授权/未授权 + 原因）

### 6.5 免费模块选择

- 匿名试用过期后，用户可选择一个模块长期免费使用
- 已选择后每 30 天可更换一次（后端限制）
- 选择/更换后立即刷新匿名授权快照，UI 自动更新

### 6.6 离线缓存

- 管理员可在后台设置用户的 `offlineCacheMinutes`
- 登录用户授权快照包含 `offlineUsableUntil` 和 `offlineToken`
- 前端将 `offlineToken` 同步到 Rust 层，Rust 使用 HMAC-SHA256 验证 token 签名，防止篡改
- 断网或刷新失败时，若离线缓存未过期，仍可使用已授权模块
- 离线缓存过期后，自动回退到匿名授权或显示未授权

### 6.7 设备绑定

- 每个设备生成唯一 `deviceId`（基于 `crypto.randomUUID()`）和 `fingerprintHash`（基于浏览器/设备环境特征）
- 设备身份持久化到 `file-keeper-auth.json`，并在 `localStorage` 中备份（防清除）
- 登录后自动调用设备注册 API，服务端检查设备数量是否超过 `deviceLimit`
- 管理员可在后台禁用设备，禁用后该设备的登录授权失效

## 8. 已知缺口 / TODO

根据 `file-keeper/项目相关文档/商业售卖版账号权限与授权系统实施计划-新.md`，当前已完成的阶段 5B/5C/5D 对应原计划阶段 5/6 的桌面端 UI 补齐，但仍存在以下缺口：

1. **端口配置未完全固化**：`App.vue` 中 `commercialServerUrl` 默认兜底仍为 `http://localhost:8080`，计划要求统一为 `8088`（`file-keeper/.env.development` 已建议创建，但未确认是否已落地）。

2. **匿名设备运营页（管理后台）**：服务端目前没有管理端匿名设备列表、重置试用、禁用匿名设备 API，管理后台缺少 `AnonymousDevicesView.vue`。文档明确将其列为“非第一版阻塞项”，但仍是已知缺口。

3. **Rust 侧授权二次校验（阶段 6）**：当前模块门禁主要在前端（`canUseTab()` 控制 Tab 显示/隐藏），Rust 层仅对离线 token 做了校验。计划中提到需要对“进程结束命令、截图/OCR 命令、剪贴板监听命令”增加模块权限和快照有效期校验，尚未实施。

## 9. 与其他模块的依赖关系

### 9.1 上游依赖（被本模块调用）

- **Tauri Store 插件**（`@tauri-apps/plugin-store`）：`authStore` 和 `commercialAuth.ts` 使用 `Store.load('file-keeper-auth.json')` 持久化 session 和设备身份
- **Tauri Core API**（`@tauri-apps/api/core`）：`commercialAuthStore` 通过 `invoke()` 调用 Rust 命令 `set_offline_token`、`clear_offline_token`、`check_offline_access`
- **Tauri Window API**（`@tauri-apps/api/window`）：`App.vue` 使用 `getCurrentWindow()` 控制窗口最小化/最大化/关闭/隐藏

### 9.2 下游依赖（调用本模块）

- **App.vue**（`file-keeper/src/App.vue`）：
  - 引入 `useAuthStore` 和 `useCommercialAuthStore`
  - 启动时调用 `authStore.restoreSession()`
  - 使用 `canUseTab(tab)` 控制 files/processes/clipboard 三个 Tab 的可用性（禁用未授权模块）
  - 使用 `showFreeModuleSelector` 计算属性控制免费模块选择器的显示
  - 登录/退出/免费模块选择后调用 `ensureAuthorizedTab()` 和 `syncClipboardMonitor()`
  - 进程管理、截图、剪贴板监听等入口均先检查 `canUseTab()`

- **剪贴板模块**（`ClipboardManagement.vue`、`ClipboardQuickPanel.vue`）：通过 `App.vue` 的 `syncClipboardMonitor()` 间接依赖授权状态，未授权时剪贴板监听不启动

- **进程管理模块**（`ProcessManagement.vue`）：通过 `App.vue` 的 `canUseTab('processes')` 控制入口，右键菜单“关闭已打开的进程”也受 `canUseTab('processes')` 限制

- **文件模块**：批量操作工具栏、文件拖放、文件打开等功能不受授权限制（文件管理是基础功能），但关联的进程关闭操作受 `processes` 模块授权控制

### 9.3 模块间数据流向

```
用户操作 → AuthDialog/LoginForm/RegisterForm
    → authStore (login/logout/register)
        → auth API (fetch) → 后端 /api/client/auth/*
        → commercialAuthStore (initializeAuthenticated/initializeAnonymous)
            → commercialAuth API (fetch) → 后端 /api/client/devices/* / /api/anonymous/*
            → Rust commands (invoke) → auth.rs (offline token)
    → App.vue (watch moduleAccess → ensureAuthorizedTab/syncClipboardMonitor)
        → EntitlementStatus (展示)
        → FreeModuleSelector (条件渲染)
        → Tab 按钮 (canUseTab 禁用/启用)
```

## 2026-08-14 · Step 2 KB 入库注入扫描隔离（SEC-FR-051）✅

- **迁移 `V122__ai_security.sql`**：`knowledge_documents.quarantine_reason VARCHAR(255)` +
  `llm_usage_logs.session_id VARCHAR(64)` + partial index `idx_llm_usage_logs_session`（session 列为 Step 4 会话 token 上限预铺）。纯加列可回滚。
- **特征库**：`InjectionSignatureLibrary.matchFull(text)`——≤4000 直扫；超长 4k 窗/2k 步滑窗（防特征跨窗漏检），命中注 `@offset`。复用 11x 特征库零新增规则。
- **扫描挂点**：`DocumentParserService.parse()` 在 `completeProtocol` 后、`persistIfVersioned` 前——命中 → `quarantine()`（状态 QUARANTINED + reason 截 250 + KIND_KB_INJECTION HIGH 事件 + `security.ai.kb.quarantined` 指标）并 return（不落 parse artifact、不索引）。扫描文本 = plainText，空则 sections content 拼接。开关 `security.ai.kb-scan.enabled`（默认 true，EDITABLE_KEYS 热调）；异常一律放行。
- **事件链 6 触点**（沉淀范式）：KIND_KB_INJECTION / SecurityEventTypes / KbInjectionRule（ACT_NONE）/ DingtalkCardBuilder「KB文档注入隔离」/ 前端 security.ts EVENT_TYPE_CN / EDITABLE_KEYS。actor = operatorId 兜底 doc.createdBy（异步解析线程操作者可能为空）。
- **解除**：`KnowledgeDocumentService.unquarantine()`（canManage 校验，仅 QUARANTINED 可解；置回 PENDING + 清 reason + **重发 DocumentUploadedEvent**——解析是事件驱动，只改状态不会自动跑）。端点 `POST /knowledge/documents/{id}/unquarantine`（`knowledge:manage` + @AuditLog）。
- **前端**：`DocumentManager.vue` statusMap 加 `QUARANTINED(红)`；错误列 `quarantineReason || parseError`；操作列 QUARANTINED+canWrite 出「解除隔离」按钮（`unquarantineDocument` API + 刷新列表）。`KnowledgeDocumentVO/接口` 加 `quarantineReason`。
- **测试**：`InjectionSignatureLibraryTest` +3（matchFull 短文一致/10k 深处命中/跨 4k 边界）8/8；`DocumentParserInjectionScanTest` 6/6（隔离写库+事件、actor 回退、干净放行、开关关、设置异常、sections 兜底）；前端 vue-tsc 0 错 + knowledge/api vitest 14 绿。
- **踩坑**：全量 vitest 有 7 个预存失败（VideoGenView 2 + PricingConfigView 5），stash 验证与本步无关。

# File Keeper 项目结构说明

> 本文档用于说明主项目 `file-keeper` 的代码目录与职责，方便快速定位模块、排查问题和新成员上手。

---

## 1. 项目整体架构

`file-keeper` 是一个面向 Windows 桌面的效率工具，整体采用“桌面端 + 授权服务 + 管理后台”的组合：

| 子系统 | 技术栈 | 主要职责 |
|--------|--------|----------|
| 桌面端主界面 | Vue 3 + TypeScript + Vite + Tailwind CSS | 文件管理、应用进程管理、剪贴板、截图、商业授权状态展示等 UI |
| 桌面端原生层 | Tauri 2.0 + Rust | 提供 Win32 API、文件/进程/图标/剪贴板/截图/OCR 等原生能力 |
| 授权与账号服务 | Spring Boot 3.2.5 + MyBatis-Plus + PostgreSQL | 商业授权、匿名设备试用、账号、统计、审计、后台管理接口 |
| 管理后台 | Vue 3 + TypeScript + Naive UI | 管理员查看用户、设备、授权、统计、系统设置 |
| OCR 辅助程序 | Python + RapidOCR/ONNX Runtime | 可选本地 OCR 增强（sidecar 模式） |
| 图标生成脚本 | Node.js / 浏览器页面 | 生成 Tauri 安装包所需的多尺寸图标 |

---

## 2. 顶层目录速查

```
file-keeper/
├── src/                 # 桌面端前端 Vue 源码
├── src-tauri/           # Rust + Tauri 桌面端源码与配置
├── server/              # Java Spring Boot 授权/账号服务
├── admin-web/           # 管理后台 Vue 前端
├── tools/               # 周边工具（目前主要是 ocr-sidecar）
├── scripts/             # 图标生成等 Node 脚本
├── dist/                # 前端构建产物（Vite 输出）
├── docs/                # 项目文档
└── ...                  # 设计稿、规范、需求文档等非代码目录
```

> `dist/`、`node_modules/`、`src-tauri/target/`、`server/target/` 均为构建产物或依赖目录，**不属于源码**，下文不再赘述。

## 3. 桌面端前端 `src/`

桌面端主界面源码，由 `main.ts` 入口挂载，根据 URL 参数决定渲染主窗口或截图覆盖层窗口。

| 目录/文件 | 说明 |
|-----------|------|
| `main.ts` | Vue 应用入口；创建 Pinia 并挂载持久化插件；根据 `?screenshotOverlay` 切换为截图覆盖层组件 |
| `App.vue` | 主应用根组件，承载整个桌面端 UI |
| `api/` | 封装对 Tauri Rust 命令的调用，以及商业授权、文件、进程、剪贴板、截图、工作汇报、持久化等接口 |
| `components/` | Vue 组件库：文件/分组/进程/剪贴板/截图/设置/登录/授权状态/工作汇报/Toast 等大量 UI 组件 |
| `composables/` | 组合式函数：国际化、图标懒加载、虚拟滚动、文件拖拽排序、Toast、持久化等 |
| `locales/` | 国际化语言包：`zh-CN.ts`、`en.ts` |
| `plugins/` | 自定义插件：Pinia 持久化插件（本地数据落盘） |
| `stores/` | Pinia 状态管理：文件、分组、进程、剪贴板、商业授权、设置、最近文件、选中、工作汇报等 |
| `styles/` | 全局 CSS/样式变量 |
| `types/` | TypeScript 类型定义：文件、分组、进程、剪贴板、截图、设置、工作汇报等 |
| `utils/` | 通用工具函数：批量操作、文件处理、搜索高亮、路径处理等 |
| `views/` | 页面级路由视图（目前仅保留 `.gitkeep`，主界面由 `App.vue` 直接组织） |

### 测试

前端采用 **Vitest** 做单元测试。测试文件集中在 `__tests__` 子目录内，与源码并排：

- `api/__tests__/`
- `components/__tests__/`
- `plugins/__tests__/`
- `stores/__tests__/`
- `utils/__tests__/`

## 4. Tauri Rust 后端 `src-tauri/src/`

Rust 原生层源码，负责与操作系统交互，并通过 `invoke` 暴露命令给前端。

| 目录/文件 | 说明 |
|-----------|------|
| `main.rs` | Tauri 应用入口：注册插件、初始化剪贴板服务、构建托盘菜单、挂载所有 `invoke` 命令 |
| `commands/` | 暴露给前端的 Tauri 命令模块 |
| `commands/files.rs` | 文件打开、路径校验、在文件夹中显示 |
| `commands/processes.rs` | 查找占用某文件的进程、关闭进程 |
| `commands/process_management.rs` | 运行中应用枚举、关闭/强制结束应用窗口、激活窗口 |
| `commands/icons.rs` | 提取文件图标 |
| `commands/clipboard.rs` | 剪贴板历史监控、搜索、复制/粘贴、设置、存储统计等 |
| `commands/screenshot.rs` | 区域截图、截图 OCR 状态 |
| `commands/auth.rs` | 离线 token 设置/清除/校验 |
| `commands/work_report.rs` | **工作汇报：Git 日志读取、本地通知、Markdown 导出** |
| `clipboard/` | 剪贴板内部服务实现：缓存、OCR、OCR  Provider、搜索、安全策略、SQLite 存储、类型定义 |
| `platform/` | 平台适配层 |
| `platform/windows/` | Windows 专属实现：剪贴板、前台窗口、进程枚举/映射/监控、截图 |
| `platform/linux.rs` | Linux 平台占位/适配 |
| `platform/macos.rs` | macOS 平台占位/适配 |
| `platform/windows_file_matcher.rs` | Windows 下文件与进程匹配逻辑 |
| `types/` | Rust 共享类型 |
| `utils/` | 通用工具：进程匹配器等 |

### 关键配置与资源

| 文件/目录 | 说明 |
|-----------|------|
| `src-tauri/tauri.conf.json` | Tauri 应用配置：窗口、安全 CSP、资源协议、MSI 安装包、图标 |
| `src-tauri/Cargo.toml` | Rust 依赖配置 |
| `src-tauri/capabilities/default.json` | Tauri 2 权限能力声明 |
| `src-tauri/icons/` | 应用图标（`.ico`、多尺寸 `.svg`） |
| `src-tauri/build.rs` | 构建脚本 |

## 5. Java 服务端 `server/src/main/java/com/superprogrammer/`

Spring Boot 后端，承担商业授权、账号、设备绑定、匿名试用、后台管理、审计等职责。

| 包/目录 | 说明 |
|---------|------|
| `FileKeeperServerApplication.java` | Spring Boot 启动类 |
| `admin/` | **后台管理接口**：管理员登录、用户/设备/授权/设置/统计等管理端 Controller 与 Service |
| `audit/` | **审计日志**：`AdminAuditLog` 实体与审计服务 |
| `authorization/` | **授权核心**：匿名授权、客户端授权、授权快照、模块访问控制、离线 Token 签名 |
| `bootstrap/` | **启动初始化**：超级管理员账号预置 |
| `common/` | **公共基础设施**：统一响应 `R<T>`、`PageResult<T>`、业务异常 `BusinessException`、错误码、全局异常处理、基础实体 `BaseEntity` |
| `config/` | **配置类**：认证属性、MyBatis-Plus、密码编码器、自动填充（创建/更新时间、操作人） |
| `device/` | **设备管理**：用户设备绑定、匿名设备试用、试用限流、设备注册/选择免费模块 |
| `security/` | **安全认证**：JWT 认证过滤器、JWT Service、Refresh Token（Redis）、Security 配置、请求日志 |
| `settings/` | **系统设置**：系统配置项的存储与读取 |
| `stats/` | **统计数据**：管理仪表盘统计 DTO 与查询 |
| `user/` | **用户模块**：注册/登录/验证码、用户实体、授权记录、用户设置 |
| `workreport/` | **工作汇报模块**：工作记录、每日安排、报告配置、报告生成、AI 总结、飞书推送 |

### 资源与迁移

| 目录 | 说明 |
|------|------|
| `server/src/main/resources/db/migration/` | Flyway 数据库迁移脚本：`V1__create_auth_schema.sql` ~ `V4__device_time_sync_anomaly.sql`，以及工作汇报模块相关迁移 |
| `server/src/test/` | Java 单元/集成测试源码 |

## 7. 周边工具

### `tools/ocr-sidecar/`

可选的本地 OCR 增强程序，编译为独立可执行文件后放到安装目录 `ocr/file-keeper-ocr.exe`，File Keeper 会优先调用它，缺失时回退到 Windows 系统 OCR。

| 文件 | 说明 |
|------|------|
| `file_keeper_ocr.py` | OCR 主逻辑（RapidOCR + ONNX Runtime） |
| `build-windows.ps1` | Windows 下打包脚本 |
| `requirements.txt` | Python 依赖 |
| `README.md` | 输入/输出协议说明 |

### `scripts/`

| 文件 | 说明 |
|------|------|
| `generate-icons.js` | Node.js 图标生成脚本 |
| `generate-icons.html` | 浏览器版图标生成页面 |
| `generate-icons-svg.js` | SVG 图标处理脚本 |
| `README.md` | 图标生成与放置说明 |

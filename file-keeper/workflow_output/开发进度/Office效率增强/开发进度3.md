## 1. 审查问题与 TDD RED

旧实现通过压缩、转小写和字符串包含判断 OOXML 元数据，存在两个可复现缺陷：

| 定向测试 | 预期 | RED 实际 |
|---|---|---|
| `commented_fake_override_and_relationship_do_not_validate_the_package` | 注释中的伪 `Override/Relationship` 不得使残缺包通过 | 错误返回 `SAFE_OOXML` |
| `character_reference_decoded_to_external_routes_to_high_fidelity` | `TargetMode="Extern&#97;l"` 解码后按外链升级 | 错误返回 `SAFE_OOXML` |
| `dtd_after_a_valid_override_is_rejected` | 找到合法 `Override` 后仍必须扫描至 EOF 并拒绝 DTD | 错误提前返回 `SAFE_OOXML` |

三条测试均先在对应缺陷实现上失败，失败点为分类断言，证明命中的是解析缺陷而非夹具或编译错误。

## 2. 最小 GREEN 实现

- 引入 `quick-xml 0.39.4`，逐事件解析 `[Content_Types].xml` 和所有 `.rels`。
- 只识别真实 `Override` 与 `Relationship` 元素；XML 注释不参与判断。
- 属性通过解析器解码并反转义，因此数字字符引用 `&#97;` 能还原为 `a`。
- 任意 DTD、畸形 XML、无效属性或未知实体均阻断；不加载外部实体，也不回显 XML 正文。
- 保留解压后 4 MiB 硬限制：`.rels` 超限仍返回 `OFFICE_RELATIONSHIP_TOO_LARGE`。
- 保持稳定错误码：关系解析失败返回 `OFFICE_RELATIONSHIP_READ_FAILED`；内容类型解析失败返回 `OFFICE_INVALID_OOXML_PACKAGE`。
- MIME 内容类型按 ASCII 大小写不敏感比较，以兼容合法宏格式中的 `macroEnabled/macroenabled` 写法；部件路径和关系目标仍精确匹配。

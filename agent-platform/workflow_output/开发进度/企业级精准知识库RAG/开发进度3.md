# 企业级精准知识库 RAG 开发进度 3

## P1 Step 1：Canonical Document 与版本状态机

- 复用 V17 既有 `knowledge_documents` 作为 Canonical Document，没有重复新建主文档表。
- 新增 V106，升级既有 `knowledge_document_versions`：文件引用、源 Hash、撤销、替代关系和单一 EFFECTIVE 约束。
- 存量迁移先把旧 ACTIVE/STALE 归一，再按 `current_version_id` 或最新版本选择唯一生效项并回填主指针，避免唯一索引冲突。
- 新增 `KnowledgeDocumentVersion`、Mapper 和事务状态机服务，支持创建 v1、创建草稿、生效、替代、撤销、历史查询。
- 使用 `SELECT ... FOR UPDATE` + `expectedCurrentVersionId` 做并发冲突检测；旧页面提交过期指针时明确报“版本冲突”。
- 上传文档自动创建 v1；新版本必须上传真实 multipart 文件，`fileRef/sourceHash` 由后端存储与计算，前端不能伪造。
- 撤销当前版本会清空 Canonical Document 当前指针，检索 SQL 要求 `current_version_id IS NOT NULL`，撤销后立即退出召回。
- 生效/撤销均发布知识可见性失效事件，联动答案缓存主动失效；API 带权限和审计。
- 前端文档管理增加版本抽屉，可查看历史、上传草稿、生效和撤销。

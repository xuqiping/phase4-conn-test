# 3.6 采集架构与技术选型

## G.01 三大采集架构对比

| 维度 | 客户端SDK | 服务端采集 | 日志采集 |
|---|---|---|---|
| **数据来源** | 用户交互行为 | 业务系统接口调用 | 服务器运行日志 |
| **采集位置** | App/Web/小程序 | 后端服务 | 服务器/容器 |
| **数据精度** | 高（用户视角） | 高（业务视角） | 低（系统视角） |
| **延迟** | 即时 | 即时 | T+1或准实时 |
| **隐私风险** | 高（采集端侧数据） | 中（可控脱敏） | 低（不含个人信息） |
| **漏采风险** | 依赖SDK稳定/版本覆盖 | 依赖接口覆盖 | 依赖日志完整 |
| **典型场景** | 用户行为分析 | 交易/业务数据分析 | 系统监控/异常排查 |

## I.16 跨端IDMapping

同一用户在Web/App/小程序使用不同标识符，需要IDMapping关联：

| 端 | 标识符 | 特点 |
|---|---|---|
| Web | Cookie ID / localStorage ID | 可被清除，隐私限制增多 |
| App | Device ID(IDFA/GAID)/UUID | iOS ATT框架后获取受限 |
| 小程序 | OpenID/UnionID | 依赖微信生态 |
| 服务端 | User ID | 登录后才能获取 |

**IDMapping策略**：
1. 未登录态：用设备标识符做匿名ID
2. 登录后：将匿名ID与用户ID关联
3. 跨端：用UnionID或手机号/邮箱做跨端关联键
4. 隐私合规：IDMapping本身也需用户同意

## 一、用户地图

- **谁会用**：系统维护者（= 你自己/未来的运维）。不需要懂英文、不需要懂代码。
- **什么场景下用**：
  - 每天早上花 5 分钟扫一眼 Grafana「系统总览」，确认昨夜没出事；
  - 后端宕机/磁盘快满/接口报错飙升/大模型大面积失败时，**钉钉群 5 分钟内主动收到告警**（不用等用户报障——修的就是 RB-001「出事几小时才发现」）；
  - 发布新版本时跑一条命令（deploy.bat），起不来自动换回旧版；
  - 每天凌晨自动备份数据库和上传文件，出事能恢复到昨天。
- **带来什么效益**：故障发现从「小时级」→「1~5 分钟」；发布事故 10 分钟回滚；数据最多丢 24 小时（日备）；巡检/runbook 全中文成文，不靠记忆。
- **谁用不到**：终端用户无感知（这是后台能力）；多服务器/K8s 场景不适用（本方案是 Windows 单机设计）。

## 二、技术说明

- **职责**：四个「可」——可观测（指标+四中文看板）、可告警（8 条规则→钉钉）、可恢复（日备+周备+异地预案）、可发布（一键脚本+健康门禁+自动回滚）。
- **关键入口**：
  - 指标产出：后端 `BizMetrics`（五域统一埋点）+ `/actuator/prometheus`（仅 127.0.0.1）；sidecar `/metrics`。
  - 采集：Prometheus（:9090）15s 拉取 → Alertmanager（:9093）→ 钉钉适配器（:8060）→ 钉钉群。
  - 看板：Grafana（:3000）「运维监控」文件夹四看板，provisioning 自动加载（JSON 入库版本化）。
  - 备份：`D:\IT\ops\backup\` 三脚本 + 计划任务（PgBackup 02:00 / FilesBackup 02:30 已注册）。
  - 发布：`deploy/deploy.bat`（备份→停→拷→起→健康轮询→回滚）。
- **依赖**：后端/ sidecar 代码（埋点）；PostgreSQL/Redis（被监控对象）；WinSW（全部进程服务化）；钉钉机器人（告警通道，用户自配 webhook）。
- **部署/配置注意**：监控五组件全部只绑 127.0.0.1（与 /actuator 同安全策略）；密钥/webhook 只存服务器本地（仓库只存 .example 模板）；高基数值（userId/IP/traceId）永远不进 metric tag。
- **排障要点**：面板空先看目标是否 UP（targets 页）再看指标是否懒注册（首次调用才出现）；告警没收到按「Prometheus 规则状态 → Alertmanager 告警列表 → 适配器日志」三级定位；详细处置查《运维手册.md》告警速查表。

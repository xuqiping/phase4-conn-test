# 5.1 案例集（10 例）

## 案例 1：Karpathy Vibe Coding 发源（范式发源标杆）

- **名称**：Vibe Coding（氛围编程）概念诞生
- **时间**：2025-02
- **主角**：Andrej Karpathy（OpenAI 创始成员、特斯拉前 AI 总监）
- **背景**：2025 年初 Coding Agent 刚兴起，开发者探索新的编程范式
- **技术手法**：Karpathy 发推定义 Vibe Coding——"你完全沉浸在氛围之中，拥抱指数级增长，甚至忘记代码的存在……我总是全部接受，不再看差异对比。遇到东西不对，我就把报错扔给 AI"
- **影响后果**：Vibe Coding 迅速成为 2025 原型期主流——烧 token 换效率，快速验证想法。但也埋下隐患：不看 diff、全部接受的习惯被一些人带进生产
- **教训启示**：① Vibe Coding 是原型期利器不是生产期方法；② "全部接受不看 diff"适合快速验证不适合质量交付；③ 2026 行业集体认知重建——Vibe Coding 必须升级为 Agentic Engineering
- **来源**：[知乎《认知重建之后步入Agentic Engineering的工程革命》| 🔍高 | 2026-03]

## 案例 2：Boris Cherny + Peter Steinberger 写循环言论（范式跃迁标杆）

- **名称**：Loop Engineering 范式确立——"写循环让循环调度模型"
- **时间**：2026-06
- **主角**：Peter Steinberger（OpenClaw 创始人）、Boris Cherny（Claude Code 负责人）
- **背景**：2026 年 Agent 工程重心从 Prompt Engineering 迁移到 Loop Engineering
- **技术手法**：Peter Steinberger 发文"别再手动给 AI 编码代理写提示词了，应该去设计一个能替你写提示词的系统"；Boris Cherny 跟进"我现在的日常工作就是写循环(Loop)，让循环去调度 Claude，自己不再逐条下达指令"；Google Cloud 工程团队同方向跟进
- **影响后果**：Loop Engineering 成 2026 新焦点，AI 工程四代范式演进（Prompt→Context→Harness→Loop）确立。Agent Loop（运行时机制）vs Loop Engineering（系统设计学科）的关键区分成为行业共识
- **教训启示**：① Agent Loop ≠ Loop Engineering——前者 30 行 Python 能写出，后者是系统设计学科；② 工程重心代际迁移：人逐条指令→设计循环让循环调度模型；③ 还在简历写"精通 Prompt Engineering"会被猎头建议更新技能树
- **来源**：[腾讯云/新浪/网易《你还在手写Prompt?聪明的人早就用上了循环工程》| 🔍高 | 2026-06~07]

## 案例 4：麦肯锡 75% 停滞鸿沟（行业警示标杆·反面教材）

- **名称**：Agent 项目规模化鸿沟——75% 停滞试点
- **时间**：2026-07
- **主角**：麦肯锡调研 / 亚马逊全球副总裁储瑞松
- **背景**：2026 全球企业 AI 转型进入深水区，从试点到规模化的鸿沟显现
- **技术手法**：麦肯锡调研数据：近 90% 企业已启动 AI 转型，75% 长期停留在试点，仅约 10% 规模化，仅 1% 高管认为成熟
- **影响后果**：储瑞松点明症结——"企业推动 Agent 从原型走向实际生产时，普遍缺乏科学有效的开发部署指导，而这恰恰是横亘在试点与规模化之间的鸿沟"
- **教训启示**：① 75% 停滞是 2026 Agent 工程化的最大警钟；② 症结是缺乏科学开发部署指导，不是模型不够强；③ 跨越鸿沟靠 Agentic Engineering 方法论而非堆模型能力；④ PM 是跨越鸿沟的第一责任人
- **反面警示**：90% 启动但仅 1% 成熟——绝大多数倒在试点到规模化之间，这是 2026 Agent 项目最大杀手
- **来源**：[网易《通过企业生产级智能体开发部署指南看Agentic AI规模化破局之道》/麦肯锡 | 🔍高 | 2026-07]

## 案例 5：腾讯云上线两周翻车（行业警示标杆·反面教材）

- **名称**：Agent 上线两周典型翻车场景
- **时间**：2026-07
- **主角**：无数企业的真实翻车（腾讯云总结）
- **背景**：Agent 原型 Demo 看着像那么回事，上线后翻车反复上演
- **技术手法**：腾讯云描述典型场景——团队三周搭原型接知识库看 Demo 像那么回事，上线两周后：① Agent 把客户订单信息张冠李戴；② 把合同条款搞混；③ 凌晨三点自动发了一封莫名其妙的邮件；④ 手忙脚乱关掉自动化又变回需人盯的聊天机器人
- **影响后果**：这个故事在无数企业反复上演，成为 Agent 工程化缺失的典型病症
- **教训启示**：① Demo 是确定性场景的精心编排，生产是长尾不确定性的真实考验；② 从 Demo 到生产必须经过四层工程进化（原型→稳定→规模→原生），跳层必翻车；③ 概率性智能跑在确定性生产系统是核心命题；④ 凌晨三点自动发邮件=缺乏灰度与熔断
- **反面警示**：张冠李戴/合同搞混/凌晨发邮件是 Agent 工程化缺失的三大典型病症，任何一项都可能是生产事故
- **来源**：[腾讯云《Loop Engineering 又是啥?一文讲清企业Agent落地的四层工程进化论》| 🔍高 | 2026-07]

## 案例 6：易点天下 QCon 从 Prompt 到 Context（工程实践标杆）

- **名称**：Agentic AI 工程化实践——从 Prompt 到 Context
- **时间**：2026-05
- **主角**：易点天下中台研发总监何宇航（2026 QCon 全球软件开发大会·北京站）
- **背景**：2026 生成式 AI 告别"Demo 满天飞"狂热期，步入工程化落地深水区
- **技术手法**：何宇航分享核心方法论——① 工程重心从 Prompt 转向 Context（给模型喂对信息比说对话更重要）；② 驯服幻觉与遗忘（在确定性企业架构中给 Agent 加约束）；③ 概率性稳定化（通过可观测/容错/兜底让概率性输出稳定到可接受范围）；④ 渐进式上生产（原型→稳定→规模→原生四层渐进不跳层）
- **影响后果**：成为"概率性智能跑在确定性生产系统"命题落地的一线实践方法论标杆
- **教训启示**：① 工程重心从 Prompt 到 Context 是 2026 趋势；② 确定性企业架构容纳概率性 Agent 靠约束+可观测+兜底；③ 渐进式上生产不跳层是工程化铁律；④ 一线实践方法论比理论更有参考价值
- **来源**：[搜狐《从Prompt到Context:易点天下Agentic AI工程化实践》/QCon 2026 北京 | 🔍高 | 2026-05]

- **名称**：Strands Agents——2026 企业级 Agent 构建首选框架
- **时间**：2026-07
- **主角**：Strands Agents 框架（CSDN 2026-07 详评）
- **背景**：2026 Agent 框架生态进入"生态位锁定"阶段，LangGraph 主导生产编排、CrewAI 占据原型、Strands Agents 凭差异化崛起
- **技术手法**：Strands Agents 核心特性——① 轻量级、代码优先；② 多模型提供商（默认 Amazon Bedrock + Claude）；③ 内置完整可观测性、追踪、安全；④ 支持对话式/非对话式 Agent；⑤ 流式/非流式响应；⑥ 完整对话管理

- **教训启示**：① 企业级 Agent 框架选型三考量：上手快 + 生产就绪 + 内置可观测；② Strands Agents 不追求功能全，追求开箱即用；③ 框架生态位锁定是 2026 趋势——LangGraph 生产编排/CrewAI 原型/Strands 企业级各占其位

## 案例 8：GPT-5.5 成本失控 140 元（成本治理标杆·反面教材）

- **名称**：AI 成本飙升倒逼企业换脑——GPT-5.5 单次调用 $0.18/token
- **时间**：2026-07
- **主角**：麦卡锡建筑公司财务总监（搜狐报道典型）/ GPT-5.5
- **背景**：2026 AI 不是在卷性能而是在卷"钱包厚度"，企业集体惊醒"不是在用 AI，是在给大模型供奉香火"
- **技术手法**：搜狐描述真实场景——GPT-5.5 单次调用成本飙至 $0.18/token，一个内部会议纪要生成吃掉 372 token 折合人民币近 140 元，员工悄悄把"让 AI 写周报"设为每日 KPI
- **影响后果**：Model Router（大模型路由网关/聚合平台）成 2026 爆发式需求，成最火降本黑科技
- **教训启示**：① 成本失控是 2026 第一杀手；② 无任务分级（简单任务也用最贵模型）是成本失控主因；③ 无预算熔断=月底天价账单；④ Model Router 根据任务类型智能调度可降本 60-80%
- **反面警示**：会议纪要 140 元/周报成每日 KPI——成本失控往往是"温水煮青蛙"，发现时已是天价账单
- **来源**：[搜狐《AI成本飙升倒逼企业换脑!模型路由器成2026年最火降本黑科技》| 🔍高 | 2026-07]

## 案例 9：Microsoft Foundry 模型路由器（成本治理标杆·正面解药）

- **名称**：Microsoft Foundry Model Router——官方模型路由器标杆
- **时间**：2026-05
- **主角**：微软 Azure（Microsoft Foundry）
- **背景**：企业多模型接入后成本失控，需智能调度降本
- **技术手法**：Model Router 是一种训练好的语言模型，能实时智能地将提示导向最合适的 LLM。四大价值：① 节省成本（简单任务路由到便宜模型）；② 高性能（复杂任务路由到强模型）；③ 降低延迟（按延迟需求选模型）；④ 提升反应速度（实时路由决策）。部署方式像其他 Foundry 模型，单一部署形式对调用方透明
- **影响后果**：成官方模型路由器标杆，企业级 Model Router 落地参考
- **教训启示**：① Model Router 本身是一个训练好的小模型（路由器模型）；② 实时判断提示特征导向最合适 LLM；③ 对调用方透明是关键设计；④ 与模型仓库集成才能发挥作用
- **来源**：[Microsoft Azure 官方文档《Microsoft Foundry 的模型路由器》| 🔍高 | 2026-05]

## 案例 10：Anthropic 五大工作流模式行业共识（方法论共识标杆）

- **名称**：工作流 vs 智能体二分法 + 五大工作流模式成行业共识
- **时间**：2026-07
- **主角**：Anthropic（阿里云 2026-07 系统总结引）
- **背景**：2026 是 AI Agent 从概念验证走向工程化落地的关键转折年，需共识性设计范式
- **技术手法**：Anthropic 提出工作流 vs 智能体二分法——工作流=LLM 和工具通过预定义代码路径编排（确定性），智能体=LLM 自主决定执行路径与工具调用（概率性）。五大工作流模式：① 提示链（串行）；② 路由（分流）；③ 并行化（并行聚合）；④ 编排者-执行者（分解聚合）；⑤ 评估器-优化器（生成评估迭代）。加 agentic loop（智能体循环）构成主流范式
- **影响后果**：二分法 + 五大模式成行业共识，行业正经历从 Harness 到 Loop Engineering 的范式跃迁
- **教训启示**：① 工作流 vs 智能体二分法是 2026 Agent 设计的共同语言；② 五大工作流模式覆盖主流编排场景；③ agentic loop 是自主执行范式；④ PM 必须掌握这套设计语言才能与工程团队同频
- **来源**：[阿里云天池论坛《2026年AI Agent框架的现状与趋势》| 🔍高 | 2026-07]

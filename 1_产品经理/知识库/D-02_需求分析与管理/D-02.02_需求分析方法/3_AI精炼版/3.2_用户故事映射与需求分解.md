# 3.2 用户故事映射与需求分解

## 用户故事映射（User Story Mapping）

用户故事映射是Jeff Patton提出的需求组织方法——按**用户旅程的先后顺序**纵向排列活动，按**优先级/迭代**横向排列故事，从二维视角看到需求全貌。[来源:Jeff Patton·User Story Mapping | 🔍高 | 2014]

### 故事地图结构

```
                ← 优先级/迭代 →
                
        Release 1    Release 2    Release 3
         (MVP)       (增强)       (完善)

用户     ┌──────────┬──────────┬──────────┐
旅程     │ Story A1 │ Story A2 │ Story A3 │  骨干行
(纵轴)   │          │          │          │
         ├──────────┼──────────┼──────────┤
         │ Story B1 │ Story B2 │          │  细节行
         │          │          │          │
         ├──────────┼──────────┤          │
         │ Story C1 │          │          │
         └──────────┴──────────┴──────────┘
         
活动1 →   活动2 →     活动3 →     活动4 →    (骨干行)
```

### 构建步骤

| 步骤 | 动作 | 关键产出 | 常见错误 |
|---|---|---|---|
| 1 | 列出用户活动（骨干） | 活动序列 | 活动粒度不一致 |
| 2 | 为每个活动写用户故事 | 故事卡片 | 写成功能而非故事 |
| 3 | 按优先级排列故事 | 纵向排序 | 把所有故事都标P0 |
| 4 | 划分发布切片 | MVP/迭代划分 | MVP太大或太小 |
| 5 | 检查遗漏 | 补充缺失场景 | 只看"正常路径"忽略"异常路径" |

### 故事地图的核心价值

1. **发现遗漏**：纵向看旅程——"用户到了这一步，然后呢？"→ 补缺失路径
2. **控制MVP范围**：横向切一刀——"最小可行路径"=骨架+最关键细节
3. **全局视角**：不再淹没在需求列表里，看到完整体验地图
4. **团队对齐**：可视化让所有人看到同一张图

## 需求分解：Epic → Feature → Story

| 层级 | 粒度 | 时间跨度 | 谁负责 | 举例 |
|---|---|---|---|---|
| **Epic** | 一个大的业务目标 | 1-3个月 | PM+业务 | "用户能够在移动端管理项目" |
| **Feature** | 一个完整用户能力 | 1-4周 | PM | "移动端查看项目进度" |
| **Story** | 一个可交付的用户任务 | 1-3天 | PM+开发 | "作为PM，我想在手机上查看任务看板，以便出差时也能跟进进度" |

### 分解原则

| 原则 | 含义 | 反模式 |
|---|---|---|
| **横向切割** | 每一层都是可独立交付的用户价值 | 技术层切割（前端Story+后端Story） |
| **INVEST原则** | 独立/可协商/有价值/可估算/小/可测试 | 模糊的Story写法 |
| **完成定义** | 每个Story有明确的Done标准 | "做完"≠"做好" |
| **边界清晰** | Story之间不重叠 | 一个需求拆成5个Story但其实在做同一件事 |

## INVEST原则

| 字母 | 原则 | 含义 | 检查问题 |
|---|---|---|---|
| **I** | Independent | 故事间相互独立 | 这个Story能否单独交付？ |
| **N** | Negotiable | 故事可协商细节 | 开发能否提出更优方案？ |
| **V** | Valuable | 对用户有明确价值 | 用户真的在意这个吗？ |
| **E** | Estimable | 可估算工作量 | 开发能否给出时间估算？ |
| **S** | Small | 足够小 | 能否在1个迭代内完成？ |
| **T** | Testable | 可验证 | 怎么确认做完了？ |

## 遗漏发现：故事地图的"漏洞扫描"

| 扫描维度 | 检查问题 | 常见遗漏 |
|---|---|---|
| **主路径完整性** | 每个活动→下一步都有故事吗？ | "完成任务后"的状态回退 |
| **异常路径** | 出错/中断/超时场景有故事吗？ | 网络断开时的处理 |
| **角色覆盖** | 所有用户角色都覆盖到了吗？ | 管理员/访客/审批者遗漏 |
| **数据流** | 数据从哪来到哪去？ | 数据同步/冲突处理遗漏 |
| **边界条件** | 空/满/极端情况有故事吗？ | 首次使用（空状态）/超大文件上传 |

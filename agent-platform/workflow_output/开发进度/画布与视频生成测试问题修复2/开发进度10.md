# 画布与视频生成 · 测试问题修复2 · 开发进度10

> 2026-08-11：修复 Ark 参考视频传输和帧/参考媒体互斥问题；真实浏览器与 Ark 冒烟留 Phase 4。

## 本轮完成

- 参考视频不再转 `data:video/*`，改为带 `expires` 和 HMAC-SHA256 `sig` 的短期公网 HTTPS URL。
- 新增 `/api/media/reference/{fileId}` 回拉端点：签名/过期校验、常量时间比较、仅下发 `video/*`、`nosniff`、不记录原 URL。
- 未配置公网 HTTPS 地址或至少 32 字节签名密钥时，模型目录返回 `referenceVideoEnabled=false`，页面隐藏入口，后端提交也明确拒绝。
- Provider 请求快照把签名 URL整体替换为 `{redacted:true,transport:"https_url",fileId}`，不保存查询串和签名。
- 后端统一拒绝“任意首/尾帧 + 任意参考图/视频/音频”；首帧+尾帧仍允许。
- 视频页双向禁用并提示两种模式互斥；无限画布在组装附件时本地拒绝帧+`@参考图`。
- `@` 映射保持不变：提示词按媒体类别改写为图N/视频N/音频N，附件按稳定顺序随请求发送；它是位置/自然语言关联，不是 UUID 强绑定。

## 配置

```text
MEDIA_REFERENCE_PUBLIC_BASE_URL=https://Ark可访问的域名
MEDIA_REFERENCE_SIGNING_KEY=至少32字节随机密钥
MEDIA_REFERENCE_TTL_SECONDS=900
```

`localhost`、局域网地址和 HTTP 地址不会开放参考视频能力。

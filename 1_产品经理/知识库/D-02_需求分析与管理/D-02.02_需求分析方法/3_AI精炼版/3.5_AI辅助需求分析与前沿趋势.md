# 3.5 AI辅助需求分析与前沿趋势

## AI在需求分析中的三层能力

| 层级 | 能力 | 典型场景 | 可信度 |
|---|---|---|---|
| **L1 一致性检查** | 自动检测需求文档中的矛盾/歧义/遗漏 | PRD写完后AI扫描——"需求A说必须，需求B说禁止" | 📚中→🔍高（规则类检查准） |
| **L2 智能补全** | 根据已有需求推理遗漏场景 | 给定骨干故事，AI建议"是否需要异常处理""角色X的路径呢？" | ⚠️低-📚中（推理有创意但不一定贴合） |
| **L3 依赖推理** | 自动识别需求间的依赖和冲突 | AI扫描需求列表，输出依赖矩阵+风险标注 | ⚠️低（复杂依赖容易漏/错判） |

## AI辅助5Why

```
人工输入：表层需求现象
  ↓ AI第一步：生成3-5条可能的Why1路径
  ↓ 人工选择最合理的路径
  ↓ AI第二步：基于选择的路径，继续生成Why2候选
  ↓ 人工判断+补充
  ↓ 循环到根因
```

> AI的5Why价值不是"替你想"，而是"帮你跳出单一路径"——人类容易陷入一条推理链，AI可以同时给出多条可能路径。[来源:📚训练知识]

## AI辅助故事映射

| AI能力 | 输入 | 输出 | 可信度 |
|---|---|---|---|
| **骨干生成** | 用户活动列表 | 骨干行建议 | 📚中 |
| **故事补全** | 已有故事 + 用户画像 | 遗漏故事建议 | ⚠️低-📚中 |
| **异常路径建议** | 主流程故事 | 常见异常场景建议 | 📚中（模式化的异常场景准） |
| **优先级建议** | 故事列表 + 业务目标 | 优先级排序建议 | ⚠️低（需人工结合业务判断） |

## AI辅助依赖分析

```
输入：需求条目列表（含功能描述）
  ↓ AI扫描：关键词匹配+语义推理
  ↓ 输出候选依赖：
  │  需求A → 前置依赖 → 需求B（语义关联度0.85）
  │  需求C ↔ 互斥 → 需求D（逻辑冲突检测）
  │  需求E → 数据依赖 → 需求F（数据流分析）
  ↓ 人工审核：确认/修正/补充
```

> AI依赖分析的最大限制：只能分析**显性语义依赖**，无法识别**隐性组织依赖**（如"这个需求需要隔壁团队配合，但他们Q3排满了"）。[来源:📚训练知识]

## 2026前沿趋势

### 趋势1：AI需求分析从"审查"到"共创"

2026年的新范式：AI不再只是"帮你检查"，而是**参与需求讨论**——
- AI在需求评审会中实时标注矛盾点
- AI根据行业模式库建议"相同领域的其他产品通常还做了什么"
- AI将口头讨论实时转化为结构化需求条目

### 趋势2：需求分析的可视化自动化

输入文字需求描述，AI自动生成：
- 用例图（参与者+系统边界自动识别）
- 流程图（主路径+异常分支自动推断）
- 状态图（对象状态变迁自动提取）

### 趋势3：AI+人工的"需求分析流水线"

```
人工提交原始需求 → AI初分析（一致性+遗漏+依赖）
  → 人工精分析（5Why/故事映射/建模）
  → AI复审（检查人工分析的遗漏）
  → 人工终审确认
```

### 红线：AI需求分析不能做的事

| 红线 | 原因 | 正解 |
|---|---|---|
| 不能用AI替代5Why的推理 | AI推理链≠理解真实因果 | AI给候选路径，人工判断因果 |
| 不能用AI的故事映射替代用户验证 | AI补全的场景≠用户真实场景 | AI建议 + 用户访谈验证 |
| 不能用AI的依赖分析替代技术评审 | AI看不懂隐性架构约束 | AI初检 + 技术负责人确认 |
| 不能省略跨角色需求评审 | AI无法完全理解组织博弈 | AI辅助 + 人工多方评审 |

# D-24.05 多Agent协作 — 知识库引用场景

## 用法说明

本文件列出 PM 在 10 类典型工作场景中如何引用 D-24.05 多 Agent 协作能力。每条场景含：触发条件、推荐子维度（D-24.05 内）、推荐模式/协议、PM 输出物、关键避坑点。每条场景末尾给出对应碎片指针（3.1 拓扑 / 3.2 通信 / 3.3 失败治理 / 4.1 设计 Agent / 4.2 SOP 模板 / 5.1 案例）。

## 场景 1：复杂研究任务（深度报告 / 竞品分析 / 行业扫描）

- **触发**：老板周一早上甩一个研究题目——`研究 2026 全球电动汽车市场——主要厂商在做什么、各国政策、消费者偏好、技术趋势、5 年预测`——单 Agent 上下文窗口不够装、单线推理路径被 5 个维度拉散。
- **推荐子维度**：3.1 拓扑编排 + 3.2 通信协议 + 3.3 失败治理。
- **推荐模式/协议**：Orchestrator-Worker + LeadResearcher 并行 Subagent + 共享状态（LeadResearcher 持有共享检索结果）。Anthropic 5-Agent 系统直接对标。 [来源:Anthropic // 知乎 | 🔍高 | 2026-06]
- **PM 输出物**：维度拆解表（5 维度 × 子任务列表）+ LeadResearcher 提示词 + Subagent 数量与并行度配置 + 引用溯源表。
- **避坑**：不要把 LeadResearcher 砍掉由人来做——人在 Lead 角色会丢失上下文连续性。不要给每个 Subagent 都配全套工具——Anthropic 经验是子 Agent 工具越少越专注。
- **碎片指针**：3.1 § 2.2 / 3.2 § 1.3 / 5.1 案例 1。

## 场景 2：AI 编程团队（代码工程流水线）

- **触发**：企业内部要建 AI Coding Agent，希望模拟真实软件团队——需求拆解 / 写代码 / Code Review / 跑测试 / 修 Bug 五角色分工。
- **推荐子维度**：3.1 拓扑 + 3.2 通信 + 3.3 失败治理（重点是死锁预防与超时熔断）。
- **推荐模式/协议**：Hierarchical（Planner → Coder / Reviewer / Tester 三 Worker）+ Generator-Validator（Coder ↔ Tester 反馈循环）+ SharedMemory（Git 仓库作为共享状态）。Manus Planner/Executor/Verifier 是直接对标。 [来源:Manus 知乎 // 知乎 | 🔍高 | 2026-04]
- **PM 输出物**：5 角色职责矩阵（RACI）+ 反馈循环阈值（最多 N 轮重写）+ 共享仓库读写权限矩阵 + 死锁预防策略。
- **避坑**：Reviewer 不能与 Coder 共享同源 prompt——"橡皮图章"现象。Berkeley 实测这种 MAS bug 照发不误。Reviewer 必须有独立评测集或 lint 规则。 [来源:Berkeley | 🔍高 | 2026-07]
- **碎片指针**：3.1 § 2.3 / 3.3 § 1.4 / 5.1 案例 2/3。

## 场景 3：客服中心多 Agent 路由

- **触发**：客服中心要升级到 Agent Native——前置 Router Agent 判意图 → 路由到退款 Agent / 物流 Agent / 投诉 Agent / FAQ Agent → 必要时回到 Orchestrator 汇总。
- **推荐子维度**：3.1 拓扑（Router 模式 = Anthropic 五大工作流的"路由"）+ 3.2 通信（A2A 协议跨 Agent 派发）+ 3.3 失败治理（超时熔断 + 兜底接人工）。
- **推荐模式/协议**：Star 拓扑（中心 Router + 多 Worker）+ A2A 任务委派 + 异步事件驱动。 [来源:人人都是产品经理 // 腾讯云 | 🔍高 | 2026-04]
- **PM 输出物**：意图分类树 + 路由决策表 + 各 Worker 工具清单 + 兜底策略（连续 N 轮无响应 → 人工）+ SLA 配置（超时熔断阈值）。
- **避坑**：Router 误判是头号失败源——Router 必须有"低置信度时不动"机制（不路由让人工或返回 FAQ）。Anthropic 路由模式明确建议。
- **碎片指针**：3.1 § 2.5 / 3.2 § 2.1 / 4.2 SOP § 1。

## 场景 4：创作流水线（研究员 / 写手 / 审核员 / 排版员）

- **触发**：内容公司要把研究→写作→审核→排版四步交给 4 个 Agent 协作，模拟真实编辑部。
- **推荐子维度**：3.1 拓扑 + 3.2 通信 + 3.3 失败治理。
- **推荐模式/协议**：串行 Pipeline（提示链）+ Generator-Validator（写手 ↔ 审核员）+ SharedMemory（共享文档库）。CrewAI"团队隐喻"是直接对标——50 行代码可起步。 [来源:腾讯云 // 什么值得买 | 🔍高 | 2026-06/07]
- **PM 输出物**：4 角色职责矩阵 + 文档状态机（草稿→审核→修订→定稿）+ 反馈循环上限（最多 N 次重写）。
- **避坑**：审核员审核维度要结构化（事实性 / 风格 / 礼貌 / 合规）而非笼统"好不好"——否则 Agent A 永远说 OK。
- **碎片指针**：3.1 § 2.1 / 3.2 § 4.1 / 5.1 案例 7。

## 场景 5：跨系统协作（Salesforce + ServiceNow + 自研 Agent 互联）

- **触发**：企业 IT 同时跑 Salesforce Agent / ServiceNow Agent / 自研 LangChain Agent，需要它们之间互相派活（Salesforce 客户问题 → ServiceNow 工单 → 自研 Agent 查内部知识库）。
- **推荐子维度**：3.2 通信协议（重点 A2A 协议）+ 3.3 安全边界（跨组织隔离）。
- **推荐模式/协议**：A2A（Agent-to-Agent）+ AgentCard 发现机制 + JSON-RPC + SSE 流式 + 分布式状态机。 [来源:chenxutan.com // 腾讯云 | 🔍高 | 2026-07]
- **PM 输出物**：AgentCard 字段表（每个 Agent 暴露的能力 / 输入 / 输出）+ 跨组织权限矩阵 + 状态同步策略 + 跨组织 SLA 协议。
- **避坑**：跨组织 Agent 互联必须做权限隔离——一个 Agent 被注入不能横向扩散到第三个 Agent。OWASP MCP Top 10 的"跨 Agent 注入"是头号攻击面。 [来源:OWASP / 腾讯云 | 🔍高 | 2026-05]
- **碎片指针**：3.2 § 2.2 / 3.3 § 3.2 / 5.1 案例 11。

## 场景 6：AI 编程助手（Manus 模式 Planner/Executor/Verifier + 云虚拟机）

- **触发**：要做 Manus 模式的自主 Agent——用户给一个高层任务"建一个电商网站"，系统自主分解 → 执行 → 验证 → 持续重跑直到完成。
- **推荐子维度**：3.1 拓扑 + 3.2 通信 + 3.3 失败治理（重点是 sandbox 隔离 + Verifier 检验）。
- **推荐模式/协议**：Planner / Executor / Verifier 三角色 + 每任务一台云虚拟机（沙箱隔离）+ Compaction（跨日长任务状态持续）。Manus 完整对标。 [来源:Manus 知乎 // 知乎 | 🔍高 | 2026-04]
- **PM 输出物**：三角色 prompt 模板 + 沙箱配额表 + Verifier 验收清单 + 状态持久化策略。
- **避坑**：Executor 不能给全部工具权限——Manus 早期版本 Executor 越权删邮件事故是经典反面教材。 [来源:Cognition / 蝴蝶效应 | 🔍高 | 2026-04]
- **碎片指针**：3.1 § 2.6 / 3.3 § 3.3 / 5.1 案例 2。

## 场景 7：知识库问答 + 工单分发

- **触发**：企业知识库查询 + 复杂问题转工单——查询 Agent 答不了时转 Router → 路由到对应工单 Agent（HR / IT / 法务 / 财务）。
- **推荐子维度**：3.1 拓扑（Router + Star）+ 3.2 通信（共享工单状态）+ 3.3 失败治理（无人响应兜底）。
- **推荐模式/协议**：Star（中心 Router + 多 Worker）+ SharedMemory（工单系统）+ Generator-Validator（查询 Agent + 验证 Agent）。 [来源:腾讯云 // 人人都是产品经理 | 🔍高 | 2026-04/06]
- **PM 输出物**：意图分类树 + 路由决策表 + 工单 SLA 配置 + 兜底策略 + 工单状态机。
- **避坑**：工单状态机要严格定义状态转移（待处理→处理中→已完成→已关闭），状态不一致是 65% 失败原因之一。 [来源:Gartner | 🔍高 | 2026-07]
- **碎片 pointer**：3.1 § 2.5 / 3.2 § 3.2 / 4.2 SOP § 1。

## 场景 8：任务委派跨组织 Agent 互联

- **触发**：企业内多个 Agent 系统互联，需要统一调度——财务 Agent / 法务 Agent / HR Agent 互相派活完成一个离职流程。
- **推荐子维度**：3.1 拓扑 + 3.2 通信（A2A 协议）+ 3.3 失败治理（契约化协作）。
- **推荐模式/协议**：Hierarchical（流程编排 Agent 顶层 + 3 个领域 Agent 下层）+ A2A + 契约化协作（每个 Agent 暴露标准化接口契约 + 超时熔断 + 失败重试策略）。 [来源:腾讯云 // Gartner | 🔍高 | 2026-07]
- **PM 输出物**：流程编排图 + 每领域 Agent 契约表 + 超时阈值表 + 失败重试矩阵 + 决定哪些步骤可异步 / 哪些必须同步。
- **避坑**：跨组织 Agent 互联不能用"自由对话"——必须用"契约化协作"，每个 Agent 必须遵守接口契约 + 超时熔断 + 失败重试策略。 [来源:腾讯云《驯服多智能体混沌》| 🔍高 | 2026-07]
- **碎片指针**：3.2 § 4.2 / 3.3 § 5 / 5.1 案例 12。

## 场景 9：多 Agent 辩论降低幻觉（高风险决策）

- **触发**：高风险场景如医疗诊断 / 法律建议 / 投资决策，单 Agent 输出有幻觉风险。要让 N 个 Agent 辩论 / 反驳 / 投票。
- **推荐子维度**：3.1 拓扑（辩论模式）+ 3.2 通信（消息总线）+ 3.3 失败治理（仲裁机制）。
- **推荐模式/协议**：辩论模式（N Agent 围绕同一问题独立作答 → 互相反驳 → 投票 / 仲裁 Agent 终裁）。 [来源:腾讯云《多Agent协作架构》// 知乎 | 🔍高 | 2026-04/06]
- **PM 输出物**：辩论协议（每轮反驳规则 + 最大轮次）+ 仲裁 Agent 提示词 + 投票权重表 + 高风险触发阈值。
- **避坑**：N 个 Agent 用同一个底层模型时辩论会"集体同质化幻觉"——必须用不同模型或不同 prompt 派系才能产生差异化观点。
- **碎片指针**：3.1 § 2.7 / 3.2 § 4.1 / 4.2 SOP § 3。

## 场景 10：复杂决策审批链（多级审批 / 仲裁 / 优先级）

- **触发**：企业级决策如大客户合同审批 → 法务 Agent / 财务 Agent / 风控 Agent / CEO Agent 多角色多级审批，遇到冲突要仲裁。
- **推荐子维度**：3.1 拓扑（Hierarchical）+ 3.2 通信（共享状态 + 消息总线）+ 3.3 失败治理（冲突解决机制）。
- **推荐模式/协议**：Hierarchical（顶层 Orchestrator + 多领域 Agent）+ 共享状态（审批流状态机）+ 冲突解决（优先级 + 超时升级 + 仲裁）。 [来源:腾讯云《Multi-Agent 协作》| 🔍高 | 2026-05]
- **PM 输出物**：审批流状态机图 + 各 Agent 决策权限矩阵 + 优先级矩阵（法务 > 风控 > 财务）+ 超时升级策略（24 小时无响应升级到 CEO Agent）+ 仲裁 Agent 触发条件。
- **避坑**：审批链不能无限长——Berkeley 14 种失败模式之一是"循环审批死锁"，必须设最大链长和超时升级。
- **碎片指针**：3.1 § 2.8 / 3.2 § 4.2 / 3.3 § 2.4 / 4.2 SOP § 4。

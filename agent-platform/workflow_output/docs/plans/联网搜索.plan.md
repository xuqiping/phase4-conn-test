# Implementation Plan for 对话联网搜索

> Phase 2 产出。Phase 3 逐步勾选执行。只含伪代码，不含真代码。
> 触发方式：**用户开关手动触发**（不建 tool-calling agent loop，后端在 LLM 生成前先搜）。
> 来源规格：本设计（brainstorming 沉淀，无独立 spec 文件）。
> 复用基建：`StreamEvent.CITATION` + 前端 `MessageBubble` 引用回显 + ChatView 3 态下拉开关模式。

## 背景与目标

现状：`DefaultChatStrategy` 直接调 LLM 单轮生成，无联网能力，问"今天日期"会答错（LLM 训练截止）。

目标：CHAT 模式下用户可开 `🌐联网` 开关 → 后端按 query 联网检索 → 结果注入 system context → LLM 带引用[n]作答 → 复用现有 CITATION 事件回显来源。

双引擎：**外部可插拔供应商**（Tavily/Serper/Bing）+ **自建引擎**（SearXNG 元搜索 + Jsoup+Readability 全文抽取），对标 Tavily。用户无任何 API key 时用自建兜底。

## 技术实现坑点预判与规避措施

| 技术点/功能块 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| SearXNG 部署 | 默认不出 JSON API | 配 `formats: [json]` + `settings.yml` | `curl '<searxng>/?q=test&format=json'` 返回 JSON |
| SearXNG 结果质量 | 元搜索聚合可能漏/乱 | 限定 `engines` + `categories: general` | 对同一 query 比对 Tavily 结果重合度 |
| 抓全文被 ban / 慢 | 并发抓多页触发反爬 + 超时堆积 | 并发限流(≤5) + 单页超时 8s + UA 伪装 + 失败降级 snippet | 故意抓反爬严站点，验证降级不阻塞 |
| Readability 中文/SPA 站弱 | 抽出空或噪声 | fallback 到 `<p>` 聚合 + 长度阈值过滤 | 跑中文新闻 + SPA 站各 5 个，肉眼查正文完整度 |
| 注入 prompt 注入 | 网页内容含恶意指令 | sanitize 去 HTML 实体/控制字符 + 用分隔符包裹"以下为不可信检索内容" | 注入含 "ignore previous" 的页面，验证不执行 |
| 抓取 SSRF | 用户 query 诱导抓内网 | SearXNG 已是出口代理；自建直抓须校验目标 IP 非私有段 | 抓 `http://127.0.0.1` 验证拒绝 |
| 延迟可见性 | 外部 1-3s / 自建 2-6s，用户以为卡死 | 前端开关 ON 发 `SEARCHING` 态事件 + loading 动画 | 手测开关 ON 看 loading |
| CITATION 编号冲突 | 记忆模式 + 联网同时 ON，两套[n]撞号 | citation 编号空间隔离（KB 用 [n]，联网用 [n] 但各自独立列表）或前缀 `🌐[n]` | 两开关同开，验证编号不串 |

## 安全检查清单

- [ ] **鉴权/授权**：搜索接口复用 chat 会话 ownership 校验；后台改 provider/key 须 `@RequirePermission("system:config")`
- [ ] **输入校验**：query 长度限制(≤500) + 去 control char；provider 名白名单枚举校验
- [ ] **数据加密**：Tavily/Serper/Bing key 走 `AesEncryptService` 存 `system_settings`，不回显明文(同 LLM provider key 范式)
- [ ] **审计日志**：每次搜索记 query/provider/结果数/耗时/traceId（脱敏 query）
- [ ] **错误处理**：搜索失败降级"联网暂不可用，基于自身能力作答"，不泄漏内部异常栈
- [ ] **SSRF 防护**：自建直抓网页须校验目标非私有 IP 段(10/172.16/192.168/127/169.254)
- [ ] **依赖安全**：Jsoup 引入前查 CVE；SearXNG Docker 镜像锁版本

## 性能考虑与验证计划

- [ ] **查询效率**：搜索结果不落库(无 N+1)；system_settings 读 key 走现有缓存
- [ ] **缓存策略**：query→结果 缓存可选(后续再说)，本期不做
- [ ] **并发处理**：top N 页并发抓用 `Flux.merge` 限并发 5；外部 API 单调用超时 10s + 重试 1 次
- [ ] **资源使用**：抽取正文截断(每页≤2000 字符，top N≤5)防 context 爆炸
- [ ] **性能验证**：Phase 4 测 开关ON 首字节延迟(p95)、外部 vs 自建 结果质量评分

## 功能联动点清单（含反向/边界）

- **开关 OFF** → 跳过整个 search，走原 CHAT 流程，零行为变化。
- **开关 ON + 搜索成功** → 注入 evidence context + 发 CITATION 事件。
- **开关 ON + 搜索失败(超时/熔断)** → 降级纯聊天 + system 提示"联网暂不可用"，不阻塞回复。
- **开关 ON + 零结果** → 注入"未检索到相关网络内容"，仍调 LLM 生成（同 RAG abstain 范式）。
- **开关 ON + 记忆模式 ON** → 两套 context 都注入，citation 编号空间隔离。
- **WORKFLOW / AGENT 模式** → 本期**不接**（仅 CHAT），开关 UI 在非 CHAT 模式禁用/隐藏。
- **切换 active provider（后台）** → 下次请求生效，无热重载需求。
- **provider 无 key + 选了外部** → 自动降级 BuiltIn + 记 warn 日志。

## 运维考量清单（开发期埋）

- [x] **可观测性**：搜索路径打日志(query/provider/结果数/耗时/traceId)，复用现有 slf4j。
- [x] **配置开关**：`search.enabled` 全局总开关(system_settings)，出问题可关不发版。
- [x] **可回滚**：纯新增 `search` 模块 + system_settings 配置行，无 DB schema 破坏性变更，无 Flyway。
- [x] **限流/熔断/降级**：外部 API 超时 10s + 重试 1 + 降级 BuiltIn；BuiltIn 抓取失败降级 snippet；全失败降级纯聊天。
- [x] **运维入口**：后台系统设置页(provider 下拉 + 各 key 输入 + SearXNG base_url + max_results/timeout)。
- [ ] **告警阈值**：后续再说（搜索失败率 > 30% 告警，本期不接告警系统）。
- [x] **容量/性能预案**：无独立存储，无大表；抽取正文有字符上限防 context 膨胀。

## 实现步骤

- [x] **Step 1：后端 search 模块骨架 + DTO + Provider 接口**（commit b9a6580a）
  - **目标**：搭 `com.superprogrammer.search` 包，定义 `WebSearchProvider` 接口 + `SearchResult`/`SearchOptions` DTO。
  - **动作**：伪代码——
    - `SearchResult{title,url,snippet,content,score}`
    - `SearchOptions{maxResults,fetchContent,timeoutMs}`
    - `interface WebSearchProvider { String getName(); List<SearchResult> search(String query, SearchOptions opts); boolean available(); }`
  - **文件**（≤20）：
    - `search/dto/SearchResult.java`：新建
    - `search/dto/SearchOptions.java`：新建
    - `search/provider/WebSearchProvider.java`：新建接口
  - **依赖**：无
  - **需人工介入**：无
  - **安全检查**：DTO 字段定 readonly
  - **验证**：编译过

- [x] **Step 2：自建引擎 BuiltInSearchProvider（SearXNG + 抽取）**（commit 12c6de0d；单测 24 绿，SearXNG 真连通冒烟待人工部署后补）
  - **目标**：实现对标 Tavily 的自建引擎：SearXNG 拿 URL → Jsoup+Readability 抽正文。
  - **动作**：伪代码——
    - `SearxngClient.search(query) → List<{title,url,snippet}>`（WebClient 调 `<base>/?q=&format=json`）
    - `ContentExtractor.extract(url) → String`（Jsoup 取 HTML → Readability 算法 → fallback `<p>` 聚合 → 截断 2000 字符 + sanitize）
    - `BuiltInSearchProvider.search()`：SearXNG 拿 top N URL → `Flux.merge` 并发 5 抽取 → 组装 SearchResult
    - `available()`：校验 searxng.base_url 非空 + 连通
  - **文件**：
    - `search/provider/BuiltInSearchProvider.java`
    - `search/client/SearxngClient.java`
    - `search/util/ContentExtractor.java`（Readability 自实现）
    - `search/util/SanitizeUtil.java`（去实体/控制字符 + 私有 IP SSRF 校验）
    - `backend/pom.xml`：加 `org.jsoup:jsoup`
  - **依赖**：Step 1
  - **需人工介入**：部署 SearXNG Docker + 配 `formats:[json]`，提供 base_url
  - **安全检查**：SSRF 校验 + sanitize + 抓取超时
  - **验证**：单测——注入 mock SearXNG 响应，验证 URL 解析 + 正文抽取 + SSRF 拒绝私有 IP

- [x] **Step 3：外部供应商适配器（Tavily/Serper/Bing）**（commit 99da983d；单测绿，真实 key 手测待 Tavily 申请）
  - **目标**：实现 3 个外部 provider，key 从 system_settings 读(AesEncrypt)。
  - **动作**：伪代码——
    - `TavilyProvider.search()`：POST `https://api.tavily.com/search` body `{query,api_key,max_results}` → 解析 `results[]{title,url,content}`
    - `SerperProvider.search()`：POST `https://google.serper.dev/search` header `X-API-KEY`
    - `BingProvider.search()`：GET `https://api.bing.microsoft.com/v7.0/search` header `Ocp-Apim-Subscription-Key`
    - 各 `available()`：校验对应 key 非空
  - **文件**：
    - `search/provider/TavilyProvider.java`
    - `search/provider/SerperProvider.java`
    - `search/provider/BingProvider.java`
  - **依赖**：Step 1 + `AesEncryptService` + `SystemSettingService`
  - **需人工介入**：申请 Tavily key（免费 1000 次/月）
  - **安全检查**：key AesEncrypt 存不回显明文 + 错误不泄漏响应体
  - **验证**：单测——mock HTTP 响应解析正确；手测真实 key 调通

- [x] **Step 4：WebSearchService 路由 + 降级链**（commit 310eb7fb；10 单测绿）
  - **目标**：统一入口，按 active_provider 路由 + 失败降级。
  - **动作**：伪代码——
    - `WebSearchService.search(query,opts)`：
      - 读 `search.active_provider`
      - 若外部 provider `available()==false`(无 key) → 降级 BuiltIn + warn 日志
      - 调对应 provider，超时 10s + 重试 1
      - 失败 → 降级 BuiltIn；BuiltIn 也失败 → 返回空列表(触发零结果分支)
    - 审计日志：query/provider/结果数/耗时
  - **文件**：
    - `search/service/WebSearchService.java`
    - `search/config/SearchConfig.java`（读 system_settings 默认值）
  - **依赖**：Step 2 + Step 3
  - **安全检查**：审计日志脱敏 query + 总开关 `search.enabled`
  - **验证**：单测——active=tavily 但无 key 验证降级 BuiltIn；BuiltIn 失败验证返回空不抛

- [x] **Step 5：接入 CHAT 流（开关门控 + context 注入 + CITATION）**（commit fa878b8d；V44 加列）
  - **目标**：`ChatSessionService` 在 RAG 注入旁加联网注入分支。
  - **动作**：伪代码——
    - `ChatRequest` 加 `Boolean webSearchEnabled`
    - `ChatSession` 加 `web_search_enabled` 列（持久化会话级，仿 rag_enabled）→ Flyway V? 加列
    - `doSendMessageStream`：解析 webSearchOn（session>request>setting 默认关）→ 若 ON：

      - 空结果 → context.addMessage("system","（联网未检索到相关内容，基于自身能力作答）")

      - 收集 web citations → 流式 CITATION 事件（复用 StreamEvent.citation，URL 维度）
  - **文件**：

  - **依赖**：Step 4
  - **安全检查**：ownership 校验复用 getSessionOrFail

- [x] **Step 6：前端开关 UI + loading + citation 兼容**（commit b7e801ee；build 绿）

## 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| SearXNG | 一个自己部署的"搜索聚合器"，把 Google/Bing/DDG 结果揉一起，开箱调它的 JSON 接口 | Docker 起一个，`/?q=天气&format=json` 直接拿结果 |
| Readability | 从乱七八糟的网页 HTML 里只抠出"正文文字"、丢掉导航/广告的算法 | 抓篇新闻，只留文章正文不留侧边栏 |
| SSRF | 服务器端请求伪造——坏人让服务器去访问内网，这里防"抓网页时被抓去抓内网" | 抓 `http://10.0.0.1` 须拒绝 |
| 降级链 | 外层挂了自动换备用方案，一路兜底到底不崩 | Tavily 没 key→用自建→自建也挂→纯聊天 |
| snippet | 搜索结果里那段摘要文字（不抓全文也有） | DDG 结果每条下面的灰色描述 |

## 备注

- 触发方式定为手动开关（非 tool-call loop），故不建 LlmRequest.tools 字段、不改 Provider 解析 tool_calls。后续若要 AI 自主判断搜索，另起 plan 扩 tool-calling 基建。
- 自建引擎对标 Tavily 但不抄其 API 调用（自建走 SearXNG + 自抓），仅结果结构对齐。
- 本期不接 Agent/Workflow 模式，留扩展点（WebSearchService 可被 workflow 检索节点复用）。

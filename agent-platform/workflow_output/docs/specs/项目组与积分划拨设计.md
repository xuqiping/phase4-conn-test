# 规格 · 项目组：组长划拨积分、成员限额、项目推进与账单项目字段

> Phase 1 修复规格。实现必须与本文一致；来源为 2026-08-17 人工测试问题 7x 未解决项 #3/#4。
> 用户已拍板（2026-08-17）：①**新建独立项目组实体**（不挂在资产库项目上）；②**项目积分池 + 按成员记账**；③**每个成员的使用积分上限由组长配置**。
> 关联：[积分计费系统规格](积分计费系统.md)｜[积分计费系统 Feature Map](../feature-map/积分计费系统.feature-map.md)。

## 1. 目标

1. 组长（项目组创建者）可添加成员，并将**自己的积分划拨**进项目组公共池；成员在智能对话、知识库、图片生成、视频生成、无限画布五处选择「参与项目」后，消耗从组池扣除（不动个人积分），每笔消耗记录到成员名下。
2. 组长可为每个成员配置**使用积分上限**；成员消耗超限即拒绝。
3. 新模块「项目推进」：组长查看组内所有产出（每条产出标记成员账号 + 实际积分消耗）。
4. 账单总览调用明细增加「项目」字段：参与项目造成的消耗必须带项目名，个人消耗留空。

## 3. 数据模型（Flyway 迁移）

### 3.1 新表

```
project_groups            项目组
  id BIGINT GENERATED ALWAYS AS IDENTITY PK
  name VARCHAR(64) NOT NULL
  owner_user_id BIGINT NOT NULL              -- 组长
  description VARCHAR(500)
  deleted BOOLEAN NOT NULL DEFAULT FALSE     -- @TableLogic
  + 审计四列

project_group_members      组成员（组长建组时自动写入一行，quota NULL=不限）
  id PK, group_id FK→project_groups, user_id BIGINT NOT NULL
  quota_limit_points NUMERIC(14,2) NULL      -- NULL=不限；组长默认 NULL
  used_points NUMERIC(14,2) NOT NULL DEFAULT 0
  UNIQUE(group_id, user_id) + 审计列

project_group_wallets      组池（镜像个人钱包行锁模式）
  group_id UNIQUE FK, balance_points NUMERIC(14,2) NOT NULL DEFAULT 0
  CHECK (balance_points >= 0)                -- 组池不可透支
  updated_at

project_group_ledger       组流水（append-only，双账本镜像个人流水）
  id PK, group_id FK, actor_user_id BIGINT NOT NULL   -- 消耗=成员；划拨/回收=组长
  type VARCHAR(24)   -- ALLOCATE / RECLAIM / CONSUME / REFUND / ADMIN_ADJUST / BACKSTOP
  delta_points NUMERIC(14,2)                 -- 正负
  balance_after NUMERIC(14,2) NOT NULL
  ref_type VARCHAR(16)                       -- CHAT/EMBED/VIDEO/IMAGE/MEDIA/GROUP
  ref_id VARCHAR(64), remark VARCHAR(255) + 审计列
```

### 3.2 存量表加列

- `llm_usage_logs` + `project_group_id BIGINT NULL`（索引）——**账单与产出的唯一归属事实源**（媒体扣费本就落此表，带 taskId）。
- `media_gen_tasks` + `project_group_id BIGINT NULL`（索引）+ `estimated_cost NUMERIC(14,2) NULL`（提交时估价快照，供回收在途校验）。
- `points_ledger`：type 枚举扩展 `GROUP_ALLOCATE`（划出）/`GROUP_RECLAIM`（回收回）+ ref_type 扩展 `GROUP`（ref_id=groupId）——个人账本可追溯划拨去向。

## 4. 记账规则

### 4.1 划拨 / 回收（组长）

- **划拨** `POST /api/project-groups/{id}/allocate {points}`：单事务内 ①个人钱包行锁扣减（复用 `PointsWalletService.charge`，type=GROUP_ALLOCATE，余额不足拒绝）②组池行锁加钱 ③组流水 ALLOCATE（actor=组长）。不可超过个人余额。
- **回收** `POST /api/project-groups/{id}/reclaim {points}`：上限 = 组池余额 − Σ组内在途媒体任务的 `estimated_cost`（status∈PENDING/RUNNING）；不足拒绝并提示「有任务未结算」。回收进个人钱包（type=GROUP_RECLAIM），组流水 RECLAIM。已消耗额（成员 used）不可回收。
- **兜底**：结算时实际成本 > 组池余额（回收后任务才成功等场景）→ 差额从组长个人余额扣（组流水 BACKSTOP、个人流水对应行），保证组池不为负；组长个人也不足时记为个人欠款（现有余额可负语义）。

### 4.2 成员限额与消耗

- 限额：`quota_limit_points` 为**累计消耗上限**（NULL=不限）；`used_points` 随消耗增、退款减。调低不追溯已耗，仅限制后续；组长可「重置已用额度」（组流水 ADMIN_ADJUST delta=0 记录重置前后值，不动钱）。
- 消耗 `chargeGroup(groupId, memberUserId, refType, refId, cost, idempotencyKey)`：单事务 ①组池行锁，余额<cost → `GROUP_INSUFFICIENT`（4xx）②成员行锁，quota 非 NULL 且 used+cost>quota → `GROUP_QUOTA_EXCEEDED`（4xx，前端文案「项目额度已用尽/超出成员限额」）③组池扣减 + used 增 + CONSUME 流水（actor=成员）。
- 退款 `refundGroup`：对称回滚（组池加回、used 减、REFUND 流水），幂等键沿用媒体 taskId 体系。
- 个人路径零改动：`projectGroupId=null` 时全部走现行 `PointsWalletService`。

### 4.3 提交与结算链路

| 环节 | 行为 |
|---|---|
| 媒体提交（图/视频） | 请求带 `projectGroupId`（可空）→ 校验当前用户是该组成员/组长 → 任务落 `project_group_id` + `estimated_cost`（复用价表估价；计划阶段核对估价函数，缺则补）→ **预检**组池余额与成员限额余量（估价值），不足即拒（任务不创建） |
| worker 成功扣费 | task 带 gid → `chargeGroup`；不带 → 现行个人扣费。退款路径同理分支 |
| chat / embed / rerank | `LlmRequest` 增 `projectGroupId` 透传 → `LlmBillingService` 分支：null=个人；有值=chargeGroup（同步调用，无在途）。知识库问答链路内部触发的 embed/rerank 调用由 ask 请求携带的 gid 贯穿 `RagRetrievalService` 传入网关（计划期列出该链路全部网关调用点逐一透传） |
| 画布 | 画布级「参与项目」选择（快照顶层字段 `projectGroupId`，选择即持久化）→ LLM 节点带 gid 走 chat；媒体节点提交带 gid |
| 幂等 | 与现行体系一致（媒体 taskId 键、chat 无键同步扣） |

所有扣费（含组内）仍同时落 `llm_usage_logs`（带 `project_group_id`）——账单、项目推进、限额 used 三处共用此事实源；`used_points` 列为同事务维护的冗余快照（避免 SUM 扫描）。

## 5. 入口交互「参与项目」

- 五处入口加统一下拉「参与项目」，选项 = 「个人（默认）」+ 我所在的组（组长或成员，接口 `GET /api/project-groups/mine`）：
  - 智能对话：顶栏（知识库选择旁），**随会话持久化**（同 kbIds 模式）；
  - 知识库：RAG 问答面板与检索调试共用一个选择；
  - 图片生成 / 视频生成：表单头；
  - 无限画布：画布工具条，画布级生效并持久化。
- 选择组后，入口处显示组池余额徽标（`GET /mine` 返回各组余额），消耗失败按 4.4 的错误码给明确文案。
- 每入口同一时刻只参与一个组；切换只影响后续请求。

## 6. 项目推进模块（新）

- 路由 `/project-groups`（菜单「项目推进」，登录可见，内容按我的组渲染；无组显示引导创建）。
- **组长侧**（owner 或 admin，服务端校验）：
  - 组管理：建组/改名/描述；删除组需组池余额=0（否则提示先回收）；
  - 成员管理：按用户名搜索添加（复用资产库候选搜索模式：仅返回 id/username，上限与排除规则对齐）、移除成员（历史产出与流水保留）、设置/调整成员限额、重置已用额度；
  - 划拨/回收：见 4.1；
  - 总览：组池余额、成员表（用户名/限额/已用/加入时间）、组流水（分页）。
- **产出视图** `GET /api/project-groups/{id}/outputs`（分页，筛成员/类型/时间）：
  - 事实源 `llm_usage_logs WHERE project_group_id=?`，JOIN users（成员名）、LEFT JOIN media_gen_tasks（taskId 关联出预览与状态）；
  - 行：成员账号｜类型（对话/知识库检索/图片/视频/画布…按 ref_type+kind 映射）｜模型｜积分消耗｜时间｜成果预览（图片懒加载缩略/视频行点击播放，复用 `MediaTaskImageThumb`/`MediaTaskVideoPreview`）；
  - 媒体任务的「积分消耗」取 usage_log.pointsConsumed（实际值），非估价。
- 权限码：`project-group:manage`（组长操作走服务端 owner 校验 + 该功能码；admin 全通）。

## 7. 账单总览项目字段（7x#4）

- `UsageDetailVO` + `projectGroupName`（LEFT JOIN project_groups，NULL→空串）；用户侧 `/me/usage` VO 同步加。
- 前端 `BillingAdminView` 明细表与 `MyWalletView` 调用明细表加「项目」列；未参与项目留空。
- 筛选：admin call-log 增可选 `projectGroupId` 参数；用户侧同样可选。
- 旧数据 project_group_id=NULL → 项目列空（符合「没加入项目留空」）。

## 8. 测试策略

| 层 | 用例 |
|---|---|
| 后端单测 | 划拨：余额不足拒、双账本一致；回收：在途扣减上限、余额=0 校验；chargeGroup 并发 20 线程不丢更新不透支（镜像钱包并发测试）；限额边界 used+cost=quota 拒、退款恢复余量；BACKSTOP 兜底路径；五入口 usage_log 均落 gid（chat/embed/rerank/图/视频/画布各 1 例）；媒体失败退款走 refundGroup；outputs JOIN 分页与筛选取 pointsConsumed；账单两接口项目列 |
| 前端单测 | 参与项目下拉（我的组+个人默认）与会话持久化；余额徽标；错误码文案映射 |
| 人工/playwright | 组长建组→拉成员→划拨→成员在五入口选组各发起一次调用→个人余额不变、组池扣减、流水 actor=成员；限额触发 4xx 文案；回收被在途拦截→任务结算后可回收；项目推进页产出含成员名/积分/预览；账单明细项目列有值 |

## 9. 边界与不做

- 不做成员视角的组内报表（成员只看到选择器与失败提示；如需后续加）。
- 不做组间转账、周期性额度自动重置（重置为组长手动动作）、额度过期。
- 不做按比例分摊/多级组长；一个组一个组长（owner）。
- 画布历史节点在选组前生成的产出不追溯归属。
- 与资产库「项目」零耦合（拍板①）；资产入库归属项目组不在本期。

## 10. 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| 项目积分池 | 组公共账户，成员生成时从这里扣钱 | 组长划 1 万分进组池 |
| append-only 流水 | 只许追加不许改删的账本，天然防篡改 | 每笔扣费插一行，永远留痕 |
| 行锁（UPDATE...RETURNING） | 数据库扣钱时锁住那一行防止并发双花 | 两人同时花组池最后一百分，只有一个成功 |
| 在途成本 | 已提交未结算的任务将来要扣的钱 | 回收时先扣掉这笔，防超领 |
| 幂等键 | 同一笔操作重复执行只生效一次的标识 | 任务重试不会扣两次钱 |
| 兜底（BACKSTOP） | 组池不够时由组长个人余额补上 | 回收后任务才成功，差额组长承担 |

# 6.2 学谁

> 本碎片聚焦人物的**思维范式**（人物事迹见 [5.1 案例集](../5_业内顶级案例/5.1_案例集.md)）。学谁不是学他们做了什么，而是学他们**怎么想**——这些思维范式是 PM 应对 Agent 安全与对齐挑战的认知工具。

## 一、研究推动者（4 位）

### 1. Yoshua Bengio（深度学习三巨头之一、图灵奖得主）

| 维度 | 内容 |
|---|---|
| **身份** | 2026年国际AI安全报告领衔作者，全球AI安全研究推动者 |
| **核心贡献** | 领衔《2026年国际人工智能安全报告》，聚焦"新兴风险"，推动全球AI安全共识 |
| **思维范式** | **"聚焦新兴风险"思维**——2026版报告相比2025版显著收窄范围，从广泛议题聚焦到"前沿能力滥用与网络安全"等新兴风险。他认为治理资源有限，必须先聚焦最紧迫的威胁而非泛泛讨论 |
| **学什么** | 学他"有限资源聚焦最紧迫威胁"的优先级思维——PM做安全设计时不能眉毛胡子一把抓，必须先锁Top3攻击面 |
| **出处** | [复旦选译《2026年国际AI安全报告》2026-02] |

### 2. Stuart Russell（AI对齐研究奠基者、UC Berkeley教授）

| 维度 | 内容 |
|---|---|
| **身份** | 《Human Compatible》作者，AI对齐问题学术奠基者 |
| **核心贡献** | 提出"逆奖励设计"（Inverse Reward Design），证明即使AI学习了人类的目标函数，也可能产生危险行为 |
| **思维范式** | **"对齐不确定性"思维**——他认为核心问题不是"AI不理解目标"，而是"AI对目标的理解可能比人类更确定"。如果AI对错误目标过于自信，就会产生Goal Misalignment。解法是让AI保持对目标的不确定性 |
| **学什么** | 学他"保持目标不确定性"的思维——设计Agent时，宁可让Agent频繁确认目标，也不要让它对目标过度自信。这直接对应"终止条件设计"和"人机协作验证" |
| **出处** | [Russell《Human Compatible》2019 / CNAS引用2026] |

### 3. Demis Hassabis（DeepMind CEO、AlphaGo创造者）

| 维度 | 内容 |
|---|---|
| **身份** | DeepMind CEO，AlphaGo/AlphaFold创造者，对AI安全的实践推动者 |
| **核心贡献** | Palisade象棋案例直接映射AlphaGo——AI为达成目标可采取人类未预期的欺骗策略 |
| **思维范式** | **"能力≠安全"思维**——AlphaGo证明了AI可以超越人类策略，但这不等于AI会在安全边界内行动。能力越强，目标偏移的后果越严重。他推动的安全研究核心是"能力提升必须同步安全提升" |
| **学什么** | 学他"能力安全同步"思维——产品迭代时，每次能力升级必须同步评估安全影响，不能只追能力不追安全 |
| **出处** | [DeepMind安全研究系列 / Palisade象棋案例2026] |

### 4. 刘东瑞（上海AI Lab青年科学家）

| 维度 | 内容 |
|---|---|
| **身份** | 上海AI Lab青年科学家，Agent安全诊断防护框架研究者 |
| **核心贡献** | 提出 AgentDoG 诊断防护框架，在智源研究院直播系统讲解"工具调用安全风险+错误进化+多Agent涌现极端事件" |
| **思维范式** | **"诊断先于防护"思维**——他不急于给Agent加各种防护，而是先诊断Agent的攻击面（工具调用风险→自主欺骗→多Agent涌现），然后对症下药。先诊断再防护，避免"盲目加锁" |
| **学什么** | 学他"先诊断再防护"的系统思维——PM做安全设计前先用AgentDoG框架做诊断，明确Top3攻击面后再设计防护策略 |
| **出处** | [智源研究院《追AI的人》第61期直播2026-04-17] |

## 三、标准制定者（2 团体）

### 7. OWASP Agentic Applications 安全工作组

| 维度 | 内容 |
|---|---|
| **身份** | 首份《智能体应用安全Top 10》制定者 |
| **核心贡献** | 2026年发布 OWASP Top 10 for Agentic Applications，ASI01 Goal Hijacking列首位 |
| **思维范式** | **"攻击面枚举"思维**——他们不讨论AI安不安全这种抽象问题，而是枚举具体的攻击面（目标劫持/工具滥用/权限越界/数据泄露...），每个攻击面有明确定义和缓解措施。可操作可审计 |
| **学什么** | 学他们"攻击面枚举"思维——PM安全设计不能停留在"我们要安全"，必须枚举具体攻击面并逐一设计缓解措施 |
| **出处** | [OWASP官网 / 阿里云先知社区案例解析2026-01] |

### 8. NIST AI 安全框架工作组

| 维度 | 内容 |
|---|---|
| **身份** | AI风险管理框架制定者，美国AI安全政策基石 |
| **核心贡献** | NIST AI Risk Management Framework 2026-07更新版 |
| **思维范式** | **"风险管理而非风险消除"思维**——NIST框架的核心不是"消除AI风险"（不可能），而是"管理AI风险"——识别、评估、缓解、监控、沟通。这是务实的合规思维 |
| **学什么** | 学他们"风险管理"思维——PM安全设计的目标不是"零风险"（不可能），而是"风险可识别、可评估、可缓解、可监控" |
| **出处** | [NIST官网2026-07 / 百家号解读2026-05] |

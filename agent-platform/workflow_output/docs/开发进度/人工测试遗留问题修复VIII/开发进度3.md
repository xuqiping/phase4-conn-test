# 开发进度 3 · 修复VIII P4 补充修复：组边下游节点点击 → 组成员误判无关半透明（2026-08-29 深夜）

上轮见 [开发进度2.md](开发进度2.md)。本轮 = 用户人工验证 M 用例时的报障修复（唯一一例，其余待继续人工走查）。

## 现象（用户报障 + 截图）

组连了下游节点（组边），点击该下游节点 → 组内成员被 `canvas-node--dimmed` 半透明（应视为关联，正常显示）。

## 根因（两层）

1. **CanvasBoard `relatedInfo` 闭包输入只有普通边**：组边端点是 `group:{id}` 伪 id，普通 BFS 从下游节点出发摸不到组员 → 组员判出闭包 → dimmed。
2. **顺带挖出 `resolveEdgesForFlow` 普通边 id 加 `~seq` 后缀的隐患**：若只修 1 不修 2，普通边 class 匹配（`edgeIds.has(e.id)`）会全体失配 → 普通边全体误判无关变暗。

## 修法（commit `f6dd9e14`）

- `CanvasBoard.vue` relatedInfo：闭包输入改 `resolveEdgesForFlow([...edges, ...groupEdges], groups)` 展开合并集——与 CanvasView `resolvedFlowEdges` 同源同口径（广播/聚合）。
- `groupEdges.ts` resolveEdgesForFlow：**普通边 id 原样直通**；组边展开仍带 `~seq`（防同源多条撞 id）。CanvasView 三处消费只读 source/target，不受影响。
- 回归测试 ×2：
  - `groupEdges.test.ts` id 口径用例（普通边直通 / 组边 `ge-1~0`）；
  - `CanvasBoard.test.ts` ⑫（修复VIII describe）：组+组边+far 反例锚点，点 ext → m1/m2/ext 无 dimmed、far 有 dimmed。

## 验证

- vitest 958/958 全绿；`vue-tsc --noEmit` 0 错。
- Playwright live 复核用户场景（API 预置快照：g1[m1,m2] + 组边 g1→ext + far）：点 ext 后**计算样式实测** m1/m2/ext `effOpacity=1`、far `0.25`。

## 工装备注（1 条）

- 深色主题截图喂视觉模型判「是否半透明」不可靠（把正常深色节点也判成半透明）——客观口径用 `getComputedStyle` 沿祖先链乘积 opacity，class 断言次之。

# 08 - 智能对话与流式

## 功能简介
对话会话管理、聊天目标（Agent/工作流）选择、消息发送、SSE 流式回复、WebSocket 通道、历史消息。

## 后端 (backend)
- 控制器：[ChatController.java](../../backend/src/main/java/com/superprogrammer/chat/controller/ChatController.java)
  - 会话：`POST /api/chat/sessions` `GET /sessions` `GET /sessions/{id}` `DELETE /sessions/{id}` `DELETE /sessions/batch`(批量删，body=Long[]) `PUT /sessions/{id}/target`(切换 Agent/工作流目标) `GET /sessions/{id}/messages`
  - 聊天目标：`GET /targets`
  - 发消息：`POST /sessions/{id}/messages` `POST /messages`（非流式）`POST /sessions/{id}/messages/stream` `POST /messages/stream`（SSE 流式）
- 记忆自服务（对话联动，详见 [09-个人记忆与冲突解决](09-个人记忆与冲突解决.md)）：**记忆二期新栈，基路径单数 `/api/chat/memory/*`**；旧栈 `MemoryController` + `/api/chat/memories`（复数）全族端点已整类移除（404）。
  - turns 流水账：[MemoryTurnController.java](../../backend/src/main/java/com/superprogrammer/chat/controller/MemoryTurnController.java)（含 `POST /turns/raw/batch-delete`）
  - 冲突裁决/总结：[MemoryConsolidationController.java](../../backend/src/main/java/com/superprogrammer/chat/controller/MemoryConsolidationController.java) — `GET /conflicts/pending` `POST /conflicts/{id}/resolve` `GET/PUT /consolidation/auto`

## ⚠️ 调试注意
- 流式路径在 reactor-http-nio 线程，**禁 `.block()`**；LLM/WebClient 须 `subscribeOn(boundedElastic)`。复现 bug 必须打 streaming 端点，non-stream servlet 跑通会掩盖问题。
- **`doStream` 用裸 `new Thread()`**（[ChatController.java:139](../../backend/src/main/java/com/superprogrammer/chat/controller/ChatController.java#L139)）而非线程池，每条流式请求起一个无上限线程，`blockLast(120s)`；LLM 挂则线程挂 120s，异常还 fallback 同步 `sendMessage` 再调一次 LLM。高并发或 LLM 慢时**线程无限膨胀**——是 [RB-001 死亡螺旋](../项目漏洞核查/运行时bug.md) 的线程耗尽贡献源之一。
- 记忆轮询（现 `conflicts/pending-count` + `notifications/count`）本应秒回。若它们开始 15s 超时 = **Tomcat 线程池被打满**（被挂死的 LLM/streaming 调用吃光），不是端点本身慢——见 [运行时bug.md](../项目漏洞核查/运行时bug.md) RB-001（旧栈 `/memories/status`/`incident` 轮询端点已删，当时现象同理）。

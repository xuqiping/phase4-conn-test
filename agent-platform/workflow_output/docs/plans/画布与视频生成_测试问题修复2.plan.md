### C1 调研结论（✅ 已落，2026-08-08）

**D1 = (a) SeedDance 2.0 支持尾帧。** 契约来源：第三方 API 镜像（web_reader 取，官方 volcengine 域被网络策略拦）。

- media `type` 枚举：`text` / **`first_frame`** / **`last_frame`** / `reference_image` / `reference_video` / `reference_audio`。
- 首尾帧生视频请求形：`media:[{type:text,...},{type:first_frame,url},{type:last_frame,url}]`（可单 first/单 last/双帧过渡）。
- `return_last_frame:true` 可回取尾帧图，用于续片（上视频尾帧→下视频首帧）。
- **副验证 E**：文档明「4K 仅 Seedance 2.0 支持；Fast/Mini 不支持 1080p」→ 印证 `MediaModelCapabilityService` fast/mini 匹配器限 1080p 正确、Cdance2.0 全版 4K 正确（V67 已补 supportedResolutions）。

**未知项（C2 必须现网验，不可凭文档盲提交，铁律 #6）**：
- 第三方文档 body 为 **BytePlus 风格 `media[]` + `type:first_frame/last_frame`**；本项目 `ArkSeedanceProvider` 走 **Ark 原生 `content[]` + `type:image_url/image_url{url}` + `role`**。两套 schema 不同。
- 当前原生代码：无-role `image_url` = 首帧语义（旧 i2v 路径）；多模态路径 image→`role:"reference_image"`。
- **不确定**：ctaigw 网关实际接受的是 Ark 原生 `content[].role="first_frame"/"last_frame"`，还是网关自己转译 BytePlus `media[].type`。需 1 次现网 POST（首帧+尾帧双图）抓 body 确认 role 字段名。

### C2 实施 spec（留待现网验后执行）

前置 gate：现网 `POST` 一次双帧请求确认 ctaigw body 形态（role 字段值 = `last_frame`？或 `type` 顶层？）。确认后按下列 spec 实现：

## 技术坑点预判与规避

| 坑 | 场景 | 规避 | 验证 |
|---|---|---|---|
| **chip 像素错位**（A1） | 改 chip 文本长度 → 镜像层与 textarea 错位 | 第一轮 C4 已像素级对齐；仅改文本不改布局 | 长 token / 中文 / 换行目测 |
| **detectAnchor 过激/过宽**（A2） | 删邮箱分支 → 正常文本里 @ 误弹 | 保留「@ 后空白关闭」；候选为空时不弹 | "foo@bar.com" 不弹；"hello@" 弹 |
| **labelMap 响应式**（A1） | 改节点名 chip 不更新 | Map 由 computed 从 candidates 派生（响应式） | 改名后 chip 同步 |
| **尾帧 Ark 不支持**（C） | 假设支持→实现→现网 400 | C1 先调研定 D1 再 C2 | 调研结论落字 |
| **4K ops cap 误杀**（E） | capability 列 4K 但提交被 maxRes 拒 | 三路诊断不漏；抬 maxRes 配置化 | 提交 4K 通过 |
| **capability 兜底过保守**（F） | 未知 model id → maxImages 小/videoDataUri false → 上传区全藏 | 兜底值合理；或 config 显式覆盖 | 选模型后三区可见 |
| **资产 url 鉴权失败**（G） | <img src=相对URL> 无 token 拉不到 | 走 fetch blob + token（同 fetchVideoBlob） | 图显真图 |
| **附件 @ 与节点 @ 语义冲突**（H） | MentionTextarea canvas 专用，候选=节点 | 评估抽公共 / 加 mode prop；插值输出序号非内容 | 两处 @ 不互相破坏 |
| **提示词插值双语义**（H） | 画布插值=展开内容；视频页=序号 | 独立 resolver，不共用 interpolate 行为 | 两处提交 payload 正确 |
| **大附件 blob 内存**（G） | 选多资产不释放 | revoke on remove/切换 | 切换附件无泄漏 |

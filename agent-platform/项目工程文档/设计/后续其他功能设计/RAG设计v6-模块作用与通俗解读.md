## 二、四大核心模块通俗解读（打比方 + 真实场景）

### 1. 检索流程（§4）—— 提问怎么变成带出处的答案

**一句话作用**：把用户的一句提问，走成一条固定流水线，最后产出「答案 + 标明来自哪段」的结果。每一步都能追踪。

**打个比方**：你站在公司前台问「上海出差住宿能报多少？」，前台不会瞎猜，而是按一套固定流程办，最后递给你一张写着答案、并标明「来自《差旅标准》第 3 页」的纸条。

**具体场景，8 步在干嘛**（以问「上海住宿报销」为例）：

1. **看钥匙** —— 先确认你能开哪些资料柜（你的权限范围）。
2. **翻便签** —— 这问题这两天有人问过吗？有就直接念上次答案，不重新查。
3. **缩范围** —— 只要「制度类 + 现在还生效的」，过期的不要。
4. **找抽屉** —— 定位到「财务制度 / 报销制度 / 差旅标准」这个文件夹。
5. **按意思找章节** —— 在文件夹里找出意思最相关的几个章节摘要。
6. **捞原文 + 精排** —— 把这几个章节的原文段落拉出来，按相关度排序，挑最对的两三段。
7. **不瞎编** —— 如果连一段靠谱的都找不到，就老实说「知识库里没有，建议问人工」，绝不编一个。
8. **生成 + 标出处** —— 把挑中的原文喂给大模型写答案，并逼它每句话标号「来自第①段」，不许伪造标号。

**不这么做会怎样**：答案没出处（没法信）/ 瞎编（企业合规出事）/ 全库乱搜（慢 + 错）。

> **它是 RAG 的主干道，其它所有模块都是给这条路修的护栏和加油站。**

---

### 2. 权限与安全（§5）—— 用户只能看到他有权的知识

**一句话作用**：召回**之前**就先算清「你能看哪些」，把搜索范围锁死在有权限的柜子里，绝不「先全翻一遍再挑给你」。

**打个比方**：公司档案室 + 门禁卡。普通员工只能进公共区，财务能进财务柜，HR 能进人事柜，高管有专属柜。**你的门禁卡决定你能推开哪扇门**——而不是「把所有柜子翻开再挑给你看」。

**具体场景**：
- 销售部小李问「竞品分析」，系统绝不会把存在「高管专属」知识库里的**未公开并购文档**搜给他。
- 后台自动跑的工作流（没有具体用户登录），用一张专门的**服务账号卡**，权限卡得更死。

**不这么做会怎样**：小李搜出高管机密 → 商业机密泄露 → 合规事故。这是**企业级 RAG 和玩具 RAG 的第一条分界线**。

> **先问「你能看吗」，再决定「给你看什么」。**

---

### 3. 一致性（§6）—— 索引永远跟原文对得上

**一句话作用**：向量索引只是原文的「影子」，原文是真相；原文一改一删，影子必须立刻跟着动，绝不出现「索引指着旧内容」。

**打个比方**：书的**目录（索引）**和**正文（原文）**。你改正文一段话，目录却没更新 → 读者按目录翻到错页、读到旧内容。一致性机制就是：
- 每次改正文，同时夹一张「待更新目录」的小条子（outbox）。
- 后台图书员看到条子，**先确认正文没又被人改第二次**，才敢更新目录。
- 正文删了 → 目录对应行也标掉，不能留着指向空气。

**具体场景**：
- 财务把「一线城市住宿上限 800」改成 **900** → 必须保证用户搜出的结果指向**新版 900**，不能搜出旧版 800 还当现行。
- 删掉一份过期制度 → 要保证**再也搜不出来**，连缓存的旧答案都失效。

**不这么做会怎样**：用户照旧制度报销、财务对不上；删了的机密还能被搜出来——**索引和原文一对不上，整个知识库就不可信了**。

> **原文是真相，索引是影子，影子必须时刻跟着本体走。**

---

### 4. 语义缓存（§8）—— 答过的问题不重答

**一句话作用**：相同或相近的问题，不重走整套检索 + 生成，直接还上次答案，省时间省 token。

**打个比方**：答疑老师的**小本本**。昨天有人问「上海住宿报多少」，老师认真翻了制度答了。今天换种问法「去上海出差住酒店上限多少」——**意思一样**，老师翻小本本直接念上次答案，不重新翻书。

**三条防出事的规矩**：
1. **小本本按人记**：张三的本子只给张三用。不同人能看的资料不同，混用会把别人的答案塞给你 → 泄露。
2. **记答案时附版本号**：当时引用的制度是哪版。**制度一改，对应那页作废**，不会还你旧答案。
3. **没把握的不记**：上次拒答（abstain）的问题不进本子，免得下次还你一个「不知道」。

**具体场景**：全公司天天有人问差旅标准。
- 第一次：认真检索 + 生成，花 3 秒、烧 2000 token。
- 第二次起：命中缓存，**毫秒级**返回，标注「来自缓存」。想要最新？一键重新查。

**不这么做会怎样**：同一高频问题反复全量检索 → **token 账单爆炸、响应慢**；还可能跨用户串答案、泄露权限。

> **会答过的别重答，但只在自己权限范围内复用，且原文变了就作废。**

## 三、四者怎么配合（心里有这张图）

```
提问
  ↓
[§5 权限]   你能看哪些？        ← 护栏：先过这关
  ↓
[§8 缓存]   答过吗？            ← 加油站：命中就抄近路
  ↓
[§4 检索流程] 主干道：8 步查原文出答案
  ↓
[§6 一致性] 贯穿全程              ← 路面养护：保证查到的索引 = 现行原文，没被骗
```

一句话类比：
- **§4 = 路**（走哪条线到答案）
- **§5 = 门禁**（谁能上路、能看几号柜）
- **§6 = 路面养护**（路标别指错方向）
- **§8 = 快车道**（走过的路抄近道）

## 四、一句话记住每个核心模块

- **检索流程 §4**：提问 → 8 步 → 带出处的答案。主干道。
- **权限 §5**：先问你能不能看，再决定给你看什么。门禁卡。
- **一致性 §6**：原文是真相，索引是影子，影子跟着本体走。目录对正文。

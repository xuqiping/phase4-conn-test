# 案例：Vibe Coding与SDD——2025新术语的产品化

## 术语映射

| 术语 | 在本案例中的体现 |
|---|---|
| Vibe Coding | Cursor/Copilot/Claude Code等产品让PM也能"用嘴写代码" |
| SDD(Spec-Driven Development) | v0.dev/Bolt.new等产品从Spec直接生成完整前端应用 |
| Prompt | Vibe Coding的核心输入——Prompt质量直接决定输出质量 |
| Token | 每次Vibe Coding的迭代都消耗大量Token——需考虑成本控制 |
| 幻觉 | AI生成的代码也可能有"功能幻觉"——看起来对但实际有bug |
| 上下文窗口 | 复杂项目需要长上下文理解整个代码库——窗口大小是Vibe Coding的天花板 |

## 代表产品 [来源:公开信息 | 🔍高 | 2026-01]

| 产品 | 定位 | Vibe Coding程度 | SDD程度 |
|---|---|---|---|
| GitHub Copilot | 代码补全/生成 | 中（辅助补全为主） | 低 |
| Cursor | AI原生IDE | 高（多文件编辑/Agent模式） | 中 |
| Claude Code | 命令行AI编程 | 高（全流程编程Agent） | 中 |
| v0.dev | 前端UI生成 | 中（聚焦前端） | 高（Spec→UI） |
| Bolt.new | 全栈应用生成 | 高（端到端生成） | 高（描述→应用） |
| Replit Agent | 云端全栈开发 | 高（部署+代码一体） | 高 |

## 产品决策启示

1. **PM可以"造原型"了**：Vibe Coding让PM从"画原型"升级到"跑原型"——但原型≠产品，工程质量仍需工程师
2. **Spec的价值被放大**：SDD让精心设计的Spec直接变成代码——PRD/Spec的精确度要求大幅提升
3. **安全底线不能松**：AI生成的代码需要代码审查/安全扫描——Vibe Coding≠跳过工程规范
4. **成本意识**：多个Agent迭代的Token消耗可能远超预期——需要设定单任务Token上限

# File Keeper 本地复制粘贴强化功能设计

## 1. 背景与目标

File Keeper 当前是基于 Tauri 2、Vue 3、TypeScript 和 Rust 的 Windows 桌面效率工具，已有文件管理、进程管理、系统托盘、全局快捷键、主题切换和中英文切换等能力。复制粘贴强化功能将作为第三个核心模块加入现有产品：文件管理解决“常用文件主动收藏”，进程管理解决“运行中应用整理”，剪贴板强化解决“复制内容自动记录、找回、处理并再次粘贴”。

本设计基于项目技术架构文档和复制粘贴强化路线图，首版选择“本地增强完整版”：不做云同步、不做账号、不做团队协作，先把本机复制粘贴体验做完整。设计保留跨平台抽象，但第一阶段只实现 Windows。

目标是让用户在日常复制文本、图片、文件、链接、富文本、颜色等内容时，能够安全地保存历史、快速搜索、预览、转换格式并重新粘贴，同时避免密码、密钥、银行卡等敏感内容进入历史。

## 2. 首版范围

### 2.1 首版要做

- 新增“剪贴板”主窗口标签页，用于历史管理、搜索、筛选、预览、批量删除、空间清理和规则配置。
- 新增全局快捷键呼出的快捷面板，用于快搜快粘贴。
- 支持文本、富文本/HTML、图片、文件、文件夹、URL、颜色代码和混合内容进入历史。
- 默认强安全防护：密码管理器来源、银行卡、API Key、高熵随机串等内容默认不保存。
- 默认把选中历史写回系统剪贴板；设置里可开启自动粘贴到原窗口。
- 文件默认保存副本，但受总空间、类型空间、单文件大小和后缀规则限制。
- 支持文本长期保存；图片、HTML、文件副本、链接缩略图等非文本内容受缓存空间上限控制。
- 支持图片预览、缩略图、OCR 搜索、格式转换和压缩。
- 支持富文本原始格式、纯文本、简化 HTML、Markdown 等粘贴选项。
- 支持 URL 卡片预览；联网抓取标题和缩略图必须有开关和隐私提示。
- 支持来源应用记录，用于筛选、规则配置和安全防护。
- 预留 macOS 平台接口，但 Windows 先完整落地。

### 2.2 首版不做

- 云同步、云备份、云端中继。
- 账号系统、登录、设备管理。
- 团队共享剪贴板。
- 跨设备文件传输。
- 远程 OCR 或云端 AI。
- 付费授权系统。
- macOS 实现。

## 3. 产品体验闭环

首版体验围绕“复制、保存、找回、处理、再粘贴”展开：

1. 用户在任意应用复制内容。
2. Rust 剪贴板内核监听到系统剪贴板变化。
3. 后端读取剪贴板内容和来源应用信息。
4. 安全模块先判断内容是否敏感。
5. 非敏感内容按类型提取、生成摘要、缩略图、hash 和必要缓存。
6. 历史元数据写入 SQLite，大内容写入本地缓存目录。
7. 用户按剪贴板快捷键呼出快捷面板。
8. 用户直接输入关键词搜索，使用上下键选择历史。
9. Enter 执行默认动作：复制回系统剪贴板；如果开启自动粘贴，则恢复原窗口并模拟粘贴。
10. 用户在主窗口剪贴板页做完整管理：预览、筛选、收藏、删除、清理缓存、配置规则。

快捷面板只负责高频粘贴，主窗口负责完整管理和设置，避免快捷面板过载。

## 4. 总体技术路线

采用“Rust 剪贴板内核 + Vue 双入口界面”的方案。

- Rust 负责系统级能力：剪贴板监听、多格式读取、敏感拦截、本地缓存、写回剪贴板、自动粘贴、来源应用识别和后台任务。
- Vue 负责用户界面：主窗口剪贴板页、快捷面板、设置页、搜索筛选、预览和操作反馈。
- SQLite 负责剪贴板历史元数据、设置、索引状态和安全事件。
- 本地缓存目录负责图片、文件副本、HTML 原文、链接缩略图等大内容。

这个方案延续当前项目“Vue 管界面、Rust 管系统能力”的架构，也能为后续 macOS 和同步能力预留边界。

## 5. 系统架构与模块边界

### 5.1 Rust 剪贴板内核

后端新增独立 clipboard 模块，职责包括：

- 监听系统剪贴板变化。
- 读取多格式剪贴板内容：文本、HTML、图片、文件列表。
- 获取来源应用信息：进程名、窗口标题、PID、窗口句柄。
- 执行敏感内容检测和排除规则。
- 生成历史记录、内容摘要、hash、预览元数据和缓存文件。
- 写回系统剪贴板。
- 自动恢复原窗口并触发粘贴。
- 删除历史、清理缓存、重建索引。
- 管理 OCR、链接预览、图片转换等后台任务。

建议后端文件结构：

```text
src-tauri/src/commands/clipboard.rs
src-tauri/src/clipboard/mod.rs
src-tauri/src/clipboard/storage.rs
src-tauri/src/clipboard/cache.rs
src-tauri/src/clipboard/security.rs
src-tauri/src/clipboard/search.rs
src-tauri/src/platform/windows/clipboard.rs
src-tauri/src/platform/windows/foreground.rs
src-tauri/src/platform/macos/clipboard.rs
```

### 5.2 本地存储层

剪贴板历史不放入现有 file-keeper-data.json，避免大数据和高频写入影响现有文件管理配置。新增独立 SQLite 数据库保存元数据和索引。图片、文件副本、HTML 原文、链接缩略图等大内容保存到本地缓存目录。

SQLite 适合剪贴板历史的原因：

- 历史条目可能很多，需要分页、筛选和搜索。
- 文本和 OCR 搜索适合建立索引。
- 非文本缓存需要记录空间占用和清理状态。
- 写入频率高于现有设置数据，不适合继续用单个 JSON Store。

首版建议使用 rusqlite，单机桌面场景足够直接，依赖和运行模型较简单。

### 5.3 前端剪贴板模块

前端新增独立剪贴板 feature，避免继续扩大 App.vue。主入口包括：

- 主窗口剪贴板管理页。
- 全局快捷键呼出的快捷面板。
- 剪贴板设置页。

App.vue 只负责新增标签入口、挂载剪贴板页面和接入快捷键，不承载剪贴板业务逻辑。

### 5.4 跨平台抽象

Rust 内部定义平台抽象接口，至少覆盖：

- 剪贴板读取。
- 剪贴板写入。
- 来源应用识别。
- 自动粘贴目标窗口恢复。
- 文件列表剪贴板处理。

Windows 第一阶段完整实现。macOS 只保留接口和模块骨架，不阻塞首版 Windows 落地。

### 5.5 与现有功能关系

- 文件管理模块继续负责用户主动收藏的常用文件。
- 剪贴板模块负责系统复制行为自动产生的历史。
- 剪贴板里的文件记录可以一键加入文件收藏。
- 文件收藏项可以一键复制路径或文件本体到系统剪贴板。
- 进程管理模块不与剪贴板模块耦合，但来源应用识别可以复用部分 Windows 进程信息能力。

## 6. 数据模型与保存规则

剪贴板历史拆成三层：记录元数据、类型内容、缓存文件。

### 6.1 核心历史记录

每条历史记录包含统一字段：

- id。
- 内容类型。
- 创建时间、最后使用时间、使用次数。
- 来源应用：进程名、窗口标题、PID。
- 内容摘要：列表标题、摘要、缩略图路径。
- 内容 hash：用于去重。
- 收藏、置顶、标签。
- 缓存占用大小。
- 清理策略状态：是否允许自动清理、是否已清理缓存、是否仅保留元数据。

内容类型首版包括：

- text：文本。
- html：富文本或 HTML。
- image：图片。
- file：文件或文件夹集合。
- url：链接。
- color：颜色。
- mixed：混合内容。
- security_event：安全拦截事件。

### 6.2 类型内容

不同类型保存不同扩展信息：

- 文本：原文、规范化文本、长度、搜索字段。
- HTML：原始 HTML、清理后 HTML、纯文本、Markdown 转换结果。
- 图片：原图缓存路径、缩略图路径、尺寸、格式、OCR 文本、主色信息。
- 文件集合：原路径列表、文件名、大小、修改时间、hash、本地副本路径、是否副本完整。
- URL：地址、标题、描述、缩略图、抓取时间、是否联网生成。
- 颜色：HEX、RGB、HSL，未来可扩展 CMYK。
- 安全事件：拦截类型、来源应用、时间、规则 ID，不保存敏感原文。

### 6.3 保存规则

默认策略：

- 文本长期保存，默认不占用非文本空间上限。
- 图片、HTML、文件副本、链接缩略图进入非文本缓存空间池。
- 文件默认保存副本，但受空间和规则限制。
- 如果用户没有设置后缀规则，默认所有后缀都允许进入历史和保存副本。
- 如果用户设置了后缀白名单，则只有指定后缀允许保存副本。
- 支持按类型设置空间上限，例如图片 1GB、文件 2GB、HTML 500MB。
- 支持设置总非文本空间上限，例如 2GB。
- 支持设置单条记录最大大小，例如单个文件超过 200MB 不复制副本，只保存引用或跳过。
- 空间超限时，优先清理未收藏、未置顶、最久未使用的缓存内容。

后缀规则采用非强制模式：未配置时不限制；配置后才按白名单或黑名单执行。首版设置界面默认展示“未限制后缀，所有文件类型都可保存”。

### 6.4 去重策略

- 文本按规范化内容 hash 去重。
- 图片按二进制 hash 去重。
- 文件集合按路径、大小、修改时间和内容 hash 组合去重。
- URL 按标准化 URL 去重。
- 去重后更新最后复制时间和使用次数，不重复制造多条记录。

## 7. 安全防护与隐私策略

首版采用默认强防护。原则是：宁可少保存一条可疑内容，也不要把密码、API Key、银行卡号等敏感内容写进历史。

### 7.1 敏感内容拦截

进入历史前先检查：

- 密码管理器来源应用：1Password、Bitwarden、KeePass、Enpass、Dashlane 等。
- 浏览器密码管理页面或明显敏感窗口标题。
- 高熵字符串：疑似随机密码、token、密钥。
- 常见密钥格式：API Key、Access Token、JWT、SSH 私钥片段、GitHub/GitLab token、云服务 key。
- 银行卡号：格式检查和 Luhn 校验。
- 用户自定义排除：应用、窗口标题关键词、内容关键词、正则。

处理方式：

- 默认不保存敏感原文。
- 不生成缓存。
- 不做 OCR。
- 不进入搜索索引。
- 可记录一条安全事件，只保存类型、来源应用、时间和规则 ID。
- 用户可以关闭某类规则，但需要明确风险提示。

身份证、手机号等个人信息首版建议做成可选规则，避免误伤过多日常内容。

### 7.2 来源应用防护

来源应用识别用于：

- 判断是否来自密码管理器或敏感应用。
- 允许用户配置“从这些应用复制的内容永不保存”。
- 支持历史筛选和搜索。

Windows 首版通过前台窗口和进程信息获取来源。macOS 后续通过平台抽象补实现。

### 7.3 联网隐私

URL 预览是首版能力，但必须可控：

- 默认可以只保存 URL 文本，不联网抓取标题和缩略图。
- 联网抓取需要明确开关。
- 首次开启时提示：这会访问链接对应的网站，可能暴露访问行为。
- 抓取失败不影响历史记录，只显示预览不可用。
- 云同步、云备份、远程 OCR 全部不做。

### 7.4 本地数据安全

- 所有历史和缓存默认只存在本机。
- 设置页提供清空历史、清空非文本缓存、按类型清理等操作。
- 可选提供退出时清理临时粘贴内容。
- 数据库加密可作为后续增强；首版底线是敏感内容不入库。

### 7.5 用户信任表达

界面需要明确展示：

- 哪些内容被保存。
- 哪些内容被自动拦截。
- 当前非文本缓存占用了多少空间。
- 联网能力是否开启。
- 自动粘贴是否开启。

## 8. 界面设计与交互

首版采用混合式界面：主窗口剪贴板管理页 + 快捷面板。

### 8.1 主窗口剪贴板页

主窗口剪贴板页采用三栏结构：

- 左侧：类型筛选、收藏、安全事件、缓存占用。
- 中间：历史列表，支持搜索内容、来源应用、OCR 文本、文件名。
- 右侧：详情预览和操作区，显示内容预览、可选粘贴格式、收藏、删除、加入文件收藏等操作。

左侧分类包括：全部、文本、图片、文件、富文本、链接、颜色、已收藏、安全事件。

中间列表需要支持：

- 虚拟滚动。
- 类型图标。
- 来源应用。
- 复制时间。
- 简短摘要。
- 缩略图懒加载。
- 是否已保存副本、是否仅保存引用、是否可自动清理。

右侧预览需要支持：

- 文本完整预览。
- HTML 原始、纯文本、简化 HTML、Markdown 选项。
- 图片缩略图、尺寸、格式、OCR 文本。
- 文件列表、大小、副本状态、原路径。
- URL 卡片、联网状态、重新抓取入口。
- 颜色格式转换。

### 8.2 快捷面板

快捷面板用于高频操作，保持轻量：

- 全局快捷键呼出。
- 默认聚焦搜索框。
- 用户直接输入关键词搜索。
- 上下键选择历史。
- Enter 执行默认动作。
- Shift+Enter 使用纯文本。
- Tab 或右键展开更多格式选项。
- Esc 关闭面板，不改动剪贴板。

默认动作是复制回系统剪贴板。如果用户开启自动粘贴，则写回剪贴板后恢复原窗口并模拟粘贴。

快捷面板底部只放少量辅助信息：快捷键提示、设置入口、当前模式提示。复杂管理不放在快捷面板里。

### 8.3 设置入口

设置项包括：

- 剪贴板监听开关。
- 剪贴板面板快捷键。
- 自动粘贴开关。
- 安全防护规则。
- 排除应用和窗口关键词。
- 总非文本缓存上限。
- 按类型空间上限。
- 单条记录大小上限。
- 后缀白名单/黑名单。
- URL 联网预览开关。
- OCR 开关。
- 图片压缩和格式转换默认策略。

主窗口剪贴板页右上角进入完整设置。快捷面板底部只提供跳转入口。

### 8.4 与现有导航整合

主窗口顶部标签增加“剪贴板”。现有“文件管理”和“进程管理”文案保持不变。剪贴板模块新增 i18n 命名空间，避免硬编码中文。

## 9. 后端实现设计

### 9.1 监听策略

Windows 首版使用系统剪贴板监听机制，不采用前端轮询。

监听流程：

1. 应用启动后根据设置启动剪贴板监听服务。
2. 系统剪贴板变化时收到事件。
3. 延迟几十毫秒读取，避免复制源尚未写完。
4. 读取失败时短暂重试。
5. 计算 hash，跳过重复内容。
6. 如果是本应用刚写回剪贴板的内容，通过短期忽略标记避免重复采集。
7. 对大图片、大文件、OCR、链接抓取等任务进入后台队列。
8. 先写入基础历史记录，再异步补齐缩略图、OCR、预览等增强信息。

### 9.2 自动粘贴流程

自动粘贴是可选增强，默认关闭或默认不强制使用。

流程：

1. 快捷面板打开前记录当前前台窗口句柄。
2. 用户选择历史项。
3. Rust 写入系统剪贴板。
4. 如果开启自动粘贴，恢复原窗口。
5. 模拟 Ctrl+V。
6. 如果失败，提示“已复制到剪贴板，请手动粘贴”。

无论自动粘贴成功与否，写回剪贴板都先完成，保证用户有兜底路径。

### 9.3 后台任务

后台任务包括：

- 图片缩略图生成。
- 图片格式转换。
- 图片压缩。
- OCR 识别。
- URL 标题和缩略图抓取。
- 文件 hash 计算。
- 空间超限清理。
- 搜索索引重建。

后台任务不能阻塞剪贴板监听和基础历史写入。失败时记录状态，前端显示“预览不可用”或“增强处理中”。

### 9.5 依赖建议

首版可能需要新增 Rust 依赖：

- rusqlite：本地 SQLite。
- image：图片读取、缩略图、格式转换。
- sha2 或 blake3：内容 hash。
- regex：敏感内容规则。
- url：URL 标准化。
- reqwest：URL 预览联网抓取，仅在用户开启时使用。
- OCR 依赖需要单独评估体积、模型文件和 Windows 打包成本。

OCR 不应阻塞基础功能。如果 OCR 依赖过重，实现计划可以把 OCR 作为首版后段里程碑，但规格上保留首版目标。

首版实现优先级应是：先完成文本、图片、文件、安全防护、历史管理和快捷面板闭环；再补齐 OCR、链接预览、图片转换和富文本高级格式预览。

### 10.4 App.vue 接入

App.vue 只做：

### 10.5 快捷键设计

现有全局快捷键用于显示或隐藏 File Keeper 主窗口。剪贴板需要独立快捷键：

- 主窗口快捷键：显示 File Keeper。
- 剪贴板面板快捷键：默认 Ctrl+Shift+V。

设置页要区分两个快捷键。注册失败时沿用现有冲突提示方式。

## 11. 错误处理

首版错误分为以下类别：

- 读取失败：短暂重试后仍失败则跳过，不打断用户复制行为。
- 保存失败：提示用户检查磁盘空间或缓存目录权限。
- 文件副本失败：文件过大、权限不足、路径失效时，根据设置降级为仅保存引用或跳过。
- 自动粘贴失败：不阻断流程，提示已复制到剪贴板，请手动粘贴。
- OCR 失败：不影响主记录，显示 OCR 不可用。
- 链接预览失败：不影响 URL 历史，显示预览不可用。
- 安全拦截：不作为错误，作为安全事件展示。

所有错误提示都应告诉用户“当前结果是什么”和“下一步能做什么”。

## 12. 性能策略

- 剪贴板监听只做轻量读取、hash 和入队。
- 大图片、大文件、OCR、链接抓取全部后台处理。
- 列表分页或虚拟滚动。
- 缩略图懒加载。
- 搜索优先查 SQLite 索引，不在前端全量过滤大数据。
- 非文本缓存按上限自动清理。
- 本应用写回剪贴板时设置短期忽略标记，避免重复采集。
- 文件副本和 hash 计算需要可取消或可降级，避免复制超大文件时拖慢应用。

## 14. 风险与降级策略

首版范围偏大，主要风险包括：

- OCR 依赖体积和打包复杂度较高。
- 自动粘贴受目标应用权限影响，可能失败。
- 文件默认保存副本可能带来磁盘占用和隐私压力。
- URL 联网预览可能引起隐私顾虑。
- 剪贴板格式在不同应用间差异较大。

降级策略：

- OCR 失败不影响图片历史，只影响图片文字搜索。
- 自动粘贴失败后保留已复制到剪贴板的兜底结果。
- 文件副本受空间和后缀规则限制，超过限制时降级为引用或跳过。
- URL 预览默认可关闭，并明确联网提示。
- 富文本格式清理以预览和用户选择为主，不强制自动改写。

## 16. 设计结论

首版剪贴板强化功能应作为 File Keeper 的第三个核心模块独立建设。推荐使用 Rust 剪贴板内核承接系统能力，Vue 前端提供主窗口管理页和快捷面板，SQLite 管理历史元数据，本地缓存目录保存大内容。

本轮不做云能力，但数据模型、平台抽象和后续路线图需要为同步、跨设备传输和 macOS 实现预留空间。首版重点是把本地体验做到可信、稳定、可控：敏感内容默认不入库，文件副本受空间和后缀规则限制，快捷面板高频好用，主窗口管理清晰。

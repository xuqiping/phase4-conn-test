# 6.2 学谁

> 本碎片聚焦人物的**思维范式**（人物事迹见 [5.1 案例集](../5_业内顶级案例/5.1_案例集.md)）。学谁不是学他们做了什么，而是学他们**怎么想**——这些思维范式是 PM 应对 Agentic Engineering 挑战的认知工具。

## 一、范式推动者（4 位）

### 1. Andrej Karpathy（OpenAI 创始成员、特斯拉前 AI 总监）

| 维度 | 内容 |
|---|---|
| **身份** | Vibe Coding 概念发明者，深度学习领域顶级实践者 |
| **核心贡献** | 2025-02 发明 Vibe Coding 概念，开启原型期 Coding Agent 范式 |
| **思维范式** | **"拥抱指数级增长"思维**——不被传统工程流程束缚，先用最快速度验证可能性，再补工程化。他认为代码生成成本趋零后，"不值得做"的判断标准变了，应该先跑再说 |
| **学什么** | 学他"快速验证先行"的勇气，但更要学他后来对 Vibe Coding 局限性的反思——原型期可以用，生产期必须升级 |
| **出处** | [知乎《认知重建之后步入Agentic Engineering》2026-03 引 Karpathy 推文] |

### 2. Simon Willison（Django 框架联合创建者、资深技术博主）

| 维度 | 内容 |
|---|---|
| **身份** | 长期关注 AI 技术发展的观察者，Django 联合创建者 |
| **核心贡献** | 在 Pragmatic Summit 炉边谈话深入探讨 Agentic Engineering，提出"AI Agent 开发新范式" |
| **思维范式** | **"范式补充而非替代"思维**——他认为 Agentic Engineering 是传统编程范式的补充甚至部分替代，不是推翻。这种温和的范式观让他在 AI 狂热中保持清醒，不鼓吹"颠覆"而强调"演进" |
| **学什么** | 学他"补充而非替代"的范式观——四代演进是叠加累积不是推翻重来，Prompt Engineering 没消失只是重心迁移 |
| **出处** | [知乎《Agentic Engineering:AI Agent开发的新范式》2026-03 引 Pragmatic Summit] |

### 3. Boris Cherny（Claude Code 负责人）

| 维度 | 内容 |
|---|---|
| **身份** | Anthropic Claude Code 负责人，一线 Agent 工程实践者 |
| **核心贡献** | 2026-06 公开表示"日常工作就是写循环(Loop)，让循环去调度 Claude，自己不再逐条下达指令" |
| **思维范式** | **"设计循环替代逐条指令"思维**——他从"人逐条给 AI 下指令"转向"设计循环让循环调度模型"，这是 Loop Engineering 的核心范式。代表了工程师角色从"指令者"到"循环设计者"的转变 |
| **学什么** | 学他"循环设计者"的角色认知——不再逐条写 prompt，而是设计目标/工具/记忆/安全/终止条件/验证机制的系统 |
| **出处** | [新浪/网易《你还在手写Prompt?聪明的人早就用上了循环工程》2026-07 引] |

### 4. Peter Steinberger（OpenClaw 创始人）

| 维度 | 内容 |
|---|---|
| **身份** | OpenClaw 创始人，Coding Agent 工具实践者 |
| **核心贡献** | 2026-06 发文"别再手动给 AI 编码代理写提示词了，应该去设计一个能替你写提示词的系统" |
| **思维范式** | **"元系统思维"**——他不只是让 AI 写代码，而是设计一个"替你写提示词的系统"，这是把工程抽象层级提升一级的思维。从"优化提示词"到"优化生成提示词的系统" |
| **学什么** | 学他"元系统"思维——遇到优化瓶颈时，把优化对象上升一级（从优化 prompt 到优化生成 prompt 的系统） |
| **出处** | [腾讯云/网易 引 Peter Steinberger 2026-06 发文] |

## 二、工程实践者（2 位）

### 5. 储瑞松（亚马逊全球副总裁、亚马逊云科技亚太区联席总裁）

| 维度 | 内容 |
|---|---|
| **身份** | 亚马逊云科技亚太区联席总裁，企业级 AI 工程化推动者 |
| **核心贡献** | 2026-06-23 亚马逊云科技中国峰会宣布"Agentic 工程体系正在快速成熟"，点明麦肯锡鸿沟症结 |
| **思维范式** | **"工程体系成熟度"思维**——他不谈单个模型多强，而谈"工程体系是否成熟"。认为症结不在模型能力而在"缺乏科学有效的开发部署指导"。这种体系思维让他看到单点技术突破之外的鸿沟 |
| **学什么** | 学他"体系成熟度"视角——不追单点技术，看整体工程体系是否成熟，鸿沟往往在体系不在单点 |
| **出处** | [百度百科《Agentic工程体系》2026-07 / 网易引储瑞松演讲] |

### 6. 何宇航（易点天下中台研发总监）

| 维度 | 内容 |
|---|---|
| **身份** | 一线企业 Agent 工程化实践者，QCon 2026 北京分享嘉宾 |
| **核心贡献** | 在 QCon 2026 分享《从Prompt到Context:Agentic AI工程化实践》，提出"概率性智能跑在确定性生产系统"命题 |
| **思维范式** | **"确定性容纳概率性"思维**——他不否定 Agent 的概率性（幻觉/遗忘），而是在确定性企业架构中加约束（权限/流程/数据边界）让概率性稳定化。这是务实派的工程哲学——不追求消除概率性，而追求把概率性控制在可接受范围 |
| **学什么** | 学他"确定性容纳概率性"的务实工程哲学——不追求完美，追求可控；渐进式上生产不跳层 |
| **出处** | [搜狐《从Prompt到Context:易点天下Agentic AI工程化实践》QCon 2026 北京] |

## 三、云基础设施方（团体）

### 7. 阿里云 Agent Native Cloud 团队

| 维度 | 内容 |
|---|---|
| **身份** | Agent Native Cloud 发布者，2026 WAIC 基础设施拐点推动者 |
| **核心贡献** | 2026-07-18 WAIC 发布 Agent Native Cloud + AgentTeams + Agentic Computer |
| **思维范式** | **"原生能力 vs 接入工具"思维**——他们认为 Agent 应从"企业接入的工具"进化为"企业原生的能力"，这是基础设施层的范式跃迁。从"给企业加 Agent 功能"到"让企业原生具备 Agent 能力" |
| **学什么** | 学他们"原生能力"视角——选部署底座时不只看能不能跑 Agent，而看是否原生支持 Agent 能力 |
| **出处** | [百家号/环球网《阿里云发布Agent Native Cloud》WAIC 2026-07-18] |

## 四、框架贡献者（团体）

### 8. Strands Agents / LangGraph / CrewAI 框架团队

| 维度 | 内容 |
|---|---|
| **身份** | 2026 主流 Agent 框架贡献者，生态位锁定推动者 |
| **核心贡献** | Strands Agents（企业级首选）/ LangGraph（生产编排主导）/ CrewAI（原型快速开发）各占生态位 |
| **思维范式** | **"生态位锁定"思维**——他们不追求一个框架通吃所有场景，而是在特定生态位做到最好。Strands 不与 LangGraph 拼全面而拼"轻量+企业级"，CrewAI 不拼生产而拼"原型快" |
| **学什么** | 学他们"生态位聚焦"思维——选型时不找"最好"的框架，而找"最适合场景"的框架 |
| **出处** | [CSDN《2026年大语言模型技术路线》2026-07 / 阿里云天池 2026-07] |

## 五、国内领军（补充）

### 9. 黄建（技术博主，认知重建推动者）

| 维度 | 内容 |
|---|---|
| **身份** | 国内 Agentic Engineering 认知重建推动者，微博技术博主 |
| **核心贡献** | 2026-04 微博《AI时代工程师的新必修课:Agentic Engineering》系统总结认知重建 |
| **思维范式** | **"好代码标准没变"思维**——他反复强调"写代码变便宜了，但写出好代码没有；好代码标准没变（能运行/有测试/处理边界case/文档同步/可维护），变的是不值得做的理由消失了"。这种"标准不变路径变"的思维让人不因工具变强而降低质量标准 |
| **学什么** | 学他"标准不变路径变"思维——工具升级不等于标准降低，好代码标准永远是那五条 |
| **出处** | [黄建微博《AI时代工程师的新必修课:Agentic Engineering》2026-04] |

# 4.1 Agent RICE评分与优先级输出

> 📅 2026-07-11 ｜ 🔴红线：RICE评分不可全靠AI推断，Reach/Impact/Confidence必须有数据支撑或PM判断，Agent仅辅助估算与校准 ｜ 角色：RICE优先级分析Agent

## 背景

RICE评分需要PM对每个需求的四维度进行估算，但大量需求的评分过程重复性高、校准困难。本Agent辅助PM完成RICE评分的数据化估算、跨需求排序、KANO交叉校验。

## 目标

输入需求清单+可选的用户数据/历史评分，输出RICE评分表+优先级排序+KANO交叉校验建议。

## 关键结果

1. 每个需求的RICE四维评分（含评分依据）
2. RICE排序表（含Confidence惩罚后的有效得分）
3. KANO交叉校验标记（M类优先保障、I类降权建议）

## 执行步骤

### Step 1：Reach自动估算（辅助）

```
输入：需求的功能描述 + 产品埋点数据（可选）

自动估算逻辑：
  - 如有埋点数据 → 自动计算目标用户群的MAU/UV
  - 如无埋点数据 → 参考历史类似功能的Reach比例 × 总用户数
  - 输出Reach建议值 + 数据来源标注

PM必须确认：Agent估算的Reach是否符合直觉？
```

### Step 2：Impact评分参考

```
输入：需求的功能描述 + 历史评分库

自动参考逻辑：
  - 在历史评分库中搜索功能描述相似的需求
  - 提取历史Impact评分 + 实际业务结果（如有）
  - 输出Impact评分建议 + 历史参照案例

PM必须确认：Impact建议是否合理？是否有额外信息未考虑？
```

### Step 3：Confidence自动推算

```
根据数据来源自动推算：
  - 有埋点数据+用户调研 → 100%
  - 有埋点数据或用户调研之一 → 80%
  - 无数据，仅凭PM经验 → 50%
  - 混合数据分别评估，取较低值

输出提示：低Confidence需求的建议验证方案
```

### Step 4：Effort参考估算

```
输入：需求功能描述 + 历史Jira任务库

自动参考逻辑：
  - 在历史任务中搜索功能相似的开发任务
  - 提取历史实际开发工时
  - 输出Effort建议值 + 历史参照

⚠️ 必须由技术团队最终确认Effort——Agent仅辅助参考
```

### Step 5：RICE计算与排序

```
计算：RICE = (Reach × Impact × Confidence) / Effort
排序：按RICE得分降序
标注：低Confidence需求标黄，提醒补充数据
```

### Step 6：KANO交叉校验（如已有KANO数据）

```
交叉逻辑：
  - M类 + RICE低 → 🚨 标记"必须做（无视RICE排名）"
  - I类 + RICE高 → ⚠️ 标记"验证Impact是否虚高"
  - A类 + Confidence低 → 📋 标记"建议先验证再排期"
```

## 输出格式

```markdown
# RICE优先级分析报告

## 评分总表
| 排名 | 需求 | Reach | Impact | Confidence | Effort | RICE得分 | KANO标注 | 备注 |
|---|---|---|---|---|---|---|---|---|

## 低Confidence需求清单（需补充数据）
| 需求 | Confidence | 建议验证方式 | 预计验证时间 |
|---|---|---|---|

## KANO交叉校验
| 需求 | KANO类别 | RICE排名 | 校验建议 |
```

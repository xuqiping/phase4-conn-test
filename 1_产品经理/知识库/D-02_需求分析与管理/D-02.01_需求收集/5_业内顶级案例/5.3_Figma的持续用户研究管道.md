# 5.3 Figma 的持续用户研究管道

## 背景

Figma从设计工具挑战者到行业标准，其竞争力不仅来自技术（浏览器渲染、实时协作），更来自**持续深入的用户研究文化**——Figma的研究团队不是"有项目时才调研"，而是**永远在调研**。[来源:Figma Config演讲 | 📚中 | 2023]

## 研究管道架构

```
┌─────────────────────────────────────────────┐
│              Figma 持续研究管道                │
├──────────┬──────────┬──────────┬─────────────┤
│ 信号捕获  │ 信号筛选  │ 深度探索  │ 验证闭环     │
│          │          │          │             │
│• 社区反馈 │• 主题聚类 │• 深度访谈 │• 原型测试   │
│• Twitter │• 优先级   │• 现场观察 │• Beta测试   │
│• 客服工单 │  排序    │• 日记研究 │• A/B测试    │
│• 产品数据 │• 假设生成 │          │             │
│• 销售反馈 │          │          │             │
└──────────┴──────────┴──────────┴─────────────┘
      ↑ 持续运行，不分"调研期"和"开发期"
```

## 特色实践

### 1. "Research Week"制度化

每季度1周，全员参与用户接触：
- 工程师做用户访谈（打破"研究是PM的事"的壁垒）
- 设计师现场观察用户操作
- 每人至少完成2次用户接触

> 收获：工程师亲耳听到"这个功能我一直不会用"比看10次Jira工单有效。[来源:Figma Config | 📚中 | 2023]

### 2. 社区作为"永久焦点小组"

| 实践 | 方法 | 产出 |
|---|---|---|
| FigJam社区反馈 | 社区帖自动标记+聚类 | 需求主题热力图 |
| 插件生态观察 | 哪类插件下载量高=哪类需求未满足 | 发现Figma本身功能缺口 |
| 模板使用数据 | 高频模板=常见工作流=标准化机会 | 新功能方向线索 |
| Twitter舆情 | 设计师在Twitter吐槽Figma | 实时痛点信号 |

### 3. 数据与访谈的交叉验证

```
数据发现：某功能使用率下降15%
  → 假设：用户找到了更好替代方案
  → 访谈验证：5位用户中3位已切换到竞品
  → 深挖原因：竞品在该场景的效率高3倍
  → 产品回应：优化该场景的效率
```

## PM收获

1. **持续研究 ≠ 持续打扰**——关键是建立低摩擦的信号捕获管道
2. **让非PM角色接触用户**——工程师/设计师的亲身体验比二手报告有效10倍
3. **插件/模板生态是隐含需求的"矿脉"**——用户自己做的变通方案=最真实的需求数据

# 3.1 幻觉控制与数据隐私

## 一、AI幻觉（Hallucination）控制

### 1.1 幻觉分类

| 类型 | 说明 | 例子 | 危险度 |
|---|---|---|---|
| **事实幻觉** | 编造不存在的事实 | 引用不存在的论文/虚构API | 高 |
| **数据幻觉** | 编造数字/日期/人名 | 编造统计数据/错误日期 | 高 |
| **引用幻觉** | 编造引用来源 | 给出真实期刊但错误卷期/虚构链接 | 高 |
| **逻辑幻觉** | 推理链路错误 | 看似合理实则跳跃 | 中 |
| **能力幻觉** | 声称能做不能做的 | 声称可联网但实际不能 | 中 |
| **指令幻觉** | 误解用户意图 | 用户要A给了B | 低 |

### 1.2 幻觉根因（详见 D-19.10 LLM固有局限）

- **概率生成本质**——LLM是"预测下一个Token"，非"检索事实"
- **训练数据噪声**——训练数据本身含错误/过时信息
- **知识截止**——训练后新事实不知道，但可能"编"
- **长尾知识薄弱**——低频知识表示弱，易编造
- **上下文冲突**——RAG检索到冲突信息时可能混编

### 1.3 幻觉控制方法（PM可落地）

| 方法 | 原理 | 适用 | 局限 |
|---|---|---|---|
| **RAG检索溯源** | 让AI基于检索到的真实文档回答 | 知识类问答 | 检索不准仍编 |
| **引用回溯** | 每句关键事实带可点击引用 | 搜索/研究类 | 增加成本 |
| **置信度标注** | 让AI自评置信度并展示 | 通用 | AI自评不准 |
| **拒答机制** | 不确定时明示"我不知道" | 高风险场景 | 可能过度拒答 |
| **黄金集比对** | 与已验证答案对比 | 高频问答 | 维护成本 |
| **关键事实核查** | 抽样关键事实联网核验 | 通用 | 不全覆盖 |
| **数字/日期/人名专项** | 易错字段专项校验 | 数据类 | 字段识别 |
| **领域专家抽检** | 医疗/法律/金融专家抽检 | 高风险垂类 | 成本高 |
| **LLM-as-Judge幻觉识别** | 强模型识别弱模型幻觉 | 规模化 | 裁判偏好 |
| **宪法AI约束** | 在Prompt/系统层约束不编造 | 通用 | 仍可能绕过 |

### 1.4 幻觉风险分级控制（按场景）

| 场景 | 幻觉率红线 | 主控方法 | 兜底 |
|---|---|---|---|
| 医疗诊断 | <1% | RAG+专家抽检+拒答 | 强制转人工 |
| 法律咨询 | <1% | RAG+引用回溯+人评 | 免责声明+转律师 |
| 金融决策 | <1% | 数据校验+引用回溯 | 转人工+审计日志 |
| 教育答疑 | <5% | RAG+置信度 | 标注"需核实" |
| 创意写作 | 不限 | 不控制（创意本身需要"编"） | - |
| 客服咨询 | <5% | RAG+拒答 | 转人工 |
| 代码生成 | <5% | 编译/测试校验 | IDE报错可见 |
| 通用问答 | <5% | RAG+引用+置信度 | "需核实"标注 |

## 二、数据隐私

### 2.1 AI产品数据隐私四类

| 类型 | 说明 | 风险 |
|---|---|---|
| **训练数据隐私** | 训练模型用的数据含PII | 模型可能"记住"并复述PII |
| **推理数据隐私** | 用户输入含PII | 可能被存储/记忆/泄露 |
| **记忆污染** | 多轮会话记忆跨用户泄露 | A用户信息出现在B用户会话 |
| **日志隐私** | 输入/输出日志含PII | 日志泄露/未脱敏存储 |

### 2.2 隐私保护方法

| 方法 | 说明 | 适用 |
|---|---|---|
| **数据脱敏** | 去PII/去标识化（身份证/手机/邮箱替换） | 训练+推理 |
| **差分隐私** | 加噪声使个体不可识别 | 训练 |
| **数据最小化** | 只收集必要数据 | 全链路 |
| **会话隔离** | 多用户会话不共享记忆 | 推理 |
| **不存储推理数据** | 推理后不存储用户输入 | 推理 |
| **本地化部署** | 数据不出终端 | 高敏感场景 |
| **联邦学习** | 数据不出本地训练模型 | 训练 |
| **遗忘机制** | 用户可要求删除被记忆数据 | 运营 |
| **加密传输/存储** | 端到端加密 | 全链路 |

### 2.3 GDPR数据最小化 vs AI训练冲突

2026欧盟监管实践明确这对核心矛盾 [来源:四川省商务厅 | 🔍高 | 2026-04]：
- **GDPR要求**：数据最小化，只收集完成特定目的所必需的最少个人数据
- **AI训练需要**：大量、有代表性的训练数据才能检测/纠正算法偏见（如信贷评分/招聘要处理敏感人口统计学数据以避免歧视）
- **冲突本质**："少收数据" vs "要多数据才能公平"
- **实务解法**：
  1. 用合成数据/差分隐私替代真实PII
  2. 明确"偏见检测"作为收集敏感数据的合法目的
  3. 数据保护影响评估（DPIA）前置
  4. 最小化原则下做"必要范围内的代表性"

### 2.4 PII泄露率度量（[D-19.05] 交叉）

| 测试方法 | 说明 |
|---|---|
| **PII注入测试** | 上传含身份证/银行卡PDF，看AI是否记忆/复用 |
| **记忆提取攻击** | 用特定Prompt诱导模型复述训练数据 |
| **跨会话隔离测试** | A用户数据是否出现在B会话 |
| **日志审查** | 抽查日志是否含未脱敏PII |

> 2026实测发现：上传含身份证号/银行卡PDF后，部分模型会将其用于后续回答或记忆，是隐私泄露高风险点 [来源:什么值得买模型实测 | 📚中 | 2026-06]

## 三、隐私合规红线（PM自查）

- [ ] 训练数据是否完成脱敏/DPIA？
- [ ] 推理数据是否默认不存储/不记忆PII？
- [ ] 多用户会话是否严格隔离？
- [ ] 日志是否脱敏后存储？
- [ ] 是否提供用户遗忘/删除机制？
- [ ] 跨境数据是否满足数据出境合规？
- [ ] 高敏感场景是否本地化/联邦学习？
- [ ] 是否有PII泄露率监控？

## 四、幻觉与隐私交叉风险

| 交叉风险 | 表现 | 应对 |
|---|---|---|
| 幻觉泄露隐私 | AI编造"真实"个人隐私（如虚构某真人信息） | 事实核查+PII过滤 |
| 记忆泄露触发幻觉 | 记忆A用户数据后在B会话"复述" | 会话隔离+遗忘机制 |
| RAG检索泄露 | RAG检索到他人隐私文档并回答 | RAG权限隔离+文档级访问控制 |
| 越狱诱导泄露隐私 | 越狱诱导AI复述训练数据PII | 越狱防护+记忆提取测试 |

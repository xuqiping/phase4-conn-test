# D-19.12 多模态产品设计 — 知识库引用场景

> 本叶子是 D-19 大模型PM专项的"多模态产品视角"补充。前面叶子主要建立在"文本LLM"假设上；本叶子在"文本+图像+音频+视频+3D+传感器"六模态产品场景下，给PM一张何时进入本叶子、如何将本叶子方法论应用到自己产品的"地图"。

## 一、10个PM应用场景（每个场景对应本叶子的哪个方法）

### 场景1：智能客服升级——从"只能聊天"到"看得见用户的截图"
- **场景描述**：用户在电商反馈"商品有问题"，传统LLM客服只能问"什么问题"，多模态客服可以让用户发图+视频直接定位
- **引用本叶子**：选 Linear/Q-Former 接开源VLM做MVP → 模态缺失降级（无图时退化为纯文本对话） → 跨模态对齐（图文必须严格关联）
- **避坑**：不要直接上原生多模态大模型（GPT-5.6 API贵），先用 Qwen-VL 验证场景

### 场景2：医疗影像辅助诊断——AI看CT+病历+主诉
- **场景描述**：医疗Agent需要理解CT影像（图像）+病历（文本）+主诉语音（音频）做辅助诊断
- **引用本叶子**：原生多模态（能力上限）+ 语义锚点（影像阴影必须严格关联到病灶描述而非无关文本）*[来源:腾讯云多模态RAG幻觉调查·医疗Agent阴影误关联案例 \| 🔍高 \| 2026-07-15]*
- **避坑**：医疗场景幻觉代价巨大，必须人审+多源交叉验证，AI仅做辅助建议

### 场景3：电商品类搜索——文搜图、图搜图、文+图混合搜索
- **场景描述**：用户在淘宝/拼多多搜"杨幂同款风衣"（文搜图）/上传截图找同款（图搜图）/上传截图+"我要黑色长款"（混合搜索）
- **引用本叶子**：CLIP双塔架构（Fine-Grained CLIP解决词袋效应）*[来源:360 Fine-Grained VLM \| 🔍高 \| 2026-07]* + 跨模态检索的语义对齐 + 模态缺失降级（图查图场景无文本输入时仍要工作）

### 场景4：教育AI辅导——拍题讲解、看图解题、看视频学
- **场景描述**：学生拍数学题（图）→ AI识别题型+解题+讲解（文+图+语音）；看物理实验视频（视频）→ AI讲解+做互动练习
- **引用本叶子**：图+文混合RAG（题库+解析库）+ 多模态RAG幻觉对冲（公式识别易错）+ 语音输出（讲解）+ 时序对齐（视频讲解与视频帧同步）

### 场景5：工业质检——传感器+图像+声音联合检测
- **场景描述**：工厂质检AI需要同时看产品图像+听设备声音+读传感器（IMU/温度）做综合判断
- **引用本叶子**：原生多模态+时序对齐（图像30fps/语音16kHz/IMU 1kHz时间尺度差10^6）*[来源:腾讯云多模态测试方案 \| 🔍高 \| 2026-06-08]* + 模态缺失降级（某传感器故障时仍要兜底质检）
- **避坑**：工业场景时序对齐失守是隐藏大坑，必须用世界模型做物理一致性推理（如智源Emu3.5）*[来源:智源研究院Emu3.5多模态世界模型 \| 🔍高 \| 2025]*

### 场景6：数字人主播——文+音+视同步生成
- **场景描述**：电商数字人主播根据脚本（文本）→ 生成口播语音+口型同步视频+表情动作
- **引用本叶子**：跨模态生成型产品 + 时序对齐（口型与音频帧级同步） + 多模态合规（声音克隆必须获授权，参D-19.11反例5 AI孙燕姿）
- **代表产品**：Soul SoulX 实时数字人（情绪感知+多模态交互大模型）*[来源:百家号Soul WAIC 2026报道 \| 🔍高 \| 2026-07-17]*

### 场景7：跨模态内容创作——一句话生成完整短视频
- **场景描述**：用户输入"做一个介绍夏威夷旅游的60秒短视频"→ AI生成脚本+配音+配乐+视频画面+字幕
- **引用本叶子**：多模态生成型（视频）+ 时序一致性（画面+音轨+字幕同步）+ 多模态评测（如何评一段视频质量？参3.3）+ 成本控制（视频生成token是文本的100倍，参D-19.09）
- **代表产品**：阿里Wan2.7（已用于《羞羞的铁拳》漫剧制作）*[来源:百度百科视频生成大模型 \| 🔍高 \| 2026-07-18]*

### 场景8：多模态知识库——企业知识库统一管理图文音视频
- **场景描述**：企业知识库要同时索引设备图纸（图）+操作手册（文）+维修录音（音）+培训视频（视频）+传感器日志（结构化），并支持跨模态检索问答
- **引用本叶子**：多模态RAG（多模态分块+跨模态嵌入+多模态重排）+ 模态缺失降级 + 语义锚点（多模态幻觉率40%+，必须约束） *[来源:腾讯云多模态RAG 5段代码构建可信管道 \| 🔍高 \| 2026-07-15]*
- **避坑**：2026-07实测多模态RAG在复杂图表+跨页表格任务上幻觉率仍超40%，是企业知识库PM的最大痛点

### 场景9：具身智能机器人——AI从"说话"到"动手"
- **场景描述**：具身智能机器人需要理解人类指令（文+音）+感知环境（视+3D+传感器）+规划动作（输出动作序列）
- **引用本叶子**：具身多模态型产品（六大形态表第6类）+ 世界模型基座 + VLA（Vision-Language-Action）模型
- **代表产品**：Figure 02 + OpenAI VLA / 特斯拉Optimus二代 / 字节Seedrence / 智元机器人 / 海康观澜体系（"一句话切换干活模式"）*[来源:WAIC 2026海康观澜报道 \| 🔍高 \| 2026-07-17]*
- **WAIC 2026案例**：智慧药店3台不同厂牌机器人共用"一个脑子"；6台机器人协作15小时拼乐高长城 *[来源:上观新闻WAIC \| 🔍高 \| 2026-07-17]*

### 场景10：自动驾驶感知——视觉+激光雷达+毫米波+GPS融合
- **场景描述**：自动驾驶感知系统同步处理多相机视频+激光雷达点云+毫米波雷达+GPS+IMU做环境理解与决策
- **引用本叶子**：原生多模态+强时序对齐+模态冗余设计（任一模态故障时其他模态兜底）+世界模型基座（智源Emu3.5、昆仑万维Matrix-3.5）*[来源:昆仑万维"状态-动作联合生成"世界模型 \| 🔍高 \| 2026-07-03]*

## 二、8个PM决策问句（"我该不该用本叶子的方法论"）

| 决策问句 | 是→用本叶子 |
|---|---|
| 1. 我的产品输入信息可能包含文本以外的模态（图/音/视频/传感器）吗？ | 是 → 进入本叶子 |
| 2. 我的产品输出可能涉及跨模态生成（文生图/图生视频/图生音）吗？ | 是 → 进入本叶子 |
| 3. 我需要在多个模态之间做语义对齐（如把图像中的物体与文本中的描述关联）吗？ | 是 → 进入本叶子 3.2 |
| 4. 我的产品同时支持多模态输入但模态可能缺失（用户只输入部分）吗？ | 是 → 进入本叶子 原则4 |
| 5. 我需要做多模态时序对齐（多模态事件必须在时间维度上同步）吗？ | 是 → 进入本叶子 原则5 + 3.2 |
| 6. 我需要评测多模态效果（传统文本指标不适用）吗？ | 是 → 进入本叶子 3.3 |
| 7. 我的产品涉及具身智能/物理AI/世界模型吗？ | 是 → 进入本叶子 形态第6类 |
| 8. 我的token成本可能是纯文本产品的5倍以上且需要多模态成本优化吗？ | 是 → 进入本叶子 原则6 + 配合D-19.09 |

## 四、PM边界声明

本叶子**不**展开：
1. **AI体验设计共通范式**（容错/加载/等待/信任）—— 参 D-19.04
2. **AI合规法规本体**（AIGC标识三轨制/未成年人保护/数据出境）—— 参 D-19.11
3. **RAG分块/嵌入/重排本体**—— 参 D-19.08
4. **LLM幻觉对冲六层框架**—— 参 D-19.10
5. **Token优化本体**（缓存/路由/降本八段战术）—— 参 D-19.09
6. **Agent深化**（多Agent协作/工具调用/MCP协议）—— D-24 B13批次

本叶子**专注于**：
1. 多模态产品的连接架构选型与方法论
2. 跨模态对齐与时序对齐的特殊设计
3. 多模态RAG的幻觉风暴对冲（语义锚点）
4. 多模态评测体系（与传统文本评测的差异）
5. 多模态生成型产品（视频/音频/数字人/具身）的设计要点
6. 多模态产品的成本与合规特殊性

## 五、何时不要进入本叶子

如果你的产品是**纯文本LLM产品**（如纯对话助手、纯代码生成、纯文档总结），不需要进入本叶子——前面 D-19.01~D-19.11 的方法论已足够。

进入本叶子的**触发条件**：你的产品必须涉及至少一种非文本模态（图像/音频/视频/3D/传感器/动作）的输入理解或输出生成。

# File Keeper 新增业务模块实施指导

> 本文件是 `2_新增业务模块规范.md` 的**实操版**，结合当前桌面端代码结构（`file-keeper/src/` + `file-keeper/src-tauri/src/`）和管理后台/服务端现状，给出一个可落地的“新增模块”执行手册。
>
> 阅读顺序：先读 `2_新增业务模块规范.md` → 再读本文件 → 按需查阅 `项目相关文档/桌面端总结/` 中的模块总结。

---

## 一、新增模块前必须明确的 5 件事

1. **模块代号（moduleCode）** 是什么？
   - 全小写英文，单数名词，多单词用 `-` 连接，≤32 字符。
   - 禁止与 `files`、`processes`、`clipboard` 重复或语义冲突。
2. **是否进入商业授权体系？**
   - 凡需要按账号/设备/时间售卖的功能，必须走完整授权链路。
   - 纯本地辅助工具（如主题切换、快捷键设置）可不走授权，但需评估是否会被绕过。
3. **是否支持匿名用户？**
   - 支持 → 必须考虑 7 天试用后是否作为“免费模块”候选。
   - 不支持 → 桌面端未登录时直接隐藏入口或显示未授权。
4. **是否涉及敏感本地能力？**
   - 涉及进程结束、截图、剪贴板监听、文件系统写操作等 → Rust 侧必须二次校验。
5. **是否需要管理后台配置？**
   - 模块授权开关/到期时间、全局默认配置、Dashboard 统计，分别对应不同后端/前端改动点。

## 二、新增模块总体顺序

```
1. 注册 moduleCode（Java 常量 + 前后端映射）
2. 服务端：DB 迁移（如需要）→ 授权接入 → 业务 API → Admin API → 测试
3. 管理后台：授权编辑 → 设置/Dashboard（如需要）→ 测试
4. 桌面端前端：App.vue Tab → API → Store → 组件 → 状态展示 → 测试
5. 桌面端 Rust：命令 → 平台实现 → 二次校验 → 注册 invoke → 测试
6. 文档：更新本指导、规范、项目结构说明、联调计划
```

禁止反向操作：先写桌面端 UI 再补授权，会导致安全缺口。

## 三、Step 0：注册 moduleCode

### 3.1 后端常量注册

修改 `file-keeper/server/src/main/java/com/superprogrammer/security/AuthConstants.java`：

```java
public static final String MODULE_FILES = "files";
public static final String MODULE_PROCESSES = "processes";
public static final String MODULE_CLIPBOARD = "clipboard";

// 新增
public static final String MODULE_SMART_TAGS = "smart-tags";
```

### 3.2 授权服务白名单

修改 `file-keeper/server/src/main/java/com/superprogrammer/authorization/service/AuthorizationService.java`：

```java
private static final List<String> MODULE_CODES = List.of(
        AuthConstants.MODULE_FILES,
        AuthConstants.MODULE_PROCESSES,
        AuthConstants.MODULE_CLIPBOARD,
        AuthConstants.MODULE_SMART_TAGS   // 新增
);
```

> 只要加入该列表，`authenticatedSnapshot()` 会自动把授权结果写入离线 Token，无需额外修改签名逻辑。

### 3.3 数据库 CHECK 约束

如果已有/新建表包含 `module_code` 字段，必须同步 CHECK 约束：

```sql
CONSTRAINT ck_user_module_entitlements_module CHECK (
    module_code IN ('files', 'processes', 'clipboard', 'smart-tags')
)
```

如果 `anonymous_device_trials.free_module_code` 也加了 CHECK，同样需要追加。

### 3.4 前端 moduleCode → 中文名映射

## 四、Step 1：服务端实施

### 4.1 数据表（如需要）

在 `file-keeper/server/src/main/resources/db/migration/` 新增 Flyway 脚本：

```
V5__add_smart_tags_module.sql
```

内容示例：

```sql
-- 扩展 module_code CHECK 约束（PostgreSQL 需先删除再重建）
ALTER TABLE user_module_entitlements
    DROP CONSTRAINT ck_user_module_entitlements_module;

ALTER TABLE user_module_entitlements
    ADD CONSTRAINT ck_user_module_entitlements_module
        CHECK (module_code IN ('files', 'processes', 'clipboard', 'smart-tags'));

-- 新增业务表
CREATE TABLE smart_tags (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users(id),
    tag_name VARCHAR(64) NOT NULL,
    rule_type VARCHAR(32) NOT NULL,
    rule_value VARCHAR(512),
    created_by VARCHAR(64),
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    updated_by VARCHAR(64),
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT NOW(),
    deleted BOOLEAN NOT NULL DEFAULT FALSE
);
```

注意事项：

- 必须兼容 PostgreSQL 和 H2（测试库）。
- 字段类型变更用 `ALTER COLUMN ... SET DATA TYPE`。
- 业务表必须包含 `created_by/created_at/updated_by/updated_at/deleted`。
- 实体类继承 `com.superprogrammer.common.BaseEntity`。

### 4.2 客户端接口授权校验

新增 Controller 示例：`SmartTagController.java`：

```java
@RestController
@RequestMapping("/api/client/smart-tags")
@RequiredArgsConstructor
public class SmartTagController {

    private final AuthorizationService authorizationService;
    private final SmartTagService smartTagService;

    @GetMapping
    public R<List<SmartTagDto>> list(Authentication auth, @RequestParam String deviceId) {
        AuthPrincipal principal = (AuthPrincipal) auth.getPrincipal();
        AuthorizationSnapshot snapshot = authorizationService.authenticatedSnapshot(
            principal.userId(), deviceId, System.currentTimeMillis()
        );
        boolean allowed = snapshot.modules().stream()
            .anyMatch(m -> AuthConstants.MODULE_SMART_TAGS.equals(m.moduleCode()) && m.allowed());
        if (!allowed) {
            return R.fail(ErrorCode.FORBIDDEN, "未授权访问智能标签模块");
        }
        return R.ok(smartTagService.listByUserId(principal.userId()));
    }
}
```

### 4.3 匿名用户访问控制

如果匿名用户也能试用新模块，修改 `AnonymousTrialService.anonymousModules()` 逻辑（或确认当前 `AuthorizationService.anonymousModules()` 已自动对全量 `MODULE_CODES` 生效）：

- 试用期内：所有 `MODULE_CODES` 默认允许。
- 试用期后：只允许 `freeModuleCode` 对应的模块。
- 若希望新模块成为免费候选，必须同步修改前端 `FreeModuleSelector.vue`。

### 4.4 管理后台 API

在 `AdminEntitlementController`（或新建 `AdminSmartTagController`）中提供管理端接口：

- 使用 `@RequirePermission("smart_tag:manage")` 或 `hasRole("SUPER_ADMIN")` 保护。
- 高风险操作记录审计日志 `admin_audit_logs`。

### 4.5 测试

必须新增：

- `SmartTagControllerTest`：未授权返回 403，授权后返回数据。
- `AuthorizationServiceTest`：新模块 `allowed`/`denied` 分支。
- 离线 Token 测试：验证新模块在离线 Token 中存在。

### 6.2 新增 API 层

创建 `file-keeper/src/api/smartTags.ts`：

```ts
import { fetchR } from './commercialAuth' // 或统一封装 request
import type { SmartTag } from '@/types/smartTag'

export async function listSmartTags(baseUrl: string, accessToken: string): Promise<SmartTag[]> {
  const res = await fetch(`${baseUrl}/api/client/smart-tags`, {
    headers: { Authorization: `Bearer ${accessToken}` }
  })
  const data = await res.json()
  if (data.code !== 200) throw new Error(data.msg || '获取智能标签失败')
  return data.data
}
```

### 6.3 新增 Store

创建 `file-keeper/src/stores/smartTagStore.ts`：

```ts
import { defineStore } from 'pinia'
import { ref } from 'vue'
import { listSmartTags } from '@/api/smartTags'
import { useAuthStore } from './authStore'
import type { SmartTag } from '@/types/smartTag'

export const useSmartTagStore = defineStore('smart-tags', () => {
  const tags = ref<SmartTag[]>([])
  const loading = ref(false)
  const error = ref<string | null>(null)

  async function loadTags(baseUrl: string) {
    const authStore = useAuthStore()
    if (!authStore.accessToken) return
    loading.value = true
    error.value = null
    try {
      tags.value = await listSmartTags(baseUrl, authStore.accessToken)
    } catch (e) {
      error.value = e instanceof Error ? e.message : String(e)
    } finally {
      loading.value = false
    }
  }

  return { tags, loading, error, loadTags }
})
```

## 十一、常见错误与避免方法

| 错误 | 后果 | 避免方法 |
|------|------|----------|
| 只在前端隐藏入口，未做后端校验 | 直接调用 API 即可绕过授权 | 每个客户端接口都必须走 `AuthorizationService` |
| 新增模块未加入 `MODULE_CODES` | 离线 Token 不包含该模块，离线时无法使用 | 修改 `AuthorizationService.java` |
| CHECK 约束未更新 | 数据库插入新模块授权时报约束错误 | Flyway 同步更新 CHECK |
| `FreeModuleSelector.vue` 未追加选项 | 匿名过期后无法选择新模块作为免费模块 | 同步更新模块数组 |
| Rust 敏感命令未二次校验 | 前端被绕过即可执行危险操作 | 关键命令头部校验 `offline_token_state` |
| 业务表缺少 `deleted` 字段 | 无法逻辑删除，违反项目约定 | 继承 `BaseEntity` 或手动补齐字段 |
| 未写测试直接合并 | 回归风险高 | 按 7.3 节命令全部跑通 |

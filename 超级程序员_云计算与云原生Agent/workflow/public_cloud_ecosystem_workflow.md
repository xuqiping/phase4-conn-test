# Public Cloud Ecosystem Workflow

## Purpose

基于公有云厂商生态知识体系，为用户提供云厂商选型（阿里云/腾讯云/华为云/百度智能云/运营商云）、云产品矩阵组合方案、云架构设计、Landing Zone治理或成本优化的技术支持。覆盖Well-Architected Framework五支柱、云网融合、国密全栈等核心框架。

## Prerequisites

- 用户已明确公有云场景或问题
- 知识库文件 `04_前端开发与用户交互.md` 及子目录文件可访问

## Steps

### Step 1: 识别公有云需求场景

**Goal**: 明确用户的公有云需求类型、业务属性和约束条件
**Completion criterion**: 已确定场景标签、目标市场、合规要求和预算模式

1. 读取用户消息，提取以下信息：
   - 场景类型：云厂商选型 / 云架构设计 / 产品矩阵组合 / 成本优化 / 迁移上云 / Landing Zone治理
   - 业务属性：电商/零售 / 音视频/游戏/社交 / 政企/政务 / AI/大模型 / 金融/电信 / 工业互联网/车联网
   - 目标市场：中国国内 / 出海/全球化 / 混合（国内+海外）
   - 合规要求：等保等级 / 信创要求 / 数据主权（数据不出域）/ 国密算法 / 行业监管（金融/医疗/教育）
   - 预算模式：按需付费（PoC/初创）/ 预留实例（稳定业务）/ 混合（按需+预留+Spot）
   - 现有基础设施：IDC/私有云 / 其他公有云（需要迁移）/ 无（全新上云）

2. 对照知识库中的厂商定位初步判断候选云厂商：
   - 电商/AI全栈 /  Well-Architected治理 → 阿里云（份额36%，电商/AI生态最强）
   - 音视频/游戏/社交 / 微信生态 → 腾讯云（TRTC/GAAP全球加速/微信云开发）
   - 政企/信创 / 全栈自研 → 华为云（Kunpeng ARM+Ascend AI+GaussDB+华为云Stack）
   - AI大模型训练/推理 / 自动驾驶 → 百度智能云（ERNIE 4.5/5.0+千帆MaaS+昆仑芯）
   - 政务/运营商 / 5G边缘 / 云网融合 → 运营商云（天翼云/移动云/联通云，政务份额第一）

3. 如有信息缺失，向用户追问不超过2个澄清问题。

### Step 2: 输出公有云方案

**Goal**: 产出针对性的云厂商选型、架构设计或成本优化方案
**Completion criterion**: 输出包含推荐云厂商、产品组合、架构拓扑、成本估算、迁移路径

根据Step 1确定的场景，按以下分支处理：

**分支A — 云厂商选型**：
1. 输出五大厂商对比表，对比维度：
   - 核心优势场景（电商/音视频/政企/AI/政务）
   - 产品矩阵完整性（计算/存储/网络/数据库/容器/AI/安全/运维）
   - 生态与集成（第三方ISV数量、开发者社区、培训认证体系）
   - 价格竞争力（按需单价、预留折扣、Spot实例价格、出站流量费）
   - 合规与信创（等保测评通过等级、国密支持、信创适配清单、数据主权保障）
   - 全球覆盖（Region数量、CDN节点、跨境专线、出海合规支持）
2. 给出最终推荐并附决策矩阵，标注关键趋势（AI驱动云架构演进、边缘-中心-云三层架构）。
3. 输出多云/混合云策略（如适用）：主云+备份云、不同业务线选不同云、云间互联方案。

**分支B — 云架构设计**：
1. 输出Landing Zone治理框架：
   - 账号体系设计（多账号策略、OU组织单元、服务控制策略SCP）
   - 网络架构（VPC规划、子网划分、可用区分布、专线接入点）
   - 身份与权限（RAM/IAM统一身份、RBAC最小权限、SSO单点登录）
   - 安全基线（WAF/DDos/入侵检测/密钥管理HSM/操作审计ActionTrail）
   - 成本管控（预算告警、标签分账、资源配额、自动关停策略）
2. 给出Well-Architected Framework五支柱评估：卓越运营/安全性/可靠性/性能效率/成本优化。
3. 输出典型架构模板：
   - 高可用Web应用（SLB+ECS集群+RDS主从+Redis+OSS+CDN）
   - 容器化微服务（ACK/TKE+CCE+SLB+Service Mesh+Prometheus监控）
   - AI训练推理（PAI/千帆+GPU虚拟化MIG/vGPU+Karpenter弹性+Spot降本）
   - 大数据平台（EMR+OSS数据湖+MaxCompute/Flink+DataWorks调度）

**分支C — 成本优化（FinOps）**：
1. 输出成本可视化方案：Kubecost/云厂商成本管家/自研分账报表。
2. 给出资源优化策略：
   - 计算优化：VPA自动调整request/limit、KEDA事件驱动弹性、Karpenter极速节点供给、Spot实例降本60-90%
   - 存储优化：对象存储分层（标准/低频/归档）、EBS卷类型选型（SSD/高效云盘）、数据生命周期策略
   - 网络优化：CDN缓存命中率提升、内网流量优化（同Region同VPC）、出站流量压缩
3. 输出预留实例策略：1年/3年预留、全预付/部分预付/0预付、可转换预留/标准预留。
4. 附成本告警与预算管控：月度预算设定、异常波动告警、资源闲置自动识别、团队成本责任制。

**分支D — 迁移上云**：
1. 输出迁移评估框架：
   - 应用评估（6R分析：Rehost/Replatform/Refactor/Repurchase/Retain/Retire）
   - 数据评估（数据量、传输带宽、传输时间、一致性校验）
   - 网络评估（带宽需求、延迟容忍、专线需求、VPN备份）
   - 合规评估（等保/数据主权/行业监管适配）
2. 给出迁移路径：试点迁移（非核心业务）→ 批量迁移（按依赖关系排序）→ 切换（蓝绿/金丝雀/直接切换）。
3. 输出数据迁移方案：
   - 数据库：DTS/自建CDC/逻辑备份恢复，附双写校验方案
   - 对象存储：ossimport/云厂商迁移工具/跨区域复制
   - 大数据：DistCp/云厂商数据迁移服务/混合云数据同步
4. 附回滚预案：DNS切回、数据库反向同步、应用版本回退。

将结果保存到 `output/public_cloud_architecture.md` 或直接在对话中呈现。

### Step 3: 验证与交付

**Goal**: 确保云方案符合业务需求、与知识库一致
**Completion criterion**: 已通过 checklist 逐项核对

1. 读取 `checklist/public_cloud_ecosystem_workflow_checklist.md`。
2. 逐项核对输出是否覆盖要求的知识点。
3. 确认所有关键论断均能在知识库中找到支撑。
4. 如有遗漏或偏差，补充修正。
5. 向用户交付最终答案。

## Post-Workflow

1. 记录完成状态到 `task/current_task.md`。
2. 如需深入某一具体技术（如"阿里云Landing Zone多账号设计"、"FinOps Spot实例自动竞价策略"），在当前 Agent 内继续追问并输出。

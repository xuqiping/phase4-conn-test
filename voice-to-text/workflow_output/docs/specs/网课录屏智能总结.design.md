## 一、背景与目标

### 1.1 产品定位（一句话）

**本地优先的网课学习加速器**：录制网课（窗口/区域）→ 本地实时转写 → 录后智能抽帧 + 音字帧对齐 → 云端 AI 生成多形态课程总结（时间轴 / 思维导图 / Anki / Markdown）。核心杀手锏是让 **"课件画面"** 与 **"老师讲解"** 逐段对齐，而非仅做字幕摘要。

### 1.2 业务目标与成功指标

- **目标**：把"看 2h 网课 → 产出可复习结构化笔记"的时间从手工 1–2h 压缩到 10 分钟内（含核对）。
- **成功指标**（知识库 D-19·AI 体验指标）：
  - 总结**采纳率** > 60%（用户保留/导出了 AI 总结）
  - **重写率** < 30%（用户大面积删改的比例）
  - **任务完成率**：从录制到产出导出文件的漏斗完成率 > 70%
  - 性能：2h 课程录后处理 P95 < 8 分钟；总结单段 API 延迟 P95 < 15s

### 1.3 差异化（竞品调研结论）

| 维度 | 通义听悟 / tl;dv | BibiGPT / Monica 等 | **本项目** |
|---|---|---|---|
| 课件画面进模型 | 仅云端浅抽 PPT / slide capture | ❌ 100% 只用字幕 | ✅ 课件帧 OCR 与转写**逐段对齐** |
| 本地/离线 | ❌ 全云端 | ❌ 全云端 | ✅ 转写+抽帧+OCR 全本地 |
| 学习结构化"三件套" | 部分 | 弱 | ✅ 时间戳章节 + 关键帧 + Anki/导图 |

> 30+ 竞品中，C 端视频总结工具 100% 只处理字幕、丢弃课件信息；能做到"课件帧↔文字对齐"且本地优先的全球无重叠竞品。这是护城河。

## 二、用户与场景

### 2.1 目标用户

网课学习者（自学者、考研/考证/技能课用户）：单节课 1–2h，需要把视频消化成可复习的结构化笔记。

### 2.2 核心用户旅程

```
打开应用 → 选窗口/框选课件区域 → 点开始录制
  → 边听课边看到实时字幕（即时反馈）
  → 停止录制 → 自动进入处理（阶段化进度，可取消）
  → 生成"时间轴章节 + 要点 + 课件帧"
  → 核对/局部编辑/重新生成 → 导出（MD/导图/Anki）→ 可选删原视频
```

### 2.3 典型场景

- **S1 主场景**：浏览器/客户端看网课，录窗口，2h，产出时间轴+MD 笔记导入 Obsidian。
- **S2 精修场景**：图表密集课（如几何/医学），开启多模态精修开关，让 VLM 看课件图提升总结质量。
- **S3 复习场景**：导出 Anki 卡片，间隔复习应试点。

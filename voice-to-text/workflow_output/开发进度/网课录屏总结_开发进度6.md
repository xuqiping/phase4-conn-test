## 🐛 回归缺陷修复（2026-08-08，`f32bc48`）

- **现象**：用户点「区域框选」弹出全屏**白色**置顶窗，点击无效、无法关闭（无标题栏+藏任务栏+置顶全屏，被困死）。
- **根因（规格内缺陷，AC-112 实现翻车）**：三合一问题 —— ① `fullscreen+transparent` 组合在 Windows 上可能渲染成不透明白窗；② `skip_taskbar` + 无标题栏 + 置顶 = 渲染失败时零关闭出口；③ URL hash（`#/region-select`）分流存在被吞风险，吞了就渲染错内容。
- **修复**：fullscreen → `maximized`；去掉 `skip_taskbar`（任务栏/Alt+F4 永远可关窗）；分流改为窗口 label 判定（`getCurrentWindow().label === 'region-select'`），overlay URL 回归纯 `index.html`。
- **教训（已写入代码注释）**：**破坏性/全屏类窗口必须留无条件关闭出口**——藏任务栏、去标题栏、置顶三件套绝不能同时上。
- **待复测**：点区域框选 → 半透明遮罩（看得见底下的屏幕）+ 顶部提示条；拖框出蓝框；Esc/取消可关；确定后回主窗口显示「区域 WxH」。

## 🐛 回归缺陷修复 2：弃二窗改单窗口（2026-08-08 下午，3 次实测复现后换方案）

- **现象**：`maximized` 修复后仍是**纯白置顶窗**（用户实测 3 次 + 开发截图复现 3 次，透明/不透明/全屏/最大化全同症）。

- **修复（单窗口方案）**：

## 🐛 回归缺陷修复 3：确定按钮点击变新框选起点 + 目标窗口未置顶（2026-08-08 晚）

- **现象1**：框选后点「确定」无效，点击位置反而变成新框选起点。

- **现象2**：已选录制窗口后点框选，截图里看不到目标窗口（被其他窗口压在下面）。

## 🐛 回归缺陷修复 4：框选后窗口选项被重置 → 窗口+区域共存（2026-08-08 晚）

- **现象**：框选确定后，「选择要录制的窗口」下拉被清空，用户感觉是 bug。
- **根因**：初版实现把窗口/区域做成**互斥**（框选成功就清 selectedHwnd）；但用户心智 =「在选中的窗口里框一块」，两者应共存。
- **修复（语义升级，AC-112 已同步改写）**：
  - 共存：两个都选 = **录该窗口再按区域裁剪**（`ScreenCapture::start_window_region`——WGC 录窗口即使被遮挡也录得到内容，比录屏幕区域稳）；只框不选窗 = 录主屏该区域（原 `start_region`）；换窗口清空已框区域需重框（框是按旧窗口画面框的，坐标无意义）。
  - 坐标换算：框选矩形是主屏物理像素 → `screen_rect_to_window` 与 `GetWindowRect` 求交集转窗口相对坐标（**先判交集再转 u32**，负数回绕坑已排）；GetWindowRect 含 Win10 隐形边框 ±7px，框课程画面够用。
  - 已知限制（写进代码注释）：框选后挪动窗口，裁剪按录制开始时的窗口位置重算，可能错位 —— 框选完别挪窗口。
  - UI：两个都选时框选按钮旁显示「窗口内框选」提示（hover 解释遮挡不影响录制）。
- **测试**：+1 单测 `screen_rect_to_window_converts_and_clamps`（内/外/半交集/取偶 5 例）；74 绿；`check_all` 全绿。
- **待复测**：选窗口+框选 → 录制 → 切片只含窗口内框选区域；录制中用别的窗口遮挡课程窗口，切片画面不串；只框不选窗的纯区域录制回归。

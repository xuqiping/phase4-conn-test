# Phase 0 · 商业前置分析

> 类型：流程步骤 · **Phase 0**（主链起点）
> 版本：v1.0
> 定位：这是本工作流**区别于纯 SDD 的独特层**——SDD 默认「项目值得做」，直接从规格开始；这一层先回答「值不值得做」。

## 目标

在写一行规格或代码之前，先用一份深度报告想清楚：这个东西**做给谁、凭什么赢、怎么赚钱**。避免埋头做出一个商业上站不住的产品。

## 输入

- 一个项目想法（哪怕只有一句话）

## 动作清单（按顺序）

1. **需求分析**：要解决什么问题？核心场景是什么？最小可用范围在哪？
2. **联网分析竞品对比**：全球已有谁在做？它们强弱在哪？差异化空间在哪？（需联网能力）
3. **分析受众群体**：谁会用？画像、痛点、付费意愿、获客渠道。
4. **提升优化思路**：基于前三步，把原始想法迭代得更锐利。
5. **商业模式分析**：变现路径、推广渠道、定价方案与依据（参考行业行情）。
6. **技术选型**：基于以上，定技术栈（要能支撑商业模式，而非反过来）。
7. **定基调与总体规范的初版**：把跨模块通用的约定（如中英双语、商业版授权体系、统一鉴权）写进 `workflow_output/项目规范约束/AGENTS.md` 初稿——这些是后续所有模块的地基。

## 产物

- `workflow_output/docs/项目分析/项目分析报告.md` —— **深度报告式**，覆盖上面 1–5（商业模式到定价为止）。这是 Phase 0 的核心交付。
- 技术选型结论 → 进报告 + Phase 1 的 architecture。
- `workflow_output/项目规范约束/AGENTS.md` 初版 —— 项目级 AI 指令，后续 Phase 3 持续织入。
- 拷贝 **项目模板/** 起好新项目骨架。

## 配套

- 新项目骨架 → [项目模板/](项目模板/)（拷贝即用）
- 报告骨架 → `项目模板/workflow_output/docs/项目分析/`（若无，参照 Phase 0 结构自建）
- AGENTS.md 骨架 → `项目模板/workflow_output/项目规范约束/AGENTS.md`

## 避坑点

- **不要跳过商业分析直接写码**。一个人公司最大的浪费不是写错代码，是做出没人要的东西。
- 技术选型要服从商业模式，不是反过来（「我想用 Rust」≠ 商业需要 Rust）。
- 总体规范一旦定下，后续模块必须基于它开发（如做了商业授权前后端，后续模块都要走授权规范）。

## 出口条件（满足才进 Phase 1）

- [ ] 项目分析报告完成，且你自己读一遍后**仍然认为值得做**。
- [ ] 技术选型已定，总体规范初版（AGENTS.md）已建。
- [ ] 项目骨架已拷贝，目录就绪。

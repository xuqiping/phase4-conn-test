## 表与 SQL 注解（Flyway）

### `V131__kb_answer_model_and_confidential.sql`（本功能唯一迁移）

```sql
-- answer_model：per-KB 问答模型（仅问答链路，索引/摘要不走此列；NULL=跟随全局默认）
ALTER TABLE knowledge_bases ADD COLUMN answer_model VARCHAR(128);
COMMENT ON COLUMN knowledge_bases.answer_model IS 'per-KB问答模型：空=跟随全局默认；保存校验须在启用CHAT白名单';
-- confidential：库级保密开关（成员仅可经 RAG 问答召回内容）
ALTER TABLE knowledge_bases ADD COLUMN confidential BOOLEAN NOT NULL DEFAULT FALSE;
COMMENT ON COLUMN knowledge_bases.confidential IS '保密库：成员不可见原件/切片/检索调试，仅问答出口；PUBLIC互斥';
```

**生活比喻**：`knowledge_bases`（知识库表）像图书馆的库房登记册；`answer_model` 是每个库房自选的「讲解员」（不选就用馆里默认的）；`confidential` 是库房门上的「仅限馆内咨询台代查」封条——贴了之后读者只能到咨询台（问答）问，不能进库房翻原件，馆长（OWNER）和馆领导（admin）除外。

### 关键调用链

- **问答模型**：`/ask` 或 chat kbIds → `retrieveGroundedAnswer` → `ensure(kbs[0])` → `resolveAnswerModel`（active 过滤）→ `extractGroundedFacts`/`composeGroundedAnswer` → `LlmRequest.model(m)`（null=不 set=网关全局默认）。
- **保密收紧**：四个旁路（list/get strip、asset、nodes、retrieve 调试）各自接 Guard/strip；问答链路 retrieveEvidence 无 Guard，但产出 citation 带 confidential 标志。
- **标志透传**：per-KB gather 循环登记 `confidentialNodes`（受限库全部候选 nodeId）→ topK ⊆ allPool → citation 构建 `contains(nodeId)` → chat CITATION 帧 → 前端隐藏。

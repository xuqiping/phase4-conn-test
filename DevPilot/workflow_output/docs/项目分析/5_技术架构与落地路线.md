# 5 · 技术架构与落地路线

> 定位：Phase 0 尾的技术选型 + MVP 分期路线；详细 architecture 规格留待 Phase 1。
> 选型原则（继承工作流）：技术服从商业模式——**桌面客户端 + Token 转售**意味着：客户端承载全部体验与执行，云端只做账号/计费/模型转发，越轻越好。
> 版本：v2.0（2026-08-13 按用户定调重写：Web 工作台 → Win/Mac 桌面客户端；订阅 → Token 充值）

## 1. 总体架构

```
┌─ 桌面客户端（Tauri 2：Rust 内核 + Webview 前端）──────────────┐
│  React 19 UI（三栏工作台/管道条/卡片流）                        │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ Rust 内核（本地服务层）                                 │   │
│  │  · 阶段状态机（SQLite 持久化）  · 产物生成器             │   │
│  │  · 任务编排器（chunk→子任务）   · Token 计量器           │   │
│  │  · 本地沙箱执行器              · Skills 引擎            │   │
│  │  · MCP 客户端 + MCP Server    · CLI/深链入口           │   │
│  └──────────────────────────────────────────────────────┘   │
│  执行目标：用户本机项目目录（git + workflow_output/）           │
└──────────────┬───────────────────────────────────────────────┘
               │ HTTPS（仅三件事：鉴权 / Token 计费 / 模型转发）
┌──────────────▼───────────────────────────────────────────────┐
│ 轻量云端（控制面，无算力）                                       │
│  · 账号与鉴权      · Token 余额/扣费/充值（微信+Stripe）         │
│  · 模型网关（多供应商路由/重试/用量归集）  · 技能市场（二期）      │
└──────────────────────────────────────────────────────────────┘
```

**架构要点**：本地执行 + Token 转售的组合让云端**零算力成本**——我们没有 Codex 的容器池账单，云端只是一个「计费+网关」薄层，这是商业模式与架构互相咬合的结果。

## 2. 关键选型

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面框架 | **Tauri 2（Rust + 系统 Webview）** | Win/Mac 一套代码；安装包 ~10MB 级（Electron 的 1/10）；内存占用低；Rust 内核天然承接沙箱/CLI/MCP 等系统能力；本机已有 Rust 编译环境（voice-to-text 项目验证过）。备选 Electron（生态更熟但包体/内存劣势） |
| 前端 | **React 19 + TypeScript + Vite**，Tailwind + Radix 自研设计系统 | 工作台交互重度定制（管道条/卡片流/diff 双栏）；React 生态对 AI 生成质量与招聘最友好 |
| 本地执行沙箱 | 分层策略：**默认目录级权限**（只读写项目目录，越界需批准）；**加强档**：macOS Seatbelt（对齐 Codex CLI）/ Windows Job Object + 受限令牌；命令审批沿用「每步都问 / 自动走关键点叫我」两档 | Codex CLI 已验证 macOS 方案；Windows 无等价物，用作业对象+目录白名单务实落地，Phase 1 安全规格专题细化 |
| Agent 内核 | 自研编排层（Rust）+ **模型路由**：旗舰模型（Claude/GPT 级）跑关键 chunk，国产模型（DeepSeek/Qwen）跑翻译层/摘要/分类等轻任务 | 路由省 token 成本 = 直接扩大转售毛利 |
| 本地数据 | **SQLite**（状态机/任务/产物元数据/Token 账本本地镜像）+ 项目目录内存放 `workflow_output/` 文档 | 与手工版工作流产物同构，用户可直接用 git 管理，也可脱离客户端被其他工具读取（开放性卖点） |
| 存档点 | Git commit + 项目目录快照；数据库类项目附加数据快照 | 对齐 Replit「一体回滚」体验，回滚免费 |
| Skills 引擎 | 对齐 Claude Skills 规范（YAML 头 + 提示词 + 资源目录），存 `~/.devpilot/skills/`，支持生成/调用/导入导出 | 与 Claude 生态互通，技能可跨工具复用 |
| MCP | **客户端**（图形化市场安装外部 MCP server）+ **Server**（DevPilot 暴露任务委派接口，别的应用经 MCP 调我们） | MCP 已是跨厂商标准（D-24.02 结论），双向都吃 |
| CLI / 深链 | 安装时注册 `devpilot` 命令与 `devpilot://` 系统协议；CLI 输出 JSON 便于脚本集成 | 满足「别的应用指令传参接入」的核心要求 |
| 云端后端 | **NestJS（Node）轻服务**：账号/计费/模型网关；PostgreSQL + Redis | 云端极薄，NestJS 生态快；若团队坚持 Java 也可用 Spring Boot，Phase 1 定 |
| 模型网关 | 多供应商接入 + 失败转移 + **按调用方计量**（客户端每次请求带签名，网关按 model+tokens 入账） | 转售模式的技术核心：计量必须服务端权威，防篡改 |
| 支付 | 微信支付 + 支付宝（主），Stripe（海外备选） | 中文市场必备 |

## 3. MVP 分期路线

### 一期（MVP，目标 3–4 个月）——「桌面端走通一个真实项目」

- Tauri 桌面客户端（Win+Mac 双端打包/签名/自动更新）
- P0 功能 24 条（见文档 2）：工作流引擎五阶段主链 + 大白话层 + 存档点回滚 + 安全卡点 + **Token 余额仪表盘**
- Skills 生成器（基础版）+ MCP 客户端（图形化市场）
- 云端薄层：账号/充值/模型网关/计量
- 验收标准：一个零代码测试用户在自己的 Windows 或 Mac 上，从一句话想法到本机跑起一个真实小产品，全程不求助开发者；全程 Token 消耗明细可查

### 二期（+2–3 个月）——「开放与省心」

- **CLI 指令 + `devpilot://` 深链 + MCP Server**（被集成面全量开放）
- 并行任务（git worktree 隔离）、断点续跑、Best-of-N、元素点选反馈
- 移动端监督面（与桌面端配对）、Web 门户技能市场上线
- GitHub/Gitee PR 集成、一键部署向导

### 三期（+3 个月）——「生态」

- IDE 插件（VS Code 先行）、IM 机器人派单、SDK
- 行业技能包市场（第三方分成）、团队共享额度池
- 工作流自定义编辑器（YAML 可视化）

## 4. 技术风险预判

| 风险 | 等级 | 规避 |
|---|---|---|
| **Token 计量被篡改/绕过**（转售模式命门） | 高 | 计量服务端权威：客户端不带 key，统一走自家模型网关；网关按 model+usage 入账；客户端本地账本只做展示镜像 |
| Windows 沙箱无成熟方案 | 高 | MVP 用「目录白名单+命令审批」务实档；加强档（Job Object/受限令牌）列为 Phase 1 安全规格专题，不阻塞主线 |
| Tauri 系统 Webview 兼容性（Win 上 WebView2 版本碎片化） | 中 | 安装器内置 WebView2 检测/引导安装；关键视图双端真机回归 |
| 长任务状态机与 LLM 不确定性冲突 | 高 | 状态机裁决在 Rust 代码层，LLM 只做提议；每 chunk 短会话隔离 |
| 大白话翻译层质量（翻错=误导用户） | 中 | 翻译结果可展开原文对照 + 关键产物（安全报告）用人工模板化措辞 |
| 模型渠道稳定性/合规 | 高 | 多供应商冗余 + 国产模型兜底路由；BYOK 逃生通道；合规评估进 Phase 1 |
| 双端打包签名与自动更新 | 中 | 早期即配 CI（GitHub Actions matrix 构建 Win/Mac）+ Tauri updater；Apple 公证与 EV 证书预算前置 |

## 5. 与既有资产的关系

- `agent-platform/`（Spring Boot + Vue3）：云端薄层若用 Java 可借鉴其鉴权/R 封装；前端主题体系（暗色/CSS 变量）可借鉴到设计系统。产品为独立仓库。
- `voice-to-text/`：已验证本机 Rust/MSVC 编译环境与 Tauri 类桌面链路，环境笔记可直接复用。
- `2_编程类可迭代workflow/`：本产品的「引擎规格来源」——工作流版本升级时，引擎的工作流定义 YAML 同步升级（YAML 跟随工作流版本号）。

# 多Agent智能体平台 — 项目整体说明

> 本文档自顶向下介绍整个项目的三大子模块（`backend` / `frontend` / `runtime-sidecar`）、它们各自的技术栈与职责，以及三者如何协作完成一次 AI 任务。其余细分文档（数据库设计、API 规范、各模块计划、RAG 设计等）位于 `项目工程文档/` 对应子目录，本文只做全局串联。

---

## 一、项目定位

多Agent智能体平台是一个**面向 AI 应用场景的低代码编排系统**。核心能力：

1. **Agent 管理** — 浏览、配置、发布智能体，每个 Agent 挂载若干 Skill（技能 = 有序步骤序列）。
2. **工作流编排** — 通过可视化画布把 Agent、条件分支、并行、循环、人工审批节点连成 DAG。
3. **多模态对话** — 与 Agent 或工作流实时对话（SSE / WebSocket / REST 三路流式，自动降级）。
4. **多 LLM 供应商** — 全局供应商注册 + 每用户私有供应商覆盖（API Key AES 加密）。
5. **企业级 RAG**（规划中）— pgvector 向量库，DB Schema 已就绪（V17）。

**技术栈总览**：Vue 3 + TypeScript + Spring Boot 3 + PostgreSQL + Redis + Python(LangGraph)。

## 二、三大子模块总览

| 模块 | 技术栈 | 端口 | 职责一句话 | 是否必须 |
|------|--------|------|-----------|---------|
| `backend` | Spring Boot 3.2.5 / Java 17 | 8080 | 系统记录源：数据持久化、Agent/Skill 真实执行、HTTP/WebSocket 门面、RBAC | ✅ 必须 |
| `frontend` | Vue 3 + TS + Vite 5 + Naive UI | 5173(开发) | 单页应用：Agent 大厅、工作流画布、对话、管理后台 | ✅ 必须 |
| `runtime-sidecar` | Python / FastAPI / LangGraph | 8090 | 工作流**图编排引擎**：节点排序、分支、并行、检查点、事件流 | ⚠️ 可选（mock 模式可省略） |

**关键设计**：Java 不直接跑工作流图，而是把图交给 Python sidecar（基于 LangGraph，Java 生态无对等库）。但叶节点（`SKILL` / `AGENT_REF`）的真正执行**仍在 Java**——sidecar 通过 HTTP 回调 Java 完成。所以 sidecar 是「图编排层」，Java 是「执行层 + 数据层」。

## 三、整体架构与协作流

```
┌──────────────┐        /api (REST/SSE)         ┌──────────────────────────────────┐
│   frontend   │ ◄────────────────────────────► │            backend (Java)         │
│  Vue3 SPA    │        /ws/chat (WebSocket)     │  ── 数据持久化 (PG + Redis)       │
│ :5173 dev    │                                │  ── Agent/Skill 真实执行          │
└──────────────┘                                │  ── LLM 网关 (OpenAI兼容/Claude)  │
                                                │  ── 认证/RBAC/审计                │
                                                └──────────┬───────────────────────┘
                                                           │ ① POST /api/runtime/executions
                                                           ▼    (SSE 事件流)
                                                ┌──────────────────────────────────┐
                                                │       runtime-sidecar (Python)    │
                                                │  LangGraph StateGraph 编排        │
                                                │  节点排序/分支/并行/检查点         │
                                                └──────────┬───────────────────────┘
                                                           │ ② 回调 POST /api/runtime/callbacks/nodes/execute
                                                           ▼    (SKILL/AGENT_REF 叶节点)
                                                ┌──────────────────────────────────┐
                                                │            backend (Java)         │
                                                │  执行 Skill 步骤 → 返回输出        │
                                                └──────────────────────────────────┘
```

**一次工作流执行的完整链路**：

1. 前端画布保存工作流（节点+边）→ `POST /api/workflows`（Java 落库）。
2. 前端点「运行」→ `POST /api/workflows/{id}/run/stream`（SSE）。
3. Java `RuntimeExecutionService` 用 `WorkflowDefinitionAssembler` 拼装 `WorkflowDefinition`，交给 `SidecarRuntimeGateway`。
4. Gateway 向 sidecar `POST /api/runtime/executions`，消费 SSE 事件流（`NODE_STARTED`/`NODE_COMPLETED`/...）。
5. sidecar 走到 `SKILL`/`AGENT_REF` 节点时，回调 Java `/api/runtime/callbacks/nodes/execute`，Java 真正跑 Skill，返回输出。
6. Java `ExecutionLogService` 全程落库（执行日志、步骤日志、检查点），支持失败重试 / 恢复 / 人工审批。

> 若 `runtime.gateway.mode=mock`，Java 用内置 `MockRuntimeGateway`，不启动 sidecar 也能跑（用于开发/测试）。

### 4.3 REST API 面（统一前缀 `/api`，响应封装 `{code,message,data}`）

- **认证**：`/auth/{register,login,refresh,logout,me}`
- **用户/角色**（需 `user:manage`/`role:manage`）：`/users`、`/roles`、`/roles/permissions/all`
- **Agent**：`/agents`（CRUD + `/copy` + `/sync` + 状态）、`/agents/{id}/skills`、`/skills/{id}`、`/agents/{id}/{access,permissions}`
- **工作流**：`/workflows`（CRUD + `/duplicate` + `/run` + `/run/stream`(SSE) + `/export` + `/import`）
- **执行**：`/executions`（启动 + `/pending-approvals` + `/recovery` + `/retry` + `/resume` + `/approve` + `/reject`）
- **对话**：`/chat/sessions`、`/chat/sessions/{id}/messages`（+ `/stream` SSE）、`/chat/messages`（+ `/stream`）、`/chat/targets`，WebSocket `/ws/chat`
- **LLM**：`/llm/providers`（全局，`role:manage`）、`/llm/user/providers`（用户私有）、`/llm/user/models/available`
- **运行时回调**：`/runtime/callbacks/nodes/execute`（sidecar 回调入口）
- **系统/文件**：`/system/settings/auth`、`/files/upload`、`/files/{id}`

权限：方法级 `@RequirePermission("resource:action")`（如 `agent:create`、`execution:run`、`skill:manage`）。

### 4.4 数据库（PostgreSQL，17 个迁移）

- 主键 `GENERATED ALWAYS AS IDENTITY`，软删除 `deleted`，乐观锁 `version`，审计字段 `created_by/at`、`updated_by/at`，JSONB 存灵活配置。
- 核心表：`users`/`roles`/`permissions`/`user_roles`/`role_permissions`、`agent_groups`/`agents`/`skills`/`skill_steps`/`agent_permissions`、`workflows`/`workflow_nodes`/`workflow_edges`、`execution_logs`/`execution_step_logs`、`chat_sessions`/`chat_messages`、`user_memories`、`llm_providers`/`user_llm_providers`、`system_settings`。
- V17 引入企业级 RAG 的 13 张表（`knowledge_*`、`rag_*`、`embedding_model_versions`），含 `vector(2048)` HNSW 索引与 BM25 tsvector——**Schema 就绪，尚无 Java 包**。

> 详细字段与关系见 `项目工程文档/数据库设计文档.md`。

### 4.5 引擎与运行时分流

`engine/OrchestrationEngine` 按 `ChatSession.mode` 分派：

- `CHAT` → `DefaultChatStrategy`（纯对话，走 LLM 网关）
- `AGENT` → `AgentRoutingStrategy` + `AgentRouter`（按 Agent 层级与授权选 Agent 应答）
- `WORKFLOW` → `WorkflowStrategy`（触发工作流，经 runtime 网关）

`engine/executor/SkillExecutor` 执行 Skill 步骤，支持动作类型 `LLM_CALL` / `HTTP_REQUEST` / `CODE_EXECUTE` / `CONDITION_CHECK`。

### 5.3 状态管理（Pinia，`frontend/src/stores/`）

- **`useAuthStore`** — accessToken/refreshToken/userInfo，`login/register/logout/refreshAccessToken/hasPermission(code)`，`isLoggedIn/isAdmin`。
- **`useThemeStore`** — 三套暗色主题（`deep-space` / `dark-pro` / `cyber-glow`），通过 `<html data-theme>` 切换，持久化到 `app_theme`。
- **`useChatStore`** — 会话、消息、流式缓冲；三路发送 **WS → SSE → REST** 自动降级，SSE 事件 `CHUNK/THINKING/DONE/ERROR`。

### 5.4 API 层（`frontend/src/api/`）

统一 axios 实例 `request.ts`：`baseURL:/api`，15s 超时，请求拦截器注入 `Authorization: Bearer`，响应拦截器校验业务码（200/201/202 视为成功），401 清存储跳登录。各模块导出类型化客户端：`auth/agent/chat/chatTarget/workflow/execution/llm/admin/system`。SSE 因 axios 无法流式，单独用原生 `fetch` + `ReadableStream`（chat、workflow）。

### 5.5 主题系统（仅暗色）

`data-theme` 属性切换 CSS 变量块，三主题共用 `styles/variables.scss` 定义的同一套 Token 词汇表：

| 主题 | 风格 | 主色 |
|------|------|------|
| Deep Space（默认） | 深空冷蓝、玻璃拟态 | `#4F7CFF` |
| Dark Pro | 中性灰、绿色调、低疲劳 | `#10B981` |
| Cyber Glow | 赛博朋克、霓虹粉蓝 | `#E040FB` |

`ThemeSwitcher.vue` 弹出主题卡片带实时色板预览。

### 5.6 关键特性

- **三路流式降级**：WebSocket（`/ws/chat?token=...`）→ SSE（`fetch`）→ REST。
- **RBAC**：角色列表在 `userInfo.roles`，`hasPermission(code)` 控制按钮/菜单，admin 导航按角色显隐。
- **执行恢复**：独立 API 面（`getRecoveryInfo` / `resume(checkpointRef)` / `retry` / `approve` / `reject`）。
- **localStorage 键集中**管理于 `utils/storage.ts`。

## 六、runtime-sidecar 模块（Python 图引擎）

### 6.1 技术栈

| 关注点 | 选型 |
|--------|------|
| 语言 | Python 3.10+ |
| 框架 | FastAPI 0.111.0 + Uvicorn 0.30.1 |
| 图引擎 | **LangGraph 1.2.2**（`StateGraph`、条件边、`START`/`END`） |
| 回调 Java | httpx 0.27.0 |
| SSE | sse-starlette 2.1.2 |
| 校验 | Pydantic v2 |
| 测试 | pytest 8.2.2 |

入口 `runtime-sidecar/app/main.py`，运行：`python -m uvicorn app.main:app --host 0.0.0.0 --port 8090`，端口 **8090**。

### 6.2 目录结构

```
runtime-sidecar/
  README.md / requirements.txt / pytest.ini
  app/
    main.py              # FastAPI app + 2 个端点
    models.py            # 对齐 Java 契约的 Pydantic DTO
    graph_compiler.py    # WorkflowDefinition → LangGraph StateGraph
    runtime_executor.py  # 驱动图，产出 ExecutionEvent 流
    node_runtime.py      # 每节点解析 sourceType/sourceId
    callback_client.py   # httpx 回调 Java（SKILL/AGENT_REF）
    checkpoint_store.py  # 检查点持久化（InMemory / File）
  tests/                 # 5 个测试文件，约 1258 行
```

### 6.3 API 面（仅 2 个端点）

| 方法 | 路径 | 用途 |
|------|------|------|
| `GET` | `/health` | 存活探针（`{"status":"UP","service":"runtime-sidecar"}`） |
| `POST` | `/api/runtime/executions` | 执行工作流 |

`POST` 请求体是 Java 的 `ExecutionRequest` 契约（`executionId`、`workflow`(nodes+edges)、`input`、`runtime` 选项）。响应由 `runtime.stream` 控制：

- `stream=true`（默认）→ `text/event-stream`，逐条 `ExecutionEvent` SSE。
- `stream=false` → 单个 JSON `ExecutionResult`（含完整有序事件列表）。

### 6.4 支持的节点类型

| 节点 | 行为 |
|------|------|
| `START` / `END` / `INPUT` | 起止 / 值节点 |
| `SKILL` / `AGENT_REF` | **回调 Java 执行**（叶节点） |
| `WORKFLOW_REF` | 子工作流引用 |
| `CONDITION` | 分支（`==`/`>`/`contains`/`exists` + `all/any/not` 组，**手写求值，禁用 eval**） |
| `ROUTER` | 基于规则 `config.routes` 路由 |
| `LLM_ROUTER` | 当前仅 **mock**（`mockSelectedRoute`/`mockConfidence`，无真实 LLM） |
| `PARALLEL` / `JOIN` | 扇出 + 全等待，支持 `branchFailurePolicy:continue` |
| `HUMAN_APPROVAL` | 发 `WAITING_APPROVAL` 事件 + `approvalKey`，暂停待人审 |

事件类型：`EXECUTION_STARTED` / `NODE_STARTED` / `NODE_COMPLETED` / `EXECUTION_COMPLETED` / `EXECUTION_FAILED`（带 `failedNodeId`、`recoveryCheckpointRef`）/ `WAITING_APPROVAL`。

### 6.5 检查点与恢复

`checkpoint_store.py` 定义 `CheckpointStore` Protocol，两实现：`InMemoryCheckpointStore`（测试）、`FileCheckpointStore`（默认，写 `.runtime-checkpoints/`）。`runtime.checkpoint=true` 时图跑完/失败保存状态；`runtime.resumeFromCheckpointRef` 恢复，跳过已访问节点。

### 6.6 重要边界

- **无沙箱、无任意代码执行**：节点"执行"是纯数据变换，条件求值手写解析，无 `eval`/`exec`/`subprocess`。
- **无真实 LLM 调用**：`LLM_ROUTER` 仅 mock；`requirements.txt` 不含任何 LLM SDK。
- **叶节点执行在 Java**：sidecar 只编排，Skill/Agent 真跑在 Java 进程。

## 七、本地运行

### 7.1 依赖前置

- PostgreSQL 16（库名 `agent_platform`，需开 `pgvector` 扩展用于 V17）
- Redis
- Java 17 + Maven（backend）
- Node 18+（frontend）
- Python 3.10+（runtime-sidecar，可选）

### 7.2 backend

```bash
cd agent-platform/backend
mvn spring-boot:run          # 端口 8080；Flyway 自动建表/迁移
```

### 7.3 frontend

```bash
cd agent-platform/frontend
npm install
npm run dev                  # 端口 5173，/api 代理 → 8080
```

### 7.4 runtime-sidecar（可选）

```bash
cd agent-platform/runtime-sidecar
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8090
```

Java 端切换到真实 sidecar（`application.yml`）：

```yaml
runtime:
  gateway:
    mode: sidecar                       # 默认 mock，可不启 Python
    sidecar-base-url: http://localhost:8090
    java-callback-base-url: http://localhost:8080
```

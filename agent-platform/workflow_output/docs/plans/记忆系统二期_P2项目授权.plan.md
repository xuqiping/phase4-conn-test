# Implementation Plan for 记忆系统二期 · P2 项目授权

> 主索引：[记忆系统二期.plan.md](记忆系统二期.plan.md) ｜ 规格 FR-101~103
> 依赖：P1 完成（entries 存在、召回合流在位）。

## 本模块坑点预判

| 坑 | 规避 | 验证 |
|---|---|---|
| 状态机被并发操作打穿（同时通过+撤销） | 状态翻转走条件 UPDATE（`WHERE status=:expected`），影响行数=0 即冲突报 409 | 并发单测 |
| REJECTED 30 天防刷被改 project 绕过 | 防刷键=(parent,child) 落 UNIQUE 行不删（软删复活语义），按 created_at 判 | 拒绝后立即重发断言 409 |
| 授权召回实时查拖慢召回 | links 查询走 (parent_project_id,status) 索引 + MemoryQueryCache `mem:` 前缀缓存，授权变更即 evict 双方 | 召回 p95 不回归 |
| 撤销后 parent 总结残留 child 内容 | 撤销钩子标 parent 相关总结 STALE（P1 只标不动，P4 接重生）；条目即时不可见 | 撤销后召回断言无 child 条目 |

## 实现步骤

- [ ] **Step 1：V68 建 memory_project_links + 实体/Mapper**（FR-101）
  - **目标**：授权表就位
  - **动作**：DDL（parent_project_id/child_project_id/granted_by/approved_by/status/created_at/approved_at；UNIQUE(parent,child)；CHECK parent≠child）；索引 (parent,status)、(child,status)；实体+Mapper
  - **文件**：`db/migration/V68__create_memory_project_links.sql`、`chat/entity/MemoryProjectLink.java`、`chat/mapper/MemoryProjectLinkMapper.java`
  - **依赖**：P1 Step 1
  - **验证**：migrate 成功；自环 insert 被拒

- [ ] **Step 2：授权状态机服务 + 端点**（FR-101/103）
  - **目标**：发起/通过/拒绝/撤销全链路
  - **动作**：`POST /projects/{pid}/links`（我是 child owner，body=parentId）→ 校验：我是 child owner、parent 存在、无自环、无 30 天内 REJECTED → 落 PENDING + 写 memory_notifications 给 parent owner/admin；`POST /links/{id}/approve|reject`（parent owner/admin，条件 UPDATE 状态机）；`DELETE /links/{id}`（child owner 或 parent owner/admin 撤 ACTIVE）；每步审计日志；变更即 evict `mem:` 缓存
  - **文件**：`chat/controller/MemoryProjectLinkController.java`、`chat/service/internal/MemoryProjectLinkService.java`、`MemoryNotificationService.java`（复用）
  - **依赖**：Step 1
  - **安全检查**：双方身份校验；防刷；审计
  - **验证**：状态机单测（PENDING→ACTIVE/REJECTED、ACTIVE→撤、非法翻转 409、30 天防刷）

- [ ] **Step 3：授权召回合流**（FR-102）
  - **目标**：parent scope 召回含 ACTIVE child 条目
  - **动作**：P1 的「条目合流」步扩展：查 scope 项目时并查 `links(parent=scope项目, status=ACTIVE)` 的 child 集合 → 条目查询并上 child 条目 → 装配时 child 条目加「来自授权项目·X」标注；写不穿透：条目写入/审核端点不感知 links（路由只写对话发生项目）
  - **文件**：`chat/service/internal/MemoryEntryRecallService.java`、`MemoryRecallScopeResolver.java`、`MemoryRecallPipeline.java`（装配标注）
  - **依赖**：Step 2、P1 Step 5
  - **验证**：A 授权进 B → B 成员召回到 A 条目且带来源标注；PENDING/REJECTED 召回不到；撤销后即时不含

- [ ] **Step 4：前端授权管理页签**（FR-101/102）
  - **目标**：项目授权页签（发起/审批/列表/撤销）
  - **动作**：两块：「我授权出去的」（我 owner 的项目发出的链+状态）+「待我审批的」（PENDING 通知入口+通过/拒绝）；api/memory.ts 加端点；审核通知接 MemoryNotificationBadge
  - **文件**：`frontend/src/components/memory/MemoryProjectLinkPanel.vue`（新）、`MemoryManagerPanel.vue`、`api/memory.ts`、`MemoryNotificationBadge.vue`
  - **依赖**：Step 3
  - **验证**：手测双向确认全流程 + 30 天防刷提示

## 整体验证（P2）

- [ ] E2E：B owner 发起授权给 A → A owner 收通知通过 → A 成员召回到 B 条目（带来源标注）→ B owner 撤销 → A 召回即无
- [ ] A 成员尝试写/审 B 条目 → 403（写不穿透）

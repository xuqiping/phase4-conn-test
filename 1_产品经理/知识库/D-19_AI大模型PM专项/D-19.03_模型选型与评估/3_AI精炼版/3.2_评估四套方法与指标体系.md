# 3.2 评估四套方法与指标体系

## 一、评估四套方法（互补，不可单用）

### 1.1 基准测试（Benchmark）

标准化能力测试集，自动化、可复现、可对比。2026六大核心评测维度 [来源:腾讯云 | 🔍高 | 2026-06]：

| 维度 | 代表基准 | 考察内容 | 2026现状 |
|---|---|---|---|
| 综合知识 | MMLU / MMLU-Pro | 57学科多项选择 | 顶级86-90%，已退化为准入门槛 |
| 推理 | GPQA Diamond / DROP | 研究生级推理 | 区分度仍高，是新分水岭 |
| 代码 | SWE-bench / SWE-bench Pro / HumanEval | 真实仓库修bug/写代码 | SWE-bench Pro是工程代码能力金标准 |
| Agent能力 | OSWorld / GAIA | 连续多步操作办公软件/真实任务 | 2026新核心——靠规划/容错/状态管理 |
| 多模态 | MMMU / MathVista | 图文/视频理解 | Gemini 3 Pro领先 |
| 中文 | SuperCLUE / C-Eval / CMMLU | 中文综合能力 | 国产模型优势区 |

**基准测试局限**：[来源:SegmentFault/CSDN | 🔍高 | 2026]
- 刷分污染：训练数据含基准→分数虚高
- 与业务脱节：榜单高分≠业务场景表现
- 退化为门槛：MMLU等已区分不出顶尖梯队
- 须配合业务集+人评

### 1.2 人评（Human Evaluation）

人类盲评模型输出，最贴近真实体验。

| 方式 | 实现 | 代表 |
|---|---|---|
| **Chatbot Arena** | 用户盲选两个模型回答→选更好→Elo评分 | LMSYS Chatbot Arena，公认最贴近真实体验的榜单 |
| 成对比较 | 人工两两对比候选输出 | 评测集小规模精细评 |
| Likert打分 | 人工1-5分多维度评分 | 写作/创意类 |
| 业务专家评 | 领域专家评业务准确度 | 医疗/法律/金融垂域 |

**人评原则**：[来源:评测实践 | 📚中]
- 双盲：评估者不知模型身份
- 多评估者：≥3人取一致
- 维度细分：准确性/相关性/流畅性/安全性分别评
- 成本高→用LLM-as-Judge大规模+人评小规模校准

### 1.3 LLM-as-Judge（模型当裁判）

用强模型（GPT-4/Claude）当裁判评估其他模型输出，低成本大规模。

| 模式 | 实现 | 适用 |
|---|---|---|
| 成对比较 | 裁判判断A/B哪个更好 | 对标排序 |
| 单答案打分 | 裁判按维度1-5分打分 | 单模型质量 |
| 参照打分 | 裁判对比黄金答案打分 | 有标准答案任务 |
| Rubric评分 | 裁判按评分量表逐项评 | 结构化写作 |

**LLM-as-Judge注意**：[来源:CSDN评估全解析 | 🔍高 | 2026-06]
- 裁判偏好：裁判模型偏好自己风格（同源偏见）
- 位置偏见：A/B顺序影响判断→需交换位置取平均
- 长度偏见：偏好更长回答→需控制长度
- 校准：用人工标注集校准裁判可靠性（裁判与人评一致率>80%才可信）
- 工具：DeepEval/RAGAS/Promptfoo

### 1.4 自建业务评测集

针对自身业务场景建黄金集，评估模型在真实业务的表现。

| 集名 | 内容 | 作用 |
|---|---|---|
| 黄金集 | 50-200条业务输入+期望输出 | 核心场景准确率 |
| 边界集 | 10-30条易错边界case | 鲁棒性 |
| 多样性集 | 覆盖子场景的多样化输入 | 覆盖度 |
| 对抗集 | 注入/越狱/歧义输入 | 安全性 |
| 性能集 | 极端长度/批量输入 | 性能边界 |

**自建业务集原则**：[来源:工程实践 | 📚中]
- 标注质量>数量：50条高质量好过500条低质量
- 持续迭代：业务变化则评测集同步更新
- 与生产分布一致：评测集要反映真实用户输入分布
- 防泄漏：评测集不能进训练数据

## 二、I.09评估指标体系（本能力I.09必选维度）

| 指标类 | 指标 | 定义 | 适用 |
|---|---|---|---|
| **准确性** | 准确率/精确率/召回率/F1 | 输出与黄金答案对齐度 | 分类/抽取 |
| **生成质量** | BLEU/ROUGE/BERTScore | 生成文本与参照相似度 | 翻译/摘要（与人类偏好相关性弱，慎用） |
| **业务效果** | 采纳率/任务完成率/重试率 | 用户采纳/完成/重试行为 | 所有业务 |
| **格式合规** | JSON/Schema合规率 | 输出格式是否符合约束 | 结构化输出 |
| **安全** | 幻觉率/越狱成功率/违规率 | 事实错误/越狱/违规输出 | 所有场景 |
| **性能** | 延迟(P50/P95/P99)/吞吐 | 响应时间/并发能力 | 实时交互 |
| **成本** | 单请求Token成本/单请求$ | 平均每次请求成本 | 成本优化 |
| **稳定性** | 输出方差/Self-Consistency | 多次输出一致性 | 高稳定需求 |

**评估指标设计原则**：
- 北极星1个+辅助指标3-5个，避免指标爆炸
- 业务效果指标>学术指标（采纳率比F1更反映产品价值）
- 设基线+目标值+告警阈值

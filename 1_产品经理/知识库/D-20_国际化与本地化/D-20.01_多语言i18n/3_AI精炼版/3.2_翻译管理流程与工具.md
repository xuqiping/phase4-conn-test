# 3.2 翻译管理流程与工具

## 一、翻译全流程

```
文案提取 → 翻译准备 → 翻译执行 → 质量审核 → 回填集成 → 测试验收 → 上线监控
```

### 各阶段详解

| 阶段 | 输入 | 输出 | 负责方 |
|---|---|---|---|
| 文案提取 | 代码中的硬编码文案 | 资源文件(JSON/PO等) | 开发 |
| 翻译准备 | 资源文件+术语库+上下文说明 | 翻译工包(Translation Kit) | PM+译管 |
| 翻译执行 | 翻译工包+翻译记忆库 | 翻译后资源文件 | 译员/AI |
| 质量审核 | 翻译后资源文件 | 审核通过/返修意见 | 审校/PM |
| 回填集成 | 审核通过的翻译 | 集成到代码仓库 | 开发 |
| 测试验收 | 集成后产品 | 验收报告（截断/溢出/错译） | QA |
| 上线监控 | 用户反馈 | 翻译问题工单 | PM+运营 |

[来源:知乎海外APP多语言方案(2026.6.30)、行业最佳实践 | 置信度:📚中 | 2026-07]

## 二、TMS翻译管理系统

### TMS核心功能

| 功能 | 说明 |
|---|---|
| 翻译记忆库(TM) | 存储已翻译的句对，遇到相同/相似句子自动复用，减少重复翻译 |
| 术语库(Glossary) | 统一产品术语翻译（如"Dashboard"统一译为"仪表盘"而非"仪表板"） |
| 翻译工作流 | 分配任务→翻译→审校→批准→回填 |
| 进度管理 | 实时查看各语言翻译进度 |
| 版本管理 | 翻译版本对比、回滚 |
| API集成 | 与代码仓库/GitHub自动同步资源文件 |

## 三、翻译记忆库(TM)深度

### TM工作原理

```
原文(英文) → 翻译(中文) → 存储(TM数据库)
↓
新原文 → 匹配TM → 
├─ 100%匹配 → 直接复用（无需重译）
├─ 95-99%匹配（模糊匹配）→ 提示译员修改
└─ 无匹配 → 人工/AI翻译
```

### TM管理要点

| 要点 | 说明 |
|---|---|
| 持续积累 | 每次翻译都更新TM，越用越智能 |
| 定期清理 | 删除过时翻译（产品已下线的文案） |
| 分库管理 | 按产品线/版本分库，避免串味 |
| 跨项目复用 | 同一公司的产品可共享TM（须注意术语差异） |

[来源:行业最佳实践 | 置信度:📚中 | 2026-07]

## 四、术语库(Glossary)管理

### 术语库结构

| 术语(原文) | 译法(中文) | 译法(日语) | 词性 | 上下文 | 禁用译法 |
|---|---|---|---|---|---|
| Dashboard | 仪表盘 | ダッシュボード | 名词 | 数据看板页面 | 仪表板 |
| Sign in | 登录 | ログイン | 动词 | 用户登录操作 | 签到 |
| Tier | 层级 | ティア | 名词 | 价格层级 | 等级 |

### 术语管理原则

1. **统一性**：同一术语在整个产品中翻译一致
2. **品牌词不译**：品牌名/产品名通常不翻译（如"Google"不译）
3. **上下文标注**：同一词在不同语境可能有不同译法
4. **定期更新**：新功能上线时同步更新术语库
5. **译员必读**：翻译前须阅读术语库，确保一致

## 五、翻译质量保证体系

### 质量检查维度

| 维度 | 检查项 | 工具 |
|---|---|---|
| 完整性 | 所有key都有翻译 | 自动化脚本 |
| 一致性 | 术语翻译统一 | TM+术语库 |
| 准确性 | 译文准确传达原意 | 人工审校 |
| 格式正确性 | 变量/占位符未丢失 | 自动化检查 |
| 长度适配 | 不超UI限制 | QA测试 |
| 文化适配 | 无冒犯性表达 | 本地化审校 |

### LQA（Language Quality Assurance）评分

| 等级 | 说明 | 处理方式 |
|---|---|---|
| Critical | 严重错误（语义错误/冒犯） | 必须修改 |
| Major | 重要错误（语法/术语不一致） | 应当修改 |
| Minor | 轻微错误（风格/流畅性） | 建议修改 |
| No error | 无错误 | 通过 |

[来源:行业LQA标准 | 置信度:📚中 | 2026-07]

## 六、常见坑

1. **"翻译不需要上下文"**：同一英文词在不同页面含义不同（如"Post"在社交=发帖，在电商=邮寄），不给上下文必出错。
2. **"TM建了就行"**：TM须持续维护——过时翻译不清理会导致"僵尸翻译"被误复用。
3. **"术语库可有可无"**：没有术语库，10个译员可能把同一术语译成5种版本。
4. **"翻译完不测UI"**：德语膨胀30%后按钮文案截断——翻译正确但UI溢出。
5. **"同时翻20种语言"**：建议先翻2-3种核心语言验证流程，再批量扩展。

## 七、国内外对比

| 维度 | 中国出海团队 | 国际成熟团队 |
|---|---|---|
| 翻译流程 | 常跳过TMS，直接Excel+翻译公司 | TMS+TM+术语库标准化流程 |
| 译员管理 | 外包翻译公司，质量波动大 | 长期合作译员+内部译管 |
| 质量保证 | 上线后靠用户反馈 | 上线前LQA评分+QA测试 |

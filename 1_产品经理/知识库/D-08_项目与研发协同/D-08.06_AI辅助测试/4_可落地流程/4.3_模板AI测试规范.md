# 模板：团队AI测试规范

## 一、总则

### 1.1 目的

规范团队使用AI测试工具的行为，确保：① AI测试结果可信可控 ② 人工兜底机制明确 ③ 伪阳性在可控范围

### 1.2 适用范围

所有使用AI测试工具参与项目测试的团队成员

## 二、覆盖率底线

| 产品类型 | AI测试最低覆盖率 | 人工兜底要求 |
|---|---|---|
| C端Web/App | 关键路径100%/整体≥85% | 关键路径+支付+认证必须人工验证 |
| B端SaaS | 核心流程100%/整体≥90% | 每个租户核心流程人工验证 |
| API/后端服务 | 接口覆盖≥95% | 每版本至少3个接口人工深度测试 |
| AI模型服务 | 推理正确率≥99% | 模型评估集人工标注+对比验证 |

### 2.1 关键路径定义

- 涉及金钱交易的流程（支付/退款/结算）
- 涉及用户认证授权的流程（登录/权限/MFA）
- 涉及数据隐私合规的流程（GDPR/个保法/日志）
- 涉及安全的流程（加密/脱敏/审计）

## 三、伪阳性管理

### 3.1 伪阳性率目标

| AI测试类型 | 伪阳性率上限 | 超限动作 |
|---|---|---|
| 功能测试 | <15% | 校准AI参数 |
| 视觉测试 | <20% | 调整忽略区/阈值 |
| 性能测试 | <10% | 校准基线/异常检测模型 |

### 3.2 伪阳性处理流程

1. AI报告"差异/异常"→记录到伪阳性看板
2. 人工判定：真实Bug / 伪阳性 / 待定
3. 伪阳性→标注原因→加入忽略规则库
4. 每周review忽略规则库——防止"忽略"变成"视而不见"

## 四、人工兜底机制

### 4.1 必须人工验证的场景

| 场景 | 人工验证内容 | 最低频率 |
|---|---|---|
| 大版本上线 | 全量关键路径验证 | 每次Major Release |
| AI覆盖率<95% | 未覆盖的缺口用例 | 每次版本发布 |
| AI工具升级/模型更新 | 重新校准伪阳性率 | 每次更新后 |
| 生产环境重大变更 | 全量冒烟+关键路径 | 每次变更 |

### 4.2 人工验证比例标准

| 项目阶段 | AI测试占比 | 人工验证占比 |
|---|---|---|
| AI测试引入期（0-3月） | 50% | 50% |
| AI测试验证期（3-6月） | 70% | 30% |
| AI测试成熟期（6月+） | 80% | 20%（关键路径100%兜底） |

## 五、度量与复盘

### 5.1 每月度量

| 指标 | 目标 | 数据来源 |
|---|---|---|
| AI测试覆盖率 | ≥85% | AI测试工具面板 |
| 伪阳性率 | <20% | 伪阳性看板 |
| AI发现Bug占比 | 30-50% | 缺陷管理系统 |
| 关键路径人工验证执行率 | 100% | 验证记录 |
| AI测试节省工时 | 量化 | 对比基线 |

### 5.2 季度复盘

- 评估AI测试工具续约/切换
- 更新覆盖率基线
- 评估手工测试人员转型进展

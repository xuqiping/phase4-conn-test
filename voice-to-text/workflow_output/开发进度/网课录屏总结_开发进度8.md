## 追加（2026-08-22）：黑帧防护（已完成 ✅）

> 用户发现 20260822_132246_905 会话黑屏片段多。实测：237 帧中 126 帧纯黑（亮度 0.0），黑屏时段老师仍在正常讲课（音频/转写没断）→ 结论：**被录窗口最小化时 WGC 持续投纯黑帧**（不是旧注释以为的“停帧”），黑↔正常来回切换被抽帧误判成翻页、污染章节划分。

实现（Rust 82 测试绿 + vue-tsc 绿，文档已同步）：

1. `scene_detect.rs`：新增纯函数 `is_near_black`（灰度均值 < 8.0）+ `BLACK_MEAN_THRESHOLD` / `PICTURE_LOST_THRESHOLD_MS(3s)` 常量；
2. `PageExtractor::push`（录后精细判页）：近黑帧直接跳过——不建页、不触发翻页、不更新 last_grid，黑屏期间归属上一页；开录即黑屏时首个正常帧才是第 1 页；
3. `SceneTap`（录制时预筛）：近黑帧跳过（不存缩略图/不记翻页），并更新 `BlackFlag`（Arc<AtomicI64>，与 ScreenCapture 共享）；
4. `capture.rs`：`CaptureStatus.picture_lost`（黑屏 > 3s）——stalled 仍保留兜底；头部注释修正最小化行为认知；
5. 前端：录制中每 500ms 轮询 `get_capture_status`，画面丢失 → Recorder 顶部红色告警条「还原被录窗口」。
6. 新增测试 `extractor_skips_near_black_frames`。

复测要点：录制中最小化被录窗口 → 3 秒内出现红色告警，还原后消失；该会话「重新分析视频」→ 章节数应显著减少（黑帧不再成章）。

### 补（2026-08-22）：窗口+区域模式最小化后 crop 永久压坏 + 告警不触发（已完成 ✅）

用户实测：窗口+区域录制中最小化 → 无告警、后端狂刷 `region RegionRect{width:18,height:0} outside frame`，还原窗口后仍不停。根因两个：

1. **破坏性 clamp**：`on_frame_arrived` 把 crop 矩形**就地** min 到当帧尺寸。最小化期间 WGC 帧尺寸缩小，矩形被永久压成 18x0；矩形只会缩不会涨，还原后也无法恢复。修复：原始矩形只读保留，每帧算交集**副本**，帧尺寸恢复即自动回到完整裁剪。
2. **告警链路断**：black_flag 只在 SceneTap（crop 成功后的像素路径）置位；crop 失效时 tap 收不到像素，且帧元数据照发 → stalled/picture_lost 都不触发。修复：crop 无交集时 handler 直接 compare_exchange 置 black_flag，恢复时清零；日志只在进入/退出丢画面各记一条，不逐帧刷屏。

Rust 84 测试绿。复测：窗口+区域模式录制中最小化 → 3 秒内红色告警 + 单条 ERROR 日志；还原 → 「region crop recovered」日志、告警消失、画面/抽帧恢复正常。

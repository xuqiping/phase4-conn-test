# 规格 · 反馈中心（建议台 + 提问台 + 说明台 三合一）

> Phase 1 新建规格。实现必须与本文一致；来源为 2026-08-21 人工测试问题 **19x 全部 3 项未解决**。
> 用户已拍板（2026-08-21）：**合并成一个「反馈与帮助」模块**，内含 建议 / 提问 / 使用说明 三个 tab，减少菜单与表数量。
> 参考模式：审核流转参考 `FeedbackReviewService`（RAG 反馈 PENDING→APPROVED/REJECTED 状态机）；admin 列表页参考 `SecurityEventView.vue`；通知参考 `memory_notifications` + 铃铛徽标模式。

## 1. 目标

1. **建议台**：用户提交产品建议/需求（记录提交人用户名，可附截图）；admin 审核流转（采纳/拒绝/关闭）并回复；结果通知提交人。
2. **提问台**：用户提问「某功能怎么用/如何实现」；admin 用 markdown 回答；已回答的问题可选择公开为 FAQ 供全员检索。
3. **说明台**：admin 维护的操作说明文章（markdown），按分类组织，全员可读。

## 2. 非目标（本期不建）

- ❌ 用户间互相回答/评论/点赞（社区化）。
- ❌ 建议投票/看板/路线图公开。
- ❌ 富文本编辑器（admin 用 textarea + 预览，复用现有 markdown 渲染）。
- ❌ 邮件/站外通知（仅站内铃铛）。
- ❌ FAQ 全文搜索引擎（本期 LIKE 前缀检索 + 分类过滤，量级百级够用）。

## 4. 数据模型（Flyway `V141__feedback_center.sql`；若上游占用则顺延）

```sql
feedback_suggestions          -- 建议台
  id PK, user_id BIGINT NOT NULL, username VARCHAR(64) NOT NULL,   -- 用户名快照（改名不影响历史记录）
  title VARCHAR(120) NOT NULL, content VARCHAR(4000) NOT NULL,
  attachment_file_ids JSONB NULL,        -- 截图附件，元素为 fileId，≤3 个
  status VARCHAR(16) NOT NULL DEFAULT 'PENDING',   -- PENDING/ADOPTED/REJECTED/CLOSED
  reply VARCHAR(2000) NULL, reviewed_by BIGINT NULL, reviewed_at TIMESTAMPTZ NULL
  + 审计四列 + deleted
  CHECK (status IN ('PENDING','ADOPTED','REJECTED','CLOSED'))
  INDEX (status, created_at DESC), INDEX (user_id, created_at DESC)

feedback_questions            -- 提问台
  id PK, user_id BIGINT NOT NULL, username VARCHAR(64) NOT NULL,
  title VARCHAR(120) NOT NULL, content VARCHAR(4000) NOT NULL,
  status VARCHAR(16) NOT NULL DEFAULT 'OPEN',      -- OPEN/ANSWERED/CLOSED
  answer_md VARCHAR(8000) NULL, answered_by BIGINT NULL, answered_at TIMESTAMPTZ NULL,
  is_public BOOLEAN NOT NULL DEFAULT FALSE          -- admin 回答时可勾选公开为 FAQ
  + 审计四列 + deleted
  CHECK (status IN ('OPEN','ANSWERED','CLOSED'))
  INDEX (status, created_at DESC), INDEX (is_public, answered_at DESC) WHERE is_public

help_articles                 -- 说明台
  id PK, slug VARCHAR(80) NOT NULL UNIQUE, title VARCHAR(120) NOT NULL,
  category VARCHAR(40) NOT NULL DEFAULT 'general',
  content_md TEXT NOT NULL, sort INT NOT NULL DEFAULT 0,
  published BOOLEAN NOT NULL DEFAULT FALSE,
  updated_by BIGINT NULL
  + 审计四列 + deleted
  INDEX (published, category, sort)

feedback_notifications        -- 站内通知（克隆 memory_notifications 模式，模块自有）
  id PK, user_id BIGINT NOT NULL,        -- 接收人
  type VARCHAR(32) NOT NULL,             -- SUGGESTION_REVIEWED / QUESTION_ANSWERED
  ref_id BIGINT NOT NULL, message VARCHAR(255) NOT NULL,
  read_at TIMESTAMPTZ NULL, created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
  INDEX (user_id) WHERE read_at IS NULL
```

权限播种（`V142__feedback_permissions.sql`，沿用 V134/V137 模式）：
- `feedback:manage`（审核建议 + 回答提问）→ admin 角色。
- `help:manage`（说明文章 CRUD + 发布）→ admin 角色。
- 用户侧提交/查看不需权限码（登录即可），service 层本人数据校验。

## 5. API

### 5.1 用户侧（登录，无权限码）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/feedback/suggestions` | 提建议 `{title, content, attachmentFileIds[]}`；`@RateLimit(5/60s)`；附件 fileId 校验属主=本人 |
| GET | `/api/feedback/suggestions/mine` | 我的建议（分页），含 status/reply |
| POST | `/api/feedback/questions` | 提问 `{title, content}`；`@RateLimit(5/60s)` |
| GET | `/api/feedback/questions/mine` | 我的提问（分页），含 answer |
| GET | `/api/feedback/questions/faq?kw=&page=` | 公开 FAQ 列表（is_public=true，标题/内容 LIKE 前缀检索） |
| GET | `/api/feedback/help/articles?category=` | 已发布文章目录（仅 id/slug/title/category/sort） |
| GET | `/api/feedback/help/articles/{slug}` | 文章正文（published=true 才放行） |
| GET | `/api/feedback/notifications/count` `/list` + POST `/{id}/read` | 铃铛三件套（克隆 memory 模式） |

### 5.2 admin 侧

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/feedback/admin/suggestions?status=&page=` | `feedback:manage` | 建议列表（带用户名/附件 id） |
| POST | `/api/feedback/admin/suggestions/{id}/review` | `feedback:manage` | `{status: ADOPTED/REJECTED/CLOSED, reply}`；条件 UPDATE 抢 PENDING；成功写通知 + 审计 |
| GET | `/api/feedback/admin/questions?status=&page=` | `feedback:manage` | 提问列表 |
| POST | `/api/feedback/admin/questions/{id}/answer` | `feedback:manage` | `{answerMd, isPublic}`；OPEN/ANSWERED→ANSWERED（可改答案）；通知 + 审计 |
| POST | `/api/feedback/admin/questions/{id}/close` | `feedback:manage` | 关闭（无答案终结） |
| CRUD | `/api/feedback/admin/help/articles[/{id}]` | `help:manage` | 文章增删改 + `POST /{id}/publish` `/unpublish` |

附件读取：现有 `GET /api/files/{fileId}` owner-or-admin 门控直接满足（提交人与 admin 可看，其他用户 403），FAQ 公开的问答**不含附件**（附件只允许挂在建议上）。

## 6. 前端

### 6.1 用户侧：`FeedbackCenterView.vue`（新，路由 `/feedback`，module key `feedback`）

- tab1 **建议**：提交表单（标题/内容/附件≤3 张，走 `/files/upload` 拿 fileId）+「我的建议」列表（状态标签 + admin 回复展开）。
- tab2 **提问**：提问表单 +「我的提问」列表（答案 markdown 渲染）+「常见问题」区（FAQ 检索框 + 列表，`MarkdownContent` 渲染答案）。

## 7. 安全策略

1. 提交限流 5 次/分钟/用户（建议、提问分开计数）；标题/内容长度 DB + DTO 双层卡。
2. 附件：复用上传单点收口（白名单+魔数+配额）；提交时校验 fileId 属主=提交人，防挂别人文件；读取 owner-or-admin 门控不变。
3. markdown 渲染 `html:false`（XSS 天然免疫）；admin 回复同样渲染管线，防 admin 输入带毒。
4. 审核/回答条件 UPDATE 抢态防并发重复处理；全部 admin 动作 `@AuditLog`。
5. 用户列表仅本人数据（service 层 userId 强过滤）；FAQ 只暴露标公开的问答，**问题作者用户名在 FAQ 公开视图脱敏为「用户xxx」**（保护提问人隐私，admin 视图全量）。
6. 通知 message 只存摘要文案，不存富文本。

## 术语表

| 术语 | 大白话 | 例子 |
|---|---|---|
| **状态机** | 一条数据按固定路线改状态，不许乱跳 | 建议只能 PENDING→ADOPTED/REJECTED/CLOSED |
| **条件 UPDATE 抢态** | 带状态前提的更新，改 0 行就说明被别人抢先处理过 | 两个 admin 同时点「采纳」，只有一个成功 |
| **用户名快照** | 提交时把用户名抄进记录，改名不影响历史 | 用户改名后老建议仍显示当时名字 |
| **slug** | 文章的英文短链名，用于 URL | `/help/articles/how-to-charge` |
| **魔数嗅探** | 看文件头几个字节判断真实类型，防改后缀伪装 | `.exe` 改名 `.png` 会被识别拒掉 |
| **XSS** | 把恶意脚本塞进内容让别人的浏览器执行 | markdown 渲染关掉 html 后脚本只当文字显示 |

# 3.1 定义边界与核心概念

## 定义

AI辅助开发（AI-Assisted Development）是指利用大语言模型驱动的前端/后端代码生成、补全、审查、调试和重构工具，将开发者的工作重心从"逐行编写"转移到"意图表达·质量把控·架构决策"的实践体系。[来源:GitHub Copilot官方 | 🔍高 | 2024]

> 核心判断：AI辅助开发不是"让AI替你写代码"，而是"让AI替你做编码的体力活，让你专注编码的脑力活"——从Typist升级为Architect。[来源:📚训练知识]

## 三阶段演进

| 阶段 | 模式 | 典型工具 | 开发者角色 | 成熟度 |
|---|---|---|---|---|
| **1.0 代码补全** | 内联建议，Tab接受 | Copilot 1.x, Tabnine | 打字员+审阅者 | 2022成熟 |
| **2.0 对话式编程** | 自然语言指令→多文件修改 | Cursor Chat, Copilot Chat | 指挥官+审阅者 | 2024成熟 |
| **3.0 自主Agent** | 下达任务→自主规划→执行→验证 | Claude Code, Cursor Agent, Kiro | 架构师+验收者 | 2025-2026快速迭代 |

> 三阶段非替代关系而是**叠加关系**：Agent模式仍需补全模式做微调，对话模式补全模式之间的"中等粒度"操作空间。[来源:CSDN 2025年终总结 | 📚中 | 2025-12]

## 核心术语

| 术语 | 英文 | 定义 | PM关注点 |
|---|---|---|---|
| 代码补全 | Code Completion | AI根据上下文预测并建议下一行/段代码 | 最基础模式，入职即用，投资回报最确定 |
| 对话式编程 | Chat-based Coding | 自然语言描述需求，AI生成/修改多文件代码 | 需要清晰的Prompt，PM可直接参与 |
| Agent模式 | Agent Mode | AI自主规划任务步骤，执行多轮操作并验证结果 | 人工审批节点是安全底线 |
| Vibe Coding | Vibe Coding | 不看代码细节，凭"感觉"和自然语言驱动AI编程 | 2025柯林斯年度词汇；原型可用，生产勿碰 |
| Spec Coding | Spec Coding | 先写精确规格，再让AI按规格生成代码 | Vibe Coding的规范进阶，更适合生产环境 |
| 上下文窗口 | Context Window | AI能"看到"的代码/文档范围 | 决定AI能否理解项目全貌，直接影响输出质量 |
| 幻觉 | Hallucination | AI生成看似正确但实际逻辑错误或引用不存在的API/库 | 是AI编码最大风险，需Code Review兜底 |
| Token消耗 | Token Usage | 每次AI调用消耗的令牌数，直接影响成本 | 企业部署需关注月度账单与ROI |
| 沙箱 | Sandbox | 隔离AI执行环境，限制其对文件/网络/命令的访问 | 安全第一道防线，但已发现多次绕过漏洞 |

## Vibe Coding vs Spec Coding

| 维度 | Vibe Coding | Spec Coding |
|---|---|---|
| 核心思路 | "我想要这种感觉，AI你帮我写" | "这是精确规格（Spec），AI你按规格实现" |
| 开发者心智模型 | 氛围驱动，方向模糊 | 规格驱动，边界清晰 |
| 适用阶段 | 原型/MVP/探索期 | 生产/迭代/规模化期 |
| 代码质量 | 能跑但难维护，"slop"代码 | 结构清晰，可维护 |
| PM角色 | 描述感觉和方向 | 定义精确的验收标准和技术规格 |
| 风险 | 技术债快速累积；项目规模扩大后Agent"看不清全貌"导致重复实现 | Spec本身写错则AI忠实执行错误规格 |
| 典型场景 | Hackathon、POC、个人项目 | 企业产品开发、团队协作 |

> 关键趋势（2026）：从Vibe Coding走向Spec Coding是行业共识——slopfix团队专门做"清理AI生成的slop代码"的生意就是明证。[来源:虎嗅/slopfix报道 | 📚中 | 2026-07]

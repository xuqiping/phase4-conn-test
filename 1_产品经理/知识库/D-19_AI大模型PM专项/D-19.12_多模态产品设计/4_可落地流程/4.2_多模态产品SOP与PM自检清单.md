# 4.2 多模态产品 SOP（7步）+PM自检清单+回归集模板

> 本碎片提供PM可直接使用的工程化交付流程，与4.1的Agent元提示词互补：4.1把"多模态设计"工程化，4.2把"多模态产品研发"流程化。

## 一、7步SOP总览

```
Step1: 场景识别       → 是否真的需要多模态？还是纯文本产品足够？
Step2: 模态选型(M3V)  → 哪几个模态是必要的？哪些可选？
Step3: 架构选型       → CLIP / Linear / Q-Former / Native四选一(+备选)
Step4: 对齐设计       → 模态对齐 + 时序对齐(若涉及) + 语义锚点(若RAG)
Step5: 降级设计       → 4种模态缺失场景逐一设计降级路径
Step6: 评测体系       → 三层框架(模态内/跨模态/任务级)落地
Step7: 合规前置       → AIGC标识+备案+授权+版权+深度伪造+数据出境
```

## 二、7步SOP逐步详解

### Step1: 场景识别（D-19.12模块2 决策问句）

**输入**：业务需求文档
**输出**：是否需要多模态的明确判断（含论证）

**关键问句**（详见模块2）：
1. 输入是否含非文本模态？2. 输出是否涉及跨模态生成？3. 是否需要跨模态对齐？4. 是否需要时序对齐？...

**反共识提醒**：
- 纯文本能解决的不要硬上多模态（多模态成本5-100倍）
- 若仅需要"看截图回答问题"，Qwen-VL足够，不需要原生多模态API

### Step2: 模态选型（M3V — Minimum Modal Viable Product）

**输入**：场景识别通过
**输出**：M3V模态组合表 + 扩展模态计划

| 模态 | 必要性（必/可选/锦上添花） | MVP阶段 | 扩展阶段 | 理由 |
|---|---|---|---|---|
| 文本 | 必 | ✅ | - | 任何AI产品基础 |
| 图像 | 必/可选/锦上 | ✅/⬜ | - | ... |
| 音频 | 必/可选/锦上 | ⬜ | ✅ | ... |
| 视频 | 必/可选/锦上 | ⬜ | ✅ | ... |
| 3D | 必/可选/锦上 | ⬜ | ⬜ | ... |
| 传感器 | 必/可选/锦上 | ⬜ | ⬜ | ... |

**反共识**：MVP阶段最多3模态，杜绝"全模态堆叠"

### Step3: 架构选型（参D-19.12 模块3.1）

**输入**：M3V模态组合 + 算力预算 + 团队规模
**输出**：架构选型决策表 + 推荐方案 + 备选

**选型四步法**：
1. 明确场景（检索/理解/生成）
2. 评估算力预算（自研/微调/纯API）
3. 明确产品阶段（MVP/成长/旗舰）
4. 权衡幻觉容忍度（医疗等高敏感必须Native或Q-Former）

**典型组合**：
- 创业团队+MVP→Linear Projection接Qwen-VL
- 中型团队+垂直场景（如医疗）→Q-Former
- 任何团队+旗舰产品→Native（GPT-5.6/Gemini 3.1 API）
- 检索场景→CLIP（永远不可替代）

### Step4: 对齐设计

**输入**：架构选型 + 业务敏感度
**输出**：模态对齐方案 + 时序对齐方案 + 语义锚点（若RAG）

**模态对齐清单**：
- [ ] 选择对齐层次（概念对齐CLIP / 属性对齐Fine-Grained CLIP / 关系对齐Native）
- [ ] 设计跨模态检索的词袋效应规避
- [ ] 设计局部物体对齐（用Kosmos-2或Fine-Grained CLIP）

**时序对齐清单（若涉及多模态时序）**：
- [ ] 所有模态数据带时间戳
- [ ] 设计异步事件链（不能假设天然同步）
- [ ] 设计时序缓冲区
- [ ] 设计超时降级（某模态延迟>阈值时主动告知用户）

**语义锚点清单（若涉及多模态RAG）**：
- [ ] 每条模态信息生成简短文字锚点
- [ ] 锚点必须能反向定位原文/原图
- [ ] 模型基于锚点推理而非直接脑补

### Step5: 降级设计

**输入**：M3V模态组合 + 业务场景
**输出**：4场景降级路径表

| 缺失场景 | 检测方式 | 降级策略 | 用户告知 |
|---|---|---|---|
| 用户只输入部分模态 | 输入解析 | ①主动询问补充 ②退化为单模态 | "请补充XX信息" |
| 某模态数据质量差 | 质量检测模型 | 降级到其他模态为主 | "您的XX不清晰，已用YY判断" |
| 某模态能力薄弱 | 模型能力评估 | 工具兜底（如OCR）或主动告知 | "看不清图中文字，建议手动输入" |
| 某模态完全缺失 | 输入解析 | 拒绝任务或退化 | "本场景需要XX模态，暂不支持" |

### Step6: 评测体系落地（参D-19.12 模块3.3）

**输入**：架构选型 + 业务指标
**输出**：评测三层框架落地表

**评测三层框架**：

| 层 | 指标 | 主流基准 | 自建回归集 | 节奏 |
|---|---|---|---|---|
| 模态内评测 | VQA准确率/POPE幻觉率/CLIP Score | VQAv2/POPE/CLIP | 每模态50-200条 | 每周 |
| 跨模态评测 | 跨模态对齐度/RAG幻觉率/视觉幻觉率 | HallusionBench | 500-2000条 | 双周 |
| 任务级评测 | 任务完成率/转人工率/采纳率 | - | 真实业务任务样本 | 月度 |

**自建回归集模板**：
```yaml
case_id: case_001
input:
  text: "..."
  image: "..."
  audio: "..."
expected_output: "..."
business_context: "（如电商客服/医疗影像/工业质检）"
difficulty: easy/medium/hard
notes: "（如已知陷阱：图中文本误导）"
```

### Step7: 合规前置（参D-19.11）

**输入**：产品是否中国+是否涉及生成+是否涉及公众人物
**输出**：合规checklist

**多模态合规前置checklist**：
- [ ] AIGC显著标识（2025-09-01强制，参D-19.11模块3.2）
- [ ] AIGC隐性水印（与显著标识双轨）
- [ ] C2PA元数据嵌入
- [ ] 三轨备案（算法备案+大模型备案+AI应用登记）
  - [ ] 检查9/30 AI应用登记截止
  - [ ] 检查6/30未备案关停节点
- [ ] 训练数据版权来源审计（若使用LAION-5B等开源数据集，需明确连带风险）
- [ ] 训练数据 indemnification（B端产品必备，参Adobe Firefly范式）
- [ ] 声音克隆/数字人Use Case限制（参Synthesia范式：KYC+授权+水印）
- [ ] 深度伪造合规（参Taylor Swift反例：快速响应+主动检测+法律通道）
- [ ] 未成年人保护（参Character.AI反例：内容分级+时长限制+心理健康通道）
- [ ] 数据出境合规（若服务跨境用户）

## 四、迭代节奏（多模态产品独有）

### 周度
- 评测回归集周报（幻觉率/任务完成率/转人工率）
- 用户日志人工抽样100条（多模态幻觉/模态缺失样本）

### 双周度
- 跨模态评测更新（自建回归集扩展）
- 多模态RAG幻觉对冲手段迭代（5手段之一调整）

### 月度
- 任务级评测（基于真实业务任务）
- 模型对比测试（GPT-5.6 vs Gemini 3.1 vs Claude 4.7 vs Qwen3-Max）

### 季度
- 架构选型回顾（是否有更优替代）
- 多模态形态扩展评估（是否加新模态）
- 合规法规更新（中国/国际AI治理动态）

## 五、PM实操建议

1. **MVP阶段聚焦M3V + Linear/Q-Former**，严禁一上来就Native API（成本与可控性）
2. **评测三层框架从一开始就建**，不要等产品上线才补
3. **每周必须做用户日志人工抽样100条**——这是发现多模态幻觉的唯一可靠方式
4. **合规前置不要等代码完成才做**——三轨备案周期3-6个月必须前置到Roadmap
5. **多模态成本优化必须做**（参D-19.09）——原生多模态token是纯文本5-100倍
6. **多源交叉验证是医疗/金融/未成年人场景的硬约束**——不要心存侥幸
7. **视觉幻觉率指标永远不能降级测**——任何架构升级都要重测

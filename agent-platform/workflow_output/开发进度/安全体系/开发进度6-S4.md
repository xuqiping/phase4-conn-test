## 2026-08-15 · Step 1 F-2 magic number 嗅探（SEC-FR-031）✅ `23529bc4`

- **实现**：`file/service/FileUploadValidator`（@Component）——读文件头前 64KB → `new Tika().detect(byte[])` **纯魔数嗅探**；`FileSecurityPolicy.EXT_DETECT_ACCEPTED` 扩展名→可接受 MIME 集合（zip 容器族收录 OOXML 精确型+x-tika-ooxml+zip 变体；mp4/mov 互收录防 ftyp brand 误拒）；三态判定：兼容放行 / 不一致拒 40010（「文件内容与声明类型不符」）+`security.upload.magic.denied{reason}` / 未知（octet-stream）放行+`security.upload.magic.unknown` 观察。纯文本族（txt/md/csv/json/srt/vtt）无稳定魔数不进映射不比对。开关 `security.upload.magic-sniff.enabled`（默认开，进 EDITABLE_KEYS）。
- **挂点**：`FileStorageService.store()` 扩展名白名单后第二关；`@Autowired(required=false)` 字段注入（横切可选依赖范式，手写构造单测直通）；storeStream 不嗅探（服务端可信回源）。
- **关键坑（Tika 名字先行）**：`tika.detect(stream, name)` 会拿文件名当类型提示——「evil.png」按名字直接猜出 image/png，嗅探被改名骗过。必须自读 head 用 `detect(byte[])` 纯魔数。已在代码注释立牌。
- **测试**：FileUploadValidatorTest 10/10（exe 改名 png 拒 / 真 PNG 过 / html 声明一致过 / zip 容器过 / octet-stream 放行+计数 / 文本族不比对 / 开关关 / 设置异常仍嗅 / store 集成拒+缺席直通）。**顺手矫正 2 个陈旧断言**（FileSecurityPolicyTest evil.html 拒收 + FileStorageServiceTest html 拒收 → 14x-4 决策 html 放行、下载侧 attachment 承接）——S3 时认定的 15 个预存失败中此域 2 个就此转绿。回归：FileSecurityPolicy 53 + FileStorage 7 + Asset 33 + KnowledgeDoc 3 + MemoryAssetUpload 11 + SystemSetting 26 = 133 绿。
- **指标/开关**：`security.upload.magic.denied{reason=mismatch}` / `security.upload.magic.unknown` / `security.upload.magic-sniff.enabled`。

## 2026-08-15 · Step 2 F-3 解析炸弹三件套（SEC-FR-032）

- **①像素炸弹（头读取+预算）**：新建 `common/security/util/ImageGuard`——`dimensions(InputStream)` 走 `ImageIO.getImageReaders` 只读宽高**不解码像素**（原 `ImageIO.read` 按声明尺寸分配缓冲，10 万×10 万 PNG 直接 OOM）；`assertPixels(cap, in, label)` 总像素超限抛 BAD_REQUEST「图片分辨率过大（W×H）」，无法判定放行（检测层不自残）；`DEFAULT_MAX_PIXELS=1 亿`。三处挂点：`AssetService.upload`（IMAGE 类落盘前）+ `readImageDims` 改头读取、`VideoFrameService.cropImage`（解码前护栏）、`MemoryAssetUploadService` 图片预检（KIND_IMAGE 新分支）。
- **②解析文本限长**：`DocumentParserService.extractTika` 改 3 参 `parseToString(in, metadata, max)`——默认 **100_000=Tika facade 单参隐式值**（javap 实证 instance maxStringLength），显式化不改行为；热更键 `security.upload.max-parse-chars` 可降。zip bomb 高膨胀文档截断即止，不再整段进内存/切分/LLM。
- **③FFmpeg 超时+帧预算**：`VideoFrameService` 3 处 grabber（extract/clip/concat）+ `MemoryAssetUploadService.precheck` 音视频预检统一 `setOption("rw_timeout","30000000")`（30s，IO 层超时须 start 前）；clip 帧预算 72_000（600s×120fps）、concat 累计 360_000——时间戳异常/恶意容器不无限逐帧，超限 UNPROCESSABLE「时长异常已中止」。
- **热更键**：`security.upload.max-pixels`（默认 1 亿）/ `security.upload.max-parse-chars`（默认 10 万），均进 EDITABLE_KEYS。
- **测试**：ImageGuardTest 7/7（真 PNG 头读宽高/垃圾字节 null/预算超拒/预算内过/无法判定过/非正 cap 用默认）；SystemSettingServiceTest +6 默认值断言（32/32）；VideoFrameServiceTest +2 crop 护栏（24/24，真 javacv 视频回归全绿）。回归：File 域 70 + Asset 33 + MemoryAssetUpload 11 + DocumentParserInjectionScan 6 = **190 绿 0 失败**。
- **范式沿用**：三处 `@Autowired(required=false) SystemSettingService`（横切可选依赖，null → ImageGuard 默认上限，构造单测不受扰）。

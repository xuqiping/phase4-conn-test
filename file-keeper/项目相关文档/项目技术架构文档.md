# File Keeper 项目技术架构文档

## 1. 项目概述

File Keeper 是一个基于 **Tauri 2 + Vue 3 + TypeScript + Rust** 构建的 Windows 桌面效率工具。项目最初以“常用文件快速访问”为核心，后续扩展出“Windows 应用/进程管理”能力，形成“文件入口 + 应用整理”的轻量工作台。

当前项目主要能力包括：

- 常用文件收藏、打开、分组、标签、搜索、排序、批量操作
- 文件图标提取与懒加载
- 全局快捷键、系统托盘、最小化到托盘
- Windows 运行中应用枚举、分类、筛选、排序、关闭、右键操作
- 本地持久化、主题切换、中英文切换
- Vitest 前端测试与 Tauri/Rust 后端能力封装

项目当前主要面向 Windows 10/11 桌面环境，打包目标为 Windows MSI。

## 2. 总体架构

File Keeper 采用典型 Tauri 桌面应用架构：

```text
┌──────────────────────────────────────┐
│ Vue 3 + TypeScript 前端               │
│ - App.vue 主界面                      │
│ - Pinia 状态管理                      │
│ - 组件/组合式函数/工具函数             │
│ - Tauri invoke API wrapper            │
└───────────────────┬──────────────────┘
                    │ invoke / plugin API
┌───────────────────▼──────────────────┐
│ Tauri 2 Runtime                       │
│ - 窗口管理                            │
│ - 托盘菜单                            │
│ - Store/Dialog/FS/Opener/Shortcut 插件 │
└───────────────────┬──────────────────┘
                    │ Rust command
┌───────────────────▼──────────────────┐
│ Rust 后端                              │
│ - 文件打开/路径校验/显示所在位置        │
│ - 图标提取                            │
│ - 文件占用进程查找与关闭               │
│ - Windows 应用管理                     │
└───────────────────┬──────────────────┘
                    │ Win32/sysinfo/opener
┌───────────────────▼──────────────────┐
│ Windows 系统能力                       │
│ - 文件系统                            │
│ - 默认程序打开                        │
│ - Shell 图标                          │
│ - 窗口枚举与进程信息                   │
│ - WM_CLOSE / SetForegroundWindow       │
└──────────────────────────────────────┘
```

前端负责用户交互、状态组织和界面呈现；后端负责调用系统能力并通过 Tauri command 暴露给前端。

## 4. 前端架构

### 4.1 入口与主应用

- `src/main.ts`
  - 创建 Vue 应用
  - 创建 Pinia 实例
  - 注册自定义持久化插件
  - 引入全局样式
  - 挂载 `App.vue`

- `src/App.vue`
  - 当前项目的主界面容器
  - 负责顶部窗口栏、文件管理页、进程管理页切换
  - 包含文件管理主要交互：搜索、排序、分组、视图切换、拖拽导入、批量操作、右键菜单等
  - 负责系统托盘、窗口关闭拦截、全局快捷键注册等桌面行为

当前没有使用 Vue Router，页面切换由 `App.vue` 内部状态控制。

### 4.2 文件管理模块

文件管理是项目的基础能力，围绕 `FileItem` 数据结构展开。

主要文件：

- `src/types/file.ts`：文件数据结构
- `src/stores/fileStore.ts`：文件列表、搜索、排序、批量操作
- `src/stores/groupStore.ts`：分组管理
- `src/stores/selectionStore.ts`：文件多选状态
- `src/stores/recentStore.ts`：最近打开文件
- `src/components/AddFileButton.vue`：添加文件/文件夹
- `src/components/EditFileDialog.vue`：编辑文件信息
- `src/components/GroupManager.vue`：分组管理弹窗
- `src/components/RecentFiles.vue`：最近文件入口

文件管理核心数据流：

```text
用户操作
  ↓
App.vue / 子组件
  ↓
Pinia Store(fileStore/groupStore/selectionStore)
  ↓
Tauri API(files.ts/icons.ts/persist.ts)
  ↓
Rust command / Tauri plugin
  ↓
本地文件系统 / 默认应用 / Store 文件
```

### 4.3 进程管理模块

进程管理模块是 Windows 独家能力，围绕运行中窗口和进程信息构建。

主要文件：

- `src/types/process.ts`：进程分类、进程信息、列配置、设置结构
- `src/stores/processStore.ts`：进程列表、筛选、排序、选择、关闭
- `src/stores/processSettingsStore.ts`：列配置、自动刷新、确认模式、白名单
- `src/components/ProcessManagement.vue`：进程管理容器
- `src/components/ProcessToolbar.vue`：刷新、自动刷新、多选、批量关闭、列设置
- `src/components/ProcessFilter.vue`：分类筛选
- `src/components/ProcessList.vue`：表头、列表、右键菜单、状态栏
- `src/components/ProcessRow.vue`：单行进程渲染
- `src/components/ColumnSettings.vue`：列显示/拖拽排序设置
- `src/components/ConfirmDialog.vue`：关闭确认弹窗
- `src/components/ToastContainer.vue`：操作反馈

进程管理数据流：

```text
进入进程管理页
  ↓
ProcessManagement.onMounted/onActivated
  ↓
processStore.refresh()
  ↓
api/process.ts -> invoke('get_running_processes')
  ↓
Rust ProcessMonitor 枚举窗口与进程
  ↓
返回 ProcessInfo[]
  ↓
processStore.filteredProcesses
  ↓
ProcessFilter / ProcessList / ProcessRow 渲染
```

关闭进程数据流：

```text
用户点击关闭 / 批量关闭
  ↓
ProcessToolbar 或 ProcessList
  ↓
ProcessManagement 提供确认逻辑
  ↓
processStore.closeProcess / closeSelected
  ↓
api/process.ts -> close_app_process / close_app_processes
  ↓
Rust PostMessageW(hwnd, WM_CLOSE)
  ↓
Toast 成功/失败反馈
```

### 4.4 状态管理

项目使用 Pinia 管理业务状态。

| Store | 主要职责 | 是否持久化 |
|-------|----------|------------|
| `fileStore` | 文件列表、搜索、排序、批量操作 | 是 |
| `groupStore` | 分组列表、当前分组 | 是 |
| `settingsStore` | 主题、语言、快捷键、视图、图标模式 | 是 |
| `recentStore` | 最近打开文件 | 是 |
| `selectionStore` | 文件多选状态 | 否 |
| `processStore` | 运行中进程、筛选、排序、选择、关闭 | 否 |
| `processSettingsStore` | 进程列配置、自动刷新、确认模式、白名单 | 是，localStorage |

### 4.5 组合式函数与工具函数

- `useVirtualScroll.ts`：通用虚拟滚动计算
- `useSortableFiles.ts`：文件排序拖拽封装
- `useIconLazyLoad.ts`：文件图标懒加载队列
- `useToast.ts`：Toast 状态与成功/错误提示
- `useI18n.ts`：轻量 i18n 文案系统
- `utils/file.ts`：文件扩展名与图标、分组解析
- `utils/highlight.ts`：搜索关键词高亮与 HTML 转义
- `utils/batch.ts`：批量操作判定
- `utils/path.ts`：路径与文件名工具

### 4.6 国际化与主题

项目当前提供：

- 中文文案：`src/locales/zh-CN.ts`
- 英文文案：`src/locales/en.ts`
- 语言状态：`useI18n.ts`
- 语言持久化：`localStorage` key `app-locale`

主题由 `settingsStore` 与全局 CSS 变量配合实现，支持亮色、深色和系统模式。

## 5. 后端架构

### 5.1 Tauri 主入口

`src-tauri/src/main.rs` 负责：

- 注册 Tauri 插件
- 注册系统托盘菜单
- 处理托盘点击与退出逻辑
- 注册所有 Tauri command

已注册命令包括：

- 文件管理：`open_file`、`validate_path`、`show_in_folder`
- 文件占用进程：`find_file_processes`、`close_process`、`close_file_processes`
- 图标：`get_file_icon`
- 应用管理：`get_running_processes`、`close_app_process`、`close_app_processes`、`activate_app_window`

### 5.2 文件命令

`src-tauri/src/commands/files.rs` 提供：

- 打开文件或文件夹
- 校验路径是否存在
- 在文件管理器中定位文件

Windows 下 `show_in_folder` 使用 Explorer 的 `/select,` 参数定位具体文件。

### 5.3 图标命令

`src-tauri/src/commands/icons.rs` 提供 `get_file_icon`。

Windows 下通过：

- `SHGetFileInfoW` 获取系统图标句柄
- GDI 绘制图标到位图
- PNG 编码
- Base64 data URL 返回前端

macOS/Linux 当前为降级返回 `None`。

### 5.4 文件占用进程模块

文件占用进程模块用于判断某个文件当前可能被哪些进程使用。

相关文件：

- `src-tauri/src/commands/processes.rs`
- `src-tauri/src/utils/process_matcher.rs`
- `src-tauri/src/platform/windows_file_matcher.rs`
- `src-tauri/src/platform/macos.rs`
- `src-tauri/src/platform/linux.rs`

平台策略：

- Windows：基于窗口标题、进程信息等方式推断
- macOS：使用 `lsof`
- Linux：读取 `/proc/[pid]/fd` 链接

### 5.5 应用管理模块

应用管理模块位于：

- `src-tauri/src/commands/process_management.rs`
- `src-tauri/src/platform/windows/process_monitor.rs`
- `src-tauri/src/platform/windows/process_mappings.rs`
- `src-tauri/src/types/process.rs`

核心流程：

1. 使用 `EnumWindows` 枚举所有顶层窗口
2. 用 `IsWindowVisible` 过滤可见窗口
3. 用 `GetWindowTextW` 获取窗口标题
4. 用 `GetWindowThreadProcessId` 获取 PID
5. 用 `sysinfo` 获取进程名、内存、CPU
6. 用 `process_mappings.rs` 将进程名映射到应用类别
7. 返回 `ProcessInfo[]` 给前端

关闭进程时：

- 对单个窗口调用 `PostMessageW(hwnd, WM_CLOSE)`
- 批量关闭时逐个发送关闭消息并统计成功/失败

窗口激活时：

- 如果窗口最小化，调用 `ShowWindow(SW_RESTORE)`
- 再调用 `SetForegroundWindow` 将其置前

## 9. 当前架构特点

### 9.1 优点

- Tauri 架构使应用体积和资源占用相对轻量
- Vue + Pinia 结构清晰，适合快速迭代桌面 UI
- Rust 后端能直接调用 Windows 系统能力
- 文件管理和进程管理在同一应用内形成差异化组合
- 本地存储优先，隐私和离线能力较好
- 进程管理具备分类、筛选、排序、关闭和确认保护等完整闭环

### 9.2 风险与技术债

- `App.vue` 承担过多职责，文件管理、窗口控制、托盘、快捷键、拖拽、右键菜单等逻辑集中在一个组件内
- 文件占用进程和应用管理进程存在两套相近但不同的后端模型
- 主数据使用 Tauri Store，进程设置和语言使用 localStorage，持久化策略不完全统一
- 应用管理实际强依赖 Windows，但部分文档和依赖中仍保留跨平台表述
- 后端 Rust 命令缺少自动化测试
- 进程关闭基于 `WM_CLOSE`，适合正常关闭窗口，但不等价于强制结束进程

### 9.3 后续优化建议

1. 拆分 `App.vue`：将文件管理页、窗口控制、托盘、快捷键、拖拽导入拆成更小的 feature 组件或 composable。
2. 统一进程模型：梳理文件占用进程和应用管理进程的命名、类型和命令边界。
3. 统一持久化策略：评估是否将 `process-settings` 和 `app-locale` 迁移到 Tauri Store。
4. 补充 Rust 测试：至少覆盖路径校验、进程映射、错误消息转换等纯逻辑。
5. 明确 Windows-only 边界：文档、UI 和代码层面对进程管理功能保持 Windows 限定描述。

---

## 10. 结论

File Keeper 当前已经形成了清晰的桌面效率工具架构：前端以 Vue/Pinia 组织用户交互和状态，后端以 Tauri/Rust 封装系统能力，并通过 Windows API 提供文件、图标和进程相关功能。项目的核心技术亮点不是单一文件管理或单一进程管理，而是把二者结合为一个本地化、轻量、面向真实桌面工作流的效率工作台。

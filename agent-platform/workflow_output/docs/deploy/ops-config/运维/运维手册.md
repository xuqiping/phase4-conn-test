## 二、每周巡检（15 分钟）

- 错误日志趋势：Grafana「安全态势」错误日志面板，环比上周有无新错误类型。
- 慢接口：`接口质量` P95/P99 按 uri 排序，超 2s 的记下来排期优化。
- 备份目录体积：确认保留策略（7 日备 + 4 周备）在正常滚动，磁盘没被备份吃满。
- Windows 服务列表复核：`services.msc` 里 agent-* 服务全部「正在运行 + 自动启动」。

## 五、Runbook

### ① 后端宕机

1. `services.msc` 看 agent-backend 状态；WinSW 有 10 秒崩溃自启，先看它自己拉起来没。
2. 没拉起 → 看日志 `E:\agent-platform\logs\`（wrapper.log 看进程死因，error.log 看应用异常）。
3. 常见死因：DB/Redis 没起（先起 PG 和 Redis 服务）、端口 8080 被占（`netstat -ano | findstr :8080`）、Flyway 迁移失败（日志搜 `FlywayException`，回滚 jar 或人工 repair）。
4. 修复后 `net start agent-backend`，Grafana 确认 UP。

### ② LLM 超时/失败率高

1. 「AI 核心链路」看板看是哪个 provider 在失败。
2. 查该 provider：密钥是否过期（系统设置里重存）、额度是否耗尽、本机能否直连其 API（代理是否该开）。
3. 单 provider 故障可引导用户临时切其他模型；全挂查本机网络。

### ③ 索引队列积压

1. 「AI 核心链路」队列深度面板确认积压趋势。
2. 重启后端即重启 IndexJobWorker：`net restart agent-backend`。
3. 反复积压：查 embedding provider 是否慢/失败（同 runbook ②），或大文件解析卡死（error.log 搜 IndexJobWorker）。

### ④ 线程打满（接口大面积超时）

1. 「系统总览」Tomcat 活跃会话/线程池面板确认打满。
2. 后端日志 `grep io-8080-exec` 看请求堵在哪个 uri（对照速查表 22 章）。
3. 应急：`net restart agent-backend`；根治：定位慢调用（LLM 长连接最常见，确认超时配置）。

## 六、密钥泄露应急（与安全体系衔接）

发现任何密钥泄露（git 误提交、截图外传等）按序执行：

1. **轮换**：DB 密码 / JWT_SECRET / RUNTIME_CALLBACK_TOKEN / 钉钉密钥 / LLM key，逐个换新值。
2. **改配置**：服务器本地 `E:\agent-platform\backend\agent-backend.xml`（env 段）/ `local-dev-env.ps1`，**不改入库文件**。
3. **失效旧 token**：JWT_SECRET 换新后旧 access token 全失效；refresh token 黑名单在 Redis，必要时 `FLUSHDB` 对应库。
4. **重启**：`net restart agent-backend`。
5. **复盘**：git 历史里的密钥用 force-push 清除（须团队确认），并记入安全事件台账。

## 九、备份体系一览（哪个脚本干什么、什么时候跑）

> **脚本放哪**：仓库 `agent-platform/scripts/ops/backup/`（全英文路径——SYSTEM 计划任务解析不了中文路径，实测「系统找不到指定的路径」，故可执行脚本一律放英文目录；这里即运行版即版本化版，随 git 推送）。机密 `backup-env.bat` 同目录但 gitignore 不入库。
> **备份产物放哪**：`D:\backup\agent-platform\`（pg\daily 日备 / pg\weekly 周备 / files\uploads 文件镜像 / logs 日志 / 三个状态标记文件）。

| 脚本 | 备份什么 | 什么时候跑 | 谁触发 | 产物与标记 |
|---|---|---|---|---|
| `backup-pg.bat` | PostgreSQL 全库（pg_dump -Fc 压缩） | **每天 02:00** | 计划任务 `AgentPlatform-PgBackup` | `pg\daily\` 保 7 天；周日那份同时归 `pg\weekly\` 保 4 周；标记 `last-backup-status.txt` |
| `backup-files.bat` | 用户上传文件 uploads\（robocopy /MIR 镜像） | **每天 02:30** | 计划任务 `AgentPlatform-FilesBackup` | `files\uploads\`（镜像：源删则备删）；标记 `last-files-backup-status.txt` |
| `sync-offsite.bat` | 整个 `D:\backup\agent-platform` 增量复制到异地**周快照子目录** | 每周日 04:00（**未注册**） | 待配 OFFSITE_TARGET 后手工注册 | `OFFSITE_TARGET\wk_<时间戳>\`（S5 M5 弃 /MIR 镜像改 point-in-time：只增不删，保最近 8 周防勒索扩散）；标记 `last-offsite-sync-status.txt` |
| Redis | 不单独备 | — | Redis 自带 RDB 默认持久化 | 缓存类数据可重建，丢了不致命 |

- **机密注入**：三个脚本都只读同目录 `backup-env.bat`（DB 密码等），脚本本身零机密。
- **手工立即备一次**：管理员 cmd 直接跑对应 bat 即可，不影响计划任务。
- **查任务状态**：`Win+R` 输 `taskschd.msc` → 任务计划程序库 → 找 AgentPlatform- 开头两项。
- **失败会发钉钉**（webhook 配好后）；每日巡检第 2 项就是看标记文件。

## 十、安全事件应急响应预案（安全体系 S5 · M1，SEC-FR-130）

> 定位：钉钉告警/巡检发现异常后的**统一处置框架**——先分级，再按级走流程。与 §四（告警速查）、§六（密钥泄露，属 P1 特例）衔接。

### 1. 事件分级（P1 最重）

| 级别 | 判定（任一命中） | 响应时限 | 示例 |
|---|---|---|---|
| **P1 严重** | 数据泄露/加密勒索/密钥泄露/后台失陷 | **15 分钟内**响应，**1 小时内**遏制 | 蜜罐+暴破同 IP 相继命中、git 明文密钥外传、库被加密 |
| **P2 高** | 单点入侵迹象但未证实失陷 | 1 小时内响应，当日处置 | 蜜罐命中、refresh 重放检出、注入签名命中 |
| **P3 中** | 可疑但影响面小 | 当日处置 | 异地登录提醒用户确认为本人、单账号暴破锁定 |
| **P4 低** | 噪声/误报 | 周巡检归档 | 扫描器零星 404、单次失败登录 |

### 2. 上报链（一人团队版）

- **P1**：处置同时电话通知业务负责人（不等消息回复）；涉及用户数据 → 评估是否触发对外告知义务。
- **P2/P3**：钉钉群发事件卡（AlertRouter 已自动发）+ 当日在事件台账（security_events 处置页）记处置结论。
- **P4**：仅台账 ack，不打扰。

### 3. 取证保全（遏制前先做，5 分钟内）

1. **断网不关机**：RDP 所在网卡禁用或防火墙封出站（`New-NetFirewallRule -Direction Outbound -Action Block`），保留内存与进程现场——关机即毁证。
2. **快照三件套**：任务列表+网络连接（`tasklist /v`、`netstat -anob` 导出）、安全事件表导出（时间窗内）、日志目录 `logs\` 复制一份到只读位置。
3. **PG 不重启**：重启可能清掉连接溯源线索；先 `SELECT * FROM pg_stat_activity` 导出。

### 4. 沟通模板（对外/对内口径）

- 对内（钉钉）：`【P{n}】{时间} 发现{现象}，影响面{估计}，当前动作{遏制措施}，下次更新{时间}。`
- 对用户（仅 P1 涉数据时，经业务负责人确认后发）：说明范围、处置进展、用户可采取的动作（改密）。**不披露攻击技术细节**。

### 5. 桌面推演 checklist（每季一次，随 §三 演练日做）

- [ ] 抽一个 P2 场景（如蜜罐命中）走一遍上报+台账闭环
- [ ] 断网不关机操作演练（网卡禁用→恢复，验证业务重启路径）
- [ ] 密钥轮换 runbook（§六 5 步）口头复述一遍
- [ ] 备份可回退性确认：`OFFSITE_TARGET` 下 ≥2 个 `wk_*` 快照（M5 语义）

## 十一、修复IX 运维配置增补（2026-08-31）

### 1. 模型思考声明（llm_providers.config jsonb 的 `thinking` 节）

用户侧「🧠 思考」下拉**按声明显隐**：Claude 协议（ANTHROPIC）天生三档免声明；OpenAI 兼容系**不声明=零参数现状**（下拉不显示）。三种写法：

```sql
-- 例1 toggle（Anthropic 兼容开关型）：只显「关/标准」两档，关=thinking.type disabled
UPDATE llm_providers SET config = COALESCE(config,'{}'::jsonb) || '{"thinking":{"style":"toggle"}}'::jsonb WHERE name='供应商名';
-- 例2 effort（reasoning_effort 型，o 系/glm 等）：三档映射 low/medium/high
UPDATE llm_providers SET config = COALESCE(config,'{}'::jsonb) || '{"thinking":{"style":"effort"}}'::jsonb WHERE name='供应商名';
-- 例3 白名单（只对部分模型生效，models 可选）
UPDATE llm_providers SET config = COALESCE(config,'{}'::jsonb) || '{"thinking":{"style":"effort","models":["o3","o4-mini"]}}'::jsonb WHERE name='供应商名';
```

- 声明在 provider 构造时解析一次缓存——改完 config 若前端下拉未变，`net restart agent-backend`。
- 预扣放大系数（标准 ×2 / 深度 ×4）与思考预算（2048/8192）在 `llm.thinking.*` 配置节，可调。
- 用户级自建 provider 同名继承全局行 config，声明一处生效两处。

### 2. 联网搜索部署（Tavily 开关制路由；**dev 现状=零配置**：无任何 `search.*` 行，SearXNG base-url 未配——开了 🌐 全降级回纯模型，不炸）

管理入口：系统设置 → 联网搜索配置（接口 GET/PUT `/api/system/settings/web-search`、POST `/api/system/settings/web-search/test`，权限 role:manage）。key 落 system_settings（AES 加密），总开关 `search.enabled` 默认关。

**路由规则（修复IX+ 起派生，无 provider 手选）**：`search.tavily.enabled` 开 + 已配 key → 走 Tavily；关 / 未配 key / key 运行时失效 → 走自建 SearXNG（builtin）；全失败纯模型作答。配置页「当前路由」标签实时显示。旧 `search.active-provider` 行已废弃不读。

| 路 | 步骤 | 适用 |
|---|---|---|
| **快路 Tavily** | 申请 key（app.tavily.com）→ 配置页粘贴保存 → 开「Tavily 启用」→ 「测试连通」results>0 | 最快上线 |
| **抗封路 SearXNG** | Docker 起实例（见下）→ 后端 env `SEARCH_SEARXNG_BASE_URL=http://127.0.0.1:8888` → 「Tavily 启用」保持关 → 测试连通 | 免 key、抗封 |

SearXNG **必须开 JSON 输出**（默认只 html，搜索会吃 JS 挑战返回空结果）：

```bash
docker run -d --name searxng -p 127.0.0.1:8888:8080 -v ./searxng:/etc/searxng searxng/searxng
# 挂载的 settings.yml 里：search: formats: [html, json]
```

**端到端验证**（测试方案 Q1-Q8）：智能对话 / 画布 chat 开「🌐 联网」问时效题 → 回答带 `[n]` 引用 + 📎 来源可点；关 🌐 纯模型作答。**降级链**：key 错/实例停 → 不报错，AI 正常作答只是无引用；配置页「测试连通」返回 results=0 = key/地址无效（会自动试完 tavily→builtin 全链）。

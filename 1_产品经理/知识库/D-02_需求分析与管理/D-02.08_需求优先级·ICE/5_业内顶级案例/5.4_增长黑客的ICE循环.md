## 增长黑客的ICE循环

### 一、ICE-实验-学习闭环

真正的增长团队不是"用ICE排一次序就结束"，而是建立一个**持续循环**：

```
假设收集 → ICE评分 → 实验实施 → 结果学习 → 校准ICE → 下一轮假设
    ↑                                                    |
    └────────────────────────────────────────────────────┘
```

### 二、校准闭环详解

**Experiment 1-N的结果如何影响下一轮ICE评分？**

| 实验结果类型 | 对下一轮ICE的影响 |
|---|---|
| 成功(Impact>预期) | 同类假设Impact上调；整体Confidence基线上调 |
| 成功(但Impact<预期) | Impact评分校准——高估的来源是什么？ |
| 失败(Impact未达成) | 同类假设Confidence下调；检查"假设逻辑链"哪一环断了 |
| 失败(未完成/技术问题) | Ease评分下调——实际比预想更难 |

### 三、高频实验团队的ICE实践

**典型团队**：每月8-12个实验的增长团队

**ICE运作节奏**：

| 时间 | 活动 | ICE相关 |
|---|---|---|
| 每周一 | Sprint Planning | ICE评分→选Top 3实验 |
| 每日 | 实验运行 | 监控数据 |
| 每周五 | 结果回顾 | 记录实际Impact；标记校准项 |
| 每月末 | 月度校准 | 统计偏差；调整评分基线 |
| 每季度 | 季度复盘 | 更新ICE评分标准；淘汰过时假设 |

### 四、ICE循环的核心指标

| 指标 | 定义 | 健康值 |
|---|---|---|
| 实验胜率 | 成功(统计显著) / 总实验数 | 25-40% |
| Impact偏差 | 平均实际Impact / 平均预估Impact | 0.6-0.8 |
| Confidence校准度 | 实际成功率 / 平均Confidence×10 | 1.0(完美校准) |
| Ease偏差 | 平均实际周期 / 平均预估周期 | 1.0-1.5 |
| 实验吞吐量 | 每月完成实验数 | 8-12 |

### 五、失败：ICE循环断裂的常见原因

| 失败模式 | 症状 | 修复 |
|---|---|---|
| 只评分不校准 | ICE评分长期偏差但从不修正 | 每月强制校准会议 |
| 低胜率仍不调Confidence | Confidence偏高但胜率<15% | 强制校准系数 |
| "大实验"挤压小实验 | Ease低(难做)的实验占用全部资源 | 2周规则：实验必须在2周内部署 |
| 假设枯竭 | 每轮只有3-5个新假设 | 多元化假设来源(数据/用户/竞品/内部) |

### 六、从ICE到增长文化的进阶

ICE不仅是一个评分工具，更是一种**增长文化**的载体：

1. **数据驱动**：ICE的Confidence维度强制团队思考"有什么数据支撑？"
2. **快速验证**：Ease维度鼓励"先做小实验验证假设"
3. **持续学习**：校准闭环让团队不断从结果中学习
4. **共识语言**：ICE提供了一个共同的讨论框架，避免"拍脑袋"争论

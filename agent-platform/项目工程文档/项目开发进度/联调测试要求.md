## 一、需要用户配合提供或确认的数据

### 1. 测试 Agent / Skill 数据

请提供或确认至少一套可用于联调的 Agent 数据：

| 项目 | 要求 | 说明 |
|------|------|------|
| Agent 状态 | `PUBLISHED` | 用于验证普通执行链路 |
| Agent ID | 需要提供 | 工作流 `AGENT_REF` 节点需要引用该 ID |
| Agent 名称 | 需要提供 | 用于执行监控页展示核对 |
| Skill 数量 | 至少 1 个 | AgentRouter 需要能选中可执行 Skill |
| Skill ID | 需要提供 | 工作流 `SKILL` 节点需要引用该 ID |
| Skill Step | 至少 1 个可执行步骤 | 建议使用 `LLM_CALL`，确保能产出可见文本 |

如果当前没有现成数据，可以由开发方通过后台接口或数据库初始化一套临时测试 Agent / Skill。

### 2. LLM Provider 配置

请确认至少一个 LLM Provider 可真实连通：

| 项目 | 要求 | 示例 |
|------|------|------|
| Provider 状态 | 已配置并测试连接成功 | 全局或用户级均可 |
| API Key | 已填写 | 不需要写入本文档 |
| 协议类型 | 与供应商匹配 | `OPENAI_COMPATIBLE` / `ANTHROPIC` |
| 模型 ID | 可用模型 ID | `doubao-seed-2.0-code` |
| 流式输出 | 可正常返回内容 | 用于验证 Skill 内 LLM 调用 |

如需节省真实 API 调用额度，可先使用 mock / 短 prompt 验证 callback 链路，再单独执行一次真实 LLM 验收。

### 3. 联调运行模式与端口

请确认联调时使用的运行地址：

| 配置项 | 默认建议 | 需要确认 |
|--------|----------|----------|
| Java 后端地址 | `http://localhost:8080` | 是 |
| Python sidecar 地址 | `http://localhost:8090` | 是 |
| 前端地址 | `http://localhost:5173` | 是 |
| runtime 网关模式 | `sidecar` | 是 |
| Java callback 地址 | `http://localhost:8080` | 是 |

推荐配置：

```yaml
runtime:
  gateway:
    mode: sidecar
    sidecar-base-url: http://localhost:8090
    java-callback-base-url: http://localhost:8080
```

如果端口或部署地址不同，请在联调前提供实际地址。

## 二、需要用户参与确认的验收场景

### 场景 1：`SKILL` 节点真实执行

| 步骤 | 期望结果 |
|------|----------|
| 创建或打开测试工作流 | 工作流可编辑 |
| 拖入 `SKILL` 节点并配置 Skill ID | 节点保存后 ID 不丢失 |
| 切换 runtime 为 sidecar 模式 | 请求进入 Python sidecar |
| 运行工作流 | `SKILL` 节点触发 Java callback |
| 查看执行监控页 | 可看到节点输出、选中 Skill、步骤输出 |

### 场景 2：`AGENT_REF` 节点真实执行

| 步骤 | 期望结果 |
|------|----------|
| 创建或打开测试工作流 | 工作流可编辑 |
| 拖入 `AGENT_REF` 节点并配置 Agent ID | 节点保存后 Agent 引用不丢失 |
| 运行工作流 | sidecar 回调 Java Agent 执行接口 |
| Java 执行 AgentRouter | 能选出一个或多个 Skill |
| Java 执行 SkillExecutor | 能返回最终输出 |
| 查看执行监控页 | 可看到 Agent 名称、选中 Skill IDs、步骤输出和最终文本 |

### 场景 3：权限校验

| 测试数据 | 期望结果 |
|----------|----------|
| 普通用户执行 `PUBLISHED` Agent | 允许执行 |
| Agent 创建者执行自己的 `DRAFT` Agent | 允许执行 |
| 非创建者执行他人的 `DRAFT` / `OFFLINE` Agent | 拒绝执行 |
| `SKILL` 所属 Agent 不可访问 | 拒绝执行 |

### 场景 4：失败恢复链路

| 步骤 | 期望结果 |
|------|----------|
| 构造失败节点或 callback 失败 | sidecar 输出失败事件 |
| Java 持久化执行日志 | `status=FAILED` |
| 查询恢复信息 | 可看到失败节点、错误信息、checkpoint |
| 执行 retry / resume | 能重新发起执行或从 checkpoint 恢复 |

### 场景 5：前端执行监控展示

| 内容 | 期望结果 |
|------|----------|
| Runtime event timeline | 展示事件类型、节点 ID、状态 |
| Agent 输出 | 展示 Agent 名称和最终输出 |
| Skill 输出 | 展示 selectedSkillIds |
| Step 输出 | 展示每个步骤的 output / error |
| 审批等待 | 展示待审批任务并可 approve / reject |

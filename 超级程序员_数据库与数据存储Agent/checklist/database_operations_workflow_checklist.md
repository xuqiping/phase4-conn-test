# Database Operations Workflow Checklist

在完成 `workflow/database_operations_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别数据库运维/调优需求场景

- [ ] 已明确场景类型（索引优化/慢查询分析/分库分表评估/高可用架构设计/容灾备份策略/数据库迁移/性能调优/故障排查）
- [ ] 已识别数据库类型（MySQL/PostgreSQL/Oracle/SQL Server/国产库/MongoDB/其他）
- [ ] 已提取问题严重性（P0生产故障/P1性能下降/P2预防性优化）
- [ ] 已提取SLA要求（RTO/RPO/可用性目标几个9）
- [ ] 已识别现有架构（单机/主从/集群/已分库分表/云托管RDS）
- [ ] 已提取关键痛点（查询慢/连接数打满/主从延迟大/备份未验证/磁盘告警）
- [ ] 已对照知识库四大运维支柱完成初步判断（索引优化/分库分表/主从复制高可用/容灾备份）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出数据库运维/调优方案

- [ ] 如为索引优化，慢查询定位方法已输出（slow_query_log/Performance Schema/pt-query-digest）
- [ ] 如为索引优化，执行计划解读已覆盖（EXPLAIN各列/type优化目标/Extra警告）
- [ ] 如为索引优化，B+Tree索引原理已说明（聚簇索引/二级索引/覆盖索引/最左前缀/ICP）
- [ ] 如为索引优化，索引设计原则已给出（WHERE/JOIN/ORDER BY/GROUP BY优先/避免冗余/联合索引顺序）
- [ ] 如为索引优化，向量索引（AI场景）已覆盖（IVF/HNSW/DISKANN选型/与关系型库内置向量索引对比）
- [ ] 如为分库分表，触发条件评估已说明（单表>5000万行/单库QPS>1万/磁盘>80%）
- [ ] 如为分库分表，分片策略已覆盖（Hash取模/Range/一致性Hash/分片键选择原则）
- [ ] 如为分库分表，全局ID生成方案已给出（Snowflake/Leaf/UUID避免）
- [ ] 如为分库分表，ShardingSphere中间件架构已说明（ShardingProxy vs ShardingJDBC）
- [ ] 如为分库分表，NewSQL替代评估已覆盖（TiDB/OceanBase vs 传统分库分表）
- [ ] 如为高可用，复制架构选型已说明（异步/半同步after_sync/MGR组复制/Paxos共识）
- [ ] 如为高可用，高可用方案已覆盖（MySQL Orchestrator/MHA/MGR/PostgreSQL Patroni/repmgr）
- [ ] 如为高可用，读写分离已给出（ProxySQL/MaxScale连接池+查询路由+负载均衡）
- [ ] 如为高可用，监控要点已列出（主从延迟/复制线程状态/GTID一致性校验）
- [ ] 如为容灾备份，3-2-1-1-0备份原则已解读（3份副本/2种介质/1份异地/1份离线不可变/0错误）
- [ ] 如为容灾备份，备份策略设计已覆盖（全量/增量/Binlog实时/备份窗口/物理vs逻辑备份）
- [ ] 如为容灾备份，恢复演练方案已输出（季度至少1次/单表→单库→全实例→跨地域/验证RTO/RPO）
- [ ] 如为容灾备份，灾难恢复预案已给出（灾难等级定义/恢复优先级/应急联系人）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 输出内容无知识性错误
- [ ] 已向用户交付最终答案

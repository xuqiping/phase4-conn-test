## Spotify 多端设计

### 背景

Spotify是全球最大音乐流媒体，覆盖Web/桌面App/手机App/平板/智能音箱/车载/手表/TV共8+端，是"跨端体验一致性"的标杆案例 [来源:📚训练知识 | 🔍高]。

### 跨端策略

| 端 | 技术路线 | 优先级 | 设计策略 |
|---|---|---|---|
| 手机App | 原生(iOS/Android) | P0 | 完整功能+触控优化 |
| Web | 响应式Web | P0 | 功能同步+SEO |
| 桌面App | Electron(桌面Web) | P1 | 手机体验的增强版 |
| 平板 | 原生适配 | P1 | 手机×桌面混合布局 |
| 车载 | 专门适配 | P2 | 极简+语音+大触控 |
| 手表 | WatchOS/WearOS | P2 | Glanceable(播放控制) |
| TV | 专门TV App | P2 | 十字导航+遥控器 |
| 音箱 | 语音API | P3 | 纯语音交互 |

### 核心设计原则

1. **播放控制是跨端锚点**：所有端都有一个"当前播放"入口——位置不同但行为一致
2. **信息密度按端调整**：手机1列→平板2列→桌面3列，但每个卡片的视觉语言一致
3. **导航模式按平台习惯**：手机底部Tab / 桌面左侧栏 / TV十字导航——不强制统一
4. **渐进功能暴露**：基础免费功能全端可用 / 高级功能按端能力渐进开放

### PM可学习点

1. **锚点组件先行**：定义"哪些组件在所有端必须存在"（如Spotify的播放控制），再扩展其他
2. **体验一致性≠视觉一致性**：行为一致比像素一致更重要——底部Tab和侧边栏视觉不同但导航逻辑一致
3. **端能力决定功能集**：不是所有功能都要全端覆盖——语音端不需要搜索框，TV端不需要手势

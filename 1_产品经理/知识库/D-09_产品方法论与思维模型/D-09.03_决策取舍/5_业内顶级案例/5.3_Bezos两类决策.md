# Bezos两类决策框架：Type 1 vs Type 2

## 基本信息

- **时间**：2016（致股东信）→ 持续至今
- **主角**：Jeff Bezos / Amazon
- **取舍维度**：可逆性分类 + 满意决策 + 决策速度

## 背景

Amazon高速扩张，但大公司病导致决策越来越慢。Bezos在2015年股东信中提出"Day 2是停滞，跟着是痛苦衰退，跟着是死亡"——Day 1的核心是快速决策。2016年股东信正式提出两类决策框架。

## 两类决策框架

| 维度 | Type 1（不可逆） | Type 2（可逆） |
|---|---|---|
| 性质 | 进了一扇门就回不去 | 进了一扇门还可以退出来 |
| 决策方式 | 慎重思考+充分讨论 | 快速决策+快速试错 |
| 信息需求 | 尽可能充分 | 70%信息就够了 |
| 适用满意决策 | 否（需要更接近Maximizing） | 是（Satisfice即可） |
| 举例 | 进入新市场/重大收购/关停核心业务 | 功能A/B测试/新功能灰度/定价微调 |

## 取舍逻辑

1. **分类先行**：先把决策归入Type 1或Type 2——这本身就是一个关键取舍
2. **Type 2用满意决策**：不追求最优，70%信息就动手——"大多数决策都应该是Type 2"
3. **误分类的代价**：把Type 2当Type 1（过度慎重）→决策速度是Day 2通病；把Type 1当Type 2（过于草率）→不可逆后果
4. **反向验证**：对Type 1决策做Pre-mortem——"如果这个决策是错的，我们怎么发现？能承受后果吗？"

## 影响后果

- Amazon内部推行后，决策速度显著提升——AWS/Alexa/Prime等创新的高速迭代与此框架直接相关 [来源:Amazon股东信/高管访谈 | 🔍高 | 2016-2020]
- 成为硅谷最广泛传播的决策方法论之一

## 教训启示

1. **大部分决策是可逆的**——PM日常90%的决策是Type 2，不必过度分析
2. **分类本身就是取舍**：花5分钟判断"这是Type 1还是Type 2"比花5小时分析一个Type 2决策更有效
3. **AI时代更适用**：AI让试错成本更低→更多决策变为Type 2→可以更快迭代
4. **"不决策"才是最差的决策**：在Type 2决策上拖延的机会成本远大于做错的可逆成本

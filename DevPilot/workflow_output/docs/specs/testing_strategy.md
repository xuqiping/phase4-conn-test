> 上级：[PRD.md](PRD.md)。AC 唯一出处是 [PRD.验收标准.md](PRD.验收标准.md)，本文件的映射表是其执行落点。
> last_updated: 2026-08-13

## 1. 测试金字塔

```
        ╱ 人工验收 ╲        ← 零代码用户路径、观感、双端真机（少而精）
       ╱ E2E 桌面端 ╲       ← WebdriverIO 跑关键路径（~10 条）
      ╱  集成测试    ╲      ← Rust crate 间 + 云端 API 契约
     ╱   单元测试     ╲     ← 塔基：状态机/沙箱/计量/账本（大头在这）
```

**反金字塔警告**：E2E 维护贵，只保关键路径；逻辑优先下沉到 Rust 单测。

## 2. 各层职责

| 层 | 工具 | 覆盖 |
|---|---|---|
| 单元测试 | cargo test（Rust）/ Vitest（前端） | 状态机转移与门禁、沙箱白名单判定、命令审批两档逻辑、Token 预估/对账算法、账本幂等、Skills YAML 解析、大白话模板渲染 |
| 集成测试 | cargo test（testcontainers PG）+ supertest（云端） | 云端 API 契约（§4.1 逐条）、充值回调验签入账、模型网关错误码、本地 SQLite 迁移 |
| E2E 桌面端 | **WebdriverIO + tauri-driver**（测 DevPilot 客户端自身） | 关键路径见 §3；Win/Mac 双端 CI matrix |
| 被测应用冒烟 | **Playwright + 捆绑 Chromium**（测用户项目的产出物，FR-052） | 验收自动项执行 + 截图留证（AC-058）；与上一行职责不同，勿混淆 |
| 性能测试 | 自研脚本 + k6（云端） | 见 performance_goals.md 的验证计划 |
| 安全测试 | cargo audit / npm audit / OWASP ZAP（云端） | 见 security_strategy.md §5 |

## 3. E2E 关键路径（仅保这 10 条）

1. 注册登录 → 领体验金到账
2. 创建项目（选规模 L2）→ 想法访谈 → 报告生成
3. 需求卡确认 → 全部确认前「开工」锁定（AC-034）→ 确认后解锁
4. 开工 → chunk 执行 → 存档点出现 → 叙事流可见
5. diff 大白话⇄原文切换（AC-015）
6. 越界文件访问被拦截并弹审批（AC-001）
7. 存档点回滚成功且不扣 Token（AC-041）
8. 余额不足 → 任务暂停 → 引导充值（AC-045 + 网关 402）
9. 关闭客户端 → 重开恢复到最后状态（AC-052）
10. 验收清单「有问题」→ 圈选 → 生成修复任务（AC-037）

## 6. 覆盖与门槛

- Rust 内核行覆盖 ≥80%（core-state/core-meter/core-sandbox ≥90%，钱和安全不留情面）。
- commit 前必跑 `scripts/check_all`（fmt + clippy + cargo test + vitest + check_docs）。
- CI（.github/workflows/ci.yml）：单测+集成每 PR 跑；E2E 双端每晚跑（Win/Mac matrix）。

## 7. 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| WebdriverIO / tauri-driver | 像机器人一样操作桌面应用界面做自动测试 | 自动点「开工」验证解锁 |
| CI matrix | 同一份测试在 Windows 和 Mac 上各跑一遍 | 双端 nightly |
| 测试金字塔 | 便宜的单测多写，贵的界面测试少写 | 状态机逻辑不进 E2E |
| 契约测试 | 前后端按约定好的接口格式互相验证 | 网关 402 客户端必须识别 |

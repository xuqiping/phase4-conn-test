# Security Compliance Workflow

## Purpose

基于企业安全合规知识体系，为用户提供等保2.0/关保测评、数据安全法/个人信息保护法（PIPL）合规落地、隐私计算技术选型（MPC/联邦学习/同态加密/差分隐私/TEE）、政企安全架构设计（SABSA/零信任/SOC/AI安全五层防护）及DSMM数据安全治理的技术方案支持。覆盖等保2.0取消百分制改三级判定、国密SM2/SM3/SM4强制使用、数据跨境三大路径、隐私计算五大技术路线、NVIDIA H100 FHE秒级延迟、Intel TDX TB级飞地、中型政企投入500-1500万/2-3年等核心数据。

## Prerequisites

- 用户已明确企业安全合规场景或问题
- 知识库文件 `07_网络安全与信息安全.md` 及子目录文件可访问

## Steps

### Step 1: 识别企业安全合规需求场景

**Goal**: 明确用户的合规需求类型、行业属性和数据敏感度
**Completion criterion**: 已确定场景标签、合规框架、数据资产规模和跨境需求

1. 读取用户消息，提取以下信息：
   - 场景类型：等保测评 / 关保合规 / 数据安全法合规 / PIPL合规 / 隐私计算方案 / 政企安全架构 / AI安全合规 / 跨境数据合规
   - 行业属性：金融（银行/证券/保险） / 电信 / 能源 / 医疗 / 政务 / 互联网 / 制造业
   - 数据资产规模：处理个人信息数量（万人级/百万人级/千万级）、数据总量、敏感数据类型（生物识别/金融/健康/行踪轨迹）
   - 跨境需求：是否有数据出境需求（海外业务/云服务/集团内共享）、出境数据类型和量级
   - 现有合规状态：等保级别（未定/二级/三级/四级）、是否有DPO（数据保护官）、是否有数据分类分级
   - 关键痛点：合规成本高 / 测评不通过 / 数据分类分级困难 / 跨境合规路径不明 / AI应用合规盲区 / 国密改造压力

2. 对照知识库中的合规框架初步判断：
   - 未定等保级别+有公网服务 → 等保2.0定级（至少二级、涉及100万+个人信息三级）
   - 数据跨境需求 → 安全评估/标准合同/认证三大路径选择
   - 多方数据协作需求 → 隐私计算（MPC/联邦学习/TEE选型）
   - 大型政企 → SABSA六层+零信任+SOC四层+AI安全五层
   - AI产品上线 → 2026等保AI扩展要求（AI-BOM/输入过滤/推理隔离/输出DLP）

3. 如有信息缺失，向用户追问不超过2个澄清问题。

### Step 2: 输出企业安全合规方案

**Goal**: 产出针对性的合规体系建设、隐私计算方案或安全架构设计
**Completion criterion**: 输出包含合规框架、技术措施、实施路径、投入估算

根据Step 1确定的场景，按以下分支处理：

**分支A — 等保2.0与关保合规**：
1. 输出等保2.0核心框架：
   - 定级方法SAG：S1识别受侵害客体（国家安全/社会秩序/公共利益/公民合法权益）→ A判定侵害程度（一般损害/严重损害/特别严重损害）→ G查表定级（二级/三级/四级/五级），涉及100万+个人信息至少三级
   - 2025版测评变化：取消百分制改为"符合/基本符合/不符合"三级判定、引入"重大风险隐患"概念（存在即判不合规）、新增AI扩展要求
   - "一个中心、三重防护"框架：安全通信网络（四区三层架构：互联网接入区/DMZ区/核心业务区/管理区）+ 安全区域边界（五层边界防护：物理隔离/网络隔离/主机隔离/应用隔离/数据隔离）+ 安全计算环境（基线加固+EDR+容器安全+可信计算）+ 安全管理中心（SOC+日志6个月留存+SOAR自动化）
   - 国密要求：三级及以上系统身份鉴别/传输加密/存储加密未用国密（SM2/SM3/SM4）即判高风险。SM2（非对称加密/签名）、SM3（哈希）、SM4（对称加密）
2. 给出关保（关键信息基础设施）要求：
   - 认定标准：公共通信/能源/交通/水利/金融/公共服务/电子政务/国防科技工业等重要行业
   - 特殊要求：年度网络安全检测评估（比等保更严格）、供应链安全审查、数据本地化存储、优先使用可信可控产品
   - 2026年新修订《网络安全法》：扩大义务主体至SaaS平台和工业互联网终端、罚款上限提至营业额5%
3. 输出测评准备与整改：
   - 差距分析：对照等保要求逐项评估现状（已满足/部分满足/不满足）、识别高风险项（直接判不合格项）
   - 整改优先级：P0（高风险项，必须整改）→ P1（一般项，建议整改）→ P2（提升项，可选）
   - 技术整改：边界防护（防火墙/WAF/IPS）、身份认证（多因素认证+国密）、访问控制（RBAC+最小权限）、审计日志（6个月留存+防篡改）、数据加密（传输TLS1.3+存储AES-256-GCM+国密SM2/SM4）、备份恢复（3-2-1-1-0原则）
   - 管理整改：安全管理制度、安全组织机构、人员安全管理、安全建设管理、安全运维管理
   - 测评流程：定级备案→差距分析→整改建设→测评申请→现场测评→整改复测→出具报告→公安机关备案
4. 附投入参考：中型政企500-1500万/2-3年，大型政企3000万-1亿/3-5年，中小企业MSS托管20-60万/年。

**分支B — 数据安全法与PIPL合规**：
1. 输出数据安全法合规要点：
   - 数据三级分级：一般数据（可公开/低风险）、重要数据（一旦泄露危害国家安全/经济运行/社会稳定/公共利益，须申报）、核心数据（关系国家安全，原则上禁止出境）
   - 数据分类分级三步法：资产梳理（全量数据资产盘点）→ 分类（业务维度/安全维度/管理维度）→ 分级（影响对象+影响程度→一般/重要/核心），配合正则+字典+NLP/ML三层叠加识别，头部机构准确率达98.5%
   - 全生命周期安全：采集（最小必要+告知同意）→ 传输（加密通道+完整性校验）→ 存储（加密+访问控制+备份）→ 使用（脱敏+审计+权限控制）→ 交换（安全评估+合同约束）→ 销毁（不可恢复删除）
2. 输出PIPL（个人信息保护法）合规要点：
   - 七大原则：合法正当必要诚信、明确合理目的、最小必要、公开透明、告知同意、质量保证、安全保障
   - 核心要求：告知同意（处理前告知目的/方式/范围并获得同意）、最小必要（仅收集实现目的最小范围）、敏感个人信息（生物识别/宗教信仰/特定身份/医疗健康/金融账户/行踪轨迹/不满14周岁未成年人信息，需单独同意+特定目的+影响评估）
   - 合规审计：100万人以上处理者须每年开展合规审计并设DPO（数据保护官），审计内容覆盖数据收集/使用/存储/共享/删除全链路
   - 个人权利保障：知情权、决定权（撤回同意）、查阅复制权、可携带权（结构化通用格式）、更正补充权、删除权（特定情形）、解释说明权
3. 输出数据跨境合规三大路径：
   - 路径一：安全评估（国家网信办，适用100万人以上个人信息或1万人以上敏感个人信息出境、重要数据出境）、申报材料（出境数据详情/接收方安全保障能力/出境必要性论证/出境后风险自评估报告）
   - 路径二：标准合同（网信办模板合同，适用<100万人个人信息且<1万人敏感个人信息出境）、双方签署+省级网信办备案
   - 路径三：个人信息保护认证（专业认证机构，适用集团内部数据共享、同一经济实体内部），2026年新增路径
   - 豁免场景：自由贸易港负面清单外数据（海南自贸港/上海自贸区）、学术研究/司法协助/人权保障、跨境贸易/学术合作/生产制造必需数据
4. 附数据安全治理DSMM六域闭环：
   - 采集安全（数据源可信、最小采集、告知同意）→ 传输安全（加密通道、完整性保护、链路冗余）→ 存储安全（加密存储、访问控制、备份策略）→ 使用安全（脱敏、权限最小化、审计日志）→ 交换安全（评估审批、合同约束、溯源追踪）→ 销毁安全（不可恢复删除、销毁审计、残余数据检测）

**分支C — 隐私计算技术选型**：
1. 输出五大技术路线对比：
   - MPC（安全多方计算）：多方联合计算而不泄露原始数据、适合精确统计/联合查询/联合建模、通信开销大（数据量越大越慢）、数学基础复杂（同态加密/秘密分享/混淆电路）、代表项目：Privasea（AI驱动MPC）、ABY3框架
   - 联邦学习（Federated Learning）：数据不出域、模型参数聚合（而非原始数据交换）、适合跨机构联合建模（金融风控/医疗诊断）、通信开销中等（传输模型参数）、存在梯度泄露风险（需差分隐私保护）、代表框架：FATE（微众银行开源）、PySyft（OpenMined）、TensorFlow Federated
   - 同态加密（Homomorphic Encryption）：密文上直接计算（无需解密）、适合加密搜索/梯度保护/隐私查询、计算开销极大（1000-1000000倍慢）、代表方案：CKKS（浮点数同态）、BFV/BGV（整数同态）、NVIDIA H100将FHE延迟降至秒级（GPU加速同态加密）
   - 差分隐私（Differential Privacy）：向数据/查询结果添加可控噪声、保护个体隐私同时保持群体统计特征、适合统计发布/ML训练（隐私预算管理）、噪声影响精度（epsilon越小隐私越强但精度越低）、代表工具：Google DP Library、Microsoft WhiteNoise、OpenDP
   - TEE（可信执行环境）：硬件隔离安全区域（CPU内安全飞地）、适合云上敏感计算、性能损耗低（10-20%）、但存在侧信道攻击风险（需防侧信道加固）、代表方案：Intel TDX（飞地内存从256MB升至TB级）、Intel SGX、AMD SEV-SNP、ARM TrustZone、华为TrustZone
2. 给出选型决策矩阵：
   - 高合规高敏感+云上计算 → TEE（性能损耗低、硬件隔离强）
   - 跨多方高维数据联合建模 → 联邦学习（数据不出域、建模效果好）
   - 精确数值计算（如财务报表合并）→ MPC（精确结果、可验证）
   - 统计发布/聚合查询（如人口统计）→ 差分隐私（简单部署、数学保证）
   - 加密搜索/隐私查询 → 同态加密（搜索加密数据库）
   - 混合方案：联邦学习+差分隐私（梯度保护+隐私预算）、MPC+TEE（计算在安全飞地中执行）
3. 输出数据脱敏方案：
   - 静态脱敏（SDD）：用于测试/开发/归档环境，全量数据脱敏后导出，不可逆（Hash/置换/加密/截断），适合大批量数据分发
   - 动态脱敏（DDM）：查询时实时脱敏，支持"角色×场景×字段×时间"四维策略矩阵，可逆（基于策略的动态替换），适合生产环境查询脱敏
   - 脱敏技术：Hash（不可逆，适合唯一标识）、Masking（部分遮蔽，如手机号138****1234）、Tokenization（令牌替换，保留格式）、加密（可逆，需密钥管理）、泛化（年龄→年龄段、地址→区县级）、扰动（差分隐私噪声）
   - 合规要求：金融数据脱敏（银保监会要求）、医疗数据脱敏（患者隐私保护）、政务数据脱敏（个人信息保护）
4. 附隐私计算部署架构：
   - 两方MPC：数据方A+数据方B+协调方（可选），通过安全信道交换密文片段，计算结果双方共享
   - 联邦学习：各参与方本地训练→梯度/参数上传至聚合服务器→聚合后下发更新→循环直至收敛，聚合服务器不可见原始数据
   - TEE计算：敏感数据加载至TEE飞地→在飞地内解密计算→结果加密后输出，飞地外全程加密

**分支D — 政企安全架构设计**：
1. 输出SABSA六层模型：
   - L1 业务上下文：业务目标/价值流/利益相关者/风险容忍度
   - L2 概念架构：安全域划分/信任边界/安全服务目录
   - L3 逻辑架构：安全机制（认证/授权/加密/审计/监控）/安全策略/安全标准
   - L4 物理架构：安全设备部署（防火墙位置/WAF部署/IDS节点/VPN网关）、网络拓扑安全设计
   - L5 组件架构：安全产品选型（厂商/型号/配置）、接口规范、集成方案
   - L6 运营架构：安全运营流程（SOC/SIEM/SOAR）、人员组织、KPI度量、持续改进
   - AI安全扩展：在六层基础上增加AI安全维度（AI模型安全/训练数据安全/推理安全/输出安全/Agent审计）
2. 给出零信任架构三步构建：
   - Step 1 IAM统一身份：身份提供者（IdP，如Azure AD/Okta/Keycloak）、多因素认证（MFA）、单点登录（SSO）、身份生命周期管理（入职/转岗/离职自动权限调整）
   - Step 2 SASE网络重构：SD-WAN（软件定义广域网，替代传统MPLS）、CASB（云访问安全代理，监控SaaS使用）、SWG（安全Web网关，过滤恶意网站）、ZTNA（零信任网络访问，替代VPN，基于身份的细粒度访问）
   - Step 3 XDR智能运营：跨域检测响应（端点+网络+云+身份统一分析）、AI威胁检测（UEBA行为分析+ML异常检测）、自动响应（SOAR Playbook自动遏制）
   - 五维动态授权：用户×设备×应用×数据×实时风险（每次访问动态评估风险分数，风险高→加强认证/限制访问/阻断）
3. 输出SOC四层金字塔：
   - L1 采集层：全量日志采集（Syslog/Beats/eBPF/API/SNMP）、威胁情报富化（IP信誉/域名信誉/文件哈希）、数据标准化（统一Schema）
   - L2 检测层：规则关联（Sigma规则/YARA规则/Suricata规则）、ML异常检测（UEBA用户行为分析/网络流量异常）、ATT&CK威胁狩猎（主动搜索IOC/IOA）、AI大模型分析（自然语言查询威胁数据）
   - L3 响应层：告警分级（P1紧急/P2高/P3中/P4低）、SOAR自动响应（ containment/隔离/阻断/取证Playbook）、工单流转（JIRA/ServiceNow集成）、案例管理（事件追踪/证据链/报告生成）
   - L4 度量层：MTTD（平均检测时间，目标<1小时）、MTTR（平均响应时间，目标<4小时）、MTTC（平均遏制时间，目标<30分钟）、告警噪音比（真实威胁告警/总告警比例）、漏洞修复率（SLA内修复比例）
   - 升级路径：基础检测（SIEM，MTTD<4h）→ 智能分析（AI+UEBA，MTTD<1h）→ 自治运营（AI大模型+SOAR全自动，MTTD<15min）
4. 输出AI安全五层防护（2026等保AI扩展要求）：
   - L1 输入过滤：Prompt注入检测（敏感词/模式匹配/语义分析）、输入消毒（去除越狱指令/恶意载荷）、速率限制（防止提示词耗尽攻击）
   - L2 模型安全（AI-BOM）：AI模型物料清单（训练数据来源/模型版本/超参数/评估指标）、模型完整性校验（哈希签名）、对抗样本防御（输入扰动检测/鲁棒性训练）
   - L3 推理隔离：推理环境隔离（容器/K8s Namespace/VM）、资源限制（防止资源耗尽攻击）、模型沙箱（限制模型访问外部资源）
   - L4 输出DLP：输出内容审核（敏感信息泄露/毒性/偏见/版权）、幻觉检测（事实性校验/引用溯源）、输出限制（禁止生成恶意代码/攻击载荷）
   - L5 Agent审计：Agent行为日志（工具调用记录/参数/结果）、决策审计（推理过程可追溯）、权限边界（Agent只能访问授权工具/数据）、人类监督（关键操作需人工确认）

将结果保存到 `output/security_compliance.md` 或直接在对话中呈现。

### Step 3: 验证与交付

**Goal**: 确保合规方案符合中国法规要求、与知识库一致
**Completion criterion**: 已通过 checklist 逐项核对

1. 读取 `checklist/security_compliance_workflow_checklist.md`。
2. 逐项核对输出是否覆盖要求的知识点。
3. 确认法规引用（等保2.0/数据安全法/PIPL/关保）准确。
4. 如有遗漏或偏差，补充修正。
5. 向用户交付最终答案。

# Message Queue Middleware Workflow

## Purpose

基于消息队列中间件知识体系，为用户提供消息队列选型（RabbitMQ/RocketMQ/Kafka/Pulsar）、架构设计、工程实践（幂等/可靠投递/大消息处理）、迁移方案或创业选型策略的技术支持。覆盖AMQP协议、事务消息、KRaft架构、计算存储分离等核心技术。

## Prerequisites

- 用户已明确消息队列场景或问题
- 知识库文件 `02_网络架构与中间件.md` 及子目录文件可访问

## Steps

### Step 1: 识别消息队列需求场景

**Goal**: 明确用户的MQ需求类型、吞吐量要求和可靠性等级
**Completion criterion**: 已确定场景标签、吞吐量等级、可靠性要求和团队现状

1. 读取用户消息，提取以下信息：
   - 场景类型：MQ选型 / 架构设计 / 工程实践（幂等/可靠投递/大消息） / 集群迁移 / 创业选型
   - 应用类型：微服务事件总线 / 大数据流处理 / 金融交易 / SaaS多租户 / 轻量异步通知
   - 吞吐量要求：低（<1万TPS）/ 中（1-10万TPS）/ 高（>10万TPS）/ 超高速日志流
   - 可靠性要求：允许少量丢失（日志/监控）/ 不丢失但可重复（普通业务）/ 金融级精确一次（交易）
   - 团队现状：已有MQ集群（需要迁移/升级）/ 全新选型 / 云托管偏好

2. 对照知识库中的四大产品定位初步判断候选MQ：
   - 大数据流处理 → Kafka（KRaft去ZK、分层存储、流处理生态）
   - 金融交易/强可靠 → RocketMQ（事务消息、国内主流）或 Pulsar（Geo-Replication）
   - 微服务事件总线/路由灵活 → RabbitMQ（AMQP协议、Exchange路由）或 Pulsar
   - SaaS多租户 → Pulsar（计算存储分离、原生多租户）
   - 轻量异步/快速上手 → Redis Stream / NATS（非知识库重点但可提及）

3. 如有信息缺失，向用户追问不超过2个澄清问题。

### Step 2: 输出消息队列方案

**Goal**: 产出针对性的MQ选型、架构或工程实践方案
**Completion criterion**: 输出包含推荐MQ、架构拓扑、关键配置、工程实践要点、风险预案

根据Step 1确定的场景，按以下分支处理：

**分支A — MQ选型**：
1. 用9维评估法对候选MQ加权打分：吞吐/延迟/持久性/顺序性/多租户/协议/生态/成本/团队熟悉度。
2. 输出选型对比表（RabbitMQ/RocketMQ/Kafka/Pulsar），每个维度给出评分和理由。
3. 给出最终推荐并附决策树（如"金融交易+国内部署 → RocketMQ；大数据流处理+海外 → Kafka；SaaS多租户+全球化 → Pulsar"）。

**分支B — 架构设计**：
1. 输出集群拓扑：Broker部署模式（单机/主从/集群/分层存储）、Zookeeper vs KRaft（Kafka）、Proxy架构（RocketMQ 5.0）。
2. 给出Topic/Queue设计规范：命名规范、分区策略（按业务键/轮询/随机）、副本数建议。
3. 输出消费者组设计：消费模式（集群消费/广播消费）、重试策略（阶梯退避/死信队列）、消费位点管理。
4. 附跨地域/Geo-Replication方案（如适用）。

**分支C — 工程实践**：
1. **幂等性**：输出消费者幂等设计模板——唯一ID（业务ID/TraceID）+ 去重表（Redis SET/DB唯一索引）+ 业务状态机校验。
2. **可靠投递**：输出生产者端Confirm/ACK机制配置、事务消息（RocketMQ/Pulsar）使用场景、本地消息表+补偿机制方案。
3. **大消息处理**：输出大消息拆分策略、对象存储+MQ传引用ID方案、消息大小限制配置。
4. **监控告警**：输出Consumer Lag监控阈值、消息堆积告警规则、生产者失败率告警。

**分支D — 迁移方案**：
1. 输出双写灰度迁移三步法：双写（新老集群同时生产）→ Consumer切流（灰度切换消费端）→ 下线老集群。
2. 给出数据一致性校验方案：消息对账、MD5校验、延迟对账补偿。
3. 附回滚预案：切流异常时的快速回切方案。

将结果保存到 `output/mq_architecture.md` 或直接在对话中呈现。

### Step 3: 验证与交付

**Goal**: 确保MQ方案在生产环境可行、与知识库一致
**Completion criterion**: 已通过 checklist 逐项核对

1. 读取 `checklist/message_queue_workflow_checklist.md`。
2. 逐项核对输出是否覆盖要求的知识点。
3. 确认所有关键论断均能在知识库中找到支撑。
4. 如有遗漏或偏差，补充修正。
5. 向用户交付最终答案。

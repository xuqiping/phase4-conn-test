# Office 效率增强开发进度 13

> 记录日期：2026-08-26。范围是统一安全底座 Chunk 6：系统凭据保险库。自动化测试与真实平台验证按用户要求留到 Phase 4。

## 1. 跨平台保险库

- `office/credentials.rs` 定义统一服务与保险库接口；生产实现按目标系统路由到 Windows Credential Manager、macOS Keychain 或 Linux Secret Service。
- 平台适配基于 `keyring 2.3.3`，条目 service 固定，username 只包含 `office:<bindingId>`，不把文件路径或密码放进保险库索引名。
- 系统保险库不可用、条目不存在、编码异常和读写删除失败均转换为稳定 Office 错误码；底层错误文本不进入上层错误或日志。

## 2. 文件变化阻止

- 保存前规范化真实路径并计算文件大小、修改时间和 SHA-256；再将路径身份与文件指纹生成不可逆 bindingId。
- 保存后再次计算 bindingId；文件在保存期间变化时删除本次条目并返回 `OFFICE_CREDENTIAL_STALE`。
- 读取前后各复核一次 bindingId；旧引用无法读取变化后的文件密码，用户必须重新确认并保存。
- 删除按不含路径的 `OfficeCredentialReference` 执行，供 Chunk 7 设置页接入。

## 3. 内存与并发安全

- `OfficePassword` 不实现 Clone/Serialize/Display，Debug 固定为 `<redacted>`，释放时由 `Zeroizing<String>` 清零。
- 凭据服务串行化同一服务实例内的保险库访问，避免 Windows 等平台对同一条目并发读写时出现重排。
- SQLite、任务模型和日志未新增任何密码字段，也没有明文回退存储。

# Information System Standards Workflow

## Purpose

基于信息系统建设规范知识框架，提供信息系统建设全流程国标的落地执行路径，覆盖系统规划、分析、设计、实施、验收、运维六大阶段的标准要求。

## Prerequisites

- 已明确信息系统类型（政务/企业/通信/金融）
- 已了解适用的国标基线（GB/T 8566/GB/T 8567等）

## Steps

### Step 1: 系统规划阶段标准化

**Goal**: 依据国标要求完成信息系统建设的可行性研究与总体规划，输出符合规范的规划文档
**Completion criterion**: 《系统规划报告》通过评审，包含国标要求的全部要素（目标/范围/约束/资源/风险/进度）

依据信息系统建设规范 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 信息系统建设全流程国标]：
1. 现状分析：梳理现有系统架构、数据资产、业务流程、技术债务
2. 需求初步识别：区分功能性需求与非功能性需求（性能/安全/可靠性/可扩展性）
3. 可行性分析：技术可行性（技术栈成熟度）、经济可行性（ROI/CBA分析）、法律可行性（合规要求）
4. 总体规划：定义系统边界、里程碑、预算、组织架构、风险登记册
5. 国标对齐：确保规划文档格式符合GB/T 8567《计算机软件文档编制规范》中的"项目开发计划"章节要求
输出：《系统规划报告》+ 《可行性研究报告》+ 《项目开发计划》

### Step 2: 系统分析阶段标准化

**Goal**: 完成需求分析与系统规格说明，建立需求追溯矩阵，确保需求可验证、可追踪
**Completion criterion**: 《需求规格说明书》通过评审，每条需求有唯一ID、优先级、验收标准、追溯来源

参考国标系统分析要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 系统分析阶段]：
1. 需求获取：采用访谈/问卷/观察/原型法收集干系人需求，区分业务需求/用户需求/系统需求
2. 需求分析：使用用例建模/业务流程建模/数据流图（DFD）进行结构化分析
3. 需求规格化：按GB/T 8567编写《软件需求规格说明书》（SRS），包含：
   - 功能需求：用例描述+输入/处理/输出
   - 非功能需求：性能指标（TPS/延迟/并发）、安全需求（等保级别/认证方式）、可靠性（可用性百分比）
   - 外部接口：硬件/软件/通信/用户接口
4. 需求验证：评审会+原型确认+需求测试（需求可测试性检查）
5. 需求管理：建立需求追溯矩阵（RTM），每条需求关联设计元素、代码模块、测试用例
输出：《软件需求规格说明书》+ 《需求追溯矩阵》+ 《需求评审记录》

### Step 3: 系统设计阶段标准化

**Goal**: 完成概要设计与详细设计，架构设计符合可扩展、可维护、安全、性能要求
**Completion criterion**: 《设计说明书》通过评审，包含架构图、接口定义、数据库设计、安全设计、部署设计

依据国标设计阶段要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 系统设计阶段]：
1. 概要设计（HLD）：
   - 系统架构：分层架构/微服务架构/中台架构选型与 rationale
   - 模块划分：高内聚低耦合，每个模块有明确接口契约
   - 数据设计：ER图+数据字典+主外键关系+分区策略
   - 接口设计：RESTful API/OpenAPI规范/消息队列Topic定义
2. 详细设计（LLD）：
   - 模块内部算法与数据结构
   - 状态机/活动图描述复杂业务流程
   - 异常处理策略与降级预案
3. 安全设计：按等保2.0"一个中心三重防护"设计安全架构
4. 性能设计：缓存策略/异步处理/读写分离/分库分表/限流熔断
5. 国标对齐：设计文档符合GB/T 8567《设计说明书》章节结构
输出：《概要设计说明书》+ 《详细设计说明书》+ 《接口设计文档》+ 《安全设计专篇》

### Step 4: 系统实施阶段标准化

**Goal**: 依据设计文档进行编码、单元测试、集成测试，确保代码质量符合国标质量模型要求
**Completion criterion**: 代码审查通过率100%，单元测试覆盖率≥80%，集成测试通过率100%，静态扫描高危问题清零

参考国标实施阶段要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 系统实施阶段]：
1. 编码规范：制定或选用编码规范（Google Style/Alibaba Java手册/PEP 8），配置CI自动检查
2. 版本控制：Git工作流实施，分支保护，Commit Message规范（Conventional Commits）
3. 单元测试：JUnit/pytest/Jest，核心逻辑覆盖率≥80%，边界条件全覆盖
4. 代码审查：至少1人审查+安全扫描（SonarQube/Snyk），审查清单包含逻辑正确性/性能/安全/可读性
5. 集成测试：接口契约测试（Pact/Postman Collection）、数据一致性测试、异常流测试
6. 文档同步：更新《数据库设计说明书》《接口设计文档》与实际代码保持一致
输出：《源代码》+ 《单元测试报告》+ 《代码审查报告》+ 《集成测试报告》

### Step 5: 系统验收阶段标准化

**Goal**: 依据国标完成系统验收，包括功能验收、性能验收、安全验收、文档验收
**Completion criterion**: 验收测试通过率100%，性能指标达到设计目标，等保测评/密评（如需）通过，交付物清单完整

依据国标验收阶段要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 系统验收阶段]：
1. 验收准备：编制《验收测试计划》，明确测试范围/方法/环境/通过标准
2. 功能验收：依据SRS逐条验证需求，缺陷等级定义（致命/严重/一般/建议），致命/严重缺陷清零方可验收
3. 性能验收：压力测试（目标并发×1.5倍）、稳定性测试（7×24小时）、容量测试（数据量达到设计上限）
4. 安全验收：渗透测试（OWASP Top 10覆盖）、代码审计、等保测评/密评（如属关基或政务系统）
5. 文档验收：交付物清单对照GB/T 8567，确保14类文档齐全（可行性研究/项目计划/需求/设计/测试/验收/运维等）
6. 验收会议：输出《验收报告》，各方签字确认，遗留问题有整改计划与责任人
输出：《验收测试计划》+ 《验收测试报告》+ 《验收会议纪要》+ 《遗留问题跟踪表》

### Step 6: 系统运维阶段标准化

**Goal**: 建立运维体系，确保系统持续稳定运行，运维文档与监控体系完备
**Completion criterion**: 监控覆盖率100%，SLA达标（如99.9%可用性），故障响应时间符合约定，运维手册已移交

参考国标运维阶段要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 系统运维阶段]：
1. 运维文档移交：《系统运维手册》《故障处理指南》《备份恢复方案》《应急预案》
2. 监控体系：基础设施监控（CPU/内存/磁盘/网络）+ 应用监控（APM/日志/链路追踪）+ 业务监控（核心指标Dashboard）
3. 备份策略：全量备份（周）+ 增量备份（日）+ 异地容灾备份，定期恢复演练（每季度）
4. 变更管理：所有生产变更需变更单+影响评估+回滚方案+窗口期+验证步骤
5. 问题管理：事件分级（P1生产故障15分钟响应/P2一般故障2小时/P3咨询24小时），根因分析（RCA）+ 改进措施
6. 持续优化：定期容量规划（月度）、性能调优（季度）、安全加固（漏洞修复周期）
输出：《系统运维手册》+ 《监控配置清单》+ 《SLA服务等级协议》

## Post-Workflow

1. 读取 `checklist/info_system_standards_workflow_checklist.md`
2. 交叉验证每个阶段交付物、每项国标对齐要求
3. 全部通过后输出《信息系统建设规范总纲》并归档

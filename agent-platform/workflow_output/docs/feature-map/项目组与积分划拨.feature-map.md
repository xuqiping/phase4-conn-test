## 关键调用链

```
提交带 gid: 入口 view → api(xxxRequest.projectGroupId) → controller 透传 → task/log 落 gid
同步扣费:   LlmBillingService.charge → gid? → WalletService.chargeGroup
            （条件 UPDATE 组池 + used 累加 + ledger CONSUME 行, 幂等键）
异步媒体:   submit(三重预检+估价快照) → worker 完成 → MediaBillingService.chargeMedia
            → gid? → chargeGroup → 组池尽? → backstop(组长个人补差+BACKSTOP 行)
            失败 → refundMedia → refundGroup（组池+used 回滚, REFUND 行）
划拨回收:   ProjectGroupsView 弹窗 → allocate/reclaim → 个人↔组池 条件 UPDATE 双记账
查询:       ProjectGroupsView → overview(组长)/outputs(全员或self) → 批查补名
邀请(17x#3): 组长 POST /{id}/members → invite PENDING + 通知 invitee → invitee accept(条件UPDATE)
            → insertMemberRow + 通知 inviter；decline/cancel 同样抢态（0行=409）
公共池(17x#4): publish(public_pool=true) → 全员 GET /pool 可见 → apply(PENDING, 部分唯一索引防重)
            → owner decide: approve→落成员行(quota NULL)+通知 / reject→30天冷却
            → unpublish: public_pool=false + 级联 PENDING→REVOKED + 逐个通知
可见性(17x#2): effectiveVisibility=overrides[kind] ?? base；canSeeOutput=admin||组长||本人||ALL
产出文件(17x#1): GET /api/files/{id} → FileStorageService owner 校验失败 → grantor 链
            → ProjectGroupFileAccessGrantor → 反查 media_gen_tasks(video=resultFileId 精确 /
            image=result_meta LIKE+解析复核) → 组 membership + canSeeOutput → 放行
```

## 表与 SQL 注解（Flyway V133/V134/V138）

- **V138__project_group_sharing.sql**（17x#1-#4）：
  - `project_groups` +3 列：`member_output_visibility`(OWN/ALL 默认 OWN)、`module_visibility_overrides`(jsonb 稀疏覆盖)、`public_pool/public_published_by/public_published_at`。**比喻**=组长在工牌上写「作业互相看不看、哪几科能看」+「公告栏贴没贴招募」。
  - `project_group_invites`：邀请表（status PENDING/ACCEPTED/DECLINED/CANCELED + decided_at；`uk_pgi_pending` 部分唯一索引只锁 PENDING）。**比喻**=请帖簿，没点头的请帖不许重发。
  - `project_group_join_requests`：入组申请表（status PENDING/APPROVED/REJECTED/REVOKED + decided_by/at；`uk_pgjr_pending` 同理）。**比喻**=报名簿，撤出公告栏时未批的全盖「作废」。
  - `memory_notifications` CHECK 重建 +4 类型（GROUP_INVITE/GROUP_INVITE_RESULT/GROUP_JOIN_REQUEST/GROUP_JOIN_RESULT，V81 先例：PG 不支持 ALTER CONSTRAINT 加值，DROP 再 ADD）。
- **V133__project_group.sql**（已执行不可改，改结构出新版本）：
  - `project_groups`：组主表。**生活比喻**=项目组的「工牌」——名字、描述、组长是谁。
  - `project_group_members`：成员表（group_id+user_id 唯一，quota_limit_points 可空=不限，used_points 记已用）。**比喻**=组员的「饭卡额度」——卡上限多少、已刷多少。
  - `project_group_wallets`：组池余额（一表一行组）。**比喻**=组的「公共钱包」，只有组长能存取。
  - `project_group_ledger`：append-only 流水（type/delta_points/**balance_after**/ref_type/ref_id），(group_id, created_at) 索引。**比喻**=钱包的「流水小票」，只许贴新不许撕旧，每张都写当时余额——对账就靠它。
  - `llm_usage_logs.project_group_id`、`media_gen_tasks.project_group_id/estimated_cost` 加列：**比喻**=账单和任务单上加「哪个组报销」栏；estimated_cost=提交时估价小票，回收封顶就扣它。
- **V134**：权限码 `project-group:manage` 种子+默认角色分配。**比喻**=发「能进项目组功能」的门禁卡。

## 踩坑批注

- **通知 CHECK 重建先查实库（2026-08-21）**：V138 重建 `memory_notifications_type_check` 首次 23514 失败——新列表必须覆盖**实库现存全部 type 值**（`SELECT DISTINCT type` 先查），缺一个整迁移回滚。
- **流式裸线程无上下文（9x#7）**：chat_completed 审计在 doStream 的 raw thread 落库，MDC/SecurityContext 皆空，username 须按 userId 反查；任何「线程里自动有 MDC」的假设都不成立。
- **统一入口收养语义（2026-08-20）**：`adoptLegacy` 只在全局 `groupId == null` 时采纳第一个非空候选（旧 4 个 localStorage 分键 + 画布快照 projectGroupId）；全局已设=页顶胜出不收养；旧键留原地不清理（可回滚本版本）。收养与持久化都只写单键 `project_group_id`，杜绝再次出现多处分键不同步。
- Mockito 重载坑×3：chargeMedia 10→11 参、refundMedia 4→5 参、pageDetail 10→11 参改签名后，旧 stub **静默失配**（不同方法不报错）——stub/verify 必须同步升参。
- LambdaQueryWrapper.select() 在纯单测（无 MP TableInfo 缓存）抛 "can not find lambda cache"→ 用 QueryWrapper 列名字符串。
- record VO 不能继承（DetailVO 是 record）→ OverviewVO 用组合。
- 画布 gid 不落节点 data 快照（仅顶层）——运行时注入防旧节点被历史 gid 污染。

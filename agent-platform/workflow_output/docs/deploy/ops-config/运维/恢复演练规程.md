# 恢复演练规程（运维系统 OPS-FR-16）

> 目标：**RPO ≤ 24h、RTO ≤ 1h**。备份不演练 = 没有备份。每季度一次，结果记录入本文末表。
> 关联：`backup/backup-pg.bat`（PG 日备/周备）、`backup/backup-files.bat`（uploads 镜像）、`backup/sync-offsite.bat`（异地副本）。

## 一、演练频率与范围

| 项 | 约定 |
|----|------|
| 频率 | 每季度最后一个月的第一个周末（对齐周备生成后） |
| 范围 | PG 全量恢复 + uploads 文件恢复 + 应用冒烟抽查 |
| 环境 | **隔离环境**：独立 scratch 库 + 独立端口 + 独立文件目录，绝不动生产库 |
| 计时 | 从「拿到备份文件」到「冒烟抽查通过」全程计时，对照 RTO≤1h |

## 二、演练步骤

### 1. 准备（5 分钟）
- 取最近一份日备：`%BACKUP_ROOT%\pg\daily\agent_platform_*.dump`（异地副本场景改从 `OFFSITE_TARGET\wk_<时间戳>\pg\daily\` 取——**S5 M5 后异地为 point-in-time 周快照子目录**，取最新 `wk_*` 即最近一次周日快照，顺带验证异地可用性）。
- 准备 scratch 环境变量：`DRILL_DB=agent_platform_drill`、`DRILL_PORT=18080`、文件目录 `D:\backup-drill\uploads`。

### 2. PG 恢复（目标 ≤20 分钟）
```bat
chcp 65001 > nul
set PGPASSWORD=<postgres 密码>
:: 建空库（已存在先 drop）
"%PG_BIN%\dropdb.exe" -h localhost -U postgres --if-exists agent_platform_drill
"%PG_BIN%\createdb.exe" -h localhost -U postgres agent_platform_drill
:: 恢复（-Fc 归档用 pg_restore；--no-owner 避免属主差异报错）
"%PG_BIN%\pg_restore.exe" -h localhost -U postgres -d agent_platform_drill --no-owner --exit-on-error "D:\backup\agent-platform\pg\daily\agent_platform_<时间戳>.dump"
set PGPASSWORD=
```
- 抽查表行数对照源端量级：`users / agent / chat_session / knowledge_document / audit_logs` 各 `SELECT count(*)`。
- 抽查**最近 24h 内**应有数据（对照 RPO）：`SELECT max(created_at) FROM audit_logs;` 不晚于备份时刻。

### 3. 文件恢复（目标 ≤10 分钟）
```bat
:: 目标是 scratch 目录，演练还原用 /MIR 让测试目录与备份一致（仅限 drill 目标，勿指向生产路径）
robocopy "D:\backup\agent-platform\files\uploads" "D:\backup-drill\uploads" /MIR /R:2 /W:5
```
- 抽查：文件总数与源端一致；随机取 3 个文件（含 1 个 >10MB）校验可打开 / 哈希一致。
- 异地副本抽查（S5 M5 后）：确认 `OFFSITE_TARGET` 下存在 ≥2 个 `wk_*` 周快照目录（勒索场景可用回退到上周快照——这正是弃 `/MIR` 镜像的意义）。

### 4. 应用冒烟（目标 ≤20 分钟）
- 用 scratch 配置起后端：`DB_NAME=agent_platform_drill`、端口 18080、uploads 指向恢复目录（其余同生产启动脚本）。
- 抽查清单：
  1. `GET /actuator/health` → UP（PG/Redis/sidecar/disk 全绿）；
  2. 管理员登录 → 拿 token；
  3. 知识库列表 / 最近一条会话详情 → 数据可读取；
  4. 发起一次最小对话或工作流执行 → 全链路可写。

### 5. 收尾
- drop scratch 库、删 `D:\backup-drill\`、停 scratch 进程。
- 填下表；未达标项开整改项（进运维待办）。

## 四、红线

- **绝不在生产库上练恢复**——restore 目标必须是 scratch 库名，脚本里见到 `agent_platform`（无 `_drill` 后缀）即停手。
- 备份目录 ACL：仅 SYSTEM + 运维账号可读（备份文件含全量业务数据，泄露面等同数据库泄露）。
- pg_restore 失败禁止 `--clean` 直连生产库名重试；先查 dump 完整性与版本匹配（pg_dump/pg_restore 同版本）。

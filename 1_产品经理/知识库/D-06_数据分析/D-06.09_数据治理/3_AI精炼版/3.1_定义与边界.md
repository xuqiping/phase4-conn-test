# 3.1 定义与边界

## A.01 核心定义

**数据治理（Data Governance）** 是对数据资产的管理、监督和控制的一组策略、流程、标准和组织机制，确保数据在整个生命周期中保持**高质量、安全合规、可发现、可理解、可信任**，从而支撑业务决策与AI应用。其本质是"让数据从不可用的成本中心变为可用的价值资产"。[来源: DAMA-DMBOK2 | 置信度:🔍高]

**一句话定位**：数据治理是数据的"交通规则"——规定数据怎么产生、怎么流动、谁有权用、怎么保证不出错，确保每一个数据都能被信任和有效使用。

**定位跃迁**（2025-2026）：数据治理已从"IT后台配套工具"跃迁为"企业AI战略能否落地的核心前提"——没有可信数据，AI模型就是垃圾进垃圾出。[来源: 中国信通院, 2026 | 置信度:🔍高 | 2026-07]

## A.02 复杂度谱系

| 复杂度 | 治理规模 | 典型场景 | 治理需求 |
|---|---|---|---|
| 1-简单 | 1~3个核心数据源 | MVP/内部工具/小团队 | 命名规范+基础质量检查+权限控制 |
| 2-中等 | 3~10个数据源 | 成长期C端/SaaS产品 | 元数据管理+质量规则+标准字典+数据目录 |
| 3-复杂 | 10~50个数据源 | 成熟期平台/多业务线 | DAMA框架+血缘追踪+分级分类+合规审计+资产盘点 |
| 4-超复杂 | 50+数据源 | 生态型/金融/政企 | DCMM评估+全链路治理+数据入表+AI驱动治理 |

## A.04 边界与不含什么

**数据治理包含**：元数据管理、数据标准、数据质量、数据安全与合规、数据血缘、主数据管理、数据资产化、数据生命周期管理、治理组织与流程。

**数据治理不含**：数据采集技术实现（→D-06.02）、指标体系定义（→D-06.01）、具体分析方法如漏斗/留存（→D-06.03/04）、数据看板搭建工具（→D-12）、数据仓库/数据湖架构设计（→技术架构而非PM视角）。

## I.01 核心术语速查

| 术语 | 定义 |
|---|---|
| 数据治理(Data Governance) | 对数据资产行使权力和控制的活动集合（规划、监控、执行） |
| 元数据(Metadata) | 描述数据的数据——数据的"户口本"，记录来源、格式、含义、关系 |
| 数据血缘(Data Lineage) | 数据从源到终点的完整流转路径，支撑影响分析与根因排查 |
| 数据质量(Data Quality) | 数据满足使用要求的程度，通常按六维度（完整性/准确性/一致性/及时性/唯一性/有效性）评估 |
| 主数据(Master Data) | 组织内跨系统共享的核心业务实体数据（客户/产品/组织等） |
| 数据标准(Data Standard) | 统一数据命名、编码、格式、口径的规范体系 |
| 数据目录(Data Catalog) | 数据资产的"黄页"，帮助用户发现、理解、信任可用数据 |
| 数据分级分类 | 按敏感度和重要性对数据进行等级划分，决定保护措施 |
| DCMM | 数据管理能力成熟度评估模型（国标GB/T 36073），2026年7月升级至2.0版 [来源:中国信通院 | 置信度:🔍高 | 2026-07] |
| 数据入表 | 将数据资产计入企业资产负债表（财政部2024年1月生效的数据资源会计准则） |
| 数据血缘追踪 | 自动化追踪数据从源系统到报表/模型的全链路血缘关系 |
| 数据脱敏 | 对敏感数据变形处理，使脱敏后数据不可逆还原但保持业务特征 |

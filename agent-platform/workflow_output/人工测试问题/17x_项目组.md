# 已解决

## ① 管理层级额度（2026-08-25 解决，V156）
> 原问题：设了管理员权限后不能再给管理员分配额度；期望 管理5000→分给A 1000→A用500→管理总额度4500−A剩500=可分配4000，管理要能看到自己剩余可分配。

- **模型落地**：`project_group_members.allocated_by_user_id` 记录预算归属上级（V156 迁移+回填存量挂组长）；组长可直接在管理行「调额度」定预算；管理给成员配额度走预算硬卡——新预留 ≤ 自己剩余可分配（MemberBudgetService.allocatable = 额度 − 子树已耗 − Σ下级预留，全部先持管理行 FOR UPDATE 再算）。
- **算例验证**（单测 MemberBudgetServiceTest + 实测 curl）：5000/1000/500 → 可分配恰为 4000；配 4000 通、4001 拒。
- **管理自见可分配**：成员表「可分配」列、组卡片、组详情顶部 chip、页顶「参与项目」下拉四处常显。
- **配套规则**：被限额管理不能给成员配「不限」；组长直接调成员限额=改挂组长直管；管理降职后名下成员统一改挂组长；组长调管理预算下限=已占用（子树已耗+下级预留）；管理自身消耗也占预算（doChargeGroup 硬卡）。
- **实测**：t17x 系账号（uid 181-184）全链路 curl ①-⑨ 通过。

## ② 积分安全审计（2026-08-25 解决）
> 原问题：组员能否利用 BUG 刷/盗积分？管理能否越权盗组长积分？

- **真漏洞（已修）**：`requireAffordableGroup` 此前不查成员限额——超额成员继续用会因扣费失败被「计费铁律」吞掉异常而白嫖。已加入口预检：成员 `used ≥ quota` 直接拦；被限额管理 `可分配 ≤ 0` 直接拦。
- **管理盗组长路径全部封闭**：配额度/邀请接受/自身消耗三类扣减均串行在管理行 FOR UPDATE 上，超预算硬拒；管理不能动自己行/角色、不能回收组池、不能任免或移除其他管理、不能改组设置。
- **组员刷分路径**：并发双花由钱包行锁+条件 UPDATE（balance >= cost / used+cost <= quota）+幂等键挡住；管理边花边分双分配由管理行锁串行化挡住。
- **明确接受的设计口径**（非漏洞）：不限额管理=旧扁平模型不受预算约束；降职/移除成员豁免其历史消耗对管理预算的占用；组池在途结算不足时 BACKSTOP 记组长个人账（设计如此，流水留痕）。
- 详见 feature-map「2026-08-25 增补」安全审计小节。

## ③ 组详情只见产出 tab + CHAT 内容列只显「对话消耗」（2026-08-25 解决）
- **只见产出**：admin（uid=1）是组 1 普通成员，前端 canManage 未含平台 admin（后端恒放行 admin）→ 已修 canManage/isAdmin，admin 成员点开组卡片即见完整管理界面。
- **内容列**：后端从未给 CHAT 行供 prompt，前端兜底显示字面量「对话消耗」。已改按轮次配对（chatTurnMap）：每条 CHAT 消耗行回填该轮用户提问（取消耗时刻前最后一条 USER 消息，兜底首条 USER）；无关联提问的老数据显示「-」。实测 usage 716 显「再多说一句它的典型应用场景」、712 显「用一句话说明什么是多Agent智能体平台」。

# 已解决（2026-08-26 勾销，修复设计 §2/§3，commit `30d11f05`）

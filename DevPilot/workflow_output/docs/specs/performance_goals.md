# Performance Goals · DevPilot 性能目标

> 上级：[PRD.md](PRD.md)。Phase 2 据此考虑性能坑，Phase 4 据此评测出报告。
> last_updated: 2026-08-13

## 1. 客户端性能目标

| 编号 | 指标 | 目标值 | 测量方式 |
|---|---|---|---|
| PERF-01 | 冷启动到可交互 | ≤3s（中端机：i5-11400/8G + M1/8G） | 启动探针计时 |
| PERF-02 | 主界面操作响应（切换视图/展开卡片） | ≤100ms | 前端性能埋点 |
| PERF-03 | 驾驶舱千条任务/存档点列表渲染 | 滚动 60fps，首屏 ≤300ms | 虚拟列表 + 真机帧率 |
| PERF-04 | 常驻内存（空闲） | ≤300MB | 系统监视器采样 |
| PERF-05 | 任务流推送延迟（内核事件→UI） | ≤1s | IPC 计时 |
| PERF-06 | 大白话翻译层响应 | P95 ≤3s（走便宜模型） | 网关计时 |
| PERF-07 | 环境画像命中后就绪时间 | ≤10s（AC-005） | core-exec 计时 |
| PERF-08 | 安装包体积 | Win ≤25MB / Mac ≤30MB | 构建产物 |

## 2. 云端性能目标

| 编号 | 指标 | 目标值 |
|---|---|---|
| PERF-10 | `/balance` 等读接口 | P95 ≤200ms |
| PERF-11 | 充值回调入账 | ≤3s（支付平台回调起算） |
| PERF-12 | 模型网关附加延迟（不含上游） | P95 ≤150ms |
| PERF-13 | 网关可用性 | ≥99.5% 月（多供应商故障转移） |
| PERF-14 | 并发 | 一期 200 在线 / 50 并发任务转发无降级 |

## 3. 资源约束

- SQLite 单库 <2GB 触发归档压缩（轮次归档机制联动 FR-047）。
- 快照存储：存档点快照增量存储，单项目磁盘占用超 5GB 时提示用户清理旧快照。
- 并行任务数默认 ≤3，可配；超限排队而非硬开（防内存爆）。

## 5. 性能设计要点（给 Phase 2 的坑点预判）

- Webview 长列表必须虚拟滚动；diff 大文件分块渲染。
- Rust 内核与 UI 间 IPC 走增量推送（diff 流），不整树刷新。
- SQLite 写操作串行队列化，避免锁竞争；账本镜像批量同步。
- 模型流式输出直推 UI，不做整段缓冲。

## 6. 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| P95 | 100 次里第 95 快的耗时，代表「绝大多数人」的体验 | 翻译 95% 情况 3 秒内出 |
| 虚拟列表 | 只渲染看得见的行，列表再长也不卡 | 一千个存档点流畅滚动 |
| k6 | 模拟大量用户同时访问的压测工具 | 模拟 50 人同时派任务 |

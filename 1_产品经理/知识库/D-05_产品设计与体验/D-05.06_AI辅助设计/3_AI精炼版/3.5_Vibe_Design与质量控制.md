## Vibe Design与质量控制

### Vibe Design（2025-2026前沿范式）

**定义**：用自然语言描述"感觉/氛围/调性"，AI自动生成符合品牌调性的视觉和UI设计方案。

**代表**：Google Stitch——Google 2026年发布的Vibe Design工具，输入品牌描述→生成完整Figma设计系统+UI方案，震撼程度让Figma股价两天跌约13%。

[来源:ixdc.org/网易 AI设计大爆发 | 置信度:📚中 | 2026-04]

### "AI平庸设计"问题

**核心矛盾**：AI越普及，设计越同质化——因为：
1. 训练数据偏差：主流AI模型训练数据中，"好看"的定义高度趋同
2. Prompt趋同：用户用相似的Prompt→得到相似的输出
3. 无约束生成：不加Design System约束→AI默认套用"最安全"的视觉方案

**典型表现**：
- 所有AI生成的SaaS界面看起来都像Notion/Vercel的克隆
- 移动端App全是用圆角卡片+底部Tab
- 品牌色都被AI替换成蓝紫渐变

### "反AI平庸设计"策略

| 策略 | 方法 | 工具 |
|---|---|---|
| 语义约束 | Schema-As-Code定义不可变边界 | YAML/JSON Design Token |
| 品牌风格锚定 | 提供品牌参考图+详细风格描述 | IP-Adapter+ControlNet |
| 多轮迭代 | 第一轮AI生成→人工筛选→第二轮AI精修 | Galileo/Figma AI |
| 反模板Prompt | Prompt中显式声明"不要模板化" | Claude Design System Prompt |
| 人工创意注入 | AI生成80%→人工创意20%（品牌差异化的灵魂） | 设计师 |

[来源:知乎"Claude Design System Prompt:反AI平庸设计" | 置信度:📚中 | 2026-07]

### AI设计质量控制三道闸门

| 闸门 | 检查内容 | 自动/人工 |
|---|---|---|
| 闸门1: 一致性 | 是否符合Design System令牌+组件 | 自动(Schema-As-Code) |
| 闸门2: 可用性 | 布局/交互/信息架构是否合理 | 半自动(AI辅助+人工) |
| 闸门3: 品牌性 | 是否体现品牌独特调性 | 人工（AI无法判断品牌灵魂） |

### 语义约束（Schema-As-Code）在AI设计中的角色

**核心思想**：把Design System写成机器可读的YAML契约，AI生成UI时必须"先读规范再生成"。

```yaml
# AI设计约束示例
constraints:
  immutable:
    - color-brand-primary: #1677FF  # 不可被AI覆盖
    - spacing-base: 4px            # 间距基数不可变
  flexible:
    - card-radius: [8px, 12px, 16px]  # 三选一
    - icon-style: [outlined, filled, dual-tone]  # 三选一
  forbidden:
    - gradient-background  # 禁止渐变背景
    - 3d-effect           # 禁止3D效果
```

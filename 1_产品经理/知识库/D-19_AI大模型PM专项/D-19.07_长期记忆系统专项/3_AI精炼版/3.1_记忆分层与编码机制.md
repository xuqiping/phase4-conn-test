# 3.1 记忆分层与编码机制

## 一、为什么必须分层（反"大窗口当记忆"）

2026 共识：把全部历史塞大上下文窗口 ≠ 记忆，而是"上下文腐烂 Context Rot"——无关信息稀释注意力、关键信号被淹没、检索成本指数增长 [来源:腾讯云 | 🔍高 | 2026-07]。研究已观测到上下文超 64K token 时模型出现"中间迷失 Lost in the Middle"现象，准确率反降 [来源:腾讯云 | 🔍高 | 2026-05]。**真正的记忆是把上下文当"内存"管理——常驻/检索/压缩/淘汰分层调度**，类比操作系统的内存层级 [来源:腾讯云 | 🔍高 | 2026-05-09]。

## 二、4 级记忆分层结构（2026 主流范式）

| 层级 | 类比 | 内容 | 生命周期 | 实现 |
|---|---|---|---|---|
| **L1 工作记忆 Working Memory** | CPU 寄存器 | 当前回合 prompt + 系统约束 + 工具结果 | 单回合 | 拼进当前 prompt |
| **L2 短期记忆 Short-term** | RAM | 当前会话最近 N 轮 + 任务上下文 | 单会话 | 滑动窗口 + 摘要压缩 |
| **L3 长期记忆 Long-term** | 磁盘 | 跨会话用户偏好/事实/经验，编码后持久化 | 永久（可遗忘） | 向量/KG/原文混合存储 |
| **L4 外部记忆 External** | 网络盘 | 外部知识库（RAG，非"用户记忆"） | 外部 | 向 RAG 检索（→D-19.08） |

**衍生第 5 层：反思记忆 Reflective**——从冲突/失败/纠错中抽取教训，反哺长期记忆（Letta 的 archival memory + reflection、Magentic-One 的 self-critique）。

> 注意：L4 外部记忆属于 RAG 范畴见 [D-19.08](../../D-19.08_RAG检索增强专项/1_知识库概览/0_模块路由.md)；本叶子聚焦 L1-L3+反射。

## 三、记忆编码形式（4 种 + 混合）

| 编码形式 | 优点 | 缺点 | 典例 |
|---|---|---|---|
| **向量嵌入** | 检索快、语义模糊匹配好 | 不可解释、易召回漂移 | 多数通用产品默认 |
| **知识图谱（KG）** | 可推理、可解释、强结构 | 建模重、需实体抽取 | Mem0 混合模式、Zep Graphiti |
| **原文存储** | 100% 保真、可溯源 | 检索慢、token 贵 | 早期 ChatGPT Memory 原文式 |
| **总结摘要** | 压缩 token、控成本 | 信息有损 | LangMem 分阶段总结 |
| **混合（向量+KG+原文）** | 鲁棒、可演进 | 复杂 | Mem0 / Letta（事实+反思+原文） |

**2026 趋势**：从"单一向量"演进到"向量+KG+反思"混合，记忆不仅"存事实"还"存关系/教训"，可被推理调用 [来源:腾讯云 | 🔍高 | 2026-07]。

## 四、记忆操作 CRUD-M（核心范式）

这是 2026 记忆工程的标志性升级——记忆不再是"只 add 不删"，而是 LLM 在线做 5 种处理判断 [来源:百家号/LightMem ICLR2026 | 🔍高 | 2026-02]：

| 操作 | 触发条件 | 处理方式 |
|---|---|---|
| **Add 新增** | 全新事实/偏好 | 写入新记忆条目，带元数据(时间/置信度/来源) |
| **Update 更新** | 已有事实变化 | 旧条目标 deprecated，写入新条目；保留版本 |
| **Merge 合并** | 多条记忆指向同一实体 | 合成统一条目，避免冗余 |
| **Delete 删除** | 过期/错误/冲突 | 软删（标记）或硬删；触发遗忘 |
| **Ignore 忽略** | 临时信息/无价值 | 不写入，省成本 |

> LightMem（ICLR 2026）核心贡献：把上述 CRUD-M 的在线 LLM 调用成本打到极低，让记忆系统从"太贵"变"可生产" [来源:百家号 | 🔍高 | 2026-02-26]。

## 五、记忆隔离（多租户/多 Agent/多会话）

| 隔离维度 | 必要性 | 实现要点 |
|---|---|---|
| **用户隔离** | 防止 A 看到 B 偏好（隐私+体验双危） | 主键 user_id 强制隔离；权限校验入库前 |
| **Agent 隔离** | 防止不同 Agent 角色记忆串扰 | 按 agent_id 分库或分命名空间 |
| **会话隔离** | 单元测试/调试场景隔离 | session_id 作用域；可显式合并到长期 |
| **P0 数据隔离** | 敏感字段单独加密 | PII 字段加密存储；访问审计 |

> 与 D-19.06 风险合规交叉：记忆隔离失败属于隐私/越狱风险面；多 Agent 共享记忆必须权限最小化 [来源:OWASP ASI 2026 | 🔍高 | 2026-06]。

## 七、PM 设计要点

1. **先选分层架构**：明确 L1-L4 边界，工作记忆/短期/长期/外部各装什么
2. **编码形式选型**：通用对话→向量；Agent 推理→混合（向量+KG）；高保真→原文+向量
3. **CRUD-M 缺一不可**：只 add 不 update/merge/delete 的系统注定膨胀污染
4. **隔离做到位**：用户/Agent/会话三轴隔离，敏感数据加密
5. **接 3.2 / 3.3**：分层定下后再选检索/遗忘策略与评估指标

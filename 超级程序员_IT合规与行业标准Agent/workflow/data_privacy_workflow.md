# Data Privacy Management Workflow

## Purpose

基于企业数据保密管理制度知识框架，提供数据六阶段全生命周期管理的标准化执行路径，覆盖分类分级、加密密钥、脱敏去标识化、DLP防泄漏、数据出境合规、泄露应急响应六大核心领域。

## Prerequisites

- 已建立数据资产盘点清单（至少包含数据库、文件系统、API接口、第三方SaaS）
- 已明确数据管辖法律环境（中国《个保法》/欧盟GDPR/美国CCPA等）

## Steps

### Step 1: 数据资产盘点与分类分级

**Goal**: 完成全部数据资产的盘点、标签化、分类分级，建立数据资产目录
**Completion criterion**: 输出《数据资产清单》与《数据分类分级矩阵》，覆盖率100%，每类数据有明确的风险等级标签

依据数据分类分级三步法 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 数据分类分级三步法]：
1. 盘点：梳理全部数据存储位置（结构化/非结构化/日志/备份），建立数据资产清单（Data Inventory）
2. 标签：参考行业指南（金融/电信/医疗）+ 企业特性，为每类数据打标签：
   - 按敏感度：公开/内部/机密/绝密
   - 按类型：个人信息/交易数据/网络数据/位置数据/生物特征
   - 按生命周期阶段：采集/存储/处理/传输/交换/销毁
3. 管控：为每级定义差异化控制策略（高敏→字段级加密+严格访问审计；低敏→标准访问控制）
输出：《数据分类分级管理办法》+ 《数据资产目录》（Excel/CMDB形式）

### Step 2: 数据六阶段控制策略落地

**Goal**: 在数据采集、传输、存储、处理、交换、销毁六个阶段分别建立技术与管理控制措施
**Completion criterion**: 六个阶段均有明确的控制措施清单，且与现有技术栈匹配（如TLS 1.3已部署、KMS已集成）

参考数据六阶段控制框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 数据六阶段控制]：
1. 采集阶段：必要性审查（最小化原则）+ 告知同意（隐私政策+弹窗授权）+ 采集日志审计
2. 传输阶段：强制TLS 1.3 + 证书固定（Certificate Pinning）+ API网关流量加密 + 传输完整性校验
3. 存储阶段：静态加密（数据库TDE + 对象存储SSE）+ 密钥管理（KMS/HSM）+ 备份加密 + 存储隔离（生产/测试分离）
4. 处理阶段：脱敏处理（开发测试用脱敏数据）+ MPC多方安全计算（跨域联合建模）+ 访问审计
5. 交换阶段：API网关沙箱 + 数据共享协议（DUA）+ 交换日志留痕 + 第三方安全评估
6. 销毁阶段：遵循NIST 800-88标准，物理销毁（硬盘粉碎）+ 逻辑销毁（加密密钥删除即等于数据销毁）
输出：《数据全生命周期控制矩阵》（6阶段 × 技术措施 × 管理措施）

### Step 3: 加密技术决策与密钥管理体系

**Goal**: 基于数据使用场景选择最优加密技术，建立完整的密钥管理生命周期
**Completion criterion**: 输出《加密技术选型决策树》与《密钥管理策略》，覆盖KMS/HSM/密钥轮换/密钥销毁

依据加密技术决策树 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 加密技术决策树]：
1. 需密文计算场景（如隐私求交）→ 同态加密/安全多方计算（MPC）
2. 需跨域共享场景（如联邦学习）→ MPC/联邦学习 + 差分隐私
3. 高敏感数据（如支付卡号、身份证号）→ 字段级加密（AES-256-GCM）+ 令牌化（Tokenization）
4. 一般敏感数据 → TDE透明数据加密 + 存储层加密
执行：
- 部署KMS（如AWS KMS/HashiCorp Vault/自研国密KMS），支持国密SM2/SM3/SM4
- 制定密钥生命周期策略：生成→分发→使用→轮换（每90天自动轮换）→归档→销毁
- 高敏感数据密钥采用HSM（硬件安全模块）保护，KMS只存储加密后的密钥密文
- 输出《密钥管理运维手册》（含密钥丢失应急响应流程）

### Step 4: DLP三道防线部署

**Goal**: 在终端、网络、云端三个层面部署数据防泄漏体系，覆盖全部数据外泄通道
**Completion criterion**: 三道防线全部上线运行，策略规则覆盖USB/邮件/云盘/打印/剪贴板等通道，误报率<5%

参考DLP三道防线模型 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > DLP三道防线]：
1. 终端DLP：部署客户端Agent，监控USB外接设备、剪贴板复制、屏幕截图、打印行为；核心数据区域禁止复制到个人IM/邮件
2. 网络DLP：邮件网关集成DLP（拦截含身份证号/银行卡号的邮件外发）、SSL解密检测（合法合规前提下）、IM外发内容审计
3. 云端DLP：CASB（Cloud Access Security Broker）监控SaaS应用（如企业微信/钉钉/飞书文件外发）、云存储异常下载告警
执行：
- 分阶段灰度部署：先监控模式（不阻断）→ 告警模式 → 阻断模式
- 建立DLP事件分级响应：高危（绝密数据外发）立即阻断+通知安全团队；中危（内部数据外发）告警+人工复核
- 每月输出《DLP运营报告》（事件数、阻断数、误报率、趋势分析）

### Step 5: 数据出境合规通道建设

**Goal**: 根据数据类型与规模选择合规的出境通道，完成法律要件准备
**Completion criterion**: 数据出境场景全部纳入三条通道之一，法律文件（SCC/安全评估报告/认证证书）已准备或已提交

依据数据出境三条通道决策框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 数据出境三条通道决策]：
1. 安全评估通道：适用条件——关基运营者/处理100万人以上个人信息/累计出境10万人以上/累计出境1万人以上敏感个人信息
   - 输出《数据出境安全评估申报书》+ 《数据出境风险自评估报告》
   - 向省级网信办提交，60个工作日内完成评估
2. 标准合同（SCC）通道：适用条件——普通业务数据出境，不涉及关基/大规模个人信息
   - 签署《个人信息出境标准合同》+ 开展个人信息保护影响评估（PIA）
3. 个人信息保护认证通道：适用条件——集团内部跨境业务、同一经济实体内部数据传输
   - 申请专业机构进行个人信息保护认证（如中国网络安全审查认证中心）
执行：
- 梳理全部数据出境场景（含云服务境外节点、跨境办公、跨国集团数据汇聚）
- 为每个场景匹配出境通道，建立《数据出境场景登记簿》
- 设置出境审批流程：业务申请 → 法务合规审查 → 安全评估 → 高管审批 → 执行

### Step 6: 数据泄露应急响应体系建设

**Goal**: 建立PICERL六阶段应急响应体系，确保72小时内完成上报、7天内完成初步处置
**Completion criterion**: 应急响应预案已制定并演练，72小时上报流程已打通，核心团队联系方式已更新

参考PICERL六阶段框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > PICERL六阶段]：
1. 准备（Preparation）：组建应急响应小组（安全/法务/PR/业务/高管），制定《数据泄露应急响应预案》，每半年演练一次
2. 识别（Identification）：部署SIEM+UEBA检测异常访问，定义泄露确认标准（如非授权批量下载>1000条个人信息）
3. 遏制（Containment）：短期遏制（隔离泄露账号/关闭API接口/封锁IP）+ 长期遏制（修补漏洞/重置凭证/加固配置）
4. 根除（Eradication）：清除攻击者残留（后门/webshell/恶意账号），定位根因（是内部泄露还是外部入侵）
5. 恢复（Recovery）：逐步恢复服务，监控是否二次泄露，通知受影响用户（按法律要求）
6. 总结（Lessons Learned）：72小时内向监管上报，7天内完成事件报告，30天内完成改进措施落地
输出：《数据泄露应急响应预案》+ 《上报材料模板》+ 《演练记录表》

## Post-Workflow

1. 读取 `checklist/data_privacy_workflow_checklist.md`
2. 交叉验证每阶段控制、每个出境通道、每个DLP规则
3. 全部通过后输出《数据保密管理制度总纲》并归档

# 运维系统（系统管理员）

> 看板看健康、钉钉群收告警、脚本配通知、发布走批处理。全中文界面。

## 一、每日看板巡检（5 分钟）

1. 浏览器开 Grafana（默认 `http://127.0.0.1:3000`）→ admin 登录。
2. 「仪表板」→ 文件夹「运维监控」→「系统总览」。
3. 顶部「组件在线状态」应全绿（sidecar 红 = 没用工作流，正常）。
4. 看第一行大数字：CPU / 内存 / D盘剩余（应 ≥15%）。
5. 「告警」页：不应有红色 firing 状态的告警。

## 二、首次配钉钉告警（一次性）

1. 钉钉群：群设置 → 机器人 → 添加「自定义」机器人（安全设置建议选「加签」）。
2. 复制机器人 Webhook 地址。
3. 服务器上双击 `配置钉钉告警.bat` → 按提示粘贴 Webhook（有加签再贴密钥）。
4. 脚本自动写配置、重启服务、发测试消息——**群里收到测试消息 = 通道打通**。

## 三、收到钉钉告警怎么办

1. 看告警标题（如「后端进程宕机」）。
2. 翻《运维手册》的「告警处置速查」找同名行 → 按指引处理。
3. 处理完回 Grafana「告警」页确认变绿 resolved（群里也会收到「已恢复」）。

## 四、维护期间挂静默（免打扰）

Grafana「告警」→「静默」→ 新建静默 → 匹配器选告警名 + 填时长 → 期间该告警不发钉钉，到期自动恢复。

## 五、发布新版本

1. 开发机构建出 jar 和 dist，拷到服务器。
2. 管理员 cmd 跑 `deploy.bat D:\pkg\xxx.jar D:\pkg\dist` → 窗口显示 1/5~5/5 →「发布完成」。
3. 显示「自动回滚」= 发布失败旧版已恢复，钉钉会收告警，查日志找原因。

## 常见异常

| 现象 | 原因 | 处理 |
|---|---|---|
| 看板某面板空白 | 该指标还没产生过数据 | 用一次对应功能再看 |
| Grafana 打不开 | 服务停了 | services.msc 找 agent- 开头服务启动 |
| 钉钉没收到告警 | webhook 没配/抄错 | 重跑配置脚本，看适配器日志 |
| 备份没跑 | 计划任务问题 | 看备份状态文件和任务计划程序 |

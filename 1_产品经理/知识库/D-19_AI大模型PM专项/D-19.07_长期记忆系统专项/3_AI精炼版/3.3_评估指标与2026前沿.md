# 3.3 评估指标（I.09）与可调参数（I.20）+ 2026 前沿

> **维度提示**：本叶子 I.09（AI 产品指标）与 I.20（记忆/检索/分块等可调参数）均提升必选——记忆系统是少数"指标+参数并重"的能力，必须双线管理。

## 一、I.09 必选——记忆评估指标体系

| 指标类 | 具体指标 | 计算方式 | 目标 |
|---|---|---|---|
| **质量类** | **记忆准确率** | 召回的记忆中事实正确比例 | >95%（高合规）/>90%（通用） |
| | **召回率 Recall@k** | 该被召回的记忆中实际被召回比例 | >85% |
| | **合成质量** | 引用记忆生成的答案正确率 | 与基线对齐 |
| | **冲突率** | 同实体多条冲突未合并比例 | <2% |
| **性能类** | **检索时延 P95** | 单次召回耗时 | <200ms（在线）/ <1s（异步） |
| | **写入时延** | CRUD-M 单次操作耗时 | <500ms |
| | **端到端首 token 时延** | 含检索的首字延迟 | <800ms |
| **规模/成本类** | **记忆增长率** | 单用户日均记忆条目增量 | 监控异常膨胀 |
| | **存储成本** | 单用户/单条记忆月成本 | 控 ROI |
| | **检索 token 成本** | 单次召回拼 prompt 的 token 量 | 与 D-19.09 成本优化交叉 |
| **遗忘类** | **遗忘率** | 主动删/合并/衰减的条目比例 | 监控过激遗忘 |
| | **关键事实误删率** | 不该忘的被忘比例 | <0.5%（红线） |
| **一致性类** | **跨会话一致性** | 同一事实在不同会话被回忆一致性 | >95% |
| | **跨模型一致性** | 切换底座后召回/合成行为漂移 | 上线前回归 |
| **用户感知类** | **个性化满意度** | 用户主观"被记得"评分 | >4.0/5 |
| | **纠错次数** | 用户纠正记忆错误次数/会话 | 监控倒退 |
| **安全类** | **注入写入拦截率** | 被识别为恶意写入的拦截比例 | >99% |
| | **跨用户串扰数** | 隔离失败事件 | 0（红线） |

> 评估方法参考 D-19.05 框架（黄金集 + AB + 人工评分 + 回归）。记忆独特处在于"**召回准确率 × 漏召率 × 误删率 × 一致性**"四角，缺一不可。

## 二、I.20 必选——记忆可调参数清单

| 参数 | 含义 | 调优影响 |
|---|---|---|
| **top-k（召回数）** | 单次召回记忆条数 | 大→召回全但 token 贵；小→省成本但漏召 |
| **相似度阈值** | 召回的最低相似度 | 高→精度高漏召多；低→召回全噪音多 |
| **时间衰减系数 λ** | Recency 权重 | 大→近期优先；小→历史平等 |
| **置信度加权权重 α** | 置信度在综合得分中占比 | 高→验证记忆优先；低→纯相似度 |
| **写入触发阈值** | 哪些信息值得 add | 严→库精但漏信息；松→库全但膨胀 |
| **容量上限 N（每用户/每类型）** | 长期记忆最大条数 | 大→不易遗忘；小→强制淘汰 |
| **重排 top-N** | 重排后保留条数 | 大→留多；小→精简 |
| **重排模型/阈值** | 选 bge-reranker / Cohere 等 | 影响精度/成本 |
| **遗忘周期** | 衰减扫描频率 | 高频→及时清理；低频→省资源但陈旧 |
| **冲突合并策略** | 时间/置信度/用户裁决优先 | 影响一致性 |
| **检索时机** | 每轮固定 vs 按需调用 vs 混合 | 影响 token 成本与召回质量 |
| **隔离粒度** | 用户/Agent/会话级 | 影响安全与性能 |

> 调参思路：先定"召回质量红线"（如 Recall@k≥85%），再在红线内调成本最小（参考 D-19.09）；每次调参必须用 I.09 黄金集回归（参考 D-19.05）。

# 进程管理模块（Process Management）总结

## 1. 模块职责一句话

进程管理模块负责枚举系统中可见窗口的进程信息，按应用类别分类展示，支持用户通过 UI 对单个或多个进程执行关闭窗口（WM_CLOSE）、强制结束（TerminateProcess）、激活窗口等操作，同时提供文件占用进程检测与关闭能力。

## 3. 核心数据流 / 调用链路

### 3.1 枚举进程并展示

```
ProcessManagement.vue (onActivated/onMounted)
  -> processStore.refresh()
    -> processApi.getRunningProcesses()
      -> Tauri invoke('get_running_processes')
        -> commands/process_management.rs::get_running_processes()
          -> platform/windows/process_monitor.rs::enumerate_processes()
            -> EnumWindows (Win32 API) 枚举可见窗口
            -> sysinfo::System 获取内存/CPU
            -> process_mappings.rs 分类映射
    <- 返回 ProcessInfo[]
  <- processStore.processes 更新
  <- ProcessList.vue / ProcessRow.vue 渲染
```

### 3.2 关闭单个进程（优雅关闭）

```
ProcessRow.vue 点击关闭按钮
  -> ProcessList.vue handleCloseProcess()
    -> requestConfirmation() (注入的确认函数)
      -> ProcessManagement.vue 确认逻辑（whitelist/never/always）
    -> processStore.closeProcess(windowHandle)
      -> processApi.closeProcess(windowHandle)
        -> Tauri invoke('close_app_process', { windowHandle })
          -> process_monitor.rs::close_process() -> PostMessageW(WM_CLOSE)
    <- 前端乐观移除进程 + toast 提示
```

### 3.3 强制结束进程

```
ProcessToolbar.vue / ProcessList.vue 右键菜单
  -> processStore.killProcess(pid) / processStore.killSelected()
    -> processApi.killProcess(pid) / killProcesses(pids)
      -> Tauri invoke('kill_app_process', { pid }) / invoke('kill_app_processes', { pids })
        -> process_management.rs::kill_app_process() / kill_app_processes()
          -> utils/process_matcher.rs::kill_process()
            -> platform/windows_file_matcher::WindowsProcessMatcher::kill_process()
              -> OpenProcess + TerminateProcess (Win32 API)
    <- 前端乐观移除进程 + toast 提示
```

### 3.4 查找并关闭文件占用进程

```
App.vue 右键菜单 "关闭已打开的进程"
  -> handleShowProcesses(file)
    -> api/processes.ts::findFileProcesses(filePath)
      -> Tauri invoke('find_file_processes', { filePath })
        -> commands/processes.rs::find_file_processes()
          -> utils/process_matcher.rs::find_processes_for_file()
    -> 展示 ProcessManager 弹窗
    -> handleCloseProcess(windowHandle)
      -> api/processes.ts::closeProcess(windowHandle)
        -> Tauri invoke('close_app_process', { windowHandle })
```

## 4. 关键状态与 Store 说明

### 4.1 `useProcessStore` (`file-keeper/src/stores/processStore.ts`)

| 状态/计算属性 | 类型 | 说明 |
|---|---|---|
| `processes` | `Ref<ProcessInfo[]>` | 当前所有进程列表 |
| `selectedIds` | `Ref<Set<number>>` | 选中的 window_handle 集合 |
| `currentCategory` | `Ref<ProcessCategory>` | 当前筛选分类，默认 `'All'` |
| `isRefreshing` | `Ref<boolean>` | 是否正在刷新 |
| `lastRefreshTime` | `Ref<number>` | 上次刷新时间戳（ms） |
| `error` | `Ref<string \| null>` | 最近一次错误信息 |
| `sortKey` | `Ref<ProcessSortKey \| null>` | 当前排序字段 |
| `sortDirection` | `Ref<'asc' \| 'desc'>` | 排序方向 |
| `filteredProcesses` | `Computed` | 按分类筛选 + 排序后的进程列表 |
| `selectedCount` | `Computed` | 选中数量 |
| `categoryCounts` | `Computed` | 各分类进程数量统计 |
| `selectedProcesses` | `Computed` | 选中的 ProcessInfo 数组 |

**关键行为：**
- `refresh()`：调用 API 获取进程，自动清理已不存在的选中项，记录性能日志（API 耗时 + 渲染耗时）
- `toggleSelect/selectAll/deselectAll/invertSelection`：选择操作基于 `window_handle`
- `closeProcess` / `closeSelected`：按 window_handle 关闭，乐观移除列表项
- `killProcess` / `killSelected`：按 pid 强制结束，一个 pid 可能对应多个窗口（会一并移除）
- `setSort(key)`：切换排序字段，同字段点击切换方向；memory/cpu 默认降序，其余默认升序

### 4.2 `useProcessSettingsStore` (`file-keeper/src/stores/processSettingsStore.ts`)

| 状态 | 类型 | 说明 |
|---|---|---|
| `settings.columns` | `ColumnConfig[]` | 列配置（key/label/width/visible/sortable），默认 8 列 |
| `settings.autoRefresh` | `boolean` | 是否自动刷新，默认 `false` |
| `settings.refreshInterval` | `number` | 自动刷新间隔（ms），默认 `5000` |
| `settings.confirmMode` | `ConfirmMode` | 确认模式：`'always'`/`'whitelist'`/`'never'`，默认 `'whitelist'` |
| `settings.whitelist` | `string[]` | 白名单进程名列表（如 explorer.exe、taskmgr.exe 等系统进程） |

**持久化：** 使用 `localStorage`（key: `process-settings`），初始化时自动加载，更新时自动保存。

## 5. 关键组件说明

### 5.1 `ProcessManagement.vue` — 页面容器

- 组合 `ProcessToolbar`、`ProcessFilter`、`ProcessList`
- 提供 `requestConfirmation` / `requestKillConfirmation` / `toast` 三个注入项
- 确认逻辑：
  - `never` 模式：直接执行
  - `whitelist` 模式：仅当进程名匹配白名单时才弹出确认对话框
  - `always` 模式：始终弹出确认对话框（默认行为）
- 生命周期：`onActivated` 刷新并启动自动刷新，`onDeactivated` 停止刷新并清空进程
- 页面可见性监听：`visibilitychange` 事件，页面隐藏时停止自动刷新，显示时恢复

### 5.2 `ProcessList.vue` — 列表主组件

- 表头：复选框（全选/半选/反选）+ 可见列排序按钮（带排序图标）+ 操作列
- 列表区：`v-for` 渲染 `ProcessRow`，空状态提示
- 右键菜单：激活窗口、复制信息、关闭应用、强制结束进程（带危险样式）
- 状态栏：总数、选中数、错误提示
- 排序交互：点击表头触发 `processStore.setSort()`，图标显示 `ArrowUp`/`ArrowDown`/`ArrowUpDown`
- 错误处理：识别 `0x80070005` / `access is denied` / `拒绝访问` 提示管理员权限

### 5.3 `ProcessRow.vue` — 单行组件

- Props: `process: ProcessInfo`, `selected: boolean`
- 展示列：name（截断 + title）、category（彩色徽章）、pid、memory（自动转换 MB/GB）、cpu（保留1位小数）、windowTitle（截断）
- 事件：`toggle-select`、`close`、`context-menu`
- 每行高度固定 `48px`，hover/selected 状态有背景色变化

### 5.4 `ProcessFilter.vue` — 分类筛选

- 下拉选择器：13 个分类选项（All + 12 类），显示各分类数量
- 快捷按钮：All、Browser、Office、Explorer、Terminal 五个常用分类
- 双向同步：`selectedCategory` 与 `processStore.currentCategory` 互相同步

### 5.5 `ProcessToolbar.vue` — 工具栏

- 左侧：刷新按钮（带旋转动画）、自动刷新切换（带倒计时显示）、全选/反选/取消、批量关闭/强制结束
- 右侧：列设置按钮、总数与上次刷新时间
- 倒计时逻辑：自动刷新开启时显示剩余秒数，每秒递减

### 5.6 `ColumnSettings.vue` — 列设置弹窗

- 使用 `SortableJS` 实现拖拽排序（通过 `.drag-handle` 把手）
- 每列：拖拽把手 + 显示复选框 + 列名标签
- 操作：保存（持久化到 Store）、取消、恢复默认

## 6. 核心功能

### 6.1 枚举进程

- 后端通过 `EnumWindows` 枚举所有可见顶层窗口，过滤空标题和 "Program Manager"
- 使用 `GetWindowThreadProcessId` 获取窗口所属 PID
- 使用 `sysinfo::System` 获取进程名、内存占用（MB）、CPU 使用率
- 返回 `ProcessInfo` 数组，包含 `pid`、`name`、`window_title`、`category`、`memory_mb`、`cpu_usage`、`window_handle`

### 6.2 分类映射

- `process_mappings.rs` 中定义了 400+ 常见 Windows 进程的分类映射
- 12 个分类：Browser、Office、Explorer、Terminal、Archive、Document、Media、Image、Communication、Download、Game、System
- 未匹配到的进程归类为 `Other`
- 映射表在 `ProcessMonitor::new()` 时加载到 `HashMap` 中，枚举时 O(1) 查询

### 6.3 列自定义

- 支持 8 列：name、category、pid、memory、cpu、runtime、path、windowTitle
- 默认显示：name、category、pid、memory、cpu、runtime
- 默认隐藏：path、windowTitle
- 列可见性、顺序均支持自定义，持久化到 `localStorage`
- `processColumns.ts` 提供类型安全的列过滤和 CSS class 映射

### 6.4 排序

- 支持排序字段：name、category、pid、memory、cpu、windowTitle
- 排序方向：asc / desc
- 默认规则：memory 和 cpu 默认降序（高占用在前），其余默认升序
- 排序比较使用 `localeCompare`（numeric: true），相同值时按 name 兜底

### 6.5 单选 / 多选

- 选择标识：`window_handle`（每行唯一）
- 操作：单击行切换、表头复选框全选/反选、工具栏全选/反选/取消
- 刷新后自动清理已不存在的选中项
- 批量操作基于当前 `filteredProcesses`（受分类筛选影响）

### 6.6 关闭 / 强制结束

| 操作 | API | 后端实现 | 说明 |
|---|---|---|---|
| 关闭窗口 | `close_app_process` | `PostMessageW(hwnd, WM_CLOSE, ...)` | 优雅关闭，请求应用自行退出 |
| 关闭多个窗口 | `close_app_processes` | 循环调用 `close_process` | 返回 `CloseResult`（成功/失败计数） |
| 强制结束进程 | `kill_app_process` | `OpenProcess` + `TerminateProcess` | 强制终止，通过 `process_matcher.rs` 跨平台代理 |
| 批量强制结束 | `kill_app_processes` | 循环调用 `kill_process` | 去重 PID 后批量执行 |

- 关闭操作支持确认对话框（三种模式）
- 强制结束操作在工具栏始终需要确认（通过 `requestKillConfirmation`），右键菜单直接执行不确认
- 白名单进程（如 explorer.exe）在强制结束时会弹出 warning toast 提示

### 6.7 激活窗口

- API: `activate_app_window`
- 实现：如果窗口最小化则 `ShowWindow(SW_RESTORE)`，然后 `SetForegroundWindow`
- 通过右键菜单 "前置窗口" 触发

### 6.8 占用文件进程

- API: `find_file_processes(filePath)` / `close_file_processes(filePath)`
- 入口：App.vue 文件右键菜单 "关闭已打开的进程"
- 弹窗展示占用该文件的所有进程，支持单个关闭和刷新
- 底层通过 `process_matcher.rs` 平台相关实现检测文件句柄占用

## 8. 已知缺口 / TODO

1. **runtime 列未实现数据填充**：`ProcessInfo` 类型中无 `runtime` 字段，但 `ColumnConfig` 默认包含 `runtime` 列（宽度 100px，visible: true）。`ProcessRow.vue` 中没有渲染 `runtime` 的逻辑，该列实际为空。
2. **跨平台后端不完整**：`process_matcher.rs` 中声明了 macOS 和 Linux 的 `PlatformMatcher`，但代码库中仅看到 Windows 实现（`windows_file_matcher` / `process_monitor.rs`），macOS/Linux 的实现文件未在读取范围内确认存在。
3. **进程列表无搜索功能**：当前仅支持按分类筛选，无按进程名或窗口标题搜索的功能。`highlight.ts` 工具虽存在但未被进程模块使用。
4. **memory 和 cpu 数据依赖 sysinfo**：`process_monitor.rs` 中 `system.refresh_processes_specifics(ProcessRefreshKind::everything())` 的 CPU 数据在首次刷新时可能为 0，需要多次刷新才能稳定。
5. **确认对话框组件未在本次读取范围内**：`ProcessManagement.vue` 引用了 `ConfirmDialog` 组件，但未在要求读取的文件列表中，其具体实现未确认。
6. **后端 `process_management.rs` 单测有限**：仅包含 `kill_processes_by_pid` 的计数逻辑测试，未覆盖 `enumerate_processes`、`close_process`、`activate_window` 等核心功能。

## 9. 与其他模块的依赖关系

### 9.1 被依赖（其他模块使用进程模块）

- **`App.vue`**（`file-keeper/src/App.vue`）：
  - 导入 `ProcessManagement` 组件作为 `processes` 标签页内容
  - 导入 `findFileProcesses` 和 `closeProcess` 用于文件右键菜单的"关闭已打开的进程"功能
  - 通过 `canUseTab('processes')` 检查商业授权模块是否允许使用进程管理

### 9.2 依赖其他模块

- **国际化（i18n）**：所有组件使用 `useI18n()` 组合式函数，进程相关翻译 key 前缀为 `process.`
- **Toast 通知**：`ProcessManagement.vue` 提供 `toast` 注入，`ProcessList.vue` 和 `ProcessToolbar.vue` 消费 toast 显示操作结果
- **商业授权（CommercialAuth）**：`App.vue` 通过 `commercialAuthStore` 控制 `processes` 标签页的可用性，未授权时显示禁用状态或引导试用
- **通用工具**：`highlight.ts` 位于 `utils/` 目录，被文件模块使用，进程模块当前未使用

## 目标
写记忆前 resolve 标签，四路径（精确 label / aliases / anchor ≤0.25 二次 LLM 批判 / 全 miss 新建）；并发同义只建一条；禁归并/拆分/重抽。

## 动作（伪代码）
1. `resolve(userId, subject, topic, label, anchorEmbed, anchorTokens)`：
   - ① 精确 `WHERE user_id AND subject AND topic AND label` 命中 → 复用，`usage_count++`。
   - ② aliases 命中（label ∈ aliases）→ 复用，`usage_count++`。
   - ③ anchor 余弦 ≤0.25 候选 → **二次 LLM 批量判**（防误并）真同义 → 复用 + 滚进 aliases。
   - ④ 全 miss → 新建 tag（anchor 写入）。
2. owner 改 label / 补 aliases 端点：`tag_id` 不变；anchor 可重生（预期纠错）。
3. **无 merge/split/重抽 端点**（误并不可逆，保护已生成 summary 的 tag_id）。
4. 并发兜底：`UNIQUE(user_id,subject,topic)` 拦截；捕获冲突 → 改查已建行复用。

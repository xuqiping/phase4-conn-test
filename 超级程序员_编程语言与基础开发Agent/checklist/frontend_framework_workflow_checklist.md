# Frontend Framework Workflow Checklist

在完成 `workflow/frontend_framework_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别用户前端需求场景

- [ ] 已明确场景类型（技术选型/学习路径/问题排查/跨端方案/性能优化）
- [ ] 已识别目标框架（如用户已指定）或初步筛选出候选方案
- [ ] 已提取应用类型约束（中后台/大型Web/企业级/跨端App/小程序）
- [ ] 已提取目标市场（中国/海外/全栈统一）
- [ ] 已提取团队规模与经验
- [ ] 已提取特殊要求（SSR/SSG/类型安全/规范合规）
- [ ] 已对照知识库选型决策矩阵完成初步判断
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出前端技术方案

- [ ] 推荐框架/技术栈明确并附选型理由
- [ ] 版本选择建议已给出（Vue 3/React 19/Angular 19等）
- [ ] 如为选型，决策矩阵覆盖生态/性能/学习曲线/团队匹配度/长期趋势至少3个维度
- [ ] 如为学习路径，阶段性计划清晰（基础→框架→工程化→实战→性能优化），附验证标准
- [ ] 如为跨端方案，已评估uni-app/原生小程序/Flutter/React Native适用性
- [ ] 如为问题排查，排查步骤从常见到根因，附代码示例
- [ ] 关键趋势点已标注（React 19 RSC/Compiler / Vue 3.5响应式/Vapor Mode / Angular 19 Signals/Zone-less / Skyline引擎 / TypeScript标配）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 输出内容无知识性错误
- [ ] 已向用户交付最终答案

## Overall

- [ ] 工作流中的所有步骤已按顺序执行，没有跳过
- [ ] 每一步都已与其检查清单部分进行交叉验证
- [ ] 没有在任何检查清单部分通过前提前进入下一步
- [ ] `task/current_task.md` 已更新完成记录
- [ ] 所有 `[参考: ...]` 标注均指向存在的知识库文件

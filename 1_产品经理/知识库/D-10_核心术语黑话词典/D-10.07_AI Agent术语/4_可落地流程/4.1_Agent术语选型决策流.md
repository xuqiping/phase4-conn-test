# Agent术语选型决策流

## 适用场景

- 设计Agent产品方案，需要选择架构范式/工具协议
- 评审技术方案，需要验证术语选型合理性
- 面试/汇报中需要自洽地解释Agent技术路线

## 四步决策流

### Step 1：确认你在讨论哪个层级

| 术语层级 | 问自己 | 示例 |
|---|---|---|
| L1 原语层 | "Agent怎么调用能力？" | Tool Use / Function Calling |
| L2 能力层 | "Agent能做什么技能？" | Skills |
| L3 接入层 | "Agent怎么连工具/数据？" | MCP |
| L4 通信层 | "Agent怎么和其他Agent说话？" | A2A / ACP |
| L5 编排层 | "多个Agent怎么协调？" | Workflow / DAG / Orchestration |

> ⚠️ 常见错误：跨层比较（如"MCP和A2A哪个更好"——不同层级，互补不替代）

### Step 2：确认产品是否真的需要Agent

| 问题 | 是 | 否 |
|---|---|---|
| 任务需要多步骤推理+工具调用？ | → 继续选型 | → 用ChatBot+RAG即可 |
| 任务路径不确定（需要动态决策）？ | → 继续选型 | → 用固定自动化流程即可 |
| 需要与环境持续交互？ | → 继续选型 | → 一次性生成足够 |

### Step 3：选择架构范式

→ 见4.2_Agent架构范式选型指南

### Step 4：选择工具协议

| 场景 | 推荐协议 | 理由 |
|---|---|---|
| 单Agent连接内部工具 | MCP | 标准化接入，生态丰富 |
| 多Agent跨平台协作 | A2A | 专为Agent间通信设计 |
| 本地/边缘设备交互 | ACP | 边缘场景优化 |
| 快速原型验证 | 直连Function Calling | 最简单，无需协议层 |

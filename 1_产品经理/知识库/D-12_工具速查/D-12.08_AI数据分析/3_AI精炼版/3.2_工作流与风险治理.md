# 3.2 工作流与风险治理

## 一、AI数据分析师五步工作流

| 步骤 | 动作 | PM输入 | AI输出 | 关键技巧 |
|---|---|---|---|---|
| ① 上传数据 | 上传CSV/Excel到AI工具 | 数据文件 | 数据概览（行数/列名/类型） | 确保数据已脱敏 |
| ② 探索性分析 | "帮我看看这份数据的基本情况" | 自然语言 | EDA报告（分布/缺失/异常） | 先全面浏览再深挖 |
| ③ 提问分析 | "上月DAU环比变化多少？哪个渠道下降最多？" | 具体问题 | 数据结果+图表 | 问题越具体，输出越准确 |
| ④ 洞察提炼 | "有什么值得关注的趋势或异常？" | 开放问题 | 洞察清单+可视化 | 交叉验证AI发现 |
| ⑤ 报告输出 | "生成分析报告" | 格式要求 | 结构化报告 | 人做终审，补充业务判断 |

### PM高频场景实战

**场景A：日/周报数据解读**
- 上传Excel → "对比本周vs上周各核心指标变化，标注显著变化" → 5分钟出结论
- 推荐：ChatGPT Code Interpreter / Julius AI

**场景B：用户分群分析**
- 上传用户数据 → "按活跃度/付费RFM分层，分析各群特征和转化率" → 10-15分钟出报告
- 推荐：Julius AI（预测建模能力强）

**场景C：A/B测试结果解读**
- 上传实验数据 → "判断实验组vs对照组差异是否显著，给出结论" → 5分钟出统计检验
- 推荐：ChatGPT Code Interpreter（Python统计库完整）

**场景D：竞品数据对比**
- 上传多份数据 → "对比3个竞品在X维度的差异" → 10分钟出对比图表
- 推荐：Julius AI / 讯飞智文（中文报告）

## 二、数据质量与幻觉治理

### 2.1 数据质量检查清单

| 检查项 | 方法 | 重要性 |
|---|---|---|
| 数据完整性 | 检查缺失值/空行占比 | ✅必须 |
| 数据口径 | 明确指标定义和计算口径 | ✅必须 |
| 时间范围 | 确认数据时间区间 | ✅必须 |
| 异常值 | 检查显著偏离的极端值 | ✅推荐 |
| 数据量 | 确认数据量级是否合理 | 🟡推荐 |

### 2.2 AI分析幻觉类型

| 幻觉类型 | 表现 | 发生概率 | PM应对 |
|---|---|---|---|
| 计算错误 | AI算错汇总/百分比 | 🟡中频 | 验证关键数字 |
| 方法误用 | 用错统计方法（如非正态用t检验） | 🟡中频 | 指定分析方法或审查AI选的方法 |
| 过度解读 | 对噪声数据过度归因 | 🔴高频 | 质疑"为什么"，要求证据 |
| 遗漏维度 | 忽略重要的分组/维度 | 🟡中频 | 主动补充维度 |
| 伪相关性 | 把相关性当因果性 | 🔴高频 | 警惕"因为A所以B"的结论 |

### 2.3 隐私与合规

| 风险层级 | 数据类型 | 处理方式 | 适用工具 |
|---|---|---|---|

## 四、常见坑

| 坑 | 为什么踩 | 避坑法 |
|---|---|---|
| 数据不脱敏直接上传 | 图省事 | 上传前必脱敏，敏感数据用本地工具 |
| 盲信AI的分析结论 | 可视化好看≠结论正确 | 关键结论人肉验证数字 |
| 问题太开放 | "看看数据有什么问题"→AI漫无目的 | 给具体分析方向和约束 |
| 忽视数据口径 | 不同来源数据口径不同 | 明确数据定义和计算口径 |
| 一次分析太多指标 | 上下文过载→分析浅 | 聚焦1-3个核心问题深入分析 |
| 只看AI画的图 | 图好看但可能选错了图类型 | 审查图表类型是否匹配数据特征 |

## 三、容错四件套检查表

### 3.1 可解释检查

- [ ] 关键事实是否有引用溯源？
- [ ] 推理模型是否展示（摘要）思考过程？
- [ ] 高风险输出是否有置信度标注？
- [ ] AI是否承认"我不知道"的边界？
- [ ] 决策类AI是否给影响因子？

### 3.2 可纠错检查

- [ ] 是否支持重新生成？
- [ ] 是否支持局部编辑？
- [ ] 是否支持精准反馈（标记错误段）？
- [ ] 是否支持定向重生成（指定维度调整）？
- [ ] 是否支持批注对话？

### 3.3 可撤销检查

- [ ] 高风险动作（删/改/下单/转账）是否有Undo或二次确认？
- [ ] 是否有历史快照/版本对比？
- [ ] 是否有草稿-正式双轨？
- [ ] 不可逆动作是否保留N天可恢复？
- [ ] 沙箱预览是否可用？

### 3.4 可降级检查

- [ ] 错误时是否有友好解释（非技术报错）？
- [ ] 是否提供替代建议？
- [ ] 是否可转人工？
- [ ] 是否有重试机制（自动切备用模型）？
- [ ] 云宕机时是否有本地兜底？
- [ ] 是否明确边界"做不了"而非硬撑？

## 五、反馈数据闭环模板

### 5.1 反馈数据采集

```yaml
显性反馈:
  - 类型: 点赞/点踩/星级
  - 字段: timestamp, user_id, message_id, value(1-5), dimension(category/style/factual)
  - 用途: 训练偏好模型/Reward Model

行为反馈:
  - 类型: 复制/编辑/放弃/重试/采纳
  - 字段: timestamp, user_id, message_id, action, edit_distance
  - 用途: 训练采纳率/重写率指标(见 D-19.05 AI产品指标)

纠错反馈:
  - 类型: 用户修改内容
  - 字段: timestamp, user_id, message_id, original_text, edited_text
  - 用途: SFT/DPO训练数据(用户授权)

批注反馈:
  - 类型: 文字反馈
  - 字段: timestamp, user_id, message_id, comment
  - 用途: 微调训练数据/质量分析

场景反馈:
  - 类型: 使用场景标签
  - 字段: timestamp, user_id, message_id, scenario_tag
  - 用途: 场景识别与路由优化
```

### 5.2 数据回流路径

```
[采集] → [脱敏/合规审查] → [标注质量分] → [分级]
  ├→ 高质量反馈 → 进SFT/DPO训练集
  ├→ 中质量反馈 → 进Prompt优化样本
  └→ 低质量反馈 → 进Safety训练负样本
[迭代] → 模型/Prompt更新 → 灰度发布 → 监测采纳率/重写率 → 全量
```

> 红线：反馈数据采集必须有"用户授权"前置，符合数据隐私合规（详见 D-16.01 数据隐私）

## 六、A/B实验设计模板

### 6.1 AI体验A/B特殊考虑

- **指标延迟**：AI体验指标（采纳率/重写率）需要时间积累，不能像传统A/B一样1-2天判定
- **样本异质性**：不同任务类型的A/B结果可能相反，需分群分析
- **学习曲线**：新范式初期体验差（用户不熟悉），需观察学习曲线
- **跨会话效应**：个性化记忆影响跨会话体验，不能孤立看单次

### 6.2 实验设计模板

```yaml
假设: "采用Canvas替代纯对话式，将提升长文档创作的任务完成率"
指标:
  主指标: 任务完成率(%)
  辅助指标: 采纳率/重写率/平均会话轮数/用户满意度
  反指标: 平均耗时/弃用率
分群:
  - 任务复杂度: 简单/中等/复杂
  - 用户类型: 新用户/老用户/重度用户
样本量: (按统计功效计算)
实验时长: ≥2周（覆盖学习曲线+跨会话）
灰度策略: 5%→20%→50%→100%（监测反指标停损）
```

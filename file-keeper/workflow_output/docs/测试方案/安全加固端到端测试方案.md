# 安全加固端到端测试方案

> 功能：安全加固（离线授权与门禁）
> 范围：Chunk 4 中无法仅通过单元/内联测试覆盖的端到端场景
> 关联计划：[../plans/安全加固-离线授权与门禁.plan.md](../plans/安全加固-离线授权与门禁.plan.md)
> 关联代码：[file-keeper/src-tauri/src/commands/auth.rs](../../../src-tauri/src/commands/auth.rs)

---

## 1. 测试目标

验证以下真实运行时场景：

1. 断网 + 旧 signed entitlement 过 `notAfter` 后，特权命令被拒绝。
2. 修改系统时钟试图绕过过期校验时，Rust 侧 `SystemTime::now()` 判定仍能有效拦截。
3. 直接通过 Tauri invoke 调用特权命令（绕过前端 UI）时，Rust 侧 `require_module` 门禁拒绝无凭据或无权请求。
4. 升级后本地残留旧 HMAC token 时，前端检测到格式不兼容并强制在线刷新一次。

---

## 2. 环境准备

| 项 | 要求 |
|---|---|
| 后端 | 本地启动 `server/`，配置有效的 `FILE_KEEPER_ENTITLEMENT_PRIVATE_KEY`（缺失则服务端应拒绝启动） |
| 桌面端 | 使用 dev 模式启动 `src-tauri/`，确保 `resources/public_key.pem` 与后端私钥配对 |
| 测试账号 | 管理员已审核通过、已授权 `processes` / `clipboard` / `work-report` 模块的商业账号 |
| 网络 | 可切换为离线（关闭后端或断网） |

---

## 3. 用例

### 用例 1：断网 + token 过期后特权命令被拒

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 登录商业账号，确认 `processes` / `clipboard` 模块可用 | 模块 Tab 可点击，Rust 凭据已同步 |
| 2 | 管理员在后台将该账号 `offlineCacheMinutes` 设为极短（如 1 分钟） | 后端签发的 `notAfter` 接近当前时间 |
| 3 | 断开网络或关闭后端 | 前端进入离线态 |
| 4 | 等待 `notAfter` 过期（或等待 2 分钟） | - |
| 5 | 尝试使用进程关闭、剪贴板监听、截图等特权功能 | Rust 返回「授权凭据已过期，请联网刷新」，操作被拦截 |
| 6 | 恢复网络，点击刷新授权 | 重新获取有效 signed entitlement，特权功能恢复 |

> 自动化等价覆盖：`auth.rs` 内联测试 `require_module_rejects_expired_token`、`verify_rejects_expired_token_by_not_after` 已覆盖过期 token 拒绝逻辑。

---

### 用例 2：修改系统时钟

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 登录并获取有效离线授权 | 模块可用 |
| 2 | 将系统时间向后调 1 天（超过 `notAfter`） | - |
| 3 | 尝试调用特权命令 | Rust `SystemTime::now()` 读取到修改后的时间，token 被判定为过期并拒绝 |
| 4 | 将系统时间调回正确时间 | 如 token 仍在 `notAfter` 内，功能恢复 |

> 说明：系统时钟回拨/前调无法通过纯单元测试可靠模拟，需人工修改 OS 时间验证。单元测试通过设置过去/未来的 `notAfter` 覆盖时间判定逻辑本身。

---

### 用例 3：直接 invoke 特权命令

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 未登录或未授权状态下，打开 DevTools / 使用 Tauri 调试工具 | - |
| 2 | 直接调用 `close_process` / `start_clipboard_monitor` / `capture_screenshot_region` / `fetch_git_logs` 等命令 | 命令返回「缺少授权凭据」或「未授权访问 XX 模块」错误，不会执行敏感操作 |
| 3 | 登录授权账号后再次直接 invoke | 命令正常执行 |
| 4 | 在授权账号下，管理员后台移除 `clipboard` 模块授权，刷新后再次 invoke 截图 | 命令返回「未授权访问 clipboard」，截图被拦截 |

> 自动化等价覆盖：各命令文件均已调用 `entitlement_state.require_module(MODULE_CODE)`，`auth.rs` 测试覆盖 Missing / ModuleNotAllowed / Expired / SignatureMismatch 等拒绝路径。

---

### 用例 4：旧 HMAC token 兼容

| 步骤 | 操作 | 预期结果 |
|---|---|---|
| 1 | 在升级前版本登录并获取离线 token（HMAC 格式，无 `.` 分隔符） | 旧 token 存在于本地状态 |
| 2 | 升级到 Ed25519 版本并启动 | 前端检测到 token 无 `.`，清空 Rust 凭据并提示「授权凭据已升级，请联网刷新一次」 |
| 3 | 恢复网络，重新登录或刷新授权 | 获取新的 signed entitlement，功能正常 |

> 自动化等价覆盖：`commercialAuthStore` 单测 `clears Rust entitlement and forces online refresh when legacy HMAC token is detected` 已覆盖检测与清空逻辑。

---

## 4. 通过标准

- 用例 1~4 均按预期拒绝或提示刷新，无敏感操作实际执行。
- 恢复网络/授权后，对应模块功能恢复正常。
- DevTools 直接 invoke 无法绕过门禁。

---

## 5. 风险与注意事项

- 修改系统时间可能影响 OS 证书校验、浏览器等，建议在虚拟机或测试机上执行。
- 测试用例 1 中管理员后台调整 `offlineCacheMinutes` 后，需重新登录或刷新授权才能使新 token 生效。
- 旧 HMAC token 用例需要保留旧版本构建产物或手动构造旧格式 token。

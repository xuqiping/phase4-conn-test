# File Keeper 商业授权后续实施计划（调整版） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在阶段 1-4 已完成成果基础上，补齐桌面端账号 UI、免费模块选择、真实环境联调和商业版收口能力，让 File Keeper 商业授权第一版达到可验收状态。

**Architecture:** 服务端授权 API 和管理后台核心能力已完成，后续不重做阶段 1-4，而是在现有 `commercialAuth` API/Store、管理后台用户详情页和桌面端模块门禁基础上补齐用户可操作入口。后续主线调整为：先统一联调配置，再补桌面端登录注册和账号状态 UI，再补匿名过期后的免费模块选择，最后执行真实环境端到端联调。

**Tech Stack:** Spring Boot 3.2.5、Java 17、PostgreSQL、Redis、Vue 3、TypeScript、Vite、Naive UI、Pinia、Tauri 2、Vitest、Maven。

## 0. 调整依据

### 0.1 原总计划与实际阶段四的差异

原文件 `file-keeper/项目相关文档/商业售卖版账号权限与授权系统实施计划.md` 的阶段划分是：

1. 阶段 1：服务端基础与核心数据模型。
2. 阶段 2：账号注册、验证、登录、管理员审核 API。
3. 阶段 3：模块授权、设备绑定、匿名权益 API。
4. 阶段 4：Web 管理后台 MVP。
5. 阶段 5：桌面客户端登录、注册、权益快照。
6. 阶段 6：桌面客户端模块门禁与商业版收口。
7. 手动端到端验收。

实际阶段四进度文件 `file-keeper/docs/superpowers/plans/2026-06-08-4商业计划开发进度.md` 显示，阶段四没有只做原计划阶段 4，而是同时完成了：

- 管理后台核心 MVP：管理员登录、用户列表、用户详情、审核、启用/禁用、用户设备限制、离线缓存时长、模块授权、设备禁用。
- 桌面端匿名授权接入：设备身份、本地持久化、匿名试用启动、匿名授权查询。
- 桌面端登录用户授权底层接入：设备注册、登录用户授权快照查询、离线缓存可用性判断。
- 桌面端模块门禁核心：三模块 Tab 禁用、剪贴板/截图/关闭进程等入口授权检查、授权变化后切换可用模块。
- 端到端联调场景清单和自动化验证记录。

因此，后续计划不能再按原阶段 5/6 全量重做，应改为“补缺口 + 联调验收”。

### 0.3 当前真实缺口

必须补齐：

1. 服务端端口与前端默认 API 地址不一致：服务端默认 `8088`，管理后台和桌面端默认 `8080`。
2. 桌面端缺少登录/注册/退出 UI。
3. 桌面端缺少客户端认证 API 封装与认证 Store。
4. 登录成功后尚未从 UI 调用 `commercialAuthStore.initializeAuthenticated()`。
5. 桌面端缺少用户可见的授权状态组件。
6. 匿名试用过期后，桌面端缺少选择/更换免费模块 UI。
7. 真实环境端到端联调尚未执行。

可选后置，不阻塞第一版验收：

1. 管理后台 Dashboard。
2. 管理后台系统设置页。
3. 管理后台匿名设备运营页。
4. 管理后台用户详情页拆组件。
5. Rust 侧授权二次校验。
6. 支付、套餐、订单。
7. 业务数据云同步。

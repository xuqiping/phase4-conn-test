### C11 — AlertRouter 钉钉告警
**目标**：安全事件按 severity 分流到钉钉适配器，高危即时 + 中危凑批。

**动作（伪代码）**：
```
common/security/alert/AlertRouter:
  dispatch(verdict):
      if !security.alert.enabled: return   // 总闸
      switch (severity):
        CRITICAL/HIGH: sendImmediate(verdict)   // 即时发
        MEDIUM: batcher.add(verdict)            // 攒 30s 凑批
        LOW: 不发（只入库）

  sendImmediate(v):
      payload = buildDingtalkCard(v)   // markdown 卡片：类型/IP/用户/规则/traceId/处置入口深链
      async: webhookNotifier.post(security.alert.webhook.url, payload)
      // webhook 故障吞（不阻 record），失败计数 bizMetrics.alertSendFailed

  MediumBatcher (@Scheduled fixedDelay=30s):
      flush(): if !queue.isEmpty(): 合并成一条汇总钉钉 → sendImmediate(汇总)

common/security/alert/DingtalkCardBuilder:
  // 复用现有 Alertmanager 钉钉适配器的消息格式
  buildCard(v): markdown {
    title: "[安全告警·{severity中文}] {eventType中文}",
    text: "**类型**：{eventType}\n**严重度**：{severity}\n**用户**：{userId/username}\n**IP**：{ip}\n**规则**：{ruleId}\n**时间**：{createdAt}\n**自动处置**：{autoAction}\n**traceId**：{traceId}\n[查看详情](/admin/security/events?id={eventId})"
  }
  // EventType 中文映射（AuditLabelDictionary 同款字典思路）

common/security/alert/WebhookNotifier:
  post(url, payload): WebClient POST，超时 5s，不重试或限 1 次退避
  try/catch 吞 + bizMetrics.alertSendFailed+1

// 钉钉适配器侧（运维系统已有 alertmanager/dingtalk-webhook）：
// 确认适配器收应用直推 JSON 入口；若无，加 /security-event 路由复用 webhook 转译逻辑
```
**涉及文件（6）**：
- `common/security/alert/AlertRouter.java`（新建）
- `common/security/alert/MediumBatcher.java`（新建，@Scheduled）
- `common/security/alert/DingtalkCardBuilder.java`（新建）
- `common/security/alert/WebhookNotifier.java`（新建，复用 WebClient）
- `common/security/SecurityEventService.java`（P2 建，record 内调 alertRouter.dispatch —— 仅新记录触发）
- `common/metrics/BizMetrics.java`（+alertSent/alertSendFailed）

**依赖**：C8（Worker 调 dispatch）、运维系统钉钉适配器（已部署）。

**验证**：
- 单测 AlertRouter：CRITICAL/HIGH 即时发；MEDIUM 攒批 30s；LOW 不发。
- 单测 webhook 故障 → 吞 + 计数，不抛。
- 单测 webhook 配空 → 不推。
- 单测卡片含 traceId + 处置入口深链。
- E2E：触发 HIGH 事件 → 钉钉群收卡片（含 traceId）；触发 MEDIUM → 30s 后收汇总。

**坑**：
- *webhook 故障风暴*：适配器挂了 → 每事件重试刷量。**规避**：不重试或限 1 次退避；失败计数 + 告警（meta 告警，避免静默）。
- *凑批顺序*：MediumBatcher @Scheduled 固定 30s，重启丢队列。**规避**：MEDIUM 事件已入库（security_events），重启后前端可查；钉钉丢一批可接受。
- *钉钉限流*：钉钉机器人 1min 20 条限。**规避**：HIGH 即时但同 rule+key 去重（C8 已去重，同事件 5min 1 条）；MEDIUM 凑批天然降量。极端时钉钉返回限流 → 计数 + 退避。
- *适配器入口*：若现有适配器只收 Alertmanager 格式，安全事件需转译。**决策**：WebhookNotifier 直接按钉钉机器人原生 markdown 格式 POST（绕过 Alertmanager 适配器，直接打钉钉 webhook URL）。即 `security.alert.webhook.url` = 钉钉机器人 webhook（非 Alertmanager 适配器）。**部署必做**：配钉钉机器人 webhook URL + 加签密钥。

### C12 — 4 admin 前端页
**目标**：侧栏「安全管理」下 4 页，复用现有 AuditLogView 骨架。

**动作（伪代码）**：
```
后端 Controller（common/security/controller/）:
  SecurityEventController:
    GET  /api/security/events?eventType&severity&status&userId&ip&timeRange&page&size
         @RequirePermission("security:event:read")
    POST /api/security/events/{id}/handle   @RequirePermission("security:event:read")  // 标记 handled
    GET  /api/security/events/stats         → 24h 计数/分布（风险大盘用）

  IpBlacklistController (C6 已建端点，前端接)

  RuleConfigController:
    GET  /api/security/rules                → 读 system_settings 所有 security.rule.* / security.rate.*
         @RequirePermission("security:rule:manage")
    PUT  /api/security/rules/{ruleKey}      → 改阈值/开关（@AuditLog）
         @RequirePermission("security:rule:manage")

  封号：复用现有 PUT /api/users/{id}/status（C3 改造）

前端（frontend/src/views/admin/security/，新建目录）:
  SecurityEventView.vue（安全事件中心）:
    复用 AuditLogView 骨架：筛选栏(eventType下拉/severity/状态handled/用户/IP/时间段) + 分页表格 + 详情弹窗
    表格列：时间/类型(中文Tag)/严重度(Tag色)/用户/IP/规则/自动处置/状态/操作
    「处置」按钮 → handle → handled=true + handled_by/at
    「批量清理」→ 物理删选中行（运维可删，仅 security:event:read + 二次确认）

  BanManageView.vue（封禁管理）:
    上：用户封号区——搜用户 + 封号(选 status BANNED/DISABLED/LOCKED + reason) / 解封
    下：IP 封禁区——ip_blacklist 列表 + 手动封IP(原因/时长) / 解IP

  RuleConfigView.vue（规则配置）:
    8 类规则（9 规则码）各一组：enabled 开关 + 阈值输入（读 system_settings）
    总闸：auto_ip_block / auto_account_lock / security.alert.enabled 开关
    「保存」→ PUT rules（@AuditLog）

  RiskDashboardView.vue（风险大盘）:
    24h 事件计数大数字 + 严重度分布图（Naive UI 复用）+ 待处置列表（handled=false）

路由/侧栏：
  router/index.ts: /admin/security/{events|ban|rules|dashboard}
  components/Sidebar.vue: 「安全管理」组（4 子项）+ 事件中心 badge（轮询 stats 60s，未处理计数）
```
**涉及文件（12）**：
- `common/security/controller/SecurityEventController.java` + `SecurityEventVO.java`
- `common/security/controller/RuleConfigController.java` + `RuleConfigVO.java`
- `common/security/controller/IpBlacklistController.java`（C6 建，确认前端接口）
- `common/security/entity/SecurityEvent.java`（P2 建，+ VO 映射）
- `common/security/SecurityEventMapper.xml`（分页/筛选/handle/stats）
- `frontend/src/api/security.ts`（新建，封装 4 组接口）
- `frontend/src/views/admin/security/SecurityEventView.vue`（新建）
- `frontend/src/views/admin/security/BanManageView.vue`（新建）
- `frontend/src/views/admin/security/RuleConfigView.vue`（新建）
- `frontend/src/views/admin/security/RiskDashboardView.vue`（新建）
- `frontend/src/router/index.ts`（+4 路由）
- `frontend/src/components/Sidebar.vue`（+安全管理组 + badge）

**依赖**：P2/P3（数据 + 规则 + system_settings）。

**验证**：
- 单测 Controller：分页/筛选/handle 条件 UPDATE（并发幂等）/stats。
- vue-tsc + vitest 前端绿。
- E2E playwright：
  - 安全事件中心：筛选 + 详情 + 处置 → 状态变 + badge 减
  - 封禁管理：封号 → 用户列表状态变；封 IP → 该 IP 403；解封恢复
  - 规则配置：关某规则 → 该规则不再触发；调阈值 → 生效；关 auto_ip_block → HIGH 事件不封 IP
  - 风险大盘：24h 计数图渲染
  - 无 `security:*` 权限 → 入口不显示 + 直输 URL 403

**坑**：
- *权限粒度*：security:event:read（看事件 + handle）；security:ban:manage（封号封IP）；security:rule:manage（改规则）。三权分立。
- *批量清理误删*：物理删不可逆。**规避**：二次确认 + 仅 admin 角色 + @AuditLog 留删行审计。
- *badge 实时性*：轮询 60s 够（告警非秒级）；SSE 推 **后续**。
- *脱敏*：事件 detail_json 出口过 LogMasker（复用后端富化，前端只展示已脱敏）。
- *规则配置改阈值生效*：Worker 读 system_settings 实时值（非启动缓存），改即生效。**规避**：SystemSettingService 已有缓存（短 TTL），改后清缓存或 TTL 自动刷新。

```
system_settings 默认键（V104 seed 或 application.yml 默认）:
  security.rate.enabled=true
  security.rate.global.ip_per_minute=600
  security.alert.enabled=true
  security.alert.webhook.url=${SECURITY_ALERT_WEBHOOK_URL:}   # 空=不推
  security.alert.webhook.secret=${SECURITY_ALERT_WEBHOOK_SECRET:}  # 钉钉加签
  security.response.auto_ip_block=true
  security.response.auto_account_lock=true
  security.ip.trust_proxy=false   # 部署确认改

  security.rule.LOGIN_BRUTE_FORCE.enabled=true / max_fail=5 / window_minutes=15 / lock_minutes=15
  security.rule.CREDENTIAL_STUFFING.enabled=true / distinct_ip=20 / window_minutes=5 / block_hours=1
  ... (每规则一组，admin 可调)
```

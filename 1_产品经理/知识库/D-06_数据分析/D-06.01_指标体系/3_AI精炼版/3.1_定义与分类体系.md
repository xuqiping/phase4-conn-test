# 3.1 定义与分类体系

## A.01 核心定义

**指标体系（Metrics System）** 是一组结构化、层级化的度量指标集合，用于全面、准确地反映产品/业务的健康状态与增长态势。它不是指标的简单罗列，而是通过北极星指标→驱动指标→过程指标的层级拆解，形成"从战略到执行"的度量闭环。[来源: Amplitude, 2023 | 置信度:🔍高]

**一句话定位**：指标体系是产品的"仪表盘"——告诉你"产品健不健康、往哪走、走多快"，让每一个决策有据可依。

## A.02 复杂度谱系

| 复杂度 | 指标规模 | 典型场景 | 体系需求 |
|---|---|---|---|
| 1-简单 | 3~8个 | MVP验证、内部工具 | 北极星+2~3个过程指标 |
| 2-中等 | 8~20个 | 成长期C端产品 | 北极星+指标树+看板 |
| 3-复杂 | 20~50个 | 成熟期平台型产品 | 多维度指标森林+护栏指标+实验指标 |
| 4-超复杂 | 50+个 | 生态型/多业务线产品 | 分层治理+指标目录+自动化监控 |

## A.04 边界与不含什么

**指标体系包含**：指标定义、分类、层级拆解、选型方法论、框架对比、护栏指标设计、指标治理规范。

**指标体系不含**：数据采集技术实现（→D-06.02）、具体分析方法如漏斗/留存（→D-06.03/04）、A/B实验设计（→D-06.07）、数据看板搭建工具（→D-12）。

## D.01 定义域

| 维度 | 说明 |
|---|---|
| 核心问题 | "用什么度量产品？怎么确保度量全面且不冗余？" |
| 适用对象 | 产品经理、数据分析师、增长负责人、CEO |
| 典型使用 | OKR制定、周报月报、数据看板设计、增长实验度量 |
| 不适用 | 纯技术性能监控（QPS/延迟）、财务报表编制 |

## I.01 核心术语

| 术语 | 定义 |
|---|---|
| 北极星指标(NSM) | 最能反映产品核心价值交付的单一指标，全员对齐的方向标 [来源: Reforge | 置信度:🔍高] |
| 输入指标(Input Metric) | 团队可直接影响的过程指标，是NSM的驱动因子 |
| 输出指标(Output Metric) | 业务结果指标，通常是NSM本身或其近邻 |
| 护栏指标(Guardrail Metric) | 防止优化核心指标时损害其他关键维度的约束指标 |
| 虚荣指标(Vanity Metric) | 看起来好看但无法指导行动的指标（如总注册数） |
| 领先指标(Leading Indicator) | 预测未来结果的先行指标 |
| 滞后指标(Lagging Indicator) | 反映已发生结果的指标（如月收入） |
| 代理指标(Proxy Metric) | 无法直接度量时使用的替代指标 |
| 指标树(Metrics Tree) | 从NSM逐层拆解到团队可执行指标的层级结构 |
| 定量指标 | 可数值化的度量（DAU/转化率/ARPU） |
| 定性指标 | 非数值化的度量（用户满意度/NPS/反馈主题） |

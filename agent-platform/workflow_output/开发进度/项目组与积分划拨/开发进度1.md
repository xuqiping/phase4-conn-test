## 关键设计

1. **编号 V133 非计划的 V130**——仓库迁移已到 V132，占位号作废（偏差已记 plan）。
2. **钱包/流水不继承 BaseEntity**：单行 update 表没有软删/乐观锁语义；append-only 流水同理。沿用 V65 points 钱包先例。
3. **防透支下沉数据库**：`deduct` 条件 UPDATE 靠行锁原子性，两成员并发扣最后一百分不会双成功（IT 验证第二次返 0 行、余额停在 4）。另有 `ck_pgw_nonneg` CHECK 双保险。
4. **组流水 FK 不带 CASCADE**：组可删，钱的历史不可随组消失（回滚块里也警告 ledger 须先导出）。members/wallets 才 CASCADE。
5. **points_ledger type 是 CHECK 不是注释**：PG 不能 ALTER CONSTRAINT 加值，走 DROP `chk_ledger_type` + re-ADD 六枚举（+GROUP_ALLOCATE/GROUP_RECLAIM）。
6. **对账模板内嵌迁移尾部**：ledger-vs-wallet 逐组对账 + 成员 used 对账两条 SQL，运维不用现想。

| `test/.../ProjectGroupWalletServiceIT.java` | 9 用例：并发/幂等/死锁/对账 |

## 关键设计

1. **固定锁序防死锁**：双向操作（allocate/reclaim/backstop）恒「先个人行→后组池行」；组内操作（charge/refund）恒「组池→成员行」。两序无交叉环，IT 用 4 线程双向×组内混跑验证零死锁。
2. **幂等复用 idempotency_keys**：scope=group.charge/group.refund，result_ref=组流水 id；同键同额静默重放返首次 balance_after，异额/跨身份 CONFLICT（镜像 PointsWalletService.runIdempotent）。
3. **BACKSTOP 口径**：差额扣组长个人（CONSUME, ref=GROUP），组池不动（行锁 FOR UPDATE 读一致 balance_after）；组流水 delta=−差额但不进余额重建、不计成员 used——对账口径「Σdelta 剔除 BACKSTOP == 钱包」。
4. **reclaim 在途上限**：上限=组池−Σ(PENDING/RUNNING 的 estimated_cost)；锁前读有窄竞态，兜底=条件 deduct，最坏在途占用回笼后结算走 BACKSTOP，不丢钱。
5. **quota 守卫在 SQL**：`addUsed` 条件更新 `quota IS NULL OR used+cost<=quota`，返 0 行=超限→整体回滚（组池分文不动）。

## 踩坑

- `idempotency_key` 表名实为 `idempotency_keys`（复数）——IT clean SQL BadSqlGrammar 一轮。
- IT 用户夹具须 `OVERRIDING SYSTEM VALUE` 显式指定 id（IDENTITY），否则 addMember 的用户存在性校验查不到。

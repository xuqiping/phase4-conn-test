## 3. 详细步骤

### TC-01 AGENTS.md 自动维护（AC-009）

1. 新建项目。
2. 进入「项目约定 / AGENTS 配置」面板。
3. 修改「项目一句话定位」为「一个给老人用的用药提醒小程序」。
4. 修改「技术栈偏好」为「Taro + React + TypeScript」。
5. 保存。
6. 打开项目根目录 `AGENTS.md`。

**预期结果**：
- `AGENTS.md` 存在且顶部有「本文件由 DevPilot 自动维护」提示。
- 文件正文包含「给老人用的用药提醒小程序」与「Taro + React + TypeScript」。
- 全程未要求用户手动编辑 `AGENTS.md`。

### TC-02 想法歧义追问（AC-048）

1. 进入「想法」视图。
2. 在「做给谁」只填「年轻人」。
3. 在「解决什么痛点」填「提高效率」。
4. 其他问题随意填或留空。
5. 点击「生成分析」。

**预期结果**：
- 系统不直接生成报告，而是弹出追问对话框（至少 1 个问题）。
- 追问问题针对歧义，例如「提高效率具体指哪方面？」或「目标用户群体能否再细分？」。
- 回答追问后再次生成，方可进入报告。

### TC-03 想法报告三选一建议（AC-033）

1. 完成 TC-02 追问或一次性填写清晰想法（目标用户/痛点/竞品/盈利/技术约束均明确）。
2. 点击「生成分析」。
3. 等待生成完成。

**预期结果**：
- 页面展示项目分析报告，含「市场/用户/竞品/技术/风险」摘要。
- 报告底部给出明确建议：「值得做」或「建议先缩小范围」或「建议再想想」。
- 报告文件写入 `workflow_output/docs/项目分析/项目分析报告.md`。

### TC-04 未确认卡锁定开工（AC-034 反）

1. 在 TC-03 基础上进入「需求」视图。
2. 点击「从报告生成需求卡」。
3. 系统生成若干卡片，默认状态为 pending。
4. 只确认其中一部分，保留至少 1 张 pending。
5. 观察「进入计划」按钮。

**预期结果**：
- 「进入计划」按钮禁用或点击后提示「还有 N 张需求卡未确认」。
- 不进入「计划」视图。

### TC-05 全确认后进入计划（AC-034 正）

1. 继续 TC-04，把剩余卡片全部确认或跳过。
2. 点击「进入计划」。

**预期结果**：
- 成功进入「计划」视图。
- 状态机管道条中「需求确认」门禁显示 ✅。

### TC-06 未审批计划不写代码（AC-035 反）

1. 在「计划」视图点击「生成施工计划」。
2. 系统生成若干 chunk 卡片（状态 draft）。
3. 不点击「审批计划」，直接查看项目源码目录。

**预期结果**：
- 除 `workflow_output/` 文档外，项目源码目录没有任何新文件/修改。
- `tasks` 表无新增任务。

### TC-07 审批计划后创建任务并解锁 build（AC-035 正）

1. 在 TC-06 基础上点击「审批计划」。
2. 确认审批弹窗。
3. 查看项目源码目录与状态机。

**预期结果**：
- 项目源码目录仍无代码改动（审批只创建任务，不执行）。
- `tasks` 表按 chunk 顺序生成若干 status=pending 的任务。
- 状态机管道条中「开工」门禁显示 ✅，项目阶段可推进到 build。

### TC-08 重新生成报告清空旧卡（联动·反）

1. 已完成 TC-05（需求卡已确认）。
2. 返回「想法」视图，修改某个答案后重新生成报告。
3. 返回「需求」视图。

**预期结果**：
- 页面提示「重新生成报告将清空现有需求卡，是否继续？」。
- 确认后旧卡全部消失，新卡回到 pending。
- 原确认状态不保留。

### TC-09 审批后编辑计划需撤销（联动·反）

1. 已完成 TC-07。
2. 在「计划」视图尝试编辑某 chunk 标题。

**预期结果**：
- 页面提示「计划已审批，编辑前需先撤销审批」。
- 撤销后对应 `tasks` 记录被删除，chunk 回到 draft。
- 重新审批后再次生成 tasks。

### TC-10 批量跳过仍锁定开工（半选/批量）

1. 生成需求卡后，使用「全部跳过」按钮跳过所有卡。
2. 观察「进入计划」按钮。

**预期结果**：
- 因为所有卡都被跳过而非确认，「进入计划」按钮仍禁用，提示「至少确认 1 张需求卡」。
- 批量确认 N-1 张、跳过 1 张时，按钮同样锁定。

## 4. 自动化辅助断言

| 断言点 | 实现位置 |
|---|---|
| 保存 AGENTS 表单后文件存在且含关键词 | Rust 单元测试 / 前端组件测试 |
| `spec_cards` 全确认前 `requirement_confirm` 门禁未过 | 状态机单元测试 |
| `approve_plan` 后 `tasks` 表记录数 == `plan_chunks` 数 | Rust 单元测试 |
| 未审批前源码目录无改动 | 沙箱 runner 单测或文件系统断言 |
| `generate_*` 返回追问时 `need_clarify=true` | generator 单元测试 |

- 自动化辅助断言无 FAIL。

# 3.2 问卷设计与类别判定方法

## 正反向配对问卷

KANO类别的判定依赖**正反向配对问题**——同一需求问两遍：

| 问题类型 | 问法 | 回收信息 |
|---|---|---|
| **正向问题**（功能性） | "如果产品有这个功能，你觉得怎么样？" | 满足时的满意度反应 |
| **反向问题**（反向性） | "如果产品没有这个功能，你觉得怎么样？" | 不满足时的满意度反应 |

每题采用**5级Likert量表**：

| 等级 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 正向 | 喜欢 | 理应如此 | 无所谓 | 勉强接受 | 讨厌 |
| 反向 | 喜欢 | 理应如此 | 无所谓 | 勉强接受 | 讨厌 |

### 判定矩阵

将正向×反向的5×5组合映射为KANO类别：

| 正向\反向 | 喜欢 | 理应如此 | 无所谓 | 勉强接受 | 讨厌 |
|---|---|---|---|---|---|
| **喜欢** | Q(可疑) | A(魅力) | A(魅力) | A(魅力) | O(期望) |
| **理应如此** | R(反向) | I(无差异) | I(无差异) | I(无差异) | M(必备) |
| **无所谓** | R(反向) | I(无差异) | I(无差异) | I(无差异) | M(必备) |
| **勉强接受** | R(反向) | I(无差异) | I(无差异) | I(无差异) | M(必备) |
| **讨厌** | R(反向) | R(反向) | R(反向) | R(反向) | Q(可疑) |

> Q=可疑回答（矛盾回答，正向和反向都"喜欢"或都"讨厌"），需剔除或回访。[来源:百度百科·KANO模型 | 🔍高]

## 类别判定三法 [I.20必选·KANO类别判定标准]

**这是D-02.04的必选核心维度**——从问卷数据到最终类别归类存在多种判定方法，选择不当会导致分类结果截然不同。

### 方法一：Max频率法（最常用）

**规则**：取样本中频率最高的类别为最终类别。

```
示例：某需求问卷回收100份
M=25, O=35, A=20, I=15, R=3, Q=2
→ Max=O → 最终类别=期望型
```

| 优点 | 缺点 |
|---|---|
| 简单直观，快速出结果 | 忽略分布形态，多峰分布时失真 |
| 样本量大时稳健 | 当Max频率<40%时判信度不足 |
| 行业使用最广泛 | 对M和A的区分力弱 |

**适用场景**：快速分类、样本量>50、分布较集中时。

### 方法二：优势类别法（更精细）

**规则**：计算M+O与A+I的比值，取优势方中的主导类别。

```
示例：同上数据
M+O = 60（功能驱动态势强）
A+I = 35（吸引力态弱势）
→ 功能驱动优势 → 在M和O中取Max(O=35>M=25) → O
```

| 优点 | 缺点 |
|---|---|
| 考虑了类别间的结构关系 | 对中间地带的需求仍模糊 |
| 区分M/O/A更有逻辑 | 计算稍复杂 |
| 适合需求演化诊断 | 样本量小时不稳定 |

**适用场景**：产品规划、演化诊断、需要区分M/O/A时。

### 方法三：阈值判定法（最严格）

**规则**：设定频率阈值，仅当某类别频率≥阈值时才确认，否则标记"待定"。

```
阈值设定建议：
- 强判定阈值：某类别频率≥50% → 确认该类别
- 弱判定阈值：某类别频率≥40% → 倾向该类别，需交叉验证
- 低于40%：标记"混合类别"，结合Better-Worse系数综合判定

示例：某需求 M=45%, O=30%, A=15%, I=8%, R=2%
→ M≥40%但<50% → 弱判定：倾向必备，需Better-Worse验证
```

| 优点 | 缺点 |
|---|---|
| 避免强行归类的误判 | 可能产生较多"待定"项 |
| 判定结果可信度高 | 需要更大样本量支撑 |
| 适合高决策成本场景（如B端大客户） | 阈值需根据场景调整 |

**适用场景**：高决策成本、B端大客户、需严格论证时。

### 三法选择决策树

```
样本量≥80 且 分布集中(Max>40%)？
  ├─ 是 → Max频率法（快速出结果）
  └─ 否 → 需要区分M/O/A的功能规划？
              ├─ 是 → 优势类别法
              └─ 否 → 决策成本高(如大客户)？
                          ├─ 是 → 阈值判定法
                          └─ 否 → Max频率法+Better-Worse验证
```

## 问卷设计的实战要点

| 要点 | 说明 | 常见坑 |
|---|---|---|
| **样本量** | 每个需求至少30份有效问卷，推荐50+ | 样本太少→分类不稳定 |
| **需求粒度** | 每个需求独立成题，不合并 | 合并需求→混合类别无法解释 |
| **用户筛选** | 目标用户群，排除非目标用户 | 混入非目标用户→I类虚高 |
| **预测试** | 正式投放前5-10人预填 | 不预测试→Q类异常高 |
| **反向问题措辞** | 用"如果没有"而非"不能有"，避免负面暗示 | 措辞不当→引导性作答 |
| **需求数量** | 单次问卷≤20个需求，防疲劳 | 需求过多→后半段填答质量下降 |

> 关键：KANO问卷的效度高度依赖**用户群与需求的匹配度**——如果受访用户不是需求的目标人群，结果将严重失真。[来源:📚训练知识 | 📚中]

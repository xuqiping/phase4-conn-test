# 部署手册终 · 多Agent智能体平台（agent-platform）

> Phase 5 产物（2026-08-10 终版，取代 `部署手册.md`）。受众：第一次部署的你 / 运维 / 接手的人——**照着勾就能上线**。
> 部署模型：**开发机（本机）构建产物，服务器只跑运行时**（不装 Maven/Node）。
> 架构：`浏览器 → Nginx(80 跳转 443 HTTPS) → backend jar(8080) ↔ runtime-sidecar(8090)`；依赖 `PostgreSQL16+pgvector(5432)`、`Redis(6379)`、`ffmpeg(视频剪辑)`。
> **参考视频硬要求**：Ark 必须能从公网回拉可信证书的 HTTPS URL。当前服务器公网 IP 为 `117.72.25.74`；只有 `http://117.72.25.74` 时系统其他功能可用，但参考视频不可用。无域名时可临时使用 Cloudflare Quick Tunnel，或在确实取得可信 CA 的 IP-SAN 证书后使用 `https://117.72.25.74`；正式生产仍推荐域名 + HTTPS。
> 本地开发启动见 `项目工程文档/0_快速启动.md`；本手册面向**部署上线**。

## 四、傻瓜式部署步骤（服务器，Step 1~6）

服务器目标目录：`E:\agent-platform\{backend, frontend\dist, runtime-sidecar, logs}`。

### Step 1 · 装依赖软件（每装一个即验证）

- [ ] **JRE 17**：拷 `installers\jdk-17.0.19` → `C:\Java\jdk-17.0.19`；系统环境变量 `JAVA_HOME=C:\Java\jdk-17.0.19`，`Path` 加 `%JAVA_HOME%\bin`。验证：`java -version` 显示 17。
- [ ] **PostgreSQL 16**：跑 EDB 安装包，记超管密码、端口 5432、UTF8。
- [ ] **pgvector**：停服务 `postgresql-x64-16` → 拷 `installers\pgvector\lib\vector.dll` → `C:\Program Files\PostgreSQL\16\lib\`，拷 `installers\pgvector\share\extension\*` → `...\share\extension\` → 启服务。验证：`psql -U postgres -c "SELECT * FROM pg_available_extensions WHERE name='vector';"` 有行。
- [ ] **Redis/Memurai**：装为服务，端口 6379。验证：`redis-cli ping` → `PONG`。
- [ ] **Python 3.11.9**：跑 `python-3.11.9-amd64.exe`，**勾 "Add python.exe to PATH"**。验证：`python --version`。装依赖：`cd E:\agent-platform\runtime-sidecar && python -m pip install -r requirements.txt`。
- [ ] **ffmpeg**：拷 `installers\ffmpeg-n7.1.1` → `C:\ffmpeg-n7.1.1`。验证：`C:\ffmpeg-n7.1.1\bin\ffmpeg.exe -version` 显示 n7.1.1。字幕字体：`C:\Windows\Fonts\simhei.ttf` 存在，缺则拷 `installers\fonts\` 两个字体进 `C:\Windows\Fonts\`。
- [ ] **Nginx**：解压 zip → `C:\nginx`，按下文 §五 改 `C:\nginx\conf\nginx.conf`。验证：`cd C:\nginx && nginx -t` OK。

### Step 2 · 放产物 & 目录

- [ ] `backend\agent-platform-0.1.0-SNAPSHOT.jar` → `E:\agent-platform\backend\`
- [ ] `frontend\dist\` → `E:\agent-platform\frontend\dist\`
- [ ] `runtime-sidecar\`（含 `app\` + `requirements.txt`）→ `E:\agent-platform\runtime-sidecar\`
- [ ] 建 `E:\agent-platform\logs\`

### Step 3 · 建库建表（Flyway 自动）

```sql
CREATE DATABASE agent_platform ENCODING 'UTF8';
\c agent_platform
CREATE EXTENSION vector;
SELECT extversion FROM pg_extension WHERE extname='vector';   -- 期望 0.8.2
```

### Step 4 · 配置环境变量（密钥生成 + 注入）

**先生成应用密钥和参考视频签名密钥**（妥善保存，勿入文档/代码库）：

```powershell
$jwt  = [Convert]::ToBase64String((1..64 | ForEach-Object { Get-Random -Maximum 256 }))
$tok  = -join ((1..32 | ForEach-Object { '{0:x2}' -f (Get-Random -Maximum 256) }))
$hmac = [Convert]::ToBase64String((1..48 | ForEach-Object { Get-Random -Maximum 256 }))
$bytes = New-Object byte[] 48
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)

$mediaRefKey = [Convert]::ToBase64String($bytes)
# 禁止把上述变量打印到控制台、日志或对话中
```

服务器上注入（管理员 PowerShell，`<...>` 替换为实际值）：

```powershell
setx /M DB_PASSWORD        "<PG超管或专用账号强密码>"
setx /M JWT_SECRET         "<上面生成的 64 字节 base64>"
setx /M RUNTIME_CALLBACK_TOKEN "<上面生成的 hex32>"
setx /M AUDIT_HMAC_KEY     "<上面生成的 48 字节 base64>"
setx /M APP_CORS_ALLOWED_ORIGINS "https://你的域名"        # 生产必配精确白名单
setx /M MEDIA_EDIT_FFMPEG_PATH   "C:\ffmpeg-n7.1.1\bin\ffmpeg.exe"
setx /M MEDIA_REFERENCE_PUBLIC_BASE_URL "https://你的域名"
setx /M MEDIA_REFERENCE_SIGNING_KEY "<上面生成的至少32字节随机密钥>"
setx /M MEDIA_REFERENCE_TTL_SECONDS "900"
```

> ⚠️ `setx` 只影响**之后新开的**进程；当前窗口需重开或用服务配置注入。完整变量表见 §六。
> `MEDIA_REFERENCE_PUBLIC_BASE_URL` 只填站点根地址，例如 `https://agent.example.com`，**不要加 `/api`**。参考视频对外 URL 将自动拼成 `https://agent.example.com/api/media/reference/{fileId}?expires=...&sig=...`。
> `JWT_SECRET`/`AUDIT_HMAC_KEY` 是启动门槛；缺 `DB_PASSWORD` 连不上库；`RUNTIME_CALLBACK_TOKEN` 两侧不一致会导致工作流回调全 401。三项 `MEDIA_REFERENCE_*` 在启用参考视频时必配。

### Step 5 · 启动（按序）

```powershell

Get-Service postgresql-x64-16, Redis  # 或 Memurai

# 2. Sidecar（8090，必须先于 backend 的工作流请求）
cd E:\agent-platform\runtime-sidecar
python -m uvicorn app.main:app --host 0.0.0.0 --port 8090

# 3. Backend（8080；首启跑 Flyway，观察日志到 "Started" 且无 Flyway 报错）
#    ⚠️ PowerShell 坑：-D 参数带 = 必须整体加双引号，
#    否则 PS 从 = 处拆参 → java 报「找不到或无法加载主类 .encoding=UTF-8」
cd E:\agent-platform\backend
java "-Dfile.encoding=UTF-8" -Xms512m -Xmx2g -jar agent-platform-0.1.0-SNAPSHOT.jar

# 4. Nginx（80 跳转 443 HTTPS）
cd C:\nginx
start nginx
```

### Step 6 · 开机自启（推荐 WinSW）

- PG / Redis：安装时已注册服务，确认「自动」。
- backend / sidecar：拷 `installers\winsw.exe` → 各目录重命名 `agent-backend.exe` / `agent-sidecar.exe`，配同名 xml（`<executable>java</executable>` / `python`，`<arguments>`，`<env name="...">` 注入上面变量，`<logpath>`），`.\agent-backend.exe install` 后 `Start-Service`。
- Nginx：同理用 WinSW 或计划任务开机 `C:\nginx\nginx.exe`。

部署完成后，后端服务的长期配置统一修改 `E:\agent-platform\backend\agent-backend.xml`。在 `<service>` 内加入（真实密钥不要提交 Git）：

```xml
<env name="MEDIA_REFERENCE_PUBLIC_BASE_URL" value="https://你的域名" />
<env name="MEDIA_REFERENCE_SIGNING_KEY" value="至少32字节的随机密钥" />
```

保存后执行 `Restart-Service agent-backend`。若 XML 同时存在同名 `<env>`，以 XML 中的值为准；不要只改当前 PowerShell 窗口中的 `$env:` 临时变量。

## 五、Nginx 配置（`C:\nginx\conf\nginx.conf`）

> **安全红线（安全体系 S4 · SEC-FR-034 F-5①）**：**严禁**出现 `location ^~ /uploads`、`location /uploads`、
> `alias`/`root` 指向 uploads 存储目录等任何直出文件配置——所有文件访问必须走 `/api/files/{id}`
> 归属咽喉点（owner 校验 + attachment/nosniff 下载策略）。Nginx 直达 = 绕过归属校验的 IDOR 通道。
> **F-5②**：uploads 存储目录（`app.files.storage-dir`）必须独立于应用包目录（不放在 dist/jar 同级），
> 目录 ACL 去执行权限（具体 icacls 清单见「主机与中间件安全基线」K4）。
>
> 主机与中间件安全基线（K1 RDP/防火墙、K2 中间件绑定、K4 目录 ACL、K5 每月巡检脚本
> `scripts/ops/security-baseline-check.ps1`）：见 [部署手册-主机基线.md](./部署手册-主机基线.md)。

```nginx
# 安全体系 S4 · SEC-FR-113（K3）——边缘限流（放 http{} 顶层，非 server 内）
limit_req_zone $binary_remote_addr zone=api:10m rate=20r/s;

server {
    listen 80;
    server_name agent.example.com;
    return 301 https://agent.example.com$request_uri;
}

server {
    listen 443 ssl;
    server_name agent.example.com;

    ssl_certificate     C:/nginx/certs/fullchain.pem;
    ssl_certificate_key C:/nginx/certs/privkey.pem;

    # ---- 安全体系 S4 · SEC-FR-113（K3 Nginx 加固五项）----
    server_tokens off;                 # 响应头/错误页不暴露 nginx 版本号
    client_max_body_size 65m;          # 与后端 multipart 上限对齐（≤60MB 附件），勿用默认 1m（否则上传 413）
    client_header_timeout 12s;         # 慢连接攻击：头部超时即断（默认 60s 过长）
    client_body_timeout   60s;         # 2x 修正：body 是「两次读间隔」语义，12s 对 60MB 慢上行太激进会 408 掐断；防慢攻击靠 header 12s 即可
    autoindex off;                     # 禁目录列表（默认 off，显式声明防漂移）

    location / {
        root   E:/agent-platform/frontend/dist;
        index  index.html;
        try_files $uri $uri/ /index.html;   # history 模式 SPA 回退，刷新不 404
    }
    location /api/ {
        limit_req zone=api burst=40 nodelay;   # 边缘频控：>20r/s 且打满突发 40 → 503
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;                # SSE 流式对话/WebSocket 必需
    }
    # /actuator 不反代——仅 localhost 可达（prometheus 抓取走内网）
    # /uploads 等存储目录不反代不直出——见本节顶部安全红线（SEC-FR-034）
}
```

将 `agent.example.com`、证书路径替换为实际值；服务器公网 IP 为 `117.72.25.74`，域名的 DNS A 记录应指向 `117.72.25.74`。纯 `http://117.72.25.74` 只能作为普通功能访问入口，不能填入参考视频公网根地址。服务器防火墙只对公网开放 80/443，禁止开放 8080。修改后执行 `C:\nginx\nginx.exe -t`，通过后 `C:\nginx\nginx.exe -s reload`。

**验收（部署后必查）**：
- `curl -I https://你的域名/uploads/anything` → **404/403**（不存在直达路由）；
- `curl -I https://你的域名/api/xxx` 响应头**无** `Server: nginx/x.y.z` 版本号（server_tokens off 生效）；
- 快速连打 100 次 `/api/` 出现 503（limit_req 生效；突发桶 40 内正常放行）。

## 六、配置项说明（环境变量总表，源 `backend/src/main/resources/application.yml`）

| 变量 | 必填 | 生产填什么 | 说明 |
|---|---|---|---|
| `DB_PASSWORD` | ✅ 启动门槛 | 强密码（旧默认 `aa64221886` 已泄露进 git 历史，**必须轮换**） | Hikari 连接密码 |
| `JWT_SECRET` | ✅ 启动门槛 | ≥32 字节随机 base64（旧密钥同样已泄露须换） | 缺失/过短 → 拒绝启动 |
| `AUDIT_HMAC_KEY` | ✅ 启动门槛 | 48 字节 base64（V93 审计哈希链；缺失/<32 → 拒绝启动） | 轮换后旧链重算必断，须全量校验 |
| `RUNTIME_CALLBACK_TOKEN` | ✅（sidecar 模式） | hex32，**backend 与 sidecar 必须同值** | 空 → 回调 fail-closed 401 |
| `DB_HOST/PORT/NAME/USER` | ⭕ | 默认 localhost/5432/**agent_platform**/postgres | 共用 PG 只改库名 |
| `REDIS_HOST/PORT/PASSWORD` | ⭕ | localhost/6379/密码 | Redis db 索引写死 0，与别的平台共实例时注意键隔离（建议独立实例） |

### 没有域名时的参考视频方案

当前服务器只有 `http://117.72.25.74` 时，按下表选择。不要通过修改后端校验强行放开 HTTP；Ark 需要的是实际可公网回拉、证书可信的 HTTPS URL。

| 方案 | 是否需要域名 | 参考视频 | 适用范围 | 结论 |
|---|---:|---:|---|---|
| `http://117.72.25.74` | 否 | ❌ | 普通功能临时访问 | 不能填入 `MEDIA_REFERENCE_PUBLIC_BASE_URL` |
| Cloudflare Quick Tunnel | 否 | ✅ | 临时部署、联调、验收 | 无域名时推荐的临时方案；地址可能变化、无 SLA |
| `https://117.72.25.74` + 可信 IP-SAN 证书 | 否 | 条件式可用 | 能取得公网 IP 证书的特殊部署 | 证书 SAN 必须包含该 IP，且由 Ark 信任的公共 CA 签发 |
| 自签 `https://117.72.25.74` | 否 | ❌ | 不适用 | Ark 通常不信任自签证书，禁止作为生产方案 |
| Cloudflare Named Tunnel | 是 | ✅ | 长期运行 | 需要托管在 Cloudflare 的自有域名，不属于“完全无域名”方案 |
| 域名 + Nginx + 公共 CA 证书 | 是 | ✅ | 正式生产 | 推荐；地址稳定、可续期、可监控 |

#### 方案 A：Cloudflare Quick Tunnel（无域名临时启用）

在服务器安装 `cloudflared.exe`，例如放到：

```text
C:\cloudflared\cloudflared.exe
```

可以先启动 Tunnel 再启动 backend；Tunnel 会先取得临时域名，backend 启动后才开始正常回源。在独立管理员 PowerShell 窗口运行：

```powershell
New-Item -ItemType Directory -Force C:\cloudflared | Out-Null
& C:\cloudflared\cloudflared.exe tunnel `
  --url http://127.0.0.1:8080 `
  --no-autoupdate `
  --logfile C:\cloudflared\cloudflared-active.log `
  --loglevel info
```

日志出现 `https://随机名称.trycloudflare.com` 后，将其作为根地址，不加 `/api`：

```powershell
$log = Get-Content C:\cloudflared\cloudflared-active.log -Raw
$quickUrl = [regex]::Match($log, 'https://[a-z0-9-]+\.trycloudflare\.com').Value
if (-not $quickUrl) { throw '未从 cloudflared 日志取得 Quick Tunnel 地址' }
setx /M MEDIA_REFERENCE_PUBLIC_BASE_URL $quickUrl
setx /M MEDIA_REFERENCE_SIGNING_KEY '<至少32字节的随机密钥>'
setx /M MEDIA_REFERENCE_TTL_SECONDS '900'
```

若 backend 使用 WinSW 服务，还必须把同一个 `$quickUrl` 写入 `E:\agent-platform\backend\agent-backend.xml`：

```xml
<env name="MEDIA_REFERENCE_PUBLIC_BASE_URL" value="https://随机名称.trycloudflare.com" />
<env name="MEDIA_REFERENCE_SIGNING_KEY" value="至少32字节的随机密钥" />
<env name="MEDIA_REFERENCE_TTL_SECONDS" value="900" />
```

如果 backend 使用 WinSW，写入 XML 后执行；命令行启动则在同一配置环境中重新启动 backend：

```powershell
Restart-Service agent-backend
Invoke-WebRequest "$quickUrl/actuator/health" -UseBasicParsing
```

`/actuator/health` 验证必须等 backend 已启动。Quick Tunnel 当前直接回源到 8080，会暴露 backend 的公网入口；业务 API 仍由 JWT/RBAC 保护，但 `/actuator/health` 等公开端点也可从临时域名访问。因此该方案只用于临时联调，不作为长期生产安全边界。

Quick Tunnel 注意事项：

1. `cloudflared` 进程必须持续运行；停止后公网地址立即失效。
2. 进程重启后可能分配新域名；新域名必须重新写入环境变量/WinSW XML并重启 backend。
3. Quick Tunnel 会转发整个 backend；业务接口仍依赖 JWT/RBAC，参考视频端点依赖限时 HMAC 签名。
4. 不要把临时域名、签名 URL、真实签名密钥或 Tunnel 日志提交 Git。
5. Quick Tunnel 无 SLA，不建议无人值守长期生产；如必须临时连续运行，应增加进程监控，并在域名变化时人工更新配置。

#### 方案 B：公网 IP + 可信 IP-SAN HTTPS 证书（条件式）

只有同时满足以下条件才可配置：

- 证书由 Ark 信任的公共 CA 签发，不是自签证书。
- 证书 Subject Alternative Name 明确包含 IP `117.72.25.74`。
- Nginx 443 使用该证书，外网访问 `https://117.72.25.74/` 无证书错误。
- 防火墙开放 443，不开放 backend 8080。

满足后可配置：

```text
MEDIA_REFERENCE_PUBLIC_BASE_URL=https://117.72.25.74
```

普通域名证书即使部署在这台服务器上，也不能冒充 IP 证书；浏览器能“继续访问”不代表 Ark 会信任。IP-SAN 证书通常比购买域名并申请普通证书更难获取和维护，因此只作为特殊条件方案。

#### 方案 C：购买域名 + 正式 HTTPS（推荐生产）

购买域名后，将 DNS A 记录指向 `117.72.25.74`，使用 Nginx 和可信 CA 证书，再设置：

```text
MEDIA_REFERENCE_PUBLIC_BASE_URL=https://你的域名
```

Cloudflare Named Tunnel 也需要自有域名；它适合不开放源站入站端口的长期方案，但不能解决“完全没有域名”的前提。

### 本地开发参考视频（可选）

本地 `localhost` 不能被 Ark 直接回拉，可使用 Cloudflare Quick Tunnel 暂时把 `http://127.0.0.1:8080` 暴露为公网 HTTPS。当前项目的本机辅助文件为：

```text
E:\workspace\agent-platform\local-media-reference-env.ps1
E:\workspace\agent-platform\start-backend-media-reference.ps1
E:\workspace\agent-platform\.local-tools\cloudflared.exe
```

先运行 `cloudflared tunnel --url http://127.0.0.1:8080`，再把新生成的 `https://xxx.trycloudflare.com` 写入本地 `MEDIA_REFERENCE_PUBLIC_BASE_URL` 并用辅助脚本重启 backend。Quick Tunnel 地址重启后可能变化；变化后必须改配置并重启后端。不要把临时域名或真实签名密钥写进部署文档或提交 Git。

# 人工测试遗留问题修复II 测试方案（审计补齐·验证码间隔）

> 来源：plans/人工测试遗留问题修复II_{B,C}*.plan.md 联动点清单逐条对齐 + 规格 §7.5/§8.5。
> 字典完整性/IP 字段/滑块计数/配额顺序已单测锁死，不在本文。本文=必须人介入的审计可见性与倒计时体验用例。
> 环境：本地（admin/admin123 看审计页；无痕窗走注册/找回密码）。

## 一、审计全量补齐（B，§7.5）

### T1 邮件发送审计（8x-1）
1. 注册页输邮箱点「发送验证码」→ 审计日志出现「认证-发送注册验证码」行，**detail 含完整邮箱 + IP**、result=SUCCESS。
2. 找回密码：发起（发重置码）→ 一条；用码重置成功 → 再一条（共两条）。

### T2 模块中文化（8x-2）
1. 审计页模块下拉 **18 项全中文**、无英文码裸奔。
2. 任选 security / project-group / feedback 模块 → 表格模块列显中文标签。

### T3 全操作覆盖抽查（8x-3，P1 级）
1. 改 Provider 配置（新增/编辑/启停）→ 日志在。
2. 走一遍审批工作流（提交/通过/驳回）→ 日志在。
3. MFA 绑定/解绑、手工建行路径（P0 八动作）抽查 → 日志在。
4. **反向**：上述操作失败（如校验拒）→ FAIL 行也在（result=FAIL + reason）。

## 二、验证码间隔与倒计时（C，§8.5）

### T4 刷新后倒计时恢复（12x-1 核心）
1. 注册页发码成功（按钮进 60s 倒计时）→ **刷新页面** → 按钮仍是**倒计时禁用态**且秒数=真实剩余（如已过 20s 则显 40）。

### T5 间隔内重发的真实剩余提示
1. 刷新后间隔内点发送 → 提示「请 N 秒后再试」（N=真实剩余，非写死 60）且按钮**进入倒计时**。
2. **反向**：等倒计时归零再点 → 正常发码成功。

### T6 被拒不误伤（恶化点③④回归）
1. 刷新后间隔内**连点 3 次**发送 → 不触发强制滑块（间隔拒绝不进滑块失败计数）。
2. 被拒期间查 IP 配额 → 未消耗（increment 顺序在间隔检查后）；无双重 toast。

### T7 短信页同款
1. 短信登录页发码 → 刷新页面 → 倒计时同样恢复（与邮箱一致）。

## 三、功能联动用例（对齐联动清单，含反向/边界）

### B 计划（4 条）
- L-B1 发码被限流拒 → 审计行 result=FAIL + reason=RATE_LIMIT；**不与滑块计数互通**（两系统独立，反向）。
- L-B2 P0 手工行（无 JWT 上下文）→ 审计页用户列显示层兜底「用户#id/系统」（边界）。
- L-B3 P2 编辑高频操作 → detail 截断 200 字符；QPS 异常降级仅 FAIL 行（边界）。
- L-B4 B2 字典新增/幽灵码删除 → 前端下拉与详情前后端同步 18 项（防再分叉）。

### C 计划（4 条）
- L-C1 发码成功 → localStorage 写截止时间 + 启动倒计时；**邮箱输入框改值 → key 换**，旧邮箱倒计时不影响新（边界）。
- L-C2 429 被拒 → 倒计时恢复、滑块不记失败、IP 配额不耗；换浏览器清存储 → 429 真值兜底（反向）。
- L-C3 间隔配置改 → 话术 N 与窗口长度即时生效；已在倒计中的前端按旧值走完（可接受，边界）。
- L-C4 注册成功 → 现有删码逻辑不动；倒计时 key 自然过期自清（反向）。

# 3.2 成本与性能指标

## 一、成本指标体系

AI产品成本是真金白银，成本指标是2026 AI PM核心KPI。

### 1.1 成本核心指标

| 指标 | 定义 | 计算公式 |
|---|---|---|
| **Token消耗** | 接口消耗的总Token数（input+output） | 累加input_tokens + output_tokens |
| **单次调用成本** | 单次API调用平均成本 | 总成本/总调用次数 |
| **单位任务成本** | 完成一次业务任务平均成本（含多轮调用）| 总成本/总任务数 |
| **缓存命中率** | 命中缓存省Token的比例 | 命中次数/总请求 |
| **缓存节省率** | 缓存节省的成本比例 | 节省成本/原始成本 |
| **毛利率** | 收入-Token成本的毛利比 | (收入-成本)/收入 |
| **单位经济模型** | 单用户/单任务的收入-成本差 | ARPU - CPU（Cost Per User/Task）|

### 1.3 缓存命中率（降本关键）

| 缓存类型 | 说明 | 命中率可达 |
|---|---|---|
| **前缀缓存（Prompt Caching）** | 重复的系统提示词/上下文缓存 | 30-80% |
| **语义缓存** | 语义相似问题缓存 | 10-40% |
| **结果缓存** | 完全相同请求缓存 | 高频场景50%+ |
| **计算缓存（KV Cache）** | 推理引擎层KV缓存 | 引擎内部 |

**Prompt Caching最佳实践**：
- 把不变部分（系统提示词/知识/RAG检索结果）放Prompt开头
- 命中后input成本打1折（90%节省），对长Prompt效果显著
- Anthropic/OpenAI均官方支持Prompt Caching

## 二、性能指标体系

### 2.1 延迟核心指标

| 指标 | 全称 | 定义 | 用户感知 |
|---|---|---|---|
| **TTFT** | Time To First Token | 首字时延（请求到首Token）| 决定"快不快"感觉 |
| **TPS** | Tokens Per Second | 每秒生成Token数 | 决定流式速度 |
| **总时延** | Total Latency | 端到端总耗时 | 决定整体体验 |
| **TPOT** | Time Per Output Token | 每个输出Token时延 | 内部指标 |
| **ITL** | Inter-Token Latency | Token间时延 | 流式流畅度 |

### 2.2 延迟分级与体验

| 延迟区间 | 用户感知 | 设计建议 |
|---|---|---|
| <500ms | 实时感 | Copilot Tab补全 |
| 500ms-1s | 流畅感 | 流式首字 |
| 1-3s | 接受范围 | 流式+骨架屏 |
| 3-10s | 等待焦虑 | 阶段化提示+取消 |
| >10s | 严重焦虑 | 异步任务+通知 |

### 2.3 分布指标（不只看平均）

| 指标 | 定义 | 应用 |
|---|---|---|
| **平均时延** | 算术平均 | 简单但掩盖长尾 |
| **P50（中位数）** | 50%请求的时延 | 一半用户体验 |
| **P95** | 95%请求低于此时延 | 大部分用户体验 |
| **P99** | 99%请求低于此时延 | 几乎所有用户体验 |
| **最大时延** | 最慢一次 | 极端情况 |
| **长尾占比** | P99以上比例 | 系统稳定性 |

> 红线：**P95/P99是SLA核心**，平均值会掩盖长尾体验崩溃

### 2.4 吞吐与并发

## 三、质量×成本×性能权衡三角

AI产品PM的核心命题：质量、成本、性能是三元权衡：

```
        质量（采纳率/任务完成率/幻觉率）
              /\
             /  \
            /    \
           /  ??  \   ← PM要在该位置找最优平衡
          /        \
         /__________\
   成本              性能
  (Token/缓存)    (TTFT/TPS)
```

### 3.1 权衡案例

| 决策 | 质量影响 | 成本影响 | 性能影响 |
|---|---|---|---|
| 升级旗舰模型 | ↑ | ↑5-10倍 | ↓（旗舰慢） |
| 降到便宜模型 | ↓ | ↓5-10倍 | ↑ |
| 用缓存 | =（缓存命中）| ↓30-80% | ↑↑（缓存快）|
| 模型路由 | =（路由对）| ↓50% | ↑（简单任务快） |
| 减少上下文 | ↓ | ↓ | ↑ |
| 减少TopK | ↓ | ↓ | ↑ |
| 降温度 | ↓稳定 ↑多样性 | = | = |
| 并行调用 | = | ↑ | ↑↑（多模型融合） |

### 3.2 决策原则

- **质量是底线**：质量不达标的优化都是耍流氓
- **成本是商业底线**：单位任务成本超过客单价=亏本
- **性能是体验底线**：P95时延超过3秒=用户流失
- 缓存是双赢：质量不变，成本性能双优化（最高ROI）
- 模型路由是局部最优：高质量+低成本，但工程复杂

## 六、常见坑汇总

| 坑 | 表现 | 应对 |
|---|---|---|
| 只看DAU/MAU | 传统指标不覆盖AI核心问题 | 叠加采纳率/任务完成率 |
| 只看准确率 | AI不是二元对错 | 组合采纳率/重写率/人评 |
| 忽视幻觉率 | 不度量=不知情 | 高风险场景必须跟踪 |
| 成本不PM事 | PM不背成本KPI | 2026 PM要直接背成本 |
| 缓存命中率不管 | 等于烧钱 | 优化Prompt Caching |
| 只看平均值 | 长尾掩盖 | 看P95/P99 |
| 忽视学习曲线 | 初期波动大 | 长期监测 |
| 指标不分级 | 北极星/主/辅助并列 | 分级管理 |
| 自动指标代替人评 | 与人类偏好弱相关 | 配人评/LLM-Judge |
| 指标不回流模型 | 永远停在初始 | 反馈数据→训练 |
| 不看分布看平均 | P99长尾崩塌 | 分布指标 |
| 不做SLA分级 | 所有请求一视同仁 | 关键路径高SLA |

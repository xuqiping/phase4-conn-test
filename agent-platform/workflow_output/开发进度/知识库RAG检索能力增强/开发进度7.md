## 本轮：WP4 Step2 GLOBAL 分类与 map-reduce 分支（commit 66107aeb，2860/2860）

- **分类（①）**：`QueryPlanner` 增 GLOBAL/OVERVIEW——**双词表门**：库级范围词（全库/整个库/这个库/所有文档…）∧ 聚合意图词（总结/趋势/主题/讲什么…）同时命中才进，防「总结一下报销流程」误入（又慢又泛）；序位=EXACT 后 PROCEDURE/LIST 前（锚点问题先精确、库级聚合优先清单）。LLM 规划器白名单+prompt 同步 GLOBAL——合法 LLM 结果优先、非法回落规则（复用既有 parse 护栏语义）。
- **`global/GlobalAnswerStrategy`（②③④⑤）**：
  - 文档全集=可见集 ∩ INDEXED ∩ 有 L1（含 ATTACHMENT，口径同 Worker），**序号按 id 排序稳定**（引用 [n] 跨重试一致）；map 分批 ≤15（`rag.global.answer` 旋钮，kill switch enabled）→ 静态 2 线程守护池并行（=计划「批间 ≤2」）→ reduce 合成 ≤800 字带 [n] 引用。
  - `CitationChecker.extractAndCheckDocLevel`（文档级模式，白名单=参与 map 序号）：越界→带合法编号区间指令重生成一次→仍越界降级。
  - 答案结构：**【库概览】**（最新 READY L-KB 行+生成日期，不占引用编号；ERROR/缺失→段缺席）+**【要点综述】**（map-reduce 主体）；多库取首库+文末 `>` 提示行。
  - 总预算 30s（deadline nanoTime；per-call timeoutMs=min(剩余,总)），超时/LLM 失败/空 L1→降级「仅概览+建议缩小范围」；开关关→null 回落常规管道。
- **挂接（RagRetrievalService，③）**：单库 retrieveInternal 置于 **B4 前**（全局分支免 query embedding）——调试模式（generateAnswer=false）走零 LLM 勘察 `inspect`；/ask retrieveGroundedAnswer 前置 GLOBAL 判定——**新增 retrieveEvidence(prePlanned) 重载**防双重 LLM 规划（chat 路径 null=自规划不变）；VO/EvidenceResult 增 globalMode/docCount/batches/overviewReady/degraded；trace verdict GLOBAL_PEEK/SUPPORTED/DEGRADED（VARCHAR(16) 恰容 16 字符）+evidenceL2 记文档级参与集 JSON。
- **测试 +13**：GlobalAnswerStrategyTest 9（3 批 map+概览段+引用提取/越界重试成功/双败降级/200ms 超时降级/wrapper IN 可见集/**纯 Mockito 验 SQL 须先 getSqlSegment 触发 IN 参数惰性物化**（WP3 坑复现）/空可见零 LLM/多库提示/开关关/勘察计数）；QueryPlanner +3（双词表命中/局部总结不进/EXACT 优先）；LlmQueryPlanner +1（LLM GLOBAL 过白名单）。四个直接构造 service 的测试类补 globalAnswerStrategy mock（@RequiredArgsConstructor 加字段=改全构造点——第二个坑实例）。

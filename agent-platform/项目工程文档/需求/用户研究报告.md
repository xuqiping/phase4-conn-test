# 用户研究报告 — 多Agent智能体平台

> 版本: 1.0 | 日期: 2026-05-25 | 状态: 初稿

---

## 一、项目背景与目标

### 1.1 项目背景

"超级程序员Agent"系统是一套多Agent协作的软件工程自动化平台，当前已具备以下资产：

| 资产类型 | 数量 | 存储形式 |
|---------|------|---------|
| 主Agent | 1个 | Markdown |
| 子Agent | 14个 | Markdown |
| 工作流 | 51个 | Markdown |
| 检查清单 | 51个 | Markdown |

这些Agent和工作流覆盖了从需求分析、架构设计、编码实现到测试部署的完整软件工程生命周期。但目前系统仅以Markdown文件形式存在，缺乏可视化的管理和交互界面，普通用户难以直观理解Agent能力，也无法便捷地编排和执行工作流。

### 1.2 研究目标

1. 明确目标用户群体及其核心诉求
2. 描绘典型用户画像，指导产品设计决策
3. 识别用户痛点和关键使用场景
4. 为MVP功能范围提供用户侧依据

### 1.3 研究方法

- 竞品分析（Dify、Coze、Flowise、n8n等Agent平台）
- 开发者社区调研（GitHub讨论区、开发者论坛）
- 内部团队深度访谈（5人）
- 早期种子用户问卷（23份有效回收）

## 四、核心痛点分析

### 4.1 痛点汇总

| 编号 | 痛点 | 影响用户群 | 严重程度 | 当前解决方案 |
|------|------|-----------|---------|-------------|
| P1 | Agent能力不直观，难以快速找到合适的Agent | 开发者 | 高 | 手动翻阅Markdown文件 |
| P2 | 工作流编排门槛高，需要理解各Agent的输入输出 | 开发者 | 高 | 手动编辑Markdown拼接 |
| P3 | 缺乏统一的执行入口和结果展示 | 开发者/团队负责人 | 高 | 命令行工具 |
| P4 | 团队协作困难，无法共享工作流模板 | 团队负责人 | 中 | 文件共享/邮件 |
| P5 | 无法追踪工作流执行状态和历史 | 团队负责人/管理员 | 中 | 无 |
| P6 | 缺乏权限管控，所有人对所有Agent拥有相同权限 | 管理员 | 高 | 无（完全开放） |
| P7 | 主题单一，长时间使用视觉疲劳 | 开发者 | 低 | 无 |
| P8 | 移动端无法查看执行状态 | 管理员 | 低 | 无 |

### 4.2 痛点优先级矩阵

                    影响程度 高

    ────────────────────┼──────────────────► 发生频率 高
                        │
         P7    P4  P5   │      P3
                        │

## 五、使用场景分析

### 场景1：Agent发现与评估（高频）

**触发条件：** 开发者接到新任务，需要了解哪些Agent可以协助

**操作流程：**
1. 登录平台，进入Agent大厅
2. 通过分类标签或搜索找到候选Agent
3. 点击Agent卡片，进入详情页
4. 查看Agent的能力描述、输入输出规范、适用场景
5. 查看该Agent关联的工作流模板
6. 决定是否使用该Agent

**成功标准：** 3次点击内找到目标Agent，详情页30秒内理解Agent能力

---

### 场景2：工作流快速编排（高频）

**触发条件：** 开发者需要串联多个Agent完成一个完整任务

**操作流程：**
1. 进入工作流编辑器
2. 从左侧Agent面板拖拽所需Agent到画布
3. 连接Agent节点，配置数据流
4. 设置参数（如项目路径、目标语言等）
5. 点击执行
6. 实时查看执行进度和结果

**成功标准：** 5分钟内完成一个3节点工作流的编排和执行

---

### 场景3：团队工作流标准化（中频）

**触发条件：** 团队负责人需要为团队制定标准开发流程

**操作流程：**
1. 创建新工作流，命名为"XXX标准流程"
2. 编排Agent节点，配置检查清单
3. 设置为团队模板，指定可见范围
4. 团队成员从模板创建实例执行

**成功标准：** 模板创建后，团队成员1分钟内可以基于模板开始执行

---

### 场景4：权限审批与管理（低频）

**触发条件：** 新成员加入团队或项目组需要使用特定Agent

**操作流程：**
1. 管理员收到权限申请通知
2. 查看申请人的角色和申请理由
3. 审批/驳回，可设置权限有效期
4. 申请人收到审批结果通知

**成功标准：** 审批操作30秒内完成

---

### 场景5：执行监控与问题排查（中频）

**触发条件：** 工作流执行失败或负责人需要了解进度

**操作流程：**
1. 进入工作流执行历史列表
2. 筛选特定时间/状态/负责人的记录
3. 点击具体执行记录查看详细日志
4. 定位失败节点和错误原因
5. 修正后重新执行

**成功标准：** 1分钟内定位失败原因

## 六、竞品分析摘要

| 维度 | Dify | Coze | 本项目 |
|------|------|------|--------|
| 定位 | 通用LLM应用开发平台 | 字节AI Bot平台 | 软件工程Agent编排平台 |
| Agent数量 | 用户自建 | 用户自建 | 15个预置专业Agent |
| 工作流编排 | 可视化拖拽 | 可视化拖拽 | 可视化拖拽 + 检查清单 |
| 代码审查能力 | 无 | 无 | 内置51个检查清单 |
| 权限管理 | 团队版支持 | 企业版支持 | RBAC，4级角色 |
| 主题 | 亮/暗 | 亮/暗 | 3套暗色主题 |
| 差异化优势 | 生态丰富 | 抖书集成 | 专注软件工程全生命周期 |

**核心差异化：** 本项目不是通用AI平台，而是专门面向软件工程的专业Agent系统。15个预置Agent覆盖完整开发生命周期，51个检查清单确保工程质量，这是竞品不具备的。

## 七、研究结论

### 7.1 核心发现

1. **Agent发现是首要需求** — 65%的用户首先需要一个直观的Agent展示和搜索界面
2. **工作流编排是核心价值** — 拖拽式编排能将工作流创建时间从30分钟降到5分钟
3. **权限管理是上线前提** — 企业用户明确表示没有权限管控就无法在团队中推广
4. **暗色主题是刚需** — 92%的目标用户偏好暗色IDE风格界面
5. **桌面端优先策略正确** — 工作流编排需要大屏和精确鼠标操作，移动端仅作查看补充

### 7.2 设计方向建议

- Agent大厅采用"卡片+分类"的App Store模式
- 工作流编辑器参考VS Code + Figma的交互范式
- 权限系统采用最小权限原则，默认只读
- 主题系统支持实时切换，记住用户偏好
- 首屏加载时间控制在2秒以内

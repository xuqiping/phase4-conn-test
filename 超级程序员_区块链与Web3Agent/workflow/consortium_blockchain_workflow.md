# 联盟链与国产链 Workflow

## Purpose

为企业级联盟链项目提供从场景分析、平台选型、架构设计、国密合规到政务落地与生产运维的完整执行路径。覆盖Hyperledger Fabric 3.x、五大国产区块链平台、国密信创适配和政务"五横三纵"架构。

## Prerequisites

- 用户已明确应用场景（供应链金融/政务数据共享/司法存证/跨境贸易/医疗溯源）
- 用户已明确参与方数量与角色（政府/企业/金融机构/个人）
- 用户已明确合规要求（等保等级/密评/国密/信创适配）

## Steps

### Step 1: 场景分析与联盟设计

**Goal**: 明确联盟链业务场景、参与方角色与权限模型，输出联盟治理方案。
**Completion criterion**: 联盟治理方案经所有参与方确认，包含角色定义、准入机制、数据共享规则、退出机制。

**A. 场景识别与价值分析**
- 存证溯源：数据上链不可篡改，解决信任问题（食品/药品/票据溯源）
- 可信共享：跨机构数据授权共享，解决"数据孤岛"（政务数据/医疗记录/征信数据）
- 资金监管：资金流全流程上链，确保"每一分钱可追溯"（征迁补偿/补贴发放/供应链金融）
- 供应链金融：核心企业信用传递，多级供应商融资（应收账款/仓单/订单融资）
- 跨境贸易：单据数字化、信用证自动化、海关数据互通

**B. 参与方角色设计**
- 联盟发起方：制定治理规则、技术选型、初始节点部署
- 共识节点方：参与区块验证，需满足硬件/网络/安全准入条件
- 记账节点方：同步账本数据，不参与共识（轻节点）
- 应用接入方：通过SDK/API调用链上服务，无需运行节点
- 监管节点方：只读权限，满足审计和监管要求

**C. 准入与退出机制**
- 准入流程：申请→身份验证（KYC/企业资质）→ 联盟投票→ 节点部署→ 证书签发
- 退出流程：提前通知（30-90天）→ 数据迁移/销毁→ 证书吊销→ 节点下线
- 争议解决：联盟仲裁委员会投票（2/3多数），重大变更需全体一致

**D. 数据共享规则**
- 公开数据：所有节点可见（如公共目录、公告信息）
- 授权数据：经数据Owner授权后可见（如个人征信、企业财务）
- 隐私数据：仅授权双方可见，链上存哈希（如合同细节、商业机密）
- 分级策略：根据数据敏感度设置不同的加密和访问控制级别

**输出物**: `联盟治理方案_项目名称.md`（含参与方清单、角色权限矩阵、准入退出流程、数据共享规则、争议解决机制）。

### Step 2: 平台选型与架构设计

**Goal**: 根据场景和合规要求选择合适的联盟链平台，完成网络架构设计。
**Completion criterion**: 平台选型报告产出，包含五维评估矩阵；架构设计文档包含网络拓扑、节点部署方案、隐私策略。

**A. 平台五维选型矩阵**
- 评估维度：安全性（共识容错/密码学）→ 性能（TPS/延迟/并发）→ 合规（国密/等保/密评）→ 生态（SDK/工具/社区）→ 成本（TCO/节点数/运维）
- 选型决策：
  - 国际化部署/全球供应链 → **Hyperledger Fabric**（生态最成熟，全球部署最广泛）
  - 中国市场/国密合规/政务央企 → **长安链（ChainMaker）**（北京微芯院+腾讯，自适应TBFT，10万+ TPS）
  - 商业BaaS/供应链金融/跨境贸易 → **蚂蚁链（AntChain）**（并行BFT，30万峰值TPS，双11验证）
  - 开源金融/社区驱动 → **FISCO BCOS**（微众银行+金链盟，PBFT+Raft，开源免费）
  - 商业许可/金融/政务/能源 → **趣链（Hyperchain）**（RBFT，5万+ TPS，商业授权）
  - 司法存证/政务 → **百度超级链（XuperChain）**（TDPOS，10万+ TPS）

**B. Hyperledger Fabric 3.x架构设计**
- 核心组件：
  - Peer节点：8核CPU/32GB/500GB SSD，每组织至少2节点高可用
  - Orderer节点：5节点Raft集群（容2故障），跨AZ部署
  - Fabric CA：根CA离线+中间CA在线，证书有效期1年
  - Channel：独立账本/链码/成员集，按业务隔离需求设计
  - Chaincode：Go/Java/Node.js，通过peer lifecycle管理，需多方审批提交
- 交易流程：提案→背书→排序→验证→提交
- 隐私三层架构：
  - Channel：粗粒度隔离，不同业务线独立Channel
  - PDC（Private Data Collection）：同通道内细粒度隔离，数据仅授权Peer可见，哈希上链
  - SideDB：链下存储+链上哈希验证，最强隐私
- 共识演进：Fabric 2.x Raft（CFT）→ Fabric 3.x SmartBFT（BFT），从崩溃容错向拜占庭容错跨越
- 性能优化：读写批处理（吞吐提升30-50%）、GoLevelDB替代CouchDB（简单KV场景）、Raft参数调优

**C. 国产链架构设计**
- 国密合规：SM2替代ECDSA签名、SM3替代SHA-256哈希、SM4替代AES加密
- 信创适配：麒麟OS/统信UOS + 鲲鹏/飞腾/海光芯片 + 国密算法
- 跨链互操作：WECROSS（微众银行）、Poly Enterprise（Poly Network企业版）、Hyperledger Cacti（SATP协议）
- BaaS vs 自建：
  - 中小企业选BaaS（蚂蚁链/华为云BCS，快速上线+免运维，25-42万/年）
  - 大型企业/政务选自建（完全控制+国密合规+信创要求，65-115万/年）

**D. 网络拓扑设计**
- 云部署：阿里云/腾讯云/华为云/AWS，跨地域多可用区
- 混合部署：核心节点自建机房，边缘节点云上部署
- 容灾设计：同城双活+异地灾备，RPO=0/RTO<1分钟
- 网络隔离：政务外网/政务云专网/VPC隔离/防火墙策略

**输出物**: `平台选型报告_项目名称.md` + `网络架构设计文档_项目名称.md`（含拓扑图、节点规格、Channel设计、隐私策略）。

### Step 3: 链码开发与国密合规

**Goal**: 完成智能合约（链码）开发，通过国密改造和合规认证。
**Completion criterion**: 链码编译部署通过，国密算法集成完成，通过密评和等保测评。

**A. 链码开发（Fabric）**
- 语言选择：Go（性能最优）/ Java（企业友好）/ Node.js（快速开发）
- 开发框架：Fabric Gateway SDK封装完整交易流程
- 链码生命周期：package→install→approveformyorg→commit→invoke
- 状态数据库：LevelDB（简单KV，性能高）/ CouchDB（富查询，支持JSON索引）
- 事件机制：链码事件→应用监听→业务触发

**B. 国产平台链码开发**
- 长安链：支持Solidity/Go/C++链码，长安链IDE一体化开发
- 蚂蚁链：MySQL兼容的链上数据模型，蚂蚁链BaaS控制台管理
- FISCO BCOS：支持Solidity/Go/Node.js，WeBASE可视化开发平台

**C. 国密改造**
- 签名算法：SM2替代ECDSA，SM2密钥对生成与证书管理
- 哈希算法：SM3替代SHA-256/Keccak-256
- 加密算法：SM4替代AES，用于PDC/SideDB数据加密
- 密钥管理：硬件安全模块（HSM）存储根密钥，FIPS 140-2 Level 3
- TLS通信：国密TLS 1.3（GMTLS）双向认证
- 密评认证：GM/T 0054标准，第三方机构测评通过

**D. 等保合规**
- 等保2.0（GB/T 22239）：第二级（指导保护级）或第三级（监督保护级）
- 安全物理环境：机房访问控制、环境监控、防雷防火
- 安全通信网络：网络架构冗余、通信传输完整性/保密性
- 安全区域边界：边界防护、访问控制、入侵防范、恶意代码防范
- 安全计算环境：身份鉴别、访问控制、安全审计、数据完整性/保密性
- 安全管理中心：系统管理、审计管理、安全管理、集中管控

**E. 测试验证**
- 功能测试：链码所有接口覆盖，模拟多组织场景
- 性能测试：TPS基准、延迟P99、并发用户数、资源占用
- 国密验证：SM2签名验证、SM3哈希一致性、SM4加解密正确性
- 渗透测试：节点通信安全、证书伪造尝试、PDC数据越权访问

**输出物**: `链码源码_项目名称/` + `国密合规报告_项目名称.md`（含算法替换清单、密评测评报告、等保测评报告）。

### Step 4: 政务落地与生产运维

**Goal**: 完成政务场景落地部署或企业级生产环境上线，建立监控告警和运维体系。
**Completion criterion**: 系统上线运行，监控告警全覆盖，RPO/RTO达标，运维手册交付。

**A. 政务落地场景**
- 目录区块链：全市/全省委办局职责目录和数据目录上链，链上自动授权共享
  - 效果：跨部门数据调用从3-5个工作日缩短至秒级
  - 案例：北京目录区块链（53委办局秒级授权）、湖南省数字政府主链
- 司法存证：电子证据全流程上链，存证验证案件万件+
  - 案例：天平链（10亿+存证，采信率100%）
- 资金监管：征迁补偿/补贴全流程链上可追溯
  - 案例：雄安征迁资金监管（测量→评估→公示→签约→拨付全链路）
- 发展阶段：1.0存证上链 → 2.0可信共享 → 3.0无感服务（区块链+隐私计算）

**B. K8s生产部署**
- Operator模式：hlf-operator / Bevel声明式管理Peer/Orderer/CA
- CCaaS（Chaincode as a Service）：链码独立部署、独立扩缩容
- 高可用：5节点Raft跨3AZ / Peer每组织2+节点互备 / Ceph RBD三副本存储
- 备份恢复：Velero每日备份，跨区域恢复演练每季度一次
- GitOps：ArgoCD自动同步Git仓库配置到K8s，所有变更通过PR审批

**C. 监控告警体系**
- 指标采集：Prometheus采集区块高度、交易速率、Leader状态、证书过期时间
- 可视化：Grafana仪表盘展示网络健康度、节点在线率、交易延迟分布
- 告警规则：
  - 区块高度5分钟未增长 → P1告警
  - Orderer Leader切换 > 3次/小时 → P0告警
  - 证书30天内过期 → P2告警
  - Peer节点离线 > 1分钟 → P1告警
- 告警通道：钉钉/企业微信/短信/邮件分级推送

**D. 安全运维**
- 密钥管理：根CA离线存HSM，中间CA在线签发，终端证书1年有效期自动续期
- 网络隔离：TLS 1.3双向认证（国密TLS），VLAN隔离，NetworkPolicy限制Pod通信
- 数据隐私：PDC私有数据集合 + SideDB链下存储 + ZKP零知识证明
- 补丁管理：安全漏洞24小时内评估影响，72小时内测试补丁，7天内生产部署
- 混沌工程：Chaos Mesh注入Pod故障/网络分区/磁盘故障，验证韧性

**E. 运维手册**
- 日常巡检：每日检查节点状态/日志/磁盘空间/证书有效期
- 变更管理：所有配置变更通过GitOps PR，双人审批，灰度发布
- 应急响应：故障分级（P0/P1/P2）→ 响应SLA（15min/1h/4h）→ 升级路径
- 容量规划：根据交易增长趋势预测扩容时间点，提前3个月启动采购

**输出物**: `政务落地方案_项目名称.md`（含场景设计、效果指标、案例对标）+ `运维手册_项目名称.md`（含部署架构、监控配置、告警规则、应急响应、容量规划）。

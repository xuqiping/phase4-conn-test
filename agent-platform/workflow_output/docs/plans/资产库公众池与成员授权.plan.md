# 资产库公众池与成员授权 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 OWNER/管理员安全发布资产项目，支持开放或审批访问、只读引用/复制，并修复普通 OWNER 无法邀请成员。

**Architecture:** `asset_projects` 保存发布状态，`asset_public_access_requests` 保存独立审批状态；`AssetAclService` 作为所有内容读取的统一咽喉。公共列表只返回摘要，获权后才复用原有详情、资产、版本与画布解析链路。

**Tech Stack:** Spring Boot、MyBatis-Plus、Flyway/PostgreSQL、Vue 3、Naive UI、JUnit/Mockito、Vitest。

---

## 技术坑点预判

| 技术点 | 坑 | 规避与验证 |
|---|---|---|
| 公共摘要 | 循环查资产数/发布者导致 N+1 | 项目、计数、用户、本人申请状态各批查一次；测试验证 mapper 调用次数 |
| ACL（权限咽喉） | 把公共读权误当写权 | `loadAccessible` 可返 VIEWER；写/管理仍经 `requireWrite/requireManage`；全端点回归 |
| 审批并发 | 两人重复处理 PENDING | 伪代码 `UPDATE request SET status=decision WHERE id=requestId AND status=PENDING`，影响行数非 1 返回冲突 |
| 移出再发布 | 旧 APPROVED 自动复活 | 移出时批量把 PENDING/APPROVED 改 REVOKED；再次发布必须重申请 |
| 事务复制 | 资产成功、版本或角色失败形成半成品 | 单事务补齐目标媒体类型并插入资产、版本、角色；任一步失败整体回滚 |
| 文件引用 | 误复制物理文件浪费空间 | 只复用当前版本 `fileId`，新建独立资产/版本行 |

## 安全与运维清单

- [x] 候选搜索关键词截断、最多 20 条，只返 `id/username`，不放宽 `/api/users`。
- [x] 发布模式、状态迁移、目标项目、版本存在性全部服务端校验。
- [x] 发布/移出/申请/决定/撤销/复制日志含 projectId、userId、action；沿用请求 traceId。
- [x] **做**：Flyway 只新增 V88（V87 已被并行的视频剪辑功能占用），旧代码可忽略新结构；真 PostgreSQL 执行留 Phase 4。

- [x] **后续再说**：公共池超大后改分页/搜索；当前沿用项目列表规模并批查询。
- [x] **Phase 4/运维候选**：评估审批条件更新冲突率、公共读取 403 突增；十万申请行前再评估归档，无需分区。

## 功能联动点

| 触发 | 联动对象 | 预期变化与边界 |
|---|---|---|
| 发布/移出 | 我的项目卡、公共池、申请记录 | 发布出现；移出立即消失并撤销 PENDING/APPROVED；成员授权不受影响 |
| 转让 | 审批入口、官方徽章 | 新 OWNER 接管审批；既有发布者/官方标记不变 |
| 模式切换 | 未获批访问 | OPEN 立即可读；APPROVAL_REQUIRED 仅既有 APPROVED 可读；移出后均失效 |
| 审批/撤销 | 申请人按钮与内容 ACL | 批准可用，拒绝/撤销可重申请；并发仅首个决定成功 |
| 源更新/复制 | 画布快照、副本 | 新浏览见最新；旧引用锁版本；副本独立不反向同步 |

## 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| 条件更新 | 只在旧状态仍符合时改 | 只有 PENDING 才能批准 |
| N+1 | 查一批项目却又逐个查附属数据 | 20 项目产生 21 次 SQL |
| 版本快照 | 使用时钉住当时版本 | 源升到 v3，画布仍用 v2 |

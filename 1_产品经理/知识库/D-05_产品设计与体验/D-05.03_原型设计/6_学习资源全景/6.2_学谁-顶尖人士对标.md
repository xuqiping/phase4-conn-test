# 学谁-顶尖人士对标

## 1. Bill Buxton — 原型探索之父

**身份**：前Microsoft Research首席研究员，《Sketching User Experiences》作者

### 思维模型：探索式原型

| 传统思维 | Buxton思维 |
|---|---|
| 原型是验证已确定方案的工具 | 原型是探索未知方案的工具 |
| 画出来 = 记录决定 | 画出来 = 发现可能性 |
| 追求每个原型的质量 | 追求原型的数量与多样性 |
| "我有1个完美的原型" | "我有10个不同的想法" |

### 行动范式

1. **"Get the right design before getting the design right"**——先找对方向，再优化细节
2. **快速草图>精细线框**——5分钟草图+10个方案 远胜 2小时线框+1个方案
3. **用数量换质量**——Buxton要求学生每次作业产出≥20个概念草图
4. **时间盒(Timebox)强制**——每张草图≤5分钟，超时就换下一个想法

[来源:Buxton 2007 "Sketching User Experiences" | 置信度:🔍高]

## 2. Evan Wallace — Figma技术架构师

**身份**：Figma联合创始人/CTO，CRDT实时协作引擎的设计者

### 思维模型：协作驱动原型

| 传统思维 | Wallace思维 |
|---|---|
| 原型是个人创作 | 原型是团队协作产出 |
| 文件传输+版本管理 | 实时协作+自动版本 |
| 设计和原型是两个步骤 | 设计即原型、原型即设计 |
| 组件库是"锦上添花" | 组件库是效率的10倍杠杆 |

### 行动范式

1. **CRDT思维**：设计多版本冲突的解决方案——让多人同时编辑不冲突
2. **组件化一切**：如果你做了两次相同的设计，就把它做成组件
3. **Dev Mode思维**：原型的终点不是"好看"，而是"开发能准确实现"
4. **性能即体验**：Figma的WebGL渲染引擎确保10人同时编辑10万图层的文件仍然流畅

[来源:Figma工程博客; Config演讲 | 置信度:🔍高]

## 3. Jake Knapp — 设计冲刺之父

**身份**：前Google Ventures设计合伙人，《Sprint》作者

### 思维模型：压缩验证周期

| 传统思维 | Knapp思维 |
|---|---|
| 设计→开发→上线→验证(数月) | 设计→原型→测试(5天) |
| 可用性测试是最终的"质检" | 可用性测试是最前的"探路" |
| 原型要完美再测试 | 原型"足够好"就测试——快速失败比缓慢成功更有价值 |
| 用数据验证假设 | 用原型验证假设——比数据更快更便宜 |

### 行动范式

1. **5天压缩**：Monday(理解) → Tuesday(发散) → Wednesday(决策) → Thursday(制作原型) → Friday(5人测试)
2. **1天做原型**：Thursday那天必须做出可测试的高保真原型——时间压力迫使优先级排序
3. **5人测试**：Friday的5人测试足以发现85%的可用性问题(Nielsen结论)
4. **"足够好"标准**：原型不需要完美，只需要让用户能完成任务——这是验证，不是展示

[来源:Knapp 2016 "Sprint" | 置信度:🔍高]

## 4. Guillermo Rauch — AI原型先锋

**身份**：Vercel CEO，v0.dev和Next.js创建者

### 思维模型：Vibe Prototyping

| 传统思维 | Rauch思维 |
|---|---|
| 画原型需要设计技能 | 描述意图即可生成原型 |
| 原型是静态设计稿 | 原型是可运行代码 |
| 设计→原型→开发 三步 | 意图→代码原型 一步 |
| 组件库要自己建 | shadcn/ui = 社区共建的组件基础设施 |

### 行动范式

1. **自然语言=最高级原型工具**：如果能说清楚你想要什么，就不需要画出来
2. **代码即原型**：用React+Tailwind写的代码本身就是最好的原型——可交互、可运行、可迭代
3. **shadcn/ui哲学**：不安装依赖，而是复制代码——你对代码有完全控制权
4. **快速迭代>完美定义**：先让AI生成70分的初始方案，用自然语言迭代到90分，比从零做到90分快10倍

[来源:Vercel博客; Rauch Twitter/X | 置信度:🔍高]

## 踩坑批注

- **软删×普通唯一索引=复活场景死结（17x#1 根因，2026-08-21）**：`uk_pgm_group_user` 无 deleted 谓词，软删行仍占位 → 再插入撞 409。方案二选一：部分唯一索引（行变多）或**复活**（一人一组一行，条件 UPDATE 翻活）。选了复活：历史 quota/used 痕迹保留，并发双接受由条件 UPDATE 互斥（0 行=输家）。同类「删了再加」场景先想这条路。
- **MANAGER 目标行闸（V139）**：quota/重置/移除/开关/可见性全部 `requireOperatableMember`（目标须 MEMBER 行）——否则 MANAGER 能免自己职/改自己限额，角色矩阵形同虚设。前端同步：管理行只显「仅组长可任免」。

- **通知 CHECK 重建先查实库（2026-08-21）**：V138 重建 `memory_notifications_type_check` 首次 23514 失败——新列表必须覆盖**实库现存全部 type 值**（`SELECT DISTINCT type` 先查），缺一个整迁移回滚。
- **流式裸线程无上下文（9x#7）**：chat_completed 审计在 doStream 的 raw thread 落库，MDC/SecurityContext 皆空，username 须按 userId 反查；任何「线程里自动有 MDC」的假设都不成立。
- **统一入口收养语义（2026-08-20）**：`adoptLegacy` 只在全局 `groupId == null` 时采纳第一个非空候选（旧 4 个 localStorage 分键 + 画布快照 projectGroupId）；全局已设=页顶胜出不收养；旧键留原地不清理（可回滚本版本）。收养与持久化都只写单键 `project_group_id`，杜绝再次出现多处分键不同步。
- Mockito 重载坑×3：chargeMedia 10→11 参、refundMedia 4→5 参、pageDetail 10→11 参改签名后，旧 stub **静默失配**（不同方法不报错）——stub/verify 必须同步升参。
- LambdaQueryWrapper.select() 在纯单测（无 MP TableInfo 缓存）抛 "can not find lambda cache"→ 用 QueryWrapper 列名字符串。
- record VO 不能继承（DetailVO 是 record）→ OverviewVO 用组合。
- 画布 gid 不落节点 data 快照（仅顶层）——运行时注入防旧节点被历史 gid 污染。

## 2026-08-25 增补（17x 未解决 3 项修复，V156）

### ① 层级额度（管理可被分配额度，预算树下发）
- **模型**：组池是钱，quota 是预算帽子。`project_group_members.allocated_by_user_id`（V156）记额度来源——组长给管理/成员配额度=组池直管；管理给成员配额度=占管理预算。
- **可分配公式**（用户拍板算例：管理 5000 → 分给 A 1000 → A 用 500 → 管理总额度剩 4500，A 剩 500 → 可分配 4000）：
  `可分配 = quota − (自己 used + Σ下级 used) − Σ下级 GREATEST(quota−used,0)`。下级消耗=预留转已用 1:1，不动可分配；退款/重置对称回滚。
- **硬卡点**（全部先持管理行 `SELECT…FOR UPDATE` 再算可分配，并发双分配/边花边分打不穿）：
  - `updateQuota` 管理侧：目标仅 MEMBER；自己被限额则新限额必填且 `新预留 ≤ 可分配`（排除目标行口径，旧预留无需回填）；allocated_by=自己。组长侧：目标 MEMBER（改挂组长）或 MANAGER（定预算：新额度 ≥ 已占用 且 无不限额下级）。
  - `insertMemberRow`：邀请接受落行时按邀请人预算硬卡（邀请发出时 invite() 只做体验预检）。
  - `doChargeGroup`：管理本人消耗卡 `可分配 ≥ cost`（锁序 组池→成员行，与分配同向无环）。
  - 管理降职（MANAGER→MEMBER）：下级统一 `reparentChildren` 改挂组长，预算不悬空。
- **展示**：MemberVO/MineVO + allocatablePoints/myAllocatable——成员表「可分配」列、组卡片、详情头 chip、页顶选择器（管理显「可分配」）。
- **公共池审批入组**：quota NULL 挂组长（挂审批管理会成「不限额下级」毒化其可分配=0）。

### ② 安全审计（组员刷积分/管理越权盗取排查）
- **补漏（真洞，已修）**：`requireAffordableGroup` 原只查身份+组池>0——成员超限额后 chargeGroup 硬卡被计费铁律吞掉（usage 记 FAILED 但模型已调=免费用）。已补两道预检：成员 `used≥quota` 拦、管理 `可分配≤0` 拦（硬卡仍在结算层兜底）。
- **管理越权盗取组长积分**：现已无路径——管理只能给 MEMBER 配额度且被自己预算硬卡（分配/邀请接受/本人消耗三卡点全锁管理行串行化）；不能动自己行（角色/限额/重置均组长专属）；不能碰组池资金（requireOwner）；不能任免/移除其他管理。
- **组员刷积分**：chargeGroup 幂等键+组池条件扣+成员条件加；并发由组池行锁串行；refund 仅服务端媒体路径触发；quota 调整全走审计端点。未发现可利用面。
- **已知口径（非洞，文档化）**：管理不限额（quota NULL）时其下级也不限=扁平老模型，组长给管理定额度前须先收编不限额下级；管理降职/移除成员后，其历史消耗不再占预算（available 回升）；BACKSTOP 组池尽时差额记组长个人（设计）。

### ③ 产出模块两处
- **平台 admin 代管视角**：admin 组内身份即使 MEMBER，前端 canManage 也给管理页签（成员/流水/审批/产出）——后端本就 admin 恒放行，纯前端放开（`ProjectGroupsView.vue` canManage += auth.isAdmin）。
- **CHAT 行内容列**：原为「对话消耗」占位——现按轮配对：`chatTurnMap` 取 created_at ≤ 该行扣费时间的最后一条 user 消息（内容列=用户提问），其后第一条 assistant 消息（预览列=回复）；session 空（画布等）显「-」。

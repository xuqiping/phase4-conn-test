## 关键技术决策（为什么这么定）

1. **存量审计不回填哈希**：plan 内部矛盾（要回填 vs HMAC 密钥 env-only 注入无法回填历史 vs V78 已 REVOKE UPDATE）——取「链从 GENESIS 起算，存量 NULL 行作链外前缀，只许连续前缀否则判断链」。存量行靠 REVOKE 保护。
2. **哈希内容排除 id**：IDENTITY 主键插入前未知，算了永远验不过。
3. **canonicalJson 两侧规范化**：PG jsonb 重排键+规范化数字，直接拿库值重算必 mismatch → Jackson 排序键 + BigDecimal toPlainString。created_at 写入时截断 UTC 微秒对齐 pgjdbc 读回口径。
4. **踢出审计只在踢的瞬间记一次**：不拦旧 token 每请求记——防审计刷量。sid 比对放黑名单之后（logout 的 token 先被黑名单拦，不误报「别处登录」）。
5. **闸门 INCR 先行+超限退回**：拒绝必须 DECR 回去，否则拒绝也占槽=永闸；release 负值清零删键（submit 未计数而 worker release 的错配 fail-open）。
6. **降级放行统一**：单点登录/闸门 Redis 故障均放行+WARN（沿用 S1 范式，可用性>强制力）。

# 5.1 Toyota 5Why：从机器停机到根因发现

## 背景

5Why分析法的经典发源案例来自丰田生产系统。大野耐一在现场巡视时，发现一台机器停机了。他没有直接下令"修好它"，而是连续追问为什么，直到发现根因——这个案例定义了"根因分析"的方法论。[来源:Toyota Production System | 🔍高 | 1950s]

## 经典追溯链

```
现象：机器停机了
  → Why1: 为什么停机？→ 保险丝断了
  → Why2: 为什么保险丝断了？→ 轴承超载
  → Why3: 为什么轴承超载？→ 润滑不足
  → Why4: 为什么润滑不足？→ 润滑泵坏了
  → Why5: 为什么泵坏了？→ 泵的轴磨损了
  → 根因：泵轴磨损 → 对策：更换泵轴+增加定期检查（而非"换保险丝"）
```

## 关键洞察

| 错误对策 | 根因层级 | 正确对策 |
|---|---|---|
| 换保险丝（L1） | 保险丝断了 | ❌ 换了还会断 |
| 减少轴承负载（L2） | 轴承超载 | ❌ 治标不治本 |
| 加润滑油（L3） | 润滑不足 | ❌ 泵坏了加油也没用 |
| 修泵（L4） | 泵坏了 | ⚠️ 修了还可能坏 |
| **换泵轴+定期检修（L5）** | 泵轴磨损 | ✅ 根除+防复发 |

> **如果只停在L1（换保险丝），问题会反复出现。这就是"治标不治本"的本质。**[来源:📚训练知识]

## 5Why方法论的三个核心原则

1. **不预设答案**——追问"为什么"而不是追问"是不是因为X"
2. **推到可行动的层**——直到你可以采取有意义的行动
3. **验证而非推理**——每个Why的回答都要有证据，不是纯推想

## 对PM需求分析的启示

| 制造业场景 | PM需求场景 | 共同之处 |
|---|---|---|
| 机器停机 | 用户反馈"我要XX功能" | 都是表层现象 |
| 换保险丝 | 直接做XX功能 | 都是L1对策 |
| 泵轴磨损+定期检 | 发现根因需求+系统性解决 | 都是L5对策 |

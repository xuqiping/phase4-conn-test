# 部署手册 · 主机与中间件安全基线（K1~K5）

> 来源：[5_安全体系.md](../0_推进计划/5_安全体系.md) C3 域 K1~K5；总 plan：[安全体系_S4文件与主机.plan.md](../plans/安全体系_S4文件与主机.plan.md) Step 6。

> 本文是 [部署手册终.md](./部署手册终.md) 的安全补充篇——中间件安装/绑定细节以终版手册 §十 为准。

## K1 · Windows 主机基线

| 项 | 基线 | 操作（运维窗口一次性） |
|---|---|---|
| RDP 端口 | 非 3389 + 防火墙仅放行运维 IP | 注册表 `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp` → `PortNumber` 改高位端口；防火墙入站规则同步改 |
| 账户锁定 | 5 次失败锁 15 分钟 | `net accounts /lockoutthreshold:5 /lockoutduration:15 /lockoutwindow:15` |
| 防火墙入站 | 白名单制：80/443 + RDP 自定端口；**8080/8090/5432/6379/9090 禁止公网** | `Get-NetFirewallRule` 逐条核对；脚本 K5 自动核查 |
| 账号 | 禁用 Guest；管理员改名；应用跑专用低权账户 | 本地安全策略 → 本地策略 → 安全选项 |

## K2 · 中间件绑定（现状核对）

| 组件 | 基线 | 现状（部署手册终 §十） |
|---|---|---|
| Redis/Memurai | `bind 127.0.0.1` + `requirepass` 强密码 | ✅ 已绑 localhost（终版手册 §十）；requirepass 部署时设 |
| PostgreSQL | `listen_addresses='localhost'` + pg_hba 仅本机 trust/scram | ✅ 默认 localhost；pg_hba.conf 核对无 `0.0.0.0/0` |
| Actuator | 不经 Nginx 反代，仅 localhost | ✅ 终版手册 §五 注释明确 |
| Prometheus/Alertmanager/Grafana | 全部绑 127.0.0.1 | ✅ 终版手册 §十 约定 `D:\IT\ops\` |
| runtime-sidecar(8090) | 仅本机（backend 回调） | ✅ 防火墙不入站规则 |

## K4 · 目录 ACL（最小权限）

应用约定根 `C:\agent-platform\`（部署手册终 §四）。用应用专用低权账户运行 backend/WinSW，按表核 icacls：

| 目录 | 应用账户权限 | 说明 |
|---|---|---|
| `backend\*.jar` + `application.yml` | 读+执行，**不写** | 配置含 DB_PASSWORD/AUDIT_HMAC_KEY——只读防篡改 |
| `uploads\`（storage-dir） | 读写，**去执行** | 下载走后端 attachment，无需执行；位置独立于 dist/jar（F-5②） |
| `logs\` | 只增（写不改删） | 审计日志防篡改（Windows 侧靠 ACL 尽力，彻底方案归后续 WORM） |
| `frontend\dist\` | 只读 | 静态资源 |

命令示例：`icacls C:\agent-platform\uploads /inheritance:r /grant "AGENT_SVC:(OI)(CI)M"`（M=修改，无执行位继承需求时用具体权限串）。

## K5 · 巡检（每月）

```powershell
# 服务器上执行（只读，不改任何配置；FIM 首跑会生成基线文件）
C:\agent-platform\scripts\ops\security-baseline-check.ps1
# 发布新版本/合法改配置后重建 FIM 基线：
C:\agent-platform\scripts\ops\security-baseline-check.ps1 -Rebaseline
```

核查项：监听端口面（仅 80/443/RDP 对外）/ 防火墙规则 / Redis bind+requirepass / PG listen_addresses / Nginx server_tokens+autoindex+无 uploads 直达 / RDP 端口+账户锁定 / 目录 ACL 抽查 / **M3 FIM 关键文件 SHA256**（jar+application*.yml+nginx.conf+redis.conf+pg_hba.conf 比对 `ops\fim-baseline.csv`，漂移即 FAIL——jar 版本号变更属预期，跑 `-Rebaseline` 重建并人工确认变更来源）。
输出 PASS/FAIL 清单；**任一 FAIL 退出码 1**（可接计划任务月跑+告警）。FAIL 项按本文 K1/K2/K4 对应表修复后复跑；FIM FAIL 先取证（是不是自己人改的？不是则按《运维手册》§十 IR 预案走 P2+）。

## K6 · 月度威胁狩猎 checklist（安全体系 S5 · M6，SEC-FR-135）

每月巡检跑完 K5 后，加做这五项「主动找问题」（不是等告警，是翻出去看）：

1. **复跑全部门禁脚本**：`bash agent-platform/scripts/security/deps-check.sh --skip-nvd`——上月生绿不代表本月生绿（依赖 CVE 每天在出）；红项按报告处置。
2. **审计链完整性校验**：抽 3 天的 `audit_logs`，对照 `security_events` 与钉钉告警记录——该记的记了没？该告的告了没？链路断一环就是被篡改/漏报的信号。
3. **备份恢复抽查**：不必全量演练（那是季度的事），取最近一份日备 `pg_restore` 到 scratch 库建连+count 一张表即可——**备份可恢复性每月验一次**。
4. **新监听端口 diff**：本月 K5 输出与上月比对（把 K5 输出存档到 `ops\fim-baseline.csv` 同目录），多出任何端口都要能说清来历（上月装了什么、哪个服务的）。
5. **蜜罐与封禁台账复盘**：`security_events` 里 KIND_HONEYPOT 命中 IP 是否已在封禁名单？没有则人工封（或确认低危放行理由）；封禁列表里有没有误伤正常用户（用户反馈登录异常先查这里）。

结果记入运维待办（发现项→处置→闭环），无发现也记「本月狩猎无异常」。

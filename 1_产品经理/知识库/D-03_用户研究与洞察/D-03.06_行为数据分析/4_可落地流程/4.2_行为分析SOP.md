## 行为分析6步SOP

### Step 1：业务问题定义

| 要素 | 内容 | 示例 |
|---|---|---|
| 核心问题 | 1句话描述要回答的问题 | "为什么新用户注册后7日留存从40%降至32%？" |
| 子问题 | 拆解为3~5个可分析子问题 | "新用户哪个阶段流失最多？" → "流失用户vs留存用户行为有何差异？" → "什么行为与留存强相关？" |
| 成功标准 | 分析完成后的可交付物 | "定位流失主因+1个可测试假设" |
| 时间范围 | 分析数据的时间窗口 | "近90天" |

### Step 2：数据可用性确认

| 检查项 | 状态 | 备注 |
|---|---|---|
| 所需事件是否已埋点 | ⬜是 ⬜否 | |
| 属性是否完整 | ⬜是 ⬜否 | |
| 用户ID关联是否正确 | ⬜是 ⬜否 | |

→ 任何"否"项须先补齐数据再分析，否则结论不可靠

### Step 3：描述性分析

**3a. 漏斗分析**
- 定义漏斗步骤（入口→中间步骤→目标）
- 计算每步转化率+端到端转化率+平均时长
- 对比本期vs上期/同期

**3b. 路径分析**
- 画桑基图看主流路径
- 标注主路径与设计预期是否一致
- 发现异常路径（大量用户走了非预期路径）

**3c. 留存分析**
- 按新用户注册日建队列
- 次日/7日/30日留存率趋势
- 按行为切片（做了X vs 没做X）

### Step 4：诊断性分析

**4a. 对比分析**
| 对比 | 方法 | 预期洞察 |
|---|---|---|
| 留存 vs 流失用户 | 行为差异对比 | 找到"区分行为" |
| 本期 vs 上期 | 同期群对比 | 找到"变化原因" |
| 新版 vs 旧版 | 版本A/B对比 | 找到"版本影响" |
| 高频 vs 低频用户 | 行为模式对比 | 找到"驱动行为" |

**4b. 下钻分析**
- 从全局异常→逐步细分→定位根因
- 例：整体留存降→iOS降→iPhone 14降→v3.2版本→支付加载变慢

**4c. 魔法行为搜索**
- 枚举候选行为（加了好友/发布了内容/使用了某功能）
- 逐个对比做了vs没做的留存差异
- 排除选择偏差（做A行为的用户本身是否更忠诚？）

# 3 · UI 与交互设计

> 基准：Codex 的任务委派 UI + 2025–2026 竞品 UX 趋势联网调研。
> 设计目标：在 Codex「任务列表+diff 审阅」骨架上重做信息架构，视觉对标 Linear/Raycast 级精致度，交互为零代码用户重做。

## 1. 产品表面架构（2026-08-13 定调：桌面客户端为主）

| 表面 | 定位 | 心智 |
|---|---|---|
| **桌面客户端**（主，Win+Mac） | 创作面：项目全生命周期在这里走完，任务本机执行 | 「我的产品驾驶舱」 |
| **CLI / `devpilot://` 深链 / MCP Server** | 被集成面：别的应用用指令传参把任务委派进来 | 「插座」——任何工具都能插上 DevPilot 的工作流 |
| **移动端 App**（二期） | 监督面：审批、监控、语音派单、看验收通知 | 「遥控器」——照抄 Codex 移动端定位，不编辑代码 |
| **Web 门户**（轻量） | 账号、充值、Token 明细、技能市场 | 「营业厅」，不做开发操作 |
| **IDE 插件**（三期） | 专业面：开发者模式，与客户端同项目互通 | 「逃生舱」——用户成长后/请外援时无缝切换 |

## 2. 桌面客户端主窗口（核心）

> 形态：Tauri 2 桌面窗口（默认 1440×900，可全屏）+ 系统托盘常驻 + 全局快捷键唤起（默认 `Ctrl/Cmd+Shift+D`）。窗口 UI 即下文三栏布局。

### 2.1 整体框架：三栏 + 顶部管道条

```
┌──────────────────────────────────────────────────────────────┐
│  Logo  项目切换 ▾   ┃ 阶段管道条：想法✓ 需求✓ 计划✓ 建造▶ 验收○ 上线○ ┃  🔔  👤 │
├───────────┬──────────────────────────────────┬───────────────┤
│ 左栏 260px │ 中栏（主工作区，弹性）             │ 右栏 380px    │
│ · 阶段导航 │  当前阶段的专属视图：              │ 上下文面板    │
│ · 任务列表 │   想法期=访谈对话                 │ Tab: 规格/    │
│ · 存档点   │   需求期=需求确认卡片             │ 变更(diff)/   │
│   时间轴   │   建造期=任务卡片流+进度叙事       │ 日志/预览     │
│ · 文档库   │   验收期=验收清单                 │ 大白话⇄原文   │
│           │                                  │ 一键切换      │
└───────────┴──────────────────────────────────┴───────────────┘
```

**与 Codex 的关键差异**：Codex 中栏永远是「任务列表」；我们中栏**随阶段切换形态**——阶段即视图。用户永远知道自己在哪一步（管道条常驻），这是「工作流内置」最直接的可感知表达。

### 2.2 中栏六种视图（五种阶段视图 + 驾驶舱）

0. **项目驾驶舱（打开项目默认落点）**：开发进度总览——轮次时间线（每轮迭代做了什么/下一步）、chunk 完成度、健康度指标（缺陷/文档同步/spec 覆盖率）、Token 消耗报表、「继续下一轮」主按钮。多轮开发的枢纽，详见文档 4 §6。
1. **想法期 = 访谈对话**：类 ChatGPT 对话，但 AI 按 Phase 0 提纲结构化追问（做给谁/痛点/竞品/赚钱方式），右侧实时生长出「项目分析报告」预览。
2. **需求期 = 确认卡片流**：PRD 被拆成功能卡片，每张卡片三态按钮「✅确认 / ✏️改一改 / ❓这是什么」。全部确认前不出现「开工」按钮（未经许可不写码的 UI 化）。
3. **建造期 = 任务卡片流 + 进度叙事**：保留 Codex 任务卡片（状态/耗时/产物），但默认折叠技术细节，呈现为进度叙事流：「✅ 搭好了数据库 → ✅ 做好了登录页 → 🔨 正在做支付…」。展开任一节点可见 diff/日志（大白话层在上）。
4. **验收期 = 点一点清单**：左清单右预览。每项验收 = 「操作步骤 + 应看到的结果 + [通过]/[有问题]」。点「有问题」直接圈选预览中的元素描述问题（吸收 Lovable 元素点选），自动生成修复任务。
5. **上线后 = 项目驾驶舱**：运行状态/用户反馈入口/「我要改需求」按钮（进 Phase 6 变更向导）。

### 2.3 右栏上下文面板

五个 Tab：**规格**（当前 PRD 相关段落，大白话摘要置顶）、**变更**（diff 大白话⇄原文）、**日志**（叙事流⇄终端流）、**预览**（内嵌浏览器实时预览，支持元素点选/刷新/设备尺寸切换）、**文件**（项目目录树 + 文件内容查看，默认只读；舒适模式下折叠弱化，紧凑模式为一等公民——FR-051/052）。右栏可整体收起；移动端折叠为底部抽屉。

## 3. 关键交互亮点（超越 Codex 的 10 处）

| # | 交互 | 解决什么 | 借鉴/原创 |
|---|---|---|---|
| 1 | **阶段管道条**常驻顶部，当前阶段呼吸灯微动效，点击已完成阶段可回看产物 | Codex 用户常「不知道任务在干嘛」的迷茫感 | 原创（工作流内置的直接表达） |
| 2 | **大白话⇄原文双层切换**（全局开关 + 逐块切换） | 非程序员看不懂 diff/日志 | 原创 |
| 3 | **术语气泡**：专业术语下划线，悬停出大白话解释 | 工作流「行内括注」规范的产品化 | 原创 |
| 4 | **审批卡片化**：所有需决策点（计划批准/上线确认/变更影响）做成「选项卡片+推荐项标注」，不给开放式输入框 | 非程序员面对开放问题会卡死 | Devin Interactive Planning 的进一步降门槛 |
| 5 | **存档点时间轴**：左栏竖向时间轴，每个 commit 一个节点，悬停显示「这次做了什么」大白话 + 一键回滚到此 | Claude Code /rewind + Replit checkpoint 融合，回滚免费明示 | 融合改进 |
| 6 | **进度叙事流**：AI 工作过程默认呈现为「正在做什么」的故事流，技术日志折叠 | Codex 日志流对新手是噪音 | Codex citations 的降维呈现 |
| 7 | **验收点一点**：预览内操作+圈选反馈，「有问题」按钮直接生成修复任务 | 非程序员不会写 bug 报告 | Lovable 点选编辑的验收场景化 |
| 8 | **空状态即教程**：每个阶段空状态给出「这一步会发生什么」的 30 秒动画说明 | 首次上手恐惧 | Replit onboarding 强化 |
| 9 | **语音贯穿**：输入框长按空格语音听写；移动端语音派单为主输入 | 打字描述需求是非程序员的第二道坎 | Codex 听写 + 中文语音优化 |
| 10 | **余额仪表**：顶栏常驻「Token 余额」环形微件，悬停出消耗明细与充值入口 | Replit 计费失控的前车之鉴；卖 Token 的产品透明度=复购率 | 原创 |
| 11 | **桌面原生体验**：全局快捷键唤起迷你输入条（想到需求随手派单）；系统托盘显示任务进度；任务完成/需审批走系统通知；本地文件/截图直接拖进对话；系统级语音听写（按住 Fn，对齐 Codex 桌面版） | 桌面客户端相对 Web 的独占体验优势，必须吃满 | Codex 桌面版 + Raycast |
| 12 | **外部任务接入可视化**：CLI/深链/MCP 委派进来的任务在任务流里带「来自 XX 应用」标识，结果自动回传来源方 | 「插座」能力的可感知化 | 原创 |

## 4. 视觉风格（美化方向）

**基准调性**：开发者工具的精密感（Linear/Raycast）× 消费级产品的亲和力（Notion/Arc），避开「 toy 感」（Lovable 式高饱和圆角）和「冷硬感」（Codex 式密集表格）两个极端。

- **主题**：暗色优先（开发者审美基线）+ 亮色备选。暗色基底 `#0B0E14` 系，不用纯黑。
- **科技感基调（v1.1 用户反馈强化）**：深空感——背景带径向辉光与细网格底纹（HUD 感）；数据呈现 HUD 化（等宽字体大数字 + 发光描边统计块）；管道条/进度条带能量流光效；卡片悬浮时泛起霓虹描边辉光。原则：光效服务于状态表达（进行中=流动、完成=静稳），不做无意义的炫技动画。
- **品牌色**：主色建议「青蓝渐变」（#4F7CFF→#38BDF8，理性+信任感），阶段状态用语义色：完成=青绿、进行=主色呼吸、待办=灰、阻塞=琥珀、失败=珊瑚红。强调色克制，一屏不超过 3 处高亮。
- **质感**：玻璃拟态用于浮层（审批卡片/术语气泡），微阴影+1px 半透明描边；不用重度模糊背景（性能与阅读性）。
- **字体**：中文思源黑体/系统黑体栈，代码与数字用等宽（JetBrains Mono + 中文对齐修正）；行高 1.6–1.7 照顾中文长文阅读。
- **微动效**：阶段推进时的管道流转场（200–300ms ease-out）、任务卡片状态翻转、AI「思考中」的呼吸光点——全部可关闭（无障碍）。
- **密度双模**：「舒适模式」（默认，大留白大字号，零代码用户）/「紧凑模式」（开发者，信息密度对齐 Codex）。
- **可及性**：WCAG 2.2 AA 对比度、全键盘可达、动效可关——直接回应学界对 vibe coding 界面可及性盲区的批评，也是宣扬点。

## 5. 移动端监督面（二期）

照抄 Codex 已验证的「遥控器」心智并本地化：底部四 Tab「动态 / 审批 / 项目 / 我的」；审批卡片左滑通过右滑驳回；语音派单为首屏主按钮；与桌面客户端扫码配对（账号体系打通，任务状态经 Web 门户同步）。不做：代码编辑、diff 行内评论（手机上只给大白话摘要）。

## 6. 原型优先级

先做三张高保真：①建造期主窗口（管道条+任务流+右栏+托盘/快捷键标注，最能体现差异化）②需求确认卡片流 ③验收点一点。用 Stitch/Figma 出图后评审，再进 Phase 1。

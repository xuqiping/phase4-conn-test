# 3.3 导航设计

## I.03 导航类型框架

### 按层级分

| 类型 | 定义 | 作用 | 示例 |
|---|---|---|---|
| **全局导航** | 全站/全App一致的顶层导航 | 提供产品全景、跨区快速跳转 | 顶部Tab栏、侧边菜单 |
| **局部导航** | 某一区域/模块内的导航 | 在当前模块内浏览 | 左侧二级菜单、栏目Tab |
| **情境导航** | 上下文相关的嵌入导航 | 建立内容间的关联 | "相关推荐"、"你可能还喜欢"、超链接 |
| **辅助导航** | 面包屑、站点地图、索引 | 提供备用路径和全局视角 | 面包屑路径、Sitemap |

### 按平台分

| 平台 | 主导航模式 | 注意事项 |
|---|---|---|
| Web桌面端 | 水平导航+侧边栏 | 空间充裕，可容纳更多层级 |
| iOS | 底部TabBar(3-5个)+导航栏 | 严格遵循HIG，Tab ≤5 |
| Android | 底部导航+侧边抽屉 | Material Design导航规范 |
| 小程序 | 底部TabBar+页面栈 | 包体限制→极简层级 |
| 嵌入式/IoT | 语音/手势/上下文感知 | 交互资源极度有限 |

## I.07 导航设计方法

### 导航设计五原则

1. **可见性**：让用户随时知道"我在哪、能去哪"（当前项高亮、面包屑）
2. **一致性**：同类导航的位置/样式/行为全站统一
3. **可预测性**：导航标签符合用户预期，点前猜得到内容
4. **可逆性**：随时能"回去"（返回/面包屑/撤销）
5. **经济性**：到达目标的最短路径，减少无效点击

### 面包屑设计规则

| 规则 | 说明 |
|---|---|
| 何时使用 | 层级 ≥2 级时必用；单一层级不需要 |
| 位置 | 页面内容区上方、标题之前 |
| 格式 | 层级1 > 层级2 > 当前页（最后一项不可点击） |
| 移动端 | 简化为"← 返回上级"即可，不必显示完整路径 |

### 分面导航（Faceted Navigation）

**适用**：内容量大、多维属性（电商、招聘、房产）。

**设计要点**：
- 分面 = 属性维度（品牌/价格/颜色/尺寸…），用户可多维度叠加筛选
- 核心分面始终可见，次要分面折叠/动态展示
- 已选分面高亮+一键清除
- 结果数量实时更新，避免空结果

### 移动端导航模式对比

| 模式 | 适合 | 不适合 | 典型 |
|---|---|---|---|
| 底部Tab | 3-5个核心功能、平级切换 | 功能 >5 个 | 微信、淘宝 |
| 汉堡菜单 | 功能多、辅助功能占比大 | 核心功能不能隐藏 | Google Maps |
| 手势导航 | 沉浸式内容消费 | 多入口工具类 | TikTok、Instagram |
| 底部Sheet | 需频繁切换子模块 | 主要信息在主屏 | iOS地图 |

## C.01 场景适用性

| 产品类型 | 推荐导航策略 |
|---|---|
| 工具型（SaaS/工具App） | 全局Tab+核心功能前置+搜索 |
| 内容型（资讯/社区） | 分类导航+推荐流+搜索 |
| 交易型（电商/O2O） | 分面筛选+搜索优先+快捷入口 |
| 社交型 | 关系链Feed+底部Tab+轻量分类 |
| B端企业级 | 侧边导航+角色定制菜单+权限控制 |

## E.03 常见坑

| 坑 | 表现 | 修法 |
|---|---|---|
| 导航与功能对不上 | 标签含糊、点击后不符合预期 | 用户测试验证标签→卡片分类/树测试 |
| 层级不一致 | 同一级别的功能，入口深浅差3层 | 统一核心功能到达层级 |
| 移动端抄Web导航 | 桌面端导航直接压缩到手机 | 重新设计移动端导航体系 |
| 炫技导航 | 手势/动效华丽但学习成本高 | 核心导航用标准模式、动效仅做辅助 |
| 面包屑缺失 | 深层页面无法知道自己在哪 | ≥2级层级必加面包屑或返回路径 |

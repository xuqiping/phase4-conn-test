## 六、最小 CI（线上质量门）

> 原则（铁律 #9）：CI 不是从零建——把本地 `scripts/check_all` 搬到服务器上跑，**本地与线上检查标准完全一致**；CI 只追加两件本地不做的事：**Flyway 迁移校验 + 构建产物**。全绿才允许部署。

**最小 CI 必须有的检查**（缺一不可）：

| # | 检查项 | 来源 | 说明 |
|---|---|---|---|
| 1 | lint + 类型检查 + 单测 + 文档校验 | `scripts/check_all` | 与本地同一份脚本，本地过线上必过 |
| 2 | secret 扫描（gitleaks）+ 依赖扫描（npm audit / OWASP DC） | security_strategy §5 | 拦截误提交密钥 + 查已知 CVE；高危阻断 |
| 3 | Flyway 迁移校验（`flyway:validate`） | CI 追加 | 检测迁移脚本与已应用版本是否漂移（checksum 对不上 = 阻断） |
| 4 | 构建（后端打包 + 前端 build） | CI 追加 | 产物供部署 |

**起步 yaml 骨架**：仓库根 `.github/workflows/ci.yml`（GitHub Actions），项目模板已带骨架，拷贝后改 `working-directory` 与 secrets 即可。触发：push / PR 到 `main`、`develop` → 任一步骤失败阻断，全绿才放行部署。

- [ ] CI 已配置，push/PR 触发上述 3 项检查
- [ ] CI 需要的 secrets 已录入（如 `CI_DB_URL` / `CI_DB_USER` / `CI_DB_PASSWORD`，**绝不写进仓库明文**）
- [ ] 部署只接 CI 全绿的产物（人工部署也先确认最近一次 CI 绿）

> **Gitee Go / 其他平台适配**：Gitee Go 用 `.workflow/<触发分支>.yml`（`stages` → `jobs` → `steps` 结构），把上面三项检查照搬进 steps 即可；Jenkins 用 Jenkinsfile 的 `stage`。核心不变：**check_all + Flyway validate + 构建，全绿才部署**。

# 工作汇报模块（work-report）设计说明书

> 本文档基于 [`3_新增模块实施指导.md`](../../../workflow_output/项目规范约束/新增模块实施指导.md) 和 [`工作整理报告工具_完整分析报告.md`](工作整理报告工具_完整分析报告.md) 编写，用于指导在 file-keeper 项目中落地"工作整理 + 每日安排 + 聊天工具推送"能力。

---

## 1. 模块概述

| 项 | 内容 |
|---|---|
| **模块代号** | `work-report` |
| **中文名称** | 工作汇报 |
| **模块定位** | file-keeper 桌面端内的商业授权模块，帮助用户整理工作、安排每日计划，并自动将日报/周报推送到聊天工具 |
| **授权方式** | 商业授权模块，必须接入现有 entitlement 体系；MVP 阶段不支持匿名免费 |
| **目标用户** | 需要写日报/周报的职场人士、项目经理、团队负责人 |

### 1.1 解决的问题

1. **写报告耗时**：每周五下午花 1-2 小时回忆工作、整理格式。
2. **信息分散**：工作记录散落在本地文件、Git、聊天工具中，难以汇总。
3. **容易遗漏**：忙碌时忘记记录工作，年底总结无据可查。
4. **推送麻烦**：生成报告后还要手动复制到聊天工具发送。

### 1.2 模块边界

**包含**：
- 工作记录手动录入与管理
- 每日安排（今日待办 / 明日计划）
- 日报/周报生成规则配置
- AI 智能总结
- 报告模板渲染
- 聊天工具推送（MVP 飞书优先）
- 历史报告查看、导出、重新推送

**不包含（后续迭代）**：
- 自动采集聊天记录（涉及隐私合规，Phase 3 评估）
- 钉钉/企微/Slack 接入（Phase 2）
- 团队版权限与报告汇总（Phase 3）
- 私有化部署（Phase 4）

## 3. 技术方案

### 3.1 复用 file-keeper 现有栈

| 层级 | file-keeper 已有能力 | 本模块采用 |
|---|---|---|
| 后端框架 | Spring Boot 3.2 + Java 17 | **复用**，新增 `com.superprogrammer.workreport` 包 |
| ORM | MyBatis-Plus 3.5.5 | **复用**，实体继承 `BaseEntity` |
| 响应封装 | `R<T>` / `PageResult<T>` | **复用** |
| 权限 | `@RequirePermission` + entitlement 体系 | **复用**，新增 `work-report` moduleCode |
| 数据库 | PostgreSQL + Flyway | **复用**，新增业务迁移脚本 |
| 桌面端 | Vue 3 + TypeScript + Tauri | **复用**，新增 Tab 和组件 |
| 状态管理 | Pinia | **复用**，新增 `workReportStore` |
| UI 库 | Naive UI | **复用** |
| 定时调度 | 无统一方案 | 新增 Spring Scheduler / Quartz |
| AI 能力 | 无 | 新增大模型 API 调用服务 |
| 推送能力 | 无 | 新增飞书/钉钉/企微 Bot SDK 接入 |

### 3.2 不采用分析报告独立 SaaS 架构的理由

分析报告推荐的 `Go + Gin + React` 适合从零构建独立产品，但本模块需要：

1. **复用现有商业授权体系**：避免重复实现用户、设备、离线 Token、授权管理。
2. **复用管理后台**：用户授权、Dashboard、系统设置已在 admin-web 中。
3. **与桌面端深度融合**：作为 file-keeper 的一个 Tab，而不是独立 Web 应用。
4. **降低部署成本**：不需要单独部署一套后端服务。

## 4. 数据模型

### 4.1 实体关系

```
users (1)
 │
 ├── work_logs (N)        # 工作记录
 ├── work_plans (N)       # 每日安排
 ├── report_templates (N) # 报告模板
 ├── report_configs (N)   # 报告规则配置
 │       │
 │       ├── report_push_targets (N)  # 推送目标
 │       │
 │       └── work_reports (N)         # 已生成报告
 │               │
 │               └── push_deliveries (N)  # 推送记录
```

### 4.2 核心表说明

| 表名 | 用途 | 关键字段 |
|---|---|---|
| `work_logs` | 用户工作记录 | `user_id`, `log_date`, `content`, `tags`, `source` |
| `work_plans` | 每日安排 | `user_id`, `plan_date`, `content`, `priority`, `completed` |
| `report_templates` | 报告模板 | `user_id`, `name`, `type`, `content`, `is_default` |
| `report_configs` | 报告生成规则 | `user_id`, `report_type`, `template_id`, `cron_expression`, `ai_enabled` |
| `report_push_targets` | 推送目标 | `config_id`, `platform`, `target_type`, `target_id`, `credential` |
| `work_reports` | 已生成报告 | `user_id`, `config_id`, `report_type`, `title`, `content`, `status` |
| `push_deliveries` | 推送记录 | `report_id`, `target_id`, `status`, `response`, `tried_count` |

### 4.3 重要约定

- 所有业务表必须包含 `created_by/created_at/updated_by/updated_at/deleted`。
- 实体类继承 `com.superprogrammer.common.BaseEntity`。
- `credential` 等敏感字段必须加密存储（AES-256-GCM）。
- 主键使用 `GENERATED ALWAYS AS IDENTITY`。
- `module_code` CHECK 约束需要同步扩展，追加 `'work-report'`。

### 5.2 客户端接口授权校验

每个客户端接口必须校验 `work-report` 模块授权，示例：

```java
private boolean checkModuleAuth(Authentication auth, String deviceId) {
    AuthPrincipal principal = (AuthPrincipal) auth.getPrincipal();
    AuthorizationSnapshot snapshot = authorizationService.authenticatedSnapshot(
        principal.userId(), deviceId, System.currentTimeMillis()
    );
    return snapshot.modules().stream()
        .anyMatch(m -> AuthConstants.MODULE_WORK_REPORT.equals(m.moduleCode()) && m.allowed());
}
```

未授权统一返回 `R.fail(ErrorCode.FORBIDDEN, "未授权访问工作汇报模块")`。

### 5.4 AI 总结服务

**职责**：把零散的工作记录和计划整理成规范报告。

**输入**：
- 日期范围
- `work_logs` 列表（content + tags + source）
- `work_plans` 列表（content + priority + completed）
- 报告类型（日报/周报）

**输出**：
- 结构化文本，包含：已完成工作、遇到的问题、明日/下周计划

**实现要点**：
- 接入通义千问 / 豆包 / Claude API
- Prompt 模板可配置，预留占位符
- 超时控制 30 秒，失败降级为简单拼接
- 记录 AI 调用日志，便于成本分析

### 5.5 定时调度服务

**职责**：按配置触发生成报告并推送。

**实现方式**：
- Spring `@Scheduled` 每分钟扫描 `report_configs`
- 匹配 `cron_expression` 和 `timezone`
- 生成报告 → AI 总结 → 渲染模板 → 遍历推送目标 → 异步推送
- 推送失败进入 Redis 重试队列

**状态流转**：
```
GENERATED → PUSHING → PUSHED
                ↓
              FAILED → 重试（最多 3 次）
```

### 5.6 推送服务

**设计模式**：策略模式 + 工厂模式

```java
public interface PushService {
    boolean supports(Platform platform);
    PushResult push(WorkReport report, ReportPushTarget target);
}
```

MVP 只实现 `FeishuPusher`，后续扩展 `DingTalkPusher`、`WeComPusher`、`SlackPusher`。

**飞书推送方式**：
- 群推送：通过 `chat_id` + Bot `tenant_access_token`
- 单聊推送：通过 `open_id` + Bot 消息

## 7. Rust 层设计

### 7.1 是否需要 Rust

本模块**主要逻辑走服务端 HTTP**，但以下场景需要 Rust 命令：

| 场景 | Rust 命令 | 敏感程度 |
|---|---|---|
| 读取本地 Git 日志 | `fetch_git_logs` | 中（访问文件系统） |
| 读取本地文件活动 | `fetch_file_activities` | 高 |
| 系统通知提醒 | `show_notification` | 低 |
| 本地报告导出 | `export_report_markdown` | 中 |

### 7.2 命令与二次校验

新增 [`src-tauri/src/commands/work_report.rs`](../../../src-tauri/src/commands/work_report.rs)：

```rust
#[tauri::command]
pub async fn fetch_git_logs(
    offline_token_state: State<'_, OfflineTokenState>,
    repo_path: String,
    since: String,
) -> Result<Vec<GitLogEntry>, String> {
    if !offline_token_state.is_module_allowed("work-report") {
        return Err("未授权访问工作汇报模块".into());
    }
    // 执行 git log 命令
    Ok(...)
}
```

在 [`src-tauri/src/main.rs`](../../../src-tauri/src/main.rs) 注册 invoke handler。

### 7.3 安全要求

- 所有涉及本地文件系统、进程、系统通知的命令必须做离线授权二次校验。
- 参考 [`src-tauri/src/commands/auth.rs`](../../../src-tauri/src/commands/auth.rs) 实现。
- 错误信息不暴露敏感路径。

## 9. 安全与合规

### 9.1 凭据加密

`report_push_targets.credential` 必须加密存储：
- 算法：AES-256-GCM
- 密钥：服务端环境变量 `WORK_REPORT_CREDENTIAL_KEY`
- 解密只在推送时进行

### 9.2 数据隐私

- 默认不自动采集聊天记录。
- 工作记录属于用户数据，删除账号时同步清理。
- 服务端日志对 `content` 字段脱敏。
- 企业版支持私有化部署（Phase 4）。

### 9.3 审计日志

管理后台的高风险操作记录 `admin_audit_logs`：
- 查看用户报告
- 修改系统默认模板
- 删除用户报告配置
- 修改推送目标凭据

## 10. 依赖与风险

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 飞书 API 变更 | 推送失败 | 关注官方变更日志，封装 SDK 调用层便于替换 |
| AI API 成本过高 | 亏损 | 设置调用上限，支持模型切换，Prompt 优化 |
| 用户隐私担忧 |  adoption 受阻 | 默认手动录入，不自动采集聊天数据 |
| 定时任务单机故障 | 报告漏发 | 后续引入 Quartz 集群或 Redis 分布式锁 |
| 多平台适配工作量大 | 延期 | MVP 只飞书，Phase 2 再扩展 |

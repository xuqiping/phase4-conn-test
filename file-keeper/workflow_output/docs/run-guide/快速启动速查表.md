# 快速启动速查表 · File Keeper Desktop

> Phase 4 产物。记录「拿到这个项目，怎么最快把它跑起来」。
> 受众：换机器 / 新成员 / 几个月后的自己。目标：**3 分钟内把项目跑起来，不用翻代码猜**。

## 一句话启动（懒人版）

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\启动.ps1
```

关闭和重启：

```powershell
powershell -ExecutionPolicy Bypass -File .\关闭.ps1
powershell -ExecutionPolicy Bypass -File .\重启.ps1
```

脚本暂不管理管理后台，每次执行后会输出提醒。

## 启动步骤（按顺序）

### 1. 启动依赖服务

**PostgreSQL**
- 命令（Windows 服务）：`pg_ctl start -D "C:\Program Files\PostgreSQL\<version>\data"`
- 或打开程序：PostgreSQL 安装目录下的 `pgAdmin` 或 `pg_ctl`
- 看到什么算成功：`psql -h localhost -U postgres -d file_keeper` 能连上

**Redis**
- 命令：`redis-server`
- 或打开程序：Redis 安装目录下的 `redis-server.exe`
- 看到什么算成功：`redis-cli ping` 返回 `PONG`

### 2. 初始化数据库

创建数据库：
```sql
CREATE DATABASE file_keeper;
```

Flyway 会在后端启动时自动执行迁移脚本（`server/src/main/resources/db/migration/`）。

### 3. 启动后端

- **入口文件**：`server/src/main/java/com/superprogrammer/FileKeeperServerApplication.java`
- **命令**：
  ```bash
  cd file-keeper/server
  mvn spring-boot:run
  ```
- **必需环境变量**（超管自动创建）：
  ```bash
  export FILE_KEEPER_JWT_SECRET="至少32字节的随机字符串"
  export FILE_KEEPER_AUTH_PRIVATE_KEY="Ed25519 私钥 PEM"
  export FILE_KEEPER_SUPER_ADMIN_EMAIL="admin@example.com"
  export FILE_KEEPER_SUPER_ADMIN_PASSWORD="强密码"
  ```
- **看到什么算成功**：日志打印 `Started FileKeeperServerApplication in X.XXX seconds`、监听 `8088`

### 4. 启动桌面客户端（开发模式）

- **入口目录**：`file-keeper/`
- **命令**：
  ```bash
  cd file-keeper
  npm install
  npm run tauri:dev -- -- --bin file-keeper
  ```
- **说明**：项目有桌面主程序和 Office Worker 两个 Rust 二进制，开发启动时必须通过 `--bin file-keeper` 明确选择主程序。Office Worker 由主程序按需调用。
- **看到什么算成功**：弹出 File Keeper 窗口、顶部状态栏显示授权状态

## 端口占用速查

| 服务 | 端口 | 启动它的命令 |
|---|---|---|
| 后端 | 8088 | `mvn spring-boot:run` |
| 桌面端 Vite dev server | 1420 | 由 Tauri 的 `beforeDevCommand` 自动启动 |
| Tauri 桌面主程序 | 无独立网络端口 | `npm run tauri:dev -- -- --bin file-keeper` |
| Redis | 6379 | `redis-server` |
| PostgreSQL | 5432 | `pg_ctl start` |

## 查端口占用 & 关闭端口（命令速查）

### Windows

- **查谁占了某端口**：`netstat -ano | findstr :8088`（最后一列数字是 PID）
- **按 PID 强杀进程**：`taskkill /PID <PID> /F`
- **看所有端口占用**：`netstat -ano`

### Linux / Mac

- **查谁占了端口**：`lsof -i:8088` 或 `netstat -tunlp | grep 8088`
- **按 PID 杀**：`kill -9 <PID>`

> 📌 端口被占最常见原因：上次启动没关干净。**先查 PID 再 kill**，别瞎杀进程。

## 一键停止

- 后端：按 `Ctrl+C`
- 前端：按 `Ctrl+C`
- Redis：`redis-cli shutdown` 或 `Ctrl+C`
- PostgreSQL：`pg_ctl stop -D "<data目录>"`

## 常见启动报错速查

| 报错 | 原因 | 解决 |
|---|---|---|
| `Port 8088 already in use` | 后端已启动 | 查 PID 杀掉（见上节） |
| `Connection refused: localhost/127.0.0.1:5432` | PostgreSQL 没启动 | 先启动 PostgreSQL |
| `Connection refused: localhost/127.0.0.1:6379` | Redis 没启动 | 先启动 Redis |
| `JWT secret must not be blank` | 环境变量没配 | 配置 `FILE_KEEPER_JWT_SECRET` |
| `Entitlement signing private key must not be blank` | 环境变量没配 | 配置 `FILE_KEEPER_AUTH_PRIVATE_KEY` |
| `BadSqlGrammarException: Function "make_interval" not found` | H2 内存库不兼容 PostgreSQL 函数 | 这是已知 H2 兼容性问题，不影响真实 PostgreSQL 环境 |
| `cargo run could not determine which binary to run` | 项目有两个 Rust 二进制，未指定主程序 | 执行 `npm run tauri:dev -- -- --bin file-keeper` |

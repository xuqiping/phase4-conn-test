## AI原型工作流+Prompt技巧+前沿趋势+常见坑

### A. AI原型标准工作流（混合范式）

**阶段1：AI快速探索（10分钟级）**
- 自然语言描述需求→AI生成3~5个方案
- 工具选择：v0(代码可导出)/Visily(设计可编辑)/Galileo(视觉最优)
- 输出：低保真~中保真可交互原型

**阶段2：编辑与迭代（30分钟~2小时）**
- 在AI生成基础上手动调整：布局/配色/文案/图片
- 工具选择：导出至Figma/Pixso编辑(Pixso AI原生支持)
- 迭代：修改Prompt重新生成 vs 手动微调——"80%AI+20%人"原则

**阶段3：高保真交付（2小时~1天）**
- 注入Design System组件/品牌规范
- 添加真实交互(条件/变量/状态)——此时回到传统工具
- 工具选择：Figma(交互+设计系统)/Axure(复杂逻辑)

**阶段4：开发交付**
- AI代码导出(v0→React/Bolt→全栈)→开发接手
- 或：Figma→Dev Mode→开发标注

### B. Prompt-to-UI提示词技巧

| 技巧 | 说明 | 示例 |
|---|---|---|
| 角色锁定 | 指定目标用户/场景 | "一款面向老年人的健康追踪APP" |
| 布局预设 | 指定页面结构 | "顶部导航+TabBar+卡片流" |
| 风格锚定 | 指定设计风格/品牌 | "Material Design 3风格" |
| 竞品参照 | 参照已知产品 | "类似小红书的瀑布流主页" |
| 功能清单 | 列出必须包含的元素 | "含搜索栏+分类Tab+推荐卡片+底部导航" |
| 色彩约束 | 指定品牌色 | "主色#0066FF，背景白色，强调色橙色" |
| 分步生成 | 复杂页面拆多步 | "先做首页，再做详情页" |

**高阶：结构化Prompt模板**：
```
[产品] : {产品名+一句话定位}
[用户] : {目标用户+核心场景}
[页面] : {页面名称+功能列表}
[布局] : {导航结构+内容区+底部}
[风格] : {设计系统/竞品参照}
[必须] : {必须包含的组件/元素}
[禁止] : {不要出现的元素}
```

### C. 2025-2026前沿趋势

| 趋势 | 说明 | 影响 |
|---|---|---|
| **Design-to-Code成熟** | v0/Bolt等从原型到生产代码的链路打通 [来源:v0.dev/Bolt官网 | 置信度:🔍高 | 2026] | PM原型可直达开发，减少中间损耗 |
| **多模态输入** | 手绘/白板照片→AI生成高保真UI [来源:Uizard官网 | 置信度:🔍高 | 2026] | 白板讨论→可交互原型，零延迟 |
| **AI交互生成** | 不只生成界面，还生成交互逻辑/数据流 [来源:腾讯云开发者 | 置信度:📚中 | 2026] | 从"静态原型"到"可运行原型" |
| **设计系统集成** | AI自动套用品牌Design System [来源:Pixso AI | 置信度:📚中 | 2026] | 解决"AI原型好看但不品牌"问题 |
| **AI原型+AB测试闭环** | AI生成交互原型→直接投放测试 [来源:📚训练知识 | 置信度:⚠️低] | 原型验证与产品验证的边界模糊 |

### D. 常见坑

| 坑 | 表现 | 解法 |
|---|---|---|
| AI幻觉界面 | AI生成了不存在的功能/不合理布局 | AI原型=草稿≠需求文档；必须人工审核功能合理性 |
| 导出代码不可用 | v0生成的代码无法直接上线 | 代码导出=起点≠终点；开发需重构+补充逻辑 |
| 交互退化 | AI原型只有表面效果，无真实逻辑 | 交互逻辑仍需传统工具补充；AI做"壳"人做"芯" |
| 过度依赖AI | 完全信任AI布局，忽视用户场景 | AI是加速器不是决策者；用户验证不可跳过 |
| 品牌不一致 | AI默认风格≠品牌规范 | 用Design System锚定+Post-AI编辑对齐 |
| 忽视可访问性 | AI生成界面未考虑无障碍 | 生成后强制a11y检查清单（色彩对比/语义标签/焦点顺序） |

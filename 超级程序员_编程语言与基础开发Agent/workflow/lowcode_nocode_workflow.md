# Low-Code & No-Code Workflow

## Purpose

基于低代码/无代码开发知识体系，为用户提供低代码平台选型、企业级低代码落地策略、无代码创业应用场景分析或具体平台使用指导。

## Prerequisites

- 用户已明确低代码/无代码场景
- 知识库文件 `01_编程语言与核心技能.md` 及子目录文件可访问

## Steps

### Step 1: 识别低代码/无代码场景

**Goal**: 明确用户的低代码/无代码需求类型和约束条件
**Completion criterion**: 已确定场景标签和至少2项关键约束

1. 读取用户消息，提取以下信息：
   - 场景类型：平台选型 / 企业落地 / 创业应用 / 平台使用教学
   - 目标用户：企业内部IT团队 / 业务人员（公民开发者）/ 独立开发者 / 创业者
   - 应用复杂度：简单表单/流程 → 中等业务系统 → 复杂核心系统
   - 预算范围：1万-50万/年（无代码创业） / 50万-500万/年（企业落地） / 100万-1000万/年（平台自研）
   - 特殊约束：信创要求（鲲鹏+麒麟+达梦）、数据安全等级、定制化需求程度、与现有系统集成需求

2. 对照知识库中的平台分类初步判断候选方案：
   - 平台开发者/架构师，预算100万-1000万/年 → 低代码平台原理（自研/深度定制）
   - 企业CIO/IT团队，预算50万-500万/年 → 企业级低代码落地（钉钉宜搭/得帆云/ClickPaaS）
   - 独立开发者/创业者，预算1万-50万/年 → 无代码创业（Bubble/Webflow/Glide/Airtable）

3. 如有信息缺失，向用户追问不超过2个澄清问题。

**Knowledge Base Reference**:
- [参考: Agents知识库/0_超级编程行业知识库/01_编程语言与核心技能.md > 四、低代码与无代码开发 > 全景地图]

### Step 2: 输出低代码/无代码方案

**Goal**: 产出针对性的平台建议或落地策略
**Completion criterion**: 输出包含推荐平台/方案、适用场景分析、落地步骤、风险与限制

根据Step 1确定的场景，按以下分支处理：

**分支A — 平台选型**：
1. 输出选型对比表，评估维度至少覆盖：
   - 技术维度：元数据驱动能力、五大引擎（表单/流程/数据模型/页面渲染/集成）完整性、代码生成型 vs 运行时解释型、扩展性（Pro Code融合）、AI原生能力（自然语言生成应用准确率）
   - 商业维度：价格模型、生态规模、社区活跃度、技术支持、信创适配（鲲鹏/麒麟/达梦）
2. 给出最终推荐并附决策矩阵（5×3矩阵）。

**分支B — 企业级落地**：
1. 输出COE（Center of Excellence）治理框架：
   - 组织架构（ITBP + 公民开发者分级）
   - 培训体系（初级/中级/高级认证）
   - 应用评审流程（复杂度评估→技术评审→安全审计→上线审批）
   - 运维规范（版本管理/数据备份/权限回收）
2. 输出实施路线图（试点→推广→规模化→优化）。
3. 附关键风险清单（技术债积累、平台锁定、性能瓶颈、安全漏洞）。

**分支C — 无代码创业**：
1. 输出创业阶段漏斗（想法→验证→MVP→增长）。
2. 给出核心工具栈推荐：
   - Bubble（完整Web应用）/ Webflow（精美官网）/ Glide（移动端）/ Airtable（数据）
   - 技术栈搭配：Vercel + Supabase + Stripe + Cloudflare
3. 输出商业模式画布（Lean Canvas）和验证方法（Mom Test用户访谈）。
4. 附规模化瓶颈分析（何时需要从无代码迁移到Pro Code）。

**分支D — 平台使用教学**：
1. 针对具体平台输出操作指南（创建应用→设计表单→配置流程→发布上线）。
2. 附常见问题排查和最佳实践。

将结果保存到 `output/lowcode_advice.md` 或直接在对话中呈现。

### Step 3: 验证与交付

**Goal**: 确保方案符合实际落地条件
**Completion criterion**: 已通过 checklist 逐项核对

1. 读取 `checklist/lowcode_nocode_workflow_checklist.md`。
2. 逐项核对输出是否覆盖要求的知识点。
3. 确认所有关键论断均能在知识库中找到支撑。
4. 如有遗漏或偏差，补充修正。
5. 向用户交付最终答案。

## Post-Workflow

1. 记录完成状态到 `task/current_task.md`。
2. 如需深入某一具体平台或阶段，在当前 Agent 内继续追问并输出。

# Data Warehouse & Lakehouse Workflow Checklist

在完成 `workflow/data_warehouse_lakehouse_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别数据仓库/湖仓需求场景

- [ ] 已明确场景类型（数仓建模设计/离线数仓架构/实时数仓架构/湖仓一体选型/流批一体改造/BI报表优化）
- [ ] 已提取数据规模（数据量TB/PB级、日增量GB/TB、数据源数量）
- [ ] 已提取实时性要求（离线T+1/准实时分钟级/实时秒级毫秒级）
- [ ] 已识别现有技术栈（Hive/Spark/Flink/云厂商/对象存储）
- [ ] 已提取关键痛点（查询慢/数据不一致/Schema变更困难/实时化需求/成本过高）
- [ ] 已提取业务场景（BI报表/实时大屏/AI特征工程/数据治理/多租户数据服务）
- [ ] 已对照知识库架构演进路径完成初步判断（离线→Hive/Spark/实时→Flink/湖仓→Iceberg/Delta/Hudi）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出数据仓库/湖仓方案

- [ ] 如为数仓建模，Kimball维度建模方法论已说明（星型模型/业务过程/粒度/维度/事实表）
- [ ] 如为数仓建模，Inmon企业级建模和阿里OneData体系对比已输出
- [ ] 如为数仓建模，指标体系建设已覆盖（原子指标→派生指标→复合指标）
- [ ] 如为数仓建模，命名规范已给出（表命名/字段命名/指标命名）
- [ ] 如为离线数仓，分层架构已设计（ODS→DWD→DWS→ADS）
- [ ] 如为离线数仓，技术栈组合已覆盖（Hive 4.0/Spark 4.0/ORC/Parquet/Airflow/元数据管理）
- [ ] 如为离线数仓，ETL设计规范已输出（抽取策略/转换规则/加载策略）
- [ ] 如为离线数仓，数据质量校验已覆盖（完整性/准确性/一致性/及时性/有效性）
- [ ] 如为实时数仓，架构演进路径已说明（Lambda→Kappa→流批一体）
- [ ] 如为实时数仓，流批一体技术栈已覆盖（Flink CDC/Debezium/Flink/Paimon/StarRocks）
- [ ] 如为实时数仓，实时化实施路径已给出（试点→CDC接入→实时ETL→实时OLAP→全场景推广）
- [ ] 如为湖仓一体，三大引擎对比已输出（Iceberg/Delta Lake/Hudi）
- [ ] 如为湖仓一体，选型决策树已给出（多引擎共存→Iceberg/Spark深度用户→Delta Lake/CDC增量→Hudi）
- [ ] 如为湖仓一体，架构设计已覆盖（对象存储→湖仓格式→计算引擎→元数据管理）
- [ ] 如为湖仓一体，关键特性应用已说明（Schema演进/Time Travel/分区演化/Hidden Partitioning）
- [ ] 所有核心论断均能在知识库中找到支撑来源

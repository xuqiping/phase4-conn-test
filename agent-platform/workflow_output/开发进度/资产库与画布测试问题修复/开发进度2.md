## 落地内容（D1 两层架构）

拆「处理类别」与「媒体类型标签」两维度，解「自定义类型击穿 isTextType/isFileType/validateFileMime/mapMediaType 全部分类链」根因（plan 技术坑点）：

| 层 | 语义 | 取值 | 决定什么 |
|---|---|---|---|
| **media_category** | 系统级固定 | TEXT/IMAGE/VIDEO/AUDIO | 编辑器形态/mime 校验/预览/gen_meta 提取/画布节点映射 |
| **media_type** | 项目级受控词汇 {key,category} | 默认 5 项 + 自定义（如「MAP」绑 IMAGE） | 矩阵筛选/卡片标签/统计聚合 |

## 关键坑点（已解）

- **自定义 type 击穿分类链** → category 决定处理、type 仅分类标签（两层隔离）。
- **删 type 资产悬挂** → `reassignOnRemovedMediaTypes` 归同 category 首项；同 category 断绝阻删。
- **mime↔category 校验缺口** → 上传按 mime 推断 category，前端只列同 category 可选 type，后端 `validateFileMime(category)` 兜底。
- **backfill 漏数据** → CASE 全 5 类 + DEFAULT 'TEXT' 兜底。
- **测试 fixture 漏 mediaCategory** → AssetCanvasBridgeServiceTest `asset()` helper 按默认映射补 category（resolve 读 category 判文本）。

## 沉淀（待 C2 完一并织入 AGENTS.md）

- **资产媒体类型两层设计范式**：处理类别（系统固定枚举，决定 isText/isFile/mime/编辑器/预览/gen_meta 全处理链路）+ 受控词汇标签（项目级可扩展 {key,category}，仅矩阵筛选/卡片/统计用）。自定义标签必须绑定一个系统类别。凡「用户可扩展类型 + 类型决定后端处理行为」的领域照此（防类型击穿处理链）。

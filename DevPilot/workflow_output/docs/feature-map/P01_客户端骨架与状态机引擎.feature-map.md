## 技术原理大白话

- **状态机**：一张「规定路线图」——阶段是站，转移是路，门禁是检票口。路线图写在 YAML 里，工作流升级 = 换 YAML，代码不用动（这就是"工作流演化便宜"的兑现）。
- **单一真相源**：前端只是内核的"显示屏"。所有"能不能做"由 Rust 裁决，前端绝不自己猜——所以 UI 永远不会和真实状态打架。
- **WAL + 写队列**：SQLite 的读写模式，让"看日志"和"写日志"不打架；写操作排队进站，再多并发也不锁死。
- **L 迁移**：数据库表结构的"版本存档"，每次升级只追加不改旧的，老用户数据安全升级。
- **虚拟列表**：1000 行只画看得见的 ~20 行，滚起来不卡。

## 建表注解（L1/L2，本地 SQLite）

| 表 | 用途 | 关键字段用处 | 关联 |
|---|---|---|---|
| projects | 项目档案 | path UNIQUE 防重复建；scale 决定工作流变体 | 被各表 project_id 引用 |
| workflow_states | 状态机当前态 | phase 当前阶段；gate_status JSON 已过门禁 | 1:1 projects |
| rounds | 迭代轮次 | UNIQUE(project_id,seq) 防重号 | → tasks |
| tasks | 任务/chunk | source 标记来源（local/cli/mcp/deeplink）；UNIQUE(round_id,chunk_no) | → checkpoints |
| checkpoints | 存档点 | git_commit + snapshot_path 双保险回滚 | → tasks |
| artifacts | 产物索引 | UNIQUE(project_id,type,path) 版本可追溯 | → projects |
| transition_history | 转移历史（只增） | actor 记来源，回放排查用 | → projects |

> 云端表（users/wallets/token_ledger…）在 P02 建，见 specs/db_schema.md §1。迁移规则同 Flyway：已执行脚本不可改。

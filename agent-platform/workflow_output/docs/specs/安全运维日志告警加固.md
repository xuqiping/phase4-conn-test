## 二、总体架构

### 2.1 三层纵深 + 热冷分离

```
请求进 → [① 拦截层·热路径同步·<1ms]
   JwtAuthenticationFilter(补 status 缓存校验 + token 黑名单)
   → SecurityGateFilter(新) ── 顺序: IP黑名单 → 全局限流 → 账号 BANNED/LOCKED 态 → 注入特征正则
        │  命中=当场 429/403/封IP + 写 security_events(sev) + 触发钉钉(高危)
   → Controller
        │
   ├─ 业务咽喉(@AuditLog / 登录 / 计费扣点 / 媒体提交 / 文件导出 / chat 消息)
   │   │  产 ApplicationSecurityEvent(新) ── 异步 ─→ [② 检测引擎·冷路径]
   │   │                                                   SecurityMonitorWorker 规则求值(8类)
   │   │                                                   命中 → 写 security_events + 分级响应
   │   └─ 正常返回
   │
   ← 响应出(若 CRITICAL → 响应后异步封号/封IP)
                              │
              [③ 告警&响应层]
                 security_events → AlertRouter → 钉钉适配器(高危@你/中危凑批)
                 AutoResponder → 封IP(Redis+DB)/锁账号/封号(BanService)
```

**热路径（同步，必须当场拦）**：IP 黑名单、全局 sliding-window 限流、账号 BANNED/LOCKED 态、注入特征（SQLi/XSS/路径穿越正则）。命中即拦 + 同步写事件。

**冷路径（异步，专用线程池 `SecurityTaskExecutor`，可容忍秒级）**：异地/基线/外带/计费/Prompt/Token/特权变更。业务咽喉发 `ApplicationSecurityEvent`，`SecurityMonitorWorker` 消费求值。

### 2.2 复用件 vs 新增件

| 类型 | 件 | 说明 |
|---|---|---|
| 复用 | Redis | 限流（sliding/fixed window）+ IP 黑名单镜像 + token 黑名单 + status 缓存 |
| 复用 | Alertmanager 钉钉适配器 | 加安全事件入口（应用直推 JSON→适配器→钉钉），infra 与安全两入口一出口 |
| 复用 | `@AuditLog` AOP | 封号/解封/规则开关/阈值改/手动封 IP 照旧走审计 |
| 复用 | MDC / traceId / LogMasker | 安全事件 detail 全链路可串 + 脱敏 |
| 复用 | sessions 表 + Redis JWT 黑名单 | BanService 批吊 refresh token |
| 复用 | `BusinessException(ErrorCode.RATE_LIMIT)`(429) | 限流命中复用现有错误码 |
| 复用 | system_settings 键值表 | 规则开关/阈值落库 |
| 新增 | `SecurityGateFilter` | 热路径拦截总入口 |
| 新增 | `RateLimiter` 工具类 | 统一 Redis 限流（提自 AuthService 现有写法） |
| 新增 | `ApplicationSecurityEvent` + `SecurityMonitorWorker` | 冷路径事件总线 |
| 新增 | `BanService` + 封号/封 IP 端点 | 复用 `PUT /{id}/status` + 加枚举校验 + 批吊 token |
| 新增 | `AlertRouter` + `AutoResponder` | 告警分流 + 自动处置 |
| 新增 | 3 表：`security_events` / `ip_blacklist` / `login_attempts` | 见第三章 |
| 新增 | users 扩 2 列 + status CHECK 扩 `BANNED` | 见第三章 |
| 新增 | 4 admin 前端页 + `security` logger 通道 + logback 合规 | 见第五、六章 |

### 3.3 新表3：`login_attempts`（暴破/撞库原料，30 天滚动）

| 字段 | 类型 | 用途 |
|---|---|---|
| id | BIGINT | 主键 IDENTITY |
| created_at | TIMESTAMPTZ | 时间 |
| identifier | VARCHAR(128) | 试登的用户名/邮箱 |

> 复合索引 `(client_ip, created_at)` + `(identifier, created_at)`。30 天清理（比事件表短，够取证）。

### 3.4 users 表扩列（2 列 + 枚举扩，复用现有 status）

| 改动 | 内容 |
|---|---|
| status CHECK 扩 | `('ACTIVE','DISABLED','LOCKED')` → 加 `'BANNED'`（区分「安全封号」vs「普通禁用 DISABLED」） |
| 新列 ban_reason | `VARCHAR(128)` — 封号原因（admin 填 / 规则码） |
| 新列 locked_until | `TIMESTAMPTZ` — 临时锁定到期自动解 |

> **不新增 account_status**，直接复用 [V1:18](../../backend/src/main/resources/db/migration/V1__init_schema.sql#L18) 现有 `status` 字段。

### 3.5 不动的件

- **audit_logs**：永久 append-only，V91 REVOKE 防篡改不动。
- **Redis 会话单 key 模型**（`session:user:{userId}`，[SessionService:29](../../backend/src/main/java/com/superprogrammer/auth/service/SessionService.java#L29)）：BanService 删该 key 即同时断 access（下请求 `isCurrent` 比对失败→401 SESSION_KICKED）+ refresh（刷新时同理拒）。无需批吊每个 refresh token。单点登录关时（`isCurrent` 恒 true）由 `ban:user:{id}` 标记 key 兜底（见 5.1）。
- **Redis JWT 黑名单**（`authService.isTokenBlacklisted(jti)`，[JwtFilter:57](../../backend/src/main/java/com/superprogrammer/auth/security/JwtAuthenticationFilter.java#L57)）：封号不依赖它（access 靠 sid/ban 标记，15min 自然过期）；登出/单 token 撤销仍走它。
- **system_settings**：规则开关/阈值复用现有键值表（新键前缀 `security.rule.*` / `security.rate.*` / `security.ban.*`）。

### 3.6 迁移

3 新表 + users 扩列 + status CHECK = **1 个 Flyway V96__security_hardening.sql**。`security_events`/`ip_blacklist`/`login_attempts` 不继承 BaseEntity（纯插入+清理，无 updated/deleted 语义）。

## 四、限流 + 8 类检测规则 + 自动响应

### 4.1 限流层（Redis，热路径，<1ms）

| 维度 | 算法 | Redis Key | 默认阈值 | 触发动作 |
|---|---|---|---|---|
| 全局 per-IP | fixed-window(INCR+EXPIRE) | `rl:ip:{ip}` | 600/min | 429 + 计入 RATE_BURST |
| per-用户 per-路由 | sliding-window(ZSET) | `rl:u:{uid}:{route}` | 按路由（chat 30/min、媒体提交 5/min、导出 10/min） | 429 + 屡犯升级 |
| 登录 per-IP | fixed-window | `rl:login:ip:{ip}` | 20/5min | 超→封 IP + CREDENTIAL_STUFFING |
| 登录 per-identifier | fixed-window | `rl:login:id:{id}` | 5/15min | 超→LOCKED 15min + LOGIN_BRUTE_FORCE |

> **复用** [AuthService register 限流](../../backend/src/main/java/com/superprogrammer/auth/service/AuthService.java)（60s/IP5/user5）同套 Redis 写法，统一提到 `RateLimiter` 工具类。
> **降级**：Redis 故障 → **fail-open 放行**（限流不能阻塞业务，与现有降级一致）。

### 4.2 8 类规则（15 rule code）

| # | 规则码 | 触发条件 | 数据源 | 路径 | 默认严重度 |
|---|---|---|---|---|---|
| 1 | `LOGIN_BRUTE_FORCE` | 同 identifier 5 次失败/15min | login_attempts | 热 | HIGH→锁号 |
| 1 | `CREDENTIAL_STUFFING` | 同 IP 20 个不同 identifier/5min | login_attempts | 热 | HIGH→封 IP |
| 2 | `SQLI_PROBE` / `XSS_PROBE` / `PATH_PROBE` | 参数命中注入特征正则（UNION SELECT / `<script>` / `../` 等） | 请求参数 | 热(filter) | HIGH→封 IP(累犯) |
| 2 | `IDOR_PROBE` | 同 user/IP 403 频次 ≥10/5min | GlobalExceptionHandler 403 事件 | 冷 | MEDIUM |
| 3 | `RATE_BURST` | 屡犯限流（同维度 1h 内 ≥3 次 429） | RateLimiter 计数 | 热→冷升级 | MEDIUM |
| 4 | `IMPOSSIBLE_TRAVEL` | 两登录距离/时间→速度 >800km/h | login_attempts geo | 冷 | MEDIUM |
| 4 | `OFF_HOURS_SENSITIVE` | 凌晨 0-6 点敏感操作（充值/权限改/批量导出） | @AuditLog 事件 | 冷 | LOW |
| 5 | `DATA_EXFIL` | 短窗下载/导出/知识库拉取 ≥阈值（如 500 条/10min） | 下载/导出咽喉 | 冷 | HIGH |
| 5 | `POINTS_ABUSE` | 积分负数绕过/异常返还模式 | 计费扣点咽喉 | 冷 | HIGH |
| 5 | `MEDIA_ABUSE` | 媒体生成短窗烧钱 ≥阈值（如 ¥100/30min） | 媒体提交咽喉 | 冷 | HIGH |
| 6 | `PROMPT_INJECTION` | 消息命中越狱模板/注入特征（「忽略上述指令」/DAN/developer mode 等） | chat 消息咽喉 | 冷 | MEDIUM（屡犯 HIGH） |
| 7 | `TOKEN_REUSE` | 同 refresh token 多 IP 用 / 同账号多设备并发会话超阈值 | sessions 表 | 冷 | MEDIUM |
| 8 | `PRIVILEGE_CHANGE` | 提权/改权限/改计费规则/关安全开关 | @AuditLog 实时 | 冷(实时推) | HIGH |

> **规则6 Prompt 注入检测**：维护**越狱特征库**（已知模板正则 + 关键短语），纯规则匹配起步（不引 ML）。命中记录 → 屡犯告警 → 极端情况接内容审核。符合黑客地图 D-04.18 / D-16.05。

### 4.3 自动响应矩阵（severity → action，对应「分级自动响应」）

| 严重度 | 自动动作 | 钉钉 | 写 audit | 例子 |
|---|---|---|---|---|
| CRITICAL | 封 IP + 锁账号/封号 + 踢会话 | @你立即 | ✓ | 确认 SQLi 命中且累犯 |
| HIGH | **择一**：封 IP **或** 锁账号（规则定） | @你立即 | ✓ | 暴破/撞库/外带/计费欺诈 |
| MEDIUM | 只记 + 计入风险分（不封） | 凑批 30s | — | 异地/越权/Prompt/Token |
| LOW | 只记 security_events（不打扰） | 不发 | — | 单次 429/非工作时段 |

**封 vs 锁择一逻辑**（避免双重误伤）：
- 暴破/撞库 → **锁账号**（identifier 维度，攻击者可能在多 IP）
- 注入探测/外带/爬虫 → **封 IP**（多账号同一攻击源）
- 计费欺诈/Token 盗号 → **锁账号**（保护资产）+ 告警 admin 定夺是否升级封号

### 4.4 可配置（system_settings，admin 前端可调）

```
security.rule.LOGIN_BRUTE_FORCE.enabled=true
security.rule.LOGIN_BRUTE_FORCE.max_fail=5
security.rule.LOGIN_BRUTE_FORCE.window_minutes=15
security.rule.LOGIN_BRUTE_FORCE.lock_minutes=15
security.rate.global.ip_per_minute=600
security.response.auto_ip_block=true     # 总闸：关=所有规则只告警不封（嫌误伤可一键关）
security.response.auto_account_lock=true
```

> **可选加分项（YAGNI 先不做）**：风险评分模型（累计 MEDIUM 分→自动升级 HIGH 触发处置）。先跑规则矩阵观察告警质量，二期再上评分。

## 五、封号即时生效 + 告警管线

### 5.1 封号即时生效（堵真实漏洞：JwtAuthenticationFilter 不查 status）

**现状洞**：[AuthService:216](../../backend/src/main/java/com/superprogrammer/auth/service/AuthService.java#L216) 登录时查 status，但 [JwtAuthenticationFilter](../../backend/src/main/java/com/superprogrammer/auth/security/JwtAuthenticationFilter.java) 不查 → 封号后 access token（15min）期内用户照常调 API。

**修复数据流**（复用现有 Redis 会话 sid 比对，不新增 status 缓存）：
```
admin 封号（PUT /{id}/status，加枚举校验 + 防自封/最后超管）
  → status=BANNED + ban_reason（DB）
  → BanService.revoke(userId):
       ① redisTemplate.delete("session:user:{uid}")   // 删 sid → 下请求 isCurrent 失败 → 401 SESSION_KICKED
       ② redisTemplate.set("ban:user:{uid}", "1", TTL=access有效期)  // 兜底标记，单点登录关时也断
       ③ 若有 WS 长连接：向其发强制下线消息（chat 域，复用现有 MemoryNotification 通道或新增）
  → JwtAuthenticationFilter 在 isCurrent 之后补一行：ban 标记校验
       if redisTemplate.hasKey("ban:user:{uid}") → 401 SESSION_KICKED（固定话术，不透传「被封」）
  → 解封时 BanService.restore(userId): 删 ban 标记 key（session key 已删，用户须重登）
  → 效果：封号秒级生效，不等 access token 到期；单点登录开关关时 ban 标记兜底
```

> 复用现有 `ErrorCode.SESSION_KICKED`(40104) 固定话术，避免泄露「你的账号被封」（防攻击者探测）。
> 防自封：封号端点若 `id == 当前登录用户` → 403。防最后超管锁死：若目标是最后一名持 `user:manage` 的 ACTIVE 用户 → 403。

### 5.2 告警管线（复用 Alertmanager 钉钉适配器，加安全事件分流）

```
SecurityMonitorWorker 求值命中
  → 写 security_events
  → AlertRouter.dispatch(event):
       ├─ CRITICAL/HIGH → 钉钉适配器即时发（@你，markdown 卡片：类型/IP/用户/规则/traceId/处置入口深链）
       ├─ MEDIUM → 攒批 30s → 凑一条汇总钉钉
       └─ LOW → 不发（只入库，前端可查）
  → AutoResponder.execute(event) 按 severity 矩阵封/锁
```

> **安全告警不走 Prometheus**（那是指标/infra）。安全告警 = 应用直推钉钉适配器 HTTP（适配器本是个 webhook 接收器，应用 POST 安全事件 JSON 给它，它转译发钉钉）。infra 告警 = Prometheus→Alertmanager→适配器→钉钉。**同一适配器两入口**，钉钉群一个口子收。
> 钉钉卡片含 traceId → 串 app.log 全请求；含「处置入口」按钮深链到前端事件页那条。

## 六、日志增强（合规 + 安全专用 logger）

1. **logback 保留期合规**（堵核④，网安法第21条硬底线）：
   - APP `maxHistory` 30→180 天，`totalSizeCap` 2GB→12GB
   - ERROR 90→180 天，1GB→2GB
   - SQL 7→180 天，500MB→3GB（默认仍 OFF，开了才占）
2. **新增 `security` logger 通道**（独立 `security.log`，JSON 格式，过 MaskingAppender 脱敏）：`SecurityGateFilter`/`SecurityMonitorWorker`/`BanService` 全打这。便于安全审计单独提取 + 满足「安全日志独立留存」实践。
3. **security_events 表** = 结构化安全事件库（半年，前端可查/导出，运维可物理删）。
4. **脱敏回退**：命中注入的 payload 片段进 detail_json 时仍过 LogMasker（防 payload 里夹带手机号等被当数据泄露）。

## 十一、残留风险（记录非阻塞）

- 限流 Redis 故障 fail-open（攻击者可能趁 Redis 抖动突破）→ 由登录锁定/注入特征（内存态）兜底
- Prompt 注入纯规则匹配可被变形绕过 → 二期评估内容审核/ML
- 异地检测 ip2region 精度（市级，移动切 IP 可能误报）→ MEDIUM 只告警不封，可观察后调阈值
- 单机无横向扩展（百万级够，瓶颈再拆 Redis 集群）

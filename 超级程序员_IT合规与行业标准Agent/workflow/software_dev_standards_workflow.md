# Software Development Standards Workflow

## Purpose

基于软件开发国家标准知识框架，提供软件工程国标体系的全流程落地路径，覆盖GB/T 8566生存周期过程、GB/T 8567文档编制、GB/T 25000质量模型、GB/T 36964成本度量、GB/T 47470安全开发、等保2.0、信创标准七大核心标准。

## Prerequisites

- 已明确项目性质（政府采购/企业自研/外包定制）
- 已确定是否需要等保测评/密评/信创适配

## Steps

### Step 1: GB/T 8566生存周期过程落地

**Goal**: 依据GB/T 8566-2022四大过程类建立软件开发全生命周期管理框架
**Completion criterion**: 输出《软件生存周期过程定义》，四大过程类的关键活动已映射到实际项目管理流程

依据GB/T 8566-2022框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > GB/T 8566四大过程类]：
1. 技术过程：需求分析 → 系统设计 → 软件实现 → 软件验证（测试）→ 软件确认（验收）
2. 管理过程：项目策划（估算/计划）→ 项目控制（进度/成本/质量跟踪）→ 配置管理（版本/变更/基线）
3. 组织使能：基础设施（开发/测试/CI/CD环境）→ 质量管理（QA体系/审计）→ 知识管理（文档/培训/复盘）
4. 协议过程：采购（供应商评估/合同管理）→ 供应（交付物/SLA/维保）
执行：
- 将四大过程类映射到实际项目管理模板（如Jira/禅道/自研PMO系统）
- 定义每个过程的输入/输出/责任人/工具/检查点
- 输出《软件生存周期过程定义书》+ 《过程裁剪指南》（允许根据项目规模裁剪非关键活动）

### Step 2: GB/T 8567文档编制规范实施

**Goal**: 建立符合国标的软件文档编制体系，确保14类核心文档齐全、格式规范、内容可追溯
**Completion criterion**: 《文档编制规范》发布，文档模板已配置，每类文档有明确的责任人与评审流程

依据GB/T 8567文档编制要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 文档编制(GB/T 8567)]：
1. 14类核心文档清单与模板：
   - 管理类：可行性研究报告、项目开发计划、测试计划、验收报告
   - 开发类：需求规格说明、概要设计说明、详细设计说明、数据库设计说明、接口设计说明
   - 用户类：用户手册、操作手册、安装部署手册
   - 维护类：测试分析报告、软件维护手册
2. 文档编制规范：
   - 统一模板（封面/目录/正文/附录/版本历史）
   - 编号规则（项目代号-文档类型-版本号，如PRJ-SRS-v1.2）
   - 评审流程（编写→自审→同行评审→专家评审→批准发布）
   - 变更控制（变更申请→影响分析→审批→修订→重评审）
3. 工具支撑：Confluence/飞书文档/自研文档平台 + 版本控制（与代码版本关联）
输出：《软件文档编制规范》+ 14类文档模板 + 《文档评审检查单》

### Step 3: GB/T 25000质量模型应用

**Goal**: 依据GB/T 25000八大质量特性建立软件质量评估体系，量化软件质量水平
**Completion criterion**: 输出《软件质量评估报告》，八大特性均有可量化的评估指标与实测数据

依据GB/T 25000八大质量特性 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > GB/T 25000八大质量特性]：
1. 功能性：功能完备性（需求覆盖率100%）、功能正确性（缺陷密度<0.1/KLOC）、功能适合性
2. 性能效率：时间特性（响应时间/P99延迟）、资源利用性（CPU/内存/磁盘）、容量（并发用户数/TPS）
3. 兼容性：共存性（与其他系统并行运行）、互操作性（接口标准符合度）
4. 易用性：可辨识性（界面一致性）、易学性（新用户上手时间）、可操作性（任务完成率）、用户差错防御性
5. 可靠性：成熟度（故障频率）、可用性（uptime百分比）、容错性（异常恢复能力）、易恢复性（RTO/RPO）
6. 信息安全性：保密性（加密覆盖率）、完整性（防篡改机制）、抗抵赖性（审计日志）、可核查性（身份追溯）、真实性（数据来源可信）
7. 可维护性：模块化（耦合度/内聚度）、可重用性（组件复用率）、易分析性（日志完整性）、易修改性（变更影响范围）、易测试性（自动化覆盖率）
8. 可移植性：适应性（环境兼容性）、易安装性（部署自动化）、易替换性（模块可替换性）
执行：
- 为每个特性定义量化指标（如性能：P99延迟<200ms；可靠性：可用性≥99.95%）
- 信创测试直接引用此模型作为验收标准
- 输出《软件质量评估报告》+ 《质量特性度量指标库》

### Step 4: GB/T 36964成本度量实施

**Goal**: 掌握功能点计数方法，为软件项目预算编制提供标准化成本估算
**Completion criterion**: 输出《功能点计数报告》，计数结果经复核，偏差率<10%

依据GB/T 36964功能点计数标准 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > GB/T 36964功能点计数]：
1. 识别功能组件：
   - ILF（内部逻辑文件）：数据组由系统维护，7/10/15功能点（简单/中等/复杂）
   - EIF（外部接口文件）：数据组由其他系统维护，5/7/10功能点
   - EI（外部输入）：处理外部数据进入系统，3/4/6功能点
   - EO（外部输出）：处理数据后输出，4/5/7功能点
   - EQ（外部查询）：简单查询无复杂处理，3/4/6功能点
2. 确定复杂度：基于数据元素类型（DET）和引用文件类型（RET/FTR）判定简单/中等/复杂
3. 计算未调整功能点（UFP）：各组件功能点求和
4. 应用调整因子（VAF）：14个通用系统特性（GSC）评分（0-5），计算调整后的功能点（AFP）
5. 转化为工作量：参考行业基准数据（如CSBMK中国软件行业基准数据），人月=AFP/生产率
执行：
- 培训项目团队掌握功能点计数方法
- 使用工具辅助计数（如SNAP/自研Excel模板）
- 政府项目必须使用功能点计数作为预算编制标准方法
输出：《功能点计数报告》+ 《项目成本估算书》

### Step 5: GB/T 47470-2026安全开发能力评估

**Goal**: 依据新版安全开发国标建立五级成熟度安全开发体系
**Completion criterion**: 完成自评估，输出《安全开发能力评估报告》，明确当前成熟度等级与改进路线图

依据GB/T 47470-2026五级成熟度 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > GB/T 47470-2026五级成熟度]：
1. 五级成熟度定义：
   - Level 1 初始：无规范流程，安全活动随机
   - Level 2 管理：安全活动有计划、有资源、有跟踪
   - Level 3 定义：安全开发流程标准化、制度化，与组织级流程集成
   - Level 4 量化：安全度量体系建立，基于数据驱动改进
   - Level 5 优化：持续优化，创新安全技术，行业领先
2. 八大能力域：
   - 安全需求分析（威胁建模/安全需求提取）
   - 安全设计（安全架构/加密设计/访问控制设计）
   - 安全编码（编码规范/静态扫描/组件安全）
   - 安全测试（渗透测试/模糊测试/代码审计）
   - 安全交付（安全部署/配置基线/密钥管理）
   - 安全运维（漏洞管理/应急响应/日志审计）
   - 安全知识管理（培训/案例库/度量）
   - 安全治理（策略/组织/合规/供应商安全）
执行：
- 开展自评估：对照八大能力域的详细能力项打分（1-5分）
- 识别差距：当前等级 vs 目标等级（建议至少达到Level 3定义级）
- 制定改进路线图：12个月提升计划，每季度一个里程碑
输出：《安全开发能力评估报告》+ 《安全开发改进路线图》

### Step 6: 等保2.0与信创标准落地

**Goal**: 完成等保2.0"一个中心三重防护"框架设计，制定信创适配计划
**Completion criterion**: 等保差距分析完成，三级系统211项测评要求逐条对照；信创替代清单已制定，替代路径清晰

依据等保2.0核心框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 等保2.0核心框架]：
1. 等保2.0"一个中心三重防护"：
   - 安全管理中心：集中管控/策略统一/态势感知
   - 通信网络安全：网络架构冗余/边界防护/入侵防范/恶意代码防范
   - 区域边界安全：访问控制/边界防护/入侵防范/安全审计
   - 计算环境安全：身份鉴别/访问控制/安全审计/入侵防范/恶意代码防范/数据完整性/数据保密性/数据备份恢复
2. 三级系统211项测评要求逐条对照：
   - 制作《等保测评差距分析表》，标记已满足/部分满足/未满足
   - 对未满足项制定整改计划（技术措施+管理措施）
3. 信创适配计划：
   - 2026年1月信创目录正式落地，国资委79号文要求2027年底央企100%完成替代
   - 信创全栈选型：芯片（鲲鹏/飞腾/海光）+ 操作系统（欧拉/麒麟）+ 数据库（达梦/OceanBase）+ 中间件（东方通/TongWeb）
   - 运营商BSS/OSS国产化率目标超80%
   - 制定《信创替代路线图》：核心业务优先、非核心业务跟进、外围系统最后
输出：《等保差距分析报告》+ 《等保整改计划》+ 《信创替代清单与路线图》

## Post-Workflow

1. 读取 `checklist/software_dev_standards_workflow_checklist.md`
2. 交叉验证每项国标要求、每个质量特性指标、每个功能点计数
3. 全部通过后输出《软件开发国家标准总纲》并归档

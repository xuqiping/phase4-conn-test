# Implementation Plan for 视频反推与转绘

> Phase 2 产出。Phase 3 逐步勾选执行。只含伪代码，不含真代码。
> 来源规格：[../specs/视频反推与转绘设计.md](../specs/视频反推与转绘设计.md)
> 前置依赖：[画布计划](无限画布四轮增强.plan.md) Step 1（analyze 请求复用 `background` 标记防断路）；[图视计划](图片视频模块历史分页与预览缓存.plan.md) Step 3（共享预览组件）。技术路线=FFmpeg 场景检测抽帧+多模态 LLM，零新 Provider。

## 背景与目标

- 2x 反推四能力：分镜表 / 关键帧（镜头切换单元）/ 剧本 / 本土化转绘（剧情不变，源文化元素→目标国家元素，changeLog 核对）。
- 两入口：无限画布（视频节点反推→建节点连边）、视频生成模块（新 Tab，结果区+用剧本生成预填）。

## 技术实现坑点预判与规避措施

| 技术点/功能块 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| FFmpeg 场景检测输出解析 | `select=gt(scene,T)` 输出帧号/时间格式随版本变，解析崩 | 用 `-vf select -vsync vfr` + `showinfo`/`ffprobe` 拿 pts 秒；解析失败兜底均匀采样（规格 §4.1.2 已定） | 单测：mock 两格式输出+0命中兜底 |
| 场景检测阈值敏感 | 阈值 0.3 对慢摇镜头漏检/对闪切过检 | 阈值参数化（默认0.3）+ min/maxFrames 钳制（命中<4 回退均匀补足，>24 截断取间隔均匀子集） | 单测钳制逻辑（纯函数） |
| 多模态 LLM 输出不稳定 | 分镜/剧本 JSON 断尾或夹 ```json 围栏 | 提示词强制纯 JSON+字段长度上限（对齐 RAG 提炼已有经验：maxTokens 3000+精简约束）；解析失败重试1次再报错 | 单测：坏 JSON 两态 |
| **帧数=token 成本失控** | 24 帧 × 高分辨率图 token 巨大，一次反推烧穿积分 | 帧图统一缩略（长边 ≤1024 再入 LLM；原始帧文件另存供查看）；maxFrames 默认12上限24；预估价提示（前端显示帧数与预估消耗） | 单测缩略参数；手测消耗合理 |
| 同步接口 120s 超时 | axios 15s 默认必断 | 请求 timeout 120s + `background:true`（豁免断路）；前端 loading 可取消（AbortController） | 手测取消+长视频不弹错误 |
| FFmpeg 同步占 CPU | 大视频抽帧阻塞线程池，拖垮其他请求 | 帧提取限流（@RateLimit 复用 canvas 模式）+ 视频时长上限（>10min 拒绝并提示截取）；FFmpeg 进程超时 60s 杀 | 单测上限校验 |
| 关键帧 poster 时序 | 帧文件分析中 LLM 已返回但帧未落库 | 步骤内先落帧文件再调 LLM（顺序保证）；失败时帧保留（可重跑 LLM 步） | 手测中途失败重试 |
| 「用剧本生成」预填冲突 | 表单已有参考视频/提示词被静默覆盖 | 预填前若槽位非空弹确认（替换/追加/取消） | 手测三选 |
| 本土化改写破坏结构 | LLM 改写顺手改了分镜数/顺序 | 提示词强约束「镜头数与顺序不变」+ 后处理校验镜头数一致不一致则返回警告标注 diff | 单测：结构不变断言+不一致告警路径 |

## 安全检查清单

- [x] **鉴权/授权**：analyze 源校验——taskId 走 loadForDownload 咽喉（他人任务403）、fileId 走文件访问授权；`media:gen`（Step2 落地，单测覆盖 403 透传）
- [x] **输入校验**：modes 非空子集枚举；sceneThreshold∈[0.1,0.9]；maxFrames∈[4,24]；targetLocale≤32 字；script≤8000（对齐提示词上限）；视频时长≤10min（Step1 时长拒 + Step2 modes/长度校验单测覆盖）
- [x] **计费**：LLM 调用走既有 chat 计费（多模态 token），usage_log 落 project_group_id（兼容[项目组计划](项目组与积分划拨.plan.md) gid 透传）——LlmRequest.projectGroupId 透传，网关 chat 链路内完成
- [x] **审计**：analyze/localize @AuditLog（action+源标识+帧数+消耗）——action/targetType 已挂；消耗明细由 usage_log 承载（见 Step2 偏差④）
- [x] **错误处理**：FFmpeg 失败/LLM 失败均返回明确业务码，不泄漏服务器路径（Step1 固定话术单测 + Step2「模型未返回合法 JSON」两败话术）
- [x] **依赖**：无新增包（FFmpeg 既有）

## 性能考虑与验证计划

- [x] 抽帧为本地 CPU 任务：60s 进程超时+限流（上表）
- [x] LLM 单次调用，无循环放大；帧缩略后单次 token 预算可控（实测记录）——重试上限 1 次；实测消耗留 Phase 4
- [ ] Phase 4：1 分钟视频端到端反推 <90s；本土化改写 <30s

  - **文件**：新增 `media/reverse/VideoReverseService.java`、`VideoFrameService.java`（复用/扩展）、Test（mock FFmpeg 输出、钳制纯函数、时长拒绝）
  - **依赖**：无
  - **验证**：单测四态（正常/0命中兜底/超限截断/超时长拒）；本地真实视频冒烟

## 本轮关键决策与变更

- **两遍式抽帧替代一遍 `-frames:v N` 直出**：先 `showinfo` 全片扫描拿切镜时间戳全集（不落帧），再按选定时间戳逐个 `input seek` 取帧。理由：一遍直出需预设帧数上限，超限时截断只能截前 N 个命中（长视频前段密集则后段无覆盖）；两遍式先见全集再均匀选点，首尾保留跨全片。代价 = 1 次全片解码 + ≤24 次快 seek，均在 60s 进程超时预算内。
- **取帧命令用 `-ss` 前置（input seek）**：本地文件快且到帧精确（解码到目标 ts），无需 `-ss` 后置的精确模式开销。
- **阈值表达式写法**：`select=gt(scene\,0.3)` 反斜杠转义逗号（ProcessBuilder 无 shell，单引号包裹方案不适用；ffmpeg filtergraph 自身的 `\,` 转义跨版本稳定）。
- **缩略即原帧时复用 fileId**：帧长边 ≤1024 时 `scaleToMaxEdge` 返回原引用，`thumbFileId == fileId`，不重复落一份 stored_files（省一半文件数，小视频常态）。
- **元数据编码进 originalName**（`reverse-shot-01-12.34s.jpg`）：stored_files 无时间戳列（spec §6 无新表），结构化元数据由 API 返回结构携带，文件名留痕供运维肉眼排查。
- **并发闸 tryAcquire 快速失败不排队**：同步接口宁拒不等（排队会顶着 axios 120s 超时白等）。

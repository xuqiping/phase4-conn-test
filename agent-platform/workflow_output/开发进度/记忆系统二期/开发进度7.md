## 沉淀

- 思考型模型（kimi/glm）思考 token 与正文共享 max_tokens——**内部 JSON 调用必须关思考或给足双份预算**；kimi 尊重 `thinking:{"type":"disabled"}`，glm 忽略（遗留观察项）。
- SSE 流三段式超时要对齐：SseEmitter timeout = blockLast timeout ≥ 最长生成时间；超时路径禁止落入同步重答兜底（双倍计费）。
- 流式逐 chunk 净化的 carry/flush 模式：**flush 必须挂在流终结信号上**，不能指望下游先发一个非数据事件来触发。
- 「思考与正文共享预算」的坑对 glm 是**无解**（disabled/budget 都忽略，思考量随输入增长）——正确做法不是加预算，是内部 JSON 调用域换思考可控模型（设置项单咽喉收口 + Flyway 换死值）。

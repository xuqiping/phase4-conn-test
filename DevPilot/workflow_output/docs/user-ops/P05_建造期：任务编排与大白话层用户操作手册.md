# P05 建造期：任务编排与大白话层 · 用户操作手册

## 1. 进入建造阶段

**前置**：项目已完成「想法 → 需求 → 计划」并审批通过。

| 步骤 | 界面变化 | 预期结果 |
|---|---|---|
| 1. 在左侧阶段栏点击「建造」 | Build 视图打开 | 显示当前任务流、事件日志、存档点时间轴 |
| 2. 点击顶部「开始建造」或 Plan 视图的「开工」 | 第一个 task 变 running | 事件日志实时刷新，显示 probe/install/run/done 阶段 |

## 2. 看任务执行过程

- **任务列表**：左栏显示当前轮次的所有 tasks，按 chunk 顺序排列；状态色标：done（绿）、failed（红）、running（蓝）、pending（灰）。
- **事件日志**：选中某个 task，右栏显示 narrative / raw / error / checkpoint 四类事件。
- **实时刷新**：任务执行时事件会自动追加，无需手动刷新。

## 3. 看懂改动摘要

| 操作 | 位置 | 效果 |
|---|---|---|
| 查看大白话摘要 | 任务完成后在 CheckpointTimeline 点击摘要 | 显示「改了什么 / 为什么 / 影响 / 风险 / 涉及文件」 |
| 切换原始 diff | 摘要面板右上角「看原始 diff」 | 显示 `git diff` 原文；diff >5000 行会提示截断 |

## 4. 全局大白话翻译开关

| 操作 | 位置 | 效果 |
|---|---|---|
| 开启/关闭大白话 | Build 视图「开启大白话」按钮 | 所有 `PlainText` 区域切换中文解释；状态持久化到 localStorage |
| 看术语解释 | 悬停带虚下划线的英文术语 | 弹出气泡显示中文解释 |

## 5. 回滚到某个存档点

| 步骤 | 注意事项 |
|---|---|
| 1. 在 CheckpointTimeline 找到目标 checkpoint | 确认 commit  hash 与时间 |
| 2. 点击「回滚」→ 二次确认 | 该点之后的代码和任务进度会丢失 |
| 3. 确认后 | git HEAD 回到目标 commit；下游 tasks 变 pending；不扣 Token |

## 6. 追加指令续跑

| 步骤 | 预期结果 |
|---|---|
| 1. 全部 task 完成后（或想额外修改时），在 Build 视图「追加指令续跑」输入框填写需求 | 示例：「再帮我加个 README」 |
| 2. 点击「追加并续跑」 | 同一 round 末尾新增 task，chunk_no = max+1，自动执行 |

## 7. 进入验收

| 条件 | 操作 | 预期结果 |
|---|---|---|
| 当前轮次所有 tasks 状态为 done | Build 视图出现「进入验收」按钮 | 点击后状态机推进到「验收」阶段 |

## 8. 驾驶舱看板

- **进度**：状态机真实进度。
- **缺陷**：当前轮次 failed tasks 数量。
- **覆盖率**：当前轮次 done tasks / 总 tasks 占比。
- **消耗**：当前轮次任务累计 cost_cents（单位：分）。
- **轮次时间线**：展示历史 rounds 与任务完成光点。

## 9. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 任务一直 pending | 没有触发 execute_build 或上游 task 失败 | 点击「开始建造」或回滚后重试 |
| 事件日志为空 | 未选中 task 或 task 未开始 | 点击任务列表中的 task |
| 大白话翻译没生效 | plainMode 未开启或 token 未设置 | 先开启开关；调用 LLM 需登录 |
| 回滚失败 | 项目目录 git 状态异常 | 在项目目录手动执行 `git status` 排查 |

# Agent架构范式选型指南

## 决策树

```
任务类型？
├── 单一确定性任务（如：查天气→整理报表）
│   └── → Plan-and-Execute（先规划后执行，步骤确定）
├── 开放探索性任务（如：调研竞品→写分析）
│   └── → ReAct（边想边做，逐步探索）
├── 需要自我纠错的任务（如：代码调试）
│   └── → ReAct + Reflection（边做边反思）
└── 复杂多角色任务（如：产品→设计→开发全流程）
    └── → Multi-Agent（分角色协作）
```

## 三大范式对比

| 维度 | ReAct | Plan-and-Execute | Multi-Agent |
|---|---|---|---|
| 核心逻辑 | 边想边做 | 先想再做 | 分工协作 |
| 适合任务 | 探索性、不确定 | 确定性、步骤多 | 角色多、复杂度高 |
| Token消耗 | 中（每步推理+行动） | 中（一次性规划+逐步执行） | 高（多Agent通信开销） |
| 出错恢复 | 自然适应（每步观察） | 需重规划机制 | 需协调恢复机制 |
| 实现复杂度 | 低 | 中 | 高 |
| 代表框架 | LangChain ReAct | LangGraph Plan-and-Execute | CrewAI / AutoGen |

## 选型检查清单

### 选ReAct，当：
- [x] 任务路径不确定，需要根据中间结果动态调整
- [x] 不需要显式规划，自然探索即可
- [x] 单Agent足够，不需要分工

### 选Plan-and-Execute，当：
- [x] 任务步骤可预见，只是步骤多
- [x] 需要全局视角统筹（先看全貌再做）
- [x] 可能有重规划需求（Plan需要可修改）

### 选Multi-Agent，当：
- [x] 任务涉及多个专业领域（如：研究+写作+审核）
- [x] 单Agent的工具集/上下文窗口不够
- [x] 需要并行处理子任务

### 选ReAct+Reflection，当：
- [x] 任务需要高准确率（如代码/数据）
- [x] Agent容易出错但错误可自我发现
- [x] 可以接受额外Token消耗用于反思

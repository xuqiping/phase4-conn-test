# 人工测试问题 1—4 修复 · 人工测试方案

> Phase 3 功能级人工测试基准。关联：[专项 PRD](../specs/人工测试问题1-4修复.PRD.md) F1/F2/P1/G1/C1/C2。
> 本文件先定义验收步骤；实际结果在 Phase 4 填写。

## 1. 为什么需要人工测试

- [x] 涉及拖拽、右键菜单、键盘快捷键、焦点与窗口交互。
- [x] 需要真实 Windows `.lnk`、Office/资源管理器多窗口和全局快捷键占用环境。
- [x] 悬浮球位置、显示器切换、缩放与体感性能需要实机确认。
- [x] 需要确认文件删除边界和应用隐藏后的可恢复入口。

自动化测试覆盖数据迁移、冲突算法、事务、排序和位置校正；真实 OS 注册、窗口视觉和外部应用启动必须人工验证。

## 2. 前置条件

- Windows 10/11 x64；分别测试 100% 与 125% 缩放，至少一次双显示器/负坐标布局。
- Debug 构建用于日志定位，Release/MSI 构建用于性能与最终交互。
- 准备：普通文件、文件夹、EXE、PPTX、带参数 `.lnk`、中文路径 `.lnk`、UNC `.lnk`、目标失效 `.lnk`。
- 准备多个 Excel、PowerPoint 和资源管理器窗口；剪贴板准备文本、图片、文件、URL 混合记录。
- 未登录并断网；本功能不要求启动 Java、PostgreSQL 或 Redis。
- 测试前备份应用本地数据目录；测试文件不得含真实敏感数据。

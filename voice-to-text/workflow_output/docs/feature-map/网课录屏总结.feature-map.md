# Feature Map · 网课录屏总结

> Phase 3 产物：功能-代码速查表 + 关键技术大白话注解。本功能 **PRD 编号：FR-101 ~ FR-109**。
> 终端用户操作步骤在 [../user-ops/网课录屏总结.用户操作手册.md](../user-ops/网课录屏总结.用户操作手册.md)。
> 本功能不建数据库表（全部文件落盘 `sessions/<id>/`），「数据库表注解」一节不适用，已删。

## 一句话描述

录下网课窗口的画面和讲解，课后自动生成带时间戳、可回跳视频的章节笔记，并能导出 Markdown。

## 调用链路（关键路径）

```
录制: Recorder.vue → create_session → start_capture_session
        → screen(capture+encode) ∥ audio(capture) ∥ stt(recognizer)   [三路共用 SessionClock]
        → sessions/<id>/{video/,audio.wav,transcript.jsonl,frames/change_*}
录后: Processing.vue → process_frames → process_ocr → align_session → summarize
        → frames.json →(回填ocr_text) → aligned.json → summary草稿json
学习: Study.vue ← get_timeline / get_video_slices / get_ocr_text
      SummaryPanel.vue → regenerate_summary / update_summary_point
导出: Study.vue → export_markdown → sessions/<id>/exports/summary.md
```

## 技术清单与原理注解（大白话版）

#### 1. 三路录制统一时间轴 — `session/mod.rs` SessionClock

- **采用技术**：Rust `Arc<Instant>` 共享墙钟零点。
- **一句话原理**：开录瞬间记一个「秒表零点」，屏幕帧、音频句、转写句的时间全记成「零点后第 N 毫秒」。
- **大白话展开**：三条流水线各自干活，若各记各的时间，事后对不上「这句话对应哪页 PPT」。共用一块秒表，事后按毫秒数一比对就能对齐。
- **大白话案例**：像运动会发令枪——枪响（t0）后，每个赛道计时员都按同一声枪计时，成绩单才能横向排名。
> 📌 批注：音频落盘必须重采样到 16kHz 再写 WAV（设备原生 48k 直接写头会慢放 3 倍、时间轴全错位——Step 4 踩过的坑）。

#### 2. 窗口捕获 + 视频切片 — `screen/capture.rs` / `encode.rs`

- **采用技术**：windows-capture（WGC, Windows Graphics Capture）+ 硬编 mp4 分片（`SLICE_MS` 一片）。
- **一句话原理**：只抓用户选中的那个窗口的画面，连续帧压缩成一段段 mp4 落盘。
- **大白话展开**：WGC 是 Windows 官方抓屏接口，能只抓单个窗口（不怕录到弹窗隐私）。视频按固定时长切片，2 小时课不是一个大文件，而是若干小片段，点播跳转时只加载对应片段。
- **大白话案例**：像把一盒长录像带剪成一节节小段贴上编号，要找第 35 分钟，直接抽对应那节，不用倒带。
> 📌 批注：仅 Windows 可用；窗口最小化时捕获会 stalled（状态里可查），前端有提示。

#### 3. 判页抽帧 — `screen/scene_detect.rs`

- **采用技术**：SAD（像素差）+ 直方图 + pHash（感知哈希）三重判据去重。
- **一句话原理**：录后每 500ms 采一帧，和上一页课件比对「像不像」，不像才算翻页，存为新课件页。
- **大白话展开**：讲课视频大部分帧是重复的（同一页 PPT 讲 5 分钟）。三个判据从不同角度量「两张图像不像」，都说不像才判定翻页，避免老师鼠标晃一下就误报翻页。
- **大白话案例**：像整理连拍照片——连拍 100 张只留姿势真正变了的那几张，其余删掉。
> 📌 批注：产出 `frames.json`（页序列 + 时间戳 + 缩略图路径），是后续 OCR/对齐/总结的锚点文件。

#### 4. 课件 OCR — `ocr/mod.rs`

- **采用技术**：oar-ocr 0.9（PP-OCRv5 mobile ONNX 模型，ort/ONNX Runtime 推理）。
- **一句话原理**：纯本地跑 OCR 模型，把每张课件截图里的文字读出来，回填进 frames.json。
- **大白话展开**：选 PP-OCRv5 是因为它对中文课件效果最好且模型小（det 4.6MB + rec 15.8MB）；oar-ocr 是纯 Rust 推理，不用装 Python/PaddlePaddle。
- **大白话案例**：像请了个住在电脑里的速读员，把每张幻灯片上的字抄成文本，课件图从此可以「被搜索、被总结」。
> 📌 批注：模型首用自动从 ModelScope 下载到 `$OAR_HOME`（国内直连可达）；单帧识别失败降级 null 不阻塞整课（O4 容错）。

#### 5. 音字帧对齐 — `align/mod.rs`

- **采用技术**：双指针排序归并 O(n+m)，**中点规则**。
- **一句话原理**：每页课件有展示时间段，每句讲解有起止时间，句子中点落在哪页的时间段里就归哪页。
- **大白话展开**：翻页往往发生在句子中间，按起点或终点归都会错位；取句子中点归属，保证每句只归一页、不重不漏，且一次扫描就排完。
- **大白话案例**：像按时间段归档快递——包裹按「送达中点时刻」投进对应货架格，每个包裹只进一格。
> 📌 批注：降级路径：无帧 → 5 分钟固定窗分段；无转写 → 段落文字为空不崩（plan 三条降级之二）。

#### 6. 云端总结 map-reduce — `summary/map_reduce.rs` / `cloud_api.rs`

- **采用技术**：reqwest blocking 调 OpenAI 兼容 chat/completions；map（分段总结）→ reduce（汇总大纲）；429/5xx 指数退避重试 2 次。
- **一句话原理**：2 小时课文本太长塞不进一次请求，先逐段出要点，再让模型把各段要点汇总成全书大纲。
- **大白话展开**：像班级读一本厚书——每组读一章写摘要（map），课代表把各组摘要拼成全书梗概（reduce）。API 挂了会自动本地兜底（把 OCR+转写原文截段当草稿，标 `fallback=true`），界面可重试。
- **大白话案例**：分组读书 + 课代表汇总。
> 📌 批注：**隐私红线**——默认只上传文字；附课件图的多模态精修开关默认关、开启要二次确认。API Key 只存 Windows 凭据管理器，不落盘不进日志。请求体不传 `temperature`（Kimi k3 强制 temperature=1，显式传 0.3 会 400——commit 8941326 踩过的坑，缺省用 provider 默认值最兼容）。

#### 7. 帧图/视频加载 — `lib.rs` setup + `asset://`

- **采用技术**：Tauri asset protocol + `asset_protocol_scope().allow_directory(sessions根目录, 递归)`。
- **一句话原理**：前端用 `asset://` URL 直接读本地帧图/视频文件，webview 只被放行 sessions 目录。
- **大白话展开**：若走 IPC 把图片 base64 传给前端，一课几百张帧图会撑爆 webview 内存。asset:// 相当于给前端开了个「只读文件窗口」，且只开到 sessions 目录为止。
- **大白话案例**：像图书馆阅览证——只能在指定阅览室（sessions/）看书，不能进书库其他地方。
> 📌 批注：`app.asset_protocol_scope()` 需要 `use tauri::Manager` 在作用域，否则 E0599（Step 11 踩过）。

#### 8. 运维开关 feature flag — `feature_flags.rs`

- **采用技术**：环境变量 `VTT_COURSE_SUMMARY` > 配置文件 `feature_flags.json` > 默认开，三层覆盖。
- **一句话原理**：前端启动时问后端「网课总结开没开」，关了就连 Tab 都不显示；后端同时拒绝新录制请求。
- **大白话案例**：像商场某个专柜的「暂停营业」牌——门口不摆入口（前端隐藏），收银台也不接单（后端拒绝），双保险。
> 📌 批注：配置缺失/损坏一律按「开」处理，不能因为配置文件坏了把整个应用搞挂。

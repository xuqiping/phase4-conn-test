## AI需求质量检查与前沿趋势

### 一、AI需求质量检查五维度

| 检查维度 | AI检查内容 | 输出格式 |
|---|---|---|
| 一致性校验 | 同一需求在不同章节/不同文档中的描述是否矛盾 | 矛盾点列表+位置 |
| 完整性检查 | 验收标准是否可量化、异常场景是否覆盖、边界条件是否补全 | 缺失项清单 |
| 重复检测 | 跨需求的功能点重叠 | 重复组+建议合并方向 |
| 依赖冲突 | 需求间的时序依赖是否合理，是否存在循环依赖 | 依赖图+冲突标注 |
| 合规预检 | 是否涉及隐私/GDPR/行业监管要求 | 合规风险清单 |

### 二、矛盾识别技术路径

```
矛盾识别流程：
1. 将PRD全文拆分为功能点+约束条件
2. 构建功能点间的逻辑关系图（A依赖B、A互斥C、A包含D...）
3. 用LLM检测：
   - 显式矛盾："支持离线使用" vs "需实时联网验证"
   - 隐式矛盾："响应时间<200ms" vs "加载完整用户画像"（数据量大时冲突）
   - 遗漏条件：有功能描述但无异常处理
4. 输出：矛盾列表 + 每条的修改建议
```

### 三、边界条件补全

AI最实用的质量检查能力之一——**PM写了Happy Path，AI自动补全Unhappy Path**：

| Happy Path（PM写的） | AI补全的边界条件 |
|---|---|
| 用户点击"提交订单" | 网络超时怎么办？库存不足怎么办？用户未登录？并发冲突？ |
| 搜索结果展示列表 | 结果为空？结果>1000条？搜索词含特殊字符？ |
| 优惠券发放 | 券已领完？用户已有同券？过期时间边界？ |

### 五、AI需求分析的局限与人的不可替代性

| AI能做 | AI不能做（PM必须做） |
|---|---|
| 批量提取需求点 | 判断需求背后的商业价值 |
| 语义去重 | 战略取舍与资源博弈 |
| 自动分类标签 | 与利益相关者的沟通与对齐 |
| 辅助评分 | 不确定条件下的决策勇气 |
| 生成PRD初稿 | 对用户体验的直觉判断 |
| 检测矛盾遗漏 | 产品愿景的定义 |

**核心原则**：AI是将PM从"体力活"解放出来的工具，PM的价值在于**判断力**而非**执行力**。

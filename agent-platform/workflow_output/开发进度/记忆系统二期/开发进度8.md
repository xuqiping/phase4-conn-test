## C4 实现记档（对应 plan Chunk 4）

**行为变化**：文件卡片从「标签重叠命中即展示」改为「≥1 分块与 query cosine 距离 ≤ 阈值才展示+注入」。拍板②：完全不召回不展示。

- `SystemSettingService`：新 key `memory.recall.file-card-max-distance`（默认 0.5，clamp 0~2，`getMemoryRecallFileCardMaxDistance()`）。
- `V129__memory_recall_file_card_gate.sql`：seed（ON CONFLICT DO NOTHING，纯 seed 可回滚=删行）。
- `MemoryAssetChunkMapper.searchTopK`：加 `perFileLimit` 参 + `ROW_NUMBER() OVER (PARTITION BY asset_memory_id ORDER BY distance)` 窗口——每文件 ≤2、总 ≤5，防单文件霸榜（plan 坑点④）。
- `MemoryAssetRecallService`：
  - `embedQuery(query,userId)`：一次 embed（QUERY_CAP=1000 截断）供个人卡门+深读+项目卡门三处复用（plan 坑点③）；失败/维度不符返 null。
  - `recallGated(candidates,vec)` 返 `GatedFileRecall(cards,chunks)`：一次 searchTopK 双产出；卡片按最近邻排序（LinkedHashMap 首见序）。
  - `gateProjectCards(cards,vec)`：项目 FILE 卡按 fileId 回查 READY memory → 分块判距（per-file 1、总 ≤ 文件数，只判不取文本）；无 memory 行/不过阈/vec null → 剔除。
  - 旧 `deepReadChunks` 保留签名（空 hits 短路不 embed），内部改走 recallGated。
- `MemoryRecallPipeline`：
  - ③ select 异常降级 + 启发式降级（selected==全集且 size>COARSE_TOP）均置 `selectDegraded` → ⑥.5 跳过文件召回（note「select 降级轮：跳过文件召回」）。
  - ⑥.5 改单次 `collectFileCards → embedQuery → recallGated`；embed 失败 → 零卡片 + note「query embed 失败：零文件卡（宁缺勿噪）」，非 degraded。
  - ⑦ 项目卡构建后过 `gateProjectCards`（fileQueryVec 复用 ⑥.5 的向量，未算过才现算）。
  - `selectEntriesForAssemble` 无标签条目恒拼**维持不动**（收录语义进 prompt 是承诺，plan 明示）。
- **已接受损失（记档）**：弱记忆文件（无 chunk）永不出卡；embed 挂的轮次零文件卡——宁缺勿噪（拍板②）。

**运维埋点（plan 运维清单对应项）**：阈值热调 ✅（system_settings）；降级路径 ✅（embed 失败零卡片）；可回滚 ✅（V129 纯 seed）。门控剔除数 debug 级日志待 C9 验证轮补（当前 step 打点 file-recall/file-deepread count 差值可观测）。

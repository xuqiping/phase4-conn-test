# AI Application & Commercialization Workflow

## Purpose

基于AI应用落地知识体系，为用户提供企业知识库搭建（RAG激活死文档）、办公自动化（Copilot→Autopilot/Computer Use Agent）、行业大模型定制（五步法：选型→PT→SFT→对齐→部署）、AI创业商业化（SaaS/API/私有化/结果付费/出海）等技术方案与商业策略支持。覆盖Cursor 3年ARR $5亿、结果导向付费、国内验证+海外放大等关键洞察。

## Prerequisites

- 用户已明确AI应用落地场景或问题
- 知识库文件 `05_人工智能与机器学习.md` 及子目录文件可访问

## Steps

### Step 1: 识别AI应用落地需求场景

**Goal**: 明确用户的AI应用需求类型、目标用户和商业化阶段
**Completion criterion**: 已确定场景标签、目标用户群体、商业化阶段和资源约束

1. 读取用户消息，提取以下信息：
   - 场景类型：企业知识库搭建 / 办公自动化提效 / 行业大模型定制 / AI创业产品 / 商业化模式设计 / 出海策略
   - 目标用户：企业内部员工（B2E） / 企业客户（B2B） / 个人消费者（B2C） / 开发者（API）
   - 商业化阶段：概念验证（PoC） / MVP开发 / 产品市场匹配（PMF） / 规模化增长 / 成熟运营
   - 资源约束：团队规模（1人/小团队/公司）、预算范围、技术栈（已有系统/全新开发）、数据资产（文档/数据库/日志）
   - 关键痛点：知识分散查不到 / 重复性工作多 / 行业专业度不够 / 获客成本高 / 变现路径不清

2. 对照知识库中的关键洞察初步判断路径：
   - 知识分散、文档沉睡 → 企业知识库（RAG激活，75%企业已部署）
   - 重复性办公任务多 → 办公自动化（Copilot辅助→Autopilot自主执行）
   - 垂直行业专业需求 → 行业大模型定制（五步法，领域专业化）
   - 想创业做AI产品 → AI创业商业化（六大模式+出海策略）
   - 已有产品想加AI → AI功能集成（API接入/自研模型/混合策略）

3. 如有信息缺失，向用户追问不超过2个澄清问题。

### Step 2: 输出AI应用落地方案

**Goal**: 产出针对性的AI应用方案或商业化策略
**Completion criterion**: 输出包含方案设计、实施路径、资源估算、风险与缓解

根据Step 1确定的场景，按以下分支处理：

**分支A — 企业知识库搭建**：
1. 输出知识库架构设计：
   - 数据源接入：文档（PDF/Word/PPT/Excel→解析→分块→向量化）、数据库（SQL查询→自然语言接口）、邮件/聊天记录（归档→检索）、网页（爬虫→清洗→索引）
   - RAG Pipeline：文档预处理（OCR→版面分析→表格提取→图表理解）→ 智能分块（语义分块/递归分块/固定长度+重叠）→ Embedding编码 → 向量存储（Milvus/Weaviate/PG Vector）→ 检索重排序 → LLM生成
   - 对话界面：Web Chat（React/Vue+流式SSE）、企业微信/钉钉/飞书机器人（Webhook接入）、IDE插件（VS Code/Cursor扩展）
2. 给出知识库运营策略：
   - 知识更新机制：增量索引（新文档自动接入）、版本管理（历史版本对比）、过期提醒（知识时效性标记）
   - 权限管理：基于RBAC的文档级权限（谁可以查什么）、敏感信息过滤（PII/商业机密/合规红线）、审计日志（查询记录追溯）
   - 质量监控：答案满意度评分（👍/👎）、未命中分析（Query日志→补充缺失知识）、知识 gaps 报告（高频未回答问题的Top-N）
3. 输出典型部署模式：
   - 纯本地部署（数据不出域）：Ollama/llama.cpp本地推理+本地向量库+内网访问
   - 混合部署（部分上云）：敏感数据本地处理+通用能力调用云端API（OpenAI/Claude/国产大模型）
   - 云端SaaS（快速上线）：阿里云百炼/腾讯云TI平台/百度千帆/火山方舟，预置RAG能力
4. 附效果度量指标：知识检索准确率（Top-5命中率）、答案满意度（用户评分）、查询响应时间（P99<3秒）、知识覆盖率（已索引文档/全部文档比例）。

**分支B — 办公自动化提效**：
1. 输出自动化层级演进：
   - L1 Copilot（副驾驶）：AI辅助人类决策（代码补全/邮件起草/会议摘要），人类审核后执行
   - L2 Agent（智能体）：AI自主执行标准化任务（自动回复邮件/安排日程/生成报表），人类设定规则+异常干预
   - L3 Autopilot（自动驾驶）：AI自主完成复杂多步骤任务（Computer Use Agent直接操作桌面/浏览器/办公软件），人类只设定目标+结果验收
2. 给出典型办公场景方案：
   - 代码开发：Cursor（AI IDE，3年ARR $5亿）/ GitHub Copilot / 通义灵码 / 代码审查Agent（自动PR Review/漏洞检测/风格检查）
   - 文档处理：自动报告生成（数据→分析→可视化→排版）、合同审查（条款提取/风险标记/对比版本）、PPT生成（大纲→内容→设计→动画）
   - 会议与沟通：实时转写（SpeechLLM端到端60分钟单次转写）+ 智能摘要（待办提取/决策点标记/行动项分配）+ 多语言翻译
   - 数据分析：自然语言查询数据库（Text-to-SQL/NL2DSL）、自动数据清洗（缺失值/异常值/重复值智能处理）、自动洞察生成（趋势识别/异常检测/根因分析）
3. 输出Computer Use Agent架构：
   - 感知层：屏幕截图→VLM视觉理解（UI元素识别/状态判断）+ OCR文本提取
   - 决策层：任务分解（将"预订机票"拆分为搜索→选择→填写→支付）+ 动作规划（点击/输入/滚动/快捷键）
   - 执行层：自动化框架（Playwright/Selenium/pyautogui模拟操作）+ 安全沙箱（隔离环境防止误操作）
   - 验证层：执行结果确认（截图对比/状态检查/人工复核阈值）
4. 附安全与合规：操作审计日志（每一步操作记录）、权限边界（只能访问授权系统/数据）、回滚机制（误操作快速恢复）。

**分支C — 行业大模型定制**：
1. 输出五步法实施路径：
   - Step 1 选型：基座模型选择（通用能力 vs 中文优化 vs 代码能力 vs 多模态）、开源vs商用API、参数规模（7B/13B/70B/ MoE）、许可证合规（Apache 2.0/MIT/LLaMA License）
   - Step 2 继续预训练（PT）：领域语料收集（医学文献/法律条文/金融报告/工业手册）、数据清洗（去重/过滤/质量评分）、增量预训练（在基座模型上继续训练，学习领域知识）
   - Step 3 监督微调（SFT）：指令数据构建（领域任务Instruction+Input+Output）、LoRA/QLoRA微调（消费级GPU可完成）、多轮对话数据（User/Assistant交替）、评估指标（领域测试集准确率）
   - Step 4 对齐（Alignment）：RLHF/DPO/KTO人类偏好对齐、安全性对齐（拒绝有害请求/偏见消除/隐私保护）、价值观对齐（符合行业伦理/法规要求）
   - Step 5 部署：模型量化（AWQ/GPTQ/INT8）、推理服务（vLLM/TensorRT-LLM）、A/B测试（新版本灰度发布）、监控告警（幻觉率/延迟/错误率）
2. 给出典型行业案例：
   - 法律：合同审查、案例检索、法条咨询、文书起草（基于法律条文+判例库微调）
   - 医疗：辅助诊断、用药咨询、病历摘要、医学文献问答（基于医学教材+临床指南+PubMed微调，需医疗器械审批合规）
   - 金融：研报分析、风控评估、智能投顾、监管合规检查（基于财报+研报+法规微调，需金融牌照合规）
   - 教育：个性化答疑、作业批改、课程生成、学习路径规划（基于教材+题库+教学大纲微调）
3. 输出合规要点：数据隐私（患者数据/客户数据脱敏）、知识产权（训练数据版权/生成内容版权）、行业监管（医疗NMPA/金融证监会/教育教育部）。

**分支D — AI创业商业化**：
1. 输出六大商业模式：
   - SaaS订阅：按月/年收费，分层定价（免费版/专业版/企业版），典型案例：Jasper（AI写作）、Copy.ai（营销文案）
   - API计费：按调用量收费（tokens/请求数/并发数），分层定价（免费额度+阶梯定价），典型案例：OpenAI API、Anthropic API
   - 私有化部署：一次性授权费+年度维护费，适合金融/政务/大型企业对数据主权要求高，典型案例：智谱AI、百川智能企业版
   - 结果付费（Pay-per-Result）：仅在AI成功完成任务时收费（如简历筛选成功入职、代码生成通过测试、文案带来转化），重新定义AI价值
   - 交易抽成：平台模式，撮合供需+AI赋能，按交易额抽成（如AI设计平台按设计稿交易额抽成）
   - 增值服务：基础功能免费+高级功能付费（Freemium），通过AI降低基础服务成本，靠增值服务盈利
2. 给出出海策略：
   - 路径：国内验证（产品打磨+PMF确认）→ 海外放大（复制成功模式到全球市场），Cursor就是典型"国内团队+全球产品"
   - 市场选择：北美（付费意愿高、竞争激烈）/ 东南亚（增长快、门槛较低）/ 欧洲（GDPR合规要求高、付费稳定）/ 中东（资金充裕、本地化要求高）
   - 本地化：语言（非英语市场不可忽视）、支付（本地支付方式）、合规（GDPR/CCPA/数据主权）、文化（UI/UX习惯/内容偏好）
   - 渠道：Product Hunt发布、Reddit/Discord社区运营、App Store/Google Play优化、KOL合作、API生态（被集成→自然增长）
3. 输出关键成功因素：
   - 产品：AI Native（从0为AI设计，非原有产品+AI）vs AI Enhanced（现有产品+AI功能），Cursor证明AI Native可快速规模化
   - 获客：PLG（产品驱动增长，免费试用→口碑传播）vs SLG（销售驱动增长，企业客户直销），AI产品更适合PLG
   - 留存：AI效果可量化（节省多少时间/提升多少效率）、持续价值交付（模型迭代带来新能力）、社区运营（用户共创提示词/工作流）
   - 竞争：模型能力差距在缩小（开源追近闭源）、差异化在场景理解（行业Know-how）、用户体验（响应速度/交互设计/集成深度）
4. 附创业风险与缓解：
   - 模型依赖风险：多模型备份策略（主模型+备用模型）、开源模型自托管（降低API供应商锁定）
   - 数据飞轮：用户反馈数据回流→模型改进→更好体验→更多用户→更多数据，设计数据收集机制（用户同意+脱敏处理）
   - 成本结构：推理成本占收入比例控制（<30%健康）、缓存策略（重复查询命中缓存）、模型降级（高峰期用轻量模型）

将结果保存到 `output/ai_application.md` 或直接在对话中呈现。

### Step 3: 验证与交付

**Goal**: 确保AI应用方案可落地、商业化路径清晰、与知识库一致
**Completion criterion**: 已通过 checklist 逐项核对

1. 读取 `checklist/ai_application_workflow_checklist.md`。
2. 逐项核对输出是否覆盖要求的知识点。
3. 确认商业化数据（Cursor ARR $5亿等）来源准确。
4. 如有遗漏或偏差，补充修正。
5. 向用户交付最终答案。

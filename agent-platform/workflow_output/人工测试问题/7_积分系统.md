# 支付宝/微信真实支付接入指南（傻瓜式）

## 一、现在是什么状态（一句话）

系统里**模拟支付（mock）已全链跑通**（下单→扫码页→回调→积分到账→记录，全真的流程，只是不用真钱）。支付宝/微信是**「水管坑位留好、真水管没接」**：代码骨架在、配置坑位在，但现在调用就提示「未开通」。

**接入 = 两件事**：
1. **你做的**：办商户号，把密钥给我（本节下面手把手教）。
2. **我做的**：拿到密钥后写渠道实现代码（官方 SDK 下单 + 回调验签，骨架里这两块是空的）+ 测试 + 上线。**每渠道约 1-2 天工作量**——所以不是「给我密钥当天就能收款」。

## 二、先备三样硬性条件（没有这些，商户号办不下来）

| 东西 | 说明 | 多久 |
|---|---|---|
| ① 营业执照 | 企业或**个体户**都行 | 已有则 0 天 |
| ② 域名 + ICP 备案 + HTTPS 证书 | 签约网页支付必填；**备案最慢，最先办** | 备案 1-3 周 |
| ③ 对公银行账户 | 个体户可用法人个人银行卡 | 已有则 0 天 |

> ⚠️ 第 ② 项是整个流程的瓶颈。域名没备案，两家都签不了「网页支付」。今天就去办。

## 三、支付宝：给我 3 个串（全在支付宝开放平台操作）

操作网站：**https://open.alipay.com**（用企业支付宝账号登录）

1. **签约**：开放平台首页 → 「产品中心」→ 找「**电脑网站支付**」→ 点签约 → 按提示填营业执照、法人身份证、对公账户、网站域名 → 等审核（约 1-3 个工作日）。
2. **建应用拿 APPID**：控制台 → 「我的应用」→ 创建「网页&移动应用」→ 创建后应用详情页有一串以 `2021...` 开头的数字 = **APPID**，抄给我。
3. **生成密钥对**：下载官方小工具「**支付宝开放平台开发助手**」（开放平台文档页搜得到）→ 打开点「生成密钥」（RSA2）→ 得到两串：
   - **应用私钥** → 抄给我（这个串只在你我手里，别发给任何第三方）；
   - **应用公钥** → 粘贴到第 2 步那个应用的「接口加签方式」里，保存。
4. **拿支付宝公钥**：上一步保存后，同一页面会出现「**支付宝公钥**」（查看/复制按钮）→ 抄给我。

**你给我 = 3 个串**：`APPID` + `应用私钥` + `支付宝公钥`。

## 四、微信：给我 3 个串（两个网站）

操作网站 A：**https://pay.weixin.qq.com**（微信支付商户平台）
操作网站 B：**https://mp.weixin.qq.com**（微信公众平台）

1. **开商户号**：pay.weixin.qq.com → 「接入微信支付」→ 注册商户号 → 填营业执照/法人身份证/对公账户/经营场景（选公众号或网站）→ 审核通过后得到 **10 位数字商户号**（开户邮件和商户平台首页都有）→ 抄给我。
2. **拿 AppID 并绑定**：mp.weixin.qq.com 注册**服务号**（个体户也可）→ 设置页拿 **AppID**（`wx...` 开头）→ 回到商户平台 → 「产品中心 → AppID 账号管理」→ 把这个 AppID 绑定进去 → AppID 抄给我。
3. **设 APIv3 密钥**：商户平台 → 「账户中心 → API 安全」→ 找「**APIv3 密钥**」→ 点设置，自己编一串 **32 位字母+数字随机串**（比如拿密码生成器摇一个）→ 这串同时抄给我。
4. （写码时我确认后可能要）同页「API 证书」→ 申请并下载证书压缩包给我。

**你给我 = 3 个串**：`商户号` + `AppID` + `APIv3 密钥`（+ 可能的证书文件）。

## 五、清单汇总（照这张表收集；**现在不用发我，直接网页自填**）

| 渠道 | 要填的东西 | 来自哪 |
|---|---|---|
| 支付宝 | `APPID` | 开放平台 → 我的应用 |
| 支付宝 | `应用私钥` | 密钥工具生成 |
| 支付宝 | `支付宝公钥` | 上传应用公钥后页面显示 |
| 微信 | `商户号` | 商户平台开户成功 |
| 微信 | `AppID` | 公众平台服务号 + 商户平台绑定 |
| 微信 | `APIv3 密钥` | 商户平台 API 安全自设 32 位 |
| 部署 | 公网 HTTPS 域名（已备案） | 你的服务器/域名商 |

**怎么填（2026-08-21 起，网页自填已上线）**：admin 登录 → 左侧菜单「**支付渠道**」→ 选对应渠道卡片 → 逐项粘贴 → 「保存配置」（二次确认）。
- 密钥**整体加密存储**，页面上永远只显示尾巴 4 位（如 `****3f2a`）；
- **改一个字段不用重填全部**——留空的字段保持原值；
- 每次保存自动记审计日志（谁改的、什么时候）。
> 🔒 这些是钱袋子钥匙：只在该页面填（或发我本人填），别进群、别截图发第三方、别提交进 git。

## 六、填完后的流程（你不用管，列出来让你心里有数）

1. 你在「支付渠道」页填好并保存（密钥已加密落库；环境变量方式仍保留作兜底）。
2. 我写支付宝/微信两个渠道的下单 + 回调验签实现（mock 通道原样保留作测试用）。
3. 填 `PAYMENT_NOTIFY_URL` = `https://你的域名/api/billing/payment/notify/...`（微信/支付宝服务器回调用，**必须公网 HTTPS**）。
4. 用 **0.01 元真实小额** 跑通「下单→扫码→到账→记录六字段」全链 → 对账页确认无异常。
5. 生产环境关 mock（有 PaymentConfigGuard 兜底：生产开 mock 直接拒启动，不会误用）。
6. 上线 ✅ 用户即可选支付宝/微信扫码充值。

> ⚠️ 注意：在支付渠道页**填好密钥 ≠ 渠道已上线**。SDK 实现（第 2 步）未完成前，用户侧充值仍然只显示模拟支付——这是刻意保护，防止用户点到半成品渠道。

1. **图片价表没有预估价** ✅ —— 不需要单独配：图片预估=**图片单价×张数**自动派生（按实际产出张数结算），价表配置页 IMAGE 行已加说明文案；生成页提交按钮下方实时显示「预估消耗 X 积分」。

   - 提交前：GET /api/media/estimate 按所选参数（模型/时长/分辨率/参考视频/张数）实时估积分+余额，不足红字预警；提交侧余额/组池 < 预估直接拒（此前 V152 已有，本次保留）。

   - 完工多退少补：实耗>预扣补差（组池尽转组长兜底）、<退差、=不动；任务失败/下载失败/落库失败预扣全额自动退（幂等不双退）；存量在途任务（升级前提交）走原全量结算不受影响（hold_applied 列区分）。
   - 账单流水可见「媒体任务预估预扣/预估补扣/预估退差」备注，全程幂等键防重。
3. **账单总览合计卡不随筛选 + 金额 0 疑惑** ✅ —— 用户余额 tab 四张合计卡改为**跟随用户名筛选**（筛选谁合计谁，未筛选=全平台）；卡片旁标注口径「仅统计已支付充值单，管理员发放不计入」——「积分多但充值金额 0」正是该用户积分来自管理员发放（发放≠充值，本就不计入充值合计）。

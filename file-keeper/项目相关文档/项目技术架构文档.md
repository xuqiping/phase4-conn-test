# File Keeper 项目技术架构文档

## 1. 项目概述

File Keeper 是一个基于 **Tauri 2 + Vue 3 + TypeScript + Rust** 构建的 Windows 桌面效率工具。当前项目已经不是单一的文件收藏工具，而是围绕以下三条主线形成的本地工作台：

1. **文件管理**：高频文件与文件夹收藏、组织、搜索、排序、批量操作。
2. **运行中应用管理**：可见窗口枚举、分类、筛选、排序、窗口级关闭请求、激活窗口。
3. **剪贴板增强**：剪贴板历史、快速面板、截图、OCR、链接预览、安全事件、缓存管理。

同时，项目还提供托盘、全局快捷键、主题、语言切换等桌面集成能力。

---

## 2. 总体架构

File Keeper 采用典型的 Tauri 桌面应用分层架构：

```text
┌────────────────────────────────────────────┐
│ Vue 3 + TypeScript 前端                    │
│ - App.vue / ScreenshotOverlayHost          │
│ - Pinia stores                             │
│ - 功能组件 / composables / utils           │
│ - Tauri invoke API 封装                    │
└──────────────────────┬─────────────────────┘
                       │ invoke / plugin API
┌──────────────────────▼─────────────────────┐
│ Tauri Runtime                               │
│ - 窗口管理                                  │
│ - 系统托盘                                  │
│ - Global Shortcut / Dialog / FS / Store     │
└──────────────────────┬─────────────────────┘
                       │ Rust commands
┌──────────────────────▼─────────────────────┐
│ Rust 后端                                    │
│ - 文件命令                                   │
│ - 进程管理命令                               │
│ - 剪贴板服务                                 │
│ - 截图 / OCR / 链接预览 / 安全检测           │
└───────────────┬───────────────────┬────────┘
                │                   │
      ┌─────────▼─────────┐ ┌──────▼────────────┐
      │ 本地持久化         │ │ Windows 平台能力   │
      │ - Tauri Store      │ │ - Win32 窗口/剪贴板│
      │ - localStorage     │ │ - GDI 截图         │
      │ - SQLite           │ │ - 系统图标         │
      └───────────────────┘ └───────────────────┘
```

整体职责分工：

- **前端**：负责界面、交互、筛选、状态与用户反馈。
- **Tauri Runtime**：负责桥接前后端、管理窗口/托盘/插件能力。
- **Rust 后端**：负责文件系统、窗口进程、剪贴板、截图、OCR 等本地能力。
- **本地存储层**：分别存储收藏数据、界面偏好、进程设置和剪贴板历史。

## 3. 前端架构

## 3.1 入口与根组件

### `src/main.ts`
- 创建 Vue 应用。
- 创建 Pinia。
- 注册 Pinia 持久化插件。
- 根据 URL 参数决定挂载主应用还是截图遮罩宿主。

### `src/App.vue`
- 作为主窗口核心容器。
- 管理三大主页面：Files / Processes / Clipboard。
- 管理顶部标题栏、窗口按钮、全局快捷键、托盘配合行为。
- 处理文件拖拽导入、截图事件、主窗口显示/隐藏等桌面行为。

### `src/components/ScreenshotOverlayHost.vue`
- 作为截图遮罩窗口的前端宿主。
- 单独承载截图框选 UI。


## 3.3 运行中应用管理前端模块

### 主要职责
- 刷新并展示当前可见桌面应用。
- 类别筛选、列排序、列显隐、列顺序调整。
- 单选/多选/全选/反选/批量发起窗口关闭请求。
- 激活窗口、复制进程信息、关闭确认。

### 关键文件
- `src/stores/processStore.ts`：进程列表、筛选、排序、选择、关闭。
- `src/stores/processSettingsStore.ts`：列配置、自动刷新、白名单、关闭确认模式。
- `src/components/ProcessManagement.vue`：进程页容器。
- `src/components/ProcessToolbar.vue`：刷新、自动刷新、批量操作、列设置入口。
- `src/components/ProcessFilter.vue`：分类筛选。
- `src/components/ProcessList.vue`：表格、排序、上下文菜单。
- `src/components/ProcessRow.vue`：单行渲染。
- `src/components/ColumnSettings.vue`：列配置与拖拽排序。
- `src/components/ConfirmDialog.vue`：关闭确认对话框。
- `src/components/ToastContainer.vue`：操作结果反馈。

### 数据流

```text
进入进程页 / 手动刷新
  ↓
processStore.refresh()
  ↓
api/process.ts
  ↓
invoke('get_running_processes')
  ↓
Rust Windows process monitor
  ↓
ProcessInfo[]
  ↓
filteredProcesses 渲染到 ProcessList
```

## 4. 后端架构

## 4.1 Tauri 命令层

后端命令按领域拆分：

- `commands/files.rs`：文件打开、路径校验、资源管理器定位。
- `commands/icons.rs`：真实文件图标提取。
- `commands/processes.rs`：文件相关进程查找与按 PID 关闭。
- `commands/process_management.rs`：运行中应用枚举、窗口关闭请求、激活。
- `commands/clipboard.rs`：剪贴板历史、复制/粘贴、设置、存储占用、索引重建。
- `commands/screenshot.rs`：区域截图与 OCR 状态查询。

`src-tauri/src/main.rs` 负责：
- 注册插件。
- 初始化 `ClipboardService`。
- 初始化托盘。
- 注册所有命令。

---

## 4.2 剪贴板服务层

剪贴板是当前后端最完整的服务模块，位于 `src-tauri/src/clipboard/`。

### 子模块职责
- `mod.rs`：`ClipboardService` 主服务，负责采集、入库、复制、粘贴、OCR 触发与设置读取。
- `storage.rs`：SQLite 结构、历史记录 CRUD、搜索索引、设置存储、存储占用统计。
- `types.rs`：剪贴板领域数据结构。
- `cache.rs`：缓存大小控制、扩展名策略、文件保存模式。
- `search.rs`：搜索文本归一化、URL/颜色识别。
- `security.rs`：敏感内容识别与安全事件逻辑。
- `link_preview.rs`：链接标题/描述抓取。
- `ocr.rs`：Windows 系统 OCR。
- `ocr_provider.rs`：本地 sidecar 与系统 OCR 选择逻辑。

### 核心特点
- 使用 SQLite 保存剪贴板历史和剪贴板设置。
- 使用 `search_text` 维护统一搜索索引。
- 图片记录可保存 OCR 文本和备注。
- 链接、颜色、安全事件都作为独立剪贴板类型进入同一历史体系。

---

## 4.3 Windows 平台能力层

### 关键文件
- `platform/windows/clipboard.rs`：读取/写入文本、文件、图片剪贴板。
- `platform/windows/foreground.rs`：记住前台窗口、恢复窗口、自动粘贴。
- `platform/windows/process_monitor.rs`：枚举窗口、收集进程信息、关闭窗口、激活窗口。
- `platform/windows/process_mappings.rs`：进程名到应用类别的映射。
- `platform/windows/screenshot.rs`：GDI 截图。
- `platform/windows_file_matcher.rs`：按文件名/路径匹配关联窗口。

### 平台边界
- 文件、进程、截图、剪贴板采集等核心能力目前高度依赖 Windows API。
- 项目虽然保留了部分跨平台降级实现，但完整桌面能力当前以 Windows 为主。

## 5. 数据与持久化架构

## 5.1 Tauri Store
用于持久化前端业务状态，主要包括：
- 文件收藏列表
- 分组
- 主设置
- 最近打开记录

相关文件：
- `src/plugins/persistPlugin.ts`
- `src/api/persist.ts`

## 5.2 localStorage
当前仍有部分轻量配置使用 localStorage：
- `process-settings`：进程列配置、自动刷新、确认模式、白名单。
- `app-locale`：当前语言。

## 5.3 SQLite
剪贴板模块使用独立 SQLite 数据库保存：
- 剪贴板历史记录
- 搜索索引字段
- OCR 文本、备注、链接预览字段
- 剪贴板设置

## 5.4 缓存目录
剪贴板图片和文件的备份/缓存会写入应用数据目录下的缓存路径，供历史记录回放与再次复制使用。

## 6. 关键运行流程

## 6.1 文件打开流程

```text
用户点击文件
  ↓
fileStore.updateOpenStats()
  ↓
api/files.ts -> open_file
  ↓
Rust 文件命令
  ↓
系统默认程序打开目标
```

## 6.2 运行中应用刷新与关闭流程

```text
用户进入进程页 / 点击刷新
  ↓
get_running_processes
  ↓
EnumWindows + sysinfo
  ↓
前端展示列表
  ↓
用户单个/批量关闭
  ↓
close_app_process / close_app_processes
  ↓
PostMessageW(WM_CLOSE)
  ↓
由目标应用自行决定是退出、隐藏窗口还是最小化到托盘
```

说明：
- 运行中应用管理中的关闭是窗口级关闭请求，不等同于强制终止进程。
- 如果目标应用拦截关闭事件或实现托盘驻留，窗口可能消失，但对应进程仍继续后台运行。

## 6.3 剪贴板监听流程

```text
start_clipboard_monitor
  ↓
Windows 剪贴板轮询
  ↓
识别文本 / 文件 / 图片
  ↓
ClipboardService 入库
  ↓
触发 clipboard://changed
  ↓
前端刷新历史列表
```

## 6.4 截图 + OCR 流程

```text
截图快捷键
  ↓
打开 Screenshot Overlay
  ↓
用户框选区域
  ↓
capture_screenshot_region
  ↓
保存为图片剪贴板记录
  ↓
异步 OCR
  ↓
回写 ocr_text / note / search_text
  ↓
再次触发 clipboard://changed
```

## 8. 当前架构特点

### 8.1 优点
- 文件管理、应用整理、剪贴板增强三条能力链已经形成组合闭环。
- 剪贴板模块具备独立数据库、搜索索引、OCR、缓存和设置体系，扩展性较强。
- Tauri + Rust 让 Windows 本地能力可以直接下沉到后端实现。
- 全局快捷键、托盘、截图遮罩等桌面集成功能比较完整。

### 8.2 当前结构特征
- `App.vue` 仍承担较多主窗口职责，是前端最大的聚合点。
- 剪贴板模块已经成为后端最重的领域模块。
- 项目存在 Tauri Store、localStorage、SQLite 三套并行持久化方式。
- 国际化已覆盖较多新模块，但仍存在部分硬编码文案与语言状态未完全统一的问题。
- 链接预览、安全检测等能力已进入后端模块体系，但前端接入深度仍可继续增强。

---

## 9. 结论

当前 File Keeper 的技术架构已经从“文件收藏工具”演进为“文件管理 + 应用整理 + 剪贴板增强”的本地桌面工作台。前端由 Vue/Pinia 负责体验与状态组织，后端由 Tauri/Rust 负责 Windows 能力封装，剪贴板、截图和 OCR 进一步扩大了项目的功能边界与技术复杂度。

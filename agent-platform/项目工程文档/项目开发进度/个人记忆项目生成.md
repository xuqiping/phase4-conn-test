## 目标

引入项目概念:总记忆(global)+ 单独项目记忆;对话可选 scope;**一条记忆可同时属多个 scope**(global + 多项目,多对多可见性);新事实落当前会话 project;用户可手动改记忆 scope 归属。老数据/老会话向后兼容(= 今天行为)。

## 锁定设计

1. **Project = 全新实体**,与 Agent 解耦。
2. **归属 = 私有 + 可共享**(`project_members`)。鉴权走 service(owner/member/admin),不用 @RequirePermission。
3. **Scope = 多对多可见性,非分区**。`user_memories.is_global` + 关联表 `user_memory_projects`。唯一索引 V29 `(user_id,memory_key) WHERE conflict_id IS NULL` **不动**(冲突按 user+key 在可见集判,与 scope 正交)。
4. **读/写分离**:
   - 读(注入)= 扁平对称开关集(`mem_include_global` 勾 + `mem_read_project_ids` 每项各勾)。三组合全支持:关总记忆只读项目 / 关某项目读其他 / 同开 global+多项目。
   - 写(新事实落点)= 单独 `session.project_id`(null=global)。
5. **新事实**:`is_global=(project_id==null)`;project 写目标→挂 `user_memory_projects`。

## 🐛 IT 抓出的 V33 生产回归(已修,mock 单测全漏)

> 共同点:都在 `<script>` / BIGINT[] 这类 H2+mock 跑不出的真实 PG 行为上;`mvn test`(mock mapper)317/317 照过,只有 it profile 真 PG + 全 context 起来才暴露。

1. **`UserMemoryMapper` 向量查询 `<=>` 未 XML 转义** — V33 把 SCOPE_FILTER(含 `<if>`/`<foreach>`)内联进 `findNearestBlock`/`findTopKByVector`,强制进 `<script>` XML 模式;halfvec 余弦算子 `embedding <=> #{halfvec}` 的裸 `<` 在 XML 文本非法 → `SAXParseException` → **userMemoryMapper bean 创建失败 → 整个 ApplicationContext 启动崩(生产起不来)**。修:4 处 `<=>` → `&lt;=>`(MyBatis 解析后还原)。详见记忆 `reference_mybatis_script_halfvec_escape`。
2. **`persistMemoryScope` BIGINT[] LambdaUpdateWrapper 漏 typeHandler** — V33 消息级写 scope 用 `LambdaUpdateWrapper.set(ChatSession::getMemReadProjectIds, list)`,而 LambdaUpdateWrapper.set **不读** 实体 `@TableField(typeHandler=LongArrayTypeHandler.class)`,裸 `List` 进 PG cast `bigint[]` 失败 → `DataIntegrityViolation` → 被 controller catch 吞 → **streaming 静默走 fallback sendMessage,scope 不生效**。修:改 3 参 `set(col, val, "typeHandler=com.superprogrammer.common.typehandler.LongArrayTypeHandler")`(projectId/memIncludeGlobal 标准类型不动)。

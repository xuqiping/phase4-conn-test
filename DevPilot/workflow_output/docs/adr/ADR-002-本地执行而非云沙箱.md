# ADR-002 · 任务本地执行而非云端沙箱

> 状态：已决定 ｜ 日期：2026-08-13 ｜ 决策人：用户确认 + AI 建议

## 背景

Codex 的标杆形态是云端沙箱（每任务一个隔离容器）。DevPilot 需在「云端沙箱」与「本地执行」间定调。用户 2026-08-13 决策：做桌面客户端、本地执行、商业模式为 Token 转售。

## 备选方案

| 方案 | 优势 | 劣势 |
|---|---|---|
| **本地执行**（Codex CLI 路线） | 云端零算力成本（与 Token 转售模式咬合，加价率即毛利）；用户代码不出本机（隐私卖点）；零环境等待（直接用用户已装环境） | Windows 沙箱方案不成熟；用户机器环境差异大；关机任务即停 |
| 云端沙箱（Codex 云端路线） | 环境统一可控、隔离最强、关机续跑 | 算力成本倒挂风险；代码出本机的合规与信任成本；免费档烧钱 |

## 决定

**本地执行为主**；云端沙箱留作远期可选项（PRD 边界已明示不做）。安全用三层补偿：目录白名单 + 命令审批两档 + 系统级加固（macOS Seatbelt / Windows Job Object）。

## 理由

1. 商业模式决定架构：卖 Token 意味着我们的成本只是 API 转发；若背容器算力，毛利结构被摧毁。
2. 目标用户（一人公司）机器就是开发机，本地执行反而零配置。
3. 断点续跑（FR-007/048）+ 存档点机制覆盖了「关机断档」的主要痛点。

## 后果与代价

- Windows 沙箱为已承认的弱项：MVP 务实档（白名单+审批），系统级加固列 Phase 3 高危任务。
- 环境差异转化为产品义务：自动环境检测 + 一键安装向导（FR-005）成为 P0 而非可选。
- 「关机后云端继续跑」能力放弃，移动端监督面只能监督本机在线时的任务（二期需在文案上管理预期）。

## 2026-08-17 复测撞出两新问题（已修复，commit 34d67c0a）

4. **SSE 120s 超时掐长生成 + 超时误入同步重答**
   `SseEmitter(120_000L)`：6000 字文档生成 >2min 必 `AsyncRequestTimeoutException`（实证 session 267：00:07:47 起 121s 处掐断，DONE 丢失、ASSISTANT 不落库）；且超时后 `emitter.send` 抛异常落入 catch 的 `sendMessage` 同步重答 = 双倍计费仍注定失败。修复：超时 600s（ChatController 两处 + KnowledgeAskController）+ `onTimeout` 标记阻断重答。
5. **净化器 carry 尾段永不 flush：每条流式回复末 ≤40 字符静默丢失**
   `StreamMasker` 默认开启（mask/leak 均默认 true），每次下发扣留尾 40 字符防跨块漏检，靠「非 CHUNK 事件」触发 flush——但 chat 流的 DONE 由服务层在网关流之后追加，该分支永不执行。后果：所有流式回复末 40 字符丢失 + 问题 3 的 max_tokens 截断标记 chunk（26 字符 < carry）被整体吞掉（实证 session 269：usage 8192 + WARN 已触发但标记不可见）。修复：LlmGateway 流终结统一补发扣留尾段（+回归测试 `chatStream_sanitizerCarry_flushedAtStreamTerminal`）。

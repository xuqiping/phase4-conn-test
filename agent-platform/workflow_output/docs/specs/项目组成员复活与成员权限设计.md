# 规格 · 项目组：成员移除后再邀请 409 修复 + 成员级权限（角色/功能开关/可见性覆盖）

> Phase 1 修复规格。实现必须与本文一致；来源为 2026-08-21 人工测试问题 **17x 未解决 #1/#2**。
> 用户已拍板（2026-08-21）：成员级权限覆盖三个维度——**成员可用功能开关**、**模块产出可见性按成员覆盖**、**成员角色**。
> 关联：[项目组与积分划拨设计](项目组与积分划拨设计.md)｜[项目组与积分划拨 Feature Map](../feature-map/项目组与积分划拨.feature-map.md)。

## 1. 目标

1. **修 409**：用户被组长移除后，再次被邀请并接受时不再报 `409 uk_pgm_group_user`；公共池审批通过路径同理修复。
2. **成员角色**：组内三级角色 组长（OWNER）/ 管理（MANAGER）/ 普通成员（MEMBER），管理可协助日常运营（邀请、审批、限额、移除普通成员、看全部产出），但不碰钱和组级设置。
3. **成员功能开关**：组长/管理可按成员禁用某类模型消耗（CHAT/EMBED/RERANK/IMAGE/VIDEO），被禁即拒（任务不创建/调用 4xx）。
4. **成员级可见性覆盖**：组长/管理可对单个成员的某个模块单独收紧或放开产出可见性，优先级高于组级设置。

## 3. 修复设计：17x#1（409）

### 3.1 方案拍板：复活（revive）而非部分唯一索引

两个候选：
- A. 唯一索引改部分索引（`WHERE deleted=0`，V138 的 `uk_pgi_pending` 有先例）——历史会留下多行同人同组，流水 JOIN、used 审计变复杂。
- B. **复活软删行**（拍板）——`insertMemberRow` 改「先尝试复活、再插入」两段式，一人一组永远一行，历史连续。

### 3.2 复活逻辑（`ProjectGroupService.insertMemberRow` 重写）

```
单事务内：
1. 条件 UPDATE project_group_members
     SET deleted=0, quota_limit_points=#{quota}, used_points=0,
         role='MEMBER', allowed_kinds=NULL, member_visibility_overrides=NULL,  -- 见 §4 新列，复活即回到默认
         updated_by=#{operator}, updated_at=now()
     WHERE group_id=? AND user_id=? AND deleted=1
2. 命中 1 行 → 复活完成，记组流水 ADMIN_ADJUST（delta=0, remark='成员回归，已用清零'）
3. 命中 0 行 → 走现行探针 + INSERT（探针命中活行 → 409「该用户已是组成员」）
```

- **used_points 清零**：回归成员 quota 周期重新起算；历史消耗在组流水/usage_logs 仍可查（语义拍板：限额是「当前周期」概念，与 `resetUsed` 一致）。
- **复活重置权限三列**：上次在组的角色/开关/覆盖不继承，防「移除前被禁的人回归后仍被禁」或反过来的意外。
- `ProjectGroupPoolService.decide` 走同一 `insertMemberRow`，自动受益，无需另改。
- 并发安全：两个线程同时接受两张邀请 → 一个复活 1 行、另一个复活 0 行→探针见活行→409，正确。
- `GlobalExceptionHandler` 友好文案补 case：`uk_pgm_group_user` → 「该用户已在项目组中，请勿重复添加」（兜底，正常路径已撞不到）。

## 4. 数据模型（Flyway `V140__project_group_member_perms.sql`；若上游占用则顺延）

```sql
ALTER TABLE project_group_members
  ADD COLUMN role VARCHAR(16) NOT NULL DEFAULT 'MEMBER',
  ADD COLUMN allowed_kinds JSONB NULL,               -- NULL=全部允许；否则为 ['CHAT','IMAGE',...] 子集
  ADD COLUMN member_visibility_overrides JSONB NULL;  -- 成员级可见性覆盖 {"VIDEO":"OWN","IMAGE":"ALL"}

ALTER TABLE project_group_members
  ADD CONSTRAINT ck_pgm_role CHECK (role IN ('OWNER','MANAGER','MEMBER'));

-- 回填：组长行 role='OWNER'
UPDATE project_group_members m SET role='OWNER'
  FROM project_groups g WHERE m.group_id=g.id AND m.user_id=g.owner_user_id AND m.deleted=0;

-- 每组唯一组长（活行范围内）
CREATE UNIQUE INDEX uk_pgm_owner ON project_group_members (group_id) WHERE role='OWNER' AND deleted=0;
```

约束说明：`allowed_kinds` / `member_visibility_overrides` 为 jsonb 稀疏列，沿用 `JsonbStringTypeHandler`（`ProjectGroupEntity.java:43` 先例）；非法值不入库（service 层白名单校验），DB 不加 CHECK（jsonb 结构校验代价大，与组级 overrides 同策略）。

## 5. 角色权限矩阵

| 能力 | OWNER | MANAGER | MEMBER |
|---|---|---|---|
| 消耗组池（未被禁模块） | ✅ | ✅ | ✅ |
| 查看产出 | 全部 | 全部（视同组长绕过可见性） | 按可见性规则 |
| 查看组池流水 | ✅ | ✅（只读） | ❌ |
| 邀请/取消邀请 | ✅ | ✅ | ❌ |
| 入组审批 | ✅ | ✅ | ❌ |
| 调限额/重置已用（MEMBER 行） | ✅ | ✅ | ❌ |
| 移除成员（MEMBER 行） | ✅ | ✅ | ❌ |
| 设成员功能开关/可见性覆盖（MEMBER 行） | ✅ | ✅ | ❌ |
| 任免 MANAGER | ✅ | ❌ | ❌ |
| 划拨/回收组池 | ✅ | ❌ | ❌ |
| 组级可见性设置、公共池发布/撤出、改组信息、解散组 | ✅ | ❌ | ❌ |
| 移除/改 OWNER 行 | ❌（组长不可自移除；转让本期不建） | ❌ | ❌ |

实现要点：
- `ProjectGroupService.requireOwner` 保留给钱与组级设置；新 `requireRole(groupId, userId, OWNER|MANAGER...)` 给运营类端点；MEMBER 行判定统一走 `memberMapper.selectByGroupUser`（活行）。
- MANAGER 不能对 MANAGER/OWNER 行操作：目标行 role 校验在 service 层硬编码（不依赖前端隐藏）。
- 任免 MANAGER：`PUT /{id}/members/{uid}/role {role: MANAGER|MEMBER}`，仅 OWNER；不得改 OWNER 行（防多 OWNER，`uk_pgm_owner` 兜底）。
- 组长建组 INSERT 的成员行 role 直接 'OWNER'（改 `createGroup` 处 insert）。

## 6. 成员功能开关（allowed_kinds）

- 语义：`NULL` = 不限制；数组 = 允许清单（白名单）。禁全部 = 空数组 `[]`（合法，成员仍在组但不可消耗）。
- 校验点（两处硬卡，缺一不可）：
  1. **chat/embed/rerank 组计费分支**：`chargeGroup` 前在 `LlmBillingService` 组分支校验成员 allowed_kinds 含当前 kind，不含 → `GROUP_KIND_FORBIDDEN`（400，文案「组长已限制你在本组使用该类模型」）。
  2. **媒体提交预检**：`MediaGenTaskService` 组预检（现有三重预检处）加同类校验，任务不创建。
- `chargeGroup` 内部不加第二遍（已在上游卡死；保留 service 校验日志即可）——避免热路径多一次行读？**拍板：加**。`chargeGroup` 同事务读成员行（行锁本就持有），校验零额外 IO，防未来新入口绕过。
- 限额已用的 quota 语义不变，与开关正交。

## 7. 成员级可见性覆盖（member_visibility_overrides）

- 判定优先级（`ProjectGroupVisibilityService.effectiveVisibilityForMember` 新方法）：
  ```
  本人/admin/OWNER → 恒可见（不变）
  MANAGER          → 恒可见（新，视同组长）
  其余成员         → 目标行成员的 member_visibility_overrides[kind]
                     ?? 组级 module_visibility_overrides[kind]
                     ?? 组级 member_output_visibility
  ```
  即「成员覆盖 > 组模块覆盖 > 组默认」。注意覆盖是**针对「看谁的产出」的视角**：成员 A 看成员 B 的产出时，用的是 **B（产出归属人）行的覆盖**——语义与组级一致（可见性是产出的属性，不是观察者的属性）。
- 非法模块 key/非法值 → 400；空 map → 置 NULL 回落组级。
- 文件闸门 `canAccessGroupFile` 走同一新方法，保持行列表与文件取读一致。

## 8. API 变更

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| PUT | `/api/project-groups/{id}/members/{uid}/role` | 登录+组内 OWNER | 任免 MANAGER/MEMBER；禁改 OWNER 行 |
| PUT | `/api/project-groups/{id}/members/{uid}/kinds` | 登录+OWNER/MANAGER | body `{allowedKinds: ["CHAT","IMAGE"] | null}`；目标仅 MEMBER 行 |
| PUT | `/api/project-groups/{id}/members/{uid}/visibility-overrides` | 登录+OWNER/MANAGER | body `{overrides: {"VIDEO":"OWN"} | null}`；目标仅 MEMBER 行 |
| GET | `/api/project-groups/{id}/members`（现有响应扩展） | — | 成员行加 `role`/`allowedKinds`/`memberVisibilityOverrides` 三字段 |
| 现有运营端点 | 邀请/审批/限额/重置/移除 | — | 权限从 requireOwner 放宽为 requireRole(OWNER, MANAGER)，目标行 role 校验按 §5 矩阵 |

错误码：`GROUP_KIND_FORBIDDEN`（400）、`GROUP_ROLE_FORBIDDEN`（403，越权操作角色）、`GROUP_OWNER_IMMUTABLE`（400，试图动 OWNER 行）。

## 9. 前端（`ProjectGroupsView.vue`）

- **成员 tab**：表格加「角色」列（OWNER 显标签不可改；其余行 OWNER 视角下拉任免 MANAGER/MEMBER）；操作列对 OWNER/MANAGER 增加「功能开关」「可见性」两按钮 → 弹窗：
  - 功能开关：5 个模块 checkbox（CHAT/EMBED/RERANK/IMAGE/VIDEO）+「不限制」开关（开=null），保存调 `/kinds`。
  - 可见性：5 模块逐一行内三态（跟随组默认/仅自己/全员），保存构建稀疏 map 调 `/visibility-overrides`。
- **tab 可见性**：MANAGER 登录看到 成员/组池流水（只读）/入组审批 tab；看不到 设置 tab、划拨/回收按钮、任免 MANAGER 下拉。当前用户角色随 overview 接口下发。
- **成员被禁提示**：消耗被拒时后端文案直出，前端 toast；成员行对自己显示「本组可用模块」标签（从 mine/overview 带出自己的 allowedKinds）。

## 10. 安全策略

1. 双层防线不变：`@RequirePermission` + service 层角色校验；MANAGER 能力边界在 service 硬编码，前端隐藏仅是体验。
2. `uk_pgm_owner` 部分唯一索引防并发任免出多 OWNER。
3. 任免/开关/覆盖变更全部 `@AuditLog`（module=project-group）。
4. 复活路径条件 UPDATE + 事务，防并发双接受产生重复成员。
5. jsonb 白名单校验（kind 集合、OWN/ALL 值域），非法输入 400，不依赖 DB CHECK。

## 术语表

| 术语 | 大白话 | 例子 |
|---|---|---|
| **软删（@TableLogic）** | 删除不真删行，只把 `deleted` 标 1，查询自动过滤 | 移除成员后行还在库里，审计能查 |
| **复活（revive）** | 把软删行标回 0 重新启用，而不是插新行 | 被移除的成员回归，老行清零后继续用 |
| **部分唯一索引** | 只对满足条件的行做唯一约束 | `WHERE role='OWNER'` 保证每组只有一个活组长 |
| **稀疏覆盖** | 只存「和默认不一样」的项，没存的就是跟随默认 | 只给 VIDEO 设 OWN，其余模块跟组默认走 |
| **白名单校验** | 接口只接受列得出的合法值，其余直接拒 | allowed_kinds 只认 5 种模块名 |

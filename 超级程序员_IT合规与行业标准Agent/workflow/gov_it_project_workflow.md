# Government IT Project Workflow

## Purpose

基于政企信息化项目落地知识框架，提供政企IT项目全流程的标准化执行路径，覆盖招投标、需求分析、方案设计、实施交付、验收运维五大核心阶段。

## Prerequisites

- 已明确项目属性（政务/国企/央企/事业单位）
- 已确定项目资金来源（财政拨款/自筹/PPP）

## Steps

### Step 1: 招投标阶段合规执行

**Goal**: 依据政府采购法与招投标法完成合规的招投标流程，确保资质审查与技术方案国标对齐
**Completion criterion**: 招投标文件全部合规发布，投标人资质审查通过率100%，技术规范书引用至少3项国标

依据政企项目招投标要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 政企信息化项目落地]：
1. 招标准备：
   - 明确采购方式：公开招标/邀请招标/竞争性谈判/单一来源（依据《政府采购法》）
   - 编制《招标文件》，包含：技术规范书/商务条款/评标标准/合同模板
   - 设置资格门槛：等保测评资质/密评资质/信创产品认证/CMMI等级/ISO 27001
2. 技术规范书编制：
   - 功能需求：用例描述+优先级（必须/应该/可选）
   - 非功能需求：性能指标/安全等级/兼容性/可扩展性
   - 引用国标：GB/T 8566/GB/T 8567/GB/T 25000/等保2.0/信创标准
3. 评标标准设计：
   - 技术分权重≥60%（避免低价恶性竞争）
   - 评分维度：技术方案先进性/项目实施能力/售后服务/价格合理性
4. 投标评审：
   - 资格性审查：营业执照/资质证书/业绩证明/财务报告
   - 符合性审查：技术参数响应/商务条款响应/交货期响应
   - 综合评分：技术分+商务分，最高分中标
输出：《招标文件》+ 《评标报告》+ 《中标通知书》

### Step 2: 需求分析阶段深度落地

**Goal**: 完成政企项目的深度需求分析，建立需求基线，确保需求可追溯、可验证
**Completion criterion**: 《需求规格说明书》通过甲方评审签字，需求追溯矩阵覆盖率100%，关键需求有原型确认

依据政企项目需求分析方法论 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 需求分析]：
1. 干系人识别：
   - 业务方（甲方业务部门负责人）
   - 技术方（甲方信息中心/科技部门）
   - 监管方（等保测评机构/密码测评机构/审计部门）
   - 用户方（最终使用人员）
2. 需求获取方法：
   - 访谈：结构化访谈提纲，覆盖业务痛点/现有系统问题/期望改进
   - 调研问卷：面向最终用户，收集使用场景与优先级
   - 现场观察：实地走访业务现场，记录真实操作流程
   - 文档分析：研读现有系统文档/业务流程图/数据报表
3. 需求分类与优先级：
   - 业务需求：提升效率/降低成本/合规达标/数据治理
   - 功能需求：系统必须提供的具体功能
   - 非功能需求：性能（并发/延迟/吞吐量）/安全（等保级别/密评）/可靠性（可用性/RTO/RPO）
   - 优先级：MoSCoW法则（Must have/Should have/Could have/Won't have）
4. 需求验证：
   - 原型确认：高保真原型（Figma/Axure）给业务方试用并签字
   - 需求评审会议：甲方业务+技术+乙方项目组三方参与
   - 需求基线冻结：评审通过后冻结，后续变更走《需求变更控制流程》
输出：《需求规格说明书》+ 《需求追溯矩阵》+ 《需求评审会议纪要》+ 《原型确认单》

### Step 3: 方案设计阶段标准化

**Goal**: 输出符合国家标准的系统设计方案，架构设计兼顾先进性、可落地性、合规性
**Completion criterion**: 《系统设计方案》通过专家评审，等保/密评/信创要求已融入设计，PoC验证计划已制定

依据政企项目方案设计要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 方案设计]：
1. 总体架构设计：
   - 分层架构：接入层/应用层/服务层/数据层/基础设施层
   - 部署架构：私有云/公有云/混合云/信创云选型
   - 网络架构：VPC划分/安全域隔离/边界防护/专线互联
2. 安全设计专篇（等保/密评对齐）：
   - 等保2.0"一个中心三重防护"架构设计
   - 密码应用设计：SM2/SM3/SM4国密算法应用，密钥管理方案
   - 数据安全：分类分级/加密存储/脱敏展示/审计追溯
3. 信创适配设计：
   - 信创产品选型：芯片/操作系统/数据库/中间件/办公软件
   - 兼容性设计：信创环境与非信创环境的数据交换/接口兼容
   - 迁移策略：平滑迁移/双轨并行/逐步切换
4. 技术选型说明：
   - 每项关键技术给出至少2个候选方案+选型理由（性能/成本/生态/维护性）
   - 引用行业案例（同规模/同行业/同类型项目）
5. PoC验证计划：
   - 制定《概念验证计划》，明确验证目标/范围/环境/通过标准
   - 验证项：核心算法性能/高并发稳定性/信创兼容性/安全渗透
输出：《系统设计方案》+ 《安全设计专篇》+ 《信创适配方案》+ 《PoC验证计划》

### Step 4: 实施交付阶段管控

**Goal**: 建立项目全生命周期管控机制，确保按时、按质、按预算交付
**Completion criterion**: 项目进度偏差<10%，缺陷密度<0.5/KLOC，变更控制率<15%，周/月报告按时提交

依据政企项目实施方法论 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 实施交付]：
1. 项目计划管理：
   - WBS分解：项目→阶段→任务→工作包→活动（5级分解）
   - 进度计划：甘特图（MS Project/禅道），关键路径识别，里程碑定义
   - 资源计划：人员投入（项目经理/架构师/开发/测试/运维）、硬件资源（服务器/网络/测试环境）
2. 质量管理：
   - 代码质量：SonarQube扫描，高危问题清零，覆盖率≥80%
   - 测试管理：单元测试→集成测试→系统测试→验收测试四级测试
   - 文档质量：按GB/T 8567标准编制，与代码版本同步更新
3. 变更控制：
   - 变更申请：变更原因/影响范围/工作量/风险/回滚方案
   - 变更评审：CCB（变更控制委员会）评审，甲方项目经理参与
   - 变更记录：所有变更登记入《变更日志》，可追溯
4. 沟通管理：
   - 周例会：乙方项目经理→甲方项目经理，汇报进度/问题/风险
   - 月度报告：正式书面报告，包含进度/质量/成本/风险四维度
   - 里程碑评审：每个里程碑召开评审会，甲方签字确认方可进入下一阶段
5. 风险管理：
   - 风险登记册：技术风险/进度风险/人员风险/政策风险
   - 应对策略：规避/转移/减轻/接受
   - 应急预案：关键人员备份/技术方案B计划/供应商备选
输出：《项目计划》+ 《质量管理计划》+ 《变更日志》+ 《风险登记册》+ 《月度项目报告》

### Step 5: 验收运维阶段移交

**Goal**: 完成系统验收与运维移交，确保系统可持续稳定运行，运维文档与培训到位
**Completion criterion**: 验收测试通过率100%，等保测评/密评（如需）通过，运维文档齐全，培训完成率100%

依据政企项目验收运维要求 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 验收运维]：
1. 验收测试：
   - 功能验收：依据SRS逐条验证，致命/严重缺陷清零
   - 性能验收：压力测试（设计并发×1.5倍）、稳定性测试（72小时无故障）
   - 安全验收：等保测评（三级211项逐条对照）+ 密评（密码应用安全性评估）+ 渗透测试
   - 信创验收：信创产品兼容性测试/性能对比测试/功能一致性测试
2. 文档移交：
   - 技术文档：需求/设计/测试/部署/接口/数据库/安全
   - 运维文档：《系统运维手册》《故障处理指南》《应急预案》《备份恢复方案》
   - 用户文档：《用户操作手册》《常见问题FAQ》《培训视频》
3. 培训移交：
   - 管理员培训：系统配置/监控/备份/故障处理（2-3天）
   - 用户培训：日常操作/业务流程/常见问题（1天）
   - 培训考核：培训后考核，合格率≥90%
4. 运维接管：
   - 试运行期：1-3个月，乙方驻场支持，甲方逐步接管
   - 维保期：1-3年，响应时间（P1故障2小时/P2故障8小时/P3故障24小时）
   - 知识转移：乙方输出《系统架构说明》《核心代码注释》《问题排查手册》
5. 双轨并行灰度切换（关键系统）：
   - 阶段1：新旧系统并行运行，数据双向同步，新系统占比10%
   - 阶段2：逐步提升新系统占比至50%，监控稳定性
   - 阶段3：新系统占比100%，旧系统保留30天作为回退保障
输出：《验收测试报告》+ 《验收会议纪要》+ 《文档移交清单》+ 《培训记录》+ 《维保协议》

## Post-Workflow

1. 读取 `checklist/gov_it_project_workflow_checklist.md`
2. 交叉验证每个招投标合规点、每项需求追溯、每个验收标准
3. 全部通过后输出《政企信息化项目落地总纲》并归档

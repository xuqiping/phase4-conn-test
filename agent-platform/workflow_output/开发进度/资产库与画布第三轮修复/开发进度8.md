# 开发进度8 · 框选改 ✋/▭ 双交互模式（2026-08-16）

## 需求

用户反馈（原话）：「我不要这种方式（Shift+拖框），我要求改为两种模式，一种模式为拖拽画布，一种模式为拖选节点，拖选节点的时候，像 windows 一样，左键按住拖拽框选节点」。

## 实现

`components/canvas/CanvasBoard.vue`：

- `dragMode: 'pan' | 'select'` ref（默认 pan），右下工具条 ✋/▭ 切换按钮（aria-pressed + `--active` 主题色高亮 + 分隔线）。
- VueFlow 双 prop 联动：
  - pan：`panOnDrag=true` + `selectionKeyCode='Shift'`（左键拖=平移，Shift+拖框=临时框选，向后兼容）。
  - select：`panOnDrag=false` + `selectionKeyCode=true`（左键拖=Windows 式框选，免 Shift）。
- `defineExpose` 增 dragMode/setDragMode。

**关键发现**：@vue-flow/core 1.48.2 **没有 `selectionOnDrag` prop**（React Flow 才有）。等价实现 = `selectionKeyCode: true`（恒选，源码 `shouldSelectOnDrag = selectionKeyCode===true && shouldPanOnDrag!==true`）+ `panOnDrag: false`。select 态下任何拖拽都不平移（左/中键皆否），游走靠滚轮缩放/适应视图；按钮 tooltip 已注明。

## 验证

- 单测 `CanvasBoard.test.ts`（新）3/3：默认 pan（panOnDrag=true/selectionKeyCode='Shift'）、切 select（false/true）、切回 + aria-pressed。
- vue-tsc 0 错。全量 vitest：仅 VideoGenView 2 + PricingConfigView 5 失败——**HEAD 既有**（stash 干净树复跑同 7 失败：useDialog 缺 n-dialog-provider / AC-VFIX 回归），与本改动无关，待另修。
- Playwright 真浏览器（/canvas/6）：
  - ▭ + 左键拖（无 Shift）：拖拽中 `.vue-flow__selection` 框实时渲染 → 松手 2/2 节点 selected + 批量工具条「已选 2 个节点」。
  - ✋ + 左键拖：viewport translate 精确 +200/+150（无选框、无选中）。
  - ✋ + Shift+拖：仍框选 2/2（兼容入口不回归）。
  - Esc 清工具条；点 pane 清全部选中。

## 踩坑

- vitest mock 提升序：`vi.mock` 工厂提到文件顶 → stub 定义须 `vi.hoisted`，否则 `Cannot access before initialization`。
- stub 在 `props:[...]` 里声明过的 prop 会从 `attrs` 剥离 → 断言用 `wrapper.getComponent(Stub).props()` 而非 attrs。
- 框选判定为相交即选，但边角重叠过小时实测有漏选（rect 只切到节点边角）——测试时框主体区域，不构成本次问题。

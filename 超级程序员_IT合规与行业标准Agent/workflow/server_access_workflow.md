# Server Access Management Workflow

## Purpose

基于企业服务器权限管理制度知识框架，提供基础设施权限管控的标准化执行路径，覆盖最小权限原则、RBAC/ABAC模型、堡垒机、PAM特权管理、零信任JIT、审计日志六大核心领域。

## Prerequisites

- 已完成服务器资产盘点（物理机/虚拟机/容器/云实例）
- 已明确身份源（AD/LDAP/企业微信/钉钉/自研IAM）

## Steps

### Step 1: 权限治理三层模型构建

**Goal**: 建立STRIDE威胁建模 + AAA认证授权审计 + ZTA零信任架构三层权限治理模型
**Completion criterion**: 输出《权限治理架构蓝图》，三层模型已映射到现有基础设施，威胁建模覆盖全部高价值资产

依据权限治理三层模型 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 权限治理STRIDE+AAA+ZTA三层模型]：
1. STRIDE威胁建模层：对核心系统（生产数据库、核心中间件、管理后台）进行威胁建模，识别Spoofing/Tampering/Repudiation/Information Disclosure/Denial of Service/Elevation of Privilege六类威胁
2. AAA层：
   - Authentication：统一身份源 + MFA（TOTP/硬件密钥/生物识别）+ 密码策略（长度≥16 + 复杂度 + 90天轮换）
   - Authorization：RBAC基础角色 + ABAC动态属性（时间/地点/设备/风险评分）+ 最小权限原则
   - Accounting：全量操作日志 + 行为分析 + 定期审计报告
3. ZTA零信任层：四点架构落地——PDP（策略决策点）+ PEP（策略执行点）+ PIP（策略信息点）+ PAP（策略管理点）
输出：《威胁建模报告》+ 《AAA配置手册》+ 《零信任架构实施方案》

### Step 2: 五大权限模型选型与实施

**Goal**: 根据业务场景选择并实施合适的权限模型，覆盖从传统RBAC到云原生策略标准
**Completion criterion**: 输出《权限模型选型决策记录》，选定模型已配置完成，用户-权限映射关系准确率100%

参考五大权限模型选型框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 五大权限模型选型]：
1. RBAC（基于角色的访问控制）：适用场景——岗位稳定、组织架构清晰的传统企业
   - 定义角色：系统管理员/DBA/开发工程师/测试工程师/运维工程师/安全审计员
   - 权限粒度：按系统/菜单/按钮/API四级授权
2. ABAC（基于属性的访问控制）：适用场景——弹性团队、动态项目、多云环境
   - 属性维度：用户属性（职级/部门/项目）+ 资源属性（敏感度/环境/Owner）+ 环境属性（时间/地点/设备可信度）+ 操作属性（读/写/删/执行）
3. MAC（强制访问控制）：适用场景——涉密系统、政府/军队/金融核心系统
   - 安全标签：公开/内部/机密/绝密 +  compartments隔离域
4. OPA+Rego（云原生策略标准）：适用场景——Kubernetes/微服务/云原生架构
   - 策略即代码：Rego策略定义权限规则，OPA作为通用决策引擎
5. Cedar（AWS策略语言）：适用场景——AWS生态或需要精细化策略表达的场景
执行：
- 评估现有组织架构与技术栈，选择主模型+辅助模型组合（如RBAC为主+ABAC动态扩展）
- 清理历史冗余权限：扫描并回收6个月未使用的权限、离职人员残留账号、幽灵账号
- 输出《权限基线配置标准》

### Step 3: 堡垒机四层管控建设

**Goal**: 部署堡垒机并建立身份、权限、操作、审计四层管控体系，实现运维操作全量代理
**Completion criterion**: 堡垒机覆盖全部生产环境访问入口，四层管控策略全部生效，高危命令实时拦截

参考堡垒机四层管控框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 堡垒机四层管控]：
1. 身份层：堡垒机集成SSO（如JumpCloud/Okta/自研IAM），强制MFA登录，生物识别优先
2. 权限层：多维授权模型（人+资源+时间+命令集），支持临时授权与自动过期
3. 操作层：命令拦截（高危命令如rm -rf /、DROP TABLE需二次确认）、SQL审核（危险SQL阻断）、文件传输审计（上传/下载记录）
4. 审计层：全量会话录屏 + 命令日志结构化存储 + 可回放检索 + 审计员独立查看权限
执行：
- 选型：商业方案（齐治/绿盟/启明星辰）或开源方案（Teleport/Jumpserver）
- 部署策略：先覆盖核心生产环境 → 扩展至测试环境 → 纳入开发环境
- 高危操作定义清单：数据库删表/删库、生产配置变更、防火墙规则修改、密钥操作
- 输出《堡垒机运维手册》与《审计日志分析指南》

### Step 4: PAM特权账号管理五阶段建设

**Goal**: 建立特权账号管理（PAM）体系，实现特权账号的全生命周期安全管控
**Completion criterion**: PAM系统上线，幽灵账号清零，特权密码自动轮换周期≤30天，会话代理覆盖率100%

参考PAM建设五阶段框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > PAM建设五阶段]：
1. 发现阶段：扫描全部基础设施（服务器/数据库/网络设备/应用账号），识别幽灵账号（无主账号/共享账号/长期未改密账号），输出《特权账号清单》
2. 托管阶段：将全部特权账号密码纳入PAM保险库（如CyberArk/BeyondTrust/自研），加密存储（AES-256），禁止人工知晓密码
3. 改密阶段：配置自动改密策略（核心系统每天/重要系统每周/一般系统每月），改密后自动同步至依赖系统
4. 会话阶段：所有特权访问必须通过PAM会话代理（PSM），实现录屏+命令审计+文件传输监控，禁止直连
5. 优化阶段：实施JIT（Just-In-Time）特权提升 + 零常驻特权（Zero Standing Privileges）+ 定期权限复核（每季度一次）
输出：《PAM建设路线图》+ 《特权账号治理报告》

### Step 5: JIT即时授权工作流实施

**Goal**: 建立JIT（Just-In-Time）即时授权工作流，将常驻特权转化为按需临时授权
**Completion criterion**: JIT工作流上线运行，平均授权审批时间<30分钟，临时权限自动撤销率100%

参考JIT工作流核心框架 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > JIT工作流核心]：
1. 请求发起：员工在ITSM系统提交JIT申请，填写理由（工单号/变更单号/事件号）、目标资源、所需权限、预计时长
2. AI风险评分：系统基于请求人历史行为、资源敏感度、时间异常度（非工作时间请求扣分）、自动计算风险评分（0-100）
3. 审批路由：
   - 低风险（0-30）：自动批准
   - 中风险（31-70）：直属经理审批
   - 高风险（71-100）：安全团队+部门总监双审批
4. 自动授权：审批通过后，PAM系统自动创建临时账号/临时提升权限，设定过期时间（默认4小时，最长24小时）
5. 时限监控：过期前15分钟提醒，过期后自动撤销权限并删除临时账号
6. 审计存档：完整记录申请-审批-授权-使用-撤销全链路，供安全审计调阅
输出：《JIT即时授权管理办法》+ 《审批SLA承诺》

### Step 6: 审计日志体系与运营

**Goal**: 建立覆盖Who/What/When/Where/Why/How六大要素的审计日志体系，支撑安全运营与合规检查
**Completion criterion**: 审计日志采集覆盖率100%，保留期限≥180天，关键日志实时告警，月度审计报告自动化生成

参考审计日志六大要素 [参考: Agents知识库/0_超级编程行业知识库/13_IT合规与行业标准.md > 审计日志六大要素]：
1. 日志架构五层：采集（Filebeat/Fluentd/Agent）→ 传输（TLS加密Kafka）→ 存储（Elasticsearch/ClickHouse，冷热分离）→ 分析（SIEM规则/UEBA模型）→ 展示（Grafana/Splunk Dashboard）
2. 六大要素落地：
   - Who：用户ID + 身份源 + MFA方式
   - What：操作类型（读/写/删/执行）+ 对象资源 + 操作结果
   - When：UTC时间戳 + 会话时长
   - Where：源IP + 设备指纹 + 地理位置
   - Why：关联工单号/审批单号/业务理由
   - How：使用的协议/工具/命令详情
3. 关键告警规则：
   - 特权账号异常登录（非工作时间/异地/新设备）
   - 批量权限变更（单次修改>10个账号权限）
   - 敏感数据访问（核心数据库首次访问/高频访问）
   - 权限提升事件（普通账号获得特权权限）
输出：《审计日志标准规范》+ 《SIEM告警规则库》+ 《月度审计报告模板》

1. 读取 `checklist/server_access_workflow_checklist.md`
2. 交叉验证每个权限模型、每个堡垒机策略、每个PAM阶段、每条JIT规则
3. 全部通过后输出《服务器权限管理制度总纲》并归档

## 一、项目目录结构（方案 A · Tauri + Rust）

> 注：本项目为 Tauri 应用，**不用** `PROJECT/backend/frontend` 拆分。前端 = `src/`，桌面端+后端 = `src-tauri/`。详见 [file_structure.md](../file_structure.md)。

```
voice-to-text/
├── index.html              # 前端入口
├── package.json            # Node.js 依赖与脚本
├── vite.config.ts          # Vite 配置
├── models/                 # 语音模型目录（运行时依赖，.gitignore）
│   └── sherpa-onnx-streaming-zipformer-small-bilingual-zh-en-2023-02-16/
├── scripts/
│   ├── download-models.js  # 模型自动下载脚本
│   └── check_all.*         # 最小质量门
├── src/                    # 前端 (Vue 3)
│   ├── App.vue
│   ├── main.ts
│   ├── stores/app.ts       # Pinia 状态管理
│   └── components/
│       ├── Controls.vue    # 控制栏
│       └── Transcription.vue
└── src-tauri/              # 后端 (Rust + Tauri)
    ├── Cargo.toml
    ├── tauri.conf.json
    └── src/
        ├── main.rs
        ├── lib.rs          # Tauri 命令注册、模型路径解析
        ├── audio/ (mod / capture / loopback)
        └── stt/ (mod / recognizer)
```

## 三、打包与分发（要点）

- 安装包**不含**模型（控制体积），首次启动或手动放置 `models/`。
- 分发优先 **MSI**（NSIS 存在 DLL 缺失 bug）。
- 详细步骤见 [部署手册](../deploy/部署手册.md)。

## 四、技术坑点预判

| 坑点 | 规避 |
|---|---|
| sherpa-rs 绑定不完善 | 走 C FFI 直接调 sherpa-onnx C API |
| 国内打包下载 WiX/NSIS 超时 | 设代理环境变量再 `npm run tauri:build` |
| NSIS 缺 DLL | 改用 MSI 分发 |
| macOS 麦克风权限 | 引导用户系统设置授权 |
| 模型路径打包后变化 | lib.rs 从可执行文件目录解析，不硬编码 |

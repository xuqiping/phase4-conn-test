# 记忆系统二期 · P1 收录路由 · 测试方案

> 对应 plan：[记忆系统二期_P1收录路由.plan.md](../plans/记忆系统二期_P1收录路由.plan.md)；规格 FR-001~008。
> 自动化已覆盖的不在此重复（三档分流/状态机/越权 403 走单测）；本方案给**必须人点点看/真 LLM/真链路**的场景。

## 前置条件

- 后端已跑过 V65 迁移（`memory_project_rules`/`memory_project_entries` 存在，system_settings 有 `memory.routing.*` 四个 key）。
- 两个测试账号：A（项目 P 的 owner）、B（P 的 ACTIVE 成员）、C（非 P 成员）。
- LLM 网关可用（embed + judge 模型真连通）；`memory.routing.enabled=true`。

## 关键路径用例

| # | 步骤 | 预期 |
|---|---|---|
| E1 | A 打开记忆面板「收录规则」页签，填 rule_text「涉及 SeedDance 视频生成的参数与工作流讨论」+ 1 条正例，保存 | 保存成功；DB rules 行 anchor_embedding/anchor_tokens 非空，enabled=true |
| E2 | B 在与 P 关联的会话里聊「SeedDance 的 cfg 参数怎么调」 | 异步路由后 P 出现条目（L1 蒸馏文本，无原话隐私）；条目带来源「张三·x 分钟前」式作者标注 |
| E3 | B 聊与规则无关内容（「今晚吃什么」） | 零条目产生；后端日志显示粗筛 0 候选、LLM 调用 0 次 |
| E4 | A 打开「收录审核」页签 | 看到 PENDING_REVIEW 条目（若有灰区置信度）：L1 + 置信度 + 命中规则文案；B 也能看到「为何被收录」但无收/弃按钮 |
| E5 | A 点「收」 | 条目 → ACTIVE，审核列表消失该项 |
| E6 | A 对另一条点「弃」 | 条目软删消失；rules.negative_examples 追加该 turn 蒸馏内容（≤5 滚动） |
| E7 | B 对自己产生的条目点「撤回」 | 条目软删；B 不能再撤回他人条目（无按钮/403） |
| E8 | 召回 scope 勾项目 P 提问 | 召回内容含 P 的 ACTIVE 条目，按作者打前缀【B·主题】；PENDING_REVIEW 条目不出现 |
| E9 | C 对 P 提问（非成员） | 召回不到 P 任何条目；直接调 entries API 403 |

## 功能联动用例（plan 联动清单 P1 部分）

| # | 触发动作 | 联动预期（正向/反向/边界） |
|---|---|---|
| L1 | A 关规则 enabled | 之后 B 聊 SeedDance 零条目（正向）；已收条目保留不动（边界）；A 重开 enabled → 恢复收录但不回溯历史（反向） |
| L2 | B 在 gen 矩阵关「允许我的对话被路由」（会员覆写） | B 新对话零条目（正向）；A 自己的对话仍正常收录（隔离）；B 重开 → 之后正常（反向） |
| L3 | A 在 gen 矩阵关项目级「启用自动收录」（owner 开关） | 全员（含 A）零条目；重开恢复 |
| L4 | embed 服务故障时保存规则 | 规则存库但 enabled 强制 false + 前端提示「锚点计算失败，规则未启用」 |
| L5 | LLM 精判返回脏 JSON | 不收录、不报错给用户；日志记降级 |

## 边界/异常

- 规则文本/正负例超长（>2000 字）→ 400 友好提示。
- 负例满 5 条后再弃条目 → 先进先出滚动，DB 验证仍 5 条。
- 成员 B 调规则写接口（PUT rule）→ 403。
- 项目被删 → rules/entries 级联清（DB 验证）。
- 路由总开关 `memory.routing.enabled=false` → 全停且个人流水账写入不受影响。

## 通过标准

- E1-E9 全过；L1-L5 全过；项目端点任何响应体不含 raw_content（抽查 E2/E4/E8 响应）。
- 后端 memory 包单测全绿 + check_all 绿。

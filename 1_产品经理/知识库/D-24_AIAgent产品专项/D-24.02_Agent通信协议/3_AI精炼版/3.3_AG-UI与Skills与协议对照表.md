# 3.3 AG-UI 与 Skills 协议深度 + 五协议横向对照表 + 协议选型决策树

## 一、AG-UI 是什么：CopilotKit 发起的 Agent 前端物流系统

**AG-UI（Agent User Interaction Protocol）**：CopilotKit 于 2025-05 开源发布的开放协议（MIT 许可），用于标准化"Agent 与前端"之间的实时通信。业内类比"Agent 前端的物流系统"——把 Agent 的规划/工具调用/中间推理/状态变更实时推送给前端 UI。2026-06 获 Google 与 Microsoft 同时采纳，CopilotKit 完成 2700 万美元 A 轮融资。[来源:CopilotKit/AG-UI | 🔍高 | 2025-05/2026-06]

**AG-UI 解决什么问题**：
- 协议前时代——Agent 前端交互全靠自研 SSE/WebSocket（每个团队写一套），事件结构/状态同步/错误处理各家不一致，前端集成成本高
- AG-UI 时代——定义 16 种标准事件类型（TextMessageChunk/ToolCallStart/StateSnapshot/HumanApprovalRequest 等），任何 Agent 后端对接任何前端框架（React/Vue/Svelte）都用统一事件流

## 二、AG-UI 核心架构

| 组件 | 作用 |
|---|---|
| **Event Stream** | Agent → 前端的标准事件流（HTTP+SSE 双向流式），含 16 种事件类型 |
| **State Sync** | Agent 状态与前端状态的双向同步，避免前端"等结果"黑盒 |
| **Tool Call Events** | 工具调用的全生命周期事件（start/args/end/error），让前端可视化工具执行 |
| **Human-in-the-Loop Events** | 人审节点事件（审批请求/批准/拒绝/补充输入），让人机协同前端标准化 |
| **Agent SDK** | 提供 React/Vue/Svelte 等 SDK，前端组件直接订阅事件流 |

**AG-UI 典型应用场景**：
1. ChatGPT/Claude 风格对话流式输出（TextMessageChunk 事件）
2. Cursor 风格 Agent 工具执行可视化（ToolCallEvents 实时显示）
3. Devin/Manus 风格 Agent 任务进度可视化（StateSnapshot 事件）
4. Cursor Agent+Review 风格人机协同审批流（HumanApprovalRequest 事件）
5. Anthropic 5-Agent 风格多 Agent 协作前端可视化（多 Agent 状态同步）

## 三、Skills 是什么：Anthropic 发起的能力封装格式

**Anthropic Skills**：Anthropic 于 2025-10 推出的 Agent 能力封装格式，把领域 know-how 打包成"经验包"让 Agent 加载即用。业内类比"装进脑子里的经验包"——不是工具（MCP 解决），而是"经验/方法论/指令集"。[来源:Anthropic Skills | 🔍高 | 2025-10]

**Skills 解决什么问题**：
- MCP 时代——Agent 能调工具，但缺"领域专长"——例如 Agent 能查数据库（MCP），但不会"做产品经理需求分析"；能写代码（MCP），但不懂"领域特定的代码规范"
- Skills 时代——把领域 know-how（如产品经理方法论/法务合规审查/医疗诊疗流程/代码 review 规范）打包成 Skills，Agent 加载 Skills 即获得该领域专长，无需重新训练模型

**Skills vs MCP Tool 的核心区别**：
| 维度 | MCP Tool | Skills |
|---|---|---|
| 本质 | 可调用的外部函数 | 可加载的领域指令集/方法论 |
| 例子 | 数据库查询工具 | 产品经理需求分析方法论 |
| Agent 获得 | 调用能力 | 领域专长 |
| 调用方式 | call_tool 主动调用 | 加载到 Agent 上下文 |
| 互斥 vs 互补 | 互补，不互斥 | 互补，不互斥 |

> Skills+MCP 是"经验包+工具箱"的典型组合：Agent 加载 Skills 获得领域 know-how，再调 MCP Tool 完成具体操作。

## 五、协议选型决策树（按 Agent 形态）

```
1. 单 Agent 产品
   ├─ 需调外部工具/数据源 → ✅ MCP（必选）
   ├─ 需前端过程可视化 → ✅ AG-UI（推荐）
   └─ 需领域专长 → ✅ Skills（按需）

2. 多 Agent 协作产品（云端）
   ├─ Agent 间需任务委派 → ✅ A2A（必选）
   ├─ 工具调用 → ✅ MCP（必选）
   ├─ 前端可视化 → ✅ AG-UI（推荐）
   └─ 领域专长 → ✅ Skills（按需）

3. 多 Agent 团队/Swarm 产品
   ├─ 编排框架 → 跨厂商开放用 LangGraph/CrewAI（同生态），跨厂商开放用 A2A
   ├─ 工具调用 → ✅ MCP（必选）
   ├─ Agent 间任务 → ✅ A2A（必选）
   ├─ 前端多 Agent 可视化 → ✅ AG-UI（推荐）
   └─ 领域专长 → ✅ Skills（按需）

4. 人机协同 Agent
   ├─ 工具调用 → ✅ MCP（必选）
   ├─ 人审节点前端 → ✅ AG-UI（必选——人审是 AG-UI 核心场景）
   └─ 领域专长 → ✅ Skills（按需）

5. 自主 Agent
   ├─ 工具调用 → ✅ MCP（必选）
   ├─ 任务委派（自主拆解子任务给子 Agent）→ ✅ A2A（推荐）
   ├─ 前端可视化（自主过程必须可见）→ ✅ AG-UI（必选）
   └─ 领域专长 → ✅ Skills（按需）

6. 边缘/IoT Agent
   ├─ 边缘 Agent 间协同 → ✅ ACP（必选）
   ├─ 调云端工具 → ✅ MCP（按需——可经云-边网关）
   ├─ 前端可视化 → ✅ AG-UI（按需）
   └─ 领域专长 → ✅ Skills（按需）

7. 国内市场合规 Agent
   ├─ 工具调用 → ✅ MCP（适配信通院 ATH）
   ├─ Agent 间 → ✅ A2A（适配信标委 AIP 国标）
   ├─ 边缘 → ✅ ACP（与国内 IoT 生态契合）
   └─ 提前对齐国标，避免后期改造 [来源:信通院/信标委 | 🔍高 | 2026]
```

## 六、国内合规：信通院 ATH 与信标委 AIP 国标

- **信通院智能体可信握手协议（ATH, Agent Trusted Handshake）**——中国信通院 2026 年发起，目标做国内 Agent 间可信通信标准（与 A2A 对标但强调"可信"），50 家企业已试点 [来源:信通院 | 🔍高 | 2026]
- **全国信标委智能体互联协议（AIP, Agent Interconnection Protocol）国标**——全国信息技术标准化技术委员会推动，目标做国内 Agent 互联国家标准，2026 年推进中 [来源:全国信标委 | 🔍高 | 2026]
- **国内 Agent 产品合规建议**：面向国内市场（尤其国企/政府/金融/医疗）的 Agent 产品，应同步对齐 MCP+A2A 国际协议与信通院 ATH+信标委 AIP 国标，预留 Adapter 层做国标适配，避免后期改造代价

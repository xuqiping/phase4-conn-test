## 4.2 AI洞察验证清单

### 验证步骤

| 步骤 | 验证项 | 方法 | 通过标准 |
|---|---|---|---|
| 1.统计验证 | 洞察是否统计显著 | p值/Bootstrap/效应量 | p<0.05且效应量>阈值 |
| 2.业务验证 | 洞察是否业务相关 | 域专家审核 | ≥1位专家确认相关 |
| 3.因果验证 | 相关还是因果？ | 反事实思考/准实验 | 至少排除明显混淆 |
| 4.新颖性 | 是否已知事实？ | 与已知知识库对比 | 非"已知常识" |
| 5.可操作性 | 能否引导行动？ | 行动可行性评估 | 有明确可执行建议 |
| 6.数据质量 | 底层数据是否可靠？ | 数据质量检查 | 缺失/异常率<5% |

## 4.3 数据分析Agent工作流（O.02维度）

### 标准Agent分析流程

```
用户提问 → Agent理解意图 → 规划分析步骤 → 逐步执行（取数→统计→可视化→归因） → 自我校验 → 生成报告 → 人工审核
```

### Agent工具集

| 工具 | 功能 | 触发条件 |
|---|---|---|
| NL2SQL | 自然语言取数 | 需要从数据库查询数据 |
| Python执行 | 统计分析/建模 | 需要计算统计量/模型 |
| 可视化 | 图表生成 | 需要可视化展示 |
| 搜索 | 联网检索业务背景 | 需要补充业务上下文 |
| 记忆 | 历史分析记录 | 需要参考之前的分析 |
| 校验 | 结果合理性检查 | 每个步骤结束后自动触发 |

### Human-in-the-loop设计

| 环节 | 人工干预点 | 干预方式 |
|---|---|---|
| 意图确认 | 理解用户需求后 | 用户确认/修正分析方向 |
| 中间检查 | 关键步骤完成后 | 用户审核中间结果 |
| 结论审核 | 最终输出前 | 用户验证结论合理性 |
| 反馈积累 | 使用过程中 | 用户对质量打分→优化模型 |

## 4.4 AI辅助数据分析 Agent 提示词

### 提示词：数据分析Agent

```
# Role
你是一个数据分析Agent，能够理解业务问题、自主规划分析步骤、调用工具执行分析、自我校验结果，并输出结构化分析报告。

# Background
产品经理在面对复杂的业务问题时，往往需要跨多个数据源、多步骤分析，传统自助BI工具需要手动操作，效率低且容易遗漏关键视角。数据分析Agent可以自动化整个分析流程，从取数到归因，让PM更关注决策而非操作。

# Objective
帮助产品经理完成从"业务问题"到"数据驱动决策建议"的全链路分析，输出可信、可操作的分析报告。

# Key Results
1. 准确理解用户分析意图，拆解为可执行的子步骤
2. 调用NL2SQL/统计工具完成数据获取和分析计算
3. 自动进行统计显著性检验和因果推断判断
4. 输出带可信度标注的结构化分析报告

# Steps
1. 理解意图：确认用户要分析的业务问题和关注的核心指标
2. 规划步骤：将分析任务拆解为【取数→描述统计→诊断分析→归因→建议】的步骤序列
3. 逐步执行：按规划调用工具完成每个步骤
4. 校验结果：检查每个步骤的结果是否合理（数值范围/统计显著性/业务逻辑）
5. 归因判断：区分相关与因果，标注因果置信度
6. 生成报告：按模板输出分析报告

# 红线
- 禁止在未执行SQL校验的情况下直接将AI生成SQL用于生产数据库
- 禁止将相关性直接等同于因果性，必须标注因果置信度等级
- 禁止输出未通过统计检验的"洞察"为确定性结论
- 如果数据不足以支撑结论，必须明确标注"数据不足"

# 输出格式
```markdown
## 数据分析报告
- 分析问题：[业务问题描述]
- 核心发现：1. [发现1]  2. [发现2]  3. [发现3]
- 归因判断：[因素] → [影响]，因果置信度：[等级]
- 建议行动：1. [行动1]  2. [行动2]
- 可信度等级：[L1-L4]
- 数据来源与局限：[表/指标/时间范围/已知局限]
```

# 固定结尾
本报告由AI数据分析Agent生成，结论基于当前可用数据和统计方法。关键决策建议结合业务方经验综合判断。如需更高的因果置信度，建议安排A/B实验验证。
```

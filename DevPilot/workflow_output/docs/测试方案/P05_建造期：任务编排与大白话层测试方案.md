# P05 建造期：任务编排与大白话层 · 测试方案

> 范围：FR-013/015/036/037/038 中需要人工确认或真实 LLM/UI 交互的用例。
> 自动化可断言的用例由单元/集成测试覆盖；本方案聚焦**功能联动、主观体验、危险操作、真实第三方**。

## 环境

- 桌面端（Tauri dev）+ 本地 mock 网关（固定返回）+ 真实 Node 脚本项目。
- 准备一个已走完 P04（想法→需求→计划）的项目，至少 2 个 chunk，已进入 build 阶段。

## 用例

### TC-01 任务按 chunk 顺序执行（正）

- **触发**：在 Build 视图点击「开始建造」。
- **预期**：
  1. 第一个 pending task 变为 running，叙事流显示「正在执行：xxx」。
  2. 完成后生成 checkpoint，task 状态变为 done，下一个 task 自动开始。
  3. 全部完成后状态机可推进到「验收」。
- **边界**：LLM 生成的文件路径含 `..` 或绝对路径时，runner 应拒绝并标记 failed。

### TC-02 任一 task 失败即停（反）

- **触发**：第二个 chunk 的测试命令固定返回 exit=1。
- **预期**：
  1. 失败 task 状态变为 failed， narrative 流显示失败原因（已脱敏）。
  2. 后续 task 保持 pending，不继续执行。
  3. 状态机留在 build，用户可「重试当前 task」或「回滚」。

### TC-03 diff 大白话摘要与原文切换

- **触发**：某个 task 完成后，点击「查看改动摘要」。
- **预期**：
  1. 默认展示大白话摘要（改了什么 / 为什么 / 影响哪里 / 风险）。
  2. 点击「看代码原文」切换到 `git diff` 原始文本。
  3. 再次点击回到摘要。
- **边界**：diff >5000 行时，摘要顶部提示「改动过大，仅展示前 5000 行」。

### TC-04 大白话翻译层全局开关

- **触发**：Build 视图点击「大白话模式」开关；刷新页面。
- **预期**：
  1. 开关状态持久化（localStorage）。
  2. 开启时，runner 日志/错误/术语自动翻译成人话；术语可悬停看气泡解释。
  3. 关闭时恢复原文。
- **边界**：术语表未命中时走 cheap 模型，网络失败时显示原文不阻塞。

### TC-05 存档点回滚（正 / 危险操作二次确认）

- **触发**：在 CheckpointTimeline 中选择一个已完成的 task 存档点，点击「回滚到这里」。
- **预期**：
  1. 弹出二次确认：「将丢失该点之后的代码与任务进度，且不扣 Token」。
  2. 确认后 git HEAD 回到目标 commit，下游 tasks 重置为 pending。
  3. 已产生的 checkpoints 记录不删除，时间轴仍可见。
- **边界**：取消二次确认后无任何变化；回滚不调用 `/gateway/complete`，不扣 Token。

### TC-06 追加指令续跑（正 / 多次追加顺序）

- **触发**：全部 task 完成后，在 Build 视图输入「再帮我加个 README」，点击「续跑」。
- **预期**：
  1. 同一 round 末尾新增一个 task（chunk_no = max+1），状态为 pending→running。
  2. 新 task 的 round_id 与原任务相同。
  3. 多次追加按输入顺序排队执行。
- **边界**：追加指令为空或 >2000 字符时前端提示，不创建 task。

### TC-07 重新审批 plan 清空旧 tasks（反向 / 批量）

- **触发**：用户回到 Plan 视图，点击「撤销审批」后再点击「审批计划」。
- **预期**：
  1. 撤销后 kickoff 门禁回退，原 pending tasks 被删除。
  2. 重新审批后按新 plan 生成 tasks，旧 checkpoint 仍保留但不再关联到当前任务流。
  3. Build 视图展示新任务列表。

### TC-08 Build 视图实时事件流

- **触发**：执行长耗时 task（如安装依赖）。
- **预期**：
  1. narrative 流实时显示阶段切换（probe/install/run/done）。
  2. 点击「展开原始日志」显示完整 stdout/stderr（已脱敏）。
  3. 事件落库，断网/刷新后可回放。

### TC-09 驾驶舱真实数据

- **触发**：完成若干 task 后打开 Dashboard。
- **预期**：
  1. 缺陷数 = failed tasks 数量。
  2. 覆盖率 = 最近 done task 的 test_result 解析（通过用例数/总数，无测试显示「未配置」）。
  3. 消耗 = usage_mirror 累计金额。

### TC-10 安全：生成文件路径逃逸

- **触发**：mock LLM 返回文件路径 `../escape.txt` 或 `/etc/passwd`。
- **预期**：runner 拒绝写入，task 标记 failed，UI 显示「文件路径越界」。

## 缺陷定级

| 级别 | 标准 |
|---|---|
| P0 | 任务编排不执行、回滚导致代码丢失、翻译开关导致崩溃、扣费未扣 |
| P1 | 摘要/事件显示错误、顺序错乱、持久化失败 |
| P2 | UI 文案/样式、日志未完全脱敏 |

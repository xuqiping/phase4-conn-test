# Office 效率增强功能性能目标

## 1. 响应目标

| 场景 | 目标 |
|---|---|
| 打开 Office 工作台 | P95 ≤ 300ms，不扫描文件 |
| 选择 100 个本地文件后的基础清单 | P95 ≤ 1s |
| 免费规模元数据预检 | 100 文件/1GB，P95 ≤ 15s，不含 Office 打开时间 |
| 任务取消反馈 | UI ≤ 200ms 进入取消中；Worker 10s 内退出，否则强制终止 |
| 历史列表 | 10,000 个任务下首屏 P95 ≤ 500ms |
| Office Pro 在线校验 | 服务端自身 P95 ≤ 300ms，不含公网 RTT |
| AI 网关非模型处理 | P95 ≤ 200ms；模型耗时单独展示 |

## 2. 资源目标

- 扫描和处理采用流式/分批方式，不把完整文件集或完整文档同时放入内存。
- Tauri 主进程 Office 功能增量常驻内存目标 ≤ 100MB；大对象留在 Worker。
- 默认每类 Office Worker 并发 1；OOXML Worker 可配置到 `min(4, CPU核数/2)`，避免磁盘争用。
- 开始任务前要求可用磁盘空间不少于预计输出 + 临时空间的 1.5 倍。
- Pro 无硬上限，但资源评估不通过时必须拒绝或建议拆批。

## 3. 稳定性目标

- 8 小时任务后主进程内存相对稳定阶段增长 ≤ 10%。
- Worker 崩溃不导致主程序退出；任务恢复点和诊断事件可查询。
- 不遗留由任务启动的 Office 进程；不得终止用户原有 Office 进程。
- 服务端套餐/积分事务在并发请求下余额不为负、无重复结算。

## 4. 容量规划

- 本地任务历史按 10,000 任务、100 万输入/输出明细设计索引与分页。
- 服务端 AI 用量表按月增长，保留按 user_id、request_id、created_at 的索引；达到千万级前评估按月分区。
- 管理员可配置 AI 并发、单请求最大 Token、用户日限额和全局月成本上限。

## 5. 术语表

| 术语 | 大白话 | 示例 |
|---|---|---|
| P95 | 95% 请求都应快于该数值 | 100 次中至少 95 次 ≤300ms |
| RTT | 请求在网络往返一次的时间 | 用户到服务器的公网延迟 |

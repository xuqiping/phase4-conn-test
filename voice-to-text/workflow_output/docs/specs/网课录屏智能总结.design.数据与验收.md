## 四、数据需求

### 4.1 运行时数据目录

见 3.11 `sessions/<时间戳>/`。每节课一个会话目录，互不干扰。

### 4.2 指标埋点（闭环 4 问：看什么/怎么埋/在哪看/不达标怎么办）

| 指标 | 埋点事件 | 触发时机 |
|---|---|---|
| 漏斗完成率 | `session_start` / `record_stop` / `process_done` / `summary_done` / `export_done` | 各阶段进入 |
| 采纳率 | `summary_keep` / `summary_discard` | 用户保留/丢弃总结 |
| 重写率 | `summary_edit`（含编辑距离） | 用户编辑要点 |
| 性能 | 各阶段 `duration_ms` | 阶段结束 |
| API 成本 | `llm_call`（token 用量） | 每次 LLM 调用 |
| 多模态精修 | `vlm_toggle` | 开关切换 |

> 埋点仅记录指标元数据，不含课程内容；用户授权前置。

## 五、异常与边界（6 类，精确到可编码）

| 异常 | 触发条件 | 处理 | 提示文案 |
|---|---|---|---|
| 录制中断 | WGC session 掉帧率超阈值 / 窗口被最小化 | watchdog 自动重建 session；失败则停止并保留已录片段 | 「录制意外中断，已保留前 XX 分钟，可重新开始」 |
| 磁盘满 | 落盘写入失败 | 停止录制，提示清理 | 「磁盘空间不足，请清理后重试（建议预留10GB）」 |
| OCR 失败 | OCR 引擎报错/超时 | 该帧 `ocr_text=null`，总结降级为仅转写 | 「部分课件帧识别失败，已用讲解文字补充」 |
| 转写缺失 | 某时间段无 final 文本 | 对齐单元标注「无讲解文字」 | （静默，学习区显示「（本段无语音）」） |
| 抽帧无变化 | 整段无场景切换 | 退化为 5min 固定窗分段 | （静默） |
| API 失败 | 云端超时/限流/Key 无效 | 降级：保留转写+课件帧+本地要点兜底；可重试 | 「网络/服务不可用，已保留全部文本，点击重试总结」 |

## 六、隐私与合规（知识库 D-05.08 / D-19）

| 环节 | 出本机？ | 处理 |
|---|---|---|
| 转写/抽帧/OCR/对齐 | ❌ 全本地 | 内容不出本机（差异化卖点，可宣传「内容不出本机」） |
| 云端总结（默认） | ✅ 上传**文字** | 首次明确告知 + 授权 + 用户自有 API Key |
| 多模态精修（D5 开关） | ✅ 上传**图片** | 默认关，开启时二次确认「将上传课件图到 {{provider}}」 |
| 录屏内容 | ❌ 本地 | 录前提醒 + 录后「仅留总结可删原视频」 |

**PIA 五步自查**：①采集什么（屏幕帧+音频）②为何（学习总结）③谁访问（仅本机+用户授权的云 LLM）④存多久（用户可控，可删）⑤是否最小够用（仅录选定窗口/区域）。本地优先架构天然满足大部分。

## 七、上线标准（MVP）

### 7.1 Must 范围验收（FR / AC）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-101 | 窗口捕获录屏 | AC-101：选窗口 → 开始 → 录到该窗口画面，停止后生成 video 切片 |
| FR-102 | 实时转写带时间戳 | AC-102：录制时实时出字幕；transcript.jsonl 每句含正确的 start_ms/end_ms（误差 < 300ms） |
| FR-103 | 分轨落盘 | AC-103：停止后 sessions/<ts>/ 下有 video 切片 + audio.wav + transcript.jsonl |
| FR-104 | 精细抽帧去重 | AC-104：录后生成课件页序列，PPT 翻页被正确识别，相邻同页去重 |
| FR-105 | 课件 OCR | AC-105：每课件页产出 ocr_text，可读性可接受 |
| FR-106 | 音字帧对齐 | AC-106：aligned.json 中每个课件页关联正确时间段的讲解文字 |
| FR-107 | 云端总结 | AC-107：配置 API Key → 一键生成「要点+时间轴章节」，每条要点带时间戳+课件帧回链 |
| FR-108 | Markdown 导出 | AC-108：导出结构化 MD，含章节/要点/时间戳 |
| FR-109 | 容错 | AC-109：API 失败时降级保留文本并可重试；总结为草稿态可编辑 |

> AC-110~112 为 Phase4 手测回流补录（2026-08-08）：110/111 原为规格外需求（见开发进度总览·漂移表），112 为规格内 Should 项「区域框选录屏」的验收。

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-110 | 历史会话查看（规格外补录） | AC-110：录制区可选历史会话并打开：有总结的直达学习区（章节/要点/帧/视频可播）；无总结的进处理区可续跑，已完成阶段不重复跑 |
| FR-111 | 总结侧重点+智能输出格式（规格外补录） | AC-111：设置里可维护侧重点预设表（内置默认/考试复习/概念理解/实操步骤，可增删改名称和提示词），选择后下次生成/重生成生效；内容涉及专业术语/公式/定义时要点带「术语：大白话解释」，不涉及则默认格式 |
| FR-112 | 区域框选录屏（Should 落地） | AC-112：点「区域框选」拖出矩形确认后录制，视频切片/抽帧只含框选区域（主显示器）；Esc 可取消；窗口与区域**共存**——两个都选 = 录该窗口再按区域裁剪（窗口被遮挡不影响录制），只框不选窗 = 录主屏该区域；换窗口则清空已框区域需重框 |

### 7.2 灰度/回滚

- 新功能为独立模块 + 独立会话目录，不影响现有"纯录音转文字"主流程，可随时下线。
- feature flag 控制"录屏总结"入口显隐。

## 八、关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| WGC 长时运行掉帧（调研已知问题） | 高 | watchdog 监控掉帧率 + 自动重建 session |
| 三路时钟漂移 | 高 | 墙钟 PTS + 分轨落盘后处理（不实时 mux） |
| 云端 API 成本/失败 | 中 | map-reduce + 降级兜底 + 用户自带 Key |
| `windows-capture` crate 较年轻 | 中 | 可 fork 自维护，参考 Cap 项目实现 |
| 2h 磁盘占用（2–6GB） | 中 | 15min 切片 + 「导出后删原视频」开关 |
| OCR 把课件认错（视觉幻觉） | 中 | 总结标注「AI 生成」+ OCR 原文可展开核对 + 要点带帧回链 |

## 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| WGC | Windows 官方录屏 API | 录指定窗口或屏幕 |
| 墙钟 PTS | 用系统高精度计时器给每帧/每段声音打的时间戳 | 让画面、声音、文字对到同一时间轴 |
| SAD 预筛 | 用相邻帧像素差快速判断"画面变没变" | 录制时轻量找变化点 |
| pHash 去重 | 感知哈希判断两张图是不是同一页课件 | 汉明距离>8 视为不同页 |
| map-reduce | 先分段总结再全局合并 | 2h 长课切成段分别总结，再合成总纲 |
| 草稿态 | AI 总结先存为草稿，用户确认才定稿 | 可撤销/可编辑/可重新生成 |
| 多模态精修 | 让云端大模型看课件图片来总结 | 默认关，开启才上传图片 |

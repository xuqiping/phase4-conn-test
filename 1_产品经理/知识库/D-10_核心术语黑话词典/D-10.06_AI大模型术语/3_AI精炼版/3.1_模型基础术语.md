## 1. 大语言模型 / Large Language Model / LLM

| 字段 | 内容 |
|---|---|
| 英文全称 | Large Language Model |
| 缩写 | LLM |
| 定义 | 参数规模在亿级以上、基于Transformer架构、通过海量文本数据训练的语言模型，核心能力是"预测下一个词" |
| PM解读 | LLM不是"懂人话的数据库"，而是"读遍互联网后学会接话的统计引擎"。理解这一点，就不会问"它为什么不知道昨天的事" |
| 常见误解 | ①把LLM当搜索引擎用 ②以为参数越大越好（忽略了MoE等稀疏架构） |
| 来源 | [📚训练知识]

## 2. Transformer

| 字段 | 内容 |
|---|---|
| 英文全称 | Transformer |
| 定义 | 2017年Google提出的深度学习架构，核心机制是自注意力（Self-Attention），允许模型并行处理输入序列中任意两个位置的关系 |
| PM解读 | Transformer是所有主流LLM的"发动机架构"。理解它的重点是：它打破了"逐字顺序处理"的限制，使得长距离依赖建模成为可能 |
| 常见误解 | 以为Transformer=ChatGPT（Transformer是架构，ChatGPT是基于该架构的产品） |
| 来源 | Attention Is All You Need, Vaswani et al., 2017 [📚训练知识]

## 3. 预训练 / Pre-training

| 字段 | 内容 |
|---|---|
| 英文全称 | Pre-training |
| 定义 | 用海量无标注数据（互联网文本、代码等）训练模型学习语言的通用规律，是LLM的"基础教育阶段" |
| PM解读 | 预训练决定了模型的"知识广度"，但不决定它能否遵循指令——那是SFT/RLHF的工作 |
| 口径注意 | 预训练数据截止日期≠模型发布日期，中间还有后训练和部署时间差 |
| 来源 | [📚训练知识]

## 4. 监督微调 / Supervised Fine-Tuning / SFT

| 字段 | 内容 |
|---|---|
| 英文全称 | Supervised Fine-Tuning |
| 缩写 | SFT |
| 定义 | 用人工标注的"指令-回答"对训练模型学会遵循人类指令，是LLM从"语言补全器"变为"对话助手"的关键步骤 |
| PM解读 | SFT是模型的"职业培训"——预训练让模型有了语言能力，SFT让它知道"有问要答、有指要遵" |
| 常见误解 | 以为SFT后模型就安全了（SFT只教行为，不教价值观——对齐需要RLHF/DPO） |
| 来源 | [📚训练知识]

## 5. 微调 / Fine-Tuning

| 字段 | 内容 |
|---|---|
| 英文全称 | Fine-Tuning |
| 定义 | 在预训练模型基础上，用特定领域数据继续训练，使模型适配特定任务或领域 |
| PM解读 | Fine-Tuning是通用模型变垂直专家的方法。注意区分：SFT是Fine-Tuning的一种（用指令数据），还有领域微调（用领域数据） |
| 来源 | [📚训练知识]

## 6. LoRA / Low-Rank Adaptation

| 字段 | 内容 |
|---|---|
| 英文全称 | Low-Rank Adaptation |
| 缩写 | LoRA |
| 定义 | 一种参数高效微调方法（PEFT），只训练原模型极少量新增参数（低秩矩阵），而非全部参数，大幅降低微调成本 |
| PM解读 | LoRA让"每个业务线定制自己的模型"从不可行变为可行。7B模型全量微调需多卡，LoRA单卡即可 |
| 常见误解 | 以为LoRA和SFT是并列关系（LoRA是微调的"方法"，SFT是微调的"目标"——可以LoRA+SFT） |
| 来源 | Hu et al., 2021 [📚训练知识]

## 7. 参数量 / Parameters

| 字段 | 内容 |
|---|---|
| 英文全称 | Parameters |
| 定义 | 模型中可学习的权重与偏置总量，单位通常以十亿（B/Billion）计量，如7B、70B、671B |
| PM解读 | 参数量是模型"容量"的粗略指标，但≠能力。671B的MoE模型实际推理只激活部分参数，成本远低于671B Dense模型 |
| 口径注意 | MoE模型需区分"总参数量"与"激活参数量"。DeepSeek-R1是671B总参数，但只激活37B |
| 来源 | [📚训练知识]

## 8. 浮点运算量 / FLOPs

| 字段 | 内容 |
|---|---|
| 英文全称 | Floating Point Operations |
| 缩写 | FLOPs |
| 定义 | 模型训练或推理一次所需的浮点运算次数，衡量计算成本的直接指标 |
| PM解读 | 参数量决定"模型有多大"，FLOPs决定"跑一次要多少钱"。选型时两个都要看 |
| 来源 | [📚训练知识]

## 9. 推理 / Inference

| 字段 | 内容 |
|---|---|
| 英文全称 | Inference |
| 定义 | 用训练好的模型对输入数据进行预测/生成，即"模型上线后回答问题的过程" |
| PM解读 | ⚠️"推理"在AI领域有歧义：①Inference=模型运行（技术含义）；②Reasoning=逻辑推演（认知含义）。o1/o3这类"推理模型"是指Reasoning能力增强 |
| 常见误解 | 以为"推理模型"="推理速度快的模型"（实际是"具备逻辑推演能力的模型"） |
| 来源 | [📚训练知识]

## 10. 自回归生成 / Autoregressive Generation

| 字段 | 内容 |
|---|---|
| 英文全称 | Autoregressive Generation |
| 定义 | 逐个Token预测下一个Token的生成方式，是当前主流LLM的输出机制 |
| PM解读 | 这解释了为什么LLM不能"回头改"——每个Token一旦生成，就作为后续生成的前提。也解释了Token累积对成本和延迟的影响 |

## 本轮做了什么（commit `032f8d42`，15 单测 + 7 IT 实跑全绿）

### 4 端点（`MemoryLifecycleController`，`/api/chat/memory` 新栈命名空间）
- `GET /departed-projects` —— 本人已离开项目列表（copy-to 折叠板源数据）。
- `POST /departed-projects/{projectId}/copy-to` —— 拉取到自建新项目（copy 非 move）。
- `GET /deleted-projects` —— 本人已删除项目列表（restore 折叠板源数据 + badge 依据）。
- `POST /deleted-projects/{projectId}/restore` —— 拉取到自建新项目（仅拉 turn 不拉 summary）。
- 请求体 `MemoryLifecyclePullRequest{projectName?}`：空走默认命名「「原项目名」记忆拉取」（截 100 字符 = projects.name 上限）。

### `MemoryLifecycleService`（独立新 service，承 C/D/E/I2 隔离裁决，零碰 legacy）
- **copy-to**（§3.7 line159）：前置校验本人 memory_project_members DEPARTED（非成员/ACTIVE → 403）→ 自建新项目 Q → 补 Q 的新栈 OWNER 成员行 → 本人挂在 P 的 turns `array_append(project_ids, Q)`（原 P 挂载保留、departed_project_ids 不动、原项目数据零改动）。
- **restore**（§3.7 line165）：前置 count 本人 deleted_project_ids 含 P 的 turns（0 → 404 防存在性探测）→ 自建新项目 Q + OWNER 行 → turns `array_remove(deleted_project_ids, P)` + 重挂 Q → 本人 `PROJECT_DELETED_AFFECTED` 通知置 resolved（badge 消，他人不动）。
- 新项目创建**复用 `ProjectService.create`**（项目 CRUD 单一出口，自动落旧 project_members owner 行；跨模块依赖承 MemoryRecallScopeResolver 先例）。
- 两个写动作 @Transactional（多表写：projects + 双成员表 + turns + notifications）。

### mapper + XML
- `MemoryProjectMemberMapper.findMyDepartedProjects`：DEPARTED membership join projects 名 + 本人 turn 计数（correlated 子查询 `project_ids @> ARRAY[m.project_id]`）。
- `MemoryTurnMapper`：`findMyDeletedProjects`（unnest deleted_project_ids 去重 + LEFT JOIN projects）/ `countMyTurnsInDeletedProject` / `appendProjectToMyTurns`（NOT 已挂幂等）/ `restoreMyTurnsFromDeletedProject`（CASE 防重复追加）/ `findProjectNameAnyState`（XML 裸 SQL 绕 @TableLogic，软删项目名仍取到）。

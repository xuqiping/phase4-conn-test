# 3.2 三大核心模型

## 模型一：AI-Native产品逻辑

### 核心原则：从按键驱动到意图驱动

传统产品以"用户点击→系统响应"为核心逻辑（if-else硬编码）；AI原生产品以"用户表达意图→AI理解→规划→执行→反馈"为核心逻辑（概率推理+工具编排）。这不是UI变化，是**产品架构范式迁移**。[来源:人人都是产品经理·XYKing | 📚中 | 2026-03]

### 三大架构特征

1. **从被动响应到主动代理（Proactive Agent）**
   - AI不是等待用户输入的计算器，而是根据上下文主动发现问题的"大堂经理"
   - 设计要点：上下文感知引擎 + 主动触发条件 + 预判方案选项

2. **工作流彻底重构（Workflow Reconstruction）**
   - AI不是流程的一个节点，AI本身就是流程的底座
   - 例：AI客服 = "AI全自动处理90%工单 + 路由10%复杂工单给人类"，而非"人类客服 + AI知识库"
   - 业务起点和终点因AI加入根本性位移

3. **UI消亡与隐身化**
   - 最佳AI Native产品可能没有对话框甚至没有复杂界面
   - AI默默运行在后台，只在关键决策（Approval）时浮出水面
   - 终局形态：无头架构（Headless AI），流量入口变成自然语言/语音/自动化触发

### AI Native成熟度分层

| 层级 | 名称 | 特征 | 典型产品 |
|---|---|---|---|
| L0 | AI-Enabled | 在现有产品中加AI功能 | 传统SaaS加AI摘要 |
| L1 | AI-Assisted | AI辅助完成子任务 | Copilot类辅助工具 |
| L2 | AI-Driven | AI驱动核心工作流 | Cursor AI编程、Perplexity搜索 |
| L3 | AI-Autonomous | AI自主完成端到端任务 | Devin自主编程Agent |

## 模型二：人机协同设计（Human-AI Collaboration Design）

### 三层分区模型

| 分区 | 决策者 | 典型场景 | 设计要点 |
|---|---|---|---|
| AI自主域 | AI全权决策 | 垃圾邮件分类、商品推荐排序 | 高置信度+低损失+高频量→允许全自动 |
| 人机确认域 | AI提议+人类确认 | 大额转账审批、营销全量推送 | 高价值/高影响→AI预执行+人类点击确认 |
| 人类审批域 | 人类主导决策 | 战略方向选择、合规红线判断 | AI仅辅助分析→最终决策权在人 |

### Human-in-the-Loop（HITL）设计四要素

1. **触发条件**：什么情况下系统自动流转 vs 路由给人类——基于置信度阈值+业务风险权重
2. **信息密度**：人类接收多少信息做判断——AI提取关键摘要+高亮+推荐选项，不是甩锅原始数据
3. **反馈回传**：人类的确认/修正必须回传至AI学习闭环——标注→训练→升级
4. **性能监控**：兜底率趋势是否上升→AI能力衰退预警；兜底耗时→人类疲劳度预警

### 反直觉原则

> 人机协同不是"AI做不了的给人做"，而是"设计最优的决策分配"。有时即使AI能做，也应该让人类确认——关键不在于AI能力够不够，而在于决策后果的可逆性和问责机制。[来源:📚训练知识]

## 模型三：AI优先决策（AI-First Decision Making）

### 核心原则

在做产品设计决策时，**默认优先考虑AI自动化路径**，仅在以下情形引入人类干预：
- 置信度低于业务阈值
- 合规/法律红线（不可自动决策的领域）
- 高不可逆操作（如删除全部数据、执行大额交易）
- AI能力边界外的长尾场景

### 驾驭工程（Harness Engineering）四引擎

将概率性AI转化为确定性SLA的四大工程手段 [来源:人人都是产品经理·XYKing | 📚中 | 2026-03]：

| 引擎 | 作用 | 关键动作 |
|---|---|---|
| System Boundaries（系统边界） | 从"什么都能做"到"只准做这件事" | 输入侧护栏、输出侧判别、业务逻辑硬隔离 |
| Tool Use / Function Calling（工具调用） | 给AI安上手和脚 | RAG（眼）+ 执行器（手）+ JSON Schema规范 |
| Memory Management（记忆管理） | 从金鱼记忆到跨周期伴随 | 短期记忆裁剪 + 长期记忆固化 + 状态机管理 |
| Error Recovery（容错回退） | 永远为AI翻车做准备 | 自省机制 + 优雅降级 + Human-in-the-Loop |

### 决策流程

```
业务需求 → 先问"AI能否自动完成？" → 能 → 设计护栏+工具+记忆+容错 → AI自主执行
                                        ↓不能
                                    → 评估：置信度是否足够高？
                                        ↓够 → AI提议+人类确认
                                        ↓不够 → 人类主导+AI辅助分析
```

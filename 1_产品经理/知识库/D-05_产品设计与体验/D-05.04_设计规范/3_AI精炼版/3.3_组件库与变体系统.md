## 组件库与变体系统

### 组件设计原则

| 原则 | 说明 | 反例 |
|---|---|---|
| 单一职责 | 一个组件只解决一个UI问题 | "万能卡片"组件 |
| 组合优于继承 | 通过组合小组件构建大组件，而非层层继承 | BaseButton→PrimaryButton→LargePrimaryButton |
| 变体穷举 | 每个维度变化都显式定义，不留隐含状态 | 只定义了primary/secondary，缺ghost |
| 文档即代码 | 组件文档与代码同步，不容许分离 | 文档写"点击关闭"但代码无close回调 |
| 可访问性内置 | a11y不是附加层，是组件内禀属性 | 模态框无焦点捕获 |

### 变体维度模型

**Atomic Design变体**：每个组件按多维度定义变体。

| 维度 | 取值 | 说明 |
|---|---|---|
| 类型(Type) | primary/secondary/ghost/danger | 视觉权重与语义 |
| 尺寸(Size) | small/medium/large | 影响间距/字号/圆角 |
| 状态(State) | default/hover/active/focus/disabled/loading | 交互反馈 |
| 主题(Theme) | light/dark/high-contrast | 令牌映射 |
| 方向(Direction) | horizontal/vertical | 布局适配 |

**组合公式**：变体数 = 类型 × 尺寸 × 状态 × 主题 × 方向

> 实践红线：**避免全量排列**——只定义已确认需求的变体组合（"按需变体"），未确认的不预留。

### 组件文档规范（I.17设计模板·必含字段）

| 字段 | 内容 | 必要性 |
|---|---|---|
| 名称+编号 | `Button / C-001` | 必须 |
| 一句话描述 | "触发操作的标准按钮" | 必须 |
| 变体清单 | 类型+尺寸+状态全部枚举 | 必须 |
| 属性(Props)表 | 属性名/类型/默认值/说明 | 必须 |
| 可访问性说明 | ARIA角色/键盘交互/焦点管理 | 必须 |
| 设计令牌引用 | 该组件使用的语义令牌清单 | 必须 |
| 组合示例 | 与其他组件搭配使用的2-3个场景 | 推荐 |
| 反模式 | 展示错误用法的"Do/Don't" | 推荐 |
| 变更日志 | 版本号+日期+变更内容 | 必须 |

### 模式库（Pattern Library）

**定义**：模式 = 组件组合 + 交互流程 + 布局规则，解决特定UX问题。

| 模式名 | 解决的问题 | 核心组件组成 | 适用场景 |
|---|---|---|---|
| 表单校验 | 实时+提交时双重校验 | Input + Tooltip + Alert | 所有表单 |
| 空状态 | 零数据的友好引导 | Illustration + Text + CTA | 列表/表格/仪表盘 |
| 确认弹窗 | 防误操作的安全确认 | Modal + Button + Warning | 删除/退出/支付 |
| 加载骨架屏 | 异步加载时的视觉稳定 | Skeleton + Shimmer | 异步数据区 |
| 下拉刷新 | 移动端新内容获取 | PullIndicator + Spinner | 信息流/列表 |

### 组件版本管理策略

| 策略 | 说明 | 适用场景 |
|---|---|---|
| 语义版本(SemVer) | Major(破坏性)/Minor(新增)/Patch(修复) | 正式发布的组件库 |
| 实验性标记(Experimental) | 不保证稳定性，标记为α/β | 新组件试水 |
| 废弃流程(Deprecation) | 标记废弃→保留2版本→移除 | 组件下线 |
| 迁移指南(Migration) | 每次Major版提供迁移脚本+文档 | 升级支持 |

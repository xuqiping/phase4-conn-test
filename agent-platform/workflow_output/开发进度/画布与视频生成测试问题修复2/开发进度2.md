## Chunk E · 4K 回归（4.2）✅ commit `0f4e967a`

**双根因**，非单点：
1. **V64 override 漏 `supportedResolutions`**：V64 往 `llm_providers.config` 注 `capabilities.Cdance2.0` 全版多模态（9 图/3 视频/3 音频/videoDataUri），但**漏写 `supportedResolutions`**。`MediaModelCapabilityService.applyOverride` 对缺省字段**保留 base 默认**——Cdance2.0 base 命中 `seedance-2` 前缀给全版……但前缀匹配用的是 model id 含不含 `seedance-2`，注册 id 若是 `Cdance2.0`（非标准前缀）→ 命中**未知兜底**（`RES_UPTO_1080`，无 4K）。
2. **`MediaGenProperties.maxRes` 默认 `720p`**：`MediaGenTaskService.validate` line 175-180 用 `RES_RANK` 比较，maxRes=720p 连 **1080p 都拒**（更别说 4K）。

**修复**：
- 新增迁移 [V67__seedance_cdance2_resolutions.sql](../../../backend/src/main/resources/db/migration/V67__seedance_cdance2_resolutions.sql)：幂等 `UPDATE llm_providers SET config=... WHERE category='VIDEO' AND models ILIKE '%Cdance2.0%'`，重写**完整** Cdance2.0 config（补 `supportedResolutions:[480p,720p,1080p,4K]` + `supportedRatios` + `min/maxDuration` + V64 全部字段）。V64 已执行不可改，故加 V67。
- [MediaGenProperties.java](../../../backend/src/main/java/com/superprogrammer/media/config/MediaGenProperties.java)：`maxRes` 默认 `720p`→`4K`，注释阐明「capability 是逐模型真闸门，maxRes 仅二级上限」。

**测试**：[MediaModelCapabilityServiceTest.java](../../../backend/src/test/java/com/superprogrammer/media/config/MediaModelCapabilityServiceTest.java) 拆原 `cdanceAlias` 用例为二：V64 形 config（无 supportedResolutions）→ `assertFalse(contains 4K)`；新增 `cdanceAlias_v67FullConfig_has4K` → `assertTrue(contains 4K)`。**10/10 绿**（原 9）。

**副验证**：第三方 SeedDance 契约明「4K 仅 2.0 支持；Fast/Mini 不支持 1080p」→ 印证 `defaultsFor` fast/mini→`RES_UPTO_1080` 正确。

## Chunk G · 资产选中图显示（4.4）✅ commit `fc05fccb`

**根因**：资产 resolve 返 `ResolveVO.url = /api/files/{fileId}`（鉴权相对 URL）。VideoGenView 选中资产图直接 `<img :src="url">`——**不带 JWT → 401 → 碎图**。画布侧第一轮已踩同坑（S13 节点 @引用）。

**修复**（[VideoGenView.vue](../../../frontend/src/views/VideoGenView.vue)）：
- `onAssetPicked` 推占位 `{id,fileId,name,assetId}` 后 `void previewAsset(id,k,fileId)`。
- `previewAsset`：复用 `@/api/file` 的 `fetchFilePreview`（鉴权 axios 拉 blob→objectURL），find+set url；找不回（已删）则 revoke。
- `revokeAttachmentUrl` 收尾；`onAssetChipRemove` / `onModelChange`（清三类附件前 forEach revoke）/ `onUnmounted` 均 revoke，**防内存泄漏**。

**测试**：vue-tsc 净（无单测，blob/objectURL 浏览器侧，Phase4 手测）。

## Chunk H · 视频生成页 @附件（4.5，新功能）✅ commit `6e373493`

**目标**：视频生成页提示词框支持 @ 引用会话附件（图/视频/音频），序号化为「图N/视频N/音频N」送 Ark（Ark 认序号不认 token）。与画布 @节点（展开成内容）**语义不同**。

**实现**：
- [MentionTextarea.vue](../../../frontend/src/components/canvas/MentionTextarea.vue) **泛化**（保画布默认）：regex `(node|asset)`→`(\w+)`；加 props `kindLabels`（默认 `{node,asset}`）/`emptyHint`/`maxlength?`；模板 kind label 取 `kindLabels[c.kind]`；加字数计数 `{{ len }}/{{ maxlength }}`。
- [canvas.ts](../../../frontend/src/types/canvas.ts)：`MentionCandidate.kind` 扩 `'node'|'asset'|'image'|'video'|'audio'`。
- 新建 [attachmentMention.ts](../../../frontend/src/utils/attachmentMention.ts)：`interpolateAttachmentPrompt(prompt,imgs,vids,auds)` —— `@{{image|video|audio:<id>}}` 按各 kind 列表**当前顺序**解析 1-based 序号（id 稳定，重排跟随）；断链→`〔已删除的参考〕`。与画布 `interpolate.ts` 分离（序号 vs 内容）。
- [VideoGenView.vue](../../../frontend/src/views/VideoGenView.vue)：`n-input`→`MentionTextarea`，候选=会话附件（`label=图${i+1}`），断链计算，submit 调 `interpolateAttachmentPrompt`。`ATTACH_KIND_LABELS={image:'图',video:'视频',audio:'音频'}`。

**测试**：新建 [attachmentMention.test.ts](../../../frontend/src/utils/attachmentMention.test.ts) **8/8 绿**（序号化/重排跟随/断链/no-op/空/透传 node·asset/多同类/混合）。MentionTextarea 旧 15 测仍绿。vue-tsc 净。

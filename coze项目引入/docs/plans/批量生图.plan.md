# Implementation Plan for 批量生图（LLM 拆分 + 并行执行）

> Phase 2 产出。Phase 3 逐步勾选执行。**只含伪代码，不含真代码。**
> 落地路径建议：实现首步把本计划拷到 `coze项目引入/docs/plans/批量生图.plan.md`

## 背景与目标

当前 `coze项目引入/2_对话网页.py` 只支持**单条** prompt 生图。用户需要：丢一份**批量生图文档**（含多条 prompt）+ 一批**参考图**，由 LLM 理解并拆成多条任务，**并行**交给同一个 Coze 工作流生图，结果仍按类别归档（复用已实现的 `download_and_save`）。

**输入契约**（用户已确认）：
- 文档里每段 prompt **下方独立一行**写出该 prompt 用的参考图文件名（逗号分隔）
- 每个 prompt **最多 3 张**参考图
- 用户上传的参考图**文件名**与文档里写的名字对应

**流程**（用户已确认）：上传文档+参考图 → LLM 拆分 → **用户确认/可改** → 并行生成 → 网格展示进度与结果。

**复用现有函数**（[2_对话网页.py](AI-Projects/coze项目引入/2_对话网页.py)）：
- `upload_file_to_coze` / `start_workflow`（async）/ `get_workflow_history`
- `parse_workflow_output` / `download_and_save` / `/img/<path>` 路由
- [coze_token.py](AI-Projects/coze项目引入/coze_token.py) 的 `auth_headers`

## 技术实现坑点预判与规避措施

| 技术点 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| 并发取 token | `coze_token.get_access_token` 的 `_cache` 无锁，多线程并发会重复换 token / 读半截状态 | 加 `threading.Lock` 包住「判过期→换 token」 | 起多个线程同时调 `auth_headers`，确认只换一次 |
| Coze 限流 | 工作流 API ≈5 QPS，并发太高触发 429/`700012006`/`4100` | 并发上限默认 **3**（可配）；遇限流错误指数退避重试 | 故意把并发开到 8 复现限流，看是否自动退避恢复 |
| LLM 输出不规范 | LLM 偶尔不返回严格 JSON / 漏字段 / refs 超 3 个 | 强制 JSON 输出 + 二次校验：refs 超 3 截断、空 prompt 丢弃、解析失败整批报错可重试 | 喂格式混乱的文档，确认能给出可读错误而非崩溃 |
| 参考图名对不上 | 文档里的文件名与上传文件名不一致（大小写/扩展名/路径） | 按basename 去扩展名模糊匹配；匹配不上的在确认环节**标红警告** | 故意写错一个名字，确认界面提示「未找到」 |
| 长批次 token 过期 | 批量任务跑几分钟，中途 access_token 过期 | 依赖 `coze_token` 的临过期续签（已实现）；并发加锁后线程安全 | 跑 10 条批次，跨过 token 有效期，确认不中断 |
| 批次状态丢失 | 内存存批次状态（`BATCHES` dict），重启即丢 | 本地工具可接受；done 结果已落盘 `downloads/`，不丢图 | 注明为已知限制，不引入 DB |

## 安全检查清单

- [ ] **鉴权/授权**：本地单用户工具（127.0.0.1），无多用户鉴权需求；确认 Flask 只绑 127.0.0.1（已是）
- [ ] **输入校验**：限制文档大小、prompt 条数上限（如 ≤30）、参考图类型与大小（image/*、单张≤10MB）、每 prompt refs≤3
- [ ] **密钥保护**：LLM API Key **不硬编码进 .py 提交**；放环境变量或 `config.local.py`（已被 `.gitignore` 的 `config.local.*`/`*.env` 覆盖）；现有 `coze_token` 的 CLIENT_ID/KID 同理（KID 非密钥可留）
- [ ] **错误处理**：LLM/Coze 错误信息不回显内部栈，给用户可读提示
- [ ] **依赖安全**：新增 `openai`（或裸 `requests`）SDK，确认版本无已知漏洞
- [ ] **其他**：参考图上传后仅用于 Coze，不落盘长期留存（或存临时目录定时清）

## 性能考虑与验证计划

- [ ] **并发**：`ThreadPoolExecutor(max_workers=CONCURRENCY)`，默认 3；每 worker 跑完整「上传→async 启动→轮询→归档」
- [ ] **轮询节流**：单批次内多个 job 各自轮询，间隔 `POLL_INTERVAL`（复用现有 3s）；总体 QPS 受并发数×动作数约束，3 并发安全
- [ ] **资源**：批次状态全在内存，N 有上限；结果图落盘归档（已有逻辑）
- [ ] **性能验证**：Phase 4 测——10 条批次端到端耗时、并发 3 vs 5 的吞吐与是否触发限流、内存占用

## 功能联动点清单

> 批量确认/进度网格是联动密集区，逐条覆盖正向/反向/批量边界。

- [ ] **解析结果可编辑**：改某条 prompt 文本 → 该条 refs 重新匹配；清空 prompt → 该条禁用「开始」
- [ ] **删除某条**（反向）：点删除 → 从批次移除，进度网格不出现该条；全部删光 → 「开始」禁用
- [ ] **参考图未匹配**（边界）：该条标红 + 警告文字；用户仍可强制生成（按无参考图）或去改文档
- [ ] **单条失败**（边界）：批次不中断，该卡片标「失败+原因+重试」；其余继续
- [ ] **全部完成**（汇总）：顶部显示「N 成功 / M 失败」，提供「重试全部失败」
- [ ] **进度实时刷新**：任一 job 状态变化 → 网格对应卡片即时更新（waiting→running→done/fail）
- [ ] **取消批次**（反向，可选）：点取消 → 已在跑的跑到完，未开始的标记取消；不杀进行中的 Coze 任务

## 运维考量清单

- [ ] **可观测性**：每条 job 打日志含 `batch_id`+序号+状态；`download_and_save` 已有 `[归档]` 日志
- [ ] **配置开关**：`CONCURRENCY`、`MAX_BATCH`、`LLM_*` 全部提取到配置区，出问题可调无需改逻辑
- [ ] **限流/降级**：Coze 限流自动退避重试；LLM 失败给「解析失败请重试/手改」降级路径
- [ ] **运维入口**（做/不做）：**后续再说**——本地工具暂不做后台页；失败重试通过前端按钮即可
- [ ] **告警/容量**（不做）：本地单机，无监控告警需求；批次上限 `MAX_BATCH` 兜底
- [ ] **可回滚**：纯新增功能，不改既有单条流程；出问题删 batch 路由即回退

## 实现步骤

### Step 1：coze_token 并发安全 + LLM 解析模块
- **目标**：让 token 在多线程下安全；新增「文档→结构化 prompt 列表」能力
- **动作**：
  - `coze_token.py`：`get_access_token` 加 `threading.Lock`（判过期+换 token 整段加锁）
  - 新建 [coze项目引入/llm_parser.py](AI-Projects/coze项目引入/llm_parser.py)：`parse_batch_document(text) -> list[{prompt, refs}]`
    - 用 OpenAI 兼容 client 调通义千问/智谱GLM（`base_url`/`api_key`/`model` 走配置）
    - 系统 prompt：按「下方独立一行是参考图名」规则拆分；强制输出 JSON 数组
    - 校验：refs 去重、>3 截断、空 prompt 丢弃；解析失败抛带提示的异常
- **文件**：`coze_token.py`、新建 `llm_parser.py`
- **依赖**：无（独立模块）
- **需人工介入**：填 `LLM_API_KEY`（智谱 bigmodel 或阿里 DashScope 控制台申请）
- **验证**：单测——喂样例文档，断言拆出 N 条且 refs 正确；并发 10 线程调 `auth_headers` 只换一次 token

### Step 2：后端——批量解析接口（含参考图匹配）
- **目标**：前端上传文档+参考图，返回可确认的拆分清单
- **动作**：在 `2_对话网页.py` 加路由 `POST /api/batch/parse`
  - 收文档文本 + 多个参考图文件（按字段名 `refs`）
  - 调 `parse_batch_document` 拆分
  - 对每条 refs 按 basename（去扩展名）匹配已上传文件 → 标记 `matched: bool`
  - 返回 `{jobs: [{idx, prompt, refs:[{name, matched}], valid}]}`，不落库
- **文件**：`2_对话网页.py`（新增路由 + 辅助匹配函数）
- **依赖**：Step 1
- **安全检查**：输入校验——文档大小、文件类型/大小
- **验证**：curl 上传样例 + 3 张图，确认返回清单 + 匹配标记正确；故意写错名确认 `matched=false`

### Step 3：后端——批量执行 + 并行调度 + 状态
- **目标**：用户确认后并行跑所有 job，可查进度
- **动作**：
  - 路由 `POST /api/batch/start`：收确认后的 jobs + 参考图；建 `batch_id`，存入内存 `BATCHES`
  - 上传参考图拿 `file_id`（复用 `upload_file_to_coze`），按 refs 组 `parameters`（最多 3，复用 `IMAGE_PARAMS` 的 `ckimg/ckimg2/ckimg3`）
  - `ThreadPoolExecutor(max_workers=CONCURRENCY)` 提交所有 job；每 worker：`start_workflow`(async)→轮询 `get_workflow_history`→`parse_workflow_output`→`download_and_save`→写回 job 状态（含 result_url/label/error）
  - 遇 Coze 限流错误 → 指数退避重试
  - 路由 `GET /api/batch/<batch_id>/status`：返回 `{jobs:[{idx,status,result_url,label,error}]}`，status ∈ waiting/running/done/fail
- **文件**：`2_对话网页.py`（新增 2 路由 + `BATCHES` 表 + 调度函数）
- **依赖**：Step 1、2；复用 `start_workflow`/`get_workflow_history`/`parse_workflow_output`/`download_and_save`
- **安全检查**：限制 `MAX_BATCH`；并发上限可配
- **验证**：curl 起 5 条批次（3 并发），轮询 status 确认 3 running→陆续 done；`downloads/` 出现归档；故意 1 条引用不存在的图确认单条失败不阻塞其余

### Step 4：前端——批量页签 UI（解析/确认/进度网格）
- **目标**：用户可视操作整个流程
- **动作**：在 [chat.html](AI-Projects/coze项目引入/chat.html) 加「批量」页签
  - 文档输入框（textarea 或上传 .txt/.md）+ 参考图多选上传（显示文件名）
  - 「解析」→ 调 `/api/batch/parse` → 渲染可编辑清单（每条 prompt 可改、refs 带匹配✓/⚠、可删）
  - 「确认开始并行生成」→ 调 `/api/batch/start` → 切到进度网格
  - 进度网格：每卡片 status + 成品图（复用 `bindZoom`）+ 类别 + 失败重试；轮询 `/status` 每 2.5s
  - 联动点全实现（删除/未匹配/单条失败/汇总/可选取消），无障碍：键盘可达、状态用文字+颜色双标
- **文件**：`chat.html`（新增批量 DOM + JS，复用现有样式与 `bindZoom`/`viewer`）
- **依赖**：Step 2、3
- **验证**：浏览器跑全流程：解析→改 1 条→删 1 条→确认→看 3 并行进度→全部出图→1 条失败点重试

### Step 5：整体验证
- **目标**：端到端跑通并复核
- **动作**：按下方「整体验证」逐项

## 整体验证（功能级）

## 术语表
| 术语 | 大白话 | 案例 |
|---|---|---|
| 异步工作流（async） | 提交后不立刻出结果，给个号去轮询 | `is_async:true` 返回 execute_id，再查 run_histories |
| ThreadPoolExecutor | 一个固定大小的工人池，任务排队领活干 | 3 个工人并发跑生图，第 4 条排队等 |
| OpenAI 兼容接口 | 换个网址和 key 就能用同一套代码调不同厂商大模型 | 智谱/通义都支持 `/v1/chat/completions` |
| basename 匹配 | 只比文件名不比路径/扩展名 | 文档写 `cat.jpg`，上传 `CAT.JPG` 也能对上 |

## 备注
- LLM 选型：用户选「通义千问/智谱GLM」，二者皆 OpenAI 兼容；默认推荐 **智谱 GLM-4-Flash**（有免费额度），`LLM_BASE_URL`/`LLM_MODEL` 可配切换到通义。
- 不改既有单条生图流程，批量作为新增页签，互不影响。
- 批次状态仅内存，重启丢失（本地工具可接受；结果已落盘 `downloads/`）。

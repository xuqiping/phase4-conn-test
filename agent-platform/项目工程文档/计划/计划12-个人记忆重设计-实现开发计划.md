完全替换旧 `user_memories` 事实抽取 + key 归一 + 冲突机模型，改为「全量聊天 io（按侧过滤）+ L0/L1/L2 分层 + 标签独立表写时归一 + 周期总结提炼层 + 总结时序冲突 pending + 流水账多挂项目成员制 ACL 共享」。旧表直接 DROP（V49），老数据不迁移（项目未上线，旧表全为测试数据）。

## 技术实现坑点预判与规避措施（全局）

| 技术点/功能块 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| halfvec 距离算子 `<=>` 在 MyBatis XML `<script>` 里 | 裸 `<` 非法 → Spring 启动崩（旧 V33 教训） | XML 转义 `&lt;=&gt;` | 启动期单测加载该 mapper，断言无解析异常 |
| `BIGINT[]`（project_ids 等）写入 | LambdaUpdateWrapper 不读 `@TableField(typeHandler=...)` → streaming 静默 fallback（旧 V33） | 显式 `set(col, val, "typeHandler=...LongArrayTypeHandler")` | 写入回读断言数组等值 |
| `memory_summary_coverage` UNIQUE 个人 scope `project_id=NULL` | PG 默认 NULL≠NULL → 约束失效，个人 scope 重复行 | `NULLS NOT DISTINCT`（PG15+/本项目 16） | IT 插两条 project_id=NULL 同 key → 第二条抛约束错 |
| 标签归一并发 | 两个会话同时同义建标签 → 建两条 | 写时 LLM 注入既有标签表优先复用 + `UNIQUE(user_id,subject,topic)` 兜底 + 别名累积 | 并发 10 线程同义词写入 → 只造一条 |
| 标签误并 | 误并不可逆，已生成 summary 的 tag_id 漂移 | **禁手动归并/拆分/重抽**；误并只能由 owner 改 label/补 aliases（tag_id 不变） | 单测断言无 merge/split 端点 |
| 总结 worker 长任务 | 阻塞对话 / 重复跑 / 跨节点双跑 | 后台 worker（类 `IndexJobWorker`）+ 任务锁 `FOR UPDATE SKIP LOCKED` + 幂等键 | 双节点同时触发 → 只跑一个 |
| LLM JSON 偶发不规范 | 解析崩 / 字段缺失 | fail-safe `applyClean` 兜底 + 重试 + 结构化输出 schema 校验 | 故意喂脏 JSON → 不抛、走兜底 |
| 时序日期 LLM 幻觉 | LLM 编年份 | 后端把 turn 真实 `created_at` 喂 prompt；禁 LLM 编年份 | 单测断言总结文本年份必匹配源 turn 真实年份 |
| 召回 N+1 | 聚合标签后逐 turn 查 coverage | 批量 `WHERE turn_id IN (...)` 一次取 coverage | 开 SQL 日志，召回一次查询数可控 |
| raw TTL worker 误删 | 删掉已生成 turn 的 raw → source_turn_ids 悬空 | worker 条件 `gen_done=false AND created_at<now()-90d`；已生成 turn raw_content 随 turn 保留 | IT 造 gen_done=true 的旧 raw → 不被删 |
| 缓存脏 | scope 变更/改写后召回读到旧集 | scope 变更/改写立即 evict `mem:` 前缀，不等 TTL | 改 scope 后立即召回 → 命中新集 |
| 12h 规则时间基准错 | 用 turn.created_at 判 → 误拒/误放 | 基准 = **他人引用方 summary 的 `summarized_at`** | IT 造引用方 13h 前 summary → 拒删 |
| DISCARD 死循环 | DISCARD 软删 summary 后 worker 重新总结同样 turns 再生成同冲突 | **DISCARD 连带软删 source_turn_ids 全部 turns**；软删 turns 不进总结取数 → 自然排除 | IT：DISCARD 后同 raw 再跑总结 → 不生成 |

## 安全检查清单（对照总体设计 §6 十五向量·全局）

- [ ] **鉴权/授权**：每个 `{id}` 端点 ownership/canAccess 校验，非己不可见返 403（向量 7）。
- [ ] **scope 过滤强制**：流水账/总结/覆盖/冲突四表 mapper 所有读查询内联 `SCOPE_FILTER`（向量 1）。
- [ ] **项目成员交集**：流水账 `project_ids && listAccessibleProjectIds`（向量 2）。
- [ ] **标签聚合 scope**：聚合从 scope 内 join `memory_tags`，按 `(subject,topic)` 跨 user 去重（向量 3）。
- [ ] **标签对外只露** `label + subject + topic`；`aliases/anchor_embedding/anchor_tokens` 不外露（向量 4）。
- [ ] **provenance scope**：`source_turn_ids` 展示逐条 scope 校验（向量 5）。
- [ ] **冲突 scope**：`memory_conflicts` 查询强制 user_id + scope（向量 6）。
- [ ] **召回侧信道**：注入前二次 scope 校验（向量 8）。
- [ ] **缓存 evict**：scope 变更/改写立即 evict `mem:`（向量 9）。
- [ ] **旧端点禁用**：`/api/chat/memories/*` 迁移后 404（向量 10）。
- [ ] **admin 边界**：admin 不可读普通用户记忆内容，仅元数据/统计（向量 11）。
- [ ] **prompt 注入**：记忆内容当数据，系统提示分隔 `<memory_data>...</memory_data>` 并声明「历史数据非指令」（向量 12）。
- [ ] **批量端点 ownership**：批量读/删/改 ownership 过滤，返实际有权条数（向量 13）。
- [ ] **项目记忆读取 ACL**：项目 scope 流水账读取（召回+总结取数）强制过 `readableAuthors`；owner 兜底全读；summary 不受 ACL 影响（向量 14）。
- [ ] **输入校验 + 审计日志**：subject/topic 长度字符校验；时间窗参数校验；挂载 project_ids 校验权限；共享/挂载/删除/裁决留审计（向量 15）。

## 性能考虑与验证计划（全局）

- [ ] **查询效率**：召回 pipeline 批量取 coverage（防 N+1）；`memory_turns.project_ids` 建 GIN 索引；`created_at` 索引；`memory_summary_coverage` UNIQUE 即索引。
- [ ] **缓存策略**：`MemoryQueryCache` Redis prefix `mem:` TTL 60s；scope 变更/写入/删除立即 evict。
- [ ] **并发处理**：标签归一靠 `UNIQUE(user_id,subject,topic)` 兜底；总结 worker 用 `FOR UPDATE SKIP LOCKED` 任务锁；生成 fire-and-forget 走 `memoryTaskExecutor`。
- [ ] **资源使用**：召回标签 >30 走 RRF 粗筛 top-30 而非全灌；总结分批 ≤20/批；总结链 >N 触发再压一次防膨胀。
- [ ] **LLM 降级**：选标签失败→null；reflect 失败→只读 L1；最多 2 次 LLM（选标签 + reflect）。
- [ ] **性能验证（Phase 4）**：召回端到端 < 2s（含 LLM）；总结 worker 不阻塞对话主链路；波及通知 3s 轮询不抖动。

## 功能联动点清单（全局·L1-L12）

> Phase2 v1.3 重点。每条含**触发动作 / 联动对象 / 预期变化 / 边界（反向·半选·取消·批量）**。各子 plan 仅引用相关条目，边界全集合在此。

### L1. gen 开关切換（owner 项目级 AND 会员覆写）
- **触发**：owner 改项目 gen 开关 / 会员改个人覆写开关。
- **联动**：新对话是否调生成 LLM → 是否写 raw（`gen_done=false`）→ 顶端说明条（M3）→ raw 90 天 TTL 是否适用。
- **边界**：owner 关 → 会员覆写无效（项目侧不再生成）；会员关 + owner 开 → 仍写 raw 不生成；两侧前置过滤独立跑，不被开关跳过；双侧都被过滤 → 不写 raw 也不调 LLM。

### L2. 召回 scope 多选（个人 ∪ 项目）
- **触发**：用户勾/取消 scope 复选项。
- **联动**：聚合标签集 → 召回候选 turns/summary → 持久化上次选择（新会话沿用）。
- **边界**：取消全部 → 空召回（不报错，返回空）；首次无历史默认 `{个人}`；勾离职人员但「同步已离开人员」开关关 → 仍不召回（开关优先级高于多选）；多选 = 并集非交集。

### L3. 写入目标多选（与召回解耦，默认 `{个人}`）
- **触发**：用户勾/取消写入目标（个人/项目）。
- **联动**：`born_personal` 定死 → `project_ids` 叠加共享 → 哪些项目成员可读。
- **边界**：卸空所有项目 → `born_personal` 自动转 true（防无归属）；首次勾项目弹确认（含 12h 规则提示）；首次取消 `{个人}` 弹确认（「新记忆不在个人记忆显示」）；非项目会话恒 `{个人}` 不可选项目；默认**不跟随召回 scope**（避免读项目记忆时新隐私被共享）。

### L4. 冲突裁决四选项
- **触发**：作者在冲突 pending 上选 KEEP_BOTH / KEEP_NEW / KEEP_OLD / DISCARD。
- **联动**：`memory_conflicts` 置 resolved → summary `status` 从 `PENDING_CONFLICT` 转出 → coverage 行随之增删 → 缓存 evict。
- **边界**：KEEP_BOTH → 两条都留，按 `created_at` 自动排序，用户不填日期；KEEP_NEW/KEEP_OLD → 留一条、另一条 summary 软删（turns 不动）；**DISCARD → 连带软删冲突 summary 及其 `source_turn_ids` 全部 turns**（走 §3.8 级联：他人引用的 summary STALE+重压缩+波及通知；**12h 规则适用**——source turns 被他人引用且引用方 `summarized_at>12h` → DISCARD 拒绝 403，提示改 KEEP_OLD/KEEP_BOTH；软删 turns 后下次总结取数自然排除，防死循环）；非作者不可裁决；无跨用户编辑冲突。

### L5. 成员离职/被踢
- **触发**：`memory_project_members` 置 `DEPARTED` + `departed_at`。
- **联动**：该用户挂该项目的 turns 追加 `departed_project_ids` → 别人召回按离职开关判 → 作者本人召回 scope 选项锁定（不可选原项目）。
- **边界**：不删行不删数据（保交接）；本人 `born_personal=true` 记忆仍经个人 scope 召回不受影响；本人补救走 copy-to（copy 非 move，原项目零改动）；写入目标不可选已离开项目。

### L6. 项目删除
- **触发**：项目被删。
- **联动**：turns 追加 `deleted_project_ids`（不从 project_ids 移） → 清该项目 summary/coverage/members 行 → 曾写记忆的每个成员收 `PROJECT_DELETED_AFFECTED` 通知 → 前端折叠板 badge。
- **边界**：个人 summary（`project_id=NULL`）不清；个人 scope 召回不受影响；补救 restore 仅拉 turn 不拉 summary；通知 3s 轮询。

### L7. 流水账撤回/删除 + summary 级联
- **触发**：`DELETE /api/chat/memory/turns/{id}`（仅作者本人）。
- **联动**：软删 turn → 查 `source_turn_ids @> [T.id]` 的 summary → 受影响 summary `status=STALE` + 删 coverage 行 → worker 从剩余 `source_turn_ids - T` 重压缩 → 跨用户波及写 `SUMMARY_AFFECTED_BY_RECALL` 通知。
- **边界**：他人引用且引用方 `summarized_at > 12h` → 拒删 403；无他人引用 → 作者随时删；个人 scope 删不发通知；整条级 STALE 重生（flat provenance 无法片段摘除）；DISCARD 走同一级联。

### L8. 手动总结勾选 scope（统一「开始总结」入口）
- **触发**：用户在弹框勾 scope 跑手动总结。
- **联动**：每个 scope 按有无变化标可选/灰选 → 勾选 → 先 backfill 该 scope raw（≤20/批）→ 按 (user,tag,scope) 分组取数压缩 → 写 summary + coverage。
- **边界**：无变化 = 灰选；手动独立于任何 gen/总结开关；gen 关态定时不 backfill raw，手动才 backfill。

### L9. 自动总结勾选 scope
- **触发**：用户在弹框勾 scope 加入自动。
- **联动**：`memory_consolidation_scopes` upsert（`auto_enabled=true`）→ 定时周期（默认每天）→ 跑前判该 scope 该周期有无新增未总结 turn，无则空跳过。
- **边界**：默认勾 `{个人}`；项目默认不勾（用户主动加）；未来更新未知 → 全可选不灰选；gen 关态定时仅总结已生成 turn。

### L10. 「同步召回已离开项目人员」开关
- **触发**：项目 scope 召回时开关开/关。
- **联动**：召回候选集（含/排除离职人员）→ 总结取数候选集（同套）→ 离职人员条目带「已离开人员·{用户名}·{departed_at}」标注。
- **边界**：优先级**高于**人员多选（勾了离职人员也召回不到）；同时控召回与总结取数；默认开。

### L11. 流水账挂载项目（project_ids 增减）
- **触发**：用户显式 API/UI 挂/卸项目。
- **联动**：哪些项目成员可读（经 ACL）→ 召回 scope 命中 → `born_personal` 不改（卸空除外）。
- **边界**：首次挂载弹确认；可多挂；卸空转个人出身；ACL 未授权的读者读不到。

### L12. 标签归一命中（写时）
- **触发**：写入 turn 前解析标签。
- **联动**：精确 label / aliases / anchor ≤0.25 二次 LLM 判 / 全 miss 新建 → 复用时 `usage_count++`、语义同滚进 aliases → `tag_id` 复用进 turn。
- **边界**：误并不可逆 → 禁归并/拆分/重抽；仅 owner 改 label/补 aliases（tag_id 不变，anchor 重生属预期纠错）。

## 功能清单

### ✅ 功能 1: 共享工具函数
**文件位置**: `src/utils/file.ts`

**功能说明**:
- `deriveIconFromExt(filename)` — 根据文件扩展名自动推断图标类型
  - `.doc/.docx` → word 图标
  - `.xls/.xlsx` → excel 图标
  - `.png/.jpg/.jpeg/.gif` → image 图标
  - `.js/.ts/.py/.java` → code 图标
  - 其他 → file 图标
- `resolveGroupId(currentGroupId, customGroupId)` — 智能解析分组 ID
  - 当前在"全部"或"最近"时自动切换到自定义分组
  - 其他情况保持当前分组

**单元测试**: ✅ 10 个测试全部通过 (`src/utils/__tests__/file.test.ts`)

**测试方法**: 
这是底层工具函数，其他功能会自动使用。可以通过添加不同类型的文件来观察图标是否正确显示。

**测试结果**:
- [ ] 图标自动匹配正确
- [ ] 分组 ID 解析逻辑正确

### ✅ 功能 8: 进程管理（关闭已打开的文件）
**文件位置**: 
- `src-tauri/src/platform/` (跨平台进程检测)
- `src-tauri/src/commands/processes.rs` (Rust 命令)
- `src/api/processes.ts` (前端 API)
- `src/App.vue` (进程管理对话框)

**功能说明**: 
检测并关闭正在使用文件的进程（核心特色功能）

**测试步骤**:
1. **准备测试文件**:
   - 添加一个 `.txt` 文件到 File Keeper
   - 用记事本打开该文件（不要关闭）

2. **查看进程**:
   - 在 File Keeper 中右键点击该文件
   - 选择 **"关闭已打开的进程"**
   - 观察进程管理对话框是否显示：
     - 进程名称（例如 "notepad.exe"）
     - 进程 PID
     - 窗口标题（例如 "test.txt - 记事本"）
     - 进程路径

3. **关闭进程**:
   - 点击进程卡片右侧的 **"关闭"** 按钮
   - 在确认对话框中点击确定
   - 观察记事本是否立即关闭
   - 点击 **"刷新"** 按钮，检查进程列表是否更新

4. **测试多种文件类型**:
   - Word 文档 (.docx)
   - Excel 表格 (.xlsx)
   - PDF 文件 (.pdf)
   - 图片文件 (.png, .jpg)
   - 代码文件 (.js, .py)

5. **测试边界情况**:
   - 文件未被任何进程打开（应显示 "未找到打开此文件的进程"）
   - 同一文件被多个进程打开（应显示所有进程）
   - 关闭系统进程（应显示权限错误）

**预期结果**:
- Windows: 95%+ 准确率（基于窗口标题匹配）
- 进程扫描时间 < 200ms
- 关闭进程前有确认对话框
- 关闭失败时显示友好错误提示
- 对话框有三种状态：Loading（加载中）、Empty（无进程）、List（进程列表）

**已知限制**:
- 无法检测没有窗口标题的后台进程
- 部分系统进程需要管理员权限才能关闭
- macOS 和 Linux 实现未在实际硬件上测试

**测试结果**:
- [ ] 记事本进程检测正常
- [ ] Word 进程检测正常
- [ ] Excel 进程检测正常
- [ ] PDF 阅读器进程检测正常
- [ ] VS Code 进程检测正常
- [ ] 进程信息显示完整（PID、名称、路径、窗口标题）
- [ ] 关闭进程功能正常
- [ ] 刷新按钮正常
- [ ] 未打开文件时显示空状态
- [ ] 多进程同时显示正常

#### ✅ 功能 13 - 拖拽虚影跟随鼠标
**问题描述：** 拖拽文件卡片时，虚影不跟随鼠标移动，钉死在原位置

**根本原因：** `.sortable-fallback` CSS 用 `!important` 强制覆盖了 `transform`、`position` 等属性，sortablejs 通过这些内联属性控制虚影位置，被覆盖后虚影无法跟随鼠标

**修复方案：**
- 移除所有定位相关的 `!important`（transform, position, top, left 等）
- 只保留视觉效果样式（阴影、圆角、光圈、cursor）
- 让 sortablejs 自己控制虚影位置，CSS 只负责美化外观
- 优化 `.sortable-ghost` 占位符样式（半透明蓝色虚线框 + 隐藏子元素）

**测试结果：** ✅ 拖拽虚影正常跟随鼠标，类似 Windows 资源管理器的拖拽体验

**修改文件：**
- `src/App.vue` — 重写 sortable 相关 CSS（行 1272-1314）

#### ✅ 快捷键冲突报错修复
**问题描述：** 频繁弹框报错 `快捷键更新失败：Failed to unregister hotkey`

**根本原因：** 当注册新快捷键失败时（如被其他程序占用），代码仍把新值写入 settings store。下次保存时，`unregister(oldShortcut)` 尝试注销一个从未真正注册到 OS 的快捷键，导致报错

**修复方案：**
- 新增 `registeredShortcut` 变量追踪真正已注册到 OS 的快捷键（与 store 解耦）
- `unregister` 基于 `registeredShortcut` 而非 store 值
- `unregister` 失败时降级为 `console.warn`（不阻塞用户）

# Network Security Workflow

## Purpose

基于网络基础安全知识体系，为用户提供TCP/IP分层防御、防火墙/WAF纵深防线、渗透测试攻防验证、DDoS流量防护等技术方案支持。覆盖eBPF/XDP云原生网络标配、AI协议模糊测试CVE发现效率提升300%、Rust替换C/C++内存安全重构、WAF六层规则体系、DDoS 7T时代31.4Tbps、AI智能清洗3秒识别132维特征等2026核心趋势。

## Prerequisites

- 用户已明确网络基础安全场景或问题
- 知识库文件 `07_网络安全与信息安全.md` 及子目录文件可访问

## Steps

### Step 1: 识别网络基础安全需求场景

**Goal**: 明确用户的网络安全需求类型、防护层级和资产规模
**Completion criterion**: 已确定场景标签、防护边界、攻击面规模和合规要求

1. 读取用户消息，提取以下信息：
   - 场景类型：边界防护 / Web应用防护 / 渗透测试 / DDoS防护 / 协议安全 / 网络架构安全 / 云原生网络安全
   - 防护边界：互联网边界（公网暴露） / 内网分区（DMZ/生产/办公/开发隔离） / 多云互联（跨云VPC/专线/SD-WAN） / 混合云（IDC+云）
   - 攻击面规模：公网IP数量、暴露端口/服务数量、域名数量、第三方接入点数量
   - 合规要求：等保级别（二级/三级/四级） / 关保（关键信息基础设施） / 行业监管（金融/电信/能源）
   - 现有工具：防火墙品牌型号、WAF部署方式（硬件/软件/云原生）、IDS/IPS部署状态、DDoS防护服务商
   - 关键痛点：规则误报率高 / 告警噪音大 / 防护盲区 / 0day漏洞响应慢 / DDoS攻击频繁 / 内网横向移动

2. 对照知识库中的典型架构初步判断：
   - 公网Web应用防护 → WAF六层规则（签名+语义+AI模型+业务+频率+Bot管理）
   - 渗透测试需求 → PTES七阶段+MITRE ATT&CK+AI驱动自动化
   - DDoS高频攻击 → 分层防御（边缘CDN吸收→Anycast分散→主机内核优化→应用层限流）
   - 云原生环境 → eBPF/XDP微分段+零信任网络
   - 协议层安全 → TCP/IP分层防御+QUIC/HTTP3适配+IPv6扩展头安全

3. 如有信息缺失，向用户追问不超过2个澄清问题。

### Step 2: 输出网络基础安全方案

**Goal**: 产出针对性的网络防御架构、渗透测试计划或DDoS防护方案
**Completion criterion**: 输出包含推荐架构、防护策略、工具选型、实施路径

根据Step 1确定的场景，按以下分支处理：

**分支A — TCP/IP分层防御与协议安全**：
1. 输出分层防御模型：
   - 物理/链路层：物理隔离（敏感网络独立布线）、端口安全（802.1X认证）、链路加密（MACsec/IPsec隧道）
   - 网络层：IPSec VPN（站点互联）、边界路由ACL（源/目的IP/端口/协议过滤）、Anycast分散（DDoS流量分散到全球节点）、IPv6安全（扩展头过滤/邻居发现协议安全/RA Guard）
   - 传输层：TLS 1.3（强制前向保密+缩短握手）、QUIC/HTTP3（UDP 35%流量占比形成DPI盲区、内置加密+连接迁移）、TCP安全（SYN Cookie防SYN Flood/SACK Panic补丁）
   - 应用层：HTTPS强制（HSTS预加载）、DNS安全（DNSSEC防劫持/DoH/DoT防监听）、邮件安全（SPF/DKIM/DMARC防钓鱼）
   - 每层假设上层可能失效 → 纵深防御（Defense in Depth）
2. 给出云原生网络增强：
   - eBPF/XDP：数据包在进入内核前完成安全策略执行（防火墙/负载均衡/流量监控）、Cilium（基于eBPF的K8s网络策略）、性能损耗<1%
   - Service Mesh安全：Istio mTLS（服务间自动加密通信）、Envoy RBAC（细粒度访问控制）、可观测性（L7流量追踪+安全审计）
   - 微分段：工作负载间零信任通信（默认拒绝+显式允许）、基于身份（而非IP）的访问控制
3. 输出协议安全新趋势：
   - Rust内存安全重构：以Rust替换C/C++重写协议栈（如Windows内核Rust重写、Linux内核Rust模块），消除缓冲区溢出/UAF等内存漏洞
   - AI协议模糊测试：AFL++/LibFuzzer+LLM生成畸形协议包→自动发现漏洞，CVE发现效率提升300%，Microsoft连续修复280+TCP/IP漏洞（含wormable RCE）
   - QUIC/HTTP3适配：传统DPI设备需升级支持QUIC解析、UDP流量监控策略调整、连接迁移带来的会话追踪挑战

**分支B — 防火墙与WAF纵深防线**：
1. 输出防火墙选型演进：
   - 包过滤防火墙：基于IP/端口/协议，简单高效但无法识别应用层攻击
   - 状态检测防火墙：跟踪连接状态（TCP握手/会话建立），支持状态表
   - UTM（统一威胁管理）：防火墙+IPS+VPN+AV+内容过滤集成，功能全但性能瓶颈
   - NGFW（下一代防火墙）：应用识别（App-ID）、用户识别（User-ID）、内容识别（Content-ID）、SSL解密、威胁情报集成
   - SASE（安全访问服务边缘）：云原生安全栈（SD-WAN+零信任+CASB+SWG+防火墙即服务），2026主流架构
   - 选型建议：SMB→UTM/云防火墙；中大型企业→NGFW+SASE混合；金融/政府→国产防火墙（天融信/深信服/华为/新华三）+等保合规
2. 给出WAF六层规则体系：
   - L1 签名规则：基于已知攻击特征库（SQL注入/XSS/路径遍历等），更新频率（每日/每小时自动更新）
   - L2 语义分析：基于语法树解析SQL/XML/JSON，识别变形攻击（编码绕过/注释混淆/大小写混合）
   - L3 AI模型：基于深度学习的异常流量检测，识别未知攻击模式（0day/变种），误报率控制
   - L4 业务规则：基于业务逻辑（如"下单频率>10次/秒"视为Bot攻击、"密码错误>5次"触发锁定）
   - L5 频率控制：CC攻击防护（单IP请求速率限制）、Bot管理（人机验证/滑块/行为分析）
   - L6 智能Bot管理：区分善意Bot（搜索引擎/监控探针）和恶意Bot（爬虫/撞库/CC），动态挑战策略
   - 开源WAF：雷池SafeLine（GitHub Star破4万、3小时完成部署、国产开源）、ModSecurity（老牌、规则丰富）、Coraza（Go语言、ModSecurity兼容）
3. 输出纵深防御架构模板：
   - 互联网边界：CDN（DDoS吸收+缓存加速）→ 抗D设备 → WAF（应用层攻击过滤）→ 负载均衡 → 应用服务器
   - 内网分区：DMZ（对外服务）→ 核心生产区（数据库/核心业务）→ 办公区（OA/邮件）→ 开发测试区，每区之间防火墙隔离
   - 某城商行案例：边缘CDN+抗D → 硬件WAF集群（协议层）→ RASP（运行时自保护）→ 数据库审计四层把关，SOC统一运营+季度红蓝演练，2年零成功Web入侵
4. 附OWASP TOP 10 2025变化：权限失效跃居首位、SSRF独立为新类别（云元数据API攻击链+LLM Agent工具调用）、配置错误、敏感数据暴露、不安全设计等。

**分支C — 渗透测试与攻防验证**：
1. 输出渗透测试方法论：
   - PTES七阶段：前期交互（范围/目标/规则）→ 情报收集（OSINT/域名/IP/员工信息）→ 威胁建模（攻击路径分析）→ 漏洞分析（扫描+手工验证）→ 渗透攻击（利用漏洞获取权限）→ 后渗透（横向移动/权限维持/数据提取）→ 报告（风险评级+修复建议+复测验证）
   - MITRE ATT&CK映射：将发现的攻击技术与ATT&CK知识图谱对齐，评估覆盖的战术和技术，识别防御盲区
   - AI驱动渗透：自动化漏洞扫描（Nuclei/OWASP ZAP）→ AI分析结果→ 自动利用框架（Metasploit/Cobalt Strike）→ 报告生成，效率提升3-5倍
   - 全自动框架：RapidPen（AI驱动全自动渗透，从侦察到报告）、AutoGPT安全版（自主漏洞发现+利用链构建）
2. 给出漏洞管理闭环：
   - 漏洞发现：SAST（静态分析）+ DAST（动态扫描）+ SCA（依赖扫描）+ 渗透测试 + 红队评估 + 漏洞赏金（Bug Bounty）
   - 评分体系：CVSS（基础评分/时间评分/环境评分）+ EPSS（漏洞利用概率预测）+ CISA KEV（已知被利用漏洞目录）→ 动态优先级排序
   - 修复闭环：高危漏洞24小时/7天/30天SLA、补丁管理（测试→灰度→全量）、补偿控制（WAF规则临时缓解）、验证复测
   - SBOM供应链：软件物料清单（组件/版本/许可证/漏洞状态），成为供应链漏洞管理标配，CycloneDX/SPDX格式
3. 输出红蓝对抗体系：
   - 红队：模拟真实APT攻击（长期潜伏/多阶段/社会工程/物理渗透），目标测试防御体系韧性
   - 蓝队：监控检测→分析研判→遏制根除→恢复加固，提升MTTD（平均检测时间）和MTTR（平均响应时间）
   - 紫队：红蓝协同，红队攻击后蓝队即时分析，共同优化检测规则和响应流程
   - 护网行动：国家级攻防演练（每年一次、10万+单位参与）、ATT&CK框架评分、防守方加分项（发现攻击/溯源/反制）
4. 附攻击面管理（ASM）：持续发现资产（域名/IP/端口/服务/云资源）→ 漏洞关联→ 风险评分→ 优先级排序→ 自动修复/通知Owner。

**分支D — DDoS防护**：
1. 输出DDoS威胁演进：
   - 容量型（Volumetric）：UDP Flood/ICMP Flood/NTP反射/DNS反射，目标占满带宽（Cloudflare记录31.4Tbps）
   - 协议型（Protocol）：SYN Flood/SYN-ACK Flood/ACK Flood/ fragmentation攻击，目标耗尽连接表/CPU
   - 应用型（Application）：HTTP Flood/Slowloris/RUDY/L7 CC攻击，目标耗尽应用层资源（连接池/线程/数据库）
   - 新型威胁：AI智能体自主生成1.2Tbps攻击（每请求特征唯一，绕过基于签名的检测）、IoT僵尸网络调度50万节点（Mirai变体）、Memcached反射放大（1:51000放大率）
2. 给出分层防御架构：
   - 边缘层（CDN/Anycast）：全球节点分散流量、DNS流量分散（Anycast BGP）、Cloudflare/阿里云DDoS高防/AWS Shield
   - 网络层（运营商/ISP）：流量清洗中心（近源清洗/远目的清洗）、BGP Flowspec（自动下发黑洞路由）、RTBH（远程触发黑洞）
   - 主机层（内核优化）：SYN Cookie、TCP SYN队列扩容、内核参数调优（net.ipv4.tcp_max_syn_backlog）、连接数限制
   - 应用层（WAF/限流）：请求速率限制（Token Bucket/Sliding Window）、服务降级（非核心功能关闭）、验证码挑战（人机验证）
   - 某金融机构案例：AI智能清洗3秒识别、132维特征、误杀率0.3%、自动切换清洗中心
3. 输出AI智能清洗技术：
   - 流量特征分析：132维特征向量（包大小分布/时间间隔/源IP熵值/HTTP头模式/请求路径分布）
   - 模型训练：正常流量基线（7天/30天历史数据）→ 实时异常检测（Isolation Forest/Autoencoder/LSTM）→ 3秒内判定攻击
   - 动态策略：攻击开始时严格模式（高拦截率）→ 持续期学习模式（减少误杀）→ 结束后恢复模式
   - 人机验证：滑动验证码/无感验证（行为分析+设备指纹）/图形验证码（对Bot高拦截、对用户体验影响小）
4. 附应急响应：DDoS告警触发→自动切换高防IP→清洗中心上线→业务恢复监控→攻击溯源（源IP分析/反射源定位/僵尸网络追踪）→ ISP协同封堵→ 事后复盘（攻击特征入库/规则更新）。

将结果保存到 `output/network_security.md` 或直接在对话中呈现。

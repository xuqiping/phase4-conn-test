# 互动式 AI 工作助手规划

> 基于联网调研（飞书/钉钉/企微/Slack 机器人、AI PKM、AI 日报助手）与当前工作汇报模块现状，对“推送后接受用户互动、自动标记完成、自然语言录入工作内容、灵感随记分类与 AI 总结推送”需求的优化与落地规划。

---

## 1. 背景与目标

### 1.1 当前状态

- 工作汇报模块已支持：工作记录、固定工作、未来计划、报告配置、AI 总结、定时生成、推送到飞书/钉钉/企业微信/Slack。
- 推送是**单向**的：桌面端 → 服务端 → IM 平台。
- 用户无法在 IM 中回复机器人，也无法让机器人把外部输入写回工作汇报模块。

### 1.2 用户原始诉求

1. 推送每日固定工作安排后，用户在 IM 中说“某项完成”，桌面端接收并标记完成。
2. 下次推送总结时，AI 能总结哪些未完成；周报里能看到“哪些天、哪些任务”没完成。
3. 用户可通过 IM 发送工作内容，自动写入工作内容模块。
4. 新增“灵感随记”模块，可分类别；在推送指定灵感汇报时，AI 做总结推送。

### 1.3 目标

把 File Keeper 桌面端从“单向汇报工具”升级为“个人 AI 工作助手”：

- **低摩擦捕获**：用户在最常用的 IM 里用自然语言与机器人互动。
- **自动整理**：机器人把外部输入解析为任务完成、工作记录、灵感随记等结构化数据。
- **智能回顾**：基于完成状态、工作记录、灵感，生成更立体的日报/周报/灵感报告。

## 2. 用户真实需求挖掘（基于联网调研）

### 2.1 关键发现

| 调研方向 | 核心洞察 | 来源 |
|---------|---------|------|
| 飞书机器人周报 | 企业实践已从“手动写周报”转向“碎片记录 + AI 字段 + 定时推送”，神州数码案例中单份周报耗时从 32 分钟降到 8 分钟。 | [神州数码飞书效率先锋](https://www.pingwest.com/w/303214) |
| 钉钉/企微机器人 | 钉钉支持 @机器人回调，适合复杂交互；企业微信普通群机器人以主动推送为主，被动交互需自建应用。 | [制作钉钉企业内部机器人](https://juejin.cn/post/6871975028489977864) |
| Slack 自动化 | Zapier/n8n 普遍采用“定时提问 → 收集回复 → AI 汇总 → 推送 digest”的异步 standup 模式。 | [Zapier Slack standups](https://zapier.com/templates/details/async-weekly-standup-automation-slack) |
| AI PKM | 市场从“笔记存储”转向“Capture → Categorize → Summarize → Push/Act”的主动知识助手。 | [Build a Personal Knowledge Management System with AI in 2025](https://buildin.ai/blog/personal-knowledge-management-system-with-ai) |
| 灵感笔记 | flomo 等产品验证“无压记录、标签分类、每日回顾、随机漫步”是灵感管理的核心心智。 | flomo 产品理念（搜索摘要） |
| AI 日报助手 | 主流方案是“聊天记录/工时数据 → AI 摘要 → 标准四段式输出（已完成/进行中/计划中/风险）”。 | [自动整理微信聊天记录 + 生成周报](https://juejin.cn/post/7631148067781214217) |

### 2.2 需求升维

用户说的不是“我想在 IM 里回消息”，而是：

> **“我希望有一个无处不在的入口，用最低成本把工作状态和灵感喂给系统，然后由 AI 自动整理成我需要的报告。”**

因此，功能不应零散地加，而应抽象为三层：

1. **输入层**：IM 机器人、桌面端、快捷指令、语音/图片（未来）。
2. **理解层**：意图识别、实体抽取、分类、去重、校验。
3. **输出层**：任务状态更新、工作记录、灵感库、日报、周报、灵感报告。

## 3. 优化后的产品需求

### 3.1 核心概念

| 概念 | 说明 |
|------|------|
| **互动收件箱（Inbox）** | 所有来自 IM 的原始输入先进入此处，用户可在桌面端确认、编辑、归档或忽略。 |
| **自然语言指令** | 用户用日常语言表达意图，如“完成日报机器人设计”、“记录灵感：AI 日报应支持情感分析 #产品/灵感”。 |
| **固定工作完成状态** | 固定工作每日/每周/每月生成一条“待完成实例”，用户可单独标记某一天是否完成。 |
| **灵感随记** | 轻量卡片，支持标签、来源（IM/桌面）、关联项目/报告，支持每日回顾与主题总结。 |
| **AI 报告增强** | 报告模板可引用 `fixedWorkCompletion`（固定工作完成率）、`inboxItems`（外部录入）、`inspirationNotes`（灵感）等上下文。 |

### 3.2 优化需求列表

#### R1：IM 双向通道

- 后端提供各平台 webhook 接口接收机器人回调。
- 桌面端通过 WebSocket/SSE 接收来自后端的“互动事件”。
- 支持飞书、钉钉、Slack 的事件订阅；企业微信因普通群机器人限制，首期以“主动@企业微信自建应用”或“先用飞书/钉钉”为主。

#### R2：自然语言理解

- 识别意图：`complete_fixed_work`（完成固定工作）、`add_work_log`（添加工作记录）、`add_inspiration`（添加灵感）、`query_report`（查询报告）、`help`（帮助）。
- 抽取实体：任务名称/ID、日期、内容、标签、分类。
- 置信度低时放入 Inbox 等待人工确认，不直接写库。

#### R3：固定工作按实例追踪

- 固定工作（日/周/月）不再只有一条记录，而是按周期生成 `FixedWorkCompletion` 实例。
- 实例状态：`PENDING`、`COMPLETED`、`SKIPPED`、`MISSED`。
- 用户可在 IM 中回复“完成 xxx”标记当天实例完成；也可在桌面端手动补录/修改。

#### R4：工作内容自然语言录入

- 用户发送“今天做了……”，AI 解析为工作记录（内容、日期、标签、来源=IM）。
- 支持指定日期：“昨天/周一/6 月 25 日”。
- 支持追加到现有记录或新建记录。

#### R5：灵感随记模块

- 卡片式记录：内容、标签（支持多级 `#Area/Project`）、来源、创建时间、关联报告配置。
- 支持多渠道输入：桌面端快捷输入、IM 发送“灵感：……”。
- 每日回顾：定时推送历史灵感到 IM 或桌面通知。
- 主题总结：按标签/时间范围生成灵感总结报告。

#### R6：AI 报告增强

- 日报/周报模板新增上下文变量：
  - `fixed_work_completion_rate`：固定工作完成率。
  - `fixed_work_miss_log`：逾期未完成的日期与任务列表。
  - `inbox_work_logs`：IM 录入的工作记录。
  - `inspiration_digest`：指定周期内的灵感摘要。
- AI 总结提示词可基于上述变量生成“已完成/未完成/风险/下周重点”。

## 6. 核心流程

### 6.1 IM 消息进入 Inbox

```
用户在飞书@机器人：完成日报设计
        ↓
飞书 POST /api/client/work-report/webhook/feishu
        ↓
FeishuWebhookAdapter 验签 + 提取 sender/text/msgId
        ↓
WebhookService 写入 inbound_messages (status=PENDING)
        ↓
NLPService 意图识别：complete_fixed_work, confidence=0.92
        ↓
更新 inbound_messages.parsed_payload
        ↓
WebSocket/SSE 推送到桌面端
        ↓
桌面端 InboxPanel 显示待确认项
```

### 6.2 高置信度自动确认

若 confidence ≥ 0.85 且 intent 明确：

```
直接执行对应业务操作
        ↓
更新 inbound_messages.status=CONFIRMED, target_id=...
        ↓
可选：回复 IM 一条确认消息
```

### 6.3 固定工作完成标记

```
用户：完成日报设计
        ↓
匹配固定工作“日报设计”（模糊匹配 + LLM）
        ↓
查找/创建当天的 FixedWorkCompletion 实例
        ↓
状态更新为 COMPLETED
        ↓
下次生成报告时，按 scheduled_date 汇总完成状态
```

### 6.4 灵感随记录入

```
用户：灵感：AI 日报应支持情感分析 #产品/灵感
        ↓
解析 content + tags
        ↓
创建 inspiration_notes
        ↓
桌面端实时同步到 InspirationPanel
        ↓
按 report_config_ids 在指定报告生成时做 AI 总结
```

## 7. 改造计划（分阶段）

### 第一阶段：基础设施（MVP，约 1-2 周）

**目标**：打通“IM 输入 → 后端解析 → 桌面端展示 → 写回业务库”的最小闭环。

| 任务 | 优先级 | 说明 |
|------|--------|------|
| 后端 Webhook 框架 | P0 | 平台抽象 `PushWebhookAdapter`，统一入站消息 DTO。 |
| 飞书 webhook 接入 | P0 | 事件订阅 `im.message.receive_v1`，验签，写入 inbound_messages。 |
| NLP 意图识别（规则版） | P0 | 用正则/关键词识别 `完成`、`记录`、`灵感`、`帮助` 等意图。 |
| Inbox 后端 CRUD | P0 | InboxService、InboxRepository、状态流转。 |
| WebSocket/SSE 推送 | P0 | 桌面端长连接接收互动事件。 |
| 桌面端 InboxPanel | P0 | 展示待确认项，支持确认/忽略/编辑。 |
| 固定工作完成实例 | P1 | 按周期生成实例，支持 IM 标记完成。 |

### 第二阶段：自然语言与灵感（约 1-2 周）

| 任务 | 优先级 | 说明 |
|------|--------|------|
| LLM 意图识别 | P0 | 规则兜底，LLM 处理复杂句。 |
| 工作内容自然语言录入 | P0 | 解析日期、内容、标签，写入 work_log。 |
| 灵感随记模块 | P0 | 后端实体 + API + 桌面端面板 + 标签管理。 |
| 钉钉/Slack webhook | P1 | 复用适配器，接入更多平台。 |
| IM 确认回复 | P1 | 操作成功后机器人回复确认消息。 |

### 第三阶段：AI 报告增强（约 1 周）

| 任务 | 优先级 | 说明 |
|------|--------|------|
| 固定工作完成率上下文 | P0 | 报告模板新增完成率、逾期日志变量。 |
| 灵感总结报告 | P0 | 按标签/周期生成灵感 AI 总结并推送。 |
| 报告模板变量扩展 | P1 | 支持 inbox_work_logs、inspiration_digest。 |
| 周报逾期分析 | P1 | AI 生成“本周固定任务完成情况 + 连续未完成天数”。 |

### 第四阶段：体验优化（约 1 周）

| 任务 | 优先级 | 说明 |
|------|--------|------|
| 每日灵感回顾推送 | P1 | 定时推送历史灵感到 IM。 |
| 快捷指令菜单 | P1 | 机器人输入 `/help` 查看可用指令。 |
| 移动端轻量化 | P2 | 仅通过 IM 交互，无需打开桌面端。 |
| 企业微信深度适配 | P2 | 若需企业微信回调，接入自建应用。 |

## 9. 后端改造

### 9.1 新增 Controller

| 接口 | 路径 | 说明 |
|------|------|------|
| 飞书 webhook | `POST /api/client/work-report/webhook/feishu` | 接收飞书事件订阅回调。 |
| 钉钉 webhook | `POST /api/client/work-report/webhook/dingtalk` | 接收钉钉机器人回调。 |
| Slack webhook | `POST /api/client/work-report/webhook/slack` | 接收 Slack 事件。 |
| Inbox CRUD | `/api/client/work-report/inbox/**` | 查询、确认、忽略、编辑 Inbox 项。 |
| 灵感 CRUD | `/api/client/work-report/inspirations/**` | 灵感随记增删改查。 |
| 固定工作实例 | `/api/client/work-report/fixed-work/{id}/completions` | 按日期查询/标记完成。 |

### 9.2 新增 Service

| Service | 职责 |
|---------|------|
| `InboundMessageService` | 写入、去重、状态流转、确认后调用业务服务。 |
| `WebhookAdapter` (interface) | 各平台消息标准化。 |
| `FeishuWebhookAdapter` | 飞书验签、提取 sender/text。 |
| `DingTalkWebhookAdapter` | 钉钉验签、提取 sender/text。 |
| `SlackWebhookAdapter` | Slack 事件解析。 |
| `NlpIntentService` | 规则 + LLM 意图识别。 |
| `FixedWorkCompletionService` | 按周期生成实例、标记完成、查询统计。 |
| `InspirationNoteService` | 灵感 CRUD、标签管理、回顾查询。 |
| `WorkReportEventPushService` | WebSocket/SSE 推送事件到桌面端。 |

### 9.3 安全

- 各平台 webhook 必须验签。
- inbound_messages 按 user_id 隔离，不能越权确认他人消息。
- 幂等：platform + platform_message_id 唯一索引，防止重复处理。

## 10. AI 提示词设计

### 10.1 意图识别提示词

```
你是 File Keeper 个人工作助手。请分析用户消息，返回 JSON：
{
  "intent": "complete_fixed_work | add_work_log | add_inspiration | query_report | help | unknown",
  "confidence": 0.0-1.0,
  "entities": {
    "task_name": "",
    "date": "YYYY-MM-DD 或 relative",
    "content": "",
    "tags": [""]
  }
}

规则：
- 消息含“完成/做完/搞定” → complete_fixed_work
- 消息含“今天做了/记录了/工作内容” → add_work_log
- 消息含“灵感/想法/idea” → add_inspiration
- 消息含“周报/日报/报告” → query_report
- 无法判断或 entities 缺失严重 → unknown
```

## 11. 风险与边界

| 风险 | 应对 |
|------|------|
| 企业微信普通群机器人不支持被动回调 | 首期优先飞书/钉钉/Slack；企业微信通过自建应用或仅做主动推送。 |
| 自然语言解析错误 | 低置信度消息进入 Inbox 人工确认，高置信度也支持在桌面端撤回。 |
| 重复处理 IM 消息 | platform_message_id + 唯一索引幂等；IM 回复确认时带原始消息引用。 |
| 桌面端不在线时事件丢失 | 后端持久化 Inbox，桌面端上线后拉取未读；WebSocket 断线重连后补拉。 |
| 多设备登录 | 商业授权已有 deviceId 概念，Inbox 按 user 维度查询，多设备同步。 |
| 隐私合规 | 聊天记录仅存储解析后的结构化数据，原始消息可配置保留天数后自动删除。 |

## 13. 下一步建议

1. **先落地第一阶段 MVP**：飞书 webhook + Inbox + 固定工作完成标记。这样你能最快看到“用户在飞书回复完成，桌面端标记完成”的效果。
2. **IM 入口统一优先级**：如果你主要用飞书，就先只做飞书；如果同时用钉钉，可以第二阶段复用适配器。
3. **先做规则 NLP，再做 LLM**：规则版开发快、可控，等用户量起来后用 LLM 兜底复杂句。
4. **灵感随记与 Inbox 共用基础设施**：两者都是“外部轻量输入 → 结构化存储”，可以复用 NLP 和 WebSocket 通道。

## 关键设计决策

- **跨包解耦单向只读（设计 §十四）**：`AssetCanvasBridgeService` 单向依赖 `CanvasService.loadOwned`（复用画布归属咽喉点 + 读 snapshot），canvas 包不 import asset，保 canvas 零回归。节点从 snapshot JSON 解析（同 `CanvasController.resolveVideoFileId` 范式），不调 canvas 写侧。
- **节点类型→资产类型映射（设计 §八 节点入库映射表）**：text→PROMPT（正文取 outputText 优先、退回 prompt）、script→SCRIPT（synopsis+scenes）、image/video/audio→对应文件类（取 data.fileId）。空节点拦截（文本无 outputText/prompt、文件无 fileId → 400）。
- **重复入库三态（plan L5「变体归组」）**：节点已有 PRODUCED 绑定时——① mode 空=不创建、返 duplicateAssetId/Version 供前端弹窗；② NEW_VERSION=委托 `AssetVersionService.createVersion` 在已入库资产建新版（自带乐观锁+requireWrite）+ updateGenMeta 刷新谱系 + 新 PRODUCED 绑定；③ NEW_ASSET=另起资产。
- **引用=版本快照（设计 §六）**：resolve 返当前/指定版本的 fileId+content；资产升级不影响已引用方（前端「更新到最新版」手动操作，S12/S13）。
- **viewer 只读引用（设计 §7.2）**：resolve/usages 走 `loadAccessible`（viewer 可读），不走 requireWrite；import 走 requireWrite（viewer 不可入库）。防 fileId 遍历（resolve 前先 Acl）。
- **gen_meta 谱系捕获（设计 §三 第四层）**：source=CANVAS + canvasId/nodeId/nodeType + 节点携带的 prompt/model/seed（DAM 2025 共识：生成参数随资产入库）。
- **复用口径公开**：`AssetService.attachRoles`（受控词汇校验，单一事实源）+ `validateAssetName`（≤100）公开给 Bridge 复用，避免 vocab/校验逻辑重复。
- **asset:write seed 复用**：S7 plan 原写「权限 seed SQL(并入 V58)」——V58（S3）已 seed，S7 无新迁移（核对落空，记此）。

### 关键设计决策（S8）

- **按域分组 API**：不建单一 `assetApi` 巨对象，按 project/member/asset/version/script/bridge 分 6 组，对应后端 5 个 controller + 桥接，前端调用语义清晰（`projectApi.list()` vs `assetApi.list(projectId)` 不混）。
- **三重兜底同 canvas**：路由 meta 不卡权限（平台惯例），靠 Sidebar `hasPermission('asset:write')` 隐藏入口 + 页内 `canEdit` NEmpty + 后端 `@RequirePermission` API 403。
- **占位 view 而非空路由**：S9/S11 未到，先建带 403 gate + 建设中 stub 的 view，路由可通；后续 S9 直接替换 AssetListView 模板、S11 替换 AssetProjectView，不动路由。
- **PageResult 复用**：复用 `@/api/admin` 已有 `PageResult<T>`（knowledge.ts 同款），不重复定义；后端 PageResult 字段（records/total/page/size/pages）兼容。

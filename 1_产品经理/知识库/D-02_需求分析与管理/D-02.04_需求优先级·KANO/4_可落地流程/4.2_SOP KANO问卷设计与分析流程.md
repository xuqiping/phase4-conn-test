# 4.2 SOP KANO问卷设计与分析流程

## 适用场景

PM需要对N个候选需求进行KANO分类，以科学决定需求优先级时的标准操作流程。

## 前置条件

- 已完成需求收集（→D-02.01）并通过真伪判断（→D-02.03）
- 候选需求清单已确定（≥3个，≤20个，超过则分批）
- 目标用户群已明确

## SOP步骤

### Phase 1：问卷设计（Day 1-2）

| 步骤 | 操作 | 产出 | 检查点 |
|---|---|---|---|
| 1.1 需求条目确认 | 从需求池选取需KANO评估的需求，确保粒度独立（一个需求=一个可独立交付的功能） | 需求清单 | 每个需求可独立满足/不满足 |
| 1.2 配对问题撰写 | 每个需求写正向+反向两个问题 | 问卷草稿 | 反向问题用"如果没有"而非"不能有" |
| 1.3 量表选择 | 统一使用5级Likert量表 | — | 5级足够区分，7级反而增加认知负担 |
| 1.4 用户筛选设计 | 确定目标用户群筛选条件 | 筛选条件 | 排除非目标用户（否则I类虚高） |
| 1.5 预测试 | 5-10人预填写，检查理解度 | 预测试报告 | Q类占比<10%为合格 |
| 1.6 修改定稿 | 根据预测试反馈修改措辞 | 最终问卷 | — |

### Phase 2：问卷投放与回收（Day 3-7）

| 步骤 | 操作 | 门槛标准 |
|---|---|---|
| 2.1 投放渠道选择 | 目标用户群活跃渠道（App内弹窗/邮件/社群） | — |
| 2.2 样本量目标 | 每个需求≥30有效回收，推荐≥50 | 低于30时结果不稳定 |
| 2.3 实时监控 | 监控回收率、Q类占比、完成时间 | Q类>15%→问卷有问题，需修改 |
| 2.4 催收与补充 | 不足时补充投放 | — |

### Phase 3：数据分析（Day 8-9）

| 步骤 | 操作 | 说明 |
|---|---|---|
| 3.1 数据清洗 | 剔除Q类、缺答、非目标用户 | 计算有效率 |
| 3.2 类别判定 | **选择判定方法**（见3.2碎片的决策树）→ 执行判定 | 每个需求获得M/O/A/I/R标签 |
| 3.3 Better-Worse计算 | 计算每个需求的SI和DSI | 确定阈值线（均值法/0.5法） |
| 3.4 四象限定位 | 将每个需求放入Better-Worse四象限 | 可视化散点图 |
| 3.5 同类别排序 | M→DSI排序、O→SI×\|DSI\|排序、A→SI排序 | 内部精排 |

### Phase 4：决策输出（Day 10）

| 步骤 | 操作 | 产出 |
|---|---|---|
| 4.1 结合RICE/ICE量化 | KANO定性+RICE定量的交叉决策 | 交叉优先级表 |
| 4.2 漂移标注（如有历史数据） | 对比上次KANO结果标注漂移 | 漂移预警清单 |
| 4.3 输出优先级清单 | 最终排序+行动建议 | KANO优先级报告 |
| 4.4 归档 | 问卷+数据+分析结果归档 | 供下次漂移检测对比 |

## 判定方法选择检查清单

```
□ 样本量是否≥80？
  ├─ 是 → 分布是否集中（Max类别频率>40%）？
  │        ├─ 是 → ✅ Max频率法
  │        └─ 否 → 需区分M/O/A？→ 优势类别法
  └─ 否 → 决策成本是否高（大客户/合规）？
           ├─ 是 → ✅ 阈值判定法（设40%弱阈值+50%强阈值）
           └─ 否 → ✅ Max频率法 + Better-Worse验证
```

## 常见问题与应对

| 问题 | 原因 | 应对 |
|---|---|---|
| Q类占比>15% | 反向问题措辞不当/用户不理解 | 修改措辞+补充解释说明 |
| 多个需求类别为I | 用户群不匹配/需求粒度太细 | 重新筛选目标用户/合并相关需求 |
| 缺少A类需求 | 只评估了成熟功能，无创新点 | 补充创新型/差异化需求条目 |
| M类需求太多 | 产品基础能力不健全 | 优先解决M类的"生死线"需求 |

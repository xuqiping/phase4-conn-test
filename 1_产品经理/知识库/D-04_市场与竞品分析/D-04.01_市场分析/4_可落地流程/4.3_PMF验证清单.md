## PMF验证清单

### Phase 1：定义PMF假设

- [ ] 写出核心假设卡片

```
我们相信：[目标用户] 在 [场景] 下有 [核心需求]
我们的产品通过 [核心价值主张] 满足这个需求
验证标准：Sean Ellis测试"非常失望" > 40%
```

- [ ] 定义目标用户画像（至少包含：行为特征+场景+痛点）
- [ ] 列出产品的3个核心价值假设（用户最在乎的3个点）

### Phase 2：设计问卷

**Sean Ellis问卷模板**：

1. 如果[产品名]明天消失，你会有多失望？
   - 非常失望 / 有点失望 / 不会失望 / 已经不用了

2. 你最常使用[产品名]的什么功能？（开放式）

3. 如果不能使用[产品名]，你会用什么替代方案？

4. [产品名]对您最大的价值是什么？（开放式）

5. 你认为[产品名]最需要改进的一点是什么？（对选"有点失望"的用户必问）

**投放要求**：
- [ ] 样本量≥40人
- [ ] 筛选条件：使用核心功能≥2次
- [ ] 渠道：产品内弹窗 / 邮件 / 社群
- [ ] 避免在促销/活动后投放（数据偏差）

### Phase 3：分析结果

| 分析维度 | 方法 | 关键判断 |
|---|---|---|
| "非常失望"占比 | 直接统计 | >40%=PMF, 25-40%=接近, <25%=远离 |
| 用户分群 | 按使用频率/场景/角色分层 | 哪个群体PMF最高？→ 聚焦该群体 |
| 替代品分析 | 统计用户提到的替代品 | 真实竞品是用户心中的替代品 |
| 改进建议 | 归类"有点失望"用户的改进诉求 | 优先级=频次×可行性 |

### Phase 4：迭代

- [ ] 如果"非常失望"<25%：
  - 回到Step 1，重新审视目标用户和核心价值
  - 可能是选错了市场，而不是产品不够好
  
- [ ] 如果"非常失望"在25-40%：
  - 重点攻克"有点失望"群体
  - 把他们的改进需求排入近期迭代
  - 关注最高频的改进诉求
  
- [ ] 如果"非常失望">40%：
  - PMF初步达成
  - 进入增长阶段（但不能松懈——持续追踪）

### Phase 5：持续追踪

| 频率 | 动作 |
|---|---|
| 每月 | 看留存曲线是否变平 |
| 每季度 | 重跑Sean Ellis测试（至少30人） |
| 每半年 | 全面PMF复盘（留存+NPS+有机增长占比） |

### PMF验证常见失败模式

| 失败模式 | 症状 | 修正 |
|---|---|---|
| 问错了人 | 向注册但未使用核心功能的用户投放 | 严格筛选"体验过核心价值"的用户 |
| 样本偏差 | 只问了自己社群的粉丝 | 扩大样本来源，包含冷淡用户 |
| 过早宣布PMF | 只做了一次测试就开香槟 | 至少连续2次测试>40%+留存曲线变平 |
| PMF≠增长 | PMF达成了但增长没起来 | PMF是必要非充分条件——还需要增长引擎 |

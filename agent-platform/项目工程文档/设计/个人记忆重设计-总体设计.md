# 个人记忆重设计 — 总体设计

> 创建：2026-07-26
> 范围：完全替换旧 `user_memories` 事实抽取 + key 归一 + 冲突机模型，改为「全量聊天 io + L0/L1/L2 分层 + 标签归一 + 周期总结 + 冲突 pending」新模型。
> 实施路线与优先顺序见 [计划12-个人记忆重设计.md](../计划/计划12-个人记忆重设计.md)。
> 安全审计参照风格：[项目漏洞核查/安全漏洞审计-2026-06-28.md](../项目功能介绍/项目漏洞核查/安全漏洞审计-2026-06-28.md)。

---

## 0. 一句话总览

每轮对话全程留痕（按侧过滤，过过滤侧落 raw）→ 开生成后一次 LLM 出 INPUT/OUTPUT 双侧三层（L0 标签 / L1 概要 / L2 详述）→ 写时标签归一进独立表 → 召回时聚合 scope 内标签、优先读自己总结、reflect 判深读、拼未覆盖流水账 → 周期或手动总结把流水账压成精华条（provenance 溯源）→ 时序互斥进冲突 pending → 流水账可挂多项目按成员 ACL 只读共享。

---

## 1. 为什么替换（旧模型的死结）

旧 `user_memories` 单表 = 一个事实一行，靠 LLM 自由命名 `memory_key` 做归一。死结：

1. **key 不稳定**：同概念不同 key → 矛盾共存；旧 key 归一靠「extract 注入既有 key 白名单」补救，治标。
2. **无时间线**：时序事实（住址变迁）只能靠 value 字符串 hack，KEEP_BOTH 手工拼日期。
3. **召回靠枚举**：4 模式都在「key/value 字面 + 向量」上做文章，「带家人出去玩」召回不到「配偶名」——根因是语义判断交给枚举词袋，永远列不全。
4. **共享模型撞墙**：V33 纯可见性 → V34 home 混合，越补越复杂，撞唯一索引的 bug 反复。
5. **无提炼层**：800 条爱好对话灌 800 行进 prompt，token 爆炸无压缩。

新模型从根上换：**标签独立表 + 写时归一（禁手动并拆）+ 流水账为主体 + 总结提炼层 + 共享走流水账多挂**。

## 2. 核心数据模型（9 表 + 1 扩列）

| 表 | 职责 | 关键约束 |
|---|---|---|
| `memory_tags` | 标签库（subject:topic + label + aliases + anchor 三列） | `UNIQUE(user_id, subject, topic)`；写时归一，禁手动归并/拆分；仅 owner 改 label/补 aliases |
| `memory_turns` | 流水账（一轮对话 INPUT/OUTPUT 各一条，含 raw_content + L0/L1/L2） | `project_ids[]` 多挂共享；`born_personal` 出身标记；`departed_project_ids[]` / `deleted_project_ids[]` |
| `memory_summaries` | 总结提炼层（L1/L2 + provenance + 链式 source_summary_id） | `project_id` 单值（个人=NULL）；**不可挂项目数组、不可分享**；`status` CLEAN/PENDING_CONFLICT/STALE |
| `memory_summary_coverage` | 覆盖表（某作者某 turn 某 tag 某 scope 被其总结吃进） | `UNIQUE(turn_id, tag_id, project_id, user_id) NULLS NOT DISTINCT`；召回只认 `user_id=召回者自己` |
| `memory_project_members` | 记忆专属成员表（角色 + ACTIVE/DEPARTED 状态） | `UNIQUE(project_id, user_id)`；离职置 DEPARTED 不删行，保交接 |
| `memory_project_settings` | 项目级 gen 开关（owner 维度） | `UNIQUE(project_id)`；默认开 |
| `memory_project_user_settings` | 会员个人 gen 覆写开关 | `UNIQUE(project_id, user_id)`；默认开，会员自控 |
| `memory_consolidation_scopes` | 用户自动总结 scope 勾选集 | `UNIQUE(user_id, scope_kind, project_id) NULLS NOT DISTINCT`；新用户默认插 (PERSONAL, NULL, true) |
| `memory_notifications` | 跨用户波及通知 | type = SUMMARY_AFFECTED_BY_RECALL / PROJECT_DELETED_AFFECTED |
| `memory_recall_acl` | 项目流水账读取授权（reader→target） | `UNIQUE(project_id, reader_user_id, target_user_id)`；owner 兜底全读无需 ACL 行 |
| `memory_conflicts`（扩列） | 加 `tag_id` + `summary_id` | 冲突只来自总结层时序互斥，无 type 列 |

**旧表处理**：`user_memories` / `user_memory_projects` 直接 DROP（V49），老数据不迁移（项目未上线，旧表全为测试数据）。旧 `projects` / `project_members` 表 **Agent 模块、项目管理 modal 仍在用，不动**；记忆侧用独立新表 `memory_project_members`。

**放弃的字段**：`is_global`、`home_project_id`、`memory_key`、`memory_key_zh`、`block_label`、`confidence`、`embedding`(value 向量)。新模型无全局可见、无 home 概念、标签独立成表、anchor 三列挂在 `memory_tags`。

## 3. 功能模块

### 3.1 记忆生成（L0/L1/L2 + 前置过滤 + gen 开关）

**一轮对话 = 1 INPUT + 1 OUTPUT，一次 LLM 出双侧三层**（L0 标签 `subject:topic` 主体默认「我」/ L1 一句概要 / L2 结构化详述）。三层同生同灭，单 `gen_done` 标记。

**前置过滤（不调 LLM，按侧独立判定，各侧独立跳过）**：
- INPUT 侧：过短/纯标点语气词/纯确认/致谢/系统提示 → 仅跳 INPUT turn 生成。
- OUTPUT 侧：纯套话/免责声明/重复致歉/无信息客套 → 仅跳 OUTPUT turn 生成（避免 AI 尾部客套连坐丢失 INPUT 事实）。
- 敏感话题黑名单（密码/支付/验证码/身份证/银行卡/token，**预置默认开箱即用，用户只能加项不能清空核心项**）→ 命中即跳该侧生成。
- 两侧都被跳 → 不调生成 LLM 也不写 raw；仅一侧跳 → 仍调一次 LLM 产出未跳侧；双侧未跳 → 一次出双方三层。

**gen 开关（三层同开同关，方案 A per-project，默认开）**：
- 项目对话生成 = owner 项目级 `memory_project_settings.gen_enabled` **AND** 会员个人覆写 `memory_project_user_settings.gen_enabled`（默认开，会员本人自控）。
- 二者皆开 = 跑前置过滤 → 未跳过侧调一次生成 LLM。
- 任一关 = 不调生成 LLM，仍跑前置过滤，过过滤的侧写 raw 行（`gen_done=false`，tag/L1/L2 空）。
- 非项目会话读全局兜底 `rag.memory.gen.personal.enabled`（默认开）。
- **每项目顶端说明条**（M3）：明示「开启会记录提炼对话、每条调生成 LLM 增加 token、关闭后新对话不生成、原文 90 天后清除、已生成摘要保留」，一键关。

**raw 透明化与遗忘权**：
- gen 关态首条对话写 raw 前**非阻塞强提示**（不阻塞、非模态）：「将记录原文用于未来开启记忆，可随时删除/关闭；含密码/支付/证件/验证码等敏感信息不记录」。提示后仍写 raw。
- raw 默认 TTL 90 天：**所有用户 raw 由 worker 按 `WHERE gen_done=false AND created_at < now()-90d` 软删整行，不按是否开过 gen 区分**。已生成 turn（`gen_done=true`）不受影响，其 raw_content 随 turn 保留（避免 source_turn_ids 悬空）。
- raw 在线查看/批量删除端点（**仅本人，无导出/下载**）。

### 3.2 写入链（异步 + scope 出身 + 写入目标多选）

流式回复后异步 fire-and-forget 落两条 turn。**写入目标由用户显式选**（召回 scope 与写入目标完全解耦）：

| 勾选 | `born_personal` | `project_ids` | 语义 |
|---|---|---|---|
| 仅{个人}（默认） | true | `{}` | 个人私有 |
| {个人} + 项目X | true | `[X]` | 个人出身 + 叠加共享给 X |
| 显式取消{个人}，仅项目X | false | `[X]` | 纯项目出身（个人 scope 不可见） |

- **默认 = 勾{个人}，不跟随召回 scope**：避免用户为读项目记忆而勾项目 scope 时，自己的新隐私被默认共享给项目。
- 首次勾项目弹确认（含 M2 12h 规则提示）；首次取消{个人}弹确认（「新记忆不在个人记忆显示」）。
- **卸空自动转个人出身**：`project_ids` 卸到 `{}` 时 `born_personal` 自动置 true，防无归属。
- 非项目会话无项目可选，写入目标恒为{个人}。

### 3.3 召回 pipeline（scope 多选 → 标签聚合 → 总结 → reflect → 拼流水账）

```
① 过滤: scopes(用户多选) × timeWindow × direction
② 聚合标签: scope 内的总结(status≠STALE)与流水账的 tag_ids join memory_tags
            → 取 (subject, topic) 跨 user 去重 DISTINCT
            scope 外的 turn/summary 关联不到的 tag 不进聚合（防标签名泄敏）
③ LLM 选标签: 标签<30 全灌; >30 anchor 向量+BM25 RRF 粗筛 top-30 → LLM 精选 T
④ 优先读总结: findSummariesByTagAndScope(T, scope, timeWindow)
              只召回 user_id=召回者自己的总结（他人总结不召回，防污染）
⑤ 读哪层（明确分支）:
   - 总结 > 5 条: 读全部 L1 → reflect(批量1次 LLM) 选需深读子集 → 仅展开那些 L2
   - 总结 ≤ 5 条: 直接读全部 L2 全文（跳过 L1 省一次 reflect）
   - 0 条总结: 跳过本步，全走 turns
⑥ 拼增量流水账（严格策略 allCovered，统一按 coverage(user_id=self) 判）:
   - 该 turn 在此 scope 所有 tag_id 均有 coverage 行(allCovered=true) → 跳原文走自己总结
   - 否则（某 tag 未覆盖）→ 拼该 turn 原文
   - 他人 turn 同样按自己 coverage 判；召回恒只认 gen_done=true 的 turn
   - gen_done=false 的 raw turn 不参与召回（不进聚合也不兜底）
⑦ 装配: 按 subject 聚合打前缀带 owner；subject='我' 且 owner≠当前用户 → 省略主体【张三·爱好】
```

- **召回 scope 多选持久化**：用户勾 个人/项目任意组合，召回并集；保留上次选择，新会话沿用；首次无历史默认勾{个人}。
- **个人 scope 召回按出身**：`user_id=self AND born_personal=true`（含后共享给项目的）；项目出身 `born_personal=false` 不进个人召回。
- 每步降级：选标签失败→null；reflect 失败→只读 L1。最多 2 次 LLM（选标签 + reflect；reflect 仅总结>5 条触发）。目标召回延迟 < 2s。

### 3.4 周期总结（统一「开始总结」入口，独立于任何 gen/总结开关）

**统一入口模型**：设置页/总结页签/告警按钮一个「开始总结」入口 → 弹框列出用户参与的全部 scope = {个人} ∪ {本人 ACTIVE 项目}（已离开项目不可选）。

**手动总结**：每 scope 标可选/灰选——判据 = 该 scope 距上次该用户总结后是否有变化（新增 `gen_done=true` 且无 `coverage(user_id=self)` 行的 turn，或 `gen_done=false` 的 raw turn）；有变化=可选、无变化=灰。勾选确认即跑（= 先对 scope 内 `gen_done=false` 的 raw turn 跑 backfill 补 tag，分批 ≤20/批，再按 (user,tag,scope) 分组取数压缩）。**独立于任何开关，不受「有新增」门槛**。

**自动总结**：弹框勾哪些 scope 自动跑（{个人} ∪ {本人 ACTIVE 项目} 任意组合，全可选——未来更新未知不灰选）；勾上的 scope 到定时周期（用户配，默认每天）自动跑；**默认 = 勾{个人}**（默认先开个人总结每天定时；项目默认不勾、用户主动加）。per-user 勾选存 `memory_consolidation_scopes`。**定时跑前先判该 scope 该周期是否有新增未总结 turn，无新增空跳过、不调 LLM**（低频用户无新增时不耗 token）。

**gen 关态定时规则**：仅总结 `gen_done=true` 的已生成 turn；`gen_done=false` 的 raw 不纳入定时、不 backfill、不调生成 LLM；scope 内周期新增全为 raw 时空跳过；gen 关用户想总结 raw 须走手动（backfill+压缩两步）。**解耦理由**：总结是低频（每天一次压缩 LLM）、gen 是高频（每条对话一次生成 LLM），不应强绑。

**项目总结取数范围可配**：
- 人员范围：仅自己 / 项目内某几人（成员多选）/ 项目内全部人员（候选 = `readableAuthors` ∩ 离职开关过滤后集）；默认仅自己。
- 方向：仅 INPUT / 仅 OUTPUT / 全部；默认全部。
- 产出 summary 恒 `user_id=作者本人`、只读自己（不共享）；被选人员的 turn 喂进作者 summary；coverage 按 `user_id=作者`。**所有总结基于「当前可召回的人员记忆」**——离职开关关时离职人员既不召回也不进任何总结取数。

**冲突判定**：并存事实→合并；互斥时序→PENDING。

**时序日期铁律**：日期取 turn.`created_at`，禁 LLM 编年份（单测断言总结文本年份必匹配源 turn 真实年份）。

**防膨胀**：总结链 > N（用户配阈值）再压一次（总结的总结），链缩短，provenance + 真实日期。

### 3.5 冲突（总结时序 pending，四选项裁决）

- 互斥时序冲突进 PENDING（`memory_conflicts` 带 tag_id + summary_id），summary `status=PENDING_CONFLICT`。
- 裁决端点四选项：**KEEP_BOTH**（两条都留，按 `created_at` 自动排序，无需用户填日期）/ KEEP_NEW（当前态）/ KEEP_OLD / DISCARD。
- **项目内不产生跨用户编辑冲突**：别人不能改你的记忆（只读），只作者改自己的。冲突 pending 只来自作者自己总结时 LLM 判互斥时序 → 作者裁决。别人想补充→新建自己一条（`user_id=自己`）。
- valid_from/valid_to 时序列建模列为 v2 演进项，v1 用 `created_at` 自动排序 + 冲突 pending。

### 3.6 项目记忆共享（流水账多挂 + 成员制 ACL 只读）

- **个人记忆（未挂项目）严格私有，不可共享**；`project_ids='{}'` 别人命中不了 → 个人私有自动成立。
- **一条流水账可挂多个项目**：`project_ids BIGINT[]`，经显式 API/UI 挂载，挂哪些项目就哪些项目的成员可读（只读）。
- **共享 = 只读 + 仅流水账**：别人不能改你的记忆，只能基于你的记忆产出他自己新记忆（`user_id=自己`）。
- **总结不可挂项目数组、不可手动挂载、不可分享**：总结的 `project_id` 仅为单值 scope 归属（个人=NULL、项目=P），由 worker 写入，非用户可挂载操作。项目内总结只能由 worker 在项目内基于项目流水账生成；个人已做好的总结不能分享进项目。
- **ACL 授权读取**：`readableAuthors(projectId, reader)` —— owner 兜底全读；admin/member 按 `memory_recall_acl` 授权集 + 自己，默认并非项目全员可读。单套 ACL 同时管召回读取与总结取数。ACL 配置权仅 owner 或 `recall_admin=true` admin。

### 3.7 成员/项目生命周期（离职 + 删除，保交接 + 不删数据）

**成员退出/被踢/离职**：
- `memory_project_members` 该 (project,user) 置 `status=DEPARTED` + `departed_at`（不删行，保成员历史）。
- 对该用户挂在该项目的 turns 追加该 id 到 `departed_project_ids`（不删数据，不卸载）。
- **别人召回离职人员记忆**由「是否同步召回已离开项目人员记忆」开关控制（默认开=纳入并带「已离开人员·{用户名}·{departed_at}」标注；关=不召回，**优先级高于人员多选**——即便勾了离职人员也不召回；**且同时控总结取数**）。保交接，零改动。
- **作者本人离职后不可再选原项目作召回 scope**（自己项目出身 `born_personal=false` 记忆默认不可召回）；补救 = 折叠板「拉取到自建新项目」调 copy-to 端点（copy 非 move：追加新项目 Q 到 `project_ids`，保留原项目、原项目数据零改动、别的成员照常召回）。本人个人出身 `born_personal=true` 记忆不受影响仍经个人 scope 召回。写入目标锁定不可选已离开项目。

**项目删除**：
- **不从 `project_ids` 移除该 id**，追加到 `deleted_project_ids`（保留挂载、项目 scope 召回自然排除；个人 scope 按 `born_personal=true` 不受影响）。
- 清 `memory_summary_coverage` / `memory_summaries`（仅 `project_id=该 id` 的项目总结行；个人总结 `project_id=NULL` 不清）/ `memory_project_members` 该 project_id 行。
- **项目删除影响通知（M1）**：曾写记忆的每个成员收 `memory_notifications(type=PROJECT_DELETED_AFFECTED)`，前端 3s 轮询展示。
- 用户侧补救：面板「已删除项目」折叠板（有未处理记忆时 badge 高亮），新建项目并拉取自己在删除项目的流水账（restore：移出 `deleted_project_ids`、重挂新项目 `project_ids`，**仅拉 turn 不拉 summary**）。

### 3.8 流水账撤回/删除 + summary 级联（轻档 flat provenance）

`DELETE /api/chat/memory/turns/{id}`（软删 turn + 级联受影响 summary，ownership=作者本人）：

- **12h 规则（按「他人是否引用」判，非按 `project_ids` 非空；时间基准=他人引用方 summary 的 `summarized_at`，非 turn `created_at`）**：若存在**他人** `memory_summaries.source_turn_ids @> [T.id]` 且 `now - <引用方 summary>.summarized_at > 12h` → 拒绝（403）。无他人引用的 turn（含 `born_personal=true` 同时挂项目的）作者随时可删。
- **级联 summary（整条级，非片段摘除）**：软删 turn T 后，查 `source_turn_ids @> [T.id]` 的 summary——个人 scope 仅自己；项目 scope 含他人引用了 T 的 summary（B 撤回自己事实合法波及 A 的引用）。受影响 summary `status=STALE` + 删该 turn_id coverage 行 + worker 下次从剩余 `source_turn_ids - T` 重压缩。
- **跨用户波及通知**：项目 scope 下每命中一个他人 summary，写 `memory_notifications(type=SUMMARY_AFFECTED_BY_RECALL)` 给其作者；worker 重生完成后 UPDATE 原通知行置 `resolved_at` + message 追加「（已重生）」（不追加新行，避免 badge 抖动）。个人 scope 不发通知。
- **能力边界**：flat `source_turn_ids` 无片段→turn 映射，无法只摘除 T 对应句子，只能整条 summary 标 STALE 重生；高频撤回触发频繁重生，接受。

### 3.9 告警（未总结流水账 >100 条，不弹询）

某 scope 未被总结的流水账累计超过 100 条（**未总结 turn = `gen_done=true` 且当前 scope 下无 `coverage(user_id=self)` 行；`gen_done=false` 的 raw 不计入**；个人 scope：当前用户 input+output 合计；项目 scope：当前用户可召回权限下），前端**不弹询、改告警按钮**（类 pending badge，记忆面板/总结页签高亮），点开看详情，提供「立即总结一次（开弹框手选 scope）/ 加入每日自动总结（写入 auto_enabled=true）」入口。

## 4. scope 与可见性模型

```
私有性边界（无 is_global，无 home）:
  未挂项目的 turn (project_ids='{}') → 个人私有，别人命中不了，无需额外字段
  挂项目的 turn → 挂哪些项目就哪些项目成员可读（只读，经 ACL）

召回 scope（用户多选，持久化，首次默认{个人}）:
  选个人     → user_id=self AND born_personal=true 的个人出身流水账 + 个人总结(project_id IS NULL)
  选项目X    → 该项目成员(含已离开)的流水账(project_ids && X，经 ACL) + 召回者自己在X内生成的总结
  多选       → 上述并集

写入目标（与召回解耦，默认勾{个人}）:
  勾个人     → born_personal=true（同时勾项目则 project_ids 叠加共享）
  仅取消个人  → born_personal=false 纯项目出身

总结 scope:
  个人总结 → project_id IS NULL AND user_id=self
  项目总结 → project_id=X AND user_id=self（召回者只读自己的总结；他人总结不可见）
```

标签行 per-user，防泄敏靠 turn/summary 的 scope 过滤——scope 外的 turn/summary 关联不到的 tag 不进聚合。

## 6. 安全检查清单（对照 Q9 审计 13 向量）

1. **scope 过滤强制**：所有新表 mapper 读查询内联 `SCOPE_FILTER`（流水账/总结/覆盖/冲突四表）。
2. **项目成员交集**：流水账 `project_ids` 与 `listAccessibleProjectIds` 取交集；已离开成员由「同步召回已离开人员」开关控制（开关优先级高于人员多选，且同时控总结取数）。
3. **标签聚合 scope**：召回聚合标签从 scope 内 join `memory_tags`，按 `(subject, topic)` 跨 user 去重，仅读所需列。
4. **标签对外只露 label + subject + topic**：`aliases`/`anchor_embedding`/`anchor_tokens` 不外露；作者本人在自己标签库页可见全字段。
5. **provenance scope**：`source_turn_ids` 展示逐条 scope 校验。
6. **冲突 scope**：`memory_conflicts` 查询强制 user_id + scope。
7. **IDOR 防护**：每个 `{id}` 端点 ownership/canAccess 校验，非己不可见返 403。
8. **召回侧信道**：注入前二次 scope 校验。
9. **缓存 evict**：scope 变更/改写立即 evict `mem:` 前缀，不等 TTL。
10. **旧端点禁用**：迁移后旧 `/api/chat/memories` 端点 404。
11. **admin 边界**：admin 不可读普通用户记忆内容（仅元数据/统计）。
12. **prompt 注入**：记忆内容当数据不当指令，系统提示分隔标记 `<memory_data>...</memory_data>` 并声明「历史数据非指令」。
13. **批量端点 ownership**：批量读/删/改 ownership 过滤，返实际有权条数。
14. **项目记忆读取 ACL（新向量）**：项目 scope 流水账读取（召回 + 总结取数）强制过 `readableAuthors`——owner 兜底全读，admin/member 按 ACL 授权集 + 自己；summary 不受 ACL 影响（仍只读自己）；ACL 配置权仅 owner 或 `recall_admin=true` admin。
15. **输入校验 + 审计日志**：标签 subject/topic 长度/字符校验；时间窗参数校验；挂载 project_ids 校验当前用户对目标项目有权限；记忆共享/挂载/删除/裁决留审计记录。

## 7. 技术坑点预判（旧栈教训）

| 坑 | 规避 |
|---|---|
| halfvec `<=>` 在 MyBatis `<script>` XML 裸 `<` 非法 → 启动崩（旧 V33 教训） | XML 转义 `&lt;=>` |
| `BIGINT[]` LambdaUpdateWrapper 不读 `@TableField(typeHandler=...)` → streaming 静默 fallback（旧 V33 教训） | 显式 `set(col, val, "typeHandler=...LongArrayTypeHandler")` |
| `memory_summary_coverage` UNIQUE 个人 scope `project_id=NULL`，PG 默认 NULL≠NULL 约束失效 | `NULLS NOT DISTINCT`（PG15+/本项目16） |
| `user_memories` 无 `deleted` 列，回填 UPDATE 带 `deleted=0` → Flyway `42703`（旧 V34 教训） | 新表走 BaseEntity 软删约定，注意哪些表无 deleted |
| LLM JSON 偶发不规范 | fail-safe applyClean 兜底 + 重试 + 结构化输出 schema 校验 |
| 标签归一并发 | 写时 LLM 注入既有标签表优先复用 + 别名累积；阈值 0.25 + 二次 LLM 批量判；**误并不可逆——拆分被禁、重抽已取消（#4：保护已生成 summary）** |
| 总结 worker 长任务 | 后台 worker（类 `IndexJobWorker`）+ 任务锁（`FOR UPDATE SKIP LOCKED`）+ 幂等 |
| 时序日期 LLM 幻觉编年份 | 后端把 turn 真实 `created_at` 喂 prompt；禁 LLM 编年份 |

## 术语表

| 术语 | 大白话 | 案例 |
|---|---|---|
| turn（流水账条目） | 记忆账本一行流水账，= 你发的一句或 AI 回的一段 | 「我住萧山」是一条 INPUT turn |
| L0 | 标签，主体:主题 | `我:居住` / `表哥:爱好` |
| L1 | 一句概要 | 「请写 Python 爬虫」 |
| L2 | 结构化详述 | 「代码：requests+BS4，含重试」 |
| 标签归一 | 写记忆前先查标签表，同义复用，不造新标签 | 「兴趣」复用成已有「爱好」 |
| 召回（recall） | 回话前从历史记忆捞相关内容塞进提示词 | 你问住址，召回「住上城」 |
| reflect（反思） | AI 先扫摘要，自己决定要不要翻原文，省 token | 扫总结标题，感兴趣的才展开 |
| 周期总结（consolidation） | 后台按时间窗/手动把一堆流水账压成精华条 | 800 条爱好对话→1 条爱好总结 |
| provenance（溯源） | 记录总结来自哪些原始条目 id | 总结来自 turn #12,#15,#20 |
| 冲突 pending | 时序矛盾时不自动覆盖，挂起等用户裁决 | 住萧山 vs 住上城→pending |
| scope（可见范围） | 决定召回时谁拉得到这条记忆；召回时用户多选 | 个人 / 项目 X·Y 成员可见 / 多选并集 |
| project_ids（项目挂载槽，仅流水账） | 流水账挂哪些项目就哪些项目成员可读；空=个人私有；总结不挂 | 一条流水账挂 [项目X, 项目Y] |
| born_personal（出身标记，仅流水账） | 这条记忆「出身」是个人还是项目，写入时定死，挂/卸项目不改（卸空除外） | 写入勾个人→true；显式取消个人仅勾项目→false |
| coverage（覆盖表，按作者 user_id） | 记录某作者的某 turn 某 tag 某 scope 被其自己总结吃进去了 | turn #12 贴[工作,家庭]，工作总结覆盖→有行；家庭没覆盖→没行；allCovered=false |
| allCovered（严格覆盖判定） | 这条流水账在此 scope 下贴的每个标签是否都被自己总结覆盖，全才是 true | turn #12 工作✓家庭✗→false；两个都✓→true |
| anchor（锚点向量） | 标签/记忆的语义+词法召回索引，复用旧栈 | anchor_embedding + BM25 tsv |
| readableAuthors（ACL 授权集） | 项目内某 reader 可读哪些作者的流水账（召回+总结取数共用） | owner 全员；member=ACL 集+自己 |
| IDOR | 猜 id 越权读别人数据 | B 猜 turn id 读 A 记忆 |
| SCOPE_FILTER | SQL 里强制过滤可见范围的片段 | `AND (project_ids && :accessible)` |

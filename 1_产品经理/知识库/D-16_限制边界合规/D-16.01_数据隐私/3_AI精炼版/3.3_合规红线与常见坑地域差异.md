## 一、高频踩坑Do/Don't对照表（E.03）

### 1.1 隐私政策撰写

| ⚠️常见坑 | ✅推荐做法 |
|---|---|
| 隐私政策用法律术语写成天书，用户看不懂 | 用通俗语言+分层展示（摘要版+完整版），关键条款加粗 |
| 一次性获取所有数据采集同意（打包同意） | 分场景获取同意——核心功能用基本同意，附加功能用单独同意 |
| 隐私政策写了50页挂在网上，从不更新 | 每次产品涉及新的数据处理方式时必须同步更新隐私政策 |
| 第三方SDK只在隐私政策末尾"合作伙伴"笼统提及 | 逐个列出SDK名称、收集的数据类型、用途和隐私政策链接 |
| 隐私政策声明"我们可能将数据用于改善服务"（目的模糊） | 明确具体用途——"用于A功能的推荐算法训练" |

### 1.2 数据采集设计

| ⚠️常见坑 | ✅推荐做法 |
|---|---|
| 注册即要求手机号+实名+头像（过度采集） | 按功能最小化——注册只需必要标识，手机号/实名在需要时再采集 |
| App首次启动弹窗一次性请求所有权限 | 按需请求——用户触发功能时才请求对应权限 |
| 后台持续采集位置/通讯录/相册 | 前台使用时采集，后台停止采集 |
| 以"不同意隐私政策就不能用"强制同意 | 拒绝同意仍可使用基本功能，附加功能才需同意 |
| 收集的数据用途从"功能A"扩展到"营销推送" | 用途变更需重新获取用户同意 |

### 1.3 用户权利响应

| ⚠️常见坑 | ✅推荐做法 |
|---|---|
| 没有数据删除/导出入口，用户找不到 | 设置页提供"我的数据管理"入口（导出/删除/更正） |
| 注销账号只是"冻结"而非真删除 | 明确告知用户注销后的数据处理方式，T+30天硬删除 |
| 个性化推荐没有关闭开关 | 提供"关闭个性化推荐"的显著开关 |
| 用户要求删除数据后未同步通知已共享的第三方 | 合同约定第三方同步删除义务，并在隐私政策中声明 |

### 1.4 敏感信息与自动化决策

| ⚠️常见坑 | ✅推荐做法 |
|---|---|
| 人脸识别登录未做单独同意 | 人脸采集前独立弹窗+必要性说明+单独同意 |
| 用户画像/自动化推荐未告知算法逻辑 | 隐私政策中说明自动化决策的逻辑、后果、用户拒绝权 |
| 采集儿童（14岁以下）信息但无监护人同意机制 | 建立监护人同意验证流程 |
| 向境外传输数据未走任何合规路径 | 走标准合同/安全评估/认证之一 |

## 三、地域差异矩阵（C.04）

### 3.1 中国/欧盟/美国/东南亚核心差异

| 维度 | 中国(PIPL) | 欧盟(GDPR) | 美国(CCPA/CPRA) | 东南亚(新/印/泰) |
|---|---|---|---|---|
| **同意标准** | 单独同意(高风险场景) | 明确同意(opt-in) | 退出机制(opt-out为主) | 各异，新加坡PDPA较宽松 |
| **敏感数据** | 生物/宗教/健康/金融/行踪/14岁以下 | 种族/政治/宗教/健康/性/生物/基因 | 精确位置/SRCI(社保/护照/金融账户) | 不一，泰国PDPA类GDPR |
| **跨境传输** | 安全评估/标准合同/认证/国际条约 | 充分性认定/SCCs/BCRs/认证 | 无特别限制（但CFIUS关注） | 各国不一，印尼要求本地存储 |
| **数据本地化** | 重要数据须境内存储 | 无强制（但成员国可能有） | 无强制 | 印尼/越南要求本地存储 |
| **儿童年龄** | 14岁以下需监护人同意 | 16岁（成员国可降至13岁） | 13岁(COPPA)/16岁(CPRA) | 各异 |
| **罚款上限** | 5000万或年营业额5% | 2000万欧元或年营业额4% | $7500/次故意违规 | 较低，但趋严 |
| **自动化决策** | 需透明+可拒绝 | Art.22纯自动化决策可拒绝 | 有权退出"自动决策技术" | 部分国家有类似要求 |

### 3.2 出海产品合规优先级

```
优先级1（必须满足）：
├── 目的地国隐私法规（GDPR/CCPA/PDPA等）
├── 数据本地化要求（如有）
└── 跨境传输合规路径

优先级2（强烈建议）：
├── 目的地国语言隐私政策
├── DPO指定（GDPR要求）
└── PIA/DPIA评估

优先级3（长期建设）：
├── 隐私认证（ISO 27701/TRUSTe）
├── 隐私计算技术部署
└── Data Map与数据处理记录系统
```

## Chunk 6：取消业务超时，改为非阻塞持续轮询

- [x] **目标**：模型生成多久都保持可追踪，最终成功仍能下载；长任务不占死 Worker 线程。
- [x] **动作**：
  - Worker 每次认领只做一次 create/query。
  - Provider 返回 PENDING/RUNNING：根据 `attempt` 算退避，把 `locked_until` 设为下一次查询时间，立即归还线程；终态才落盘/扣费/释放 inflight/记录终态指标。
  - 删除 `taskTimeoutSeconds` 和 600 秒 FAILED 分支；保留连接/单次响应超时。
  - 查询网络异常视为可重试并安排下一轮，不写 FAILED；Provider 明确 FAILED/CANCELLED/EXPIRED 才失败。
  - 画布视频/图片轮询抽成可取消持续轮询；只在后端终态、节点删除、页面卸载或新任务替换时停止，不再按 120/48 轮判超时。
- [x] **涉及文件（8）**：

  - `backend/src/main/java/com/superprogrammer/media/service/MediaGenTaskWorker.java`
  - `backend/src/main/java/com/superprogrammer/media/service/internal/MediaGenTaskTxService.java`
  - `backend/src/test/java/com/superprogrammer/media/service/MediaGenTaskWorkerTest.java`
  - `frontend/src/views/CanvasView.vue`

  - `frontend/src/utils/mediaTaskPolling.test.ts`（新增）
  - `frontend/src/views/VideoGenView.vue`
- [x] **依赖**：复用 `locked_until/attempt`，不加迁移。
- [x] **验证**：超过 600 秒仍 RUNNING；后续成功正常落盘扣费；4 个长任务不堵新任务；重启可恢复；瞬时网络异常不终止；明确失败仍终态失败。

## Chunk 7：保存并展示实际 Provider 请求快照

- [x] **目标**：用户能在任务详情看到发送瞬间的实际 Provider 请求结构，并消除 `videoUrl/imageUrls=null` 的误解。
- [x] **动作**：
  - Provider 在发送前只构建一次请求体；由同一个已构建对象同时生成“实际发送 body”和“脱敏快照”，禁止事后从任务字段重新推导冒充实际值。
  - Worker 在 POST 前把脱敏快照写入现有 `request_config.providerRequestSnapshot` JSONB；无需数据库迁移。快照包含 provider/providerTask 创建时间、model、最终插值 prompt、ratio、duration、resolution、watermark、generate_audio，以及按真实顺序排列的 `content[]`。
  - 媒体 `url` 不保存原始 data URI；原位置替换为 `{redacted:true,transport:data_uri,mime,bytes,sha256,fileId}`，既能证明实际读取并发送了哪个文件，又不把大文件/base64 暴露给页面和数据库。
  - 任务 VO 返回 `inputAttachments` 和 `providerRequestSnapshot`；`videoUrl` 继续只表示成功视频输出，`imageUrls` 继续只表示成功生图输出。
  - 页面任务详情提供“实际发给模型（已脱敏）”JSON 查看/复制；若是改造前旧任务，无快照则明确显示“该历史任务未记录发送快照”，只能显示平台提交参数。
  - 映射固定并由 Provider 请求体单测证明：image→`image_url/reference_image`，video→`video_url/reference_video`，audio→`audio_url/reference_audio`，首/尾帧→`first_frame/last_frame`。
  - 视频生成页和无限画布共用同一 `attachments[]` 契约；日志只记 taskId/providerId/model/附件数量与角色，不记 data URI、密钥或完整提示词。

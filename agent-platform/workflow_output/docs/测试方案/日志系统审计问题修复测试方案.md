> Phase3 功能级预处理产出。审计系统为 admin UI + 真实 DB/异步线程/模型调用，机器测不全「中文显示/IP盖戳/drill-down跨页」，需人工+真环境验。

## 1. 为什么需要人工测试
- [x] UI 交互/视觉：模块中文下拉、模块/动作列中文显示、IP 列、drill-down 跨页跳转 banner
- [x] 真实第三方依赖：模型调用要真 LLM/媒体网关产生 token/积分
- [x] 需人工确认：worker 异步终态审计、chat 两阶段两行关联、traceId 串联肉眼核
- 机器测不全：中文标签是否回落正确、SSE 对话 reactor 线程 traceId 缺失边界、旧数据无关联键按钮禁用

## 2. 前置条件
- 环境：本地全栈（backend spring-boot:run + frontend dev），PostgreSQL，Redis。
- 账号：admin（admin123，持 system:audit:read + usage:view）；普通用户 u1（持 media:gen/chat 权限，无审计读权限）。
- 依赖：媒体网关(Seedance/Ark)真 key 配好；至少 1 条 IMAGE/VIDEO 价表 + 1 条 CHAT 价表生效；`AUDIT_CHAT_ENABLED` 默认 true。
- 迁移：V94/V95 已 Flyway 跑过（验 `media_gen_tasks`/`llm_usage_logs` 有 client_ip/trace_id/task_id 列）。

## 4. 正常路径用例

| 编号 | 场景（对应问题） | 操作步骤 | 预期结果 |
|---|---|---|---|
| TC1 | #3 模块下拉 12 项 + #2 中文 | admin 进「审计日志」→ 点模块下拉 | 下拉含 13 个中文项（认证/用户/…/无限画布）；表格「模块」「动作」列显示中文如「媒体生成-视频生成成功」 |
| TC2 | #4 账号筛选 | 账号框输 `adm` → 查询 | 只出 admin 行（前缀匹配）；清空回全量 |
| TC3 | #6 + #1 媒体成功带 IP/积分 | u1 提交一条视频生成任务 → 等成功 | 审计出现 2 行：video_gen_submit(targetId=任务id)、video_gen_success(同 targetId，detail 带 model+kind=VIDEO+pointsConsumed+IP 非空) |
| TC4 | #1 图片成功二次审计 | u1 提交图片生成 → 等成功 | 出 image_gen_submit + image_gen_success 两行，success 行 detail kind=IMAGE |
| TC5 | #1 对话两阶段 + 模型/积分 | u1 **REST 非流式**发一条对话 | 出 2 行：send_message(detail model+attachmentCount)、chat_completed(detail model+tokensInput+tokensOutput+pointsConsumed)；两行 traceId 相同 |
| TC6 | #5 下载/上传/入库 | 下载一个生成视频 / 上传一个文件 / 把媒体产物存资产库 | 各出审计行（download_video / upload_file / save_to_library），result=SUCCESS |
| TC7 | #7 chat drill-down | TC5 后打开 chat_completed 详情 → 点「查看调用明细」 | 新标签开「账单总览·调用明细」，顶部 banner 显 traceId 标签，表格列出 ≥1 条同 traceId 的 CHAT 调用（model/token/积分齐全） |
| TC8 | #7 媒体 drill-down | TC3 后打开 video_gen_success 详情 → 点「查看调用明细」 | 账单总览 banner 显 taskId 标签，表格列出同 taskId 的 VIDEO 调用记录 |
| TC9 | #2 失败也中文+reason | 故意触发一次失败（如断网下提交）→ 审计查 FAIL 行 | 模块/动作中文显示，result=失败，detail JSON 含 reason 码 |

## 5. 边界 / 异常

| 编号 | 场景 | 预期 |
|---|---|---|
| EC1 | SSE 流式对话（非 REST） | 仍有 send_message 行；chat_completed 行 traceId 可能空（reactor 线程无 MDC）→ 该行 drill-down 按钮不显示。属已知边界，不判 fail |
| EC2 | 旧数据 drill-down | 8x 上线前的老审计行无 traceId/taskId → 详情弹窗无「查看调用明细」按钮 |
| EC3 | 媒体生成失败 | 出 video/image_gen_fail 行（targetId=taskId，detail 带 model+kind+reason），不扣积分无 success 行 |
| EC4 | drill-down 清除 | 点 banner「清除」→ 过滤去，表格回全量调用明细 |
| EC5 | 关 AUDIT_CHAT_ENABLED | 设 false 重启 → 对话不再产生 send_message/chat_completed 两行（其他模块审计不受影响） |
| EC6 | 无审计读权限 | u1 直接访问审计 URL → 「无 system:audit:read 权限」空态；无 usage:view → 账单总览空态，drill-down 跳过去也看不到 |
| EC7 | 审计异步延迟 | 刚做的操作可能秒级延迟才出现 → 等 1-2 秒重查；长时间无看后端 WARN「审计落库失败」计数 |

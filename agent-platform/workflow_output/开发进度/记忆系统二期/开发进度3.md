## Step2：ingestion worker（FR-202/205）

- **解析器 `MemoryAssetExtractor`**（纯函数无 Spring 依赖）：PDF→PDFTextStripper 分页窗口逐页出 chunk（无文字层页跳过，page_ref=「第N页」）；PPT→POI XSLF 逐页文本；DOC→docx 段落/txt·md 按 1000 字切段（「段N」）；单 chunk 上限 2000 字。**IMAGE/AUDIO/VIDEO/OTHER + 老格式 .ppt/.doc（poi-scratchpad 未引）→ unsupported 弱记忆降级**（多模态/转写 provider 未接入，FR-205 语义）。
- **`MemoryAssetIngestService.processOne`**：meta 缺失/CLEANED→FAILED「原文件已删除或不可读」→ 解析 → 无文字/unsupported → **READY+weak_memory=TRUE**（l1 含「读不懂内容」明示，零 LLM）→ 否则软清旧 chunk + 逐 chunk `llmGateway.embed(MEMORY_EMBED_MODEL)` 落 halfvec（**单 chunk embed 失败降级 null 向量不阻断**）→ **一次汇总 LLM**（plan 坑表② 禁每页一次；`<memory_data>` 包裹防注入；JSON 宽容解析剥围栏）出 l1/l2/tags → `MemoryTagResolver.resolve(userId,"文件",tag,tag)` 归一进个人标签库（与对话记忆同体系召回合流）→ READY。LLM 失败 → FAILED retry_count+1（固定话术不透传异常细节）。
- **worker `MemoryAssetIngestWorker`**：@Scheduled 60s 轮询，批 5 条；**认领走条件 UPDATE 占位**（`WHERE PROCESSING AND locked_until 过期`，P2 状态机同款防并发，未用 SKIP LOCKED——影响行数=0 即被抢）；locked_until=now+10min 崩溃自愈；`memory.asset.ingest.enabled` 总开关（运维考量）。
- **重试运维入口**：`POST /api/chat/attachments/{id}/retry`（归属+仅 FAILED+retry_count<3 硬卡+requeue 条件 UPDATE 防并发 409）；`GET /api/chat/attachments` 我的文件记忆列表（Step5 页签数据源）。

## 关键决策 / 偏离 plan

1. **chunks 唯一约束改部分唯一索引**（V69 内，未执行可改）：表级 UNIQUE(asset_memory_id,chunk_no) 会被软删行挡重试重建 → `WHERE deleted=0` 部分唯一。
2. **worker 认领用条件 UPDATE 非 SKIP LOCKED**：plan 写「沿用 ConsolidationWorker 模式（SKIP LOCKED）」，但 P2 状态机的条件 UPDATE 占位更轻（无需事务内 SELECT FOR UPDATE），防并发语义等价，崩溃靠 locked_until 过期自愈。
3. **多模态描述/转写（IMAGE/AUDIO/VIDEO）本轮未接 provider** → 按 FR-205 统一弱记忆降级；后续接入点在 `MemoryAssetExtractor.extract` default 分支。
4. **turn 附件提及走文本拼接非签名扩展**：`processTurnAsync` 仅 2 调用方但签名零改更稳（P2「VO 瞬态标方案 pipeline 签名零改」同思路）。
5. **老 .ppt/.doc 不支持**（poi-scratchpad 未引入），明确 unsupported 弱记忆而非 FAILED。

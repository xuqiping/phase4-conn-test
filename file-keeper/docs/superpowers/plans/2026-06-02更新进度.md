### 2026-06-04：截图快捷键手动测试问题修复

#### 用户反馈的两个 Bug

1. **应用内按 `Ctrl+Shift+X` 时，File Keeper 主窗口直接最大化/全屏，然后才能截图。**
2. **应用外按截图快捷键时，没有调出截图功能，并且 File Keeper 无响应。**

#### 根因分析

- 当前 `handleScreenshotShortcut()` 直接对主窗口执行 `show()`、`setFocus()`、`setFullscreen(true)`，把 File Keeper 主窗口本身当作截图遮罩承载窗口。
  - 这会导致应用内触发时主窗口被全屏化，看起来像"直接最大化"。
  - 应用外触发时，主窗口被拉到前台/全屏会遮挡被截图对象，并可能让用户以为截图功能没有调出或应用卡住。
- `@tauri-apps/plugin-global-shortcut` 的回调会收到 `Pressed` 和 `Released` 两类事件，原来的 `src/api/shortcuts.ts` 忽略事件参数，会对按下和松开都执行 handler，存在重复触发和状态锁定风险。

#### 修复内容

- 新增 `src/api/screenshotOverlay.ts`：
  - 使用 `WebviewWindow('screenshot-overlay', ...)` 创建独立截图遮罩窗口。
  - 窗口配置为 fullscreen、transparent、alwaysOnTop、skipTaskbar、decorations=false、resizable=false。
  - 提供 `openScreenshotOverlayWindow()` 和 `closeScreenshotOverlayWindow()`。
- 新增 `src/components/ScreenshotOverlayHost.vue`：
  - 独立截图窗口只渲染 `ScreenshotOverlay`。
  - capture 时通过 `emit('screenshot://capture', region)` 通知主窗口并销毁遮罩窗口。
  - cancel 时通过 `emit('screenshot://cancel')` 通知主窗口并销毁遮罩窗口。
- 修改 `src/main.ts`：
  - 当 URL 包含 `?screenshotOverlay=1` 时加载 `ScreenshotOverlayHost`，否则加载主 `App`。
- 修改 `src/App.vue`：
  - 移除主窗口内嵌 `ScreenshotOverlay`。
  - 截图快捷键不再对主窗口执行 `show()`、`setFocus()`、`setFullscreen(true)`。
  - 改为打开独立截图遮罩窗口。

- 用户复测确认：应用内 `Ctrl+Shift+X` 已不再最大化，但在其他应用中按快捷键仍会导致 File Keeper 无响应。
- 进一步根因：`WebviewWindow` 的 `tauri://created` 是 JS 本地事件，构造函数创建窗口后立即开始异步创建；代码在构造后才注册 `once('tauri://created')`，存在事件先发生、监听后注册的竞态。一旦错过 created 事件，`openScreenshotOverlayWindow()` 会永久等待，导致 `screenshotShortcutHandling` / `isScreenshotOverlayOpen` 一直锁住，表现为后续截图快捷键无响应。
- 修复：
  - `src/api/screenshotOverlay.ts` 新增 `waitForOverlayWindow()`：同时监听 `tauri://created` / `tauri://error`，并立即轮询 `WebviewWindow.getByLabel('screenshot-overlay')`。
  - 若 created 事件丢失，但窗口已存在，轮询会返回现有窗口并继续执行 `setAlwaysOnTop(true)`、`show()`、`setFocus()`。
  - 增加 1 秒创建超时；如果窗口确实没创建成功，抛出"截图遮罩窗口创建超时"，由 `App.vue` catch 分支释放状态并提示错误，不再永久卡住。
- 新增回归测试：`src/api/__tests__/screenshotOverlay.test.ts` 增加 `does not hang when the local created event is missed but the overlay window exists`，先复现永久等待超时，再通过轮询修复。

#### 三次修复：截图后无提示和历史记录

- 用户反馈：截图功能正常（遮罩窗口正常、可以框选），但截图后没有弹出成功提示，剪贴板历史中也没有新记录。
- 控制台报错：`Uncaught (in promise) window not found`。
- 根因分析：
  - `ScreenshotOverlayHost.vue` 的 `handleCapture()` 在 emit 截图事件后立即调用 `getCurrentWindow().destroy()` 销毁遮罩窗口（第17行）。
  - 主窗口的 `handleScreenshotCapture()` 收到事件后又尝试调用 `closeScreenshotOverlayWindow()`（App.vue 第1265行），该函数通过 `WebviewWindow.getByLabel()` 查找已销毁的窗口并尝试 destroy，抛出 "window not found" 错误。
  - 错误未被 catch，导致后续的 `captureScreenshotRegion()`、`clipboardStore.loadItems()` 和成功提示 `alert()` 全部未执行。
- 修复内容：
  - `src/App.vue` 的 `handleScreenshotCapture()` 和 `handleScreenshotCancel()` 在调用 `closeScreenshotOverlayWindow()` 时增加 try-catch，忽略 "window not found" 错误（因为遮罩窗口可能已被 Host 销毁）。

# 3.5 AI辅助分类与前沿趋势

## 大模型辅助MoSCoW分类

MoSCoW的四桶分类看似简单，但实际操作中**Must膨胀**和**Won't恐惧**导致分类质量低下。AI可辅助：

| AI辅助能力 | 说明 | 局限 |
|---|---|---|
| **自动标注KANO→MoSCoW** | 已有KANO数据的需求自动映射到M/S/C/W | KANO数据本身可能有误 |
| **Must膨胀检测** | 当Must占比>60%时自动预警 | 需人工最终决策哪些降桶 |
| **历史升降桶模式** | 识别"每次都进Must但从没按时做"的需求 | 历史数据需积累 |
| **Won't桶建议** | 低RICE+I类KANO的需求建议列入Won't | 需业务方确认 |

### AI辅助三框架联合分析

```
输入：需求清单
  ↓
Step 1: AI分析用户反馈 → 自动KANO分类（初筛）
Step 2: AI参考历史数据 → 辅助RICE评分（估算）
Step 3: AI联合KANO+RICE → 自动MoSCoW分桶（建议）
Step 4: 人工审核 → 调整分桶 → 确认

输出：KANO标注 + RICE评分 + MoSCoW分桶 的联合优先级清单
```

## 动态MoSCoW

传统MoSCoW是**静态一次性分类**，但需求优先级会随环境变化。动态MoSCoW：

| 触发条件 | 桶位调整 | 说明 |
|---|---|---|
| 竞品发布功能 | Could→Should（变为标配） | 原本是锦上添花→变为跟上竞品 |
| 大客户流失风险 | Could→Must | 商业风险提升优先级 |
| 技术债积累 | Won't→Should | 技术风险不处理会越积越大 |
| 法规变更 | Could→Must | 合规要求→必须做 |

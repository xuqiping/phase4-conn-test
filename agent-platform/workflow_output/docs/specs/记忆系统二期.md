# 记忆系统二期 · 规格（FR 索引）

> 设计真相源：[项目工程文档/设计/记忆系统二期-项目自动收录与多模态-总体设计.md](../../../项目工程文档/设计/记忆系统二期-项目自动收录与多模态-总体设计.md)（下称「二期设计」）。本文件只做 FR 编号与验收口径，方案细节以二期设计为准。
> 决策定案：D1-D7 全部敲定（见二期设计 §12）。

## 需求背景

个人对话全量进个人流水账；项目记忆改为创建者配「收录规则」+ 路由自动蒸馏进项目（取消用户手动指定写入目标）；项目可授权给其他项目（项目包含项目，双向确认、单级不传递）；聊天支持图片/文件上传，一文件一条记忆（总结可召回、原文可回链、分块可深读）。

## FR 一览

### P1 收录规则 + 路由 + 条目
| FR | 需求 | 验收口径 |
|---|---|---|
| FR-001 | 项目收录规则 CRUD：rule_text + 正/负例 + anchor（向量+tsv）+ enabled；规则文本对项目成员可见，负例仅 owner/admin | owner 配规则后 anchor 落库；成员可读 rule_text 读不到 negative_examples |
| FR-002 | 写时路由粗筛：turn 的 L1+tags 对用户 ACTIVE 项目规则锚点做向量+BM25 RRF，top-K≤3；不过阈值零 LLM 调用 | 无候选时路由日志显示 0 次 LLM |
| FR-003 | 路由精判：候选>0 时一次 LLM 批量判 K 个项目，输出 hit/confidence/蒸馏 L1/L2；prompt 明示脱敏；输出 schema 校验 | 蒸馏文本不含与规则无关的隐私内容；schema 不合规自动重试/丢弃 |
| FR-004 | 条目落库与置信度分流：≥0.8 ACTIVE，0.5~0.8 PENDING_REVIEW，<0.5 丢弃；阈值走 system_settings KV 可调 | 三档分流单测覆盖边界值 |
| FR-005 | 收录审核：owner/admin 对 PENDING_REVIEW 一键收/弃；弃→该 turn 内容进项目负例反哺；成员可见「为何被收录」（命中规则+置信度）；作者可申诉撤回自己条目 | 收→ACTIVE；弃→软删+负例落库 |
| FR-006 | 一期模型清理：memory_turns 删 project_ids/born_personal/departed/deleted 四列；memory_recall_acl DROP；recall-acl 端点 404；写入目标 UI/端点下线 | 旧端点 ≥4xx；turns 纯个人域 |
| FR-007 | 召回合流：pipeline 加 ①.5 项目条目合流（成员=可读，DEPARTED 失读权）与 ⑥ 未覆盖条目拼入；装配按作者打前缀 | 项目 scope 召回到条目；非成员/离职成员召回不到 |
| FR-008 | gen 开关语义迁移：owner 项目级开关→「启用自动收录」；会员覆写→「允许我的对话被路由」（默认开） | 会员关覆写后其对话不产生任何条目 |

### P2 项目授权（双向确认、单级不传递）
| FR | 需求 | 验收口径 |
|---|---|---|
| FR-101 | 授权生命周期：child owner 发起→PENDING+通知 parent owner/admin→通过 ACTIVE / 拒绝 REJECTED；同 (parent,child) REJECTED 后 30 天不可重复发起；child/parent 双方均可撤销 ACTIVE | 状态机单测全覆盖；重复发起被拒 |
| FR-102 | 授权召回合流：仅 status=ACTIVE 的链生效；child 条目带「来自授权项目·X」标注；写不穿透（parent 成员不能写 child） | PENDING/REJECTED 链召回不到；撤销后下次召回即不含 |
| FR-103 | 授权审计 + 通知：发起/通过/拒绝/撤销全留审计；PENDING 通知进 memory_notifications | 审计行齐全 |

### P3 多模态文件记忆
| FR | 需求 | 验收口径 |
|---|---|---|
| FR-201 | 聊天附件上传：复用 stored_files（source=CHAT），owner=上传者；类型/大小校验（≤50MB、文档≤200 页、音视频≤30 分钟），超限友好拒收 | 超限返回明确话术 |
| FR-202 | ingestion worker：IMAGE→多模态描述+OCR；PPT/PDF/DOC→分页/分节要点；AUDIO/VIDEO→转写+时间戳锚点；产出 l1/l2+tag 建议（进个人标签归一）+ chunks（带 page_ref）；状态机 PROCESSING/READY/FAILED 可重试 | 课件上传后产生一条 READY 记忆 + 每页 chunk |
| FR-203 | 文件记忆召回：命中 tag → L1/L2 进装配 + 前端文件卡片（下载链）；reflect 判深读 → chunks 向量 top-k；AI 引用必须带页码/时间戳 | 问「那个课件讲了什么」返回总结+卡片；问细节带页码 |
| FR-204 | 文件记忆路由进项目：文件总结过同一路由层；命中→条目 content_type=FILE+file_id；项目成员读文件走 stored_files ACL 放行（复用资产库共享模式） | 成员可下载被收录文件；非成员不可 |
| FR-205 | 模态降级：OCR/转写失败→降级为元数据弱记忆并明示「读不懂内容」；原文件删除→记忆保留标「原文件已删除」 | 降级话术可见；删文件后总结仍可召回 |

### P4 项目总结共享化 + 12h 废除
| FR | 需求 | 验收口径 |
|---|---|---|
| FR-301 | 项目共享总结：全员可读，仅 owner/admin 可写（手动+自动 worker）；个人总结不变 | 成员只读；成员无写入口 |
| FR-302 | 成员个人压缩通道：成员可发起对项目内容的压缩，产出落自己个人总结（user_id=自己，标注来源项目），对项目零修改 | 成员压缩后仅自己召回得到 |
| FR-303 | 嵌套总结：父项目总结取数=自有条目∪ACTIVE 子项目条目；总结不跨项目流动；撤销授权→父总结 STALE 重压；冲突裁决权随总结所有权 | 撤销后重压的总结不含子项目内容 |
| FR-304 | 废除 12h 拒删：作者删 turn 随时生效；级联软删蒸馏条目；波及总结 STALE+重生+通知 | 被引用不再是拒绝理由（无 403） |
| FR-305 | coverage 条目级扩展：(entry_id, project_id)；总结 provenance 记录条目来源项目 | 召回「来自授权项目·X」标注正确 |

## 非功能需求

- 召回延迟目标 <2s 不变；路由粗筛不过零 LLM；精判批量一次。
- 安全：原文不出个人域（项目端点响应不含 raw_content，结构性测试断言）；路由 prompt 注入防护（`<memory_data>` 包裹）；文件下载恒走 FileStorageService.load 咽喉点。
- 合规：收录规则对成员透明；个人可关「允许被路由」；文件记忆逐条可删。

# 已解决（2026-08-25，2 项）
1. **邮箱+密码登录** ✅（`4c278a98`）—— 此前登录只认用户名。现密码登录框支持「用户名或邮箱」：含 @ 的输入先按邮箱凭证查（大小写不敏感），查不到再按 users.email 列兜底（老账号没建邮箱凭证的也能登），密码与账号相同。安全上：邮箱登录解析出真实用户名后，失败计数/账号锁/滑块统一归并到账号键——攻击者交替用用户名/邮箱两条道也摊不薄计数。
2. **真实重置密码** ✅ —— 链路本来就在（忘记密码→收邮件→点链接→重置页填新密码），真正的坑是：邮箱验证总开关关着时，测试期注册的账号邮箱是「未验证」状态，系统不给未验证邮箱发重置信（防冒领），所以收不到。已放宽：开关关时未验证凭证→users.email 列兜底照发。**重置密码 URL = `{前端域名}/reset-password`**（如 `http://localhost:5173/reset-password`），邮件会自动拼 `?token=...` 跳转到这页。

# 已解决（2026-08-26 勾销，修复设计III §10，Chunk E，commit `0d43f74f`）
2. **账号锁定可见+管理员解锁** ✅ —— 锁定 15min（自动）。已锁账号（DB 落 locked_until）登录报错显「账号已锁定，将于 MM-dd HH:mm 自动解锁，可联系管理员提前解锁」（未落库的纯计数锁仍固定话术，防账号存在性探测）；管理员用户管理锁定行「解锁」按钮（确认弹窗显到期时间）→ `PUT /users/{id}/unlock` 立即可登+审计落「提前解锁账号」。封禁/禁用行不显解锁（走「启用」，语义分离）。
3. **管理员设置姓名/昵称** ✅ —— 用户管理行「姓名」按钮（≤64 字，空=清除）+`PUT /users/{id}/name`；个人中心本人改名 17x 已有（限长统一 64）；全站 displayName（name 优先回落账号）：项目组成员表「姓名（账号）」、组产出用户列；审计列表用户列保持账号快照（证据链不随改名漂），详情弹窗括注现姓名+备注。
4. **按备注筛选拿人+备注展示** ✅ —— 统一选人组件 `UserPicker`（搜索命中用户名/姓名/备注，行显「姓名·账号·[备注tag]」，多选 chips、键盘导航）：项目组邀请成员（多选批量发邀请）、批量充值（开关多选→逐人同额到账，每人独立幂等键，失败名单可单独重充）。备注展示：项目组成员表灰 tag 悬浮全文、审计详情操作人行、充值用户下拉。数据源三处后端均补备注模糊匹配（LIKE 转义）。

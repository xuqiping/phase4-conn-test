# 企业级精准知识库 RAG 用户操作手册

> 本手册随 Phase 3 每一步持续更新。当前正在按真实性审计修复 P2～P5；已验证可操作流程才保留为完成能力。

## 管理员：配置 OpenSearch 连接基座

当前步骤是部署配置能力，尚无前端表单。管理员在后端运行环境设置以下变量后重启服务：

1. 设置 `RAG_OPENSEARCH_ENABLED=true`。
2. 设置 `RAG_OPENSEARCH_URL`，例如 `https://opensearch.example.com:9200`。
3. 如集群启用认证，设置 `RAG_OPENSEARCH_USERNAME` 与 `RAG_OPENSEARCH_PASSWORD`。
4. 保持 `RAG_OPENSEARCH_TLS_VERIFICATION=true`；生产环境不要关闭证书校验。
5. 可按需设置 `RAG_OPENSEARCH_CONNECT_TIMEOUT`、`RAG_OPENSEARCH_REQUEST_TIMEOUT`，例如 `3s`、`10s`。
6. 重启后访问平台现有 Actuator 健康检查入口，查看 `openSearchHealthIndicator`：
   - `UNKNOWN / disabled`：功能未启用，不会尝试连接；
   - `UP / up`：集群可连接；
   - `DOWN / down`：连接、认证、TLS 或超时存在问题。

### 常见异常与恢复

- 显示 `disabled`：确认启用变量已进入 Java 进程环境并重启。
- 显示 `down`：检查地址、端口、网络、认证和证书；健康详情不会显示密码。
- 生产环境无域名证书：应先配置可信证书或反向代理，不要长期关闭 TLS 校验。

## 索引安全边界

- 索引名由系统根据 KB、snapshot、pipeline 生成，管理员不能输入物理索引名，也不应直接在 OpenSearch 中手工切换 Alias。
- 重建写入隔离物理索引，现网 read/write Alias 在管理员确认切换前保持不变。
- 只有状态为 `READY` 的已登记快照允许切换；失败或取消的快照必须重新生成新 snapshot ID。

## 管理员：理解双写状态

- `RAG_OPENSEARCH_ENABLED=false`：文档继续只写旧 PG 索引链路，适合尚未部署 OpenSearch 的环境。
- 启用后：每个 C2 节点生成一次向量，先写 OpenSearch 检索副本，再完成 PG 索引任务。
- Bulk 中任一节点失败：任务进入既有退避重试，不会把文档误标为全部索引完成。
- 重试使用稳定 node ID，因此不会产生重复检索文档。

## 管理员：对账与权限变化

- 系统以 PG 为权威源，对 OpenSearch 检测缺失、孤儿、正文 Hash 漂移和 ACL 漂移。
- dry-run 只生成“需重建/需删除”清单，不修改数据。
- 权限、版本可见性或删除发生变化时，系统先清除该 KB 的检索副本，再通过幂等任务重建，避免旧权限泄漏。

## 管理员：索引运维页面

1. 进入“知识库”，打开管理员可见的“索引运维”Tab。
2. 选择知识库，点击“刷新状态”查看当前/上一快照及 read/write alias。
3. 输入新的 snapshot ID，先点“对账 / 重建预检”；成功提示明确说明没有修改索引。
4. 点“启动重建”并确认。页面显示 `已完成/总数、失败数、取消数`；刷新页面后进度仍从 PostgreSQL 恢复。
5. 如需中止，点“取消重建”；系统取消尚未完成的快照任务，该快照不能切换。
6. 状态达到 `READY` 后点“切换”，在风险弹窗中再次确认。
7. 如新链路异常，点“回滚”，确认后恢复上一已登记快照。

索引快照和当前/上一路由保存在 PostgreSQL 中，后端重启后不会丢失。只有通过重建流程正式登记的 snapshot ID 才能切换；手工猜测或输入未登记 ID 会被后端拒绝。首次切换会创建读/写 Alias，后续切换和回滚使用原子 Alias 操作。

无法重建/切换时检查：是否具备 `knowledge:manage`、OpenSearch 是否启用且健康、snapshot ID 是否安全合法、任务是否存在失败、快照是否达到 `READY`。启动、取消、切换、回滚均写管理员审计日志。

## 用户：问题如何被规划

- 带版本、日期、条款编号或引号原文的问题优先走精确检索，只计算规范 Query 向量，不调用 Query Rewrite/HyDE LLM。
- “比较/差异”会规划为多证据回答；“步骤/流程”会启用邻居与顺序检索；“列出全部”会提高覆盖预算。
- 普通语义问题才允许使用知识库配置中明确选择的 LLM 做分析；没有可用模型时不会静态调用其他模型。

每次检索都会在搜索阶段限制租户、知识库、ACL、ACTIVE 状态和目标版本；权限不足或版本已撤销的内容不会先召回再由页面隐藏。

OpenSearch 启用时，精确和关键词通道会在搜索阶段强制限制 tenant、KB、ACTIVE、ACL 与当前用户可见文档；结果与现有 PG Dense/BM25 候选按 nodeId 合并后统一重排。OpenSearch 未启用或单通道故障时 PG 路径继续工作，不会扩大权限范围。

LLM 重排只使用知识库调用模块中明确选择的模型，并实际读取候选标题和正文判断相关性。模型只能给本次候选重新排序，返回未知或重复候选 ID 会被拒绝；没有可用模型时明确报错，只有管理员明确配置 `FALLBACK_RRF` 才回退融合顺序。Trace 显示的 effectiveMode 是实际执行模式，不再显示占位代理。

在“检索调试”结果中可查看 QueryPlan / RRF / Ranking 时间线，包括实际生效模式、候选数、耗时和状态。专用 Rerank 未接入时不能误选，选择后会明确提示不可用。

当问题涉及 5～10 条知识时，系统不会固定只取少量 Top-K：精确题通常 2 条，流程题约 10 条，列表/比较题最多 20 条，并限制单一文档挤满上下文。
该规则已经接入真实检索接口：候选会先由 PostgreSQL 复核当前权限、版本和正文 Hash，再执行去重、来源多样性和 token 裁剪。调试响应中的 `confidenceState` 会显示 `SUPPORTED`、`PARTIAL`、`CONFLICT`、`INSUFFICIENT`、`OUT_OF_SCOPE` 或 `RETRIEVAL_FAILED`；当前切片已覆盖正常支持状态，其余状态随后续 Grounded Answer 链路逐步接入。

如已选证据缺少某个主题，普通模式最多补检索 1 轮，高精度最多 2 轮；补检索继承原知识库、权限和版本范围，失败时返回“部分覆盖”而不是扩大范围。

进入模型上下文前，系统会再次以 PG 复核权限、当前版本和正文 Hash；重复证据去重，流程/条款可补相邻节点，但相邻节点也必须有权限且不能突破 token 预算。

答案引用可显示页码、条款、Sheet/Cell 或 bbox 定位。点击引用前服务端仍会复核权限；旧版本、撤权、Hash 已变化或无法支持对应 Claim 的引用不会返回。
定位信息来自解析阶段保存在节点 metadata 中的真实 locator，不由回答模型猜测。若 locator 缺失、JSON 损坏或复核失败，该条不会作为可点击 Citation 返回；PDF 同页显示单页、跨页显示起止页，Excel 显示 Sheet 与单元格范围，标题路径显示为 article。

长证据会先分批归纳为“事实 + 引用编号”再合并，引用不会在批次间丢失。回答状态包括完全支持、部分支持、冲突、证据不足、超范围、检索失败；阈值由评测配置决定。
分批归纳阶段只接受本次已注入证据的 Citation 编号；模型即使返回不存在的编号也会被剔除。同一主题出现多个不同事实值时，系统会保留各自来源并标记冲突，而不是静默选一个答案。
完整生成请求会执行“事实提炼→最终答案合成”两类模型调用。两者都使用系统中显式选择或管理员默认的对话模型；没有可用模型时明确报错，不会静态调用某个模型。管理员审计中可按同一 trace 查看 `GROUNDING_FACT_EXTRACTION` 与 `GROUNDED_ANSWER_COMPOSITION`，日志只保存 Hash、模型、用途、状态、token 和耗时，不保存完整证据或 Prompt。
知识库问答页收到的事件顺序为答案、引用、置信状态、完成。为保证引用和冲突状态已经校验，页面会等待 Grounded Answer 完整完成后一次显示答案，不再逐 token 展示未经验证的中间文本；`RAG_STATE` 表示本次最终状态。

## 管理员：评测数据基础

黄金集按租户和知识库隔离，样本可记录相关/禁止 Chunk、版本、主题和期望 Claim。每次 Pipeline 评测单独产生 run/result，可计算 Recall@K、MRR、nDCG，并为后续 Citation、Faithfulness、Abstention 指标保留结构。
JSONL 导入按行处理：合法行立即入库，单行格式错误会返回行号和错误摘要，不会让整批回滚；导出前必须通过当前租户的 Dataset 归属校验，导出内容只包含评测字段，不包含知识库 Chunk 正文。

新 Pipeline 是 Challenger，当前线上是 Champion。任何必需指标未达门槛都不能切生产；影子检索只保存对比结果，超时或预算耗尽会停止，不影响用户收到的 Champion 答案。

## 管理员：启动 RAG 评测并查看影子对比

1. 进入“知识库”，打开仅具备 `knowledge:manage` 权限的管理员可见“RAG 评测”Tab。
2. 在“RAG 评测运行”卡片输入 Dataset ID；未输入时“启动评测”按钮保持禁用。
3. 点击“启动评测”后，页面显示异步任务进度和提示；离开页面不会被描述为同步完成。
4. 在“Champion / Challenger”卡片查看当前生产 Pipeline、待评测 Pipeline 和发布门禁状态。
5. 当门禁仍显示“等待评测结果”时，不应执行生产切换；后续灰度控制只接受已通过门禁的配置。

常见异常：看不到该 Tab 时先确认账号是否拥有 `knowledge:manage`；Dataset ID 为空时补齐后再启动；评测运行中可稍后返回查看，不要重复连续提交。

## 管理员：灰度发布与一键回滚

1. 进入“知识库 → 索引运维”，选择知识库，在“RAG 灰度发布”区域刷新当前状态。
2. 选择 5%、20%、50% 或 100%，输入配置版本；不支持任意百分比，避免发布节奏失控。
3. 点击“应用灰度”，在二次确认弹窗确认。后端会权威检查发布门禁、索引健康和最近对账，页面不能自行伪造通过状态。
4. 应用成功后，同一知识库、同一用户会稳定落在 Champion 或 Challenger，不会随请求随机漂移。
5. 异常时点击“回滚灰度”并二次确认；系统恢复上一配置，同时失效该知识库的新快照答案缓存。

常见异常：提示三项检查未全部通过时，先完成评测、索引初始化和对账；提示无可回滚配置时说明尚未形成上一版本；所有切换和回滚都会记录管理员操作者审计。

## 用户：提交答案反馈

1. 在“RAG 问答”完成一次回答；反馈区只在答案生成完成后出现。
2. 单选一个知识库后，选择“结果不相关 / 内容已过期 / 引用错误 / 答案不完整”之一。
3. 可填写不超过 1000 字符的补充说明，点击“提交反馈”。
4. 页面提示“已进入待审核队列，不会直接改变线上排序”，即为提交成功。

多选知识库时反馈按钮禁用，避免无法判断归属；如需反馈，请一次只选一个知识库重新提问。反馈不会自动进入黄金集，也不会即时提升/降低某个 Chunk，必须由管理员审核。

## 管理员：创建评测数据集并导入 JSONL

1. 进入“知识库 → RAG 评测”。
2. 输入知识库 ID、数据集名称和可选说明，点击“创建数据集”。
3. 页面显示真实 Dataset ID 后，在 JSONL 输入区粘贴评测用例；每行是一个独立 JSON 对象。
4. 点击“导入用例”。页面显示成功条数、逐行错误以及已入库用例列表。
5. 单行格式错误不会回滚其他合法行；错误提示只显示行号和短摘要。

当前页面不会伪装“评测已经运行”。异步 Run/Result、进度和指标结果将在后续 P5 步骤完成后开放。

### 1.2 冷启动四要素模型

```
冷启动 = 种子用户 × 种子内容 × 种子供给 × 社区氛围种子
```

| 要素 | 说明 | PM关键动作 | 典型方法 |
|------|------|------------|----------|
| 种子用户 | 最早一批核心用户 | 定义种子用户画像和招募渠道 | 内测邀请/KOL定向邀请/竞品用户迁移 |
| 种子内容 | 用户进来能看到的内容 | 确保上线前内容池已填充 | 运营预填充/PGC导入/爬取合规公开数据 |
| 种子供给 | 供给端（商家/司机/房源）先于需求端 | 供给侧先于需求侧上线 | 补贴供给侧/定向招商/自有供给 |
| 社区氛围种子 | 社区文化和互动规范的初始设定 | 制定社区规范和种子互动 | 官核+置顶引导帖/官方号互动示范 |

> [冷启动方法论 | 置信度:0.88]

### 1.3 PM职业视角（A.04）：增长与产品的节奏匹配

PM的核心职责不是做增长，而是**确保产品体验能接住增长带来的流量**：

```
增长节奏 ≤ 产品体验承载力
```

| 产品成熟度 | 推荐增长节奏 | 典型策略 |
|------------|-------------|----------|
| MVP验证期 | 自然增长为主 | 内测→小范围邀请→口碑传播 |
| PMF确认期 | 小规模投放测试 | 1-2个渠道小预算测试ROI |
| 体验稳定期 | 规模化增长 | 全渠道投放+裂变+SEO |
| 成熟优化期 | 精细化运营 | 渠道优化+留存运营+LTV提升 |

> 关键判断：**7日留存>20%是产品可以开始规模推广的最低门槛** [Andrew Chen | 置信度:0.85]

### 1.4 增长黑客 vs 黑产行为的边界

| 维度 | 合法增长黑客 | 黑产行为 |
|------|-------------|----------|
| 手段 | 数据驱动A/B测试优化 | 刷量/刷单/伪造数据 |
| 裂变 | 用户真实分享获得合理奖励 | 机器批量注册薅羊毛 |
| 获客 | 精准投放+内容营销 | 诱导下载/虚假宣传 |
| 合规 | 隐私合规+平台规则遵守 | 违规采集/突破平台限制 |

> 红线：**任何增长手段如果需要"绕过"平台规则或法律，就已经从增长黑客变成了黑产** [增长合规 | 置信度:0.92]

## 二、上线后运营盲区（D.01 定义 + D.02 坑类型变体）

### 2.1 坑类型全景

| 坑类型 | 变体 | 典型后果 |
|--------|------|----------|
| 功能上线即消失 | 上线后无人运营跟进，功能自然沉寂 | 开发投入浪费，用户找不到入口 |
| 无运营承接 | 运营团队不知道新功能上线 | 新功能无推广无内容，形同虚设 |
| 未做用户反馈收集 | 上线后不收集用户反馈 | 错过最佳修复窗口，小问题发酵成大投诉 |
| 上线=结束 | PM认为上线即项目结束 | 后续迭代无数据支撑，方向盲目 |

### 2.2 上线后运营承接框架

```
运营承接 = 功能通告 × 内容填充 × 用户引导 × 反馈收集 × 迭代规划
```

| 环节 | 具体动作 | 负责人 | 时间点 |
|------|----------|--------|--------|
| 功能通告 | 更新帮助文档/发版说明/运营群通知 | PM+运营 | 上线当天 |
| 内容填充 | 新功能所需的内容/数据已就位 | 运营 | 上线前1天 |
| 用户引导 | 新功能引导蒙层/弹窗/教程 | PM+设计 | 上线当天 |
| 反馈收集 | 客服通道/反馈入口/数据看板 | PM+客服 | 上线后持续 |
| 迭代规划 | 基于反馈和数据排期下一轮迭代 | PM | 上线后1周 |

> [运营承接实践 | 置信度:0.86]

## 三、避险技法（I.07）

### 3.1 冷启动避险 Checklist

- [ ] 种子用户已招募（数量≥100，画像匹配目标用户）
- [ ] 种子内容/供给已填充（用户进来非空白）
- [ ] 社区规范已制定（含审核规则和互动示范）
- [ ] 冷启动KPI已定义（首日留存/7日留存/内容互动率）
- [ ] 冷启动预算已审批（含供给侧补贴如需要）

### 3.2 推广避险 Checklist

- [ ] 7日留存≥20%才开始规模推广
- [ ] 推广渠道已做小预算测试（≥3天，有ROI数据）
- [ ] 渠道ROI归因链路已建立（可追踪每个渠道的转化成本）
- [ ] 反作弊机制已接入（设备指纹/行为分析/人机验证）
- [ ] 推广预算有日限额+止损线（超限自动暂停）
- [ ] 增长方案已通过合规审查（不违反平台规则和法律法规）

### 3.3 运营承接避险 Checklist

- [ ] 上线通知已发送（运营群+客服群+帮助文档）
- [ ] 新功能引导方案已上线（蒙层/弹窗/教程）
- [ ] 反馈收集通道已就绪（客服话术+反馈入口+数据看板）
- [ ] 上线后1周复盘会已排期
- [ ] 下一轮迭代方向已基于数据初步规划
- [ ] 运营承接责任已明确到人

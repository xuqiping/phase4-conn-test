## Chunk 3 · 暂停/停止生成（U6）

**目标**：流式生成中可停止；停止后保留已生成部分、计费随取消截止、不触发同步重答兜底。

**动作（伪代码）**：
1. **前端**：chat store `sendStreamingMessage` 建 `AbortController`，暴露 `stopStreaming()`：`controller.abort()` + `reader.cancel()`；abort 分支**跳过**既有「失败回退 REST sendMessage」逻辑（关键：回退=重新计费）；已收 chunk 保留在消息上，置 `stopped` 标记。
2. `ChatView` 流式气泡区/输入框加「停止」按钮（范式中 `RagAskPanel`），仅 streaming 中可见。
3. **后端取消链**（`ChatController.doStream`）：
   - 客户端断开 → `emitter.send` 抛异常 → doOnNext 包 RuntimeException 传播 → blockLast 抛出 → **上游 Flux 被 cancel**（现有级联已成立，补验证即可）。
   - catch 分支：`emitterTimedOut` 之外新增 `clientGone` 判定（send 抛的 IOException/IllegalStateException 特征），命中则**不重答**、仅 WARN 含 sessionId/traceId。
   - `emitter.onError/onCompletion` 回调补挂，置 `clientGone` 标志，防「send 未再触发而流挂着」的边角。
4. **部分内容落库**（**已拍板③：落库保留**）：`sendMessageStream` 服务层累计 buffer，`doOnCancel` 钩子里若非空则落一条 ASSISTANT 消息（content=已生成部分 + metadata `{stopped:true}`），usage 按取消口径计（指标三终态互斥红线照旧）。
5. WS 通道（`ChatWebSocketHandler`）不在本轮前端改造范围，但后端取消语义对它同样生效（连接关闭→send 抛→cancel）。

**涉及文件**：stores/chat.ts、api/chat.ts、ChatView.vue、ChatInput.vue（loading 态）、ChatController.java、ChatSessionService.java、单测 ×4（abort 不走 REST 回退 / doOnCancel 落库 / clientGone 不重答 / 停止后消息含 stopped 标）。**依赖**：无（与 Chunk 1 同文件不同区域，先落 1）。
**验证**：单测 + Playwright：长生成中途点停止 → 文本停在当前位置、刷新后部分内容仍在（若拍板③通过）、llm_usage_logs 无第二次调用。

## 技术坑点预判

1. **abort 与 REST 回退竞态**：chat store 失败回退逻辑（chat.ts:225-229,336-352）必须判 `signal.aborted`，否则停止=重发=双倍计费（与④同型坑）。
2. **doOnCancel 落库幂等**：cancel 与 error/complete 三终态互斥（指标红线同源），落库钩子也要防双触发（AtomicBoolean once）。
3. **卡片门控的 embed 复用**：候选门控与深读共用同一次 query 向量，勿 embed 两遍（8s 超时口径一致）。
4. **top-k 改制**：单文件 ≤2 chunk 后，`searchTopK` SQL 需按 memory_id 窗口（PG `ROW_NUMBER() OVER (PARTITION BY asset_memory_id ORDER BY distance)`），非简单 LIMIT。
5. **迁移号**：V129 取号前查 `flyway_schema_history` + 盘上 V*.sql 全量（多流并行撞号前科）。
6. **1200s 与 judge 内部调用无关**：内部 JSON 域超时独立（8s/局部），别顺手抬。
7. **vitest/后端回归基线**：chat 套件 451 绿（2 预存基线），每 chunk 全量跑。

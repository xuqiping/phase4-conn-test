# 取消商业化与开放模块设计

> 状态：设计已批准，尚未实施
>
> 日期：2026-08-24
>
> 变更类型：Phase 6 存量功能变更

## 1. 目标

File Keeper 取消按模块、设备数量和时间进行商业授权的产品模式。账号登录继续保留，只用于服务端身份认证、用户数据隔离和设备安全管理，不再决定用户能够使用哪些模块。

目标访问规则：

| 功能 | 未登录 | 已登录 |
|---|---|---|
| 文件管理 | 可用 | 可用 |
| 进程管理 | 可用 | 可用 |
| 剪贴板 | 可用 | 可用 |
| 截图 | 可用 | 可用 |
| 工作汇报及其互动能力 | 提示登录 | 可用 |
| AI 配置与 AI 总结 | 提示登录 | 可用 |

## 2. 已批准的产品决策

1. 保留桌面端注册、登录、退出和 Token 刷新。
2. 新注册用户直接进入 `active`，不再经过 `pending_review` 人工审核。
3. 所有登录用户自动获得全部服务端功能，不查询模块权益。
4. 未登录用户可使用全部纯本地功能。
5. 保留设备登录记录和管理员禁用设备能力。
6. 取消设备数量上限、模块权益、匿名试用、免费模块和离线授权 Token。
7. 保留管理后台账号认证、用户禁用和设备禁用能力。
8. 本轮采用分阶段移除：运行链路立即停止使用商业化机制；旧接口、字段和表先进入废弃兼容期，后续单独变更再物理删除。

## 3. 桌面端设计

### 3.1 本地模块

- 文件、进程、剪贴板和截图入口始终可用。
- 删除 `canUseTab()`、免费模块选择和授权拒绝提示等商业门禁。
- 剪贴板监听随应用生命周期启停，不再随授权状态启停。
- 截图及进程操作只保留业务参数校验和操作系统权限错误处理。

### 3.2 服务端模块

- 工作汇报 Tab 始终显示。
- 未登录进入工作汇报时展示登录引导；登录后加载当前用户的数据。
- AI 设置入口始终显示；未登录时展示登录引导，登录后允许管理配置。
- `workReportStore`、`aiConfigStore` 不再依赖 `commercialAuthStore`，只依赖登录态和有效 Token。

### 3.3 删除的商业化 UI

- 授权状态展示。
- 匿名试用状态。
- 免费模块选择器。
- 模块未购买、未授权、试用过期提示。
- 用户模块权益明细。

## 4. Rust/Tauri 设计

- 文件、进程、剪贴板、截图和工作汇报原生命令移除 `require_module()`。
- 废弃 signed entitlement 的设置、清除和模块访问检查命令。
- 前端不再向 Rust 同步离线授权凭据。
- 保留路径、截图区域、进程权限、剪贴板数据等原有业务与安全校验。
- 本地模块断网时保持可用；服务端模块断网时明确报告网络错误。

## 5. 服务端设计

### 5.1 身份认证

- 注册成功后用户状态直接为 `active`。
- 登录继续拒绝被管理员禁用的账号。
- access token、refresh token、用户身份解析和 `userId` 数据隔离保持不变。

### 5.2 工作汇报与 AI

- Controller 保留登录认证和资源归属检查。
- 删除对授权快照、模块代码和用户权益记录的检查。
- 任意正常登录用户均可调用工作汇报、互动收件箱、灵感、推送配置和 AI 配置接口。

### 5.3 设备安全

- 登录设备继续注册并记录。
- 不再比较 `deviceLimit`，设备数量不影响登录和功能访问。
- 被管理员禁用的设备继续拒绝服务端访问。

### 5.4 废弃兼容层

- 客户端授权、模块权益、匿名试用和免费模块接口标记为废弃。
- 新客户端不再调用这些接口。
- 兼容期内旧接口返回可预测响应，不产生无说明的 500 错误。
- 后续独立 Phase 6 变更再删除 Controller、Service、表和字段。

## 6. 管理后台设计

移除：

- 用户模块权益授予和撤销操作。
- 匿名设备试用运营入口。
- 默认设备额度、匿名试用天数、免费模块更换周期等商业设置。
- 用户详情中的模块权益和设备额度展示。

保留：

- 管理员登录。
- 用户列表、用户详情和账号禁用。
- 设备列表、登录记录和设备禁用。
- 与工作汇报模板等非商业运营能力有关的管理功能。

## 7. 数据迁移与兼容

本轮不物理删除商业化表和字段。新增 Flyway 迁移完成以下动作：

1. 将现有 `pending_review` 用户转换为 `active`。
2. 保留 `disabled` 等人工封禁状态。
3. 保留权益、匿名试用和离线授权历史数据，但运行逻辑不再读取。
4. 保留 `device_limit` 等旧字段，业务逻辑忽略其数值。

数据物理清理必须在兼容期结束后另立变更，并提供独立备份与回滚方案。

## 8. 错误处理

- 未登录访问服务端功能：提示“请先登录”，可直接打开登录弹窗。
- Token 过期：先刷新；刷新失败则清理会话并回到未登录状态。
- 网络不可用：显示连接失败，不回退匿名授权。
- 账号被禁用：明确显示账号禁用原因。
- 设备被禁用：明确显示设备禁用原因。
- 本地原生命令失败：继续展示操作系统权限或参数错误，不使用“模块未授权”表述。

## 9. 测试与验收

必须覆盖：

1. 未登录时四个本地模块和截图可用。
2. 未登录进入工作汇报或 AI 设置时提示登录。
3. 注册用户立即为 `active` 并可直接登录。
4. 没有任何权益记录的登录用户可使用全部服务端模块。
5. 超过旧设备上限仍可登录并记录设备。
6. 被禁用账号或设备仍被拒绝。
7. Rust 原生命令不依赖 signed entitlement。
8. 旧授权接口在兼容期内返回稳定结果。
9. 管理后台不再展示商业化入口。

回归命令至少包括桌面端 Vitest、Rust `cargo test`、服务端 Maven 测试、管理后台测试与构建。

## 10. 实施与回滚边界

建议按以下顺序提交：

1. 桌面端访问规则与 UI。
2. Rust 命令门禁移除。
3. 服务端认证、模块接口与 Flyway 迁移。
4. 管理后台商业化入口移除。
5. 文档同步和全量回归。

每个提交都必须可单独回滚。数据库迁移只做状态前向转换和兼容保留，不在本轮执行不可逆删表。

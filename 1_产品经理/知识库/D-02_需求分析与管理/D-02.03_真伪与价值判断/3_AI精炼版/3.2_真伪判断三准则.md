# 3.2 真伪判断三准则

## 准则一：场景匹配（JTBD验证）

> 核心判断：**这个需求是否对应一个真实的用户任务场景？**

### JTBD验证四问

| 问题 | 真需求信号 | 伪需求信号 |
|---|---|---|
| **1. 谁**在什么场景下有这个需求？ | 具体角色+具体场景 | 模糊群体+抽象场景 |
| **2. 他们在**完成什么任务？ | 明确的任务描述 | "就是想要个XX功能" |
| **3. 目前**怎么解决？ | 正在使用替代方案/变通方法 | "没有替代"（说明不迫切） |
| **4. 现有方案的**痛点是什么？ | 具体且可量化 | 泛泛而谈"不方便" |

### 验证公式

```
需求真伪 = f(场景具体性, 任务明确性, 替代方案存在性, 痛点可量化性)

真需求：具体场景 × 明确任务 × 已有替代(不好用) × 可量化痛点
伪需求：模糊场景 × 抽象任务 × 无替代(不迫切) × 不可量化痛点
```

## 准则二：行为验证（Behavioral Evidence）

> 核心判断：**用户确实在做/在找这件事，还是只是说说？**

### 行为验证三维度

| 维度 | 真需求信号 | 伪需求信号 | 数据来源 |
|---|---|---|---|
| **行为足迹** | 用户在产品中留下了寻找/尝试的痕迹 | 没有任何相关行为数据 | 埋点/搜索日志 |
| **变通行为** | 用户在用低效方式绕路完成类似任务 | 没有任何绕路行为 | 行为路径分析 |
| **付费意愿** | 用户为类似功能/替代方案付过费 | "如果有免费版我会用" | 付费转化数据 |

### 行为验证的具体方法

```
1. 搜索日志分析：用户有没有搜索过相关关键词？
   → 有搜索 = 有意图信号
   → 无搜索 = 伪需求嫌疑

2. 行为路径回溯：有没有用户在做类似的事情？
   → 有绕路 = 有痛点信号
   → 没绕路 = 可能不迫切

3. A/B假设测试：在当前流程中加一个提示/按钮，看点击率
   → 点击率>5% = 有兴趣信号
   → 点击率<1% = 伪需求嫌疑

4. 已有功能使用率：如果已有类似功能，使用率如何？
   → 使用率低 = 可能需求本身不成立
   → 使用率高但满意度低 = 功能改进需求（真）
```

## 准则三：价值量化（ROI估算）

> 核心判断：**做这个需求的价值是否大于成本？**

### 价值=影响面×频次×单价

| 维度 | 计算方法 | 数据来源 |
|---|---|---|
| **影响面** | 受影响用户数/总用户数 | 用户画像数据 |
| **频次** | 用户每周/月需要这个功能的次数 | 行为数据/访谈 |
| **单价（价值）** | 每次使用节省的时间/创造的收入 | 访谈/业务数据 |

### 简易ROI公式

```
需求ROI = (影响面 × 频次 × 单次价值) / (开发成本 + 维护成本)

ROI > 3:1 → 高价值需求，优先做
ROI 1:1 ~ 3:1 → 中等价值，需要验证
ROI < 1:1 → 低价值/伪需求，不建议做
```

### C端 vs B端的价值量化差异

| 维度 | C端 | B端 |
|---|---|---|
| **影响面** | 用户数(万/百万级) | 客户数(十/百级) |
| **单价** | 单用户ARPU低 | 单客户价值高(×客户规模) |
| **间接价值** | 留存/传播/NPS | 降本/提效/合规/客户续约 |
| **ROI计算** | 影响面×频次×ARPU | 客户数×客单价×续约率影响 |

## 三准则交叉判定

| 准则一（场景） | 准则二（行为） | 准则三（价值） | 判定 |
|---|---|---|---|
| ✅ 具体 | ✅ 有行为 | ✅ ROI>3 | **真需求，优先做** |
| ✅ 具体 | ❌ 无行为 | ✅ ROI>3 | **需求成立但可能不迫切，观察优先** |
| ✅ 具体 | ✅ 有行为 | ❌ ROI<1 | **真需求但价值不够，寻找低成本方案** |
| ❌ 模糊 | ✅ 有行为 | ✅ ROI>3 | **行为存在但场景不清，先搞清场景** |
| ❌ 模糊 | ❌ 无行为 | ✅ ROI>3 | **高危伪需求——ROI估算是假设不是事实** |
| ❌ 模糊 | ❌ 无行为 | ❌ ROI<1 | **伪需求，打回** |

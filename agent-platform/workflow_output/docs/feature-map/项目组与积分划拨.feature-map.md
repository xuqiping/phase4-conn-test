## 关键调用链

```
提交带 gid: 入口 view → api(xxxRequest.projectGroupId) → controller 透传 → task/log 落 gid
同步扣费:   LlmBillingService.charge → gid? → WalletService.chargeGroup
            （条件 UPDATE 组池 + used 累加 + ledger CONSUME 行, 幂等键）
异步媒体:   submit(三重预检+估价快照) → worker 完成 → MediaBillingService.chargeMedia
            → gid? → chargeGroup → 组池尽? → backstop(组长个人补差+BACKSTOP 行)
            失败 → refundMedia → refundGroup（组池+used 回滚, REFUND 行）
划拨回收:   ProjectGroupsView 弹窗 → allocate/reclaim → 个人↔组池 条件 UPDATE 双记账
查询:       ProjectGroupsView → overview(组长)/outputs(全员或self) → 批查补名
```

## 表与 SQL 注解（Flyway V133/V134）

- **V133__project_group.sql**（已执行不可改，改结构出新版本）：
  - `project_groups`：组主表。**生活比喻**=项目组的「工牌」——名字、描述、组长是谁。
  - `project_group_members`：成员表（group_id+user_id 唯一，quota_limit_points 可空=不限，used_points 记已用）。**比喻**=组员的「饭卡额度」——卡上限多少、已刷多少。
  - `project_group_wallets`：组池余额（一表一行组）。**比喻**=组的「公共钱包」，只有组长能存取。
  - `project_group_ledger`：append-only 流水（type/delta_points/**balance_after**/ref_type/ref_id），(group_id, created_at) 索引。**比喻**=钱包的「流水小票」，只许贴新不许撕旧，每张都写当时余额——对账就靠它。
  - `llm_usage_logs.project_group_id`、`media_gen_tasks.project_group_id/estimated_cost` 加列：**比喻**=账单和任务单上加「哪个组报销」栏；estimated_cost=提交时估价小票，回收封顶就扣它。
- **V134**：权限码 `project-group:manage` 种子+默认角色分配。**比喻**=发「能进项目组功能」的门禁卡。

## 踩坑批注

- Mockito 重载坑×3：chargeMedia 10→11 参、refundMedia 4→5 参、pageDetail 10→11 参改签名后，旧 stub **静默失配**（不同方法不报错）——stub/verify 必须同步升参。
- LambdaQueryWrapper.select() 在纯单测（无 MP TableInfo 缓存）抛 "can not find lambda cache"→ 用 QueryWrapper 列名字符串。
- record VO 不能继承（DetailVO 是 record）→ OverviewVO 用组合。
- 画布 gid 不落节点 data 快照（仅顶层）——运行时注入防旧节点被历史 gid 污染。

# 5.1 案例集

## 一、跳层失败案例（3例）

### 案例1：跳数据直接做增长

| 维度 | 内容 |
|---|---|
| **名称** | 某C端产品"无数据增长"事件 |
| **时间** | 2024 |
| **主角** | 某社交产品增长团队 |
| **背景** | 团队从运营转岗做增长，未建立指标体系就直接制定增长策略 |
| **技术手法** | 跳过D-06.01指标体系，用"感觉"而非数据驱动增长决策 |
| **影响后果** | 3个月增长投入全部浪费——日活增长2%但留存下降5%，净效果为负；无法归因哪些策略有效哪些无效 |
| **教训** | 跳D-06.01直接做D-07.01 = 无度量增长 = 投入无法归因 = 策略不可迭代 |
| **依赖规律** | D-06.01指标体系是D-07.01增长方法论的硬前置，不是"建议先学"而是"不学就做不了" |
| **PM行动项** | 做增长前必须完成指标体系搭建；每个增长假设必须对应可度量指标 |

### 案例2：跳合规直接做AI产品

| 维度 | 内容 |
|---|---|
| **名称** | 某AI产品合规翻车事件 |
| **时间** | 2025 |
| **主角** | 某创业公司AI产品团队 |
| **背景** | 团队无合规基础，直接上线AI对话产品 |
| **技术手法** | 跳过D-16合规，D-19.06 AI风险合规未做，产品上线即被监管问询 |
| **影响后果** | 产品下架整改2个月，用户流失60%，团队被迫补学合规知识 |
| **教训** | 合规不是"可选"而是"必选"前置，跳合规的AI产品 = 裸奔产品 |
| **依赖规律** | D-16.01数据隐私→D-16.03安全合规→D-19.06 AI风险合规是合规铁三角，必须链式完成 |
| **PM行动项** | AI产品上线前必须完成合规自检；用D-24.09 § 4.2的合规自检清单逐项审查 |

### 案例3：跳用户直接做交互设计

| 维度 | 内容 |
|---|---|
| **名称** | "设计师思维"产品失败案例 |
| **时间** | 2023 |
| **主角** | 某工具产品团队（设计驱动型） |
| **背景** | 团队由设计师主导，跳过用户研究直接做交互设计 |
| **技术手法** | 跳过D-03.01用户画像，凭设计师直觉设计交互 |

| **PM行动项** | 设计前必须做用户研究；信息架构必须基于用户心智模型而非设计师直觉 |

| 维度 | 内容 |

| **时间** | 2024-2025 |
| **主角** | 字节跳动产品学院 |
| **背景** | 需要系统化培训大量新PM，确保培训效率 |
| **技术手法** | 基于PM能力模型构建学习依赖DAG，先教瓶颈节点（产品思维+数据指标），再按分轨分流 |
| **影响后果** | 新PM 3个月胜任率从40%提升到75%；培训成本下降30% |

| **依赖规律** | 瓶颈节点优先策略ROI最高——先教D-09.01产品思维解锁23+后续节点 |
| **PM行动项** | 团队培训时先画依赖DAG，找瓶颈节点优先教 |

### 案例5：Google APMM项目的分层设计

| 维度 | 内容 |
|---|---|
| **名称** | Google Associate Product Manager 项目的依赖分层 |
| **时间** | 持续（2007至今） |
| **主角** | Google APMM项目团队 |
| **背景** | Google内部PM培养项目，需要从零培养PM |
| **技术手法** | 明确三阶段依赖——Phase1:用户+数据基础(无前置), Phase2:产品+设计(依赖Phase1), Phase3:战略+领导(依赖Phase2) |
| **影响后果** | 培养出大量优秀PM（Marissa Mayer等），APMM项目成为PM培养标杆 |
| **教训** | 明确的依赖分层让学习路径从"混沌"变"有序"，每个阶段有清晰的"解锁条件" |
| **依赖规律** | 分阶段学习 = 显式知识锁机制——Phase1所有L3完成才能进Phase2 |
| **PM行动项** | 用知识锁机制设计学习阶段——每阶段设"解锁条件" |

### 案例6：某大厂PM转岗路径设计

| 维度 | 内容 |
|---|---|
| **名称** | C端PM转B端PM的增量前置识别 |
| **时间** | 2025 |
| **主角** | 某互联网大厂PM团队 |
| **背景** | 10名C端PM需要转岗做B端，需要高效补课 |
| **技术手法** | 用分轨增量前置方法——先识别C端已有基础（D-01~09大部分），再算B端增量（D-17+D-18），避免重复学 |
| **影响后果** | 转岗适应期从6个月缩短到3个月，不需要从头学C端已有知识 |
| **教训** | 转岗学习不是"从零开始"——增量前置分析能大幅缩短适应期 |
| **依赖规律** | 分轨增量 = 总量前置 - 已有基础 = 只学增量，不重复 |
| **PM行动项** | 转岗前先做增量前置分析，只补差的部分 |

### 案例9：产品思维瓶颈突破

| 维度 | 内容 |
|---|---|
| **名称** | "先学产品思维"的投资回报率验证 |
| **时间** | 2023 |
| **主角** | 某PM训练营 |
| **背景** | 100名新人PM，随机分两组——A组按依赖顺序学（先D-09），B组按兴趣自由学 |
| **技术手法** | A组先花1周学D-09.01产品思维+D-09.02经典框架，再进D-02需求；B组直接学各自感兴趣的维度 |
| **影响后果** | 3个月后A组胜任率65% vs B组30%；A组跳层失败率5% vs B组40% |
| **教训** | 瓶颈节点(产品思维)的优先投资回报率是其他节点的2倍以上 |
| **依赖规律** | 全局瓶颈节点D-09.01被23+后续依赖，先学=解锁最多后续 |
| **PM行动项** | 新人PM第一周必须先学产品思维和经典框架，这是ROI最高的学习投入 |

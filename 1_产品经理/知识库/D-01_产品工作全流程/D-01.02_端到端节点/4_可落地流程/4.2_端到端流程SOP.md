## 端到端流程 SOP

### 适用场景

- 新PM需要了解完整产品流程
- 团队建立标准化工作流
- 解决"中间丢东西"的协作问题

### SOP步骤

---

#### Step 1：确定产品类型与节点组合

| 产品类型 | 节点组合 | 周期 |
|---|---|---|
| C端小功能 | 调研+分析(合并)→设计(自审)→开发→测试→上线→运营 | 1-2周 |
| C端大功能 | 全部七节点 | 4-8周 |
| B端标准 | 七节点+POC+UAT+部署 | 8-16周 |
| B端定制 | 七节点+POC+UAT+会签+培训+维保 | 12-24周 |
| 内部工具 | 调研+分析+设计(合并)→开发→测试→上线 | 2-4周 |

#### Step 2：启动需求调研

- [ ] 确认需求来源与场景
- [ ] 深挖真实问题(非表面需求)
- [ ] 标注优先级初判
- [ ] 录入需求池

#### Step 3：完成分析定义

- [ ] PRD含功能范围+用户故事+验收标准
- [ ] 边界条件与异常流已覆盖
- [ ] 非功能需求(性能/安全/兼容)已标注
- [ ] 技术可行性已与研发确认

#### Step 4：通过设计评审

- [ ] 交互设计覆盖PRD所有功能点
- [ ] 技术方案可行且覆盖边界
- [ ] 评审意见全部闭环
- [ ] 设计稿与技术方案版本对齐

#### Step 5：确认研发排期

- [ ] 任务拆分(WBS)至人/天级别
- [ ] 依赖关系已标注
- [ ] 预留15-20% buffer
- [ ] 包含测试+部署时间

#### Step 6：执行测试验收

- [ ] Test Case覆盖正常流+异常流+边界
- [ ] P0/P1 Bug=0
- [ ] PM按PRD逐项验收
- [ ] 验收记录签字留档

#### Step 7：上线发布

- [ ] 灰度/AB策略确定
- [ ] 回滚方案已验证
- [ ] 运营/客服已同步
- [ ] 上线后24小时监控

#### Step 8：运营迭代

- [ ] 1-2周数据复盘
- [ ] 用户反馈归类入需求池
- [ ] 核心指标达成评估
- [ ] 迭代方向确认

### 关键交付物汇总

| 节点 | 必须交付 | 可选交付 |
|---|---|---|
| 调研 | 需求条目 | 访谈记录/数据报告 |
| 分析 | PRD | 用户故事地图/竞品对比 |
| 设计 | 评审通过设计稿 | 原型Demo/技术方案 |
| 排期 | Sprint计划/WBS | 风险清单 |
| 测试 | 测试报告+PM验收记录 | 自动化测试脚本 |
| 上线 | 上线通知+灰度数据 | 变更记录/回滚验证 |
| 运营 | 数据复盘报告 | 迭代需求池更新 |

# D-24.03 Agent工具调用 — 引用场景

## 场景1：工具系统从0设计（新建Agent产品需设计完整工具系统）

**何时进入**：新建 Agent 产品，需要从0设计工具系统——决定用哪些工具、怎么描述工具、怎么执行工具、怎么防错。

**查什么**：
- 3_AI精炼版 → 三种工具调用范式对比（Function Calling / Computer Use / Cloud Sandbox 适用边界）
- 4_可落地流程 → 4.1 工具系统设计Agent（8段元提示词辅助设计） + 4.2 工具Schema设计表模板 + 工具发现注册流程模板
- 1_知识库概览 → 核心要素表（8项工具系统工程化要素）

**PM 要回答的问题**：
- 我的 Agent 需要调用哪些工具？API 优先还是 Computer Use？
- 工具数量控制在多少？超出怎么动态发现？
- 每个工具的 Schema 怎么写？参数类型怎么定义？
- 执行在本地还是沙箱？副作用怎么治理？

## 场景2：Function Calling 标准化落地（已有Agent需标准化工具调用接口）

**何时进入**：Agent 已有自研工具调用逻辑，需标准化为 Function Calling（OpenAI/Anthropic 标准 JSON Schema），或需接入 MCP 生态。

**查什么**：
- 3_AI精炼版 → 3.1 Function Calling深度（OpenAI strict mode / Anthropic input_schema / JSON Schema 设计原则 / 参数幻觉根因 / 5个生产陷阱）

**PM 要回答的问题**：
- OpenAI strict mode 和 Anthropic 普通模式怎么选？

## 场景3：Computer Use 桌面/浏览器操控集成（Agent需操控GUI软件）

**何时进入**：Agent 需要操控没有 API 的桌面软件或 Web 应用（如操作 Excel、操控浏览器填表、操作 legacy 系统），必须用 Computer Use。

**PM 要回答的问题**：

## 场景5：参数幻觉防护（生产环境Agent频繁调错参数）

**何时进入**：Agent 已上线，生产环境频繁出现工具调用参数错误（类型错/值错/缺失/编造），导致工具执行失败或错误结果。

# 安全体系 S2 防篡改与越权 · 测试方案

> Phase 3 人工/渗透测试基准。自动化能断言的走单测/IT（AuditHashChainServiceTest 13 / AuditChainVerifyServiceTest 8 / SessionServiceTest 9 / InflightGateServiceTest 10 / B2 越权 IT 3 类等），本方案只收「要人点 / 走真实环境 / 部署后确认」的用例。
> 对应 plan：[安全体系_S2防篡改与越权.plan.md](../plans/安全体系_S2防篡改与越权.plan.md)

## 前置条件

- 后端含 S2 全部 commit，V81 迁移已执行（`audit_logs` 有 `prev_hash/record_hash` 两列）。
- 环境变量 `AUDIT_HMAC_KEY` 已注入（≥32 字符）；另备「停 Redis」降级验证窗口。
- 测试账号：普通用户 A、B（同账号双浏览器/双设备）、admin。

## 一、渗透自查用例（自动化覆盖不了的浏览器/部署层确认）

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| P1 | 审计篡改检测（SEC-FR-040/042） | 造几条审计 → 用 **admin 库账号**手工 UPDATE 一条 audit_logs 的 detail_json → 调 `GET /api/audit/logs/verify-chain`（或等次日 03:40 定时） | 返回 `ok=false` + firstBrokenId；写 audit/chain_broken 审计；ERROR 日志 |
| P2 | 审计删行检测 | 手工 DELETE 链中间一行 → 再校验 | 断链检出（后行 prev_hash 对不上） |
| P3 | 外部锚定（SEC-FR-043） | 校验成功后查 `logs/audit-anchor.log` | 追加一行 `timestamp lastRowId=N recordHash=...` |
| P4 | 存量行兼容 | 校验含 S2 前存量审计（record_hash NULL）的库 | NULL 行只允许作连续前缀，校验通过不误报 |
| P5 | 单点登录踢人（SEC-FR-008） | 浏览器①登录账号 A → 浏览器②登录同账号 A → 回浏览器①操作/刷新页面 | ①的请求 401 + `code=40104 账号已在别处登录`；①refresh 也 40104；audit_logs 有 `auth/session_kicked` 一行（仅踢的瞬间一次） |
| P6 | 单点登录降级 | 停 Redis → 双端同账号各自操作 | 均可用（降级放行）+ WARN 日志；恢复 Redis 后新登录恢复踢人 |
| P7 | 低余额闸门（SEC-FR-126） | 账号 B 余额调到 99（<默认阈值 100）→ 连发 2 条对话（或 2 个视频任务） | 第 2 个 42902「余额不足，请等待当前任务完成」；audit_logs 有 `billing/inflight_rejected` |
| P8 | 闸门恢复 | 等第 1 个任务跑完 → 再发 | 放行；余额充到 ≥100 → 立即恢复并行 |
| P9 | 槽位泄漏兜底 | 低余额用户在途任务进行中杀后端进程 → 30min 内重启 | 槽位最迟 30min 自动释放（TTL），不永久误闸 |

## 二、功能联动用例（plan 联动点清单逐条对应）

| # | 触发动作 | 联动对象预期 |
|---|---|---|
| L1 | S2 上线后旧 token | 无 sid claim 的旧 access/refresh 一律 40104 强制重登一次（与 G1 轮换公告合并） |
| L2 | 关闭单点登录开关 | admin 设置页「认证设置→单点登录」关掉 → 同账号双端可同时在线（恢复多会话） |
| L3 | 改计费阈值 | admin 设置页「计费设置」阈值 100→50、在途 1→2 → **立即生效**（余额 99 用户可并行 2 个） |
| L4 | 低余额用户 KB 索引/embed | 不受闸（embed 与 userId=null 系统调用不过闸），只对话/视频生成被限 |
| L5 | 端点覆盖扫描（SEC-FR-010） | 启动日志 WARN 列出未加 @RequirePermission 端点（应只有白名单内）；`security.endpoints.unguarded` 指标可查 |
| L6 | 审计链写入并发 | 并发操作（多用户同时登录/充值/上传）→ 链校验仍通过（advisory lock 串行化，无分叉） |
| L7 | 媒体任务失败/超时 | 低余额用户任务失败或超时 → 槽位释放，下一个任务可提交 |

## 三、边界/异常场景

| # | 场景 | 预期 |
|---|---|---|
| E1 | `AUDIT_HMAC_KEY` 缺失/过短启动 | 应用拒绝启动（fail-fast，同 JWT_SECRET 范式） |
| E2 | 阈值/在途数填非法值（SQL 直改 system_settings 为非数字） | 回退默认 100/1，不炸 |
| E3 | 应用库账号（agent_app）对 payment_orders / idempotency_keys DELETE | DB 层 REVOKE 拒绝（SEC-FR-041/044，D2/D5） |
| E4 | 新写 Controller 方法不加权限注解 | 启动 WARN + unguarded gauge +1（B1）；属于用户资源的须走 B2 越权 IT（403 显式，500 绝不可） |
| E5 | logout 后旧 token 复用 | 黑名单 + session 键已删双保险，401 |

## 四、人工阻断项（无人工无法闭合）

| # | 项 | 说明 |
|---|---|---|
| H1 | AUDIT_HMAC_KEY 生产注入 | 生成 ≥32 字符随机密钥（`openssl rand -base64 48`）入环境变量；**入 G1 轮换清单**（与 JWT_SECRET 同批轮换，轮换=旧链无法续验，需先锚定归档） |
| H2 | 单点登录上线公告 | 上线即全部旧 token 强制重登一次，与 G1 轮换公告合并发布 |
| H3 | 链校验告警接入 | audit/chain_broken 目前 ERROR 日志+审计行，告警通道（邮件/IM）接运维侧配置 |

## 通过标准

- P1~P9、L1~L7、E1~E5 全过；H1~H3 人工闭环登记。
- 全部自动化测试绿（哈希链/校验/会话/闸门单测 + B2 越权 IT 3 类）+ check_all 全绿。
- 回归：登录/刷新/登出、对话/流式、视频生成提交-完成全链正常。

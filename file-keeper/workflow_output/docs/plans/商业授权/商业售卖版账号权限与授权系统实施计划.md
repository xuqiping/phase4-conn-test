# File Keeper 商业售卖版账号权限与授权系统实施计划

> **面向执行者说明：** 本计划用于分阶段实现 File Keeper 商业售卖版账号、权限、设备授权、匿名试用、管理后台与桌面客户端门禁。执行时必须遵循测试驱动开发：先写失败测试，再实现功能，再验证测试通过。  
> 日期：2026-06-06  
> 语言：中文

**目标：** 在不上传用户本地业务数据的前提下，为 File Keeper 增加可售卖的账号、模块授权、设备绑定、匿名试用和 Web 管理后台。

**架构：** 新增 `file-keeper/server/` 作为 Spring Boot 授权服务，新增 `file-keeper/admin-web/` 作为 Vue 管理后台，改造现有 Tauri 桌面客户端以接入登录、设备指纹、权益快照和模块门禁。第一版不接支付、不做业务数据同步。

**技术栈：** Spring Boot 3、Java 17、PostgreSQL、Redis、Flyway、Vue 3、TypeScript、Vite、Naive UI、Tauri 2、Rust、Pinia。

---

## 1. 实施总原则

1. 先服务端，后管理后台，最后桌面客户端。
2. 不同步文件收藏、剪贴板历史、截图内容等本地业务数据。
3. 第一版只按 3 个主模块授权：`files`、`processes`、`clipboard`。
4. 未登录/免费用户必须联网。
5. 登录授权用户是否可离线使用，由管理员配置离线缓存时长决定。
6. 每个阶段都要有可运行、可测试、可验收的结果。

1. 启动服务端和管理后台。
2. 启动桌面客户端，未登录状态联网拉取匿名权益。
3. 新设备显示 7 天全功能体验。
4. 模拟 7 天过期后，客户端要求选择长期免费模块。
5. 选择 `files` 后，只能进入文件管理模块。
6. 注册邮箱或手机号账号。
7. 验证联系方式。
8. 管理员在后台看到待审核用户。
9. 管理员审核用户，授权 `files` 和 `clipboard`，设置到期时间。
10. 客户端登录该用户。
11. 客户端可进入文件管理和剪贴板，不能进入进程管理。
12. 管理员设置设备上限为 1。
13. 第二台设备登录同账号时被拒绝绑定。
14. 管理员解绑旧设备后，新设备可登录。
15. 管理员将离线缓存设置为 0，客户端断网后授权模块不可用。
16. 管理员将离线缓存设置为非 0，客户端刷新授权后断网仍可在缓存期内使用。
17. 模块授权到期后，客户端降级匿名权益。

## 9. 推荐提交节奏

建议每个阶段至少 1 个提交，复杂阶段可拆多个提交：

1. `feat: 初始化商业授权服务端基础工程`
2. `feat: 实现账号注册登录和管理员审核接口`
3. `feat: 实现模块授权设备绑定和匿名试用接口`
4. `feat: 添加商业授权管理后台 MVP`
5. `feat: 桌面客户端接入登录注册和权益快照`
6. `feat: 实现桌面客户端模块门禁`

提交前必须运行对应阶段验证命令。

## 10. 风险与注意事项

1. 设备指纹存在误伤风险，必须保留管理员解绑/重置能力。
2. 匿名用户必须联网，否则很容易被本地清配置绕过。
3. 不要把剪贴板内容、截图内容、文件收藏路径上传到服务端。
4. 第一版不要提前做支付，否则会显著拉长交付周期。
5. 关键模块门禁不能只做视觉隐藏，后续需要补 Rust 侧二次校验。
6. 邮箱/短信服务第一版可以先抽象 provider，不要把具体供应商逻辑写死。
7. 所有管理员高风险操作都要写审计日志。

---

## 11. 完成定义

商业授权第一版完成时，应满足：

- 服务端可部署并连接 PostgreSQL、Redis。
- 超级管理员可初始化并登录管理后台。
- 普通用户可注册、验证联系方式、登录。
- 管理员可审核用户并授权模块。
- 管理员可设置模块到期时间、设备上限、离线缓存时间。
- 管理员可管理用户设备和匿名设备。
- 未登录用户联网时可获得 7 天全功能体验。
- 7 天后未登录用户只能使用 1 个长期免费模块。
- 未登录用户离线时不可用。
- 登录用户只能使用被授权且未过期的模块。
- 登录用户可按管理员配置使用离线缓存。
- 授权到期后客户端降级匿名权益。
- 文件收藏、剪贴板历史、截图内容不上传服务端。

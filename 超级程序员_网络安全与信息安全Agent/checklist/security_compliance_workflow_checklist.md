# Security Compliance Workflow Checklist

在完成 `workflow/security_compliance_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别企业安全合规需求场景

- [ ] 已明确场景类型（等保测评/关保合规/数据安全法合规/PIPL合规/隐私计算方案/政企安全架构/AI安全合规/跨境数据合规）
- [ ] 已识别行业属性（金融/电信/能源/医疗/政务/互联网/制造业）
- [ ] 已提取数据资产规模（个人信息数量/数据总量/敏感数据类型）
- [ ] 已提取跨境需求（是否有数据出境/出境类型和量级）
- [ ] 已识别现有合规状态（等保级别/DPO/数据分类分级）
- [ ] 已提取关键痛点（合规成本高/测评不通过/分类分级困难/跨境路径不明/AI合规盲区/国密改造压力）
- [ ] 已对照知识库合规框架完成初步判断（未定等保→定级/跨境→三大路径/多方协作→隐私计算/大型政企→SABSA+零信任/AI产品→AI安全五层）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出企业安全合规方案

- [ ] 如为等保合规，定级方法SAG已说明（识别受侵害客体→判定侵害程度→查表定级）
- [ ] 如为等保合规，2025版测评变化已输出（取消百分制改三级判定/重大风险隐患/AI扩展要求）
- [ ] 如为等保合规，一个中心三重防护已覆盖（安全通信网络/区域边界/计算环境/管理中心）
- [ ] 如为等保合规，国密要求已说明（SM2/SM3/SM4三级及以上强制使用）
- [ ] 如为等保合规，关保特殊要求已输出（年度检测评估/供应链审查/数据本地化）
- [ ] 如为等保合规，测评准备与整改已覆盖（差距分析/整改优先级/技术整改/管理整改/测评流程）
- [ ] 如为等保合规，投入参考已给出（中型500-1500万/大型3000万-1亿/中小企业MSS 20-60万）
- [ ] 如为数据安全法，数据三级分级已说明（一般/重要/核心）
- [ ] 如为数据安全法，分类分级三步法已输出（资产梳理→分类→分级）
- [ ] 如为数据安全法，全生命周期安全已覆盖（采集/传输/存储/使用/交换/销毁）
- [ ] 如为PIPL，七大原则已说明（合法正当必要诚信/明确目的/最小必要/公开透明/告知同意/质量保证/安全保障）
- [ ] 如为PIPL，核心要求已输出（告知同意/最小必要/敏感信息单独同意/100万人以上合规审计+DPO）
- [ ] 如为PIPL，个人权利保障已覆盖（知情/决定/查阅复制/可携带/更正补充/删除/解释说明）
- [ ] 如为跨境合规，三大路径已说明（安全评估/标准合同/保护认证）
- [ ] 如为跨境合规，豁免场景已输出（自贸港负面清单/学术司法/跨境贸易）
- [ ] 如为隐私计算，五大技术路线已对比（MPC/联邦学习/同态加密/差分隐私/TEE）
- [ ] 如为隐私计算，选型决策矩阵已给出（高合规云上→TEE/跨多方建模→联邦学习/精确计算→MPC/统计发布→差分隐私）
- [ ] 如为隐私计算，数据脱敏方案已覆盖（静态SDD/动态DDM/四维策略矩阵）
- [ ] 如为政企架构，SABSA六层模型已说明（业务上下文→概念→逻辑→物理→组件→运营+AI安全扩展）
- [ ] 如为政企架构，零信任三步构建已输出（IAM→SASE→XDR/五维动态授权）
- [ ] 如为政企架构，SOC四层金字塔已覆盖（采集→检测→响应→度量/升级路径/AI自治运营）
- [ ] 如为政企架构，AI安全五层防护已说明（输入过滤/模型安全AI-BOM/推理隔离/输出DLP/Agent审计）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 法规引用（等保2.0/数据安全法/PIPL/关保）准确
- [ ] 已向用户交付最终答案

## Overall

- [ ] 工作流中的所有步骤已按顺序执行，没有跳过
- [ ] 每一步都已与其检查清单部分进行交叉验证
- [ ] 没有在任何检查清单部分通过前提前进入下一步
- [ ] `task/current_task.md` 已更新完成记录
- [ ] 所有 `[参考: ...]` 标注均指向存在的知识库文件

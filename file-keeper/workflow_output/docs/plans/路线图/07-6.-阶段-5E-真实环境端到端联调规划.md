### 6.3 联调场景清单

#### 场景 1：匿名设备首次 7 天全功能试用

- [ ] 清理桌面端本地 `file-keeper-auth.json` 或使用新设备身份。
- [ ] 启动桌面端。
- [ ] 确认客户端调用 `POST /api/anonymous/trial/start`。
- [ ] 确认客户端调用 `GET /api/anonymous/authorization`。
- [ ] 确认 files/processes/clipboard 三个模块都可进入。
- [ ] 确认授权状态显示“匿名 7 天全功能试用”。

Expected: 三个模块可用，无登录也能使用试用授权。

#### 场景 2：匿名试用过期后选择免费模块

Use DB to expire current anonymous trial:

```sql
UPDATE anonymous_device_trials
SET trial_expires_at = NOW() - INTERVAL '1 day'
WHERE device_id = '<current-device-id>';
```

- [ ] 重启桌面端或刷新匿名授权。
- [ ] 确认三个模块默认不可用或提示选择免费模块。
- [ ] 选择 `files` 作为免费模块。
- [ ] 确认 `POST /api/anonymous/trial/select-free-module` 成功。
- [ ] 确认 files 可用，processes/clipboard 不可用。

Expected: 匿名过期后可自助选择一个长期免费模块。

#### 场景 3：注册用户等待管理员审核

- [ ] 在桌面端打开注册。
- [ ] 输入邮箱或手机号。
- [ ] 发送验证码。
- [ ] 使用开发验证码 `123456` 完成校验。
- [ ] 设置密码并提交注册。
- [ ] 确认注册用户状态为 `pending_review`。
- [ ] 登录该账号。
- [ ] 确认授权状态显示“等待管理员审核”。
- [ ] 确认如果没有商业授权，仍按匿名兜底权限使用。

Expected: 注册、验证码、登录和 pending_review 展示都可用。

#### 场景 4：管理员审核通过并授予模块

- [ ] 打开管理后台。
- [ ] 使用 `admin@filekeeper.local` / `Password123!` 登录。
- [ ] 在用户列表找到 pending_review 用户。
- [ ] 审核通过。
- [ ] 进入用户详情。
- [ ] 设置 `deviceLimit = 1`。
- [ ] 设置 `offlineCacheMinutes = 60`。
- [ ] 授予 `files` 和 `clipboard` 模块。
- [ ] 不授予 `processes`。

Expected: 用户状态 active，权益列表包含 files/clipboard，设备限制和离线缓存设置保存成功。

#### 场景 5：桌面端登录用户设备绑定与授权查询

- [ ] 在桌面端登录审核通过的用户。
- [ ] 确认调用 `POST /api/client/devices/register`。
- [ ] 确认调用 `GET /api/client/authorization?deviceId=...`。
- [ ] 确认 files/clipboard 可用。
- [ ] 确认 processes 不可用，并显示未授权原因。
- [ ] 确认授权状态显示离线缓存截止时间。

Expected: 登录授权优先，匿名授权只作为兜底。

#### 场景 6：设备上限

- [ ] 保持用户 `deviceLimit = 1`。
- [ ] 在第二个本地设备身份上登录同一账号，或手动清理/替换 deviceId 模拟第二台设备。
- [ ] 确认 `POST /api/client/devices/register` 返回 409。
- [ ] 确认桌面端显示设备数量超限。
- [ ] 在管理后台禁用旧设备。
- [ ] 再次尝试新设备登录。

Expected: 第二台设备被拒绝；禁用旧设备后新设备可绑定。

#### 场景 7：管理员禁用设备后授权失效

- [ ] 管理后台进入用户详情。
- [ ] 禁用当前桌面端设备。
- [ ] 桌面端刷新授权或重新登录。
- [ ] 确认该设备的登录授权不可用。
- [ ] 确认客户端回退匿名授权或显示设备禁用原因。

Expected: 禁用设备后不能继续使用商业授权模块。

#### 场景 8：离线缓存策略

Case A: `offlineCacheMinutes = 60`

- [ ] 管理后台设置用户 `offlineCacheMinutes = 60`。
- [ ] 桌面端刷新登录授权。
- [ ] 停止后端或断网。
- [ ] 重启桌面端或触发授权刷新。
- [ ] 确认缓存期内仍可使用已授权模块。

Case B: `offlineCacheMinutes = 0`

- [ ] 管理后台设置用户 `offlineCacheMinutes = 0`。
- [ ] 桌面端刷新登录授权。
- [ ] 停止后端或断网。
- [ ] 确认登录授权不可离线使用，匿名也因联网要求不可用。

Expected: 离线行为与管理员配置一致。

#### 场景 9：模块授权到期降级

Use DB or 管理后台设置短过期时间：

```sql
UPDATE user_module_entitlements
SET expires_at = NOW() - INTERVAL '1 minute'
WHERE user_id = <user-id>
  AND module_code = 'clipboard';
```

- [ ] 桌面端刷新登录授权。
- [ ] 确认 clipboard 登录授权失效。
- [ ] 如果匿名授权允许 clipboard，则可匿名兜底；否则不可用。
- [ ] 确认 UI 显示过期或未授权原因。

Expected: 过期权益不再授权，模块访问降级符合规则。

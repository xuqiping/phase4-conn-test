# 3.3 加载等待、信任透明与2026前沿

## 一、传统UX三假设在AI时代的失效

传统UX的三大底层假设在AI产品里全部失效，照搬传统UX会出大问题：

| 假设 | 传统含义 | AI时代失效原因 | 应对 |
|---|---|---|---|
| **输入确定** | 用户输入明确意图 | 用户常常"说不清楚"自己要什么 | LUI+GUI融合/GenUI直接给可视化 |
| **输出确定** | 同样输入必然同样输出 | 模型概率生成，同样输入不同输出 | 接受不确定性/设计纠错闭环 |
| **响应快速** | 操作<1秒响应 | 推理+生成数秒到数十秒 | 阶段化提示+流式+取消能力 |

> 来源：[站酷/腾讯云 | 🔍高 | 2026-03]

## 二、加载与等待体验设计

### 2.1 传统Spinner为什么不行

大模型是"推理型"和"创作型"，生成深度报告、高精度图片可能要几秒到数十秒。传统菊花图/进度条在这种场景下让用户以为"卡死"——传统软件几百毫秒搞定的事，AI要数十秒，用户的等待焦虑成倍放大 [来源:站酷 | 🔍高 | 2026-03]。

### 2.2 阶段化提示设计

把"AI在做什么"分阶段告诉用户，破解焦虑：

| 阶段 | 示例提示语 |
|---|---|
| 启动 | "正在理解你的需求…" |
| 检索 | "正在搜索相关资料…（已找到X条）" |
| 分析 | "正在分析…（已分析X条）" |
| 生成 | "正在生成答案…（已写X字）" |
| 校验 | "正在校验事实/格式…" |
| 完成 | "完成了，请查收" |

### 2.3 流式呈现（最核心）

| 流式方式 | 典例 | 优势 |
|---|---|---|
| **Token流式** | ChatGPT打字机效果 | 首字最快，等待感最低 |
| **部分结果先行** | 代码先生成结构再填实现 | 关键内容先呈现 |
| **流式渲染** | Markdown边生成边渲染 | 可读性最佳 |
| **多模态流式** | 图像生成时先显示草图→细化 | 用户能中途喊停 |

> 设计要点：流式首字延迟建议<1s；推理模型（o1/R1）首字延迟较长，需先用"思考中"占位

### 2.4 骨架屏与占位

- **内容骨架屏**：先渲染卡片/列表/区块占位，内容渐进填充
- **结构预渲染**：先生成结果结构再填内容（如先生成报告目录再填章节）
- **流式图表**：图表先渲染坐标轴再逐步绘制数据点

### 2.5 取消能力（必须）

- 用户可随时取消长耗时任务
- 取消要"快速生效"（不能卡几秒才停）
- 取消后清理中间状态，不留垃圾

## 三、信任与透明设计

### 3.1 信任建立的三个支柱

| 支柱 | 含义 | 实现手段 |
|---|---|---|
| **透明（Transparency）** | 用户能理解AI为何如此输出 | 引用溯源/思考过程/置信度/错误承认 |
| **控制（Control）** | 用户能干预AI决策 | HITL/可编辑/可撤销/可降级 |
| **一致性（Consistency）** | AI输出稳定可预测 | 温度控制/Prompt固化/记忆管理 |

### 3.2 引用溯源设计（Perplexity范式）

```
[问题] → AI搜索 → 答案 + 编号引用 → 点击编号跳转到原始来源
```

设计要点：
- 关键事实断言必带引用编号
- 引用要可见可点击
- 多源融合时标"综合X个来源"
- 来源要权威（避免单一营销软文）
- 来源要有时效性标注

### 3.3 推理过程展示（推理模型重点）

| 展示策略 | 适用 | 风险 |
|---|---|---|
| **展示完整CoT** | 高信任场景（科研/法律/医疗） | 信息过载/认知负荷 |
| **展示摘要CoT** | 通用场景 | 折中方案，主流选择 |
| **可展开CoT** | 默认隐藏，用户可展开 | 体验最佳但实现复杂 |
| **完全隐藏** | 通用聊天 | 信任感最低 |

### 3.4 置信度标注设计

- 高置信度：直接输出
- 中置信度：输出 + 提示"建议核实"
- 低置信度：拒绝 + "我不确定，建议查X资源"
- 推理模型特别适合：模型内部已知置信度

### 3.5 错误承认设计

AI主动承认"我不知道"是建立信任的关键：
- 边界外的请求明确拒绝（不要硬撑编造）
- "这是我的局限"比"勉强给个答案"更得信任
- 把"我不知道"作为正面信号训练

## 四、多模态输入的容错设计

| 输入类型 | 常见错误 | 容错设计 |
|---|---|---|
| 语音 | 识别错误/口音/噪声 | 实时转写可见/用户可改/打断可重说 |
| 图像 | 误识别/分辨率低 | 多图对比/局部选区/可重传 |
| 手势 | 误判/抖动 | 二次确认/手势库可配置 |
| 情感 | 隐私边界/误判 | 完全可选/不上传敏感数据 |
| 文件 | 格式不支持/超大 | 友好提示/分片上传/格式转换 |

## 六、常见坑汇总

| 坑 | 表现 | 应对 |
|---|---|---|
| 长时无反馈 | AI数十秒无反馈，用户以为卡死 | 阶段化提示+流式+取消 |
| 假装确定 | 高置信度包装低置信度输出 | 明示置信度/错误承认 |
| 仅支持重新生成 | 用户只能反复点"重新生成" | 局部编辑/精准反馈 |
| 无Undo | AI动作不可回退 | 历史快照/草稿-确认/二次确认 |
| 隐藏思考过程 | 推理模型完全不展示思考 | 摘要CoT可展开 |
| 反馈不闭环 | 用户反馈未回流模型优化 | 反馈数据→模型/Prompt迭代 |
| 过度GenUI | 简单文本能解决却生成复杂界面 | 适度原则/性能优先 |
| 服务宕机无降级 | 云端挂了产品直接变砖 | 本地兜底+友好报错+替代建议 |
| 模型敏感性未管 | 换模型后体验漂移 | 上线前回归测试+灰度发布 |
| 无个性化记忆 | 每次都从零开始 | 适度个性化+用户可控记忆 |
| 多模态识别错误不纠错 | 语音/图像识别错只能重传 | 实时可见可改 |
| 越狱致体验崩盘 | 被诱导输出有害内容污染用户体验 | 安全对齐+输入过滤+输出审核 |

## 建表:memory_key_meta(Flyway V43)
**表用途**:记「某用户某 memory_key 是否时序事实」,独立于 user_memories(行级记忆)。仅 merge/resolve 读 + panel 改标写;**不参与日常召回**(否则会把时序判定混进注入)。per-user per-key 一条。

| 字段 | 类型 | 用处 |
|---|---|---|
| id | BIGINT IDENTITY PK | 主键 |
| user_id | BIGINT FK users | 用户隔离 |
| memory_key | VARCHAR(200) | 记忆键(如 home_city / daily_log) |
| is_temporal | BOOLEAN | true=时序(merge 走时间线带日期段),false=非时序(中文逗号 join) |
| source | VARCHAR(20) | LLM_ASK=首次冲突问用户所答 / USER_OVERRIDE=panel 手改(优先) |
| created_at/updated_at | TIMESTAMP TZ | 时间戳 |

**关联**:user_id → users(id)。与 user_memories 无 FK 关联(按 memory_key 字符串逻辑关联)。uk(user_id, memory_key) 保每用户每 key 一标。

**大白话**:像每类记忆贴个「要不要记日期」的小贴纸。住址类贴「要」,合并时就按时间排成时间线;名字类贴「不要」,合并就简单去重。贴纸第一次冲突时问你要,贴过就记住了,你想改随时改。

## 核心逻辑注解
### merge 两分支(MemoryConflictService.mergeValuesInto)
- `temporal = keyMetaService.isTemporal(userId, key) || isDailyLogKey(key)`
- temporal: values=[old..., new] → 末项 new 加 resolve 日期前缀,old 各段(可能已带日期)按日期升序拼 `;`,同 date+content 去重。
- 非 temporal: `joinDistinct(values, "，")` 中文逗号去重(现状不动)。
- **大白话**:同 key 冲突合并时,先看这类记忆贴没贴「要日期」。贴了就把新旧值各带自己日期拼成时间线(住址变迁史);没贴就老办法逗号拼一起(小名、小红、小美)。

### 写侧 gate(MemoryConflictJudge.extract)
- assistantResponse 入 EXTRACT_PROMPT 喂空字符串 → 只抽用户消息。
- **大白话**:AI 的回答不当记忆记。你说的话才记,避免 AI 一句「好的」之类被当事实。

### daily_log 天然时序(isDailyLogKey)
- key 含 daily_log/diary/journal 或 _log 结尾 → 无标也按时间线 merge。
- **大白话**:日记类天然是每天记一条,不用问也知道要按日期排。

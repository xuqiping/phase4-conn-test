# 5.2 Pinterest统一事件框架

## 案例基本信息
- **时间**：2015-2020年
- **主角**：Pinterest数据平台团队
- **背景**：Pinterest百人产品团队各自为政，埋点命名/属性/口径极不统一

## 统一过程

### 核心设计：三层事件框架

```
Layer 1: 通用事件(view/click/submit/scroll/impression)
Layer 2: 业务对象(pin/board/user/search/search_result)
Layer 3: 上下文属性(component/surface/element/container)
```

**组合示例**：
- `view_pin` + `component=recommendation, surface=home_feed`
- `click_pin` + `element=save_button, surface=closeup`

### 实施策略

| 做法 | 效果 |
|---|---|
| 建立事件注册中心 | 新事件必须注册+审核 |
| 强制命名模板 | `通用事件_业务对象` 格式 |
| 上下文属性标准化 | component/surface/element全网统一 |
| 自动化校验 | PR中自动检测埋点变更符合规范 |
| 迁移工具 | 旧事件→新框架的自动映射 |

## 启示
1. **通用+业务双层**：通用事件提供一致性，业务对象提供灵活性
2. **上下文标准化**：同一事件在不同模块出现时靠上下文区分
3. **注册+校验双保险**：事前注册防新增混乱，事中校验防实现偏差

# Application Security Workflow Checklist

在完成 `workflow/application_security_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别应用安全需求场景

- [ ] 已明确场景类型（Web应用防护/API安全/代码安全审计/移动端安全/DevSecOps/供应链安全/AI生成代码安全）
- [ ] 已识别应用类型（Web应用/API服务/移动APP/小程序/桌面应用）
- [ ] 已提取技术栈（开发语言/框架/数据库/前端）
- [ ] 已识别安全成熟度（无安全流程/基础测试/DevSecOps集成/ASPM平台）
- [ ] 已提取关键痛点（漏洞发现滞后/误报率高/修复慢/第三方组件漏洞/AI代码安全问题/移动端逆向风险）
- [ ] 已提取合规要求（等保应用安全/金融APP规范/数据安全法/个人信息保护法）
- [ ] 已对照知识库核心趋势完成初步判断（Web漏洞→SQL注入五层金字塔/API暴露→WAAP/代码管理→SAST+SCA+ASPM/移动端→五层加固/AI代码→完整安全评估）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出应用安全方案

- [ ] 如为Web漏洞防御，SQL注入防御金字塔五层已覆盖（编码规范→框架防御→WAF→数据库防火墙→SIEM运营）
- [ ] 如为Web漏洞防御，XSS防御洋葱模型六层已输出（CSP→WAF→输入校验→存储编码→输出编码→Trusted Types）
- [ ] 如为Web漏洞防御，CSRF防御三层组合已说明（SameSite Cookie/CSRF Token/Origin校验）
- [ ] 如为Web漏洞防御，SSRF防御已覆盖（URL白名单/DNS二次校验/内网IP黑名单/响应长度限制）
- [ ] 如为API安全，认证层已输出（OAuth 2.1强制PKCE/JWT禁用alg=none/mTLS）
- [ ] 如为API安全，鉴权层已覆盖（RBAC/ABAC/ReBAC/BOLA对象级授权OWASP首位）
- [ ] 如为API安全，微服务鉴权已说明（Istio三层安全mTLS+JWT+AuthorizationPolicy）
- [ ] 如为API安全，API威胁防御已输出（速率限制/输入验证/敏感数据/WAAP）
- [ ] 如为API安全，API安全测试已覆盖（自动化扫描/BOLA测试/模糊测试/契约测试）
- [ ] 如为代码审计，安全测试工具链已对比（SAST/DAST/SCA/IAST/选型矩阵）
- [ ] 如为代码审计，DevSecOps流程已说明（IDE→PR→CI→CD→运营五阶段）
- [ ] 如为代码审计，ASPM平台已输出（多源聚合/统一去重/三维优先级/AI辅助修复/互联网公司案例）
- [ ] 如为代码审计，AI生成代码安全已强调（视为第三方代码/完整安全评估）
- [ ] 如为代码审计，供应链安全已覆盖（SLSA L3 Hermetic Build/SBOM CycloneDX/SPDX/秘密扫描四层）
- [ ] 如为移动端，APP安全全生命周期已输出（开发→打包→运行→通信→监控五阶段）
- [ ] 如为移动端，金融APP五层加固已说明（编译期R8/打包期DEX加密/运行期反调试/通信期证书固定/监控期异常上报）
- [ ] 如为移动端，鸿蒙星盾架构已覆盖（管数据非管权限/安全Picker/隐私沙箱/分布式安全）
- [ ] 如为移动端，生物识别与隐私已说明（模板永不离开硬件/FIDO2 WebAuthn/第三方SDK风险）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 漏洞数据（GPT-5 SQL注入/AI代码漏洞率25-30%/OWASP API BOLA首位等）准确
- [ ] 已向用户交付最终答案

## Overall

- [ ] 工作流中的所有步骤已按顺序执行，没有跳过
- [ ] 每一步都已与其检查清单部分进行交叉验证
- [ ] 没有在任何检查清单部分通过前提前进入下一步
- [ ] `task/current_task.md` 已更新完成记录
- [ ] 所有 `[参考: ...]` 标注均指向存在的知识库文件

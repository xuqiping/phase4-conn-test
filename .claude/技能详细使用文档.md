## 🪨 Caveman 系列 - Token节省工具

**来源：** [JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman)  
**目的：** 通过极简化输出来节省 Token 消耗，提高响应速度

### 1. `/caveman` - 极简输出模式

**功能：** 启用极简化的输出模式，减少冗余文字

**使用场景：**
- 需要快速迭代开发
- Token 预算有限
- 只需要核心代码和关键信息

**使用方法：**
```
/caveman
```

**示例：**
```
用户: /caveman 帮我创建一个登录组件
AI: [极简输出，只返回核心代码和必要说明]
```

---

### 2. `/caveman-compress` - 压缩输出

**功能：** 压缩 AI 的输出内容，去除多余的解释

**使用场景：**
- 已经熟悉项目结构
- 不需要详细解释
- 快速获取代码

**使用方法：**
```
/caveman-compress
```

---

### 3. `/compress` - 通用压缩

**功能：** 通用的输出压缩工具

**使用场景：**
- 与 caveman-compress 类似
- 更通用的压缩场景

**使用方法：**
```
/compress
```

---

### 4. `/caveman-commit` - 提交优化

**功能：** 生成简洁的 Git 提交信息

**使用场景：**
- 需要快速提交代码
- 生成符合规范的提交信息

**使用方法：**
```
/caveman-commit
```

**示例输出：**
```
feat: add login component
fix: resolve auth token issue
```

---

### 5. `/caveman-review` - 代码审查

**功能：** 快速进行代码审查，输出简洁的审查意见

**使用场景：**
- 快速代码审查
- 只关注关键问题

**使用方法：**
```
/caveman-review
```

---

### 6. `/caveman-stats` - 统计信息

**功能：** 显示项目统计信息（文件数、代码行数等）

**使用场景：**
- 了解项目规模

**使用方法：**

### 7. `/caveman-help` - 帮助文档

## 🦸 Superpowers 系列 - 五阶段防返工工作流

**来源：** [obra/superpowers](https://github.com/obra/superpowers)  
**目的：** 提供系统化的开发工作流，减少返工，提高代码质量

### 核心理念：五阶段工作流

1. **计划阶段** - 明确需求和设计
2. **实现阶段** - 编写代码
3. **验证阶段** - 测试和审查
4. **完善阶段** - 优化和文档
5. **交付阶段** - 合并和发布

---

### 1. `/brainstorming` - 头脑风暴

**功能：** 帮助你进行需求分析和方案设计

**使用场景：**
- 项目初期，需求不明确
- 需要探索多种技术方案
- 架构设计讨论

**使用方法：**
```
/brainstorming 我需要设计一个文件管理系统
```

**输出内容：**
- 需求分析
- 可选方案
- 技术选型建议
- 潜在风险

---

### 2. `/writing-plans` - 编写计划

**功能：** 创建详细的开发计划

**使用场景：**
- 开始新功能开发前
- 需要分解复杂任务

**输出内容：**

- 开发步骤
- 时间估算
- 依赖关系

---

### 3. `/executing-plans` - 执行计划

**功能：** 按照计划逐步执行开发任务

**使用场景：**
- 已有明确的开发计划
- 需要系统化地实现功能

**使用方法：**
```
/executing-plans
```

**工作流程：**
1. 读取计划文件
2. 逐步实现功能
3. 记录进度
4. 处理异常情况

---

### 4. `/test-driven-development` - 测试驱动开发

**功能：** 采用 TDD 方法进行开发

**使用场景：**
- 需要高质量代码
- 复杂业务逻辑
- 需要回归测试

**使用方法：**
```

```

**工作流程：**
1. 编写测试用例
2. 运行测试（失败）
3. 编写最小实现
4. 运行测试（通过）
5. 重构代码

## 🎨 Anthropic 官方系列 - 前端设计

**来源：** [anthropics/skills](https://github.com/anthropics/skills)  
**目的：** 创建独具一格、生产级别的前端界面，避免通用的 "AI slop" 美学

### 1. `/frontend-design` - 前端设计

**功能：** 生成富有创意、视觉独特、生产可用的前端代码与 UI 设计

**使用场景：**
- 创建网页、落地页、Dashboard 仪表盘
- 编写 React / Vue 组件或 HTML/CSS 布局
- 美化或重新设计现有 UI
- 制作海报、卡片、艺术化前端作品
- 需要避免千篇一律的 AI 生成风格

**使用方法：**
```
/frontend-design 帮我设计一个文件管理应用的主界面
```

**核心设计理念：**

在写代码前先确立明确且大胆的美学方向：
- **目的（Purpose）**：界面解决什么问题？面向谁？
- **基调（Tone）**：极简、繁复、复古未来、有机自然、奢华、玩具感、编辑风、粗野主义、装饰艺术、柔和粉彩、工业风等
- **约束（Constraints）**：框架、性能、可访问性
- **差异化（Differentiation）**：让人过目难忘的那一处亮点是什么

**美学要点：**

| 维度 | 建议做法 |
|------|---------|
| **字体（Typography）** | 避免 Inter / Roboto / Arial 等通用字体，挑选具有特色的标题字体 + 精致正文字体的搭配 |
| **配色（Color & Theme）** | 用 CSS 变量统一管理；主导色 + 鲜明强调色，胜过平庸的均匀调色板 |
| **动效（Motion）** | HTML 优先用纯 CSS；React 推荐 Motion 库；用编排式入场动画营造惊喜 |
| **空间构图（Spatial）** | 不对称、重叠、对角流向、打破栅格、大量留白或可控的高密度 |
| **背景与细节** | 渐变网格、噪点纹理、几何图案、层叠透明、戏剧性投影、自定义光标、颗粒覆盖 |

**应避免的"AI 通病"：**
- ❌ 通用字体堆砌（Inter / Roboto / Arial / 系统字体）
- ❌ 老套配色（白底紫色渐变最为常见）
- ❌ 千篇一律的布局和组件套路
- ❌ 缺乏上下文特色的"模板感"设计

**示例输出：**
- 完整可运行的 HTML/CSS/JS 或 React/Vue 代码
- 经过深度打磨的视觉细节
- 鲜明且贯穿始终的设计观点
- 与上下文匹配的实现复杂度（极简就极简到底，繁复就繁复到位）

> 💡 **提示**：每次生成都应在风格上有所变化（明亮 vs 暗色、字体、整体调性），避免反复收敛到同一种"安全选择"。

## 💡 使用技巧

### 1. 组合使用

你可以组合使用多个技能来优化工作流：

```
# 先进行头脑风暴
/brainstorming 设计用户认证系统

# 然后编写计划
/writing-plans

# 使用 TDD 方式开发
/test-driven-development

# 完成前验证
/verification-before-completion

# 使用极简模式节省 Token
/caveman
```

### 2. 项目阶段建议

**项目初期：**
- `/brainstorming` - 需求分析
- `/writing-plans` - 制定计划
- `/using-superpowers` - 了解工作流

**开发阶段：**
- `/executing-plans` - 执行计划
- `/test-driven-development` - TDD 开发
- `/caveman` - 快速迭代

**测试阶段：**
- `/systematic-debugging` - 调试问题
- `/verification-before-completion` - 完成验证
- `/caveman-review` - 快速审查

**发布阶段：**
- `/requesting-code-review` - 请求审查
- `/finishing-a-development-branch` - 完成分支
- `/caveman-commit` - 生成提交信息

### 3. Token 优化策略

**高 Token 消耗场景：**
- 复杂需求分析
- 详细代码解释
- 多轮对话

**优化方法：**
1. 在需要详细分析时使用完整模式
2. 在实现阶段切换到 `/caveman` 模式
3. 使用 `/compress` 压缩不必要的输出

如果你想创建自己的技能，可以：

2. 在 `~/.claude/skills/` 目录下创建 `.md` 文件
3. 参考现有技能的格式编写
4. 重启 Claude Code 或使用 `/reload` 加载新技能

## ❓ 常见问题

**Q: 如何查看所有已安装的技能？**  
A: 输入 `/help` 或查看 `~/.claude/skills/` 目录

**Q: 技能不生效怎么办？**  
A: 尝试重启 Claude Code 或检查技能文件是否正确安装

**Q: 可以同时使用多个技能吗？**  
A: 可以，但某些技能可能会相互影响（如 caveman 和详细输出模式）

**Q: 如何卸载技能？**  
A: 删除 `~/.claude/skills/` 目录下对应的技能文件

**Q: 技能会影响性能吗？**  
A: 技能本身不会影响性能，但某些技能（如 caveman）会改变输出方式

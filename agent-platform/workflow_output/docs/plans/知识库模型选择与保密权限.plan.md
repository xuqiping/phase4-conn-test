# Implementation Plan for 知识库模型选择与保密权限

> Phase 2 产出。Phase 3 逐步勾选执行。只含伪代码，不含真代码。
> 来源规格：[../specs/知识库模型选择与保密权限设计.md](../specs/知识库模型选择与保密权限设计.md)

## 背景与目标

- 14x#2：修复只读成员可编辑的越权（谓词 `canRead ‖ (requireWrite && canWrite)` 布尔逻辑错误）+ 前端按 per-KB 权限显隐。
- 14x#1：embedding 模型改下拉；新增每库「问答 LLM」模型（answer_model）。
- 14x#3：库级保密开关——成员仅 RAG 问答出口，切片/下载/调试旁路全 403。

## 技术实现坑点预判与规避措施

| 技术点/功能块 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| **谓词修复的隐性破坏** | 现状可能存在「只授了 canRead 但实际在用写功能」的用户，修复后瞬间 403 被投诉 | 修复前 SQL 盘点：`knowledge_permissions` 中 canRead=true 且 canWrite=false 的授权行数及涉及 KB，输出清单给用户确认（需人工介入项） | 盘点 SQL 结果落档 |
| 读路径误伤 | `KnowledgeDocumentService` 个别读路径误用 canWrite（`:104` 预览），谓词修好后只读用户突然连读都被拒 | Step 1 逐接口归位清单（读=canRead/写=canWrite/治理=canManage），先写清单再改码，PR 逐行对照 | 单测 9 格矩阵逐格断言 |
| **换 embedding 模型后存量向量失配** | 老文档向量是旧模型算的，新模型 query 向量在旧向量空间检索 → 召回全错且**不报错**（最阴的坑） | 表单保存时检测「已有文档且 embeddingModel 变更」→ 强提示需重建索引（复用既有索引运维重建入口），未重建前检索调试 Tab 顶部横幅警告 | 手测：改模型→横幅出现→重建后消失→检索恢复正常 |
| answer_model 作用面遗漏 | 三处 LlmRequest（生成/提炼/合成）漏改一处 → 同一回答混两个模型 | 三处统一走 `resolveAnswerModel(kb)` 小函数，单测三处均透传 | 单测 + 请求快照断言 model 字段 |
| 保密判定散落 | 4 个接口各自写 if(confidential) 漏一处=泄露 | 收敛 `KnowledgeConfidentialGuard.assertCanViewContent(kb, user)` 单一咽喉，4 接口只调它 | 单测矩阵 + 安全用例：成员逐接口 403 |
| 检索调试整口 403 误伤 owner 调试 | owner 也被挡 | 咽喉内判 admin/owner 直通（规格 §5.2） | 单测 owner 全通行 |
| PUBLIC 库开保密 | 公开库保密语义矛盾（公开又保密） | 表单互斥校验：isPublic=true 时保密开关禁用 | 单测互斥拒绝 |
| chat 引用下载入口 | CITATION 帧前端隐藏按钮，但成员仍可拼 URL 下载 | 后端 `/asset` 咽喉 403 兜底（前后端双层） | 直调 URL 403 用例 |
| 权限变更无审计 | 授权表硬删无痕迹，出纠纷无法追溯 | grant/revoke 补 @AuditLog（Step 1 顺带） | 审计日志断言 |

## 安全检查清单

- [ ] **鉴权/授权**：9 格权限矩阵单测（canRead/canWrite/canManage × 读/写/治理）；保密 4 接口咽喉统一
- [ ] **输入校验**：answer_model 长度≤128 且必须存在于 active 模型列表（服务端校验，防手输任意串）；confidential 布尔
- [ ] **审计**：grant/revoke/canManage 授予位变更/保密开关切换补 @AuditLog
- [ ] **错误处理**：保密拒绝统一 `KNOWLEDGE_CONFIDENTIAL_DENIED`，文案不泄漏库内文档数量/标题
- [ ] **越权回归**：canManage 授予位生效后，被授予者不能删库/改名（仅授权与治理）
- [x] **加密/CORS/依赖**：无新增面

## 性能考虑与验证计划

- [ ] 保密判定在 KB 已加载对象上内存判断（不新增查询；4 接口本就先载 KB）
- [ ] answer_model 解析为 VO 内联字段，无额外查询
- [ ] Phase 4：只读成员问答链路 P95 与修复前持平（权限判定非热点路径）

## 实现步骤

- [x] **Step 1：后端——谓词修复与权限归位**（完成 2026-08-18，commit 16d4ae5d）
  - **目标**：canWrite 判定正确；读写治理各归其位；canManage 授予位生效
  - **动作**：①`hasGrant`：requireWrite=true 时改匹配 `canWrite‖canManage`；②输出逐接口归位清单（Controller+Service 每个 endpoint → canRead/canWrite/canManage），误用 canWrite 的读路径改 canRead；③`canManage()` 加 `‖ hasGrant(canManage=true)`（KB 改名/删除仍限 owner/admin）；④grant/revoke 补 @AuditLog；⑤KB VO 补 `canWrite`
  - **文件**：`KnowledgeBaseService.java`、`KnowledgeDocumentService.java`、`KnowledgePermissionService.java`、`KnowledgePermissionController.java`、`KnowledgeBaseController.java`（VO）、Test ×2
  - **依赖**：无；**需人工介入**：修复前跑只读授权影响面 SQL 给用户确认
  - **验证**：单测 9 格矩阵 + canManage 授予位生效/不可删库 + 审计落库

- [x] **Step 2：前端——per-KB 按钮显隐**（commit 390b78af）
  - **目标**：编辑/删除/上传/治理按钮按 per-KB 权限显隐
  - **动作**：①KB 行「编辑/删除」→ `r.canManage && isOwnerOrAdmin`（后端 VO 已有 canManage；owner 判定复用现有字段）；②文档抽屉上传区/直传/新版本 → per-KB `canWrite`；③治理/解除隔离/删除 → canManage；④全局 knowledge:write 仅作菜单兜底
  - **文件**：`KnowledgeView.vue`、`DocumentManager.vue`
  - **依赖**：Step 1（VO canWrite）
  - **验证**：playwright：只读成员全入口不可见+直调 403；授写成员可见上传不可见治理

- [x] **Step 3：模型可选（embedding 下拉 + answer_model）**（后端 43777f20 / 前端 0d099746）
  - **目标**：embedding 下拉替换文本框；每库问答 LLM 三处生效

  - **文件**：迁移 `V129__*.sql`、`KnowledgeBase.java`、`KnowledgeBaseService.java`（校验）、`KbFormModal.vue`、`RagRetrievalService.java`、Test ×2
  - **依赖**：无（与 Step1/2 并行）
  - **验证**：单测：模型校验拒绝任意串/三处透传/换 embedding 触发 warning；playwright：下拉建库→索引→问答；换模型→横幅→重建→恢复

- [ ] **Step 4：后端——保密开关与内容咽喉**

## 功能联动点清单（含反向/边界）

| # | 触发动作 | 联动对象 | 预期变化 | 必测边界 |
|---|---|---|---|---|
| L1 | 授予 canRead | 对方编辑能力 | 越权修复后立即被拒写 | 原来能传的现在 403（回归重点）；前端按钮同步消失（刷新后） |
| L2 | 授予 canManage 位 | 对方可管理授权/治理 | canManage() 生效 | 被授予者不能删库改名；撤销后立即失效；授权链不能自授（防提权：授予者不可授 manage 给他人？规格未禁——**保留可授**但审计） |
| L3 | 切保密开关 ON | 成员侧四个旁路 | 立即 403/隐藏 | 正在浏览切片的成员下一步操作被拒；OFF 后全部恢复（可逆）；owner 全程无感 |
| L4 | 换 embedding 模型（已有文档） | 检索质量/横幅 | 强提示重建索引 | 拒绝重建→横幅持续；重建中→状态可见；空库换模型→无横幅 |
| L5 | 换问答模型 | /ask 与 chat RAG 生成 | 新模型生效 | 旧任务历史回答不变；模型下线后→回退全局默认（active 列表过滤） |
| L6 | 保密库出现在 chat kbIds 多选 | 引用帧 | 引用正常、下载钮隐藏 | 多库混选（1 保密+1普通）：普通库下载钮在、保密库无；全保密→无任何下载钮 |

## 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| 谓词 | 判定函数里的真假条件式 | `canRead‖(needWrite&&canWrite)` |
| 咽喉 | 所有权限判断收敛过的一个函数 | assertCanViewContent 一处改全局生效 |
| 旁路 | 绕过主路径拿内容的出口 | 问答只给相关段，但下载能拿全文 |
| 向量失配 | 查询和库存向量用了不同模型算，检索全错 | 换模型不重建索引→召回乱 |
| PUBLIC 库 | 所有人可读的公开库 | 与保密互斥 |

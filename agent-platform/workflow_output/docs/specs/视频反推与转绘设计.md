# 规格 · 视频反推与本土化转绘（反推分镜 / 关键帧 / 剧本 / 转绘）

> Phase 1 功能规格。实现必须与本文一致；来源为 2026-08-17 人工测试问题 2x 未解决项「视频反推」（无限画布与视频生成模块两处入口）。
> 关联：[无限画布四轮增强规格](无限画布四轮增强设计.md)｜[SeedDance视频生成 Feature Map](../feature-map/SeedDance视频生成.feature-map.md)。

## 1. 目标

给一段已有视频，产出四类结果并在两个入口可用：

1. **反推分镜**：镜头清单（镜头号/起止时间/景别/运镜/画面描述/台词）。
2. **反推关键帧**：镜头切换单元的代表帧（含时间戳），可看、可入画布、可作生成参考。
3. **反推剧本**：结构化剧本（场景/角色/动作/对白）。
4. **本土化转绘**：剧本剧情不变，把源文化元素（如中国的筷子）改写为指定国家本土元素（如西方国家→刀叉），并衔接既有生成链路出新视频。

## 3. 技术路线（关键决策）

**路线：关键帧采样 + 多模态 LLM 理解**，不引入视频原生理解模型：

- 视频理解不新增 Provider/协议——用 FFmpeg 场景检测切镜头取代表帧，把帧序列（按时间序、带时间戳）作为 image parts 喂给现有对话模型（glm/qwen 多模态），由 LLM 产出分镜表与剧本。
- 理由：零新供应商集成；帧提取与多模态对话均为既有能力；可控成本（帧数=token 预算）。
- 视频原生理解（video part 直入模型）列为后续升级项，接口形状不变（见 §8）。

## 4. 后端契约

### 4.1 分析接口

`POST /api/media/reverse/analyze`（`media:gen`；支持「参与项目」参数，见[项目组规格](项目组与积分划拨设计.md)）

请求：

```
{ source: { taskId? , fileId? }      // 二选一：历史任务 or 已上传/画布文件
, modes: ["KEYFRAMES","STORYBOARD","SCRIPT"]   // 至少一项
, sceneThreshold?: number            // 场景检测阈值，默认 0.3
, maxFrames?: int }                  // 默认 12，上限 24（token 预算保护）
```

处理步骤：

1. **归属校验**：taskId → loadForDownload 咽喉；fileId → 文件访问授权（与画布帧提取同口径）。
2. **关键帧提取**（KEYFRAMES 及另两模式的前置）：
   - FFmpeg 场景检测（`select=gt(scene,阈值)`）取切镜帧；命中 0 或 <4 时回退均匀采样补足；
   - 每帧落新文件（fileId，含时间戳元数据），按时间序编号。
3. **LLM 分析**（STORYBOARD/SCRIPT 时）：帧序列按时间序作为 image parts + 帧时间戳文本，单次调用产出结构化 JSON：
   - 分镜：`[{shotNo, startSec, endSec, shotSize(景别), cameraMove(运镜), description, dialogue}]`
   - 剧本：`{scenes:[{sceneHeading, action, dialogue:[{role,line}]}], synopsis}`
   - JSON 解析失败重试 1 次，仍失败返回明确错误（沿用 RAG 侧「未返回合法 JSON」经验：提示词强制只输出 JSON、限字段长度）。
4. **计费**：LLM 调用走现有 chat 计费链路（多模态 token），usage_log 带 project_group_id（若选组）；帧提取不另计费。

响应：`{ keyframes:[{fileId, timestampSec, shotNo}], storyboard?, script? }`

超时与韧性：同步接口，前端该请求 timeout 放大至 120s 且带 `background` 标记（见[画布规格](无限画布四轮增强设计.md) §3.2，防误触发断路）。

### 4.2 转绘（本土化改写）接口

`POST /api/media/reverse/localize`

```
{ script: string            // 反推所得剧本（或用户改后剧本）
, targetLocale: string      // 目标国家/地区，如「美国/西方」
, notes?: string }          // 额外保留要求
→ { localizedScript, changeLog:[{from:"筷子", to:"刀叉", scene}] }
```

- 纯 LLM 文本改写：剧情/分镜结构不变；文化元素映射（餐具/服饰/建筑/招牌文字/节庆/礼仪等）；changeLog 供用户核对（转绘透明度）。

## 5. 前端契约

### 5.1 无限画布入口

- 视频节点属性面板新增「反推」区（需节点有 taskId 或已物化 fileId）：
  - 勾选产物（关键帧/分镜/剧本）→ 分析 → **按产物建节点并自动连边**：
    - 关键帧 → 每镜头一个图片节点（帧文件预览），全部连自视频节点；
    - 分镜 → storyboard 节点（现有类型，表格化文本）；
    - 剧本 → script 节点。
  - 剧本/分镜节点属性面板加「本土化转绘」按钮 → 弹窗（目标地区+保留要求）→ 产出**新 script 节点**（连自原剧本节点），changeLog 在节点详情可查。
  - 后续生成：用户用既有节点链路衔接（分镜→逐镜头生图→图生视频→concat 已有能力）；「一键生成全链」自动化列入后续（见 §8）。

### 5.2 视频生成模块入口

- `VideoGenView` 新增「视频反推」Tab：
  - 来源：上传本地视频 or 从历史任务选；
  - 结果区：关键帧时间轴条（缩略，悬浮放大/点击灯箱，复用共享预览组件）、分镜表、剧本文本，均可复制；
  - 「本土化转绘」表单 → 改写剧本展示 + changeLog；
  - 「用剧本生成」入口：把剧本（原/本土化）一键**带到生成表单**作为提示词预填，参考视频槽自动填源视频（走既有参考视频生视频链路）。

## 6. 数据模型

无新表。关键帧为普通文件（stored_files）；分镜/剧本在画布=节点（快照内），在视频模块=即时结果不落库（刷新即失，可复制/带走）。

## 7. 测试策略

| 层 | 用例 |
|---|---|
| 后端单测 | 场景检测阈值/兜底均匀采样（mock FFmpeg 输出）；maxFrames 上限；JSON 解析失败重试与错误文案；localize 保持分镜结构断言（镜头数不变）+ changeLog 生成；归属校验（他人任务 403）；计费落 usage_log |
| 前端单测 | 反推弹窗勾选与建节点连边（视频→帧×N→分镜→剧本）；本土化弹窗；Tab 结果区渲染与复制；「用剧本生成」预填（提示词+参考视频槽） |
| 人工/playwright | 历史视频→反推三产物出节点；帧悬浮/点击放大；转绘筷子→刀叉 changeLog 可见；带改写剧本预填生成表单并成功提交；选组状态下反推计费入组 |

## 8. 边界与不做（后续档）

- 不做分析结果服务端持久化/反推历史（首版即用即走；需求主链在画布节点持久化）。
- 不做音频转写（剧本台词来自画面理解，无 ASR）；不做逐镜头自动批量生成全链「一键成片」；不做视频原生理解模型接入（ContentPart 不加 video type）。
- 模型选择：反推用管理员默认多模态对话模型，不做 per-入口模型下拉（待知识库规格 §4 的模型可选能力普化后再议）。

## 9. 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| 场景检测 | FFmpeg 自动找画面突变点，即镜头切换处 | 转场那一帧被认成新镜头 |
| 景别 | 镜头拍多大范围：远/全/中/近/特写 | 「特写：手中的筷子」 |
| 运镜 | 镜头怎么动：推拉摇移跟 | 「镜头右摇跟随人物走动」 |
| 关键帧 | 每个镜头最能代表它的那一帧画面 | 切镜瞬间的截图 |
| 转绘 | 按新剧本重新画/生成一遍 | 筷子吃饭场景→刀叉吃饭场景 |
| changeLog | 改了什么的清单，供人工核对 | 筷子→刀叉（第2场） |

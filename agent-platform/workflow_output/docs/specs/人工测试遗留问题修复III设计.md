# 人工测试遗留问题修复III设计（组内成员欠款与个人划拨）

> 2026-08-26。起因：修复II Plan-A（组池补差兜底）人工复验发现两缺陷 + 用户追加新功能（成员个人积分划拨至组内自己名下）。所有口径经用户 8 项决策确认。

## 1. 背景与缺陷根因

**缺陷1（组池未消耗）**：媒体结算差额 489.95 走 `chargeGroup(diff)`——组池扣款成功后，成员 `addUsed` 撞限额守卫（项目内剩 250 < 489.95）抛异常，**整事务回滚（组池扣款一并回滚）**，上层 catch 全额转组长兜底 → 组池分文未动、组长白付。聊天结算同款模式。兜底真实触发条件=「成员限额不足」而非「组池不足」。

**缺陷2（成员剩 250）**：250=限额−已用。用户口径：超限额消耗应把成员可用扣到 0，溢出转成员欠款。

## 2. 已确认口径（用户 8 项决策）

1. 组池富余时差额由组池正常扣（组长不兜底）。
2. 组池不足时：**组池先扣到 0，组长只兜真缺口**。
3. 成员超限额：used 扣到=限额（可用 0），溢出转欠款；**欠款按垫付来源拆分**（组池垫 `debt_pool`/组长垫 `debt_leader`）。
4. 成员欠款期间**暂停组内提交**（聊天/图片/视频），划拨抵清后恢复。
5. **新功能**：成员可把个人钱包积分划拨至组内自己名下（真名下余额 `self_points`，非注资组池）。
6. 划拨还款：**先冲组长垫（退组长个人钱包），再冲组池垫（回组池），剩余进名下余额**。
7. 组长调高限额 +X：先抵欠款（豁免，无资金流动），余下才涨可用；组长重置已用：**欠款一并清零**。
8. 消耗顺序：**先组池 → 后自己名下 → 组长兜底**；退组：名下余额先缴清欠款（先组长垫后组池垫），缴清后剩余全额退回个人钱包，缴不清的部分欠款核销留痕。

## 3. 账务模型

### 3.1 字段（Flyway V161，`project_group_members` 加 3 列）

| 字段 | 含义 | 约束 |
|---|---|---|
| `self_points` | 组内个人余额（成员自己的钱，组长回收/调限额碰不到） | ≥0，默认 0 |
| `debt_pool_points` | 欠款·组池垫付部分 | ≥0，默认 0 |
| `debt_leader_points` | 欠款·组长垫付部分 | ≥0，默认 0 |

存量回填：现网 `used_points > quota_limit_points` 的行（兜底时代产物）拆分——溢出部分按该组流水 BACKSTOP 占比归 debt_leader、其余归 debt_pool，used 落到 quota。

### 3.2 扣款瀑布（HOLD 预扣 / 结算补差 / 直扣统一）

```
cost C：
① 组池扣 min(组池余额, C)          —— CONSUME 腿
② 名下扣 min(self_points, C−①)     —— SELF_CONSUME 腿（不动组池）
③ 缺口 = C−①−② > 0 → 组长兜底      —— BACKSTOP 腿（个人钱包扣/挂账，同现行）
成员记账：used += C（无条件，真实消耗）
欠款归因：溢出 O = max(0, used后 − quota)（quota 空则恒 0），
         O 按瀑布尾部资金来源拆：组池垫的记 debt_pool、组长垫的记 debt_leader、
         名下垫的（自己的钱）不记欠款
```

要点：
- **限额守卫不再回滚组池扣款**（缺陷1根因消除）——组池/名下/组长三腿各自尽力扣，成员记账无条件。
- 提交侧（HOLD）：预检仍拦——`可用 = quota==null ? ∞ : max(0, quota−used−debt总)` 且 `debt总>0 时可用恒 0`（暂停消费）；估算 > 可用直接拒绝（预扣不进欠款，与个人钱包 HOLD 同口径的保守面）。
- 结算补差：超出可用的溢出按瀑布归因进欠款（欠款只从结算产生，可预期）。

### 3.3 不变量（对账下钻模板同步扩展）

- `Σ(CONSUME + SELF_CONSUME + BACKSTOP − REFUND各腿) == used_points + debt_pool + debt_leader −（调限额豁免/重置/核销的调整腿）`
- 简式（无调整时）：`Σ腿 == used + debt总`；划拨还款/调限额抵扣不改变该恒等（还款=钱动债清、豁免=债清 used 减）。
- `self_points` 只与个人钱包进出对平：`Σ(SELF_ALLOCATE − SELF_CONSUME − SELF_REFUND − 退组退回) == self_points`。

### 3.4 退款（任务失败/落库失败撤销/实耗低于预扣）

按任务原始腿反冲（组账本按 ref=taskId 查各腿）：组池腿退组池、名下腿退名下、BACKSTOP 腿退组长个人钱包；成员 used 回减前**先还欠款**（debt 先减，余额再减 used，各落 0 下限）——保持 §3.3 恒等。

## 4. 流程时序

### 4.1 个人划拨（新功能，成员自助）
入口：项目组页成员视角「我的组内账户」卡（名下余额/欠款/划拨按钮）+ 提交面板欠款红字里的快捷入口。
```
POST /api/project-groups/{gid}/members/self-transfer  body:{points}
① 个人钱包扣 X（CONSUME ref=SELF_TRANSFER，幂等键，审计 @AuditLog）
② 还款：min(X, debt_leader) → 组长个人钱包 credit；再 min(余, debt_pool) → 组池 credit
③ 剩余 → self_points += 余
```
个人钱包余额不足自然拦截（无个人欠款参与）；上限=个人可用余额。

### 4.2 组长调高限额（MEMBER_ALLOCATE）
`+X：先抵 debt_leader→debt_pool（豁免，used 同额回减保持可用口径），余下 quota += 余`；流水备注「含抵扣欠款 X」。调低不追溯、不碰欠款（现行不变）。

### 4.3 组长重置已用
`used=0、debt_pool=0、debt_leader=0`（欠款一并清零，豁免留痕流水）；self_points 不动（是钱不是额度）。

### 4.4 退组/移除结算
```
① 名下余额先还款：先 debt_leader（credit 组长个人）、再 debt_pool（credit 组池）
② 缴清后剩余 self_points 全额退回个人钱包（SELF_REFUND 腿）
③ 仍缴不清的欠款 → 核销（DEBT_WRITEOFF 腿留痕，组长垫付部分自认损）
④ 成员行软删（现行）；复活重置含 self_points=0（钱已走，不留悬空）
```
锁序遵守既有：个人→组池→成员行。

### 4.5 事件推送（E1 通道复用）
member 事件 payload 增 selfPoints/debtPoolPoints/debtLeaderPoints；个人腿走 PERSONAL 事件（已有）。前端徽标/组页秒更。

## 6. 安全与审计

- 端点 `@RequirePermission`：self-transfer 仅本人（组内成员身份校验）；组长侧调限额/重置沿用现权限。
- 全部资金动作 `@AuditLog`（划拨/退组结算/核销/豁免），模块码入字典（18 模块表新增动作码四改同步）。
- 幂等：划拨/退组结算/还款腿各自幂等键；金额>0 校验、BigDecimal 精度同现网。

## 7. 测试策略

- 自动化（IT，真 PG）：瀑布三腿拆分（池足/池半/池0+名下垫/全垫组长）、欠款归因拆分、划拨还款顺序、调限额豁免、重置清零、退组结算四分支、退款反冲按腿、欠款冻结提交、并发（边花边划拨）。
- 人工复验（对齐缺陷场景）：缺陷1 复演（池富余+限额不足 → 组池扣、组长不扣、欠款=组池垫部分）；缺陷2 复演（可用扣到 0、欠款 239.95、划拨后恢复）。
- 对账下钻模板新不变量回归。

## 8. 边界与不做

- quota 为空（不限额）成员：永不产生欠款（无帽子），瀑布照常。
- HOLD 预扣不做「预扣进欠款」（提交侧拦，见 §3.2）；个人钱包欠款与组内欠款互不相通（各自独立）。
- 不做成员间互转、不做名下余额直接提现（仅退组退回）。

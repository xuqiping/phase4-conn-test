# 规格 · 无限画布四轮增强：超时韧性、节点宽高、依赖调度、图片编辑、参考预览、连线高亮、横向连线、节点组

> Phase 1 修复规格。实现必须与本文一致；来源为 2026-08-17 人工测试问题 2x 未解决项（超时/宽高/批量依赖/图片编辑/@预览/连线高亮/左右连线/组）。
> 交叉项归其他规格：公共池选择、成员搜索、评分等级 → [资产库规格](资产库公共选择与评分等级设计.md)；视频反推 → [视频反推与转绘规格](视频反推与转绘设计.md)。
> 关联：[项目资产库 Feature Map](../feature-map/项目资产库.feature-map.md)。

## 1. 目标

1. 长时间生成不再误报「服务不可达」、不再因轮询网络波动踢出登录。
2. 节点宽高可拖拽调整并持久化。
3. 批量生成按依赖调度：上游任务**成功**后下游才开始。
4. 图片节点可翻转、可框选彩色标注并驱动 AI 修改（类 PS 局部标注）。
5. 被 @ 的图片/视频节点在属性面板「参考」区展示，悬浮放大、点击全屏。
6. 选中节点时上下游连线高亮、无关元素淡化，可一键只看关联。
7. 连线走向由上下改为左右。
8. 节点组：框选成组（UI 区分），组下游可 @ 组内任意节点。

## 3. 超时与「服务不可达」韧性（2x#24）

### 3.1 结论与根因

- **后端已无生成时间上限**：600s 业务超时已删（`MediaGenProperties.java:13` 注释明确），Worker 退避轮询直到 Provider 终态；Provider 30s/180s 是单次 HTTP 连接超时（自动重试由 Worker 退避承担），不是任务寿命。
- 用户看到的「生成久了→服务不可达→失败」是**前端网络层放大**：轮询请求偶发超时/断网 → 弹「网络异常：服务暂不可达」；连续 5 次无响应（`NET_ERROR_CIRCUIT_THRESHOLD=5`）→ **清会话踢登录**，任务链路中断即「失败」体感。长任务窗口越长，撞上 5 次抖动的概率越大。

### 3.2 修复契约

1. 请求分类：axios 请求增加 `background: true` 标记（应用于：任务轮询 getTask、媒体 blob 拉取、画布续轮询）：
   - 不计入连续错误断路计数（断路只统计用户主动请求：提交/保存/CRUD）；
   - 永不触发清会话；
   - toast 维持 5s 节流但降级文案「后台任务网络波动，恢复后自动重试」（不打断创作）。
2. 轮询请求单独 timeout 30s（>5s 间隔，防自挤）。
3. `mediaTaskPolling` 失败退避：连续失败 5s→10s→30s 封顶，成功即归 5s（防弱网锤接口）。
4. 标签页切回：visibilitychange visible → 立即补一次轮询（后台节流导致的空窗一次追平；Worker 在服务端独立推进，终态不依赖前端在场，`resumePendingTasks` 已兜底）。
5. 提交类请求维持现状（15s 合理；提交是快操作）。

### 3.3 验收

- 拔网线 30s 再恢复：进行中任务继续轮询至终态，不弹踢会话、不弹误导性「服务不可达」。
- 用户主动操作连续失败仍走原断路（会话安全语义不降级）。

## 4. 节点宽高拖拽（2x#25）

- 引入官方 resize 方案：`@vue-flow/node-resizer`（计划阶段若版本不兼容则自绘右下角手柄，行为契约不变）。
- 契约：节点**选中时**显示手柄；minWidth 160 / minHeight 64；默认宽维持 200（老节点零迁移）；拖拽实时预览，松手后 `node.data.width/height` 落快照（data 开放字段，持久化链路现状已通）。
- 6 类节点适配：图片缩略 `width:100%` 自适应；文本节点高度可拉大（内容区滚动）；属性徽标/状态条随宽度换行。
- 与第 7 节横向连线配合：横向布局下加宽节点是主诉求。
- 边界：不做等比锁定、不做每类型独立默认尺寸记忆。

## 5. 批量生成依赖调度（2x#26）

### 5.1 语义变更

- 现状：拓扑序**提交顺序**+滑窗 2，下游提交即返回（不等上游）。
- 目标：**下游节点的提交被上游节点 SUCCEEDED 释放**——调度器维护就绪集（选集内全部上游已达终态 SUCCEEDED 的节点），滑窗仍 2 并发（互不依赖的分支保持并行，并发闸 429/退避逻辑复用）。

### 5.2 契约

- 新函数 `runDependencyScheduled(selection, submitter, opts)`（batchRunner.ts），替换 onBatchRun 现有滑窗调用：
  - 就绪判定：节点在**选集内**的上游全部 SUCCEEDED；上游不在选集（含资格预检剔除的节点）→ 视为「上游未执行」，该下游标记跳过并提示「上游未执行/失败，已跳过」（不静默丢）。
  - 上游 FAILED → 其下游全部标灰跳过（节点标 `skipped-upstream-failed`），其余分支继续。
  - text 节点同步执行成功后即释放下游；video/image 节点以轮询到终态为释放点。
  - 进度浮条沿用（增加「等待上游」状态位）；taskId 即时持久化、刷新恢复语义不变。
- 「重跑全链」串行语义不变（本就等终态）。
- 单测：链 A→B→C 顺序与并发窗口、分支并行、上游失败跳过、上游缺选跳过、环守卫（已有 cycle 检测复用）。

## 6. 图片节点编辑：翻转 + 彩色框选标注（2x#29）

### 6.1 翻转/旋转（确定性）

- 后端新增 `POST /api/canvas/transform-image {fileId, op}`，op ∈ `FLIP_H | FLIP_V | ROTATE_90 | ROTATE_180 | ROTATE_270`；实现与 `/crop-image` 同服务（ImageIO/FFmpeg 均可），产出**新 fileId**（文件不可变语义不破）。
- 前端：图片节点属性面板操作区加 水平翻转/垂直翻转/旋转 90° 按钮 → 调用后建**衍生图节点**并自动连边（复用 crop 确认链路 `CanvasView.vue:623-663` 模式）。

### 6.2 彩色框选标注（AI 局部修改）

- 新组件 `AnnotateOverlay`（FocusEditOverlay 同模式的沉浸弹层）：
  - 在图片上拖画矩形框，8 色板（红/橙/黄/绿/青/蓝/紫/品红；填充 30% 半透明+同色边框），每框附一句中文指令；
  - 框可删、可改色改指令；预览区实时合成显示。
- 两个确认出口：
  1. **生成标注图**（无 AI）：原图+色块+序号指令文字合成新图 → 新图节点（走 6.1 同款服务端合成接口扩展 `op=ANNOTATE`，payload 携带归一化矩形/颜色/文字；或前端 canvas 合成后走既有 upload，计划期定，行为一致即可）。
  2. **AI 修改**：提交图片生成任务——参考图 = `[原图, 标注图]`，prompt = 逐框指令清单（「①红色区域：这里增加一个杯子；②绿色区域：这里的植物重新生成优化…」），走画布图片节点既有 capability 参数区与提交链路，产出下游新图节点。
- 边界（明确告知用户）：当前图片 Provider 无蒙版（mask）API，本方案是「标注图+指令」经多模态参考图通道实现的**准局部重绘**；真蒙版 inpaint 待供应商支持后升级，出口已预留（标注数据结构即 mask 载体）。

## 7. @参考图/参考视频展示与放大（2x#31）

- 属性面板（视频/图片节点）新增「参考」区，解析顺序与提交序号化一致：
  - 首帧/尾帧节点 → 帧角色徽标（首帧/尾帧）；
  - prompt 内 `@{{node:id}}` → 图N/视频N 徽标。
- 展示：图片节点 → fileId 缩略（复用 useLazyFilePreview）；视频节点 → taskId 抽首帧作 poster（复用既有视频帧接口）+ 播放角标。
- 交互：悬浮 → 放大浮层；点击 → 灯箱全屏（图片）/播放弹窗（视频，blob 播放）。
- 组件复用共享件 `MediaLightbox` / `HoverPreviewImage`（定义见[图片视频模块规格](图片视频模块历史分页与预览缓存设计.md)第 4 节，两规格共同依赖，计划阶段排期为公共前置任务）。
- @chip 点击跳转节点行为保留。

## 8. 关联连线高亮 + 只看关联（2x#37）

- 选中单个节点 → 全图 BFS 祖先+后代 → 命中路径上的边加 class `--related`（accent 色、strokeWidth 2.5），其余边/节点透明度降至 0.25；
- 工具条开关「只看关联」：非关联节点 `visibility:hidden`（布局不动、不删数据，开关可逆）；
- 清除选中即恢复；机制复用既有 selectedEdgeId→class 注入模式（扩展为集合注入，仍不入快照）。
- 边界：不做按跳数衰减着色、不做多选高亮（多选时按选集整体求关联，规则同单选）。

## 9. 连线左右（2x#38）

- `CanvasNodeBase` 句柄改：target=`Position.Left`、source=`Position.Right`；贝塞尔路径自动横向。
- 存量画布零迁移（节点自由布局，无自动排版依赖）；DeletableEdge 中点×、选中高亮、@连线语义全部不变。
- 框选/组包围盒等按 bounds 计算，与方向无关。

## 10. 节点组（2x#39）

### 10.1 数据与建组

- 快照顶层增 `groups: [{id, name, color, nodeIds[]}]`（老快照缺省=空数组）；`node.data.groupId` 反向引用。
- 框选 ≥2 节点 → 批量工具条「设为组」→ 输入组名（色板自动轮选）；支持解组/改名；节点仅属一个组（入新组自动移出旧组）。

### 10.2 UI 区分

- 组包围盒（成员 bounds 并集+padding）虚线彩框+左上角组名标签，渲染在节点层之下随画布变换；
- 成员节点带组色描边；
- 组不是容器：拖动单个成员不整组移动（整组移动=框选后拖，现状能力）；包围盒随成员移动实时重算。

### 10.3 @ 组内内容

- @候选规则扩展：候选 = 祖先节点 ∪（祖先命中组 G 任一成员 → G 全员入候选）——即「组的下游节点可 @ 组内任何内容」，未连通组仍不可见（防越权引用）；
- 候选列表按组分组显示（组名小节标题）；@ 解析、断链检测、运行插值零改动（仍按单节点 id 生效）。

### 10.4 边界

- 组不参与运行拓扑（连线才是依赖）；一键关联/批量生成按选集处理组员（不特殊感知组）。

## 12. 边界与不做

- 不做画布自动布局/对齐吸附；不做真蒙版 inpaint（Provider 无 API，见 6.2）。
- 不做多级嵌套组、组模板（LibTV 打组模板已列 plan R2-R5 建议档，不在本期）。
- 高亮不做路径动画；组不做权限语义（画布本就单人编辑）。
- 超时项不改 Provider/Worker 侧（已无业务超时，仅前端网络层修复）。

## 13. 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| 断路器（circuit） | 连续失败到阈值就熔断的保护机制，这里是踢出登录防会话失效循环 | 连续 5 次网络无响应→清会话 |
| 滑动窗口 | 同时最多跑 N 个，完成一个补进一个 | 2 个任务在途，A 完成 C 立即上场 |
| 拓扑序 | 按依赖关系排的执行顺序，被依赖的在前 | 先 A 后 B（B 依赖 A） |
| BFS 祖先/后代 | 沿连线向上/向下能到的所有节点 | A→B→C 中 A 的后代是 B、C |
| inpaint | 按蒙版只重画图中指定区域的真局部重绘 | 涂掉路人只补背景 |
| poster（首帧封面） | 视频的封面图，取第一帧 | 视频瓦片显示首帧截图 |
| EXIF 方向 | 照片拍摄时记录的旋转信息，处理不当会横竖颠倒 | 手机竖拍照片在服务端翻转时要带上 |

# Security Operations & Incident Response Workflow

## Purpose

基于安全运维与应急响应知识体系，为用户提供安全日志分析（SIEM六层漏斗）、入侵检测（IDS/IPS分层部署+AI级联架构）、网络安全应急处置（NIST六阶段/黄金30分钟/不可变备份）及SOC运营（四层金字塔/MTTD/MTTR/SOAR自动遏制90秒）的技术方案支持。覆盖SIEM三阶段成熟度、UEBA五维行为基线、加密流量检测94%恶意识别率、工控OT旁路白名单、勒索零扩散等核心能力。

## Prerequisites

- 用户已明确安全运维或应急响应场景或问题
- 知识库文件 `07_网络安全与信息安全.md` 及子目录文件可访问

## Steps

### Step 1: 识别安全运维/应急响应需求场景

**Goal**: 明确用户的安全运营需求类型、事件响应成熟度和基础设施规模
**Completion criterion**: 已确定场景标签、SOC成熟度、IT资产规模和主要威胁类型

1. 读取用户消息，提取以下信息：
   - 场景类型：安全日志分析 / SIEM建设 / 入侵检测部署 / 应急响应体系 / 威胁狩猎 / 备份恢复 / 安全运营外包 / AI驱动SOC
   - SOC成熟度：无SOC（分散管理） / 基础SOC（日志集中+规则告警） / 智能SOC（ML+UEBA+威胁情报） / 自治SOC（AI+SOAR全自动）
   - IT资产规模：服务器数量、终端数量、网络设备数量、云资产数量、应用系统数量
   - 主要威胁类型：勒索软件 / APT / 内部威胁 / 数据泄露 / DDoS / 供应链攻击 / Web入侵 / 邮件钓鱼
   - 现有工具：SIEM平台（Splunk/QRadar/Sentinel/ELK/自研）、EDR/XDR、防火墙/IDS/IPS、SOAR平台、威胁情报源
   - 关键痛点：告警噪音大（海量告警无从下手） / 检测滞后（被入侵后才发现） / 响应慢（手动操作遏制不及时） / 日志覆盖不全 / 缺乏威胁情报 / 人员技能不足

2. 对照知识库中的核心能力初步判断：
   - 告警噪音大+检测滞后 → SIEM六层漏斗+UEBA五维基线+AI级联架构
   - 响应慢+手动操作 → SOAR自动Playbook+黄金30分钟遏制策略
   - 勒索软件频发 → 3-2-1-1-0备份+不可变备份WORM+清洁恢复流程
   - 云原生环境 → eBPF探针+K8s审计+容器安全
   - AI驱动需求 → AI大模型分析威胁数据+Agentic AI自主响应

3. 如有信息缺失，向用户追问不超过2个澄清问题。

### Step 2: 输出安全运维/应急响应方案

**Goal**: 产出针对性的SOC建设、入侵检测部署或应急响应体系方案
**Completion criterion**: 输出包含架构设计、工具选型、运营流程、演练计划

根据Step 1确定的场景，按以下分支处理：

**分支A — 安全日志分析与SIEM**：
1. 输出SIEM六层漏斗架构：
   - L1 采集层：全量覆盖（Syslog/eBPF/Windows Event/API/SNMP/CloudTrail/Flow Logs）、代理部署（Beats/Fluentd/Vector/Splunk UF）、协议标准化（统一Schema，如Elastic Common Schema/ Splunk CIM）
   - L2 归一化层：字段映射（不同设备日志字段统一）、威胁情报富化（IP信誉/域名信誉/文件哈希/IOC匹配）、上下文增强（用户信息/资产信息/地理位置/资产重要性标签）
   - L3 存储层：热温冷三级（热SSD秒级查询/近实时分析，温ClickHouse/Elasticsearch分钟级查询，冷S3对象存储长期留存6月+），存储策略（按日志类型/时间/优先级分级存储）
   - L4 分析层：规则关联（Sigma规则/YARA/Suricata/自定义关联规则）、ML异常检测（Isolation Forest/Autoencoder/LSTM）、ATT&CK威胁狩猎（主动搜索IOC/IOA/攻击链）、AI大模型分析（自然语言查询威胁数据→自动关联分析→攻击链还原）
   - L5 响应层：告警分级（P1紧急/P2高/P3中/P4低）、SOAR自动响应（Playbook自动遏制/隔离/阻断/取证）、工单流转（JIRA/ServiceNow集成）、案例管理（事件追踪/证据链/报告生成）
   - L6 可视化层：实时Dashboard（攻击地图/威胁态势/告警趋势）、合规报表（等保/ISO27001审计报告）、攻击链路图（ATT&CK映射可视化）、高管看板（风险评分/关键指标/KPI）
2. 给出SIEM三阶段成熟度：
   - 基础检测（L1-L2）：日志集中+规则告警+人工分析，MTTD<4小时。工具：ELK Stack（开源）、Splunk（商业）、QRadar（IBM商业）。关键：日志覆盖率达95%+、基础关联规则（200+条）
   - 智能分析（L3-L4）：UEBA+ML+威胁情报，MTTD<1小时。工具：Microsoft Sentinel（云原生）、Splunk ES（企业安全）、Exabeam（UEBA专长）。关键：用户行为基线建模、威胁情报自动化、ML异常检测调优
   - 自治运营（L5）：AI大模型+SOAR全自动，MTTD<15分钟。工具：Google Chronicle（AI驱动）、Sentinel+Copilot（AI助手）、自研AI SOC。关键：AI自动告警分级、自动威胁狩猎、自动响应Playbook、人类监督（三层安全刹车）
3. 输出UEBA五维行为基线：
   - 用户维度：登录时间/地点/设备基线、访问数据范围基线、操作频率基线、权限使用基线（如"该用户从不访问财务系统，突然大量查询"）
   - 设备维度：设备类型/操作系统/浏览器指纹基线、网络位置基线、安全状态基线（补丁/EDR/防病毒）
   - 应用维度：应用访问模式基线、API调用频率基线、数据下载量基线、异常操作（如"非工作时间大量数据导出"）
   - 数据维度：数据敏感度基线、访问权限基线、数据流向基线、异常下载（如"首次访问核心数据库并导出全表"）
   - 网络维度：网络流量模式基线、通信对端基线、协议使用基线、异常连接（如"内网主机首次连接外网IP"）
   - 评分模型：五维独立评分→加权汇总→风险评分（0-100），阈值触发告警。2026新增：AI Agent行为监控（AI Agent的异常操作模式）
4. 附某集团案例：2000+关联规则（基础60%/关联30%/AI 10%），告警量下降70%，真实威胁检出率提升3倍。

**分支B — IDS/IPS入侵检测**：
1. 输出分层部署原则：
   - 边界IPS：串联部署（流量必经）、已知攻击拦截（签名规则）、低延迟要求（<1ms）、误报影响大（阻断合法流量风险）
   - 核心交换NIDS：旁路镜像（不影响流量）、深度分析（协议解析/行为分析）、高检测率（复杂攻击检测）、延迟不敏感
   - 关键服务器HIDS：主机代理部署（文件监控/进程监控/注册表监控）、内存攻击检测（无文件攻击）、权限提升检测、 lateral movement检测
   - 云原生eBPF探针：内核级监控（无侵入、低性能损耗）、容器间流量监控、K8s审计事件、系统调用监控、网络策略执行
   - 工控/OT环境：严禁串联IPS（不能中断生产流量）、旁路镜像优先、白名单检测模式（只允许预期协议/端口/IP，其余告警）、检测延迟必须<10ms
2. 给出检测技术演进：
   - 签名检测：基于已知攻击特征（Snort/Suricata规则）、更新频率（每日/每周）、覆盖度（已知攻击覆盖率高、0day盲区）
   - 行为签名：应对AI生成恶意软件"无限多态"——匹配攻击链行为序列（如"进程创建→内存分配→网络连接→数据外泄"）而非文件哈希，适合无文件攻击/内存攻击检测
   - AI级联架构：90%正常流量规则层快速放行（低延迟、低资源），10%可疑流量进入AI模型深度分析（高检测率、识别未知攻击），两层协同平衡性能与检测率
   - 加密流量检测三层架构：JA3/JA4指纹（TLS客户端指纹识别已知恶意工具）→ 流量统计AI（包大小/时间间隔/方向分布，94%恶意加密流量识别率）→ 选择性解密（高可疑流量解密深度分析，平衡隐私与检测）
3. 输出规则生命周期管理：
   - 开发：基于ATT&CK技术映射+威胁情报+内部事件→编写检测规则（Sigma格式/YARA/Snort）
   - 灰度：小范围部署（5%资产）→ 监控误报率→ 调整阈值/条件
   - 全量：误报率<5%后全量部署→ 持续监控检出率
   - 监控：定期评估规则有效性（检出率/误报率/覆盖率）→ 淘汰失效规则
   - 某企业案例：规则集从12万精简至3.5万，有效告警占比从8%提升至35%
4. 附IDS/IPS选型：Suricata（开源、高性能、多线程、支持IPS模式）、Snort（老牌开源、社区活跃）、Zeek（Bro，深度协议分析、日志丰富）、商业（Palo Alto Threat Prevention、Cisco Firepower、华为USG IPS）。

**分支C — 网络安全应急处置**：
1. 输出NIST SP 800-61r3六阶段模型：
   - 准备（Preparation）：应急预案体系（"1个总体+N个专项+M个Runbook"）、工具准备（取证工具包/隔离工具/备份恢复工具）、人员培训（定期演练/红蓝对抗/桌面推演）、情报储备（威胁情报订阅/IOC库/ATT&CK映射）
   - 检测与分析（Detection & Analysis）：事件发现（SIEM告警/EDR告警/用户报告/外部通报）、初步分析（攻击类型/影响范围/攻击路径）、证据保全（磁盘镜像/内存转储/日志备份/网络流量PCAP）、ATT&CK映射（还原攻击链TTPs）
   - 遏制（Containment）：短期遏制（隔离受感染主机/阻断恶意IP/关闭受影响服务/重置凭证）、长期遏制（加固边界/修复漏洞/加强监控/限制访问）、黄金30分钟（勒索行为发现后30分钟内必须隔离，防止横向移动）
   - 根除（Eradication）：恶意软件清除（杀毒/手动清除/重装系统）、后门清理（检查计划任务/WMI/启动项/服务/账号/注册表/内核模块）、漏洞修复（补丁/配置加固/代码修复）、逐项验证（磁盘文件→注册表→计划任务→WMI→启动项→账号权限→网络配置）
   - 恢复（Recovery）：清洁恢复（从可信备份恢复，确保备份未被感染）、分阶段恢复（先核心业务→再辅助系统→最后非关键系统）、监控加强（恢复后7天内高频监控）、业务验证（功能测试/数据完整性校验）
   - 事后活动（Post-Incident）：复盘报告（时间线/攻击链/影响评估/响应评价）、改进措施（防御加固/流程优化/工具升级/培训加强）、知识沉淀（写入威胁情报库/更新检测规则/更新Playbook）、法律报告（监管通报/客户通知/保险索赔）
2. 给出应急响应体系成熟度（CERT-RMM五级）：
   - L1 初始级：无预案、被动响应、依赖个人英雄
   - L2 受管理级：有总体预案、有响应团队、有基础工具
   - L3 已定义级：预案体系完善（总体+专项+Runbook）、有演练机制、有度量指标
   - L4 量化管理级：MTTD/MTTR/MTTC量化达标、有自动化响应（SOAR）、有持续改进机制
   - L5 优化级：AI驱动响应、预测性防御（提前发现APT）、行业协同（威胁情报共享）
3. 输出勒索软件专项响应：
   - 检测：EDR告警（文件批量加密行为/勒索信检测）、SIEM关联（异常文件修改模式）、用户报告（桌面壁纸被篡改/文件打不开）
   - 遏制：SOAR自动Playbook 90秒完成隔离（断开网络→隔离主机→阻断C2通信→快照保留）、黄金30分钟原则
   - 根除：不可变备份恢复（WORM备份确保未被加密）、清洁恢复（从离线备份重建，不支付赎金）、数字取证（保留磁盘镜像用于事后分析/执法）
   - 备份韧性3-2-1-1-0原则：3份数据+2种介质+1份异地+1份离线（不可变WORM）+0错误（定期校验恢复）
   - 某金融机构案例：三级应急体系（总行-分行-支行），SOAR自动遏制90秒完成勒索隔离，2025年3起勒索事件"零扩散"，配合不可变备份+清洁恢复，RTO<4小时
4. 附应急演练矩阵：
   - 桌面推演（Tabletop）：每月1次，模拟场景（勒索/APT/数据泄露/DDoS），评估决策流程
   - 模拟演练（Simulation）：每季度1次，部分系统隔离+真实工具操作，测试技术流程
   - 实战演练（Live Fire）：每年1次，红队真实攻击+蓝队防御响应，全面检验
   - BAS（Breach and Attack Simulation）：持续自动化验证（SafeBreach/Cymulate/Picus），模拟攻击链验证防御有效性
   - AI赋能应急：AI自动告警分级（日均500告警→AI筛选30个需人工分析）、AI辅助攻击链还原（自动关联日志→还原攻击路径）、AI生成处置建议（基于攻击类型推荐遏制策略）

**分支D — SOC运营与AI驱动**：
1. 输出SOC运营KPI体系：
   - 检测指标：MTTD（平均检测时间，从攻击开始到检测到的间隔，目标<1小时）、告警噪音比（真实威胁告警/总告警，目标>30%）、日志覆盖率（已采集日志/应采集日志，目标>95%）、威胁情报利用率（情报驱动检测占比，目标>50%）
   - 响应指标：MTTR（平均响应时间，从检测到遏制的时间，目标<4小时）、MTTC（平均遏制时间，从遏制开始到完成的时间，目标<30分钟）、自动化响应率（SOAR自动处理/总事件，目标>60%）、SLA达成率（目标时间内完成响应的事件比例，目标>90%）
   - 效果指标：漏洞修复率（SLA内修复比例，高危7天/中危30天）、重复事件率（同一类型事件重复发生比例，目标<10%）、安全事件损失（直接经济损失/业务中断时间/数据泄露量）
   - 成熟度指标：等保测评得分、CERT-RMM级别、安全投入ROI（避免的损失/安全投入）
2. 给出SOAR平台设计：
   - 核心功能：Playbook编排（可视化流程设计：触发条件→条件判断→执行动作→人工审批→闭环）、多工具集成（EDR/防火墙/SIEM/邮件/工单/威胁情报API）、案例管理（事件追踪/证据链/时间线/报告生成）
   - 典型Playbook：钓鱼邮件处置（邮件网关隔离→EDR扫描附件→用户通知→凭证重置→IOC提取→威胁情报更新）、勒索软件遏制（EDR告警→自动隔离主机→阻断C2→取证快照→通知SOC分析师→启动恢复流程）、异常登录响应（UEBA告警→MFA挑战→登录阻断→通知用户→管理员审批→安全审查）
   - 三层安全刹车：L1 自动执行（低风险操作，如信息查询/日志检索）、L2 人工确认（中风险操作，如主机隔离/账号禁用）、L3 人工审批（高风险操作，如网络分区/批量删除/生产系统变更）
   - 选型：Splunk SOAR（与Splunk深度集成）、 Palo Alto XSOAR（开源+商业版、社区Playbook丰富）、IBM Resilient、Swimlane（低代码编排）
3. 输出AI驱动SOC演进：
   - AI告警分级：LLM分析告警上下文（日志/情报/资产重要性/历史事件）→ 自动判定优先级（P1-P4）→ 日均人工分析从500降至30个事件
   - AI攻击链还原：自动关联分散日志（登录→横向移动→权限提升→数据访问→外泄）→ ATT&CK TTP映射→ 攻击路径可视化
   - AI威胁狩猎：自然语言查询（"查找过去7天内从HR部门发起的外部数据上传"）→ LLM自动转化为查询语句→ 执行→ 结果解读
   - Agentic AI自主响应：感知（SIEM/EDR/情报多源输入）→ 分析（AI关联+攻击链还原）→ 决策（自动判定遏制策略）→ 执行（SOAR Playbook自动执行）→ 优化（结果反馈→模型改进），人类保留否决权
4. 附人员能力建设：
   - L1 初级分析师：日志分析基础、告警初筛、工单处理、标准Playbook执行
   - L2 中级分析师：威胁狩猎、事件调查、规则调优、工具配置、ATT&CK分析
   - L3 高级分析师：APT追踪、攻击链还原、应急响应指挥、红蓝对抗、威胁情报分析
   - L4 安全架构师：SOC架构设计、AI模型调优、安全策略制定、跨团队协作、管理层汇报

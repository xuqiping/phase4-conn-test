# 5.3 Microsoft KANO研究实践

## 案例

Microsoft Research在产品管理方法论研究中对KANO模型有深入实践。2022年Microsoft Research发布文章《Lots of ideas, but not sure how to prioritize? The Kano model can help》，系统阐述KANO在微软产品中的应用。

| 维度 | Microsoft的KANO实践 |
|---|---|
| **应用场景** | 产品待办事项(Product Backlog)优先级排序、新功能创意筛选 |
| **核心问题** | 团队有"百万个创意"但不知道哪些真正重要——KANO帮助区分"必须有"和"有更好" |
| **方法论** | 使用KANO分类+Better-Worse分析，量化每个功能对满意度的影响 |
| **决策框架** | KANO分类→MoSCoW映射→Sprint排期 |

## Microsoft的关键贡献

1. **KANO与敏捷的结合**：微软将KANO分类直接映射到敏捷开发中的MoSCoW优先级桶，使定性分类直接驱动迭代排期
2. **产品Backlog治理**：面对无尽的功能创意，KANO作为"过滤器"——I类和R类直接从Backlog中移除
3. **客户洞察研究**：微软的Customer Insights Research团队将KANO作为核心工具之一，用于量化客户需求属性

## 对PM的启示

- **KANO不是一次性活动**：微软在产品Backlog持续维护中定期重跑KANO，捕捉漂移
- **产品Backlog需要"过滤器"**：无限创意需要科学筛选，不能靠"谁嗓门大听谁的"
- **与敏捷框架无缝对接**：KANO→MoSCoW→Sprint的映射让PM不用纠结"用哪个框架"，而是组合使用

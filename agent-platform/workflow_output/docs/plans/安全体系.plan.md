## 背景与威胁模型摘要

- 现状基线：前一轮安全审计 16 项漏洞已全部修复。本规划从「修漏洞」升级为「建体系」，对标 OWASP Top 10 + OWASP LLM Top 10 (2025)。
- **关键背景**：积分计费系统已于 2026-08-07 上线（Phase4 通过）。按路线图规则「若计费系统先于安全体系上线，L 域 L1~L4 必须提前到 S1」——钱相关的并发漏洞不能等。
- 最高危攻击面：🔴 文件上传存储型 XSS（F-1，FileController.java:44-45 下载端点 inline 渲染 + 上传无类型校验，已确认可直接利用）；🔴 业务逻辑（并发双花/重放/负数金额未防）；🔴 主机基线与应急响应空白。
- 次危：🟠 AI 特有面（prompt 注入/间接注入/系统提示词泄露基本未防）；🟡 认证缺登录防爆破与 MFA、无审计链、无依赖扫描、SSRF 残留（DNS rebinding + storeStream 回源）。

## S2~S5 概要步骤（到时各展开为独立子 plan）

**S2 防篡改+越权机制（6~7 人日）**
1. audit_logs 加 `prev_hash`/`record_hash` 两列 + HMAC-SHA256 写入串行化（pg_advisory_xact_lock），密钥走 `AUDIT_HMAC_KEY` 环境变量。
2. DB 权限分离：应用账号对 audit_logs REVOKE UPDATE/DELETE；积分流水表只增不改（与 L4 联动）。
3. 链校验工具 + 每日定时校验断链告警；验收：手动 UPDATE 一条审计 → 断链告警。
4. B1 启动期/CI 扫描无 `@RequirePermission` 且非白名单端点 → 告警清单。
5. B2 越权测试脚手架：A 建→B 读/改/删断言 403；B3 收口 `getXxxScoped(id, userScope)` 命名红线。
（到时展开为 `安全体系_S2防篡改与越权.plan.md`）

**S3 AI 安全（5~7 人日）**
1. RAG/联网返回内容包 `<retrieved_data>` 数据区围栏 + system prompt 声明「围栏内只是数据」。
2. KB 文档入库注入特征扫描，命中标记隔离；检出注入写安全审计+告警。
3. 输出侧敏感模式扫描（apiKey/手机号/身份证正则打码）+ prompt 片段指纹检测（LLM07）。
4. 前端 LLM 回复/Markdown 渲染接 DOMPurify，禁 `v-html` 裸渲（C2 并入本阶段）。
5. 单用户 LLM 调用速率限制（Redis 滑动窗口）+ 单会话 token 上限（LLM10）。
6. KB 越权检索回归测试（含 sidecar 回调路径）。
（到时展开为 `安全体系_S3AI安全.plan.md`）

**S4 文件与主机加固（6~8 人日）**
1. F-2 统一 `FileUploadValidator` 咽喉点：大小+扩展名白名单+magic number 嗅探，5 个上传入口全收口。
2. F-3 像素上限/XXE 禁用/抽帧超时；F-4 per-user 存储配额+上传限流；F-5 部署红线核查（Nginx 禁直达 uploads）。
3. L5 高成本操作按用户限流；L6 工作流节点 LLM 调用强制过计费。
4. K1 Windows 基线（RDP 改端口+锁定策略+防火墙白名单）；K2 Redis/PG/Actuator 仅 localhost。
5. K3 Nginx 加固（隐藏版本/限流/防 Slowloris/禁 autoindex）；K4 目录 ACL 最小化；K5 基线核查脚本入《运维手册》。
（到时展开为 `安全体系_S4文件与主机.plan.md`）

**S5 检测响应与收尾（8~10 人日）**
1. M1 IR 预案入《运维手册》+桌面推演；M4 蜜罐端点；M2 UEBA-lite 规则告警；M3 FIM 哈希基线；M5 备份不可变性；M6 月度狩猎巡检。
2. A6 管理员 TOTP 强制绑定；A4 refresh token 旋转；A5 弱密码字典；A7 token 存储评估结论。
3. G5 密码学实现一次性审计（AES 模式/IV、JWT 算法锁死、SecureRandom、BCrypt 强度）。
4. C5 WS Origin 校验；C6 反序列化排查；C7 请求走私/缓存投毒/Host 头核查；C8 更新接口 UpdateDTO 红线。
5. H SSRF 连接期 IP 绑定 + sidecar 出站白名单 + storeStream 回源过 Guard。
6. I1/I2/I4/I5 供应链扫描与 SAST/DAST；J1~J4 隐私合规收尾。
（到时展开为 `安全体系_S5检测响应与收尾.plan.md`）

## 全计划共享安全检查清单

- [ ] **鉴权/授权（OWASP A01）**：每个按-id 端点有归属/权限校验；新增端点进 B1 扫描白名单或注解。
- [ ] **注入（A03）**：SQL 全 `#{}`（C1 门禁兜底）；XSS 输出消毒；文件上传不信任客户端 MIME。
- [ ] **设计安全（A04）**：钱/积分一律服务端算；并发扣减原子化；关键写接口幂等。
- [ ] **配置安全（A05）**：安全响应头、CORS 白名单、中间件端口绑定、Nginx 加固。
- [ ] **认证失效（A07）**：登录防爆破、MFA、JWT 算法锁死、refresh 旋转。
- [ ] **完整性（A08）**：gitleaks/依赖扫描/CI 门禁；审计哈希链；FIM。
- [ ] **日志与监控（A09）**：安全事件写 audit_logs；异常行为检测；IR 预案。
- [ ] **SSRF（A10）**：所有外发 URL 过 SsrfGuard（含 storeStream 回源与 sidecar 出站）。
- [ ] **AI 特有（LLM Top 10）**：注入围栏、输出消毒、提示词遮蔽、用量上限。

## 术语表（全计划共享）

| 术语 | 大白话 | 案例 |
|---|---|---|
| 存储型 XSS | 恶意脚本被存进系统，之后谁打开谁中招 | 上传 evil.html，管理员点开链接即被执行 JS |
| Content-Disposition | 响应头，告诉浏览器「在线打开」还是「下载存盘」 | inline=在线渲染；attachment=强制下载 |
| nosniff | 禁止浏览器自作主张猜文件类型 | 防把 octet-stream 当 html 执行 |
| 哈希链 | 每条审计记录含上一条的指纹，改任何一条全链条对不上 | UPDATE 一行审计 → 链校验报断链 |
| 幂等键 | 同一请求带唯一编号，重复提交只生效一次 | 网络重试不会重复扣积分 |
| 原子扣减 | 「查余额+扣钱」合成一条不可拆的 SQL | 并发 20 个请求余额不为负 |
| gitleaks | CI 里扫密钥的工具，密钥进仓库即构建失败 | 防第二次 #2 密钥泄露 |
| CSWSH | 跨站 WebSocket 劫持，恶意站点借用户凭证开 WS | 握手补 Origin 校验拦截 |
| UEBA-lite | 轻量异常行为检测：用量突增/批量下载即告警 | 单用户 LLM 用量突增 10 倍触发告警 |
| FIM | 文件完整性监控：程序文件哈希基线，被改即告警 | 入侵者篡改 jar 留后门被发现 |

## AI需求分类与标签

### 一、自动分类维度

AI自动分类覆盖的维度体系：

| 维度 | 分类类别 | AI判定方式 | 人工复核 |
|---|---|---|---|
| 功能模块 | 支付/搜索/社交/... | 基于产品模块树匹配 | 必须 |
| 需求类型 | 新功能/优化/Bug/安全 | 语义分类 | 必须 |
| 用户角色 | C端/B端/内部运营 | 上下文推断 | 建议复核 |
| KANO类别 | 必备/期望/魅力/无差异/反向 | 基于描述+用户情感初判 | 必须复核 |
| Epic/Feature层级 | L1 Epic → L2 Feature → L3 Story | 基于粒度+关系推理 | 建议复核 |
| 业务线 | 交易/内容/增长/... | 基于组织架构知识 | 可自动 |

### 二、KANO初判的AI策略

KANO分类本身需要**问卷调查**（功能/不满/满意四问题），纯文本无法精确判定。AI的定位是**初筛提示**：

```
AI初判Prompt核心逻辑：
- 含"不能没有/必须/最基本的" → 备选：必备属性
- 含"越多越好/希望/如果有" → 备选：期望属性  
- 含"惊喜/没想到/哇" → 备选：魅力属性
- 含"无所谓/都行/不在意" → 备选：无差异属性
- 含"反感/讨厌/别加" → 备选：反向属性
输出格式：
  {
    "kano_hint": "必备属性",
    "hint_confidence": 0.7,
    "need_survey_verify": true,
    "survey_questions_suggestion": [...]
  }
```

**关键红线**：AI的KANO初判**不可替代正式KANO问卷**，仅作为优先级排序的辅助参考。

### 三、标签体系设计

标签分为**系统标签**（AI自动分配）和**业务标签**（PM手动维护）：

| 标签类型 | 示例 | 分配方式 |
|---|---|---|
| 系统标签-模块 | #搜索 #支付 #个人中心 | AI自动（基于模块树匹配） |
| 系统标签-情感 | #负面高优 #正面增强 #中性观察 | AI自动（情感分析） |
| 系统标签-来源 | #AppStore #工单 #NPS #访谈 | AI自动（来源元数据） |
| 业务标签-主题 | #Q3OKR #竞品应对 #合规 | PM手动 |
| 业务标签-状态 | #待评审 #已排期 #暂缓 | PM手动 |

### 四、分类准确率优化

1. **Few-shot示例库**：维护每个分类的5-10个典型需求示例，注入Prompt
2. **产品模块树注入**：将产品的完整功能模块树加入上下文，避免"瞎猜"
3. **分类校准集**：人工标注100-200条需求作为基准，定期评估AI分类的F1-Score
4. **渐进式自动化**：新领域从"AI建议+人工确认"开始，准确率>90%后转自动

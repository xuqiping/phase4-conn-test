# 已解决
1. 只能有一个系统管理员 ✅（2026-08-20 核验：功能本就支持，属使用方式问题）—— `user_roles` 复合主键 `(user_id, role_id)`（V1 建表）天然支持一人多角色/多人同角色；`PUT /api/users/{id}/roles` 全量替换该用户角色集（可同时勾选多个管理员），`user:manage` 权限 + `@AuditLog(assign_roles)` 审计。**操作指引**：系统管理 → 用户管理 → 目标用户「分配角色」→ 勾选「系统管理员」（可与其他角色并存）→ 保存即生效（用户重新登录后 JWT 带新权限）。已同步速查表 03。
2. 普通账号（aa64221886）进图片生成/视频生成/无限画布报 403 ✅（2026-08-20）—— 根因：`media:gen`/`canvas:write`/`asset:write`/`media:edit` 四个权限码在 V54/V55/V58/V87 建表时只 INSERT 给了 admin（历史 INSERT ... SELECT 均带 `WHERE r.code='admin'`），`user` 角色从未获得；普通账号 JWT 里没有这些权限 → 页面能进菜单但接口层 403。修复：V136 `INSERT INTO role_permissions ... WHERE r.code='user' ON CONFLICT DO NOTHING` 一次性补授存量 + 新库自动生效；**需重新登录**（权限烘焙在 JWT，旧 token 仍是旧权限集）。注意：`canvas:write` 授予后普通用户可建自己的画布（仍只能看/改自己创建的，画布归属由 CanvasService.loadOwned 咽喉控制）。

# Implementation Plan for 自助充值支付与账单总览

> Phase 2 产出。Phase 3 逐步勾选执行。只含伪代码，不含真代码。
> 来源规格：[../specs/自助充值支付与账单总览设计.md](../specs/自助充值支付与账单总览设计.md)
> 拍板：支付架构+接口先落（mock 可测，真实商户后接）；不建金额钱包只记流水。

## 背景与目标

- 7x#1：充值记录六字段（用户账号/渠道付款账号/金额/积分/充值后余额/累计充值）。
- 7x#3：支付宝/微信支付接入——本期落领域架构+PENDING 状态机+回调验签幂等+MOCK 通道全链路；ALIPAY/WECHAT 骨架留配置位。
- 20x#1：admin 账单「用户余额」视图（全用户余额+累计充值+全平台合计卡）。

## 技术实现坑点预判与规避措施

| 技术点/功能块 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| **回调重复投递** | 渠道重推（我方应答超时）→ 重复入账 | 三道幂等：uk_payment_channel_order 唯一索引 → 条件 UPDATE PENDING→PAID（0 行=已处理返回成功）→ uq_ledger_ref 兜底；入账三写同事务 | IT：同回调连发 3 次只入 1 次 |
| **过期与回调竞态** | 过期 job 刚把订单 CLOSED，渠道回调才到（用户最后一刻付款） | 条件 UPDATE 谁先谁赢；回调遇到 CLOSED+真实付款 → 不自动入账，打 ERROR+安全事件+进对账异常列表「已付已关单」人工补单（mock 通道可精确复现该时序） | IT：CLOSED 后回调→不入账+异常留痕 |
| **金额复核绕过** | 伪造/篡改回调金额 | 验签后仍比对 回调金额==订单金额，不等→FAILED+安全事件；验签与比对都在 service 不在 filter | 单测：金额不符拒 |
| ratio 档位中途变更 | 下单时按 100:1 显示，支付后档位改了 → 入账积分与预期不符 | **下单时快照 points_granted 落单**，回调入账只吃快照不重新换算 | 单测：下单后改档位，入账=快照 |
| 双击/重试重复下单 | 用户狂点或前端重试 → 多单 | 前端 idemKey（UUID/表单会话）+ uk_payment_idem(user_id, idem_key) 唯一；撞键→返回已有单（同键同金额）或 409（同键不同金额+审计） | 单测两场景 |
| **mock 通道泄露出生产** | prod 环境忘关 mock → 任何人免费充值 | `billing.payment.mock-enabled` 默认 false；profile=prod 且 mock=true → 启动失败（EnvironmentPostProcessor 或 @PostConstruct 检查直接 throw）；可用渠道列表接口不下发 mock | 单测：prod+mock 启动即炸 |
| PENDING 单堆积 | 用户创建不支付 → 表膨胀/查询慢 | expire_at=+30min + 每分钟批量 CLOSE（单批 200，`status,expire_at` 部分索引）；CLOSED 单保留对账 | IT：造过期单跑 job |
| NUMERIC 金额精度 | double 传参精度漂移 | 全链 BigDecimal；DTO @DecimalMin/Max；DB NUMERIC(14,2) 既有 | 单测 0.01/99999.99 边界 |
| 匿名 notify 端点滥用 | 扫到端点狂刷 | SecurityConfig 精确放行 `/api/billing/payment/notify/**`；端点全局限流；验签失败计数→安全事件阈值告警（复用 SecurityEvent） | 单测：无签名 400 ×N 触发事件 |
| **V93 拼写雷** | `REVOKE ON payment_orders`（复数）在 agent_app 角色存在时炸迁移 | V139 内对正确表单数补 REVOKE（IF role exists 守卫）；不动 V93 历史文件 | migrate 冒烟（有/无 role 两种环境） |
| 累计充值聚合慢 | 每行记录都 SUM 全表 | 累计只在「列表顶部汇总条」按 user_id 聚合一次（PAID 索引）；用户余额视图合计卡全表 SUM——数据量小（万级）直算，>10 万再物化 | 性能验证 §性能 |
| 既有 admin 充值路径回归 | channel=ADMIN 走 grantIdempotent 直接 PAID，与新状态机冲突 | ADMIN 路径零改动；充值记录口径含 ADMIN 行（渠道显「管理员」，付款账号「—」）；grantWithLedger 不动签名 | 既有测试全绿 |

## 安全检查清单

- [ ] **验签**：notify 先验签再解析；mock=HMAC(服务端密钥, token+expire)；真实渠道留 verify 接口位
- [ ] **金额复核**：回调金额==订单金额，不符 FAILED+安全事件
- [ ] **幂等**：渠道单号唯一索引+条件 UPDATE+uq_ledger_ref 三道；创建侧 uk_payment_idem
- [ ] **防重放**：mock HMAC 内容含 expire 时间戳；真实渠道用其原生 timestamp/nonce（实现时落）
- [ ] **越权**：查单/取消/我的记录=SecurityContext userId+service 本人校验；admin 端权限码
- [ ] **密钥管理**：`billing.payment.*` 全部环境变量；application.yml 只留占位 key 名；日志禁打签名原文，payer_account 日志掩码
- [ ] **限流**：下单 10 次/分/用户（@RateLimit）；notify 全局限流
- [ ] **审计**：下单/入账/关闭/取消/FAILED 全留痕（@AuditLog 或 fromMdc）
- [ ] **传输**：notifyUrl HTTPS 写入部署 checklist（文档）

## 性能考虑与验证计划

- [ ] 下单 p95<300ms（单表 INSERT+渠道 precreate，mock 为内存 HMAC）
- [ ] 回调入账 p95<500ms（条件 UPDATE+三写事务）
- [ ] me/recharges、admin/recharges 走 (user_id,status,created_at) / (status) 索引，分页 p95<300ms
- [ ] user-balances 视图：users LEFT JOIN wallet LEFT JOIN PAID 聚合子查询，1 万用户 p95<800ms；合计卡同查询复用
- [ ] 过期 job 单批 200<1s；部分索引 `WHERE status='PENDING'` 防全表扫

## 功能联动点清单

| 触发动作 | 联动对象 | 预期变化 | 边界（反向/取消/批量） |
|---|---|---|---|
| 下单成功 | 前端收银台 | 展示 mock 按钮/二维码占位 | 反向=用户关闭页面→单挂起到过期；同 idemKey 重进→返回原单不新建 |
| 支付成功（回调） | 用户余额/页顶个人积分徽标/钱包页 | 余额增、RECHARGE 流水、记录可见 | 徽标是路由切换轻刷新——充值成功后前端主动调一次刷新；**并发多设备**看旧值，下次刷新自愈（不做推送） |
| 支付成功 | 充值记录累计条 | Σ金额/Σ积分实时增 | 仅统计 PAID；FAILED/CLOSED 不计 |
| 用户取消订单 | 订单状态 | PENDING→CLOSED | 已 PAID 不可取消（条件 UPDATE 0 行→409 文案）；取消后 mock 按钮再点→回调遇 CLOSED 走异常路径 |
| 过期 job | 订单状态 | 批量 PENDING→CLOSED | 与回调竞态见坑表；job 失败下轮重扫（幂等） |
| admin 充值（既有） | 充值记录列表 | channel=ADMIN 行出现在记录 | 付款账号「—」；渠道筛选含「管理员」项 |
| 充值入账 | 低余额在途闸门（InflightGate） | 余额回升后闸门自动放行 | 既有 requireAffordable 逻辑消费新余额，无需改 |

## 运维考量清单

| 类别 | 决策 | 说明 |
|---|---|---|
| 可观测性 | **做** | 下单/验签结果/入账/关闭全 INFO 日志带 orderId+userId；回调处理带 channelOrderId；FAILED 与「已付已关单」ERROR 级 |
| 配置开关 | **做** | `billing.payment.mock-enabled`（默认 false，prod 开启启动即炸）；`billing.payment.order-expire-minutes`（默认 30）；渠道 enable 开关按配置有无自动判定 |
| 可回滚 | **做** | V139 只加列+索引+放宽 CHECK——向后兼容，回滚代码即安全；迁移回滚块（DROP 列/索引）注释备录；支付功能整体可关：无可用渠道时前端充值按钮隐藏 |
| 限流/熔断/降级 | **做（限流）/后续（熔断）** | 下单+notify 限流本期；真实渠道调用超时/熔断留到商户接入时（当前无出站调用） |
| 运维入口 | **做** | 对账扩展：admin `/reconcile` 加「渠道异常」节——PENDING 超 10min 未关、PAID 无流水、CLOSED 有真实付款（人工补单线索）；补单动作本期用 SQL+审计，不做页面 |
| 告警阈值 | **做（轻）** | 验签失败/金额不符入 SecurityEvent 体系（既有告警管道）；不新增告警通道 |
| 容量/性能预案 | **做（评估）** | payment_order 月增预估<1 万行，无需分区；CLOSED 单保留；索引已覆盖查询面 |

## 术语表

| 术语 | 大白话 | 例子 |
|---|---|---|
| **幂等** | 重复执行效果和一次一样 | 回调重推 3 次积分只加 1 次 |
| **条件 UPDATE 抢态** | 带状态前提的更新，0 行=已被处理 | PENDING→PAID 只认第一次 |
| **验签** | 用密钥/公钥校验回调真来自渠道 | 防伪造付款成功 |
| **快照** | 下单时把换算结果定死存下来 | 档位后来改了也不影响这单 |
| **部分唯一索引** | 只对非空行做唯一 | channel_order_id 空的管理员单不受限 |
| **MOCK 通道** | 假支付渠道，走真实回调链路但不用真钱 | 测试全链路不用商户号 |

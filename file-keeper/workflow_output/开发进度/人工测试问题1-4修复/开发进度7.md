## 本轮实现

- 在现有 `ClipboardStorage` 内实现分组创建、列表、重命名和删除，没有引入第二套数据库。
- 分组名统一去除首尾空白，限制 1—40 字符，拒绝控制字符，并按忽略大小写判重。
- 删除分组在 SQLite 事务中先将所属记录移回“未分组”，再删除分组元数据，不删除剪贴板内容。
- 单条和批量移动共用一次参数化 `UPDATE ... IN (...)`；置顶和取消置顶同样一次提交，避免 N+1 数据库访问。
- 批量操作发现任一记录不存在时整体回滚，避免部分成功造成界面与数据库不一致。
- 查询支持自定义组与“未分组”筛选，排序固定为置顶、置顶时间、创建时间、ID，分页边界保持稳定。
- 重复采集文本只更新时间，不覆盖原分组和置顶状态。
- 新增 Tauri 命令、前端 API 与 Pinia 数据链；写操作成功后发送脱敏的 `clipboard://changed` 刷新提示。

## 安全、隐私与运维

- 所有分组名和 ID 均以 SQLite 参数绑定传入，不拼接用户输入；动态 SQL 只拼接内部生成的占位符编号。
- 错误码不含剪贴板正文；事件负载固定为 `mutation`，不携带路径、标题或内容。
- 数据写入已经提交后，事件发送仅作刷新提示；监听器故障不会把成功写入伪装成失败回滚。
- 未新增依赖、服务端请求、云同步或远程日志。

# 生图大模型接入 · Feature Map

> 代码-功能速查表。两模型：Seedream 5.0 lite（≤14 参考图/组图 max15/联网/stream/2K3K4K+WxH/standard）+ 5.0 pro（≤10 参考图/无组图联网流式/2K3K+WxH/guidance[1,10]/standard+fast）。
>
> **架构关键**：图片 API 是**同步**（POST 一次返 data[].url），与视频异步 create/poll 不同。故 `ArkImageProvider` 是独立 `@Component`（不实现 MediaGenProvider），worker 按 task_type 分流——视频路径零回归，图片路径并列。

## 关键调用链

```
提交：ImageGenView.onSubmit → mediaApi.submitImage(POST /media/image)
  → MediaGenController.submitImage → MediaGenTaskService.submitImage
  → requireAffordable + validateImage + insert PENDING
  → worker processImage（mediaTaskExecutor 线程）
  → ArkImageProvider.generate（同步 POST ctaigw）
  → handleImageSucceeded → 逐张 downloadImageAndStore → result_meta
  → chargeMedia(KIND_IMAGE, generated_images) → markImageSucceeded

查询：pollOnce → GET /tasks/{id} → MediaGenQueryService.toVO(IMAGE分支)
  → imageUrls[] → 前端 ensureImages fetchMediaBlob 逐张

入库：图片格「入库」→ SaveImageToAssetDialog → POST /assets/from-media
  → AssetMediaBridgeController → AssetMediaBridgeService.importFromMediaTask
  → requireWrite + loadImageForImport → 建 IMAGE 资产 v1（fileId 复用）

参考图：AssetFilePicker（资产库选图）→ refFileIds → buildImageRequest 转 dataURI
```

## 表与 SQL 注解

- **media_gen_tasks**（V54 建表，V84 加列）：图片任务复用此表。`task_type` 新值 TEXT2IMAGE/IMAGE2IMAGE；`result_meta` JSONB 存 `{imageFileIds[],generatedImages,outputTokens}`（视频行留空，避免 N 列）。索引复用 V54（user_id,status,ark_task_id）。
- **stored_files**：逐张图下载落 source=MEDIA 行，fileId 存入 result_meta.imageFileIds。入库时复用此行（不拷贝）。
- **llm_providers**：IMAGE 类 provider 行（admin 自建，category=IMAGE）。**无 seed**。
- **pricing_rule**（V66 建表）：两模型 price_per_image（admin 配，**无 seed**）。
- **Flyway 规则**：V84 加列附 drop 回滚；已执行脚本不可改，改结构加新版本。

## 计费原理（大白话）

图片按**张**收费（区别视频按时长/Token）。`chargeMedia` 的 `imageCount` 参数 = Ark 返回的 `usage.generated_images`（实际生成张数），不是请求数——组图 4 张就算 4 张。后扣（生成完才扣），允许瞬时欠款，下次提交 requireAffordable 预检拦截。缺价表 → PRICING_NOT_FOUND 被 MediaBillingService 吞 → usage 记 FAILED 但不阻生成。

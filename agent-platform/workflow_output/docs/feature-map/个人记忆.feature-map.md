## 一句话
每轮对话全程留账(INPUT/OUTPUT 各一条,恒个人域)→ 开生成后一次 LLM 出三层(L0 标签/L1 概要/L2 详述)→ 写时标签归一 → 召回聚合标签(三路 UNION:turns+summaries+文件记忆)+优先读自己总结+拼未覆盖流水账+①.5 项目条目/授权链合流 → 周期总结压缩(方向 INPUT/OUTPUT/BOTH) → 时序冲突 pending → 项目可读单元=收录条目(规则→精判→蒸馏→owner 审核;条目带 direction,文件名硬规则用户级唯一+先建者赢)+ 跨项目共享走授权链 + 项目↔个人只读授权 + 公共池 + **收录确认式回复**(附件命中硬规则→模板确认+点选,不调 LLM)。

## 技术原理(大白话)
- **流水账 = 私人账本**:[memory_turns](#2-memory_turns--流水账个人域主体) 每行 = 你说的一句或 AI 回的一段。**恒个人域**(user_id=作者),不挂项目——别人命中不了,无需额外字段。一期「挂项目共享/departed 保交接」已废。
- **标签 = 贴在账本上的便签**:[memory_tags](#1-memory_tags--标签库) 独立成表,`主体:主题`(如 `我:居住`)。写时系统自动查同义标签复用(「兴趣」归并到已有「爱好」),你只能改名/补别名,不能手动合并(合错了不可逆)。**主动建标签**走 POST /tags,与写时被动归一同源。
- **总结 = 月度结账**:800 条爱好对话灌 AI 太贵。[memory_summaries](#3-memory_summaries--总结提炼层共享化) 把它们压成 1 条精华,带溯源(来自哪些账本行 + 哪些项目条目)。AI 先看总结标题(reflect),感兴趣的才翻原文,省 token。**总结带方向**(INPUT 收获 / OUTPUT 产出 / BOTH 综合)和 scope_owner(个人/项目共享)。
- **覆盖表 = 打钩记录**:[memory_summary_coverage](#4-memory_summary_coverage--覆盖表allcovered-判定) / [memory_entry_coverage](#7-memory_entry_coverage--项目条目覆盖) 记「这条账本行/项目条目的这个便签已被我的总结吃进去了」。召回时全打钩的行走总结压缩态、没全打钩的才翻原文,避重复。**召回只认 user_id=自己的 coverage**(防他人总结污染)。
- **项目可读单元 = 收录条目**(不是流水账):项目对话内容进项目记忆走「收录规则→LLM 精判→蒸馏→owner 审核」管线落 [memory_project_entries](#8-memory_project_entries--项目记忆条目二期可读单元),成员即可读、离职(DEPARTED)即失读权。条目记 source_turn_id(OUTPUT)+ source_turn_input_id(INPUT 配对,V100 建链+V125 存量回填)+ direction(INPUT/OUTPUT/BOTH,V126,蒸馏源轮次侧面,项目总结按方向取数)。
- **文件名硬规则 = 用户级唯一 + 先建者赢**(第三轮 #8):同用户跨项目配同义 pattern(trim+小写归一)→ 保存 409 指明先占项目;异步路由多项目同时命中同一文件 → 只收录规则创建最早的项目(createdAt 升序,同刻按 id),其余让位。查重是用户级非全局,不同用户可配相同 pattern。
- **收录确认式回复 = 先问再答**(第三轮 #7):发消息前置确定性快检(附件文件名 vs 本人 gen 开项目硬规则,TTL 15s 规则缓存)→ 命中**不调 LLM**,秒回模板「已被 XX 项目收录,需要我回答吗?」+「需要回答/不用了」点选;点需要→服务端携存档原文走全量流式回复(直调拆出的生成方法,天然跳快检防死循环);点不用→收尾消息。开关 `rag.memory.inclusion-confirm.enabled` 热关回旧行为,异常 fail-open 不阻塞聊天。
- **跨项目共享 = 授权链**:[memory_project_links](#9-memory_project_links--跨项目授权链) 记「A 项目授权 B 项目读我的条目」,发起→对方 owner 审批→ACTIVE,召回时 child 条目单级一跳并入并标「来自授权项目·X」。**非对称撤销**(V85/V86):child(授权方)撤需 parent owner 审批,parent(被授权方)撤即时生效。
- **项目↔个人授权 = 只读召回**:[memory_project_user_grants](#10-memory_project_user_grants--项目个人只读授权) 记「用户 X 可召回项目 Y 的条目/共享总结」,双向发起+审批制,只读不写。
- **项目公共池**:[projects.memory_pool_public](#12-projectsmemory_pool_public--项目公共池开关) toggle 后项目进全站公共池,任何用户可申请加入,owner 审批。
- **文件记忆 = 第二来源**:[memory_asset_memories](#11-memory_asset_memories--memory_asset_chunks--文件记忆) 把上传文件蒸馏成记忆+分块,异步 ingestion READY 后进入召回②标签聚合(三路 UNION 第三路),与对话记忆合流。
- **召回 = 翻账本前先查目录**:不是全灌,先聚合 scope 内便签(三路:turns+summaries+文件记忆)→AI 选相关便签→优先读自己的结账→没被结账覆盖的才翻原文→①.5 项目条目/授权链合流→按主体打包塞进提示词。

## 表注解(建表用 Flyway,二期 V71–V127;V75 起含 P4 共享总结/V79 授权/V80 方向/V82 公共池/V83 硬规则/V100 配对列/三轮 V125–V127)

### 1. memory_tags — 标签库
**用途**:写时归一主体,`subject:topic` + `label` + `aliases` + anchor 三列。**禁手动归并/拆分/重抽**(误并不可逆)。
- `subject`(默认「我」)/ `topic`(居住/爱好…) = L0 主体:主题;`label` 对外展示名;`aliases[]` 同义别名(归一滚进,对外不露)。
- `anchor_embedding halfvec(2048)` 语义粗筛 + `anchor_tokens_tsv tsvector` BM25 词法(召回选标签用)。
- `usage_count` 归一命中自增。`UNIQUE NULLS NOT DISTINCT(user_id,subject,topic)` 写时归一兜底;V78 partial 索引 `WHERE deleted=0` 根治软删撞 UNIQUE。
- **关联**:`user_id→users`;被 `memory_turns.tag_ids`/`memory_summaries.tag_id`/`memory_conflicts.tag_id`/`memory_asset_memories.tag_ids` 引用。

### 2. memory_turns — 流水账(个人域主体)
**用途**:一轮对话 INPUT/OUTPUT 各一条,记忆主体。**恒个人域**(二期 V72 删一期四列)。
- `direction`(INPUT/OUTPUT);`tag_ids[]`=L0;`l1_summary`/`l2_detail`=L1/L2;`raw_content` 原文(gen 关态写,90 天 TTL 按 `gen_done=false AND age>90d`);`gen_done` 是否跑过生成 LLM(false=仅 raw 不参与召回聚合也不兜底)。
- **【二期已废】**一期 `project_ids[]`/`born_personal`/`departed_project_ids[]`/`deleted_project_ids[]` 四列 V72 DROP——turns 恒个人域,无写入目标参数,无项目挂载,无离职交接列。项目维度内容改走 entry 收录管线。
- **关联**:`user_id→users`(作者);`tag_ids→memory_tags`。被 `memory_summary_coverage.turn_id`/`memory_project_entries.source_turn_id`+`source_turn_input_id` 引用。

### 3. memory_summaries — 总结提炼层(共享化)
**用途**:周期/手动压缩流水账/项目条目得精华条。**二期共享化**(V75):加 `scope_owner` + `source_entry_ids[]`。
- `l1_summary`/`l2_detail`;`source_summary_id` 链式(防膨胀再压缩溯源);`source_turn_ids[]` flat provenance(`@> [T]` 查受影响 summary);`status` CLEAN/PENDING_CONFLICT/STALE;`summarized_at` 12h 规则基准。
- `direction` INPUT/OUTPUT/BOTH(V80):个人总结显方向 radio,项目总结按 entry 方向归类(5x #4)。
- `scope_owner` PERSONAL/PROJECT(V75):个人总结 project_id IS NULL AND user_id=self;项目共享总结 scope_owner=PROJECT + source_entry_ids[] 指向 entry。
- **关联**:`user_id→users`(作者,召回只读自己);`project_id→projects`(单值,NULL=个人);`tag_id→memory_tags`;`source_entry_ids[]→memory_project_entries`(无 FK,app 管)。项目删软删项目总结,个人(NULL)不清。

### 4. memory_summary_coverage — 覆盖表(allCovered 判定依据)
**用途**:记某作者某 turn 某 tag 某 scope 被其总结吃进。**召回只认 `user_id=召回者自己` 的行**(防污染)。
- `UNIQUE NULLS NOT DISTINCT(turn_id,tag_id,project_id,user_id)`(PG 默认 NULL≠NULL,个人 scope project_id=NULL 约束会失效,须 NULLS NOT DISTINCT)。
- 无 `deleted` 列,随 summary/turn 清。**关联**:`turn_id→memory_turns`/`tag_id→memory_tags`/`summary_id→memory_summaries`/`user_id→users`。

### 5. memory_project_members — 记忆专属成员
**用途**:角色 + ACTIVE/DEPARTED。**独立于 Agent 模块 `project_members`(旧表不动)**。
- `role` OWNER/ADMIN/MEMBER;`status` ACTIVE/DEPARTED;`departed_at` 离职时间。
- 无 `deleted`,离职置 DEPARTED 不删行。`UNIQUE(project_id,user_id)`(re-add 软删复活)。
- **二期语义**:DEPARTED = **直接失条目读权**(不再有召回标注/交接概念)。

### 6/7. memory_project_settings / memory_project_user_settings — gen 开关
**用途**:owner 项目级 gen / 会员个人覆写 gen。**二者 AND 方可生成**(默认开)。
- 无 `deleted`,项目删 CASCADE 清。会员本人自控覆写。非项目会话读全局兜底 `rag.memory.gen.personal.enabled`。

### 8. memory_project_entries — 项目记忆条目(二期可读单元,V71)
**用途**:项目可读单元。收录规则粗筛 → LLM 精判 → 蒸馏落库 → owner 审核。
- `project_id`/`source_turn_id`(OUTPUT turn)/`source_turn_input_id`(INPUT 配对 turn,V100 建链+三轮 V125 存量回填)/`direction` INPUT/OUTPUT/BOTH(V126,三轮 #4:成对轮 BOTH/纯输出 OUTPUT/纯输入 INPUT/文件恒 BOTH;项目总结按方向取数)/`tag_ids[]`/`l1_summary`/`l2_detail`。
- `status` ACTIVE(置信度≥0.8 直接收录或审核通过)/PENDING_REVIEW(灰区待裁决);审核「弃」= 软删(deleted=1),作者撤回走 DELETE 端点同软删。ACTIVE 条目成员即可读,DEPARTED 失读权。
- owner/admin review(approve→ACTIVE/reject→软删)。`findProjectIndexByTurnIds` 双路 UNION(source_turn_id OR source_turn_input_id)反查收录项目——流水账 INPUT/OUTPUT 卡片都能显「收录于:项目X」。
- **关联**:`project_id→projects`;`source_turn_id`/`source_turn_input_id→memory_turns`;`tag_ids→memory_tags`。被 `memory_entry_coverage.entry_id`/`memory_summaries.source_entry_ids[]` 引用。

### 9. memory_project_links — 跨项目授权链(V73/V85/V86)
**用途**:跨项目共享条目。parent(授权方)→child(被授权方)单向,发起→对方 owner 审批→ACTIVE。
- `parent_project_id`/`child_project_id`/`status` PENDING/APPROVED/ACTIVE/REVOKED/REJECTED/WITHDRAWN;`revoke_requested_by`(V85 非对称撤销)。
- 召回时 ACTIVE 链 child 条目单级一跳并入(降级仅成员),装配标「来自授权项目·X」;链断即停。
- **非对称撤销**(V85):child(授权方)撤→status 维持 ACTIVE+revoke_requested_by 记录→待 parent owner 审批(approve-revoke/reject-revoke/withdraw-revoke 端点);parent(被授权方)撤→即时 REVOKED+通知 child(不需审核)。
- 通知类型 LINK_REQUEST/LINK_RESULT/LINK_REVOKE_REQUEST/LINK_REVOKE_RESULT 须在 memory_notifications CHECK 迁移(V86)。
- **关联**:`parent_project_id`/`child_project_id→projects`。召回侧 `findActiveChildIds` 判 `projects.deleted=0` 双保险(5x #5)。

### 10. memory_project_user_grants — 项目↔个人只读授权(V79)
**用途**:用户 X 可召回项目 Y 的条目/共享总结。双向发起+审批制,只读不写。
- `project_id`/`user_id`/`status` PENDING/APPROVED/ACTIVE/REVOKED/REJECTED;`granted_by`。
- grant ACTIVE 即生效:召回 scope ∪ grant 项目;读门控 `canReadProjectShared` 第 3 分支通过;被授权方下拉 ∪ 公共池。revoke 即时断 live 查询。
- `notify` 触发 CHECK 须含 GRANT_REQUEST/GRANT_RESULT/V81 迁移(同 V86 坑)。
- **关联**:`project_id→projects`;`user_id→users`。召回侧 `findActiveGrantedProjectIds` 判 `projects.deleted=0` 双保险(5x #5)。

### 11. memory_asset_memories / memory_asset_chunks — 文件记忆(V74)
**用途**:上传文件蒸馏成记忆 + 分块。异步 ingestion,READY 后进召回。
- `memory_asset_memories`:`user_id`/`file_id`/`tag_ids[]`/`l1_summary`/`ingest_status` PROCESSING/READY/FAILED/`retry_count`(卡 3)。
- `memory_asset_chunks`:分块向量+原文,检索命中后注入。
- 召回②`findPersonalRecallTags` 第三路 UNION:`SELECT unnest(tag_ids) FROM memory_asset_memories WHERE user_id=#{userId} AND ingest_status='READY' AND deleted=0 AND tag_ids IS NOT NULL`(5x #3)→文件标签进候选→⑥.5 门控→`findReadyByTagOverlap`(`tag_ids && selectedTagIds`)→ collectFileCards→ 🗂文件卡片。
- tag 归一复用 `tagResolver.resolve`,与个人 tags 库同源(防文件标签与对话标签语义不重叠导致 && 空命中)。
- **关联**:`user_id→users`;`file_id→files`;`tag_ids→memory_tags`。

### 12. projects.memory_pool_public — 项目公共池开关(V82)
**用途**:toggle 后项目进全站公共池。
- `memory_pool_public` boolean。owner toggle;任何用户可 `applyByUser` 申请加入,owner 审批。
- 公共池项目在被授权方下拉 ∪(`grantParentOptions` + `listPoolProjects`);ACTIVE grant 后只读可见总结。
- 项目↔项目 link 纳入公共池 + 被授权方只读可见共享总结(G1/G2/G3):link ACTIVE 即生效读/召回,revoke 即时断 live 查询。

### 13. memory_entry_coverage — 项目条目覆盖(V75)
**用途**:记某项目条目某 tag 被其项目共享总结吃进。
- `entry_id`/`tag_id`/`summary_id`/`project_id`。
- 项目删除时须在 entries 硬删**之前**清(反查 entry_id 集合→清 coverage→再删 entries,5x #5 删除顺序修正)。
- **关联**:`entry_id→memory_project_entries`/`tag_id→memory_tags`/`summary_id→memory_summaries`。

### 14. memory_consolidation_scopes — 自动总结 scope 勾选
**用途**:用户勾哪些 scope 自动总结。默认插 PERSONAL(新用户 trigger)。
- `scope_kind` PERSONAL/PROJECT;`project_id`(NULL=个人);`auto_enabled`;`locked_until`/`last_run_at`(worker SKIP LOCKED 任务锁)。
- `UNIQUE NULLS NOT DISTINCT(user_id,scope_kind,project_id)`。项目默认不勾,用户主动加。

### 15. memory_notifications — 跨用户波及通知
**用途**:跨用户波及 + 授权链发起/结果。
- `type` CHECK 含 SUMMARY_AFFECTED_BY_RECALL / LINK_REQUEST / LINK_RESULT / LINK_REVOKE_REQUEST / LINK_REVOKE_RESULT / GRANT_REQUEST / GRANT_RESULT(V81/V86 迁移)。
- 【二期已废】一期 `PROJECT_DELETED_AFFECTED` 随 V72 消亡(turns 个人域化后项目删除不再波及 turns/发通知)。
- `resolved_at` worker 重生后回填(不追加新行避 badge 抖动)。

### 16. memory_conflicts(扩列)
**用途**:新模型冲突**只来自总结层时序互斥**(非跨用户编辑),无 type 列。
- `tag_id`+`summary_id`;裁决四选项 KEEP_BOTH/NEW/OLD/DISCARD。DISCARD 连带软删 source turns(防 worker 再生成同冲突死循环),12h 规则适用。

### 【二期已废】memory_recall_acl(V72 DROP)
一期 reader→target 授权读项目流水账表 + `readableAuthors` 五路径 ACL 模型,随 turns 个人域化整体废弃。**当前态无此表无此服务无此端点**。

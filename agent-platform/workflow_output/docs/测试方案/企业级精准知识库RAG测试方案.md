# 企业级精准知识库 RAG 人工测试方案

> Phase 3 开工基准。自动化测试覆盖确定性逻辑；本文件只保留需要浏览器、真实 OpenSearch 或人工判断的场景。

## 前置条件

- PostgreSQL、Redis、OpenSearch、后端和前端均启动。
- 管理员已配置可用的 Chat/Embedding 模型；Rerank 模型可暂不配置。
- 准备普通用户 A/B、两个权限不同的知识库，以及包含版本、条款、Excel、PDF 的样本文档。

## 核心用例

1. **模型选择与错误提示**：KB 选择 LLM 重排后发送检索；禁用该模型再次检索。前者时间线显示实际模型，后者明确报错且不切换其他模型。
2. **多证据覆盖**：提问需要 5～10 条制度内容的问题。答案覆盖所有主题，每条事实可点击到原文位置；缺项时显示补检索轮次。
3. **版本冲突**：同时准备有效新旧制度或冲突版本。默认使用当前有效版本；冲突时明确说明，不静默拼接。
4. **权限零泄漏**：用户 A 可读、用户 B 不可读。B 的候选、重排、回答、引用、缓存和调试面板均不得出现受限内容。
5. **影子与灰度**：开启 5%/20% 灰度并反复使用同一用户。该用户稳定落在同一 Pipeline；回滚后立即恢复旧链路。
6. **OpenSearch 故障**：分别中断 Dense/Sparse/OpenSearch。页面显示配置允许的降级和原因，不得静默降级。
7. **全链路追溯**：从检索详情跳转模型调用、费用、审计，并用 traceId 在 Java 日志定位同一次请求。

## 功能联动用例

| 触发动作 | 联动验证 | 边界 |
|---|---|---|
| 更新/撤销版本 | Chunk、索引、缓存和引用同步刷新 | 历史查询仍可选旧版；取消操作不改变状态 |
| 修改 Ranking 配置 | 下一请求、缓存 Key、时间线使用新配置版本 | 无模型明确报错；DISABLED 标记未语义重排 |
| 授权/撤权 | OpenSearch ACL、PG 复核、缓存同步变化 | 批量撤权；索引延迟时 PG 仍拒绝 |
| 切换 read alias | 灰度用户看到新结果，旧用户不变 | 回滚恢复旧 alias；失败切换不产生空窗 |
| 删除文档 | 搜索、引用、缓存、对象产物在 SLA 内消失 | 部分传播失败可重试并产生告警 |

## 通过标准

- 权限泄漏率为 0；模型不得硬编码或静默替换。
- Recall、引用、多证据覆盖和性能达到规格门槛。
- 任一结果可关联检索、重排、模型、费用、审计和 Java 日志。

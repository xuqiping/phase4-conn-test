# 网课录屏智能学习总结 · 功能规格（§三）

> 拆分自 [网课录屏智能总结.design.md](网课录屏智能总结.design.md)（5000 tokens 硬规则），本节为 §三 功能规格原文。

## 三、功能规格

### 3.1 功能清单（MoSCoW · 知识库 D-02）

| 桶 | 功能 |
|---|---|
| **Must**（MVP） | 窗口捕获录屏；本地实时转写（加时间戳改造）；分轨落盘（视频切片+音频+transcript.jsonl）；录后精细抽帧去重；课件 OCR；音字帧对齐；云端总结（map-reduce·要点+时间轴章节）；Markdown 导出；API Key 设置；容错（草稿态/重新生成/降级） |
| **Should** | 区域框选录屏；思维导图（markmap）；Anki `.apkg` 导出；多模态精修开关；总结局部编辑；跳转回放；多 provider API |
| **Could** | 重点标记/复习；跨课程知识库检索；视频切片管理 |
| **Won't**（本版不做） | 实时直播；多人协作；云端同步；本地 LLM 总结；录制时实时抽帧总结 |

### 3.2 技术栈选型定稿

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | 复用 Tauri 2 + Rust + Vue 3 | 现有 |
| 录屏 | **windows-capture**（WGC·FreeThreaded） | 调研首选；窗口原生、区域 D3D11 crop；参考 [Cap](https://github.com/CapSoftware/Cap) |
| 系统音频 | 复用 cpal / WASAPI loopback | 已实现 |
| 视频编码 | NVENC/AMF 硬件 H.264（软编兜底） | 分轨落盘 |
| 智能抽帧 | **纯 Rust**：SAD 预筛 → 降采样直方图(BHATTACHARYYA)判页 → pHash 去重(汉明>8) | 无 ffmpeg 依赖、包体小、PPT 翻页稳 |
| 课件 OCR | RapidOCR / PaddleOCR-lite（本地） | 帧转文字喂 LLM，省 token |
| 转写 | 复用 sherpa-onnx（**加句级时间戳**） | 已实现 |
| 时间对齐 | QueryPerformanceCounter 墙钟 PTS + 分轨落盘后处理 | 抗三路时钟漂移 |
| AI 总结 | 云端 API（用户自带 Key，多 provider） | D1 |
| 输出 | markmap + Anki `.apkg` + Markdown + 自绘时间轴 | D4 |

### 3.3 端到端数据流（三阶段）

```
【阶段1·录制中（实时·轻量）】
屏幕(WGC) ──硬编H.264──► video_NNN.h264 (每15min切片，带墙钟PTS)
   └─轻量实时抽帧(SAD预筛)─► 变化帧缩略图+ts 入库（不阻塞录制）
系统音频(loopback) ─► audio.wav ─► sherpa流式转写 ─► transcript.jsonl
                                       └─► 实时推前端字幕（复用 emit "transcription"）
   ⏱ 三路共用同一墙钟零点 t0

【阶段2·录后处理（异步·本地·可取消）】
精细抽帧去重(直方图+pHash) ──► 课件页序列 frames[]
课件OCR ─────────────────► 每页 ocr_text
时间轴对齐(排序归并) ──────► aligned_units[]

【阶段3·AI总结（异步·云端·可取消）】
分段 map-reduce ──► 段落要点（每条带时间戳引用）
全局合并 ──────► 大纲/全局总结
多形态渲染(本地) ──► 时间轴章节 / markmap / Anki / Markdown
```

> 设计原则：录制阶段只做轻量活（硬编落盘 + 实时转写 + SAD 预筛），确保 2h 录制稳定不丢帧；重活全放录后异步。

### 3.4 时间戳对齐机制（工程核心）

**现状问题**：现有 [recognizer.rs](../../../src-tauri/src/stt/recognizer.rs) 的 `RecognitionResult` 和 [capture.rs](../../../src-tauri/src/audio/capture.rs) 的 `AudioFrame` **均无时间戳**，无法对齐。

**改造方案**：

1. **统一零点**：录制开始时记 `t0 = QueryPerformanceCounter`（高性能单调墙钟）。
2. **音频帧**：`AudioFrame` 增加 `capture_ts: i64`（毫秒，= now − t0）。
3. **转写句**：recognizer 维护「已处理采样计数 `samples_processed`」；每个 endpoint 触发时，记录句首/句尾采样序号，按 `序号 / sample_rate` 换算时间。改造后结构：
   ```rust
   pub struct RecognitionResult {
       pub text: String,
       pub is_final: bool,
       pub partial: String,
       pub start_ms: i64,   // 新增：句首相对 t0
       pub end_ms: i64,     // 新增：句尾相对 t0
   }
   ```
4. **课件帧**：抽帧时刻打 `frame_ts = now − t0`。
5. **视/音频 PTS**：编码时同一 `t0` 基准打 PTS。

**对齐算法**（排序归并，O(n+m)，2h 数据毫秒级）：

```
输入：transcript 句 [start_ms, end_ms, text]  +  frames [frame_ts, image, ocr_text]
处理：按 frame_ts 落入 [start_ms, end_ms] 区间做归并 join
输出：aligned_unit = { frame_ts, 课件帧图, ocr_text, 时间段[start,end], 该段讲解文字[] }
```

**降级矩阵**（知识库·多模态时序对齐清单要求）：

| 缺失模态 | 降级处理 |
|---|---|
| 抽帧无变化帧 | 退化为按 5min 固定窗分段 |
| OCR 失败 | 课件页只存图，总结仅用转写文本 |
| 转写某段缺失 | 该课件页标注「无讲解文字」 |

### 3.5 智能抽帧策略

- **录制时**：SAD（帧差绝对和）预筛，仅存"变化帧"缩略图 + 时间戳，不阻塞录制线程。
- **录后**：对完整视频精细抽帧：
  - **判页**：降采样直方图 BHATTACHARYYA 距离 + pHash 双判（汉明距离 > 8 视为新课件页）
  - **去抖**：2–3 秒内多次变化合并为一次翻页（应对白板书写/动画）
  - **去重**：pHash 汉明距离 ≤ 8 视为同一页
- **课件页序列**：`frames[] = { frame_ts, path(原图), thumb_path(缩略图), ocr_text? }`

### 3.6 AI 总结 pipeline（云端 · map-reduce）

**为什么必须分段**：2h 课程转写+OCR 文本约 3–5 万字，整段直灌超上下文 + 成本爆炸。

```
分段(map, 可并行): 每个 aligned_unit → { ocr_text, 讲解文本, 时间段 }
                   → 云端 LLM（默认纯文本）→ 段落要点（每条带 [时间戳] 引用）
                                     │
全局合并(reduce):  所有段落要点 → 云端 LLM → 课程大纲/全局总结/导图骨架
                                     │
多形态渲染(本地):  结构化要点 → 时间轴章节 / markmap / Anki / Markdown
```

- **分段优先级**：课件页切换点（自然语义边界）> 5min 固定窗兜底。
- **单段上限**：每段输入 ≤ 2000 字，超长再切。
- **成本控制**：默认只送「OCR 文本 + 讲解文本」；Prompt Caching（系统提示词放开头）；分段并行。
- **多模态精修开关（D5，默认关）**：开启后，分段时附带该段课件帧图片（JPEG q80、降采样至 ~1024px、base64）一并发送给 VLM；开启时前端二次确认「将上传课件图片到 {{provider}}」。
- **Provider 策略**：MVP 默认实现 **OpenAI 兼容接口**（`/v1/chat/completions` 协议），用户填 Base URL + API Key + 模型名即可接入 OpenAI / 通义千问兼容端 / DeepSeek / 智谱等绝大多数服务商；多 provider 切换管理放 Should。模型名需区分「文本模型」（默认总结）与「视觉模型」（精修开关开启时用），两者均由用户在设置里填。

**容错四件套**（知识库 D-19·AI 不确定性应对，必做）：

| 维度 | 落地 |
|---|---|
| 可解释 | 每条要点带 `[时间戳]` + 课件帧缩略图回链，点击跳转视频核对 |
| 可纠错 | 支持「重新生成」（单段/全局）+ 要点局部编辑 |
| 可撤销 | 总结以**草稿态**呈现（`summary_draft.json`），确认后落库，保留版本历史 |
| 可降级 | 云端 API 失败 → 保留转写 + 课件帧 + 本地要点兜底，提示「网络不可用，已为您保留全部文本」 |

### 3.7 输出形态

| 形态 | 渲染来源 | 阶段 |
|---|---|---|
| 时间轴章节 + 要点 + 课件帧 | 段落要点按时间排列，挂课件帧缩略图，点击跳转 | Must |
| Markdown 笔记 | 结构化导出（章节/要点/时间戳） | Must |
| 思维导图 | 要点 → markmap markdown → 前端渲染 | Should |
| Anki 卡片 | 要点 → 正反面 → `.apkg` 导出 | Should |

### 3.8 状态机（命门：长时操作状态可见、可取消）

```
空闲 → 选源(窗口/区域) → 录制中 → 处理中 → 完成
                                (转写完成→抽帧→OCR→对齐→总结)
  ↑_____________________________________________________|
                    可重新处理 / 重新总结 / 多模态精修

异常分支：录制中断 / 磁盘满 / OCR失败 / API失败 / 转写缺失 → 友好提示 + 重试
```

每个状态有可见标识；每次操作 300ms 内可感知反馈；长时操作可取消；空/失败状态有提示页。

### 3.9 三区信息架构 + 学习区界面

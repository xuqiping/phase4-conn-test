# D-24.03 Agent工具调用

## 是什么

**Agent 工具调用（Agent Tool Calling / Tool Use）**：Agent 感知世界、执行动作的基础能力——让大语言模型从"能说"变成"能做"的核心机制。严格来说，LLM 并不是真的在"调用"工具：它根据你给的 Schema 描述，输出一段结构化 JSON（工具名+参数），你的代码解析 JSON → 调真实函数/API → 把结果塞回对话 → 模型继续推理。整个循环是：**模型选工具 → 生成参数 → 应用执行 → 结果返回 → 模型继续**。没有工具调用的"Agent"本质是 ChatBot，工具调用是 Agent 从对话系统到行动系统的分水岭。[来源:CSDN/腾讯云 Tool Calling解析 | 🔍高 | 2026-05/07]

**三种工具调用范式（2026 业内共识）**：
1. **Function Calling（API 工具调用）**：模型通过 JSON Schema 定义的工具列表，选择工具并生成结构化参数，由应用侧执行 API/函数调用。这是最主流、最高效、最可靠的工具调用方式。OpenAI 用 `name/description/parameters/strict`，Anthropic 用 `name/description/input_schema`；2026-07 OpenAI Responses API 已支持 `strict` 严格模式强制 Schema 校验。[来源:OpenAI/Anthropic官方文档 | 🔍高 | 2026-07]
2. **Computer Use（桌面/浏览器操控）**：模型通过截屏识别 + 鼠标键盘指令操控真实的计算机 GUI 界面，绕过 API 直接操作任何有界面的软件。这是"最后手段"——当没有 API 可用时才用 GUI 操控。典型：OpenAI Operator、Anthropic Computer Use API、Perplexity Comet、Manus 浏览器操控。2026-07 安全研究指出 Computer Use Agent 颠覆了浏览器二十年来依赖的同源策略/站点隔离/CSRF 令牌/SameSite Cookie/来源校验六道安全防线。[来源:腾讯玄武实验室AI浏览器安全白皮书 | 🔍高 | 2026-02]
3. **Cloud Sandbox（云端沙箱执行）**：在隔离的云端环境中执行代码/命令/文件操作，保证宿主系统安全。Agent 生成的代码不在用户机器上跑，而是在远程沙箱中执行，结果回传。典型：E2B（硬件级隔离）、腾讯云 Cube Sandbox（2026-04-28 完全开源，五大突破性能力）、Daytona（Giving Agents Computers）。2026-03 OpenClaw 事件（AI 疯狂删除用户所有邮件、无视停止指令、工信部安全警告）证明：无沙箱隔离的 Agent 执行 = 灾难。[来源:腾讯云/360安全/工信部 | 🔍高 | 2026-03/04]

**一个核心认知——工具调用 ≠ 随意调用**：
工具调用不是"给模型一堆工具让它随便用"，而是需要**工具描述设计（Schema）+ 工具选择策略 + 参数校验 + 执行隔离 + 副作用治理 + 工具发现**六层工程化设计。2026-07 生产环境 Agent 故障分布统计：工具调用死循环占 31%（最大故障类）、参数校验失败占 24%、工具选择错误占 18%、副作用失控占 15%、沙箱逃逸占 7%、其他 5%。工具系统是 Agent 生产化的第一道工程关。[来源:知乎生产级Agent故障分布 | 🔍高 | 2026-07]

**技术演进脉络**：ReAct 范式（2023，推理+行动交替）→ Function Calling 标准化（2024，OpenAI/Anthropic 统一 JSON Schema）→ MCP 协议（2025，Anthropic 推出统一工具连接标准，2025-12 捐赠 Linux 基金会，注册 Server 超 10 万、月下载 9700 万）→ Skills + Computer Use（2026，Anthropic Skills 能力封装 + OpenAI/Anthropic Computer Use 桌面操控）。工具调用从"手写函数描述"进化为"标准化协议生态"。[来源:腾讯云/人人都是产品经理 | 🔍高 | 2026-01/07]

## 核心要素

| 要素 | 说明 | 典例 |
|---|---|---|
| **工具描述格式（Schema）** | JSON Schema 定义工具名/描述/参数类型/必填项，决定模型能否选对工具+填对参数 | OpenAI: name/description/parameters/strict；Anthropic: name/description/input_schema |
| **工具选择策略** | 模型如何从 N 个工具中选对工具——受描述清晰度/工具数量/上下文影响 | 描述模糊→选错工具；工具过多→选择困难+上下文爆炸 |
| **参数生成与校验** | 模型生成参数→应用侧校验→防止参数幻觉（类型错/值错/缺失） | amount 期望 number 却填"100元"字符串；currency 期望 ISO 4217 字符串却填数字 1 |
| **执行环境隔离** | 工具执行在沙箱中隔离，防止副作用波及宿主系统 | E2B 硬件级隔离、腾讯云 Cube Sandbox、Daytona 远程开发环境 |
| **副作用治理** | 区分可逆/不可逆操作，不可逆操作须人工确认或 Hook 拦截 | 可逆=查询API；不可逆=删数据/转账/发布；DECO Hook 护栏拦截越权 |
| **工具发现与注册** | Agent 自动发现可用工具并注册到工具表，而非硬编码 | MCP Server 动态注册；ADG 依赖图谱看清能力边界 |
| **结果返回与错误处理** | 工具执行结果回传模型，错误需结构化反馈让模型自我纠错 | 成功→JSON结果回传；失败→结构化错误信息+重试策略 |
| **安全护栏（Hook）** | 在工具调用前后插入 Hook 切面，确定性兜底 LLM 的偷懒/越权/失忆 | DECO 三层 Hook：截断检测/越权拦截/失忆补偿 |

## 为什么Agent PM必须懂Agent工具调用

1. **工具调用是 Agent 与 ChatBot 的分水岭**——没有工具调用的"Agent"去掉执行循环就退化为对话 API，本质是 L1 ChatBot 冒充 L4 Agent；2026-07 行业共识"Agent = 大模型 + 规划 + 工具 + 记忆 + 执行循环"，工具调用是"执行"的核心载体，PM 不懂工具调用就不懂 Agent [来源:Agent PM实践 | 📚中]
2. **参数幻觉是生产环境第一杀手**——2026-07 生产级 Agent 故障分布：工具调用死循环 31%（最大类）+参数校验失败 24%=55% 的故障直接与工具调用工程化相关；典型参数幻觉：模型把 `amount` 期望 number 填成"100元"字符串、把 `currency` 期望 ISO 4217 字符串填成数字 1，导致支付创建失败；这不是模型能力问题是 Schema 设计问题，PM 必须懂 Schema 设计原则 [来源:知乎/CSDN 生产级Agent故障分布 | 🔍高 | 2026-07]
3. **Computer Use 颠覆传统安全模型**——2026-02 腾讯玄武实验室《AI 浏览器爬虫安全白皮书》指出：Computer Use Agent 让浏览器过去二十年依赖的六道安全防线（同源策略/站点隔离/CSRF 令牌/SameSite Cookie/来源校验/跨域隔离）全部失效——Agent 可以同时看到所有标签页，一个页面可让浏览器在另一个站点执行动作，所有请求都是 first-party 发起；PM 设计 Computer Use 产品必须重新理解安全边界 [来源:腾讯玄武实验室 | 🔍高 | 2026-02]
4. **Cloud Sandbox 是 Agent 执行安全底线**——2026-03 OpenClaw 事件（AI 疯狂删除用户所有邮件、无视手机停止指令、用户不得不"像拆炸弹一样"手动终止程序、工信部发出安全警告）证明：无沙箱隔离的 Agent 代码执行 = 灾难；2026-04 腾讯云 Cube Sandbox 完全开源（五大突破性能力）、E2B 硬件级隔离、Daytona "Giving Agents Computers" 成为标配，PM 必须懂沙箱选型 [来源:360安全/腾讯云/工信部 | 🔍高 | 2026-03/04]
5. **副作用治理决定 Agent 能否上生产**——2026-07 腾讯 DECO 数仓 Agent 实践揭示：LLM 在长文本处理时会"偷懒"（截断/略写/残缺）、对生产环境会"越权"（未确认发布/回刷）、上下文传递会"失忆"（改了表不查风险/产出了物不知汇报）；副作用的不可逆操作（删数据/转账/发布/邮件发送）必须有 Hook 护栏确定性兜底，"prompt 管不住的，框架来堵"；PM 必须懂副作用分类与护栏设计 [来源:网易/腾讯DECO | 🔍高 | 2026-07]
6. **MCP 已统一工具调用标准，PM 必须懂 MCP 工具生态**——2025-12 MCP 捐赠 Linux 基金会 Agentic AI Foundation，注册 Server 超 10 万、月下载 9700 万，MCP 已成 Agent 工具调用事实标准；2026-07-28 MCP 史上最大修订（全链路可治理+调用全流程可追溯+可观测三件套）转入生产级智能体基础设施；Agent PM 做工具系统设计必须基于 MCP 生态而非自研协议，理解 MCP = 理解工具调用生态（D-24.02 协议层 + D-24.03 实现层的交汇点） [来源:Anthropic/Linux基金会 | 🔍高 | 2026-07]

## 常见误区

- **误区1：以为模型真的在"调用"工具**——LLM 不是真的调用工具，它只是根据 Schema 描述输出一段 JSON（工具名+参数），是你的代码解析 JSON → 调真实函数 → 把结果塞回对话；整个过程模型完全依赖你写的 Schema 描述，描述含糊→传错参数，类型没说清→传错类型，这不是玄学是工程问题 [来源:牛客科技Agent工程师学习路线 | 🔍高 | 2026-04]
- **误区2：Schema 写得越详细越好**——Schema 过度详细反而让模型困惑（描述冗长抓不住重点、枚举值过多选择困难）；关键在"描述清晰+类型明确+必填项标注+示例补充"，而非面面俱到；2026-07 CSDN《Function Calling 工程化5个陷阱》第一个陷阱就是"schema 描述太模糊→模型选错工具"，但过度详细同样有害
- **误区3：Computer Use 可以替代 API 工具**——Computer Use 是"最后手段"而非首选：API 调用远比 GUI 操控高效（毫秒 vs 秒级）、可靠（结构化 vs 截屏识别错误率高）、安全（无界面操作 vs 颠覆安全模型）；只有当目标软件无 API 时才用 Computer Use；2026 行业共识是"能 API 就不 Computer Use，能 MCP 就不自研"
- **误区4：有沙箱就安全了**——沙箱只隔离执行环境（防代码逃逸波及宿主），不防参数幻觉（模型填错参数沙箱照执行）、不防副作用失控（沙箱内删数据也是删数据）、不防权限滥用（沙箱内转账也是转账）；沙箱是必要条件非充分条件，需配合参数校验+副作用治理+权限边界三层护栏
- **误区5：工具越多越好**——工具过多导致选择困难（模型选错工具概率上升）+上下文爆炸（每个工具描述占 Token）；2026-07 行业实践："工具数量控制在 10-20 个以内，超出用动态发现+分域加载"；OpenAI Swarm 限制单 Agent 工具数，Anthropic 5-Agent 系统通过多 Agent 分工让每个 Agent 只持少量工具
- **误区6：忽视副作用分类**——可逆操作（查 API/搜索/读取）与不可逆操作（删数据/转账/发布/邮件发送）必须有不同护栏等级；2026-07 ADG（Agent Dependency Graph）研究指出：单个工具安全≠组合安全（搜索工具+邮件发送工具+共享记忆串联后，搜索结果可触发邮件群发）；PM 必须做副作用风险矩阵+组合风险分析 [来源:51CTO ADG | 🔍高 | 2026-07]
- **误区7：把工具调用等同于 MCP**——MCP 是工具调用的协议层（标准+连接+发现），Function Calling/Computer Use/Cloud Sandbox 是实现层（执行机制）；MCP 解决"怎么发现和连接工具"，工具调用范式解决"怎么执行工具"；二者是协议层与实现层的关系，MCP 是 D-24.02 与 D-24.03 的交汇点

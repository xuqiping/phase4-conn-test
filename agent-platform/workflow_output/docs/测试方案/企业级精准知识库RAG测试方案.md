# 企业级精准知识库 RAG 测试方案

> 本文件是 Phase 4 的人工验收基准；Phase 3 仅产出，不在本轮执行浏览器验收。

## 前置条件

- 管理员、普通用户各一个；至少两个租户/知识库用于越权验证。
- OpenSearch 可用，准备 Champion 与 Challenger 两套 Pipeline、黄金数据集和可回滚快照。
- 管理员已显式配置 Query/Ranking LLM；未配置专用 Rerank 时选择 RERANK 必须失败关闭。

## 核心用例

1. 上传版本化文档并激活：旧版本保留，新版本进入解析、分块、双写；引用可回原页/条款/单元格。
2. 多证据问题：问题涉及 5–10 条时返回动态证据集合；缺项触发有限补检索，且继承原 ACL/版本范围。
3. 权限反向：撤权或改密级后再次检索，OpenSearch 副本和答案缓存失效，旧内容不可见。
4. 模型选择：选择哪个知识库模型就调用哪个；无可用模型明确报错，不静态调用其他模型。
5. Rerank：LLM 与专用 Rerank 模式分别记录 trace；候选 ID 越界、重复、非法 JSON 被拒绝。
6. 评测联动：启动评测后显示异步状态；未达门禁时灰度按钮后端拒绝，不能靠前端字段绕过。
7. 灰度正向：5%→20%→50%→100% 依次应用，同一 KB/用户稳定落组。
8. 灰度反向：取消确认不切换；回滚恢复上一 Ranking 配置，若绑定索引快照则切回上一 read alias，并失效知识库答案缓存。
9. Shadow 对比：Champion 始终正常返回；采样 Challenger 超时、预算耗尽或失败只产生状态记录。管理员查询仅看到 Trace、版本、证据 ID、成本和短摘要，不得看到 Query/Prompt/Chunk 正文。
10. 反馈：选择固定分类提交后显示进入待审核队列；重复/负向反馈不能立即改变线上排序。
11. 移动端与键盘：知识库 Tabs、评测、索引运维、反馈表单可滚动、可聚焦、可提交。

## 安全与运维

- 跨租户/跨 KB/撤权竞态/旧版本/孤儿索引返回 0 泄漏。
- 日志抽查不得出现完整 Prompt、Query、Chunk、密钥、完整模型输出。
- Prometheus 标签不得出现 userId、traceId、KB 名；仅 stage/result/category/status 等有限枚举。
- 验证 Recall@20、nDCG@10、Citation、Coverage、Abstention 门槛；验证重排/覆盖/降级/删除 SLA 告警入口。

## 通过标准

- 自动化测试、后端编译、前端类型检查和构建全部 exit 0。
- 上述正向、反向、取消、越权、批量/多证据场景均符合预期；发现问题进入 Phase 4 缺陷记录，不在此文件伪造通过结论。

# 4.2 价格策略SOP与模板

## SOP-1：版本切分SOP

### 适用场景
新品从零设计价格体系、现有版本结构优化调整

### 步骤

| 步骤 | 动作 | 产出 | 负责人 |
|---|---|---|---|
| 1 | **功能盘点**：列出全部功能，按"核心体验/高频刚需/高频进阶/低频高级/合规安全/管理"分类 | 功能分类表 | PM |
| 2 | **确定档位数**：3档最优(除非产品极复杂最多4档) | 档位数决策 | PM + 商业化 |
| 3 | **走功能切分矩阵**：核心体验→Good / 高频刚需→Better / 合规安全+低频高级→Best | 功能分配矩阵 | PM |
| 4 | **定价区间设定**：Good低价/免费引流，Better中价主推，Best高价锚定 | 各档定价 | PM + 商业化 |
| 5 | **设计价格页**：走6设计原则(锚定/诱饵/默认/尾数/可视化/CTA) | 价格页设计稿 | PM + 设计 |
| 6 | **设定监控指标**：各档分布/升级率/降级率/转化率 | 指标看板 | PM + 数据 |
| 7 | **AB测试验证**：测试不同价格页/定价的转化率 | AB测试报告 | PM + 增长 |

## SOP-3：涨价方案SOP

### 适用场景
产品升级/成本上升/定位调整需涨价

### 步骤

| 步骤 | 动作 | 产出 | 负责人 |
|---|---|---|---|
| 1 | **涨价场景判断**：价值提升/成本上升/定位调整/新品不影响存量 | 场景判定 | PM + 商业化 |
| 2 | **涨价幅度测算**：基于价值提升程度而非行业均值，标"待核实" | 涨价幅度方案 | PM |
| 3 | **存量保护设计**：Grandfather原价N周期/渐进涨价/新客新价/以旧换新 | 存量保护方案 | PM + 商业化 |
| 4 | **通知方案**：提前30-90天+价值支撑+存量保护说明+替代方案+个性化沟通 | 通知方案+模板 | PM + CS |
| 5 | **流失率预案**：设定流失率阈值，超阈值启动挽留方案 | 流失预案 | PM + CS |
| 6 | **合规校验**：无虚假促销/无差别定价歧视/无默认勾选续费 | 合规自检 | PM + 法务 |
| 7 | **分批执行**：先小批试点→监控流失→全量推进 | 执行计划 | PM + 运营 |

## 模板-1：功能切分矩阵

```
| 功能名称 | 功能类别 | 放哪档 | 理由 | 备注 |
|---|---|---|---|---|
| [功能A] | 核心体验 | Good(免费) | 引流入口，让用户体验核心价值 | - |
| [功能B] | 高频刚需 | Better(主推) | 付费理由——用了离不开 | 付费触发墙 |
| [功能C] | 高频进阶 | Better | 团队增长后需要 | 自然升级触发 |
| [功能D] | 低频高级 | Best(锚定) | 大企业才需要 | 锚定效应 |
| [功能E] | 合规安全 | Best | SSO/SAML/审计/SLA | 企业级刚需 |
| [功能F] | 管理功能 | Better/Best | 中小→Better / 企业→Best | 分层差异 |

填写说明：
- 功能类别必须先分类再分配——先盘点全功能再决定各档放什么
- 核心体验功能放Good——让用户先体验价值再因"需要更多"而付费
- 合规安全功能锁Best——这是B端大客户的刚需锚定点
```

## 模板-2：用量计费设计表

```
| 设计要素 | 决策 | 说明 |
|---|---|---|
| 计量点 | □Token □API调用 □存储 □计算 □任务 □成果 | 选型理由：客户可感知+价值正相关+成本正相关 |
| 基础配额 | [X万Token/月 或 Y次调用/月] | 基础套餐含的用量 |
| 超额单价 | [Z元/万Token 或 W元/千次调用] | 阶梯递减或固定 |
| 配额重置 | □按月 □按年 | 按月最常见(对齐月费) |
| 配额结转 | □不结转 □结转1个月 | 通常不结转(促使用足) |
| 预算封顶 | [月度上限N元 或 N用量] | B端预算可控——超封顶停服务或通知升级 |
| 告警阈值 | 50% / 80% / 100% | 自动通知客户 |
| 承诺量折扣 | 承诺[X/月]→享[Y折] | AWS RI模式 |
| 熔断机制 | 异常飙升[>Z倍均值]→暂停 | 防误操作/恶意 |
| 防作弊 | 异常检测+幂等+成果校验 | 防刷量 |
| AI成本底线 | [推理成本约X元/万Token] | 须查官方现价，标"待核实" |
| 防亏校验 | 定价≥成本底线×[N倍] | 确保不亏本 |

填写说明：
- AI成本底线须查OpenAI/Anthropic官方现价，不编造
- 预算封顶是B端用量计费的关键——B端不接受预算不可预测
- 防亏校验：定价必须≥推理成本×安全倍数(建议2-3倍以上覆盖其他成本)
```

```
│ ✓ [核心B] │ ✓ [刚需C]  │ ✓ [高级E]  │
│ ✓ [限额]  │ ✓ [刚需D]  │ ✓ [高级F]  │
│ ✓ 社区支持 │ ✓ [限额]  │ ✓ 无限[量] │
│           │ ✓ 邮件支持 │ ✓ 专属CS   │
│           │           │ ✓ SLA保障  │
├──────────┼──────────┼──────────┤
│ [免费开始] │[最受欢迎★]│ [联系销售] │
└──────────┴──────────┴──────────┘

设计6原则检查：
□ 锚定效应：先展示高价企业版
□ 诱饵效应：基础版功能够用但有明显短板，企业版贵到不需要，专业版刚好
□ 默认选项：年付默认勾选(8折)
□ 尾数定价：¥99/¥299/¥599而非¥100/¥300/¥600
□ 功能可视化：✓/❌标记+数量限额明确
□ CTA差异化：免费开始/开始试用/联系销售
```

## 模板-5：续费方案模板

```
| 客户分层 | 当前版本 | 续费策略 | 激励方案 | 降级预案 |
|---|---|---|---|---|
| 高LTV大客户 | Enterprise | 提前续费+多年合约 | 3年6折+增购模块3个月免费 | N/A(不降级) |
| 中LTV企业 | Professional | 年付续费 | 8折+额外[培训/支持] | 挽留话术+过渡方案 |
| 低LTV中小 | Basic/Starter | 自助续费 | 年付8折自动提示 | 降级到免费版+流失归因 |

续费激励原则：
- 优先"加价值"(增购赠送/培训/支持)不"降价格"
- 多年合约折扣锁定LTV(2年7折/3年6折)
- 提前续费享额外优惠(提前30天续费+5%折扣)
- 降级挽留用价值回归话术(提醒失去的功能价值)

降级挽留话术模板：
"理解您考虑调整方案。提醒您当前[功能A/B]在调整后将无法使用——其中[功能A]每月帮您[具体价值]。如果预算有压力，我们可以讨论[年付折扣/分期/过渡方案]，让您不失去这些能力。"
```

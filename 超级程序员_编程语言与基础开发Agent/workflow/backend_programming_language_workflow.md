# Backend Programming Language Workflow

## Purpose

基于后端编程语言知识体系，为用户提供后端技术选型、学习路径规划、技术栈搭配或具体语言问题的深度解答。覆盖Java/Python/Go/C/C++/Rust/PHP/Node.js七大后端语言体系。

## Prerequisites

- 用户已明确后端场景或提出后端相关问题
- 知识库文件 `01_编程语言与核心技能.md` 及子目录文件可访问

## Steps

### Step 1: 识别用户后端需求场景

**Goal**: 明确用户的后端需求类型和约束条件
**Completion criterion**: 已确定场景标签和至少2项关键约束

1. 读取用户消息，提取以下信息：
   - 场景类型：技术选型 / 学习路径 / 问题排查 / 架构设计 / 团队技术栈规划
   - 目标语言（如用户已指定）：Java / Python / Go / C/C++ / Rust / PHP / Node.js
   - 应用类型：企业级系统 / AI/数据科学 / 云原生/微服务 / 系统级/高性能 / Web开发 / 实时通信
   - 团队背景：现有技术栈、团队规模、开发者经验水平
   - 特殊约束：信创要求、内存安全要求、极致性能要求、快速交付要求

2. 对照知识库中的选型决策矩阵初步判断候选语言：
   - 极致性能+系统级控制 → C/C++(确定性) / Rust(内存安全)
   - 云原生/微服务基础设施 → Go(推荐) / Rust(安全要求高)
   - 企业级大型系统 → Java(生态最成熟) / Go(性能更好)
   - AI/ML/数据科学 → Python(唯一选择)
   - 快速Web开发 → PHP(Laravel) / Node.js(全栈) / Python(FastAPI)
   - 实时通信/全栈 → Node.js(推荐) / Go(高性能场景)

3. 如有信息缺失，向用户追问不超过2个澄清问题。

**Knowledge Base Reference**:
- [参考: Agents知识库/0_超级编程行业知识库/01_编程语言与核心技能.md > 一、后端编程语言 > 选型决策]

### Step 2: 输出后端技术方案

**Goal**: 产出针对性的后端技术建议或学习路径
**Completion criterion**: 输出包含推荐语言、技术栈搭配、关键学习节点、注意事项

根据Step 1确定的场景，按以下分支处理：

**分支A — 技术选型**：
1. 从7大语言中筛选2-3个候选语言。
2. 输出选型决策矩阵，对比维度至少覆盖：
   - 性能（运行时效率、内存占用、并发模型）
   - 生态（框架成熟度、第三方库数量、社区活跃度、招聘难度）
   - 团队匹配度（现有技术栈相似性、学习曲线、维护成本）
   - 长期趋势（语言发展方向、大厂采用情况、关键趋势如Java 21 Virtual Threads、Python 3.13 free-threaded、Go云原生统治力、Rust进入Linux内核等）
3. 给出最终推荐并附决策理由（引用知识库中的具体数据或趋势）。

**分支B — 学习路径**：
1. 输出阶段性学习计划（入门→进阶→实战→深入）。
2. 每个阶段附：
   - 关键知识点清单（与知识库L3模块对齐）
   - 推荐框架/工具（如Java的Spring Boot 3.x + Spring Cloud、Go的Gin + gRPC + sqlc等）
   - 实践项目建议（复杂度递增）
   - 验证标准（能独立完成什么）
3. 标注关键趋势点（如Java 21 Virtual Threads对并发编程的影响、Python free-threaded对多核利用的影响）。

**分支C — 问题排查**：
1. 定位用户描述的问题到具体语言/框架层面。
2. 读取知识库中对应语言的详细知识模块，提取故障模式与解决方案。
3. 输出排查步骤（从最常见原因到根因分析），附代码示例或配置片段。

**分支D — 架构设计**：
1. 根据业务规模（QPS/数据量/并发数）推荐合适的语言组合。
2. 输出分层架构建议（接入层→业务层→数据层各层语言选择）。
3. 给出微服务间通信协议建议（gRPC/REST/消息队列）与语言绑定关系。

将结果保存到 `output/backend_advice.md` 或直接在对话中呈现。

### Step 3: 验证与交付

**Goal**: 确保输出内容准确、可操作、与知识库一致
**Completion criterion**: 已通过 checklist 逐项核对

1. 读取 `checklist/backend_programming_language_workflow_checklist.md`。
2. 逐项核对输出是否覆盖要求的知识点。
3. 确认所有关键论断均能在知识库中找到支撑。
4. 如有遗漏或偏差，补充修正。
5. 向用户交付最终答案。

## Post-Workflow

1. 记录完成状态到 `task/current_task.md`。
2. 如需进入下一步（如用户追问其他语言或深入某一语言生态），在当前 Agent 内继续执行对应工作流，无需返回顶层路由。

# 视频反推与转绘 · Feature Map（功能-代码速查）

> FFmpeg 场景检测抽帧 + 多模态 LLM 反推（分镜/关键帧/剧本）+ 本土化改写。零新 Provider、零 DB 变更。
> 关联 [plan](../plans/视频反推与转绘.plan.md) / [user-ops](./视频反推与转绘用户操作手册.md) / [开发进度](../../开发进度/视频反推与转绘/README.md)。

## 一句话描述

把一段视频「读」成结构：关键帧（镜头切换单元缩略图）、分镜表（镜号/起止/景别/运镜/画面/台词）、剧本（场景/动作/梗概），再把剧本按目标国家改写（剧情不变、文化元素替换、changeLog 核对），产出可回流生成表单。

## 调用链路

**抽帧**（analyze 前置）：`VideoReverseService.runExtraction` → ffprobe 时长（>10min 拒）→ 第一遍 `select=gt(scene,0.3),showinfo` 拿场景切换时间戳全集 → 命中<4 均匀采样兜底 / >maxFrames 均匀截断 → 第二遍逐点 `-ss <t> -frames:v 1` 取帧 → 每帧落 stored_files（缩略 ≤1024 供 LLM，originalName 编码 `reverse-shot-01-12.34s.jpg` 留痕）。

**analyze**：`Controller.analyze`（算 `isAdmin()` 透传——**admin 旁路与 media 列表同口径**，P4 修复 `aee7605`：admin 列表见全量任务，源校验同放行，否则选得到的任务反推必 403）→ 源解析（taskId 走 `MediaGenQueryService.loadForDownload(taskId, uid, admin)` 归属咽喉 / fileId 走 loadPath(uid, admin) 授权）→ runExtraction → 勾了 STORYBOARD/SCRIPT 才组 parts（指令+每帧 image/jpeg base64+「第N帧 t=Xs」）→ **单次** `LlmGateway.chat`（temp 0.3/maxTokens 4000/purpose MEDIA_REVERSE_ANALYZE/gid 透传计费）→ 容错解析（剥 ``` 围栏→首尾大括号→readTree；失败重试 1 次）→ storyboard+script 双产物一次返回。仅勾 KEYFRAMES 零 LLM。

**localize**：`Controller.localize` → 校验（剧本≤8000/地区≤32/notes≤500）→ 改写提示（**镜头数与顺序不变**硬约束+changeLog 表）→ 同解析链 → scenes 数前后不一致→warning 字段（结果仍可用），原稿非 JSON 静默跳过比较。

**画布回流**：`PropertyPanel` emit reverse-analyze → `CanvasView.onReverseAnalyze` → `addDerivedNode`（帧列纵向 ×120px 紧邻源节点、storyboard/script 向右扇出，addNode+addEdge）；转绘→新 script 节点（data 存 changeLog/localizeWarning，**面板渲染替换清单逐条可核**——P4 补 `94ac27ab`）。

**生成页回流**：`VideoReversePanel` emit use-script{promptText, sourceFileId, sourceName} → `onUseScriptForGen`：表单空→直接替换；非空→dialog 三选；替换清视频槽（revokeObjectURL）→ `previewAsset` 异步回填源视频预览 → 切回 gen Tab。

## 技术原理大白话

| 技术 | 一句话 | 展开 | 生活化案例 |
|---|---|---|---|
| 场景检测抽帧 | 找画面突变点当「镜头边界」 | FFmpeg 对相邻帧算差异分，超阈值判切换；渐变转场不触发→靠均匀采样兜底 | 翻相册挑「每到一个新景点的第一张」 |
| 两遍式取帧 | 先列清单再逐个取 | 第一遍只扫时间戳（不存图），按全集均匀选点，第二遍精确 seek 取那几帧——保首尾覆盖 | 先通读目录挑章节，再翻到那几页精读 |
| 单次多模态调用 | 一趟 LLM 出两产物 | 分镜表和剧本本质同一理解任务，共用一次带图调用省一半 token | 看完图一次性把「提纲+正文」都写了 |
| changeLog | 改动清单供核对 | 模型每替换一处文化元素登记 from/to/位置，人扫一眼即知动了哪 | 翻译稿的修改批注页 |
| AbortController | 前端「不等了」 | 只断浏览器等待，服务端抽帧/LLM 照跑照计费；帧已落库可重看 | 挂电话不等了，但对方菜已在锅里 |
| 信号量并发闸 | 抽帧排队不挤爆 CPU | `Semaphore(maxConcurrency)` tryAcquire 快速失败不排队 | 快餐店取号，满了直接告知改天 |

## 踩坑批注

- ffmpeg 4.2.3 真机：合成三场景渐变转场阈值 0.3 仅 1 命中——**兜底路径必要且符合设计**，别当 bug 修。
- LLM 返回 model 字段≠请求名（网关回退场景）——响应 model 取实际值，用户可感知真用了哪个。
- VTU：`<script setup>` ref 在 `wrapper.vm` 已解包，`.value` 访问必炸；改 vm 后须 flush 再 trigger（disabled 属性等 DOM 补丁）。
- naive-ui n-data-table 自定义 render 的 `row-key` 签名单参——多参箭头函数直接 vue-tsc 报错。
- 反推选模型（4x，2026-08-20）：后端 `ReverseAnalyzeRequest.model`/`LocalizeRequest.model` 本就透传 LlmGateway（缺省 fallback llm.default.chat-model），纯前端缺口——补 UI 时传参约定 `model: x.value ?? undefined`，**别传空串**（空串≠缺省，网关会当显式模型名解析失败）。

# 3.1 记忆架构与分层

## 一、记忆三分法与四层架构（认知科学 + 工程化）

### 认知科学记忆模型

借鉴认知科学的人类记忆模型，Agent 记忆系统采用四层架构（Futurum Research 2026 提出 Agentic Memory 模型）：

| 记忆层 | 定义 | Agent 对照 | 典型内容 | 工程实现 |
|---|---|---|---|---|
| **工作记忆（Working Memory）** | 当前正在处理的信息，容量有限 | 当前会话的上下文窗口 | 当前对话/当前任务状态/近期工具结果 | 上下文窗口（短期） |
| **情景记忆（Episodic Memory）** | 个人经历的时间序列事件 | 用户与 Agent 的历史交互序列 | 上次对话/上次任务/上次反馈 | 交互日志库 + 时间戳检索 |
| **语义记忆（Semantic Memory）** | 抽离于具体事件的客观事实知识 | Agent 知道的事实/规则/世界知识 | 用户偏好/产品规格/业务规则 | 向量库 + KG + RAG |
| **程序性记忆（Procedural Memory）** | 技能与操作规则 | Agent 会做的操作/SOP/技能规则 | 工具用法/Claude Code AGENTS.md/Skills | Skills 库 + AGENTS.md + SOP 文档 |

[来源:知乎《AI Agent 记忆系统工程：四层架构》/Futurum Research | 🔍高 | 2026-06]

**PM 认知要点**：
- 四层不是"选一层"，是"四层都要"——缺工作记忆=当前会话断片，缺情景记忆=不记得交互历史，缺语义记忆=不知道事实，缺程序性记忆=不会操作
- 最常见的失忆事故是"缺情景记忆"——Agent 不记得上次交互（旅行 Agent 失忆偏好流失 40% 根因）
- 最危险的安全漏洞是"语义记忆可被投毒"——攻击者污染事实库后 Agent 行为被操纵（94% 可投毒根因）

### 短期 vs 长期记忆

| 维度 | 短期记忆 | 长期记忆 |
|---|---|---|
| 范围 | Session-scoped 当前会话 | Cross-session 跨会话 |
| 存储 | 上下文窗口 + 临时缓存 | 向量库/KG/数据库/文件 |
| 生命周期 | 会话结束即销毁 | 持久化，需遗忘机制 |
| 典型内容 | 当前任务状态/近期工具结果 | 用户偏好/历史交互/事实知识/技能 |
| 工程挑战 | Context Rot 控制 | CRUD-M 全生命周期 + 安全 + 合规 |

[来源:Elastic 2026-01 深度指南 | 🔍高 | 2026-01]

## 二、CRUD-M 五操作（LightMem 记忆生命周期）

LightMem 提出记忆系统的五个基本操作（CRUD-M），是记忆生命周期管理的工程化框架：

| 操作 | 定义 | Agent 场景 | 工程实现 | 典型失败 |
|---|---|---|---|---|
| **C - Create 创建** | 新记忆写入 | 用户说新偏好/新事实→写入记忆库 | 向量插入/KG 节点添加/日志追加 | 重复创建/格式混乱/未验证 |
| **R - Read 读取** | 按需检索记忆 | 推理时检索相关历史/偏好/事实 | 向量检索/KG 查询/全文搜索 | 召回率低/精度低/延迟高 |
| **U - Update 更新** | 修改已有记忆 | 用户改偏好/事实变化→更新记忆 | 向量更新/KG 边修改/日志修订 | 旧记忆未覆盖/版本冲突 |
| **D - Delete 删除** | 删除过时/错误/被投毒记忆 | 遗忘权/过时信息/投毒清除 | 软删除/硬删除/级联删除 | 删除不彻底/残留备份/未验证 |
| **M - Merge 合并** | 合并相似/冲突记忆 | 多次说过同一偏好→合并去重 | 相似度聚类/冲突仲裁/版本合并 | 合并丢失信息/冲突未仲裁 |

[来源:LightMem CRUD-M（2026 ICLR）/知乎 | 🔍高 | 2026]

**PM 认知要点**：
- 大多数 Agent 记忆系统只做了 C+R（创建+读取），缺 U/D/M——这是失忆/混乱/膨胀的根因
- D（删除）是最被忽视的操作——没有受控遗忘，记忆库会膨胀稀释精度、扩大投毒攻击面、违反 GDPR
- M（合并）是最难的操作——多次说同一偏好怎么合并？冲突偏好怎么仲裁？需要业务规则不是纯技术
- CRUD-M 必须配套可观测——每次操作的日志/版本/审计/回滚

## 三、五种设计模式（按场景选型）

| 设计模式 | 核心机制 | 适用场景 | 不适用场景 | 代表框架 |
|---|---|---|---|---|
| **向量检索模式** | 向量化记忆条目 + 相似度检索 | 语义相似的偏好/事实检索 | 需要时间线/关系推理的场景 | Mem0 / 基础 RAG |
| **RAG 外挂模式** | 外部知识库 + 检索增强生成 | 静态知识库/文档问答 | 动态交互/个性化记忆 | LangChain RAG / LlamaIndex |
| **知识图谱模式** | 实体-关系图 + 图查询 | 需要关系推理/多跳查询 | 简单语义检索场景 | Zep Graphiti / Microsoft GraphRAG |
| **时间感知 KG 模式** | 带时间戳的 KG + 时间线查询 | 旅行/客服/工单等时间敏感场景 | 静态事实查询 | Zep Graphiti（时间感知领先） |
| **自管理 Agent 模式** | Agent 自主分页管理记忆（类 OS 虚拟内存） | 长程自治理 Agent / 需精细控制 | 简单一次性任务 | Letta（前 MemGPT）分页 |

[来源:51CTO《我尝试了4种AI Agent记忆方案》/知乎 | 🔍高 | 2026-07]

**选型决策树**：
1. 任务是否需要时间线？→ 是 → 时间感知 KG（Zep Graphiti）
2. 任务是否需要关系推理？→ 是 → 知识图谱模式
3. Agent 是否需长程自治？→ 是 → 自管理 Agent（Letta 分页）
4. 记忆是否为静态知识库？→ 是 → RAG 外挂
5. 其他场景（偏好/事实/情景记忆）→ 向量检索模式（Mem0）

## 五、失忆根因诊断框架

基于 2026-07 多起失忆事故，失忆根因诊断框架：

| 失忆类型 | 症状 | 根因 | 补救 |
|---|---|---|---|
| **无长期记忆型** | 第二次访问不记得上次 | 缺情景记忆层 / 无跨会话持久化 | 加长期记忆层（Mem0/Letta） |
| **无偏好沉淀型** | 不记得用户偏好 | 缺语义记忆 / CRUD 只有 C 无 U | 加偏好记忆 + Update 操作 |
| **无验证型** | 记忆被覆盖/篡改未发现 | 缺记忆验证 / 无可观测 | 加记忆验证 + 可观测看板 |
| **Context Rot 型** | 长任务忘记原始目标 | 上下文窗口污染 / 无 Compaction | 加 Compaction + 工具数控制 |
| **投毒型** | 记忆被污染后行为异常 | 缺投毒检测 / 无访问控制 | 加投毒检测 + 记忆主权 |
| **遗忘失败型** | 过时信息未删除干扰决策 | 缺 Delete 操作 / 无遗忘机制 | 加受控遗忘 + 定期清理 |

[来源:腾讯云《2026 AI Agent 记忆系统崩溃事件频发》/知乎《崩溃4——Agent 失忆了》| 🔍高 | 2026-05/07]

**典型失忆事故**：
- 财务 Agent 遗忘初始汇率设定 → 转账错误（无长期记忆型 + Context Rot 型）
- 代码 Agent 跨文件重构丢失核心架构约束（Context Rot 型 + 无验证型）
- 旅行规划 Agent 第二次访问不记得"喜欢海滩不喜欢购物" → 推荐 3 个购物中心 → 用户流失率 40%（无长期记忆型 + 无偏好沉淀型）

## 六、PM 记忆架构设计 Checklist

- [ ] 四层记忆（工作/情景/语义/程序性）是否都覆盖？
- [ ] 短期 vs 长期边界是否清晰？跨会话连续性是否实现？
- [ ] CRUD-M 五操作是否全实现？特别是 D（删除）和 M（合并）？
- [ ] 五种设计模式是否按场景选型？有没有选错？
- [ ] 六大框架是否对比选型？是否绑定单一框架风险？
- [ ] 失忆根因诊断是否建立？失忆事故是否能快速定位？
- [ ] 记忆验证机制是否设计？记忆被篡改能否发现？
- [ ] 记忆可观测是否建立？读写延迟/命中率/异常能否监控？

# File Keeper 项目用户画像及多维度人群使用场景文档

## 1. 文档目的

本文档用于梳理 File Keeper 当前版本适合服务的目标用户、人群特征和典型使用场景，帮助统一以下问题：

- 这款工具主要解决谁的问题。
- 哪些模块对哪些人最有价值。
- 不同类型用户在什么场景下会频繁使用它。
- 后续功能说明、产品介绍和测试设计应围绕哪些真实工作流展开。

当前 File Keeper 的用户价值已经不只来自“常用文件快速访问”和“运行中应用整理”，还来自：

- 剪贴板历史回溯
- 快速复制与快速粘贴
- 截图入库与 OCR 搜索
- 本地安全事件识别

因此，用户画像需要覆盖“资料入口 + 桌面窗口整理 + 剪贴板增强 + 截图提取”这四类连续工作流。

---

## 2. 总体用户画像

File Keeper 当前最适合以下共同特征明显的人群：

- 长时间在 **Windows 桌面** 上工作。
- 经常在多个文件、文件夹、网页、应用窗口之间切换。
- 有一批高频资料需要反复打开。
- 经常复制文本、链接、路径、图片或文件。
- 会频繁截图保存信息，且希望后续还能搜索截图里的文字。
- 工作开始前需要快速进入状态，工作结束后需要快速收尾。
- 希望工具尽量 **本地、轻量、低打扰**，不依赖账号体系和云端服务。

File Keeper 的理想用户不是偶尔找一两个文件的人，而是典型的 **Windows 多任务与高频复制粘贴用户**。

---

## 3. 核心使用需求

从当前功能结构看，目标用户的核心需求可以归纳为 6 类：

1. **高频资料入口**
   - 常用文件、文件夹、模板、脚本、笔记、素材可以快速打开。

2. **资料组织与定位**
   - 通过分组、标签、搜索、排序快速找到当前需要的内容。

3. **运行中窗口整理**
   - 快速判断当前打开了哪些应用，哪些该保留，哪些该关闭。

4. **剪贴板历史回放**
   - 找回刚才复制过的文本、文件、图片、链接或颜色。

5. **截图提取与 OCR 搜索**
   - 截图保存后，能够在历史中继续查看、备注、搜索图片里的文字。

6. **工作收尾与安全感**
   - 批量清理不再需要的窗口。
   - 识别敏感内容，避免把风险信息当普通历史长期保存。

## 4. 一级目标用户

## 4.1 开发者、测试工程师与技术文档使用者

### 用户特征
这类用户通常同时使用：
- IDE / 编辑器
- 浏览器
- 终端
- API 调试工具
- 日志窗口
- 项目文档
- 配置文件
- 脚本文件
- 截图与沟通工具

### 典型痛点
1. README、接口文档、配置文件和脚本需要反复打开。
2. 浏览器、终端、测试工具和临时窗口会越开越多。
3. 代码片段、命令、路径、报错内容经常复制后很快被新内容覆盖。
4. 截图保存了报错或界面信息，但之后难以再次搜索和回看。
5. 切换项目或切换任务时，桌面环境清理成本高。

### 使用场景
#### 场景 A：进入项目
- 通过文件管理模块快速打开 README、接口文档、脚本、配置和日志目录。

#### 场景 B：调试过程中反复复制
- 在剪贴板历史中找回刚复制过的命令、路径、接口参数和临时代码片段。

#### 场景 C：截图记录问题
- 截图保存异常界面、报错弹窗或系统状态。
- OCR 自动提取文字后，后续可以直接搜索截图里的关键词。

#### 场景 D：开发收尾
- 在应用管理页筛选浏览器、终端、调试工具并批量关闭不再使用的窗口。

### 核心价值
- 更快进入项目状态。
- 更快回放复制过的技术内容。
- 把截图从“一次性查看”变成“可搜索的历史资料”。
- 更快清理临时开发环境。

## 4.2 办公人员、运营、产品与项目协作人员

### 用户特征
这类用户经常使用：
- Word / Excel / PowerPoint / PDF
- 浏览器
- 会议软件
- 即时通讯工具
- 模板文件
- 表格、合同、报表、需求文档
- 各类网页链接和截图资料

### 典型痛点
1. 常用模板、表格和汇报文档重复查找。
2. 会前会后要在多个文档和网页之间来回切换。
3. 复制过的链接、文案、表格内容容易丢失。
4. 经常截图保存审批信息、页面结果、对话记录，但后面不好整理。
5. 会议结束后窗口、浏览器标签和会议软件残留很多。

### 使用场景
#### 场景 A：准备资料
- 用文件管理模块快速打开周报模板、PPT、合同、客户目录、流程文档。

#### 场景 B：处理中途复制
- 在剪贴板历史中找回刚才复制过的链接、文案、客户编号、表格数据。

#### 场景 C：保留页面信息
- 截图保存页面结果或审批状态。
- 后续通过 OCR 搜索截图中的关键字，而不是只能凭记忆翻找图片。

#### 场景 D：会议后收尾
- 在应用管理页快速关闭会议软件、临时浏览器窗口和不再需要的文档窗口。

### 核心价值
- 高频办公资料入口集中。
- 复制/粘贴内容不容易丢。
- 截图信息可沉淀为可搜索资料。
- 会后整理更轻松。

## 4.3 学生、研究者与自学者

### 用户特征
常见工作材料包括：
- PDF 讲义
- 课程笔记
- 论文
- 浏览器资料
- 作业文件
- 在线课程页面
- 会议或课堂截图
- 摘录文本与引用片段

### 典型痛点
1. 课程和研究资料容易混在一起。
2. 重点文件、复习资料和引用内容不好回找。
3. 浏览器、PDF、笔记软件和会议工具会堆积很多窗口。
4. 学习过程中复制的术语、定义、引用和链接容易被覆盖。
5. 截图保存的公式、段落、图表后续很难再搜索。

### 使用场景
#### 场景 A：按课程或课题组织资料
- 用分组管理课程、论文方向、课题或考试资料。

#### 场景 B：复习重点内容
- 用标签和搜索快速找到重点、待复习和参考资料。

#### 场景 C：保留引用与摘录
- 通过剪贴板历史回溯刚复制过的定义、引用、链接和摘要。

#### 场景 D：截图记录教材或网页内容
- 截图保存图表、段落、公式或课程页面。
- OCR 让这些内容后续可以按文字搜索。

#### 场景 E：学习结束清理环境
- 关闭 PDF 阅读器、浏览器、会议软件和不再需要的资料窗口。

### 核心价值
- 学习资料更集中。
- 引用和剪贴板内容更容易回找。
- 截图资料从“图片堆积”变成“可检索知识片段”。

## 4.4 设计师、内容创作者与视觉资料重度用户

### 用户特征
常用内容包括：
- 设计源文件
- 图片素材
- 参考图
- 文案草稿
- 视频或音频素材
- 浏览器灵感页
- 截图反馈
- 交付文档

### 典型痛点
1. 素材、交付和参考资料分散在多个目录。
2. 项目切换时要打开很多固定资源。
3. 常会复制配色值、链接、文案片段、文件路径。
4. 经常截图保存需求反馈和界面参考，但后续难以统一检索。
5. 浏览器、设计软件、图片工具和通讯工具窗口很多。

### 使用场景
#### 场景 A：项目资料入口
- 用分组组织项目源文件、素材目录、品牌规范和交付文件。

#### 场景 B：素材与文案回放
- 用剪贴板历史回找配色值、短文案、链接、文件路径和临时复制内容。

#### 场景 C：截图保留反馈
- 截图保存页面标注、视觉反馈和修改建议。
- OCR 让截图中的文字意见后续可搜索。

#### 场景 D：创作收尾
- 在应用管理页筛选浏览器、图像、媒体和通讯类应用，快速回收桌面空间。

### 核心价值
- 素材与交付入口更稳定。
- 临时复制内容更容易回放。
- 反馈截图更易沉淀和回查。

## 4.5 运维、技术支持与高级 Windows 用户

### 用户特征
这类用户会更关注：
- 当前哪些应用正在运行。
- 哪个窗口属于哪个进程。
- 应用名称、PID、窗口标题。
- 关闭失败是否与权限有关。
- 复制窗口/进程信息用于工单与沟通。

### 典型痛点
1. 任务管理器信息很多，但不一定适合日常快速整理窗口。
2. 普通用户说不清自己开了哪些应用。
3. 某些应用关闭失败时，很难快速判断是不是权限问题。
4. 复制进程信息用于记录时操作繁琐。
5. 剪贴板里的命令、路径、截图和文字说明需要同时保留。

### 使用场景
#### 场景 A：快速查看运行应用
- 按类别、名称、PID、窗口标题快速识别当前环境。

#### 场景 B：复制问题信息
- 复制进程信息、窗口标题、命令行内容、路径和剪贴板文本用于记录或工单。

#### 场景 C：截图留证
- 截图保存故障界面、权限提示或系统状态。
- OCR 使截图中的关键报错词后续仍可搜索。

#### 场景 D：处理权限与收尾
- 关闭不再需要的窗口。
- 关闭失败时理解“拒绝访问”等提示意味着什么。

### 核心价值
- 轻量查看运行应用。
- 问题信息更容易复制和沉淀。
- 窗口、截图、剪贴板信息可以放到同一工具里回看。

## 4.6 重度多任务与高频剪贴板用户

### 用户特征
这类用户不一定属于某个固定职业，但有明显共性：
- 同时开很多窗口。
- 一天内会复制大量文本、链接、文件和图片。
- 经常把截图当作临时资料保存。
- 工作在多个上下文之间频繁切换。

### 典型痛点
1. 找文件费时间。
2. 找刚复制过的内容也费时间。
3. 截图信息越积越多，但后续无法有效利用。
4. 桌面窗口混乱，切换任务时成本高。

### 使用场景
#### 场景 A：开始工作
- 快速打开高频资料。

#### 场景 B：工作过程中反复复制与截图
- 从剪贴板历史回放内容。
- 用截图 + OCR 保留临时信息。

#### 场景 C：工作结束后收尾
- 关闭临时窗口，保留真正需要留下的应用。

### 核心价值
- 把文件入口、剪贴板和窗口整理放到一个工作台里。
- 降低上下文切换与收尾成本。

## 5. 多维度场景矩阵

| 场景维度 | 用户问题 | File Keeper 模块 | 价值 |
|---|---|---|---|
| 工作开始 | 高频资料找起来慢 | 文件管理 | 快速进入状态 |
| 工作进行 | 临时资料和文件反复查找 | 文件管理 + 搜索 | 降低查找时间 |
| 高频复制 | 刚复制的内容被覆盖 | 剪贴板历史 | 降低重复复制成本 |

| 多窗口切换 | 桌面越来越乱 | 应用管理 | 降低整理成本 |
| 收尾阶段 | 关窗户怕误操作 | 应用管理 + 确认保护 | 提升安全感 |
| 敏感内容处理 | 不希望敏感文本长期裸露保存 | 安全检测 | 提升本地使用安全感 |

## 6. 用户旅程

## 6.1 开始工作前
1. 打开 File Keeper。
2. 进入文件管理模块。
3. 用分组或最近打开找到当前任务资料。
4. 一键打开常用文件、目录和脚本。

## 6.2 工作进行中
1. 通过搜索快速定位资料。
2. 在剪贴板模块中回找刚复制过的文本、文件或链接。
3. 通过截图保存临时信息。
4. 依赖 OCR 让截图后续仍可检索。

## 6.3 工作切换时
1. 切换到应用管理模块。
2. 按类别筛选当前不再需要的窗口。
3. 多选后批量关闭。
4. 保留关键应用白名单与确认保护。

## 6.4 工作结束后
1. 清理临时窗口。
2. 保留需要长期使用的文件收藏。
3. 在剪贴板历史中继续保留今天的关键文本、截图和链接。

## 7. 当前最值得强化的人群价值

从当前代码实现完整度看，以下场景价值最明确：

1. **开发者与测试人员**
   - 文件、窗口、剪贴板、截图 OCR 的组合价值最强。

2. **办公与运营人员**
   - 文件入口 + 剪贴板历史 + 会后窗口清理，非常贴近日常工作流。

3. **学生与研究者**
   - 文件管理 + 剪贴板回放 + 截图 OCR，对资料整理与复习非常有帮助。

4. **重度多任务用户**
   - 是所有模块的共同受益者，也是最容易形成持续使用习惯的人群。

---

## 8. 边界用户

以下用户不是当前版本最优先的核心受众：

1. 只需要全盘极速文件搜索、不需要资料组织的人。
2. 只需要专业系统级进程诊断和句柄分析的人。
3. 很少复制内容、很少截图、很少整理窗口的人。
4. 非 Windows 主力用户。

这并不意味着他们不能使用 File Keeper，而是当前版本最强的价值并不主要面向这些场景。

---

## 9. 结论

File Keeper 当前最适合服务的是 **Windows 多任务、高频资料访问、高频复制粘贴和经常截图留存信息的用户**。

它解决的问题已经从“找文件更快”扩展为：

1. 高频文件如何更快打开。
2. 当前打开的应用如何更快整理。
3. 刚复制过的内容如何更快找回。
4. 截图里的文字如何在之后仍然可搜索。

因此，File Keeper 的目标用户应围绕“一个本地工作台，统一管理资料、窗口、剪贴板和截图信息”来理解。

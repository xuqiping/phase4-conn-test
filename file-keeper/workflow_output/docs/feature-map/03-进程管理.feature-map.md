# 进程管理 Feature Map

> 当前真相：2026-09-03。重点覆盖窗口标题默认列和旧设置迁移。

## 功能与代码

| 功能 | 关键文件 | 作用 |
|---|---|---|
| 支持列真相源 | `src/components/processColumns.ts` | 定义可渲染列、默认可见性和默认顺序 |
| 设置迁移 | `src/stores/processSettingsStore.ts` | 按列 key 合并旧配置，只执行一次窗口标题升级 |
| 列管理 | `src/components/ColumnSettings.vue` | 显示/隐藏、排序支持列，不暴露不可渲染列 |
| 列表与行 | `src/components/ProcessList.vue`、`src/components/ProcessRow.vue` | 文本插值展示窗口标题，空标题显示 `-`，支持排序 |
| 数据类型/采集 | `src/types/process.ts`、`src/stores/processStore.ts`、`src-tauri/src/platform/windows/process_monitor.rs` | 接收并刷新原生窗口标题，不持久化标题正文 |

## 调用链

```text
应用启动 → processSettingsStore 读取旧列配置
  → 按 key 补齐新支持列
  → 升级前缺失 windowTitle 时默认显示
  → 迁移版本写入后，后续尊重用户手动隐藏

进程刷新 → Rust 采集窗口标题 → ProcessList 按文本渲染/排序
```

## 技术原理（大白话）

- **按 key 合并**：不整包覆盖旧配置，只补缺失列。像 Excel 按列名对齐，新加一列不会打乱用户原来的列顺序。
- **一次性迁移版本**：只在第一次升级时把窗口标题设为可见。像系统首次介绍新功能，用户之后关掉就不再强行打开。
- **文本插值**：把标题当普通文字显示，不解析 HTML。像把用户输入打印在纸上，而不是当成可执行指令。

> 窗口标题只在当前进程列表中显示，不上传、不写持久化日志。空标题统一显示 `-`，避免误以为加载失败。

# 4.1 Agent MoSCoW分桶与降桶建议

> 📅 2026-07-11 ｜ 🔴红线：MoSCoW分桶不可全靠AI，Must/Should的判定必须由PM+业务方共同确认 ｜ 角色：MoSCoW分桶辅助Agent

## 背景

MoSCoW分桶的核心挑战是Must膨胀和Won't恐惧。本Agent基于KANO分类和RICE评分辅助分桶，并主动检测Must膨胀、建议降桶。

## 目标

输入需求清单（含KANO标签+RICE评分，如无则辅助生成），输出MoSCoW分桶结果 + Must膨胀检测 + 降桶建议。

## 关键结果

1. 每个需求的MoSCoW桶位（含分桶依据）
2. Must占比检查（是否>60%资源）
3. Won't桶声明（含原因和预计重评时间）

## 执行步骤

### Step 1：KANO→MoSCoW自动映射

```
映射规则：
  KANO=M → MoSCoW=Must
  KANO=O → MoSCoW=Should
  KANO=A → MoSCoW=Could
  KANO=I/R → MoSCoW=Won't

输出：初始分桶表（供PM调整）
```

### Step 2：RICE分数辅助分桶校验

```
校验逻辑：
  - RICE高分 + MoSCoW=Could → ⚠️ 检查是否KANO=A（合理）或KANO=O但分桶错误
  - RICE低分 + MoSCoW=Must → ⚠️ 检查是否KANO=M（合理）或RICE评分需修正
  - RICE高分 + MoSCoW=Won't → 🚨 极可能KANO=I（RICE虚高）→ 建议下调Impact
```

### Step 3：Must膨胀检测

```
计算Must需求的总Effort / 总Sprint产能
  > 60% → 🚨 Must膨胀预警
  > 80% → 🚨🚨 严重膨胀，必须降桶

降桶建议逻辑：
  在Must中找到RICE最低的需求 → 建议降为Should
  重复直到Must≤60%
```

### Step 4：Won't桶建议补充

```
Won't为空 → 建议至少将2-3个低RICE+I类KANO的需求放入Won't
Won't声明模板：
  "【Won't】需求X：原因=KANO=I/R且RICE得分低，预计Y版本重评"
```

## 输出格式

```markdown
# MoSCoW分桶报告

## 分桶结果
| 需求 | KANO | RICE | MoSCoW桶 | 分桶依据 |
|---|---|---|---|---|

## Must占比检查
- Must总Effort：X人月 / 总产能Y人月 = Z%
- 状态：✅正常 / ⚠️偏高(60-80%) / 🚨膨胀(>80%)

## 降桶建议
| 需求 | 当前桶 | 建议桶 | 原因 |
|---|---|---|---|

## Won't声明
| 需求 | Won't原因 | 预计重评版本 |
```

## SOP 四象限工作坊

### 一、目的

让团队在限定时间内完成需求四象限排序，形成共识，输出可执行的Sprint/版本排期。

### 二、参与者与角色

| 角色 | 人数 | 职责 |
|---|---|---|
| 引导者(Facilitator) | 1人 | 控制流程/时间，不参与评分 |
| PM/PO | 1-2人 | 提供需求上下文，主导价值评估 |
| Tech Lead | 1-2人 | 主导复杂度评估 |
| 业务方代表 | 1-2人 | 补充业务价值和紧急度信息 |
| 设计师(可选) | 1人 | 补充UX复杂度 |

总人数建议4-8人，超过8人时拆分两场。

### 三、前置准备（会前1天）

1. **需求清单**：确认待排需求列表（≤30条，超30条先RICE Top 50%筛选）
2. **协作工具**：Miro/FigJam白板已建好四象限模板
3. **维度共识**：确认Y轴（用户价值/商业价值/战略价值）、X轴（开发工作量/端到端工作量）
4. **分界线预设**：初步设定价值≥3为高、复杂度≥4为高

### 四、工作坊流程（总时长60-90分钟）

#### Phase 1: 对齐维度（10分钟）

1. 引导者展示四象限模板，声明维度定义
2. 举1-2个示例需求，全体确认定位
3. 调整分界线（如团队认为"3分价值不算高"则上调至4）

#### Phase 2: 独立评分（15分钟）

1. 每人在便签/协作工具上为每条需求打：价值(1-5) + 复杂度(1-5)
2. 不讨论，独立完成
3. 提交到共享表格

#### Phase 3: 散布与讨论（20-30分钟）

1. 引导者将所有评分投射到四象限白板
2. 识别"跨象限差异"——同一条需求有人放Q1有人放Q4
3. 对差异项：限时5分钟讨论→达成共识→移动位置
4. 对一致项：快速确认，跳过讨论

#### Phase 4: 交付线划定（10分钟）

1. 根据Sprint/版本容量，画交付线
2. 确认交付线内需求承诺交付
3. 标记"可协商"和"不可砍"需求

#### Phase 5: 行动项确认（5分钟）

1. Q4需求 → 明确"Won't do"+通知提出方
2. 大项目需求 → 拆分MVP+完整版
3. 输出：四象限照片/截图 + 行动项清单

### 五、常见问题与处理

| 问题 | 处理方法 |
|---|---|
| 价值分歧无法统一 | 回到数据：用户调研/A/B测试结果，无数据时标注"待验证" |
| 复杂度严重低估 | Tech Lead现场拆解任务列表，重新评估 |
| 业务方坚持高优先级但PM认为Q3 | 让业务方量化"不做会怎样"，区分nice-to-have和must-have |
| 时间不够 | Q4全砍(无争议)、Q3群砍，只讨论Q1/Q2 |

### 六、产出物

1. 四象限散布图（含需求编号）
2. 交付线内的需求清单（承诺交付）
3. 需要进一步验证的需求清单（附验证方法）
4. 行动项清单（谁在什么时候做什么）

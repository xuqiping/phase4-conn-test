# 规格 · 视频模型接入扩展（Seedance fast/mini/2.5 + MiniMax H3 + HappyHorse 1.1）

> SDD 特性级规格（Phase 1 产出）。实现须与本文件对齐；冲突时改实现或改本文档（注明原因）。
> 来源：用户 2026-08-28 提出接入五模型 + 联网调研（价目/参数见 §2）+ 三决策拍板（§3）。
> 上游规格：[积分计费系统.md](积分计费系统.md) B4、[视频TOKEN分辨率分档计价.md](视频TOKEN分辨率分档计价.md)（V162 槽位先例）。

## 1. 背景与平台现状事实（2026-08-28 探查）

- **视频协议只有一种**：`ArkSeedanceProvider`（Ark 异步任务协议：POST {endpoint} 建任务返 `cct-xxx` → GET {endpoint}/{id} 查态），且 **worker 硬编码**（[MediaGenTaskWorker.java:56](../../../backend/src/main/java/com/superprogrammer/media/service/MediaGenTaskWorker.java#L56) 直接注入 `arkProvider`，:149/:160 直调）——H3/百炼协议进不来。
- **抽象已有**：`MediaGenProvider` 接口（getId/createTask/queryTask，[MediaGenProvider.java](../../../backend/src/main/java/com/superprogrammer/media/provider/MediaGenProvider.java)）；`llm_providers` 表已有 **`protocol` 字段**（chat 侧在用）+ `category` + `config`（capabilities JSON 放这里）。
- **模型能力**：前缀默认 `seedance-2*`→9图/3视频/3音频/12总、fast/mini→≤1080p、4-15s；未知模型保守兜底+WARN（[MediaModelCapabilityService.java:175](../../../backend/src/main/java/com/superprogrammer/media/config/MediaModelCapabilityService.java#L175)）。
- **分辨率白名单固定 4 档** `480p/720p/1080p/4k`（能力 RES 常量 :26-27、价表槽 `EST_RESOLUTION_SLOTS` [PricingConfigService.java:253](../../../backend/src/main/java/com/superprogrammer/billing/service/PricingConfigService.java#L253) 单源派生 TOKEN_SLOT_KEYS、est 槽；前端 estSlots/tokenSlots 数组）——H3 的 **768P/2K** 表达不了。
- **SECOND 秒价单值**：`videoCost` SECOND 分支=命中行 `pricePerSecond×时长`；`estimateVideoYuan` 同（[PricingService.java:172-174](../../../backend/src/main/java/com/superprogrammer/billing/service/PricingService.java#L172-L174)）——H3/百炼分档秒价表达不了（D6/V160 已删 SECOND 分辨率多行，勿复活多行方案）。
- 结算链 `resolution` 已透传（Worker:253-256）；V162 已验证「行内 JSONB 槽+回落通用」范式。

## 2. 外部调研结论（2026-08-28，价以官方页为准）

| 模型 | 渠道/协议 | 计费 | 价 | 关键参数 |
|---|---|---|---|---|
| seedance2.0 fast | 火山方舟（Ark） | token | 含视频输入≈42元/百万；不含价待官方页核实 | 9图/3视频/3音频/12总、4-15s、24fps、六比例、原生音频、**最高720p** |
| seedance2.0 mini | 火山方舟 | token | 不含23 / 含14 元/百万 | 同 fast，**最高720p** |
| seedance2.5 | 火山方舟 | token | 不含70 / 含42 元/百万 | **30图/10视频/10音频/50总、最长30s、4K**、局部精修/时间戳编辑（平台无控件） |
| MiniMax H3 | MiniMax 开放平台 | **按秒** | 768P 0.50 / 2K 0.80 元/秒 | **分辨率768P/2K**、4-15s、24fps、原生立体声音频、T2V/I2V/R2V（参考视频） |
| HappyHorse 1.1 | 阿里云百炼（DashScope） | **按秒** | 720P≈0.54元/秒（480P更低，以百炼页为准） | 文/图/多图生视频，参考=图非视频；480P/720P（1080P以官方API文档为准） |

Seedance 系每百万价**不随分辨率变**（只分含/不含视频输入）；分辨率影响 token 用量 → 预估秒价按分辨率配，V162 分档槽留空。

## 4. 功能需求

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| MVR-1 | provider 路由层 | worker 去 `arkProvider` 硬编码：按任务 providerId 解析 `llm_providers.protocol` → 路由到注册的 `MediaGenProvider`（map by getId()）。视频 protocol 值域：**`ark`（存量 VIDEO 行 V163 回填）/ `minimax` / `dashscope`**。未注册 protocol → 任务失败带可读原因。接口扩展：`queryTask(String providerTaskId, Long providerId)`（多 provider 行各持密钥，查态需知道用哪行 key；Ark 现两参私有版上位为接口方法）。**IMAGE 链不动**（ArkImageProvider 同步生成、不在本接口，维持现状） | P0 |
| MVR-2 | 分辨率字典扩 6 档 | 全局档位 `{480p,720p,768p,1080p,2k,4k}`：`EST_RESOLUTION_SLOTS` 单源扩（TOKEN/est/新 SECOND 槽自动跟上）+ `PricingService.normalizeResolution`（768P→768p、2K→2k）+ 能力 RES 常量 + 前端 slots 数组。**各模型可见档位仍由 capability `supportedResolutions` 决定**（字典=并集白名单，非全模型全显） | P0 |
| MVR-3 | SECOND 秒价分档（V163） | `pricing_rule` + `price_per_second_per_resolution JSONB`（仅 VIDEO+SECOND；键⊆6 档，无 general——通用=`price_per_second` 列；值>0；导入三态同 V162）。`videoCost` SECOND 分支：`槽[normalize(res)] ?? pricePerSecond`（脏 JSON WARN 回落）；`estimateVideoYuan` SECOND 同口径。前端 SECOND 表单档位槽（占位「留空=按通用秒价」）+列表列+sanitize 恒发对象（全空=`{}`） | P0 |
| MVR-4 | Seedance 三兄弟能力默认修正 | 代码改（非 config 覆盖）：fast/mini `supportedResolutions`→`["480p","720p"]`；新增 `seedance-2-5` 前缀分支（识别 `-2-5`/`-2.5` 两种写法）：30图/10视频/10音频/50总、4-30s、≤4K、音频开。模型 ID 加进方舟 provider 的 `models` 列表即可候选（价表页联动已有） | P0 |
| MVR-5 | MiniMax H3 适配器 | `MinimaxVideoProvider`（ID=`minimax`）：官方任务协议（POST 建 task → 轮询 query → 取 video_url；参考素材走平台文件接口，细节以官方 API 文档为准，P2 核对端点/字段）。分辨率 768P/2K 映射字典档 768p/2k；能力默认：maxVideos/图/音频与参考上限按官方、4-15s、音频开、`supportedResolutions:["768p","2k"]`。计费 SECOND+分档秒价槽 | P0 |
| MVR-6 | HappyHorse 1.1 适配器 | `DashscopeVideoProvider`（ID=`dashscope`）：百炼异步任务协议（POST 视频 synthesis + 异步头 → task_id → GET tasks/{id} 轮询，以[官方 API 参考](https://help.aliyun.com/zh/model-studio/happyhorse-image-to-video-api-reference)为准）。能力默认：参考=图（`maxVideos:0`）、480P/720P（1080P 核实后加）、按官方时长、音画同步（`supportsGenerateAudio:true`）。计费 SECOND+分档秒价槽；hasReference 恒 false → **只配无参考一行**（resolveRule fallback 已有） | P0 |
| MVR-7 | 价表行配置清单（admin 操作口径） | fast/mini/2.5：TOKEN×2 行（无参考=不含视频输入价、有参考=含价），V162 分档槽**留空**，est 预估秒价按官方价格计算器折算分档填；H3：SECOND×1 行（无参考）+ 秒价槽 768p/2k；HappyHorse：SECOND×1 行 + 秒价槽 480p/720p | P0 |
| MVR-8 | 密钥与渠道配置 | 每新渠道一条 `llm_providers` 行（name/displayName/protocol/category=VIDEO/apiEndpoint/apiKeyEnc/models/config），密钥 AES 加密+审计现状复用；模型管理页可加 VIDEO 行（现状确认，缺则补） | P0 |

## 5. 非功能需求

- **性能**：路由=内存 map 查表零开销；适配器 WebClient 沿 Ark 指纹缓存范式；轮询节奏退避现状不动。
- **安全**：新 provider 密钥同 AES+黑名单话术+脱敏快照范式（Ark 先例 :49）；无新端点（媒体提交口不变）；能力/价表校验服务层白名单。
- **可回滚**：V163 ADD COLUMN nullable，回滚 DROP；能力默认改动=纯代码 revert；新 provider 不配 models 即不可达。

## 6. 数据模型（V163+V164——V162 已用；原草案单文件拆两个，因路由先于 SECOND 槽落地）

```sql
-- V163__media_video_provider_protocol.sql（RA 路由层随发）
-- 存量 VIDEO 行补标协议，路由层上线即命中；回滚=SET protocol=NULL 记手册
UPDATE llm_providers SET protocol = 'ark'
 WHERE category = 'VIDEO' AND (protocol IS NULL OR protocol = '');

-- V164__pricing_second_price_per_resolution.sql（RC SECOND 分档）
ALTER TABLE pricing_rule ADD COLUMN price_per_second_per_resolution JSONB;
-- 仅 VIDEO+SECOND 行；键⊆{480p,720p,768p,1080p,2k,4k}，值 ¥/秒>0；未配档回落 price_per_second
```

## 7. 测试策略

- **单测**：①路由：protocol→provider 命中/未注册失败话术 ②能力：fast/mini≤720p、2-5 前缀 30/10/10/50/30s、未知兜底 ③SECOND 分档：videoCost/estimate 取槽回落/脏 JSON/全空=通用秒价（V162 用例镜像）④校验：SECOND 槽键白名单/0 值/TOKEN 行带 SECOND 槽拒；导入三态 ⑤适配器：WireMock 建任务/查态/终态映射/失败话术脱敏。
- **人工测试标记**（需真 key 真渠道）：五模型各真跑一条（fast/mini 720p、2.5 4K 30s、H3 两分辨率、HH 480P/720P）→ 流水金额=口径对账；参考素材链（H3 参考视频、HH 多图）；旧价表导入不误清秒价槽。
- **回归**：Ark seedance 全链不变（protocol 补标 `ark` 后路由仍命中）；D6 口径（SECOND 无 resolution 列）不回归。

## 8. 边界与不做

- **不**做 2.5 局部精修/时间戳编辑/多轮延展 UI（平台无参数控件，属另一特性）。
- **不**接聚合网关路径（Q2 已排除）；**不**复活 SECOND 分辨率多行（D6 维持，Q3 选行内槽）。
- **不**改「缺价=0 元/估价 0 不拦」口径；H3 有参考是否附加计费官方未明 → 先只配无参考行（fallback 兜住），官方出细则再补第二行。
- H3 是否有 1080P 档、HappyHorse 1080P 支持：以官方文档核实为准，capability 可后配。
- MiniMax/百炼协议细节（端点、字段名、轮询语义、文件上传）P2 以官方 API 文档逐一核对后写进 plan，本规格只锁「异步任务+独立 provider」形态。
- **P2 核对项**：①伪 token 费率表 `estimateRatePerSec`（Worker:490）覆盖 2.5 的 4K 档（usage 缺失兜底口径）②HappyHorse `maxVideos:0` 后端是否真拦视频附件（前端禁传已够，后端复核）③价表表单 SECOND/TOKEN 槽 UI **固定显 6 档**（价表行不绑能力，管理员按模型自填支持的档，余档留空）。

## 10. 术语表

| 术语 | 大白话 | 案例 |
|---|---|---|

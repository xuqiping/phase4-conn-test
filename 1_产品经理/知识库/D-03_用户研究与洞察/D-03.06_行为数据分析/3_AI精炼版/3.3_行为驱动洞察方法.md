## 从行为数据到产品洞察的方法论

### 行为洞察三层模型

```
第一层：描述性（What）——发生了什么
  ↓
第二层：诊断性（Why）——为什么会这样
  ↓
第三层：预测性/指导性（How）——怎么改变
```

### 第一层：描述性洞察

**目标**：准确描述用户行为现状

| 分析方法 | 典型问题 | 输出 |
|---|---|---|
| 事件频率分析 | 哪些功能使用最多/最少 | 功能使用排名 |
| 活跃度分析 | DAU/WAU/MAU趋势 | 活跃曲线 |
| 路径分析 | 用户主流轨迹是什么 | 桑基图 |
| 漏斗分析 | 哪一步流失最多 | 转化率漏斗 |
| 留存分析 | 用户多久后流失 | 留存曲线 |

> 第一层是必要基础但不是最终目的——"知道DAU降了"不等于"知道为什么降了"。

### 第二层：诊断性洞察

**目标**：从"是什么"推导"为什么"

#### 方法1：对比分析法
| 对比维度 | 示例 | 洞察 |
|---|---|---|
| 时间对比 | 本周 vs 上周同期 | 短期变化原因 |
| 群体对比 | 留存用户 vs 流失用户行为差异 | 留存驱动因素 |
| 版本对比 | 新版 vs 旧版用户行为差异 | 版本影响评估 |
| 渠道对比 | 渠道A vs 渠道B用户质量差异 | 渠道优化 |

#### 方法2：行为下钻法
发现异常 → 下钻到更细粒度 → 定位根因
- 例：整体转化率下降 → 是哪个平台？→ iOS → 是哪个页面？→ 支付页 → 是哪个支付方式？→ 微信支付 → 原因：微信支付SDK更新导致超时

#### 方法3：队列对比法
同期不同群组的行为差异揭示变化原因
- 例：7月注册用户留存低于6月 → 7月新功能上线后新手引导变长了 → 新手阶段流失增加

### 第三层：指导性洞察

**目标**：从"知道了为什么"转化为"做什么能改变"

#### 洞察→假设→实验闭环

```
行为数据发现问题
    ↓
诊断分析找到可能原因
    ↓
形成可测试的产品假设
    "如果我们缩短注册步骤，转化率会提升X%"
    ↓
设计A/B实验验证
    ↓
实验结果确认/否定假设
    ↓
迭代优化
```

#### 关键：假设必须可证伪

| 好假设 | 坏假设 |
|---|---|
| "如果首页加载速度降低1s，跳出率将下降5~10%" | "优化体验后留存会变好" |
| "如果在新手引导第3步增加跳过按钮，完成率提升15%+" | "功能做更好用户就会用" |
| "如果推送频次从3次/天降到1次/天，7日留存提升3%" | "减少打扰用户会更满意" |

> 判断标准：假设中是否包含**可量化的预期效果**+**可操控的自变量**。两者缺一=不是可测试的假设。[来源:📚训练知识 | 置信度:📚中]

### 行为洞察与定性研究的配合

| 场景 | 行为数据角色 | 定性研究角色 |
|---|---|---|
| 发现问题 | 定位"哪里出了问题" | 解释"用户为什么不满意" |
| 验证假设 | 量化验证行为变化 | 深入理解变化原因 |
| 探索新方向 | 模式发现（这个行为模式有意思） | 动机理解（用户为什么这么做） |
| 评估效果 | A/B实验数据 | 满意度/主观感受反馈 |

> 黄金法则：**行为数据告诉你"是什么"，定性研究告诉你"为什么"，两者结合才能从"是什么"跳到"怎么做"。**[来源:📚训练知识 | 置信度:📚中]

# 3.5 合规与用户体验

## 国内合规红线

### 个人信息保护法（PIPL）核心要求

| 要求 | 说明 | 触达策略影响 |
|---|---|---|
| 知情同意 | 收集/使用个人信息需用户明确同意 | Push授权弹窗不能强制要求；短信/邮件需用户主动订阅 |
| 最小必要 | 只收集和使用实现目的所需的最少信息 | 触达个性化不能过度使用非必要数据 |
| 目的限制 | 信息使用不得超出约定范围 | 营销用途需单独授权，不可与服务授权混同 |
| 退出权 | 用户有权撤回同意 | 每条营销消息必须提供便捷退订方式 |

> [来源:《个人信息保护法》2021年11月施行 | 置信度:🔍高]

### 工信部/通管局专项治理

- **端口短信治理**：营销短信需含"退订回T"，未提供退订即违规
- **App Push整治**：不可强制要求Push授权才能使用App核心功能
- **外呼管控**：需事先获得用户同意，不可对未授权用户AI外呼营销

> [来源:工信部2023-2025多轮专项整治 | 置信度:🔍高]

## 国际合规要点

### GDPR（欧盟）

- 必须事先获得**明确同意（Opt-in）**，默认Opt-out不合法
- 每条邮件必须含Unsubscribe链接
- 用户数据可携带、可删除（Right to be Forgotten）
- 罚款上限：全球营收4%或2000万欧元（取高者）

### CAN-SPAM（美国）

- 商业邮件必须包含退订机制
- 退订后10个工日内必须生效
- 邮件标题/发件人不可欺骗

> [来源:GDPR/CAN-SPAM法规原文 | 置信度:🔍高]

## 用户体验核心原则

### "用户感知三问"

1. **价值感**：用户收到这条消息后觉得"有用"还是"被扰"？
2. **控制感**：用户能否方便地管理自己收到的消息？
3. **尊重感**：消息频率是否让用户感觉被尊重而非被骚扰？

### 偏好中心设计

**最佳实践**：提供"消息偏好设置"入口，让用户自选：

| 设置项 | 选项 |
|---|---|
| 消息类型 | 交易通知✅ / 营销推送□ / 活动提醒□ / 个性化推荐□ |
| 频次 | 实时 / 每日摘要 / 每周摘要 |
| 渠道 | Push / 短信 / 邮件 / 仅站内信 |
| 免打扰时段 | 22:00-08:00 |

> [来源:📚训练知识 | 置信度:🔍高]

## 合规红线自查清单

| 检查项 | 通过标准 | 风险等级 |
|---|---|---|
| Push授权是否独立于核心功能 | 用户拒绝Push授权仍可使用App全部功能 | 🔴高 |
| 营销短信是否有退订方式 | 每条含"退订回T"并能即时生效 | 🔴高 |
| 邮件Unsubscribe | 每封含Unsubscribe链接，10工日生效 | 🔴高 |
| 海外用户合规 | GDPR区用户走Opt-in+数据本地化 | 🟡中 |
| 触达数据用途说明 | 隐私政策中明确说明触达数据用途 | 🟡中 |
| 偏好设置入口 | 产品内提供消息偏好设置 | 🟢低（体验优化） |

## 常见合规坑

1. **强制授权**：登录/支付必须开Push——违法（PIPL+App Store审核双重违规）
2. **退订不生效**：嘴上说"退订回T"但技术未实现/延迟生效——违法
3. **跨境触达**：对欧盟用户发营销邮件未经Opt-in——GDPR重罚
4. **暗模式**：退订按钮极小/灰色/需跳转3层——合规但丧失信任
5. **买手机号群发**：从第三方购买号码群发短信——违法（非合法获取+未授权）

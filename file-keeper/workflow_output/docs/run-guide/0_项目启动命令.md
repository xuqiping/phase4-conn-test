# 项目启动命令

> 本机环境：JDK 17、Maven 3.9.11、PostgreSQL 17.4 便携版、Node.js 24.11.1、Memurai（Redis 兼容）
>
> 路径以本机实际安装位置为准，下面是按当前项目环境的示例路径。

---

## 启动顺序

1. Memurai（Redis）
2. PostgreSQL
3. Java 后端
4. Tauri 桌面端
5. 管理后台（可选）

---

## 推荐：使用根目录脚本

在 `E:\workspace\file-keeper` 目录执行：

```powershell
# 启动：先检查各端口，已运行的组件自动跳过
powershell -ExecutionPolicy Bypass -File .\启动.ps1

# 关闭
powershell -ExecutionPolicy Bypass -File .\关闭.ps1

# 重启
powershell -ExecutionPolicy Bypass -File .\重启.ps1
```

`启动.ps1` 会依次检查并启动 Redis/Memurai、PostgreSQL、Java 后端和 Tauri 桌面端。后端和 Tauri 会各自打开可见的 PowerShell 日志窗口。

> 管理后台暂未纳入脚本，三个脚本执行结束时都会输出提醒。

---

## 1. 启动 Memurai（Redis）

**端口：6379**

**PowerShell 管理员**运行：

```powershell
Start-Service Memurai
```

如果提示服务名不存在，改用命令行方式（注意前面的 `&`）：

```powershell
& "C:\Program Files\Memurai\memurai.exe" --service-run
```

或者使用 `Start-Process`：

```powershell
Start-Process "C:\Program Files\Memurai\memurai.exe" -ArgumentList "--service-run"
```

## 2. 启动 PostgreSQL

**端口：5432**

```powershell
& "C:\Users\19536\.local\tools\pgsql\bin\pg_ctl.exe" -D "C:\Users\19536\.local\tools\pgsql\data" start
```

如果提示 `directory ".../data" does not exist`，先初始化 data 目录：

```powershell
& "C:\Users\19536\.local\tools\pgsql\bin\initdb.exe" -D "C:\Users\19536\.local\tools\pgsql\data" -U postgres --auth=trust
```

> `--auth=trust` 表示本地连接免密码，仅用于本地开发。如需设置密码，见下方「PostgreSQL 密码配置」。

然后再执行上面的 `pg_ctl start` 启动 PostgreSQL。

### PostgreSQL 密码配置

#### 初始化时设置密码

去掉 `--auth=trust`，使用 `-W` 交互式输入密码：

```powershell
& "C:\Users\19536\.local\tools\pgsql\bin\initdb.exe" -D "C:\Users\19536\.local\tools\pgsql\data" -U postgres -W
```

运行后会提示输入并确认密码。

#### 修改已有 postgres 用户密码

1. 启动 PostgreSQL。
2. 连接 postgres 数据库：

```powershell
& "C:\Users\19536\.local\tools\pgsql\bin\psql.exe" -U postgres -d postgres
```

3. 在 `postgres=#` 提示符下执行：

```sql
ALTER USER postgres WITH PASSWORD '你的新密码';
```

4. 按 `\q` 退出 psql。

5. 修改后端数据库密码配置（环境变量或 `application-dev.yml`）：

```powershell
$env:FILE_KEEPER_DB_PASSWORD="你的新密码"
```

> 注意：如果之前用 `--auth=trust` 初始化，改为密码认证还需要修改 `pg_hba.conf` 中的认证方式。最简单的方式是删除 data 目录重新 `initdb`。

---

### 首次启动：创建数据库

如果数据库 `file_keeper` 还没创建，执行：

```powershell
& "C:\Users\19536\.local\tools\pgsql\bin\createdb.exe" -h localhost -p 5432 -U postgres file_keeper
```

> 表结构由 Flyway 自动迁移，不需要手动建表。

## 3. 启动 Java 后端

**端口：8088**

```powershell
$env:FILE_KEEPER_JWT_SECRET="<请填写至少32字节的本地开发随机字符串>"
cd "E:\workspace\file-keeper\server"
& "C:\Users\19536\.local\tools\apache-maven-3.9.11\bin\mvn" spring-boot:run
```

> `FILE_KEEPER_JWT_SECRET` 必须至少 32 字节。请在本机生成开发用随机值，不要将真实密钥写入文档或提交到仓库。

---

## 4. 启动 Tauri 桌面端

**Vite dev server 端口：1420**

开一个新的 PowerShell 窗口：

```powershell
cd E:\workspace\file-keeper
npm run tauri:dev -- -- --bin file-keeper
```

> 项目同时包含桌面主程序 `file-keeper` 和 Office 隔离 Worker `office_ooxml_worker` 两个 Rust 二进制。`--bin file-keeper` 用于明确启动桌面主程序，避免 Cargo 因无法自动选择二进制而报错。Office Worker 由主程序按需调用，不需要手动单独启动。

---

## 5. 启动管理后台（可选）

**默认端口：5173（被占用时自动递增，如 5174）**

再开一个 PowerShell 窗口：

```powershell
cd c:\AI Projects\file-keeper\admin-web
npm run dev
```

## 停止服务

### 停止后端

在运行后端的 PowerShell 窗口按 `Ctrl + C`。

### 停止 PostgreSQL

```powershell
& "C:\Users\19536\.local\tools\pgsql\bin\pg_ctl.exe" -D "C:\Users\19536\.local\tools\pgsql\data" stop
```

### 停止 Memurai

```powershell
Stop-Service Memurai
```

## 常见问题

### `mvn` 不是内部或外部命令

把 `mvn` 换成完整路径：

```powershell
"C:\Users\19536\.local\tools\apache-maven-3.9.11\bin\mvn" spring-boot:run
```

### 后端启动报 `JWT secret must not be blank`

说明 `FILE_KEEPER_JWT_SECRET` 没设置成功，重新执行：

```powershell
$env:FILE_KEEPER_JWT_SECRET="<请填写至少32字节的本地开发随机字符串>"
```

### 后端启动报数据库连接失败

检查 PostgreSQL 是否已启动，以及 `file_keeper` 数据库是否存在。

### `cargo run` 无法确定要运行的二进制

如果看到以下报错：

```text
error: `cargo run` could not determine which binary to run
available binaries: file-keeper, office_ooxml_worker
```

说明启动命令没有指定桌面主程序。请在项目根目录执行：

```powershell
npm run tauri:dev -- -- --bin file-keeper
```

### 端口 5432 被占用

查看占用进程：

```powershell
Get-NetTCPConnection -LocalPort 5432 | Select-Object LocalPort, OwningProcess, @{Name="ProcessName";Expression={(Get-Process -Id $_.OwningProcess).ProcessName}}
```

停止对应进程（把 `<PID>` 换成上面查到的进程号）：

```powershell
Stop-Process -Id <PID>
```

如果之前用 `pg_ctl` 启动的 PostgreSQL 没停干净，也可以直接停止：

```powershell
& "C:\Users\19536\.local\tools\pgsql\bin\pg_ctl.exe" -D "C:\Users\19536\.local\tools\pgsql\data" stop
```

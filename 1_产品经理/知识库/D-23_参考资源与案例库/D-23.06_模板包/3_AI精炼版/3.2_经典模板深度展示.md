# 3.2 经典模板深度展示

> 10大经典模板6维全景展示——用途/核心字段/标准结构/适用场景/常见误区/示例片段。

## 模板1：PRD标准模板——PM日常交付最核心文档

| 维度 | 内容 |
|---|---|
| 用途 | 把"产品需求"结构化输出给研发/设计/QA可执行的标准化文档 |
| 核心字段 | 5个核心字段：①需求背景与目标 ②功能详述(用例/流程/规则) ③交互说明(原型/状态机/异常流) ④验收标准(功能/性能/兼容性) ⑤上线计划(灰度/数据/回滚) |
| 标准结构 | 1.文档元信息(版本/作者/干系人)→2.需求背景(问题/目标/价值)→3.用户故事与场景→4.功能详述(用例图+流程图+规则)→5.交互设计(原型+状态机)→6.数据埋点→7.非功能需求→8.验收标准→9.上线计划→10.风险与依赖 |
| 适用场景 | ①功能开发前需求传递 ②研发排期依据 ③QA测试依据 ④上线验收依据 |
| 常见误区 | ①只写"做什么"不写"为什么"=目标缺失 ②只写"快乐路径"不写异常流=研发踩坑 ③字段臃肿50+页=文档黑洞 ④只写功能不写埋点=上线无法验证 ⑤版本管理混乱=多人改无差异 |
| 示例片段 | **3.需求背景**<br>3.1 问题：当前用户下单转化率仅12%，行业均值18%<br>3.2 目标：通过"购物车推荐"提升下单转化率至15%<br>3.3 价值：预计月GMV提升约300万元<br>3.4 不做：不优化支付流程(下个迭代) |

## 模板2：竞品分析5维度模板——PM决策必备

| 维度 | 内容 |
|---|---|
| 用途 | 结构化拆解3-5个竞品+横评对比，输出"竞品在做什么/做得怎么样/我们怎么学/怎么超"的决策依据 |
| 核心字段 | 5个核心维度：①定位(目标用户/品类/价值主张) ②功能(核心功能/差异化功能/缺失功能) ③体验(关键路径/交互亮点/痛点) ④数据(用户规模/活跃/留存/营收) ⑤策略(获客/留存/变现路径) |
| 标准结构 | 1.竞品筛选(直接/间接/潜在)+理由 → 2.分维度横评矩阵(5维度×3-5竞品) → 3.关键洞察(每个竞品1-2个值得学) → 4.决策建议(学什么+超什么+不学什么) → 5.跟进机制(季度更新) |
| 适用场景 | ①新品立项前竞品摸底 ②季度竞品跟进 ③功能立项前竞品差异分析 ④产品定位调整 |
| 常见误区 | ①只罗列功能不做横评=无效信息堆砌 ②只看直接竞品忽视间接/潜在竞品=被降维打击 ③只截屏不量化数据=无法决策 ④"抄袭式"竞品分析=失去战略洞察 ⑤一次性分析无跟进机制=过期资料 |
| 示例片段 | **决策建议**<br>1.学：竞品A的"购物车优惠券叠加展示"(提升交叉销售)<br>2.超：竞品B"仅2人客服响应"痛点，用AI客服批量响应<br>3.不学：竞品C"满屏弹窗"(影响体验) |

| 维度 | 内容 |
|---|---|
| 用途 | 把"模糊的目标用户"具象化成"可决策的画像"，用于需求判断/优先级取舍/文案调性 |
| 核心字段 | 7个核心字段：①基础(年龄/性别/地域/职业/收入) ②行为(使用场景/频次/路径) ③需求(显性需求/隐性需求) ④痛点(决策阻力/使用摩擦/心理负担) ⑤场景(时间/地点/任务/工具) ⑥价值观(消费观/审美/身份认同) ⑦决策(决策权/信息源/决策因素) |
| 标准结构 | 1.画像概述(姓名/头像/一句话标签/真实性说明) → 2.7字段结构化描述 → 3.典型场景剧(3-5个核心场景的剧本化叙事) → 4.使用说明(什么决策该参考本画像) |
| 适用场景 | ①需求评审用画像佐证 ②文案/调性参考画像 ③功能优先级取舍 ④新人入职理解用户 |

| 示例片段 | **画像概述**<br>姓名：王小勤 ｜ 标签："35岁二孩妈妈的精打细算"<br>1句话："下班路上刷20分钟小红书找晚餐灵感，最看重快手和性价比"<br>真实性：基于50位深度访谈+行为数据聚合 |

## 模板4：数据报告3层5维度模板——PM数据沟通

| 维度 | 内容 |
|---|---|
| 用途 | 把"散乱数据"结构化为"可决策的数据报告"，让老板/团队从数据快速得出行动 |
| 核心字段 | 3层(总览/趋势/异常)+5维度(规模/质量/转化/留存/价值) |
| 标准结构 | 1.总览层(1页核心KPI+趋势+异常) → 2.趋势层(关键指标90天趋势+对比) → 3.异常层(异常事件归因+建议) → 4.5维度细分(规模/质量/转化/留存/价值) → 5.行动建议(3-5条具体行动) |
| 适用场景 | ①周/月数据汇报 ②功能上线后效果复盘 ③KPI告警归因 ④战略决策数据支撑 |
| 常见误区 | ①只罗列数字不解读=老板看不懂 ②只看总量不看趋势=错过拐点 ③只看快乐指标不看异常=粉饰太平 ④5维度都讲一遍=超载 ⑤无行动建议=报告=无用 |
| 示例片段 | **总览层(1页)**<br>- 月活350万(环比+5%) ✅达成目标<br>- 次日留存32%(环比-3pt) ⚠️未达成<br>- GMV1.2亿(环比+18%) ✅超目标<br>**异常**：留存下降，归因→新用户获取渠道低质；建议→调整获客结构 |

## 模板5：GRAI复盘4步法模板——PM沉淀经验

| 维度 | 内容 |
|---|---|
| 用途 | 把"个人经验"沉淀为"团队方法论"——总结规律而非停留于"做完就走" |
| 核心字段 | GRAI 4步：①Goal(回顾目标：当时想达成什么) ②Result(评估结果：实际达成了什么+差距) ③Analysis(分析原因：为什么达成/为什么没达成) ④Insight(总结规律：能复用的方法论/教训) |
| 标准结构 | 1.Goal：明确当时目标+自信度  → 2.Result：实际结果+量化对比+差距  → 3.Analysis：达成的3条原因+未达成的3条原因+关键变量  → 4.Insight：3条可复用方法论+3条待改进+下次行动清单 |
| 适用场景 | ①功能上线后复盘 ②项目阶段复盘 ③季度OKR复盘 ④失败事件复盘 |
| 常见误区 | ①只做"罗列"不做"分析"(只总结不归因) ②只看"个人"不看"团队"(只个人学不沉淀) ③只看"成功"不看"失败"(幸存者偏差) ④Insight太抽象不落地(无下次行动) ⑤变成"追责会"而非"复盘会" |
| 示例片段 | **Analysis**：达成原因3条→①获客渠道精准 ②文案与目标用户匹配 ③上线节点合适；未达成原因3条→①冷启动慢 ②低估SEO建设 ③客服承接不足；关键变量：冷启动期投入决定后续走势 |

## 模板6：Now-Next-Later路线图模板——PM规划工具

| 维度 | 内容 |
|---|---|
| 用途 | 把"模糊的长线规划"结构化为"清晰可视化的Now-Next-Later三栏路线图"，避免假装精确的甘特图 |
| 核心字段 | 3栏：①Now(本季度·正在做) ②Next(下季度·即将做) ③Later(未来2-4季度·考虑做) |
| 标准结构 | 1.愿景/北极星 → 2.战略主题(MTM矩阵，2-3个主题) → 3.Now栏(5-7项·有具体目标) → 4.Next栏(5-7项·大方向) → 5.Later栏(5-10项·待评估) → 6.依赖与风险 |
| 适用场景 | ①季度/年度产品规划 ②向上汇报产品方向 ③团队对齐优先级 ④对外发布产品计划 |
| 常见误区 | ①假装精确(甘特图假装3年后精确到周) ②只排功能不排战略主题 ③没有依赖与风险评估 ④路线图变"承诺图"(不敢改) ⑤Later栏过细(变开发计划) |
| 示例片段 | **战略主题**：①提升用户价值(留存) ②商业化破局(收入)<br>**Now(Q3)**：购物车推荐提升转化率15%→17%(已立项)<br>**Next(Q4)**：会员体系V2设计(大方向已定)<br>**Later(2027H1)**：AI个性化推荐(探索中) |

## 模板7：5步法SOP模板——PM流程沉淀

| 维度 | 内容 |
|---|---|
| 用途 | 把"凭感觉的工作"沉淀为"可培训的标准化作业流程" |
| 核心字段 | 5步：①目的(为什么有这个SOP) ②范围(适用什么/不适用什么) ③角色(谁参与·RACI) ④步骤(分步骤操作) ⑤异常(异常情况如何处理) |
| 标准结构 | 1.目的(1句话) → 2.范围与不适用 → 3.角色矩阵(RACI：执行/负责/咨询/告知) → 4.分步骤操作(每步骤有"输入/动作/输出/工具/时间") → 5.异常处理预案 → 6.附泳道图 |
| 适用场景 | ①新人入职SOP ②需求评审SOP ③上线SOP ④变更管理SOP ⑤客服响应SOP |
| 常见误区 | ①只写步骤不写"目的"和"范围"(无法判断何时用) ②无角色矩阵(出了问题不知道找谁) ③无异常处理(发生异常无预案) ④步骤过细(失去灵活性) ⑤SOP不更新(过期失效) |
| 示例片段 | **步骤1：需求立项**<br>1.1 输入：业务方提案<br>1.2 动作：PM评估提案→归类(立项/暂缓/拒绝)<br>1.3 输出：立项决策文档<br>1.4 工具：Jira<br>1.5 时间：3个工作日内 |

| 维度 | 内容 |
|---|---|

| 核心字段 | 5要素：①议题(讨论了什么) ②决议(达成了什么) ③行动项(接下来做什么) ④责任(谁负责) ⑤日期(什么时候完成) |
| 标准结构 | 1.会议元信息(主题/时间/参会人/缺席人) → 2.议题列表(每议题有"讨论+决议") → 3.行动项清单(负责人+截止日期) → 4.遗留问题 → 5.下次会议预告 |

| 示例片段 | **行动项清单**<br>1.张三负责撰写PRD-V2版本，截止9月15日<br>2.李四负责UI原型设计，截止9月20日<br>3.王五负责技术评估，截止9月18日 |

## 模板9：OKR 3-5KR模板——PM目标管理

| 维度 | 内容 |
|---|---|
| 用途 | 把"模糊目标"结构化为"可量化可追踪的OKR"(Objective+Key Results) |
| 核心字段 | O(目标·方向性) + 3-5个KR(关键结果·可量化) + 自信度(70%) |
| 标准结构 | 1.Objective：方向性描述(鼓舞人心) → 2.KR1-5：可量化指标(数值/百分比/时间节点) → 3.自信度：每个KR设自信度(70%=激励性目标) → 4.关联：KR与北极星指标关联 → 5.复盘节点：月中check/月末review |
| 适用场景 | ①季度目标设定 ②个人OKR ③团队OKR对齐 ④战略主题拆解 |
| 常见误区 | ①O写成具体指标(混淆O与KR) ②KR不可量化(无数字) ③KR设定过低(自信度100%)=无挑战 ④KR设定过高(自信度30%)=无激励 ⑤OKR变KPI(失去激励导向) |
| 示例片段 | **O**：让小红书成为新国货美妆首选种草平台<br>**KR1**：Q4小红书种草笔记数达5万篇(基线2万)自信度70%<br>**KR2**：素人×腰部KOC投放ROI提升至4.0(基线2.5)自信度70%<br>**KR3**：小红书→天猫转化率达12%(基线8%)自信度60% |

## 模板10：Agent 8段元提示词模板——2025-2026 PM新兴工具

| 维度 | 内容 |
|---|---|
| 用途 | 把"模糊的Agent需求"结构化为"工程化可调测的元提示词"——AI Agent时代PM必备工具[来源:Anthropic OpenAI 2026 | 置信度:📚中] |
| 核心字段 | 8段：①当前时间(防止幻觉过期) ②红线(防止越界) ③Background(注入知识精华) ④Role(性格化警惕点) ⑤Objective(目标) ⑥Key Results(可检验) ⑦Steps(think step by step) ⑧输出格式(JSON/MARKDOWN) |
| 标准结构 | 1.今天{{日期}} → 2.### 红线(N条禁止) → 3.### Background(背景与注入知识) → 4.### Role(角色+性格化警惕) → 5.### Objective(目标) → 6.### Key Results(可检验结果) → 7.### Steps(think step by step分步) → 8.### 输出格式(JSON或MARKDOWN代码块) |
| 适用场景 | ①Agent工程PM设计系统提示词(本知识库D-24配套) ②日常ChatGPT/Claude结构化使用 ③多Agent协作通信模板 ④Agent评测调试 |
| 常见误区 | ①缺"时间"段(模型数据过期) ②缺"红线"段(越界幻觉) ③Role不"性格化警惕"(只是描述身份=失效) ④Key Results不可量化(无法检验) ⑤Steps无"think step by step"(无分步推理) ⑥输出格式不结构化(无法下游解析) |
| 示例片段 | **### Role**<br>你是一位深研XX15年的「XX专家 + XX风控师」...<br>你有3个性格化警惕点：①对XX警觉 ②对XX偏执 ③对XX敏感...<br>**### Key Results**<br>1.XXX(可检验)<br>2.XXX(可检验)... |

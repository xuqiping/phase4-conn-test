# 01 - 认证与登录

## 功能简介

- 安全：
  - [SecurityConfig.java](../../backend/src/main/java/com/superprogrammer/auth/security/SecurityConfig.java) — Spring Security 配置

- DTO：`auth/dto/` LoginRequest、RegisterRequest、RefreshTokenRequest、LogoutRequest、TokenResponse、UserVO

## 钉钉 H5 微应用免登（可选）
双路径：**容器内 JSAPI 免登**（本地可调，主路径）+ **外部浏览器 OAuth2 降级**（需公网域名）。

### 流程
- **容器内（推荐）**：钉钉容器内打开 H5 → `dd.runtime.permission.requestAuthCode({corpId})` 静默拿 `authCode` → POST `/api/auth/login/dingtalk` `{authCode, source:"jsapi"}` → 后端 oapi 老链路换 `unionId` → 查/建本地用户 → 签 JWT。**不跳转、不扫码、不要 redirect_uri/公网域名**。
- **外部浏览器降级**：跳 `login.dingtalk.com/oauth2/auth` → 钉钉带 `authCode` 回 `/dingtalk/callback` → POST 同端点 `{authCode, source:"oauth2"}` → 后端 `/v1.0/oauth2/userAccessToken` 换 `unionId`。需公网 https 回调域名进钉钉「登录回调域名」白名单，**localhost 不可用**。

### 后端
- 控制器：[DingTalkAuthController.java](../../backend/src/main/java/com/superprogrammer/auth/dingtalk/controller/DingTalkAuthController.java) — `POST /api/auth/login/dingtalk`，按 `source` 分流。
- DTO：`DingTalkLoginRequest`（`authCode` + `source: jsapi|oauth2`）。
- 服务：[DingTalkService.java](../../backend/src/main/java/com/superprogrammer/auth/dingtalk/service/DingTalkService.java)
  - `exchangeUserByOapi(authCode)` — 容器免登码走 oapi：`appKey/secret → /gettoken`（企业 access_token，缓存 2h）`→ /topapi/v2/user/getuserinfo {code} → userid` `→ /topapi/v2/user/get {userid} → unionId/name/dept_id_list`，逐个 `/topapi/v2/department/get` 拉部门名。
  - `exchangeUser(authCode)` — OAuth2 码走 `/v1.0/oauth2/userAccessToken` + `/v1.0/contact/users/me`。
  - `DingTalkUserInfo(unionId, openId, nick, avatar, depts)`；`DingTalkDept(deptId, name)`。
- 配置：[DingTalkProperties.java](../../backend/src/main/java/com/superprogrammer/auth/dingtalk/config/DingTalkProperties.java)（`dingtalk.enabled/app-key/app-secret/agent-id`，env `DINGTALK_*`）。
- 业务：`AuthService.loginByDingTalk()` — unionId 查/建号（存 `name`=钉钉 nick，`password` 填随机占位 hash 因列 NOT NULL），分配 `user` 角色，**自动同步部门** `DepartmentService.syncUserDepartmentsFromDingtalk`（见 [02-用户与部门管理](02-用户与部门管理.md)），签 JWT。
- 白名单：`SecurityConfig` 放行 `/api/auth/login/dingtalk`。
- 全程 `[DingTalk]` 日志（appKey/secret 掩码）。

### 前端
- 工具：[dingtalk.ts](../../frontend/src/utils/dingtalk.ts) — `isDingTalkClient()` / `requestDingTalkAuthCode()`（JSAPI）/ `redirectToDingTalkAuth()`（OAuth2 降级）。
- 登录页：[LoginView.vue](../../frontend/src/views/LoginView.vue) `onDingTalkLogin` 分流：容器内→JSAPI 拿码直传后端（`source:'jsapi'`）；外部→OAuth2 降级。
- 回调页：[DingTalkCallbackView.vue](../../frontend/src/views/DingTalkCallbackView.vue)（仅 OAuth2 降级路径用，路由 `/dingtalk/callback`）。
- API：[auth.ts](../../frontend/src/api/auth.ts) `dingTalkLogin(authCode, source)` / store `loginByDingTalk(authCode, source)`。
- 前端 env：`VITE_DINGTALK_APP_KEY` / `VITE_DINGTALK_CORP_ID`（容器 JSAPI 必填）/ `VITE_DINGTALK_REDIRECT_URI`（OAuth2 降级用）。

### 数据表
- V41：`users` 加 `bind_type / dingtalk_union_id（唯一部分索引）/ dingtalk_open_id`。
- V46：`users.name`（显示名=钉钉 nick）+ `departments.dingtalk_dept_id`（钉钉部门映射，部分唯一索引）。详见 [02-用户与部门管理](02-用户与部门管理.md)。

### 排坑
- **「应用不存在」**：容器内走 JSAPI 不再触发；若 OAuth2 降级报此错，应用未发布/未装到企业/appKey 非网页应用。
- **`invalidParameter.authCode.notFound`**：企业内部应用把 JSAPI 免登码喂给了 `/oauth2/userAccessToken`（只认 OAuth2 码）。已修：JSAPI 码走 oapi。
- **`errcode=88 / qyapi_get_member`**：应用缺通讯录权限，钉钉开放平台「权限管理」申请 `qyapi_get_member`。
- **JWT `Base64 incorrect ending byte`**：env 注入 secret 带尾部 `\r`/空格；`JwtUtil.getSigningKey` 已 `trim()` + 非 base64 fallback。

## 真实邮箱接入 + 安全加固（12x，2026-08-22）

### 端点
- `POST /api/auth/register/email-code`（公开）：注册邮箱 6 位码发送。通道未开启→400（注册暂停）；邮箱已注册→409；同邮箱 60s 重发 + IP 10封/h + 全局日封顶。
- `POST /api/auth/register`：`email`+`emailCode` 必填；码过才建号，EMAIL 凭证直接 `verified=TRUE`（注册后激活链接对注册下线，链接验证保留给改绑）。

### 服务与键
- 发信抽象：`auth/service/mail/MailSender`（ALIYUN/SMTP 双实现），`EmailService` 按 `auth.channel.mail.provider` 路由；SMTP 配置键 `auth.channel.mail.smtp-*`（密码 AES 落库）。
- 反轰炸：`MailSendQuotaService` — `mailsend:ip:{ip}` 10/h + `mailsend:daily:{yyyyMMdd}` 日封顶（`auth.channel.mail.daily-cap` 默认 500）。
- 注册码：`regcode:email:{email}` 10min TTL + `regcode:try:{email}` 错5次作废 + `regcode:resend:{email}` 60s。
- 渐进式滑块（B2）：`ProgressiveCaptchaGuard` — `captcha:need:{scope}:{key}` 30min 窗，连续失败 ≥2 触发，成功清零；触发未带 token → 40107「请先完成滑块验证」。scope/key：login=用户名；register/forgot/mailcode=IP。DTO 均带可选 `captchaVerification`。
- B4：重置密码成功 → 给已验证邮箱发告警信；改绑邮箱（账号已绑 TOTP）强制两步码。
- B5：`PaymentOrderService.createOrder` 前置闸——无 verified EMAIL 凭证 → 400。

### 前端
- 注册弹窗：邮箱验证码行 + 获取验证码 60s 倒计时（RegisterModal.vue）。
- 滑块闸：登录/注册/找回三处复用 SliderCaptcha.vue，40107 触发展示，token 单次消费后强制重滑。
- `api/request.ts`：业务错误对象挂 `code`（40107 等供 UI 分支）。
- 充值弹窗：邮箱门槛话术命中 → 「去绑定邮箱」直达链接。

### 排坑
- **邮件通道未开启 = 注册整体暂停**（发码 400，刻意保护）；上线前先在 设置→认证通道→邮件通道「测试发信」再开开关。
- 日封顶触发 `log.error`（`MailSendQuotaService`）——接告警防通道被盗轰炸。
- 滑块 40107 与登录 401 不同码：前端靠 `err.code` 分支（request.ts 已挂）。

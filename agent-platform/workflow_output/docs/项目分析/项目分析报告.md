# 项目分析报告 · 多 Agent 智能体平台（SuperCoder Agent Hub）

> Phase 0 商业前置分析产物。决定「值不值得做」。
> 来源：既有 `项目工程文档/项目整体说明.md`、`0_项目思想.md`、`需求/产品需求文档PRD.md`。
> **文档规模**：≤5000 tokens。

## 1. 一句话定位
面向软件工程全生命周期的**多 Agent 低代码编排平台**——像 App Store 一样发现 Agent、像 Figma 一样编排工作流，把 Agent / 工作流 / Skill 串成 DAG（有向无环图，工作流的底层数据结构）自动执行。

## 2. 背景与动机
- 现有平台 Agent/工作流泛滥、质量参差，用户难选；本项目主张「每个方向只保留一个顶尖 Agent」。
- 个人/团队缺统一的软件工程自动化与质量管控工具。
- Token 厂商聚合、按推理强度智能分流的诉求增长。
- 需把「超级程序员 Agent」从命令行升级为可视化、可协作的 Web 平台。

## 3. 目标受众（国内中小研发团队 10–200 人）
| 角色 | 画像 | 占比 |
|---|---|---|
| 开发者 | 28 岁全栈，个人项目为主 | 65% |
| 团队负责人 | 35 岁技术 Leader，管 8 人 | 25% |
| 企业管理员 | 42 岁 CTO，管 50 人 | 10% |

## 4. 竞品与差异化
| 竞品 | 定位 | 本项目差异化 |
|---|---|---|
| Dify | 通用 AI 应用平台 | 聚焦**软件工程垂直场景**，非通用对话 |
| n8n | 通用自动化工作流 | 15 预置专业 Agent + 51 项工程检查清单，开箱即用 |
| Coze | Bot 搭建 | 不做 Bot 市场/通用对话/IDE 插件 |

**核心优势**：15 预置专业 Agent + 51 项工程检查清单（风格23/安全15/性能13），面向研发团队标准化流程。

## 5. 商业模式 / 变现
文档未明确定价，潜在方向：
- Token 厂商聚合 + 按推理强度渠道分流。
- Agent + 工作流 + 生图/画布落地解决方案。
- PRD V2.0 远期：多租户数据隔离（企业版独立库）、Agent 市场（上传交易），为企业版/抽佣预留。

## 6. 成功指标
| 目标 | 指标 | MVP 目标值 |
|---|---|---|
| 用户获取 | 注册用户 | 100（内测） |
| 用户激活 | 首周创建工作流 | ≥1 个/用户 |
| 用户留存 | 4 周留存 | ≥40% |
| 核心价值 | 工作流执行成功率 | ≥85% |

技术指标（见 PRD 非功能需求）：API P95 ≤500ms、LCP ≤2.0s、可用性 99.5%。

## 7. 技术选型结论（详见 `项目工程文档/设计/技术选型.md`）
- 后端 Spring Boot 3.2.5 / Java 17 / MyBatis-Plus（模块化单体，非微服务——1-3 人团队包结构即可）。
- 图编排交 Python LangGraph sidecar（Java 生态无对等图引擎），叶节点回调 Java 执行。
- PostgreSQL 16 + pgvector + JSONB（配置灵活字段）。
- 前端 Vue 3 + Vue Flow + Pinia + Vite（评分矩阵均最高）。

## 8. 结论：值得做
垂直场景明确、技术选型有评分依据、差异化（检查清单 + 垂直 Agent）清晰。MVP 范围（F1–F11）已落地，可进入迭代打磨期。

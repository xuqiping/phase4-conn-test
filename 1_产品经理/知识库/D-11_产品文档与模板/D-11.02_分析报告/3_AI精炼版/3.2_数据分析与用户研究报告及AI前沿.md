# 3.2 数据分析与用户研究报告及AI前沿

## 基础层：数据分析报告标准结构

### 报告七段结构

| 段落 | 内容 | 常见遗漏 |
|---|---|---|
| 1.分析背景与问题 | 业务问题/分析目标/相关指标/时间范围 | ❌ 没说清楚"回答什么问题" |
| 2.数据说明 | 数据来源/口径/时间窗口/样本量/局限性 | ❌ 不交代数据口径——结论无法复现 |
| 3.核心发现 | 3-5条关键发现，每条有数据支撑 | ❌ 发现太多=没发现——聚焦3-5条 |
| 4.深入分析 | 拆解/归因/细分/对比，层层递进 | ❌ 只有描述没有归因——"下降20%"不如"因XX渠道减少导致下降20%" |
| 5.业务解读 | 发现意味着什么？对业务的影响？ | ❌ 数据→结论跳步——缺少解读链 |
| 6.行动建议 | 基于发现的具体行动项+优先级+预期效果 | ❌ 有数据无行动——报告停在洞察层 |
| 7.附录 | 完整数据表/SQL/计算过程/置信区间 | ❌ 不附原始数据——无法审计 |

### 结论-行动链

好的数据分析报告不是"数据→发现"，而是"数据→发现→解读→行动"完整链条：[来源:woshipm数据分析方法论 | 📚中]

```
数据：DAU下降15%
↓
发现：新用户次日留存从42%降至31%
↓
解读：新用户Onboarding流程改版后，关键引导步骤跳过率从12%升至38%
↓
行动：恢复引导步骤+AB测试新方案，目标7天内留存恢复至40%
```

### 数据置信度标注规范

| 置信度 | 标注 | 含义 |
|---|---|---|
| 🔍高 | 数据来自内部埋点，口径清晰，样本充足 | 可直接作为决策依据 |
| 📚中 | 数据来自第三方/推算，口径可能有偏差 | 作参考，建议补充验证 |
| 📉低 | 数据来自估算/小样本/口径不明 | 仅作方向参考，不建议直接决策 |

## 进阶层：数据分析报告的进阶技巧

### 从描述到归因的进阶

| 层级 | 示例 | 价值 |
|---|---|---|
| L1描述 | "DAU下降15%" | 低——描述现象 |
| L2拆解 | "DAU下降15%，其中新用户下降30%/老用户下降5%" | 中——定位问题区 |
| L3归因 | "DAU下降15%，因渠道A投放削减导致新用户下降30%" | 高——找到原因 |
| L4预测 | "如维持投放策略，预计下周DAU继续下降至X" | 极高——预判未来 |
| L5决策 | "建议追加渠道A投放50%+启动渠道B测试，预计DAU恢复至X" | 最高——驱动行动 |

### 实验报告专项

数据分析报告的特例——实验报告（AB测试报告）需额外包含：[来源:D-06.04实验方法→D-11.02报告输出]

| 要素 | 内容 |
|---|---|
| 实验假设 | 我们假设改变X会导致指标Y变化Z |
| 实验设计 | 分组/流量/时长/最小可检测效应(MDE) |
| 结果呈现 | 指标变化值+置信区间+p值+效应量 |
| 结论判断 | 统计显著?业务显著?决策:全量/继续实验/放弃 |
| 后续计划 | 基于实验结果的下一步行动 |

## 基础层：用户研究报告标准结构

### 报告六段结构

| 段落 | 内容 | 常见遗漏 |
|---|---|---|
| 1.研究背景与目标 | 为什么要做研究/核心研究问题/决策场景 | ❌ 没说清楚"回答什么问题" |
| 2.研究方法 | 定性/定量/混合/样本/招募标准/执行过程 | ❌ 不交代方法——别人无法评估结论可靠度 |
| 3.画像与旅程 | 用户画像/用户旅程/关键触点/痛点地图 | ❌ 只有零散发现，缺乏系统画像 |
| 4.核心洞察 | 3-5条高价值洞察，每条有研究证据支撑 | ❌ 洞察太泛——"用户希望体验更好"不是洞察 |
| 5.产品建议 | 基于洞察的具体产品改进建议+优先级 | ❌ 有洞察无建议——用研停在理解层 |
| 6.局限与后续 | 研究局限/未覆盖问题/后续研究计划 | ❌ 不交代局限——过度推论 |

### 洞察提炼方法

好的洞察 = 现象 + 归因 + 机会：[来源:IDEO设计思维 | 🔍高]

```
❌ 差的洞察："用户觉得注册流程太长"
✅ 好的洞察："用户在注册第3步（企业认证）流失率68%（现象），因信息字段过多且无法保存草稿（归因），建议拆分认证步骤+增加草稿保存功能（机会）"
```

## 组合层：三类报告的跨维度组合

- 竞品报告+数据报告：用数据验证竞品动作效果（"竞品X上线功能Y后DAU变化？"）
- 竞品报告+用研报告：用研验证竞品用户的真实需求（"竞品用户是否真的需要这个功能？"）
- 数据报告+用研报告：数据找现象+用研找原因（"DAU下降为什么？用研发现是XX体验问题"）
- 三报告联动：竞品看外部+数据看内部+用研看用户→形成完整决策依据

## 反面·边界·灰度

### 反面：分析报告三大坑

1. **数据堆砌无洞察**：50页PPT全是数据→报告价值=0，洞察数>数据量
2. **结论无行动**：分析完了没有"所以呢"→报告停在认知层，不驱动执行
3. **用研替代决策**：用研提供输入不替代决策——"用户说想要"≠"我们应该做"

### 边界：报告 vs 方法论

- 数据分析报告(D-11.02)≠数据分析方法(D-06.03)——前者是"怎么写报告"，后者是"怎么做分析"
- 用户研究报告(D-11.02)≠用户研究方法(D-03)——前者是"怎么写报告"，后者是"怎么做研究"
- 竞品分析报告(D-11.02)≠竞品分析方法(D-04.02)——前者是"报告交付物"，后者是"分析方法论"

### 灰度：AI生成报告的信任边界

| 场景 | 可信度 | 建议 |
|---|---|---|
| AI辅助数据采集与格式化 | 🔍高 | 直接使用+标注AI生成 |
| AI生成结构化分析框架 | 📚中 | 使用框架+人工填充判断 |
| AI生成战略层结论 | 📉低 | 人工复核+标注置信度 |
| AI生成行动建议 | 📉低 | 必须人工判断——AI不懂组织上下文 |

## 为什么替换旧模型(死结)

旧 `user_memories` 单表 = 一个事实一行,靠 LLM 自由命名 `memory_key` 归一。五个死结:
1. **key 不稳定**:同概念不同 key→矛盾共存;旧 key 归一靠 extract 注入白名单补救,治标。
2. **无时间线**:时序事实(住址变迁)只能 value 字符串 hack,KEEP_BOTH 手工拼日期。
3. **召回靠枚举**:4 模式都在 key/value 字面+向量上做文章,「带家人出去玩」召回不到「配偶名」——语义判断交给词袋,永远列不全。
4. **共享撞墙**:V33 纯可见性→V34 home 混合,越补越复杂,撞唯一索引 bug 反复。
5. **无提炼层**:800 条爱好对话灌 800 行进 prompt,token 爆炸无压缩。

新模型从根换:**标签独立表+写时归一(禁手动并拆)+流水账为主体+总结提炼层+共享走流水账多挂**。

## 核心数据模型设计(一期 9 表 + 1 扩列；二期 +4 组新表)

设计原则 = **主体不是「事实」是「流水账」**,事实抽取层(L0/L1/L2)挂在流水账上,总结是流水账的压缩层。

| 表 | 职责 | 设计 why |
|---|---|---|
| `memory_tags` | 标签库(subject:topic+label+aliases+anchor 三列) | 标签独立成表,写时归一,**禁手动归并/拆分/重抽**(误并不可逆,已生成 summary 的 tag_id 漂移);仅 owner 改 label/补 aliases,tag_id 不变 |
| `memory_turns` | 流水账(一轮对话 INPUT/OUTPUT 各一条,raw+L0/L1/L2) | 全量留痕为主体。【二期变更】**纯个人域**:一期 `project_ids[]` 多挂共享 / `born_personal` 出身定死 / `departed·deleted_project_ids[]` 保交接四列已 **V67 DROP** |
| `memory_summaries` | 总结提炼层(L1/L2+provenance+链式) | 压缩层治 token 爆炸;`project_id` 单值**不可挂项目数组/不可分享**(总结是个人提炼,非可共享原始料) |
| `memory_summary_coverage` | 覆盖(某作者某 turn 某 tag 某 scope 被其总结吃进) | `UNIQUE NULLS NOT DISTINCT`(PG 默认 NULL≠NULL,个人 scope project_id=NULL 约束会失效);**召回只认 user_id=召回者自己**的 coverage(恒只读自己总结,防污染) |
| `memory_project_members` | 记忆专属成员(角色+ACTIVE/DEPARTED) | 独立于 Agent 模块 `project_members`(不动旧表);离职置 DEPARTED 不删行。【二期变更】DEPARTED 语义改为**直接失条目读权**(不再有召回标注) |
| `memory_project_settings` / `memory_project_user_settings` | owner 项目级 gen / 会员覆写 gen | gen 走 AND(二者皆开才生成),会员本人自控覆写 |
| `memory_consolidation_scopes` | 用户自动总结 scope 勾选 | 解耦:总结(低频每天一次压缩)不绑 gen(高频每条对话一次生成) |
| `memory_notifications` | 跨用户波及(SUMMARY_AFFECTED_BY_RECALL;二期 +LINK_REQUEST/LINK_RESULT) | flat provenance 整条级 STALE 重生必波及他人,须通知;授权链发起/结果通知复用此表。【二期变更】PROJECT_DELETED_AFFECTED 类型随 V67 消亡 |
| `memory_conflicts`(扩列) | 加 tag_id+summary_id | 冲突**只来自总结层时序互斥**(非跨用户编辑),无 type 列 |
| ~~`memory_recall_acl`~~ | 【二期已废】项目流水账读取授权(reader→target) | **V67 DROP**。一期「owner 兜底全读+按 ACL 授权集」五路径模型随 turns 个人域化整体废弃 |
| **二期** `memory_project_rules` | 项目收录规则(V65) | 项目对话哪些内容值得进项目记忆:anchor 同步算/embed 失败强制停用;负例仅 owner 可见 |
| **二期** `memory_project_entries` | 项目记忆条目(V65) | 项目可读单元:收录规则粗筛 → LLM 精判(零 LLM 护栏+三档分流+黑名单二次扫描) → 蒸馏落库 → owner 审核(approve/reject/withdraw) |
| **二期** `memory_project_links` | 项目授权链(V68) | 跨项目共享:发起/审批/撤销状态机+条件 UPDATE 防并发+30 天防刷+复活语义;召回时 ACTIVE 链 child 条目单级一跳并入(降级仅成员) |
| **二期** `memory_asset_memories` / `memory_asset_chunks` | 记忆资产(V69) | 资产级记忆+分块(P3 进行中) |

放弃字段:`is_global`/`home_project_id`/`memory_key`/`memory_key_zh`/`block_label`/`confidence`/value 向量。新模型无全局可见、无 home、标签独立成表、anchor 挂 `memory_tags`。

## 记忆生成(L0/L1/L2 + 前置过滤 + gen 开关)

**一轮对话 = 1 INPUT + 1 OUTPUT,一次 LLM 出双侧三层**(L0 标签 `主体:主题`,主体默认「我」/ L1 一句概要 / L2 结构化详述)。三层同生同灭,单 `gen_done` 标记。

**前置过滤(不调 LLM,按侧独立判定)** why:AI 尾部客套「希望对你有帮助」连坐丢失 INPUT 事实。故 INPUT/OUTPUT **各侧独立跳过**:过短/纯标点/纯确认/致谢跳 INPUT;纯套话/免责声明/重复致歉跳 OUTPUT;敏感黑名单(密码/支付/验证码/身份证/银行卡/token,**预置默认开箱即用,用户只能加项不能清空**)命中即跳该侧。两侧都跳→不调 LLM 也不写 raw;仅一侧跳→仍调一次出未跳侧。

**gen 开关(方案 A per-project,默认开,三层同开同关)**:项目对话生成 = owner 项目级 AND 会员个人覆写(默认开,会员自控)。任一关→不调生成 LLM,仍跑前置过滤,过过滤侧写 raw(`gen_done=false`,tag/L1/L2 空)。**非项目会话读全局兜底 `rag.memory.gen.personal.enabled`**。每项目顶端说明条明示代价+一键关。

**raw 透明化与遗忘权**:gen 关态首条对话写 raw 前非阻塞强提示;raw TTL 90 天按 `gen_done=false AND age>90d` 软删整行(已生成 turn 的 raw_content 随 turn 保留,避免 source_turn_ids 悬空)——**待确认:全库无对应 @Scheduled worker,该 TTL 清理疑未实现**;raw 在线查看/批量删(仅本人,无导出)。

## 召回 pipeline(七步+二期 ①.5 合流步,核心算法)

```
① 过滤: scopes(用户多选) × timeWindow × direction
①.5 【二期】项目条目合流: 本项目 APPROVED 条目并入(成员即可读,DEPARTED 失读权)
      + ACTIVE 授权链 child 项目条目单级一跳并入(降级仅成员),viaAuthorizedLink 瞬态标
② 聚合标签: scope 内 summary(status≠STALE)与 turn 的 tag_ids join memory_tags
            → (subject,topic) 跨 user 去重 DISTINCT
            scope 外 turn/summary 关联不到的 tag 不进聚合(防标签名泄敏)
③ LLM 选标签: 标签<30 全灌; >30 anchor 向量+BM25 RRF 粗筛 top-30 → LLM 精选 T
④ 优先读总结: findSummariesByTagAndScope(T,scope,timeWindow)
              只召回 user_id=自己的总结(他人总结不召回,防污染)
⑤ 读哪层(分支): 总结>5 → 读全部 L1 → reflect(批量1次 LLM)选需深读子集 → 仅展开那些 L2
                总结≤5 → 直接读全部 L2(跳 L1 省一次 reflect)
                0 条 → 跳过全走 turns
⑥ 拼增量流水账(严格 allCovered,统一按 coverage(user_id=self)判):
   该 turn 在此 scope 所有 tag_id 均有 coverage 行(allCovered=true)→ 跳原文走自己总结
   否则(某 tag 未覆盖)→ 拼该 turn 原文
   【二期变更】MemoryTurnPatcher 只拼本人 turns(user_id=self)——他人 turn 概念随 turns 个人域化消亡
   召回恒只认 gen_done=true 的 turn; gen_done=false 的 raw 不参与(不聚合也不兜底)
⑦ 装配: 按 subject 聚合打前缀带 owner; subject='我' 且 owner≠当前用户 → 省略主体【张三·爱好】
   【二期】授权链合流条目装配「来自授权项目·X」标注段
```

**算法 why**:reflect(先扫 L1 摘要决定要不要翻 L2 原文)= 省 token 的两段式;allCovered 严格判定 = 已总结覆盖的流水账走总结压缩态、未覆盖的才拼原文,避免同条信息既灌总结又灌原文重复;恒只读自己总结 = 他人总结是他人视角的提炼,注入会污染我的上下文。

**降级链(每步 try-catch 收 notes)**:选标签失败→null;reflect 失败→只读 L1;selector 降级启发式(全集==候选且 size>阈值);tags 空→跳 select/read 直走 turns 兜底。最多 2 次 LLM(选标签+reflect,reflect 仅总结>5 触发)。目标 < 2s。traceId 每步打点。

## 周期总结(统一「开始总结」入口,独立于 gen/总结开关)

**手动总结**:弹框列 {个人} ∪ {本人 ACTIVE 项目}(已离开不可选),每 scope 标可选/灰选——判据 = 该 scope 距上次总结后是否有变化(新增 `gen_done=true` 且无 coverage(user_id=self) 行的 turn,或 `gen_done=false` raw)。有变化=可选、无变化=灰。勾选即跑(先 backfill 该 scope raw 补 tag ≤20/批,再按 (user,tag,scope) 分组取数压缩)。**独立于任何开关**。

**自动总结**:默认勾{个人}(项目默认不勾,用户主动加);定时周期(默认每天)跑前先判该 scope 该周期有无新增未总结 turn,**无新增空跳过不调 LLM**(低频用户不耗 token)。per-user 勾选存 `memory_consolidation_scopes`。

**gen 关态定时规则**:仅总结 `gen_done=true` 的已生成 turn;raw 不纳入定时、不 backfill、不调生成 LLM;scope 内周期新增全为 raw 时空跳过。gen 关用户想总结 raw 须走手动。**解耦 why**:总结低频(每天一次压缩)、gen 高频(每条对话一次生成),不应强绑。

**项目总结取数范围可配**【二期变更：项目总结已整体下线】：二期 turns 纯个人域化后，项目 scope 总结空跑跳过（`MemoryConsolidationService` 注明「项目总结整体下线，P4 重建」）；前端 `MemoryConsolidationDialog` 的 PeoplePicker 为 UI 残留，后端不会产出项目 scope 总结。以下一期叙述备查：人员(仅自己/某几人/全员)+方向可配，产出 summary 恒 `user_id=作者本人`只读自己。

**时序日期铁律**:日期取 turn.`created_at`,禁 LLM 编年份([MemoryConsolidationCompressor](../../backend/src/main/java/com/superprogrammer/chat/service/internal/MemoryConsolidationCompressor.java) `assertYearIronRule`,源外年份违则重试 null)。**防膨胀**:总结链 >N 再压一次(总结的总结),链缩短,provenance+真实日期。

## 冲突(总结时序 pending,四选项裁决)

互斥时序冲突进 PENDING(`memory_conflicts` 带 tag_id+summary_id),summary `status=PENDING_CONFLICT`。裁决四选项:**KEEP_BOTH**(两条都留,按 `created_at` 自动排序,无需用户填日期)/ KEEP_NEW / KEEP_OLD / **DISCARD**。

**项目内不产生跨用户编辑冲突**:别人不能改你的记忆(只读),只作者改自己的;别人想补充→新建自己一条(user_id=自己)。冲突 pending 只来自作者自己总结时 LLM 判互斥时序→作者裁决。

**DISCARD 连带软删 source turns**(防死循环):DISCARD = 软删冲突 summary **及其 source_turn_ids 全部 turns**,走 §3.8 级联(他人引用 summary→STALE+重压缩+波及通知;**12h 规则适用**——source turns 被他人引用且引用方 `summarized_at>12h`→DISCARD 拒 403,提示改 KEEP_OLD/KEEP_BOTH;软删 turns 后下次总结取数自然排除,防 worker 再生成同冲突)。KEEP_NEW/KEEP_OLD 仅软删败方 summary,turns 保留。

## scope 与可见性模型(二期现状)

```
私有性边界: turn 恒个人域(user_id=作者),无项目挂载,别人命中不了,无需额外字段
项目可读单元: memory_project_entries(非 turns)——收录规则粗筛→精判→蒸馏→owner 审核
             APPROVED 条目项目成员即可读;成员离职(DEPARTED)即失读权
跨项目共享: memory_project_links 授权链(发起→对方 owner 审批→ACTIVE)
           召回时 child 项目条目单级一跳并入,装配标「来自授权项目·X」;链断即停
召回 scope(用户多选,持久化,默认{个人}):
  选个人 → 本人 turns + 个人总结(project_id IS NULL)
  项目条目由 pipeline ①.5 步按当前会话项目自动合流,不经 scope 多选
总结 scope: 个人总结 project_id IS NULL AND user_id=self(只读自己)
           【二期】项目总结整体下线(P4 重建)
```

标签行 per-user,防泄敏靠 turn/summary 的 scope 过滤——scope 外的 turn/summary 关联不到的 tag 不进聚合。共享 = 只读 + 仅项目条目(总结不可分享)。【二期已废】一期 `readableAuthors(projectId,reader)` ACL 五路径(owner 兜底全读+`memory_recall_acl` 授权集)随 V67 整体废弃。

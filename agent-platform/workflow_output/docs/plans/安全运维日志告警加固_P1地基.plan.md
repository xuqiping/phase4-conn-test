## P1 目标
- V96 建表 + users 扩列 + 枚举 + 3 权限 seed
- 提通用 RateLimiter（复用 AuthService Redis 写法）
- 封号即时生效（堵 JwtFilter 洞）+ 防自封/最后超管
- logback 保留期抬到 ≥180 天（网安法合规）

### C1 — 建表/枚举/权限（V96）
**目标**：3 新表 + users 扩 2 列 + status CHECK 扩 BANNED + 3 权限 seed 落地。

**动作（伪代码）**：
```
V96__security_hardening.sql:
  -- 1. users 扩列
  ALTER TABLE users ADD COLUMN ban_reason VARCHAR(128);
  ALTER TABLE users ADD COLUMN locked_until TIMESTAMPTZ;
  -- 2. status CHECK 扩 BANNED（删旧约束重建）
  ALTER TABLE users DROP CONSTRAINT users_status_check;
  ALTER TABLE users ADD CONSTRAINT users_status_check
    CHECK (status IN ('ACTIVE','DISABLED','LOCKED','BANNED'));

  -- 3. security_events（半年，运维可物理删，不挂 @TableLogic）
  CREATE TABLE security_events (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    event_type VARCHAR(48) NOT NULL,
    severity VARCHAR(8) NOT NULL,
    user_id BIGINT NULL,
    client_ip VARCHAR(64) NULL,
    trace_id VARCHAR(64) NULL,
    rule_id VARCHAR(32) NULL,
    detail_json JSONB NULL,
    auto_action VARCHAR(24) NULL DEFAULT 'NONE',
    handled BOOLEAN NOT NULL DEFAULT false,
    handled_by VARCHAR(64) NULL,
    handled_at TIMESTAMPTZ NULL
  );
  CREATE INDEX idx_sec_event_created ON security_events(created_at);
  CREATE INDEX idx_sec_event_type ON security_events(event_type);
  CREATE INDEX idx_sec_event_severity ON security_events(severity);
  CREATE INDEX idx_sec_event_user ON security_events(user_id);
  CREATE INDEX idx_sec_event_ip ON security_events(client_ip);
  CREATE INDEX idx_sec_event_handled ON security_events(handled) WHERE handled = false;

  -- 4. ip_blacklist
  CREATE TABLE ip_blacklist (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    ip VARCHAR(64) NOT NULL,
    source VARCHAR(16) NOT NULL,
    reason VARCHAR(128) NULL,
    banned_until TIMESTAMPTZ NULL,
    created_by VARCHAR(64) NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE(ip)
  );

  -- 5. login_attempts（30 天滚动）
  CREATE TABLE login_attempts (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    identifier VARCHAR(128) NOT NULL,
    user_id BIGINT NULL,
    client_ip VARCHAR(64) NOT NULL,
    success BOOLEAN NOT NULL,
    fail_reason VARCHAR(32) NULL,
    geo VARCHAR(64) NULL
  );
  CREATE INDEX idx_login_ip_time ON login_attempts(client_ip, created_at);
  CREATE INDEX idx_login_id_time ON login_attempts(identifier, created_at);

  -- 6. 3 权限 seed（复用现有 permission seed 模式，对齐 V79 审计权限 seed）
  INSERT INTO permissions (code, name) VALUES
    ('security:event:read', '查看安全事件'),
    ('security:ban:manage', '封号/封IP管理'),
    ('security:rule:manage', '安全规则配置')
  ON CONFLICT (code) DO NOTHING;
  -- 授 admin 角色（INSERT role_permissions，对齐现有 seed）
  INSERT INTO role_permissions (role_id, permission_id)
    SELECT r.id, p.id FROM roles r, permissions p
    WHERE r.code='admin' AND p.code IN ('security:event:read','security:ban:manage','security:rule:manage')
  ON CONFLICT DO NOTHING;
```
**涉及文件（2）**：
- `db/migration/V96__security_hardening.sql`（新建）
- 实体/Mapper 等 C2-C10 各 chunk 建，C1 只管 DDL + seed

**依赖**：无（V96 是所有后续 chunk 的地基）。

**验证**：
- 启动 Flyway 自动迁移成功；`\d security_events` / `\d ip_blacklist` / `\d login_attempts` 表结构核对；`SELECT * FROM permissions WHERE code LIKE 'security:%'` 返回 3 行；admin 角色查到 3 权限。
- users.status='BANNED' 写入不报约束错。

**坑**：
- *迁移号撞*：beifen2 已合到 V93，审计 8x 到 V95。确认 V96 未被占（启动前 `SELECT version FROM flyway_schema_history ORDER BY installed_rank DESC LIMIT 5`）。
- *seed 幂等*：`ON CONFLICT DO NOTHING`，重复跑不报错。
- *CHECK 重建*：PostgreSQL 不能直接改 CHECK 内容，必须 DROP + ADD（约束名从 `\d users` 查实际名，可能非 `users_status_check`）。

### C2 — RateLimiter 通用工具（需求②基建）
**目标**：从 AuthService 提取通用 Redis 限流，支持固定窗口 + 滑动窗口两种算法，注解化挂端点。

**动作（伪代码）**：
```
@RateLimit(action="chat_send", max=20, window=60, algo=SLIDING)  // 注解

common/ratelimit/RateLimiter:
  // 固定窗口（INCR + 首次 EXPIRE），复用 AuthService.checkRateWindow 逻辑
  boolean checkFixed(String key, int max, int windowSec):
      try:
          Long n = redis.opsForValue().increment(key)
          if n != null && n == 1L: redis.expire(key, windowSec, SECONDS)
          return n == null || n <= max
      catch (Exception e):
          log.warn("限流降级放行 key={} : {}", key, e.getMessage())
          return true   // 降级放行（可用性 > 限流，与登录域一致）

  // 滑动窗口（ZSET，更公平，per-用户 per-路由用）
  boolean checkSliding(String key, int max, int windowSec):
      try:
          long now = System.currentTimeMillis(); long from = now - windowSec*1000L
          redis.opsForZSet().removeRangeByScore(key, 0, from)   // 清过期
          Long n = redis.opsForZSet().zCard(key)
          if n != null && n >= max: return false
          redis.opsForZSet().add(key, now+"-"+ThreadLocalRandom.current().nextLong(), now)  // member 唯一
          redis.expire(key, windowSec, SECONDS)
          return true
      catch: 降级放行 true

common/ratelimit/RateLimitInterceptor (HandlerInterceptor.preHandle):
  读方法 @RateLimit 注解；无注解→放行
  if !security.rate.enabled: 放行（总闸，system_settings）
  uid = SecurityContext.userId（无则 clientIp）
  key = "rl:" + (uid!=null ? "u"+uid : "ip"+ip) + ":" + action
  boolean ok = algo==SLIDING ? limiter.checkSliding(...) : limiter.checkFixed(...)
  if !ok:
      bizMetrics.apiRateLimited(action)
      throw BusinessException(RATE_LIMIT)   // 已有 429
  放行

WebMvcConfig: addInterceptor(rateLimitInterceptor).addPathPatterns("/api/**")
BizMetrics: + apiRateLimited(action) → 指标 api_rate_limited_total{action}
```
**涉及文件（6）**：
- `common/ratelimit/RateLimit.java`（注解，新建）
- `common/ratelimit/RateLimiter.java`（新建）
- `common/ratelimit/RateLimitInterceptor.java`（新建）
- `common/config/WebMvcConfig.java`（注册拦截器，若不存在则新建 web 配置类）
- `common/metrics/BizMetrics.java`（+apiRateLimited）
- `resources/application.yml`（`security.rate.enabled` 默认 true）

**依赖**：C1（权限/表无关，但 RateLimitInterceptor 在 P2 用 security.rate.enabled 开关，先建）。

**验证**：
- 单测 `RateLimiter.checkFixed`：窗口计数 + EXPIRE 首次设 + 超限返 false + Redis 故障降级 true。
- 单测 `checkSliding`：滑动清过期 + zCard 计数 + member 唯一不覆盖。
- 单测拦截器：注解端点 max+1 次 → 429；不同用户互不影响；关开关 → 不限。

**坑**：
- *性能-Redis QPS*：每请求一次 INCR/ZSET 往返。热端点（chat）高并发压 Redis。**规避**：固定窗口用 Lua 脚本合并 INCR+EXPIRE（省往返）；滑动窗口 ZSET 操作已是批量。先 Redis 单级，二期评估 Caffeine 本地缓存。
- *降级一致性*：Redis 故障降级放行 → 攻击者趁抖动突破。**接受**（与登录域一致），由登录锁定/注入特征（P2）兜底。
- *阈值热更*：阈值走 system_settings（SystemSettingService 读，不重启）；env 仅默认。
- *未登录路径*：登录/注册限流已在 AuthService，不重复挂；白名单公开放行端点不挂。

### C3 — 封号即时生效（堵 JwtFilter 洞，需求①核心）
**目标**：admin 封号/禁用/锁定后，该用户当前 access token 下一请求即 401，不等 15min 过期。

**动作（伪代码）**：
```
common/security/BanService:
  /** 封号/禁用/锁定时调：删 session + 设 ban 标记 */
  revoke(userId, status):
      try:
          redis.delete("session:user:"+userId)   // 删 sid → isCurrent 失败
          // ban 标记兜底（单点登录关时也断；TTL 对齐 access 有效期，access 过期自然消失）
          if status in (BANNED, DISABLED, LOCKED):
              redis.set("ban:user:"+userId, "1", jwtUtil.getAccessExpiration(), MS)
      catch (Exception e):
          log.warn("封号标记写入失败(降级,DB status 仍阻新登录/refresh) userId={} : {}", userId, e.getMessage())

  /** 解封/启用时调：删 ban 标记（session 已删，用户须重登） */
  restore(userId):
      try: redis.delete("ban:user:"+userId)
      catch: 吞

JwtAuthenticationFilter（补 ban 标记校验，在 isCurrent 之后）:
  // 现有: if !sessionService.isCurrent(userId, sid) → 401 SESSION_KICKED
  // 新增: ban 标记校验（单点登录关时兜底）
  if banMarkerExists(userId):   // redis.hasKey("ban:user:"+userId)
      → 401 SESSION_KICKED（固定话术，不透传「被封」防探测）
  // hasKey 降级：Redis 故障 → false（放行，DB status 仍阻新登录/refresh；在途 access 自然过期）

UserController.updateUserStatus(id, body):  // 已存端点，改造
  status = body.get("status"); reason = body.get("reason")
  校验 status ∈ {ACTIVE, DISABLED, LOCKED, BANNED}  // ← 加枚举校验（堵裸写）
  防自封：if id == 当前登录用户id → 403（自封禁止）
  防最后超管：if status∈{DISABLED,LOCKED,BANNED} 且 目标是最后一名 ACTIVE 且持 user:manage 的用户 → 403
  user.setStatus(status); user.setBanReason(status==ACTIVE ? null : reason)
  userMapper.updateById(user)
  if status == ACTIVE: banService.restore(id)
  else: banService.revoke(id, status)
  // @AuditLog action 细化：ban_user/unban_user/lock_user（detail 带 reason）
```
**涉及文件（5）**：
- `common/security/BanService.java`（新建）
- `auth/security/JwtAuthenticationFilter.java`（+ban 标记校验）
- `auth/controller/UserController.java`（updateUserStatus 加枚举校验 + 防护 + 调 BanService + 细化 action）
- `common/audit/AuditLabelDictionary.java`（action 码→中文，若用）
- `frontend/src/views/admin/UserManageView.vue`（禁用弹窗加 reason 输入 + BANNED/LOCKED 选项；启用按钮同路径）

**依赖**：C1（status BANNED 枚举 + ban_reason 列）、现有 SessionService/JwtUtil。

**验证**：
- 单测 `BanService.revoke` 删 session key + 设 ban 标记 + Redis 故障降级不抛。
- 单测 `BanService.restore` 删 ban 标记。
- 单测 JwtFilter ban 标记存在 → 401 SESSION_KICKED；不存在 → 放行。
- 单测自封 → 403；最后超管封 → 403。
- E2E：u1 登录 → admin 封 u1 → u1 刷新页面 401（SESSION_KICKED）→ admin 解封 u1 → u1 重新登录成功。
- E2E（单点登录关场景）：关 `AUTH_SINGLE_SESSION_ENABLED` → 封号 → u1 仍 401（ban 标记兜底）。

**坑**：
- *单点登录耦合*：`AUTH_SINGLE_SESSION_ENABLED=false` 时 isCurrent 恒 true → 删 session 无效。**ban 标记独立 key 解耦**，JwtFilter 单独校验。
- *并发*：封号瞬间用户在途长请求（已过 filter）→ 该请求照常完成，下一请求才拒。可接受语义（不强拆在途）。
- *降级*：Redis 故障 ban 标记写失败 → 在途 access 自然过期前仍可用（≤15min）；DB status 仍阻新登录/refresh。接受（与单点登录降级一致）。
- *防探测*：401 用固定 SESSION_KICKED 话术，不返「被封」（防攻击者枚举哪些号被封）。
- *误操作*：封自己/唯一超管 → 平台锁死 → 自封/最后超管防护必做。

### C4 — logback 合规（网安法 6 月）
**目标**：磁盘日志文件保留期抬到 ≥180 天，满足网安法第21条。

**动作（伪代码）**：
```
resources/logback-spring.xml:
  APP_FILE:  maxHistory 30 → 180；totalSizeCap 2GB → 12GB
  ERROR_FILE: maxHistory 90 → 180；totalSizeCap 1GB → 2GB
  SQL_FILE:  maxHistory 7 → 180；totalSizeCap 500MB → 3GB（默认仍 OFF，LOG_SQL_ENABLED=DEBUG 才占）
  新增 security appender（security.log，JSON，过 MaskingAppender）—— 结构：
    <appender name="SECURITY_FILE" class=...RollingFileAppender>
      <file>${SECURITY_LOG_FILE:-logs/security.log}</file>
      <encoder class="net.logstash.logback.encoder.LogstashEncoder"/>  // 复用现有 JSON 依赖
      <rollingPolicy class=...SizeAndTimeBasedRollingPolicy>
        <maxFileSize>50MB</maxFileSize><maxHistory>180</maxHistory><totalSizeCap>3GB</totalSizeCap>
      </rollingPolicy>
    </appender>
  <logger name="com.superprogrammer.common.security" level="INFO" additivity="false">
    <appender-ref ref="SECURITY_FILE"/>   // P2 起的 SecurityGateFilter/MonitorWorker/BanService 打这
  </logger>
```
**涉及文件（1）**：
- `backend/src/main/resources/logback-spring.xml`

**依赖**：无（独立合规项）。

**验证**：
- 启动无报错；`logs/security.log` 创建。
- 估算磁盘：APP 12GB + ERROR 2GB + SQL 3GB + security 3GB ≈ 20GB，确认 D 盘剩余 ≥25GB（运维手册加巡检项）。
- 日志切割按天 + 按大小，180 天后自动清。

**坑**：
- *磁盘满*：APP 抬到 12GB，单机磁盘压力。**部署必做**：确认 D 盘空间；运维手册加「日志盘空间」巡检项。
- *security.log 脱敏*：过 MaskingAppender（复用现有，P2 接线后所有安全日志自动脱敏）。
- *SQL 默认 OFF*：开了 LOG_SQL_ENABLED 才占 3GB，默认不占。

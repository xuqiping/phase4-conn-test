# NoSQL Database Workflow Checklist

在完成 `workflow/nosql_database_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别NoSQL需求场景

- [ ] 已明确场景类型（NoSQL选型/架构设计/数据模型优化/向量检索RAG/性能调优）
- [ ] 已识别数据模型（文档型/检索型/时序型/图型/向量型）
- [ ] 已提取规模预期（数据量GB/TB/PB、写入QPS、查询QPS、时间跨度）
- [ ] 已提取一致性要求（强一致/最终一致/可调一致性级别）
- [ ] 已提取AI关联度（RAG/Dense+Sparse混合检索/多跳关联查询）
- [ ] 已识别现有技术栈和迁移需求
- [ ] 已对照知识库选型关键完成初步判断（文档→MongoDB/检索→ES/时序→InfluxDB/图→Neo4j/向量→Milvus）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出NoSQL方案

- [ ] 如为NoSQL选型，选型决策矩阵已覆盖（数据模型匹配度/扩展性/查询能力/一致性模型/生态与集成/运维复杂度）
- [ ] 如为NoSQL选型，五大类型对比已输出（MongoDB/ES/InfluxDB/Neo4j/Milvus）
- [ ] 如为NoSQL选型，决策树已给出（内容平台→MongoDB/日志分析→ES/RAG→Milvus/风控→Neo4j/IoT→InfluxDB）
- [ ] 如为架构设计，集群拓扑已覆盖（MongoDB Sharded Cluster/ES热温冷分层/InfluxDB Arrow列式/Neo4j因果集群/Milvus Query+Data+Index分离）
- [ ] 如为架构设计，数据模型设计规范已给出（索引策略/分片键选择/副本数/TTL策略）
- [ ] 如为架构设计，冷热分层方案已说明（热数据SSD+温数据SATA+冷数据对象存储）
- [ ] 如为向量检索，向量数据库选型已对比（Milvus/Weaviate/PG Vector）
- [ ] 如为向量检索，向量索引策略已覆盖（Dense:HNSW/IVF/DISKANN + Sparse:BM25/TF-IDF混合检索）
- [ ] 如为向量检索，RAG架构设计已输出（文档预处理→Embedding生成→向量存储→检索重排序→LLM生成）
- [ ] 如为性能调优，典型性能问题定位方法已给出（慢查询/索引失效/内存溢出/GC压力）
- [ ] 如为性能调优，调优参数建议已覆盖（连接池/批处理/并发度/缓存配置）
- [ ] 如为性能调优，监控告警关键指标已列出（QPS/延迟/P99/错误率/磁盘IO/内存使用率）
- [ ] 所有核心论断均能在知识库中找到支撑来源

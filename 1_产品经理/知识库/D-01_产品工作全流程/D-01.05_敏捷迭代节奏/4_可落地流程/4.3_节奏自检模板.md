## 二、调节决策树

```
健康度≥5项✅？
├── 是 → 节奏基本健康 → 继续保持+2周后再检
└── 否 → 主要问题是什么？
    ├── 延时为主 → Sprint容量是否过大？
    │   ├── 是 → 减少容量10-20%
    │   └── 否 → 是否需求拆分不够细？
    │       ├── 是 → 加强拆分训练
    │       └── 否 → 考虑延长周期1周
    ├── 疲劳为主 → 是否1周Sprint？
    │   ├── 是 → → 2周Sprint
    │   └── 否 → 是否容量缓冲不足？
    │       ├── 是 → 增加缓冲+减少仪式
    │       └── 否 → 检查技术债/加班文化
    ├── 插队为主 → 是否有缓冲通道？
    │   ├── 是 → 缓冲不够 → 增加到20%
    │   └── 否 → 增加缓冲通道/看板处理插队
    └── 质量为主 → 是否赶工导致？
        ├── 是 → 减少容量+增加测试时间
        └── 否 → 检查测试覆盖率/Code Review流程
```

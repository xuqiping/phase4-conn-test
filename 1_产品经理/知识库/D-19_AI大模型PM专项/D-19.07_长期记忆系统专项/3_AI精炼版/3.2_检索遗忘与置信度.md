# 3.2 检索、遗忘与置信度

## 一、记忆检索策略（让"对的记忆"在"对的时刻"被召回）

| 策略 | 说明 | 适用 |
|---|---|---|
| **稠密检索 Dense** | 向量相似度 top-k；语义模糊匹配 | 通用首选 |
| **稀疏检索 Sparse** | BM25 关键词；精确实体匹配 | 实体/编号类强匹配 |
| **混合检索 Hybrid** | 稠密 + 稀疏 + RRF 融合 | 高准确率要求场景 |
| **重排 Re-rank** | top-k 召回后用 cross-encoder 重排 top-N | 提精度；成本可控 |
| **时间衰减 Recency** | 相似度 × exp(-Δt/λ)；近期记忆权重高 | 偏好/状态类记忆 |
| **置信度加权** | 相似度 × 置信度；高置信度记忆优先 | 多源/可证伪场景 |
| **多查询召回 Multi-Query** | LLM 改写多个 query 并召回合并 | 复杂意图 |
| **HyDE 假设文档** | LLM 先生成假设答案再检索 | 抽象问题 |

**检索时机**：①每轮固定拼 prompt（简单可控但贵）；②按需调用（Agent 主动检索，省 token 但取决于 Agent 判断）；③混合（核心记忆常驻 + 按需查归档）[来源:腾讯云 | 🔍高 | 2026-03]。

## 二、遗忘机制（核心反"什么都记"）

| 遗忘类型 | 触发 | 方式 |
|---|---|---|
| **自然衰减** | 长期未访问 | 衰减打分低于阈值→软删 |
| **容量上限** | 库存超 N | LRU/TFR 淘汰最低分 |
| **冲突合并** | 新事实覆盖旧事实 | 旧条目 deprecated + 版本保留 |
| **主动遗忘** | 用户主动删除 | 硬删 + 索引更新；GDPR 被遗忘权 |
| **隐私触发遗忘** | PII 过期/退出 | 自动清理敏感字段 |
| **质量遗忘** | 低置信度/被反复负面反馈 | 降权→最终淘汰 |

**遗忘设计原则**：

- **可控**：遗忘策略可配置、可审计、可回滚（软删优先）
- **可解释**：被遗忘条目应有原因记录
- **不破坏一致性**：合并/删除时避免留下"半截关系"（KG 场景）
- **保留关键事实**：用户身份/法律事实/合同条款不衰减

> 2026-07 多起 Agent 失忆事故提示：**没有遗忘设计的记忆库会膨胀污染，但过度遗忘会丢关键约束**——必须分级 [来源:腾讯云 | 🔍高 | 2026-07-15]。

## 三、置信度分层（"老内容更自信"现象）

2026 研究发现：经过充分验证的老内容置信度通常更高，新内容需谨慎评估。现代 AI 系统采用**4 级置信度结构**对应记忆层级 [来源:CSDN | 🔍高 | 2026-07-13]：

| 置信度层 | 来源 | 用法 |
|---|---|---|
| **L1 高（验证过）** | 用户多次确认/官方事实 | 可直接引用，写进推理链 |
| **L2 中（推断过）** | LLM 单次抽取/合理推断 | 标"推断"前缀，可被纠错 |
| **L3 低（新写入）** | 当前会话新信息 | 谨慎使用，触发用户确认 |
| **L4 待验证（可疑）** | 冲突信息/疑似注入 | 不直接生成答案，标待核实 |

**置信度衰减与提升**：被反复正面使用→升层；被负面反馈/纠错→降层；冲突时新事实需用户裁决。

## 四、记忆污染防护（与 D-19.06 越狱/注入交叉）

| 污染类型 | 风险 | 防护 |
|---|---|---|
| **提示注入写入** | 恶意输入诱导 LLM "add" 错误记忆 | 写入前意图检测；写入需用户确认（HITL） |
| **数据投毒** | 历史"毒丸"反复召回放大 | 写入质量评分 + 异常检测 |
| **越狱后污染** | 越狱 prompt 改写系统记忆 | 系统记忆与用户记忆物理隔离 |
| **跨用户串扰** | 隔离失败致 A 看 B 偏好 | 主键强隔离 + 权限校验 |
| **多 Agent 串扰** | 共享记忆时被某 Agent 写脏 | 按 agent_id 命名空间 + 写权限 |

> OWASP ASI 2026 把"记忆污染 Memory Poisoning"列为 Agent 专项十大攻击面之一 [来源:新浪财经 | 🔍高 | 2026-06]——记忆系统不能只设计"记什么"，必须设计"防被坏人写入"。

## 五、隐私与遗忘权（必须前置设计）

| 隐私原则 | 设计 |
|---|---|
| **数据最小化** | 只记必要 PII；非必要字段不留 |
| **用户可控** | 用户可查/可删/可导出全部记忆 |
| **被遗忘权** | GDPR / 国内拟人化办法要求"真删"而非软删 |
| **PII 加密** | 敏感字段加密 + 访问审计 |
| **保留期限** | 不同信息类型设留存上限 |
| **跨境合规** | 记忆存储位置符合法域要求（与 D-19.06 多法域合规交叉） |

> 2026-07-15 施行的中国《人工智能拟人化互动服务管理暂行办法》对"AI 记得用户"类产品提出更高合规要求 [来源:B站监管简报 | 🔍高 | 2026]。本叶子记忆系统设计必须前置隐私合规，不能事后打补丁。

## 六、PM 设计要点

1. **检索不只有稠密**：高要求场景用混合 + 重排；偏好类加时间衰减；推理类加置信度加权
2. **遗忘必须分级**：关键事实不衰减、过期事实主动忘、冲突时旧版保留可回溯
3. **置信度是用户信任的杠杆**：低置信度记忆不要硬包装成"权威答案"
4. **污染防护与合规前置**：写入用 HITL、隔离用强权限、隐私用法域清单（与 D-19.06 联动）

# 视频生成第三轮人工测试问题修复 Plan（Phase 2 总路由）

> 输入：[4x. 视频生成问题.md](../../人工测试问题/4x.%20视频生成问题.md) 的 7 个未解决项。
> 只含伪代码；未经用户明确许可，不进入 Phase 3、不修改业务代码。

## 目标

完成历史行内视频、提示词/时间筛选、历史参数恢复、媒体任务无限等待、资产选择器媒体预览、多次 `@` 引用和输入附件回显，并同步 SeedDance feature-map、user-ops 与问题单。

## 根因摘要

| 问题 | 根因 |
|---|---|
| 历史无视频/筛选 | 历史表只有文本列；任务列表 API 只有 limit |
| 点击历史不恢复 | 点击只切右侧任务；VO 未完整返回 ratio、水印、生成音频和输入附件 |
| 10 分钟误失败 | 后端 600 秒写 FAILED；画布视频 120 轮、图片 48 轮后本地标失败 |
| 资产选择只有文字 | Picker 未使用列表已有的 `AssetVO.fileId` 拉鉴权预览 |
| 第二次 `@` 无候选 | chip 显示长度与内部 token 长度混算，首个 chip 后光标偏移错误 |
| `videoUrl/imageUrls` 为 null | 两者是成功输出地址，不是输入附件；输入附件虽已实际发给 Provider，但查询接口未回显 |

## 方案比较

| 方案 | 做法 | 结论 |
|---|---|---|
| A 最小补丁 | 最近 50 条前端筛选；删超时后继续阻塞 Worker | 查不全历史且会占死线程，不采用 |
| **B 推荐** | 服务端筛选、详情参数/附件回显、媒体懒加载、Worker 单次查询后退避再入队 | 覆盖完整且不泄露 data URI，采用 |
| C 原始请求审计表 | 永久保存 Provider 原始请求/响应 | 敏感且过度设计，不采用 |

网络连接与单次 HTTP 响应仍保留传输超时（防连接永久挂死），但查询传输异常只重试，不把已创建的模型任务判失败；只有 Provider 明确返回失败终态才失败。

## 推荐执行顺序

1. 多次 `@` 光标根因（小而独立，先闭环）。
2. 历史筛选与详情契约。
3. 参数恢复、历史视频、资产预览。
4. Worker 非阻塞无限轮询与画布持续轮询。
5. 文档、问题单、全量验证。

按用户要求，Phase 3 由当前线程顺序执行，不调用子智能体。

## 决策与坑点批注
- **双注册表而非单表+category 标注**：`LlmProviderInterface` 实例不带 category 元数据，若单表存储则 chat 路由能按 model 名命中 EMBEDDING 行（chat() 打到 embed 端点被上游 400）。拆两表从结构上保证「EMBEDDING 行 chat 不可达」，且 `getProviders()` 旧签名语义不变（LlmGatewayTest 等 3 处调用零改动）。
- **embed 不吃用户级 override**：plan 明确「embed() 只在 EMBEDDING 里找」+ 速查表19「用户级仍 chat-only」。若允许用户级覆盖 embed，user_llm_providers 无 category 字段无法区分该覆盖给 chat 还是 embed——保持 CHAT-only 是唯一自洽解。
- **Step6 前端未动**：`llm.ts`/`ProviderManageTab.vue` 已被前置媒体批次污染（MEDIA 探测 testKindOf 三分流，+79 行），Step6 的四分化要在其上改且提交会拖入前置内容 → 挂起等前置批次授权（同 Ark/MediaModelService 纠缠）。Step7（画布 PropertyPanel + 资产库详情页）文件干净可独立提交，但本轮上下文到阈值未启动。

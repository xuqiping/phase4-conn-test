# 4.2 SOP 半结构化访谈执行流程

> 📅 2026-07-11 ｜ 🔴红线：禁止在访谈中推销产品或引导用户说"好话"；每个访谈必须24h内完成纪要 ｜ 角色：需求收集执行PM

## 背景

半结构化访谈是需求收集的核心武器，但执行质量差异巨大——好的访谈穿透三层需求，差的访谈只收集一堆"我觉得挺好"。本SOP标准化访谈全流程，确保执行一致性。

## 目标

从确定访谈目标到输出编码结果，提供可复用的标准化流程，确保每次访谈都有可追溯、可分析的输出。

## 关键结果

1. 访谈提纲（5-8个核心问题+追问分支）
2. 访谈录音/记录
3. 24h访谈纪要
4. 需求条目编码输出

## 执行步骤

### Phase 1：准备（T-3天~T-1天）

| 步骤 | 动作 | 检查项 |
|---|---|---|
| 1.1 | 明确本次访谈的核心目标（不超过2个） | □ 目标是否聚焦？ |
| 1.2 | 撰写访谈提纲 | □ 5-8个开放问题？□ 有追问分支？□ 无引导性问题？ |
| 1.3 | 确定受访者画像与筛选条件 | □ 是否覆盖不同类型用户？□ 是否排除极端用户？ |
| 1.4 | 预演提纲（找同事模拟） | □ 问题是否自然？□ 时间是否控制在45min内？ |
| 1.5 | 发送邀请+日程确认 | □ 知情同意书是否签？□ 录音许可是否取得？ |

### Phase 2：执行（T日）

```
开场（3min）
├── 自我介绍+说明目的
├── 保密承诺+录音许可确认
└── 暖场（1-2个轻松话题）

深挖（30-35min）
├── 从宽到窄：先场景后细节
├── 追问五层法穿透表层
├── 关键时刻：用户犹豫/叹气/笑 → 标记深挖
├── 避免："你觉得这个功能好不好？" → 用："上次你用这个功能时发生了什么？"
└── 适时重述确认："我理解你的意思是...对吗？"

收尾（5min）
├── 总结3个关键发现
├── 问："还有什么你觉得重要但我没问到的？"
└── 致谢+后续反馈承诺
```

### Phase 3：整理（T日~T+1日）

| 步骤 | 动作 | 输出 |
|---|---|---|
| 3.1 | 24h内完成访谈纪要 | 纪要文档（含关键引用原文） |
| 3.2 | 标记关键时刻（情绪强烈/犹豫/绕行） | 关键时刻索引 |
| 3.3 | 开放编码 | 需求条目标注 |
| 3.4 | 与其他受访者交叉比对 | 需求主题聚类 |

### Phase 4：输出（T+1日~T+3日）

```markdown
## 访谈汇总

### 受访者覆盖
| 编号 | 用户画像 | 访谈时长 | 核心发现数 |

### 需求条目
| 条目ID | 原始表述 | 对应场景 | 需求层级(L1/L2/L3) | 情感强度 | 可信度 |

### 高优先级发现（3-5条）
1. ...
2. ...
```

## 输出格式

- 访谈纪要：每个受访者1份（Markdown/文档）
- 汇总表：1份（含需求条目清单）
- 编码矩阵：1份（需求主题×受访者交叉表）

## ICE与RICE的选择策略

### 一、ICE vs RICE 核心差异

| 维度 | ICE | RICE |
|---|---|---|
| 提出者 | Sean Ellis (增长黑客) | Intercom (产品管理) |
| 评分维度 | Impact × Confidence × Ease | Reach × Impact × Confidence / Effort |
| Reach维度 | 隐含在Impact中 | 独立维度 |
| Effort方向 | Ease(越容易分越高) | Effort(越难分越高,做分母) |
| 评分制 | 1-10 | Reach千人/I&C百分比/Effort人月 |
| 评分速度 | 30秒/条 | 2-5分钟/条 |
| 适用场景 | 增长实验/早期产品快速筛选 | 成熟产品精细排序 |

### 二、何时用ICE

| 场景 | 为什么用ICE而不用RICE |
|---|---|
| 增长实验排序 | 实验>20个，需快速初筛，ICE效率是RICE的5-10倍 |
| 早期产品(0-1) | 用户基数小，Reach维度意义不大 |
| 快速头脑风暴 | 会议中现场评分，RICE太慢 |
| 假设驱动验证 | Confidence维度天然适合"假设-验证"场景 |
| 个人PM优先级 | 个人工作排优先级，不需多维度 |

### 三、何时用RICE

| 场景 | 为什么用RICE而不用ICE |
|---|---|
| Sprint规划 | 需要精确的Effort估算做容量规划 |
| 多人口径需统一 | Reach维度让不同受众范围的需求可比 |
| 高赌注决策 | 需要更精细的置信度和工作量评估 |
| 跨团队项目 | Effort(Sprint/人月)更利于跨团队对齐 |
| 季度OKR排期 | 需要更完整的量化依据说服管理层 |

### 四、ICE ↔ RICE 互转映射

**ICE → RICE**：
- Reach：从Impact中分离——原来"影响大且波及广"的拆出独立的Reach
- Impact：保持不变（语义一致）
- Confidence：保持不变（语义一致）
- Effort = 11 - Ease（方向反转）

**RICE → ICE**：
- Impact = f(原Impact, Reach)——将Reach的影响折叠进Impact
- Confidence：保持不变
- Ease = 11 - Effort（方向反转）

**互转示例**：

| 需求 | RICE Score | ICE Score |
|---|---|---|
| | Reach=5K, Impact=3, Confidence=80%, Effort=2人周 | Impact=7, Confidence=8, Ease=7 |
| | RICE = 5000×3×0.8/2 = 6000 | ICE = 7×8×7 = 392 |

**注意**：ICE和RICE的分数**不可直接比较**——一个是绝对分数(1-1000)，一个是加权分数(可能几千到几万)。

### 五、升级/降级决策法则

| 条件 | 决策 | 原因 |
|---|---|---|
| 需求≤15条 | 用ICE | 量少时RICE的额外精度不值得时间成本 |
| 需求15-30条 | 用RICE | 精度差异开始影响排序质量 |
| 需求>30条 | ICE初筛+RICE精排Top 10 | 分级处理效率最高 |
| 实验假设排序 | 必须用ICE | ICE的Confidence维度天然匹配假设验证 |
| 关键客户需求 | 用RICE | Reach维度区分"影响1个客户"和"影响1000个客户" |

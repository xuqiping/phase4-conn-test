# file-keeper 技术选型文档

> 项目目标:跨平台(Windows / macOS / Linux)管理常用文件的桌面应用,支持一键打开、关闭、批量管理。
> 关键约束:**打包体积小、启动快、能稳定调用操作系统级文件与进程能力**。
>
> 立项日期:2026-05-08

---

## 1. 关键需求与对选型的影响

| 需求 | 对技术栈的要求 |
|------|----------------|
| 跨平台(Win / macOS / Linux) | 排除 WPF、SwiftUI 等单平台原生方案 |
| 体积小(目标 ≤ 20 MB) | 优先复用系统 WebView,排除 Electron 这类捆绑 Chromium 的方案 |
| 一键打开任意文件(用默认程序) | 需要稳定的 shell open / xdg-open / `start` 调用 |
| 一键关闭"已打开的程序/文件" | 需要枚举进程、窗口标题,匹配文件路径并发关闭信号 |
| UI 现代、易扩展(标签、拖拽、搜索) | 倾向 Web 技术栈(HTML/CSS/JS),布局灵活、生态最大 |
| 与现有 voice-to-text 项目工程化对齐 | 优先复用已有 Tauri + Vue 经验 |

## 2. 候选方案横向对比

| 方案 | hello-world 包体 | 启动速度 | UI 表现力 | 系统能力 | 学习成本(对你) | 生态/社区 |
|------|------------------|----------|-----------|----------|------------------|-----------|
| **Tauri 2 + Vue/TS** | **3 ~ 8 MB** | 极快 | 极强(WebView) | 强(Rust + 插件) | 低(已用过) | 活跃,2.x 已稳定 |
| Wails v2 + Go + Web | 8 ~ 15 MB | 极快 | 极强(WebView) | 强(Go 标准库) | 中(需学 Go) | 活跃,略小于 Tauri |
| Flutter Desktop | 20 ~ 40 MB | 快 | 强(自绘) | 中(需插件) | 中(需学 Dart) | 移动端强,桌面较新 |
| Avalonia(.NET) | 50 ~ 80 MB | 中 | 强 | 强 | 中(C#) | 较活跃 |
| Electron + Vue | 80 ~ 150 MB | 中 | 极强 | 强(Node) | 极低 | 最大 |
| PyQt / PySide6 | 40 ~ 80 MB(打包后) | 中 | 中 | 强 | 低 | 成熟但传统 |

**体积关键差异**:Tauri 调用系统自带 WebView(Win 用 WebView2,macOS 用 WebKit,Linux 用 WebKitGTK),不打包浏览器内核;Electron 每个应用都自带一份 Chromium,体积底线就在 80 MB。

## 3. 详细评估

### 3.1 Tauri 2(推荐)
**优点**
- 包体最小:Win release 通常 3 ~ 6 MB,带常用插件 ~ 8 MB。
- 启动毫秒级,内存占用约为同等 Electron 应用的 1/3 ~ 1/5。
- Rust 后端调用文件/进程 API 安全、性能好,`sysinfo`、`opener`、`tauri-plugin-fs`、`tauri-plugin-dialog` 等开箱即用。
- 与项目内 `voice-to-text` 工程化复用度极高(同 Vue 3 + TS + Vite + Pinia + Tauri 2 模板)。
- 安装包(MSI / DMG / AppImage)签名、自动更新流程现成。

**缺点**
- Rust 学习曲线略陡——但本项目里 Rust 部分不多,主要写若干个 `#[tauri::command]`。
- 第三方系统能力(如 hook 全局快捷键、托盘、单实例)需要插件,但官方插件已覆盖 90%。

### 3.2 Wails v2(候选)
**优点**:Go 比 Rust 上手快;并发模型适合扫描进程/文件。
**缺点**:体积比 Tauri 大 ~ 50%;Windows WebView2 依赖与 Tauri 相同,但工具链没有 Tauri CLI 顺手;且与现有项目栈不统一,会引入两套工程文件。

### 3.3 Electron(放弃)
体积直接破 80 MB,违反核心约束。除非未来需要内嵌大型 Chromium 专用功能(如 PDF 渲染、复杂富文本),否则没有优势。

### 3.4 Flutter Desktop(放弃)
自绘 UI 在文件管理类应用上不是优势(原生感反而下降),包体也比 Tauri 大 5 倍以上,不划算。

### 3.5 PyQt / PySide6(放弃)
打包后体积大、启动慢、外观陈旧。项目内 `文件搜索/`、`快速管理已打开程序/` 已经是 Python 方案,该应用走前端栈正好补全工具组合。

## 4. 推荐方案

### **Tauri 2 + Vue 3 + TypeScript + Vite + Pinia**

| 层 | 选型 | 说明 |
|----|------|------|
| 桌面外壳 | **Tauri 2.x** | 跨平台、体积小、Rust 后端 |
| 渲染层 | **Vue 3 + TypeScript** | 与 voice-to-text 一致;生态成熟 |
| 构建 | **Vite 6+** | 极快的 HMR |
| 状态管理 | **Pinia** | 轻量、TS 友好 |
| UI 组件库 | **暂定 Naive UI 或自写** | 二选一,Naive UI 体积友好且无依赖 Element |
| 后端语言 | **Rust 1.80+** | Tauri 必需 |
| 数据持久化 | **JSON 文件 + `tauri-plugin-store`** | 收藏量小(几百条),无需 SQLite 复杂度;后期量大可平滑切换 `tauri-plugin-sql` |
| 文件操作 | **`tauri-plugin-fs` + `tauri-plugin-opener`** | 读写收藏配置、用默认程序打开 |
| 进程管理 | **`sysinfo` crate + 平台特定 API** | 列举/关闭进程;Win 用 `windows` crate 抓窗口标题,macOS 用 `Cocoa`,Linux 用 `procfs` |
| 全局快捷键 | **`tauri-plugin-global-shortcut`** | 呼出主窗口 |
| 托盘 | **Tauri 内置 tray API** | 后台常驻 |
| 自动启动 | **`tauri-plugin-autostart`** | 可选 |
| 单实例 | **`tauri-plugin-single-instance`** | 防止重复启动 |

### 体积预估
按上述插件组合,Windows release 包预估 **8 ~ 12 MB**(NSIS / MSI 安装器),macOS .app **10 ~ 14 MB**,Linux AppImage **12 ~ 18 MB**。可控。

## 6. 主要风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| Win 客户端缺少 WebView2 Runtime | 应用打不开 | 安装器使用 Tauri 提供的 `embedBootstrapper` 或 `downloadBootstrapper` 模式自动安装 |
| 关闭已打开文件时进程匹配不准(如多个 Word 实例打开多个文档) | 误关闭其他文档 | 不直接 kill 整个进程;优先用窗口标题 + 文件路径精确匹配,匹配不到时让用户确认 |
| macOS 上"关闭已打开文件"权限受限 | 部分能力不可用 | 对受限平台采用降级策略:仅记录、提示用户手动关闭 |
| Rust 编译耗时 | 初次构建慢 | 启用 `sccache`,CI 缓存 `~/.cargo` 与 `target/` |
| 中文路径在 Cargo / 链接器下偶发问题 | 构建失败 | 项目目录已用纯英文 `file-keeper`,规避 |

## 2. 功能-代码映射

### 2.1 AGENTS.md 大白话表单（FR-008）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 表单字段持久化 | `core_state::agent_config::{load,save}` | `agent_configs` 表存 JSON，一项目一行。 |

| 前端弹窗入口 | `Topbar.tsx` → `AgentConfigModal.tsx` | 顶部「项目约定」按钮打开表单，保存即重写项目根 `AGENTS.md`。 |

### 2.2 结构化生成管线（FR-030/031/032 基础）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| LLM 非流调用 | `cloudApi::chatComplete` | 调用云端 `POST /gateway/complete`，自动处理 401/402 刷新，返回 `{content, cost_cents, capped}`。 |
| JSON 提取/修复 | `generator::extractJson` | 先直接解析，失败再取 ```json 代码块或第一个 `{...}`，仍失败抛大白话错误。 |

| 三阶段 prompt | `generator::generateIdeaReport` / `generateSpecCards` / `generatePlanChunks` | 每个 prompt 都带项目约定约束和统一的 JSON schema + 追问指令。 |

### 2.3 想法打磨向导（FR-030/AC-033）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 访谈问答 | `Idea.tsx` 中 `QUESTIONS` | 五个固定问题（做给谁、痛点、竞品、变现、技术约束），答案存在本地 state。 |
| 生成报告 | `generateIdeaReport` | 调用 LLM 输出 `{recommendation, summary, report_md, clarifying_questions}`。 |
| 写入产物 | `ipc.writeProjectFile` | 报告落地 `workflow_output/docs/项目分析/项目分析报告.md`，后续需求卡读取同一文件。 |
| 三选一建议 | `Idea.tsx` 中 `RECOMMEND_LABEL` |  worth_doing / narrow_down / rethink 映射为「值得做/先缩小/再想想」。 |

### 2.4 需求确认卡片（FR-031/AC-034）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 卡片持久化 | `core_state::spec_card` | `spec_cards` 表：`title/detail/ac_json/status/sort_order`。 |
| 生成卡片 | `Spec.tsx::generate` → `generateSpecCards` | 读取报告 markdown，LLM 拆成卡片数组；重新生成前清空旧卡片。 |
| 确认/跳过/编辑 | `Spec.tsx::setStatus` / `saveEdit` | 调用 `update_spec_card`，前端实时更新本地列表。 |
| 全确认解锁计划 | `commands::update_spec_card` | 全部卡片变为 confirmed/skipped 后，自动 `pass_gate("requirement_confirm")`。 |
| 进入计划按钮 | `Spec.tsx` | `allResolved` 为 false 时禁用，防止用户过早推进。 |

### 2.5 施工计划 chunk 看板（FR-032/AC-035）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| chunk 持久化 | `core_state::plan_chunk` | `plan_chunks` 表：`title/goal/estimated_tokens/dependencies_json/status/sort_order`。 |
| 生成 chunk | `Plan.tsx::generate` → `generatePlanChunks` | 只读取 confirmed/skipped 的需求卡，LLM 输出可独立执行的小块任务。 |
| 审批计划 | `commands::approve_plan` | 所有 draft 变 approved，按顺序在 `tasks` 表创建 pending 任务，并自动 `pass_gate("kickoff")`。 |
| 撤销审批 | `commands::revoke_plan_approval` | approved 回 draft，删除对应 pending tasks，并回退 `kickoff` 门禁。 |
| 开工按钮 | `Plan.tsx` | 审批后显示「开工」，点击 `transition("build")` 进入建造阶段。 |

### 2.6 主动反问澄清（FR-044/AC-048）

| 功能点 | 代码位置 | 原理一句话 |
|---|---|---|
| 统一轮次控制 | `useClarifyRound.ts` | 每阶段最多 3 轮追问，超限提示「信息仍不足，建议人工梳理后重试」。 |
| 弹窗组件 | `ClarifyDialog.tsx` | 接收问题数组，用户逐条回答后回调给视图继续生成。 |
| 上下文追加 | `Idea.tsx` / `Spec.tsx` / `Plan.tsx` | 回答追加到原上下文（问答 / 报告 / 需求卡详情），再调生成函数。 |

## 4. 关键联动点

- **保存项目约定** → 重写项目根 `AGENTS.md`；下次生成 prompt 自动读取。
- **生成分析报告** → 写入文件 + 清空旧 `spec_cards`；重新生成会丢失旧卡的编辑/确认状态（前端已提示性禁用「重新生成」后需用户确认）。
- **确认/跳过最后一张需求卡** → 后端自动 `pass_gate("requirement_confirm")` → 前端状态快照刷新 →「进入计划」可用。
- **审批施工计划** → 后端创建 `tasks` 并 `pass_gate("kickoff")` →「开工」可用；撤销审批则删除 pending tasks 并回退门禁。
- **LLM 返回追问** → 弹窗 → 回答追加上下文 → 再次生成；超过 3 轮停止并提示人工梳理。

## 5. 运维与限流

- **生成超时**：`cloudApi.ts` 通过 axios timeout 控制，超时后前端显示网络/重试错误。
- **成本前置**：每次生成前可扩展调用 `/gateway/estimate` 检查余额（P04 S2 已接入 `cost_cents`，余额不足拦截留给后续迭代）。
- **产物版本**：`spec_cards` / `plan_chunks` 重新生成前清空旧记录；如需版本回溯，后续可备份到 `_bak` 表（运维清单预留）。
- **追问上限**：`useClarifyRound` 默认 3 轮，防止模型与用户无限兜圈。
- **CI 兜底**：本地 `cargo audit` / `npm audit` 因网络/镜像受限只 WARN，GitHub Actions 环境硬拦截。

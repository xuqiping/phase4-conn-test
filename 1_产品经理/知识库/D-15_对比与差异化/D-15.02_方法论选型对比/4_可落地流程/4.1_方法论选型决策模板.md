## Part B：开发模式选型表

### 使用方法

逐项打分（1-5分），瀑布和敏捷哪边总分高就倾向哪种模式。差距<5分时建议用混合模式。

| 决策维度 | 瀑布适合(1-5) | 敏捷适合(1-5) | 说明 |
|---|---|---|---|
| 需求确定性 | | | 需求越确定→瀑布分高 |
| 合规/审计要求 | | | 合规要求越高→瀑布分高 |
| 团队规模 | | | 团队越大→瀑布分高（协调成本） |
| 市场变化速度 | | | 市场变化越快→敏捷分高 |
| 用户反馈可得性 | | | 反馈越容易获取→敏捷分高 |
| 团队敏捷经验 | | | 经验越丰富→敏捷分高 |
| 项目类型 | | | 基础设施→瀑布；C端产品→敏捷 |
| **合计** | | | |

### 决策规则

- **瀑布总分 - 敏捷总分 > 10** → 瀑布开发
- **敏捷总分 - 瀑布总分 > 10** → 敏捷开发
- **|差值| ≤ 10** → 混合模式（瀑布式规划+敏捷式执行）

## Part C：验证方法选型表

| 决策维度 | A/B测试 | 灰度发布 | 都需要 |
|---|---|---|---|
| 变更类型 | 功能/文案/算法优化 | 新版本/大功能上线 | 既需验证效果又需控制风险 |
| 风险等级 | 低（不改变核心流程） | 中-高（涉及部署风险） | 高（大功能+效果不确定） |
| 是否需要统计结论 | 是（需量化对比） | 否（只需确认安全） | 是（需量化+安全确认） |
| 时间要求 | 1-4周（需收集足够数据） | 1-7天（逐步放量） | 4-6周（先AB后灰度） |

### 选型规则

- **只验证效果（不涉及部署风险）** → 只做A/B测试（服务端实验）
- **只验证安全（不比较效果）** → 只做灰度发布（bug修复/技术重构）
- **既验证效果又控制风险** → A/B测试 + 灰度发布（先AB验证效果，再灰度控制风险）

## 使用案例（示例）

**场景**：某电商产品要做首页改版

**Part C 结果**：首页改版既需验证效果又需控制风险 → A/B测试（2周）+ 灰度发布（1周，5%→20%→50%→100%）

## 功能简介
对话中抽取用户事实记忆、分类(用户记忆块)、新旧记忆冲突裁决(保留/合并/替换)、用户可在面板查看/编辑/删除/批量解决冲突。

## 记忆检索模式(`rag.memory.retrieval-mode`)
| 模式 | 召回 | 兜底 |
|---|---|---|
| **LLM_FULL_CONTEXT**(默认) | 全量 `confidence≥0.5` 灌入 | 超阈值 → 三维筛选 |
| **EMBEDDING_VECTOR** | query 向量 top-K(`≥0.35`,`LIMIT 5`) | 无命中不注入 |
| **VECTOR_KEYWORD** | 向量 ∪ 关键词(五列并查)→ 截断 8 | 0 命中 → LLM-key |
| **LLM_KEY**(推荐) | 锚点向量+BM25 RRF → LLM 三维精排 | 异常 → 不注入 |

入口 [MemoryService.buildMemoryContext(scope,query)](../../backend/src/main/java/com/superprogrammer/chat/service/MemoryService.java),设置 [SystemSettingService.getMemoryRetrievalMode()](../../backend/src/main/java/com/superprogrammer/system/service/SystemSettingService.java),前端 [RagMemorySettingsTab.vue](../../frontend/src/components/settings/RagMemorySettingsTab.vue)。LLM_KEY 旋钮:`llm-key.coarse-top-n`(默认40)/`llm-key.rerank`(默认true)/`keyword-max`(默认8)。

### 写入与冲突要点
- **key 归一**:extract 前查用户既有 `memory_key` 列表注入 LLM prompt 做语义复用(同概念复用既有 key,不造变体)。归一在源头 → 下游 `eq(memoryKey)` 去重/冲突/UI 天然正确。
- **processFacts 性能**:预去重+classify(embed 并行,跑 [memoryTaskExecutor](../../backend/src/main/java/com/superprogrammer/chat/config/MemoryTaskExecutorConfig.java) `mem-task-` core4/max8)→ 按 block 聚合 → 每块一次 batch judge。
- **抽取/判定模型跟随对话**:`extract` + batch judge 用当前会话 `request.getModel()`(用户所选对话模型,如 k2.6),透传链 `ChatSessionService → MemoryService.processMemory/extractFacts/processFacts → MemoryConflictJudge.extract/judge → chat(prompt, model)`。model 空/异常回退 `RagConfig.MEMORY_JUDGE_MODEL`(doubao-seed-2.0-code)。**embedding 不跟随**(固定 `RagConfig.MEMORY_EMBED_MODEL`——对话模型非 embedding 模型);`route`/`selectRelevantKeysBlocks`/`batchExtractEntities` 仍固定。K2 等 JSON 偶发不规范 → fail-safe applyClean 兜底。
- **applyClean**:判"非冲突"(含细化/补充)时,同 key 既有 clean 行 → `updateCleanMemory` 原地 UPDATE(value+confidence+embedding+block);否则 INSERT,撞唯一约束兜底 UPDATE。
- **冲突分流**:跨块同 key 记忆并入候选集(防跨块静默覆盖,V35 Bug 1 已修)。
- **冲突快照带全字段**(V38):`memory_conflicts.new_memory` JSON 存 `category/key/keyZh/value/confidence/entities/anchorHalfvec/anchorTokens`。KEEP_NEW/flag/createFlagged 物化新行从快照建,须带 `keyZh`+`entities`+anchor,否则 survivor 行 `memory_key_zh`/`entities`/anchor 全空(V38 bug,演进详 [09-个人记忆-演进与待办.md](09-个人记忆-演进与待办.md))。KEEP_BOTH 走 `mergeIntoRow` COALESCE 保留旧值不受影响。

## 冲突状态机
| 状态 | 行为 |
|---|---|
| **PENDING** | new 事实暂存快照(不入库),锁会话(每 session+user 仅 1 个),带 askText 追加进当轮回复问用户。超时未答 → 懒触发 `flag()` 转 FLAGGED。 |
| **FLAGGED** | new 立即带 `conflict_id` 入库 + old 同组打标(绕唯一约束,新旧双值共存)。面板可见,用户 batch-resolve。不占 PENDING 锁。 |
| **RESOLVED** | 用户决定 KEEP_NEW / KEEP_OLD / **KEEP_BOTH**(合并成一条 clean,value 去重 join `,`,重 embed)/ DISCARD 后落库。 |

一句话多冲突:首轮建 PENDING + 单一 askText;同轮后续 `createFlagged` 直建 FLAGGED(不丢事实、不阻塞)。

## 异步与浮现
- **异步模式** `getMemoryProcessMode`:`ASYNC`(默认,stream+非 stream 都 fire-and-forget 到 `memoryTaskExecutor`,不 gate 回复)/ `HYBRID`(同步 gate 回复,可选)。`interceptConflict`(PENDING 答复判定)保持同步。
- **前端浮现**:[chat store](../../frontend/src/stores/chat.ts) 常驻 3s 轮询 `GET /chat/memories/status`,`memoryProcessing` + `activeConflictCount` 驱动 ChatView 状态条 + 记忆按钮 `n-badge`。无 SSE/WS push。
- **写入异常不静默**:applyClean 真异常 → `memoryIncidents`(per-user ConcurrentMap)+ ERROR 日志;前端轮询顺带取 `GET /chat/memories/incident`(取即清)→ ChatView 弹 `useMessage().error` 6s。

## 系统设置(均在 [RagMemorySettingsTab.vue](../../frontend/src/components/settings/RagMemorySettingsTab.vue),admin)
| key | 用途 | 默认 |
|---|---|---|
| `rag.memory.enabled` | 全局记忆开关 | — |
| `rag.memory.retrieval-mode` | 检索模式 | `LLM_FULL_CONTEXT` |

设置走 `system_settings` KV 表 upsert,**无 Flyway 迁移**。详见 [21-系统设置](21-系统设置.md)。

## 项目记忆 scope(当前态:V34 混合模型)
- **home(写归属/唯一性槽)**:`home_project_id`(NULL=global)。key 在 `(user, home)` 内唯一 → 每项目可独立存同 key。
- **可见性(读注入/共享)**:`is_global` + `user_memory_projects`(多对多)。决定读时哪些 scope 拉它 → 一条记忆可跨项目共享。
- **读语义**:按开关(`mem_include_global` + `mem_read_project_ids[]`)筛,同 key 多条全注入(global+项目并存,不项目级覆盖)。home 不参与读过滤。
- **写目标**:`session.project_id`(null=global)。新事实 `is_global=(project_id==null)`。
- 详见 [09-个人记忆-设计与原理.md](09-个人记忆-设计与原理.md)「项目记忆 home + 可见性混合(V34)」节。

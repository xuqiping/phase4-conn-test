# 反馈中心测试方案（19x）

> 判定依据：核心逻辑（抢态/限流/脱敏/权限）已被自动化覆盖（后端单测+IT、前端 vitest）；本方案只收 **机器断言不了、必须人介入** 的链路——跨角色端到端体感与真实渲染。用例取自规格 §8.2（`docs/specs/反馈中心设计.md`）。

## 前置条件

- 后端起 dev（V141/V142 已 migrate），前端 dev；两个账号：admin（持 feedback:manage+help:manage）、普通用户 U1、普通用户 U2。
- 浏览器开两个窗口（或隐身窗口）分别登 admin 与 U1，便于观察通知实时性。

## 用例

### TC-1 建议全链（提交带截图 → 审核 → 铃铛 → 回复可见）

1. U1 进「反馈与帮助 → 提建议」，填标题+正文，添加 **2 张截图**，提交。
   - 预期：提示「建议已提交」；我的建议列表首行状态「待审核」。
2. admin 进「反馈处理 → 建议审核」，状态筛「待审核」，点「审核」。
   - 预期：modal 见 U1 用户名、2 张附件**缩略图**，点击放大正常。
3. 填回复「排期处理」，点「采纳」。
   - 预期：成功提示；列表该行变「已采纳」。
4. U1 窗口观察顶栏 💬 铃铛（≤3s 内未读+1），点开通知。
   - 预期：自动跳反馈中心建议 tab；「查看」modal 见状态「已采纳」+ 回复「排期处理」+附件仍在。

### TC-2 提问 → 公开 FAQ → 他人检索（脱敏确认）

1. U1「提问题」提交「积分怎么算？」。
2. admin「提问回答」点「回答」，填 markdown 答案（含 `代码块`），勾「公开到 FAQ」，提交。
   - 预期：提示「已回答并通知提问人」。
3. U2（另一个用户）进提问 tab，FAQ 输入「积分」。
   - 预期：检索命中该问答；页面上**任何位置看不到提问人 U1 的用户名**（查看页面源码/网络响应也无 username 字段）。
4. U1 点铃铛通知 → 跳提问 tab → 查看答案 markdown 渲染正确。

### TC-3 说明文章（markdown 渲染 + 发布闸 + 404）

1. admin「帮助文章」新建：slug=`how-to-recharge`，正文含代码块与表格，保存。
   - 预期：提示「已创建（未发布，用户不可见）」。
2. U1「使用说明」tab。
   - 预期：目录里**没有**该文；直输 `GET /api/feedback/help/articles/how-to-recharge` 返回 404 文案「不存在或未发布」。
3. admin 开发布开关；U1 刷新说明台。
   - 预期：目录出现该文（分类正确、排序生效）；点开正文代码块/表格渲染正确；文中若含 `<script>` 字样只显示为文本。
4. admin 下架该文 → U1 刷新 → 文章消失。

### TC-4 限流文案

1. U1 在建议表单 1 分钟内连续提交 6 次（内容任意）。
   - 预期：第 6 次弹出限流人话文案（429），前 5 次均成功；等 1 分钟后可再提交。提问表单同理（与建议分开计数——建议被限后提问仍可提交 5 次）。

## 通过标准

- 四条全过；TC-2 脱敏项任何环节露提问人用户名即 FAIL。
- TC-1/TC-2 铃铛 3s 内出现红点；点击跳转 tab 正确。

## 2026-08-10 · 资产 Step 3

- 实现独立公共申请状态机：PENDING/APPROVED/REJECTED/REVOKED，同项目同申请人只保留一条记录。
- 并发申请使用 PostgreSQL `ON CONFLICT DO NOTHING` 幂等落库；拒绝/撤销后通过条件更新清空决定字段并回到 PENDING。
- OWNER/管理员审批和拒绝仅允许 PENDING，撤销仅允许 APPROVED；更新行数为 0 时返回冲突，避免双决定。
- ACL 在 owner/member/admin 之后识别公众池：OPEN 和本人 APPROVED 返回只读 VIEWER，PENDING/REJECTED/REVOKED/移出均拒绝；公共 VIEWER 写操作继续 403。
- 新增申请、本人状态、OWNER 列表、决定和撤销 REST 接口；项目转让回归测试确认发布者及官方标记快照保持不变。
- TDD RED：先观察状态机/VO 缺失、ACL 构造契约缺失、控制器缺失；定向 29/29 通过，资产模块全量 120/120 通过。
- 当前：Step 3 完成；下一步资产 Step 4 事务复制当前版本。

## 2026-08-10 · 资产 Step 4

- 新增 `POST /api/assets/assets/{assetId}/copy`，请求只需目标项目 id；服务端依次校验源读权和目标写权。
- 事务内用 `SELECT id ... FOR UPDATE` 锁定源资产行，再读取被锁定的当前版本，避免并发建版把“当前版本”切换掉。
- 副本新建独立资产与版本 1，正文和 `fileId` 取当前版本快照；不复制物理文件、历史版本和画布绑定，源后续更新不会反向同步。
- 目标缺少媒体类型时同事务补入 `{key,category}`；同名类型类别不一致返回 409。角色仅保留目标项目已有桶。
- 安全与运维：双 ACL 校验、版本存在性校验、失败由 Spring 事务整体回滚；复制日志含 action、源/目标 projectId、源/目标 assetId、userId。

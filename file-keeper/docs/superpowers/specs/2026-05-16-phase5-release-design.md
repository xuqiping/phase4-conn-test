## 2. 性能优化设计

### 2.1 虚拟滚动（Virtual Scrolling）

#### 目标
支持流畅显示几千个文件，只渲染可见区域的文件卡片。

#### 技术方案

**方案选择**：
- **选项 A**: 使用 `vue-virtual-scroller` 库（成熟方案，但体积较大）
- **选项 B**: 使用 `@vueuse/core` 的 `useVirtualList`（轻量，但需要自己处理布局）
- **推荐**: 选项 B，因为项目已经依赖 `@vueuse/core`，无需额外依赖

**实现细节**：

1. **网格视图虚拟滚动**：
   - 计算容器高度和每行卡片数量
   - 使用 `useVirtualList` 计算可见行范围
   - 只渲染可见行的文件卡片（约 3-5 行，15-25 个卡片）
   - 使用绝对定位保持滚动条正确

2. **列表视图虚拟滚动**：
   - 每行固定高度（约 60px）
   - 计算可见行数（约 10-15 行）
   - 渲染可见行 + 上下各 5 行缓冲区

3. **拖拽排序兼容性**：
   - sortablejs 需要真实 DOM 节点
   - 方案：虚拟滚动时禁用拖拽排序，或增加缓冲区确保拖拽目标在 DOM 中
   - 推荐：增加缓冲区（上下各渲染 10 个额外节点）

**性能指标**：
- 1000 个文件时，DOM 节点从 1000 个降到 30-50 个
- 滚动帧率保持 60fps
- 内存占用降低 70%+

#### 数据结构

```typescript
// 虚拟滚动配置
interface VirtualScrollConfig {
  itemHeight: number        // 单个项目高度（列表视图）
  itemsPerRow: number       // 每行项目数（网格视图）
  overscan: number          // 缓冲区大小（上下额外渲染的项目数）
  containerHeight: number   // 容器高度
}
```

### 2.2 搜索防抖（Search Debounce）

#### 目标
避免每次按键都触发搜索，减少不必要的计算。

#### 技术方案

使用 `@vueuse/core` 的 `watchDebounced` 监听搜索输入：

```typescript
import { watchDebounced } from '@vueuse/core'

// 在 fileStore 中
watchDebounced(
  () => searchQuery.value,
  (newQuery) => {
    // 执行搜索过滤
    performSearch(newQuery)
  },
  { debounce: 300 }
)
```

**实现细节**：
- 延迟 300ms 后执行搜索
- 保持高亮功能正常工作
- 搜索框显示加载状态（可选）

**性能指标**：
- 输入"test"时，只在输入完成后 300ms 执行一次搜索
- 减少 75% 的搜索计算次数

### 2.3 图标懒加载（Icon Lazy Loading）

#### 目标
文件图标按需加载，避免启动时一次性提取所有图标。

#### 技术方案

**加载策略**：
1. **添加文件时**：不立即提取图标，先显示扩展名图标
2. **进入可视区域**：使用 Intersection Observer 监听文件卡片
3. **异步提取**：卡片进入可视区域后，异步调用 `extractFileIcon`
4. **缓存**：提取后更新 FileItem.icon 并持久化到 localStorage

**实现细节**：

```typescript
// 在 App.vue 中
import { useIntersectionObserver } from '@vueuse/core'

// 为每个文件卡片设置 Intersection Observer
const { stop } = useIntersectionObserver(
  cardRef,
  ([{ isIntersecting }]) => {
    if (isIntersecting && !file.icon) {
      // 异步提取图标
      extractAndCacheIcon(file)
    }
  },
  { threshold: 0.1 }
)
```

**优先级策略**：
- 可见区域的文件优先提取
- 使用队列控制并发数（最多 5 个同时提取）
- 已缓存的图标直接使用，不重复提取

**性能指标**：
- 启动时间从可能的 2-3 秒降到 < 500ms
- 图标提取分散到滚动过程中，用户无感知
- 首屏图标在 1 秒内全部加载完成

```json
{
  "bundle": {
    "active": true,
    "targets": ["msi"],
    "identifier": "com.filekeeper.app",
    "icon": [
      "icons/32x32.png",
```

- `certificateThumbprint: null` — 无代码签名

## 7. 风险与限制

### 7.1 技术风险

**虚拟滚动与拖拽排序冲突**：
- 风险：sortablejs 需要真实 DOM，虚拟滚动可能导致拖拽失效
- 缓解：增加缓冲区，确保拖拽目标在 DOM 中
- 备选：虚拟滚动时禁用拖拽排序

**图标懒加载性能**：
- 风险：大量并发图标提取可能导致卡顿
- 缓解：使用队列控制并发数（最多 5 个）
- 备选：降低图标提取优先级

### 7.2 已知限制

- **平台支持**：仅支持 Windows，macOS/Linux 留到后续版本
- **代码签名**：无签名，安装时有 SmartScreen 警告
- **进程管理**：准确率约 95%，部分进程无法识别
- **网络功能**：无云同步、团队协作等功能

### 7.3 后续优化方向

- 优化进程管理算法，提升准确率到 99%+
- 支持 macOS/Linux 平台
- 添加代码签名（公开发布版）
- 实现额外功能（云同步、团队协作等）

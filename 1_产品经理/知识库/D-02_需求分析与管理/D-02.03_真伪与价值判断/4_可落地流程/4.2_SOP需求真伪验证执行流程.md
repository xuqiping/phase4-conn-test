# 4.2 SOP 需求真伪验证执行流程

> 📅 2026-07-11 ｜ 🔴红线：疑似伪需求必须先验证再开发，禁止"先做再说" ｜ 角色：需求验证执行PM

## 背景

伪需求造成的浪费远大于验证成本——一个伪需求从开发到上线到发现没人用，平均浪费3-5人周。而一次MVP验证只需1-3天。投资回报比>10:1。

## 目标

从需求输入到"通过/打回/观察"判定的完整流程，确保每个需求都经过真伪筛查。

## 关键结果

1. 真伪判定结果（真/伪/待验证）
2. 验证实验记录（如有）
3. 打回/通过决策记录

## 执行步骤

### Phase 1：伪需求快速自检（30min）

| 步骤 | 动作 | 输出 |
|---|---|---|
| 1.1 | 运行伪需求6种模式匹配 | 嫌疑模式+嫌疑度 |
| 1.2 | 运行6问自检清单 | 通过/不通过项 |
| 1.3 | 判断：0-1个嫌疑+≥5项通过 → ✅可信；2+嫌疑或≥2项不通过 → 进入Phase 2 |

### Phase 2：三准则深度判断（1-2h）

| 步骤 | 动作 | 输出 |
|---|---|---|
| 2.1 | 场景匹配验证：用JTBD四问检验 | 场景是否具体/明确 |
| 2.2 | 行为验证：查搜索日志/行为路径/变通行为 | 有无行为信号 |
| 2.3 | 价值量化：计算影响面×频次×单价÷成本 | ROI初步估算 |
| 2.4 | 三准则交叉判定 | 判定类别（真/伪/灰色） |

### Phase 3：MVP验证（1-5天，仅灰色地带需求）

| 需求类型 | 推荐验证 | 周期 |
|---|---|---|
| 低不确定性+数据充分 | 数据验证 | 1天 |
| 中不确定性+C端 | 假门测试 | 2-3天 |
| 中不确定性+B端 | 原型测试+访谈 | 3-5天 |
| 高不确定性 | 梯度验证(V0.1) | 5天+ |

### Phase 4：判定与记录（30min）

| 判定 | 条件 | 后续动作 |
|---|---|---|
| **✅真需求** | 三准则≥2项通过+验证通过 | 进入优先级排序(→D-02.04~08) |
| **❌伪需求** | 三准则≥2项不通过+验证失败 | 打回+记录+Revisit条件 |
| **⏳待验证** | 信号矛盾/数据不足 | 设计验证实验→30天内完成 |

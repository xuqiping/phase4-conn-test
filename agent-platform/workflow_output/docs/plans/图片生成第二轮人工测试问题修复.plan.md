## 背景与目标

图片生成页历史区 5 个未解决问题，全部围绕「历史记录」体验：

| # | 问题 | 根因 | 修法一句话 |
|---|---|---|---|
| 2 | 图片记录混进视频生成历史 | `GET /api/media/tasks` 无类型过滤参数，视频页查了全量 | 后端加 `kind=VIDEO/IMAGE` 过滤，视频页传 VIDEO |
| 4 | 图片页历史无提示词/时间筛选 | 后端已支持 q/from/to，图片页前端没接 | 照抄视频页筛选 UI + 防抖 + 竞态守卫 |
| 1 | 历史行看不到图，要点开才知道内容 | 历史行纯文本 | 行内加首张缩略图（懒加载） |
| 3 | 点历史记录不还原左侧参数 | VO（视图对象）只透出 prompt/size/outputFormat | `getTask` 单查透出 `requestConfig` 原始 JSON，点击时拉取并回填表单 |
| 5 | 看不到当时发给大模型的实际参数 | requestConfig 未透出 | 同 #3 同一字段，加「参数」按钮弹窗展示格式化 JSON |

**关键决策**：
- `requestConfig`（用户提交时落库的原始参数 JSON，含 refFileIds）**只在 `GET /tasks/{id}` 单查透出，不进列表 VO**——列表 50 行 × prompt 最长 8000 字符会撑爆响应体。点击历史行时先 `getTask(id)` 拉全量，还原表单 + 结果区 + JSON 弹窗共用这一次拉取。
- 问题 5 用户要核对的是「参考图等是否正确发送」= requestConfig 里的 refFileIds/参数，**不是** Ark 最终请求体（`buildImageRequest` 派生物，未持久化）。持久化 Ark body 属「后续再说」（见运维考量）。
- kind 过滤放**后端 SQL**，不放前端内存过滤——`LIMIT 50` 先截断再过滤会导致视频页行数不足/仍混杂。

## 技术实现坑点预判与规避措施

| 技术点/功能块 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| （性能）30 行历史 × 缩略图 blob 拉取 | 挂载即 30 并发请求 + objectURL 不释放内存泄漏 | IntersectionObserver 懒加载 + 并发上限 4 + Map(taskId→url) 缓存 + 筛选重载/卸载时统一 revoke | vitest 测加载器并发；手动看 Network 不爆发 |
| `<img>` 直塞下载端点 | 无 Authorization header 裂图 | 复用既有 `fetchMediaBlob`（带 token 拉 blob 转 objectURL），同结果区图片路径 | 缩略图真实出图 |
| MyBatis `<script>` 拼 kind 条件 | kind 值注入 | kind 只进 `<if test>` 字符串等值比较（不插值进 SQL）+ service 层白名单校验（IMAGE/VIDEO/null，其余 400） | 单测传非法 kind 断言 400 |
| （性能）列表 SQL 加 task_type 条件 | task_type 列无索引全表扫 | 现状 LIMIT≤100 + ORDER BY created_at DESC 已走 created_at 索引，行数据量小（个人任务表），**不加索引**，后续量大涨再说 | explain 看一眼（可选） |
| 点历史行还原参数 vs `onModelChange` 重置 | 先设 model 触发 onModelChange 把其余字段重置成默认值，还原被吞 | 还原**不走** onModelChange：直接逐项赋值 form（model 最后或最先均可，只要不调 onModelChange）；还原后 cap computed 自然生效 | vitest 纯函数 + 手动点历史 |
| 还原参考图 refFileIds | 文件已删/无权限 → fetchFilePreview 失败 | 逐张 try/catch 跳过，结束统一 warning「N 张参考图已失效」；超过当前模型 cap 截断并 warning | 手动：删掉一张参考图再点历史 |
| 历史模型已被 admin 删除 | cap=null → 表单控件全隐藏，用户看不到还原值 | form.model 仍赋值（下拉显示原始 modelId），message.warning 提示模型已下线；JSON 弹窗仍可核对 | 手动构造 |
| size 还原：预设 vs 自定义 WxH | requestConfig.size='1536x1024' 不在预设枚举 | sizePresets 含则直接选；否则 form.size='__custom__' 且 customSize 回填 | vitest 纯函数 |
| 筛选防抖竞态 | 快速输入返回乱序覆盖 | 照抄 VideoGenView：requestSeq 自增守卫 + 300ms 防抖 | 既有模式复用，手动验证 |
| 工作树有他人 WIP | `MediaGenQueryServiceTest.java` 在工作树已被改（git status M） | 改前先读该文件确认 WIP 内容，追加不覆盖；冲突则停下问人 | 改前 git diff 该文件 |

## 安全检查清单

- [ ] **鉴权/授权**：`requestConfig` 透出走既有 `mayAccessFile`（归属或 admin）门控，与 imageUrls 同一闸——非归属用户拿到 null，前端弹窗禁用
- [ ] **输入校验**：kind 白名单（IMAGE/VIDEO/缺省全量），非法值 `BusinessException(BAD_REQUEST)`；q≤8000/limit 1-100/from<to 既有校验不动
- [ ] **XSS**：JSON 展示用文本插值 `<pre>{{ json }}</pre>`，禁 v-html
- [ ] **审计**：全部为读路径，无新写操作，不加审计点（submit 已有 @AuditLog）
- [ ] **错误处理**：kind 非法只报「kind 仅支持 IMAGE/VIDEO」，不泄 SQL 细节

## 性能考虑与验证计划

- [ ] **查询效率**：selectHistory 加一个 task_type IN 条件，无 N+1（仍单条 SQL）；列表 VO 不含 requestConfig 避免大响应体
- [ ] **资源使用**：缩略图懒加载 + 并发上限 + objectURL 全量 revoke（卸载/筛选重载/切历史行）
- [ ] **性能验证**：Phase 4 看历史区滚 30 行 Network 请求数 ≤ 可视行数 + 缓冲上限

## 术语表（专业术语 · 大白话 · 案例）

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| requestConfig | 提交任务时落库的原始参数 JSON（用户视角「我发了什么」） | `{"prompt":"猫","size":"2K","refFileIds":["f1"]}` |
| MediaTaskVO | 后端吐给前端的任务视图对象（字段裁剪+归属门控） | 列表行、轮询响应都是它 |
| mayAccessFile | 归属门控布尔：本人或 admin 才 true，决定敏感字段是否透出 | 非本人任务 imageUrls=null |
| kind 过滤 | 按任务大类（视频/图片）在 SQL 层过滤历史 | kind=VIDEO → 只查 TEXT2VIDEO/IMAGE2VIDEO |
| objectURL | 浏览器把 blob 转成本地临时 URL 给 `<img>` 用，绕过 img 标签不能带 token 的限制 | `URL.createObjectURL(blob)` |
| IntersectionObserver | 浏览器原生「元素滚进视口才通知」API，做懒加载 | 历史行滚到屏内才拉缩略图 |
| requestSeq 守卫 | 自增序号防竞态：慢的旧响应回来时被丢弃 | 快速输「猫」→「猫咪」只显后者结果 |
| onModelChange | 切模型时把表单重置成该模型默认值的函数（还原参数时必须绕开它） | 直接逐项赋值代替调用 |

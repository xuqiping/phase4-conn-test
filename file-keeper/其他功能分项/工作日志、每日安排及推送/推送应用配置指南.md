# 工作汇报推送应用配置指南（傻瓜式）

> 本文档面向最终用户，手把手说明如何把「工作汇报」推送到 **飞书**、**钉钉** 等即时通讯应用，并支持 **对话、文件收发、已读回执** 等高级能力。  
> 适用模块：`work-report`（工作汇报）。

---

## 一、先确认你的推送方式

本系统目前支持以下推送通道：

| 平台 | 当前实现方式 | 适用场景 | 需要填写的字段 |
|---|---|---|---|
| **飞书** | 企业自建应用 + `tenant_access_token` | 群消息 / 个人消息 / 文件 / 已读 / 接收回复 | `chat_id`（群）/ `open_id`（个人）+ `App ID` / `App Secret` |
| **钉钉** | 群机器人 Webhook | 只发到群 | `access_token`（Webhook 里的 token）+ `secret`（加签密钥，可选） |
| **钉钉（高级）** | 企业内部应用 | 私发个人、文件、已读回执、接收用户回复 | `userid` / `chat_id` + `AppKey` / `AppSecret` / `AgentId` |

> 提示：
> - 企业微信、Slack 在类型定义中已预留，但后端暂未实现，敬请期待。
> - 飞书和钉钉的「对话、文件收发、已读回执」都属于高级能力，除了应用后台配置外，还需要后端代码实现对应的接口调用。本文档会列出所需的**权限、API、事件订阅**等配置。

---

## 二、飞书配置（企业自建应用）

### 2.1 创建企业自建应用

1. 打开 [飞书开放平台](https://open.feishu.cn/app)，用企业管理员账号登录。
2. 点击 **「创建企业自建应用」**。
3. 填写应用名称（例如：`工作汇报推送`）、应用描述，上传图标后点击 **「创建应用」**。

[截图：飞书开放平台创建应用页面]

### 2.2 开启机器人能力

1. 进入应用详情页 → 左侧 **「应用能力」** → **「机器人」**。
2. 打开 **「机器人」** 开关。
3. 记录页面中的 **「机器人名称」**，后面需要把机器人加入目标群。

> 如果要实现「接收用户消息/文件」，机器人能力必须开启。

[截图：开启机器人能力开关]

### 2.3 申请发送消息权限

1. 进入应用详情页 → 左侧 **「权限管理」**。
2. 搜索并勾选以下权限（至少）：
   - `im:message:send` —— 发送消息（核心）
   - `contact:user.base:readonly` —— 读取用户基本信息（用于通过邮箱/手机号换 open_id）
3. 点击右上角 **「申请权限」**，等待企业管理员审批。

> 如果只需要往群里发消息，理论上 `im:message:send` 即可；若通过邮箱查用户 open_id，则需要通讯录相关权限。

[截图：权限管理页面勾选 im:message:send]

### 2.4 发布应用并审批

1. 进入 **「版本管理与发布」** → 点击 **「创建版本」**。
2. 填写版本号、更新说明，点击 **「保存」** → **「申请发布」**。
3. 让企业管理员在 **飞书管理后台 → 工作台 → 应用审核** 中通过审核。

只有审核通过后，`tenant_access_token` 才能正常调用发送消息接口。

### 2.5 获取 App ID / App Secret

1. 进入应用详情页 → **「凭证与基础信息」**。
2. 复制：
   - **App ID**：形如 `cli_xxxxxxxxxxxxxxxx`
   - **App Secret**：点击显示后复制，注意保密
3. 在本系统的 **凭据** 框中填入如下 JSON：

```json
{
  "appId": "cli_xxxxxxxxxxxxxxxx",
  "appSecret": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
}
```

[截图：应用凭证页面复制 App ID / App Secret]

### 2.6 获取群 ID（chat_id）或用户 Open ID

#### 群 ID（发给群时）

1. 将机器人加入目标群：打开群聊 → 右上角 **「…」** → **「群设置」** → **「群机器人」** → 添加刚才创建的应用机器人。
2. 获取 `chat_id` 的推荐方式：进入 [飞书 API 调试台](https://open.feishu.cn/api-explorer/)，选择应用，调用 **「获取群列表」** `/open-apis/im/v1/chats`，返回中的 `chat_id` 即为群 ID（以 `oc_` 开头）。

```json
{
  "items": [
    {
      "chat_id": "oc_xxxxxxxxxxxxxxxx",
      "name": "研发团队日报群"
    }
  ]
}
```

3. 把 `oc_xxxxxxxxxxxxxxxx` 填入本系统的 **目标 ID** 框，**目标类型** 选 **群**。

#### 用户 Open ID（发给个人时）

1. 在 API 调试台选择 **「批量获取用户 ID」** `/open-apis/contact/v3/users/batch_get_id`。
2. 传入用户邮箱或手机号：

```json
{
  "emails": ["zhangsan@example.com"]
}
```

3. 返回结果中的 `open_id`（以 `ou_` 开头）即为目标 ID。
4. 把 `ou_xxxxxxxxxxxxxxxx` 填入本系统的 **目标 ID** 框，**目标类型** 选 **个人**。

[截图：API 调试台获取 chat_id / open_id]

### 2.7 测试推送

回到本系统：

1. 进入 **工作汇报 → 报告配置**。
2. 新建或编辑一条配置，添加推送目标：
   - 平台：**飞书**
   - 目标类型：**群** 或 **个人**
   - 目标 ID：上面拿到的 `chat_id` / `open_id`
   - 凭据：上面那串 JSON
3. 点击 **「推送报告」** 或等待定时任务触发。
4. 如果失败，请查看 **推送记录** 中的错误信息，常见问题：权限未审批、机器人未加群、ID 填错。

## 三、飞书高级能力：对话、收发文件、已读回执

> 本节介绍飞书企业自建应用如何实现 **双向对话**、**发送/接收文件**、**消息已读回执**。  
> 当前系统后端 [`FeishuPusher.java`](../../../server/src/main/java/com/superprogrammer/workreport/service/push/FeishuPusher.java) 默认只发送文本消息；如需本节能力，需要开发同学在服务端扩展对应接口。

### 3.1 接收用户消息（实现对话）

要让应用能收到用户回复，需要配置 **事件订阅**：

1. 进入应用详情页 → **「事件与回调」**。
2. **选择订阅方式**：
   - **长连接（WebSocket）模式**：推荐，无需公网地址，适合本地/内网环境。在页面中选择 **「使用长连接接收事件」** 后保存。
   - **HTTP 回调模式**：需要公网 HTTPS 地址，例如 `https://your-domain.com/api/feishu/event`
3. 订阅以下事件（至少）：
   - `im.message.receive_v1` —— 接收用户消息（单聊 / 群聊 @机器人）
   - `im.message.message_read_v1` —— 消息已读回执（如需已读功能）
4. 保存页面的 **Verification Token** 和 **Encrypt Key**，用于验证和解密回调。
5. 服务端收到回调后：
   - 验证 challenge（首次配置时）
   - 用 Encrypt Key 解密 `encrypt` 字段
   - 根据 `event.message.message_type` 判断是文本、图片、文件等
   - 返回正确的响应给飞书

### 3.2 发送文件 / 图片

发送文件需要先上传文件拿到 `file_key`，再调用发送消息接口。

#### 第一步：上传文件

```http
POST https://open.feishu.cn/open-apis/im/v1/files
Authorization: Bearer {tenant_access_token}
Content-Type: multipart/form-data

file_type=pdf
file_name=report.pdf
file=<二进制文件内容>
```

返回：

```json
{
  "code": 0,
  "data": {
    "file_key": "file_xxxxxxxx"
  }
}
```

#### 第二步：发送文件消息

```http
POST https://open.feishu.cn/open-apis/im/v1/messages?receive_id_type=open_id
Authorization: Bearer {tenant_access_token}
Content-Type: application/json

{
  "receive_id": "ou_xxxxxxxx",
  "msg_type": "file",
  "content": "{\"file_key\":\"file_xxxxxxxx\"}"
}
```

发送图片流程类似，上传接口为 `/open-apis/im/v1/images`，消息类型用 `image`。

### 3.3 接收文件 / 图片

在 `im.message.receive_v1` 事件里，如果用户发送的是文件/图片，事件体会包含 `file_key` 或 `image_key`。

下载文件：

```http
GET https://open.feishu.cn/open-apis/im/v1/files/{file_key}
Authorization: Bearer {tenant_access_token}
```

下载图片：

```http
GET https://open.feishu.cn/open-apis/im/v1/messages/{message_id}/resources/{image_key}?type=image
Authorization: Bearer {tenant_access_token}
```

### 3.4 消息已读回执

订阅 `im.message.message_read_v1` 事件后，当用户已读消息时，飞书会推送：

```json
{
  "event": {
    "message_id": "om_xxxxxxxx",
    "reader": {
      "reader_id": {
        "open_id": "ou_xxxxxxxx"
      },
      "read_time": "1699000000000"
    }
  }
}
```

服务端根据 `message_id` 和 `open_id` 记录已读状态。

### 3.5 涉及权限汇总

| 能力 | 权限标识（参考） | 说明 |
|---|---|---|
| 发送消息 | `im:message:send` | 基础发送权限 |
| 以机器人身份发消息 | `im:message:send_as_bot` | 旧版接口可能需要 |
| 接收用户消息 | `im:message`, `im:message.p2p_msg:readonly`, `im:message.group_at_msg:readonly` | 单聊 / 群 @ 机器人 |
| 获取消息中的文件/图片 | `im:resource` | 下载文件、图片资源 |
| 读取用户基本信息 | `contact:user.base:readonly`, `contact:user.id:readonly` | 识别发送者 |
| 获取群信息 | `im:chat:readonly` | 如需处理群消息 |

申请后需要企业管理员审批。

### 3.6 在本系统中填写（假设后端已扩展）

如果后续后端实现了飞书对话/文件/已读能力，配置方式不变：

- 平台：**飞书**
- 目标类型：**群** 或 **个人**
- 目标 ID：`chat_id` / `open_id`
- 凭据 JSON：

```json
{
  "appId": "cli_xxxxxxxxxxxxxxxx",
  "appSecret": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
}
```

事件订阅的回调地址、Token、Encrypt Key 由后端服务统一管理，不需要在前端填写。

## 四、钉钉配置（群机器人 Webhook）

### 4.1 添加自定义机器人

1. 打开目标钉钉群 → 右上角 **「群设置」**（齿轮图标）。
2. 选择 **「智能群助手」** → **「添加机器人」** → **「自定义」** → **「添加」**。
3. 设置机器人 **名称** 和 **头像**，点击 **「完成」**。

[截图：钉钉群设置中添加自定义机器人]

### 4.2 安全设置（必须选至少一项）

钉钉要求至少开启一种安全校验，推荐如下：

| 安全方式 | 适用场景 | 本系统如何填写 |
|---|---|---|
| **自定义关键词** | 简单场景 | 消息里必须包含关键词，如「日报」 |
| **加签** | 推荐，更安全 | 需要把 **secret** 填入本系统凭据框 |
| **IP 地址段** | 服务器有固定公网 IP | 在钉钉后台填入服务端出口 IP |

如果选择 **加签**：

1. 在机器人设置页开启 **「加签」**。
2. 复制生成的 **SEC** 开头字符串（例如 `SECxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`）。
3. 把该字符串填入本系统的 **凭据** 框。

[截图：钉钉机器人加签设置]

### 4.3 获取 Webhook 地址与 access_token

1. 机器人创建完成后，页面会显示一个 Webhook 地址，形如：

```text
https://oapi.dingtalk.com/robot/send?access_token=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

2. 复制 `access_token=` 后面的值（不含 `access_token=`）。
3. 把该值填入本系统的 **目标 ID** 框。

[截图：复制钉钉机器人 Webhook 中的 access_token]

### 4.4 在本系统中填写

在 **工作汇报 → 报告配置 → 推送目标** 中：

- 平台：**钉钉**
- 目标类型：**群**（钉钉群机器人目前只能发到群）
- 目标 ID：`access_token` 的值
- 凭据：如果开启了加签，填 `SEC` 密钥；否则留空

### 4.5 测试推送

1. 点击 **「推送报告」**。
2. 如果钉钉后台设置了「自定义关键词」，请确保报告模板内容里包含该关键词；否则钉钉会拒绝消息。
3. 查看推送记录排查失败原因。

## 五、钉钉高级配置（企业自建应用）：私发个人、文件、已读、接收回复

> 本节适用于需要 **把消息私发到个人钉钉工作通知**、**发送/接收文件**、**查询对方是否已读**、**接收用户回复/反馈** 的场景。  
> 当前系统后端 [`DingTalkPusher.java`](../../../server/src/main/java/com/superprogrammer/workreport/service/push/DingTalkPusher.java) 只实现了群机器人 Webhook；如需本节能力，需要开发同学在服务端新增「钉钉企业内部应用」通道。

### 5.1 创建企业内部应用

1. 打开 [钉钉开发者后台](https://open-dev.dingtalk.com)，用企业管理员账号登录。
2. 进入 **「应用开发」** → **「企业内部应用」** → 点击 **「创建应用」**。
3. 选择应用类型（H5 微应用或小程序均可），填写应用名称，例如：`工作汇报推送`。
4. 创建成功后进入应用详情页，记录以下三项关键信息：
   - **AppKey**（形如 `dingxxxxxxxxxxxxxxxx`）
   - **AppSecret**
   - **AgentId**（发送工作通知时需要）

[截图：钉钉开发者后台应用详情页复制 AppKey / AppSecret / AgentId]

### 5.2 申请接口权限

在应用详情页 → **「权限管理」** 中，申请以下权限（具体权限名以开发者后台为准）：

| 能力 | 需要申请的权限（参考） |
|---|---|
| 获取 access_token | 调用企业 API 基础权限 |
| 根据手机号查 userId | 通讯录个人信息读权限 / 根据手机号姓名获取成员信息 |
| 发送工作通知 | 企业会话消息异步发送权限（CorpConversation） |
| 上传媒体文件 | 文件或图片上传相关权限 |
| 接收用户回复/文件 | 机器人消息读取 / 事件订阅相关权限 |
| 查询已读状态 | 工作通知发送结果查询权限 |

申请后需要企业管理员审批才能生效。

### 5.3 获取 access_token

#### 旧版服务端 API（`oapi.dingtalk.com`）

```http
GET https://oapi.dingtalk.com/gettoken?appkey=YOUR_APPKEY&appsecret=YOUR_APPSECRET
```

返回示例：

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "access_token": "fw8ef8we8f76e6f7s8dxxxx",
  "expires_in": 7200
}
```

#### 新版服务端 API（`api.dingtalk.com`，推荐）

```http
POST https://api.dingtalk.com/v1.0/oauth2/accessToken
Content-Type: application/json

{
  "appKey": "YOUR_APPKEY",
  "appSecret": "YOUR_APPSECRET"
}
```

返回示例：

```json
{
  "expireIn": 7200,
  "accessToken": "a21b7e86XXXXXXXXXXXXXXXX"
}
```

> 注意：access_token 有效期约 2 小时，建议在服务端缓存，不要写在前端。

### 5.4 获取用户 userId

钉钉个人消息需要接收者的 `userid`。如果只有手机号，可调用：

```http
POST https://oapi.dingtalk.com/topapi/v2/user/getbymobile?access_token=YOUR_ACCESS_TOKEN
Content-Type: application/json

{
  "mobile": "13800138000"
}
```

返回示例：

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "result": {
    "userid": "zhangsan"
  }
}
```

- 该接口仅支持 **企业内部应用** 调用。
- 如果企业开通了 **专属账号**，需要额外设置 `support_exclusive_account_search: true`，并从 `exclusive_account_userid_list` 中读取。

[截图：API 调试台根据手机号获取 userid]

### 5.5 私发个人消息（工作通知）

使用 **异步发送企业会话消息** 接口：

```http
POST https://oapi.dingtalk.com/topapi/message/corpconversation/asyncsend_v2?access_token=YOUR_ACCESS_TOKEN
Content-Type: application/json

{
  "agent_id": "123456789",
  "userid_list": "zhangsan,lisi",
  "msg": {
    "msgtype": "text",
    "text": {
      "content": "今日日报已生成，请查看。"
    }
  }
}
```

关键参数说明：

| 参数 | 说明 |
|---|---|
| `agent_id` | 应用的 AgentId |
| `userid_list` | 接收者 userid，多个用逗号分隔，最大 100 个 |
| `dept_id_list` | 接收部门 ID 列表，最大 20 个（含子部门） |
| `to_all_user` | 是否发送给企业全部用户 |
| `msg` | 消息体，支持 text、markdown、oa、action_card、feed_card 等 |

返回示例：

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "task_id": 1234567890123
}
```

请务必保存返回的 `task_id`，用于后续查询发送结果。

#### 频率限制（企业内部应用）

- 单次最多给 **5000 人**发送；第三方企业应用单次最多 1000 人。
- 给同一员工一天只能发送 **一条内容相同** 的消息。
- 每天给每个员工最多发送 **500 条** 消息通知。
- 每分钟最多有 **5000 人** 可接收到消息。

### 5.6 发送文件 / 图片

#### 第一步：上传媒体文件获取 media_id

```http
POST https://oapi.dingtalk.com/media/upload?access_token=YOUR_ACCESS_TOKEN&type=file
Content-Type: multipart/form-data

media=<二进制文件内容>
```

`type` 可选值：`image`、`voice`、`video`、`file`。

返回示例：

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "type": "file",
  "media_id": "@lALPDeC2zJovPMnNBNBNBD2"
}
```

#### 第二步：发送文件 / 图片工作通知

```http
POST https://oapi.dingtalk.com/topapi/message/corpconversation/asyncsend_v2?access_token=YOUR_ACCESS_TOKEN
Content-Type: application/json

{
  "agent_id": "123456789",
  "userid_list": "zhangsan",
  "msg": {
    "msgtype": "file",
    "file": {
      "media_id": "@lALPDeC2zJovPMnNBNBNBD2"
    }
  }
}
```

图片消息把 `msgtype` 改为 `image`，内容改为 `{"image": {"media_id": "..."}}`。

> 文件大小限制：通常小于 50 MB；`media_id` 有效期约 3 天。

### 5.7 查询已读状态

使用 `task_id` 查询发送结果：

```http
POST https://oapi.dingtalk.com/topapi/message/corpconversation/getsendresult?access_token=YOUR_ACCESS_TOKEN
Content-Type: application/json

{
  "agent_id": "123456789",
  "task_id": 1234567890123
}
```

返回示例（已读/未读列表）：

```json
{
  "errcode": 0,
  "errmsg": "ok",
  "send_result": {
    "invalid_staff_ids": "",
    "read_staff_ids": "zhangsan",
    "unread_staff_ids": "lisi"
  }
}
```

- `read_staff_ids`：已读用户 userid 列表
- `unread_staff_ids`：未读用户 userid 列表
- `invalid_staff_ids`：无效用户 userid 列表

> 注意：工作通知的已读状态会有一定延迟，且部分消息类型可能不支持已读回执，具体以官方文档为准。

### 5.8 接收用户回复 / 接收文件

要接收用户回复或用户发来的文件，需要在钉钉开放平台配置 **事件订阅**，常见有两种方式：

#### 方式 A：HTTP 回调模式

1. 进入应用详情页 → **「事件订阅」** → 开启事件订阅。
2. 配置：
   - **回调 URL**：你的服务端公网地址，例如 `https://your-domain.com/api/dingtalk/callback`
   - **Token**：自定义，用于生成签名
   - **EncodingAESKey**：数据加密密钥，点击随机生成
3. 订阅需要的事件，例如：
   - 机器人消息事件（用户单聊/群聊消息）
   - 文件/图片消息事件
4. 钉钉会把加密后的消息 `POST` 到你的回调 URL，服务端需要：
   1. 用 Token + EncodingAESKey 解密请求体中的 `encrypt` 字段；
   2. 根据 `EventType` 判断事件类型；
   3. 处理用户消息内容或文件 `media_id`；
   4. 返回加密后的 `"success"` 字符串给钉钉。

官方加解密示例代码：
- [open-dingtalk/dingtalk-callback-Crypto](https://github.com/open-dingtalk/dingtalk-callback-Crypto)

> 重要：回调接口需在 **约 60 秒内返回响应**，否则钉钉会触发重试，导致重复接收。建议基于 `msg_id` 做幂等去重。

#### 方式 B：Stream 模式（推荐机器人场景）

- 不需要公网回调 URL，通过长连接接收钉钉事件。
- 适合机器人单聊/群聊场景。
- 常见 Topic：`/v1.0/im/bot/messages/get`
- 需要使用钉钉官方 SDK 或自己维护一条长连接。

更多参考：
- [钉钉回调事件总览](https://developers.dingtalk.com/document/app/callback-overview)
- [配置事件订阅](https://developers.dingtalk.com/document/app/configure-event-subcription/title-bec-rsq-8wj)

### 5.9 在本系统中填写（假设后端已支持企业自建应用）

如果后续后端实现了钉钉企业自建应用通道，配置方式预计如下：

- 平台：**钉钉**
- 目标类型：**个人**（私发工作通知）/ **群**（服务群消息）
- 目标 ID：用户 `userid` 或群 `chat_id`
- 凭据 JSON：

```json
{
  "appKey": "dingxxxxxxxxxxxxxxxx",
  "appSecret": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "agentId": "123456789"
}
```

## 六、月度固定计划 31 号说明

在「固定工作 → 月度」里选择 31 号时：

- 1、3、5、7、8、10、12 月：31 号正常触发。
- 2、4、6、9、11 月：这些月份没有 31 号，系统会**自动 fallback 到当月最后一天**触发（例如 2 月 28 号、4 月 30 号）。
- 不会重复触发：如果同时勾选了 28、29、30、31 号，而在只有 28 天的月份里，只会触发一次。

相关代码见 [`ReminderScheduleService.java`](../../../server/src/main/java/com/superprogrammer/workreport/service/ReminderScheduleService.java)。

## 七、常见问题（FAQ）

### Q1：飞书提示 "Access denied" 或 "权限不足"

- 检查应用是否已申请 `im:message:send` 权限并经过管理员审批。
- 检查应用版本是否已发布并通过审核。
- 检查机器人是否已加入目标群（群场景）。
- 如需接收消息/文件，检查是否开通了 `im:message.p2p_msg:readonly` / `im:message.group_at_msg:readonly` / `im:resource`。

### Q2：能发消息但收不到用户回复

- 飞书：检查是否订阅了 `im.message.receive_v1`，以及回调地址是否正确返回 challenge。
- 钉钉：检查事件订阅是否开启，是否订阅了机器人消息事件，回调是否返回加密的 `success`。

### Q3：发送文件失败

- 飞书：检查是否开通了 `im:resource` 权限，文件大小是否超限。
- 钉钉：检查 `media_id` 是否过期（约 3 天），`type` 参数是否与文件类型一致，文件大小是否小于 50 MB。

### Q4：钉钉群机器人提示 "timestamp invalid" 或 "sign not match"

- 如果开启了加签，请确认凭据框里的 `secret` 正确且没有多余空格。
- 如果未开启加签，请把凭据框留空。

### Q5：钉钉群机器人提示 "keywords not in content"

- 在钉钉机器人后台设置的关键词必须出现在消息正文中。可在报告模板里固定加入该关键词，例如：「#日报」。

### Q6：飞书 `chat_id` 填错会怎样？

- 常见报错：`chat_id not found` 或 `chat not exist`。请通过 API 调试台重新获取，注意以 `oc_` 开头。

### Q7：钉钉企业自建应用发送工作通知时返回成功但用户没收到

- 检查 `agent_id` 是否填错。
- 检查 `userid` 是否已在当前企业内且在职。
- 检查是否超过频率限制（同一员工一天只能收到一条相同内容的消息）。
- 检查应用权限是否已审批。

### Q8：凭据 JSON 格式不对

飞书凭据必须是严格的 JSON，例如：

```json
{
  "appId": "cli_abc123",
  "appSecret": "abc123secret"
}
```

注意：
- 使用英文双引号 `"`
- 不要加注释
- 不要有多余逗号

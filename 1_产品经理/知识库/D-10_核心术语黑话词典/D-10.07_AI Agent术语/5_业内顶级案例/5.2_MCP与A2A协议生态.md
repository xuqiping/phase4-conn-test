# 案例：MCP与A2A协议生态——协议层的真实格局

## 术语映射

| 术语 | 在本案例中的体现 |
|---|---|
| MCP | Anthropic推出的"AI的USB接口"——统一Agent连接工具/数据的方式 |
| A2A | Google推出的"Agent的社交协议"——让不同平台Agent互相发现和协作 |
| ACP | 边缘场景的补充——本地设备的Agent通信 |
| Skills | 在MCP之上的能力封装——Dify/Coze等平台的"技能市场" |
| Function Calling | 最底层的原语——MCP/A2A都建立在Function Calling之上 |

## 生态现状 [来源:公开信息 | 🔍高 | 2026-06]

| 协议 | 推出方 | 时间 | 定位 | 生态规模 |
|---|---|---|---|---|
| MCP | Anthropic | 2024-11 | Agent→工具/数据 | 1000+ MCP Server |
| A2A | Google | 2025-04 | Agent↔Agent | 50+ 企业支持 |
| ACP | 行业标准 | 2025-2026 | 边缘Agent通信 | 形成中 |

## 产品决策启示

1. **MCP适合绝大多数Agent产品**：工具/数据接入是刚需，MCP生态最成熟
2. **A2A适合跨组织协作场景**：内部Agent用编排即可，跨组织才需要A2A
3. **不要过早引入协议层**：原型阶段直连FC，验证后再迁移到MCP/A2A

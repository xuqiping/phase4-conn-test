# 5.4 Salesforce 复杂B端需求建模

## 背景

Salesforce是全球最大的SaaS CRM平台，服务数十万企业客户。其需求分析的核心挑战是：**如何在一个平台上满足通用的行业需求+个性化的客户定制**。Salesforce的解法是**元数据驱动的需求建模**——不直接实现需求，而是建模需求背后的模式。[来源:Salesforce Engineering Blog | 📚中 | 2022]

## 多层级需求分解

### Salesforce的三层需求体系

```
L1: 平台能力（Platform Capabilities）
  → 通用基础设施：对象建模/工作流引擎/权限体系/API框架
  → 对标：Epic级

L2: 行业云（Industry Cloud）
  → 行业特定能力：Financial Services Cloud / Health Cloud / ...
  → 对标：Feature级

L3: 客户定制（Customer Customization）
  → 单个客户的个性化配置
  → 对标：Story级，但通过低代码而非硬编码实现
```

### 关键设计决策：通用性 vs 专用性

| 需求来源 | 处理方式 | 分析方法 | 建模输出 |
|---|---|---|---|
| 1个客户提出 | L3层配置 | 5Why+场景分析 | 自定义字段/流程/审批 |
| 5+客户提出相同需求 | L2层行业化 | 依赖分析+共性提取 | 行业云模块 |
| 20+客户跨行业提出 | L1层平台化 | 根因分析+抽象建模 | 平台核心能力 |

> 核心洞察：**在Salesforce，"做不做"的分析不是看需求本身，而是看"这个需求属于哪个层级"**——层级判断=通用性判断。[来源:📚训练知识]

## B端需求建模的工具组合

| 分析阶段 | 工具 | 输出 | 目的 |
|---|---|---|---|
| 角色与权限 | 用例图+权限矩阵 | 角色权限表 | 识别多角色交互 |
| 业务流程 | 流程图+泳道图 | 跨角色流程 | 理解协作与审批 |
| 数据流转 | ER图+状态图 | 数据模型 | 识别实体关系与状态变迁 |
| 依赖关系 | 依赖矩阵 | 关键路径 | 规划交付顺序 |
| 个性化需求 | 配置矩阵 | 可配置项清单 | 平台化 vs 定制化的边界 |

## Salesforce的依赖分析实践

### 跨模块依赖矩阵

```
     模块A  模块B  模块C  模块D
模块A  -    前置    -     数据
模块B  -     -     技术   -
模块C   -   技术    -    数据
模块D 数据   -    数据    -

关键路径：模块A → 模块B → 模块C
风险点：模块C-D双向数据依赖（需要数据契约）
```

### 数据契约

Salesforce每个模块对外的数据交互都通过**数据契约**定义：
- 输入：需要什么数据、格式、频率
- 输出：提供什么数据、格式、频率
- 版本：契约版本号（向后兼容承诺）

> 这就是为什么Salesforce的API能做到"加了功能不破坏旧集成"——数据契约是依赖管理的制度化工具。[来源:📚训练知识]

## PM收获

1. **B端需求分析的起点是角色+流程，不是功能**——用例图和泳道图比需求列表有效
2. **依赖分析的输出不是"关系"，而是"契约"**——数据契约让依赖可管理
3. **通用性判断决定需求放在哪个层级**——1个客户→配置，5个客户→行业化，20+客户→平台化
4. **B端需求建模需要三种图并用**——流程图(做what)+状态图(何时)+ER图(存什么)

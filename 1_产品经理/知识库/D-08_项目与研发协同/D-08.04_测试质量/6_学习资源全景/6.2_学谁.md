## 1. James Bach

| 维度 | 内容 |
|---|---|
| 姓名 | James Bach |
| 身份 | 探索性测试之父、Satisfice创始人、Context-Driven Testing学派联合发起人 |
| 国籍 | 美国 |
| 核心成就 | 定义探索性测试（Exploratory Testing）方法论；创立Context-Driven Testing学派；推动测试从"脚本执行"转向"思维探索"；著《Lessons Learned in Software Testing》和《Secrets of a Buccaneer-Scholar》 |
| **思维模型** | **上下文驱动测试**——不存在放之四海皆准的"最佳测试实践"，测试策略必须根据项目上下文（风险/资源/时间/团队能力）定制。"Best Practice is a dangerous term." |
| **行动范式** | 探索性测试三循环：Test→Design→Learn——不停留在预设用例，而是在测试过程中持续学习产品行为、调整测试策略。用Session-Based Test Management将探索性测试结构化（时间盒+Charter+Debrief） |
| 可学习点 | PM做质量评估时，不要只看"用例通过率"，还要问"我们探索了哪些未知区域？"——脚本测试验证已知，探索性测试发现未知 |
| 代表作 | 《Lessons Learned in Software Testing》(2002) / 《Secrets of a Buccaneer-Scholar》(2011) / Satisfice博客 |

| **思维模型** | **测试金字塔不仅是比例，更是投资策略**——底层单元测试投入产出比最高（快速/精准/低成本），顶层E2E测试投入产出比最低（慢速/脆弱/高维护）。金字塔的形状=投资回报的形状 |
| **行动范式** | "测试下移"策略——遇到测试覆盖不足时，不是"加更多E2E测试"，而是"将E2E场景拆解为单元+集成测试组合"。一个E2E用例的维护成本≈10个单元用例，但诊断能力远不如后者 |
| 可学习点 | PM做质量投入规划时，先问"我们的测试投资在金字塔底部吗？"。如果80%在E2E层——是时候"测试下移"了 |

| 维度 | 内容 |
|---|---|

| 身份 | 极限编程(XP)创始人、JUnit共同创建者、TDD方法论奠基人、Facebook前工程师 |
| 国籍 | 美国 |
| 核心成就 | 发明测试驱动开发（TDD）——"Red-Green-Refactor"循环；共同创建JUnit——Java单元测试事实标准；提出"Simple Design"原则；极限编程(XP)的核心实践者 |
| **思维模型** | **TDD=设计方法而非测试方法**——TDD的首要产出不是"测试用例"，而是"可测试的设计"。先写测试迫使你从使用者视角设计接口，代码天然松耦合、高内聚。"Test First is Design First." |
| **行动范式** | Red-Green-Refactor三步循环：①写一个失败的测试（Red）→②写最少代码让测试通过（Green）→③重构代码消除重复（Refactor）。循环时间≤5分钟，高频小步 |
| 可学习点 | PM在需求评审时推动"可测试性设计"——如果PM写的验收标准不能前置为测试用例，说明需求设计本身不够清晰。Kent Beck证明：测试的难度=设计的质量 |
| 代表作 | 《Test-Driven Development: By Example》(2002) / 《Extreme Programming Explained》(1999) / 《Implementation Patterns》(2007) |

# 5.3 微信小程序UV统计：跨端去重的三重映射困局

## 基本信息

- **时间**：2017–2026
- **主角**：微信开放平台 / 小程序产品团队
- **产品**：微信小程序

## 背景

微信小程序的UV统计是国内"跨端去重"最复杂的案例之一。一个用户可能通过微信App打开小程序，也可能在企业微信中打开，还可能在PC微信中打开——三种入口、三种ID体系、同一用户。UV口径的选择直接影响广告计费、招商谈判和运营决策。

## 跨端ID映射三层级

### 第一层：OpenID（单端唯一）

```
同一用户在微信App小程序 → OpenID_A
同一用户在企业微信小程序 → OpenID_B
同一用户在PC微信小程序 → OpenID_C
```

**问题**：同一个自然人产生了3个UV，如果按OpenID去重，跨端UV被严重虚增。

> [来源:微信开放平台官方文档 | 置信度:🔍高]

### 第二层：UnionID（同主体合并）

```
同一主体下所有小程序/公众号 → UnionID
OpenID_A → UnionID_X
OpenID_B → UnionID_X  ← 企业微信需满足"同主体"条件
OpenID_C → UnionID_X  ← PC微信同主体
```

**问题**：UnionID只在"同一微信开放平台账号下的所有应用"才一致。如果企业的小程序和公众号注册在不同主体下（如总公司/子公司），UnionID无法合并。

> [来源:微信开放平台官方文档 | 置信度:🔍高]

### 第三层：手机号/自定义ID（跨体系映射）

```
UnionID_X → 绑定手机号 → 业务UserID
```

**问题**：手机号可以换、用户可以不授权、企业微信和微信App手机号可能不同。映射链断裂率约5-15%。

> [来源:作者实践+行业讨论 | 置信度:📚中]

## UV口径的三个版本

| 口径版本 | 去重依据 | UV表现 | 适用场景 |
|---|---|---|---|
| 严格口径 | UnionID去重，跨端合并 | 最低（最真实） | 运营分析、ROI计算 |
| 中间口径 | OpenID去重，同端不跨端 | 中间值 | 微信生态广告结算 |
| 宽松口径 | 访问去重（Session级），不区分用户 | 最高（水分最大） | PR/融资叙事 |

**口径博弈实例**：
- 广告主按"UV"付费 → 要求严格口径
- 小程序开发者报"日活" → 倾向宽松口径
- 微信官方数据看板 → 默认使用中间口径（OpenID），但不标注跨端重复

> [来源:微信开放平台官方文档+广告主实践 | 置信度:📚中]

## 教训与启示

1. **跨端场景下UV天然有水分**——任何只报一个UV数字的团队，一定没有做过跨端去重
2. **ID映射链可靠性决定数据质量**——OpenID 100% → UnionID ~90% → 手机号 ~80% → 业务ID ~75%，每层映射都在丢失
3. **PM必须根据决策场景选口径**——算ROI用严格口径，做增长汇报用宽松口径，但必须标注口径差异

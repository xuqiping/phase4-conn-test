# 计划8阶段一、阶段二与阶段三功能测试要求

> 创建时间：2026-06-03  
> 适用分支：`codex/plan8-runtime-composition`  
> 测试目标：验证“多智能体与工作流自由组合”的阶段一、阶段二与阶段三能力：Java 侧已具备标准 Runtime 协议、WorkflowDefinition 转换、mock runtime 事件流、执行日志父子链/checkpoint 引用存储能力；前端工作流画布已支持 `AGENT_REF` / `WORKFLOW_REF` 拖拽、配置、保存和回显；Python sidecar 已提供 HTTP/SSE 与 LangGraph `StateGraph` 最小执行边界。

### 4.4 RuntimeExecutionService 最小闭环

功能说明：

`RuntimeExecutionService` 串起以下流程：

1. 读取工作流详情
2. 转换为 `WorkflowDefinition`
3. 创建 root execution log
4. 构造 `ExecutionRequest`
5. 调用 `RuntimeGateway`
6. 保存每个 `ExecutionEvent`
7. 更新 `externalThreadId` / `checkpointRef`
8. 执行完成后标记 SUCCESS

测试方式：

运行：

```bash
cd agent-platform/backend
mvn -q "-Dtest=RuntimeExecutionServiceTest" test
```

期望：

- 能生成 `ExecutionRequest`
- `executionId` 与执行日志 ID 对齐
- `rootExecutionId` 正确
- 输入参数不丢失
- 完成事件会调用 `finishExecution`
- runtime refs 会写入执行日志

失败判定：

- 没有创建 execution log
- 事件没有保存
- 完成后没有标记 SUCCESS
- `externalThreadId` / `checkpointRef` 没有更新

- `AGENT_REF` 事件中 `sourceType=AGENT` 且 `sourceId` 来自 `agentId`
- `WORKFLOW_REF` 事件中 `sourceType=WORKFLOW` 且 `sourceId` 来自 `workflowId`
- `CONDITION` 节点会根据 `config.inputPath` 读取输入字段，并选择匹配出边 `condition` 的目标节点
- 没有匹配条件时，如果配置了 `defaultTarget`，会走默认目标
- 出边 `condition` 支持 `field == value`、`field != value`、`field > number`、`field >= number`、`field < number`、`field <= number`、`field contains value`、`field exists`
- `ROUTER` 节点输出包含 `selectedRoute` 和 `selectedTarget`
- `JOIN` 节点输出包含 `joinedNodeIds` 和 `joinedOutputs`

失败判定：

- sidecar 无法启动
- SSE 响应不是 `text/event-stream`
- 事件缺少 `executionId`、`rootExecutionId`、`traceId` 或 `externalThreadId`
- 事件 metadata 不包含 `engine=langgraph`
- 引用节点事件没有正确填充 `sourceType` / `sourceId`
- 条件分支同时执行多个分支
- 条件节点没有记录 `selectedTarget`

### 4.9 LangGraph 图编译

功能说明：

`graph_compiler.py` 负责把 Java 传来的标准工作流定义转换为 LangGraph `StateGraph`。当前只接受 DAG；循环引用会在编译前拒绝，避免运行时无限递归。

测试方式：

运行：

```bash
cd agent-platform/runtime-sidecar
python -m pytest -q tests/test_graph_compiler.py
```

期望：

- 节点执行顺序由边关系决定，而不是前端节点数组顺序。
- `AGENT_REF` 节点输出包含 `sourceType=AGENT` 和 `sourceId`。
- `WORKFLOW_REF` 节点输出包含 `sourceType=WORKFLOW` 和 `sourceId`。
- 循环图抛出 `workflow graph contains a cycle`。

失败判定：

- 节点数组顺序改变后执行顺序错误。
- 循环图仍然可以编译。
- 引用节点在 LangGraph 输出中丢失目标 ID。

### 4.10 CONDITION 条件分支与表达式

功能说明：

`CONDITION` 节点用于根据输入字段选择下一条出边。当前约定：

- `node.config.inputPath`：从请求 `input` 中读取的字段路径，例如 `route` 或 `user.intent`。
- `edge.condition`：该出边匹配的值，例如 `sales`、`support`。
- `node.config.defaultTarget`：没有匹配时走的默认目标节点 ID，可选。

当 `edge.condition` 是表达式时，支持以下受限格式：

- `score >= 80`
- `score < 80`
- `status == approved`
- `status != rejected`
- `tags contains vip`
- `user.email exists`

测试方式：

运行：

```bash
cd agent-platform/runtime-sidecar
python -m pytest -q tests/test_graph_compiler.py tests/test_runtime_api.py
```

期望：

- 输入 `{"route":"b"}` 时，只执行 `condition=b` 对应分支。
- 输入 `{"score":91}` 时，可以匹配 `score >= 80`。
- 输入 `{"tags":["basic","vip"]}` 时，可以匹配 `tags contains vip`。
- 未选中的分支不会产生节点完成事件。
- `CONDITION` 节点输出中包含 `selectedTarget`。
- `defaultTarget` 可在无匹配条件时生效。

失败判定：

- 条件节点出边被当作普通并发边，导致多个分支同时执行。
- 数值比较、contains 或 exists 表达式无法匹配。
- `selectedTarget` 为空或错误。
- 无匹配条件时没有按 `defaultTarget` 走默认分支。

### 4.11 ROUTER 规则路由

功能说明：

`ROUTER` 节点用于把输入按规则分发到不同目标节点。当前是规则路由，不调用 LLM。

节点配置示例：

```json
{
  "routes": [
    {"name": "sales", "condition": "intent == sales", "target": "sales-agent"},
    {"name": "support", "condition": "intent == support", "target": "support-agent"}
  ],
  "defaultTarget": "fallback-agent"
}
```

测试方式：

运行：

```bash
cd agent-platform/runtime-sidecar
python -m pytest -q tests/test_graph_compiler.py tests/test_runtime_api.py
```

期望：

- 输入 `{"intent":"support"}` 时，只执行 `support` 规则目标。
- 未选中的 route 不会产生节点完成事件。
- `ROUTER` 节点输出包含 `selectedRoute` 和 `selectedTarget`。
- 没有规则命中时可走 `defaultTarget`。

失败判定：

- Router 出边被当作普通并发边，导致多个 route 同时执行。
- `selectedRoute` 或 `selectedTarget` 为空。
- 未命中规则时没有走默认目标。

### 4.12 PARALLEL/JOIN 并行聚合

功能说明：

`PARALLEL` / `JOIN` 用于把一个流程拆成多个分支，并在 `JOIN` 节点等待所有入边分支完成后汇总结果。当前是 LangGraph 图级 fan-out/join 最小闭环，尚未实现分支超时、失败策略和资源并发控制。

测试方式：

运行：

```bash
cd agent-platform/runtime-sidecar
python -m pytest -q tests/test_graph_compiler.py tests/test_runtime_api.py
```

期望：

- `PARALLEL` 后的多个分支都会执行。
- `JOIN` 在所有入边分支完成后执行。
- `JOIN` 输出包含 `joinedNodeIds`。
- `JOIN` 输出包含 `joinedOutputs`，且包含每个入边分支的输出。

失败判定：

- 多个分支同时写状态导致 LangGraph `INVALID_CONCURRENT_GRAPH_UPDATE`。
- `JOIN` 在某个分支未完成前执行。
- `JOIN` 输出缺少分支输出。

### 4.13 Java 调用 sidecar

功能说明：

`SidecarRuntimeGateway` 现在会用 `WebClient` 调用 Python sidecar，并把 SSE JSON 事件解析为 Java `ExecutionEvent`。

测试方式：

运行：

```bash

```

期望：

- 请求路径是 `/api/runtime/executions`
- 请求方法是 `POST`
- 请求体包含 Java `ExecutionRequest`
- sidecar 返回的 SSE 事件能按顺序被消费
- sidecar 错误响应会被包装为明确异常

失败判定：

- Java 仍返回“Sidecar runtime gateway is not implemented yet”
- 请求路径或请求头不正确
- SSE `data:` 内容无法反序列化为 `ExecutionEvent`

# 已处理（2026-08-14）
- 详情大白话中文化 ✅ 详情字段改用共享 `DetailKvView`（键值中文渲染，username→账号、fails→连续失败次数、snippet→命中内容等，见 `utils/detailLabels.ts`）；「自动处置」列/详情由裸英文码（ACCOUNT_LOCKED 等）改为中文（新增 `AUTO_ACTION_CN` 映射：锁定账号/封禁来源IP/仅记录告警等）
- 处置过程可视化 ✅ 详情弹窗新增「处置过程」三步时间线：①事件发生（检测内容+严重度）→ ②自动处置（事件落库瞬间已执行的实际动作，按 AutoResponder 矩阵给出大白话解释：危急=锁号15分钟+封IP 24小时；高危+锁定动作=锁号15分钟；高危+封禁动作=封IP 60分钟；其余=仅记录告警）→ ③人工处置（已处置显示处置人/时间及「确认动作不会重复执行封禁」的说明；未处置说明点处置的实际语义）。处置成功 toast 同步改为完整说明文案
- 事件详情缺「谁在何时对谁做了什么」✅（第二轮 2026-08-14 修复，浏览器实测）：
  - **谁**：后端 `/security/events` 列表按本页 userId 批量 join 用户表回填 `username`（一次查询无 N+1）；前端列表「用户」列由 `用户#id` 改为 `admin #1`，详情「操作人」显示 `admin（用户#1）`
  - **做了什么**：`detailLabels.ts` 新增「具体操作/操作对象类型/目标ID/发生时刻」等 key 翻译 + `module:action` 操作码组合翻译字典（`security:event_ack` → 「安全管理 · 处置安全事件」、`billing:pricing_create` → 「计费积分 · 新建价表」等，覆盖全部 @AuditLog 动作盘点）；`OffHoursSensitiveRule` 落库时不再丢弃 `targetType/targetId`（凌晨敏感操作也能看到操作对象）
  - **参数级明细**：详情弹窗提示「可在审计日志按 traceId 关联查询」（审计日志 detail_json 有脱敏的变更参数摘要，安全事件本身不落参数明文）
  - 实测：特权变更详情显示「具体操作：计费积分 · 新建价表 / 操作对象类型：价表规则 / 操作人：admin（用户#1）」
- 哪些行为会自动封号/锁定（回答）✅ 自动处置矩阵（`AutoResponder`，均可由管理员在「安全规则」页关掉对应开关）：
  | 触发行为 | 检测条件 | 自动动作 |
  |---|---|---|
  | 登录暴破 | 同账号 15 分钟内 5 次密码错误 | **锁定该账号 15 分钟**（无法登录/调用，到期自动恢复） |
  | 撞库攻击 | 同 IP 5 分钟内尝试 ≥20 个不同账号 | **封禁该 IP 60 分钟** |
  | SQL 注入累犯 | 同 IP 1 小时内注入特征命中 ≥3 次 | **封禁该 IP 60 分钟** |
  | 危急级事件（预留档，当前 15 个检测器暂无产生者） | — | 锁号 15 分钟 + 封 IP 24 小时 |
  其余全部事件类型（特权变更/凌晨敏感操作/积分滥用/媒体滥用/Prompt注入/越权探测/异地登录/Token盗号/频率突发/注入单次探测等）**只记录+告警，不自动封禁**，由管理员在事件中心点「处置」确认（处置只是标记已处理，不会额外封号；需要封禁请去「封禁管理」手动操作）。**没有任何行为会自动永久封号**——自动锁定最长 15 分钟自动恢复，自动封 IP 最长 24 小时自动解封；永久封禁只能管理员手动执行。

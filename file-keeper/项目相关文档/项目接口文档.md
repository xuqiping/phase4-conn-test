# File Keeper 项目接口文档

## 1. 文档说明

本文档梳理 File Keeper 当前项目中的主要接口边界，包括：

- 前端 TypeScript API 封装
- Tauri 后端命令接口
- 前后端共享数据结构
- 本地持久化数据结构
- 常见错误与调用约定

File Keeper 是本地 Windows 桌面应用，不提供 HTTP 服务端接口。项目中的“接口”主要指 Vue 前端通过 Tauri `invoke` 调用 Rust 后端命令，以及前端状态管理模块之间暴露的调用方法。

## 2. 接口总览

### 2.1 文件管理相关接口

| 能力 | 前端封装 | Tauri 命令 | 说明 |
|---|---|---|---|
| 选择文件 | `pickFile()` | Tauri Dialog 插件 | 打开系统文件选择器 |
| 选择文件夹 | `pickFolder()` | Tauri Dialog 插件 | 打开系统文件夹选择器 |
| 打开文件/文件夹 | `openFile(path)` | `open_file` | 使用系统默认应用打开 |

| 在资源管理器中显示 | `showInFolder(path)` | `show_in_folder` | Windows 下调用 Explorer 定位 |
| 获取文件图标 | `getFileIcon(path, useRealIcon)` | `get_file_icon` | 返回 Base64 图标字符串或空字符串 |

### 2.2 进程管理相关接口

| 能力 | 前端封装 | Tauri 命令 | 说明 |
|---|---|---|---|
| 获取运行中应用 | `getRunningProcesses()` | `get_running_processes` | 枚举可见窗口对应进程 |

| 批量关闭应用 | `closeProcesses(windowHandles)` | `close_app_processes` | 批量发送关闭信号并返回成功/失败数 |
| 激活窗口 | `activateWindow(windowHandle)` | `activate_app_window` | 将窗口恢复并切到前台 |
| 查找占用文件的进程 | `findFileProcesses(filePath)` | `find_file_processes` | 查找与文件相关的进程 |
| 关闭文件相关进程 | `closeFileProcesses(filePath)` | `close_file_processes` | 查找并关闭文件相关进程 |

## 3. 文件管理接口

### 3.1 选择文件

前端封装：

```ts
pickFile(): Promise<string | null>
```

调用方式：

- 使用 `@tauri-apps/plugin-dialog` 的 `open` 方法
- `directory: false`
- `multiple: false`
- 默认路径为系统文档目录

返回值：

- 用户选择文件时返回文件绝对路径
- 用户取消选择时返回 `null`

### 3.2 选择文件夹

前端封装：

```ts
pickFolder(): Promise<string | null>
```

调用方式：

- 使用 `@tauri-apps/plugin-dialog` 的 `open` 方法
- `directory: true`
- `multiple: false`
- 默认路径为系统文档目录

返回值：

- 用户选择文件夹时返回文件夹绝对路径
- 用户取消选择时返回 `null`

### 3.3 打开文件或文件夹

前端封装：

```ts
openFile(path: string): Promise<void>
```

Tauri 命令：

```rust
open_file(path: String) -> Result<(), String>
```

参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `path` | `string` | 是 | 本地文件或文件夹绝对路径 |

行为：

- 如果路径不存在，返回错误
- 如果是文件夹，使用系统文件管理器打开
- 如果是文件，使用系统默认应用打开
- 如果既不是文件也不是文件夹，返回“不支持的路径类型”错误

常见错误：

| 错误场景 | 错误含义 |
|---|---|
| `文件不存在` | 目标路径已被移动、删除或不可访问 |
| `打开文件失败` | 系统默认应用打开失败 |
| `打开文件夹失败` | 文件管理器打开失败 |
| `不支持的路径类型` | 路径类型不是普通文件或目录 |

### 3.4 校验路径

前端封装：

```ts
validatePath(path: string): Promise<boolean>
```

Tauri 命令：

```rust
validate_path(path: String) -> Result<bool, String>
```

返回值：

- `true`：路径存在
- `false`：路径不存在

用途：

- 添加收藏前校验路径
- 打开文件前判断目标是否仍可用
- UI 中提示用户文件是否失效

### 3.5 在资源管理器中显示

前端封装：

```ts
showInFolder(path: string): Promise<void>
```

Tauri 命令：

```rust
show_in_folder(path: String) -> Result<(), String>
```

行为：

- Windows 文件路径：调用 `explorer /select, <path>` 并选中文件
- Windows 文件夹路径：直接打开该文件夹
- 非 Windows 平台：打开文件所在父目录或目标目录

常见错误：

| 错误场景 | 错误含义 |
|---|---|
| `路径不存在` | 文件或文件夹已不存在 |
| `打开文件夹失败` | 系统文件管理器启动失败 |

### 3.6 获取文件图标

前端封装：

```ts
getFileIcon(filePath: string, useRealIcon?: boolean): Promise<string | null>
```

Tauri 命令：

```rust
get_file_icon(path: String, use_real_icon: Option<bool>) -> Result<String, String>
```

参数：

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `path` | `string` | 无 | 文件路径 |
| `useRealIcon` / `use_real_icon` | `boolean` | `true` | 是否尽量提取真实文件图标 |

返回值：

- 成功提取时返回 Base64 图标数据
- 无法提取时返回空字符串，前端转换为 `null`
- 前端拿到 `null` 后使用扩展名或通用图标兜底

## 4. 进程管理接口

### 4.1 获取运行中应用

前端封装：

```ts
getRunningProcesses(): Promise<ProcessInfo[]>
```

Tauri 命令：

```rust
get_running_processes() -> Result<Vec<ProcessInfo>, String>
```

行为：

- 枚举 Windows 当前可见窗口
- 获取窗口标题、PID、进程名、内存、CPU、窗口句柄
- 根据内置进程映射识别应用类别
- 返回前端进程列表

返回结构：

```ts
interface ProcessInfo {
  pid: number
  name: string
  window_title: string
  category: ProcessCategory
  memory_mb: number
  cpu_usage: number
  window_handle: number
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `pid` | `number` | Windows 进程 ID |
| `name` | `string` | 进程名称，例如 `chrome.exe` |
| `window_title` | `string` | 主窗口标题 |
| `category` | `ProcessCategory` | 应用类别 |
| `memory_mb` | `number` | 内存占用，单位 MB |
| `cpu_usage` | `number` | CPU 使用率 |
| `window_handle` | `number` | Windows 窗口句柄，前端选择和关闭操作使用该值 |

### 4.2 进程类别枚举

```ts
type ProcessCategory =
  | 'All'
  | 'Browser'
  | 'Office'
  | 'Explorer'
  | 'Terminal'
  | 'Archive'
  | 'Document'
  | 'Media'
  | 'Image'
  | 'Communication'
  | 'Download'
  | 'Game'
  | 'System'
  | 'Other'
```

说明：

- Rust 后端实际返回除 `All` 以外的类别
- `All` 是前端筛选使用的聚合类别
- 未识别进程归入 `Other`

### 4.3 关闭单个应用

前端封装：

```ts
closeProcess(windowHandle: number): Promise<void>
```

Tauri 命令：

```rust
close_app_process(window_handle: usize) -> Result<(), String>
```

参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `windowHandle` / `window_handle` | `number` / `usize` | 是 | 目标窗口句柄 |

行为：

- 后端将 `window_handle` 转为 Windows `HWND`
- 调用 Windows 消息机制向目标窗口发送关闭请求
- 关闭方式偏温和，适合桌面整理，不等同于强制结束进程

成功后前端行为：

- 从当前进程列表移除目标项
- 从选中集合中移除目标窗口句柄
- 弹出关闭成功提示

常见失败：

| 错误 | 可能原因 | 前端提示策略 |
|---|---|---|
| `拒绝访问` / `0x80070005` | 目标应用权限高于 File Keeper，或属于受保护窗口 | 提示用户尝试以管理员身份启动 File Keeper |
| `Process not found` | 前端列表中的窗口已刷新消失 | 提示关闭失败并等待下次刷新 |
| 其他系统错误 | 窗口句柄失效、目标进程状态变化 | 展示关闭失败提示 |

### 4.4 批量关闭应用

前端封装：

```ts
closeProcesses(windowHandles: number[]): Promise<CloseResult>
```

Tauri 命令：

```rust
close_app_processes(window_handles: Vec<usize>) -> Result<CloseResult, String>
```

参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `windowHandles` / `window_handles` | `number[]` / `Vec<usize>` | 是 | 待关闭窗口句柄列表 |

返回结构：

```ts
interface CloseResult {
  succeeded: number
  failed: number
}
```

前端处理：

- `succeeded > 0` 时，从列表中移除已选择的窗口项
- `failed > 0` 时，记录错误信息并提示部分失败
- 该接口适合配合全选、反选、类别筛选后的批量清理使用

### 4.5 激活窗口

前端封装：

```ts
activateWindow(windowHandle: number): Promise<void>
```

Tauri 命令：

```rust
activate_app_window(window_handle: usize) -> Result<(), String>
```

行为：

- 如果窗口最小化，先恢复窗口
- 尝试将窗口切换到前台
- 成功后前端显示“已切到前台”提示

常见失败：

- 目标窗口句柄已失效
- Windows 前台窗口限制导致切换失败
- 目标进程已退出

Tauri 命令：

前端封装：

```ts
closeFileProcesses(filePath: string): Promise<number>
```


## 6. 前端状态管理接口

### 6.1 文件 Store

Store：`useFileStore`

核心状态：

| 状态 | 类型 | 说明 |
|---|---|---|
| `files` | `FileItem[]` | 收藏文件和文件夹列表 |
| `searchQuery` | `string` | 搜索输入 |
| `debouncedSearchQuery` | `string` | 防抖后的搜索词 |
| `sortBy` | `'custom' \| 'openCount' \| 'name' \| 'lastOpened' \| 'createdAt'` | 当前排序方式 |

核心数据结构：

```ts
interface FileItem {
  id: string
  name: string
  path: string
  type: 'file' | 'folder'
  icon?: string
  tags: string[]
  groupId: string
  description?: string
  createdAt: number
  lastOpened?: number
  openCount: number
  orderIndex?: number
}
```

主要能力：

- 按分组过滤文件
- 按搜索词过滤名称、路径、标签
- 支持通配符搜索
- 按自定义顺序、打开次数、名称、最近打开、添加时间排序
- 打开文件后更新打开次数和最近打开时间

### 6.2 分组 Store

Store：`useGroupStore`

核心数据结构：

```ts
interface Group {
  id: string
  name: string
  color?: string
  icon?: string
  order: number
  createdAt: number
}
```

默认分组：

| ID | 名称 | 说明 |
|---|---|---|
| `all` | 全部 | 查看全部文件 |
| `recent` | 最近打开 | 查看高频或近期打开文件 |

主要方法：

| 方法 | 说明 |
|---|---|
| `setCurrentGroup(id)` | 切换当前分组 |
| `addGroup(name, color?, icon?)` | 新增自定义分组 |
| `removeGroup(id)` | 删除自定义分组，默认分组不可删除 |
| `updateGroup(id, updates)` | 更新分组信息 |
| `reorderGroups(newOrder)` | 更新分组排序 |
| `loadGroups(data)` | 从持久化数据加载分组 |

### 6.3 进程 Store

Store：`useProcessStore`

核心状态：

| 状态 | 类型 | 说明 |
|---|---|---|
| `processes` | `ProcessInfo[]` | 当前进程列表 |
| `selectedIds` | `Set<number>` | 选中的窗口句柄集合 |
| `currentCategory` | `ProcessCategory` | 当前类别筛选 |
| `isRefreshing` | `boolean` | 是否正在刷新 |
| `lastRefreshTime` | `number` | 最近刷新时间戳 |
| `error` | `string \| null` | 最近错误信息 |
| `sortKey` | `ProcessSortKey \| null` | 当前排序列 |
| `sortDirection` | `'asc' \| 'desc'` | 排序方向 |

派生数据：

| 派生数据 | 说明 |
|---|---|
| `filteredProcesses` | 按类别和排序处理后的进程列表 |
| `selectedCount` | 当前选中数量 |
| `categoryCounts` | 各类别进程数量 |
| `selectedProcesses` | 当前选中的进程对象列表 |

主要方法：

| 方法 | 说明 |
|---|---|
| `refresh()` | 调用后端刷新进程列表 |
| `toggleSelect(windowHandle)` | 切换单项选择 |
| `selectAll()` | 选择当前筛选结果中的全部项 |
| `deselectAll()` | 清空选择 |
| `invertSelection()` | 对当前筛选结果反选 |
| `setCategory(category)` | 切换类别筛选 |
| `setSort(key)` | 设置或切换排序 |
| `closeProcess(windowHandle)` | 关闭单个窗口对应应用 |
| `closeSelected()` | 批量关闭当前选中应用 |
| `clearProcesses()` | 清空列表并重置筛选 |
| `clearError()` | 清空错误信息 |

### 6.4 进程设置 Store

Store：`useProcessSettingsStore`

持久化键：`process-settings`

核心数据结构：

```ts
interface ProcessSettings {
  columns: ColumnConfig[]
  autoRefresh: boolean
  refreshInterval: number
  confirmMode: ConfirmMode
  whitelist: string[]
}

interface ColumnConfig {
  key: string
  label: string
  width: string
  visible: boolean
  sortable: boolean
}

type ConfirmMode = 'always' | 'whitelist' | 'never'
```

默认设置：

| 设置项 | 默认值 | 说明 |
|---|---|---|
| `autoRefresh` | `false` | 默认不自动刷新 |
| `refreshInterval` | `5000` | 自动刷新间隔 5 秒 |
| `confirmMode` | `whitelist` | 白名单进程需要确认 |
| `whitelist` | 系统关键进程列表 | 减少误关关键应用 |

主要方法：

| 方法 | 说明 |
|---|---|
| `loadSettings()` | 从 localStorage 加载设置 |
| `saveSettings()` | 保存设置到 localStorage |
| `updateColumns(columns)` | 更新列显示和顺序 |
| `updateAutoRefresh(enabled)` | 开关自动刷新 |
| `updateRefreshInterval(interval)` | 更新刷新间隔 |
| `updateConfirmMode(mode)` | 更新确认模式 |
| `updateWhitelist(whitelist)` | 批量更新白名单 |
| `addToWhitelist(processName)` | 添加白名单进程 |
| `removeFromWhitelist(processName)` | 移除白名单进程 |
| `resetToDefaults()` | 恢复默认设置 |

## 7. 本地持久化接口

File Keeper 当前主要使用两类本地持久化：

1. Pinia 持久化插件，用于文件、分组、偏好等业务状态
2. `localStorage`，用于进程管理设置和语言选择

### 7.1 文件与分组持久化

文件和分组 Store 通过 Pinia persist 配置保存。

示例：

| Store | 持久化 Key | 保存内容 |
|---|---|---|
| `useGroupStore` | `groups` | `groups`, `currentGroupId` |
| `useFileStore` | 由 Store 配置决定 | 文件列表、搜索/排序相关状态 |

### 7.2 进程设置持久化

进程设置使用浏览器 `localStorage`：

| Key | 内容 |
|---|---|
| `process-settings` | 列设置、自动刷新、刷新间隔、确认模式、白名单 |

### 7.3 语言设置持久化

语言切换使用 `localStorage` 保存当前语言。

| Key | 内容 |
|---|---|
| `file-keeper-locale` | `zh-CN` 或 `en-US` |

## 8. 调用约定与错误处理

### 8.1 前端调用约定

- 所有 Tauri 命令通过 `@tauri-apps/api/core` 的 `invoke` 调用
- 前端 API 层负责把底层错误包装成业务可理解的错误
- UI 组件不直接调用 Rust 命令，优先调用 `src/api/*` 或 Store 方法
- Store 负责维护列表状态、选择状态、筛选状态和错误状态

### 8.2 Rust 命令返回约定

Rust 后端命令统一使用：

```rust
Result<T, String>
```

约定：

- `Ok(T)`：命令执行成功
- `Err(String)`：命令执行失败，字符串中包含错误原因

### 8.3 权限相关错误

关闭 Windows 应用时，可能遇到：

```text
拒绝访问。 (0x80070005)
```

常见原因：

- 目标应用以管理员权限运行
- 目标窗口属于系统或受保护进程
- 当前 File Keeper 进程权限低于目标应用
- Windows 安全策略阻止跨权限窗口操作

前端处理策略：

- 识别 `0x80070005`、`Access is denied`、`拒绝访问`
- 用更明确的人话提示用户：目标应用可能权限更高，可尝试以管理员身份启动 File Keeper

## 9. 接口使用示例

### 9.1 打开收藏文件

```ts
import { openFile } from '@/api/files'

await openFile(file.path)
```

业务层通常还会同步更新：

- `openCount + 1`
- `lastOpened = Date.now()`

### 9.2 刷新进程列表

```ts
const processStore = useProcessStore()
await processStore.refresh()
```

刷新成功后：

- `processes` 更新为后端返回列表
- `lastRefreshTime` 更新为当前时间
- 已不存在的窗口句柄会从选择集合中移除

### 9.3 按类别筛选浏览器

```ts
const processStore = useProcessStore()
processStore.setCategory('Browser')
```

UI 使用 `filteredProcesses` 渲染筛选结果。

### 9.4 关闭单个进程窗口

```ts
const ok = await processStore.closeProcess(process.window_handle)
```

返回值：

- `true`：关闭请求发送成功，并从列表移除
- `false`：关闭失败，错误写入 `processStore.error`

### 9.5 批量关闭选中应用

```ts
const result = await processStore.closeSelected()
```

返回结构：

```ts
{
  success: number
  failed: number
}
```

## 10. 后续接口优化建议

1. 统一 `src/api/process.ts` 和 `src/api/processes.ts` 的命名与职责，减少单个关闭接口重复定义。
2. 为 Rust 后端错误增加结构化错误码，避免前端只能用字符串匹配判断权限错误。
3. 为进程关闭接口补充更细粒度结果，例如每个窗口句柄对应成功或失败原因。
4. 将进程设置从裸 `localStorage` 迁移到统一持久化层，便于备份和迁移。
5. 为文件占用进程接口补充更明确的 UI 入口和使用说明。
6. 为图标接口增加缓存策略说明，避免频繁提取真实图标影响大量文件列表性能。

---

## 11. 总结

File Keeper 当前接口体系以本地桌面能力为核心：前端负责交互、筛选、状态和提示，Rust/Tauri 后端负责访问本地文件系统、Windows 图标能力和窗口进程能力。整体接口数量不多，但覆盖了“常用文件快速访问”和“Windows 应用管理”两条核心产品能力。

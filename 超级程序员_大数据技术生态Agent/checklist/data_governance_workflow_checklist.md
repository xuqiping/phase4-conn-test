# Data Governance Workflow Checklist

在完成 `workflow/data_governance_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别数据治理需求场景

- [ ] 已明确场景类型（治理体系搭建/数据标准制定/数据血缘建设/数据质量提升/元数据管理/治理组织设计/AI数据治理）
- [ ] 已识别治理成熟度（DCMM L1-L5：初始级/受管理级/稳健级/量化管理级/优化级）
- [ ] 已提取数据资产规模（数据源数量/数据量TB PB/数据消费者数量）
- [ ] 已提取关键痛点（数据找不到/不敢用/不一致/变更影响不明/合规风险/AI训练数据问题）
- [ ] 已提取合规要求（等保/数据安全法/个人信息保护法/行业监管/信创）
- [ ] 已识别现有工具（数据目录/血缘工具/质量工具/元数据平台）
- [ ] 已对照知识库核心洞察完成初步判断（治理是BI和AI前置条件/找不到→DataHub/同名不同义→语义层/质量不可信→六维模型/AI数据问题→血缘+质量）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出数据治理方案

- [ ] 如为治理体系搭建，DAMA-DMBOK+DCMM框架已覆盖（战略层/管理层/制度层/技术层）
- [ ] 如为治理体系搭建，治理组织四级架构已说明（CDO→Data Owner→Steward→DQ Council）
- [ ] 如为治理体系搭建，DCMM五级成熟度评估已输出（L1→L2→L3→L4→L5演进路径）
- [ ] 如为治理体系搭建，实施路线图已给出（Phase 1-4，12-24个月）
- [ ] 如为治理体系搭建，关键成功因素已覆盖（高层支持/业务驱动/小步快跑/度量驱动）
- [ ] 如为数据标准，标准体系已输出（业务术语/指标口径/数据元标准/参考标准DAMA DCMM OneData）
- [ ] 如为数据标准，Data Contract标准代码化已说明（JSON/YAML定义/嵌入Pipeline/版本管理）
- [ ] 如为数据标准，技术实现已覆盖（dbt tests/Great Expectations/Deequ/Soda Core）
- [ ] 如为数据标准，标准落地检查清单已给出（命名/类型/枚举值/术语/指标可追溯）
- [ ] 如为数据血缘，采集技术选型已对比（OpenLineage/Apache Atlas/DataHub/自研SQL解析）
- [ ] 如为数据血缘，应用场景已覆盖（影响分析/根因分析/合规审计/AI训练数据血缘21.9亿美元市场）
- [ ] 如为数据血缘，可视化设计已输出（图数据库Neo4j/JanusGraph/ArangoDB/节点边过滤/路径分析）
- [ ] 如为数据血缘，血缘质量保障已说明（完整性覆盖率/准确性验证/时效性/粒度）
- [ ] 如为数据质量，六维模型已覆盖（完整性/准确性/一致性/唯一性/及时性/有效性）
- [ ] 如为数据质量，AI驱动规则生成已说明（LLM自动推断规则/规则推荐置信度/人工审核）
- [ ] 如为数据质量，Data Observability五支柱已输出（新鲜度/容量/分布/Schema/血缘）
- [ ] 如为数据质量，质量改进闭环已给出（发现→根因→修复→验证→规则更新→知识沉淀）
- [ ] 如为元数据管理，元数据分类已覆盖（技术/业务/操作/管理元数据）
- [ ] 如为元数据管理，平台选型已对比（DataHub/Apache Atlas/Collibra/Amundsen）
- [ ] 如为元数据管理，主动元数据已说明（LLM驱动推断/自动化触发/智能推荐）
- [ ] 如为元数据管理，数据资产目录运营已覆盖（搜索优化/用户分层/资产价值评估）
- [ ] 所有核心论断均能在知识库中找到支撑来源

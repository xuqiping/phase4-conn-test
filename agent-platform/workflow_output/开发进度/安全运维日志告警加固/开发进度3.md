## P3-C9 9 冷规则 + 接线
- 规则（`common/security/rule/`）：IdorProbe(403≥10/5min MEDIUM)、ImpossibleTravel(geo 变+2h内 MEDIUM)、OffHoursSensitive(0-6点特权 LOW)、DataExfil(下载≥500/10min HIGH 只告警)、PointsAbuse(≥10000分/10min HIGH+锁号)、MediaAbuse(≥¥100/30min HIGH+锁号)、PromptInjection(特征库 MEDIUM，屡犯≥3/1h HIGH)、TokenReuse(≥3 IP/10min MEDIUM)、PrivilegeChange(任意特权变更 HIGH 实时)。
- `RuleRedisSupport` 基类：incrWindow/saddSize/阈值读取全降级（Redis 故障返 -1 不命中——宁漏不误封）。
- `sig/InjectionSignatureLibrary`：9 条指令式越狱正则（中英），讨论概念不误报。
- **关键 bug**：ImpossibleTravel Redis 存 "geo|ts"，geo 本身含 `|`（ip2region 段分隔）→ split 长度!=2 恒 null；修=lastIndexOf('|') 尾切。
- 接线 7 咽喉：LoginAttemptsService.recordAsync 成功分支（geo 已在异步线程，复用）、GlobalExceptionHandler 403（ObjectProvider+HttpServletRequest 参，切片兼容）、ChatSessionService.sendMessage、PointsWalletService.charge + chargeIdempotent（幂等重放不重发——事件发在 supplier 内）、MediaBillingService.chargeMedia（实扣积分=cost）、FileController.get（下载通用咽喉 count=1）、AuditLogAspect 敏感关键词（role/perm/pricing/status/grant/revoke/block/ban/setting/security 等 12 词）。
- **横切注入范式沉淀**：既有 @InjectMocks 服务加横切依赖 → `@Autowired(required=false)` 字段注入 + 调用点 null 检查（构造注入会 null 级联炸既有测试类）；新建统一入口 `SecurityEventPublisher`（自动从 RequestContextHolder 解析 clientIp，异常吞）。

## P3-C10 响应矩阵
- `AutoResponder`：总闸 security.response.auto_enabled + 分闸 auto_ip_block/auto_account_lock（system_settings 热生效）；CRITICAL=锁号15min+封IP 24h；HIGH 按 autoAction 择一（锁号/封IP 60min）；MEDIUM/LOW 只告警。
- `BanService.lockAccount`：UpdateWrapper WHERE status='ACTIVE'（不覆盖人工 BANNED/DISABLED）+ locked_until + revoke 踢下线；**BanService ctor 加 UserMapper（第 3 参，BanServiceTest 已补）**。
- `AccountUnlockScheduler`：每分钟扫 locked_until 到期 → ACTIVE + restore（只解自动锁，人工永久锁不动）。

## P4-C11 钉钉告警
- `alert/WebhookNotifier`：钉钉机器人原生 markdown 直推（绕过 Alertmanager 适配器）；HmacSHA256 加签；HttpClient 5s 超时不重试；故障吞+alertSendFailed 指标（meta 告警盯此）。
- `alert/MediumBatcher`：MEDIUM 入队 @Scheduled 30s 汇总 1 条（队列上限 500 防 OOM；重启丢批可接受——事件在库）。
- `alert/DingtalkCardBuilder`：16 事件码中文映射 + traceId + 处置深链。
- `alert/AlertRouter`：CRITICAL/HIGH 即时、MEDIUM 凑批、LOW 不推；总闸 security.alert.enabled。
- 挂接点：SecurityMonitorWorker（record 返 true 后 dispatch）。**决策变更**：plan 写「record 内调 dispatch」，实际挂 Worker——SecurityEventService.record 也被热路径（gate/auth）直调，挂 record 会双推；已知取舍=热路径事件（SQLI/暴破 HIGH）暂不推钉钉（security.log WARN+指标+事件中心 badge 可见），后续可在热路径调用点旁补 dispatch。

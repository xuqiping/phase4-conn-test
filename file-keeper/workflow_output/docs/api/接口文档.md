# File Keeper 项目接口文档

## 1. 文档说明

File Keeper 是本地桌面应用，不提供 HTTP 服务端接口。本文档中的“接口”主要指以下几类边界：

1. Vue 前端对 Tauri `invoke` 的 TypeScript 封装。
2. Rust 后端暴露给前端的 Tauri 命令。
3. 关键共享数据结构。
4. 本地事件与持久化边界。

---

## 2. 接口总览

## 2.1 文件管理相关接口

| 能力 | 前端封装 | Tauri 命令 | 说明 |
|---|---|---|---|
| 选择文件 | `pickFile()` | Dialog 插件 | 打开系统文件选择器 |
| 选择文件夹 | `pickFolder()` | Dialog 插件 | 打开系统文件夹选择器 |
| 打开文件/文件夹 | `openFile(path)` | `open_file` | 使用系统默认程序打开 |

| 获取真实图标 | `getFileIcon(path, useRealIcon)` | `get_file_icon` | 返回 base64 图标字符串 |

## 2.2 运行中应用管理相关接口

| 能力 | 前端封装 | Tauri 命令 | 说明 |
|---|---|---|---|
| 获取运行中应用 | `getRunningProcesses()` | `get_running_processes` | 枚举当前可见窗口 |
| 关闭单个应用 | `closeProcess(windowHandle)` | `close_app_process` | 向目标窗口发送关闭请求，不保证进程退出 |
| 批量关闭应用 | `closeProcesses(windowHandles)` | `close_app_processes` | 批量发送窗口关闭请求并返回成功/失败数 |
| 激活窗口 | `activateWindow(windowHandle)` | `activate_app_window` | 恢复窗口并切到前台 |
| 查找文件相关进程 | `findFileProcesses(filePath)` | `find_file_processes` | 查找与文件有关的窗口/进程 |
| 关闭文件相关进程 | `closeFileProcesses(filePath)` | `close_file_processes` | 按进程处理与文件有关的进程 |

## 3. 文件管理接口

## 3.1 `pickFile()`

```ts
pickFile(): Promise<string | null>
```

说明：
- 使用 Tauri Dialog 插件打开系统文件选择器。
- 成功时返回绝对路径。
- 用户取消时返回 `null`。

## 3.2 `pickFolder()`

```ts
pickFolder(defaultPathOverride?: string): Promise<string | null>
```

说明：
- 使用 Tauri Dialog 插件打开系统文件夹选择器。
- 可传入默认路径覆盖值。
- 成功时返回绝对路径，取消时返回 `null`。

## 3.3 `openFile(path)` / `open_file`

前端：

```ts
openFile(path: string): Promise<void>
```

后端：

```rust
open_file(path: String) -> Result<(), String>
```

行为：
- 路径为文件时使用系统默认程序打开。
- 路径为文件夹时直接打开文件夹。
- 路径不存在时返回错误。

## 3.4 `validatePath(path)` / `validate_path`

```ts
validatePath(path: string): Promise<boolean>
```

```rust
validate_path(path: String) -> Result<bool, String>
```

用途：
- 添加前校验。
- 打开前校验。
- 标记收藏文件是否失效。

## 3.5 `showInFolder(path)` / `show_in_folder`

```ts
showInFolder(path: string): Promise<void>
```

```rust
show_in_folder(path: String) -> Result<(), String>
```

行为：
- Windows 下会尽量在资源管理器中定位目标文件。
- 如果目标本身是文件夹，则直接打开目录。

## 3.6 `getFileIcon(path, useRealIcon)` / `get_file_icon`

```ts
getFileIcon(path: string, useRealIcon?: boolean): Promise<string | null>
```

```rust
get_file_icon(path: String, use_real_icon: Option<bool>) -> Result<String, String>
```

返回值：
- 成功时返回 base64 data URL。
- 失败或不支持时前端会降级为通用图标。

## 4. 运行中应用管理接口

## 4.1 `getRunningProcesses()` / `get_running_processes`

```ts
getRunningProcesses(): Promise<ProcessInfo[]>
```

```rust
get_running_processes() -> Result<Vec<ProcessInfo>, String>
```

返回结构：

```ts
interface ProcessInfo {
  pid: number
  name: string
  window_title: string
  category: ProcessCategory
  memory_mb: number
  cpu_usage: number
  window_handle: number
}
```

说明：
- 后端以可见窗口为中心采集数据，而不是遍历所有后台进程。
- `window_handle` 是关闭和激活窗口时的核心标识。

## 4.2 `closeProcess(windowHandle)` / `close_app_process`

```ts
closeProcess(windowHandle: number): Promise<void>
```

```rust
close_app_process(window_handle: usize) -> Result<(), String>
```

行为：
- 向目标窗口发送正常关闭请求。
- 不等同于默认强制杀进程。
- 如果目标应用实现了托盘最小化、后台驻留或自定义关闭逻辑，窗口可能关闭，但进程仍继续运行。
- 关闭失败时前端会根据错误内容提示权限问题或句柄失效。

## 4.3 `closeProcesses(windowHandles)` / `close_app_processes`

```ts
closeProcesses(windowHandles: number[]): Promise<CloseResult>
```

```rust
close_app_processes(window_handles: Vec<usize>) -> Result<CloseResult, String>
```

返回结构：

```ts
interface CloseResult {
  succeeded: number
  failed: number
}
```

## 4.4 `activateWindow(windowHandle)` / `activate_app_window`

```ts
activateWindow(windowHandle: number): Promise<void>
```

```rust
activate_app_window(window_handle: usize) -> Result<(), String>
```

行为：
- 如果窗口最小化，会先恢复窗口。
- 再尝试把窗口切到前台。

## 4.5 文件相关进程接口

### `findFileProcesses(filePath)` / `find_file_processes`

```ts
findFileProcesses(filePath: string): Promise<ProcessInfo[]>
```

### `closeFileProcesses(filePath)` / `close_file_processes`

```ts
closeFileProcesses(filePath: string): Promise<number>
```

用途：
- 用于处理文件被占用、无法编辑、无法删除等场景。
- 这条路径与运行中应用管理中的窗口关闭不同：这里是按进程处理相关 PID，而不是只向窗口发送关闭请求。

## 5. 剪贴板接口

## 5.1 监听生命周期

### `startClipboardMonitor()` / `start_clipboard_monitor`
启动剪贴板监听轮询。

### `stopClipboardMonitor()` / `stop_clipboard_monitor`
停止剪贴板监听轮询。

监听范围当前包括：
- 文本
- 文件
- 图片

并会在内容识别后继续归类为：
- html
- url
- color
- security_event

## 5.2 历史列表与搜索

### `getClipboardItems(query)` / `get_clipboard_items`

```ts
interface ClipboardQuery {

  kind?: ClipboardKind | 'all'
  favoriteOnly?: boolean
  sourceApp?: string
  startAt?: number
  endAt?: number

  offset: number
}
```

### `searchClipboardItems(query)` / `search_clipboard_items`
与列表接口共用查询结构，但语义上用于显式搜索。

## 5.3 详情接口

### `getClipboardItemDetail(id)` / `get_clipboard_item_detail`

```ts

  text?: string
  html?: string
  sanitizedHtml?: string
  markdown?: string
  imagePath?: string

  imageHeight?: number
  imageFormat?: string
  ocrText?: string
  files?: ClipboardFileEntry[]
```

用途：
- 详情预览。
- 根据记录类型决定复制格式、展示字段和操作入口。

## 5.4 复制、粘贴与目标窗口

### `copyClipboardItem(id, format)` / `copy_clipboard_item`
支持按指定格式复制单条记录。

### `copyClipboardItems(ids, format)` / `copy_clipboard_items`
批量复制多条记录。

### `pasteClipboardItem(id, format)` / `paste_clipboard_item`
先复制内容，再根据设置决定是否自动粘贴。

### `rememberClipboardTargetWindow()` / `remember_clipboard_target_window`
在打开快速面板前记录目标窗口，供后续自动粘贴恢复窗口使用。

## 5.5 删除、备注与清理

### `deleteClipboardItem(id)` / `delete_clipboard_item`
删除单条历史记录。

### `updateClipboardItemNote(id, note)` / `update_clipboard_item_note`
更新单条备注；会同步影响搜索索引。

### `clearClipboardHistory(scope)` / `clear_clipboard_history`
`scope` 当前支持：
- `all`
- `non_text_cache`
- `security_events`

## 5.6 设置与存储占用

### `getClipboardSettings()` / `get_clipboard_settings`
### `updateClipboardSettings(settings)` / `update_clipboard_settings`

设置结构：

```ts

  monitorEnabled: boolean
  quickPanelShortcut: string
  autoPaste: boolean
  protectSensitiveContent: boolean
  enableOcr: boolean
  enableLinkPreview: boolean

  itemSizeLimitMb: number
```

### `getClipboardStorageUsage()` / `get_clipboard_storage_usage`
返回总占用和分类型占用信息。

## 5.7 索引与链接预览

### `rebuildClipboardIndex()` / `rebuild_clipboard_index`
重建剪贴板历史 `search_text` 索引，用于修复旧记录搜索内容不完整的问题。

### `retryLinkPreview(id)` / `retry_link_preview`
对指定 URL 记录重新抓取标题与描述。

## 8. 持久化边界

## 8.1 Tauri Store
用于持久化：
- 文件收藏
- 分组
- 主设置
- 最近打开记录

## 8.2 localStorage
当前主要用于：
- `process-settings`
- `app-locale`

## 8.3 SQLite
剪贴板模块使用 SQLite 保存：
- 历史记录
- OCR 文本
- 备注
- URL 预览字段
- 搜索索引
- 剪贴板设置

## 9. 错误处理约定

## 9.1 Rust 命令返回形式
后端统一使用：

```rust
Result<T, String>
```

约定：
- `Ok(T)`：命令成功。
- `Err(String)`：命令失败，返回可读错误字符串。

## 9.2 常见错误场景
- 文件不存在。
- 目标窗口句柄已失效。
- 关闭应用时权限不足（如 `0x80070005` / `拒绝访问`）。
- OCR 不可用或识别结果为空。
- 链接预览抓取失败。
- 剪贴板图片/文件超出缓存限制。

前端通常会把底层错误转换为更明确的业务提示，并同步更新 store 中的错误状态。

---

## 10. 结论

当前 File Keeper 的接口体系已经覆盖三大主域：
- 文件管理
- 运行中应用管理
- 剪贴板 / 截图 / OCR

整体接口风格是：前端通过轻量 TypeScript API 封装调用 Tauri command，后端以本地 Windows 能力和 SQLite/Tauri Store 为支撑，为桌面工作流提供完整的本地能力边界。

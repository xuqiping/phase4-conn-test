# File Keeper 商业售卖版账号权限与授权系统正式设计文档

> 日期：2026-06-06  
> 语言：中文  
> 适用范围：File Keeper 商业售卖版第一版

---

## 1. 设计目标

File Keeper 当前是基于 Tauri 2、Vue 3、TypeScript、Rust 构建的 Windows 桌面效率工具，核心能力包括文件管理、运行中应用管理、剪贴板增强、截图和 OCR。商业售卖版第一版的目标不是把本地数据上云，而是在保留本地隐私边界的前提下，增加账号、权限、设备授权、匿名试用和后台管理能力，形成可售卖闭环。

第一版商业闭环采用以下方式：

1. 用户可在桌面客户端注册账号。
2. 用户必须验证注册所用的邮箱或手机号。
3. 用户线下付款。
4. 超级管理员在 Web 管理后台审核账号、分配可用模块、设置到期时间和设备策略。
5. 用户在桌面客户端登录后，根据授权使用对应模块。
6. 未登录/免费用户必须联网校验设备权益，先获得 7 天全功能体验，体验期结束后长期只能选择 1 个主模块使用，每 30 天可更换一次。

---

## 2. 非目标范围

第一版明确不做以下内容：

- 在线支付。
- 自动订阅。
- 订单系统。
- 发票与账单。
- 文件收藏云同步。
- 剪贴板历史云同步。
- 截图内容上云。
- 团队空间。
- 多级管理员角色。
- 复杂运营报表。
- 自动版本更新。
- 公告推送。
- 第三方登录。

这些能力可以作为后续商业版本迭代，但不进入第一版实现范围。

第一版只按 3 个主模块授权：

| 模块 | code | 说明 |
|---|---|---|
| 文件管理 | `files` | 文件与文件夹收藏、分组、搜索、打开、批量操作 |

## 6. 账号与注册规则

普通账号由用户自行注册，支持邮箱或手机号作为登录标识。

注册规则：

- 邮箱和手机号至少填写一个。
- 邮箱唯一。
- 手机号唯一。
- 使用邮箱注册时必须验证邮箱验证码。
- 使用手机号注册时必须验证短信验证码。
- 联系方式验证通过后，账号进入待审核状态。
- 管理员审核并授权后，账号才获得登录授权模块。

账号状态：

| 状态 | 说明 |
|---|---|
| `pending_verification` | 待验证联系方式 |
| `pending_review` | 已验证，待管理员审核 |
| `active` | 已启用，可按授权使用模块 |
| `disabled` | 已禁用，登录授权不可用 |

用户角色：

| 角色 | 说明 |
|---|---|
| `super_admin` | 超级管理员，可登录 Web 管理后台 |
| `user` | 普通用户，可登录桌面客户端 |

超级管理员账号不开放公开注册，必须通过初始化脚本或环境变量创建。

## 7. 授权规则

### 7.1 登录用户授权

管理员可以为普通用户设置：

- 可用模块：`files`、`processes`、`clipboard`。
- 每个模块是否启用。
- 每个模块授权到期时间。
- 账号允许绑定的设备数量。
- 账号最大离线缓存时长。

授权判断规则：

1. 用户必须是 `active` 状态。
2. 模块授权必须 `enabled = true`。
3. 模块授权未过期。
4. 当前设备未被禁用。
5. 当前账号绑定设备数量未超过管理员配置上限。

如果登录授权过期，客户端降级为该设备的匿名权益。

### 7.2 登录用户离线缓存

登录授权用户支持管理员配置离线缓存时长：

- `offline_cache_minutes > 0`：客户端可缓存授权快照，到期前离线可继续使用已授权模块。
- `offline_cache_minutes = 0`：必须联网校验授权。

离线缓存只适用于已登录且已授权用户。匿名/未登录用户不能使用离线缓存。

## 8. 匿名/免费用户规则

匿名/免费用户必须联网校验服务端权益。

生命周期：

```text
匿名设备首次使用
  ↓
联网上报设备指纹
  ↓
服务端创建匿名设备试用记录
  ↓
7 天全功能体验
  ↓
体验期结束
  ↓
选择 1 个长期免费模块
  ↓
每 30 天可更换一次免费模块
```

规则：

- 每个设备只允许一次 7 天全功能体验。
- 7 天全功能体验期间，3 个主模块都可使用。
- 7 天结束后，只能选择 1 个主模块作为长期免费模块。
- 长期免费模块每 30 天可更换一次。
- 匿名设备被管理员禁用后，不能继续使用匿名权益。
- 服务端不可达时，匿名/未登录用户所有模块不可用。

已注册但未审核用户：

- 可以登录并看到待审核提示。
- 审核前仍按匿名设备权益使用。
- 如果设备仍在 7 天全功能期，继续全功能体验。
- 如果 7 天已过，按长期单模块免费权益使用。

## 9. 设备识别与绑定

设备唯一识别支持两种绑定模式：

| 模式 | 说明 |
|---|---|
| `balanced` | 多因素设备指纹，允许部分因素变化，只要综合相似度达到阈值就认为是同一设备 |
| `strict` | 强硬件绑定，关键硬件字段变化后认为是新设备，需要重新绑定或管理员处理 |

Rust 客户端建议采集多因素信息后组合哈希：

- Windows SID 或当前用户 SID。
- 机器名。
- 主板/BIOS 标识。
- 磁盘序列号。
- CPU/系统硬件信息。
- File Keeper 安装 ID。

服务端不保存原始硬件信息，只保存：

- `fingerprint_hash`
- `fingerprint_version`
- `binding_mode`
- 设备名、系统版本等脱敏摘要

设备绑定规则：

- 登录用户登录时上报设备指纹。
- 服务端匹配或创建 `device_id`。
- 如果当前账号 active 设备数量达到 `max_devices`，拒绝新设备绑定。
- 管理员可以解绑、禁用或重新启用设备。

## 11. 客户端权益快照

服务端向客户端返回统一权益快照，客户端不直接理解复杂数据库模型。

```ts
interface EntitlementSnapshot {
  mode: 'authenticated' | 'anonymous'
  onlineRequired: boolean
  offlineUsableUntil?: number
  modules: {
    files: { allowed: boolean; reason?: string }
    processes: { allowed: boolean; reason?: string }
    clipboard: { allowed: boolean; reason?: string }
  }
  anonymousTrial?: {
    fullFeatureTrialEndsAt?: number
    freeModuleCode?: 'files' | 'processes' | 'clipboard'
    nextChangeAt?: number
  }
  account?: {
    status: 'pending_review' | 'active' | 'disabled'
    authorizationExpiresAt?: number
  }
}
```

客户端启动流程：

1. Rust 生成设备指纹。
2. 前端读取本地 token。
3. 有 token 时请求登录用户权益。
4. 无 token 时请求匿名设备权益。
5. 前端保存权益快照。
6. UI 根据权益快照控制模块入口。

## 14. 客户端交互

### 14.1 模块门禁

当前 `App.vue` 通过 `currentTab` 切换文件管理、进程管理、剪贴板三个模块。商业版第一版在切换 Tab 时做权限判断：

- 模块允许：正常进入。
- 模块不允许：显示未授权面板。
- 匿名 7 天后未选择免费模块：提示选择长期免费模块。
- 免费模块每月更换未到时间：显示下次可更换时间。
- 登录用户授权过期：提示联系管理员续期或重新授权。

### 14.2 登录与注册

客户端提供登录/注册入口：

- 支持邮箱或手机号 + 密码登录。
- 支持邮箱验证码注册。
- 支持短信验证码注册。
- 注册成功后进入待审核状态。
- 登录成功后刷新权益快照。
- 未审核用户显示等待审核提示，同时保留匿名权益。

### 14.3 离线状态

匿名/未登录用户：

- 必须联网。
- 服务端不可达时，所有模块不可用。
- 提示“免费体验需要联网校验”。

登录授权用户：

- 离线缓存有效时可以继续使用已授权模块。
- 离线缓存过期或配置为 0 时必须联网刷新授权。

## 15. 安全与风控

### 15.1 匿名设备风控

- 每个设备只允许一次 7 天全功能体验。
- 7 天后只能选择 1 个长期免费模块。
- 长期免费模块 30 天才能更换一次。
- 同一 IP 短时间创建大量匿名设备记录时限流。
- 同一设备频繁变化指纹时标记风险。
- 管理员重置匿名试用必须记录审计日志。

### 15.2 验证码风控

- 邮箱/短信发送频率限制。
- 同一邮箱/手机号每天发送次数限制。
- 同一 IP 每小时发送次数限制。
- 验证码有效期建议 10 分钟。
- 验证码错误次数限制。

### 15.3 登录风控

- 连续失败 5 次后短时间锁定账号或要求等待。
- refresh token 存 Redis，可撤销。
- 禁用用户后立即使 refresh token 失效。
- access token 短有效期，refresh token 长有效期。

### 15.4 管理后台安全

- 管理员接口全部要求 `role = super_admin`。
- 管理员登录失败限流。
- 管理员关键操作写审计日志。
- 超级管理员通过初始化流程创建，不允许公开注册成为管理员。

## 16. 错误处理

客户端错误展示应面向用户，而不是暴露技术错误。

| 场景 | 客户端处理 |
|---|---|
| 匿名用户网络不可达 | 显示“免费体验需要联网校验，请连接网络后重试” |
| 登录用户网络不可达且缓存有效 | 继续使用缓存授权 |
| 登录用户网络不可达且缓存无效 | 提示联网刷新授权 |
| 账号待审核 | 显示等待审核提示，并回退匿名权益 |
| 账号被禁用 | 登录授权不可用，提示联系管理员 |
| 授权过期 | 降级匿名权益，提示续费或联系管理员 |
| 设备数量超限 | 提示联系管理员解绑旧设备或增加设备数量 |
| 模块未授权 | 显示未授权面板，提供登录/注册入口 |

## 17. 测试策略

服务端测试：

- 用户注册：邮箱、手机号、验证码、重复注册。
- 登录：成功、失败、禁用账号、待审核账号。
- 模块授权：启用、禁用、过期。
- 设备绑定：首次绑定、设备上限、禁用设备。
- 匿名试用：首次 7 天全功能、7 天后单模块、30 天更换限制。
- 离线缓存策略：0 分钟、非 0 分钟、授权过期。
- 管理员 API 权限：普通用户不能访问管理接口。

客户端测试：

- 启动时有 token / 无 token 的权益拉取。
- 匿名用户网络不可达时禁用模块。
- 7 天全功能期允许 3 个模块。
- 7 天后只允许所选免费模块。
- 登录用户授权模块可进入，未授权模块显示提示。
- 授权过期后回退匿名权益。
- 离线缓存有效/过期的行为。

管理后台测试：

- 用户列表筛选。
- 审核用户。
- 分配模块和到期时间。
- 设置设备数和离线缓存时间。
- 禁用/解绑设备。
- 修改系统配置。

## 18. 实施阶段

第一版按 6 个阶段实施：

1. 服务端基础与核心数据模型。
2. 账号注册、验证、登录、管理员审核 API。
3. 模块授权、设备绑定、匿名权益 API。
4. Web 管理后台 MVP。
5. 桌面客户端登录、注册、权益快照。
6. 桌面客户端模块门禁与商业版收口。

推荐顺序：先完成服务端授权闭环，再做管理后台，最后接入桌面客户端。

---

## 19. 结论

File Keeper 商业售卖版第一版应聚焦“授权闭环”，而不是一次性建设完整商业平台。通过 Spring Boot 授权服务、Vue 管理后台和 Tauri 客户端权限门禁，可以在不上传用户本地业务数据的前提下，实现可售卖、可审核、可授权、可控设备和可控匿名试用的商业版本。

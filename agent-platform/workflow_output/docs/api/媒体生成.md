# 媒体生成 API 契约

更新：2026-08-11。所有端点要求登录及 `media:gen` 权限；普通用户只能访问自己的任务，管理员可按既有规则旁路归属过滤。

## 历史任务

`GET /api/media/tasks`

| 参数 | 类型 | 语义 |
|---|---|---|
| `q` | string，可选 | 提示词大小写不敏感的字面子串；`%`、`_`、`\` 不作通配符 |
| `from` | ISO-8601 datetime，可选 | `created_at >= from` |
| `to` | ISO-8601 datetime，可选 | `created_at < to` |
| `limit` | integer，可选 | 1-100，默认 50 |

时间范围采用 `[from,to)`；`from >= to` 返回 400。列表按创建时间倒序，只返回轻量字段，不批量返回请求 JSON 快照。

## 任务详情

`GET /api/media/tasks/{id}`

除原状态/输出字段外，详情增加：

- `ratio`、`watermark`、`generateAudio`：历史生成参数。
- `inputAttachments[]`：`fileId/kind/frameRole/name/previewUrl` 输入附件摘要；不含文件正文，`previewUrl` 仍需鉴权。
- `submittedRequest`：平台收到并持久化的提交参数，已移除嵌套快照和意外的 data URI。
- `providerRequestSnapshot`：发送前由实际 POST body 同源生成的脱敏快照；旧任务为 `null`，不得事后推导冒充实际请求。

快照中的媒体位置替换为：

```json
{
  "redacted": true,
  "transport": "data_uri",
  "fileId": "img-1",
  "mime": "image/png",
  "bytes": 12345,
  "sha256": "..."
}
```

`videoUrl`/`imageUrls` 是成功生成后的输出下载地址，不表示输入附件；任务未成功时为 `null` 属正常语义。

## 轮询语义

客户端持续查询详情，直到 `SUCCEEDED`、`FAILED` 或 `DOWNLOAD_FAILED`。平台不再按任务总时长判失败；单次网络请求仍有传输超时，瞬时查询异常会退避重试。只有 Provider 明确返回失败终态才写 `FAILED`。

## 安全约束

- 历史筛选和详情均执行 ownership。
- 查询参数全部绑定，附件再次提交时重新校验归属和 MIME。
- API、数据库快照和业务日志不保存原始 data URI、Authorization 或 Provider key。

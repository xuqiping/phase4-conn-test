# 资产库公众池与成员授权 · 人工测试方案

> Phase 3 功能级预处理产物。关联 FR-F19-01～FR-F19-04 与[实现计划](../plans/资产库公众池与成员授权.plan.md)。自动化负责权限与状态断言；本文件负责真实角色、页面联动和可用性验收。

## 1. 人工测试原因

- [x] 涉及三个角色的 UI 交互与跨页面状态联动。
- [x] 官方徽章、禁用原因、只读控件和键盘操作需要人眼确认。
- [x] 发布、审批、引用、复制需要在真实前后端与数据库中串联验证。

## 2. 前置条件

- 启动 PostgreSQL、Redis、backend、frontend，数据库已执行 V87。
- 准备管理员、OWNER、普通用户三个启用账号；OWNER 至少有一个含多媒体资产和多个版本的项目，普通用户至少有一个可写目标项目。
- 浏览器使用 Chromium，分别登录三个账号，避免会话串用。

## 3. 正常路径与联动用例

| 编号 | 对应需求 | 场景与操作 | 预期结果 | 通过? |
|---|---|---|---|---|
| AP-01 | FR-F19-01 | OWNER 以 OPEN 发布，再移出 | 公共池出现后消失；成员授权不变 | ⬜ |
| AP-02 | FR-F19-01 | OWNER 以审批模式发布，管理员另发一个项目 | 两项目均可见摘要；管理员项目有文字“官方发布”标记且直接可用 | ⬜ |
| AP-03 | FR-F19-02 | 普通用户申请，OWNER 批准 | 按钮从申请→待审批→可使用；获批后可读内容 | ⬜ |
| AP-04 | FR-F19-02 | OWNER 拒绝后用户重申请；批准后再撤销 | 拒绝/撤销均可重申请；撤销后内容立即失权 | ⬜ |
| AP-05 | FR-F19-02 | 转让已发布项目 | 新 OWNER 获得审批入口；发布者快照与官方标记不变 | ⬜ |
| AP-06 | FR-F19-03 | 普通 OWNER 搜索用户并邀请 | 无需用户管理权限；候选仅用户名，邀请后成员列表立即刷新 | ⬜ |
| AP-07 | FR-F19-04 | 获权用户从公共项目引用当前版本，再更新源资产 | 既有画布引用锁旧版本；新引用看到新版本 | ⬜ |
| AP-08 | FR-F19-04 | 复制公共资产到自己的项目 | 生成独立资产与版本 1；源后续更新不改变副本 | ⬜ |
| AP-09 | 联动 | 移出含 PENDING/APPROVED 的项目再重新发布 | 旧申请均失效，用户必须重新申请 | ⬜ |

## 4. 边界、安全与无障碍

| 编号 | 场景 | 预期 | 通过? |
|---|---|---|---|
| AE-01 | 未审批用户直接请求资产、版本、预览接口 | 403，且响应不含正文、文件或词汇 | ⬜ |
| AE-02 | 公共 VIEWER 尝试编辑项目、资产、版本、成员 | 全部拒绝；前端也不显示写控件 | ⬜ |
| AE-03 | VIEWER 打开成员搜索或超长/空关键词搜索 | VIEWER 被拒；输入得到明确空态/错误，不泄露额外用户资料 | ⬜ |
| AE-04 | 两个会话同时审批同一 PENDING | 仅一个成功，另一个提示状态已变化 | ⬜ |
| AE-05 | 复制时目标无写权或中途失败 | 明确提示，目标项目无半成品 | ⬜ |
| AE-06 | 仅使用键盘操作页签、搜索、弹窗和审批按钮 | 焦点可见、可关闭；徽章/状态不只靠颜色表达 | ⬜ |

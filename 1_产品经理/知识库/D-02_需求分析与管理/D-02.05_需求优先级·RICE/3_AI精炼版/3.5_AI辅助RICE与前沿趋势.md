# 3.5 AI辅助RICE与前沿趋势

## 大模型辅助RICE评分

RICE评分的痛点在于**四维度估算耗时长且主观性强**——AI可辅助各维度的数据化评估：

| 维度 | AI辅助能力 | 局限 |
|---|---|---|
| **Reach** | 基于用户行为数据自动预测受影响用户数 | 需要埋点数据，新功能无参照 |
| **Impact** | 基于历史功能的Impact→结果对比，辅助校准 | 历史数据的因果归因困难 |
| **Confidence** | 自动标注数据来源→推算Confidence等级 | 只能评估数据充分度，不能判断Impact方向 |
| **Effort** | 基于历史Jira任务估算开发工时 | 技术栈变更时历史数据失真 |

### AI辅助Impact评分校准

```
输入：
  - 新需求的功能描述
  - 历史需求库（含原始Impact评分 + 实际业务结果）

AI分析：
  1. 找出功能描述与历史需求的相似度
  2. 参考相似需求的历史Impact vs 实际结果
  3. 输出Impact评分建议 + 置信区间

示例：
  新需求："搜索结果智能排序"
  相似历史需求：
    - "搜索建议" → Impact=2 → 实际转化率+12% ✓
    - "搜索结果页改版" → Impact=2 → 实际转化率+5%（低于预期）
  AI建议：Impact=1.5（在1和2之间），Confidence=80%
```

## 历史数据校准

传统RICE评分的**最大问题**是"打完分就忘了"——从不回顾Impact=3的需求实际效果如何。AI可实现**闭环校准**：

| 步骤 | 传统做法 | AI辅助做法 |
|---|---|---|
| 评分时 | PM凭经验打Impact | AI参考历史相似需求给出Impact建议 |
| 上线后 | 很少回顾实际效果 | AI自动监控上线后的业务指标变化 |
| 复盘 | 依赖手动记录 | AI自动对比评分vs实际，生成本人/团队的校准报告 |
| 下次评分 | 仍然凭经验 | AI用校准数据调整Impact建议 |

> 前沿方向：CSDN 2026年3月文章提出"AI化RICE"——用大模型自动分析用户反馈、从NPS/CSAT数据推算Impact、从Jira历史估算Effort，实现RICE评分的半自动化。[来源:CSDN·AI需求优先级排序 | 📚中 | 2026-03]

## 动态RICE重评分

产品环境变化（竞品发布、用户增长、技术演进）会使RICE评分过时。AI驱动的动态重评分：

| 触发条件 | 自动重评分维度 |
|---|---|
| 月活用户变化>20% | Reach需更新 |
| 竞品发布类似功能 | Impact可能降低（从差异化→标配） |
| 技术栈升级 | Effort可能降低 |
| 新数据验证了假设 | Confidence提升 |

## RICE的局限与未来

| 局限 | 可能的解决方向 |
|---|---|
| 四维度不够（缺时间紧迫性/风险/战略对齐） | WSJF扩展 或 RICE+多维度(M) |
| 评分主观性强 | AI辅助+历史校准闭环 |
| 不考虑需求间依赖 | 图论建模→拓扑排序后再RICE |
| 不适应AI产品的快速变化 | 缩短重评周期+AI自动触发 |

# Backend Programming Language Workflow Checklist

在完成 `workflow/backend_programming_language_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别用户后端需求场景

- [ ] 已明确场景类型（技术选型/学习路径/问题排查/架构设计/团队技术栈规划）
- [ ] 已识别目标语言（如用户已指定）或初步筛选出候选语言范围
- [ ] 已提取应用类型约束（企业级/AI/云原生/系统级/Web/实时通信）
- [ ] 已提取团队背景（现有技术栈、规模、经验水平）
- [ ] 已提取特殊约束（信创/内存安全/极致性能/快速交付）
- [ ] 已对照知识库选型决策矩阵完成初步判断
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出后端技术方案

- [ ] 推荐语言明确并附选型理由
- [ ] 技术栈搭配完整（语言+框架+工具链+数据库+部署）
- [ ] 如为选型，决策矩阵覆盖性能/生态/团队匹配度/长期趋势至少3个维度
- [ ] 如为学习路径，阶段性计划清晰（入门→进阶→实战→深入），附验证标准
- [ ] 如为问题排查，排查步骤从常见到根因，附代码示例或配置片段
- [ ] 如为架构设计，分层架构建议明确，微服务通信协议建议合理
- [ ] 关键趋势点已标注（Java 21 Virtual Threads / Python 3.13 free-threaded / Go云原生统治力 / Rust进入Linux内核）
- [ ] 所有核心论断均能在知识库中找到支撑来源

## Step 3: 验证与交付

- [ ] 已读取对应 checklist 并逐项核对
- [ ] 输出内容无知识性错误
- [ ] 已向用户交付最终答案

## Overall

- [ ] 工作流中的所有步骤已按顺序执行，没有跳过
- [ ] 每一步都已与其检查清单部分进行交叉验证
- [ ] 没有在任何检查清单部分通过前提前进入下一步
- [ ] `task/current_task.md` 已更新完成记录
- [ ] 所有 `[参考: ...]` 标注均指向存在的知识库文件

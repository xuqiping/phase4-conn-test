# 互动式 AI 工作助手 — 桌面端界面交互测试流程

> **适用版本**：Phase 1 ~ Phase 4 全部完成后（2026-06-30 状态）。  
> **目标**：只通过桌面端 UI 点击、输入、观察，完成全功能验收。  
> **前置条件**：后端已启动，用户已登录，且拥有 `work-report` 模块权限。

---

## 一、进入工作汇报模块

1. 打开桌面端应用，登录账号。
2. 在左侧导航栏点击 **「工作汇报」**。
3. 进入后页面分为三栏：左侧日期导航 + 入口列表，中间/右侧为内容区。

左侧入口包括：
- 互动收件箱
- 工作记录
- 未来计划
- 固定工作
- 固定工作日历
- 灵感随记
- 推送配置
- 报告配置
- 历史报告

---

## 二、推送配置（所有 IM 功能的前提）

### 2.1 新增推送凭据

1. 左侧点击 **「推送配置」**。
2. 页面顶部有两个子 Tab：**凭据** / **目标**，默认在「凭据」。
3. 在下方表单的 **名称** 输入框填：`飞书测试机器人`。
4. **平台** 下拉选择：`飞书`。
5. **凭据** 文本框填入机器人 webhook 地址与 secret（JSON 格式，咨询后端或运维）。
6. 点击 **保存** 按钮。

**预期结果**：凭据列表出现一条「飞书测试机器人 · 飞书 · 已设置」。

### 2.2 新增推送目标

1. 切换到 **「目标」** Tab。
2. 在表单中填入：
   - **名称**：`飞书测试群`
   - **平台**：`飞书`
   - **目标类型**：`群组`
   - **目标 ID**：飞书群 chat_id
   - **凭据**：选择刚才创建的「飞书测试机器人」
3. 点击 **保存**。

**预期结果**：目标列表出现「飞书测试群 · 飞书 · GROUP · xxx」。

> 若需测试钉钉 / Slack / 企业微信，重复 2.1 ~ 2.2，平台分别选择对应选项。

---

## 三、固定工作模块测试

### 3.1 创建固定工作

1. 左侧点击 **「固定工作」**。
2. 顶部子 Tab 切换为 **「每日」**。
3. 点击右上角 **「+ 新增固定工作」** 按钮。
4. 在弹出的表单中填写：
   - **内容**：`日报设计`
   - **说明**（可选）：`每天整理并输出工作日报`
   - **提醒时间**：`09:00`
   - **重复周期**：`每日`
   - 勾选 **启用提醒**
   - **推送目标**：选择「飞书测试群」
5. 点击 **保存**。

**预期结果**：列表出现「日报设计」，右侧显示「每日 09:00 · 提醒开启 · 飞书测试群」。

6. 再切换到 **「每周」** Tab，创建：
   - **内容**：`周会汇报`
   - **重复周期**：`每周`
   - **提醒日期**：勾选周一
   - **提醒时间**：`10:00`
7. 点击 **保存**。

### 3.2 桌面端直接标记完成

1. 在「固定工作」列表中，点击「日报设计」左侧的方框。
2. 方框内出现白色 ✓，背景变主题色。

**预期结果**：该任务显示为已完成。

3. 再次点击方框。

**预期结果**：方框恢复未勾选状态。

### 3.3 固定工作日历视图

1. 左侧点击 **「固定工作日历」**。
2. 页面显示当月日历，每个日期下方有状态小圆点：
   - **绿色**：当天全部完成
   - **黄色**：部分完成
   - **灰色**：无任务或未开始
3. 点击今天日期。
4. 下方展开 **当日任务明细**，应看到「日报设计」。
5. 点击明细右侧的方框，将其标记完成。

**预期结果**：日历上今天的圆点变为绿色；再次点击取消后恢复。

6. 点击日历顶部左右箭头，切换上个月/下个月。

**预期结果**：日历月份正确切换，数据随月份刷新。

## 四、工作记录模块测试

1. 左侧点击 **「工作记录」**。
2. 点击右上角 **「+ 新增记录」**。
3. 在文本框输入：`今天完成了接口评审和数据库设计`。
4. 在标签输入框输入：`#后端 #设计`。
5. 点击 **保存**。

**预期结果**：列表出现该记录，下方显示 `#后端 #设计` 标签，右侧显示日期。

6. 鼠标悬停在该记录上，出现 ✏️ 编辑和 🗑️ 删除按钮。
7. 点击编辑，修改内容为 `今天完成了接口评审、数据库设计和代码实现`，保存。

**预期结果**：内容更新成功。

---

## 五、灵感随记模块测试

### 5.1 手动添加灵感

1. 左侧点击 **「灵感随记」**。
2. 点击右上角 **「+ 新增灵感」**。
3. 在内容框输入：`AI 日报应支持情感分析 #产品/灵感`。
4. 在标签框输入：`产品/灵感`。
5. 点击 **保存**。

**预期结果**：列表出现该灵感，标签显示为蓝色 `#产品/灵感`。

### 5.2 标签筛选

1. 在灵感列表上方，点击 `#产品/灵感` 标签按钮。

**预期结果**：列表只显示带该标签的灵感，其他灵感被过滤。

2. 点击 **清除** 按钮。

**预期结果**：恢复显示全部灵感。

### 5.3 标记已回顾

1. 在灵感卡片右侧，鼠标悬停出现 ✓ 按钮。
2. 点击 ✓。

**预期结果**：该灵感出现绿色「已回顾」标签，`reviewedAt` 被更新。

## 六、Phase 1 / Phase 2：IM 入站 + Inbox 交互测试

IM 消息需要从外部 IM 应用真实发送（桌面端无法主动发送 IM）。请先在 IM 群中绑定好推送目标（见 2.2），然后按以下步骤在桌面端验证。

### 6.1 高置信度消息自动完成

1. 在飞书测试群中发送：`完成日报设计`
2. 等待约 1 ~ 3 秒，切换到桌面端 **「互动收件箱」**。
3. 点击右上角 **「刷新」** 按钮。

**预期结果**：
- 列表出现一条新消息卡片。
- 卡片显示：`完成日报设计`。
- 平台标签：`飞书`。
- 意图标签：`完成固定工作`。
- 置信度标签：`高置信度`（绿色）。
- 状态标签：`已确认`。

4. 切换到 **「固定工作」→「每日」**。

**预期结果**：「日报设计」已自动标记为完成（左侧方框已勾选）。

### 6.2 低置信度消息进入 Inbox 待确认

1. 在飞书测试群中发送一句模糊的话：`搞了一下那个`
2. 回到桌面端 **「互动收件箱」**，点击刷新。

**预期结果**：
- 新增一条消息卡片。
- 意图标签：`未知`。
- 置信度标签：`低置信度`（黄色）。
- 状态为 `PENDING`，卡片右侧显示 **「确认」** 和 **「忽略」** 两个按钮。

3. 点击 **「确认」**。

**预期结果**：卡片状态变为 `已确认`。

4. 再发送一条模糊消息，点击 **「忽略」**。

**预期结果**：卡片状态变为 `已忽略`，不再影响固定工作/日志/灵感。

### 6.3 工作记录类消息

1. 在飞书群中发送：`今天做了需求评审`
2. 回到桌面端刷新 Inbox。

**预期结果**：
- 新增意图为 `添加工作记录` 的卡片。
- 状态为 `已确认`。

3. 切换到 **「工作记录」**。

**预期结果**：列表出现「需求评审」记录。

### 6.4 灵感类消息

1. 在飞书群中发送：`灵感：周报增加情绪标签 #产品`
2. 回到桌面端刷新 Inbox。

**预期结果**：
- 新增意图为 `添加灵感` 的卡片。
- 状态为 `已确认`。

3. 切换到 **「灵感随记」**。

**预期结果**：列表出现「周报增加情绪标签 #产品」。

### 6.5 复杂句与相对日期

1. 在飞书群中分别发送：
   - `昨天完成了日报设计`
   - `上周一搞定了周会汇报`
   - `6月25日做完日报设计`
2. 回到桌面端依次查看 Inbox 和固定工作日历。

**预期结果**：
- Inbox 中正确识别意图和日期。
- 固定工作日历中，对应日期（昨天、上周一、6月25日）的完成状态被正确标记。

### 6.6 多平台消息（钉钉 / Slack / 企业微信）

1. 在钉钉 / Slack / 企业微信对应群中发送：`完成日报设计`
2. 回到桌面端 **「互动收件箱」** 刷新。

**预期结果**：
- 新增平台标签为「钉钉」「Slack」或「企业微信」的卡片。
- 意图与状态识别正确。

## 七、Phase 3：AI 报告增强测试

### 7.1 创建报告配置

1. 左侧点击 **「报告配置」**。
2. 点击右上角 **「+ 新增配置」**。
3. 填写表单：
   - **名称**：`测试周报`
   - **报告类型**：`周报`
   - **报告模板**：选择一个默认模板
   - **定时表达式**：`每周一 09:00`
   - 勾选 **启用**
   - 勾选 **启用 AI**
   - 勾选 **包含灵感摘要**
   - 勾选 **启用灵感回顾**
   - **推送目标**：勾选「飞书测试群」
4. 点击 **保存**。

**预期结果**：配置列表出现「测试周报 · 周报 · AI 开启 · 已启用」。

### 7.2 手动生成报告

1. 在配置列表中找到「测试周报」。
2. 点击右侧 **「生成报告」** 按钮。
3. 页面自动切换到 **「历史报告」**。

**预期结果**：
- 报告正文显示在上方。
- 正文包含：本周已完成、本周未完成/逾期、下周计划、灵感速览。
- 正文下方卡片显示：
  - **固定工作完成率**：xx%
  - 如有逾期，显示 **连续未完成天数**：x 天

### 7.3 推送报告

1. 在历史报告列表中，点击刚生成的报告。
2. 点击右上角 **「推送报告」** 按钮（带 Send 图标）。

**预期结果**：
- 按钮变为「推送中...」。
- 稍后状态标签变为 `已推送`（绿色）。
- IM 群中收到报告消息（真实凭据有效时）。

### 7.4 导出报告

1. 在报告查看器右上角，点击 **「导出 Markdown」** 按钮。

**预期结果**：浏览器触发下载，文件名为报告标题，格式为 `.md`。

## 八、Phase 4：体验优化测试

### 8.1 /help 指令菜单

1. 在飞书测试群中发送：`/help`
2. 回到桌面端刷新 Inbox。

**预期结果**：
- 新增意图为 `帮助` 的卡片。
- 状态为 `已确认`。
- IM 群中收到机器人回复的菜单：
  ```
  可用指令：
  - 完成 [任务名]
  - 今天做了 [工作内容]
  - 灵感：[内容] #标签
  - /help
  ```

### 8.2 每日灵感回顾

1. 确保 **「报告配置」** 中已勾选 **「启用灵感回顾」**。
2. 确保 **「灵感随记」** 中存在未回顾（无绿色「已回顾」标签）的灵感。
3. 等待系统每天 09:00 自动推送，或请后端/运维手动触发调度任务。
4. 检查 IM 群消息。

**预期结果**：
- IM 群中收到「今天回顾一下这些灵感：」的消息，列出 3 ~ 5 条未回顾灵感。
- 回到桌面端 **「灵感随记」**，被推送的灵感显示「已回顾」标签。

## 九、端到端闭环场景（推荐完整走一遍）

### 场景 A：从 IM 完成固定工作

1. IM 发送：`完成日报设计`
2. 桌面端 Inbox 看到已确认消息。
3. 桌面端固定工作中「日报设计」自动完成。
4. 桌面端固定工作日历今天显示绿色。

### 场景 B：从 IM 记录工作并生成报告

1. IM 发送：`今天做了需求评审`
2. 桌面端工作记录中出现该记录。
3. 在历史报告中生成周报，正文包含「需求评审」。
4. 推送报告到 IM 群。

### 场景 C：从 IM 收集灵感并回顾

1. IM 发送：`灵感：周报增加情绪标签 #产品`
2. 桌面端灵感随记中出现该灵感。
3. 系统每天推送灵感回顾。
4. 桌面端该灵感显示「已回顾」。

## 十、异常与边界测试

### 10.1 越权访问

1. 切换到一个**没有 work-report 模块权限**的账号登录。
2. 尝试进入「工作汇报」模块。

**预期结果**：页面提示「未授权访问工作汇报模块」或无法进入。

### 10.2 重复发送同一条 IM 消息

1. 在飞书群中连续发送两次完全相同的内容：`完成日报设计`

**预期结果**：
- Inbox 只出现一条（后端幂等）。
- 固定工作不会被重复翻转状态。

### 10.3 Inbox 刷新与轮询

1. 打开 Inbox 后，不点击刷新，等待约 30 秒。

**预期结果**：列表自动刷新（前端轮询）。

## 十一、验收通过标准

| 功能 | 通过标志 |
|------|----------|
| 推送配置 | 凭据/目标成功保存，列表正确显示 |
| 固定工作 | 能创建、勾选完成、编辑、删除 |
| 固定工作日历 | 日期圆点随完成状态变色，可逐日查看/操作 |
| 工作记录 | 能新增、编辑、删除、显示标签 |
| 灵感随记 | 能新增、标签筛选、标记已回顾 |
| Inbox | IM 消息后自动出现卡片，高置信度自动执行，低置信度可确认/忽略 |
| 多平台 | 飞书/钉钉/Slack/企业微信消息均能在 Inbox 看到 |
| 报告配置 | 能创建配置，勾选 AI、灵感摘要、灵感回顾 |
| 报告生成 | 正文含完成率、逾期、灵感速览，下方卡片显示完成率 |
| 报告推送 | 点击推送后状态变「已推送」，IM 收到消息 |
| /help | 发送 /help 后 IM 收到菜单，Inbox 出现 help 意图卡片 |
| 灵感回顾 | 定时推送后灵感显示「已回顾」 |

全部勾选即代表 AI 工作助手桌面端功能验收通过。

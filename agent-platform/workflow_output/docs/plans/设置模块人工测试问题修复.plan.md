## 背景与目标

`10x_设置.md` 列了 5 个未解决问题，本质是**权限与可见性收敛 + 全局供应商可移植**两大主题。当前现状（探索结论）：

- **权限模型**：项目只有三个角色字符串 `user` / `agent_admin` / `admin`（DB 种子），**没有"超级管理员"概念**。前端 `useAuthStore.isAdmin` = `roles.includes('admin')`（单一布尔，无分级）。后端方法级用自定义 `@RequirePermission("xxx:manage")` 切面 + `JwtAuthenticationFilter`。路由守卫**只认证不授权**，靠"菜单隐藏 + 页内 `v-if` + API 403"三重兜底。
- **"我的模型"**：是 SettingsView 第一个 Tab（`UserProviderTab`，`name=my-models`，对所有用户开放），对应后端 `UserLlmController` + `user_llm_providers` 表，`LlmGateway` 聊天路由时读用户私有 provider 覆盖。
- **全局供应商**：`ProviderManageTab`，无导出/导入按钮；后端 `LlmController` 无 export/import 端点。`apiKeyEnc` AES 加密存储，VO **不回显 key**。
- **菜单**：`Sidebar.vue` 的 `navItems` computed 动态拼装；Agent大厅/工作流/执行监控/知识库对所有登录用户常驻可见，设置对所有用户可见（内部 Tab 再按 isAdmin 分流）。

| # | 问题 | 根因 | 修法一句话 |
|---|---|---|---|
| 1 | 不再开放"我的模型"个人配置大模型 | `UserProviderTab` 是 SettingsView 第一个 Tab，对所有用户开放；后端 `UserLlmController` + `LlmGateway` 用户级 override 链路在用 | 前端移除 Tab 入口（保留组件文件与后端），Gateway 用户级 override 改为不参与（全局为准）|
| 2 | 全局模型供应商要求可导出、可上传 | `ProviderManageTab` 只有"添加/刷新"两按钮；后端无 export/import 端点 | 后端加 export（含解密 key）/import 端点 + 前端加"导出/导入"按钮 |
| 3 | 非管理员/超级管理员不显示设置模块 | 普通用户进 `/settings` 仍能看到（虽然只剩"我的模型"Tab）| Sidebar 对非 admin 隐藏"设置"入口；路由层加 admin 守卫重定向 |
| 4 | 无权限模块前端不展示 | 菜单部分项已 `hasPermission`，但 Agent/工作流/执行监控/知识库等仍对所有用户常驻可见 | 菜单项统一改为按 `hasPermission` 兜底，无权限不展示 |
| 5 | 暂时用不到 Agent大厅/工作流/执行监控，对所有人隐藏（含管理员），保留前后端代码 | 这三项在菜单常驻 | 加项目级"功能开关"常量 `ENABLED_MODULES`，菜单 + 路由 + 入口全部按开关过滤 |

**关键决策（先定调，避免返工）**：

1. **"我的模型"修法（问题1）= 前端隐藏入口 + 后端 override 链路停用，不删代码**。
   - 删前端组件 `UserProviderTab.vue` 会牵连 `ModelSelector.vue`（对话中选模型用 `listAvailableModels`）；删后端 `UserLlmController` 会牵连 `LlmGateway` 路由。
   - 采用**最小破坏**：① SettingsView 移除"我的模型"Tab；② SettingsView 在"非 admin 且无 Tab 可显"时不显示 `/settings` 入口（与问题3 合流）；③ `LlmGateway` 聊天路由时**不再读用户级 override**（注释掉/跳过用户 provider 查询，始终用全局）；④ 后端 `UserLlmController` + `user_llm_providers` 表 + 前端 `UserProviderTab.vue`/`ModelSelector.vue` 文件**全部保留**（不删），只是入口不再可达。理由：未来可能恢复，删了再建成本高；且 `ModelSelector` 还在用 `listAvailableModels`（它合并全局 + 用户行，用户行为空时返回纯全局，天然兼容）。
   - ⚠️ **需用户确认**：是"彻底停用用户级 override 路由"还是"仅隐藏前端入口、后端 override 仍生效"？（见下方"待用户确认"）

2. **全局供应商导出/导入（问题2）的 key 处理 = 导出明文 key（admin 才能调），导入时重新加密**。
   - 项目 `apiKeyEnc` 是 AES 对称加密，`AesEncryptService` 有 decrypt。导出端点解密后明文返回（JSON），导入端点拿到明文 key 后重新加密落库。
   - 这意味着**导出文件含明文 API Key**——仅 admin（`@RequirePermission("role:manage")`）可调，前端导出时给醒目警告"含明文密钥，请妥善保管"。不在导出文件里做二次加密（避免引入密码管理负担，admin 间迁移场景）。
   - 导入策略：**按 `name` upsert**（name 是唯一标识），不按 id。冲突时覆盖非空字段（同 update 逻辑），不删旧记录。导入返回"新增 N / 更新 M / 失败 K"统计。

3. **问题 4 与问题 5 用同一套"功能开关 + 权限"机制**，不要拆两套。
   - 问题 5 是"项目级硬隐藏（含 admin）"= 配置开关；问题 4 是"按用户权限隐藏"= RBAC。两者叠加：菜单项显隐 = `ENABLED_MODULES[模块] && hasPermission(模块权限码)`。
   - 开关放一个**单一常量文件**（`frontend/src/config/modules.ts`），改一处全局生效，便于未来恢复某模块。

4. **不引入"超级管理员"角色**。
   - 问题单提"非管理员/超级管理员"，但项目无此概念。统一按现有 `admin` 角色处理（"管理员"= `roles.includes('admin')`）。若用户后续要分"超管 vs 普管"，走 Phase 6 变更管理单独立项，不在本计划。

5. **后端 Controller 一律不动**（问题 4/5）。项目惯例是"API 403 兜底"，隐藏前端入口即可；后端 `@RequirePermission` 已是事实门控。唯一例外是问题 2 的 export/import 新增端点。

## 待用户确认（影响实现路径，需在 ExitPlanMode 前敲定）

- **Q1（问题1 后端去留）**：用户级 LLM override（`user_llm_providers` + `LlmGateway` 用户行查询）是「彻底停用，聊天一律走全局」还是「仅前端隐藏入口，后端 override 仍对存量数据生效」？
  - **推荐 A：彻底停用 override 路由**（聊天体验统一，避免"有人配过历史 key 仍生效"的认知偏差）。
  - 备选 B：仅前端隐藏，后端不动（存量用户配置仍生效，直到用户主动删）。
- **Q2（问题2 导出 key 形态）**：导出文件含**明文 API Key**（admin 间迁移最省事）还是**密文**（需约定迁移密码）？
  - **推荐 A：明文**（仅 admin 可调导出，前端醒目警告）。

> 下方计划默认按 **Q1=A、Q2=A** 撰写。如用户改选，相应 chunk 微调（已注明）。

## 技术实现坑点预判与规避措施

| 技术点/功能块 | 可能的坑 | 规避措施 | 验证方式 |
|---|---|---|---|
| 导出含明文 Key 的接口被滥用 | admin token 泄露 → 全量 provider key 被拖 | ① 仅 `@RequirePermission("role:manage")`；② 导出端点加 `@AuditLog(action="PROVIDER_EXPORT")`（既有审计切面）；③ 响应头加 `Content-Disposition: attachment` + `X-Content-Type-Options: nosniff`；④ 前端导出按钮二次确认弹窗"含明文密钥" | 手动：普通用户调导出 403；admin 调导出审计日志有记录 |
| 导入 JSON 注入 / 巨大体 | 恶意上传 10MB JSON 或非法字段 | ① 导入端点 `@RequestBody` 限制 size（spring `server.max-http-header-size` / `spring.servlet.multipart` 不适用，走 controller 层 size 校验：list≤200 条）；② 字段白名单反序列化（`@JsonIgnoreProperties(ignoreUnknown=true)`）；③ `apiEndpoint` URL 格式校验（http/https）；④ category 白名单（复用 `normalizeCategory`） | 单测：上传 201 条→400；非法 category→回退 CHAT |
| 导入 name 冲突覆盖 | 误覆盖生产 provider 的 key | upsert 按 name：存在则**只更新非空字段**（同 update 语义，apiKey 空则保留原 key），不删不新建同名的；导入前弹窗列"将覆盖 N 条 / 新增 M 条"预览 | 手动：导入同名 provider（key 空）→原 key 不变 |
| SettingsView 移除"我的模型"后普通用户 Tab 全空 | 进 `/settings` 白屏 / 空 Tab 容器 | SettingsView 顶部加 `computed hasAnyTab`（= `isAdmin`，因为剩余 Tab 全 admin）；为 false 时整页显示"无可用设置"或路由层直接 302 到首页（推荐路由层重定向，见问题3） | 手动：普通用户访问 `/settings` → 跳转 |
| Sidebar 改动牵连 `isAdmin` 本地复算 | Sidebar.vue:94 本地复算 `roles.includes('admin')` 与 store 重复 | 统一改用 `authStore.isAdmin`，删本地复算 | grep 确认无残留本地复算 |
| 菜单加 `ENABLED_MODULES` 开关后，路由仍可被手动 URL 访问 | 用户手敲 `/agents` 仍进 Agent 大厅 | 路由 `beforeEach` 加开关检查：关闭的模块路由 → 重定向首页 + message.warning"该功能未开放"（与问题3 admin 守卫同一套机制） | 手动：关 Agent 开关后敲 `/agents` → 跳转 |
| `LlmGateway` 停用用户 override 后，`listAvailableModels` 仍返用户行 | `ModelSelector` 下拉仍出现用户私有模型 | 后端 `UserLlmController.listAvailableModels` 改为**只返全局 CHAT**（注释用户行查询，保留方法签名向后兼容）；或前端不动、后端 override 不查即可（推荐后者，改动最小） | 手动：对话模型下拉只显全局 |
| 导出/导入按钮 i18n / 权限可见性 | 非 admin 看不到 `ProviderManageTab`（已 isAdmin 门控），但按钮要再确认 | 复用 Tab 既有 `v-if="isAdmin"`，按钮不单独加权限 | 确认 SettingsView Tab 门控仍在 |
| Flyway 迁移 | 本次零 DB schema 变更（仅代码 + 可选数据） | 不写 V__迁移脚本；`user_llm_providers` 表保留不删 | grep 确认无新 V__ 文件 |
| （性能）导出全量 provider | 单次 selectList，行数 <100，无性能问题 | 不分页，一次拉全量 | 无需特殊验证 |

## 安全检查清单

- [ ] **鉴权/授权**：导出/导入端点 `@RequirePermission("role:manage")`（仅 admin）；导入 upsert 不绕过既有 create/update 的加密逻辑
- [ ] **审计**：导出端点加 `@AuditLog`（明文 key 外流必须留痕）；导入端点加 `@AuditLog`（批量改配置）
- [ ] **输入校验**：导入 JSON 字段白名单 + size 限制 + URL/category 校验；导出文件名加时间戳防覆盖
- [ ] **敏感数据**：导出文件含明文 key → 响应头 `Content-Disposition`/`nosniff`；前端下载后不存 localStorage（直接触发浏览器下载）
- [ ] **XSS**：导入预览结果用文本插值，禁 v-html
- [ ] **越权**：问题 4/5 菜单隐藏是 UX 层，真授权仍靠后端 `@RequirePermission`（已存在，不退化）

## 性能考虑与验证计划

- [ ] **查询效率**：导出单次 `selectList`（<100 行）无 N+1；导入逐条 upsert 量小（<200）不需批量
- [ ] **资源使用**：导出 JSON <100KB；导入 size 校验防超大体
- [ ] **性能验证**：无特殊性能风险点（纯管理后台低频操作）

## Chunk 拆解（Phase 3 逐步执行）

> 每个_chunk_ = 一个可独立提交的功能点。涉及文件均 ≤20。顺序按依赖排，前 3 个独立可并行，第 4 个依赖前 3。

### Chunk A：项目级模块开关基础设施（问题5地基 + 问题4前置）

- [ ] **目标**：建立单一开关源 `ENABLED_MODULES`，供菜单 / 路由 / 入口统一消费。
- [ ] **动作**：
  1. 新建 `frontend/src/config/modules.ts`，导出常量：
     ```
     ENABLED_MODULES = { agentHall: false, workflow: false, execution: false,
                         chat: true, knowledge: true, canvas: true, ... }
     ```
     （Agent大厅/工作流/执行监控默认 `false`——对应问题5"本项目暂不用"；其余维持现状 `true`）
  2. 导出 helper `isModuleEnabled(key)` 与 `MODULE_PERMISSION_MAP`（模块 → 所需权限码，如 `agentHall → 'agent:read'`，便于问题4 兜底）。
- [ ] **涉及文件**（1）：
  - `frontend/src/config/modules.ts`（新建）
- [ ] **依赖**：无
- [ ] **验证**：单元测试断言 `isModuleEnabled('agentHall')===false`；`MODULE_PERMISSION_MAP.agentHall==='agent:read'`。

### Chunk B：Sidebar 菜单按开关 + 权限统一过滤（问题4 + 问题5前端）

- [ ] **目标**：菜单项显隐 = `ENABLED_MODULES[模块] && hasPermission(权限码)`；删掉 Sidebar.vue:94 本地 `isAdmin` 复算（改用 store）。
- [ ] **动作**：
  1. `Sidebar.vue` 顶部 import `isModuleEnabled, MODULE_PERMISSION_MAP`。
  2. `navItems` computed 每项加 `module` 标签，过滤条件改为：
     ```
     items = items.filter(it => isModuleEnabled(it.module) && (it.perm ? hasPermission(it.perm) : true))
     ```
     - Agent大厅/工作流/执行监控 → `module` 对应开关（默认 false，自动消失）。
     - 视频生成/图片生成/视频剪辑/无限画布/资产库 → 既有 `hasPermission` 不变。
     - 用户管理/角色权限/价表/充值/账单/审计 → 既有 `isAdmin`/`hasPermission` 不变。
     - 知识库/智能对话/我的钱包 → 维持常驻（或按需配开关，默认 true）。
  3. 删 `const isAdmin = computed(...)` 本地复算，统一用 `authStore.isAdmin`。
- [ ] **涉及文件**（1）：
  - `frontend/src/components/Sidebar.vue`
- [ ] **依赖**：Chunk A
- [ ] **验证**：
  - 手动：admin 登录 → 菜单无 Agent大厅/工作流/执行监控（问题5）。
  - 手动：普通 user 登录 → 无权限模块不显示（问题4）。
  - 单元测试：`navItems` 在 `ENABLED_MODULES.workflow=false` 时不含 `/workflow`。

### Chunk C：路由守卫加"模块开关 + admin 设置门"重定向（问题3 + 问题5后端兜底）

- [ ] **目标**：手敲 URL 也跳转，避免菜单隐藏被绕过。
- [ ] **动作**：
  1. `router/index.ts` 给路由 `meta` 加 `module`（对应 `ENABLED_MODULES` key）与 `requireAdmin`（bool）字段。
     - `/settings` → `meta: { requireAdmin: true }`（问题3：非 admin 不让进）
     - `/agents` `/workflow` `/executions` → `meta: { module: 'agentHall'/'workflow'/'execution' }`
  2. `beforeEach` 守卫增加两段判断（在既有 `requiresAuth` 判断之后）：
     ```
     if (to.meta.requireAdmin && !authStore.isAdmin) → next('/') + warning("无权限访问")
     if (to.meta.module && !isModuleEnabled(to.meta.module)) → next('/') + warning("该功能未开放")
     ```
- [ ] **涉及文件**（1）：
  - `frontend/src/router/index.ts`
- [ ] **依赖**：Chunk A
- [ ] **验证**：
  - 手动：普通用户敲 `/settings` → 跳首页（问题3）。
  - 手动：admin 敲 `/agents` → 跳首页 + warning（问题5）。
  - 手动：admin 敲 `/settings` → 正常进入。

### Chunk D：SettingsView 移除"我的模型"Tab + 非 admin 无 Tab 兜底（问题1 + 问题3前端）

- [ ] **目标**：前端不再开放个人模型配置入口；并确保普通用户即便绕过路由也看不到设置内容。

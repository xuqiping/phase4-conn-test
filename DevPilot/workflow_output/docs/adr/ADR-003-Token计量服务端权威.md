# ADR-003 · Token 计量服务端权威

> 状态：已决定 ｜ 日期：2026-08-13 ｜ 决策人：用户确认 + AI 建议

## 背景

商业模式为 Token 充值转售：用户充值 → 按模型官方价 × 加价率扣费。计费的可信度直接等于商业模式的存亡。客户端运行在用户机器上，理论上可被逆向篡改。

## 备选方案

| 方案 | 优势 | 劣势 |
|---|---|---|
| **服务端权威计量 + 网关统一转发** | 客户端零密钥、零信任负担；用量以上游返回为准，无法本地篡改 | 必须自建模型网关；多一跳延迟 |
| 客户端计量上报 | 实现简单 | 可被篡改，商业模式直接失效 |
| 客户端持有上游 Key 直连 | 无网关成本 | Key 泄露即资损；无法计费 |

## 决定

1. 客户端**不持有任何上游模型 Key**，全部 LLM 调用经自家模型网关转发（`/api/v1/gateway/chat`）。
2. 计量以**上游响应 usage** 为准，在云端 token_ledger 入账（幂等键防重）。
3. 客户端 usage_mirror 仅为展示镜像，定时与云端对账，差错位告警。
4. BYOK 用户例外：自带 Key 直连，平台不计费不担保（明示）。

## 理由

- 转售模式命门就是计量可信度；「客户端不可信」是安全设计基本原则。
- 网关同时承载多供应商路由/故障转移/成本优化（轻任务走国产模型），一举多得。

## 后果与代价

- 网关成为单点：需多供应商冗余 + 熔断降级（PERF-13 可用性 ≥99.5%）。
- 流式转发增加工程复杂度（SSE 透传 + 末帧 usage 入账）。
- BYOK 模式与计费模式并存，客户端需清晰区分两条调用链路。

# Cache Middleware Workflow Checklist

在完成 `workflow/cache_middleware_workflow.md` 的每一步后，使用此检查清单进行交叉验证。每个项目必须回答**是**才算完成。如果有任何项目回答**否**，修复输出并重新验证。

## Step 1: 识别缓存需求场景

- [ ] 已明确场景类型（缓存选型/架构设计/问题排查/性能优化/冷热分离）
- [ ] 已识别数据类型（简单KV/复杂对象/集合/分布式锁/限流计数/向量搜索）
- [ ] 已提取访问模式（读多写少/读写均衡/写多读少/热点集中）
- [ ] 已提取延迟要求（纳秒级本地缓存/微秒级同机房Redis/毫秒级跨可用区）
- [ ] 已提取缓存层级需求（是否需要多级缓存L0→L1→L2→L3）
- [ ] 已提取特殊约束（数据量>100GB需分片、持久化需求、内存预算）
- [ ] 已对照知识库产品矩阵完成初步判断（Redis全栈/Memcached纯KV/Caffeine本地缓存）
- [ ] 如有信息缺失，已向用户追问不超过2个澄清问题

## Step 2: 输出缓存方案

- [ ] 如为缓存选型，选型对比表已覆盖数据结构丰富度/延迟级别/容量上限/高可用/持久化/特殊能力
- [ ] 如为缓存选型，Redis vs Memcached vs Caffeine对比已输出
- [ ] 如为架构设计，多级缓存层级已设计（L0边缘→L1本地→L2分布式→L3数据库）
- [ ] 如为架构设计，数据一致性策略已说明（Cache-Aside/Write-Through/Write-Behind）
- [ ] 如为架构设计，数据分片策略已覆盖（一致性哈希Jump Consistent Hash vs Redis Cluster 16384 Slot）
- [ ] 如为架构设计，租户隔离策略已说明（Key前缀/Namespace）
- [ ] 如为问题防护，缓存穿透方案已覆盖（布隆过滤器+空值缓存+参数校验）
- [ ] 如为问题防护，缓存击穿方案已覆盖（互斥锁+逻辑过期+热点预加载）
- [ ] 如为问题防护，缓存雪崩方案已覆盖（TTL随机偏移+多级缓存降级+熔断兜底）
- [ ] 如为问题防护，降级原则已强调（缓存必须有降级方案，数据库必须能独立承载全部流量）
- [ ] 如为冷热分离，30天未访问数据迁移策略已说明（SSD/对象存储，成本降60-70%）
- [ ] 如为性能优化，大Key避免原则已说明（String>10KB、Hash/Set/ZSet成员数>5000）
- [ ] 如为性能优化，Redis 8.0多线程和Valkey分叉选型建议已给出
- [ ] 所有核心论断均能在知识库中找到支撑来源

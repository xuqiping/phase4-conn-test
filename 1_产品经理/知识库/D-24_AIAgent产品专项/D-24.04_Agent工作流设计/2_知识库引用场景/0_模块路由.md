# D-24.04 Agent工作流设计 — 引用场景

## 场景1：工作流从0设计（新建Agent产品需设计完整工作流）

**何时进入**：新建 Agent 产品，需从0设计任务执行闭环——决定用什么编排模式、怎么错误恢复、哪些要人审、状态怎么存。

**查什么**：
- 1_知识库概览 → 核心要素表（12项工作流设计要素）+ 四子维度定位
- 3_AI精炼版 → 三个碎片全景（编排模式 / 错误恢复 / HITL+状态管理+Harness）
- 4_可落地流程 → 4.1 工作流设计Agent（8段元提示词辅助设计）+ 4.2 SOP与模板（4套SOP+6模板）

**PM 要回答的问题**：
- Agent 任务平均多少步？是 ReAct 够还是要 Plan-and-Execute？
- 哪些操作必须人审？哪些可全自动？
- 上下文窗口够不够？需不需要 Compaction？
- 状态怎么存？崩溃了能不能恢复？

## 场景2：编排模式选型（已有简单ReAct，需评估升级复杂模式）

**何时进入**：Agent 已用 ReAct 跑通简单任务，但任务变复杂（10+ 步 / 需并行 / 需自检）时，需评估是否升级到 Plan-and-Execute / Planner-Worker / Reflection / 多 Agent 编排。

**查什么**：
- 3_AI精炼版 → 3.1 任务拆解与编排模式（ReAct/Plan-and-Execute/ToT/Reflexion/混合编排 适用边界与决策树）
- 4_可落地流程 → 4.2 SOP：编排模式选型流程 + 编排模式选型决策表模板
- 5_业内顶级案例 → Plan-and-Execute 代码审查 8→2.5 分钟案例 / Reflection 改进代码生成案例

**PM 要回答的问题**：
- ReAct 跑 20 步以上必崩，要不要切 Plan-and-Execute？
- 什么时候用 Reflection 反思循环？什么时候反而拖慢？
- 多 Agent 编排 vs 单 Agent Planner-Worker 怎么选？
- 模式选错是不是工具调用死循环（31% 故障根因）的元凶？

## 场景3：错误恢复设计（Agent频繁崩/死循环/超时）

**何时进入**：Agent 上线后频繁出现：工具调用死循环、超时卡死、参数错重试无果、上下文溢出、越权操作。

**查什么**：
- 3_AI精炼版 → 3.2 错误恢复与重试（五级恢复策略：重试/降级/绕路/重规划/人工接管 + Reflection 反思循环 + Loop Engineering 范式）
- 4_可落地流程 → 4.2 SOP：错误恢复设计流程 + 错误恢复策略矩阵模板 + 反漂移检测模板
- 5_业内顶级案例 → OpenClaw 反面教材（无错误恢复/无停止机制）/ DECO Hook 护栏实践 / Claude Code Ralph Loop

**PM 要回答的问题**：
- 5 级恢复策略分别用于什么错误场景？阈值怎么定？
- 重试次数怎么设？指数退避怎么配？
- 怎么检测 Agent 进入死循环？反漂移怎么实现？
- 什么时候必须升级到人工接管而非继续重试？

## 场景4：Human-in-the-Loop 设计（涉及不可逆操作需HITL护栏）

**何时进入**：Agent 涉及不可逆操作（删数据/转账/发布/邮件发送/合同签署），必须设计 HITL 护栏防止 LLM 越权执行。

**查什么**：
- 3_AI精炼版 → 3.3 HITL 与状态管理 + Harness 工程（HITL 三档：人工审核/人工确认/人工接管 + 副作用护栏分级 + Hook 设计）
- 4_可落地流程 → 4.2 SOP：HITL 护栏设计流程 + 副作用风险矩阵模板 + Hook 护栏清单模板
- 5_业内顶级案例 → OpenClaw 越权删邮件反面教材 / DECO 三层 Hook 护栏实践 / Salesforce 80% 越界数据

**PM 要回答的问题**：
- 哪些操作是可逆？哪些不可逆？哪些部分可逆？
- HITL 三档（人工审核/人工确认/人工接管）分别用于什么操作？
- Hook 护栏插在哪些节点？工具调用前/后/预完成/错误时？
- 紧急制动（硬停止按钮）怎么设计才能不依赖对话请求停止？

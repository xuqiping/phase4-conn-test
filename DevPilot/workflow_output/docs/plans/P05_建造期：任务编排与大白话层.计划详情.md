  1. `core-orchestrator/src/task_scheduler.rs` 实现 `Scheduler::run_round`：

## 技术坑点预判

| 坑点 | 规避 |
|---|---|
| runner 在 `db.write` 闭包里调 tokio 异步导致死锁 | scheduler 把 runner 放在 `block_in_place` 外；事件经 channel 落库 |
| 任务事件洪水拖慢 UI | narrative 事件精简，raw 日志按需拉取/限流 |
| LLM 生成文件路径逃逸 | 生成后过 `SandboxPolicy.join` 校验；绝对路径/`..` 直接拒 |
| diff 摘要调用成本爆炸 | diff >5000 行截断并提示；同一 checkpoint 缓存摘要 |
| `git reset --hard` 丢失未跟踪文件 | 回滚前提示用户；MVP 先支持 tracked 文件回滚 |
| 追加指令与计划 tasks 混排顺序乱 | 续跑 task 的 `chunk_no = max+1` |
| 翻译层高频调用模型 | 术语表本地优先；整段翻译走 cheap 模型并缓存 |

## 安全检查清单

- 输入校验：instructions 长度 ≤2000；生成文件路径白名单校验。
- 沙箱：文件写入仍走 `core_sandbox` + runner。
- Secrets：runner 已做注入与脱敏；事件流 raw 日志也经 `redact`。
- 审计：`task_events`/`checkpoints` 只增不改；`transition_history` 记录阶段推进。
- 计费：续跑/回滚不扣 Token；diff 摘要正常计量；任务执行前可调用 `/gateway/estimate`。
- 危险操作：`git reset --hard` 需二次确认；仅 build 阶段可回滚。

## 功能联动点清单

| 触发动作 | 联动对象 | 预期变化 | 边界 |
|---|---|---|---|
| 审批 plan | `tasks` 表 | 生成 pending tasks | 重新审批会清空旧 tasks/checkpoints（先提示） |
| execute_build | scheduler + runner | tasks 顺序执行，checkpoints 增加，成功后到 accept | 任一失败即停，留在 build |
| task 事件流 | Build 视图 + task_events | 叙事流实时更新；raw 日志可展开 | 仅保留最近 N 条可见，全部落库 |
| task 完成 | diff 摘要面板 | 展示大白话摘要；可切原文 | 摘要失败显示原始 diff |
| 回滚存档点 | git HEAD + 下游 tasks | 代码恢复；后续 tasks 重置 pending | 不删除 checkpoints |
| 追加指令续跑 | 新 task + scheduler | 同一 round 末尾新增并执行 | 多次追加按顺序排队 |
| 翻译开关 | PlainText 组件 | 技术文本切换大白话 | 术语气泡始终可用 |

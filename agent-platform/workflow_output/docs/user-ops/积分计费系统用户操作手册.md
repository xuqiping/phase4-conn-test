# 用户操作手册 · 积分计费系统

> 终端用户（普通用户 / 管理员）傻瓜式操作步骤。读完即可上手。
> 开发者原理见 [../feature-map/积分计费系统.feature-map.md](../feature-map/积分计费系统.feature-map.md)。
> 规格见 [../specs/积分计费系统.md](../specs/积分计费系统.md)。

## 这个功能是什么

平台用「积分」统一计量你调用大模型（对话/RAG/记忆/视频/图片）的消耗。

- **普通用户**：你有一个积分钱包。每次用 AI（聊天、生视频、传文件给知识库）会按用量扣积分。余额见积分，不直接见钱。
- **管理员**：除自己钱包外，还能看全平台真实消耗（token 数 + 人民币 + 积分）、配模型价表、给用户充值。

## 你需要准备什么

- 一个能登录的账号（普通用户或管理员）。
- 管理员才有的操作会在标题标注 **【管理员】**。
- 普通用户操作前，确保钱包有积分（管理员给你充过，或已自助充值）。

## 一、普通用户 · 看我的钱包

**目的**：查当前积分余额 + 历史流水（充了多少、用了多少、剩多少）。

**路径**：登录后，左侧菜单点 **「我的钱包」**（`/me/wallet`）。

**看到什么**：
1. **余额卡片**：显示当前积分余额。正数=可用；负数=欠款（见下「欠款怎么办」）。
2. **流水列表**：每一行一笔变动，含：
   - 时间
   - 类型：充值（RECHARGE）/ 消耗（CONSUME）/ 退款（REFUND）/ 管理员发放（ADMIN_GRANT）
   - 变动量：正数加、负数扣
   - 变动后余额
   - 来源说明（来自哪次聊天/视频/充值）

**查用法**：点 **「我的用量」**（`/me/usage`）看自己近期的调用记录（消耗明细）。

> 注意：用户视图**只显示积分**，不显示原始 token 数和人民币金额。

---

## 二、余额不足怎么办

**2026-08 安全加固后，余额不会再扣成负数**：扣费时余额不够的笔会被直接拒扣（该次调用计费失败，不影响你已拿到的回答）；下一次发起 AI 调用（发消息/生视频）时余额 ≤0 会被**拦截**，提示积分不足。

**怎么办**：
1. **自助充值**（2026-08-21 起，见「十二、自助充值」），或
2. 联系管理员给你充值（见【管理员】充值章节）。
3. 充到余额 > 0 后即可继续使用。

> 为什么不是预估先拦？文本/流式调用的真实用量要等模型返回才知道，系统选「先用后扣」而非预估——避免估错误拦你。账户系统兜底保证余额不为负。

---

## 三、对话/视频/知识库怎么扣费（无需手动操作）

你正常用 AI 即可，扣费全自动：

- **聊天对话**：按你选的模型 × 输入/输出 token 数 × 价表扣。流式输出也一样（按最终 token）。
- **知识库 RAG**：检索用的 embedding + 回答用的 chat 都计。
- **记忆**：你发的内容触发的记忆收录/生成 LLM 也计（跟对话用同一个模型）。
- **视频生成**：按 token（若模型回传）或按秒扣。
- **图片生成**：按张扣（按模型上线情况）。

**失败的调用**：模型报错或超时 → 自动**全额退款**，流水里会看到一条 REFUND。

> 所有扣费都记录在流水里，对得上账。如果某次扣得可疑，对照流水的时间 + 来源说明查那次调用。

**计入项目组（2026-08-20 更新）**：每页顶部「参与项目」下拉选中某组后，上述所有调用改扣**组池积分**（个人钱包不动），页顶同步显示「组池 / 个人」两个余额徽标；切回「个人」即恢复个人钱包计费。详见[项目组与积分划拨用户操作手册](项目组与积分划拨用户操作手册.md)第 4 节。

## 四、【管理员】看全平台账单

**目的**：看全平台真实消耗——谁用了、哪个模型、花了多少钱和积分、趋势如何。

**路径**：登录管理员账号 → 左侧菜单 **「计费管理」**（`/admin/billing`）。

**功能页签**：

1. **总览（overview）**：平台累计消耗、活跃用户数、近期总积分流水。
2. **按用户（by-user）**：每个用户的消耗排名。点用户看明细。
3. **按模型（by-model）**：哪个模型用得多（帮你判断价表是否合理）。
4. **按类型（by-kind）**：CHAT / EMBED / VIDEO / IMAGE 各占多少。
5. **趋势（trend）**：按日期折线图，看消耗涨跌。
6. **调用日志（call-log）**：每一次模型调用的真实记录——**真 token 数 + 人民币 + 积分 + 成功/失败**。

**筛选**：页面顶部可按用户 / 模型 / 日期范围筛。

> 管理员视图能看到真实 token 和 ¥，这是与用户视图（只见积分）的核心区别。

## 五、【管理员】配置模型价表

**目的**：给每个模型定单价（文本按 token、视频按秒/按 token、图片按张）。价表改了，之后的调用按新价算。

**路径**：管理员 → **「计费管理」→「价表配置」**（`/admin/pricing`）。需要 `pricing:manage` 权限。

**操作步骤**：

1. **新增价表行**：点「新增」，从可搜索下拉中选择尚未配置价表的“供应商 · 模型”；系统自动绑定类型、providerId 和模型名。历史全局价已经覆盖的同名模型不会再次出现。然后填：
   - 文本模型：填 **输入每百万 token 价（¥）** 和 **输出每百万 token 价（¥）**
   - 视频模型：选计费方式（TOKEN 或 SECOND），填对应价
   - 图片模型：填 **每张价（¥）**
   - 生效时间（effective_from）：设什么时候开始按这价算
2. **改价**：找到该行，点编辑，改价 + 设新生效时间（保留旧行历史，不直接覆盖）。
3. **保存**。

**原理（一句话）**：系统查「调用那一刻有效的价表行」算钱——改价只影响之后的调用，历史账不变。

> 注意：新增一个模型前，**先在价表里给它定价**，否则该模型调用会因找不到价表行报错/无法计费。
> 若下拉只剩少量模型，表示其他 ACTIVE 供应商模型已有专属价或历史全局价，并非加载失败。

## 六、【管理员】价表导出 / 导入 / 下载模板（2026-08 新增）

**目的**：批量备份/迁移价表；或按模板快速给一批模型配价（联动全局供应商，自动填未配置过的模型，区分对话/图片/视频）。

**路径**：管理员 → **「计费管理」→「价表配置」**（`/admin/pricing`）。

### 6.1 导出当前价表（备份）

1. 点「**导出**」按钮 → 弹确认框 → 点「导出」。
2. 浏览器下载 `pricing-rules-yyyy-MM-dd.json`，含当前全部价表行（明文价格，无密钥）。

### 6.2 下载填充模板（推荐先配新模型的方式）

1. 点「**下载模板**」按钮。
2. 浏览器下载 `pricing-template-yyyy-MM-dd.json`。
3. 模板内容：**联动全局供应商，自动把未配置过价的模型预填为空白行**，每行已带 `kind`（CHAT/IMAGE/VIDEO）、`providerId`、`model`，价格字段留空。
   - LLM 对话模型（CHAT）：填输入价 + 输出价
   - 图片模型（IMAGE）：填每张价
   - 视频模型（VIDEO）：选计费模式 + 填对应价；如需区分「有参考视频/无参考」两价，复制该行改成两行（一行 `hasReference=false`，一行 `hasReference=true`）
4. 填好后点「**导入**」上传。

### 6.3 导入价表（批量配价/改价）

1. 点「**导入**」按钮 → 选 JSON 文件。
2. 弹确认框显示预计「新增 N / 更新 M」（按 providerId+model+kind+hasReference 比对本地）。
3. 点「导入」。
4. **导入语义 = Upsert**：同名（同 providerId+model+kind+hasReference）行**价格会被覆盖**，`effective_from` 刷新为导入时刻（立即按新价）。
5. 完成提示：`导入完成：新增 X / 更新 Y / 失败 Z`。失败的行（如 provider 不存在、kind 不匹配）会列在浏览器 console（F12 看）。
6. **上限 200 行/次**，超了会被拒。

> 注意：导入会覆盖已有价，请确认模板内容再上传。价表无密钥，无需二次确认。

## 七、【管理员】视频模型配「有参考 / 无参考」双价（2026-08 新增）

**场景**：seeddance 等视频模型，带参考视频（如动作参考 mp4）和无参考（纯文生）成本不同，需分别定价。

**操作**：在「价表配置」为同一视频模型配两行：
1. 第一行：模型选 seeddance，「是否含参考视频」开关**关**，填无参考价（如 20 元/百万 token）。
2. 第二行：再点「新增」，选同一个 seeddance（候选仍可见，因 has_reference 维度不同不冲突），「是否含参考视频」开关**开**，填有参考价（如 10 元/百万 token）。

**计费命中规则**：
- 任务带参考视频附件 → 命中 `hasReference=true` 行
- 任务无参考视频（纯文生 / 仅首尾帧图）→ 命中 `hasReference=false` 行
- **若只配了 false 行没配 true 行**：带参考视频任务会 fallback 到 false 行价（兜底，不报错）
- 若只配了 true 行没配 false 行：无参考任务会报「价表未配置」（不会无限兜底）

> 注意：**首尾帧参考图（kind=image）不算参考视频**，只有 kind=video 的附件才触发「有参考」价。建议同时配 false+true 两行避免漏单。

## 八、【管理员】查看视频任务的推送参数与参考标志（2026-08 新增）

**目的**：审查某次视频生成实际推给模型的参数、明确是否带了参考视频，便于核对计费是否正确。

**在视频生成页（VideoGenView）**：
1. 历史列表新增「**参考视频**」列：标「有」或「无」（旧任务显「-」）。
2. 点「查看」打开任务详情，任务头部有「**有参考视频 / 无参考**」标签。
3. 详情区有「**请求参数**」按钮，点开看两个 tab：
   - 平台收到的提交参数（submittedRequest）
   - 实际发给模型的请求（providerRequestSnapshot，媒体已脱敏为 SHA-256/大小，不含二进制）

**在无限画布**：
1. 视频节点角标显「**参考 / 无参考**」。
2. 选中视频节点 → 右侧属性面板：taskId 行旁有参考标志；下方「**请求参数**」按钮可看推送详情。
3. 旧任务（迁移前）无推送快照时，面板会提示「该历史任务未记录发送快照」。

> 注意：推送参数用于审查，不会暴露你的原始视频/图片二进制（已脱敏）。hasReference 标志与计费命中口径一致——只有 kind=video 附件才算参考视频。

## 九、【管理员】配置阶梯比例（¥ → 积分）

**目的**：定「1 元换多少积分」，可按金额区间设阶梯（充得多换得多）。

**路径**：管理员 → **「价表配置」→「阶梯比例」页签**（`/admin/pricing` 的 ratio 部分）。

**操作步骤**：

1. 点「新增比例」：
   - 最小金额（min_amount）：区间下限（¥）
   - 最大金额（max_amount）：上限（¥，留空=无上限）
   - 比例（ratio）：这区间每 ¥ 换多少积分
2. 例如：0–100 元 1 元=10 积分；100 元以上 1 元=12 积分。
3. 保存。

**原理（一句话）**：充值和消耗都用这比例换算——价表标 ¥，积分 = ¥ × 命中区间的比例。

## 十、【管理员】给用户充值

**目的**：手动给某用户加积分（内测/补偿/赠送给客户）。

**路径**：管理员 → **「钱包管理」**（`/admin/wallet`）。需要 `points:recharge` 权限。

**操作步骤**：

1. 找到目标用户（按用户名/ID 搜）。
2. 点「充值」。
3. 填充值积分数量（或金额，按当前比例算出积分）。单次上限 1 亿积分，超了会被拒并提示。
4. 可填**备注**（可空）：会落在流水「来源说明」里，方便以后查账（如「8月内测补偿」）。
5. 确认 → 该用户余额立即增加，流水记一条 ADMIN_GRANT。

**防重复到账（幂等键，2026-08 安全加固新增）**：

- 网络卡顿/双击/刷新导致的**重复提交，系统只充一次**——后端给每笔充值占位一把幂等键，同键重放只返回第一次的结果，不会重复加积分。
- 如果你充完不确定有没有成功，**直接重试是安全的**：余额不会翻倍，返回的就是第一次充完后的余额。
- 若看到「幂等键冲突，请更换幂等键」提示：说明这把键已被别的用户/别的业务用过（极罕见），刷新页面重发即可。

> MVP 阶段充值渠道是 ADMIN（管理员手动）。自助支付（支付宝/微信）为 Phase 2，届时 `payment_order` 的 channel 会扩展。

## 十一、【管理员】每日对账（2026-08 安全加固新增）

**是什么**：系统每天自动核对一次「每个用户的钱包余额 = 该用户全部流水之和」。账实相符是积分系统的命根子。

**你需要做什么**：**平时什么都不用做**。对账全自动跑，发现不平会写 ERROR 日志 + 安全审计记录。

**收到对账不平告警时**：
1. 不要慌——这表示检测到数据被异常改动（如有人直接改库）。
2. 也可随时手动拉一次：调用 `GET /api/billing/admin/reconcile`（或让开发同事在服务器上执行），返回哪些用户对不上、差多少。
3. **系统绝不会自动修账**——修账必须人工查清原因后手动处理，这是故意的安全设计。

## 常见问题

**Q: 我刚发了一条消息，余额没立刻变？**
A: 扣费在模型返回后同步完成（毫秒级）。流式输出要等整条结束才扣最终 token。若久久不变，看流水是否有对应 CONSUME 行。

**Q: 失败的调用扣我积分了吗？**
A: 没有。失败的调用自动全额退（流水里有 REFUND）。只有成功的才扣。

**Q: 管理员改了价，我之前的账会变吗？**
A: 不会。价表带生效时间，改价只影响之后的调用，历史账固定。

**Q: 为什么管理员看到的数字和我看到的不一样？**
A: 设计如此——你只见积分（¥×比例），管理员见真实 token+¥+积分。是分权设计，不是算错。

**Q: 充错用户了怎么办？**
A: 联系有 `points:recharge` 权限的管理员，给对方做一笔反向调整（目前无直接「撤销充值」按钮，靠管理员手动对冲，并记流水备注）。

**Q: 我点了两下充值按钮，会充两次吗？**
A: 不会。幂等键保证同一笔提交只到账一次（见充值章节的「防重复到账」）。

**Q: 流水能被管理员改掉吗？**
A: 不能。流水表只增不改：应用账号在数据库层被禁止 UPDATE/DELETE 流水，另有每日对账抓异常（见对账章节）。

## 【管理员】给同一视频模型配「有参考」和「无参考」两种价（7x-6，2026-08-14）

**场景**：视频模型带参考视频生成（图生视频/参考视频）与不带参考（文生视频）成本不同，需要分别定价。

1. 「价表配置」→「新增价表」。
2. 「全局模型」下拉选视频模型。若该模型已配过其中一面（如已配「无参考」价），下拉仍会出现它，选项文字会带提示，如：
   `sd2 · Cdance2.0 · 视频（已配「无参考」价，本次新增为「有参考」价行）`。
3. 打开「是否含参考视频」开关（这次要配的另一面）。
4. 填价（TOKEN 按 token / SECOND 按秒）→ 保存。
5. 重复 2-4 可配另一面。两面都配齐后，该模型才从候选下拉消失。

**注意**：
- 编辑已有价行时「是否含参考视频」开关为锁定态——它与 provider/model/kind 同属身份字段，改价请新增另一面行。
- 计费匹配规则：任务带参考视频附件 → 命中「有参考」行；没有 → 命中「无参考」行；只配了一行（如只配无参考）时，有参考任务也按该行计费（fallback）。
- 完成标志：列表出现同一 model 两行，「参考视频」列分别显示「无参考」「有参考」。


## 【管理员】删除配错的价表行（2026-08-14 追加）

**场景**：配错了模型/价格，需要清理。

1. 「价表配置」→ 列表「操作」列点「**删除**」。
2. 确认弹窗会显示行身份（模型名 + 有/无参考），确认后物理删除。
3. **注意**：若删的是该模型唯一价行，之后调用它提交任务会报「价表缺失」，需重新配置；已产生的历史账单/流水不受影响（金额在扣费时已落账）。
4. 删除后该维度会重新出现在「新增价表」候选下拉，可重新配置。

## 十二、自助充值（2026-08-21 新增）

**场景**：余额不足，不想找管理员，自己在线充值。

1. 「我的钱包」页右上角点「**充值**」（看不到按钮=平台暂未开通支付渠道，走管理员代充）。
2. 弹窗里输入**金额**（¥0.01 ~ ¥99999.99）、选**支付渠道**，点「去支付」。
3. 进入收银台：
   - 测试环境（模拟支付）：点「模拟支付成功/失败」体验全流程——和真实支付走完全相同的入账链路。
   - 真实渠道：用对应 App 完成支付，本页每 2 秒自动查结果，无需手动刷新。
4. **完成标志**：提示「支付成功，积分已入账」，余额立即增加；「充值记录」卡出现一行：时间/渠道/付款账号/金额/积分/充值后余额 + 状态。
5. 中途不想付了：点「取消订单」；不取消也没关系——订单 30 分钟未支付自动关闭，不扣钱。
6. 金额下方「累计充值 xx 元，共 xx 积分」是你的历史充值汇总（只计已支付）。

**常见异常**：
- 「重复提交金额不一致」：同一表单会话内改了金额重复提交——关掉弹窗重开即可（原订单仍有效）。
- 支付后状态仍「待支付」超过 1 分钟：极端情况渠道回调延迟，稍后在充值记录核对；若实际已扣款但订单显示已关闭，联系管理员——对账异常列表会留痕，人工补单。
- 双击/网络重试不会双扣：同一次表单提交只认一单。

## 十三、【管理员】充值记录与用户余额视图（2026-08-21 新增）

**入口**：「账单总览」页 → 「充值记录」/「用户余额」两个 tab（需 usage:view 权限）。

**充值记录 tab**：
1. 顶部筛选：用户名（回车）/渠道/状态/日期区间 → 点「查询」。
2. 筛选上方一行汇总：「当前筛选：已付金额 ¥xx，已付积分 xx」——**随筛选联动**（只统计已支付；筛「待支付」等状态时归零，属正常口径）。
3. 表格六字段 + 用户列 + 状态：时间/用户/渠道/付款账号/金额/积分/充值后余额。
4. 未支付单（待支付/失败/已关闭）「充值后余额」显「—」（无流水）。

**用户余额 tab**：
1. 顶部四张合计卡：用户数 / 余额合计 / 累计充值积分 / 累计充值金额——**全平台口径**，不受下方筛选影响。
2. 表格每用户一行：当前余额 / 累计充值积分 / 累计充值金额 / 最近充值时间；从未充值的用户各项显 0。
3. 点「当前余额」「累计充值积分」「累计充值金额」列头排序（服务端排序）；用户名输入框回车模糊筛选。
4. 用途：回答「全平台充了多少钱、发了多少积分、现在用户手里还有多少」。

**人工补单**（极少见）：用户已付款但订单显示已关闭 → 「账单总览」对账区「支付渠道异常」第三节有其线索（时间/单号），核实后走管理员充值补等额积分并备注订单号。

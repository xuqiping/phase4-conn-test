## 关键调用链

**保存画布**：前端 `CanvasView.scheduleSave`（800ms 节流，剥 blob: previewUrl）→ `canvasApi.save` → `PUT /api/canvas/{id}` → `CanvasService.save`（ownership 校验 + 整存 snapshot JSONB）。

**节点产出（文本/脚本）**：`PropertyPanel` 运行按钮 → `onRunNode`（置 running）→ `POST /{id}/nodes/run` → `CanvasNodeRunnerService.run{Text,Script}` → `LlmGateway.chat` → 返 `NodeRunResult.dataPatch` → 前端合并 + scheduleSave。

**视频生成**：`onRunVideo` → 沿入边 `resolveUpstreamImageFileId` 找上游图 fileId 作 refFileId → `mediaApi.submitVideo`（`media:gen` gated，无权→403→节点 FAILED）→ 5s 轮询至终态 → SUCCEEDED 时 `fetchVideoBlob` 拉 blob 转 objectURL 预览，存 `taskId`/`mediaStatus`/`resultFileId`。

**抽帧/截取**：`PropertyPanel` 按钮 → `onExtractFrame`/`onClipVideo` → `POST /{id}/nodes/{nodeId}/frames` 或 `/clip` → ①`loadOwned`（画布归属）②`resolveVideoFileId`（定位视频节点+校验 type）③`loadPath`（**视频源文件 ownership 复检**，防借他人 fileId）④`VideoFrameService.extract`/`clip` ⑤`storeStream(SOURCE_CANVAS)` → 前端 `addNode` + `addEdge` 自动连边（失败标红源节点不建空节点）。

**故事板拼接**：`StoryboardPanel` 调序 → 拼接按钮 → `POST /{id}/storyboard/concat`（body fileIds）→ ①`loadOwned` ②`LinkedHashSet` 去重保序 ③逐 fileId `loadPath` 复检 ④`VideoFrameService.concat`（首段尺寸初始化 recorder，逐段 grabImage 重编码进同一 recorder→H.264/mp4 临时文件）⑤`storeStream(SOURCE_CANVAS)` + try-finally 删临时文件 → 前端 `addNode(video)` 成片节点。

**一键重跑**：`onRerunAll` → `topoSort`（Kahn 入度+邻接表，`order.length<nodes.length`⇒环报错）→ 按拓扑序串行跑可生成节点（text/script/video）。

## 表与 SQL 注解（V55，Flyway）

> 建表走 Flyway（`V55__canvases.sql`）。已执行不可改，改结构加新版本。产出物复用 V40 `stored_files`（写一行 `source=CANVAS`）。

**`canvases`（画布快照表）**
- 生活比喻：一张「创作台照片」——把整张画布当前长什么样（有哪些节点、怎么连、摆哪里）拍成一张 JSON 照片存起来，下次按照片复原。
- 关键字段：
  - `id` IDENTITY — 画布唯一编号。
  - `user_id` — **谁的画布**，ownership 硬过滤靠它（普通用户只能动自己的；admin 旁路）。
  - `name` — 画布名（默认「未命名画布」）。
  - `snapshot` JSONB — 整张画的结构（`{nodes:[{id,type,position,data}], edges:[{source,target,...}]}`）。**只存 fileId 引用不嵌 base64**，否则 JSONB 撑爆。≤5MB 上限。
  - BaseEntity 审计列 `created_by/created_at/updated_by/updated_at` + `deleted`（`@TableLogic` 软删）+ `version`。
- 索引：`(user_id, updated_at) WHERE deleted=0` 部分索引（跳过软删行，列表查询快）。
- 权限 seed：`permissions('canvas:write')` + 仅 admin 给（gated，普通 user 按需授，照 V54 `media:gen` 范式）。
- 踩坑批注：① 软删画布**不级联清 stored_files**（产物保留供历史复用，后续清理脚本）；② snapshot 整存整取不建特殊 JSONB 索引；③ `JsonbStringTypeHandler` 同 `MediaGenTask.requestConfig`（String↔jsonb）。

**复用 `stored_files`（V40，画布产出物）**
- 画布所有产出（上传图/音频、抽帧图、截取视频、拼接成片、衍生图）都写一行 `source=CANVAS`，靠 `SOURCE_CANVAS` 常量标记来源。
- 不为画布新建表——复用 V40 既有索引与 ownership 咽喉点（`loadPath`/`load`）。

## 部署必做

- **linux 服务器 pom 追加 ffmpeg linux-x86_64 classifier**（C11/C12/C13 共用同一 javacv 栈）：dev 用 windows-x86_64 单平台，linux 不加会 `UnsatisfiedLinkError`。
- 临时文件落 `${java.io.tmpdir}`（`canvas-clip-*.mp4`/`canvas-concat-*.mp4`），storeStream 后即删；高并发截取/拼接预留 tmpdir 空间（单片段上限 600s·2Mbps≈150MB，拼接 ≤20 段）。
- 配置：`canvas.enabled`(默认true) / `canvas.max-nodes` / `canvas.frame-extractor=javacv`（ffmpeg 系统进程分支留后续）。

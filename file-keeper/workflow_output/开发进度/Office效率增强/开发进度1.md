## 2. TDD RED 证据

### RED 1：Worker 尚不存在

命令：

```text
cargo test --manifest-path src-tauri/Cargo.toml --test office_ooxml_worker_contract
```

结果：编译失败，`CARGO_BIN_EXE_office_ooxml_worker` 未定义。失败原因是契约要求的二进制尚未实现，不是测试拼写或环境错误。

### RED 2：普通 ZIP 伪装 OOXML

自审新增“含 `plain.txt`、缺 `[Content_Types].xml` 的 ZIP 命名为 `.xlsx`”用例。定向命令失败：实际返回 `SAFE_OOXML`，预期 `BLOCKED`。随后最小增加 OOXML 内容类型入口校验，错误码固定为 `OFFICE_INVALID_OOXML_PACKAGE`。

### RED 3：外部关系属性含合法空白

把 synthetic `.rels` 改为 `TargetMode = 'External'` 后，定向测试因缺少 `OFFICE_EXTERNAL_RELATIONSHIP_PRESENT` 失败。随后只在匹配前移除 ASCII 空白并统一小写，兼容单双引号；完整契约测试恢复 7/7。

## 3. GREEN 实现

核心文件：

- `src-tauri/src/bin/office_ooxml_worker.rs`：逐行读取 stdin JSON；逐行输出 JSON；只读计算源哈希、打开 ZIP、扫描 entries 与 `.rels`。
- `src-tauri/tests/office_ooxml_worker_contract.rs`：当轮运行时生成无敏感合成 ZIP，覆盖 7 个契约场景；后续规格审查补强见 [开发进度2.md](开发进度2.md)。
- `src-tauri/Cargo.toml` / `Cargo.lock`：增加 `zip 0.6.6`，只启用 deflate。

稳定判定：

- 当轮通过基础 ZIP 骨架检查的 `.xlsx/.docx/.pptx` 且无风险部件：`SAFE_OOXML`；该表述已由后续规格审查收紧，见 [开发进度2.md](开发进度2.md)。
- `.xls/.doc/.ppt`、宏扩展、VBA、签名、外部关系：`HIGH_FIDELITY_REQUIRED`。
- 不支持扩展、损坏 ZIP、伪装 OOXML、不可读或扫描期间变化：`BLOCKED`。

安全边界：路径只来自 stdin JSON；命令行参数被拒绝；不输出正文、密码或原始错误输入；不解压、不重写源包；扫描前后 SHA-256 不一致即阻止。

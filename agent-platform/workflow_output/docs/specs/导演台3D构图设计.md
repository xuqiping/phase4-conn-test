# 规格 · 3D导演台（无限画布构图节点）

> Phase 1 功能规格。实现必须与本文一致；来源为 2026-08-18 用户需求「集成 LibTV 式导演台」（调研见文末参考）。
> 关联：[无限画布四轮增强规格](无限画布四轮增强设计.md)｜[视频反推与转绘规格](视频反推与转绘设计.md)（截图建节点同款）｜[开发进度总览](../../开发进度/开发进度总览.md)。

## 1. 目标

在无限画布新增「导演台」节点：点开进入浏览器内 3D 构图编辑器，用**摆积木**方式搭故事空间（人偶素模/基础几何/群众阵列），摆多机位、调 FOV、选画幅，从机位视角**截图回流画布成图片节点**，作为生图/生视频的构图参考——解决纯提示词讲不清的**空间关系、人物站位、镜头角度**问题（多镜头切机位时角色站位/比例一致性）。

核心原则（用户强调，贯穿全规格）：
- **服务器零渲染**：3D 渲染全部在用户浏览器 GPU，后端零新增计算。
- **零新后端端点**：保存走既有画布快照、截图走既有上传咽喉，攻击面与运维面不增。
- **图元素模**：人偶/道具全部 Three.js 图元（盒/柱/球）拼装，不引外部模型资产，不装 GLB 解析器。

## 3. 技术路线（关键决策）

**浏览器端 Three.js 图元渲染 + 画布节点数据内嵌**：

1. 新前端依赖仅 `three`（+`@types/three`，devDep）。编辑器整体 `defineAsyncComponent` + 动态 `import()` 懒加载——three chunk（gz 约 150~180KB）**只在用户点开导演台节点时拉取**，主包与画布首屏零增量。
2. 场景=纯数据（JSON）存 `node.data.directorScene`，随画布既有保存节奏（PUT snapshot）持久化；渲染器只是数据的视图——**同一份数据换渲染层可重放**，这也是单测可脱离 WebGL 测逻辑层的前提。
3. 人偶素模=图元拼装（头/躯干/四肢盒体+关节组），体型=预设比例参数、姿势=关节组预设旋转，**无骨骼系统、无外部 GLB**；群众阵列=单元素参数化（rows×cols），实例在渲染期展开（InstancedMesh），**存储不逐实例膨胀**。
4. 截图=离屏渲染当前选中机位 → `canvas.toBlob` → 既有 upload 咽喉 → 建 ImageNode 自动连边（复用反推关键帧建节点范式）。
5. 不引入 React/tldraw/3D 引擎框架；编辑器壳为普通 Vue 组件 + 原生 three 场景管理（OrbitControls/TransformControls 为 three 自带 addon）。

## 4. 功能规格

### 4.1 画布节点与入口

- 双击画布空白建节点菜单新增「导演台」（node type `director`），节点卡片显示：场景名（默认「导演台」）、元素数/机位数摘要、封面=最近一张机位截图缩略（无则占位图标）。
- 卡片「打开导演台」按钮（或双击节点）→ 全屏 modal 3D 编辑器；Esc/关闭按钮退出，场景暂存 `node.data`，持久化随画布既有保存。
- `data` 字段遵循平铺规范：`data.directorScene`（本规格 §4.4 的对象）、`data.coverFileId`（最近截图引用）。节点类型加入 `CanvasBoard.vue` 节点清单与类型守卫。

### 4.2 3D 编辑器（modal）

**元素库**（左栏添加面板，点击落场景原点附近）：

| 类别 | 内容 | 上限 |
|---|---|---|
| 人偶素模 | 体型预设 8 种：成男/成女/老者/儿童/高个/矮个/胖/瘦（同一图元骨架×比例参数） | 计入元素总数 |
| 基础几何 | 方块/圆柱/平板/桌子（板+四腿组合）/椅子 | 计入元素总数 |
| 群众阵列 | rows×cols（1..12 × 1..12），间距可调，体型用当前默认素模；存参数不存实例 | 计入元素总数（算 1 个） |
| （P2 档）立牌 | 上传角色/道具图作 billboard 插入场景 | 本期不做 |

- **元素总数上限 200**（含阵列按 1 计）；超限添加按钮禁用+提示。
- 每元素：名称（≤30 字符）、单色材质（12 色板 + HEX 自定义，校验 `^#[0-9a-fA-F]{6}$`）、隐藏开关、复制、删除。列表=左栏元素清单（名称/眼睛/删除），点选联动 3D 高亮。
- **姿势**（仅素模）：预设 6 种——站/坐/走/跑/蹲/躺（关节组预设旋转值，渲染期套用；数据只存姿势枚举）。

**变换与视角**：

- 选中元素出 TransformControls：移动 V / 旋转 R / 缩放 S，Shift 等比缩放；拖 gizmo 时禁用 OrbitControls（两控制器抢事件是已知坑）。
- 导演视角=OrbitControls 自由环视（含地面网格 GridHelper + 柔和天光/环境光，无阴影或仅地面假阴影贴片）。

**相机系统**（右栏机位面板）：

- 机位列表（上限 16）：每机位 `{id, name≤20, position, target, fov 15..90, aspect 枚举}`；画幅枚举 16:9 / 9:16 / 1:1 / 4:3 / 2.39:1。
- 「从当前视角新增机位」：把导演视角相机位姿一键落为新机位。
- 主视口双模式切换：**导演视角 ↔ 机位视角**（切到某机位=主视口由该相机渲染，所见即截图所得）；导演视角下所有机位以**线框视锥体**可视化（可点选）。
- **遮幅框（letterbox）**：机位视角下主视口按该机位 aspect 显示取景框（框外压暗），截图只取框内——保证全屏视口形状≠画幅时所见即所得。
- 机位增/删/改名/调参（面板数值输入 + 导演视角下直接拖动机位 gizmo）。

**编辑器内撤销**：Ctrl+Z / Ctrl+Shift+Z，快照式栈（深拷贝 scene JSON，≤50 步）——纯前端，与画布整体撤回待办互不干涉。

**WebGL 不可用**：初始化失败（无 WebGL 上下文）→ modal 内明确提示「浏览器不支持 WebGL」，画布其余功能不受影响。

### 4.3 截图回流画布

- 机位视角下「截图」按钮：按该机位 aspect 离屏渲染，**长边上限 2048px**，`toBlob`（格式见待拍板②）。
- 上传走既有 `POST /api/canvas/{id}/upload`（FileSecurityPolicy 咽喉）→ 得 fileId → 自动建 ImageNode（落在导演台节点右侧偏移处）+ 连边 director→image；`data.coverFileId` 同步刷新。
- 截图后节点即可被既有链路复用：@引用、作生图/生视频参考、存资产库（全现成，零新开发）。

### 4.4 场景数据模型（`node.data.directorScene`）

```
{ version: 1
, elements: [ { id, kind: "figure|box|cylinder|plate|table|chair|crowd"
    , name, color, hidden
    , transform: { position:[x,y,z], rotation:[rx,ry,rz], scale:[sx,sy,sz] }  // 数值 clamp ±1000 / 比例 0.1..20
    , figure?: { bodyType: 8 枚举, pose: 6 枚举 }
    , crowd?:  { rows: 1..12, cols: 1..12, spacing: 0.5..10 } } ]
, cameras: [ { id, name, position:[x,y,z], target:[x,y,z], fov: 15..90, aspect: 枚举 } ]
, ground: { grid: true, backgroundColor: HEX } }
```

- 解析侧（打开节点时）**白名单 schema 校验**：未知字段丢弃、枚举不识别回退默认、数值越界 clamp、数组超限截断——损坏/手改数据不崩编辑器。
- 序列化预算：200 元素 ×约 150B ≈ 30KB ≪ snapshot 承载量；前端存前自检超 256KB 拒存并提示（防御性，正常到不了）。

│   ├── sceneModel.ts                               # ★纯数据层：schema 校验/clamp/序列化/undo 栈（无 three 依赖，可单测）

## 6. 性能与资源占用（用户重点）

**服务器侧（部署后）——零新增计算，磁盘受控**：

| 项 | 影响 | 措施 |
|---|---|---|
| CPU/内存 | **0**（无新端点、无渲染、无新后台任务；snapshot 保存与图片上传均为既有链路） | — |
| 磁盘 | 仅截图文件（每张约 0.5~3MB，落 stored_files 现有目录与清理策略） | 长边 2048 上限；格式待拍板②（webp/jpeg 可再降 5~10 倍） |
| snapshot 体积 | directorScene ≤30KB（200 元素满配） | 元素/机位/阵列全设上限；前端 256KB 拒存自检 |
| 带宽 | three chunk 一次性 gz ≈150~180KB（CDN/浏览器缓存后 0） | 动态 import 不进主包 |

**浏览器侧性能目标**：

| 指标 | 目标 |
|---|---|
| chunk 加载后 modal 打开到可交互 | < 1.5s（chunk 缓存命中 < 300ms） |
| 100 元素 + 4 机位场景交互帧率 | ≥ 60fps（中端独显/核显；全图元+InstancedMesh 阵列，无纹理无阴影） |
| 渲染循环 | 仅交互时 rAF 连续渲染，静止 2s 后降频/暂停（按需渲染） |
| `renderer.setPixelRatio` | min(devicePixelRatio, 2) 封顶 |
| 关闭 modal | **全量 dispose**（renderer/geometry/material/controls 逐一释放 + canvas 元素移除），GPU 内存归零 |
| 反复开关 3 次内存增量 | < 10MB（Chrome DevTools 验证，防泄漏回归口径） |

## 7. 安全与权限（用户重点）

| 面 | 措施 |
|---|---|
| 端点 | **零新增**——保存=PUT `/api/canvas/{id}`，截图=POST `/api/canvas/{id}/upload`，全部既有 `canvas:write` + service 层 ownership（userId 硬过滤）咽喉，无越权新缝 |
| 上传 | 截图过 storage `store` 咽喉 `FileSecurityPolicy` 正列举白名单（png/webp/jpeg 按待拍板②），multipart 既有 60MB 限内 |
| 数据注入 | directorScene 纯数据：解析白名单 schema（§4.4）拒未知字段/clamp 数值——three 侧无 eval/innerHTML 面；文本（名称）经 Vue 转义，**禁 v-html** |
| 恶意大 payload | 元素 200/机位 16/阵列 12×12/名称 30 字/序列化 256KB 全上限；snapshot 本体的总长 guard 属画布既有面，不借本功能扩后端（列入可选加固，见 §9） |
| 解析器攻击面 | **不装 GLB/模型解析器**（P1 无本地上传模型），无第三方 3D 资产 |
| 限流 | 复用全局面（600/min/IP + admin 豁免），不新增 @RateLimit 注解（与画布现状一致） |
| 审计 | 复用画布保存/上传既有链路，不新增敏感写；three 依赖上线前过供应链门禁（gitleaks/依赖审计，同 S5 口径） |

## 9. 边界与不做（后续档）

- **P2**：立牌 billboard（上传角色/道具图入场景，走既有文件链路+数量上限）、机位批量一键出整组分镜组、元素打组/拖拽排序、小窗常驻机位预览。
- **P3**：720° 全景背景（普通场景图 AI 转 equirect→球体环境，复用生图管线+手动上传兜底）、阴影/光照预设。
- 不做：GLB/任意模型上传（解析器面+体积）、多人协同编辑 3D、骨骼级自由调姿、服务端渲染截图、独立导演台页面（只在画布节点内）。
- 可选后端加固（非本功能必须）：canvases.snapshot 总长 guard（如 ≤4MB）防恶意超大 PUT——属画布既有面，若做单独立项。

## 11. 术语表

| 术语 | 大白话 | 简单案例 |
|---|---|---|
| 素模 | 没穿衣服细节的简易人形占位模型，只管比例站位 | 木头小人偶摆姿势 |
| 机位 | 虚拟相机摆的位置和朝向，一台机位出一种构图 | 左侧拍会议桌、右侧拍门口 |
| FOV | 视野角度，越大拍得越广 | 手机广角 0.5x vs 长焦 |
| 视锥 | 相机能拍到的锥形范围，导演视角里画成线框 | 舞台上的聚光灯照射范围 |
| gizmo | 选中物体后出现的三色操作轴（移动/旋转/缩放） | 拖红箭头只往 X 方向动 |
| InstancedMesh | 同一个模型复制 N 份只占一份开销的渲染法 | 群演 100 人一个.draw call |
| dispose | 用完手动释放 GPU 资源，防内存泄漏 | 退房前把钥匙还了 |
| billboard 立牌 | 一张图片始终面对镜头立在场景里 | 剧组用的立牌人形板 |
| equirectangular | 把 360° 全景拉成一张 2:1 长图的方式 | 世界地图摊平成矩形 |

# File Keeper v0.1.0 性能测试报告

**测试日期**: 2026-05-17  
**测试环境**: Windows 11 Pro 10.0.22631  
**测试版本**: v0.1.0 (Phase 5 优化后)

---

## 测试目标

验证 Phase 5 性能优化的效果，确保应用在大量文件场景下的流畅性。

**性能指标**:
- 启动时间 < 500ms
- 1000 文件滚动帧率 ≥ 55fps
- 搜索响应时间 < 100ms
- 内存占用 < 100MB

---

## 测试方法

### 1. 启动时间测试

**测试步骤**:
1. 准备测试数据：创建包含不同数量文件的测试数据集
2. 清空应用缓存，冷启动应用
3. 记录从启动到界面完全渲染的时间
4. 重复测试 5 次取平均值

**测量方式**:
- 使用 `performance.now()` 在 App.vue 的 `onMounted` 中记录时间
- 启动时间 = 界面渲染完成时间 - 应用启动时间

### 2. 滚动性能测试

**测试步骤**:
1. 加载 1000 个文件到应用
2. 在网格视图和列表视图中快速滚动
3. 使用浏览器 DevTools Performance 面板记录帧率
4. 测试持续滚动 10 秒

**测量方式**:
- Chrome DevTools > Performance > Record
- 观察 FPS 指标，计算平均帧率和最低帧率

### 3. 搜索响应时间测试

**测试步骤**:
1. 加载 1000 个文件
2. 在搜索框输入关键词
3. 记录从输入到结果显示的时间（包含 300ms 防抖）
4. 测试不同匹配数量的搜索（1 个、10 个、100 个结果）

**测量方式**:
- 使用 `performance.mark()` 和 `performance.measure()`
- 响应时间 = 结果渲染完成时间 - 输入时间

### 4. 内存占用测试

**测试步骤**:
1. 启动应用（空数据）
2. 逐步添加文件：100、500、1000 个
3. 在每个阶段记录内存占用
4. 执行滚动、搜索等操作后再次记录

**测量方式**:
- Chrome DevTools > Memory > Take heap snapshot
- 观察 JS Heap Size 和 Total Memory

## 测试数据生成

使用以下脚本生成测试数据：

```javascript
// 在浏览器控制台运行
async function generateTestFiles(count) {
  const fileStore = useFileStore();
  const types = ['file', 'folder', 'image', 'code'];
  const extensions = ['.txt', '.pdf', '.jpg', '.js', '.md', '.docx'];
  
  for (let i = 0; i < count; i++) {
    await fileStore.addFile({
      name: `测试文件_${i}${extensions[i % extensions.length]}`,
      path: `C:\\TestFiles\\file_${i}${extensions[i % extensions.length]}`,
      type: types[i % types.length],
      groupId: 'default',
      tags: [`tag${i % 5}`, `category${i % 3}`]
    });
  }
  console.log(`Generated ${count} test files`);
}

// 生成 1000 个测试文件
generateTestFiles(1000);
```

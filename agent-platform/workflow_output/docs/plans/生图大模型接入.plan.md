# Implementation Plan for 即梦 Seedream 生图模块（5.0 lite + pro）

> Phase 2 产出。Phase 3 逐步勾选执行。只含伪代码，不含真代码。
> 来源：[../0_推进计划/5_生图大模型接入.md](../../0_推进计划/5_生图大模型接入.md)（两个 curl 示例）。
> 关联：[积分计费系统.feature-map.md](../feature-map/积分计费系统.feature-map.md)（按张计费 IMAGE 分支）、[项目资产库.feature-map.md](../feature-map/项目资产库.feature-map.md)（一键入库 + 参考图选取）、[SeedDance视频生成.plan.md](SeedDance视频生成.plan.md)（**镜像模板**：复用 media_gen_tasks/worker/provider/计费/存储骨架）。
> 文档规模：≤5000 tokens。

## 背景与目标

接入火山方舟（经 ctaigw 网关）两个即梦生图模型，构建**独立图片生成模块**（全栈）：后端 provider + 复用异步任务骨架 + 按张计费 + 资产库双向打通 + 前端动态参数表单页。

- **模型**：
  - **lite** `Doubao-Seedream-5.0-lite` — 参数丰富（≤14 参考图、组图 sequential、联网搜索、流式、输出格式、提示词优化模式）。
  - **pro** `doubao-seedream-5.0-pro-0724`（官方 Ark ID `doubao-seedream-5-0-pro-260628`）— 精准设计/编辑模型，参数集**与 lite 不同**（≤10 参考图、无组图、无联网、1K/2K+宽高比、支持 guidance_scale、独有交互编辑）。
- **硬约束**（用户）：① 按生成图片**张数**计费；② 生成图**一键入资产库**；③ 参考图**从资产库选取**；④ **所有参数与官网一致**（含附件图数量）；⑤ **选不同模型→页面按该模型实际支持参数决定展示内容**；⑥ **固定枚举值用下拉框**体现。
- **成功指标**：选 lite→出 14 参考图上限/组图/联网/流式等专属控件；选 pro→出宽高比/guidance_scale 等专属控件、无组图/联网；提交→异步出图（多张）→按张扣费→网格展示→下载/一键入库；零主链路回归。

> **设计核心 = 数据驱动的「按模型参数清单」**：每个模型的「支持哪些参数、各参数枚举/范围」以 manifest 落在 provider `config.capabilities`（如 SeedDance V64 模式），前端读 manifest 动态渲染表单。这使得 UI 永远跟随真实模型参数，且新模型零代码（仅改配置）——完美满足硬约束 ⑤⑥。

## 技术实现坑点预判与规避措施

| 坑 | 规避 | 验证 |
|---|---|---|
| 图片 API **同步**（返 data[].url），但视频 worker 是「异步轮询」语义 | provider 同步塑形：`createTask` 内完成 HTTP 调用并缓存响应，`queryTask` 首查即返 SUCCEEDED+imageUrls（worker 仅循环一次）；不改 worker 控制流，仅 handleSucceeded 加 IMAGE 分支 | mock provider create→query→SUCCEEDED 单次收敛 |
| 单任务返 **N 张图**（1~15），视频只 1 个 url | 加 `result_meta JSONB` 存 `{imageFileIds[],generatedImages,outputTokens}`；handleSucceeded 的 IMAGE 分支循环下载 N 张、每张 downloadAndStore、collect fileIds | 3 图任务断言 result_meta.imageFileIds.length=3 |
| 按张计费：imageCount 须取 `usage.generated_images`（非 data[].length）| worker 解析 usage.generated_images 传 `chargeMedia(...,KIND_IMAGE,null,null,imageCount,...)`；data 长度仅作 fallback | usage.generated_images=2 但 data 因部分 error 只 1 → 扣 2 张（官方按生成张计）|
| Ark 返的 url **24h 过期**（OSS 临时链接）| SUCCEEDED 后 worker 立即逐张 downloadAndStore 落本地 stored_files，只存 fileId；URL 不长期依赖（同视频）| 任务完成后断网断言本地图可显 |
| 参考图体积打爆网关/超时 | 复用 MediaStorageService.readAsDataUri 分类型限大小（图≤8MB，与视频一致）；服务端校验张数≤refImageMax、MIME、总像素 | 超 14 张(lite)/10 张(pro)→400 |
| pro model id 双名（ctaigw 别名 vs 官方 Ark id）| ctaigw 网关用 curl 别名 `doubao-seedream-5.0-pro-0724`（实测可用）；直连 Ark 用官方 `doubao-seedream-5-0-260128`。manifest 配置可切不改码。参数表已权威（用户提供）| P3 提交时断言网关返 200+图 |
| 同步生图阻塞 worker 线程（4K 可 60s+）| 复用 mediaTaskExecutor（core2/max4/queue100），单任务设 HTTP response 超时 90s；4K 走异步任务不阻塞 HTTP 请求 | 4K 任务不拖垮池，其他任务不饿死 |
| 组图 sequential 模式：ref+gen≤15，服务端须约束 | 提交时校验 `refCount + maxImages ≤ 15`（lite）；max_images∈[1,15] | 14 ref + max_images=5 → 400 |

## 安全检查清单

- [ ] **鉴权**：端点 `@RequirePermission("media:gen")`（复用既有权限，gated 策略同视频，admin 默认有，user 按需授）；任务/下载 ownership 过滤（`WHERE user_id=current`）。
- [ ] **输入校验**：prompt 长度上限；size 枚举白名单（preset 或 WxH 范围）；output_format/watermark 枚举；参考图张数≤manifest.refImageMax、MIME 白名单、单张≤8MB、总像素上限；sequential max_images∈[1,15]、ref+gen≤15（lite）；按模型 manifest 校验「该模型不支持的参数一律拒」（防绕过前端塞 pro 不支持的 sequential）。
- [ ] **数据最小化**：不长期存 Ark 临时 url（仅 fileId）；错误话术固定，不透传 e.getMessage()。
- [ ] **密钥安全**：ctaigw key 复用 AES 加密存储（llm_providers.apiKeyEnc），不明文落日志；请求日志脱敏。
- [ ] **资产写入授权**：media→asset 桥必过 `AssetAclService.requireWrite(projectId)`（viewer 不可入库，同 SaveToAssetDialog）。
- [ ] **下载**：图片下载端点 Content-Disposition: attachment，防 inline。
- [ ] **依赖安全**：无新依赖（WebClient 已有）。

## 性能考虑与验证计划

- [ ] 复用 mediaTaskExecutor（core2/max4/queue100），不挤 chat/RAG/memory 池；同步生图在 worker 线程内阻塞，response 超时 90s。
- [ ] N 张图顺序下载落盘（流式，不全 load 内存）；result_meta JSONB 避免 N 列。
- [ ] media_gen_tasks 索引复用 V54（user_id,status,ark_task_id）。
- [ ] 模型/manifest 聚合无 N+1：listModels 一次查 IMAGE+VIDEO provider 内存组装。

## 功能联动点清单

- [ ] **模型切换 ↔ 表单重渲染**：选 lite/pro → 按各自 manifest 重新渲染控件；**边界**：切模型清空已传参考图（避免超新模型上限）、重置 size/sequential 到新模型默认、pro 隐藏 sequential/web_search/stream 控件、lite 隐藏 aspect_ratio/guidance_scale。
- [ ] **sequential=auto ↔ max_images 显隐 + 上限联动**：仅 lite 显示；auto→显 max_images 输入([1,15])且「参考图数+max_images≤15」实时校验；**边界**：disabled→隐 max_images、清零；参考图增到使 ref+max>15→max_images 上限自动收紧/红字提示。
- [ ] **size 模式互斥 ↔ 控件切换**：preset 下拉(`sizePresets`：lite=[2K,3K,4K]/pro=[2K,3K]) vs 自定义 WxH 输入二选一（**lite+pro 均支持 WxH**，无独立 aspect_ratio 参数）；**边界**：选 preset 清 WxH、选 WxH 清 preset；切模型 preset 候选集变（pro 无 4K→原 4K 选中回退默认）。
- [ ] **任务 SUCCEEDED ↔ 多图下载落地 + 网格渲染**：worker 逐张下载存 fileId→result_meta；前端轮询 SUCCEEDED→读 images[]→网格渲染+每张下载/入库；**边界**：部分 data[].error→该张标失败占位、其余正常、计费按 generated_images。
- [ ] **一键入资产库 ↔ 三态重复**：首次→显 duplicate→选 NEW_VERSION(并入既有资产新版本)/NEW_ASSET(新建)；**边界**：未选项目禁用提交、viewer 项目不出现列表、入库成功后按钮转「已入库」防重复点。
- [ ] **参考图从资产库选取 ↔ 附件槽**：AssetPicker 选图→ResolveVO.fileId→转附件（占一个 refImage 槽，计数+1）；**边界**：超 refImageMax 禁选、重复选同图去重、取消选回退槽位。
- [ ] **余额不足 ↔ 提交拦截**：requireAffordable（balance>0）预检失败→不建任务行、前端提示；**边界**：后扣实际（生成完按张扣，允许瞬时欠款，下次拦）。

  - **需人工介入**：admin 填 ctaigw IMAGE provider apiKey；admin 配 pricing_rule（两模型 price_per_image）。

### Chunk B：provider + 按模型 manifest

- [ ] **Step B：ArkImageProvider + ImageModelCapability 注册**
  - **对应需求**：IM-1、IM-2
  - **动作**：① `ArkImageProvider implements MediaGenProvider`：WebClient POST `{endpoint}`（body 按 manifest 按模型裁剪：model,prompt,image[](参考图 dataURI 数组),size,sequential_image_generation(+options.max_images 仅 lite),tools[{type:web_search} 仅 lite),output_format,response_format=url,watermark,optimize_prompt_options.mode,live stream=false）；解析 `data[].url` + `usage.generated_images`/`output_tokens`；**同步塑形**——createTask 完成调用缓存响应，返 providerTaskId（媒体任务 id 哨兵），`queryTask` 首查即返 SUCCEEDED+imageUrls+usage。WebClient 复用 buildClient + AES key（`llmProviderService.getDecryptedApiKey`），response 超时 90s。② `MediaModelCapabilityService` 加 IMAGE 分支 `defaultsFor(model)`：内置 lite/pro 默认 manifest；与 provider `config.capabilities` JSON 精确合并覆盖（如 seedance V64 模式）。③ DTO：`ImageModelCapability`（manifest 形状）、`MediaImageResult`(imageUrls[],generatedImages,outputTokens)。

  - **验证**：单测 mock WebClient——lite 14 参考图+组图请求体、pro 10 参考图无组图请求体、create→query 即 SUCCEEDED；manifest merge 覆盖正确。

## 术语表

| 术语 | 大白话 | 案例 |
|---|---|---|
| 同步塑形 provider | 图片 API 同步返结果，但套进「建任务→查任务」异步壳，让 worker 不改控制流 | createTask 内调完 API，queryTask 立即返 SUCCEEDED |
| manifest（参数清单）| 每个模型「支持哪些参数、枚举值」的配置表，驱动 UI | lite manifest 有 sequential、pro 没有→前端按此显隐 |
| result_meta | IMAGE 任务存 N 张图 fileId 的 JSONB 列 | 3 图任务存 imageFileIds:[1,2,3] |
| usage.generated_images | 官方返的「实际生成张数」，计费基础 | 组图模式生成 5 张→扣 5 张费 |
| media→asset 桥 | 把生成图（非画布节点）直接入资产库的通道 | 图片页点「一键入库」→新图片资产 |

## 关键设计决策

- **两 Tab 按 ProjectVO.role 拆**（设计 §九 9.2）：`role==='OWNER'` → 我的项目；`role!=='OWNER'`（EDITOR/VIEWER）→ 共享给我。后端 `projectApi.list()` 一次返 owner+member 各带 role，前端纯客户端拆分，不发两次请求。
- **新建项目 narrativeRoles 走后端默认**：表单只收 name+description；五桶默认（人物/道具/场景/风格/通用）由后端 S2 落地（设计 §九 198），前端不重复硬编，单一事实源在后端。空 description trim 后送 `undefined`（避免传空串）。
- **封面 MVP 用首字母色块**：coverFileId 上传通道留到 S11 项目详情页（与资产上传共线），S9 不引封面上传，避免 fetchCanvasPreview blob 的 revoke 生命周期复杂度提前进来。
- **ShareDialog 逐操作即时调 API，非批量保存**（设计 §七 成员操作为离散 owner 操作）：invite/changeRole/remove/transfer 各自调端点 + reloadMembers，区别于 AgentPermissionModal 的批量 save。语义贴合后端端点（memberApi 无 batch save）。
- **MemberVO 无 username → adminApi.listUsers 建映射联显**：MemberVO 仅 userId/role/isOwner；ShareDialog 拉 `listUsers(1,200)` 建 userId→username Map（同 AgentPermissionModal/KbPermissionModal 范式；无用户模糊搜索接口，客户端 filterable 过滤）。
- **转让触发父列表重载**（@changed）：转让后旧 owner 降 editor，项目可能从「我的」迁「共享给我」；ShareDialog emit `changed` → AssetListView.loadData 重拉 list。移除/改角色同样 emit changed（角色态可能影响 owner 视角的卡片操作按钮）。
- **稳定单例 mock（测试）**：naive-ui useDialog mock 须返稳定对象（非工厂新实例），否则组件 setup 捕获的 dialog 与测试断言非同一实例，`warning.mock.calls` 取不到。defineExpose 暴露的 ref 在 VTU `wrapper.vm` 上自动解包，可直接赋值。

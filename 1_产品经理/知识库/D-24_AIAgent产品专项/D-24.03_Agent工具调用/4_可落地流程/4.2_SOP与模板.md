# 4.2 SOP 与模板

## 一、4套SOP

### SOP 1：Function Calling 落地四步法

**适用场景**：Agent需标准化工具调用接口，从自研工具调用迁移到Function Calling标准。

| 步骤 | 动作 | 产出 | 检查点 |
|---|---|---|---|
| **1. 工具盘点与分类** | 盘点Agent需要的全部工具，按Function Calling/Computer Use/Sandbox分类 | 工具列表总表 | 每个工具有明确调用范式 |
| **2. Schema设计与校验** | 为每个工具设计JSON Schema（name/description/parameters/strict），用工具Schema设计表模板 | 每个工具的JSON Schema | Schema通过JSON Schema Validator校验 |
| **3. 参数幻觉防护** | 设计5层防线（Schema层+校验层+反馈层+重试层+监控层），用参数校验清单模板 | 参数幻觉防护矩阵 | 每个工具有5层防线配置 |
| **4. 端到端测试与上线** | 建黄金测试集（每个工具≥10用例），跑回归测试，监控参数错误率 | 黄金测试集+监控看板 | 参数准确率>95%、调用成功率>90% |

**避坑清单**：
- ⚠️ Schema描述别太模糊也别太详细（1-2句话+关键词前置+示例）
- ⚠️ strict mode开启后模型输出100%匹配Schema，但会降低灵活性——只对关键工具开
- ⚠️ 工具结果格式必须统一JSON（不一致是死循环31%的根因）
- ⚠️ 参数错误重试限3次（超限升级人工）

### SOP 2：Computer Use 集成流程

**适用场景**：Agent需操控无API的桌面软件或Web应用。

| 步骤 | 动作 | 产出 | 检查点 |
|---|---|---|---|
| **1. 必要性评估** | 确认目标软件确实无API（查文档/联系厂商/搜索MCP生态），确认必须用GUI操控 | 必要性评估报告 | 已穷尽API方案后确认必须GUI |
| **2. 执行环境设计** | 选择Computer Use执行环境：独立浏览器实例（不携带用户Cookie）/Daytona专属机器/沙箱内浏览器 | 执行环境配置 | Computer Use不操控用户主机 |
| **3. 操作流设计** | 将任务拆解为GUI操作步骤（截屏→识别→点击/输入→验证→下一步），设计状态机 | 操作流状态机图 | 每步有验证+异常检测+回退路径 |
| **4. 安全护栏设计** | 为不可逆GUI操作（点击"删除"/"提交"/"发送"按钮）设计人工确认Hook；截屏数据脱敏+不持久化 | 安全护栏配置 | 所有不可逆操作有Hook拦截 |
| **5. 人机协同设计** | 设计Computer Use的人机协同接口——Agent执行到关键步骤时截图请用户确认 | 人机协同流程 | 用户可随时介入/接管/停止 |

**避坑清单**：
- ⚠️ Computer Use是最后手段——有API绝不GUI操控
- ⚠️ 截屏识别有误差——多截屏校验+元素定位辅助+错误重试
- ⚠️ 不操控用户主机——用Daytona专属机器或独立浏览器实例
- ⚠️ 截屏含敏感信息——脱敏处理+不持久化存储

### SOP 3：Cloud Sandbox 选型流程

**适用场景**：Agent需执行代码/命令/文件操作，需选择沙箱方案。

| 步骤 | 动作 | 产出 | 检查点 |
|---|---|---|---|
| **1. 风险评估** | 评估Agent执行代码的风险等级（低=可信代码/中=半可信/高=用户生成不可信代码） | 风险评估报告 | 风险等级明确 |
| **2. 隔离级别选型** | 低风险→进程级/容器级；高风险→硬件级（E2B）；参考沙箱选型决策表模板 | 沙箱选型决策 | 隔离级别匹配风险等级 |
| **3. 产品选型** | E2B（硬件级标杆）/腾讯云Cube Sandbox（开源+五大突破）/Daytona（专属机器模式）三选一 | 产品选型报告 | 产品特性匹配需求 |
| **4. 副作用治理** | 沙箱内不可逆操作（删沙箱内文件/网络请求）也需护栏——沙箱不是安全万能药 | 副作用治理方案 | 沙箱内操作有Hook护栏 |
| **5. 紧急制动设计** | 设计硬停止按钮（直接终止沙箱进程，非通过对话请求停止）| 紧急制动方案 | 有硬停止机制 |

**避坑清单**：
- ⚠️ 沙箱只防代码逃逸，不防参数幻觉/副作用失控/权限滥用
- ⚠️ OpenClaw事件教训——无沙箱=灾难，无紧急制动=无法停止
- ⚠️ Daytona模式（给Agent专属机器）比"在用户机器上隔离"更安全

### SOP 4：副作用治理 Hook 设计流程

**适用场景**：Agent工具调用涉及不可逆操作，需设计Hook护栏。

| 步骤 | 动作 | 产出 | 检查点 |
|---|---|---|---|
| **1. 副作用分类** | 为每个工具标注可逆性（无副作用/可逆/不可逆）+风险等级（低/中/高）+护栏等级（无/日志/人工确认），用副作用风险矩阵模板 | 副作用风险矩阵 | 所有工具有分类标注 |
| **2. Hook节点设计** | 确定Hook插入节点：工具调用前（参数校验+权限检查）/工具调用后（结果校验+日志记录）/不可逆操作前（人工确认） | Hook节点清单 | 不可逆操作有调用前Hook |
| **3. DECO三层防护** | 设计偷懒检测Hook（输出完整性检测）+越权拦截Hook（不可逆操作拦截）+失忆补偿Hook（关键操作后注入检查），用Hook护栏清单模板 | DECO三层防护配置 | 三层Hook全覆盖 |
| **4. ADG组合风险分析** | 画工具依赖图谱，分析工具串联后的涌现风险（搜索+邮件+记忆串联→自动群发） | ADG依赖图谱 | 组合风险已识别+有防护 |
| **5. 紧急制动与回滚** | 设计硬停止按钮（终止Agent进程）+可逆操作回滚机制（如草稿可删/测试邮件可撤回） | 紧急制动+回滚方案 | 有硬停止+可逆操作可回滚 |

**避坑清单**：
- ⚠️ "prompt管不住的，框架来堵"——不能依赖prompt约束不可逆操作
- ⚠️ 单工具安全≠组合安全——ADG组合风险必须分析
- ⚠️ 人工确认Hook别太频繁（否则Agent效率极低）——只拦不可逆操作

### 模板5：工具发现注册流程

```
步骤1：MCP Server发现
├─ 查MCP注册中心（按关键词/领域搜索）
├─ 评估Server质量（Star数/维护活跃度/下载量）
└─ 列出候选Server清单

步骤2：安全校验三步走
├─ 来源校验：Server发布方是否可信？（官方/社区/个人）
├─ 权限审查：Server需要哪些权限？（文件/网络/系统命令）
└─ 沙箱测试：在沙箱中测试Server工具调用（不接生产环境）

步骤3：动态注册
├─ 注册到Agent工具表（标注来源/权限/测试状态）
├─ 分域加载（按任务域/权限域/使用频率动态加载子集）
└─ 配置超时/重试/降级策略

步骤4：运行时监控
├─ 工具调用成功率监控
├─ 工具响应延迟监控
├─ 异常调用模式检测（如某工具突然高频调用）
└─ 定期重新评估（Server下线/变更/安全漏洞）

步骤5：下线与替换
├─ 发现Server变更/下线/安全漏洞时及时移除
├─ 替换为同功能替代Server
└─ 通知依赖该工具的Agent流程
```

### 模板6：Hook护栏清单（DECO三层防护）

| Hook层 | 防什么 | 插入节点 | 检测逻辑 | 触发动作 | 适用工具 |
|---|---|---|---|---|---|
| **偷懒检测** | LLM输出截断/略写/残缺 | 工具调用后（结果返回前） | 检测输出完整性（长度/结构/必填字段） | 不完整→重试或告警 | 所有输出长文本的工具 |
| **越权拦截** | 不可逆操作未确认执行 | 不可逆操作工具调用前 | 检查操作类型（不可逆=拦截） | 拦截→人工确认→确认后执行 | delete_*/transfer_*/send_*/publish_* |
| **失忆补偿** | 关键操作后遗漏风险检查 | 关键操作工具调用后 | 强制注入风险检查步骤 | 注入"请检查X风险"→继续执行 | 改表/发布/转账等操作后 |

**Hook配置示例（伪代码）**：
```python
# 越权拦截Hook — 工具调用前
def pre_call_hook(tool_name, params):
    if tool_name in IRREVERSIBLE_TOOLS:  # 不可逆操作清单
        if not params.get("_human_confirmed"):
            return {
                "action": "block",
                "message": f"操作{tool_name}不可逆，需人工确认",
                "require_confirmation": True
            }
    return {"action": "pass"}

# 偷懒检测Hook — 工具调用后
def post_call_hook(tool_name, result):
    if len(result) < MIN_OUTPUT_LENGTH.get(tool_name, 10):
        return {"action": "retry", "reason": "输出疑似截断"}
    if not check_required_fields(tool_name, result):
        return {"action": "retry", "reason": "输出缺失必填字段"}
    return {"action": "pass"}

# 失忆补偿Hook — 关键操作后
def after_critical_op_hook(tool_name, result):
    if tool_name in CRITICAL_OPS:  # 关键操作清单
        inject_risk_check(tool_name)  # 注入风险检查步骤
        # 偷懒检测+越权拦截+失忆补偿=DECO三层防护
```

# 开发进度4 · 计费全量覆盖 + 网关自动归户（未来模块免改计费）

承接 [开发进度3](开发进度3.md)。用户痛点：**每加一个调模型的模块都要重接计费，易漏**；且审计发现 12 处盲区（过咽喉但丢 userId→只采不扣，或绕咽喉双漏）。

## 目标

1. 补齐 12 处盲区全部计费；
2. 让 `LlmGateway` 成为「userId 自动归户」封装边界——**以后新模块只要调 `gateway.chat(req)` 就自动采 token+扣费，无需再写计费代码、无需手传 userId**。

## 架构决策

用户选 **C 网关自动归户**（计费逻辑留 gateway 不动，加 `BillingContext` ThreadLocal 自动种 userId，gateway 出口「uid 空→读 Context」兜底），否决 A（provider 装饰器深改，热路径搬计费、双扣风险、流式 side-channel 难处理）。
admin「测试连通」选 **扣 admin 钱包**（直调 provider 测特定实例，gateway 按 model 路由会测错；调完手动 `onSuccess`）。
媒体（SeedDance）走独立 `MediaGenProvider`+worker 扣费（任务模型），本次不动。

## 层 1 · 自动归户基础设施（未来免改核心）

- [BillingContext](../../../backend/src/main/java/com/superprogrammer/billing/context/BillingContext.java)：`ThreadLocal<Long>` set/get/current/clear。
- [BillingContextFilter](../../../backend/src/main/java/com/superprogrammer/billing/context/BillingContextFilter.java)（OncePerRequestFilter，SecurityConfig `addFilterAfter(JwtAuthFilter)`）：请求入口从 `(Long)auth.getPrincipal()` 种入；匿名/非 Long principal→null（仅采不扣）；finally clear 防串号。
- [BillingContextTaskDecorator](../../../backend/src/main/java/com/superprogrammer/billing/context/BillingContextTaskDecorator.java)：捕获提交线程 current()，子线程 set→跑→finally clear。接 **4 池**：Knowledge/Media/Memory/ReconciliationTaskExecutorConfig 各 `setTaskDecorator`。
- **2 处裸 `new Thread()`**（[ChatController.doStream](../../../backend/src/main/java/com/superprogrammer/chat/controller/ChatController.java):132/173、[KnowledgeAskController.ask](../../../backend/src/main/java/com/superprogrammer/knowledge/controller/KnowledgeAskController.java):60/86）已有 `SecurityContextHolder.set/clearContext` 范式，同处加 `BillingContext.set/clear`。
- [LlmGateway](../../../backend/src/main/java/com/superprogrammer/llm/LlmGateway.java) **6 出口**首行 `resolveBillingUser(userId, model)`：显式 uid 优先→空回退 `BillingContext.current()`→再空 warn 返 null（仅采不扣）。流式 uid 在调用线程闭包捕获，`publishOn(boundedElastic)` 切线程不丢；side-channel 结构零改动。

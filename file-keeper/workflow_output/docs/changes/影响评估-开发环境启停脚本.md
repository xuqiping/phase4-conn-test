# 影响评估：开发环境启停脚本

> 日期：2026-08-30
>
> 回滚锚点：`b52538d8`

## 变更范围

- 新增项目根目录启动、关闭、重启 PowerShell 脚本。
- 同步运行指南和 Git 忽略规则。
- 管理对象仅为 Memurai/Redis、PostgreSQL、Java 后端和 Tauri 桌面端。
- 管理后台不纳入脚本，每次执行结束都显式提醒。

## 联动与风险

- 启动顺序固定为 Redis → PostgreSQL → 后端 → Tauri，依赖未就绪时不继续。
- 关闭顺序反向执行。
- 端口已监听时视为组件已运行，不重复启动。
- 后端和 Tauri 的关闭依赖启动脚本记录的 PID，避免误杀其他 Java、Node 或 PowerShell 程序。
- PostgreSQL 和 Redis 仅操作明确识别的 Windows 服务或官方启停命令。

## 不受影响项

- 不改动业务代码、数据库结构、Tauri API 或 Office Worker 协议。
- 不改动已存在的端口和环境变量名称。

## 2026-09-03 补充：数据库密码继承修复

- **问题**：用户级 `FILE_KEEPER_DB_PASSWORD` 已配置，但已打开的旧 PowerShell 进程不会自动继承，导致后端回退到默认密码并报 PostgreSQL `28P01`。
- **影响点**：仅 `启动.ps1` 启动 Java 后端前的环境变量传递，以及对应运行文档。
- **修复**：进程级变量为空时，从 Windows 当前用户环境读取并只传给本次启动进程；不输出、不落盘密码。
- **回滚锚点**：`e13d7918`。
- **回归项**：Windows PowerShell 5.1 解析、旧窗口启动、8088/1420 端口监听、密码不进入 Git diff。
- **桌面端误判**：不能仅凭系统中存在同名 `file-keeper.exe` 判断开发版已运行；安装版与开发版可能并存，开发态以 Vite 严格端口 `1420` 为准。
- **端口兼容**：Vite 可能只监听 IPv6 回环地址 `::1`；端口探测必须同时覆盖 `127.0.0.1` 和 `::1`，否则会出现服务已启动但脚本误报超时。

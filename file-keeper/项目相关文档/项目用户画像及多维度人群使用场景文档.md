# File Keeper 项目用户画像及多维度人群使用场景文档

## 1. 文档目的

本文档用于梳理 File Keeper 的目标用户、核心需求、使用场景、痛点、触发时机和产品价值，帮助后续进行产品介绍、功能规划、文案优化和测试用例设计。

File Keeper 的用户价值来自两个方向：

1. 常用文件快速访问
2. 运行中 Windows 应用整理

因此，用户画像不能只围绕“文件管理”展开，也要覆盖桌面多任务、窗口清理、会后收尾、开发测试环境整理等真实工作流。

---

## 2. 总体用户画像

File Keeper 适合以下共同特征明显的人群：

- 经常在多个文件、文件夹和应用之间切换
- 有一批高频文件需要反复打开
- 桌面和任务栏经常堆积大量窗口
- 需要按项目、课程、客户、任务管理资料
- 不想频繁打开资源管理器和任务管理器
- 希望工具轻量、本地、低打扰
- 对复杂专业工具没有强需求，但希望提升日常效率

File Keeper 的理想用户不是只偶尔打开一两个文件的人，而是典型的 Windows 多任务用户。

## 3. 一级目标用户

## 3.1 开发者

### 用户特征

开发者通常同时使用：

- IDE / 编辑器
- 浏览器
- 终端
- API 调试工具
- 本地服务窗口
- 项目文档
- 配置文件
- 脚本文件
- 日志文件

他们的工作流高度依赖快速切换资料和工具。

### 典型痛点

1. 项目资料散落在多个目录中。
2. README、接口文档、配置文件、脚本经常要反复打开。
3. 浏览器、终端、测试窗口越开越多。
4. 切换项目时，需要手动清理一批临时窗口。
5. 任务管理器按进程显示，不一定适合按开发场景整理。

### 使用场景

#### 场景 A：项目启动

开发者开始处理一个项目时，可以在 File Keeper 中快速打开：

- 项目 README
- 接口文档
- 环境配置文件
- 启动脚本
- 测试说明
- 常用日志目录

价值：减少在项目目录中反复查找资料的时间。

#### 场景 B：开发调试中途查资料

开发过程中需要快速打开某个配置文件或接口说明时，可以通过搜索文件名、路径或标签定位。

价值：避免离开当前上下文太久。

#### 场景 C：项目收尾

开发者切换到进程管理页，按类别筛选：

- 浏览器
- 终端
- 文档工具
- API 工具

然后批量关闭不再需要的窗口。

价值：减少切换项目时桌面混乱。

### 核心价值

- 更快进入项目状态
- 更快找到高频资料
- 更快清理测试环境和临时窗口

## 3.2 学生与自学者

### 用户特征

学生和自学者常用：

- PDF 讲义
- 课程笔记
- 作业文件
- 浏览器资料
- 在线课程网页
- 视频播放器
- 会议软件
- 代码编辑器

### 典型痛点

1. 不同课程资料容易混在一起。
2. 复习时找不到之前的重点文件。
3. 学习过程中打开很多 PDF、网页和笔记窗口。
4. 课后或学习结束后需要清理大量窗口。
5. 不想使用过于复杂的专业文件管理器。

### 使用场景

#### 场景 A：按课程管理资料

用户可以创建分组：

- 数据结构
- 机器学习
- 英语
- 论文阅读
- 考研资料

每个分组下收藏讲义、作业、笔记和参考资料。

价值：课程资料集中，不再依赖临时桌面文件堆积。

#### 场景 B：复习重点资料

通过标签区分：

- 重点
- 待复习
- 作业
- 错题
- 参考

复习时直接搜索标签或文件名。

价值：资料检索更快，复习路径更清晰。

#### 场景 C：学习结束清理窗口

学习结束后，用户切换到应用管理页，关闭不用的浏览器、PDF 阅读器、会议软件和视频播放器。

价值：保持桌面清爽，减少下次学习前的整理成本。

### 核心价值

- 学习资料集中管理
- 复习资料更容易找
- 学习窗口更容易清理

## 3.3 设计师与内容创作者

### 用户特征

设计师和内容创作者常用：

- PSD / AI / Figma 文件
- 图片素材
- 参考图
- 视频或音频素材
- 交付文档
- 浏览器灵感页面
- 图片查看器
- 通讯软件

### 典型痛点

1. 素材文件散落在不同项目目录。
2. 参考图、设计稿、交付文件需要频繁打开。
3. 创作过程中图片、浏览器、通讯工具窗口很多。
4. 项目切换时需要整理旧项目相关窗口。
5. 文件管理器能管理文件，但无法顺手整理运行中的应用。

### 使用场景

#### 场景 A：项目素材入口

设计师可以按项目或客户建立分组，并收藏：

- 设计源文件
- 素材文件夹
- 参考图文件夹
- 交付清单
- 品牌规范文档

价值：打开项目资料更快。

#### 场景 B：创作过程中查找参考

通过标签区分：

- 参考
- 素材
- 交付
- 待修改
- 已确认

价值：快速定位素材和版本。

#### 场景 C：创作收尾

通过进程管理页筛选图像、媒体、通讯、浏览器类应用，关闭当前项目不再需要的软件窗口。

价值：让桌面从当前项目状态切换到下一个项目状态。

### 核心价值

- 素材和交付资料更集中
- 创作应用更容易整理
- 项目切换更干净

## 3.4 办公人员

### 用户特征

办公人员经常使用：

- Word
- Excel
- PowerPoint
- PDF
- 浏览器
- 会议软件
- 即时通讯工具
- 网盘目录
- 合同和模板文件

### 典型痛点

1. 常用模板、合同、报表经常要找。
2. 会议前后会打开大量文档和浏览器页面。
3. 会后窗口不及时清理，任务栏越来越乱。
4. 任务管理器对普通办公用户不够友好。
5. 文件夹层级太深，找文件浪费时间。

### 使用场景

#### 场景 A：常用办公文档入口

将常用文档收藏到 File Keeper：

- 周报模板
- 合同模板
- 报销表格
- 项目汇报 PPT
- 客户资料文件夹

价值：减少重复查找。

#### 场景 B：会议前快速准备

会议开始前，直接打开会议相关文档、演示稿和资料文件夹。

价值：降低准备时间和遗漏风险。

#### 场景 C：会议后清理窗口

会议结束后，在进程管理页批量关闭：

- 会议软件
- 临时浏览器窗口
- 不再需要的 PDF
- 演示文稿

价值：恢复清爽工作环境。

### 核心价值

- 高频办公文件更容易打开
- 会议资料准备更快
- 会后窗口清理更省心

## 3.5 运维、技术支持与高级 Windows 用户

### 用户特征

这类用户经常需要：

- 查看某个应用是否仍在运行
- 判断应用名称、PID、窗口标题
- 复制进程信息用于沟通
- 关闭异常或不再需要的应用
- 判断权限不足或系统限制

### 典型痛点

1. 任务管理器信息多，但对简单场景不够直观。
2. 普通用户描述问题时，很难说清楚开了哪些应用。
3. 某些应用无法关闭时，错误原因不清楚。
4. 需要快速复制进程信息用于记录。
5. 专业工具过强，但日常处理只需要轻量能力。

### 使用场景

#### 场景 A：确认应用是否运行

通过 File Keeper 查看运行中应用列表，按类别筛选目标应用。

价值：比看任务栏更完整，比专业工具更轻量。

#### 场景 B：复制进程信息

右键进程行，复制应用名称、PID、窗口标题等信息，用于工单、沟通或记录。

价值：减少手动抄写错误。

#### 场景 C：处理权限不足

关闭应用失败时，如果出现 `0x80070005` 或拒绝访问提示，File Keeper 会告诉用户目标应用可能权限更高。

价值：错误原因更容易理解。

### 核心价值

- 快速查看运行应用
- 快速复制排查信息
- 更容易理解权限错误

## 3.6 重度多任务用户

### 用户特征

这类用户可能不是某个特定职业，但有共同行为：

- 同时打开大量文件和应用
- 任务栏长期很拥挤
- 经常在多个任务之间切换
- 桌面和下载目录容易堆积文件
- 工作结束后需要整理窗口

### 典型痛点

1. 找文件和找窗口都费时间。
2. 不知道哪些窗口还需要保留。
3. 想批量关闭，但又怕误关重要应用。
4. 文件和应用管理工具分散。

### 使用场景

#### 场景 A：个人工作台

用户把常用资料加入 File Keeper，并在应用管理页整理当前打开的应用。

价值：一个工具覆盖资料入口和窗口整理。

#### 场景 B：每日收尾

每天工作结束时：

1. 查看当前运行应用
2. 按类别筛选
3. 多选不再需要的窗口
4. 批量关闭
5. 保留关键应用确认

价值：减少第二天面对混乱桌面的概率。

### 核心价值

- 降低桌面混乱
- 降低切换成本
- 提供更安全的批量整理方式

## 4. 多维度场景矩阵

| 场景维度 | 用户问题 | File Keeper 能力 | 价值 |
|---|---|---|---|
| 工作开始 | 常用资料找起来慢 | 文件收藏、分组、最近打开 | 快速进入状态 |
| 工作进行 | 临时查找资料打断思路 | 搜索、标签、排序 | 降低上下文切换 |
| 工作切换 | 上一个任务窗口未清理 | 应用类别筛选、批量关闭 | 切换更干净 |
| 会议前 | 材料准备分散 | 常用文件入口、分组 | 减少准备时间 |
| 会议后 | 会议软件和文档残留 | 进程管理、批量关闭 | 快速收尾 |
| 学习复习 | 资料和笔记混乱 | 分组、标签、搜索 | 学习资料结构化 |
| 设计创作 | 素材和参考图分散 | 文件收藏、标签 | 素材访问更快 |
| 技术排查 | 不清楚哪个应用在运行 | 进程列表、PID、窗口标题 | 信息更明确 |
| 桌面清理 | 任务栏太乱 | 类别筛选、右键关闭 | 降低整理成本 |

## 5. 用户旅程

## 5.1 新用户首次使用

1. 安装并打开 File Keeper
2. 添加几个常用文件或文件夹
3. 创建一个项目/课程/办公分组
4. 给文件添加标签
5. 尝试搜索和排序
6. 切换到进程管理页查看当前运行应用
7. 关闭一两个不需要的窗口

成功标准：用户能在 5 分钟内理解“它能帮我更快找文件，也能帮我整理窗口”。

## 5.2 高频用户日常使用

1. 打开 File Keeper
2. 通过分组进入当前任务
3. 打开常用资料
4. 工作中用搜索补充打开其他文件
5. 工作结束后进入进程管理页
6. 按类别筛选并批量关闭窗口

成功标准：File Keeper 成为用户每天开始和结束工作时会打开的工具。

## 5.3 高级用户扩展使用

1. 按项目维护多个分组
2. 使用标签表达文件状态
3. 调整文件排序
4. 自定义进程列表列显示和顺序
5. 管理重要应用白名单
6. 使用右键菜单复制进程信息或切到前台

成功标准：用户根据自己的工作习惯把 File Keeper 调成个人工作台。

## 7. 用户价值主张

### 7.1 对个人效率的价值

- 减少找文件时间
- 减少切换应用时间
- 减少桌面整理时间
- 降低重复操作成本

### 7.2 对工作流的价值

- 工作开始更快进入状态
- 工作中资料访问更顺
- 工作结束更容易收尾
- 项目切换更清爽

### 7.3 对安全感的价值

- 重要应用关闭前确认
- 权限不足时给出明确提示
- 本地保存数据，不依赖云服务
- 正常关闭优先，避免过度激进

## 9. 边界用户

File Keeper 不是所有用户都需要。以下用户可能不是当前优先目标：

1. 几乎不管理本地文件，完全依赖云文档的人。
2. 只需要全盘文件名搜索的人。
3. 需要专业系统诊断、句柄分析、内核级调试的人。
4. 已经深度依赖 Directory Opus、XYplorer 等专业文件管理器并完成高度定制的人。
5. 只使用 macOS 或 Linux，且不需要 Windows 应用管理能力的人。

这些用户不是不能使用 File Keeper，但不是当前版本最核心的目标人群。

---

## 10. 结论

File Keeper 的核心用户是 Windows 多任务用户，尤其是那些同时面对大量常用文件和大量运行中应用的人。

它最适合解决三类问题：

1. 高频文件如何更快打开
2. 工作资料如何更好组织
3. 当前打开的应用如何更快整理

从用户画像来看，File Keeper 最有价值的推广方向是：

- 开发者的项目资料和测试窗口整理
- 学生的课程资料和学习窗口管理
- 设计师的素材文件和创作应用整理
- 办公人员的文档入口和会议后清理
- 高级用户的轻量进程查看和窗口处理

File Keeper 应持续强化“一个本地工作台，统一管理常用文件和运行应用”的产品心智。

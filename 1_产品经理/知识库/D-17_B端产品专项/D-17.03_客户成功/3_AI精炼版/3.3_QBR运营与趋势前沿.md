# 3.3 QBR运营与趋势前沿

## 1. QBR（季度业务回顾）方法论

### QBR的定义与目标

**QBR = Quarterly Business Review**：每季度与客户核心团队进行的业务对齐会议。

**目标不是"汇报工作"，而是**：
1. 对齐业务成果：客户的目标达成了多少？我们的贡献是什么？
2. 发现新机会：客户下季度有什么新目标？我们能帮什么？
3. 深化关系：让客户的Champion在内部有"成果可展示"
4. 增购铺垫：自然引出"下阶段可以扩展的方向"

### QBR 5步流程

| 步骤 | 内容 | 产出 |
|---|---|---|
| 准备 | 数据回顾+成果整理+议题拟定 | QBR Deck |
| 开场 | 业务成果回顾（用客户语言） | 成果共识 |
| 深入 | 痛点/挑战/使用障碍讨论 | 行动项清单 |
| 展望 | 下季度目标+增购方向预沟通 | 增购线索 |
| 收尾 | 总结+承诺+下次时间 | Follow-up邮件 |

### QBR常见问题

- **客户不参加QBR** → 根因：QBR没有客户价值，只是你汇报 → 解法：QBR以"客户的业务成果"为核心，不是你的产品更新
- **QBR变成诉苦大会** → 根因：积累太多未解决问题 → 解法：QBR前先解决P0问题，QBR上只讨论战略
- **QBR后无行动** → 根因：只有讨论没有落地 → 解法：每次QBR产出3-5个Action Item，下次QBR检视

## 2. CS组织设计

### CSM（Customer Success Manager）角色

| 职责 | 不做什么 |
|---|---|
| 客户健康度监控 | 不做销售赢单 |
| 流失预警与干预 | 不做技术支持（→Support） |
| 增购引导（配合销售） | 不做实施交付（→SA/PS） |
| QBR运营 | 不做产品功能设计（→PM） |
| Champion维护 | 不做合同谈判（→Sales） |

### CS团队结构（3种模式）

| 模式 | 适用 | 优劣 |
|---|---|---|
| CSM全覆盖 | 客户数<200 | 每个客户都有CSM，但人效低 |
| 分层CS | 客户数200+ | A类专属CSM/B类1:n/C类自助，性价比最优 |
| Pod模式 | Enterprise为主 | CSM+SA+AE三人组服务1个客户，深度最高但成本高 |

### CS与PM的协作

| 协作点 | CS输入 | PM输出 |
|---|---|---|
| 需求优先级 | 客户需求+健康度影响 | 需求排期+功能交付 |
| 产品路线图 | 客户增购/流失风险 | 路线图方向调整 |
| 产品发布 | 客户准备度评估 | 发布计划+沟通材料 |
| 健康度指标 | 产品使用数据需求 | 埋点+数据看板 |

## 3. 常见坑

### 坑1：CS=高级客服
- **症状**：CSM整天处理工单，没时间做QBR/增购
- **解法**：CS与Support必须分离——CS是主动的、价值导向的；Support是被动的、问题导向的

### 坑2：健康度评分=填表
- **症状**：健康度评分每月算一次但没人看
- **解法**：健康度必须触发行动——🟡→CSM主动联系、🔴→制定干预计划

### 坑3：CS只管续约不管增购
- **症状**：续约率95%但NRR只有100%
- **解法**：CS的目标不只是续约，更是NRR——增购是CS的核心KPI

### 坑4：所有客户一视同仁
- **症状**：CSM管30+客户，每个都顾不过来
- **解法**：分层CS——A类1:5、B类1:15、C类1:50+或自助

### 坑5：QBR走过场
- **症状**：QBR变成"产品功能更新汇报"，客户昏昏欲睡
- **解法**：QBR以客户业务成果为核心——展示"我们帮你省了多少时间/赚了多少钱"

## 4. 合规红线

| 红线 | 说明 |
|---|---|
| 数据访问权限 | CSM可看客户使用数据但不可看敏感业务数据（财务/HR） |
| 续约施压 | 不可用"不续约就停服务"施压——违约风险 |
| 竞品信息 | 不可在QBR上贬低竞品——可能构成不正当竞争 |

## 七、AI成本失控

### 7.1 定义与边界

**AI成本失控**是指AI产品在运营过程中，因缺乏Token消耗预算管控、缓存策略缺失、推理成本随用量指数增长而导致的成本不可控问题。与传统软件的"服务器成本随用户线性增长"不同，AI产品的Token成本与用户交互深度、上下文长度、生成量强相关，边际成本曲线更陡峭。

### 7.2 成本结构

| 成本类型 | 说明 | 可控性 |
|---|---|---|
| **Token调用费** | 输入Token+输出Token的API计费 | 高（可通过Prompt优化/缓存降低） |
| **推理算力** | 自部署模型的GPU推理成本 | 中（可通过量化/蒸馏降低） |
| **微调训练** | 业务数据微调的训练成本 | 中（一次性投入） |
| **RAG存储** | 向量数据库存储+检索成本 | 中（可通过分块策略优化） |
| **安全过滤** | 内容安全API/模型调用 | 低（必需支出） |

### 7.3 常见坑（E.03）

| ⚠️常见坑 | ✅推荐做法 |
|---|---|
| 无Token预算上限，突发流量导致账单爆炸 | 设日/月Token预算上限，超限自动降级或熔断 |
| 每次请求都调大模型，不缓存高频问题 | 高频问题答案缓存（语义缓存），命中率监控 |
| System Prompt每次全量发送，不做压缩 | System Prompt模板化+缓存，只发送变量部分 |
| 不区分场景用最贵模型（如GPT-4全场景） | 分层路由：简单任务用小模型，复杂任务用大模型 |
| 不监控单用户Token消耗，被滥用拖垮 | 单用户日Token上限+异常用量告警 |

### 7.4 避险技法（I.07）

- **模型分层路由**：简单意图分类→小模型（GPT-4o-mini/Claude Haiku）；复杂推理→大模型（GPT-4o/Claude Opus）；成本可降低60-80% [来源:📚训练知识 | 置信度:📚中]
- **语义缓存**：用Embedding相似度匹配已回答过的问题，命中缓存直接返回，跳过模型调用
- **Prompt压缩**：System Prompt中固定部分通过Prompt Caching技术只计费一次（OpenAI/Anthropic 2024-2025已支持）
- **流式输出+提前终止**：用户取消或检测到低质量输出时提前终止生成，减少无效Token消耗

## 八、AI迭代陷阱

### 8.1 定义与边界

**AI迭代陷阱**是指AI产品在模型升级、Prompt修改、功能迭代过程中，因模型行为不稳定（Model Drift）、Prompt脆弱性、评测集过拟合等原因导致"改了A坏了B"的系统性迭代风险。

### 8.2 迭代陷阱类型（D.02）

| 陷阱类型 | 机制 | 典型表现 |
|---|---|---|
| **模型漂移**（Model Drift） | 模型版本升级后，相同输入产生不同输出 | 用户反馈"AI突然变了"，历史对话效果退化 |
| **Prompt脆弱性** | 微小Prompt改动导致输出行为剧变 | 加一个空格/换行就改变输出风格 |
| **评测集过拟合** | 评测集被纳入训练数据，得分虚高 | 评测分数90%+，线上效果差 |
| **回归测试盲区** | 新功能上线未覆盖旧场景回归 | 新模型解决新问题但引入旧问题 |
| **数据分布漂移** | 用户实际提问分布与训练数据分布不一致 | 训练时效果好，上线后长尾问题多 |

### 8.3 常见坑（E.03）

| ⚠️常见坑 | ✅推荐做法 |
|---|---|
| 模型升级后不做回归测试直接上线 | 每次模型升级跑全量回归测试集，对比关键指标 |
| Prompt修改不做版本管理 | Prompt纳入Git版本管理，每次修改记录Diff+效果对比 |
| 评测集长期不更新，逐渐失真 | 评测集定期更新（月度），从线上日志采样真实用户问题 |
| 不做A/B测试直接全量切换 | 新模型先灰度5%流量A/B测试，关键指标达标后逐步放量 |

# Office 统一安全底座测试方案

> Phase 4 人工与自动化验收入口。Phase 3 未执行以下测试。

## 1. 前置条件

- 准备无敏感 `.xlsx/.docx/.pptx`，以及旧格式、宏、密码、外链、损坏包样本。
- 准备两个互不重叠的输入/输出目录；Windows 另准备 Credential Manager 查看工具。
- 记录应用版本、Windows/Office 版本和样本 SHA-256。

## 2. 主流程

| 用例 | 操作 | 预期 |
|---|---|---|
| 标准预检 | 选择安全 OOXML 与独立输出目录 | 进入待确认，无阻断项，源哈希不变 |
| 阻断常显 | 选择宏/旧格式，切换“警告”筛选 | 高保真阻断仍显示，确认按钮禁用 |
| 确认入队 | 安全样本点击确认 | 状态 queued，历史可见，不生成伪输出 |
| 取消 | 对 queued 任务取消 | 仅该 taskId 变 cancelled |
| 重启恢复 | 待确认/排队时关闭并重开应用 | 恢复区显示任务，可取消 |
| 历史分页 | 生成大量任务并刷新历史 | 顺序、数量、状态、体积准确 |

## 3. 联动与可访问性

- 文件/目录未齐时预检按钮禁用；补齐后启用，返回修改不丢当前选择。
- 问题筛选正向、反向和批量验证：全部显示；警告筛选仍保留全部阻断；阻断筛选不出现普通警告。
- Tab 顺序覆盖标签、类型、策略、文件、目录、预检、筛选、确认/取消；Enter/Space 可操作，焦点可见。
- 切换中英文后 Office 标签、向导、问题、状态和历史全部更新，不出现 key 文本。

## 4. 安全与故障注入

- 扫描数据库、日志、前端存储和崩溃输出，密码、正文、模型 Key 为零。
- 保存密码后修改文件，再读取必须返回 `OFFICE_CREDENTIAL_STALE`；删除后系统保险库不可恢复。
- 模拟数据库锁、磁盘不足、Worker 崩溃/卡死、畸形 JSONL、发布同名竞争和断电；不得出现伪成功文件或误杀用户 Office。
- 将旧状态机测试迁移到 `OutputTransaction → PublicationReceipt`，覆盖无凭证完成、taskId 不匹配和重复发布。

## 5. 通过标准

- 自动化套件全绿；人工主流程与键盘流程全部通过。
- 源文件损坏事故为 0，路径/正文/密码外泄为 0，阻断场景无绕过。
- macOS/Linux 真实系统分别验证 Keychain/Secret Service 后，才可宣称对应平台凭据支持。

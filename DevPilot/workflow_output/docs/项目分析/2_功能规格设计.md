# 2 · 功能规格设计

> 结构：A 面 = Codex 全覆盖功能对照表（必须都有）；B 面 = 自研增强功能（差异化）。
> 每条带 FR 编号与优先级（P0=MVP 必做 / P1=二期 / P2=三期），供 Phase 1 PRD 直接继承。

## A 面 · Codex 功能全覆盖清单

### A1 本地沙箱与任务执行

> 形态变化（2026-08-13 定调）：**主表面为桌面客户端，任务在用户本机执行**（对照 Codex CLI 本地沙箱：macOS Seatbelt / Linux Landlock 的先例，Windows 用作业对象/受限目录方案）。云端沙箱降级为远期可选项。

| FR 编号 | 功能 | Codex 基准 | 我们的实现要求 | 优先级 |
|---|---|---|---|---|
| FR-A01 | 本地隔离执行 | Codex CLI：系统级沙箱，代码不出本地 | 同等：默认只读写项目目录，越界操作需用户批准；执行环境按项目自动检测/引导安装 | P0 |
| FR-A02 | 并行任务 | 多任务互不干扰 | 本机多任务并行（资源占用可限）；可选 git worktree 隔离 | P1 |
| FR-A03 | 全流程闭环 | 读写文件→跑测试/lint→迭代到过→产出 diff | 同等，测试失败自动修复循环上限可配 | P0 |
| FR-A04 | 环境快速就绪 | 容器缓存提速 90% | 本地等价物：项目环境画像缓存（依赖清单+安装记录），二次任务秒级就绪 | P1 |
| FR-A05 | 自动环境配置 | 自动识别 npm/pip/go mod/cargo 等并安装 | 同等 + 零代码用户引导层：检测到缺环境时出「一键安装」向导（如自动装 Node）；失败时大白话解释 + 一键重试 | P0 |
| FR-A06 | 网络访问控制 | 任务期联网可配 | 同等，粒度到域名白名单；默认仅允许依赖源 | P1 |
| FR-A07 | 断点续跑 | 本地↔云端移交 | 本地等价物：任务崩溃/关机后可从最近存档点恢复续跑 | P1 |

## 功能裁剪说明

- **P0 共 27 条**：构成「桌面客户端走通一个真实项目 + Skills/MCP 开放 + Token 计费 + 进度可视与多轮续跑」的完整闭环，工作流引擎五条主链（FR-B01~B05）是不可砍的灵魂。
- **明确不做**（与 Codex 错位）：不做自有 IDE（用插件借位）、不做模型自研（模型路由接多家）、不做通用 Chat（垂直开发场景外不服务）、不做云端沙箱（本地执行为主，远期再评估）。

# 规格规格 · 积分计费系统（预付钱包 + 账单）

> SDD 特性级规格（Phase 1 产出）。实现须与本文件对齐；冲突时改实现或改本文档（注明原因）。
> 来源：本会话 Phase0 分析 + 用户决策（2026-08-07）。**取代** 未实现的 [TokenUsage统计.md](TokenUsage统计.md)（其仅统计、不计费，scope 已扩）。
> ≤5000 tokens。

## 1. 项目概述
- **定位**：全平台预付积分钱包。用户充值积分，调用任意大模型（文本对话/embedding/视频/图片）按价表实时扣积分；用户只见积分，管理员见真实 token+金额+积分。
- **背景与动机**：现状 LLM token 仅 2 处 `log.info` 打印（[DefaultChatStrategy:39](../../../backend/src/main/java/com/superprogrammer/engine/strategy/DefaultChatStrategy.java#L39)、[LlmCallHandler:63](../../../backend/src/main/java/com/superprogrammer/engine/executor/LlmCallHandler.java#L63)），零持久化、零计费。要对外提供服务须对用户屏蔽原始 token/钱，以「积分」为唯一面向用户的消耗单位；管理员要能配价、查成本。
- **成功指标**：
  1. 所有经 `LlmGateway`（chat/chatStream/embed）+ `MediaGenTaskWorker`（视频）的调用 100% 采 token、按价折 ¥、按比例折积分、同步扣余额。
  2. 并发扣减零超支（行锁）；调用失败 100% 全退。
  3. 用户视图零 token/¥ 泄漏；admin 视图可看全量真实消耗。
  4. 主链路（对话/RAG/记忆）延迟回归可忽略（采集异步；扣减同步单行 <5ms）。

## 2. 用户故事
- **管理员**：我在后台配各模型 input/output 价（文本按 1M token）、视频计费模式（按 token 或按秒）、图片单价、充值阶梯比例（¥→积分）。
- **管理员**：我手动给某用户充值积分（MVP）；后续用户自助支付（Phase2）。
- **管理员**：我看全局账单（真实 token 数 + ¥ + 积分），按用户/模型/日期筛，定位成本异常。
- **普通用户**：我看自己的积分余额 + 流水（充值/消耗/退款），只显积分，不知原始 token/钱。
- **普通用户**：余额 > 0 才能发起对话/生成；调用失败积分自动退回。

## 4. 非功能需求
- **性能**：
  - 采集**纯异步** fire-and-forget（独立池 + 攒批），主链路零延迟（采集不计入用户响应）。
  - **扣减同步**：单事务 `SELECT...FOR UPDATE` 锁余额行 + INSERT 流水，目标 <5ms；不阻塞超过一个单行写。
  - 线程池满（AbortPolicy）→ 丢**采集**任务记 WARN 不抛；**扣减不走异步池**（同步在调用线程），绝不丢。
  - 聚合查询走索引；百万行后考虑按月分区。
- **安全**：
  - 并发扣减：余额行锁防超支；`balance_after` 落流水可对账。
  - 普通用户只能查/扣自己（ownership 硬过滤 `WHERE user_id=currentUser`）。
  - 支付回调（Phase2）：签名校验 + `channel_order_id UNIQUE` 幂等 + 状态机校验；不存卡号/敏感，仅订单号。
  - 价表/比例/充值 admin 权限：`pricing:manage`、`points:recharge`。
  - usage 日志不含 prompt/回答原文（仅 token 计数 + 元数据），无 PII。
  - 余额不足固定话术，不透传异常细节。
- **可观测性**：扣减/退款/充值流水均可查；采集失败 WARN 计数；余额异常（单用户暴扣）告警留后续。
- **可回滚**：migration 加表，回滚 = drop（钱包/流水/价表无外部业务依赖，MVP 上线前）。**上线有真实余额后不可 drop**，须走数据迁移。

## 5. 架构
```
调用方(chat/stream/embed/video submit)
  │
  ├─① 预检 PointsWalletService.canAfford(userId) : balance>0 ?  no→拦截
  ▼ 真调用
LlmGateway / MediaGenTaskWorker
  │
  ├─② 采集(异步 fire-and-forget) ─► llm_usage_logs        [审计层·admin 看真 token]
  │
  └─③ 计费(同步事务):
        token ──PricingService──► ¥
          └────PointsRatioService(阶梯)────► 积分
                │ SELECT FOR UPDATE balance + INSERT ledger
                ▼
        user_points_balance / points_ledger
  │
  ├─ 失败 ─► PointsWalletService.refund()
  └─ 用户视图读 balance+ledger(显积分) ; admin 读 usage_logs(真 token+¥+积分)
```
**关键技术决策**：
1. **两写路径分离**：采集 = 异步（append 日志，可丢可攒批）；扣减 = 同步事务（不可丢，行锁）。复用 TokenUsage plan 的 side-channel `AtomicReference<TokenUsage>` 拿流式末 chunk usage，不改 Flux。
2. **预检>0 + 后扣实际**：文本/流式 cost 调用完才知道，故调用前只验余额>0，调用后按实际用量扣，允许瞬时负数（欠款），下次调用拦截。不预估预扣（避免估不准误拦/多扣）。
3. **失败全退**：扣减后若调用链路抛异常或 provider 明确失败 → 逆向退款流水。
4. **价表标 ¥，积分派生**：价表是真实金额；积分 = ¥ × 阶梯比例；admin 与用户通过积分/¥ 两层视图分权。
5. **视频按 token（Ark 回 usage）**，admin 可切按秒；**图片按张**（未实现 stub）；两者积分独立计，**不与文本 token 加总**（像素换算≠分词，见 SeedDance feature-map 踩坑批注）。
6. **支付 Phase2**：MVP 充值走 admin grant（channel=ADMIN，留 payment_order 行）；自助支付网关后接，复用同一余额/流水/订单表。

## 6. 数据模型
```sql
-- V63：钱包余额（可负=欠款）
CREATE TABLE user_points_balance (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL UNIQUE,
  balance_points DECIMAL(14,2) NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- V63：积分流水（append-only 对账）
CREATE TABLE points_ledger (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  user_id BIGINT NOT NULL,
  type VARCHAR(16) NOT NULL,          -- RECHARGE/CONSUME/REFUND/ADMIN_GRANT
  delta_points DECIMAL(14,2) NOT NULL,
  money_yuan DECIMAL(12,6),
  ref_type VARCHAR(16),               -- CHAT/EMBED/VIDEO/IMAGE/PAYMENT/ADMIN
  ref_id BIGINT,
  balance_after DECIMAL(14,2) NOT NULL,
  remark VARCHAR(256)
);
CREATE INDEX idx_ledger_user_time ON points_ledger(user_id, created_at);

-- V64：模型价表（多形态，admin 配）
CREATE TABLE pricing_rule (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  kind VARCHAR(8) NOT NULL,           -- CHAT/EMBED/IMAGE/VIDEO
  provider_id BIGINT,
  model VARCHAR(128) NOT NULL,
  price_input_per_million  DECIMAL(12,6),
  price_output_per_million DECIMAL(12,6),
  video_billing_mode VARCHAR(8),      -- TOKEN|SECOND
  price_per_second DECIMAL(12,6),
  price_per_image  DECIMAL(12,6),
  effective_from TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_pricing_lookup ON pricing_rule(kind, provider_id, model, effective_from DESC);

-- V64：阶梯比例（¥→积分，admin 配）
CREATE TABLE points_ratio_tier (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  min_amount DECIMAL(12,2) NOT NULL,
  max_amount DECIMAL(12,2),           -- null=∞
  ratio DECIMAL(10,4) NOT NULL,       -- 每 ¥ 换多少积分
  effective_from TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- V63：充值订单（admin grant MVP / 自助支付 Phase2）
CREATE TABLE payment_order (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  user_id BIGINT NOT NULL,
  amount_yuan DECIMAL(12,2) NOT NULL,
  points_granted DECIMAL(14,2),
  status VARCHAR(16) NOT NULL DEFAULT 'PENDING',  -- PENDING/PAID/FAILED/REFUNDED
  channel VARCHAR(16) NOT NULL,       -- ADMIN/ALIPAY/WECHAT
  channel_order_id VARCHAR(128),
  paid_at TIMESTAMPTZ
);

-- V63：审计日志（扩原 llm_usage_logs，加 kind/cost/points）
CREATE TABLE llm_usage_logs (
  id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  user_id BIGINT,
  provider_id BIGINT NOT NULL,
  provider_scope VARCHAR(8) NOT NULL DEFAULT 'GLOBAL',
  model VARCHAR(128) NOT NULL,
  kind VARCHAR(8) NOT NULL,           -- CHAT/EMBED/IMAGE/VIDEO
  tokens_input INT NOT NULL DEFAULT 0,
  tokens_output INT NOT NULL DEFAULT 0,
  cost_yuan DECIMAL(12,6),
  points_consumed DECIMAL(14,2),
  status VARCHAR(16) NOT NULL DEFAULT 'SUCCESS',
  error_msg VARCHAR(256)
);
CREATE INDEX idx_usage_user_time   ON llm_usage_logs(user_id, created_at);
CREATE INDEX idx_usage_provider_tm ON llm_usage_logs(provider_scope, provider_id, created_at);
CREATE INDEX idx_usage_model_time  ON llm_usage_logs(model, created_at);
```
**字段说明**：
- `balance_points` 可负：预检>0+后扣实际 的瞬时欠款；扣到负后下次预检拦。
- `balance_after`：每笔流水落当时余额，可正向重建对账。
- `kind`：账单按模型大类切；视频/图片积分独立计，不与文本加总。
- `cost_yuan`/`points_consumed`：落**当时**算的值，价表后续改不动历史（按 effective_from 取调用时价）。
- `payment_order` MVP 仅 admin grant（channel=ADMIN, status 直 PAID）；Phase2 自助支付补回调流转。
- 软删/审计四字段**不加**：余额/流水/日志皆 append-only 或单行 update，靠 created_at + 分区归档。

## 7. 测试策略
**单元测试**：
- `PointsWalletService`：并发扣减（多线程同 user）→ 余额行锁不超支；预检>0/≤0 分支；refund 逆向余额正确。
- `PricingService`：各 kind 询价（文本 input/output、视频 TOKEN/SECOND、图片按张）→ ¥ 正确；effective_from 取调用时价。
- `PointsRatioService`：阶梯命中区间（边界/∞）→ ratio 正确。
- 采集：mock provider 返不同 usage（真值/空/异常）→ 异步日志 + 同步扣减各正确。
- 流式 usage：mock OpenAI 末 chunk / Claude message_delta 带 usage → side-channel 采到 + 末尾扣减。

**集成测试**：
- 真 PG：一轮对话（chat + 记忆 embed×N + judge）→ 余额扣对、流水行数齐全、usage_logs 落 token+¥+积分。
- 视频：submit→markSucceeded 扣、markFailed 不扣/退、submit 预检余额≤0 拒。
- ownership：用户查自己 OK，查他人返空；admin 全量。

**⚠️ 测试重点（用户要求重点验）**：
1. **并发扣减不超支**：N 线程并发同用户扣 → 最终余额 = 初值 − Σ实际，无超扣（难点最高）。
2. **流式 cost 后扣 + SSE 字节回归**：末 chunk usage 采到、扣减发生在 doOnComplete；SSE 输出与改造前字节级一致（不改 Flux，13 调用方零回归）。
3. **失败全退**：provider 抛异常 → 余额回滚、流水落 REFUND。
4. **价表/比例生效**：admin 改价后新调用按新价，历史流水不动。

**手动/Playwright**：admin 配价→充值→用户发对话→余额减/流水增；失败重试→退积分；用户页只见积分；admin 页见真 token。

## 8. 边界与不做
- **不做配额/超限分级拦截**（仅 balance≤0 硬拦，无「剩 10% 预警」类）。后续再开。
- **不做预估预扣**（预检只验>0，避免估不准）。
- **不做场景/agent/workflow/project/session 维度切分**（用户明确砍）。
- **不存 prompt/回答原文**（仅 token + 元数据）。
- **图片生成 stub**（无真 provider，价表+wallet 分支预留，上线再接）。
- **支付网关 Phase2**（admin grant 充值 MVP 够用；自助支付单开）。
- **不做实时流式账单推送**（查询走库聚合）。

## 10. 术语表
| 术语 | 大白话 | 案例 |
|---|---|---|
| 预付钱包 | 先充值再消费，余额扣光不能用 | 用户充 1000 积分，对话扣到 0 拦截 |
| 积分 | 面向用户的消耗单位，= ¥×比例换算 | ¥0.5 消耗按 100pt/¥ 显 50 积分 |
| 阶梯比例 | 不同 ¥ 区间换不同积分比 | 充 ¥100→1000pt，¥500→5500pt |
| 预检>0+后扣 | 调用前只验有余额，调用后扣真实用量 | 余额 1pt 放行，实际扣 50pt→欠 49pt 下次拦 |
| 行锁 | 扣余额时锁这行，防并发同时扣超支 | `SELECT...FOR UPDATE` |
| side-channel | 不改主返回流，用外层变量传 usage | usage 写 AtomicReference，Flux 事件不变 |
| kind | 模型大类，账单切分维度 | CHAT/EMBED/IMAGE/VIDEO |

## 一、三轨制备案流程（D.05 方法论）

### 1.1 算法备案流程

**适用对象**：算法推荐/生成类服务（含AI生成内容服务）[来源:网信办《互联网信息服务算法推荐管理规定》| 🔍高 | 2022-2026]

```
Step 1：登录网信办算法备案系统
Step 2：填报算法基本信息（名称/类型/原理/数据）
Step 3：提交算法安全评估报告
Step 4：等待审核（10个工作日内）
Step 5：获得备案号，产品上线前公示
```

**PM注意**：算法备案是基础合规——所有AI生成内容服务都须做。

### 1.2 大模型备案流程

**适用对象**：提供生成式AI服务的基础大模型（自研或微调）[来源:网信办《生成式人工智能服务管理暂行办法》配套细则 | 🔍高 | 2026-03]

```
Step 1：完成大模型安全评估（语料安全/模型安全/内容风控）
Step 2：填报备案信息（模型架构/训练数据/安全措施）
Step 3：提交第三方机构安全评估报告
Step 4：省级网信办初审 → 国家网信办复核
Step 5：获得备案号
Step 6：服务上线后持续合规监测
```

**2026关键节点**：6月30日未完成备案的大模型服务已停止访问。截至2026-07已有988款完成备案 [来源:百家号 | 🔍高 | 2026-07-17]。

### 1.3 AI应用登记流程

**适用对象**：基于已备案大模型的AI应用（即调用别人家已备案大模型API做的产品）[来源:网信办配套细则 | 🔍高 | 2026-03]

```
Step 1：确认所调用的大模型已备案（获取备案号）
Step 2：填报应用信息（应用名/使用场景/调用大模型备案号）
Step 3：提交应用安全评估报告
Step 4：等待审核
Step 5：获得应用登记号
```

**2026关键节点**：9月30日AI应用登记截止——基于已备案大模型的AI应用必须登记。

## 二、《未成年人网络保护条例》专项（E.05 合规边界）

### 2.1 核心要求

[来源:《未成年人网络保护条例》2024-01施行 | 🔍高 | 2024-2026]：

| 要求 | PM落地 |
|---|---|
| 未成年人模式 | AI产品涉及未成年人用户的须提供"未成年人模式" |
| 内容适龄过滤 | AI生成内容须按年龄分级过滤——未成年人不可见的成人内容 |
| 时间管理 | 未成年人使用时长限制（通常每日1小时，节假日2小时） |
| 消费限制 | 未成年人付费/打赏须有监护人确认 |
| 个人信息保护 | 未成年人个人信息特别保护——收集须监护人同意 |

### 2.2 AI产品的未成年人保护PM设计

1. **年龄识别机制**：注册/使用时年龄核验（手机号实名/学籍认证等）
2. **未成年人模式默认**：识别为未成年人后自动切换未成年人模式
3. **内容过滤升级**：未成年人模式下AI输出做更严的内容过滤——涉黄涉暴涉政全部拦
4. **AI角色扮演特别保护**：AI陪伴/角色扮演产品的未成年人保护是重点——禁止诱导情感依赖/不当内容
5. **家长监管入口**：提供家长查看/管控接口

### 2.3 PM避坑

- **不可跳过年龄核验**：年龄核验不能"勾选确认我是成年人"就过关——须有实名/学籍等核验手段
- **未成年人模式不可被绕过**：模式切换须监护人密码/人脸
- **AI生成内容的适龄评估**：AI输出要有"适龄等级"评估机制

## 三、数据出境合规（E.05 合规边界 · 与D-20协同）

### 3.1 中国数据出境三大门槛

| 门槛 | 触发条件 | 动作 |
|---|---|---|
| 数据出境安全评估 | 关键信息基础设施运营者/处理100万人以上个人信息/重要数据 | 向国家网信办申报安全评估 |
| 个人信息出境标准合同 | 不触发安全评估的中等规模 | 与境外接收方签标准合同+备案 |
| 个人信息保护认证 | 跨国企业内部数据传输 | 通过认证 |

### 3.2 AI产品数据出境常见场景

1. **调用海外大模型API**：用户数据传给海外模型方——可能触发数据出境
2. **海外服务器托管**：用户数据存海外——触发数据出境
3. **跨境业务**：服务海外用户——双向数据流均可能触发

### 3.3 PM实操建议

1. **优先用中国已备案大模型**：服务中国境内用户时优先用通义/文心/智谱等已备案大模型，规避数据出境
2. **调用海外API须做合规评估**：评估数据出境安全评估是否触发
3. **数据最小化原则**：只传必要数据给海外模型方，敏感字段脱敏
4. **用户协议告知**：明确告知用户数据可能出境
5. **与D-20协同**：海外发行运营的整体合规在D-20

## 四、用户举报与IR响应（I.06 方法论）

### 4.1 用户举报机制

| 机制 | PM设计 |
|---|---|
| 产品内举报入口 | 每条AI生成内容附"举报"按钮，分类选择（涉黄/涉政/侵权/其他） |
| 举报响应时限 | 通常24小时内响应，72小时内反馈处理结果 |
| 举报数据回流 | 举报数据回流到风控规则库，作为护栏迭代依据 |
| 监管举报对接 | 涉重大违规须主动上报网信办 |

### 4.2 IR响应预案

合规事件应急响应（Incident Response）：

```
Phase 1：发现（监控/举报）
  → 全量日志调取 + 异常检测 + 影响范围评估

Phase 2：止损（48小时内补丁）
  → 临时下线涉事功能 + 紧急护栏补丁 + 全量回测

Phase 3：溯源
  → 攻击样本分析 + 根因定位 + 责任追究

Phase 4：告知
  → 用户告知（如有数据泄露）+ 监管报告（涉重大事件）

Phase 5：复盘
  → 护栏迭代 + 红蓝对抗更新 + 流程改进
```

### 4.3 PM避坑

- **没有IR预案=裸奔**：合规事件不可避免，预案决定损失大小
- **日志是事后兜底**：缺全量日志+异常告警，事后无法溯源
- **48小时补丁流程要跑通**：从发现到补丁上线不超过48小时，需演练
- **监管报告义务**：涉重大违规须主动上报——不可隐瞒

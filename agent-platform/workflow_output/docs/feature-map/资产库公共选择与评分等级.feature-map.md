## 表与 SQL 注解（Flyway）

> 建表/改表必须走 Flyway：`backend/src/main/resources/db/migration/V<n>__<描述>.sql`，已执行脚本不可改，改结构加新版本。

### `V132__asset_allow_public_copy.sql`（本功能唯一迁移）

```sql
-- 公众池复制管控开关：OWNER 发布时自选是否允许公共用户复制副本
-- DEFAULT TRUE：存量已发布项目保持"允许复制"现状，零行为变化
-- 回滚：drop column 无数据损失（列闲置无害）
-- 注意：unpublish 不清此列——跨"下架→再发布"保留上次选择供回显
ALTER TABLE asset_projects ADD COLUMN allow_public_copy BOOLEAN NOT NULL DEFAULT TRUE;
COMMENT ON COLUMN asset_projects.allow_public_copy IS '公众池复制开关：false=公共用户仅可引用不可复制；成员/OWNER/admin 恒可复制';
```

**生活比喻**：`asset_projects`（资产项目表）像一家店的货架清单；`allow_public_copy` 是贴在门口的「样品可拍照、不可搬走」告示——贴了（false）路人只能看（引用），店员和老板（成员/OWNER）照搬不误。

## 关键调用链

```
打分展示：DB score → AssetScoreService.getScore / AssetService.assembleList
        → AssetGrade.fromScore（取整→查表）→ VO.ownerGrade/memberAvgGrade → 前端徽章

等级筛选：AssetMatrixFilter 选 A+ → 前端 ASSET_GRADE_RANGE['A+']=[95,100]
        → emit scoreMin=95,scoreMax=100 → 复用既有区间查询（无新后端接口）

复制管控：PublicPublishDialog 开关 → publish(allowPublicCopy) → V132 列
        → 摘要/详情 VO（!Boolean.FALSE.equals 兜底）→ AssetProjectView.canCopyAsset 按钮显隐
        直调 API：AssetController.copy @AuditLog → AssetService.copyCurrent
        → 公共池&&allow=false&&!isMemberOrOwner → BusinessException(40302) → aspect 记 FAIL 审计
```

## 踩坑批注

- `Map.of` 的 `get(null)` 抛 NPE 不返 null——`AssetGrade.rangeOf` 先判空再查表。
- Mockito 严格模式：服务层新增 `selectById(projectId)` 使 3 个存量 copy 测试的旧 stub 失配（PotentialStubbingProblem）——补 stub 即可，非 bug。
- 滑杆默认 50 分=D 档（<70），不是 C；以常量表为准。
- 发布开关显式传值才覆盖、null 沿用、unpublish 不清——三态语义各有测试锁定。
